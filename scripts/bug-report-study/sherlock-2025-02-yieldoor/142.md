# Malicious vault owner will lock fee distribution and reduce yields for LP depositors.

### Summary

The lack of a maximum vesting duration check in the `addVestingPosition` function will cause indefinite fee lock-up for LP depositors as a malicious vault owner will set an excessively long vesting duration.

This results in reduced yields and potential capital flight for liquidity providers.

### Root Cause

In the [addVestingPosition function](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L426) of the [Strategy contract](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol), there is no cap on the `_vestDuration` parameter.

```solidity
/// @notice Creates a new position which is vested over time to the Vault depositors
    /// @param amount0 Amount of token0 to use when creating the position
    /// @param amount1 Amount of token1 to use when creating the position
    /// @param _vestDuration The duration over which the position will be vested
    /// @dev Any unused amounts of token0/ token1 are treated as a direct donation to the Vault
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;

        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;

        (uint160 sqrtPrice,,,,,,) = IUniswapV3Pool(pool).slot0();
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPrice,
            TickMath.getSqrtRatioAtTick(vp.tickLower),
            TickMath.getSqrtRatioAtTick(vp.tickUpper),
            amount0,
            amount1
        );

        vp.initialLiquidity = liquidity;
        vp.remainingLiquidity = liquidity;

        IUniswapV3Pool(pool).mint(address(this), vp.tickLower, vp.tickUpper, liquidity, "");

        vp.startTs = block.timestamp;
        vp.lastUpdate = block.timestamp;
        ongoingVestingPosition = true;
        vp.endTs = block.timestamp + _vestDuration;

        vestPosition = vp;
    }
```

The choice to allow vault owners to set an arbitrary vesting duration permits the creation of vesting positions with durations (e.g., 10 years) that delay fee distribution indefinitely, thereby harming LP yields.


### Internal Pre-conditions

1. The vault owner has the ability to call `addVestingPosition`.
2.  The `_vestDuration` parameter is allowed to be set to any value, such as a multi-year period, without any enforced upper limit.

### External Pre-conditions

Not needed.

### Attack Path

1. Vault owner calls `addVestingPosition` with `_duration = 10 years`, locking fees in a non-liquid position.
2. Fees generated by the Strategy are allocated to the vesting position but remain unclaimable until the vesting period ends.
3. LPs receive reduced yields due to locked fees, leading to capital flight.

### Impact

Liquidity providers (LPs) suffer reduced yields due to locked fees. LPs lose access to fee distributions for the duration of the vesting period. No direct financial gain; the attack is purely griefing.

### PoC

1. Vault owner sets an excessively long vesting duration (e.g., 10 years)
`uint256 maliciousDuration = 10 * 365 days;` // 10 years
`uint256 token0Amount = 1000 * 1e18;` // Example amount for token0
`uint256 token1Amount = 1000 * 1e18;` // Example amount for token1

2. Vault owner calls `addVestingPosition` with the malicious duration.
`vault.addVestingPosition(token0Amount, token1Amount, maliciousDuration);`

3. As a result, fees from this vesting position will remain locked for 10 years, indefinitely delaying fee distribution and reducing yields for LPs.

### Mitigation

Introduce a check in the `addVestingPosition` function to cap the vesting duration.

```solidity
require(_vestDuration <= 30 days, "Duration too long");
```
