# Incorrect Token Deduction in Withdraw Function

### Summary

A critical typo in Leverager.sol's withdraw function ([Line 232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#232#L232)) causes direct financial loss for users by failing to use available token1 balances for debt repayment, forcing unnecessary out-of-pocket payments.

### Root Cause

In `Leverager.sol` at [Line 273](https://github.com/your-repo/Leverager.sol#L273):

```javascript
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount; // BUG: Uses token0 balance
```
When handling token1-denominated positions, the code incorrectly uses amountOut0 (token0 balance) instead of amountOut1 (token1 balance) to calculate repayment amounts.


### Internal Pre-conditions

1. Position uses token1 as borrowed asset
2. Vault withdrawal returns token1
3. token1 balance exceeds debt (amountOut1 > owedAmount)

### External Pre-conditions

1. Active DEX liquidity for token1 (users must acquire it externally if short)
2. LendingPool allows token1 borrowing with accruing interest

### Attack Path

1. User opens position with token1 debt
2. Withdraws when vault returns token1
3. Contract ignores available token1 due to [Line 273](https://github.com/your-repo/Leverager.sol#L273) bug
4. User forced to repay full debt from wallet instead of using vault funds

### Impact

Users lose 100% of available token1 from withdrawal + pay equivalent debt from personal funds. 
Example: 10K debt +10K token1 from withdrawal -> User pays 10K from wallet(20K total loss).

### PoC

_No response_

### Mitigation

```javascript
// Line 273 - Before (bugged)
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;

// After (fixed)
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
```
