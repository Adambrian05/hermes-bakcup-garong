# Vault Share Manipulation in Leveraged Position Valuation

### Summary

A vulnerability in the vault share valuation mechanism will cause an overvaluation of leveraged positions for the lending protocol as an attacker will manipulate vault balances through a sandwich attack to artificially inflate their position's collateral value. The attacker can manipulate share pricing by first depositing a large amount into the vault, then upon detecting a pending openLeveragedPosition() transaction, quickly withdrawing their funds before the victim's transaction executes. This causes the victim to purchase shares at an unfavorable price, after which the attacker can deposit at the corrected, lower price, profiting from the price differential.

### Root Cause

In [Leverager.sol:openLeveragedPosition](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L103) the position's collateral value is calculated based on the current vault balances at the time of position creation:
```solidity
(uint256 shares, uint256 a0, uint256 a1) =
    IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);

up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price);

```
This design choice enables manipulation since it relies on the current vault balances which can be temporarily inflated. The key vulnerability is that the initCollateralUsd value is permanently recorded and used for important calculations, but it doesn't get updated to reflect the true value after a manipulated transaction.

### Internal Pre-conditions

The protocol must have initialized a vault
The openLeveragedPosition() function must calculate collateral value based on the current vault state 


### External Pre-conditions

The transaction ordering must allow for a successful sandwich attack execution

### Attack Path

Attacker prepares two accounts: one for temporary vault inflation (attackerExtra) and one for creating the leveraged position (attacker)
Attacker identifies the target vault with sufficient lending capacity and favorable liquidation parameters
AttackerExtra deposits significant funds into the vault to temporarily inflate the vault's token balances
Attacker immediately opens a leveraged position using the inflated vault balances as reference for share value
When calculating the collateral value, the protocol uses the current (inflated) vault balances, resulting in an artificially high collateral valuation
AttackerExtra immediately withdraws their temporary funds, returning the vault balances to normal
The attacker's leveraged position retains its inflated valuation, despite now being backed by a smaller pool of actual assets

### Impact

The protocol suffers an overvaluation of leveraged positions, allowing attackers to borrow more against their collateral than should be permitted. This undermines the protocol's risk management, potentially leading to undercollateralized positions that cannot be properly liquidated in case of market downturns. The attacker gains excess borrowing capacity, which can result in protocol insolvency if multiple positions using this technique default.

### Mitigation

Record and use fixed values for position valuation at the time of position creation, rather than relying on dynamically calculated values based on current vault balances

Implement slippage checks for vault deposit and withdrawal operations to prevent large temporary balance manipulations
