# Inconsistent сollateralization logic may allow immediate liquidation of newly opened positions

## Description:
The `Leverager::openLeveragedPosition()` function calls `_checkWithinlimits()` to verify that a new leveraged position adheres to the protocol’s risk parameters. This function includes a check to ensure that the position leverage does not exceed `vp.maxTimesLeverage` and `maxLevTimes`:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464
```solidity
// Leverager.sol
function _checkWithinlimits(Position memory up) internal {
    VaultParams memory vp = vaultParams[up.vault];
    (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
        ILendingPool(lendingPool).getLeverageParams(up.denomination);

    uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

    require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
    require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
    // ...
}
```

However, `_checkWithinlimits()` does not verify whether `initCollateralValue` meets the minimum collateralization percentage (`minCollateralPct`) used in `isLiquidateable()`.

The `Leverager::isLiquidateable()` function determines whether a position is eligible for liquidation based on its total collateral value (totalDenom) compared to the borrowed amount (`owedAmount`), ensuring that the position maintains sufficient margin:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411
```solidity
// Leverager.sol
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        // ...
        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
        // ...
    }
```

Since `_checkWithinlimits` does not validate whether `up.initCollateralValue` satisfies the same `minCollateralPct` threshold, a position may pass the leverage check but still be immediately liquidatable due to insufficient initial collateralization.

## Impact:
A user can open a position that complies with leverage limits but is immediately subject to liquidation because it does not satisfy the `minCollateralPct` requirement. Users have no chance to add more collateral or reduce debt before being liquidated. This may eventually create more uncovered and bad debt for the protocol.

## Recommended Mitigation:
To prevent this inconsistency, `_checkWithinlimits` should verify that the initial collateral value meets the same collateralization percentage requirement that is enforced in `isLiquidateable()`
