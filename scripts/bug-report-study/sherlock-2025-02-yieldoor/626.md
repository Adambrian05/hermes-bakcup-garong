# Allowing `weird ERC20s` to interact with the smart contract is a big red flag allow only whitelisted tokens to interact with the contract

### Summary

`Leverager.sol` is open to call `swap` with any pool as long as token to be sent back to the contract be either `token0` or `token1`. However this is an issue. an attacker can create a pool with a weird erc20 and pair it up with a token out, then when the contract calls swap. or forceApprove(router, 0). the contract may drain the `vault` for example.
- contract calls `forceApprove()`,
- however `forceApprove` has been twirked to `pullFunds()` the rest from `lendingPool.sol`.
- Tokens are sent to `Leverager.sol`, 
- After `PushFunds()` sends the first `pullFunds()`
- So the tokens that were pulled later will be `refunded` as if were the `attackers` own

### Root Cause

in Leverager.sol allow any type of tokens as long as the pair has the leveragers `token` 0 or 1, however an attacker can deploy a pair that uses for example the forceApprove(router, 0); to drain funds after the first transaction. This is because the protocol doesn't have a mapping of allowed tokens to interact with the contract. 

### Internal Pre-conditions

Lack of a check of allowed tokens while `openingLeverage` or `withdrawing`, or `repaying`,  
note: i really wanted to write the contract but time is runing out 

### External Pre-conditions

1. Weird Erc20 that alters how approve works, `IERC20(tokenIn).forceApprove(swapRouter, 0);` to `pullFunds()` from `lendingPool`

### Attack Path

1. while swapping from the weird Token to the registed tokenIn 
 ```javascript 
IERC20(tokenIn).forceApprove(swapRouter, 0); 
```
2. The weird ERC20 can set the forceApprove to max instead


```javascript
function approve(address spender, uint256 amount) public override returns (bool) {
    // If the contract tries to pulls funds from `lendingPool()`
    if (amount == 0) {
        lendingpool.pullFunds(asset, tobeStolen);
    } else {
        _allowances[msg.sender][spender] = amount;
    }
    return true;
}
```

### Impact

High possibility of losing all collateral of `lendingPool`
