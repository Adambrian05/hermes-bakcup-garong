# Funds Loss Due to Improper Validation Order in Deposit Function

## Summary
The `deposit` function in the `Vault` contract performs token transfers before validating that the calculated shares are greater than zero. If the deposit fee reduces the calculated shares to zero, the transaction will revert after tokens have already been transferred to the `Strategy` contract, resulting in permanent loss of user funds.

## Snippet
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L48

## Description
The issue stems from an improper sequence of operations in the `deposit` function of the `Vault` contract. The function transfers user tokens to the strategy contract before validating that the number of shares to be minted is greater than zero.
```solidity
function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
    external
    returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
{
    IStrategy(strategy).collectFees();

    (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

    (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

    IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
    IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1);

    if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

    require(shares > 0, "shares cant be 0");
    require(depositAmount0 >= amount0Min, "slippage0");
    require(depositAmount1 >= amount1Min, "slippage1");

    if (totalSupply() == 0) _mint(BURN, 1000);
    _mint(msg.sender, shares);

    return (shares, depositAmount0, depositAmount1);
}
```
The key issue is that the deposit fee is applied to the calculated shares after the tokens have been transferred but before validating that the resulting shares are greater than zero.

If `depositFee` is high enough and the number of `shares` calculated is small, reducing the fee in `if (depositFee > 0) shares -= (shares * depositFee) / 10_000;` can result in `shares = 0`. When the validation `require(shares > 0, "shares cant be 0")` is executed, the transaction will revert, but the tokens will have been transferred to the `strategy` contract.

## Scenario
1.	The vault owner sets a deposit fee (e.g., `depositFee = 10` which is 0.1%).
2.	A user attempts to make a small deposit that results in a low number of shares (e.g., `shares = 1`).
3.	After calculating the deposit fee: `shares -= (shares * depositFee) / 10_000`, the shares value becomes `0.999` which is truncated to `0` due to integer division.
4.	The transaction reaches the `require(shares > 0, "shares cant be 0")` check and reverts.
5.	However, the user's tokens have already been transferred to the strategy contract at this point.
6.	Since the transaction reverts after the transfer but before minting shares, the user loses their deposited tokens without receiving any shares in return.
7.	There is no mechanism to recover these tokens as they are now owned by the strategy contract, but not accounted for in the vault's total supply.
## Impact
Users making small deposits when a deposit fee is active could permanently lose their funds. The tokens would be transferred to the strategy contract but no shares would be minted to represent ownership of these tokens. This creates a discrepancy between the actual assets under management and the total supply of shares, effectively resulting in a donation to existing shareholders.

## Recommendation
Modify the `deposit` function to validate that shares will be greater than zero before transferring any tokens.
```solidity
function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
    external
    returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
{
    IStrategy(strategy).collectFees();

    (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

    (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

    // Apply deposit fee before validation
    if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

    // Validate before transferring tokens
    require(shares > 0, "shares cant be 0");
    require(depositAmount0 >= amount0Min, "slippage0");
    require(depositAmount1 >= amount1Min, "slippage1");

    // Transfer tokens after validation
    IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
    IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1);

    if (totalSupply() == 0) _mint(BURN, 1000);
    _mint(msg.sender, shares);

    return (shares, depositAmount0, depositAmount1);
}
```
