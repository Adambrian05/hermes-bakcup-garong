# An incorrect amount of tokens is sent to the `DEAD_ADDRESS` in the `LendingPool::_deposit` function.

## Summary:
The `LendingPool` transfers an incorrect amount of tokens to the `DEAD_ADDRESS` upon first deposit in a reserve..

## Bug Description:

Since tokens are ERC20 tokens, they follow decimals like 18, 12, 8, or 6.
The comment above the mint suggests that the `LendingPool` should transfer 1000 tokens, but the variable `MINIMUM_YTOKEN_AMOUNT` stores the value `1000`, which does not represent 1000 tokens since the token follows a certain number of decimals.

For example, if the YToken follows 18 decimals, 1000 tokens will be represented as `1000 * 10^18`.
Which is not followed in the `_deposit` function and `MINIMUM_YTOKEN_AMOUNT` variable.

## Impact 
If the token follows 18 decimals, the `LendingPool::_deposit` function transfers 0.000000000000001000 instead of `1000 * 10^18` tokens.
Incorrect tokens are send to  `DEAD_ADDRESS`, lp inflation attacks will not be defended.

## Mitigations
```solidity
IyToken(reserve.yTokenAddress).mint(DEAD_ADDRESS, MINIMUM_YTOKEN_AMOUNT * decimals); 
//decimals -> what ever decimals the token follows.
```
