# Incorrect leverage collateral value's calculation

### Summary

In [Leverager.sol:131](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L131), we use the total position's value as the initial collateral value. This will cause the leverage will always be less than 2x.

### Root Cause

In [Leverager.sol:131](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L131), users can borrow some denomination token and exchange to token0/token1 to increase the vault's share amount.

In `openLeveragedPosition`, we will calculate the collateral value and check the leverage. We need to make sure that the actual leverage cannot exceed our leverage limitation.

The leverage step is as below:
1. Alice transfers `amount0In` token0 and `amount1In` token1.
2. We pull `delta0` token0 and `delta1` token1 from the lending pull.
3. deposit all token0/token1 into the vault to generate some vault shares.
4. borrow denomination token.
5. exchange denomination token to get token0(around delta0) and token1(around delta1) to push token0/token1.

The problem here is the collateral calculation `initCollateralUsd` will include `delta0` token0 and `delta1` token1.

For example:
1. Alice's input token0 is 1000, input token1 is 1000.
2. We want to leverage 5X. We pull 4000 (delta0) token0 and 4000(delta1) token1. Deposit all token0 and token1 into the vault. Our vault share position's value is 10000. Here we assume token0/token1/denomination have the same decimal and prices.
3. Borrow 8000 denomination tokens to swap out 4000 token0 and 4000 token1.
4. Pay back token0 and token1. User's input collateral value is 2000. And the position's value is 10000. So we have one 5x leveraged position.
5. In `initCollateralUsd`'s calculation, we use `a0` and `a1` to calculate the collateral value, 10000. Considering that borrowed `denomination` token will always be less than the total position's value. So `positionLeverage` will always be less than 2X.

### Attack Path
1. Alice's input token0 is 1000, input token1 is 1000.
2. We want to leverage 5X. We pull 4000 (delta0) token0 and 4000(delta1) token1. Deposit all token0 and token1 into the vault. Our vault share position's value is 10000. Here we assume token0/token1/denomination have the same decimal and prices.
3. Borrow 8000 denomination tokens to swap out 4000 token0 and 4000 token1.
4. Pay back token0 and token1. User's input collateral value is 2000. And the position's value is 10000. So we have one 5x leveraged position.
5. In `initCollateralUsd`'s calculation, we use `a0` and `a1` to calculate the collateral value, 10000. Considering that borrowed `denomination` token will always be less than the total position's value. So `positionLeverage` will always be less than 2X.

### Impact
1. The leverage limit cannot work as expected. Because the calculated position's leverage is less than the actual leverage.
2. Users can open positions with one higher leverage. The position's health is impacted by token0/token1/denomination token's price. If the denomination token price increases, higher leverage position's debt will increase quickly. This will increase system risk for the bad debt.

### Mitigation
User's initial collateral value should be `opened position's value - borrowed denomination token's value`.
