# Mismatch in vesting position ticks in collectFees() may lead to DoS

### Summary

[Strategy.sol:collectFees()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159) reverts if main position is rebalanced after vesting position creation because of mismatch in vesting position ticks.

### Root Cause

`collectFees()` uses the current main position's upper tick for the vesting position, which may cause a `revert` in Uniswap pool contract if the main position is rebalanced:
```solidity
/// @notice Collects all outstanding position fees
/// @notice In case there's ongoing vested position, collects the already vested part of it.
function collectFees() public {
    (uint256 preBal0, uint256 preBal1) = idleBalances();

    if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
    if (secondaryPosition.liquidity != 0) {
        collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
    if (ongoingVestingPosition) {
        //@audit tickLower is vestPosition, but tickUpper from mainPosition
        collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
    }
    ...
}

function collectPositionFees(int24 tickLower, int24 tickUpper) internal {
    IUniswapV3Pool(pool).burn(tickLower, tickUpper, 0);
    IUniswapV3Pool(pool).collect(address(this), tickLower, tickUpper, type(uint128).max, type(uint128).max);
}
```

### Internal Pre-conditions

1. `ongoingVestingPosition = true`

### External Pre-conditions

1. Main position is rebalanced after vesting creation

### Attack Path

_No response_

### Impact

DoS of `collectFees()` and functions where it's used after rebalancing main position when vesting is ongoing

### PoC

Add this test to `yieldoor/test/Leverager.t.sol`:
```solidity
function test_collectFeesRevertOnVestingPosition() public {
    vm.startPrank(owner);

    deal(address(wbtc), owner, 2e8);
    deal(address(usdc), owner, 100_000e6);

    wbtc.approve(vault, type(uint256).max);
    usdc.approve(vault, type(uint256).max);

    (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();

    int24 tickLower = IStrategy(strategy).getMainPosition().tickLower;
    int24 tickUpper = IStrategy(strategy).getMainPosition().tickUpper;

    );
    (uint256 amount0, uint256 amount1) = LiquidityAmounts.getAmountsForLiquidity(
        sqrtPriceX96, TickMath.getSqrtRatioAtTick(tickLower), TickMath.getSqrtRatioAtTick(tickUpper), liquidity

    IVault(vault).addVestingPosition(amount0, amount1, 1 days);

    bytes32 slot6 = vm.load(address(strategy), bytes32(uint256(6)));
    int24 _tickLower = int24(uint24(uint256(slot6)));

        (uint256(uint24(uint24(newTickUpper))) << 24)// tickUpper in next 24 bits
    );
    vm.store(address(strategy), bytes32(uint256(6)), packedValue);

    vm.expectRevert(bytes("NP")); //https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/libraries/Position.sol#L54
    IStrategy(strategy).collectFees();
```

### Mitigation

Change upper tick for vesting position in `collectFees()`:
```solidity
collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
```
