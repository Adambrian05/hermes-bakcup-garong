# Missing update of states in the `setBorrowingRateConfig()` function

### Summary
The `reserve.updateState()` and `reserve.updateInterestRates()` should be called before modifying the borrowing rate configuration in the `setBorrowingRateConfig()` function. This function is essential for accounting for the time elapsed since the last update and for accruing interest from borrowing operations. It relies on the current borrowing rate to calculate the compounded interest for the previous time period.

To ensure accuracy, the `reserve.updateState()` and `reserve.updateInterestRates()`function should be invoked before every administrative call to update the borrowing rate configuration, similar to how it is called before each deposit, redeem, borrow, or repay operation. This is necessary because the time that has passed must be accounted for using the previous rate.

### Root Cause
In the [setBorrowingRateConfig](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/LendingPool.sol#L348-L358) function, there is no update of state and interest rate.

```solidity
    /// @notice Sets the BorrowingRateConfig for an asset
    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    }

    function setBorrowingRateConfig(
        DataTypes.ReserveData storage reserve,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) internal {
        // (0%, 0%) -> (utilizationA, borrowingRateA) -> (utilizationB, borrowingRateB) -> (100%, maxBorrowingRate)
        reserve.borrowingRateConfig.utilizationA = PRECISION * utilizationA / 10_000;

        reserve.borrowingRateConfig.borrowingRateA = PRECISION * borrowingRateA / 10_000;

        reserve.borrowingRateConfig.utilizationB = PRECISION * utilizationB / 10_000;

        reserve.borrowingRateConfig.borrowingRateB = PRECISION * borrowingRateB / 10_000;

        reserve.borrowingRateConfig.maxBorrowingRate = PRECISION * maxBorrowingRate / 10_000;
    }
```

### Internal pre-conditions
The owner changes the borrowing rate config.

### External pre-conditions
N/A

### Attack Path
N/A

### Impact
Unfair and incorrect interest calculations occur when the protocol fails to calculate and apply interest up to the last update before changing the interest rate configuration. If the admin updates the interest rate, the new rate should only apply to future periods, while past periods should utilize the previous rate.

### PoC
N/A

### Mitigation
Add the `reserve.updateState()` and the `reserve.updateInterestRates()` functions in the `setBorrowingRateConfig()` function.
