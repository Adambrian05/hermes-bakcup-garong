# `LendingPool::setBorrowingRateConfig` function should call the `ReserveLogic::updateState` and `ReserveLogic::updateInterestRates` functions

### Summary

The `setBorrowingRateConfig` function is missing the calls of `updateState` and `updateInterestRates` functions and this will lead to use the incorrect borrowing rate instead of using current borrowing rate which is correct.

### Root Cause

The [LendingPool::setBorrowingRateConfig](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/LendingPool.sol#L241) function updates the `borrowingRateA` and `borrowingRateB`.

The function is as follows:

```solidity
    function setBorrowingRateConfig(
        DataTypes.ReserveData storage reserve,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) internal {
        // (0%, 0%) -> (utilizationA, borrowingRateA) -> (utilizationB, borrowingRateB) -> (100%, maxBorrowingRate)
        reserve.borrowingRateConfig.utilizationA = PRECISION * utilizationA / 10_000;


        reserve.borrowingRateConfig.borrowingRateA = PRECISION * borrowingRateA / 10_000;


        reserve.borrowingRateConfig.utilizationB = PRECISION * utilizationB / 10_000;


        reserve.borrowingRateConfig.borrowingRateB = PRECISION * borrowingRateB / 10_000;


        reserve.borrowingRateConfig.maxBorrowingRate = PRECISION * maxBorrowingRate / 10_000;
    }
```

As evident from the code snippet, the function is missing the calls of [updateState](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/libraries/ReserveLogic.sol#L131-L133) and [updateInterestRates](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/libraries/ReserveLogic.sol#L140-L143) and this will lead to incorrect calculation of borrowing rates after this function is invoked and until the next update of the state, the old incorrect borrowing rates will be used.

### Attack Path

1. The `setBorrowingRateConfig` function is called and set new borrowing rates.
2. But this new config won't be used until the update of the state is called.

### Impact

The impact is that the protocol is not able to make the new borrowing rates to be used. This means that old borrow rates will be used until the call of  sth like `deposit/borrow` that updates the state. And it could lead to loss of funds to the protocol if the new borrow rate is higher than the older one

N/A

### Mitigation

It is recommended to call the above mentioned functions in the `setBorrowingRateConfig`.
