# Users can create 40x leverage position

### Summary

Incorrect calculation of position's leverage will make it possible for a user to create a position with up to 40x leverage.

### Root Cause

Let's check how position's leverage ratio is [calculated](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L459-L474):

```solidity
    function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

@>      uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
        require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        require(up.initBorrowedUsd <= vp.maxUsdLeverage, "too high borrow usd amount");
        require(up.borrowedAmount <= maxIndividualBorrow, "too high borrow for the vault");
        require(
            vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD,
            "vault exceeded borrow limit"
        );
    }
```

From the above implementation, we can state that:

```math
positionLeverage = \dfrac {initCollateralValue + borrowedAmount} {initCollateralValue} 
```

`initCollateralValue` is calculated [as the following](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L129-L131):

```solidity
        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); // returns the USD price in 1e18
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;
```

In other words:

```math
initCollateralValue = userFund + borrowedAmount
```

Thus

```math
\begin{equation}
\begin{split}
positionLeverage &= \dfrac {initCollateralValue + borrowedAmount} {initCollateralValue} \\
&= \dfrac {userFund + borrowedAmount + borrowedAmount} {userFund + borrowedAmount} \\
&= 1 + \dfrac {borrowedAmount} {userFund + borrowedAmount} \\
& \le 2
\end{split}
\end{equation}
```

So position's leverage ratio will always be less than 2 no matter how much money the position borrowed.

### Impact

So what will be the maximum leverage the protocol allows?

When a leveraged position is opened, there is a check that if the newly created position is liquidatable.

```solidity
    uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
    base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

@>  if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
```

If the position is liquidatable, the opening transaction will revert, so we need to find out the max value that meets the OR condition.

For new positions, the first condition `owedAmount > totalDenom` is always FALSE, so let's check the second one.

Assuming `vp.maxTimesLeverage = 5`, we can state the following:

- `totalDenom - owedAmount = userFund`
- `vp.minCollateralPct = 0.1` (by parameters set in tests and in security doc)
- `base = owedAmount / 4`
- Thus, `userFund < 0.1 * owedAmount / 4 = owedAmount / 40`

So theoritical leverage ratio is 40, instead of 5.


> NOTE: Position's borrowed amount will be capped by other guardrails such as `vp.maxUsdLeverage`, `lendingPool.maxIndividualBorrow` and `vault.maxCumulativeBorrowedUsd`

In overall, users can break market's leverage limit and perform highly risky operations. 40x leverages will bring significant fund loss to the protocol, as price change will be enlarged by 40 times and users don't have enough collateral to cover their debt  when they are liquidated.



### PoC

**Scenario**
- User has total 2500 USD 
  - 0.0125 WBTC = 1250 USD
  - 1250 USDC = 1250 USD
- User is able to a leveraged position worth 100k USD
  - 0.5 WBTC = 50000 USD
  - 50000 USDC = 50000 USD
  - Borrowed USDC amount is roughly 100k USD
- Actual leverage ratio is 100k / 2500 = 40x

### Mitigation

Leverage ratio calculation should be fixed as the following:

```diff
diff --git a/yieldoor/src/Leverager.sol b/yieldoor/src/Leverager.sol
index b59c56c..bf75659 100644
--- a/yieldoor/src/Leverager.sol
+++ b/yieldoor/src/Leverager.sol
@@ -461,7 +461,7 @@ contract Leverager is ReentrancyGuard, Ownable, ERC721, ILeverager {
         (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
             ILendingPool(lendingPool).getLeverageParams(up.denomination);
 
-        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
+        uint256 positionLeverage = (up.initCollateralValue) * 1e18 / (up.initCollateralValue - up.borrowedAmount);
 
         require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
         require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");

```

With the above implementation, leverage ratio will be calculated as the following:

```math
positionLeverage = \dfrac {userFund + borrowedAmount} {userFund}
```
