# The first deposit logic issue caused user losses



# Summary

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L104-L132

In the _deposit function, the following logic will be executed for the first deposit (i.e., when the total supply of yTokens is 0):

```solidity
if (IyToken(reserve.yTokenAddress).totalSupply() == 0) {
    // Burn the first 1000 yToken, to defend against lp inflation attacks
    IyToken(reserve.yTokenAddress).mint(DEAD_ADDRESS, MINIMUM_YTOKEN_AMOUNT);
    yTokenAmount -= MINIMUM_YTOKEN_AMOUNT;
}
```

The purpose is to prevent LP inflation attacks (such as the first depositor manipulating the exchange rate with a very small amount) by burning a certain number of yTokens (assuming MINIMUM_YTOKEN_AMOUNT = 1000).

An error in the handling logic caused significant losses for the first user's deposit.

# Vulnerability Detail

Contradiction in threshold handling:

Condition check: require(yTokenAmount > MINIMUM_YTOKEN_AMOUNT) ensures that the yTokens generated from the user's deposit must exceed 1000.

Actual effect: If the user's deposit generates yTokenAmount = 1000, the transaction is rejected; if it generates 1001, after burning 1000, the user only receives 1 yToken.

Contradiction: The user must deposit enough assets to generate more than 1000 yTokens, but the actual return may be far below expectations (e.g., 1001 → 1), losing 99.9% of the value, causing financial loss to the user.

fix:
We can choose to replace the fixed amount reduction with setting a certain percentage (for example, 1%), or ensure that the initial deposit amount is significantly greater than 1000.

# Impact

Caused user losses

# Recommendation

Change the burned yTokens from MINIMUM_YTOKEN_AMOUNT to a proportional deduction (e.g., 1% of the first deposit) to avoid extreme situations caused by a fixed value.

```solidity
if (totalSupply == 0) {
    uint256 burnAmount = yTokenAmount * BURN_RATE / PRECISION; // e.g., BURN_RATE = 100 (1%)
    IyToken(reserve.yTokenAddress).mint(DEAD_ADDRESS, burnAmount);
    yTokenAmount -= burnAmount;
}
```
