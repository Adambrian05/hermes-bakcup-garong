# Uninitialized Strategy in Vault Constructor Enables User Interaction with Non-Functional Vault

## Affected lines of code

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L191-L194

## Details

The Vault contract in `Vault.sol` implements critical functionality that depends on an initialized strategy address for operations like deposits, withdrawals, and balance management. Currently, the strategy is set after deployment via `setStrategy()` function (lines 191-195), while the constructor (lines 33-38) only initializes token addresses.

This implementation creates a window where the vault exists with strategy = address(0) and users can still attempt to interact with it. All core functions in the vault make calls to the strategy address, including:

- deposit()
- withdraw()
- balances()
- checkPoolActivity()


## Impact

The impact is severe as it affects the core functionality of the vault and user funds:

1. Failed Deposits: Users attempting deposits during this uninitialized state would have their transactions revert when trying to call IStrategy(strategy).collectFees(), losing gas fees.

2. Blocked Withdrawals: Any shares minted before strategy initialization would be temporarily locked as withdrawals would fail when trying to interact with the non-existent strategy.

3. Incorrect Balance Reporting: Balance queries would revert, preventing users from getting accurate information about their positions.

e4. System Integration Issues: Other protocols integrating with the vault could malfunction if they interact with it before strategy initialization.


## Illustration

Current vulnerable implementation:

```solidity
constructor(address _token0, address _token1) ERC20("", "") Ownable(msg.sender) {
    if (_token0 > _token1) (_token0, _token1) = (_token1, _token0);
    token0 = _token0;
    token1 = _token1;
}

function setStrategy(address _newstrategy) external onlyOwner {
    require(strategy == address(0), "strat cant be set twice");
    require(_newstrategy != address(0), "strat cant be address(0)");
    strategy = _newstrategy;
}
```

```solidity
function deposit(...) external returns (...) {
    IStrategy(strategy).collectFees();  // Reverts if strategy = address(0)
    // ... rest of deposit logic
}
```

## Recommendation

Modify the constructor to require and set the strategy address during deployment:

```solidity
constructor(
    address _token0,
    address _token1,
    address _strategy
) ERC20("", "") Ownable(msg.sender) {
    if (_token0 > _token1) (_token0, _token1) = (_token1, _token0);
    
    require(_strategy != address(0), "strategy cannot be zero address");
    token0 = _token0;
    token1 = _token1;
    strategy = _strategy;
}
```

This ensures the vault is fully initialized and functional before any user interaction can occur, preventing potential issues with uninitialized strategy addresses.
