# Strategy is not collecting all vested position fees on Uniswap

### Summary

There is a typo in the function `Strategy.collectFees()` where, when a vested position is ongoing (`ongoingVestingPosition = true`), the fee is wrongly collected on Uniswap tickUpper 

### Root Cause

There is a typo in the function `Strategy.collectFees()` where, when a vested position is ongoing (`ongoingVestingPosition = true`), the fee is wrongly collected on Uniswap tickUpper  

In [Strategy.sol#L167](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167), 

we should use `vestPosition.tickUpper` instead of `mainPosition.tickUpper`. Otherwise, it is possible that not all fees are collected. 

### Internal Pre-conditions

1 - Vesting Position should be ongoing

### External Pre-conditions
1 - The price move below the current price 

### Attack Path

1 - Vesting position are create
2 - The price move below the current price 
3 - the rebalancer call balancer 
4 - user try to collected fee by calling on of the function like (deposit)

### Impact

If vestPosition.tickUpper differs from mainPosition.tickUpper, part (or all) of the fees from the vested liquidity range will not be harvested.
The function intends to collect fees specifically for the vested position, but by using the wrong upper tick, the contract might be collecting from the wrong range—or not collecting the entire range—compromising the accuracy of the vesting process.

or if the price vestPosition.tickUpper < vestPosition.tickLower , we could have DOS , and nobody will be able to deposit or withdraw until the vestPosition.tickUpper > vestPosition.tickLower

### Mitigation

Change the code to 

```diff
/// @notice Collects all outstanding position fees
/// @notice In case there's an ongoing vested position, collects the already vested part of it.
function collectFees() public {
    (uint256 preBal0, uint256 preBal1) = idleBalances();

    if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
    if (secondaryPosition.liquidity != 0) {
        collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
    if (ongoingVestingPosition) {
-       collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+       collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
    }

    (uint256 afterBal0, uint256 afterBal1) = idleBalances();

    uint256 protocolFees0 = (afterBal0 - preBal0) * protocolFee / 10_000;
    uint256 protocolFees1 = (afterBal1 - preBal1) * protocolFee / 10_000;

    if (protocolFees0 > 0) IERC20(token0).safeTransfer(feeRecipient, protocolFees0);
    if (protocolFees1 > 0) IERC20(token1).safeTransfer(feeRecipient, protocolFees1);

    if (ongoingVestingPosition) {
        _withdrawPartOfVestingPosition(); // Doing this now, otherwise, we'd charge protocol fees for the vested position
    }
}
```
