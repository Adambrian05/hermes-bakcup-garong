# Due to the loss of precision, _calculateTokenValues ​​will severely underestimate the value of the collateral.

### Summary

The function _calculateTokenValues is used to calculate the USD value of token0(amount0) and token1(amount1). When there is no price feed for token1 in pricefeed, the price of token1 will be calculated by using the price of the token0/token1 pool. However, due to loss of precision in calculating the `amount1 * PRECISION / price * chPrice0 / decimals0`, the usdValue will be lower than expected.

Here we take WETH/USDC(WETH is token0 and USDC is token1) as an example. According to the logic of the contract, the price of the pool will be about 3000e36 (if 1ETH = 3000USD). If chPrice1==0(there is no price feed for USDC) and amount1=1000e6. Then according to the calculation logic: amount1 * PRECISION / price = 1000e6 * 1e30 / 3000e36 = 0, which means the USDC (token1) part has a 0 USD value.

### Root Cause

Dividing and then multiplying will result in a loss of precision, making the USD value calculation incorrect.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L446-L448

```solidity
        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0; //@@@audit: ETH/USD, usdValue will be 0 because division precedes multiplication 
        }
```

### Internal Pre-conditions

1. No price feed for token1
2. Pools such as ETH/USD or BTC/USD are used.

### External Pre-conditions

1. When the function _calculateTokenValues ​​is called, this can be an external call to liquidatePosition, openLeveragedPosition.

### Attack Path

None

### Impact

In the function openLeveragedPosition, the initial collateral value of the user will be seriously underestimated, causing losses to the user. 

Or in the function isLiquidateable, the collateral value will be underestimated, causing the position to be liquidated (which should not be liquidated).

### PoC

_No response_

### Mitigation

Adjust the order of calculations.

```solidity
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION * chPrice0 / price / decimals0; //@@@audit: ETH/USD, usdValue will be 0 because division precedes multiplication 
        }
```
