# Incorrect collateral comparison will prematurely liquidate positions

### Summary

The `isLiquidateable` function incorrectly compares `base` against `pos.initCollateralValue` instead of `pos.initCollateralValue - pos.borrowedAmount`. This causes some positions to be liquidated even when they are **not liquidateable**.  

### Root Cause

[`base`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408) is calculated from `owedAmount` and `maxTimesLeverage` for `minCollateralPct` check.
After that, `isLiquidateable` function compares `base` with the initial collateral asset amount when opening the position, and use the minimum value in the `minCollateralPct` condition.
`pos.initCollateralValue` is the position size and the real collateral from user, is `pos.initCollateralValue - pos.borrowAmount`.
In short, `pos.initCollateralValue - pos.borrowAmount` should be used instead `pos.initCollateralValue`.

```solidity
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        ...
        uint256 totalDenom = totalValueUSD * (10 ** ERC20(pos.denomination).decimals()) / bPrice;

        uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(pos.denomination);
        uint256 owedAmount = pos.borrowedAmount * bIndex / pos.borrowedIndex;

        /// here we make a calculation what would be the necessary collateral
        /// if we had the same borrowed amount, but at max leverage. Check docs for better explanation why.
@>      uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
@>      base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
        else return false;
    }
```

### Internal Pre-conditions

Certain position satisfies following condition:
`pos.initCollateralValue - pos.borrowAmount` < `owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18)`

### External Pre-conditions

No response

### Attack Path

No response

### Impact

Positions which are not liquidateable, can be liquidated prematurely due to the incorrect comparison.

### PoC

1. When open leverage position, `initCollateralValue` = 650, `borrowedAmount` = 550.
2. `maxLeverage`= 5,  `minCollateralPct` = 10%
3. When checks whether the position is liquidateable, `totalDenom` is 610 and `owedAmount` is 600. (borrowAmount increases and position worth decreases)
4. `base` is calculated from `owedAmount` and `maxLeverage`:
base = 600 / (5  -1) = 150
5. `base` is compared to `initCollateralValue`:
base = min(150, 650) = 150
6. `totalDenom - owedAmount` is compared to `minCollateralPct * base`:
610 - 600 < 150 * 10%
7. position is liquidateable.

But if `base` is compared with real user collateral(`initCollateralValue - borrowedAmount`), position is not liquidateable.
base = min(150, 650 - 550) = 100, 610 - 600 >= 100 * 10%

### Mitigation

1. Update the comparison in `isLiquidateable` function:
```diff
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        ...
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
-       base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
+       base = base < pos.initCollateralValue - pos.borrowAmount? base : pos.initCollateralValue - pos.borrowAmount;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
        else return false;
    }
```
