# Secondary position range misalignment could fragment liquidity and break out-of-range invariant

### Summary

The way `tick - modulo` is calculated in [_setSecondaryPositionsTicks()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L366) does not guarantee that the secondary position is correctly aligned with the main position. An attacker can exploit this to immediately steal from the protocol due to double counting caused by overlapping.

### Root Cause

In `Strategy.sol`, _setSecondaryPositionsTicks sets the secondary position range but does not ensure proper alignment with the main position.

```solidity
if (bal0in1 < bal1) {
    secondaryPosition.tickLower = mainPosition.tickLower;
    secondaryPosition.tickUpper = tick - modulo;  // Could be > mainPosition.tickUpper
} else {
    secondaryPosition.tickLower = tick - modulo + tickSpacing;  // Could be < mainPosition.tickLower
    secondaryPosition.tickUpper = mainPosition.tickUpper;
}
```

The issue arises because:

1.`tick - modulo` could result in any tick value.

2. There's no validation that the secondary position's range properly aligns with the main position.

3. The calculation doesn't guarantee the out-of-range property required by the strategy.

Assume a market condition lead to a tick value where:

```solidity
   tick - modulo > mainPosition.tickUpper  // Case 1
   // or
   tick - modulo + tickSpacing < mainPosition.tickLower // Case 2
```

During rebalance, the secondary position could take any of these misaligned form:

- Overlap with the main and secondary positions
                    Current Price (tick)
                          ↓
                          *

|-------- Main Position --------|
      |---- Secondary Position ----|
      ^^^^^^^^ Overlap region ^^^^^^

Impact: Both positions compete for same liquidity range, breaking single-token holding strategy

- Gaps between main and secondary positions

|-------- Main Position --------|
                                    |---- Secondary Position ----|
        ^^^^^^^ Dead zone - unused liquidity range ^^^^^^^

Impact: Wasted potential liquidity range, reducing capital efficiency

3. Secondary position not being fully out-of-range
                      
|-------- Main Position --------|
                      |---- Secondary Position ----|
                      * Current Price
                      ↑ Secondary includes current price

Impact: Secondary position holds both tokens instead of intended single token, breaking strategy invariant

### Impact

1. Broken Strategy Invariant: Secondary positions might not be fully out-of-range after rebalancing, defeating their purpose of holding excess single-token liquidity.

2. Fragmented Liquidity: Gaps or overlaps between main and secondary positions could lead to inefficient liquidity utilization.

3.  Attacker leverages double-counted liquidity from overlapping positions to extract borrowed funds.

### Mitigation

Design the `_setSecondaryPositionsTicks` to align with the main position and ensure that the out-of-range property is achieved.

```solidity
   if (bal0in1 < bal1) {
        // More token1, position below main
        secondaryPosition.tickLower = mainPosition.tickLower - positionWidth;
        secondaryPosition.tickUpper = mainPosition.tickLower;
    } else {
        // More token0, position above main
        secondaryPosition.tickLower = mainPosition.tickUpper;
        secondaryPosition.tickUpper = mainPosition.tickUpper + positionWidth;
    }
```
