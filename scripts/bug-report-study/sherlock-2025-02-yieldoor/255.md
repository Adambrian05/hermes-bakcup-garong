# Not enough Chainlink checks can make the protocol behave incorrectly

### Summary

The missing checks in `PriceFeed.sol` can make protocol behave incorrectly 

### Root Cause

In [`PriceFeed.sol`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/PriceFeed.sol?plain=1#L58) there are missing checks on
1. Latest price. It can return negative number or 0.
2. Sequencer is running. Optimistic rollup protocols move all execution off the layer 1 (L1) Ethereum chain, complete execution on a layer 2 (L2) chain, and return the results of the L2 execution back to the L1. These protocols have a sequencer that executes and rolls up the L2 transactions by batching multiple transactions into a single transaction. If a sequencer becomes unavailable, it is impossible to access read/write APIs that consumers are using and applications on the L2 network will be down for most users without interacting directly through the L1 optimistic rollup contracts. The L2 has not stopped, but it would be unfair to continue providing service on your applications when only a few users can use them. Check the official documentation: <https://docs.chain.link/data-feeds/l2-sequencer-feeds>
The staleFeedThreshold should be unique for each data feed because their heartbeats varies.
