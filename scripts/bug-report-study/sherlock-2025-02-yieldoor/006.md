# Attacker will front-run user transactions to profit

#### Summary
The lack of protection against front-running in functions like `openLeveragedPosition `will cause a financial loss for users as an attacker will execute transactions before the user's transaction.

#### Root Cause
In `Leverager.sol:openLeveragedPosition` the lack of protection against front-running allows for manipulation of the transaction order.

#### Internal Pre-conditions
User needs to call `openLeveragedPosition()` to initiate a leveraged position.

#### External Pre-conditions
Transaction fees need to be low enough for the attacker to execute transactions quickly.

#### Attack Path
1. User calls `openLeveragedPosition()` to open a leveraged position.
2. Attacker front-runs the user's transaction, manipulating the price or other conditions.
3. User's transaction executes at the manipulated conditions, resulting in a less favorable outcome.

#### Impact
The users suffer an approximate loss due to the manipulated conditions. The attacker gains this difference.
