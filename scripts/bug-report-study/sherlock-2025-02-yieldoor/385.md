# Insufficient Rebalancing Control - The rebalancer cannot reduce strategy's imbalance due to fixed token ratios


## Summary
The rebalancer cannot effectively reduce imbalances in the strategy because adding and removing funds from the vault are strictly tied to token0/token1 ratios. When the current tick moves away from the main position's center, this fixed ratio prevents proper rebalancing.

## Root Cause
In `Vault.sol`, the token0/token1 ratio is strictly maintained through deposit and withdrawal calculations:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119-L151
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L80-L109
```solidity
    function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        uint256 totalSupply = totalSupply();

        // If total supply > 0, vault can't be empty
        assert(totalSupply == 0 || bal0 > 0 || bal1 > 0);

        if (totalSupply == 0) {
            // For first deposit, just use the amounts desired
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
        } else if (bal0 == 0) {
            amount1 = depositAmount1;
            shares = amount1 * totalSupply / bal1;
        } else if (bal1 == 0) {
            amount0 = depositAmount0;
            shares = amount0 * totalSupply / bal0;
        } else {
            uint256 cross0 = depositAmount0 * bal1;
            uint256 cross1 = depositAmount1 * bal0;
            uint256 cross = cross0 > cross1 ? cross1 : cross0;
            require(cross > 0, "cross");

            // Round up amounts
->          amount0 = (cross - 1) / bal1 + 1;
->          amount1 = (cross - 1) / bal0 + 1;
            shares = cross * totalSupply / bal0 / bal1;
        }
    }

    function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
        public
        returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
    {
        IStrategy(strategy).collectFees();

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        uint256 totalSupply = totalSupply();
        _burn(msg.sender, shares);

->      withdrawAmount0 = totalBalance0 * shares / totalSupply;
->      withdrawAmount1 = totalBalance1 * shares / totalSupply;

        (uint256 idle0, uint256 idle1) = IStrategy(strategy).idleBalances();

        if (idle0 < withdrawAmount0 || idle1 < withdrawAmount1) {
            // When withdrawing partial, there might be a few wei difference.
->          (withdrawAmount0, withdrawAmount1) = IStrategy(strategy).withdrawPartial(shares, totalSupply);
        }

        require(withdrawAmount0 >= minAmount0 && withdrawAmount1 >= minAmount1, "slippage protection");

        IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
        IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);

        return (withdrawAmount0, withdrawAmount1);

        // TODO emit event
    }
```

When the pool's tick moves away from the main position's center, the rebalancer attempts to rebalance the strategy by decreasing main position liquidity and increasing secondary position liquidity. However, neither the rebalancer nor users can effectively reduce this imbalance because the strategy's token0/token1 ratio must be maintained.

## Internal Pre-conditions
- Strategy has significant funds deployed

## External Pre-conditions
- Pool's price moves significantly away from the main position's center

## Attack Path
1. Pool price moves away from main position center
2. Rebalancer attempts to rebalance by shifting liquidity
3. Fixed token ratio prevents effective rebalancing
4. Users withdrawing from vault may break it due to imbalance

## Impact
The protocol's fixed token ratio mechanism is insufficient to handle price changes, potentially leading to vault failure.

## Mitigation
Add functionality for the rebalancer to perform token swaps to reduce strategy imbalances.
