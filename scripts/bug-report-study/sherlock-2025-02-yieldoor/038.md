# Unauthorized Withdrawal Authorization in Vault Contract

## Summary
The `withdraw` function in the Vault contract attempts to transfer tokens from the Strategy contract to users using `safeTransferFrom`, but the Vault is never granted approval to spend tokens on behalf of the Strategy. This design flaw completely breaks the withdrawal functionality, permanently locking user funds in the protocol.

## Description
The root cause of this issue is an incorrect token transfer mechanism in the `withdraw` function of the Vault contract. The function uses `safeTransferFrom` to transfer tokens from the Strategy contract to the user, which requires the Vault to have an allowance from the Strategy. However, no such allowance is ever granted.
```solidity
// In Vault
function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
    public
    returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
{
    // ... Another code ...

    IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
    IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);

    // ... Another code ...
}
```
For `safeTransferFrom` to work, the Strategy contract would need to call `approve(vault, amount)` for both tokens, but this approval is missing from the Strategy contract. The Strategy contract does approve the Vault to spend tokens in its constructor, but it approves the tokens to be transferred to the Vault itself, not from the Strategy to users.
```solidity
// In Strategy.sol constructor
IERC20(token0).forceApprove(_vault, type(uint256).max);
IERC20(token1).forceApprove(_vault, type(uint256).max);
```
This approval allows the Vault to transfer tokens from users to the Strategy (for deposits), but not from the Strategy to users (for withdrawals).

## Scenario
1.	A user deposits tokens into the Vault by calling the `deposit` function
2.	The Vault mints shares to the user and transfers their tokens to the Strategy
3.	Later, the user attempts to withdraw their tokens by calling the `withdraw` function
4.	The Vault calculates the correct amount of tokens to return to the user
5.	The Vault attempts to call `safeTransferFrom` to transfer tokens from the Strategy to the user
6.	The transaction reverts because the Vault does not have approval from the Strategy to transfer tokens
7.	The user's funds remain locked in the Strategy contract with no way to withdraw them

## Impact
This issue completely breaks the core withdrawal functionality of the protocol. Users can deposit funds but cannot withdraw them, effectively creating a permanent lock of all user funds.

## Recommendation
The withdrawal mechanism should be redesigned to use the correct token transfer pattern.
```solidity
// Opsi 1: Strategy transfer directly to users
function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
    public
    returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
{
    // ... other codes ...
    
    IStrategy(strategy).transferToUser(msg.sender, withdrawAmount0, withdrawAmount1);
    
    return (withdrawAmount0, withdrawAmount1);
}

// Opsi 2: Strategy provides allowance to Vault
// In constructor Strategy
IERC20(token0).approve(vault, type(uint256).max);
IERC20(token1).approve(vault, type(uint256).max);
```
