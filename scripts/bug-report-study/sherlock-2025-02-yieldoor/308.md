# Function collectFees incorrectly uses parameter  to collect fees of vestPosition.

### Summary

The function collectFees collects fees based on the tick range of each position record. However, when collecting fees for VestingPosition, incorrect parameter(i.e., mainPosition.tickUpper) is used, which may result in fewer fees being collected.
Note: Although vestPosition.tickLower = mainPosition.tickUpper initially, since mainPosition's tickUpper will change when the function rebalance is called, vestPosition.tickLower is still likely to be unequal to mainPosition.tickUpper.

### Root Cause

Code mistake:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167

```solidity
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper); //@@@audit: vestPosition.tickUpper
        }
```


### Internal Pre-conditions

1. ongoingVestingPosition = true
2. mainPosition.tickUpper != vestPosition.tickUpper

### External Pre-conditions

1. collectFees is called.

### Attack Path

None

### Impact

Fewer fees will be collected, causing the loss of fees.

### PoC

_No response_

### Mitigation

```solidity
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper); //@@@audit: vestPosition.tickUpper
        }
```
