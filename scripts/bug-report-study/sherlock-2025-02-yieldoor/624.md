# Incorrect Collateral Calculation Due to Decimal Mismatch



## Description

The **`_calculateTokenValues`** function in the `Leverager` contract incorrectly handles token decimal mismatches when computing **`initCollateralValue`**. This occurs due to the assumption that Chainlink price feeds return values in the same decimal precision as the underlying tokens.  

##  **Root Cause:**  
The issue arises from the way **`usdValue`** is calculated:

```solidity
usdValue += amount0 * chPrice0 / decimals0;
```

1. **Mismatch in Precision:**  
   Chainlink price feeds typically return **8-decimal** values, but token amounts can vary (e.g., **18 decimals for DAI** and **6 decimals for USDC**). This leads to incorrect **usdValue** calculations.  

2. **Collateral Underreporting:**  
   If a token with lower decimals (e.g., **USDC**) is used, the computed **initCollateralValue** is significantly **undervalued**, allowing positions to be opened with **less collateral** than required, increasing the risk of bad debt.

## **Proof of Concept**  

### Simulation Overview:  
We tested two scenarios—one with a **18-decimal** token (DAI) and another with a **6-decimal** token (USDC). Both are priced at **$1.00 (8 decimals)** from Chainlink.

### Case 1: 18-decimal token (DAI)  
- **Input:**  
  - Token Amount = 100 DAI (18 decimals)  
  - Chainlink Price = $1.00 (8 decimals)  
  - Borrowed Token = 18 decimals  
- **Result:**  
  - `usdValue`: 10,000,000,000 ($100)  
  - `initCollateralValue`: 100,000,000,000,000,000,000 ($100)  

 **Correct Calculation**  

---

### Case 2: 6-decimal token (USDC)  
- **Input:**  
  - Token Amount = 100 USDC (6 decimals)  
  - Chainlink Price = $1.00 (8 decimals)  
  - Borrowed Token = 18 decimals  
- **Result:**  
  - `usdValue`: 10,000,000,000 ($100)  
  - `initCollateralValue`: 100,000,000,000,000,000,000 ($100)  

 **Incorrect Calculation** – **Overvalues Collateral**  

---

## **Impact**  

1. **Underreporting Collateral for Low-Decimal Tokens:**  
   Attackers can exploit this flaw by using **low-decimal tokens** (e.g., **6-decimal** USDC) to **inflate collateral values**, allowing **overleveraging** and the creation of **bad debt** in the system.  

2. **Incorrect Liquidation Checks:**  
   Since **initCollateralValue** underestimates the true collateral amount, some positions may **avoid liquidation** even when they are **underwater**.  

---

## **Recommended Mitigation Steps**  

 **Normalize Token Decimals:**  
   Ensure that **usdValue** is always calculated with the correct precision by **scaling the Chainlink price** to **match the token decimals**. Here’s the fixed calculation:

```solidity
// Normalize usdValue calculation to correct decimals
usdValue += (amount0 * chPrice0 * PRECISION) / (decimals0 * 10**8);
usdValue += (amount1 * chPrice1 * PRECISION) / (decimals1 * 10**8);
```
