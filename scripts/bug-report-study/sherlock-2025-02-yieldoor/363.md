# Withdraw Calculation Bug in Leverager::Withdraw (Underflow & DoS)

### Summary

A bug in the Leverager.sol withdraw function causes an underflow when token1 is the borrowed asset. This miscalculation prevents withdrawals, leading to a denial-of-service condition.

### Root Cause

When token1 is the borrowed asset, the withdraw function mistakenly uses the available amount of token0 instead of token1 in the repayment calculation. The problematic code block is:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235

Here, the ternary condition incorrectly uses amountOut0 instead of amountOut1 when comparing against the owed amount. This error results in subtracting a value from amountOut1 that may exceed its balance, leading to an underflow and causing the transaction to revert.

### Internal Pre-conditions

token1 is the borrowed token.

### External Pre-conditions

N/A

### Attack Path

Consider a simplified example with the following numbers:
	•	Owed token1 amount (owedAmount): 50 units
	•	Available token1 amount (amountOut1): 10 units
	•	Available token0 amount (amountOut0): 20 units

Expected behavior:
	•	The contract should use the available token1 amount (10 units) to reduce the owed amount.

Bug behavior:
	•	The code incorrectly sets repayFromWithdraw to 20 (from amountOut0) since 10 < 50.
	•	It then subtracts 20 from amountOut1 (10 - 20), causing an underflow, and reverts the transaction.


### Impact

Underflow & Revert: The miscalculation can trigger an underflow error, reverting the transaction.

Denial-of-Service (DoS): Withdrawals become impossible when token1 is the borrowed asset, effectively locking users’ funds in the contract.

### Mitigation

Replace the incorrect variable reference so that token1’s available amount is used.
```solidity
} else if (borrowed == up.token1) {
-   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
