# Lack of Validation in Token Initialization

### Summary
The constructor of the vault contract does not validate token addresses properly.
```solidity
constructor(address _token0, address _token1) ERC20("", "") Ownable(msg.sender) {
    if (_token0 > _token1) (_token0, _token1) = (_token1, _token0);

    token0 = _token0;
    token1 = _token1;
}

```
### Issue

**Invalid Token Addresses:**
- The contract does not check whether _token0 and _token1 are valid ERC20 tokens.
- A user might mistakenly pass an incorrect address, which could break the system.

**Same Token Passed Twice:**
- If _token0 and _token1 are the same, the vault will hold only one token instead of a pair.
- This can lead to liquidity pool failure or misconfigured swaps.

**No Recovery Mechanism:**
- If the contract is deployed with wrong token addresses, there is no way to fix it without redeploying.

### Example Attack Scenario
If a deployer accidentally passes an invalid token address:
```solidity
constructor(0x0000000000000000000000000000000000000000, 0x1111111111111111111111111111111111111111)
```
- Here, 0x000...000 is not a valid token address.
- The vault will be initialized incorrectly and may become unusable.
- Since the constructor does not allow updates, the only option would be to redeploy the contract.

### Impact
- Vault Misconfiguration
- Potential Exploit


### Recommandation
Validate the token's address:
```solidity
constructor(address _token0, address _token1) ERC20("", "") Ownable(msg.sender) {
    require(_token0 != _token1, "Tokens must be different");
    require(_token0 != address(0) && _token1 != address(0), "Invalid token address");
    require(IERC20(_token0).totalSupply() > 0, "Invalid token0");
    require(IERC20(_token1).totalSupply() > 0, "Invalid token1");

    if (_token0 > _token1) (_token0, _token1) = (_token1, _token0);

    token0 = _token0;
    token1 = _token1;
}

```
