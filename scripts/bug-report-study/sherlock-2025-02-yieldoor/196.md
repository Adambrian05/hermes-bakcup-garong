# Users can avoid the deposit fee when using wbtc as collateral


### Summary
Users can avoid the deposit fee when using wbtc as collateral due to a flaw in the deposit function.

### Root Cause
The deposit fee is calculated as follows:
`deposit fee = (shares * depositFee) / 10_000`
When `shares < 1000`, this results in a zero deposit fee. 
This vulnerability allows a user to deposit small amounts of wbtc repeatedly without incurring fees.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L61
```solidity
    function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
        external
        returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
    {
        IStrategy(strategy).collectFees();

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

61:     if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

        require(shares > 0, "shares cant be 0");
        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);

    }
```

### PoC
token0 = wbtc, token1 = usdc, wbtcPrice = 100,000 usd.
Let's assume that the first deposit's amount of wbtc (in wei) is greater than the amount of usdc (in wei).
This can be performed by any user.
At this time, `totalSupply = totalWbtc`
A malicious user deposits 0.999e-5 wbtc (equivalent to 0.999 usd).
At this moment, the shares awarded are 999, and the deposit fee is 0.
Therefore, if the malicious user repeatedly deposits 0.999e-5 wbtc, the user can deposit any amount of wbtc without incurring a fee.

### Impact
This vulnerability allows malicious users to bypass deposit fees.
