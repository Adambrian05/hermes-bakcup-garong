# Missing check for pricefeed's existence causes zero division error when calling `openLeveragedPosition`

### Summary

If the price of the denomination token hasn’t been set yet, the entire transaction of openLeveragedPosition will revert because the price is 0, causing a division by zero error.

### Root Cause

[Leverager.sol::130-131](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L130-L131)
```solidity
    function openLeveragedPosition(LeverageParams calldata lp) external nonReentrant returns (uint256 _id) {
    ...
>       uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
>       up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;
    ...
    }
```

The value of `bPrice` is 0 due to a missing pricefeed, causing the whole transaction to revert due to zero division error.

### Internal Pre-conditions

- The pricefeed for the denomination token hasn't been set.

### External Pre-conditions

None.

### Attack Path

None.

### Impact

Causing the whole transaction to fail, negatively impacting the user experience.

### PoC

_No response_

### Mitigation

Add this line of code to `openLeveragedPosition` for checking pricefeed's existence.
```diff
+ require(IPriceFeed(pricefeed).hasPriceFeed(address(lp.denomination)), "pricefeed for denomination not set");
```
