# Borrowers will exceed vault borrowing limits by exploiting untracked interest accumulation in the cumulative borrowed USD tracking system

### Summary

The Leverager contract’s cumulative borrowed USD tracking system allows borrowers to systematically exceed the maximum borrowing limits set by the protocol. While positions initially log the borrowed amount in `currBorrowedUSD`, the subsequent interest accrual in `LendingPool` is never reflected back into this running total. As a result, large amounts of untracked debt can accumulate, effectively bypassing the `maxCumulativeBorrowedUSD` restrictions for each vault.

### Root Cause

When a new leveraged position is opened, the contract updates [`currBorrowedUSD`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L185) only with the initial borrowed principal:

```solidity
vaultParams[lp.vault].currBorrowedUSD += up.initBorrowedUsd;
```

However, the actual amount owed in `LendingPool` increases over time due to interest accrual, calculated via a rising [`borrowingIndex`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/ReserveLogic.sol#L109):

```solidity
function latestBorrowingIndex(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
    return reserve.borrowingIndex
            * (InterestRateUtils.calculateCompoundedInterest(reserve.currentBorrowingRate, reserve.lastUpdateTimestamp))
            / (PRECISION);
}
```

Rather than growing `currBorrowedUSD` in tandem with this index, the Leverager code subtracts only portions of the initial `up.initBorrowedUsd` when positions are partially closed. It never increments for interest that has accumulated. For example, during a partial [`withdrawal`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L209):

```solidity
vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
...
positions[wp.id].borrowedAmount = totalOwedAmount - amountToRepay;
positions[wp.id].borrowedIndex = bIndex;
```

Because the contract references `initBorrowedUsd` (a static opening value) instead of adding accrued interest, `currBorrowedUSD` lags further behind the real owed amount. Over time, a vault’s true borrowed value can exceed its nominal borrowing limit (`maxCumulativeBorrowedUSD`) because that limit only checks this under-reported total. Borrowers can repeatedly open positions, let interest accumulate off-chain in LendingPool, and still appear under the borrowing cap.


### Internal Pre-conditions

1. Vault needs to be initialized with `maxCumulativeBorrowedUSD` limit
2. User needs to open a leveraged position with initial borrow amount under the limit
3. `borrowingIndex` in LendingPool needs to increase over time due to interest accrual
4. Position needs to remain open long enough for significant interest to accumulate

### External Pre-conditions

1. Market conditions need to maintain positive borrowing rates
2. Time needs to pass for interest to accumulate significantly

### Attack Path

1. Attacker opens multiple leveraged positions just under the borrowing limit:
```solidity
vaultParams[lp.vault].currBorrowedUSD += up.initBorrowedUsd;
require(vaultParams[lp.vault].currBorrowedUSD <= vaultParams[lp.vault].maxCumulativeBorrowedUSD);
```

2. Interest accumulates in LendingPool over time:
```solidity
uint256 newIndex = latestBorrowingIndex(reserve);
uint256 actualOwed = borrowedAmount * newIndex / initialIndex;
```

3. When partially withdrawing, only initial borrowed amount is reduced:
```solidity
vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
```

4. Attacker opens new positions since `currBorrowedUSD` remains artificially low:
```solidity
// Can still borrow more despite actual debt being higher
require(vaultParams[lp.vault].currBorrowedUSD + newBorrowAmount <= vaultParams[lp.vault].maxCumulativeBorrowedUSD);
```

5. Cycle repeats, accumulating more untracked debt

### Impact

Untracked interest inflates the borrowing capacity for each vault, allowing users to bypass the protocol’s maximum cumulative borrow limit. As more interest accrues unaccounted for, the protocol’s intended risk controls fail, putting it at risk of excessive concentrated debt, insolvency scenarios, and liquidity shortfalls.

### Mitigation

Implement interest-aware borrowed USD tracking:
```solidity
function updateVaultBorrowedUSD(address vault) public {
    uint256 totalActualBorrowed = 0;
    for (uint256 i = 0; i < positions[vault].length; i++) {
        Position memory pos = positions[vault][i];
        uint256 currentIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(pos.denomination);
        uint256 actualOwed = pos.borrowedAmount * currentIndex / pos.borrowedIndex;
        totalActualBorrowed += actualOwed;
    }
    vaultParams[vault].currBorrowedUSD = totalActualBorrowed;
}
```
