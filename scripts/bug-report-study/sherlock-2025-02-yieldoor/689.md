# TWAP manipulation in price oracle mechanism

### Summary

The Yieldoor protocol relies on Time-Weighted Average Price (TWAP) from Uniswap V3 pools for critical functions including pricing leveraged positions, liquidation checks, and rebalancing decisions. However, the implementation fails to ensure sufficient observation cardinality in the Uniswap pools, making the TWAP oracle vulnerable to manipulation. This could lead to mispriced assets, incorrect liquidations, or blocked protocol operations.
The low observation cardinality in Uniswap V3 pools allows an attacker to manipulate TWAP prices, affecting leveraged positions and deposits. Since TWAP only considers the latest price update in low-liquidity pools, an attacker can temporarily inflate or deflate asset prices, disrupting normal trading activity and potentially blocking or enabling leveraged positions unfairly.

### Root Cause

- In [`Strategy.sol#twapTick()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L345-L354), the protocol does not ensure enough historical price observations before using TWAP data:

```solidity
    /// @notice Returns the TWAP tick
    function twapTick() public view returns (int24) {
        uint32[] memory secondsAgos = new uint32[](2);
        secondsAgos[0] = twap;
        (int56[] memory tickCumulatives,) = IUniswapV3Pool(pool).observe(secondsAgos);
        int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0]; // --> Uses only two data points!

        int24 tick = int24(tickCumulativesDelta / int32(twap));
        if (tickCumulativesDelta < 0 && (tickCumulativesDelta % int32(twap) != 0)) tick--;
        return tick;
    }
```

- Uniswap starts with `observationCardinality = 1`, meaning TWAP initially only considers the most recent price update, making it easy to manipulate.

### Internal Pre-conditions

1. Protocol initializes a Uniswap pool without increasing `observationCardinality`.
2. TWAP oracle is used for deposits, swaps, or leveraged positions.

### External Pre-conditions

1. The attacker needs control over the Uniswap V3 liquidity (or a large enough portion).
2. Low market activity allows the attacker to influence the TWAP price before the next observation is recorded.

### Attack Path


1. Attacker moves liquidity out of Uniswap, making the pool highly volatile.
2. Attacker executes a large buy/sell order, artificially pumping or dumping the price.
3. Since `observationCardinality = 1`, the new price is immediately used for TWAP calculations.
4. Attacker quickly deposits into the Yieldoor vault at a manipulated price, causing:
   - Overvalued deposits (attacker gets extra yield).
   - Underpriced withdrawals (attacker drains protocol funds).
   - Invalid leveraged positions (allowing exploits on liquidations).
5. After some time, the price normalizes, but the attacker already profited or caused a denial-of-service.

### Impact

- Users may get blocked from opening leveraged positions due to a false TWAP price.
- Attacker can profit by depositing underpriced tokens and withdrawing at a manipulated high value.
- Potential DoS attack on the protocol if TWAP remains unstable.
