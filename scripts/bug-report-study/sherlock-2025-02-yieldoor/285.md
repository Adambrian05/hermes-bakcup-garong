# Rounding error can prevent protocol from collecting fees

### Summary

Rounding error can prevent protocol from collecting fees

### Root Cause

In [Vault.sol#L61](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L61), the fee on shares is calculated. The comment states:
“Will only be set to 0.01% if griefers spam deposit/withdraws to remove liquidity from the positions,” implying that the depositFee parameter can be set to 100 (0.01%) under certain circumstances.

However, the following line:
```solidity
if (depositFee > 0) shares -= (shares * depositFee) / 10_000;
```
introduces a rounding issue when the shares amount is less than or equal to 99. Due to integer division, the fee calculation will round down to 0, resulting in no fee being deducted from the shares amount.

This allows a malicious actor to repeatedly deposit small amounts of tokens (up to 99 shares worth) and completely avoid paying fees, circumventing the intended anti-griefing mechanism.

### Internal Pre-conditions

1. DepositFee needs to be set to 100
