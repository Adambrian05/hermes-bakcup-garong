# Incorrect initCollateralValue Calculation Allows Zero-Collateral Positions

### Summary

The initCollateralValue in the Leverager contract incorrectly includes borrowed funds when calculating a user’s collateral value. Instead of using amount0In and amount1In (the user’s actual deposit), it is derived from a0 and a1, which include both collateral and borrowed amounts.

This mistake enables attackers to open a position without depositing any collateral. Since the leverage formula:
```solidity
uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```
results in positionLeverage == 2, the attacker can never lose money when the market drops but still profit when it rises. Additionally, the incorrect initCollateralValue leads to miscalculated liquidation thresholds, potentially allowing undercollateralized positions to remain open.


### Root Cause

In the [Leverager.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L129-L131), initCollateralValue should only represent the user’s actual collateral. However, it is mistakenly calculated using a0 and a1, which include both the collateral and borrowed amounts.

### Internal Pre-conditions

The initCollateralValue calculation includes borrowed funds instead of just user-deposited collateral.

### External Pre-conditions

The attacker opens a leveraged position with zero collateral.

### Attack Path

1.	The attacker opens a position with zero collateral.
2.	The contract mistakenly calculates initCollateralValue including borrowed funds, making positionLeverage == 2.
3.	When the market drops, the attacker’s position remains safe.
4.	If the market rises, the attacker profits without any downside risk.
5.	Since liquidation thresholds are incorrect, the attacker can maintain this risk-free strategy indefinitely.

### Impact

Attackers can open risk-free leveraged positions, profit in up-markets, and avoid losses in down-markets.
Protocol insolvency risk increases as undercollateralized positions may remain open indefinitely.
Liquidation mechanisms fail, making it harder for the protocol to recover bad debt.

### PoC

_No response_

### Mitigation

Use amount0In and amount1In to calculate initCollateralValue instead of a0 and a1.
