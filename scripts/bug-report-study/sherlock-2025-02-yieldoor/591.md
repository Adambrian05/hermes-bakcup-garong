# Incorrect Fee Collection Range in collectFees()

### Summary

The `collectFees() `function incorrectly calls `collectPositionFees() `using an unintended tick range:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167 
Instead of using `vestPosition.tickUpper`, it uses `mainPosition.tickUpper`, potentially allowing fee collection beyond the intended range. This could lead to incorrect fee distributions and possible exploitation.

### Root Cause

The bug originates from an incorrect parameter passed to `collectPositionFees()`. The function should be collecting fees within the vesting position’s defined range (`vestPosition.tickLower` to `vestPosition.tickUpper`), but instead, it extends beyond this by using `mainPosition.tickUpper.`

### Internal Pre-conditions

-The contract must have an active vesting position (`ongoingVestingPosition == true`).
-The `rebalance() `function must have been called, modifying `mainPosition.tickUpper.`
-The `collectFees() `function must be called.

### External Pre-conditions

-The protocol must have liquidity positions generating fees.
-An attacker or privileged user must be able to trigger `collectFees()`.

### Attack Path

-The attacker ensures there is a mismatch between `vestPosition.tickUpper` and `mainPosition.tickUpper.`
-They trigger the `collectFees() `function.
-Fees are collected from a range exceeding the vesting position’s intended bounds.
-This may result in incorrect distribution, affecting either protocol or user rewards.

### Impact

Fee leakage: Fees may be misallocated, affecting protocol revenue and user earnings.
Unintended financial consequences: Depending on the severity, an attacker might manipulate positions to extract excess fees.
Potential governance concerns: If fee distribution is tied to governance, this could affect incentive structures.

### PoC

_No response_

### Mitigation

Modify the collectFees() function to correctly collect fees only within the vesting position’s range:
`collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);`
