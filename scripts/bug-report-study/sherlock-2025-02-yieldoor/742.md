# Medium: Users Can Deposit Funds Before Strategy is Set, Leading to Permanent Loss

## Summary
A user can deposit funds into the **Vault** contract before the `strategy` address is properly set, leading to a loss of funds. Since `strategy` is initially set to `address(0)`, deposits will fail when trying to call `IStrategy(strategy).collectFees()`, but the funds will already have been transferred to `address(0)`.

If users call `deposit()` before `setStrategy()` is executed, their funds will be transferred to `address(0)`, making them **permanently unrecoverable**.


## Impact
- **Loss of user funds**: Deposited tokens may be sent to an invalid address, permanently locking them.
- **Denial of Service (DoS) risk**: Users can mistakenly send funds before a valid strategy is assigned, leading to confusion and potential trust issues with the protocol.

## Proof of Concept

The issue occurs in the `deposit()` function:
[Line 45 in Vault.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L48)

### **1️⃣ The Issue: `deposit()` Allows Transfers Before `strategy` is Set**
```solidity
function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
    external
    returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
{
    IStrategy(strategy).collectFees();  // 🔴 strategy could be address(0) here!

    (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

    (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

    IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0); // 🔴 Funds are sent to address(0) if strategy is not set
    IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); 

    require(shares > 0, "shares cant be 0");
    require(depositAmount0 >= amount0Min, "slippage0");
    require(depositAmount1 >= amount1Min, "slippage1");

    if (totalSupply() == 0) _mint(BURN, 1000);
    _mint(msg.sender, shares);

    return (shares, depositAmount0, depositAmount1);
}
```

## Recommendation (Mitigation Strategies)

1️⃣ Prevent Deposits Until strategy is Set

Modify deposit() to include a require statement that ensures strategy is initialized:
```javascript

require(strategy != address(0), "Strategy not set");
```

Updated code:
```javascript
function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
    external
    returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
{
    require(strategy != address(0), "Strategy not set"); // ✅ Mitigation added
    IStrategy(strategy).collectFees();
    ...
}
```

or other way is:
Ensure strategy is assigned during contract deployment via constructor:

```solidity
constructor(address _strategy) {
    require(_strategy != address(0), "Invalid strategy address");
    strategy = _strategy;
}
```

## Severity - Medium

Likelihood: Low – Users will likely attempt deposits before the strategy is assigned.
Impact: High – Funds can be irreversibly lost.
