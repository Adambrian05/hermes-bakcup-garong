# `Leverager::_calculateTokenValues` will return incorrect token values when neither token has a price feed

### Summary

A missing validation check in the `Leverager::_calculateTokenValues` function will cause an incorrect USD value calculation for token pairs as `Leverager` will attempt to use price feeds that don't exist. 
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L424

### Root Cause

In `Leverager::_calculateTokenValues` function the code attempts to convert tokens using price feeds without verifying that at least one token has a valid price feed. This violates the function's own requirement stated in its documentation: "Requires at least one of them to have set a trustworthy pricefeed."

### Internal Pre-conditions

1. Neither token0 nor token1 has a price feed configured in the pricefeed contract.
2. The `Leverager::_calculateTokenValues` function is called with tokens that don't have price feeds

### External Pre-conditions

None

### Attack Path

1. User or contract calls _calculateTokenValues with two tokens lacking price feeds
2. The function will attempt calculations with zero values for chPrice0 and chPrice1
3. When chPrice0 is 0, it tries to calculate: usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
4. Since chPrice1 is also 0, this calculation will always result in 0
5. Similarly, the calculation in the else-if branch will also result in 0 when chPrice0 is 0

### Impact

The Leverager contract incorrectly calculates token values, which could impact collateral valuation, liquidation thresholds, and borrowing limits. Users of the protocol may have their positions incorrectly valued, potentially leading to unexpected liquidations or allowing excessive borrowing against inadequate collateral.
