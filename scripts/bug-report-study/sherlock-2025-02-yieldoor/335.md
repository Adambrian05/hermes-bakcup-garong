# Lack of liquidity check in `pullFunds()` function can cause flashloans to potentially fail

### Summary
The `pullFunds()` function in the `LendingPool` contract does not verify that the reserve has sufficient underlying liquidity before transferring funds. 

### Vulnerability Details
```solidity
function pullFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData memory reserve = getReserve(asset);
    IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
}
```

The function fetches the reserve data as a memory copy and directly calls` transferUnderlyingTo()` to send the requested amount to the caller without checking if the reserve holds enough liquidity.

The function doesn't include a condition such as

```solidity
require(amount <= reserve.availableLiquidity(), "not enough available liquidity");
```

### Impact
If an external call to `pullFunds()` is made  when the reserve does not have enough liquidity, the transaction might fail preventing leverager from executing a flashloan which will prevent the leverager from opening a leverage position

### Recommendation
Before calling `transferUnderlyingTo()`, add a condition to ensure that the reserve has sufficient liquidity

```solidity
require(amount <= reserve.availableLiquidity(), "not enough available liquidity");
```
