# Attacker can DoS rebalancing, compounding and adding a vested position by doing a 1 wei swap each block

### Summary

The `Strategy` makes sure the spot price is not manipulated by looking at the twap price and [comparing](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L298). However, it requires the observations to be at least `TWAP` in the past, reverting if they aren't. As such, with a block time of 2 seconds, if `TWAP` is 300, if there are up to 150 observations available, an attacker can DoS the `Strategy` and cause loss of fees for users. Note that many pools have number of observations in the 100s so this is likely.

### Root Cause

In `Strategy:412` it reverts if the oldest observation is more recent than `TWAP` ago.

### Internal Pre-conditions

None.

### External Pre-conditions

Pool observation cardinality divided by block time is smaller than `TWAP`.

### Attack Path

1. Attacker swaps 1 wei for 150 blocks, such that the oldest observation is 300 seconds ago with a block time of 1 (rough numbers).

### Impact

DoSed rebalancing and compounding, leading to loss of fees for users and the protocol. Note that fees are accrued in a per swap basis, so any missed big swap leads to significant loss of fees, even in a very short span of time.

### PoC

See above.

### Mitigation

When setting the twap in the constructor or in the setter, increase the observations cardinality of the pool accordingly.
