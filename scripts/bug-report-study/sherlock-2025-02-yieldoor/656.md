# Missing Price Feed Validation Allows Invalid Vault Configurations

### Summary

The `Leverager` contract fails to enforce its core security invariant requiring at least one price feed per vault. When both tokens in a vault lack price feeds, the `Leverager._calculateTokenValues` function returns zero collateral value without explicit validation. This invalid state propagates to leverage calculations, causing division-by-zero errors in `Leverager._checkWithinlimits` that obscure the root configuration issue. The lack of enforcement at vault initialization and valuation stages allows creation of operationally broken vaults that violate the protocol's intended design, leading to failed transactions and erosion of system integrity guarantees.

### Root Cause

The function `Leverager._calculateTokenValues()` ([`Leverager.sol#L444-L448`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L444-L448)) assumes at least one token has a price feed but doesn't enforce it. When both tokens in a vault lack price feeds:
1. Protocol's security invariant ("at least one asset must have price feed") is violated
2. Collateral value calculation returns 0 instead of reverting
3. Subsequent checks fail with misleading arithmetic errors rather than configuration issues

```solidity
contract Leverager is ReentrancyGuard, Ownable, ERC721, ILeverager {
    /// @notice Calculates the USD value of amount0 and amount1
@>  /// @dev Requires at least one of them to have set a trustworthy pricefeed.
@>  /// If one of them doesn't have a pricefeed, it uses the pool TWAP price to convert said token to the other one.
    // ...
    function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
    {
        // ...
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }

        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
@>      if (chPrice0 == 0) {
@>          usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }

        return usdValue;
    }
}
```

This occurs because:
- No `require` statement validates price feed existence before calculations
- Error manifests as division-by-zero in `Leverager._checkWithinlimits()` instead of failing early

```solidity

        // ...

```

The core mistake is implementing partial validation (price conversion logic) without enforcing the prerequisite condition (at least one valid price feed) that the protocol's design depends on.

### Attack Path

1. **Protocol allows two unpricefed tokens**  
   - Missing code validation for price feed requirement during vault initialization
   - External oracle deprecation event occurs, let previously valid price feed becomes null/disabled for an asset

2. **User attempts legitimate position opening in approved vault**  
   - Follows normal `Leverager.openLeveragedPosition()` flow with valid parameters

3. **System calculates $0 collateral value silently**  
   - Missing price feeds cause zero-value USD conversion without explicit revert

4. **Division-by-zero crashes leverage validation**  
   - `positionLeverage` calculation fails at `Leverager._checkWithinlimits()`

5. **Transaction reverts with misleading error**  
   - Obscures root configuration issue behind arithmetic failure

### Impact

**Protocol fails to enforce its own security invariants**  
- Trusted owner actions can create operationally broken vaults that appear legitimate
- Whitelisted vaults can silently transition to invalid states due to external changes    
- Violates explicit design rule: "At least one vault asset must have trustworthy price feed"  
- Users waste gas on transactions destined to fail in "approved" vault configurations  

**System integrity damage:**  
- Whitelisting process appears functional but allows invalid states  
- Erodes user trust in protocol's configuration safeguards  
- Requires emergency governance intervention to rectify false-positive approvals

### Mitigation

Enforce price feed requirement checks at both vault initialization and value calculation stages:

```solidity:Leverager.sol
function _calculateTokenValues(
    address token0,
    address token1,
    uint256 amount0,
    uint256 amount1
) internal view returns (uint256 usdValue) {
    // Add validation check before calculations
    require(
        IPriceFeed(pricefeed).hasPriceFeed(token0) || IPriceFeed(pricefeed).hasPriceFeed(token1),
        "At least one token must have price feed"
    );
    
    // ... existing calculation logic ...
}
```

**Implementation rationale:**  
1. **Protocol invariant enforcement** - Explicit require statement codifies the documented security rule  
2. **Early failure** - Reverts with clear error message during valuation phase if misconfigured  
3. **Defense in depth** - Recommend adding duplicate check in `initVault` for proactive prevention:
```solidity:Leverager.sol
function initVault(/*...*/) external onlyOwner {
    // ... existing code ...
    require(
        IPriceFeed(pricefeed).hasPriceFeed(token0) || IPriceFeed(pricefeed).hasPriceFeed(token1),
        "Invalid vault: missing price feeds"
    );
    // ... existing code ...
}
```

**Post-fix behavior:**  
- Vaults violating price feed requirement cannot be initialized  
- Existing malformed vaults (if any) would revert with explicit error on interaction  
- Preserves protocol security model while maintaining owner flexibility to choose feed-enabled assets
