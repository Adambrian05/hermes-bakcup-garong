# Reserve State Desynchronization Exploit: Manipulating Interest Accrual & Liquidity Calculations

### Summary

The Reserve State Desynchronization Exploit occurs due to the failure to update the reserve state before executing fund transfers in the `LendingPool.sol::pullFunds` and `pushFunds` functions. Since the protocol relies on `updateState()` to track accrued interest, liquidity, and borrowing rates, skipping this update allows an attacker to manipulate reserve calculations.

### Root Cause

The root cause of the exploit is failing to update the reserve state before executing fund transfers (`pullFunds` and `pushFunds`). This omission leads to stale borrowing indices and outdated debt calculations, which can be manipulated by an attacker.

### Impact

1️⃣ Underpayment of Interest (Debt Manipulation)
Borrowers avoid paying full interest on their loans by withdrawing and repaying funds at an outdated borrowing index.
This reduces the protocol’s revenue from interest payments.
Attackers can borrow at a much lower cost than legitimate users.
📌 Example Calculation:
Initial Borrowing:

Attacker borrows 100 ETH at a borrowing index of 1.0.
Their total debt is 100 ETH.
Interest Accrues Over Time:

Due to time passing, the correct borrowing index should be 1.2 (20% accrued interest).
Their debt should be 100 × 1.2 = 120 ETH.
Pull and Push Funds Without Updating the Borrowing Index:

Since pullFunds and pushFunds do not update the state, the borrowing index remains at 1.0.
When the attacker repays, the contract incorrectly calculates the debt using the old index, meaning they only owe 100 ETH instead of 120 ETH.
Result: The attacker gains 20 ETH for free at the protocol’s expense.

### Mitigation

```solidity
function pullFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData storage reserve = getReserve(asset);

    // ✅ Fix: Update reserve state before transfer
    reserve.updateState();

    IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
}
```

```solidity
function pushFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData storage reserve = getReserve(asset);

    // ✅ Fix: Update reserve state before transfer
    reserve.updateState();

    IERC20(asset).safeTransferFrom(msg.sender, reserve.yTokenAddress, amount);
}
```
