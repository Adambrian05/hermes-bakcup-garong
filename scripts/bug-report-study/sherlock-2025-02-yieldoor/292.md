# First Deposit Price Manipulation in Vault contract

### Summary

 https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L129-#L133

First depositor can deposit imbalance token amounts into vault  and extract excess value when withdrawing.



### Root Cause

In `vault.sol::_calcDeposit()` the share calculation for first deposits is based solely on the larger of the two token amounts, this will lead to manipulation with imbalanced deposits.

```solidity
if (totalSupply == 0) {
    // For first deposit, just use the amounts desired
    amount0 = depositAmount0;
    amount1 = depositAmount1;
    shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
}
```

### Attack Path


1.Attacker deposits highly imbalanced token amounts (e.g., 0.000001 USDC and 100 WETH) when vault is empty.
2.Attacker receives shares based on the larger token amount: shares = 100 WETH - 1000 wei

3. Pool now has an extreme imbalance between token0 and token1
4.Subsequent depositors must match this ratio when providing liquidity

5.After legitimate users deposit balanced amounts based on the manipulated ratio
6.Attacker withdraws their shares and receives tokens proportional to their share percentage
7.Due to having shares primarily based on WETH contribution while providing minimal USDC, attacker extracts excess USDC value

`Initial deposit: 0.000001 USDC (token0) and 100WETH (token1)
Shares received: ~100 WETH worth
Legitimate deposit: 10 USDC and 10 WETH
After withdrawal, attacker receives their WETH back plus a significant portion of USDC they never deposited`







### Impact

 The protocol and subsequent depositors suffer loss as the attacker gains the difference between their initial deposit and the manipulated value extraction when withdrawing, which could be substantial depending on deposit volumes.
