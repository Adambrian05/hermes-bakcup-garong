# Positions can be liquidated unfairly due to incorrect min() operation in calculation

### Summary

Positions can be liquidated unfairly due to incorrect min() operation in calculation

### Root Cause

In [Leverager::isLiquidateable()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408C1-L409C80) function, we check the position is whether liquidateable or not. We have an extra handling here for fair position liquidation. Users may don't use the max leverage and they can be liquidated unfairly if we don't adjust the base value with following lines:

```solidity
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
        base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
```

But it's still incorrect due to incorrect parameter usage in second line. initCollateralValue actually holds the whole position value instead of just holding the collat value provided by the user.

In order to understand the issue we should understand why this base adjustment is needed. I will directly use sponsor's explanation for it:

> It would be unfair as it a user who initially opened $1250 position ($250 borrowed) at 1.25x position dropped to $350 value (collateral is down to 10%) and that would be considered liquidateable

> At the same time a user could open a $100 collateral $250 borrowed 3.5x leverage and they wouldnt be liquidateable

How adjustment works ? Let say our max leverage is equal to 5x. But an user created a position with 3x. He provided x amount of collateral and borrowed 2x amount of tokens. What would be the collateral amount if this position has 5x leverage with same amount of borrowing ? First line is answering this question's answer.

2x / (5x - 1x) = 1/2 * x

Now, let's explain the second line. Our owedAmount value will increase in time due to interest. But we don't want to overestimate user's collateral amount and we're applying `min()` operation here. For instance, if user provides 100 dollar collateral, base shouldn't exceed that 100 dollar.

But currently, initCollateralValue holds total position value because it's calculated with position's tokens after flash loan:

```solidity
        if (delta0 > 0) ILendingPool(lendingPool).pullFunds(up.token0, delta0); // we flashloan the difference between amounts desired to be deposited in Vault
        if (delta1 > 0) ILendingPool(lendingPool).pullFunds(up.token1, delta1); // and the amount pulled from the user

        // a0 and a1 represent the actual amounts deposited within the vault.
        // We keep track of them as we later make exactOutput swaps based on them
        (uint256 shares, uint256 a0, uint256 a1) =
            IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);

        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); // returns the USD price in 1e18
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;

```


### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

> Assume position doesn't farm any value for simplicity

1. Let say user created 5x position with 10K collateral ( he borrowed 40K )
2. In time this position's debt accrued interest and became 48,800 
3. Now let's calculate base value:

48,800 / ( 5 - 1 ) = 12,200 

Min:

12,200 < 50,000 ? 12,200 : 50,000

Base will be equal to 12,200.
But normally it should be 10,000 because user has provided 10K collateral at the beginning.

Let say minCollatPct = 10%

1,220 Dollar is needed as excess of position value

48,800 + 1,220 = 50,020 > 50K => It's liquidateable

Normally it should calculate with following way:

48,800 + 1,000 = 49,800 > 50K => It's not liquidateable

### Impact

User may be liquidated unfairly due to wrong base calculation mechanism. It will be loss of funds for the position owner

### Mitigation

Substract borrowed amount from initCollateralValue in order to find collateral value in calculation
