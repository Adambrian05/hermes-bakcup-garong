# Flawed Liquidation Threshold Calculation Allows Underwater Positions to Avoid Liquidation, Leading to Protocol Bad Debt

## Summary
The Leverager contract's `isLiquidateable()` function uses a flawed calculation to determine when positions should be liquidated. The current implementation allows positions to remain active even when the user's debt exceeds their actual collateral. This creates a significant risk of bad debt for the protocol, as underwater positions can continue to accrue interest without being liquidated, potentially leading to losses that cannot be recovered during eventual liquidation.

## Vulnerability Details
The liquidation logic in the Leverager contract fails to properly account for the relationship between a user's actual collateral and their debt. Instead, it uses a calculation based on the total position value (which includes borrowed funds) and a "base" value derived from the maximum leverage.

**Key definitions to note:**
- pos.initCollateralValue: is the original value of the user's LP position at the point of create. This value compromise of the tokens provided the user themselves and the tokens borrowed from the LendingPool. [See where this is set in `openLeveragedPosition`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L394-L401):
```js
        uint256 delta0 = lp.vault0In - lp.amount0In;
        uint256 delta1 = lp.vault1In - lp.amount1In;
        if (delta0 > 0) ILendingPool(lendingPool).pullFunds(up.token0, delta0); // we flashloan the difference between amounts desired to be deposited in Vault
        if (delta1 > 0) ILendingPool(lendingPool).pullFunds(up.token1, delta1); // and the amount pulled from the user

        // a0 and a1 represent the actual amounts deposited within the vault.
        // We keep track of them as we later make exactOutput swaps based on them
        (uint256 shares, uint256 a0, uint256 a1) =
            IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);

        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); // returns the USD price in 1e18
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;

```
The contract first pulls the required tokens need to open the desired position size by the user, and store the value of that position as `initCollateralValue`.

- owedAmount: This is the initial borrowed amount of tokens by the user plus the accrued interest.

When a user opens a leveraged position, they provide some initial collateral, and the protocol lends them additional funds. The `pos.initCollateralValue` represents the total value of the position at creation, which includes both the user's collateral and the borrowed amount.

The current liquidation check is:
```solidity
uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
else return false;
```

This formula calculates a "base" value that represents the theoretical minimum collateral needed at maximum leverage, then compares the remaining collateral against a percentage of this base. Critically, it does not directly compare the user's actual collateral against their debt, which is the fundamental check needed to prevent bad debt.

## Proof of Concept
Consider a scenario with the following parameters:
- pos.initCollateralValue = 800 USDC (initial collateral provided by user (500) + initial borrowed amount (300))
- owedAmount = 600 USDC (initial borrowed amount (300) + accrued interest (300))
- vp.maxTimesLeverage = 3e18 (3x maximum leverage, scaled by 1e18)
- vp.minCollateralPct = 0.5e18 (50% minimum required collateral, scaled by 1e18)
- totalDenom = 800 USDC (assuming position value hasn't changed)

**Step 1:** Calculate the base value
```js
base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18)
base = 600 * 1e18 / (3e18 - 1e18)
base = 600 * 1e18 / 2e18
base = 300
```

**Step 2:** Compare base with initCollateralValue and take the minimum
```js
base = min(300, 800) = 300
```

**Step 3:** Check liquidation conditions
```js
Condition 1: owedAmount > totalDenom
600 > 800? No

Condition 2: totalDenom - owedAmount < vp.minCollateralPct * base / 1e18
800 - 600 = 200
vp.minCollateralPct * base / 1e18 = 0.5e18 * 300 / 1e18 = 150
200 < 150? No

Result: Not liquidatable
```

However, if we look at the user's actual position:
- Real user collateral: initCollateralValue - initial borrowed amount = 800 - 300 = 500 USDC
- User's debt: owedAmount = 600 USDC

The user's debt (600 USDC) exceeds their actual collateral (500 USDC), yet the position is not flagged for liquidation. If liquidated at this point, the protocol would incur a loss of at least 100 USDC.

## Impact Details
This vulnerability exposes the protocol to significant bad debt risk as positions can remain active even when underwater. As interest continues to accrue or position values decrease, the protocol's losses will compound. Additionally, liquidators may be reluctant to liquidate positions where they cannot recover the full debt amount, further exacerbating the problem.

## Recommendations
Modify the liquidation logic to include a direct comparison between the user's actual collateral and their debt:

```solidity
// Track the initial borrowed amount in the Position struct
function isLiquidateable(uint256 id) public view returns (bool liquidateable) {
    Position memory pos = positions[id];
    VaultParams memory vp = vaultParams[pos.vault];


	// ... existing code

	
    // Calculate user's actual collateral (excluding borrowed amount)
    uint256 actualUserCollateral = pos.initCollateralValue - pos.borrowedAmount;
    
    // Calculate current debt including interest
    uint256 owedAmount = ILendingPool(lendingPool).getOwedAmount(pos.denomination, pos.borrowedAmount, pos.borrowedIndex);
    
    // Check if debt exceeds actual collateral (with safety margin)
    if (owedAmount > actualUserCollateral * safetyFactor) return true;
    
    // Keep existing checks as additional safeguards
    uint256 totalDenom = _getPositionValue(id, pos.denomination);
    uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
    base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
    
    if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
    else return false;
}
```

This ensures positions are liquidated before the debt exceeds the user's actual collateral, protecting the protocol from bad debt.
