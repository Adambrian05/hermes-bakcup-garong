# Incorrect UpperTick for VestingPosition in `collectFees()`

### Summary

The `collectFees()` function incorrectly calls `collectPositionFees()` with `mainPosition.tickUpper` instead of the correct `vestPosition.tickUpper` when `ongoingVestingPosition == true`. This can result in an invalid position reference when `mainPosition.tickUpper != vestPosition.tickUpper`, causing a revert in Uniswap V3 pool `burn()`.

### Root Cause

In `Strategy.collectFees()`, the function incorrectly references `mainPosition.tickUpper` for vesting position:
```solidity
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
        }
``` 
Since `mainPosition.tickUpper` may change due to rebalancing, this can cause `collectPositionFees()` to attempt to burn a non-existent position on Uniswap V3 pool.

```solidity
    function collectPositionFees(int24 tickLower, int24 tickUpper) internal {
        IUniswapV3Pool(pool).burn(tickLower, tickUpper, 0);
        IUniswapV3Pool(pool).collect(address(this), tickLower, tickUpper, type(uint128).max, type(uint128).max);
    }
```


### Internal Pre-conditions

1. `addVestingPosition()` is called, creating a vesting position using current `mainPosition.tickLower` and `mainPosition.tickUpper`.
2. `rebalance()` adjusts `mainPosition.tickLower` and `mainPosition.tickUpper` based on the latest Uniswap pool tick.
3. `collectFees()` is later called, attempting to collect fees from a position using `mainPosition.tickUpper`, which may no longer match the original upper tick of the vesting position.

### Attack Path

1. A vesting position is created using the initial `mainPosition.tickLower` and `mainPosition.tickUpper`.
2. `rebalance()` updates `mainPosition.tickUpper`, causing a mismatch between `mainPosition.tickUpper` and `vestPosition.tickUpper`.
3. `collectFees()` is called, attempting to collect fees using the wrong upper tick, leading to a revert.

### Impact

The `collectFees()` function is called by core functions to update `amount0` and `amount1` before calculating `shares`. However, because `collectPositionFees()` attempts to `burn()` a position using an incorrect upper tick, it reverts due to the position not existing in Uniswap V3 pool. This causes core functions in `Strategy.sol` to revert.

### Mitigation

```solidity
    function collectFees() public {
        (uint256 preBal0, uint256 preBal1) = idleBalances();

        if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }

        if (ongoingVestingPosition) {
 -          collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
 +          collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
        }

        (uint256 afterBal0, uint256 afterBal1) = idleBalances();

        uint256 protocolFees0 = (afterBal0 - preBal0) * protocolFee / 10_000;
        uint256 protocolFees1 = (afterBal1 - preBal1) * protocolFee / 10_000;

        if (protocolFees0 > 0) IERC20(token0).safeTransfer(feeRecipient, protocolFees0);
        if (protocolFees1 > 0) IERC20(token1).safeTransfer(feeRecipient, protocolFees1);

        if (ongoingVestingPosition) {
            _withdrawPartOfVestingPosition(); // doing that now, otherwise we'd charge protocol fee for the vested position
        }
    }
```
