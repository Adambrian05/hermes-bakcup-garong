# [m-01] Withdraw Calculation Bug

### Summary

The withdraw function in the `Leverager.sol` contract has a bug when users borrow token1. It wrongly uses the balance of token0 instead of token1 to calculate repayment. This causes an underflow error (trying to subtract too much), which makes the transaction fail. Users can’t withdraw their funds if token1’s balance is too low.

How It Breaks:

What happens:
User tries to withdraw when they borrowed token1.
Code checks how much token1 they owe (e.g., 150).
It should use token1’s balance (e.g., 100), but it grabs token0’s balance (e.g., 300) instead.
Tries to subtract 300 from 150, which underflows (goes negative).
Transaction reverts—user can’t withdraw.

Example:
Owed: 150 token1
Available: 100 token1, 300 token0
Bug: Subtracts 300 (wrong token) instead of 100 (right token).
Result: Fails every time token1 balance is less than owed.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232

A copy-paste mistake. For token1 withdrawals, the code uses amountOut0 (token0’s balance) instead of amountOut1 (token1’s balance). This messes up the math.
```solidity
// Wrong: Uses amountOut0 for token1
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```
