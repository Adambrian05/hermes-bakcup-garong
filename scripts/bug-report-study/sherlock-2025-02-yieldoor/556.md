# The `Leverager.withdraw()` Function Incorrectly Utilizes `amountOut0` Instead of `amountOut1` to Determine `repayFromWithdraw`

### Summary

The `repayFromWithdraw` variable should be set to the minimum value between `amountOut1` and `owedAmount` when the `borrowed` token equals `token1`. In cases where `amountOut1 < owedAmount`, `repayFromWithdraw` should be set to `amountOut1`, but instead, `amountOut0` is used due to a typo.

### Root Cause

Let's consider the [line 232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) of the `Leverager.withdraw()` function. In the case `amountOut1 < owedAmount`, it determines `repayFromWithdraw` to `amountOut0` instead of `amountOut1`. This is unreasonable and a typo.

As a result, during the subsequent operation `amountOut1 -= repayFromWithdraw;`, it could revert due to integer underflow if `amountOut0` is greater than `amountOut1`. Then, the transaction will revert.

```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        ...

        // In case either of the tokens is denomination token, we directly take from it.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
232         uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }

        ...
    }
```
