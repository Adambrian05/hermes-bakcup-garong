# Uniswap V3 Tick Boundary Miscalculation in Strategy::_setMainTicks


## Description
`_setMainTicks` function determines the tick range for `mainPosition` during a `rebalance()` operation based on the current pool price (tick). But, in volatile market conditions, this function may set a liquidity range that becomes misaligned with the active price range shortly after rebalancing. Specifically, `_setMainTicks` uses a fixed `positionWidth` (e.g., 240 ticks for a 0.3% fee pool) and rounds the current tick to the nearest initializable tick without dynamically adjusting for rapid price movements. This can result in the selected range (`tickLower`, `tickUpper`) being outside the current price immediately or soon after execution, causing the liquidity to become inactive.

```solidity
function _setMainTicks(int24 tick) internal {
    int24 halfWidth = int24(positionWidth / 2);
    int24 modulo = tick % tickSpacing;
    if (modulo < 0) modulo += tickSpacing; // if tick is negative, modulo is also negative
    bool isLowerSided = modulo < (tickSpacing / 2);

    int24 tickBorder = tick - modulo;
    if (!isLowerSided) tickBorder += tickSpacing;
    mainPosition.tickLower = tickBorder - halfWidth;
    mainPosition.tickUpper = tickBorder + halfWidth;

    emit NewMainTicks(tickBorder - halfWidth, tickBorder + halfWidth);
}

function rebalance() public onlyRebalancer {
    require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");
    _requirePriceWithinRange();
    collectFees();
    _removeLiquidity();
    (uint256 amount0, uint256 amount1) = idleBalances();
    (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();
    _setMainTicks(tick);
    (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);
    _setSecondaryPositionsTicks(tick);
    _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
    lastRebalance = block.timestamp;
}
```

- `positionWidth` is a uint24 set during initialization (default: `4 * tickSpacing`, e.g., 240 for a 0.3% fee pool with `tickSpacing = 60`).

- tick is the current pool tick from slot0(), rounded to the nearest initializable tick (`tickBorder`) based on `tickSpacing`.

- `mainPosition.tickLower` and `tickUpper` are set symmetrically around `tickBorder` using `halfWidth` (`positionWidth / 2`), with no adjustment for volatility.

In volatile markets (e.g., rapid WBTC/USDC price swings), the current tick can move outside the [`tickLower`, `tickUpper`] range before or during `_addLiquidityToMainPosition`, rendering the liquidity inactive or causing reverts in subsequent operations due to price range checks (e.g., `_requirePriceWithinRange`).

## Impact 
- If the price moves beyond the selected range (e.g., tick jumps from 67391 to 68000 or drops to 66800 in minutes), the `mainPosition` liquidity stops accruing fees, reducing protocol income (9% protocol fee per `protocolFee = 900/10000`).
- Subsequent rebalances may revert if the price exits the allowed TWAP deviation range (`tickTwapDeviation`, default 200 ticks), halting strategy adjustments and compounding fee loss.

## Proof of Concept
Consider the WBTC/USDC pool (`0x99ac8cA7087fA4A2A1FB6357269965A2014ABc35`, 0.3% fee, `tickSpacing = 60`):
- Initial State: Tick = 67391 (~$66k WBTC/USD), `positionWidth = 240.`

- rebalance() Calls` _setMainTicks(67391)`:
 - `modulo = 67391 % 60 = 11`, `isLowerSided = 11 < 30` (true).
 - `tickBorder = 67391 - 11 = 67380`.
 - `halfWidth = 240 / 2 = 120`.
 - `tickLower = 67380 - 120 = 67260`.
 - `tickUpper = 67380 + 120 = 67500`.
 - Range: [`67260, 67500`].
Volatility Spike: Price drops 5% in minutes (~$66k to ~$62.7k, tick ~66800, below 67260).

- Outcome:
 - Liquidity at [`67260, 67500`] becomes inactive (out-of-range).
 - Next `rebalance()` may revert if tick (66800) deviates >200 ticks from TWAP (e.g., 67391), triggering `_requirePriceWithinRange()` failure.

## Recommendation
You should enhance `_setMainTicks` to dynamically adjust the tick range based on historical volatility, adding a buffer to keep liquidity active:

- Use Uniswap V3’s `observe` function to sample recent price movements (e.g., 1-hour TWAP variance).
- Scale `positionWidth` by a volatility factor, ensuring the position encompasses likely price swings.
- Limit the buffer to avoid overly wide, inefficient ranges.

```solidity
uint256 public constant VOLATILITY_PERIOD = 3600; // 1 hour
uint256 public constant MAX_RANGE_MULTIPLIER = 3e18; // 3x max widening (300%)

function _setMainTicks(int24 tick) internal {
    int24 halfWidth = int24(positionWidth / 2);
    int24 modulo = tick % tickSpacing;
    if (modulo < 0) modulo += tickSpacing; // if tick is negative, modulo is also negative
    bool isLowerSided = modulo < (tickSpacing / 2);
    int24 tickBorder = tick - modulo;
    if (!isLowerSided) tickBorder += tickSpacing;

    uint32[] memory secondsAgos = new uint32[](2);
    secondsAgos[0] = uint32(VOLATILITY_PERIOD);
    secondsAgos[1] = 0;
    (int56[] memory tickCumulatives, ) = IUniswapV3Pool(pool).observe(secondsAgos);
    int24 twapTick = int24((tickCumulatives[1] - tickCumulatives[0]) / int56(VOLATILITY_PERIOD));
    int24 tickDelta = tick > twapTick ? tick - twapTick : twapTick - tick;
    uint256 volatilityBuffer = uint256(int256(tickDelta)) * 1e18 / uint256(int256(tickSpacing));
    uint256 rangeMultiplier = 1e18 + (volatilityBuffer > MAX_RANGE_MULTIPLIER ? MAX_RANGE_MULTIPLIER : volatilityBuffer);

    uint256 adjustedWidth = positionWidth * rangeMultiplier / 1e18;
    int24 adjustedHalfWidth = int24(adjustedWidth / 2);
    mainPosition.tickLower = tickBorder - adjustedHalfWidth;
    mainPosition.tickUpper = tickBorder + adjustedHalfWidth;

    emit NewMainTicks(mainPosition.tickLower, mainPosition.tickUpper);
}
```
