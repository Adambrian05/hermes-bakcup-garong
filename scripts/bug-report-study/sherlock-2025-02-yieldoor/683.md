# User can misdirect swapped funds in Leverager

### Summary

Inadequate validation of swap parameters in Leverager allows users to specify any recipient for swapped tokens, enabling fund misdirection as an attacker can set the recipient to their own address

### Root Cause

In [Leverager.sol: openLeveragedPosition function](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol?plain=1#L143-L154), the user-provided `swapParams1 `and `swapParams2 `include the recipient for the swapped tokens, and the contract does not validate or modify this recipient, allowing funds to be sent to any address.

### Internal Pre-conditions

The user is opening a leveraged position and provides swap parameters with a recipient address different from the Leverager contract.

### External Pre-conditions

None

### Attack Path

1. The attacker calls `openLeveragedPosition` with `swapParams1 `or `swapParams2 `where the recipient is set to the attacker's address.
2. The Leverager contract performs the swap, and the output tokens are sent to the attacker's address instead of itself.
3. The Leverager contract does not have the necessary tokens to complete the deposit, leading to failure or incorrect state.

### Impact

The Leverager contract fails to open the position correctly, or the attacker gains the swapped tokens, potentially leading to loss of funds for the protocol or users, with an approximate loss depending on the swapped amount.

### PoC

_No response_

### Mitigation

The Leverager contract should set the recipient to itself when calling `exactOutput`, or validate that the user-provided recipient is the contract's address.
