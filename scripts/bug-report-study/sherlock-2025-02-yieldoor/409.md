# Liquidation Price Manipulation via Fee Collection Bypass

### Summary

A critical vulnerability exists in the Leverager contract's liquidation mechanism where users can manipulate position valuation by bypassing fee collection. The `liquidatePosition` function does not use the `collectFees` modifier, while the `isLiquidateable` function does. This discrepancy allows attackers to avoid fee collection before liquidation, potentially leading to incorrect position valuations, unfair liquidations, and loss of funds.

### Root Cause

The `liquidatePosition` function lacks the `collectFees` modifier that is present in the `isLiquidateable` function. This inconsistency creates a state where fee-uncollected positions (with higher apparent value) can be liquidated despite not meeting the liquidation criteria when fees are properly accounted for.

Example: [Leverager.sol#L269-L338](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L269-L338) (Missing modifier in liquidatePosition) vs [Leverager.sol#L424-L425](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L424-L425) (modifier present in isLiquidateable).

The `collectFees` modifier ensures that fees are collected from the strategy before checking if a position is liquidatable, which affects the position's valuation. When this modifier is missing in the liquidation function, the position's value may appear higher than it should be, creating a discrepancy between the validation and execution stages.

### Internal Pre-conditions

1. The protocol must have a position with accumulated but uncollected fees
2. Fee collection significantly affects position valuation
3. The `collectFees` modifier must be present on `isLiquidateable` but missing on `liquidatePosition`

### External Pre-conditions

1. Liquidity pools must be active and generating fees
2. A position must exist where fee collection would put it below liquidation threshold
3. The position must have sufficient time since last fee collection for meaningful fees to accumulate

### Attack Path

1. An attacker identifies a leveraged position that is close to the liquidation threshold
2. The attacker monitors the position and waits until sufficient uncollected fees accumulate
3. The attacker calls `isLiquidateable` on their own, which applies the `collectFees` modifier and confirms the position is not yet liquidatable
4. The attacker immediately calls `liquidatePosition` to liquidate the position, bypassing fee collection
   - Since `liquidatePosition` doesn't have the `collectFees` modifier, the position valuation will be inaccurate
   - This allows the attacker to liquidate a position that should not be liquidatable if fees were properly accounted for
5. The attacker successfully liquidates the position and receives the liquidation bonus, despite the position not meeting the actual liquidation criteria

### Impact

- Users can be unfairly liquidated, resulting in loss of principal and potential profits
- The protocol's economic model can be manipulated, leading to unexpected behaviors
- Loss of trust in the protocol due to unpredictable liquidations
- Financial impact affects any position that accumulates significant fees between fee collection events, potentially worth 5-15% of position values
- Systematic risk as liquidators exploit this vulnerability to maximize profits

### Mitigation

Add the `collectFees` modifier to the `liquidatePosition` function to ensure consistency between validation and execution:
```solidity
function liquidatePosition(
    LiquidateParams calldata params
) external nonReentrant collectFees(params.id) returns (uint256 fee, uint256 liquidatorFee) {
    // ... existing function body ...
}
```
Alternatively, add an explicit fee collection call at the beginning of the function.

Additionally, consider implementing a two-step liquidation process:
1. First call validates and marks a position as liquidatable
2. Second call executes the liquidation only if the position was previously marked
3. Include a time lock between validation and execution to prevent race conditions
