# Title: `setBorrowingRateConfig` without updating interest rates leads to incorrect interest calculation.

### Summary

Owner can call the `setBorrowingRateConfig` function to set the borrowing rate configuration for a reserve. However, the function does not call `updateInterestRates` after modifying the borrowing rate configuration.
This can lead to incorrect interest calculation.

### Root Cause

When owner updates config by calling the [`setBorrowingRateConfig`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/LendingPool.sol#L357) function, borrowing rate is updated with new `utilization` and `borrowingRate`, but reserve's borrowing rates isn't updated.
So forward calling `deposit` or `redeem` function will calculate the incorrect interest.

Let's explain with example:

1. at t0, borrowing rate was b0.
2. at t1, owners calls `setBorrowingRateConfig` function. New borrowing rate is b1 but not updated.
3. at t2, user calls 'deposit' function.

In above case, from t0 to t1, borrowing rate is b0 and from t1 to t2, borrow rate is b1.
But current code implementation will calculate with b0 from t0 to t2 all the duration.

### Mitigation

```solidity
function setBorrowingRateConfig(
    address asset,
    uint16 utilizationA,
    uint16 borrowingRateA,
    uint16 utilizationB,
    uint16 borrowingRateB,
    uint16 maxBorrowingRate
) public onlyOwner notPaused {
    DataTypes.ReserveData storage reserve = reserves[asset];

    // Update the reserve state before modifying the borrowing rate configuration.
    reserve.updateState();

    // Set the new borrowing rate configuration.
    setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);

    // Update the interest rates after modifying the borrowing rate configuration.
    reserve.updateInterestRates();
}
```
