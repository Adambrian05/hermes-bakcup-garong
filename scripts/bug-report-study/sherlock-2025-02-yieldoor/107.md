# minBorrow check in `Leverager._checkWithinlimits()` should be done on borrowedAmount instead

### Summary

min borrow check  will always revert for figures around the min borrow value except for high figures

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L466

### Root Cause

```solidity
function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
```

 in `Leverager._checkWithinlimits()`,  minBorrow check is done on `initBorrowedUsd`. The issue with this is that `initBorrowedUsd` isn't really the amount borrowed but the converted amount (i.e to say, `initBorrowedUsd` is the borrowed amount converted with price).  

```solidity
up.initBorrowedUsd = up.borrowedAmount * bPrice / (10 ** ERC20(lp.denomination).decimals());
```
 
Leverager.sol contract specifies a minBorrow amount `20e18`, there's a problem with `Leverager.openLeveragedPosition()` that makes min borrows i.e borrows with amount of around `20e18` to revert with "position must be at least minBorrow amount" msg even though it is the accepted min borrow amount.


Just to throw more light, checking `Leverager.openLeveragedPosition()` when `lendingPool.borrow()` is called `lp.maxBorrowAmount` is what is borrowed from the lending pool and not `initBorrowedUsd` which is the converted version of `lp.maxBorrowAmount`.
```solidity
 {
            // we first borrow the maximum amount the user is willing to borrow. Any unused within the swaps is later repaid.
            ILendingPool(lendingPool).borrow(lp.denomination, lp.maxBorrowAmount);
```
