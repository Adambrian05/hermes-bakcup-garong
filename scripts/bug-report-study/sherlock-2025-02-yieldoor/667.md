# Attacker will cause overflow in yToken calculation

### Summary

Lack of overflow checks in yToken amount calculation will cause incorrect yToken minting for users as an attacker can deposit extremely large amounts

### Root Cause


In [LendingPool.sol: _deposit function](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol?plain=1#L117-L119) , the calculation `yTokenAmount = amount * exchangeRate / PRECISION` can overflow if amount is very large, potentially exceeding uint256 limits (up to 1.15e77).


### Internal Pre-conditions

The attacker has a large amount of the asset to deposit, potentially exceeding typical token limits (e.g., 1e60 tokens).

### External Pre-conditions

None specific, but the contract must be in a state where such a large deposit is possible.

### Attack Path

1. Attacker deposits an extremely large amount of the asset.
2. The calculation overflows, leading to an incorrect yTokenAmount.
3. The attacker receives more yTokens than they should, potentially allowing them to redeem more assets later.

### Impact

The lending pool suffers from an incorrect amount of yTokens being minted, leading to potential loss of assets when the attacker redeems, with an approximate loss depending on the overflow magnitude.

### PoC

_No response_

### Mitigation

Use OpenZeppelin's SafeMath for multiplication or check overflow before calculation.
