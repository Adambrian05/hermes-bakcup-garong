# Incorrect token amount used in repayment calculation leads to potential repayment failures

## Summary
A logical error in repayment calculation where amountOut0 is incorrectly used instead of amountOut1 when borrowed token is token1, leading to incorrect repayment amounts and potential transaction failures
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232-L234

## Root Cause
In the repayment calculation logic, when borrowed token is token1 (borrowed == up.token1), the code incorrectly uses amountOut0 instead of amountOut1 in the ternary operation for repayFromWithdraw calculation

## Internal Pre-conditions:
1. borrowed token must be token1 (borrowed == up.token1)
2. amountOut1 must be less than owedAmount to trigger the incorrect branch
3. amountOut0 and amountOut1 must have different values

## External Pre-conditions:
1. User must initiate a repayment transaction
2. Position must have an outstanding loan in token1

## Attack Path:
1. User has a position with borrowed token1
2. User initiates repayment
3. Code calculates repayFromWithdraw using incorrect token amount (amountOut0)
4. If amountOut0 > amountOut1:
   - System attempts to repay more than available token1 balance
   - Transaction reverts due to insufficient balance
5. If amountOut0 < amountOut1:
   - System repays less than possible
   - Remaining debt is higher than necessary

## Impact: 
The protocol calculates incorrect repayment amounts when token1 is borrowed, leading to either transaction failures due to insufficient balance or suboptimal repayment amounts that leave unnecessary remaining debt


## Recommendation:
Fix the ternary operation to use correct token amount:
```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
```
