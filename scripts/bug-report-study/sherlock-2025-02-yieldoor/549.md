# Mathematical Flaw in `InterestRateUtils.calculateCompoundedInterest`

### Summary

The formula for compounded interest is given as `(1 + rate / year) ^ exp`. This formulation is mathematically unsound. Here, `rate` represents an annual interest rate. If one year has passed (i.e., `exp = 1 year`), the compounded interest should be `1 + rate`. However, the current formula does not align with this principle, as `(1 + rate / year) ^ year > 1 + rate`.

### Root Cause

The [calculateCompoundedInterest()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/InterestRateUtils.sol#L98) function implements an approximate formula of `(1 + rate / year) ^ exp`. In this context, `rate` is defined as an annual rate, which implies that if one year has elapsed, the compounded rate should indeed be `1 + rate`. However, under the current formula, if `exp = 1 year`, the compounded rate calculates to `(1 + rate / year) ^ year > 1 + rate`, thereby misrepresenting the intended meaning of `rate` as an annual rate.

This represents a mathematical error. The correct formula should be `(1 + rate) ^ (exp / year)`. As a result of this miscalculation, the interest model is flawed, leading borrowers to pay more interest than they should.
