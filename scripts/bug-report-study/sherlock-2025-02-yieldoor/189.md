# Incorrect calculation of `usdValue` caused by decimals.

### Summary
There is incorrect handling of decimals in `_calculateTokenValues::L445-L447`.

### Root Cause
In line 445 and 447 of the `_calculateTokenValues` function, there is an incorrect handling of decimals.
The `decimal0` and `decimal1` is changed.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L445
```solidity

        internal
        view
        returns (uint256 usdValue)
    {
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
435:        usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }

        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
```

### PoC
Scenario:
`token0Price = 100,000 usd`, `token1Price = 1 usd`, `decimals0 = 8`, `decimals1 = 6`.
In the `_calculateTokenValues` function: `amount0 = 1e8`, `amount1 = 100,000e6`, `price = 100,000e30`.
The `usedValue` should be `100,000 + 100,000 = 200,000 usd`.
Let's assume that there are no pricefeed of `token1`, so `chPrice1 = 0` and `chPrice0 = 100,000e18`, 
In L435, `usdValue = 1e8 * 100,000e18 / 1e8 = 100,000e18 (100,000 usd)`.
In L447, `usdValue = 100,000e18 + 100,000e6 * 1e30 / 100,000e30 * 100,000e18 / 1e8 = 100,000e18 + 100,000e16 = 101,000e18`.
Therefore, the calculated `usdValue` is `101,000 usd`, which is not equal to the actual `usdValue` of `200,000 usd`.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L399
In the `isLiquidateable` function, the `_calculateTokenValues` fucntion is used.

### Impact
Leveraged positions may be liquidated when there is sufficient collateral, and they may not be liquidated even if the collateral is underwater.
