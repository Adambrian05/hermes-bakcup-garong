# Leverager::withdraw() uses the incorrect amounts for both repayments and transfer when token1 is borrowed

### Summary

The `Leverager` allows users to make leveraged positions by borrowing either `token0` or `token1` of the vault.

If `token1` is borrowed from the vault, the amount calculation is not handled correctly in `Leverager::withdraw()`, which leads to incorrect amounts being transferred or DoS.

### Root Cause

`amountOut0`, which is the amount corresponding to `token0`, is used for the calculation for `token1`
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235

Assume the user is withdrawing 10% of the position - this will cause `amountOut1 < owedAmount`
When `token1` is being borrowed, `borrowed == up.token1` as well.
`repayFromWithdraw` will be set to `amountOut0` instead of `amountOut1` in this case.
As a result, `owedAmount` and `amountOut1` will be subtracted by the incorrect amount.
These values are later used for repayment and `token1` withdrawal, respectively.

### Internal Pre-conditions

The conditions for this bug to be triggered are:
- A leverage position is opened borrowing `token1` of the vault.
- `amountOut1 < owedAmount `

### Impact

Outcomes:
- DoS due to underflow on subtraction (i.e. `amountOut0 > amountOut1` or `token0.decimals() > token1.decimals()`, or `amountOut0 > owedAmount` …)
- Incorrect amount pulled from user for repayment and for withdraw
    - If the user holds enough funds to cover the inflated `owedAmount`, the incorrect amounts are used for transfer.
    - If the user does not hold enough funds to cover the inflated `owedAmount`, users would be DoSed from paying back their loans.

In `test_withdrawToken1UnfundedUser()`, the user opens a leveraged position borrowing `token1` again.
The user assumes that the `token1` output will cover the loan - the user is seeded with only enough funds to cover the actual owed amount.
The transaction reverts because the incorrect owed amount is pulled from the user.
