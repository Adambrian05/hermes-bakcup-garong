# `_Leverager::_calculateTokenValues()` incorrectly assumes the returned decimals

### Summary

`_Leverager::_calculateTokenValues()` incorrectly assumes the returned decimals

### Root Cause

Calculating prices uses the following code:
```solidity
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += (amount0 * chPrice0) / decimals0;
        }
```
`getPrice()` returns the USD price of a token from Chainlink. Then, we turn that into the price decimals as we are dividing by the token decimals. The function is supposed to return the price in 18 decimals as written in comments and as perfectly clear by the code:
> /// @return usdValue The total token value, denominated in USD, scaled in 1e18.

The issue is that a Chainlink price feed can also return prices in 8 decimals, such is the [SOL/USD feed](https://data.chain.link/feeds/arbitrum/mainnet/sol-usd) on Arbitrum. This will result in incorrectly scaled prices, causing all kinds of accounting issues. Also, if the price for `token1` is in 18 decimals, then we will `usdValue` will be mixed of 8 and 18 decimal prices.


NOTE: While the price feed is OOS, the issue is in the calling contract (`Leverager`) as it incorrectly assumes the decimals of the price feed. Hence, this issue is in-scope.

### Internal Pre-conditions

1. The token used has a feed with 8 decimals

### External Pre-conditions

_No external pre-conditions_

### Attack Path

No attack path necessary.

### Impact

Accounting will be completely broken, we are using incorrect prices for important functions.

### PoC

_No response_

### Mitigation

Fetch the decimals and scale the price accordingly.
