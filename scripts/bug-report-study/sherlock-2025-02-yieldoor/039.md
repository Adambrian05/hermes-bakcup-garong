# Missing Price Feed Validation in _calculateTokenValues

### Summary

In the `Leverager.sol` `_calculateTokenValues` the natspec explicitly states the below
`@notice Calculates the USD value of amount0 and amount1`
`/// @dev Requires at least one of them to have set a trustworthy pricefeed.`   
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L415-L451

The require statement to enforce this is never implemented as an edge case both tokens can lack a valid price feed, the function has if statements for each token to check if there's a price feed. If either has one, it calculates the USD value. If not, it uses TWAP. But without a require statement, if both are missing, the code skips both if blocks and then tries the TWAP conversion. However, since both chPrice0 and chPrice1 are zero, the TWAP conversion would multiply by zero, resulting in a total USD value of zero.

### Root Cause

In `Leverager.sol`, `_calculateTokenValues`
 https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L415-L451
 there is no require statement to enforce the validation of atleast one token address having a valid priceFeed.

### Impact

If both tokens in _calculateTokenValues lack a price feed, the function returns usdValue = 0, as neither chPrice0 nor chPrice1 will be set. This directly affects the` isLiquidateable` function {https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L382-L413}  which relies on totalValueUSD to determine if a position should be liquidated. Since totalValueUSD is zero, totalDenom (the collateral value in the denomination token) is also zero. However, owedAmount, which represents the borrowed funds, remains positive.

The liquidation check then evaluates if 
``` solidity
(owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) 
  ```

With totalDenom = 0 and owedAmount > 0, the first condition (owedAmount > totalDenom) is always true, incorrectly marking the position as liquidatable. Additionally, the collateral check totalDenom - owedAmount < vp.minCollateralPct * base / 1e18 will also hold due to the negative result, reinforcing the faulty liquidation.
This creates a critical issue where positions without valid price feeds will always be liquidated, even if they are properly collateralized.

### Mitigation

consider updating the _calculateTokenValues to the below to enforce atleast one token address having a priceFeed else reverting with an error
```solidity
function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
    internal
    view
    returns (uint256 usdValue)
{
    uint256 chPrice0;
    uint256 chPrice1;
    uint256 decimals0 = 10 ** ERC20(token0).decimals();
    uint256 decimals1 = 10 ** ERC20(token1).decimals();

 require(
    IPriceFeed(pricefeed).hasPriceFeed(token0) || IPriceFeed(pricefeed).hasPriceFeed(token1),
    "At least one token must have a valid price feed"
);

    if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
        chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
        usdValue += amount0 * chPrice0 / decimals0;
    }
    if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
        chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
        usdValue += amount1 * chPrice1 / decimals1;
    }

    // Ensure at least one token has a reliable non zero value
    require(chPrice0 != 0 || chPrice1 != 0, "No reliable price feed available");

    // If chPrice0 is 0, it means token0 doesn't have a pricefeed.
    // Therefore, convert it to token1 and from there, convert it to USD
    if (chPrice0 == 0) {
        usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
    } else if (chPrice1 == 0) {
        usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
    }

    return usdValue;
} ```
