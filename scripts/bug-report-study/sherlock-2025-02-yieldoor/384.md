# Inability to collect fees from vesting position after rebalancing

### Summary

In the `Strategy.sol::collectFees` will use a wrong tick when collecting fees from the vesting position. This will cause inability to collect fees from the vesting position in a particular case

### Root Cause

The root cause is that in the `collectFees` function the `mainPosition.tickUpper` is used instead of the `vestPosition.tickUpper`:
```solidity
 if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, **mainPosition.tickUpper**); 
        } 
```
 This will cause inability to collect fees whenever `vestPosition.tickUpper!=mainPosition.tickUpper`. More particularly if there is a price deviation, rebalancing will result in inability to collect fees from the vesting position.

### Internal Pre-conditions

1. There shall be a vesting position.
2. A rebalancing should occur.

### External Pre-conditions

1.There must be a price deviation.

### Attack Path

1. Owner calls `addVestingPosition`
2. Due to price deviation `rebalance` is called by the `Rebalancer`.
3. Now because the `vestPosition.tickUpper!=mainPosition.tickUpper` fees from vesting position will not be charged. This is because the protocol will not have a position with ticks vestPosition.tickLower and mainPosition.tickUpper. As a result the UniswapV3Pool will return 0 amounts as it is stated [here](https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/UniswapV3Pool.sol#L497C8-L498C90)

### Impact

Inability to collect fees from vesting positions - Medium

### PoC

_No response_

### Mitigation

Use the vestPosition.tickUpper
