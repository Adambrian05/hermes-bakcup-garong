# Borrowing rate update delay in LendingPool#setBorrowingRateConfig()

### Summary

The setBorrowingRateConfig() allows the owner to update the borrowing rate parameters for a reserve. However, the update does not take effect immediately, as the function fails to call updateState() and updateInterestRates().
This delay enables a borrower to take out a loan at the old rate or repay it before the new rate is applied, avoiding increased interest costs.

### Root Cause

[LendingPool#setBorrowingRateConfig()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L348-L358) modifies the borrowingRateConfig struct but does not update the borrowing index or reserve state.
Interest rates only update when another transaction (deposit, borrow, redeem) triggers updateInterestRates().
This delay allows borrowers to exploit outdated interest rates.

### Internal Pre-conditions

Owner updates the borrowingRateConfig by setBorrowingRateConfig().

### External Pre-conditions

User deposit/redeem/borrow/repay.

### Attack Path

A borrower takes out a loan at the old (lower) borrowing rate.
The owner calls setBorrowingRateConfig() to increase borrowing rates.
The contract does not update interest rates immediately.
The borrower quickly repays the loan before another transaction triggers an update.
The borrower pays the old (lower) interest rate instead of the new (higher) one.
The borrower repeats the process, gaining an unfair advantage.

### Impact

The owner doesn't have control of currentBorrowingRate when the new borrowingRateConfig will be actually activated.
During between the setBorrowingConfigRate until the next action on the LendingPool which will update the interest rates, the old currentBorrowingRate will be used instead of new.
Thus the protocol can lose funds or user can lose funds.

### PoC

_No response_

### Mitigation

Immediately update state and interest rates modify setBorrowingRateConfig() to update the reserve state and interest rates immediately:

```diff

    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
+       reserve.updateState();
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
+       reserve.updateInterestRates();
    }
```
