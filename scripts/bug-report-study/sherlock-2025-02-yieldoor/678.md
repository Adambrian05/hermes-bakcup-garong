# Risk of locking user position due to use `_mint` instead of `_safeMint` in `Leverager.sol::openLeveragedPosition` function

### Summary

The `Leverager.sol` inherits ERC721 contract and the position is represented as a NFT, so the position is transferable.

However, if the `msg.sender` of the `openLeveragedPosition` is a contract that doesn't support NFT, the position may be frozen in the contract although it is still transferable.

### Root Cause

[Leverager.sol::197](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L197)
```Solidity
    function openLeveragedPosition(LeverageParams calldata lp) external nonReentrant returns (uint256 _id) {
    ...
>   _mint(msg.sender, _id);
    ...
    }
```

### Internal Pre-conditions

None.

### External Pre-conditions

None.

### Attack Path

None.

### Impact

Although the position remains liquidatable since it can still be burned, it affects the user experience because the idea of making the position represented as an NFT is to make it transferable.

### PoC

_No response_

### Mitigation

Consider using `_safeMint` with try/catch to implement error handling to prevent DoS attack.
If the user reverts the transfer intentionally, consider blacklisting the user.
