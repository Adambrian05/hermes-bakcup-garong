# Incorrect debt repayment due to wrong variable usage

### Summary

Using `amountOut0` instead of `amountOut1` in the repayment logic will cause incorrect debt repayment for positions where `borrowed == up.token1`, as the contract will repay using the wrong token, potentially leading to underpayment, liquidation risks, or bad debt accumulation.


### Root Cause

In [`Leverager.sol#withdraw()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L209-L293):

```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {

        // ... code ...

        if (borrowed == up.token1) {
        uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;  // ❌ Wrong variable used!
        owedAmount -= repayFromWithdraw;
        amountOut1 -= repayFromWithdraw;
        }

        // ... code ...
    }
```

- Should use `amountOut1` instead of `amountOut0` for debt repayment.
- If `borrowed == up.token1`, the function must use `amountOut1` to repay the debt.
- Currently, it mistakenly checks `amountOut0`, leading to incorrect calculations and potential underpayment of debt.


### Internal Pre-conditions

1. A position is opened with `borrowed == up.token1`.
2. The user attempts to withdraw from the position.
3. The protocol calls `withdraw()` and calculates repayment amounts.


### External Pre-conditions

1. The Uniswap pool provides liquidity for both tokens.
2. The lending pool expects repayment in `token1`.

### Attack Path

1. User opens a leveraged position, borrowing `token1`.
2. User initiates a withdrawal, triggering repayment logic.
3. Contract mistakenly uses `amountOut0` instead of `amountOut1`.
4. Debt remains unpaid or is underpaid, leading to:
   - Liquidation risks due to unpaid debt.
   - Protocol accumulating bad debt if underpayment persists.
   - Potential exploit where users escape full repayment.

### Impact

Incorrect debt repayment logic.  
Users may underpay debt, leading to liquidation risks.  
Protocol may accumulate bad debt due to incorrect repayments.  
Potential exploit where users avoid full repayment and drain liquidity.


### PoC

_No response_

### Mitigation

Replace `amountOut0` with `amountOut1` in the repayment logic:

```solidity
if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
}
```
