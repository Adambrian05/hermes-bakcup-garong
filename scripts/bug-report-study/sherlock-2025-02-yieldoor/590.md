# Incorrect Tick Upper Value in Strategy::collectFees Can Cause Revert

### Summary

The `Strategy::collectFees` function may revert when attempting to collect fees from a non-existent position.

[Strategy::collectFees](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167) function:
```javascript
function collectFees() public {
    (uint256 preBal0, uint256 preBal1) = idleBalances();

    if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
    if (secondaryPosition.liquidity != 0) {
        collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
    if (ongoingVestingPosition) {
=>      collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
    }
    ...
}
```

When collecting fees from the vesting position, the function incorrectly passes `mainPosition.tickUpper` instead of `vestPosition.tickUpper`:  

```javascript
collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
```

This can cause an issue if `mainPosition.tickUpper` has changed due to a rebalance (`Strategy::rebalance`). As a result, the position `(vestPosition.tickLower, mainPosition.tickUpper)` may not exist, leading to a revert when calling:  

```javascript
IUniswapV3Pool(pool).burn(tickLower, tickUpper, 0);
```

This issue propagates to other functions that call `Strategy::collectFees`, such as `Vault::deposit` and `Vault::withdraw`, disrupting core protocol functionality. 

### Root Cause

- The `Strategy::collectFees` function incorrectly uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper` when collecting fees from the vesting position.  
- If `mainPosition.tickUpper` changes after a rebalance (`Strategy::rebalance`), the position `(vestPosition.tickLower, mainPosition.tickUpper)` may not exist, causing a revert. 

### Internal Pre-conditions

1. There is an active vesting position.  
2. After executing `Strategy::rebalance`, `mainPosition.tickUpper` differs from `vestPosition.tickUpper`.

### Impact

- The `Strategy::collectFees` function may revert, preventing the collection of protocol fees.  
- Functions relying on `collectFees`, such as `Vault::deposit` and `Vault::withdraw`, may also revert, breaking protocol functionality.

### Mitigation

Update the `Strategy::collectFees` function as follows:

```diff
function collectFees() public {
    (uint256 preBal0, uint256 preBal1) = idleBalances();

    if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
    if (secondaryPosition.liquidity != 0) {
        collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
    if (ongoingVestingPosition) {
-       collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+       collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
    }
    ...
}
```
