# Depositors are disincentivised to make a first deposit containing both tokens

### Summary

When making a the first deposit in a Vault, the user can choose whether to deposit both token0 and token1, or only one of them. If they submit both tokens, the relative proportion of shares they will receive would be less than it should be.

### Root Cause

In the `Vaulet::_calcDeposit` method, when totalSupply is zero, the shares the depositor receives are taken as the larger of amount0 and amount1, instead of the sum of both:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L133

### Internal Pre-conditions

1. A target vault is empty (totalSupply is 0)

### External Pre-conditions

1. User deposits both token0 and token1 into this vault.

### Attack Path

1. User calls `Vault:deposit` with numbers > 0 for both amount 0 and amount 1.

### Impact

If a user deposits both token0 and token1, they will receive less shares than they ought to.
