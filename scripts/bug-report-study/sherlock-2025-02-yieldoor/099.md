# Malicious user can receive vested position without paying fees to the protocol on `strategy::collectFees()`

### Summary

The strategy collects fees when swaps happen to the protocol. The more liquidity the vault/strategy has, the more fees are given to the protocol. The owner may also choose to add vested positions to incentivize adding liquidity to the vault, which is collected over time. As fees are accrued on swaps, malicious users can do the following to receive fees from swaps and vested positions without the protocol getting any fees:
1. Swap is coming
2. Malicious user withdraws from the vault, deposits in the pool directly.
3. Swap happens, user collects fees because he was in the pool. As the user was not in the vault, the protocol will not collect fees from the swap.
4. User deposits in the vault again to continue receiving the vested position.

Depending on deposit fees, the attack may still be profitable, depending on the swap. The attack is always profitable in case the user decides to withdraw before the swap and not deposit again, as no withdrawal fee is enforced.

### Root Cause

In `Vault:80`, no [withdrawal](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L80) fee is enforced.
