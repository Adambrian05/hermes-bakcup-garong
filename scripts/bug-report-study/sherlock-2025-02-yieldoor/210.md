# Usage Of `slot0` To Get `sqrtPriceX96` Is Extremely Prone To Manipulation

### Summary

The slot0 variable contains the most recent price update for a pool in Uniswap V3, [slot0](https://docs.uniswap.org/contracts/v3/reference/core/interfaces/pool/IUniswapV3PoolState#slot0). This data point is crucial for the pool's functionality but is also highly susceptible to manipulation. `The Strategy.sol` relies on this value to calculate the balance of tokens, which is also used in the `Vault.sol` to calculate the number of shares minted to users when a liquidity provider deposits. This creates a potential vulnerability, as a malicious actor can manipulate the slot0 price, thereby affecting the number of shares minted for a user.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L497-L521
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L67-L68


### Root Cause

In `Strategy.sol` the balances of the strategy uses `sqrtPriceX96` which is gotten directly from `slot0` to calculate the balances of the strategy, this is also used to calculate the shares minted to a liquidity provider in the `Vault.sol`

Nil

### Impact

Pool lp value can be manipulated and cause other users to receive less lp tokens

### Mitigation

To make any calculation which involves balances of the strategy and calculating shares use a TWAP instead of slot0. `TWAP` is a pricing algorithm used to calculate the average price of an asset over a set period.
