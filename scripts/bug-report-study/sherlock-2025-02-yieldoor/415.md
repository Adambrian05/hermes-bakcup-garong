# `_calculateTokenValues` may severely underestimate a position's value due to rounding down to 0

### Summary

In the `_calculateTokenValues` there is algorithm for treating tokens without a price feed. However due to flawed calculations, the token's usd value might be rounded down to 0.

### Root Cause

In the [`Leverager.sol::_calculateTokenValues`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L447) we can see that the following calculation is performed when the token1 address does not have a price feed:
```solidity
else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }
```
Due to devision before multiplication the usdValue of some assets could be rounded down to 0 potentially underestimating the user's collateral causing unfair liquidation.
Consider we have token0 = WBTC and token1 = wstETH
The protocol is launched on a chain which does not have a wstETH/USD price feed so that the twap price is used
1e8WBTC = 37e18 ETH => twap price = 37e48
Now when we try to execute the above code with any eth amoun which is less than 37e18 wstEth will be rounded down to 0.

### Internal Pre-conditions

1.Token1 will have to be missing a price feed.
