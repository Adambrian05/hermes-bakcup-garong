# Introducing fees allows previous depositors to steal funds.

### Summary

If an attacker deposits before a fee was introduced, and then the fee was added and `user2` deposits, the attacker will be able to steal funds on the expense of `user2`. And end up with more funds that what he started with.

### Root Cause

The problem stems from how withdrawal amounts are calculated in relation to total balance and total supply of shares. Specifically:

- The line [Vault.sol:91](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L91) assumes that each share is worth the same fraction of `totalBalance`, ignoring the dilution effect caused by fees.
- When new deposits occur, they increase `totalBalance`, while the `totalSupply` will be reduced due to the fee, This makes it seem like legacy shares should be worth more.
- Older depositors benefit unfairly because they got more shares per token when they deposited, and when withdrawing, their shares pull from the entire balance (which includes taxed deposits from newer users).

### Internal Pre-conditions

Admin needs to set a fee.

### External Pre-conditions

N/A

### Attack Path

1 - Attacker deposits before a fee was introduced.
2 - Attacker raises some red flags to cause the admin to set a deposit fee ( as in the docs ).
3 - Victim deposits after the fee was introduced.
4 - The attacker withdraws, restoring his funds and stealing a portion of what the victim deposited, ending up with more than what he had.

### Impact

- If the fee is set to 0.01% , and 10 users deposit, attacker gains 0.03%.
- If the fee is set to 0.1% ( the fee cap ) , and 10 users deposit, attacker gains 0.34%.
- The more users deposit, the more profit the attacker makes.
