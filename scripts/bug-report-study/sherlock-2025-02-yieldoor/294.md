# Flashloan can still be performed with frozen assets

## Summary
The `LendingPool#pullFunds` function lacks a frozen asset check, allowing the leverager to bypass asset freezing controls through flashloans.

## Relevant Context
The `LendingPool` contract implements a freeze mechanism that prevents new deposits and borrows while allowing withdrawals and repayments. This is controlled through the `freezeReserve` and `unFreezeReserve` functions that can only be called by the owner.

## Root Cause
While the `borrow` function properly checks if an asset is frozen via `require(!reserve.getFrozen(), "reserve frozen")`, the `pullFunds` function used for flashloans lacks this check. This oversight allows the leverager to continue accessing frozen asset liquidity through flashloans, even when direct borrowing is disabled.

The `pullFunds` function only verifies that the caller is the leverager contract but does not enforce that the asset is not frozen:

[`LendingPool.sol#L209`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/LendingPool.sol#L209)

```solidity
function pullFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData memory reserve = getReserve(asset);
    IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
}
```

## Attack Path

1. Protocol owner freezes an asset due to market conditions or security concerns using `freezeReserve`
2. Despite the freeze, the leverager contract can still:
   - Call `LendingPool#pullFunds` to extract tokens
   - Perform operations with the tokens
   - Return them via `LendingPool#pushFunds`
3. This effectively nullifies the freeze mechanism's intended protection for flashloan operations

## Impact Explanation
Medium. While the vulnerability allows bypassing the freeze mechanism through flashloans, several factors limit its severity:

1. The issue only manifests when reserves are frozen, which is an exceptional state
2. The flashloan mechanism enforces full repayment within the same transaction via `pushFunds`, meaning no permanent loss of funds occurs

## Proof of Concept

1. Owner calls `freezeReserve(USDC)`
2. Regular borrows of USDC are blocked
3. Leverager can still:
```solidity
// In Leverager#openLeveragedPosition
if (delta0 > 0) ILendingPool(lendingPool).pullFunds(up.token0, delta0);
// ... perform operations ...
if (delta0 > 0) ILendingPool(lendingPool).pushFunds(up.token0, delta0);
```

## Recommendation
Add the frozen asset check to `pullFunds`:

```diff
function pullFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData memory reserve = getReserve(asset);
+   require(!reserve.getFrozen(), "reserve frozen");
    IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
}
```
