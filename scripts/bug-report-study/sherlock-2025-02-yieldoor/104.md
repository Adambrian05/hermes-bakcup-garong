# Security Vulnerability Report: Incorrect Repayment Calculation in withdraw Function in 'Leverager.sol'

### Summary

A logical error in the withdraw function of the smart contract incorrectly determines the repayment amount when the borrowed token is token1. This issue arises due to a mistaken variable assignment, which could lead to an unintended deduction of funds, incorrect debt repayment, and potential financial loss. [here](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231)

### Root Cause

The vulnerability is caused by the following incorrect logic:
```solidity
} else if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
The line uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount; mistakenly references amountOut0 instead of amountOut1.

This incorrect assignment means that when amountOut1 is less than owedAmount, the function mistakenly considers amountOut0 instead of the actual available balance of token1, leading to miscalculations in repayment.

### Internal Pre-conditions

A user has an active leveraged position within the protocol.
The user's position includes token0 and token1 as collateral or borrowed assets.
The user initiates a withdrawal request with a valid WithdrawParams.

### External Pre-conditions

The lending pool and vault systems are operational.
The user executing the withdrawal is the approved owner of the position.
The swapRouter is functional if the withdrawal requires swapping tokens

### Attack Path

A user with a leveraged position attempts to withdraw a portion of their collateral.
The withdraw function executes, determining the repayment amounts based on the denomination token.
If borrowed == up.token1, the function incorrectly assigns the repayment amount using amountOut0 instead of amountOut1.
This may result in an incorrect deduction of funds and leave the contract with an incorrect outstanding debt balance.
Depending on the execution, this could either cause financial loss for the user or create an opportunity for exploitation where debt is not fully repaid.

### Impact

Financial Loss: Users withdrawing token1 as the borrowed asset may face incorrect deductions, potentially paying more than required or failing to clear their debt properly.

Contract Integrity Risk: Incorrect debt repayment could lead to an unstable lending pool where obligations are not properly recorded.

Potential Exploitation: Malicious actors might find ways to manipulate the incorrect logic to leave unpaid debt, harming the system’s financial health.

### PoC

Assume a user has a leveraged position where borrowed = token1.

The user attempts to withdraw 50% (0.5e18) of their position.

The contract executes:
```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```
If amountOut1 < owedAmount, amountOut0 is mistakenly used instead of amountOut1.

The function incorrectly reduces the owed amount and adjusts balances based on the wrong token.

This can lead to a mismatch where the user's debt is not correctly accounted for, allowing possible exploitation.

### Mitigation

Replace the incorrect assignment with:
```solidity
} else if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
