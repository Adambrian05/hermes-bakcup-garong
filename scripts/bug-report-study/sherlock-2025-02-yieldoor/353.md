# Leverager::_calculateTokenValues() uses the incorrect scaling when a feed is unavailable

### Summary

In `Leverager::_calculateTokenValues()`, there are fallback calculations for when a price feed is unavailable.
The issue is these calculations are not accurate and will result in either unintended DoS or users will be calculated more / less collateral than actually deposited.

### Root Cause

Incorrect calculation for collateral value in USD - https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L444-L448

### Internal Pre-conditions

N/A

### External Pre-conditions

At least one feed is unavailable

### Attack Path

N/A

### Impact

If the value is inflated, the user's collateral would be calculated to be worth more than what it is.
`vaultParams[vault].currBorrowedUsd` would deviate over time as well.
Eventual insolvency or unintended DoS

function test_calculateTokenValues() external {
    // function parameters - wbtc / usdc vault
    uint256 amount0 = 1e8;  
    uint256 amount1 = 100_000e6;   
    uint256 price = IVault(vault).twapPrice();
    uint256 usdValue = _calculateTokenValues(address(wbtc), address(usdc), amount0, amount1, price);

    uint256 difference = usdValue - 200_000e18;
    console2.log("Incorrect difference when both feeds are on: %s", difference);

    // disable feed for token0 (WBTC)
    vm.startPrank(owner);
    IPriceFeed(priceFeed).setChainlinkPriceFeed(address(wbtc), address(0), 0);
    usdValue = _calculateTokenValues(address(wbtc), address(usdc), amount0, amount1, price);
        
    difference = 200_000e18 - usdValue;
    console2.log("Incorrect difference when token0 feed is off: -%s", difference);
        
    // disable token1 feed (USDC)
    IPriceFeed(priceFeed).setChainlinkPriceFeed(address(usdc), address(0), 0);
    IPriceFeed(priceFeed).setChainlinkPriceFeed(address(wbtc), address(wbtcOracle), 604800);
    usdValue = _calculateTokenValues(address(wbtc), address(usdc), amount0, amount1, price);

    difference = usdValue - 200_000e18;
    console2.log("Incorrect difference when token1 feed is off: %s", difference);
    
    IPriceFeed(priceFeed).setChainlinkPriceFeed(address(usdc), address(usdcOracle), 604800);
    vm.stopPrank();
}

function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
    internal
    view
    returns (uint256 usdValue)
{
    uint256 chPrice0;
    uint256 chPrice1;
    uint256 decimals0 = 10 ** ERC20(token0).decimals();
    uint256 decimals1 = 10 ** ERC20(token1).decimals();
    if (IPriceFeed(priceFeed).hasPriceFeed(token0)) {
        chPrice0 = IPriceFeed(priceFeed).getPrice(token0);
        usdValue += amount0 * chPrice0 / decimals0;
    }
    if (IPriceFeed(priceFeed).hasPriceFeed(token1)) {
        chPrice1 = IPriceFeed(priceFeed).getPrice(token1);
        usdValue += amount1 * chPrice1 / decimals1;
    }

    // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
    // Therefore, convert it token1 and from there, convert it to USD
    if (chPrice0 == 0) {
        usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
    } else if (chPrice1 == 0) {
        usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
    }

    return usdValue;
}

In `test_calculateTokenValues()`, it is shown that there is no error when both price feeds are available, but the calculations are incorrect when at least one feed is off.
In `test_depositToken1FeedOff()`, it is shown that after the feed is turned off, a user's position is worth 'more' for opening an identical position.

### Mitigation

Rework the calculations in `Leverager::_calculateTokenValues()` for when feeds are unavailable or remove it completely and rely on oracles.
