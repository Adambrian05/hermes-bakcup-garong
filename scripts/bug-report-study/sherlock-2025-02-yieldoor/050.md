Fresh Snowy Hedgehog

Medium

# lack of notPaused  check for LendingPool.sol#repay()

### Summary

lack of notPaused  check for LendingPool.sol#repay(), will cause repay() still available after owner pause the contract.


### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L186

deposit(), borrow() and redeem() all check if the contract is paused, however, repay() missed the check. If the owner set this contract to the pause state, it means all those operations should be unavailable then, till the owner unPauseAll() to enable them again.

 repay()  should obey the same rule to deposit(), borrow() and redeem().

### Internal Pre-conditions

none

### External Pre-conditions

none

### Attack Path

1, the owner unpause contract LendingPool.
2, user deposit to the account.
3, leverager borrow some amount.
4, the owner pause contract LendingPool.
5, leverager repay some amount.

### Impact

repay() still available when the contract is paused.

### PoC

_No response_

### Mitigation

add notPaused  to repay()
    
function repay(address asset, uint256 amount) external notPaused  nonReentrant returns (uint256) {
        require(msg.sender == leverager, "borrower not leverager");
        DataTypes.ReserveData storage reserve = getReserve(asset);
        // update states
        reserve.updateState();

        if (amount > reserve.totalBorrows) {
            amount = reserve.totalBorrows;
        }

        reserve.totalBorrows -= amount;
        reserve.underlyingBalance += amount;

        // Transfer the underlying tokens from the vaultPosition to the yToken contract
        IERC20(asset).safeTransferFrom(_msgSender(), reserve.yTokenAddress, amount);

        reserve.updateInterestRates();

        return amount;
    }
