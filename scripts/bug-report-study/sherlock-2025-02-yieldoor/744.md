# Secondary position is not created initially out of range.

### Summary

[https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L363-L365](url)

Strategy::_setSecondaryPositionsTicks claim that it should initially be Out-Of-Range, but that is not true, actually it is created inside of the main position

### Root Cause

See PoC

n/a

### External Pre-conditions

n/a

### Attack Path

### Impact

This problem affects one of the main purposes of this contract, which is to use the secondary position as a strategy to utilize idle balances, but having secondary positions overlapping the main position destroys the purpose.

### PoC

Let's assume these values:

mainPosition.tickUpper = 202940
mainPosition.tickLower = 202900
tickSpacing = 10
tick = 202919
modulo = tick % tickSpacing;
module = 202919 % 10 = 9 

if bal0in1 < bal1:

secondaryPosition.tickLower = mainPosition.tickLower
secondaryPosition.tickLower = 202900

secondaryPosition.tickUpper = tick - modulo;
secondaryPosition.tickUpper = 202919 - 9 = 202910

if bal0in1 >= bal1

secondaryPosition.tickLower = tick - modulo + tickSpacing;
secondaryPosition.tickLower = 202919 - 9 + 10 = 202920;
secondaryPosition.tickUpper = mainPosition.tickUpper; 
secondaryPosition.tickUpper = 202940 

As you can see in both scenarios secondary.position won't be out-of-range.
