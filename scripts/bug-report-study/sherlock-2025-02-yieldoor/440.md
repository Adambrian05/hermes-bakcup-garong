# Misvaluation of `initCollateralValue` in `Leverager.withdraw()` Causes False Liquidations or Bad Debt Accumulation

### Summary

The protocol incorrectly adjusts `positions[wp.id].initCollateralValue` by a proportional reduction when `shares` is withdrawn from the vault for partial repayment. This fails to reflect real market conditions, leading to over or under-valuation of collateral. Because `isLiquidateable()` dynamically calculates `totalDenom` and `owedAmount` accurately, an inaccurate `initCollateralValue` causes either premature liquidations or delayed bad debt accumulation.

### Root Cause

Currently, `Leverager.withdraw()` reduces `initCollateralValue` in proportion to the share withdrawal percentage:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L288

```solidity
            positions[wp.id].initCollateralValue -= up.initCollateralValue * wp.pctWithdraw / 1e18;
```
While it doesn't matter that the `initBorrowedUsd` doesn't represent the real value (due to market price fluctuations) which is applicable to the non-consequential update of [`vaultParams[up.vault].currBorrowedUSD`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L285) or poised for [`minBorrow`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L280) check, this intended approach will be essentially concerning the actual collateral value, i.e. `initCollateralValue` after withdrawal.

This is because [`isLiquidateable()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L394-L411) recalculates `totalDenom` and `owedAmount` dynamically. Any inaccuracy in `initCollateralValue` directly impacts liquidation decisions, leading to incorrect liquidations or delayed liquidations causing bad debt.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408-L411

```solidity
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
        base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
```
Apparently, if `owedAmount > totalDenom` is false, `totalDenom - owedAmount < vp.minCollateralPct * base / 1e18` could be true if `base` having been assigned by `pos.initCollateralValue` is overvalued leading to unintended liquidation, and vice versa.

### Internal Pre-conditions

1. A user has an open leveraged position.

2. The user withdraws a portion of their collateral.

3. The system applies a proportional reduction to `initCollateralValue` instead of recalculating it.

### External Pre-conditions

1. The price of collateral fluctuates after withdrawal.

2. `isLiquidateable()` correctly calculates `totalDenom` and `owedAmount`, making any inaccuracy in `initCollateralValue` problematic.

### Attack Path

1. A user withdraws a portion of their collateral, triggering an incorrect proportional reduction in `initCollateralValue`.

2. If `initCollateralValue` is underestimated, the position remains open even when it should be liquidated, leading to bad debt accumulation. Apparently, by the time [`owedAmount > totalDenom == true`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411), it's deemed too late and no sound bots would proceed to liquidating the position at a loss.

3. If `initCollateralValue` is overestimated, the position is prematurely liquidated due to [`totalDenom - owedAmount < vp.minCollateralPct * base / 1e18`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411) prone to erroneously returning true, causing unnecessary loss for the user.

4. Because `isLiquidateable()` accurately determines `totalDenom` and `owedAmount`, an incorrect `initCollateralValue` leads to systemic miscalculations.

### Impact

- Premature Liquidations: Users may lose collateral unnecessarily due to an overestimated `initCollateralValue`.

- Delayed Liquidations & Bad Debt: Underestimated `initCollateralValue` prevents liquidation when it is necessary, allowing bad debt to accumulate.

- Systemic Risk: Incorrect liquidation logic can destabilize the protocol’s intended design if multiple positions are affected.

### Mitigation

Replace the proportional reduction of `initCollateralValue` with a full recalculation based on market prices, similar to `isLiquidateable()`. This parallels the recreation of a new leveraged position in `openLeveragedPosition()`:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L287-L288

```diff
+            uint256 vaultSupply = IVault(up.vault).totalSupply();

+            (uint256 vaultBal0, uint256 vaultBal1) = IVault(up.vault).balances();
+            uint256 userBal0 = (up.shares - sharesToWithdraw) * vaultBal0 / vaultSupply;
+            uint256 userBal1 = (up.shares - sharesToWithdraw) * vaultBal1 / vaultSupply;
+            uint256 price = IVault(up.vault).twapPrice();

+            uint256 totalValueUSD = _calculateTokenValues(up.token0, up.token1, userBal0, userBal1, price);
+            uint256 bPrice = IPriceFeed(pricefeed).getPrice(up.denomination);
+            positions[wp.id].initCollateralValue = totalValueUSD * (10 ** ERC20(up.denomination).decimals()) / bPrice;

            positions[wp.id].initBorrowedUsd -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
-            positions[wp.id].initCollateralValue -= up.initCollateralValue * wp.pctWithdraw / 1e18;
```
