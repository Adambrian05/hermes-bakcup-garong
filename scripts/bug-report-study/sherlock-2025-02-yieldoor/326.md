# Reentrancy attack in `collectFees`

in Strategy.sol:collectFees 

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159-L182

The function is vulnerable to a reentrancy attack due to unsafe external token transfers before completing all internal state changes.
The function calls `IERC20(token0).safeTransfer(feeRecipient, protocolFees0);` and `IERC20(token1).safeTransfer(feeRecipient, protocolFees1);` before handling the vested position withdrawal.
These external token transfers could trigger malicious contract callbacks that re-enter `collectFees` before `_withdrawPartOfVestingPosition()` executes.
A reentrant call could manipulate `idleBalances()` before the function completes, leading to incorrect protocol fee calculations.
This could allow the attacker to drain extra funds or cause misaccounting of fees.
Impact:
-Double withdrawal attack: an attacker could repeatedly trigger `collectFees`, artificially increasing protocol fee calculations and withdrawing excess funds.
-Potential Fund Loss: The protocol fee recipient could receive excessive funds due to manipulated balance calculations.

Fix:
Use `nonReentrant` modifier
