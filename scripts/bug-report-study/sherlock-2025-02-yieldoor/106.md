# Exempting leverager from depositFee in Vault#deposit()

### Summary

The Leverager contract interacts with the Vault by depositing token0 and token1 to receive shares in return. However, if depositFee is set, the Leverager receives fewer shares than expected due to fee deductions.
Since depositFee is intended to mitigate spam deposits, and the Leverager is a trusted contract executing leveraged positions, it should be exempt from the deposit fee.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L61
The Leverager is a legitimate contract that should not be penalized by this fee.
There is no condition to exempt the Leverager, leading to unexpected share reductions for leveraged positions.

### Internal Pre-conditions

The Vault has a nonzero depositFee.
The Leverager deposits token0 and token1 into the Vault.

### External Pre-conditions

The Leverager contract calls openLeveragedPosition().
The deposit fee is active (depositFee > 0).

### Attack Path

The Leverager calls openLeveragedPosition and it calls Vault#deposit() to deposit token0 and token1.
The Vault applies a depositFee, reducing the shares issued.
The Leverager receives fewer shares than expected.
This reduces leverage efficiency, affecting overall leveraged position calculations.

### Impact

Leveraged positions receive fewer shares.

### PoC

_No response_

### Mitigation

Set leverager address in Vault by owner.
Exempt the Leverager from depositFee in Vault.deposit() Modify deposit() to check if msg.sender == leverager

```diff
- if (depositFee > 0) shares -= (shares * depositFee) / 10_000;
+ if (depositFee > 0 && msg.sender != leverager) shares -= (shares * depositFee) / 10_000;
```
