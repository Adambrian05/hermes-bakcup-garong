# The vesting position is never rebalanced, which could cause it to not acumulate fees

### Summary

When adding a vesting position it's `tickLower` and `tickUpper` are set to the `mainPosition.tickLower` and `mainPosition.tickUpper`.


```solidity
 function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;
       
        // @audit - This position is never rebalanced
        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;

        (uint160 sqrtPrice,,,,,,) = IUniswapV3Pool(pool).slot0();
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPrice,
            TickMath.getSqrtRatioAtTick(vp.tickLower),
            TickMath.getSqrtRatioAtTick(vp.tickUpper),
            amount0,
            amount1
        );

        vp.initialLiquidity = liquidity;
        vp.remainingLiquidity = liquidity;

        IUniswapV3Pool(pool).mint(address(this), vp.tickLower, vp.tickUpper, liquidity, "");

        vp.startTs = block.timestamp;
        vp.lastUpdate = block.timestamp;
        ongoingVestingPosition = true;
        vp.endTs = block.timestamp + _vestDuration;
        vestPosition = vp;
    }
```

When the rebalancer calls [rebalance(https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198-L215), it is only rebalancing the main and the secondary position.

In situations where the tick goes out of boundaries, the vesting position will never be rebalanced, which causes it to not earn any fees.


### Root Cause

The vesting position is never rebalanced with the main one, causing loss of yield for the users.

### Internal Pre-conditions

1. A vesting position must be added

### External Pre-conditions

1. The current tick must be outside of `vestingPosition.tickLower` and `vestingPosition.tickUpper` boundaries.

### Attack Path

None

### Impact

The users will not receive any fees from the vesting position, when it goes out of boundaries, resulting in loss of yield.

### PoC

1. Vesting position is added to the same boundaries as the main position
2. Main position goes out of boundaries and is rebalanced
3. The vested position is never rebalanced and the price does not go back to boundaries for the whole vesting period
4. The vested position never acumulates any fees, resulting in loss of yield for the holders

### Mitigation

1. When adding the vesting position, increment `mainPosition.liquidity`.
2. When rebalancing the main position change the tickUpper and tickLower of the vesting position
3. When withdrawing from the vested position, consider decrementing the withdrawed liquidity from `mainPoisition.liquidiy`

These changes ensure that the main and the vested positions are always rebalanced and reflect eachother, making sure it earns fees along the process
