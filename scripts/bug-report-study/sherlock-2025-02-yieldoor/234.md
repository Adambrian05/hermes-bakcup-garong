# users could borrow more than max leverage times and  accrue bad debt due to incorrect accounting for collaterals when open leverage position

### Summary

The incorrect accounting for collateral value as opening leverage will break procotol's liquidation check logic

### Root Cause

Leverager::openLeveragedPosition() is meant for open an leveraged position with borrowings from lending pool. The borrowed amount is gap between lp.vault0In/lp.value1In and lp.amount0In/lp.amount1In, where the user's actual transferred token lp.amount0In/lp.amount1In should serve as collateral. However, openLeveragePosition() misuses vault deposited value as collateral, which including all the tokens from user transferring and borrowing.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L129

### Internal Pre-conditions

None

### External Pre-conditions

Users borrow as many times leverage as they want

### Attack Path

An example of surpass max leverage would be:
attacker borrows m times of the his collateral value, which makes
 up.initCollateralValue=m*realCollateral;
up.borrowedAmout = (m-1)*realColllateral;
positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue
                               = (m+m-1)/m = 2 - 1/m
which will always fall below either vp.maxTimesLeverage or mxLevTimes
_checkWithinlimits() method on checking leverage will always pass.


### Impact

Users can borrow more than max leverage and accrue bad debts
