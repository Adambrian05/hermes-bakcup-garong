# Incorrect tickUpper in collectFees Causes Revert, Disabling Core Protocol Functions

### Summary

In the collectFees function, the calculation of VestingPosition’s earnings mistakenly uses mainPosition.tickUpper instead of vestPosition.tickUpper. However, vestPosition.tickUpper remains unchanged until maturity, while mainPosition.tickUpper may be modified during this period.

This incorrect reference causes Uniswap V3 to fail to locate the position, leading to a revert when calling burn(0):
```solidity
IUniswapV3Pool(pool).burn(tickLower, tickUpper, 0);
```

Since Uniswap V3 requires the position to exist (liquidity > 0), the call fails with the error:
```solidity
        if (liquidityDelta == 0) {
            require(_self.liquidity > 0, 'NP'); // disallow pokes for 0 liquidity positions
            liquidityNext = _self.liquidity;
```
This issue has severe consequences:
	•	All protocol functions relying on collectFees will revert, including withdrawals and fee collection.

### Root Cause

In [Strategy.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L167), the function collectFees uses mainPosition.tickUpper instead of vestPosition.tickUpper when referencing VestingPosition.

### Internal Pre-conditions

mainPosition.tickUpper changes dynamically, but vestPosition.tickUpper remains fixed until maturity.

### External Pre-conditions

none

### Attack Path

1.	A user triggers any function that calls collectFees.
2.	collectFees incorrectly references mainPosition.tickUpper instead of vestPosition.tickUpper.
3.	The contract calls Uniswap V3’s burn(0) with an invalid tick range.
4.	Uniswap V3 fails to find the position and reverts with NP (Nonexistent Position).
5.	Since all protocol functions depend on collectFees, the entire protocol becomes unusable.

### Impact

1. The entire protocol breaks down.
2. Users cannot withdraw funds, leading to a full lock-up of assets.

### PoC

_No response_

### Mitigation

1.	Use vestPosition.tickUpper instead of mainPosition.tickUpper in collectFees.
2.	Validate the position before calling burn(0) to prevent invalid tick references.
