# `secondaryPosition`'s `tickLower` can be equal or larger than `tickUpper`

### Summary

`secondaryPosition`'s `tickLower` can be equal or larger than `tickUpper` due to the fault logic of `_setSecondaryPositionsTicks`.
This leads to the revert of `rebalance` and `compound` function.

### Root Cause

In case of `bal0in1 >= bal1`, `secondaryPosition.tickLower` is set to [`tick - modulo + tickSpacing`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L377).


 `tick` can be lower than 0 and the initial `positionWidth` is [`4 * tickSpacing`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L102).

In case of `tick < 0 && positionWidth = 4 * tickSpacing && bal0in1 >= bal1`, `secondaryPosition.tickLower = secondaryPosition.tickUpper`.

If positionWidth = 2 * tickSpacing, `secondaryPosition.tickLower` will be larger than `secondaryPosition.tickUpper`.

The main root cause is that `_setSecondaryPositionsTicks` function doens't consider the case where `tick` is less than 0.

### Internal Pre-conditions

`positionWidth = 4 * tickSpacing` and bal0in1 >= bal1

### External Pre-conditions

UniswapV3Pool's tick < 0

### Attack Path

Scenario1:
1. When strategy is constructed with `positionWidth = uint24(4 * tickSpacing)`.
2. At that time, `UniswapV3Pool.slot0` is less than 0.
3. `_setSecondaryPositionsTicks` function sets `secondaryPosition` of `secondaryPosition.tickLower = secondaryPosition.tickUpper`.
4. Any call of `compound` function reverts and `collectFees` function doesn't works until change of `PositionWidth` or change of `UniswapV3Pool.slot0`.
5. `idleBalances` of `Strategy` contract may not be used effectively with `collectFees` function.
6. This may lead to the liquidation of the leverage position `Leverager` contract.
Scenario2:
1. Owner calls `rebalance` function when  `UniswapV3Pool.slot0` is less than 0.
2. `rebalance` function reverts.

Owner can eliminate the error by increasing `PositionWidth`. However, in order to call the `rebalance` function again, it must wait for the `rebalanceInterval` period. During `rebalanceInterval` period, position liquidation may occur which is time-sensitive.

In fact, there is a certain purpose and meaning to setting `PositionWidth`, so changing `PositionWidth` to eliminate the error is an inevitable method.
In short, the root cause of this issue is not because `positionWidth` is set to `4 * tickSpacing`, but because it did not consider the case where `tick` becomes smaller than 0.

### Impact

`rebalance` and `compound` function reverts and `idleBalances` of `Strategy` contract may not be used effectively with `collectFees` function.
This may lead to the liquidation of the leverage position in `Leverager` contract.

In the `_setSecondaryPositionsTicks` function, consider the case where `tick` becomes less than 0, as in `_setMainTicks`.
