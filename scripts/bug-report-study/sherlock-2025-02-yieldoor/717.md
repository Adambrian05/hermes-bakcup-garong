# Wrong calculation of `borrowedValue` will make liquidator able not to pay protocol fee or make liquidation itself impossible

### Summary

Wrong calculation of `borrowedValue` will make liquidator able not to pay protocol fee as it's calculate `borrowedValue` bigger than it's real value or liquidation itself might be impossible because of overflow issue

It should be `uint256 borrowedValue = owedAmount * bPrice / (10 ** ERC20(up.denomination).decimals());` or something like that, not `uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();`

### Root Cause

Wrong calculation of `borrowedValue`.
[https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L318-L332](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L318-L332)



### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Try to liquidate a liquidatable position that `owedAmount * bPrice / ERC20(up.denomination).decimals()` can cause overflow.
2. Try to liquidate a liquidatable position that `owedAmount * bPrice / ERC20(up.denomination).decimals()` don't cause overflow problem and it can be `owedAmount * bPrice / ERC20(up.denomination).decimals() >= totalValueUSD`  without paying fees to protocal

### Impact

1. It would make the liquidatable(`isLiquidateable = true`) positions that meets the overflow condition unliquidatable as `liquidatePosition` can't be executed.
2. It would provide liquidators the opportunity that can liquidate some positions without paying protocal fee.

### PoC

_No response_

### Mitigation

Replace

```solidity
uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();
```

With

```solidity
uint256 borrowedValue = owedAmount * bPrice / (10 ** ERC20(up.denomination).decimals());
```

Or(further consideration for overflow)
```solidity
uint256 borrowedValue = owedAmount / (10 ** ERC20(up.denomination).decimals()) * bPrice ;
```
