# Attacker Can Steal Fees from Vesting Position by Exploiting Incorrect Price Range in Strategy.sol

### Summary

The `collectFees()` function in the `Strategy.sol` contract incorrectly uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper` when collecting fees for the vesting position, potentially leading to incorrect fee calculations and unfair fee distribution.

### Root Cause

The root cause is a error in the `collectFees()` function where the wrong tick upper bound is used: the fee for `vestingPosition` is incorrectly calculated using the price cap of the main position ( `mainPosition.tickUpper` ) instead of the price cap of the vesting position itself ( `vestPosition.tickUpper` ).

[yieldoor/src/Strategy.sol:collectFees#L167](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L167)
```solidity
function collectFees() public {
...
if (ongoingVestingPosition) {
    collectPositionFees(
        vestPosition.tickLower,
        mainPosition.tickUpper  // @audit Using wrong upper tick
    );
}
```

### Internal Pre-conditions

1. `ongoingVestingPosition` must be true
2. A vesting position must exist with valid `vestPosition.tickUpper`

### External Pre-conditions

1. The Uniswap V3 pool must have accumulated fees within the affected price range
2. Price movements must have occurred between `vestPosition.tickLower` and `vestPosition.tickUpper`

### Attack Path

1. Monitor for situations where `mainPosition.tickUpper` ≠ `vestPosition.tickUpper`
2. When fees accumulate in the gap between these ticks, this error causes fee collection to use wrong price range, leading to uncollectable fees and incorrect fee attribution.

```solidity
// Example scenario
vestPosition.tickLower = 0
vestPosition.tickUpper = 1000
mainPosition.tickLower = 0
mainPosition.tickUpper = 800

// bugs
collectPositionFees(
    vestPosition.tickLower,    // 0
    mainPosition.tickUpper     // Using 800 instead of 1000
);

// Fees in range 800-1000 will be:
1) Fees lost if they belong to vestPosition
2) Results in lost revenue for vesting position holders
```

### Impact

1. Incorrect fee collection to use wrong price range, leading to uncollectable fees and incorrect fee attribution.
2. Incorrect protocol fee collection
3. This is not an active attack, but rather a error that results in financial loss. Partial returns are lost due to the use of incorrect price range.

- The original code misses some fees
- The fix allows for proper fee collection

### Mitigation

It is recommended to use correct upper tick `vestPosition.tickUpper` instead of `mainPosition.tickUpper` to ensure accurate fee collection and fair distribution of rewards.

```solidity
if (ongoingVestingPosition) {
    collectPositionFees(
        vestPosition.tickLower,
-       mainPosition.tickUpper
+       vestPosition.tickUpper  // @audit Use correct upper tick
    );
}
```
