# Short TWAP duration makes protocol vulnerable to price manipulation

### Summary

The Yieldoor protocol implements a TWAP oracle with a 5-minute window (300 seconds) in its Strategy contract, which falls well below the industry standard of 30 minutes (1800 seconds). This shortened timeframe substantially increases the risk of price manipulation attacks, as it requires less capital and coordination to influence prices over a 5-minute period versus 30 minutes. This vulnerability affects core protocol functions including position management, liquidations, and rebalancing operations.

### Root Cause

The vulnerability stems from the hardcoded TWAP duration in the Strategy contract's constructor:

```solidity
constructor(address uniPool, address _vault, address _rebalancer, address _feeRecipient) Ownable(msg.sender) {
    token0 = IUniswapV3Pool(uniPool).token0();
    token1 = IUniswapV3Pool(uniPool).token1();
    pool = uniPool;
    vault = _vault;
    IERC20(token0).forceApprove(_vault, type(uint256).max);
    IERC20(token1).forceApprove(_vault, type(uint256).max);
    rebalancer = _rebalancer;
    tickSpacing = IUniswapV3Pool(pool).tickSpacing();
    twap = 300; // 5 minutes
    tickTwapDeviation = 200; // ~2%
    positionWidth = uint24(4 * tickSpacing);
    // ...
}
```

While the protocol does include a function to update this value, it only enforces a minimum of 30 seconds:

```solidity
function setTwap(uint32 _twap) external onlyOwner {
    require(_twap > 30, "twap has to be at least 30 seconds");
    twap = _twap;
}
```

### Internal Pre-conditions

- The Strategy contract is deployed with `twap = 300` (5 minutes)
- This TWAP value is used throughout the protocol in critical price checks:
  - In `twapTick()` and `twapPrice()` functions
  - Within `_priceWithinRange()` to determine if operations can proceed
  - For calculating collateral values and liquidation thresholds

### External Pre-conditions

- A Uniswap V3 pool with moderate liquidity that can be influenced by large trades
- A sophisticated attacker with sufficient capital to influence pool prices over several minutes
- No additional safeguards or secondary price sources to validate the TWAP values

### Attack Path

1. Attacker conducts market analysis to identify a Uniswap V3 pool used by Yieldoor with manageable liquidity

2. Attacker calculates the capital required to manipulate the TWAP over a 5-minute window (substantially less than would be needed for a 30-minute TWAP)

3. Attacker initiates multiple trades over several blocks to push the price in their desired direction

4. Once the TWAP has moved sufficiently, the attacker exploits the manipulated price by:

   - Opening a leveraged position at an artificially advantageous price
   - Preventing their own position from being liquidated by manipulating the TWAP upward
   - Triggering unfair liquidations of other users' positions by manipulating the TWAP downward
   - Exploiting price discrepancies during vault deposits or withdrawals

5. After achieving their objective, the attacker unwinds their position and allows the price to normalize

### Impact


This vulnerability creates multiple risks for the protocol:

1. Reduced Manipulation Cost: The 5-minute window significantly lowers the capital threshold required to influence the TWAP compared to a 30-minute window

2. Unfair Liquidations: Users could have their positions liquidated based on short-term price movements rather than genuine market trends

3. Unfair Value Extraction: Attackers can open positions at favorable prices or avoid liquidation when they should be liquidated

4. Protocol Instability: Excessive manipulation could lead to undercollateralized positions and bad debt

5. Reduced Time for Intervention: The shorter window gives users and protocol guardians less time to react to manipulation attempts

### Mitigation

I recommend implementing the following changes:

1. Increase the Default TWAP Duration:

```diff
- twap = 300; // 5 minutes
+ twap = 1800; // 30 minutes
```

2. Enforce a Minimum TWAP Duration in the Setter Function:

```diff
function setTwap(uint32 _twap) external onlyOwner {
-    require(_twap > 30, "twap has to be at least 30 seconds");
+    require(_twap >= 1800, "twap has to be at least 30 minutes");
    twap = _twap;
}
```
