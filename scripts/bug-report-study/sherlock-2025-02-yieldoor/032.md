# Leverager.sol : Precision Loss Due to Division Before Multiplication in _calculateTokenValues Function"

### Summary

Performing division before multiplication in Solidity calculations will cause precision loss for protocol users and lenders as the smart contract will incorrectly calculate position values, potentially leading to wrongful liquidations or financial inaccuracies.

### Root Cause

In Leverager.sol, the calculation of position values and liquidation thresholds performs division before multiplication, leading to precision loss.

This mistake results in incorrect position valuations, potentially causing erroneous liquidations and mispriced assets within the protocol.

### Internal Pre-conditions

1. The smart contract needs to perform division before multiplication to set computed position values to be lower than the actual correct values due to truncation.
2. A user's position value needs to fall within a range where the incorrect calculation pushes it below the liquidation threshold.
3. The protocol needs to use the incorrectly computed position value to determine whether a position is liquidatable.
4. A liquidation event needs to occur based on the miscalculated position value, leading to wrongful liquidations.

### External Pre-conditions

1. Market price fluctuations need to occur, affecting collateral values and triggering position evaluations.
2. An external price oracle needs to provide updated asset prices that interact with the flawed liquidation logic.
3. A liquidation bot or keeper needs to initiate a liquidation based on the incorrect position valuation.
4. Network conditions (e.g., gas fees, mempool congestion) need to allow the liquidation transaction to be executed successfully.

### Attack Path

1. A borrower opens a leveraged position by depositing collateral and borrowing assets.
2. The smart contract computes the position value using division before multiplication, leading to truncation errors and an incorrect (lower) position valuation.
3. An external price oracle updates asset prices, triggering a re-evaluation of the position.
4. The smart contract checks the position’s health based on the flawed calculation and incorrectly determines that it is below the liquidation threshold.
5. A liquidation bot or keeper calls the liquidate() function, assuming the position is undercollateralized.
6. The borrower’s position gets liquidated even though, under correct calculations, it should not have been.
7. The liquidator profits from the wrongful liquidation, while the borrower unfairly loses assets due to the precision loss.

### Impact

The borrowers suffer an approximate loss of their entire liquidated position due to wrongful liquidations caused by precision loss.

The liquidators gain the liquidated collateral at a discounted price, profiting from the incorrect calculation.

The protocol may suffer reputation damage and potential financial losses if wrongful liquidations deter users from using the platform.

### Mitigation

he vulnerability should be mitigated by reordering the operations to perform all multiplications before divisions:

// Before (vulnerable)
usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;

// After (fixed)
usdValue += amount1 * PRECISION * chPrice0 / (price * decimals0);
