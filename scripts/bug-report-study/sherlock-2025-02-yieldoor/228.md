# Arithmetic Underflow in borrowedAmount Calculation

## Summary
An arithmetic underflow in `Leverager.sol`’s `openLeveragedPosition` function occurs when calculating `borrowedAmount`, causing transactions to revert. Triggered when the denomination token balance exceeds the borrow amount, this bug disrupts leveraged position creation with realistic inputs.


## Vulnerability Details
```solidity
uint256 denomBalance = IERC20(lp.denomination).balanceOf(address(this));
ILendingPool(lendingPool).repay(lp.denomination, denomBalance);
up.borrowedAmount = lp.maxBorrowAmount - denomBalance;
```
The `denomBalance` represents the total balance of the denomination token (e.g., WBTC) in the `Leverager` contract after borrowing from the `LendingPool` and depositing assets into the Vault.

This balance includes the user-supplied amount (`amount0In` or `amount1In`, if the denomination matches `token0` or `token1`) and the borrowed amount (`maxBorrowAmount`).

If `denomBalance` exceeds `maxBorrowAmount` (due to additional user-supplied tokens), the subtraction `lp.maxBorrowAmount` - `denomBalance` results in a negative value. Since `up.borrowedAmount` is a uint256, this causes an underflow, reverting the transaction with Panic(0x11) (arithmetic underflow/overflow).

Lack of validation or adjustment to ensure `denomBalance` <= `maxBorrowAmount` before performing the subtraction.

The user supplies a non-zero amount of the denomination token (amount0In or amount1In) in addition to borrowing maxBorrowAmount.

Example: If amount0In = 0.1 WBTC and maxBorrowAmount = 10 WBTC, then denomBalance = 10.1 WBTC, leading to 10 - 10.1 = underflow.

## Proof of Concept (POC)
Below is the PoC integrated into the LeveragerTest.t.sol file, demonstrating the vulnerability with realistic token amounts (0.1 WBTC and 10 WBTC).
```solidity
    function test_underflowInBorrowedAmountCalculation() public {
        vm.startPrank(depositor);

        deal(address(wbtc), depositor, 0.1e8); // 0.1 WBTC
        deal(address(usdc), depositor, 100e6); // 100 USDC
        wbtc.approve(leverager, type(uint256).max);
        usdc.approve(leverager, type(uint256).max);

        // Create LeverageParams with small amount
        ILeverager.LeverageParams memory lp;
        lp.amount0In = 0.1e8; // 0.1 WBTC
        lp.amount1In = 100e6; // 100 USDC
        lp.vault0In = 0.1e8; // 0.1 WBTC deposit to Vault
        lp.vault1In = 100e6; // 100 USDC  deposit to Vault
        lp.vault = vault;
        lp.maxBorrowAmount = 10e8; // 10 WBTC borrow from LendingPool 
        lp.denomination = address(wbtc);
        lp.min0in = 0;
        lp.min1in = 0;
        lp.swapParams1 = ""; 
        lp.swapParams2 = "";

        // Call openLeveragedPosition 
        vm.expectRevert(abi.encodeWithSignature("Panic(uint256)", 0x11));
        ILeverager(leverager).openLeveragedPosition(lp);
    }
```

## Recommendations

Limit repayment to maxBorrowAmount and refund excess:

```solidity
uint256 denomBalance = IERC20(lp.denomination).balanceOf(address(this));
uint256 repayAmount = denomBalance > lp.maxBorrowAmount ? lp.maxBorrowAmount : denomBalance;
ILendingPool(lendingPool).repay(lp.denomination, repayAmount);
up.borrowedAmount = lp.maxBorrowAmount - repayAmount;
```
