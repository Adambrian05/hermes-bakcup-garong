# Incorrect Token Deduction in Withdrawal (Logical Error)

### Summary

In the withdraw function, when the borrowed token is token1, the code incorrectly uses amountOut0 instead of amountOut1 to calculate the repayment from the withdrawal. This logical error leads to an incorrect deduction of tokens.


-> https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232

### Root Cause

The mistake is in the conditional block for handling token1 repayment. Instead of using amountOut1 to determine how much can be repaid, the code mistakenly references amountOut0. This results in an inaccurate computation of the repayment amount.

### Internal Pre-conditions

-> The position’s borrowed token must be token1.

-> The withdrawal call must result in non-zero values for both amountOut0 and amountOut1.

### External Pre-conditions

-> The user must call the withdrawal function with parameters that trigger the else if (borrowed == up.token1) block.
->The external liquidity pool must provide non-symmetric amounts causing a difference between amountOut0 and amountOut1.

### Attack Path

-> A user initiates a withdrawal on a position where the borrowed token is token1.
-> The function enters the conditional block for token1 but uses amountOut0 to calculate the repayment.
-> The incorrect repayment amount is applied, causing either under-repayment or over-repayment.

### Impact

-> Under-repayment of Debt: The user’s debt may not be fully repaid, leaving the position undercollateralized.

-> Over-repayment: Alternatively, more tokens than necessary might be deducted, leading to an unintended loss of funds.

### Mitigation

Replace the incorrect line with :

```solidity 

uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;


```

This ensures that the repayment for positions borrowing token1 correctly uses the available amount from token1.
