# Users can withdraw when they are liquidator can also grief the liquidator by withdrawing partially

### Summary

Users can still make partial or full withdrawals even when they're liquidatable. Since liquidators might need to know the exact amount to repay—especially if liquidation involves a swap—their transaction could revert if the user withdraws partially before them. This could be repeated until the withdrawable amount is tiny or the position turns into full bad debt, making liquidation unappealing.

### Root Cause

If the liquidation requires a swap, the liquidator calculates the required swap amount beforehand and prepares the Uniswap V3 swap struct. But if the user makes a small withdrawal right before the liquidation, the liquidator's transaction will revert since the amounts have changed.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L346-L367

### Internal Pre-conditions

1. User is liquidatable

### External Pre-conditions

1. User can perform a frontrun attack to liquidator

### Attack Path

1. Liquidator prepares the liquidation transaction that requires a swap
2. Just before the liquidation user withdraws, changing the amounts that his position has
3. Liquidation tx will revert due to insufficient balance on swapping

### Impact

Liquidations will be delayed and frustrated liquidators can give up liquidation the griefing account leading to bad debt.

### Mitigation

Do not allow partial withdrawals when the position is liquidatable
