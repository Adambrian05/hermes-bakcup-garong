# Secondary Position Might Not Always Be "Out-of-Range", Potentially Leading to Strategy Risks

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L366
Secondary Position Might Not Always Be "Out-of-Range", Potentially Leading to Strategy Risks

The contract's documentation says:

/// @notice The Secondary position
/// @dev Upon rebalancing, this position is always Out-Of-Range ...
However, _setSecondaryPositionsTicks(tick) doesn't strictly ensure the secondary position remains out-of-range:

function _setSecondaryPositionsTicks(int24 tick) internal {
    int24 modulo = tick % tickSpacing;
    uint256 bal0 = IERC20(token0).balanceOf(address(this));
    uint256 bal1 = IERC20(token1).balanceOf(address(this));
    uint256 _price = price();
    uint256 bal0in1 = bal0 * _price / PRECISION;

    if (bal0in1 < bal1) {
        secondaryPosition.tickLower = mainPosition.tickLower;
        secondaryPosition.tickUpper = tick - modulo;
    } else {
        secondaryPosition.tickLower = tick - modulo + tickSpacing;
        secondaryPosition.tickUpper = mainPosition.tickUpper;
    }
}
(a) How Could This be Exploited?

Manipulate balances or prices to bring the secondary position in-range:
An attacker could deposit tokens into the contract or briefly manipulate token balances or prices (via flash loans) to influence the bal0in1 < bal1 condition.
As a result, the secondary position, intended as a strictly out-of-range holding, could end up providing liquidity in-range, exposing the contract to impermanent loss or arbitrage scenarios.
Partial overlap with the main position:
Since secondary positions reuse main position ticks (mainPosition.tickLower, etc.), it's possible to force partial overlap.
An attacker could trigger this situation near the edges of the main position, expanding the strategy’s exposure and increasing potential impermanent loss.
(b) Potential Real-World Impact

Unexpected impermanent loss:
The strategy's original intent is typically for the secondary position to hold a single asset safely out-of-range. If instead it enters the price range, impermanent loss risks emerge.
Mismanaged asset allocation:
If the team assumes certain funds are single-asset, safe holdings, but these funds suddenly provide liquidity, strategy performance diverges significantly from expectations.
Complex reporting and tracking:
Overlapping positions complicate accurate reporting of liquidity, profits, losses, and withdrawal calculations.
(c) How to Mitigate?

If the intent is truly for the secondary position to always remain fully out-of-range:
Explicitly offset the secondary ticks far from the current market price or main position's boundaries.
For example, define secondary position bounds significantly above or below the current tick.
If occasional overlap is acceptable:
Update documentation clearly stating the possibility of partial overlap, and clarify conditions under which this occurs.
Assess and communicate any additional risks clearly.
