# [M-1] - Vesting fee collection tick range mismatch leads to overcharging protocol fees

### Summary

When collecting fees, the `Strategy` contract mistakenly uses the main position’s current upper tick (`mainPosition.tickUpper`) instead of the vesting position’s fixed upper tick (`vestPosition.tickUpper`) for [fee collection](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167). Since vesting positions are created with their tick range set to the main position’s tick range values at creation time, any subsequent rebalances that adjust the main position’s upper tick will cause a discrepancy. The fee collection for an ongoing vesting position will then be computed over a wider (or different) tick range than intended.

### Root Cause

During fee collection, the `Strategy::collectFees` function contains the following code for ongoing vesting positions:

```javascript
    function collectFees() public {
//..
//..
//@audit uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper`.
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
        }
//..
//..
    }
```

Because the vesting position’s `tickUpper` was set at creation time to be equal to the main position’s tickUpper at that time and does not update with later rebalances, using `mainPosition.tickUpper` instead of `vestPosition.tickUpper` leads to a mismatch in the range used to collect fees.

```javascript
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
//..
//..
        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;
//..
//..
    }
```

This means that fees will only be charged correctly until the first `rebalance`. After the first rebalance of the `Strategy`, when `_setMainTicks()` is called inside the `rebalance()` function, the `mainPosition.tickUpper` ticks will likely be misaligned and subsequent calls to the `compound`, `collectFees` and `rebalance` functions will overcharge fees.

### Attack Path

This will happen under normal usage of the protocol.

### Impact

In a typical scenario, this mismatch leads to fees being overcharged relative to the vesting position’s actual liquidity range. For example, if the vesting position was set over a 100‑tick range, it should accrue fees corresponding to that range. However, if the main position’s tick upper moves upward (say, by 20 ticks) after a rebalance, the fee collection will compute fees over 120 ticks instead of 100. Over time, this systematic overcharging of fees will reduce the returns of vesting depositors and send more fees than intended to the protocol.

- Loss of funds for users due to overcharged fees
- Protocol receives more fees than intended
- After the first `rebalance()` calling `collectFees`, `compound` and `rebalance()` will overcharge fees.
- Strategy's performance will be systematically affected

### PoC

Let's look at a numerical example.

**At Creation (T0):**

- A vesting position is created with liquidity over a tick range of [100, 200] (i.e. 100 ticks wide) with 1,000 liquidity units.
- Assuming a fee accrual rate of 1 fee unit per tick, the expected fees are 100 fee units.


**After a Rebalance (T1):**

- A rebalance causes the main position’s tickUpper to go upward to 220, while the vesting position’s tick range remains [100, 200].
During fee collection, the contract calls:

```javascript
collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
```
- This computes fees over the range [100, 220] (120 ticks) instead of the vesting position’s actual 100 ticks, resulting in an extra 20 fee units being charged and collected by the `feeRecipient`.

**Over Multiple Rebalances (T2, T3, … Tn):**

- Repeated discrepancies would accumulate, leading to a systematic misallocation of fees away from the vesting depositors and toward the protocol.

### Mitigation

Modify the fee collection logic to use the vesting position’s fixed upper tick.

```diff
    function collectFees() public {
//..
        if (ongoingVestingPosition) {
-           collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+           collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
        }
//..
    }
```
