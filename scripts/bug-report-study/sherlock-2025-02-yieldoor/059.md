# Zero Value Calculation Due to Missing Price Feeds Will Cause Position Opening Failure for Users in the `_calculateTokenValues` Function of `Leverager.sol` Contract

### Summary

In the `_calculateTokenValues` function, the absence of both price feeds can lead to incorrect price calculations, returning 0 as the asset value instead of reverting. This could potentially cause severe issues in asset valuation and liquidation processes in the `openLeveragedPosition` function.

### Root Cause

The function attempts to calculate USD values using price feeds but fails to properly validate the presence of at least one valid price feed before performing calculations. When both price feeds are missing, it silently proceeds with calculations using zero values.

[yieldoor/src/Leverager.sol:_calculateTokenValues#L444-L445](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L444C1-L445C78)
```solidity
    /// @dev Requires at least one of them to have set a trustworthy pricefeed.
    function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
{
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();
    if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
        chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
        usdValue += (amount0 * chPrice0) / decimals0;
    	}
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }
    
    // @audit When no price feed exists for token0 & token1
    if (chPrice0 == 0) {
        // @audit Uses chPrice1 which is also 0 when token1 has no price feed
        usdValue += (((amount0 * price) / PRECISION) * chPrice1) / decimals1;
    }else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
    }

    return usdValue;
}
```

### Internal Pre-conditions

1. Function is called with valid token addresses
2. Both tokens are registered in the system
3. Caller has necessary permissions to access the function

### External Pre-conditions

1. Both token0 and token1 have no price feeds configured
2. The system is in a state where price calculation is needed (e.g., opening position, liquidation check)

### Attack Path

1. System state:
   ```solidity
   - token0: no price feed
   - token1: no price feed
   ```

2. Execution flow:
   ```solidity
   // Both conditions fail
   if (IPriceFeed(pricefeed).hasPriceFeed(token0)) { ... }
   if (IPriceFeed(pricefeed).hasPriceFeed(token1)) { ... }
   
   // Variables remain at default values
   chPrice0 = 0
   chPrice1 = 0
   
   // Enters this condition
   if (chPrice0 == 0) {
       // Calculates: amount0 * price * 0 / PRECISION / decimals1 = 0
       usdValue += (((amount0 * price) / PRECISION) * chPrice1) / decimals1;
   }
   ```

3. Result:
   - Returns 0 as the USD value
   - No revert or error indication

### Impact

In the `openLeveragedPosition` function, when attempting to open a leveraged position with tokens that lack price feeds: 
1.The `_calculateTokenValues` function returns 0, leading to `up.initCollateralUsd` and `up.initCollateralValue` both being set to 0. 
2.However, the position creation doesn't fail immediately at these value assignments. Instead, the transaction will revert at the subsequent `require(!isLiquidateable(_id))` check, as a position with zero collateral value would be immediately liquidatable. 
3.This security check effectively prevents the creation of positions with invalid (zero) collateral values, providing a critical safety mechanism in the protocol.

### Mitigation

It is recommended to add explicit validation to ensure proper price validation and error handling.
