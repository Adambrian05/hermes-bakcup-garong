# LendingPool::setBorrowingRateConfig does not update the borrowingIndex and currentBorrowingRate

### Summary

 The missing calls to `updateState` and `updateInterestRates` from `LendingPool::setBorrowingRateConfig` will result to the update to not having an immediate effect on the `borrowingIndex` and `currentBorrowingRate`.

### Root Cause

```solidity
    function setBorrowingRateConfig(
        DataTypes.ReserveData storage reserve,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) internal {
        // (0%, 0%) -> (utilizationA, borrowingRateA) -> (utilizationB, borrowingRateB) -> (100%, maxBorrowingRate)
        reserve.borrowingRateConfig.utilizationA = PRECISION * utilizationA / 10_000;

        reserve.borrowingRateConfig.borrowingRateA = PRECISION * borrowingRateA / 10_000;

        reserve.borrowingRateConfig.utilizationB = PRECISION * utilizationB / 10_000;

        reserve.borrowingRateConfig.borrowingRateB = PRECISION * borrowingRateB / 10_000;

        reserve.borrowingRateConfig.maxBorrowingRate = PRECISION * maxBorrowingRate / 10_000;
    }
```
```solidity
    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    }
```
The calling flow of changing borrowing rate config is:
setBorrowingRateConfig(public) → setBorrowingRateConfig(internal)
The owner changed borrowing rate config, but the new config cannot take effect immediately.

### Internal Pre-conditions

1. Owner call `setBorrowingRateConfig`.

### External Pre-conditions

N/A

### Attack Path

 1. Owner call `initReserve`. A specific `borrowingRateConfig` was set.
 2. After some time, owner wants to update this `borrowingRateConfig` and calls `setBorrowingRateConfig`.
 3. However, this new `borrowingRateConfig` won't actually take effect until an deposit/redeem/borrow/repay action on
 the LendingPool being performed.

### Impact

 The impact of this vulnerability is that the protocol will actually have not control of when the new borrowingRateConfig will be actually activated.

### PoC

_No response_

### Mitigation

Consider calling `updateState` before the change of the configuration and `updateInterestRates` after the change of the configuration during the `setBorrowingRateConfig` call.
Refer to Extra Finance: https://github.com/ExtraFi/extra-contracts/blob/a66e925d78ee5c990eb2bafa5009cebcbeafe42d/contracts/lendingpool/LendingPool.sol#L527-L560.
