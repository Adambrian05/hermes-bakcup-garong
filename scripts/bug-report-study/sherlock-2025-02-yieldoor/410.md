# Secondary Position Not Guaranteed Out-Of-Range Post-Rebalance

### Summary

The documentation states that any leftover tokens after rebalancing are placed in a second Uniswap V3 position that is always out-of-range—ensuring single-sided exposure that avoids impermanent loss. However, the code places the secondary position’s tick boundaries very close to the current spot tick, often exactly at or near the current price. As a result:

A small price fluctuation can immediately bring the secondary position in-range.

Surplus tokens intended to be “idle” can become active liquidity, exposing them to impermanent loss and contradicting the stated design in the documentation.


This mismatch jeopardizes user expectations and can lead to unintended risk for depositors relying on the claimed “single-sided leftover” behavior.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L366 
The function _setSecondaryPositionsTicks calculates ticks for the secondary position by anchoring to the current tick (or a very tight offset). For example, if token1 is leftover, it sets:

secondaryPosition.tickLower = mainPosition.tickLower;
secondaryPosition.tickUpper = tick - modulo;

These boundaries can land exactly at or near the current spot price if modulo == 0 or if the tick is close to tick - modulo. The result is a position that can be partially or fully in-range with even a minor price movement.
 

### Internal Pre-conditions

The rebalance() procedure always updates the main position and calculates leftover tokens for the secondary position.

_setSecondaryPositionsTicks(tick) is called after the main position’s liquidity is minted.

The code uses the same tick from slot0 with minimal offset, without adding any buffer.


### External Pre-conditions

The rebalancer (an externally controlled process) triggers the rebalance() logic.

The Uniswap V3 pool’s spot tick can shift slightly at any time due to normal trading.

The leftover tokens can be substantial if the main position was forced to remain near 50:50.


### Attack Path

the mismatch can be exploited or triggered by normal market movements:

1. Rebalancer calls rebalance().


2. The secondary position is minted with boundaries at or near the current tick.


3. Minimal price movement (or slight arbitrage trades) pushes the spot tick inside the secondary range.


4. The leftover tokens, which should have been purely single-sided, become active liquidity—subjecting them to impermanent loss or partial swaps that contradict the design goals.


### Impact

Impermanent Loss: Tokens intended for low-risk storage incur standard Uniswap V3 impermanent loss if the price moves into their range.

### PoC

Consider a scenario where:

The current Uniswap V3 tick is exactly 10,000.

tickSpacing is 10.

We have leftover token1.


Code Calculation
```solidity 
int24 modulo = 10000 % 10 = 0;
secondaryPosition.tickLower = mainPosition.tickLower; // e.g., 9950
secondaryPosition.tickUpper = 10000 - 0 = 10000;
```
Here, `secondaryPosition.tickUpper` is exactly at the spot tick. The leftover token1 position is effectively pinned right at the current price boundary—meaning it’s not truly out-of-range. If the market ticks even slightly below 10,000, the leftover `token1` is fully or partially in-range, gets swapped, and experiences impermanent loss.

This violates the doc statement that leftover tokens are “always” out-of-rang
