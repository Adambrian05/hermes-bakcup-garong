# Miss bad debt process

### Summary

When the leverage position become unhealthy because of the token price's change and debt value is higher than position's value, liquidators may have no incentives to liquidate this position because there is not profit. Bad debt will be generated. But we do not have any ways to process these bad debt.

### Root Cause

In [Leverage.sol:299](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L299), liquidators will liquidate unhealthy positions to gain some profits.

Liquidators will help to repay all debt (in term of denomination) and get back this position's token0 and token1. If the borrow debt's value is larger than leverage position's value, the liquidator will not have the incentive to liquidate this positions. And some bad debt will be generated.

The problem is that we don't clear these bad debt. We can cover these bad debt by the protocol owner or let all lenders to cover this bad debt. But we don't process this part of bad debt. So when lenders want to redeem their token, lenders who redeem later will fail to redeem because of the bad debt. It means that the last several lenders will take the loss for all bad debt. This is very unfair.

```solidity
    function liquidatePosition(LiquidateParams calldata liqParams) external collectFees(liqParams.id) nonReentrant {
        IERC20(up.denomination).safeTransferFrom(msg.sender, address(this), owedAmount);
        ILendingPool(lendingPool).repay(up.denomination, repayAmount);
        if (amount0 > 0) IERC20(up.token0).safeTransfer(msg.sender, amount0);
        if (amount1 > 0) IERC20(up.token1).safeTransfer(msg.sender, amount1);
}
```

### Internal Pre-conditions

N/A

### External Pre-conditions

Token0/token1 price drops or denomination token price increases, the leverage position become unhealthy and generate some bad debt when the debt's value is higher than position's value.

### Attack Path

1. Alices leverage one position(token0/token1) via denomination token.
2. denomination token price increases or the token0/token1 price drops. Alice's position is unhealthy and nobody would like to liquidate this position because there is no profit for it.
3. There are two lenders in the lending pool.
4. Bob monitors the generated bad debt, redeem his denomination token. He can redeem successfully.
5. Cathy wants to redeem, Cathy's transaction will be reverted because of the bad debt.

### Impact

Some bad debt will be kept in the system. And the last several lenders will take the loss for all bad debt.

N/A

### Mitigation

Add one mechanism to process the possible bad debt. 
1. The protocol owner will cover all bad debt.
2. The bad debt can be covered by all lenders.
