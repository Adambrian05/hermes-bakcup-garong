# Spikes in the borrowing rate computation in the function calculateBorrowingRate in library

## Summary
Instead of smooth transition in the borrowing rates at the junctions of the utilisation range boundaries, spikes corresponding to the borrowing rate of the following range are seen in the function calculateBorrowingRate. 

## Root Cause
In the InterestRateUtils.sol, the function calculateBorrowingRate calculates the borrowingRate for the three regions of utilisation ranges viz. 0 to config.utilizationA, config.utilizationA to config.utilizationB and config.utilizationB to PRECISION. It uses piecewise linear model with a different interest rate formula for each utilisation range. However, the given codebase has sudden jump in the calculated Borrowing Rate at the junctions. For instance, when the config.utilizationA is ‘0’, the Borrowing Rate is given as config.borrowingRateA instead of ‘0’. 

The function must give smooth and linear borrowingRate. 
1.	For range 0 to config.utilizationA , the borrowing rate must vary from 0 to config.borrowingRateA linearly. This region will have slope1.
2.	For range config.utilizationA to config.utilizationB, the borrowing rate must vary from config.borrowingRateA to config.borrowingRateB. This region will have slope2.
3.	For range config.utilizationB to PRECISION (or 100%), the borrowing rate must vary from config.borrowingRateB to config.maxBorrowingRate. This region will have slope3.
4.	Utilisation rate may likely exceed 100% momentarily and this region too should be taken care of with fixed borrowing rate equal to config.maxBorrowingRate.

The function provides the above except for the junction of the utilisation ranges. 

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/libraries/InterestRateUtils.sol#L19-L44
```solidity
    function calculateBorrowingRate(DataTypes.InterestRateConfig storage config, uint256 utilizationRate)
        internal
        view
        returns (uint256 borrowingRate)
    {
        if (utilizationRate <= config.utilizationA) {
            if (config.utilizationA == 0) {
                return config.borrowingRateA;	//@audit   erroneous
            }
            borrowingRate = utilizationRate * config.borrowingRateA / config.utilizationA;
        } else if (utilizationRate <= config.utilizationB) {
            if (config.utilizationB == config.utilizationA) {
                return config.borrowingRateB; 	//@audit   erroneous
            }
            borrowingRate = (uint256(config.borrowingRateB) - config.borrowingRateA)
                * (utilizationRate - config.utilizationA) // (rateB - rateA) * (uR - uA) / (uB - uA) + bA
                / (config.utilizationB - config.utilizationA) + config.borrowingRateA;
        } else {
            if (config.utilizationB >= PRECISION) {	//@audit   erroneous
                return config.maxBorrowingRate; 	    //@audit   erroneous
            }
            borrowingRate = (uint256(config.maxBorrowingRate) - config.borrowingRateB)
                * (utilizationRate - config.utilizationB) / (PRECISION - config.utilizationB) + config.borrowingRateB;
        }
        return borrowingRate;
    }
```

## Impact
The borrowing rate is changing abruptly at the junction of the different ranges of the utilisation rates.

Consider the contract wants to have 
Case A:	only two utilisation ranges viz. utilizationA = 0, utilizationB and PRECISION implying the ranges are 0 to utilizationB, utilization to PRECISION.
Then, the borrowing rates will be
For range 1 
@ utilisation rate = 0, borrowingRateA
@ utilisation rate just above 0 will be borrowingRateA and will linearly increase to borrowingRateB @ utilisation rate = utilizationB.

For range 2, it starts with a peak of maxBorrowingRate, immediately dropping to borrowingRateB and then linearly increasing to maxBorrowingRate.

This shows there is not smooth transition in the borrowing rates at the junction of the utilisation ranges.

## Mitigation
Ensure the condition 
0 <= utilizationA <= utilizationB < = PRECISION (100%) is always met.
In order to have a proper piecewise smooth linear model without sudden changes in the borrowing rate, consider the modifications as shown:
