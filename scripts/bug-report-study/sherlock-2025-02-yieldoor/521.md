# First deposit can receive amount that is not deposited

### Summary

While a vault is created it is responsible for how `shares` are minted according to the balance and totalSupply, however, during first deposit, only  a check is conducted on which amount is greater, and the larger amount of `tokenA` or `tokenB` is minted to the `user` as `shares` this will later result to an issue, for when deposits continue, to flow in the contract, the `first depositor`, will receive both tokens even he deposited `$1000 usdc` and `1 WETH`,  he will receive both tokens `$1000` of `usdc` and `weth`. even if `owner` is the first to deposit has the ability to rug pull, where he gets a first big `discount`. 

### Root Cause

In `Vault.sol::_calcDeposit()`
```javascript
if (totalSupply == 0) {
            // For first deposit, just use the amounts desired
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000)
```
we see first depositor shares is equal to the larger amount of token between `token0` or `token1`.

### Internal Pre-conditions

1. Add `cooldown` function that allows users to deposit till a specific balance, is reached then mint shares to the new users, then start from there this will eliminate the big discount in the beginning

### External Pre-conditions

NA

### Attack Path

First Deposit:
1. `Owner` or `attacker` deposits, `10000 usdc` and `0.00001 weth`
2. Shares minted become `10000` shares
3. The protocol receives `deposits` and TVL becomes 30000 usd worth of asssets
4. `Attacker` or `owner` withdraws receiving both tokens 10000 usdc and 10000 worth of weth,

Loss of funds
