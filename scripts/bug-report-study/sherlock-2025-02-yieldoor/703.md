# Using 2 tokens without price feeds can cause wrong calculations in `Leverager`

### Summary

Inside `Leverager::_calculateTokenValues`, it is possible for both token0 and token1 not to have valid price feeds, despite what the dev notes say. This would cause the returned `usdValue` to be smaller, than it should be, as it would include only the converted `amount0` value.

The wrong return value of `_calculateTokenValues` would mess up the calculations whenever it is used in the `Leverager` contract - `liquidatePosition`, `isLiquidateable` and `openLeveragedPosition`

### Root Cause

In `Leverager.sohl:444` (https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L444), there is a missing clause which checks whether both `chPrice0` and `chPrice1` are equal to zero.  In that case, the code will enter the first if-branch and return a `usdValue` including only amount0:

```solidity
if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
}
```


### Internal Pre-conditions

None.

### External Pre-conditions

1. There should be a vault, in which both token0 and token1 have no price feed.

### Attack Path

1. User opens a leveraged position, in which both token0 and token1 have no price feed.
[optional] 2. Anyone calls `liquidatePosition()`

### Impact

Wrong calculations of the total USD value of the position or of its collateral amount. In the first case, this could lead to the position being liquidatable earlier than it should be. In the latter, the position will appear less collaterised than it actually is.
In both cases, the user's position can be liquidated earlier than it should be, which would mean a loss of funds for the user.
The likelihood is low, as both tokens need not to have a price feed.

### Mitigation

```diff
function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
    {
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }

+      require(chPrice0 !=0 || chPrice1 != 0, "Neither token has a price feed.");
        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }

        return usdValue;
    }
```
