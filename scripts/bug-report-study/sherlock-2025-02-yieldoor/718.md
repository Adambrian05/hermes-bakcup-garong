# Attacker will exploit incorrect borrowing rate at full utilization

### Summary

The `InterestRateUtils.sol` incorrectly calculates the borrowing rate when the utilization rate reaches 100%, allowing borrowers to pay a lower rate than intended.

### Root Cause

In [InterestRateUtils.sol: calculateBorrowingRate function](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/InterestRateUtils.sol?plain=1#L29-L38), when `utilizationRate `equals `utilizationB `(set to `PRECISION`), the borrowing rate is calculated using linear interpolation instead of `maxBorrowingRate`, undercharging borrowers.

### Internal Pre-conditions

1. The reserve's utilization rate is set to 100%.
2. The `utilizationB `in the reserve's configuration is set to `PRECISION `(100%).

### External Pre-conditions

None

### Attack Path

1. An attacker borrows from the lending pool when the utilization rate is at 100%.
2. The borrowing rate is calculated as the rate at `utilizationB `instead of `maxBorrowingRate`.
3. The attacker pays a lower interest rate than intended, gaining an advantage over other borrowers and the protocol.

### Impact

The protocol suffers from reduced interest income as borrowers pay less than the maximum intended rate, potentially destabilizing the reserve's financial health.

### PoC

_No response_

### Mitigation

Modify `calculateBorrowingRate `to return `maxBorrowingRate `when `utilizationRate >= utilizationB` and `utilizationB >= PRECISION`.
