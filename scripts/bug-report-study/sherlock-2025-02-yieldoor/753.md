# Incorrect `sqrtPrice` Retrieval from `slot0()`

### Summary

The function retrieves `sqrtPrice` from `slot0()` of a Uniswap V3 pool. However, if the pool address is incorrect, uninitialized, or manipulated, it may return an invalid sqrtPrice, leading to incorrect calculations and potential financial losses.

### Root Cause

 ``` solidity 
   function addVestingPosition(
        uint256 amount0,
        uint256 amount1,
        uint256 _vestDuration
    ) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(
            !ongoingVestingPosition,
            "there's a currently ongoing VestingPosition"
        );

        _requirePriceWithinRange();
        VestingPosition memory vp;

        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;

        // @auidts sqrtpricex96
>>        (uint160 sqrtPrice, , , , , , ) = IUniswapV3Pool(pool).slot0();
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPrice,
            TickMath.getSqrtRatioAtTick(vp.tickLower),
            TickMath.getSqrtRatioAtTick(vp.tickUpper),
            amount0,
            amount1
        );
```

### Internal Pre-conditions

{Contract} needs to retrieve {sqrtPrice} from {slot0()} on a misconfigured or uninitialized pool.

### External Pre-conditions

{A manipulated Uniswap V3 pool} returns an incorrect slot0().sqrtPrice, causing contracts that rely on it to miscalculate liquidity.

### Attack Path

{LiquidityAmounts.getLiquidityForAmounts()} computes incorrect liquidity values, leading to mispriced liquidity provisioning.
{Attacker} exploits the mispriced liquidity or swap rates, withdrawing excessive funds or executing arbitrage.

### Impact

Loss Estimate: Potential loss of funds due to incorrect liquidity or swap pricing, leading to financial inefficiencies or drained pools.
