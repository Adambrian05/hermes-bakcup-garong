# An Incorrect `base` Calculation in `Leverager.isLiquidateable()` Will Cause Bad Debts When It is Finally Liquidateable

### Summary

The incorrect calculation of base in `isLiquidateable()` will cause bad debts to pile up as the contract underestimates the initial collateral amount and prevents timely liquidations (when max Leverage is more than 2x), allowing positions to accrue debt beyond recoverable levels.

### Root Cause

In `isLiquidateable()`, `base` is first calculated as follows:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408

```solidity
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
```

However, according to the doc explanation:

> Liquidations explained: 
The regular flow is that whenever the user’s collateral drops below the `minCollateralPct`, they become liquidateable
However, in scenarios where the users are not using max leverage, this could cause unfair liquidations. Assume minPctCollateral is 10%. Consider the following scenario: max Leverage is 2x, user has opened a 1.25x and has since then lost 90% of their collateral, meaning that 0.1X collateral has remained and 0.25X still borrowed. We treat the borrowed amount as if it was opened at max leverage, which would make the initial collateral `0.25 * (2 - 1) = 0.25X`. Since minimum collateral pct is 10%, this would mean that the position will become liquidateable once collateral drops below `0.25 * 0.1 = 0.025X` 
To put it into a numerical example, user opens up a $1,250 position with $1,000 of collateral (1.25x leverage). User’s position would have to fall below $275 value ($250 borrowed, $25 collateral) in order to become liquidateable. 

It should instead be:

```solidity
        uint256 base = owedAmount * (vp.maxTimesLeverage - 1e18) / 1e18;
```
The incorrect formula underestimates the collateral required to remain above the liquidation threshold, preventing necessary liquidations and leading to bad debt accumulation.

If max leverage is 2x:

```solidity
// Incorrect Calculation
base = owedAmount * 1e18 / (2e18 - 1e18);
base = owedAmount * 1e18 / 1e18;
base = owedAmount;

// Correct Calculation
base = owedAmount * (2e18 - 1e18) / 1e18;
base = owedAmount * 1e18 / 1e18;
base = owedAmount;
```

The incorrect and correct formulas yield the same result, so there is no issue when max leverage is 2x since multiplying or dividing by 1 makes no difference algebraically.

However, if max leverage is, e.g. 5x:

```solidity
// Incorrect Calculation
base = owedAmount * 1e18 / (5e18 - 1e18);
base = owedAmount * 1e18 / 4e18;
base = owedAmount / 4;

// Correct Calculation
base = owedAmount * (5e18 - 1e18) / 1e18;
base = owedAmount * 4e18 / 1e18;
base = owedAmount * 4;
```
The incorrect formula underestimates base, making it 4 times smaller than it should be. This causes the liquidation condition to fail when it should trigger liquidation, leading to bad debt.

### Internal Pre-conditions

1. The user must have an active leveraged position in the Leverager contract whose net collateral has dropped below liquidation threshold.

2. The `maxTimesLeverage` parameter must be greater than 2x, making the incorrect calculation significant.

### External Pre-conditions

1. The lending pool must continue providing leverage.

2. The price feed must provide accurate asset prices.

3. The market must experience moderate volatility to justify an actual liquidation.

### Attack Path

1. A borrower opens a leveraged position with a leverage factor greater than 2x.

2. Due to market fluctuations, their collateral value drops below the correct liquidation threshold.

3. The incorrect formula in `isLiquidateable()` underestimates the initial collateral (base) where `owedAmount > totalDenom` still remains false, and sadly also makes `totalDenom - owedAmount < vp.minCollateralPct * base / 1e18` false.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411

```solidity
        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
```
4. The contract incorrectly determines that the position is not liquidateable.

5. The borrower’s collateral continues to decrease, eventually dropping below the borrowed amount.

6. The position now incurs bad debt when `owedAmount > totalDenom` eventually becomes true, as liquidation no longer recovers enough funds to repay the borrowed amount.

### Impact

The lending pool suffers bad debt as positions that should have been liquidated earlier remain open, accumulating losses. Eventually, the lenders absorbs the losses when liquidators cannot practically make any arbitraged profits.

### Mitigation
Consider making the following fix:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411

```diff
-                uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
+                uint256 base = owedAmount * (vp.maxTimesLeverage - 1e18) / 1e18;
```
