# Uninitialized Fee Recipient Address Causes Permanent Loss of Protocol Fees

## Summary
The `Leverager` contract collects protocol fees during liquidations but lacks a mechanism to initialize the [`feeRecipient` address](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L47). When liquidations occur, fees are sent to the zero address (the default value), resulting in permanent loss of protocol revenue. This oversight prevents the protocol from collecting any fees from successful liquidations.

## Vulnerability Details
The `Leverager` contract includes a `feeRecipient` state variable that should receive a portion of the profits when underwater positions are liquidated. However, this address is never initialized in the constructor or through a setter function.

When a position is liquidated with profit, the contract calculates a fee based on the profit percentage and the `liquidationFee` parameter:

```solidity
if (totalValueUSD > borrowedValue) {
    uint256 protocolFeePct = 1e18 * liquidationFee * (totalValueUSD - borrowedValue) / (totalValueUSD * 10_000);
    uint256 pf0 = protocolFeePct * amount0 / 1e18;
    uint256 pf1 = protocolFeePct * amount1 / 1e18;

    if (pf0 > 0) IERC20(up.token0).safeTransfer(feeRecipient, pf0);
    if (pf1 > 0) IERC20(up.token1).safeTransfer(feeRecipient, pf1);
    amount0 -= pf0;
    amount1 -= pf1;
}
```

Since `feeRecipient` remains at its default value of `address(0)`,[ all fees are sent to the zero address and permanently lost](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L328-L329). Unlike other critical parameters like `pricefeed` and `swapRouter`, there is no setter function for `feeRecipient`.

## Proof of Concept
1. The `feeRecipient` state variable is declared but never initialized:
```solidity
/// @notice The protocol fee recipient.
address public feeRecipient;
```

2. The contract has setter functions for other parameters but not for `feeRecipient`:
```solidity
function setPriceFeed(address _priceFeed) external onlyOwner {
    pricefeed = _priceFeed;
}

function setSwapRouter(address _swapRouter) external onlyOwner {
    swapRouter = _swapRouter;
}
```

3. During liquidation, fees are sent to the uninitialized `feeRecipient`:
```solidity
if (pf0 > 0) IERC20(up.token0).safeTransfer(feeRecipient, pf0);
if (pf1 > 0) IERC20(up.token1).safeTransfer(feeRecipient, pf1);
```

## Impact Details
All protocol fees from liquidations are permanently lost by being sent to the zero address. This represents a direct financial loss to the protocol, reducing its revenue stream and sustainability. The impact scales with the volume of liquidations and the size of the profits generated from them.

## Tools Used
Manual

## Recommendations
1. Add a setter function for the `feeRecipient` address:
```solidity
function setFeeRecipient(address _feeRecipient) external onlyOwner {
    require(_feeRecipient != address(0), "Fee recipient cannot be zero address");
    feeRecipient = _feeRecipient;
}
```

2. Initialize `feeRecipient` in the constructor:
```solidity
constructor(string memory name_, string memory symbol_, address _lendingPool, address _feeRecipient)
    Ownable(msg.sender)
    ERC721(name_, symbol_)
{
    require(_feeRecipient != address(0), "Fee recipient cannot be zero address");
    lendingPool = _lendingPool;
    feeRecipient = _feeRecipient;
}
```

3. Add a check in the `liquidatePosition` function to ensure fees aren't sent to the zero address:
```solidity
require(feeRecipient != address(0), "Fee recipient not set");
```
