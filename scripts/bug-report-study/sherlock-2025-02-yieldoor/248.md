# Leverager contract will mint tokens to non-ERC721-compliant addresses, impacting token holders

### Summary

The use of [ERC721’s _mint()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L68) instead of _safeMint() in the Leverager contract will cause tokens to be minted to addresses that do not support ERC721 tokens. This will result in tokens becoming locked and unusable for token holders, as the contract does not verify that the recipient can handle ERC721 tokens.

### Root Cause

- In **Leverager.sol:197** there is an unsafe minting call using _mint(msg.sender, _id) instead of _safeMint(msg.sender, _id). The absence of a safety check means that if msg.sender is a contract that does not implement the onERC721Received interface, the token may be locked permanently.

### Internal Pre-conditions

1. The Leverager contract calls _mint(msg.sender, _id) when opening a leveraged position.  
2. The caller (msg.sender) is an address that does not implement the ERC721Receiver interface.


### External Pre-conditions

1. An attacker or user deploys a contract that does not implement ERC721Receiver.  
2. The attacker or user uses this non-compliant contract to interact with the Leverager contract to open a leveraged position.


### Attack Path

1. The attacker deploys a contract that lacks the ERC721Receiver implementation.  
2. The attacker uses this contract as their msg.sender when calling the Leverager contract’s function that triggers _mint(msg.sender, _id).  
3. The Leverager contract mints the ERC721 token without performing a recipient safety check.  
4. Since the recipient contract does not implement onERC721Received, the token is locked in the non-compliant contract.


### Impact

Token holders (or users interacting via contracts) suffer the inability to manage or transfer their ERC721 tokens if minted to a non-compliant address. This results in a loss of utility, as the tokens can become permanently locked and inaccessible.


### PoC

```solidity
// Example PoC: Contract without ERC721Receiver implementation
contract NonERC721Receiver {
    // This contract intentionally does not implement onERC721Received
}

// Deploy the non-compliant contract
NonERC721Receiver nonReceiver = new NonERC721Receiver();

// Attacker uses nonReceiver's address to interact with the Leverager contract
// The Leverager contract calls _mint(nonReceiver, _id) without safety checks,
// resulting in the token being locked in nonReceiver, with no ability to transfer it.
```


### Mitigation

Implementing _safeMint() in place of _mint() in the Leverager contract is strongly recommended to enforce recipient safety checks and prevent tokens from being locked in non-ERC721-compliant addresses.
