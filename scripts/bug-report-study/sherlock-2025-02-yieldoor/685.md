# Incorrect Calculation of Precision in 'calculateLinearInterest'

In contract `InterestRateUtils.sol` there is a slight miss calculation for precision at function `calculateLinearInterest`  .  

Vulnerability Details:

If `rate` and `timeDifference` is small as compared to `SECONDS_PER_YEAR`  . 
the result of the division can be very small or even zero.
This is because the fractional part of the division result is truncated, leading to a loss of precision.

Solidity performs integer division, which means any fractional part of the result is truncated . 
`For example, 5 / 2 in Solidity would result in 2, not 2.5` .


https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/InterestRateUtils.sol#L57

```
 function calculateLinearInterest(uint256 rate, uint40 lastUpdateTimestamp) internal view returns (uint256) {
        //solium-disable-next-line
        uint256 timeDifference = block.timestamp - (uint256(lastUpdateTimestamp));

        return rate * (timeDifference) / (SECONDS_PER_YEAR) + PRECISION; // q uint256 interestFactor = (rate * timeDifference * PRECISION) / SECONDS_PER_YEAR + PRECISION;

    }

```
