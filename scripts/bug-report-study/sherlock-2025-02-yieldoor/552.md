# `minBorrow` Value is Excessively High

### Summary

In the `Leverager` contract, `minBorrow` represents the minimum limit for the user’s borrowed amount in USD. Currently, the default value for `minBorrow` is set to `20e18`, and it can be adjusted to any value greater than `1e18`. Given that the USD price has 8 decimal places, `20e18` equates to `$200 billion`, while `1e18` corresponds to `$10 billion`. Both of these amounts are excessively high.

### Root Cause

The default value for `minBorrow` is set to `20e18` (see [here](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L54)). Although the owner can modify this value, the new value must exceed `1e18` (see [here](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L553)).

```solidity
    /// @notice The minimum borrowed amount
@>  uint256 minBorrow = 20e18;

----------------------------------------

    function setMinBorrow(uint256 _minBorrow) external onlyOwner {
@>      require(_minBorrow > 1e18, "must be at least $1");
        minBorrow = _minBorrow;
    }
```

This `minBorrow` value sets the minimum limit for the user’s borrowed USD amount, which is derived from the Chainlink price feed. The Chainlink USD price feed returns a value with 8 decimal places. Therefore, `20e18` represents `$200 billion`, while `1e18` stands for `$10 billion`—both of which are excessively high.
