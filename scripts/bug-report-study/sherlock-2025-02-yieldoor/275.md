# Repayment could fail when withdrawals on leveraged positions are made with denomination token

### Summary

The use of `amountOut0` in place of `amountOut1` when taking from denomination token during withdrawals from leveraged position, could cause repayment to fail.

### Root Cause

On [L232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) of the `Leverage:withdraw()`.

The bug is that when amountOut1 < owedAmount is true (meaning token1 is insufficient to cover the debt), it incorrectly uses amountOut0 as the repayment amount. This is problematic because:

1. If token1 is the borrowed token (which needs to be repaid), and if amountOut1 is less than what we owe, we should NOT be using amountOut0 for repayment - we need to use the correct token type for repayment.

2. The logic should instead be checking which token is the borrowed token and use the corresponding amountOut value for that specific token.

Using the wrong amountOut value can lead to incorrect debt tracking and potentially insufficient repayment.

### Internal Pre-conditions

1. User opens a leveraged position

### External Pre-conditions

1. Always reverts for withdrawing with denomination token
   - If token1 == lp.denomination
   - and amountOut0 > amount1


### Attack Path

1. User can call to make incorrect repayment amount
    - If one repaid token is the denomination
    - amountOut0 < amountOut1

### Impact

1. Failed repayment transaction
2. Incorrect repayment amount

### PoC

```solidity
function testRepaymentLogicBug() public {
    // Setup: token1 is the borrowed token
    address borrowed = token1;
    
    // Scenario where amountOut0 > amountOut1
    uint256 amountOut0 = 1000;  // Large amount
    uint256 amountOut1 = 100;   // Small amount
    uint256 owedAmount = 500;   // Amount to repay
    
    // When borrowed == token1 and amountOut1 < owedAmount
    // The code will incorrectly use amountOut0 (1000) instead of amountOut1 (100)
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
    
    // 1. repayFromWithdraw will be 1000 (amountOut0) instead of 100 (amountOut1)
    // 2. We're trying to repay with more tokens than we actually have in amountOut1
    assertEq(repayFromWithdraw, 1000); // Will pass, showing the bug
    assert(repayFromWithdraw <= amountOut1); // Will fail, proving the bug
}
```

### Mitigation

```diff
++ uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
-- uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```
