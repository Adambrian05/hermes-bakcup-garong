# Attacker will extract value by exploiting interest rate accrual precision loss

## Summary
The binomial approximation error in the InterestRateUtils library will cause significant protocol insolvency over time as attackers will strategically time borrowing and repayment to exploit precision loss in interest calculations.

## Root Cause
In [InterestRateUtils.sol#L45-L65](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/InterestRateUtils.sol#L45-L65) the `calculateCompoundedInterest` function uses a binomial approximation for exponentiation that introduces significant precision loss:

```solidity
function calculateCompoundedInterest(uint256 rate, uint128 lastUpdateTimestamp, uint256 currentTimestamp)
    internal
    pure
    returns (uint256)
{
    uint256 exp = currentTimestamp - (uint256(lastUpdateTimestamp));

    if (exp == 0) {
        return PRECISION;
    }

    uint256 expMinusOne = exp - 1;
    uint256 expMinusTwo = exp > 2 ? exp - 2 : 0;

    uint256 ratePerSecond = rate / SECONDS_PER_YEAR;

    uint256 basePowerTwo = ratePerSecond * ratePerSecond / PRECISION;
    uint256 basePowerThree = basePowerTwo * ratePerSecond / PRECISION;

    uint256 secondTerm = exp * expMinusOne * basePowerTwo / 2;
    uint256 thirdTerm = exp * expMinusOne * expMinusTwo * basePowerThree / 6;

    return (PRECISION) + (ratePerSecond * exp) + (secondTerm) + (thirdTerm);
}
```

The issues are:
1. Using binomial approximation causes significant deviation from actual compound interest for longer time periods
2. Division by SECONDS_PER_YEAR before multiplication leads to precision loss
3. Insufficient precision handling in intermediate calculations

## Internal Pre-conditions
1. The protocol must have active lending pools with borrowed funds
2. The interest rate mechanism must use the vulnerable `calculateCompoundedInterest` function
3. The time period between interest rate updates must be long enough for precision errors to accumulate

## External Pre-conditions
1. Interest rates must be high enough for the precision error to become economically exploitable
2. Market conditions must allow for strategic borrowing and repayment

## Attack Path
1. Attacker identifies interest rate parameters that maximize precision errors in the calculation
2. Attacker deposits a significant amount of assets to a lending pool
3. Attacker or an accomplice borrows a large amount when the utilization rate causes a favorable interest rate calculation
4. Attacker waits until the interest accrual calculation error accumulates to a profitable amount
5. New users deposit funds during this high-interest period
6. Attacker repays the borrowed amount, lowering utilization and interest rates
7. Attacker withdraws their funds with more interest than they should have earned
8. Later users withdraw their funds and receive less than they should

## Impact
The protocol suffers from a gradual loss of capital as each exploitation extracts a small percentage of value. Over time and with larger pool sizes, this can lead to significant protocol insolvency. Users who deposit later will suffer disproportionate losses as the precision errors accumulate. The economic impact scales with interest rates, time periods, and pool sizes.

## Mitigation
Replace the binomial approximation with a more accurate compound interest formula:

```solidity
function calculateCompoundedInterest(uint256 rate, uint128 lastUpdateTimestamp) internal view returns (uint256) {
    uint256 timeDifference = block.timestamp - uint256(lastUpdateTimestamp);
    
    // Use the standard compound interest formula with fixed-point arithmetic
    // For small time differences, use a more precise linear approximation
    if (timeDifference < 1 days) {
        uint256 ratePerSecond = rate * PRECISION / SECONDS_PER_YEAR;
        return PRECISION + (ratePerSecond * timeDifference / PRECISION);
    }
    
    // For longer periods, use a more accurate compound interest calculation
    // using expanded logarithmic/exponential functions or a dedicated math library
    return exponentialFunction(rate, timeDifference);
}
```
