# Incorrect rounding of deposit amount values in the `Vault::_calcDeposit` function.

## Summary
The `else` condition in the `Vault::_calcDeposit` function does not round up the values of `amount0` and `amount1`.

## Bug Description

The comment above the calculation states that the following calculation should round up the value, but the calculation is incorrect and does not round up the value.

```solidity
 function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        .....
        .....
        } else {
            uint256 cross0 = depositAmount0 * bal1;
            uint256 cross1 = depositAmount1 * bal0;
            uint256 cross = cross0 > cross1 ? cross1 : cross0;
            require(cross > 0, "cross");

            // Round up amounts
 @>>           amount0 = (cross - 1) / bal1 + 1;
 @>>          amount1 = (cross - 1) / bal0 + 1;
            shares = cross * totalSupply / bal0 / bal1;
        }
    }
```

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L147

## Proof of code :- 

lets take an example :- 
```diff
cross = 75250
bal1 = 3500

amount0 = 75250 -1 / 3500 + 1 = 21.493.....   it will round to 21
now  , 75250 / 3500 = 21.5  it should be roundup to 22 not 21, thats why the calculation is incorrect.
                
```

## Impact :- 

contract may receive slightly fewer amount of token than expected in the deposit function.
May lead to discrepancies in accounting and fairness issues.

## Recommendation :- 
use the below given formula

```solidity
amount0 = (cross + bal1 - 1) / bal1;
amount1 = (cross + bal0 - 1) / bal0;
```
taking the same example as given in proof of code ;
amount0 = 75250 + 3500 -1 / 3500 = 22.4997..........
This will round up to 22.
