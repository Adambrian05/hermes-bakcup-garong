# Incorrect Borrowing Index Update in Partial Withdrawals Allows Users to Evade Interest Payments

## Summary
The `withdraw()` function[ incorrectly updates the `borrowedIndex`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L290) during partial withdrawals, allowing users to manipulate interest calculations by splitting their withdrawals into two transactions. This enables users to avoid paying most of their accrued interest, resulting in lost revenue for protocol lenders.

## Vulnerability Details
When users borrow tokens, interest accrues based on the time between the initial borrow (tracked by `borrowedIndex`) and the current time (current `bIndex`). The protocol calculates owed interest using:
```solidity
totalOwedAmount = up.borrowedAmount * currentBorrowIndex / position.borrowedIndex
```

The vulnerability exists in the `withdraw()` function where `borrowedIndex` is incorrectly updated during partial withdrawals:
```solidity
if (wp.pctWithdraw == 1e18) {
    // Full withdrawal logic
} else {
    positions[wp.id].borrowedAmount = totalOwedAmount - amountToRepay;
    positions[wp.id].borrowedIndex = bIndex;  // <-- Incorrect update
    positions[wp.id].shares -= sharesToWithdraw;
}
```

This update resets the interest calculation baseline, effectively treating the remaining borrowed amount as if it was just borrowed.

## Proof of Concept
1. User opens position borrowing 100 tokens
   - Initial `borrowedIndex` = 1000

2. After time passes:
   - Current `bIndex` = 1100 (10% interest accrued)
   - Expected interest = 100 * 1100/1000 - 100 = 10 tokens

3. User executes exploit:
   ```solidity
   // Transaction 1: Withdraw 1%
   withdraw({
       id: positionId,
       pctWithdraw: 0.01e18,  // 1%
       // other params...
   });
   // Pays correct interest on 1 token: 0.1 tokens
   // position.borrowedIndex updated to 1100
   
   // Transaction 2: Withdraw 99%
   withdraw({
       id: positionId,
       pctWithdraw: 0.99e18,  // 99%
       // other params...
   });
   // Almost no interest paid since borrowedIndex ≈ currentIndex
   ```

4. Result:
   - User pays ~0.1 tokens interest instead of 10 tokens
   - Protocol loses ~9.9 tokens of interest revenue

## Impact Details
This vulnerability allows borrowers to evade approximately 90-99% of their interest payments by splitting withdrawals into two transactions, with the first withdrawal being minimal. The direct impact is lost interest revenue for protocol lenders, undermining the economic incentives of the lending protocol.

## Tools Used
Manual Review

## Recommendations
Remove the `borrowedIndex` update in partial withdrawals:
```solidity
if (wp.pctWithdraw == 1e18) {
    // Full withdrawal logic
} else {
    positions[wp.id].borrowedAmount = totalOwedAmount - amountToRepay;
    // positions[wp.id].borrowedIndex = bIndex;  <-- Remove this line
    positions[wp.id].shares -= sharesToWithdraw;
}
```
This ensures interest calculations always use the original borrowing index from when the position was opened.
