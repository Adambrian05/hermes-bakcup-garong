# Attacker will reenter Strategy's collectFees function

### Summary

Lack of reentrancy protection in Strategy's collectFees will cause fund misappropriation for users as an attacker can reenter during external calls

### Root Cause

In [Strategy.sol: collectFees function](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol?plain=1#L159-L169), external calls to Uniswap V3 pool (`burn` and `collect`) are made without ReentrancyGuard, risking state changes during reentry.

### Internal Pre-conditions

The attacker has a contract that can be called by the Strategy during `collectFees`.

### External Pre-conditions

None, but the Uniswap V3 pool must be accessible.

### Attack Path

1. Attacker's contract is called during collectFees external calls.
2. Attacker reenters collectFees, altering balances before the function completes.
3. Funds are misappropriated due to state changes.

### Impact

Users suffer an approximate loss of funds during fee collection, with the attacker potentially gaining the misappropriated amount.

### PoC

_No response_

### Mitigation

Add `ReentrancyGuard `to Strategy or ensure no state changes post-external calls.
