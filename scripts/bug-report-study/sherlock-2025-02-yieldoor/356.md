# Incorrect Use of `initCollateralValue` in `isLiquidateable()` Causes False Liquidations and Position Reverts

### Summary

The incorrect `base` assignment in `isLiquidateable()` causes leveraged positions to be falsely flagged for liquidation and prevents new positions from being opened at higher leverage. This happens because `pos.initCollateralValue` includes both the user’s collateral and the borrowed amount, inflating the liquidation threshold and making all active positions incorrectly liquidatable.

Note: There's another issue making the `base` calculation returning a false positive when it should be liquidateable that I have submitted separately.

### Root Cause

In `isLiquidateable()`, `base` is incorrectly set to:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L409

```solidity
        base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
```
First off, one needs to be aware that [`a0` and `a1`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L46-L47) are the actual amounts of `token0` and `token1` the user deposited into the Vault after flash loaning [`delat0` and `delta1`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L121-L122) albeit to be corrected later for the actual amount of denominated tokens borrowed. As such, [`up.initCollateralUsd`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L129) and [`up.initCollateralValue`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L131) are inclusive of both the user's and the borrowed collateral.

As such, `base` will be artificially inflated if assigned `pos.initCollateralValue` in the ternary logic.

This causes:

1. All active positions prone to falsely triggering liquidations.

2. `openLeveragedPosition()` to revert due to `require(!isLiquidateable(_id))` failing when the position appears liquidatable immediately upon creation unless it's a low enough leveraged position.

### Internal Pre-conditions

1. The user must have an active leveraged position.

2. The borrowed amount must be included in `pos.initCollateralValue`.

3. The protocol must rely on `isLiquidateable()` for liquidation decisions.

### External Pre-conditions

1. The price feed must provide token prices.

2. The lending pool must allow leveraged positions.

3. The swap router must be functional.

### Attack Path

1. A user opens a leveraged position with high leverage.

2. `openLeveragedPosition()` calls [`require(!isLiquidateable(_id))`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L195) towards the end of its function logic.

3. Due to inflated base, `isLiquidateable()` returns true, making the transaction revert. Apparently, `owedAmount > totalDenom` is false, but `totalDenom - owedAmount < vp.minCollateralPct * base / 1e18` will be prone to true due to `base` has earlier been assigned the inflated `pos.initCollateralValue`:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L411

```solidity
        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
```
4. Alternatively, for active positions, all positions will be falsely liquidatable.

### Impact

1. Users cannot open positions at higher leverage.

2. Active positions that should not be liquidated become liquidatable.

3. Mass liquidations for big arbitrage by the bots at the expense of users' losses that should not have happened.

### Mitigation

In accordance with [liquidation explained](https://docs.google.com/document/d/1FUjXMXBRBRVgOYSMGORTFmS9fj_nh-ifQhoY0jjhwPY/edit?tab=t.0) in the doc, consider excluding the originally borrowed collateral, `pos.borrowedAmount` from `pos.initCollateralValue`. The `vp.minCollateralPct` (generally 5-40% depending on each whitelisted market according to the sponsor as disclosed in the discord channel) when multiplied by the assigned `base` in the second conditional check of the if clause should work as intended then:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408-L411

```diff
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
+        uint256 userOriginalNetCollateral = (pos.initCollateralValue - pos.borrowedAmount);
-        base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
+        base = base < userOriginalNetCollateral ? base : userOriginalNetCollateral;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
```
