# In the `Leverager.isLiquidateable()` Function, Comparison Between `base` and `initCollateralValue` is Unreasonable

### Summary

In the `Leverager.isLiquidateable()` function, `base` represents the minimum margin amount for the position. Currently, `base` is compared with `initCollateralValue`, but this comparison is unreasonable, as `initCollateralValue` is never related to maintaining the leveraged position. It's sufficient to compare `base` with the remaining amount of the position after repayment.

### Root Cause

The [isLiquidateable()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L409) function compares `base` with `initCollateralValue`, and the minimum value among both is reassigned to `base`. This is unreasonable.

Let's consider the following scenario:

- `base` = 3000
- `initCollateralValue` = 2000
- `totalDenom - owedAmount` = 250
- `minCollateralPct` = 10%

In this case, `base` is reassigned to `2000`, and the position is not liquidatable since `250 < 2000 * 10%` is not satisfied.

However, the position should actually be liquidatable, as `250 < 3000 * 10%`. As a result, unhealthy positions can avoid liquidation.

```solidity
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        ...

        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
```
