# First depositor can break the vault in such a way that only one asset will be accepted.

### Summary

A malicious first depositor can deposit only one asset in the vault. When this happens subsequent users won't be able to add liquidity in the other asset. For example, in a pool for USDT-WETH, the attacker deposits 10 USDC and Alice tries to deposit 100 USDC and 0.1 WETH. The transaction will go through but only  100 USDC will be deposited.


### Root Cause

The root cause of this issue lies in the `_calcDeposit`, the if statement only allows deposits in the direction of `amount1` if `bal0 = 0` and `amount0` if `bal1 = 0`. What this has done is that it makes it impossible to deposit the other token when the initial balance is zero.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119
```solidity

            // For first deposit, just use the amounts desired

            amount1 = depositAmount1;

```

### Internal Pre-conditions

The attacker must be the first depositor.

### External Pre-conditions

None

### Attack Path

1. The Pool is USDC-ETH
2. The attacker is the first depositor and they deposit 10 USDC
3. Alice tries to deposit 1000 USDC and 0.5 ETH, the transaction will go through but only 1000 USDC will be sent to the value.

### Impact

Users won't be able to deposit both tokens into the vault.
