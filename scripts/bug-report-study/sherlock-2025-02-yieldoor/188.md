# Insufficiant `setBorrowingRateConfig` function.


### Summary
In the `LendingPool::setBorrowingRateConfig` function, the state is not updated.

### Root Cause
The `LendingPool::setBorrowingRateConfig` function fails to update the state. 
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L348
```solidity
348:function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    }
```

### Internal pre-conditions
N/A

### External pre-conditions
N/A

### Attack Path
N/A

### PoC
The changed borrowing rates are not applied until `reserve.updateInterestRates` is called. 
When `reserve.updateState()` is invoked, the old borrowing rates are still in effect.

### Impact
Borrowers may pay more than they should due to the lack of updates from the state when the borrowing rate changes.

### Mitigation
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L348
```diff
348:function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
+       reserve.updateState();
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
+       reserve.updateInterestRates();
    }
```
