# Missing slippage protection in liquidity addition functions

## Description:
The `Strategy` contract functions `_addLiquidityToMainPosition()` and `_addLiquidityToSecondaryPosition()` lack slippage protection mechanisms when adding liquidity to Uniswap V3 positions. These functions directly call the `mint()` method on the Uniswap V3 pool without specifying minimum amounts of tokens to be used (`amount0Min` and `amount1Min`)

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L251
```solidity
function _addLiquidityToMainPosition(uint160 sqrtPriceX96, uint256 amount0, uint256 amount1)
    internal
    returns (uint256, uint256)
{
    // ...
    (uint256 used0, uint256 used1) =
        IUniswapV3Pool(pool).mint(address(this), tickLower, tickUpper, liquidity, "test");
    // No verification that used0 and used1 meet minimum expected values
    // ...
}
```

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L280
```solidity
function _addLiquidityToSecondaryPosition(uint160 sqrtPriceX96, uint256 amount0, uint256 amount1) internal {
    // ...
    if (liquidity > 0) IUniswapV3Pool(pool).mint(address(this), tickLower, tickUpper, liquidity, "test");
    // No verification of returned token amounts
    // ...
}
```

## Impact:
Without slippage protection, the protocol is vulnerable to front-running attacks where malicious actors can manipulate the pool price just before the transaction is executed. This can result in:
1. The protocol receiving significantly less liquidity than expected
2. Users experiencing unexpected losses when depositing funds

## Recommended Mitigation:
Add `amount0Min` and `amount1Min` parameters to both functions
