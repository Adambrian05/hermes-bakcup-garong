# Dust debt will cause protocol's loss by bad debt.

### Summary

The prices of position's collateral and debt both can be decreased.   
This can lead to dust debt.   
Any liquidator does not liquidate that position.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L280

`Leverage.sol#_checkWithinLimits()` checks minBorrow when `openLeveragedPosition()`.   
```solidity
    function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

@>      require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
        require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        require(up.initBorrowedUsd <= vp.maxUsdLeverage, "too high borrow usd amount");
        require(up.borrowedAmount <= maxIndividualBorrow, "too high borrow for the vault");
        require(
            vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD,
            "vault exceeded borrow limit"
        );
    }
```
But `Leverage.sol#withdraw()` function checks remained borrow amount from initial borrowed borrowed value.
```solidity
    // Here, it doesn't matter that the initBorrowedUsd doesn't represent the real value. The scenarios are 2:
    // 1) Price has dropped. In this case, this would allow the user to actually have less than minBorrow opened,
    // but since borrowed asset's price has dropped, position is less likely to be liquidated
    // 2) Price has increased. In this case the user has to remain higher position value.
    require(
        up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18 > minBorrow,
        "remaining should be at least minBorrow"
    );
```
It seems not to have any problem from doc.   
But developer did not consider dust debt by decreasing usd value of both collateral and debt.

### Internal Pre-conditions

A dust debt position is happened.

### External Pre-conditions

The prices of a position's collateral and debt are decreased.

### Attack Path

Liquidators can not collect yield from dust bad debt.  

### Impact

Dust bad debts can lead to protocol's loss.

### PoC

We say that minBorrow is 20.
When a user calls openLeveragedPosition(), we say that pos.token0's init price: 40, pos.token1's init price: 40.
And denomination is token0 and borrowAmount is 1.
After time is passed, token0's price is decreased to 10 and token1's price is decreased to 5.

At this time, we say that the position is liquidateable but current usd value of total collateral is too small.   
Then, liquidators don't liquidate that position because of no-profit.

### Mitigation

Add a logic to `Leverage.sol#withdraw()` so that remained borrowed usd value at current market is not less than minimum borrowed usd value.
