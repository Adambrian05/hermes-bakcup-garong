# `Leverager::withdraw()` repays incorrect amount due using amountOut1 instead of amountOut0

### Summary

`Leverager::withdraw()` [uses](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) `amount0` when it should use `amount1` instead, leading to the repayment of incorrect amounts and failure to withdraw, DoSing withdrawals.

### Root Cause

In `Leverager:232`, amountOut0 is used instead of amountOut1.

### Internal Pre-conditions

`amountOut0 > amountOut1` and ` amountOut1 < owedAmount`

### External Pre-conditions

None.

### Attack Path

1. User opens a leveraged position, borrowing token1 only.
2. User withdraws the position, and the amount1 withdrawn is not enough to cover the debt owed, so the user would `repayFromWithdraw` `amountOut1`. However, due to the bug, `repayFromWithdraw` will be `amountOut0`. Now, if the value of `amountOut0` is bigger than `amountOut1`, it reverts due to underflow. If the value is smaller, the user will be pulled more funds than it should and then receives more funds later.

### Impact

DoSed withdrawals.

### PoC

See above.

### Mitigation

`uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;`
