# Strategy is DoS due to incorrect ticks of secondary position

### Summary

Not handling negative tick in function `Strategy::_setSecondaryPositionsTicks()` will cause the secondary position ticks to be invalid and the contract `Strategy` is unable to operate 

### Root Cause

Function [`Strategy::_setSecondaryPositionsTicks()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L366C1-L382C6) does not handle the case when `tick` is negative. In such case, the `modulo` is also negative and as a result, the calculated tick lower and tick upper for the secondary position are incorrect

For example with [WETH-USDT pool on Ethereum](https://etherscan.io/address/0x11b815efB8f581194ae79006d24E0d814B7697F6#readContract), pool current tick is negative value. Given numerical that current tick is `-198126`, with tick spacing `10`. At deployment when there is no token0, token1 balances, the execution goes into the `else` branch and the position's ticks will be `tickLower = -198110` and `tickUpper = -198110` -> This is an invalid position against UniV3.

Note that if branch `if (bal0in1 < bal1)` still computes valid ticks for the position.

```solidity
    function _setSecondaryPositionsTicks(int24 tick) internal {
@>        int24 modulo = tick % tickSpacing; // <-- negative when `tick` is negative
        uint256 bal0 = IERC20(token0).balanceOf(address(this));
        uint256 bal1 = IERC20(token1).balanceOf(address(this));
        uint256 _price = price();
        uint256 bal0in1 = bal0 * _price / PRECISION; // usually either of them should be 0, but might be non-zero due to rounding when minting

        if (bal0in1 < bal1) {
            secondaryPosition.tickLower = mainPosition.tickLower;
            secondaryPosition.tickUpper = tick - modulo;
        } else { // <<-- go into this branch
@>            secondaryPosition.tickLower = tick - modulo + tickSpacing;
@>            secondaryPosition.tickUpper = mainPosition.tickUpper; // TODO check if these need to be reversed.
        }

        emit NewSecondaryTicks(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
```
