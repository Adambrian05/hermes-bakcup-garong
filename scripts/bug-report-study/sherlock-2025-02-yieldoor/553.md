# Lack of Enforcement For Returning Pulled Funds

### Summary

The `pullFunds()` function allows the leverager to withdraw tokens from the protocol, but the system does not enforce that same amount must be returned via `pushFunds()`

The protocol assumes that every pulled amount will eventually be pushed back, but there is no mechanism to track or verify this.
As a result, the leverager can withdraw funds permanently without returning them or returning less than they pulled from the system, draining the system.

This is the line that says it but it is not enforced 
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L208

### Root Cause

Missing balance tracking for pulled funds 
The protocol assumes that the leverager will  always return the same amount of funds after calling `pullFunds()`, but this assumption is not enforced in the code. 

````solidity
function pullFunds(address asset, uint256 amount) external nonReentrant {
        require(msg.sender == leverager, "borrower not leverager");
        DataTypes.ReserveData memory reserve = getReserve(asset);

        IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
    }

function pullFunds(address asset, uint256 amount) external nonReentrant {
        require(msg.sender == leverager, "borrower not leverager");
        DataTypes.ReserveData memory reserve = getReserve(asset);

        IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
    }

 /// @notice Allows leverager to push back funds to yAsset
    function pushFunds(address asset, uint256 amount) external nonReentrant {
        require(msg.sender == leverager, "borrower not leverager");
        DataTypes.ReserveData memory reserve = getReserve(asset);

        IERC20(asset).safeTransferFrom(msg.sender, reserve.yTokenAddress, amount);
    }
````


### Internal Pre-conditions

No tracking of pulled funds 
No enforcement in pushed funds 

### External Pre-conditions

- Protocol holds large reserves 
- Low User withdrawal at the time of attack 

### Attack Path

- Attacker repeatedly called `pullfunds()` because the contract does not track pulled amounts they can pulled funds multiple times 

- Never call `pushFunds()` or return less than pulled 

### Impact

- It will affect all depositors and withdrawals 
- Financial Risk
- Operational risk 
- loss of funds 

### PoC

_No response_

### Mitigation

A tracking mechanism should be added to store the amount pulled and ensure the same amount is pulled back
