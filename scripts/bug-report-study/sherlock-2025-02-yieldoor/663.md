# The user will receive more tokens due to a logical error

### Summary

Logical error during partial withdrawal (withdraw) of a position. An error was detected in the `Leverager.withdraw` function within the block where the borrowed asset coincides with the position's token1. Instead of using `amountOut1` to calculate the amount returned from collateral, the condition checks `amountOut1 < owedAmount ? amountOut0 : owedAmount` —clearly a typo: it should be `? amountOut1 : owedAmount`.

This bug clearly requires correction. It is confirmed by the code: the comparison line for the token1 branch incorrectly uses `amountOut0` instead of `amountOut1`. This oversight in tests indicates that the partial withdrawal scenario with the borrowed asset equal to the second token was likely not covered by tests; otherwise, such an error would have surfaced.

### Impact

Consequence: If the borrowed asset equals token1 and the withdrawn part of token1 is less than the debt, the code subtracts a completely different value (`amountOut0`) instead of deducting that portion from the debt. This results in an incorrect reduction of `owedAmount`. Two scenarios are possible:

Underpayment logic: For example, a debt of 100, collateral provides 20 of token1, and 50 of token0. Instead of subtracting 20 from the debt, the code compares 20 < 100, selects `amountOut0=50` as `repayFromWithdraw`, subtracts 50 from the debt (remaining debt becomes 50), and also subtracts 50 from token1 (resulting in a negative `amountOut1 = 20-50`, which immediately triggers arithmetic underflow and revert). Thus, certain value combinations will cause the withdraw function to revert instantly (making partial withdrawal impossible) due to an incorrect variable.

Overpayment logic: If, by chance, `amountOut0` is smaller than the debt and also smaller than `amountOut1, repayFromWithdraw` becomes `amountOut0`. For example, debt is 50, `amountOut1` is 40, `amountOut0` is 30 -> it takes 30, reducing the debt to 20, and decreases token1 by 30 (leaving 10). As a result, 10 token1 remain unused for repayment, despite being sufficient to cover the remaining debt (20). Consequently, the protocol asks the user for 20 via `safeTransferFrom`, even though the user still has 10 unused token1 from collateral, which will later be returned to them. In other words, due to the bug, part of the debt is repaid not by collateral but by the user's own funds, despite sufficient collateral—an excessive debt demand. The user will lose extra personal funds in such a withdraw (or simply overpay gas if they lack the required amount, causing the transaction to fail).
