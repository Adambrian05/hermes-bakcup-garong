# Incorrect Calculation of Leverage Rate


### Summary
The current implementation of the leverage rate calculation allows users to open positions with leverage exceeding the intended limit of 5x.

### Root Cause
The `initCollateralValue` is defined as the sum of collateral and borrowed amounts. 
However, the leverage rate is calculated using the formula: `(userCollateral + 2 * borrowed) / (userCollateral + borrowed)`
This formula will always yield a value less than 2, which is incorrect and allows for excessive leverage.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464
```solidity
    function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

464:    uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
        require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        require(up.initBorrowedUsd <= vp.maxUsdLeverage, "too high borrow usd amount");
        require(up.borrowedAmount <= maxIndividualBorrow, "too high borrow for the vault");
        require(
            vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD,
            "vault exceeded borrow limit"
        );
    }
```

Senario1:
vp.maxTimesLeverage := lendingPool's maxLevTimes := 5.
Alice opens a position worth 10,000 usd using 1000 usd, which represents 10x leverage.
At this moment, `borrowedUsd = 9000 usd`, `initCollateralUsd = 10,000 usd`.
In L464, `positionLeverage = (10,000 + 9000) / 10,000 ~= 1.9x`
Thus, all requirements are satisfied.

In the `openLeveragedPosition` function:
    `amount0In := 1 wbtc`, `amount1In := 100,000 usdc`, `vault0In := 1 wbtc`, `vault1In := 100,000 usdc`, `BorrowAmount := 79.4 weth`.
    At this moment:
    Deposit to Vault with `1 wbtc` and `100,000 usdc`.
    `initCollateralUsd = 1 * 101,000 + 100,000 * 1 = 201,000 usd`.
    `initCollateralValue = 201,000 / 2500 = 80.4 weth`.
    exchange 79.4 eth for usdc in swapRouter: `amountOut = 79.4 * 2525 = 200,485 usdc`

At this time, this leverage position is not liquidatable.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L385
Because, in the `isLiquidateable` function:
    In L408, `base = 79.4 / (5 - 1) = 19.85`
    In L411, `totalDenom - owedAmount = 80.4 - 79.4 > 5% * 19.85`
As a result attacker's gain = 485 usd.

Attacker can perform this attack without any funds.
Attacker can repeat this attack to extract funds from the protocol.

### Impact
1. Excessive Leverage: Users can open positions with leverage greater than 5x.
2. Potential Exploitation: Attackers can exploit this to extract funds through positions that 80x leverage, especially under 1% Chainlink price slippage.
