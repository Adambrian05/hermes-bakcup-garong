# Wrong Upper Tick Used When Collecting Fees

### Summary

In `Strategy::collectFees` the protocol is supposed to collect all outstanding position fees. It collects fees from the main and the secondary position as well as the fees from the ongoing vesting position. The problem lies in the vesting collection. To collect fees, the function `collectPositionFees` needs 2 inputs - lower and upper ticks. When collecting the fees from the vesting position, the protocol wrongly uses the upper tick of the main position instead of the vesting position. 

### Root Cause

In `Strategy.sol::167`  the protocol wrongly uses the upper tick of the main position instead of the upper tick of the vesting position to calculate the vesting position fees.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167

### Attack Path

1. Protocol calls `collectFees`
2. Wrong vesting fee is collected every time

### Impact

Wrong fees collected, which may cause the protocol lose or gain unintended funds.

### Mitigation

Change the logic. Upper tick when collecting fees for vesting positions should be the upper tick of the vesting position.
