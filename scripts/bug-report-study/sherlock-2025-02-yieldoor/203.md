# Incorrect Leverage Calculation Allows Users to Exceed Maximum Limits

### Summary

Miscalculation in the leverage formula allows users to exceed the protocol’s maximum leverage limit. Instead of correctly determining leverage as **(Total Position Value / User's Own Collateral)**, the existing calculation significantly **underestimates leverage**, allowing users to take on excessive risk without restriction.

By exploiting this flaw, a user can **take over 25x leverage when the maximum allowed leverage is 2x**, increasing the risk of liquidation failures and potential protocol insolvency.

### Root Cause

The protocol currently calculates leverage using the following formula:

```solidity
uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464

Where:

- `initCollateralValue`: The **total** position value, including both **user's deposit + borrowed amount**.
- `borrowedAmount`: The amount borrowed from the protocol.

**Expected Behavior**

Leverage should be calculated as:

$$
Leverage=\frac{\text{Total Position Value}}{\text{User’s Own Collateral}}
$$

For a **2x leverage** scenario:

- **User deposit:** $1000
- **Borrowed amount:** $1000
- **Total position value:** $2000
- **Correct leverage calculation:**

$$
 \frac{2000}{1000} = 2x
$$

**Actual Behavior**

Using the flawed formula:

$$
\frac{2000+1000}{2000}=1.5x(Incorrect)
$$

This **underestimates the actual leverage**, causing the protocol to **approve higher-than-intended leverage requests**.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L467

### Attack Path

If the **max leverage allowed is 2x**, a user can **bypass the limit** as follows:

- **User deposit:** $1000
- **Requests a 10x leveraged position ($10,000 total exposure, borrowing $9,000)**
- **Correct leverage:** $$\frac{10,000}{1,000} = 10x$$
- **Protocol's incorrect calculation:** $$\frac{10,000 + 9,000}{10,000} = 1.9x(Incorrect)$$ 
- Since **1.9x is within the "2x limit," the protocol approves the position**, **allowing 10x leverage instead of enforcing the 2x cap**.
- https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L467

### Impact

- **Bypassing Leverage Limits:** Users can take on **15x more leverage than allowed**, exposing the system to extreme risks.
- **Protocol Insolvency:** Excessive leverage increases liquidation risk, potentially **leading to bad debt accumulation**.
- **Increased Liquidation Cascades:** If large positions with excessive leverage go underwater, the **protocol may struggle to liquidate them efficiently**, causing **cascading liquidations** and **capital loss**.

None

### Mitigation

Replace the incorrect formula with:

```solidity
uint256 positionLeverage = (up.initCollateralValue * 1e18) / (up.initCollateralValue - up.borrowedAmount);
```

This ensures leverage is **correctly calculated**:

$$\text{Leverage} = \frac{\text{Total Position Value}}{\text{User's Own Collateral}}$$

For **10x leverage attempt**, this fix correctly flags the violation:

$$\frac{10,000}{1,000} = 10x(\text{Correct, and now properly blocked})$$
