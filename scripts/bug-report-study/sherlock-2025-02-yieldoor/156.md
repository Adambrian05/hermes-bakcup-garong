# Updating the debt capt in the leverager requires DoSing opening leveraged positions

### Summary

[Leverager::initVault()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L75) changes the parameters of the vault such as the `maxCumulativeBorrowedUSD` cap. The issue is that for it to go through, `leverageEnabled` has to be false. However, when this is false, users can not [open](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L104) leveraged positions. Thus, opening positions would be DoSed for some time to allow updating the parameter.

### Root Cause

In `Leverager:87`, debt cap can not be updated without DoSing opening positions.

### Internal Pre-conditions

None.

### External Pre-conditions

`vaultParams[up.vault].currBorrowedUSD` is off due to interest accrual and debt price change.

### Attack Path

1. User calls `Leverager::openLeveragedPosition()`.
2. Protocol sets `leverageEnabled` to false to change the debt cap.
3. User transaction reverts.

### Impact

DoSed open leveraged position, which is time sensitive as the user will miss out on fees, the pool price may change, oracle prices may change, so on and so forth.

### PoC

See links above.

### Mitigation

Consider a adding a setter to adjust the cap.
