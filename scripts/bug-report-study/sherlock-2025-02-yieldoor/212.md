# Code implementation error will DOS users who try to open leverage position with multiswap params

### Summary

Not reassigning `path` argument to the new calculated path in the `while` block in `Leverager::_getTokenIn` will cause an out of gas evm revert when users call `Leverager::openLeveragedPosition` with multiswap params.

### Root Cause

In [Leverager.sol::568](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L568), the `path` argument is not reassigned to the returned value of the function call, leading to an infinite loop.

### Impact

The protocol will always be unable to process `openLeveragedPosition` calls for swaps that require more than one pool. This is particularly bad because uniswap's `ExactOutputParams` struct and `exactOutput` function exists solely for multiswaps, making it highly likely that a large number of users will be DOSed.

### Mitigation

```diff
function _getTokenIn(bytes memory path) internal pure returns (address) {
        while (path.hasMultiplePools()) {
-           path.skipToken();
+          path = path.skipToken(); 
        }

        (, address tokenIn,) = path.decodeFirstPool();
        return tokenIn;
    }
```
