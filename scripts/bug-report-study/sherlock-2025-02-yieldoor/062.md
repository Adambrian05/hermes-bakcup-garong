# Unchecked tick boundaries in `Strategy` contract causes position creation to revert

### Summary

The missing boundary checks for tick values in the `Strategy` contract will cause position creation to fail in cases where the current tick is close to the extreme boundaries.

### Root Cause

In `Strategy.sol`, when calculating position ticks, there are no checks to ensure that the calculated tick values are within Uniswap V3's valid range (`TickMath.MIN_TICK` to `TickMath.MAX_TICK`). This oversight allows for the creation of positions with invalid tick values that will cause transactions to revert when interacting with Uniswap V3.

This affects `_setMainTicks()`, `_setSecondaryPositionsTicks()` and `addVestingPosition()` functions.

### Internal Pre-conditions

N/A

### External Pre-conditions

1. The Uniswap V3 pool price must be very close to the extreme boundaries, causing calculated ticks to fall outside the valid range

### Attack Path

1. After one or multiple swaps, the pool price is very close to an extreme (near `MIN_TICK` or `MAX_TICK`)
2. The rebalancer attempts to call `rebalance()` on the `Strategy` contract
3. The contract calculates position ticks based on the current price
4. Due to the lack of boundary checks, the calculated ticks may fall outside the valid range (`-887272` to `+887272`)
5. When the contract attempts to create a position with these invalid ticks, the Uniswap V3 position manager reverts the transaction
6. The user's transaction fails, preventing them from creating positions

### Impact

The protocol suffers a denial of service for critical functionality. `Strategy` cannot create new positions or rebalance existing ones when the pool price is near extreme boundaries.

### PoC

_No response_

### Mitigation

Add boundary checks to ensure that calculated tick values are within Uniswap V3's valid range:

```solidity
// Add these checks before creating main positions
mainPosition.tickLower = Math.max(mainPosition.tickLower, TickMath.MIN_TICK);
mainPosition.tickUpper = Math.min(mainPosition.tickUpper, TickMath.MAX_TICK);

// Also add similar checks for secondary positions
secondaryPosition.tickLower = Math.max(secondaryPosition.tickLower, TickMath.MIN_TICK);
secondaryPosition.tickUpper = Math.min(secondaryPosition.tickUpper, TickMath.MAX_TICK);
```
