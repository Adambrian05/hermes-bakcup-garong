# User is blacklisted will causing withdraw failed

### Summary

The `withdraw` function in the `Vault` contract may fail if a user is blacklisted by an ERC20 token contract, such as USDC. This can prevent the user from successfully withdrawing their funds, leading to potential loss of access to their assets.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L103-L104

### Root Cause

the reliance on the `safeTransferFrom` function from the `SafeERC20` library, which will revert if the token transfer fails. If a user is blacklisted by the token contract, the transfer will fail, causing the entire transaction to revert.

```solidity
        IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
        IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);
```

### Internal Pre-conditions

None

### External Pre-conditions

The user must be blacklisted by the ERC20 token contract (e.g., USDC).

### Attack Path

## Attack Path
1. A user who is blacklisted by the ERC20 token contract attempts to withdraw their shares from the `Vault`.
2. The `withdraw` function is called, and the `safeTransferFrom` function attempts to transfer tokens from the strategy to the user.
3. The transfer fails due to the user's blacklisted status, causing the transaction to revert.

### Impact

Blacklisted users are unable to withdraw their funds from the `Vault`, effectively locking their assets within the contract. 

### PoC

_No response_

### Mitigation

Consider implementing a mechanism to handle failed transfers gracefully. Allow users to specify an alternative address for withdrawals if their primary address is blacklisted.
