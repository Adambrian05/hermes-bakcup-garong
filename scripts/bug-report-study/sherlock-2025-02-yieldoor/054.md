# Inefficient Liquidity Withdrawal in Vault Contract

## Summary
The `withdraw` function in the `Vault` contract has an inefficient implementation for handling withdrawals that require liquidity to be removed from a position. The function uses a binary approach where it uses the idle balance or calls `withdrawPartial` to remove liquidity proportionally to the stake withdrawn. This implementation can lead to excessive liquidity removal, increased gas fees, and loss of value for users.

## Description
The root cause of this issue is in the `withdraw` function of the `Vault` contract.
```solidity
// In Vault
function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
    public
    returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
{
    IStrategy(strategy).collectFees();

    (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

    uint256 totalSupply = totalSupply();
    _burn(msg.sender, shares);

    withdrawAmount0 = totalBalance0 * shares / totalSupply;
    withdrawAmount1 = totalBalance1 * shares / totalSupply;

    (uint256 idle0, uint256 idle1) = IStrategy(strategy).idleBalances();

    if (idle0 < withdrawAmount0 || idle1 < withdrawAmount1) {
        // When withdrawing partial, there might be a few wei difference.
        (withdrawAmount0, withdrawAmount1) = IStrategy(strategy).withdrawPartial(shares, totalSupply);
    }

    require(withdrawAmount0 >= minAmount0 && withdrawAmount1 >= minAmount1, "slippage protection");

    IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
    IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);

    return (withdrawAmount0, withdrawAmount1);
}
```
The function only calls `IStrategy(strategy).withdrawPartial(shares, totalSupply)` if `idle0 < withdrawAmount0 || idle1 < withdrawAmount1`, this means `withdrawPartial` is only called if the idle balance (tokens not used in liquidity positions) is not enough to cover the withdrawal.

When `withdrawPartial` is called, the function ignores the initial calculations of `withdrawAmount0` and `withdrawAmount1` and relies entirely on the value returned by `withdrawPartial` without any logic to handle the case where only a portion of the liquidated position needs to be liquidated.

The issue is in the conditional logic that determines when to call `withdrawPartial`.
```solidity
if (idle0 < withdrawAmount0 || idle1 < withdrawAmount1) {
    // When withdrawing partial, there might be a few wei difference.
    (withdrawAmount0, withdrawAmount1) = IStrategy(strategy).withdrawPartial(shares, totalSupply);
}
```
This logic has some drawbacks, namely it uses a binary approach - either using only idle balances or calling `withdrawPartial` for the entire amount. When `withdrawPartial` is called, it removes liquidity proportionally to the shares withdrawn from all positions and there is no optimization to minimize the amount of liquidity that needs to be removed.

It can be seen that `withdrawPartial` removes liquidity proportionally from all positions without any optimization.
```solidity
// In Strategy
function withdrawPartial(uint256 shares, uint256 totalSupply)
    external
    onlyVault
    returns (uint256 amount0Out, uint256 amount1Out)
{
    (uint256 bal0, uint256 bal1) = idleBalances(); // before withdrawing any liquidity, but after collecting fees.

    uint256 liqToRemove = mainPosition.liquidity * shares / totalSupply;
    (uint256 m0, uint256 m1) =
        _removeFromPosition(uint128(liqToRemove), mainPosition.tickLower, mainPosition.tickUpper);
    mainPosition.liquidity -= uint128(liqToRemove);

    liqToRemove = secondaryPosition.liquidity * shares / totalSupply;
    (uint256 s0, uint256 s1) =
        _removeFromPosition(uint128(liqToRemove), secondaryPosition.tickLower, secondaryPosition.tickUpper);
    secondaryPosition.liquidity -= uint128(liqToRemove);

    amount0Out = m0 + s0 + (bal0 * shares / totalSupply);
    amount1Out = m1 + s1 + (bal1 * shares / totalSupply);

    return (amount0Out, amount1Out);
}
```

Scenario
1.	A user has 100 shares in the Vault, representing 10% of the total supply (1000 shares)
2.	The Strategy has the following assets:
•	Idle balances: 50 token0, 20 token1
•	Main position: 200 token0, 300 token1 (in liquidity)
•	Secondary position: 100 token0, 150 token1 (in liquidity)
•	Total: 350 token0, 470 token1
3.	The user wants to withdraw 50 shares (5% of total supply), which should entitle them to:
•	17.5 token0 (5% of 350)
•	23.5 token1 (5% of 470)
4.	The idle balances (50 token0, 20 token1) are sufficient for token0 but insufficient for token1 (need 23.5)
5.	Since `idle1 (20) < withdrawAmount1 (23.5)`, the contract calls `withdrawPartial(50, 1000)`
6.	`withdrawPartial` removes 5% of liquidity from both positions:
•	5% from main position: 10 token0, 15 token1
•	5% from secondary position: 5 token0, 7.5 token1
•	Plus 5% of idle balances: 2.5 token0, 1 token1
•	Total: 17.5 token0, 23.5 token1
7.	The issue is that the contract removed liquidity from both positions when it only needed to remove a small amount of liquidity to cover the shortfall in token1 (3.5 token1)

## Impact
Excessive liquidity removal reduces the amount of capital actively earning fees in Uniswap positions and each liquidity removal and subsequent rebalancing exposes the protocol to price impact and slippage, which can erode value over time.

## Recommendation
Implement a more efficient withdrawal strategy that minimizes liquidity removal.
```solidity
function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
    public
    returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
{
    IStrategy(strategy).collectFees();

    (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();
    uint256 totalSupply = totalSupply();
    
    // Calculate user's proportional share
    withdrawAmount0 = totalBalance0 * shares / totalSupply;
    withdrawAmount1 = totalBalance1 * shares / totalSupply;
    
    // Burn shares before any external calls
    _burn(msg.sender, shares);
    
    // Get current idle balances
    (uint256 idle0, uint256 idle1) = IStrategy(strategy).idleBalances();
    
    // Calculate how much we need to withdraw from positions
    uint256 neededFromPositions0 = 0;
    uint256 neededFromPositions1 = 0;
    
    if (idle0 < withdrawAmount0) {
        neededFromPositions0 = withdrawAmount0 - idle0;
    }
    
    if (idle1 < withdrawAmount1) {
        neededFromPositions1 = withdrawAmount1 - idle1;
    }
    
    // Only remove liquidity if needed
    if (neededFromPositions0 > 0 || neededFromPositions1 > 0) {
        // Call a new function that removes only the required amount of liquidity
        (uint256 received0, uint256 received1) = IStrategy(strategy).withdrawOptimal(
            neededFromPositions0, 
            neededFromPositions1
        );
        
        // Update withdrawal amounts based on what was actually received
        withdrawAmount0 = (idle0 < withdrawAmount0) ? idle0 + received0 : withdrawAmount0;
        withdrawAmount1 = (idle1 < withdrawAmount1) ? idle1 + received1 : withdrawAmount1;
    } else {
        // If we have enough idle balance, just use that
        withdrawAmount0 = (withdrawAmount0 > idle0) ? idle0 : withdrawAmount0;
        withdrawAmount1 = (withdrawAmount1 > idle1) ? idle1 : withdrawAmount1;
    }
    
    require(withdrawAmount0 >= minAmount0 && withdrawAmount1 >= minAmount1, "slippage protection");
    
    // Transfer tokens to user
    IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
    IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);
    
    return (withdrawAmount0, withdrawAmount1);
}
```
