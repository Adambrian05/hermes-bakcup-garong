# User will be unable to deposit small amounts for tokens with low decimals

### Summary

The lack of decimal adjustment in `LendingPool.sol` will cause a denial of core functionality for users as a user will attempt to deposit small amounts of low-decimal tokens and fail due to incorrect scaling.



### Root Cause

In `LendingPool.sol` (https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L118), the calculation of `yTokenAmount` does not adjust the amount parameter based on the token’s decimals, treating all tokens as having 18 decimals by default.



### Internal Pre-conditions

1. Owner needs to call `initReserve(address(lowToken))` to set up a reserve for a token with 6 decimals.
2. User needs to have a balance of at least 500000 wei (0.5 * 10^6) of the low-decimal token to attempt a deposit.



### External Pre-conditions

None – the issue is entirely within the `LendingPool` contract and does not depend on external protocols.



### Attack Path

1. User calls `deposit(address(lowToken), 500000, user)` expecting to deposit 0.5 units of a 6-decimal token (500000 wei).
2. The contract calculates `yTokenAmount` as `(500000 * 1e27) / 1e27 = 500000`, which is interpreted as 500000 wei (far exceeding the intended 0.5 * 10^6 wei due to lack of decimal scaling).
3. The transaction succeeds unexpectedly because `yTokenAmount > MINIMUM_YTOKEN_AMOUNT (1000)`, while it should fail as a "dust amount" for a 6-decimal token.



### Impact

The user cannot deposit small amounts of low-decimal tokens as intended, suffering a denial of core deposit functionality. The protocol may lose user engagement due to this limitation.



### PoC

```solidity
// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../src/LendingPool.sol";
import "../src/yToken.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

contract MockERC20LowDecimals is ERC20 {
    constructor() ERC20("LowDecimalToken", "LDT") {
        _mint(msg.sender, 10000 * 10**6); // 10000 tokens = 10000 * 10^6 wei
    }

    function decimals() public view virtual override returns (uint8) {
        return 6;
    }
}

contract LendingPoolPoCTest is Test {
    LendingPool pool;
    MockERC20LowDecimals lowToken;
    address yTokenLowAddress;
    address owner = address(0x1);
    address user = address(0x2);

    function setUp() public {
        vm.startPrank(owner);
        pool = new LendingPool();
        lowToken = new MockERC20LowDecimals();
        pool.initReserve(address(lowToken));
        yTokenLowAddress = pool.getYTokenAddress(address(lowToken));
        lowToken.approve(address(pool), type(uint256).max);
        lowToken.transfer(user, 5000 * 10**6); // 5000 tokens
        vm.stopPrank();

        vm.startPrank(user);
        lowToken.approve(address(pool), type(uint256).max);
        yToken(yTokenLowAddress).approve(address(pool), type(uint256).max);
        vm.stopPrank();
    }

    function testIncorrectDecimalHandling() public {
        vm.prank(user);
        // Attempt to deposit 0.5 tokens (500000 wei for 6 decimals)
        // Expected: revert "deposit is dust amount" as 0.5 tokens should be too small
        // Actual: succeeds due to incorrect scaling (treated as 500000 * 10^18)
        uint256 yTokens = pool.deposit(address(lowToken), 500000, user); 
        assertGt(yTokens, 0, "Deposit should fail but succeeded due to decimal mismatch");
        
        uint256 expectedYTokens = 500000 - 1000; // After MINIMUM_YTOKEN_AMOUNT burn
        assertEq(yTokens, expectedYTokens, "Incorrect yToken amount minted");
    }
}
```

### Mitigation

Adjust the `yTokenAmount` calculation in `LendingPool.sol` to account for token decimals.
