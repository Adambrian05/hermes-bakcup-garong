# Logic in `_setSecondaryPositionTicks()` in `Strategy.sol` has error.

### Summary

The UniswapV3 pool expects `tickLower` and `tickUpper` to provide a range and `tickLower` != `tickUpper`. But the logic in `_setSecondaryPositionTicks()` may cause them to be equal, resulting a revert in `rebalance()`.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L366-L382

In the function, at the end, there should be a check to ensure `secondaryPosition.tickLower` != `secondaryPosition.tickUpper`. If found equal, changes should be made to either of them to ensure the function does not revert.

### Internal Pre-conditions

1. `rebalance()` is called.

### External Pre-conditions

1. `tickPrice` is such that the function logic produces `secondaryPosition.tickLower` == `secondaryPosition.tickUpper`.

### Attack Path

1. `rebalance()` is called.
2. `tickPrice` is such that the function logic produces `secondaryPosition.tickLower` == `secondaryPosition.tickUpper`.
3. `rebalance()` will keep reverting till `tickPrice` does not change or till `changePositionWidth()` is not called.
4. `changePositionWIdth()` cannot be called before the expiry of the `rebalanceInterval`.
5. There may be multiple such values.
### Impact

1. `rebalance()` will keep reverting till `tickPrice` does not change or till `changePositionWidth()` is not called.
2. `changePositionWIdth()` cannot be called before the expiry of the `rebalanceInterval`.
3. Worst case, the protocol gets stuck for sometime.
4. There may be many such values across many pools.

### PoC

1. Add function declarations in `IStrategy.sol`
```solidity
    function _setMainTicks(int24 tick) external;
    function _setSecondaryPositionsTicks(int24 tick) external;
    function setTickSpacing(int24 _tickSpacing) external;
    function setPositionWidth(int24 _tickSpacing) external;

```
2. Add function definition in `Strategy.sol`
```solidity

    // Add this setter function
    function setTickSpacing(int24 _tickSpacing) external onlyOwner {
        tickSpacing = _tickSpacing;
    }
    function setPositionWidth(int24 _tickSpacing) external onlyOwner {
        positionWidth = uint24(4 * _tickSpacing);
    }

```
3. Change visibility of `_setSecondaryPositionsTicks()` to `public` in `Strategy.sol`. Change visibility of `_setMainTicks()` to `public` in `Strategy.sol`

4. Test Case - Check for different values of `tickSpacing` like `1, 10, 60, 200`
```solidity
    function test_POC_2(int24 ticks) public {

        if ((ticks >= -887272) && (ticks <= 887272)) {
                vm.startPrank(owner);
                Strategy(address(strategy)).setTickSpacing(200); //Check for these values [1, 10, 60, 200]
                assertEq(Strategy(address(strategy)).tickSpacing(), 200);
                IStrategy(strategy).setPositionWidth(200);
                assertEq(Strategy(address(strategy)).positionWidth(), 4*200);
                IStrategy(strategy)._setMainTicks(ticks);
                IStrategy(strategy)._setSecondaryPositionsTicks(ticks);
                vm.stopPrank();

                assertNotEq(IStrategy(strategy).getSecondaryPosition().tickLower, IStrategy(strategy).getSecondaryPosition().tickUpper);
        }        
    }
```


### Mitigation

Short term:
Adjust either one of `secondaryPosition.tickLower` or `secondaryPosition.tickUpper` if they are equal.

Long term:
Refine the logic.
