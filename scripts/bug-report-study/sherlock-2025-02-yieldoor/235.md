# `Strategy::checkPoolActivity` considers observations as valid that have not been initialized


### Root Cause

The `Strategy::checkPoolActivity` function is responsible for verifying price changes between different timestamps. It returns false if the price delta between T1 and T2 exceeds maxObservationDeviation or if there are insufficient observations within a TWAP window. However, the function mistakenly considers uninitialized observations as valid. As a result, `Strategy::checkPoolActivity` may return false even when there is no actual issue.

### PoC

The observationCardinalityNext parameter can be increased by anyone via a call to [Pool.increaseObservationCardinalityNext](https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/UniswapV3Pool.sol#L255-L267). Additionally, blockTimestamp can be overwritten to 1 to prevent fresh SSTOREs during swaps.

The observationCardinality is updated to observationCardinalityNext when currentIndex + 1 equals observationCardinality, as seen in [Oracle::write](https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/libraries/Oracle.sol#L94).

### Impact

`Strategy::checkPoolActivity` is used by`Leverager::openLeveragedPosition` and this causes `Leverager::openLeveragedPosition` will be reverted

### Mitigation

The `Strategy::checkPoolActivity` function must not consider observations as valid that have not been initialized
