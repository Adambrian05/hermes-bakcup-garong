# Strategy contract will lose vesting position fees for liquidity providers

### Summary

The incorrect tick range usage in fee collection will cause a loss of fees for liquidity providers as the Strategy contract will attempt to collect fees from non-existent position ranges after rebalancing.

### Root Cause

In [`src/Strategy.sol:167`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167) the `collectFees()` function incorrectly uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper` when collecting fees from vesting positions:
```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
}
```

### Internal Pre-conditions

1. A vesting position must exist (`ongoingVestingPosition` is true)
2. The main position must be rebalanced to have different ticks than the vesting position

### External Pre-conditions

The Uniswap pool price must move enough to trigger a rebalance (price movement beyond `tickTwapDeviation`)

### Attack Path

1. Liquidity provider creates a vesting position with initial ticks (e.g., 67680, 67920)
2. Price movement occurs in the pool through swaps
3. Rebalancer calls `rebalance()`, moving main position ticks to new range (e.g., 67620, 67860)
4. When `collectFees()` is called, it attempts to collect from non-existent range (67680, 67860)
5. The transaction reverts with "NP" (No Position), failing to collect fees from the actual vesting position range

### Impact

The liquidity providers suffer a permanent loss of fees accrued in their vesting position's original tick range (67680, 67920). These fees become permanently locked in the pool as the contract can never collect them due to using the wrong tick range.

contract VestingRangeBugTest is BaseTest {

        super.setUp();
    }

    function test_vestingRangeBug() public {
        // 1. First create a vesting position
        vm.startPrank(owner);
        deal(address(wbtc), owner, 2e8);
        deal(address(usdc), owner, 100_000e6);

        wbtc.approve(vault, type(uint256).max);
        usdc.approve(vault, type(uint256).max);

        // Get current pool price and ticks
        (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();
        IStrategy.Position memory mainPos = IStrategy(strategy).getMainPosition();

        int24 originalUpper = mainPos.tickUpper;
        
        emit log_named_string("Step", "Creating vesting position");
        emit log_named_int("Original Main Lower Tick", originalLower);
        emit log_named_int("Original Main Upper Tick", originalUpper);
        
        // Add vesting position
        IVault(vault).addVestingPosition(2e8, 100_000e6, 1 days);
        vm.stopPrank();
        
        // Verify vesting position was created with correct ticks
        IStrategy.VestingPosition memory vestPos = IStrategy(strategy).getVestingPosition();
        assertEq(vestPos.tickLower, originalLower, "Vesting position should have original lower tick");
        assertEq(vestPos.tickUpper, originalUpper, "Vesting position should have original upper tick");
        
        emit log_named_string("Step", "Vesting position created");
        emit log_named_int("Vesting Lower Tick", vestPos.tickLower);
        emit log_named_int("Vesting Upper Tick", vestPos.tickUpper);
        
        // Do larger swaps to generate fees and move price significantly
        vm.startPrank(depositor);
        deal(address(wbtc), depositor, 100e8);
        deal(address(usdc), depositor, 1_000_000e6);
        wbtc.approve(uniRouter, type(uint256).max);
        usdc.approve(uniRouter, type(uint256).max);
        
        emit log_named_string("Step", "Performing swaps to generate fees and move price");

        swapWbtc(50e8);
        skip(1 minutes);
        swapUsdc(500_000e6);
        vm.stopPrank();
        
        // Record balances before fee collection
        (uint256 beforeBal0, uint256 beforeBal1) = IStrategy(strategy).balances();
        
        emit log_named_string("Step", "Triggering rebalance");
        // 2. Now trigger a rebalance to move the main position's ticks
        skip(6 minutes);
        vm.startPrank(rebalancer);
        IStrategy(strategy).rebalance();
        vm.stopPrank();
        
        // Get the new main position ticks
        IStrategy.Position memory newMainPos = IStrategy(strategy).getMainPosition();
        assertTrue(newMainPos.tickUpper != originalUpper, "Main position ticks should have changed");
        
        emit log_named_string("Step", "After rebalance");
        emit log_named_int("New Main Lower Tick", newMainPos.tickLower);
        emit log_named_int("New Main Upper Tick", newMainPos.tickUpper);
        
        // 3. Now collect fees - this will fail due to wrong tick range
        emit log_named_string("Step", "Attempting to collect fees (will fail)");

        emit log_named_string("Expected Error", "Will revert with 'NP' (No Position) when trying to collect from non-existent position range");
        
        vm.startPrank(rebalancer);

        vm.stopPrank();
        
        emit log_named_string("Result", "Test passed - vulnerability confirmed");
        emit log_named_string("Impact", "Fees from vesting positions may be lost due to collecting from wrong tick range");
    }

### Mitigation

Replace `mainPosition.tickUpper` with `vestPosition.tickUpper` in the `collectFees()` function:
```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
}
```
