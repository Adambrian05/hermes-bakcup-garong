# Division Before Multiplication in Token Value Calculation Causes Precision Loss Leading to Undervalued Positions and Incorrect Liquidations

## Summary
The `_calculateTokenValues` function in the Leverager contract performs [division before multiplication when calculating the USD value of tokens without a price feed](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L445-L447). This causes significant precision loss, resulting in undervalued positions, reduced protocol fees, and potentially incorrect liquidation decisions. The issue specifically occurs in the calculation for token1 when it doesn't have a direct price feed.

## Vulnerability Details
In the `_calculateTokenValues` function, when token1 doesn't have a price feed (i.e., `chPrice1 == 0`), the contract uses the TWAP price to convert token1 to token0 and then calculates its USD value:

```solidity
else if (chPrice1 == 0) {
    usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
}
```

The calculation divides `amount1 * PRECISION` by `price` before multiplying by `chPrice0`. This division-before-multiplication pattern causes precision loss due to Solidity's integer division, which truncates any decimal portion.

For example, if:
- `amount1 = 1e18` (1 token with 18 decimals)
- `PRECISION = 1e30`
- `price = 2e30` (token0/token1 price)
- `chPrice0 = 1000e18` ($1000 per token0)
- `decimals0 = 1e18`

The current calculation would be:
1. `1e18 * 1e30 / 2e30 = 0.5e18` (truncated to `0` due to integer division)
2. `0 * 1000e18 / 1e18 = 0`

The correct calculation should be:
1. `1e18 * 1e30 * 1000e18 / 2e30 / 1e18 = 500e18` ($500)

This precision loss affects multiple critical functions:
1. `openLeveragedPosition`: Undervalues the initial collateral
2. `liquidatePosition`: Calculates lower protocol fees
3. `isLiquidateable`: May incorrectly flag positions as liquidatable

## Impact Details
This precision loss causes positions to be significantly undervalued, especially for tokens without direct price feeds. Undervalued positions lead to reduced borrowing capacity for users, lower protocol fees during liquidations, and increased risk of incorrect liquidations. In extreme cases, positions might be liquidated when they should remain solvent, causing direct financial loss to users.

## Tools Used
Manual

## Recommendations
Reorder the arithmetic operations to perform multiplications before divisions to minimize precision loss:

```solidity
else if (chPrice1 == 0) {
    usdValue += (amount1 * PRECISION * chPrice0) / price / decimals0;
}
```

This change ensures that the highest possible precision is maintained throughout the calculation, providing accurate token valuations for all protocol operations.
