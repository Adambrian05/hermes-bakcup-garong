# Unchecked Borrow Cap Vulnerability in Leverager

### Summary

The [`_checkWithinlimits`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L459) function in the Leverager contract uses an initial borrowed USD value for leverage checks, failing to account for dynamic asset price changes that could lead to systemic over-leveraging.

### Root Cause

In `Leverager.sol`, the borrow cap validation relies on the initial borrowed USD value:

```solidity
require(
    up.initBorrowedUsd <= vp.maxUsdLeverage,
    "too high borrow usd amount"
);
```


### Internal Pre-conditions

1. Borrow cap set for the vault
2. Initial position within stated limits
3. Significant price volatility possible

### External Pre-conditions

1. Price oracle provides real-time updates
2. Sufficient market liquidity
3. Notable price divergence potential

### Attack Path

1. Open a leveraged position near maximum borrow cap
2. Wait for borrowed asset price to drop
3. Exploit static USD valuation
4. Maintain position despite over-leveraging
5. Increase protocol's systemic risk

### Impact

- Positions remain over-leveraged
- Increased protocol insolvency risk
- Potential for catastrophic liquidation failures
- Undermines risk management controls

### PoC

```solidity
function test_borrowCapExploitation() public {
    vm.startPrank(owner);
    ILeverager(leverager).changeVaultMaxBorrow(vault, 50_000e18);

    vm.startPrank(depositor);
    ILeverager.LeverageParams memory lp;
    lp.amount0In = 0.5e8;
    lp.amount1In = 50_000e6;
    lp.vault0In = 1e8;
    lp.vault1In = 100_000e6;
    lp.vault = vault;
    lp.maxBorrowAmount = 50_000e18;
    lp.denomination = address(wbtc);

    deal(address(wbtc), depositor, 0.5e8);
    deal(address(usdc), depositor, 50_000e6);
    wbtc.approve(leverager, type(uint256).max);
    usdc.approve(leverager, type(uint256).max);

    uint256 initialWbtcPrice = 30_000e18;
    MockOracle(wbtcOracle).setPrice(initialWbtcPrice);

    uint256 posId = ILeverager(leverager).openLeveragedPosition(lp);

    uint256 initialBorrowedUsd = ILeverager(leverager).getPosition(posId).initBorrowedUsd;
    assertLe(initialBorrowedUsd, 50_000e18, "Initial borrow within cap");

    MockOracle(wbtcOracle).setPrice(10_000e18);

    uint256 currentBorrowedUsdValue = ILeverager(leverager).getPosition(posId).borrowedAmount 
        * IPriceFeed(priceFeed).getPrice(address(wbtc)) 
        / (10 ** ERC20(lp.denomination).decimals());

    assertTrue(currentBorrowedUsdValue > 50_000e18, "Actual borrowed USD exceeds cap after price drop");

    Position memory position = ILeverager(leverager).getPosition(posId);
    assertFalse(
        ILeverager(leverager).isLiquidateable(posId), 
        "Position should remain non-liquidatable despite over-leverage"
    );
}
```

### Mitigation

- Add dynamic liquidation triggers
- Continuously validate position against current market prices
- Enhance collateralization ratio monitoring
