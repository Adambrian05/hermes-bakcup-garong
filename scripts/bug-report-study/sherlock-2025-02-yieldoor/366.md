# Malicious User can prevent burning id by withdrawing pct Small positions

## Summary
The `withdraw function` allows users to withdraw a portion of their leveraged position. However, a malicious user can `repeatedly withdraw small amounts (just above the 0.01e18 threshold) to avoid triggering full liquidation and ID burning`. This manipulation can allow them to keep a low-value position open indefinitely, potentially bypassing liquidation mechanisms and increasing protocol risk. `This is caused due to lack of update during withdrawals the wp.pct is not tracked`.
https://vscode.dev/github/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L270-273

The function allows users to withdraw a percentage (pctWithdraw) of their position, with a minimum of 0.01e18 (1%) and a maximum of 1e18 (100%).If pctWithdraw == 1e18, the position is fully closed, the borrowed amount is repaid, and the ID is burned.However, if a user repeatedly withdraws amounts just under 1e18, they can maintain a minimal position, preventing automatic ID removal.
## Impact
exploiting borrowed positions
## Recommended Mitigation
Tract amounts of pct withdrawn
