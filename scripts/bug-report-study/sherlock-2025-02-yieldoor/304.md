# Leverager#withdraw use the wrong repayFromWithdraw when `borrowed == up.token1`

### Summary

When borrowed token == up.token1, repayFromWithdraw may be assigned with the wrong value (amountOut0 instead of amountOut1), which may lead to revert due to integer underflow.

### Root Cause

Code mistake where amountOut0 is used.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232

```solidity
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount; //@@@audit: amountOut1
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```

### Internal Pre-conditions

1. borrowed == up.token1

### External Pre-conditions

1. User calls `withdraw` and amountOut1 < owedAmount.

### Attack Path

None

### Impact

1. DOS: amountOut0 maybe greater than owedAmount or amountOut1
2. Unintended functionality, token1(amountOut1) is not fully used for repaying. 

### PoC

_No response_

### Mitigation

Use amountOut1 instead of amountOut0.
