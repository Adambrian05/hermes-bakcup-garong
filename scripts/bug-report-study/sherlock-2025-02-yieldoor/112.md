# Decreasing vault's max leverage parameter enables immediate liquidation of healthy positions

## Summary
The `Leverager#changeVaultMaxLeverage` function allows the owner to decrease a vault's maximum leverage, which can make previously healthy positions immediately liquidatable due to how the liquidation threshold is calculated.

## Relevant Context
The `isLiquidateable` function uses `maxTimesLeverage` to calculate a base collateral value that determines the liquidation threshold. A position becomes liquidatable if its collateral falls below `minCollateralPct` of this base value.

## Root Cause
The `changeVaultMaxLeverage` function allows reducing the `maxTimesLeverage` parameter without any checks on existing positions. Since this parameter is used in `isLiquidateable` to calculate the minimum required collateral, lowering it increases the base collateral requirement for all positions in that vault. This can make previously healthy positions immediately eligible for liquidation, even though their actual collateral ratio hasn't changed.

## Attack Path

1. Users open leveraged positions in a vault with `maxTimesLeverage` set to 3x
2. The positions maintain healthy collateral ratios based on the initial parameters
3. Owner calls `changeVaultMaxLeverage` to decrease `maxTimesLeverage` to 1.5x
4. The base collateral calculation in `isLiquidateable` now uses the new lower leverage limit:
   ```solidity
   uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
   ```
5. This results in a higher base value, making positions liquidatable even if their actual collateral ratio hasn't deteriorated

## Impact Explanation
Medium. This allows immediate forced liquidation of user positions that were opened under different parameters and are maintaining their originally required collateral ratios. Users can suffer significant losses through no fault of their own, as liquidations typically result in losses due to slippage and liquidation fees.

## Proof of Concept
1. Alice opens a position with 2.5x leverage when `maxTimesLeverage` is 3x
2. Her position maintains required collateral ratio based on initial parameters
3. Owner decreases `maxTimesLeverage` to 1.5x
4. Alice's position becomes immediately liquidatable because:
   - Original base = borrowedAmount * 1e18 / (3e18 - 1e18) = borrowedAmount/2
   - New base = borrowedAmount * 1e18 / (1.5e18 - 1e18) = 2 * borrowedAmount
   - Required collateral threshold quadruples, making position liquidatable

## Recommendation
Add protection for existing positions when decreasing `maxTimesLeverage`:

```diff
function changeVaultMaxLeverage(address vault, uint256 maxLeverage) external onlyOwner {
    VaultParams storage vp = vaultParams[vault];
+   require(maxLeverage >= vp.maxTimesLeverage, "Cannot decrease max leverage");
    vp.maxTimesLeverage = maxLeverage;
}
```

Alternatively, implement a time-delayed decrease that gives users time to adjust their positions.
