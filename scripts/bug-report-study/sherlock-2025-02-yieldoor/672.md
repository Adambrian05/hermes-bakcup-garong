# Incorrect Collateral Calculation Due to Decimal Mismatch


## Description

The **`_calculateTokenValues`** function in the `Leverager` contract improperly handles token decimal mismatches when computing **`initCollateralValue`**. This issue arises from the assumption that Chainlink price feeds return values in the same decimal precision as the underlying tokens.

## **Root Cause**

The problem stems from how **`usdValue`** is calculated:

```solidity
usdValue += amount0 * chPrice0 / decimals0;
.
.
usdValue += amount1 * chPrice / decimals0;
```

### Key Issues:
1. **Precision Mismatch:**
   - Chainlink price feeds typically return **8-decimal** values, whereas token amounts can have varying precisions (e.g., **18 decimals for DAI** and **6 decimals for USDC**).
   - This discrepancy results in incorrect **usdValue** calculations.

2. **Collateral Underreporting:**
   - When a low-decimal token (e.g., **USDC**) is used, the calculated **initCollateralValue** is **undervalued**.
   - This allows positions to be opened with **less collateral** than required, increasing the risk of **bad debt**.

## **Proof of Concept**

### Simulation Overview:
We tested two scenarios—one using a **18-decimal** token (DAI) and another using a **6-decimal** token (USDC). Both were priced at **$1.00 (8 decimals)** from Chainlink.

### Case 1: 18-Decimal Token (DAI)
- **Input:**
  - Token Amount = 100 DAI (18 decimals)
  - Chainlink Price = $1.00 (8 decimals)
  - Borrowed Token = 18 decimals
- **Result:**
  - `usdValue`: 10,000,000,000 ($100)
  - `initCollateralValue`: 100,000,000,000,000,000,000 ($100)

✅ **Correct Calculation**

---

### Case 2: 6-Decimal Token (USDC)
- **Input:**
  - Token Amount = 100 USDC (6 decimals)
  - Chainlink Price = $1.00 (8 decimals)
  - Borrowed Token = 18 decimals
- **Result:**
  - `usdValue`: 10,000,000,000 ($100)
  - `initCollateralValue`: 100,000,000,000,000,000,000 ($100)

❌ **Incorrect Calculation** – **Overvalues Collateral**

---

## **Impact**

1. **Underreporting Collateral for Low-Decimal Tokens:**
   - Attackers can exploit this flaw by using **low-decimal tokens** (e.g., **6-decimal** USDC) to **inflate collateral values**, leading to **overleveraging** and the creation of **bad debt** in the system.

2. **Incorrect Liquidation Checks:**
   - Since **initCollateralValue** underestimates the true collateral amount, some positions may **avoid liquidation** even when they are **underwater**.

---

## **Recommended Mitigation Steps**

### **Normalize Token Decimals:**
Ensure that **usdValue** is always calculated with the correct precision by **scaling the Chainlink price** to **match the token decimals**. Here’s the corrected formula:

```solidity
// Normalize usdValue calculation to correct decimals
usdValue += (amount0 * chPrice0 * PRECISION) / (decimals0 * 10**8);
usdValue += (amount1 * chPrice1 * PRECISION) / (decimals1 * 10**8);
```
