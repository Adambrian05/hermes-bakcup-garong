# Missing Slippage Protection in `Leverager::openLeveragedPosition`

### Summary

In [`Leverager::openLeveragedPosition`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L103), the `exactOutput` swap parameters do not validate the actual input tokens used against the user-specified `amountInMaximum`. This allows MEV bots to front-run swaps, forcing users to overpay for tokens and making leveraged positions unprofitable. Attackers can steal up to 100% of the borrowed funds through sandwich attacks.

### Root Cause

In [`Leverager.sol`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol), the code performs swaps via `exactOutput` but does not verify if the actual `amountIn` used is ≤ `amountInMaximum` from user parameters. This violates the invariant that users should never pay more than their specified maximum.

### Internal Pre-conditions

1. User calls `Leverager::openLeveragedPosition` with `swapParams1` or `swapParams2` containing `ExactOutputParams.amountInMaximum`  
2. Attacker observes transaction in mempool  

### External Pre-conditions

1. Uniswap pool liquidity must be sufficient to execute the swap  
2. Gas price must be high enough for front-running  

### Attack Path

1. User submits `openLeveragedPosition` with valid `amountInMaximum`  
2. MEV bot front-runs the transaction, manipulating pool prices  
3. Swap consumes more input tokens than `amountInMaximum`  
4. User's collateral is drained to pay for overpriced swap  

### Impact

- **Affected Party**: Position openers  
- **Loss**: Up to 100% of swapped tokens  
- **Attacker Gain**: Stolen tokens from inflated swap prices  


### PoC

```solidity
function test_SwapSlippageAttack() public {
    vm.startPrank(depositor);
    
    ILeverager.LeverageParams memory lp;
    lp.denomination = address(wbtc);
    lp.maxBorrowAmount = 1e8; 
    lp.swapParams1 = _createMaliciousSwapParams(0.5e8); 

    uint256 preWbtcBalance = wbtc.balanceOf(depositor);
    ILeverager(leverager).openLeveragedPosition(lp);
    
    uint256 postWbtcBalance = wbtc.balanceOf(depositor);
    assertLt(postWbtcBalance, preWbtcBalance - 0.5e8); 
}

function _createMaliciousSwapParams(uint256 maxIn) internal pure returns (bytes memory) {
    IMainnetRouter.ExactOutputParams memory ep;
    ep.amountInMaximum = maxIn; // User's intended limit
    ep.path = abi.encodePacked(address(usdc), uint24(3000), address(wbtc));
    return abi.encode(ep);
}
```

### Mitigation

Add input validation after swaps:
```solidity
// In Leverager::openLeveragedPosition
uint256 balanceBefore = IERC20(tokenIn).balanceOf(address(this));
IMainnetRouter(swapRouter).exactOutput(swapParams);
uint256 actualSpent = balanceBefore - IERC20(tokenIn).balanceOf(address(this));
require(actualSpent <= swapParams.amountInMaximum, "Slippage exceeded");
```
