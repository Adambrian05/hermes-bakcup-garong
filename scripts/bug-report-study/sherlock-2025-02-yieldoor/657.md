# Leverage limit can be bypassed

### Summary

Users can create leveraged positions more than the desired amount due to how leverage is calculated. 

### Root Cause

The leverage concept is not accounting how much user put and how much borrowed correctly. 
A user can put smaller amount of funds from its balance and borrow the rest up to more than the leveraged amount due to how liquidations and the leverage is calculated. 
https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L411

### PoC



**Textual PoC:**
Let's say a user wants to LP in a WBTC-USDC pool. They want to LP 1 WBTC and 100K USDC. If 1 WBTC is $100K and 1 USDC is $1, the user needs to borrow around $200K worth of ETH.

If 1 ETH is $2500 and we assume perfect swaps (though not realistic), the user's total collateral balance will be 80 ETH.

The amount borrowed must follow this equation:
`totalDenom - owedAmount < vp.minCollateralPct * base / 1e18`

If vp.minCollateralPct is 0.1 (as in tests), the actual leverage increases dramatically. For example in a 5x leverage market, if a user only puts in 5000 USDC from their pocket, they'd need $195K worth of ETH to pay the flashloaned WBTC and USDC - about 78 ETH.

Calculating the base:
```solidity
uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
```

78 * (5-1) = 19.5
Then multiplying by 0.1:
19.5 * 0.1 = 1.95 ETH. This means the user can put in just 1.95 ETH and have a collateral value of 80 ETH!
