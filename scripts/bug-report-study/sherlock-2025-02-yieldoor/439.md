# The `LendingPool.setBorrowingRateConfig` function does not update the state and the interest rate of the reserve

### Summary
In the `LendingPool.setBorrowingRateConfig` function, it does not call the `reserve.updateState()` and `reserve.updateInterestRates()`.
As a result, this will cause incorrect calculation of the exchange Rate from yToken to reserve liquidity.

### Root Cause
In `ReserveLogic:updateState()`, it calculates the borrow interest accured from last update time to current timestamp. The latest borrow index's calculation is related with borrowing rate.

```solidity
        function updateState(DataTypes.ReserveData storage reserve) internal {
            _updateIndexes(reserve);
        }
        function _updateIndexes(DataTypes.ReserveData storage reserve) internal {
            uint256 newBorrowingIndex = reserve.borrowingIndex;
            uint256 newTotalBorrows = reserve.totalBorrows;

            if (reserve.totalBorrows > 0) {
                newBorrowingIndex = latestBorrowingIndex(reserve);
                newTotalBorrows = newBorrowingIndex * (reserve.totalBorrows) / (reserve.borrowingIndex);

                require(newBorrowingIndex <= type(uint128).max);

                reserve.borrowingIndex = newBorrowingIndex;
                reserve.totalBorrows = newTotalBorrows;
            }
            reserve.lastUpdateTimestamp = uint128(block.timestamp);
        }
```
```solidity
    function reserveToYTokenExchangeRate(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
        (uint256 totalLiquidity,) = totalLiquidityAndBorrows(reserve);
        uint256 totalYTokens = IERC20(reserve.yTokenAddress).totalSupply();

        if (totalYTokens == 0 || totalLiquidity == 0) {
            return PRECISION;
        }
        return totalYTokens * PRECISION / totalLiquidity;
    }
```

The problem is that when admin update borrowing rate config via setBorrowingRateConfig(), it doesn't update the borrow interest accured from last update to current timestamp.
In the [`LendingPool.setBorrowingRateConfig`](https://github.com/sherlock-audit/2025-02-yieldoor/tree/main/yieldoor/src/LendingPool.sol#L348) function, it does not call the `reserve.updateState()` and `reserve.updateInterestRates()`.
```solidity
    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    }
```
This will cause the incorrect borrow interest fee.

### Internal pre-conditions
None

### External pre-conditions

1. None

### Attack Path
Let's consider the following scenario:
- `reserve.lastUpdateTimestamp` is `time1` and `reserve.currentBorrowingRate` is `rate1`.
- In timestamp of `time1 + 100`, the admin updates the borrow rate config.
- When Alice deposits in timestamp `time1 + 200`, the `deposit` function calculates the borrow interest between timestamp of `time1` and `time1 + 200` with the previous borrow rate calculated by the previous borrow rate config. This will cause the borrow rate calculated incorrectly.

### Impact
The borrow interest is calculated incorrectly and this will cause the loss of funds to protocol or users.

### PoC
None

### Mitigation
```diff
    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
+       reserve.updateState();
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
+       reserve.updateInterestRates();
    }
```
