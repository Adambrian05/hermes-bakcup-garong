# Improper Validation of Parameters in setBorrowingRateConfig

### Summary

The lack of parameter validation in setBorrowingRateConfig will cause an invalid interest rate model for borrowers as incorrect utilization and borrowing rate values can create unintended or unstable borrowing conditions.

### Root Cause

The function setBorrowingRateConfig does not validate that:

utilizationA < utilizationB

borrowingRateA < borrowingRateB < maxBorrowingRate

utilization values are <= 10000 (100%)

If incorrectly set, the interest rate curve may behave erratically, allowing lower interest rates at higher utilizations or abrupt interest rate jumps.

### Internal Pre-conditions

The owner calls setBorrowingRateConfig(...) with arbitrary parameters.

The function updates borrowingRateConfig without ensuring logical constraints are met.

Borrowers interact with the protocol using an incorrectly configured interest rate model.

### External Pre-conditions

No external function verifies that the interest rate parameters conform to expected logic.

The protocol does not enforce constraints through governance checks before setting parameters.

### Attack Path

The owner (or a compromised admin key) sets invalid parameters in setBorrowingRateConfig.

Borrowers experience incorrect interest rate behavior, such as higher utilization leading to lower interest rates or sudden jumps in borrowing costs.

Users may take advantage of mispriced borrowing rates, leading to an unstable lending market.

The protocol may suffer from liquidity imbalances or capital inefficiencies due to unpredictable borrowing incentives.

### Impact

Incorrect borrowing rate configurations can destabilize the protocol’s lending mechanics, leading to exploitative borrowing conditions, liquidity imbalances, and financial losses for lenders and depositors.
