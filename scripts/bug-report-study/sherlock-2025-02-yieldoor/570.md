# Protocol will not receive fees from vesting position

### Summary

Per the code, `Strategy.collectFees()` is expected to collect accumulated fees from all 3 positions: 
```solidity
if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper); 
        }
```
But after rebalancing main position, fees from vesting position cannot be collected using `collectPositionFees()`, because the function uses different ticks.

### Root Cause

[Link](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L166-L168)

During creation of Vesting position the same ticks as main position's ticks are used:

```solidity
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;

        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;
//...
        IUniswapV3Pool(pool).mint(address(this), vp.tickLower, vp.tickUpper, liquidity, "");
```
And this is not a problem until outstanding position fees can be collected and claimed by `feeRecipient`. But after rebalancing, main position's ticks will be updated, and vesting position's ticks will remain unchanged. The issue is function `collectPositionFees()` uses `tickLower` from `vestPosition` mapping, but `tickUpper` is taken from updated `mainPosition` mapping:

```solidity
if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper); 
        }
```

This is incorrect, because position with this ticks does not exists anymore - rebalancing creates new main position.  Every position is uniquely identified by first 3 params in  `IUniswapV3Pool(pool).mint()`:
>Each position is uniquely identified by three keys: owner address, lower tick index, and upper tick index. We hash the three to make storing data cheaper: when hashed, every key will take 32 bytes, instead of 96 bytes when owner, lowerTick, and upperTick are separate keys. 
https://uniswapv3book.com/milestone_1/providing-liquidity.html#:~:text=Each%20position%20is,is%20not%20applied).

So basically after rebalancing main and vesting positions will have different ticks, and protocol will not be able to collect fees from vesting position - all fees will be sent to strategy instead of 91% to strategy and 9% to `feeRecipient`, because `_withdrawPartOfVestingPosition` will send vested part + accumulated fees to Strategy, and this fees will not be accounted in `afterBal0 - preBal0`.

### Internal Pre-conditions

Rebalance must be called during ongoing vesting position.

### External Pre-conditions

 `IUniswapV3Pool(pool).slot0()` must return defferent tick that that tick that was usen in previous `rebalance` call.

### Attack Path

1. Rebalancer creats main and secondary positions with this ticks:
```solidity
mainPosition.tickLower = 84222;
mainPosition.tickUpper = 86129;

secondaryPosition.tickLower = 84222;
secondaryPosition.tickUpper = 87142;
```
2. Owner adds vesting position, that will always have the same ticks as current main position's ticks:
```solidity
vp.tickLower = mainPosition.tickLower = 84222;
vp.tickUpper = mainPosition.tickUpper = 86129;
```
3. Rebalancer calls `rebalance` and main position's ticks was changed:
```solidity
mainPosition.tickLower = 83224;
mainPosition.tickUpper = 85299;
```
4. `collectPositionFees()` will try to collect fees from vesting position using only 1 correct tick - `tickLower`:
```solidity
if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);  
            // vestPosition.tickLower = 84222, mainPosition.tickUpper = 85299
            //position with ticks 84222 and 85299 does not exists
        }
```

### Impact

Protocol will lose 9% of profit from vesting position.

### Mitigation

When claiming fees, use the actual ticks of vesting position:
```diff
if (ongoingVestingPosition) {
-           collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+           collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);  
        }
```
