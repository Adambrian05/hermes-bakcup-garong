# Incorrect repayment calculation when withdrawing and the borrowed token is `token1`

### Summary

When the user wants to withdraw from his position and repay the owed debt he calls `Leverager::withdraw`.

```solidity
function withdraw(WithdrawParams calldata wp) external nonReentrant {
        Position memory up = positions[wp.id];
        require(_isApprovedOrOwner(msg.sender, wp.id), "msg.sender not approved or owner");
        require(wp.pctWithdraw <= 1e18 && wp.pctWithdraw > 0.01e18, "invalid pctWithdraw");

        address borrowed = up.denomination;
        uint256 sharesToWithdraw = up.shares * wp.pctWithdraw / 1e18;

        (uint256 amountOut0, uint256 amountOut1) =
            IVault(up.vault).withdraw(sharesToWithdraw, wp.minAmount0, wp.minAmount1);

        uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(borrowed);
        uint256 totalOwedAmount = up.borrowedAmount * bIndex / up.borrowedIndex;
        uint256 owedAmount = totalOwedAmount * wp.pctWithdraw / 1e18;

        uint256 amountToRepay = owedAmount; // this should be transferred to yAsset

        // In case either of the tokens is denomination token, we directly take from it.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }

....
        }
    }
```

If the user has borrowed one of the tokens he holds in the position, his amount will be deducted directly from the withdrawn amount.

However, when `borrowed == up.token1`, and `amountOut1 < owedAmount`, we are setting it to `amountOut0` instead of `amountOut1`.

Below we are trying to deduct `repayFromWithdraw` from `amountOut1`, which could cause underflows in the situations where `amountOut0` is greater than `amountOut1`.

### Root Cause

Incorrect setting of [repayFromWithdraw](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232), when the borrowed token is `token1`.

### Internal Pre-conditions

1. User has to have borrowed `token1`.

### External Pre-conditions

None

### Attack Path

1. User has a position of:
- `1e18` WETH (token0)
- `0.003e8` WBTC (token1)
- He owes `0.0035e8` due to some interest being accumulated
- When he tries to withdraw `repayFromWithdraw` is set to `1e18`, since `0.003e8` is less than `0.0035e8`.
- When trying to deduct from `amountOut1` it reverts due to underflow.

### Impact

Any user that has borrowed `token1`, will not be able to withdraw his position, until `amountOut1`, becomes more than `owedAmount`. 

### PoC

_No response_

### Mitigation

Consider replacing `amountOut0`, with `amountOut1`.

```diff
 if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
-           uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+           uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```
