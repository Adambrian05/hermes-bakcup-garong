# Stale Borrowing Index in Leverager::withdraw Leads to Incorrect Debt Calculations and Repayment Amounts

## Summary
The `Leverager::withdraw` function retrieves the[ current borrowing index from the LendingPool](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L220) contract without ensuring the lending pool's state is updated first. This results in calculations based on stale data, causing users to potentially repay incorrect debt amounts when partially withdrawing from leveraged positions.

## Vulnerability Details
In the LendingPool contract, the borrowing index (which tracks interest accrual) is only updated when the `updateState()` function is called. This function is automatically called at the beginning of state-changing functions like `_deposit`, `_redeem`, `borrow`, and `repay`, but not when read-only functions like `getCurrentBorrowingIndex()` are called.

The issue occurs in the following sequence:
1. `Leverager::withdraw` calls `ILendingPool(lendingPool).getCurrentBorrowingIndex(borrowed)`
2. `getCurrentBorrowingIndex()` returns a value based on the last time `updateState()` was called
3. The index is always stale because `updateState()` is only called at the beginning of state-changing functions, not after they complete
4. The stale index is used to calculate `totalOwedAmount`, `owedAmount`, and other critical values

This pattern creates a discrepancy between:
- What users actually owe (based on the current time)
- What the contract calculates they owe (based on the last state update)

```ascii
	Leverager                          LendingPool
	    |                                  |
	    |---getCurrentBorrowingIndex()---->|
	    |                                  | ❌ State is stale since updateState() 
	    |                                  |    was only called before previous 
	    |                                  |    state changes, not after
	    |<-----returns stale index---------|
	    |                                  |
	    |---calculate debt with stale------|
	    |     index                        |
	    |                                  |
	    |---repay()----------------------->|
	    |                                  | ✅ updateState() called here
	    |                                  | (too late - already calculated
	    |                                  |  repayment with stale data)
```


**Note:**
There is another instance of this issue in [`liquidatePosition`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L304) and [`isLiquidateable`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L403), where positions can be incorrectly liquidated.

## Proof of Concept
Consider this scenario:
1. A user opens a leveraged position with 10 ETH borrowed at index 1.0
2. Some time passes and interest accrues
3. The actual current index should be 1.05 (5% interest accrued)
4. User calls `withdraw()` with `pctWithdraw = 0.5e18` (50%)
5. `getCurrentBorrowingIndex()` returns 1.0 instead of 1.05 because the state hasn't been updated since the last operation
6. `totalOwedAmount` is calculated as `10 ETH * 1.0 / 1.0 = 10 ETH` (should be 10.5 ETH)
7. `owedAmount` is calculated as `10 ETH * 0.5 = 5 ETH` (should be 5.25 ETH)
8. User repays 5 ETH instead of 5.25 ETH, underpaying by 0.25 ETH

## Impact Details
This vulnerability leads to incorrect debt calculations, causing users to either underpay or overpay when withdrawing from leveraged positions. Underpayment benefits users at the expense of the protocol, while overpayment harms users. The impact is systematic and affects every withdrawal operation, potentially resulting in significant accounting errors that accumulate over time as interest accrues between operations.

## Tools Used
Manual

## Recommendations
Add the updateState() call in  `getCurrentBorrowingIndex` before returning the reserve.borrowingIndex

```diff
function getCurrentBorrowingIndex(address asset) external nonReentrant returns (uint256) {
    DataTypes.ReserveData storage reserve = getReserve(asset);
+    reserve.updateState();
    return reserve.borrowingIndex;
}
```
