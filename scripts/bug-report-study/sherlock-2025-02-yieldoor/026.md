# Wrong variable usage upon withdrawing, resulting in unexpected results

### Summary

Wrong variable usage upon withdrawing, resulting in unexpected results

### Root Cause

Upon withdrawing from `Leverager`, we have the following code:
```solidity
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```
The issue is that if the borrowed token is `token1`, then we incorrectly set `repayFromWithdraw` to `amountOut0` instead of `amountOut1`.

### Internal Pre-conditions

1. `borrowed` token is `token1` and the amount received from that token after the withdrawal is less than the `owedAmount`, pretty much no constraint

### External Pre-conditions

_No external pre-conditions_

### Attack Path

1. A withdrawal occurs giving us 160 tokens of `token0` and 100 tokens of `token1`
2. The owed amount is 150 tokens and the `borrowed` token is `token1`
3. `repayFromWithdraw` will incorrectly give us 160 (`100 < 150 ? 160 (amountOut0) : ...`)
4. Upon the deduction, we will underflow and revert (`150 - 160`)
5. Withdrawal won't be possible

### Impact

Different impacts such as the inability to close a position

### PoC

_No response_

### Mitigation

```diff
+ uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
- uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```
