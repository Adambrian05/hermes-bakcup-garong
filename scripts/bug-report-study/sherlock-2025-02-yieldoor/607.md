# High-Severity Gas Limit Issue in Yieldoor's Leverager Contract

### Summary

The `test_fundsLockDueToGasLimit` test failure reveals a critical gas exhaustion vulnerability in the Yieldoor protocol's `Leverager` contract. The function execution consumes excessive or unbounded gas, leading to an `EvmError: OutOfGas` or `EvmError: Revert`. This could result in funds being locked, failed liquidations, and protocol instability under specific conditions.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L98-L201

### Root Cause

In `Leverager::openLeveragedPosition`, the function call is giving the `EvmError: OutOfGas`.
```solidity
Leverager::openLeveragedPosition(LeverageParams({ 
    amount0In: 50000000 [5e7], 
    amount1In: 100000000000 [1e11], 
    vault0In: 100000000 [1e8], 
    vault1In: 100000000000 [1e11], 
    min0in: 0, 
    min1in: 0, 
    vault: 0x7df69408E5AFa164E16DA08E0fB243B90f488feC, 
    denomination: 0x2260FAC5E5542a773Aa44fBCfeDf7C193bc2C599, 
    maxBorrowAmount: 60000000 [6e7], 
    swapParams1: 0x, 
    swapParams2: 0x 
}))
```
The test is given below in `Leverager.t.sol`
```solidity
function test_fundsLockDueToGasLimit() public {
    // Set up depositor's balance
    deal(address(wbtc), depositor, 50_000_000); // 0.5 WBTC
    deal(address(usdc), depositor, 100_000_000_000); // 100,000 USDC

    vm.startPrank(depositor);

    // Approve max spend for Leverager
    wbtc.approve(leverager, type(uint256).max);
    usdc.approve(leverager, type(uint256).max);

    // Set low gas limit
    uint256 lowGasLimit = 10_000; // Simulating gas exhaustion
    vm.expectRevert("Out of gas");

    // Try opening a leveraged position with a gas constraint
    ILeverager.LeverageParams memory lp;
    lp.amount0In = 50_000_000;
    lp.amount1In = 100_000_000_000;
    lp.vault0In = 100_000_000;
    lp.vault1In = 100_000_000_000;
    lp.min0in = 0;
    lp.min1in = 0;
    lp.vault = vault;
    lp.denomination = address(wbtc);
    lp.maxBorrowAmount = 60_000_000;

    // Calling openLeveragedPosition with low gas
    ILeverager(leverager).openLeveragedPosition{gas: lowGasLimit}(lp);

    vm.stopPrank();
}
```
The function might be iterating over a large data structure, such as vault positions or a liquidity pool, causing it to exceed the gas limit.



### Internal Pre-conditions

To trigger the `OutOfGas` error in `openLeveragedPosition()`, the following conditions must be met:

1. Insufficient Gas Allocation

The function requires more than 5,000,000 gas to execute successfully.
The test is executed with --gas-limit 5000000, which is insufficient for completing the logic.
Looping Over Large Data Structures

2. The function iterates over vault positions, liquidity pool positions, or swap parameters.
If the number of positions is too high, the loop exhausts available gas.

3. The function is handling large values:
amount1In = 1e11
vault1In = 1e11
maxBorrowAmount = 6e7
These values might trigger expensive storage updates or high computational costs during execution.
Revert in an External Contract Without Error Data

The error log shows:
```plaintext
[Revert] call reverted as expected, but without data
```
This suggests a silent failure in an external contract, which can happen when:
A low-level call (call(), delegatecall(), staticcall()) fails without bubbling up an error message.
The external contract does not handle unexpected conditions properly.

### External Pre-conditions

`Gas Price Volatility`

The test relies on a fixed gas limit (5,000,000).
If network gas prices spike, execution costs may increase unexpectedly, causing the transaction to fail.
Example condition:
Gas price increases to 300 gwei within 2 minutes.

### Attack Path

Preparation: Setting Up Conditions
Attacker ensures external conditions align (as described in External Pre-conditions)
Gas prices spike or liquidity in Uniswap is reduced.
Oracle manipulation causes abnormal gas consumption.
Vault contract state is altered (paused, delayed, or pending governance updates).

Attacker calls openLeveragedPosition() in Leverager contract

Uses specific LeverageParams where:
Large amounts of amount0In, amount1In, vault0In, vault1In are supplied.
High maxBorrowAmount is set, increasing computation requirements.

EVM throws an OutOfGas error, reverting the entire transaction.
Funds remain locked, as the contract logic does not properly handle partial executions.
Impact of Exploit
DoS Attack on Leverager Contract

Repeatedly triggering OutOfGas errors can prevent legitimate users from opening positions.
Denial of Funds Withdrawal

If funds are locked due to transaction failure, users cannot access their capital, leading to protocol instability.
