# Protocol fails to collect fees from the vesting position due to incorrect tick upper

### Summary

Wrong tick upper for the vesting position in `Strategy::collectFees` will cause uncollected Uniswap fees for the vesting position as the function attempts to collect from an incorrect tick range.

### Root Cause

- In [`Strategy::rebalance()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198), only the main position and secondary position are rebalanced (`_removeLiquidity` only removes the main position and secondary position liquidity, and not the vesting position liquidity.

- The vesting position retains its original tick range and does not get updated.

- In `Strategy::collectFees()` [`Strategy.sol::167`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167), the upper tick for the vesting position is incorrectly set to `mainPosition.tickUpper`, which has changed due to rebalancing and is no longer the same as `vestPosition.tickUpper`.

- Since Uniswap V3 identifies positions by their exact tick range, the vesting position will not be identified and fees cannot be collected from it, leading to a loss of accrued fees.

### Internal Pre-conditions

1. The protocol must have an active vesting position with a defined tick range.

2. The[ `Strategy::rebalance()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198) function must be executed, which updates `mainPosition.tickUpper` but does not update `vestPosition.tickUpper` to be the same as `mainPosition.tickUpper`.

### External Pre-conditions

1. The pool price must have changed, triggering a rebalance.

2. Uniswap V3 must have accumulated trading fees for the vesting position's tick range.

### Attack Path

1. The protocol rebalances its positions by calling `rebalance()`, which updates `mainPosition.tickUpper` but does not update `vestPosition.tickUpper`.

2. The protocol (or an external user) calls `collectFees()`.

3. The function attempts to collect fees from the vesting position using `collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper)`.

4. Since the tick upper is incorrect, Uniswap V3 does not recognize the position, returning zero fees.

5. The protocol loses out on all accrued fees from the vesting position.



### Impact

- The protocol suffers a loss of all fees generated by the vesting position, reducing yield for liquidity providers.

- There is no direct attacker gain, but the protocol suffers inefficiencies and reduced profitability.



### PoC

_No response_

### Mitigation

1. Update the vesting position's tick range when rebalancing: Modify `rebalance()` to also update `vestPosition.tickUpper` and `vestPosition.tickLower`.

or:

2. Ensure [`collectFees()` ](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159 )uses the correct tick values: Instead of `mainPosition.tickUpper`, use `vestPosition.tickUpper`: Modify [`collectPositionFees`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167) to:
```solidity
collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
```
