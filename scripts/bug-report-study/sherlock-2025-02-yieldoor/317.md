# Borrowing index not updated when total borrows is zero

## Description:
The `_updateIndexes()` function in `ReserveLogic` contract only updates the borrowing index when there are active borrows (`reserve.totalBorrows > 0`). However, it always updates the `lastUpdateTimestamp` regardless of whether there are active borrows:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/ReserveLogic.sol#L163
```solidity
function _updateIndexes(DataTypes.ReserveData storage reserve) internal {
    uint256 newBorrowingIndex = reserve.borrowingIndex;
    uint256 newTotalBorrows = reserve.totalBorrows;

    if (reserve.totalBorrows > 0) {
        newBorrowingIndex = latestBorrowingIndex(reserve);
        newTotalBorrows = newBorrowingIndex * (reserve.totalBorrows) / (reserve.borrowingIndex);

        require(newBorrowingIndex <= type(uint128).max);

        reserve.borrowingIndex = newBorrowingIndex;
        reserve.totalBorrows = newTotalBorrows;
    }
    reserve.lastUpdateTimestamp = uint128(block.timestamp);
}
```
This creates a situation where if all borrows are repaid, making `totalBorrows = 0`, and then new borrows are taken later, the interest that should have accrued during the period with zero borrows is lost. This happens because the `latestBorrowingIndex()` function calculates the new index based on the time elapsed since `lastUpdateTimestamp`, which was updated when borrows reached zero, rather than when the index was last updated.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/ReserveLogic.sol#L109
```solidity
    function latestBorrowingIndex(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
        if (reserve.lastUpdateTimestamp == uint128(block.timestamp)) {
            //if the index was updated in the same block, no need to perform any calculation
            return reserve.borrowingIndex;
        }

        return reserve.borrowingIndex
            * (InterestRateUtils.calculateCompoundedInterest(reserve.currentBorrowingRate, reserve.lastUpdateTimestamp))
            / (PRECISION);
    }
```

## Impact:
This vulnerability leads to:
- Loss of interest income for lenders during periods when all borrows are repaid and then new borrows are taken
- Unfair advantage for new borrowers who effectively get "interest-free" periods

For example, if a reserve has a 10% annual interest rate:
- At time T1: Active borrows exist, index = 1.0
- At time T2 (30 days later): All borrows are repaid, index remains at 1.0, lastUpdateTimestamp updated to T2
- At time T3 (60 days after T1): New borrows are taken
- The correct index at T3 should reflect 60 days of interest (approximately 1.0164), but due to this issue, it will only reflect 30 days of interest (approximately 1.0082), resulting in lenders losing about 0.82% of expected interest.

Recommended Mitigation:
Always update the borrowing index regardless of whether there are active borrows
