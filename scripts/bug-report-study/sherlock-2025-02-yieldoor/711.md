# Observe might fail for newly created pools

### Summary

The TWAP oracle in Yieldoor (`twapTick()` in `Strategy.sol`) uses Uniswap V3’s `observe()` function to fetch past tick observations for time-weighted average price (TWAP) calculations.

However, if the Uniswap V3 pool hasn’t recorded enough price updates yet (e.g., in a newly launched pool), `observe()` will fail, leading to transaction reverts.

Root cause: Uniswap V3 pools start with an observation cardinality of 1, meaning they only store one past price update. Until additional observations accumulate, calls to `observe()` with a nonzero interval will revert.

### Root Cause

Yieldoor Calls `observe()` Without Checking if Observations Exist

In [`Strategy.sol#twapTick()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol):

```solidity
function twapTick() public view returns (int24) {
    ui](2);
    secondsAgos[0] = twap;  // TWAP interval
    (int56[] memory tickCumulatives,) = IUniswapV3Pool(pool).observe(secondsAgos);
    int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0];

    int24 tick = int24(tickCumulativesDelta / int32(twap));
    if (tickCumulativesDelta < 0 && (tickCumulativesDelta % int32(twap) != 0)) tick--;
    return tick;
}
```

Problem:

- If the Uniswap V3 pool is new, it may not have enough past price updates.
- Calling `observe()` will revert if there aren’t enough historical observations.
- This can block vault deposits, pricing, and risk management functions.


### Internal Pre-conditions

1. Yieldoor protocol uses Uniswap V3’s TWAP oracle (`twapTick()`).
2. The pool is new (e.g., recently created or has low trading activity).
3. Not enough observations have been recorded (`observationCardinality < 2`).

### External Pre-conditions


1. A Uniswap V3 pool has been created, but no trades have occurred to populate observations.
2. Low liquidity or trading volume prevents additional observations from being recorded.


### Attack Path

1. A new Uniswap V3 pool is created for an asset used in Yieldoor.
2. The pool has an observation cardinality of 1, meaning it only tracks the last trade.
3. A user tries to open a leveraged position, deposit, or withdraw, triggering `twapTick()`.
4. The `observe()` function reverts because there aren’t enough historical observations.
5. The transaction fails, blocking protocol functionality.


### Impact

New Yieldoor vaults or lending pools may fail to function properly due to missing TWAP data.  
TWAP-based calculations can revert, blocking user actions (deposits, withdrawals, liquidations).  
Liquidity providers may be unable to deposit if TWAP-based pricing is required.  
Denial-of-Service (DoS) risk: A low-liquidity Uniswap pool could prevent Yieldoor from operating correctly.
