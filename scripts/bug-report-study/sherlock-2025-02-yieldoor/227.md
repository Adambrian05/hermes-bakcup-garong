# In the withdraw function, the code erroneously uses amountOut0 (instead of the correct amountOut1) to calculate repayment amounts.

### Summary

In the `borrowed == up.token1` branch, the [code](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232) erroneously uses amountOut0 (instead of the correct amountOut1) to calculate repayment amounts. 

```solidity
 // In case either of the tokens is denomination token, we directly take from it.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
>>            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }

```

### Root Cause

In [withdraw()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L209C14-L209C22) function,the [code](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L231) erroneously uses `amountOut0` (instead of the correct `amountOut1`) to calculate repayment amounts. 
```solidity
else if (borrowed == up.token1)  {  
    // Incorrect variable usage: amountOut0 instead of amountOut1  
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;  
    owedAmount -= repayFromWithdraw;  
    amountOut1 -= repayFromWithdraw;  // Misplaced deduction  
}  

```

This leads to two critical issues when amountOut1 < owedAmount:

1.Incorrect Debt Repayment: Funds from token0 (e.g., WBTC) are used to repay token1 (e.g., USDC) debt, resulting in unfulfilled debt obligations.

2.Malicious Deduction of User Funds: The code wrongly deducts amountOut1, causing users to lose their withdrawal amounts.

### Internal Pre-conditions

1.User create position
2.User withdraw collateral

### External Pre-conditions

1.Create Position: Open a leveraged position with token1 (USDC) as borrowed asset.
2.Withdraw Collateral: Initiate withdrawal of token0 (e.g., WBTC) and token1 (USDC).

### Attack Path

1.A user creates a position with token1 (e.g., USDC) as the denomination token and borrows 1,000 USDC.
2.During withdrawal, the `borrowed == up.token1` branch is triggered, but the code mistakenly references `amountOut0 `(e.g., WBTC holdings) instead of `amountOut1` (USDC holdings).
3.The repayment amount is calculated as `amountOut0`, which is unrelated to the actual token1 debt, resulting in failure to accurately repay the debt.
4.Users’ token1 (USDC) withdrawal amounts are maliciously deducted，resulting in financial losses for users.

### Impact

1. Resulting in failure to accurately repay the debt.
2. Withdrawal funds are maliciously deducted, causing users to lose funds.

### Mitigation

Code Fixes


```solidity
else if (borrowed == up.token1)  {  
    // Corrected logic: use amountOut1 for token1 repayment  
    uint256 repayFromWithdraw = (amountOut1 < owedAmount) ? amountOut1 : owedAmount;  
    owedAmount -= repayFromWithdraw;  
    amountOut1 -= repayFromWithdraw;  // Proper deduction  
}  

```
