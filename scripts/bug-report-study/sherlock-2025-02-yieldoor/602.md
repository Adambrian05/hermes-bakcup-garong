# Protocol will lose all liquidation fee revenue due to decimal scaling error

### Summary

A mathematical error in `borrowedValue` calculation will cause a complete loss of liquidation fee revenue for the protocol as the calculation incorrectly divides by the number of decimals instead of the decimal scaling factor, inflating the `borrowedValue` to astronomically high values. This problem leads into the protocol not receiving any of the liquidation fees 

### Root Cause

In [[Leverager.sol:318](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L318)](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L318) the borrowed value calculation divides by `ERC20(up.denomination).decimals()` which is the number of decimal places, instead of `10 ** ERC20(up.denomination).decimals()` the atcual decimal scaling factor:

```solidity
uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();

```

### Internal Pre-conditions

1. Any position is liquidated through the `liquidatePosition()` function

### External Pre-conditions

No response

### Attack Path

1. A position becomes liquidatable
2. Liquidator calls `liquidatePosition()`
3. Inside the function, the `borrowedValue` is calculated as `owedAmount * bPrice / ERC20(up.denomination).decimals()`
4. Due to this calculation error, the `borrowedValue` is massively inflated.
5. When the function checks `if (totalValueUSD > borrowedValue)`, this condition always evaluates to false
6. Since the condition is false, the protocol fee calculation and transfer code is never executed
7. Liquidator receives the entire liquidation value with no fees going to the protocol

### Impact

Due to this error on the calculation the protocol will not earn any of all the fees available from  liquidations, leading into all fees going to the liquidator and not giving any to the protocol.

### PoC

```solidity
// PATH: yieldoor/src/test/Leverager.t.sol
function test_borrowedValueCalculationBug() public {
    // --- Setup values from the protocol ---
    uint256 owedAmount = 1_000_000_000;  // 1,000 USDC (6 decimals)
    uint256 bPrice = 1 * 10**18;         // $1.00 (18 decimals)
    uint256 decimalsValue = 6;           // USDC.decimals() = 6
    
    // dividing by decimals() instead of 10**decimals()
    
    // INCORRECT calculation in the contract:
    // borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();
    uint256 buggyBorrowedValue = owedAmount * bPrice / decimalsValue;
    
    // CORRECT calculation:
    // borrowedValue = owedAmount * bPrice / (10 ** ERC20(up.denomination).decimals());
    uint256 correctBorrowedValue = owedAmount * bPrice / (10**decimalsValue);
    
    // --- Log the results for the report ---
    console.log("Bug: Division by decimals() instead of 10**decimals()");
    console.log("---------------------------------------------");
    console.log("INCORRECT borrowedValue:", buggyBorrowedValue);
    console.log("CORRECT borrowedValue:  ", correctBorrowedValue);
    console.log("---------------------------------------------");
    
    // --- Demonstrate the impact on liquidation fee collection ---
    uint256 totalValueUSD = 1_100 * 10**18;  // $1,100 (greater than the correct value)
    
    console.log("For a position with $1,100 value and $1,000 debt:");
    console.log("totalValueUSD > correctBorrowedValue:", totalValueUSD > correctBorrowedValue ? "TRUE" : "FALSE");
    console.log("totalValueUSD > buggyBorrowedValue:  ", totalValueUSD > buggyBorrowedValue ? "TRUE" : "FALSE");
    console.log("The protocol will never collect fees, since the check will always be False");
}
```

### Mitigation

Fix the `borrowedValue` calculation in the `liquidatePosition` function:

```diff
- uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();
+ uint256 borrowedValue = owedAmount * bPrice / (10 ** ERC20(up.denomination).decimals());

```
