# Missing liquidation fee on withdrawals allows users to bypass protocol fees

## Summary
The `Leverager#withdraw` function does not charge liquidation fees when withdrawing from a liquidatable position, allowing users to bypass protocol fees by withdrawing instead of being liquidated.

## Relevant Context
The protocol charges a liquidation fee when positions are liquidated through `Leverager#liquidatePosition`. This fee is calculated as a percentage of the profit (difference between total value and borrowed value) and is sent to the fee recipient.

## Root Cause
The `Leverager#withdraw` function allows users to withdraw from their positions without checking if the position is liquidatable. When a position is liquidatable, users can withdraw 100% of their position through `withdraw` instead of being liquidated through `liquidatePosition`, thereby avoiding the liquidation fee that would normally be charged.

[`Leverager.sol#L209`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L209)

The key issue is that `withdraw` and `liquidatePosition` handle the same underlying action (closing a position) differently with respect to fees, creating an opportunity for fee avoidance.

## Attack Path

1. User opens a leveraged position through `Leverager#openLeveragedPosition`
2. Position becomes liquidatable due to market conditions
3. Instead of waiting for liquidation:
   - User calls `Leverager#withdraw` with `pctWithdraw = 1e18` (100% withdrawal)
   - Position is closed without any liquidation fees being charged
   - User receives full amount of `token0` and `token1` minus repayment
4. Protocol loses out on liquidation fees it would have earned if position was liquidated

## Impact Explanation
High. Loss of 100% protocol liquidation fee if the position is withdrawn instead of liquidated.

## Proof of Concept
1. User opens position with:
   - 10 ETH collateral
   - 20 ETH borrowed
   - Position value: 30 ETH
2. ETH price drops, making position liquidatable
3. Position now worth 25 ETH with 20 ETH debt
4. Instead of liquidation (which would charge fee on the 5 ETH profit):
   - User calls `withdraw(100%)`
   - Receives full 25 ETH (minus 20 ETH debt repayment)
   - Protocol receives no liquidation fee

## Recommendation
Add liquidation fee charge to `withdraw` function when position is liquidatable:

```diff
function withdraw(WithdrawParams calldata wp) external nonReentrant {
    Position memory up = positions[wp.id];
+   bool isLiq = isLiquidateable(wp.id);
    require(_isApprovedOrOwner(msg.sender, wp.id), "msg.sender not approved or owner");
    require(wp.pctWithdraw <= 1e18 && wp.pctWithdraw > 0.01e18, "invalid pctWithdraw");

    address borrowed = up.denomination;
    uint256 sharesToWithdraw = up.shares * wp.pctWithdraw / 1e18;

    (uint256 amountOut0, uint256 amountOut1) =
        IVault(up.vault).withdraw(sharesToWithdraw, wp.minAmount0, wp.minAmount1);

    uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(borrowed);
    uint256 totalOwedAmount = up.borrowedAmount * bIndex / up.borrowedIndex;
    uint256 owedAmount = totalOwedAmount * wp.pctWithdraw / 1e18;

    uint256 amountToRepay = owedAmount; // this should be transferred to yAsset
    
+   if (isLiq) {
+       uint256 totalValueUSD = _calculateTokenValues(up.token0, up.token1, amountOut0, amountOut1, price);
+       uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();
+       
+       if (totalValueUSD > borrowedValue) {
+           uint256 protocolFeePct = 1e18 * liquidationFee * (totalValueUSD - borrowedValue) / (totalValueUSD * 10_000);
+           uint256 pf0 = protocolFeePct * amountOut0 / 1e18;
+           uint256 pf1 = protocolFeePct * amountOut1 / 1e18;
+           
+           if (pf0 > 0) IERC20(up.token0).safeTransfer(feeRecipient, pf0);
+           if (pf1 > 0) IERC20(up.token1).safeTransfer(feeRecipient, pf1);
+           amountOut0 -= pf0;
+           amountOut1 -= pf1;
+       }
+   }
    
    // ... continue with remaining logic ...
}
```
