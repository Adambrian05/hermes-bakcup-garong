# Leverager will bypass accounting for pool depositors

### Summary

The missing update in `LendingPool.pullFunds` will cause a critical miscalculation of funds for pool depositors as a leverager can withdraw tokens without updating the internal balance.

### Root Cause

In `LendingPool.sol:pullFunds:209` there is a missing update to `underlyingBalance` after transferring tokens.
http://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L209

### Internal Pre-conditions

  1. The LendingPool reserve has an internal variable `underlyingBalance` set equal to the deposited amount.
  2. The authorized leverager is set in the LendingPool.
  3. The `pullFunds` function is called with a nonzero borrow amount.

### External Pre-conditions

1. The ERC20 token has been deposited into the LendingPool via the yToken contract.
2. The external environment reflects a normal deposit scenario, with the leverager being properly whitelisted.

### Attack Path

1. The leverager (or an attacker impersonating the leverager) calls the `pullFunds` function on the LendingPool with a specified borrow amount (e.g., 100 ether).
2. The function transfers tokens from the yToken contract to the leverager without updating the LendingPool's internal accounting variables.
3. Consequently, the actual token balance decreases while the recorded `underlyingBalance` remains unchanged.

### Impact

The pool depositors suffer because the LendingPool’s internal accounting no longer reflects the actual funds available. This can lead to miscalculation of interest rates and unexpected liquidity issues, potentially enabling further exploits.

### PoC

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "forge-std/Test.sol";

import { ERC20 } from "openzeppelin-contracts/contracts/token/ERC20/ERC20.sol";

import { yToken } from "../src/yToken.sol";
import { LendingPool } from "../src/LendingPool.sol";
import { Leverager } from "../src/Leverager.sol";

contract ERC20Mock is ERC20 {
    constructor(
        string memory _name,
        string memory _symbol,
        uint256 _initialSupply
    ) ERC20(_name, _symbol) {
        _mint(msg.sender, _initialSupply);
    }
}


contract AccountingInconsistencyTest is Test {
    ERC20Mock public erc20Token;
    LendingPool public lendingPool;
    Leverager public mockLeverager;
    address public owner;

    function setUp() public {
        owner = address(this);

        erc20Token = new ERC20Mock("Test Token", "TTK", 1_000_000 ether);

        lendingPool = new LendingPool();
        lendingPool.initReserve(address(erc20Token));

        uint256 depositAmount = 1000 ether;
        erc20Token.approve(address(lendingPool), depositAmount);
        lendingPool.deposit(address(erc20Token), depositAmount, owner);

        mockLeverager = new Leverager("Leverager", "LEV", address(lendingPool));

        lendingPool.setLeverager(address(mockLeverager));
    }

    function test_pullFunds_does_not_change_underlyingBalance() public {
        address yTokenAddress = lendingPool.getYTokenAddress(address(erc20Token));

        uint256 recordedUnderlyingBefore = lendingPool.getUnderlyingBalance(address(erc20Token));
        uint256 totalBorrowsBefore = lendingPool.totalBorrowsOfReserve(address(erc20Token));
        uint256 yTokenUnderlyingBefore = erc20Token.balanceOf(yTokenAddress);

        uint256 borrowAmount = 100 ether;

        vm.prank(address(mockLeverager));
        lendingPool.pullFunds(address(erc20Token), borrowAmount);

        uint256 recordedUnderlyingAfter = lendingPool.getUnderlyingBalance(address(erc20Token));
        uint256 totalBorrowsAfter = lendingPool.totalBorrowsOfReserve(address(erc20Token));
        uint256 yTokenUnderlyingAfter = erc20Token.balanceOf(yTokenAddress);

        assertEq(
            yTokenUnderlyingAfter,
            yTokenUnderlyingBefore - borrowAmount,
            "yToken underlying balance should decrease by borrowAmount"
        );

        assertEq(
            recordedUnderlyingAfter,
            recordedUnderlyingBefore,
            "Recorded underlying balance should remain unchanged"
        );

        assertEq(
            totalBorrowsAfter,
            totalBorrowsBefore,
            "Total borrows should remain unchanged"
        );
    }
}
```

### Mitigation

Update the pullFunds function in LendingPool to subtract the withdrawn amount from the internal accounting variables so that the state correctly reflects the funds transferred.
