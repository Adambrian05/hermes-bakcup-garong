# withdraw()

After a close look, the **`withdraw()`** function contains two clear logical flaws:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L209
1. **Incorrect ternary operand**  
   In the branch where the borrowed token is `token1`, the code does:
   ```solidity
   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
   ```
   Notice that the ternary check is on `amountOut1 < owedAmount`, but the “true” branch returns `amountOut0` instead of `amountOut1`. This is almost certainly a copy-paste error. It should read:
   ```solidity
   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
   ```

2. **Partial repayment from vault tokens is never actually repaid to the pool**  
   Inside `withdraw()`, the code tries to let part of the debt be repaid directly from the withdrawn vault tokens (if they are the borrowed token). However, while the function subtracts that “repayFromWithdraw” amount from both `owedAmount` and `amountOut0/amountOut1`, it never calls `ILendingPool(lendingPool).repay` for that portion.  
   
   Concretely:
   ```solidity
   uint256 amountToRepay = owedAmount; // e.g. 100

   if (borrowed == up.token0) {
       uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
       owedAmount -= repayFromWithdraw;      // e.g. owedAmount = 50 now
       amountOut0 -= repayFromWithdraw;      // subtract from user’s withdraw
   } 
   // else if token1, same structure but referencing token1

   // Then we only ever repay 'amountToRepay', which was never updated.
   ILendingPool(lendingPool).repay(borrowed, amountToRepay);  // amountToRepay is still the original owedAmount (100)
   ```
   So the portion `repayFromWithdraw` that was “taken out” of the vault tokens never gets passed into the `repay` call. Instead, the code repays the original full `owedAmount` (stored in `amountToRepay`) using user-supplied tokens. Meanwhile, the tokens deducted as `repayFromWithdraw` are effectively just burned from the user’s withdrawal but never used to repay anything.

#### How to fix it

1. **Correct the ternary**:
   ```solidity
   // if (borrowed == up.token1)
   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
   ```
2. **Actually repay the partial amount**:
   - Either *reduce* `amountToRepay` by `repayFromWithdraw` before calling `repay`, or
   - Call `ILendingPool(lendingPool).repay` twice (once with `repayFromWithdraw` if it’s > 0, and a second time with the remainder).
   - Alternatively, combine the logic so that `amountToRepay` always reflects the final total that needs to be sent to the lending pool.

For example, a minimal fix would be:

```solidity
uint256 totalOwedAmount = up.borrowedAmount * bIndex / up.borrowedIndex;
uint256 owedAmount = (totalOwedAmount * wp.pctWithdraw) / 1e18;
uint256 repayFromWithdraw;

if (borrowed == up.token0) {
    repayFromWithdraw = (amountOut0 < owedAmount) ? amountOut0 : owedAmount;
    amountOut0 -= repayFromWithdraw;
} else if (borrowed == up.token1) {
    repayFromWithdraw = (amountOut1 < owedAmount) ? amountOut1 : owedAmount;
    amountOut1 -= repayFromWithdraw;
}

// Now subtract repayFromWithdraw from owedAmount:
owedAmount -= repayFromWithdraw;

// If anything remains owed, pull from user:
if (owedAmount > 0) {
    IERC20(up.denomination).safeTransferFrom(msg.sender, address(this), owedAmount);
}

// Repay the total needed (the piece from the vault + user tokens):
ILendingPool(lendingPool).repay(borrowed, (repayFromWithdraw + owedAmount));
```

That way, both the partial repayment from the vault tokens and the user-supplied repayment actually go back to the lending pool, and the arithmetic lines up with what is subtracted from the withdrawn amounts.
