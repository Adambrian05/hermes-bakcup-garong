# Incorrect Tick Parameter in Vesting Fee Collection

In the [collectFees](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159-L181) function, the contract intends to collect fees from three liquidity positions: the main, secondary, and an ongoing vesting position. While fees for the main and secondary positions are collected correctly using their own tick bounds, the vesting position fee collection is implemented as follows:

```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
}
```

Here, instead of using `vestPosition.tickUpper` as the upper tick bound for the vesting position, the contract mistakenly uses `mainPosition.tickUpper`. This creates a critical flaw:
The vesting position’s tick bounds are set at the time of its creation (in `addVestingPosition`), but subsequent rebalances update the main position’s ticks. As a result, `mainPosition.tickUpper` may diverge from the originally set `vestPosition.tickUpper`. When fees are collected using the updated main position’s upper tick, the contract may:
  - Collect fees from an unintended tick range that does not correspond to the vesting position.
  - Miscalculate or even lose fees that rightfully belong to the vesting position.
  
## Impact  
  If fees are not correctly accounted for due to this misalignment, it could lead to a loss of funds or an incorrect distribution of fees between the protocol and the liquidity providers.

## Mitigation
The vesting fee collection call should use the vesting position’s own upper tick. For example, update the code to:

```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
}
```
