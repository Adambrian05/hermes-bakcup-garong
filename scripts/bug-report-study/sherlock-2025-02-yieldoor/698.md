# Vault will lose fee value for users by omitting uncollected fees in withdrawPartial

### Summary

The unenforced fee collection in withdrawPartial will cause a loss of fee value for users as the Vault will calculate withdrawals without including accrued fees when collectFees fails.

### Root Cause

In Strategy.sol:159-181 the assumption that collectFees is called prior lacks enforcement, leading to understated idleBalances when Vault’s collectFees call fails.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159-L181

### Internal Pre-conditions

User needs to call deposit in Vault.sol to set totalSupply to be at least 100 (depositing 100 token0 and 100 token1).
Strategy needs to accrue fees to set mainPosition fees to be at least 10 token0 and 10 token1 via pool activity.

### External Pre-conditions

No external preconditions required,the issue depends on internal fee accrual and Vault behavior.

### Attack Path

User calls deposit in Vault.sol, depositing 100 token0 and 100 token1, minting shares in a 1:1 ratio.
Strategy accrues 10 token0 and 10 token1 in fees from mainPosition through pool trading activity.
Vault calls withdraw but collectFees fails (gas limit or revert), leaving fees uncollected in Strategy.
Strategy’s withdrawPartial executes, using idleBalances() without fees, returning 100/100 instead of 110/110.

### Impact

The users suffer an approximate loss of 10% of their entitled value per withdrawal.



### PoC

// SPDX-License-Identifier: UNLICENSED
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../Vault.sol";
import "../Strategy.sol";

contract FeeLagPoC is Test {
    Vault vault;
    Strategy strategy;
    address token0 = address(0x1);
    address token1 = address(0x2);
    address user = address(0x3);

    function setUp() public {
        vault = new Vault(token0, token1);
        strategy = new Strategy(address(0x4), address(vault), address(this), address(this)); // Mock pool, rebalancer, feeRecipient
        vault.setStrategy(address(strategy));
        vm.etch(token0, abi.encodePacked(type(IERC20).runtimeCode));
        vm.etch(token1, abi.encodePacked(type(IERC20).runtimeCode));
        deal(token0, user, 1000e18);
        deal(token1, user, 1000e18);
        vm.startPrank(user);
        IERC20(token0).approve(address(vault), type(uint256).max);
        IERC20(token1).approve(address(vault), type(uint256).max);
        vm.stopPrank();
    }

    function testFeeCollectionLag() public {
        vm.prank(user);
        (uint256 shares,,) = vault.deposit(100e18, 100e18, 0, 0);
        assertEq(shares > 0, true);

      
        vm.mockCall(
            address(strategy),
            abi.encodeWithSelector(IStrategy.balances.selector),
            abi.encode(110e18, 110e18) // Fees accrued
        );
        vm.mockCall(
            address(strategy),
            abi.encodeWithSelector(IStrategy.idleBalances.selector),
            abi.encode(100e18, 100e18) // No fees collected
        );
        vm.mockCall(
            address(strategy),
            abi.encodeWithSelector(IStrategy.collectFees.selector),
            abi.encode() // Fails silently
        );

        vm.prank(user);
        (uint256 amount0Out, uint256 amount1Out) = vault.withdraw(shares, 0, 0);


        assertEq(amount0Out, 100e18); // Expected 110e18
        assertEq(amount1Out, 100e18); // Expected 110e18
        // Ratio 1:1 deposited, expected 1:1 with fees, got 1:1 without
    }
}

### Mitigation

Call collectFees() internally within withdrawPartial and revert if fees remain uncollected (check idleBalances() increases post-call)
