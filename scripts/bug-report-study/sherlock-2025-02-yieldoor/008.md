# Users will experience accounting errors due to tokens with transfer fees

#### Summary
The lack of handling for tokens with transfer fees will cause accounting errors for users as these tokens will reduce the actual transferred amount.

#### Root Cause
In `LendingPool.sol:deposit` and `LendingPool.sol:withdraw` the lack of handling for tokens with transfer fees causes accounting errors.

#### Internal Pre-conditions
Users need to deposit or withdraw tokens that have transfer fees.

#### External Pre-conditions
Tokens with transfer fees need to be used within the protocol.

#### Attack Path
1. User deposits a token with transfer fees into the protocol.
2. The protocol calculates the deposit amount without accounting for the transfer fee.
3. User withdraws the token, and the protocol calculates the withdrawal amount without accounting for the transfer fee.
4. User suffers a loss due to the discrepancy between the recorded and actual token amounts.

#### Impact
The users suffer an approximate loss due to the discrepancy between the recorded and actual token amounts. The protocol does not gain or lose anything directly.

#### PoC
```solidity
// Assuming a token with a 1% transfer fee
function testTokenWithTransferFee() public {
    address user = address(0x1234567890123456789012345678901234567890);
    
    ERC20WithFee token = new ERC20WithFee();
    LendingPool lendingPool = new LendingPool();
    
    // User deposits 100 tokens with a 1% fee
    token.mint(user, 100e18);
    vm.prank(user);
    token.approve(address(lendingPool), 100e18);
    vm.prank(user);
    lendingPool.deposit(address(token), 100e18, user);
    
    // Protocol records 100 tokens, but only 99 tokens are actually transferred
    assertEq(lendingPool.totalLiquidityOfReserve(address(token)), 100e18); // Incorrect accounting
    
    // User withdraws the tokens
    vm.prank(user);
    lendingPool.redeem(address(token), 100e18, user);
    
    // User receives 99 tokens instead of 100 due to the fee
    assertEq(token.balanceOf(user), 99e18); // User suffers a loss
}
```
