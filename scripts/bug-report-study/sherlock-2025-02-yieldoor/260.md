# Incorrect position leverage calculation

### Summary

Incorrect position leverage calculation

### Root Cause

In [Leverager::_checkWithinlimits()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464) function incorrectly calculates the position leverage.

```solidity
    function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue; // @audit wrong calculation

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
```

In here, collateral value already counts position's borrowed amount because that value cover the whole positions value. For instance, if there is x amount of collateral supplied by the user and there is 4x borrowed amount. It will create 5x position. `up.initCollateralValue` holds that 5x value. 

Current calculation method will underestimate the position leverage.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. User supplied x amount of token for 3x leverage
2. Contract will flashloan 2x amount of token
3. Collateral is calculated as 3x
4. Borrowed amount is calculated as 2x 
5. Formula will give us (3x + 2x ) / (3x) = 5/3 leverage

It makes our leverage formula to = ( c + 2b ) / ( c + b )

In fact, the issue makes the leverage is only limited by several conditions because this equation will never reach the max leverage if max leverage is higher than and equal to 2. Those conditions are:

1. maxUSDLeverage
2. maxIndividualBorrow

The last thing that will limit the position leverage is isLiquidateable function. Because it calculates the base collateral amount based on max leverage correctly. 

Let say max leverage is 5 for a leverager and let's try to open 800 dollar position with 20 dollar, which makes 40x.

First of all, it won't be problem in within limits function because it will never reach 5x
( 20 + 780 + 780 ) / ( 800 ) = 1.975x

Let's check the isLiquidateable call:

Base value will be equal to:

780 / 4 = 195 ( base )

Let say minCollatPCT is equal to 10%

195 * 10% = 19.5 Dollar

We already supplied 20 dollar for position. So, we can create 40x position in here. 

In advance, there is also another problem in base calculation, I will report it in another submission but in correct calculation base will be equal to 20 dollar at position creation. In conclusion, if the other issue wasn't exist, there won't be any leverage limit.

### Impact

User can open really higher leverage positions than intended due to underestimation. This may cause massive losses for the protocol because every parameter is configured based on leverage. If leverage is too high, minimum collateral percentage value would be useless because it's designed for that max leverage value. If an user can create 40x position, 10% collat percentage won't be enough to give a reaction for liquidators and it will cause a bad debt in the end. 


In the README, it's stated that maximum 5x leverage will be allowed. It will break the invariant and it will also increase the risk of the positions because of high leverage.


### Mitigation

Correct formula:

initCollat * 1e18 / ( initCollat - borrowedAmount)
