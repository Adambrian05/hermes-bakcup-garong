# Incorrect usage of `amountOut0` in `Leverager.withdraw()` function for `repayFromWithdraw`

### Summary

The `repayFromWithdraw` variable should be assigned the lower value between `amountOut1` and `owedAmount` when the borrowed token is `token1`. Currently, if `amountOut1` is less than `owedAmount`, `repayFromWithdraw` is incorrectly set to `amountOut0` due to a typographical error.

### Root Cause

Examining line 232 in the `Leverager.withdraw()` function reveals that when `amountOut1` is less than `owedAmount`, the code mistakenly assigns `repayFromWithdraw` to `amountOut0` instead of `amountOut1`. This is an unreasonable mistake.

As a consequence, the subsequent operation `amountOut1 -= repayFromWithdraw;` may lead to an integer underflow if `amountOut0` exceeds `amountOut1`, causing the transaction to revert.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232
