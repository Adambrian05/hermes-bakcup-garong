# Missing Swap Output Accounting for Position's `token1` Causes Users to Overpay Debt when Withdraw Leverage Position

### Summary

The `Leverager.withdraw()` function fails to account for borrowed tokens obtained through swap for position's `token1` when calculating the remaining debt amount users need to repay. While the function correctly deducts borrowed tokens obtained directly from vault withdrawals, it does not deduct tokens obtained through swap. This forces users to transfer the extra remaining debt amount even though part of it was already obtained via swap, resulting in direct loss of funds as to the swap output amount. The issue affects any user performing a withdrawal that involves swapping collateral for borrowed tokens.

### Root Cause

In [Leverager.sol#L258-L259](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L258-L259), the `Leverager.withdraw()` function fails to deduct the swapped output amount from remaining debt `owedAmount` for `up.token1` after performing token swap. While the function correctly deducts direct borrowed token amounts from `owedAmount` when they are available to repay the lending pool, it does not apply the same logic for borrowed tokens obtained through swap. This causes users to overpay when repaying their debt since they must transfer the extra remaining `owedAmount` even though some portion was already obtained via swap.

### Attack Path

1. User has a leveraged position in the Vault where:
   - Vault contains token0 and token1
   - User borrowed token0 as denomination token
   - Position has both token0 and token1 as liquidity
2. User calls `withdraw()` with:
   - `hasToSwap=true`
   - Valid swap parameters to swap some token1 into token0 for debt repayment
3. The contract:
   - Withdraws both token0 and token1 from vault
   - If withdrawn token0 amount is available, correctly deducts it from `owedAmount`
   - Performs swap of token1 to get additional token0
   - Does not deduct the swapped token0 amount from `owedAmount`
4. User is forced to transfer the extra remaining `owedAmount` of token0, even though part of this amount was already obtained through the swap
5. Leverage Contract:
   - Repays the lending pool with original `amountToRepay` amount
   - Keeps the excess token0 (equal to swap output amount) in the contract with no way to recover
6. The excess token0 amount is permanently lost to the user

### Impact

The user suffers a direct loss of funds equal to the amount of borrowed tokens obtained through swap, as they are forced to provide these tokens again when transferring the unmodified `owedAmount`. For example, if a user needs to repay 100 USDC and: 
- Gets 30 USDC from vault withdrawal (correctly deducted)
- Swaps token1 to get 40 USDC (not deducted)

They will still need to transfer 70 USDC (instead of the actual remaining 30 USDC), resulting in a 40 USDC loss. This impacts any user performing a withdrawal that involves swapping collateral for borrowed tokens, and there is no mechanism to recover these lost funds.

### Mitigation

The issue can be fixed by properly tracking and deducting the swap output amount from `owedAmount` for `up.token1`. Update the swap section in `Leverager.withdraw()` to:

1. Capture the swap output amount
2. Deduct it from `owedAmount` before requesting the remaining amount from user

