# Attacker will exploit invalid token interfaces to compromise protocol funds

### Summary

 https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L106-#L109

Lack of proper validation that token0 and token1 adhere to the expected ERC20 interfaces will cause critical calculation and transfer errors for the protocol as an attacker will supply malicious token contracts via a compromised vault. This can lead to unauthorized fund transfers and asset loss.

```solidity
 Position memory up;
up.token0 = IVault(lp.vault).token0();  // USDC
up.token1 = IVault(lp.vault).token1();  // ETH
up.vault = lp.vault;
```

### Root Cause

 There is no verification that the tokens returned by IVault(lp.vault).token0() and IVault(lp.vault).token1() implement the proper ERC20 interface, leaving the protocol open to abuse if the vault returns non-standard or malicious token addresses.

### Attack Path

1.  A non-standard token (fee-on-transfer, rebasing, etc.) is accepted as token0 or token1 in a vault
2. Functions interacting with this token assume standard ERC20 behavior
When the token behaves unexpectedly (takes fees on transfer, rebases balances, etc.):

3.Accounting calculations become inaccurate
4.Token balances may not match expected values
5.Protocol operations may revert unexpectedly


Users experience failed transactions or locked funds

### Impact

  The protocol’s users and overall fund security are at risk, as malicious tokens can lead to:
- Unauthorized or erroneous token transfers.
- Manipulation of balance calculations.
- Potential loss or misappropriation of assets.

 // No verification that token0 and token1 are valid tokens with proper interfaces

### Mitigation

1. Implement checks to ensure that token0 and token1 implement the essential ERC20 functions. This can be done using interface detection methods such as ERC165 or by explicitly verifying that key functions (e.g., transfer, balanceOf) are callable.

2.Vault Whitelisting:
Restrict acceptable vault addresses to a predefined list of audited and trusted contracts.
