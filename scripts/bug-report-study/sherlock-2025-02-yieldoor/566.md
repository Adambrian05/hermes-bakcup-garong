# Incorrect collectPositionFees ticks for VestingPosition

### Summary

The collectFees function incorrectly collects fees for the vesting position by using mainPosition.tickUpper instead of vestPosition.tickUpper. This causes an incomplete fee collection, as the vesting position’s liquidity remains allocated from its original tick range, but fees are only collected from a reduced range. 

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159-#L181

### Root Cause

VestingPosition and MainPosition have same ticks but after rebalance is called which updates the ticks for MainPosition it causes VestingPosition to use his same lowerTick but also uses the mainPosition upperTick. The vesting position’s fees are collected using the incorrect upper tick value:

```solidity
function collectFees() public {
        (uint256 preBal0, uint256 preBal1) = idleBalances();

        if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);  <----
        }
       

        (uint256 afterBal0, uint256 afterBal1) = idleBalances();

        uint256 protocolFees0 = (afterBal0 - preBal0) * protocolFee / 10_000; 
        uint256 protocolFees1 = (afterBal1 - preBal1) * protocolFee / 10_000;

        if (protocolFees0 > 0) IERC20(token0).safeTransfer(feeRecipient, protocolFees0);
        if (protocolFees1 > 0) IERC20(token1).safeTransfer(feeRecipient, protocolFees1);

        if (ongoingVestingPosition) {
            _withdrawPartOfVestingPosition(); // doing that now, otherwise we'd charge protocol fee for the vested position
        }
    }
```

### Impact

Reduced Fee Collection: Fees for the vesting position are only collected up to mainPosition.tickUpper, which may have changed after a rebalance, instead of the actual vestPosition.tickUpper.
Lost Revenue: Any liquidity between mainPosition.tickUpper and vestPosition.tickUpper does not contribute to fee accrual, leading to a loss of collected fees.

### Mitigation

Replace it with this:

```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper); // Corrected
}
```
