# Uninitialized Strategy will block deposit/withdraw operations for Vault users

### Summary

The absence of a check to ensure that the strategy is initialized in Vault.sol will cause failed deposit and withdraw operations for Vault users as the deposit and withdraw functions call strategy methods while the strategy remains uninitialized (address(0)), allowing the transaction to revert.

### Root Cause

- In **Vault.sol**, there is a missing check on the strategy variable before calling [functions](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L52) such as `IStrategy(strategy).collectFees()` and `IStrategy(strategy).balances()`, which causes the transaction to fail if the strategy address is still address(0).

### Internal Pre-conditions

1. Admin needs to leave the strategy variable uninitialized (i.e., set to address(0)).  
2. A user needs to call the `deposit` or `withdraw` function while the strategy remains unset.


### External Pre-conditions

1. No external protocol changes or conditions are required; the vulnerability exists solely due to the missing check in the contract code.


### Attack Path

1. The Vault contract is deployed without calling `setStrategy()`, leaving the strategy address as address(0).  
2. A user calls the `deposit` (or `withdraw`) function on the Vault contract.  
3. The function attempts to call `IStrategy(strategy).collectFees()` (or other strategy functions), but since `strategy == address(0)`, the call fails and the transaction reverts.


### Impact

Vault users cannot execute deposit or withdraw operations, effectively locking their funds and disrupting normal contract functionality.

### PoC

```solidity
// Example PoC: Deploying Vault without initializing strategy and attempting a deposit
Vault vault = new Vault(token0, token1);
// Note: strategy remains uninitialized (address(0))
vault.deposit(100 ether, 50 ether, 90 ether, 45 ether); // This call will revert due to uninitialized strategy
```
