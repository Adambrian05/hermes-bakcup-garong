# All functions calling `_priceWithinRange()` can be DoSed

### Summary

All functions calling `_priceWithinRange()` can be DoSed

### Root Cause

`_priceWithinRange()` has the following code:
```solidity
        int24 _twapTick = twapTick();
        (, int24 currentTick, , , , , ) = IUniswapV3Pool(pool).slot0();

        int24 minTick = _twapTick - tickTwapDeviation;
        int24 maxTick = _twapTick + tickTwapDeviation;
        if (currentTick < minTick || currentTick > maxTick) return false;
```
If the twap tick deviates from the spot tick too much, then we will return false, which will simply cause a revert in functions calling the function. Any malicious user can disallow calling those functions perpetually. The issue can also occur without malicious intervention during volatile markets.

_No internal pre-conditions_

### External Pre-conditions

_No external pre-conditions_

### Attack Path

1. Markets are very volatile and the TWAP lags behind the spot price
2. The deviation check will fail over and over again

This can also be abused by a malicious user by frontrunning. Even though the chains to deploy on are all with a private mempool, the rebalance function is called on a certain interval (clear by the function checks) by a bot (written in the README). This means that the user can anticipate it and swap the spot price over the allowed deviation.

### Impact

DOS of important functionalities such as rebalancing.
