# Liquidators Will Incur Losses Leading to Bad Debt Accumulation for the Leverager Protocol

### Summary

The absence of a bad debt handling mechanism in Leverager.sol will cause a systemic accumulation of bad debt for the protocol as liquidators will refuse to liquidate undercollateralized positions due to financial losses.



### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L295C4-L381C1

In Leverager.sol:liquidatePosition, there is a missing mechanism to handle bad debt when collateral value falls below the debt amount. Specifically, when the collateral withdrawn from the vault (amount0 and amount1) is insufficient to cover the owedAmount, the liquidator is forced to transfer the shortfall from their own funds via IERC20(up.denomination).safeTransferFrom(msg.sender, address(this), owedAmount). This design lacks a reserve or insurance fund to absorb losses, unlike industry-standard protocols.



### Internal Pre-conditions

1. A user needs to call openLeveragedPosition() to set a position’s borrowedAmount to be at least minBorrow (20e18).
2. The vault’s twapPrice() needs to decrease significantly, causing positions[id].initCollateralUsd to fall below positions[id].initBorrowedUsd.
3. The lendingPool’s getCurrentBorrowingIndex() needs to increase the owedAmount beyond the collateral’s current value within a short timeframe (e.g., due to interest accrual).

### External Pre-conditions

1. The price of token0 or token1 (via IPriceFeed(pricefeed).getPrice()) needs to drop sharply, reducing collateral value below debt within minutes (e.g., from $100 to $50).
2. The IVault(vault).withdraw() function must execute successfully, returning amount0 and amount1 less than the owedAmount.

### Attack Path

1. An user  calls openLeveragedPosition() with maximum leverage on a volatile asset pair (e.g., token0 and token1), borrowing a large maxBorrowAmount.
2. The user  waits for (or triggers via external market manipulation) a rapid price drop in token0 or token1, making the position undercollateralized (e.g., collateral value drops to 50% of debt).
3. A liquidator attempts to call liquidatePosition(), withdrawing collateral worth less than the owedAmount.
4. The liquidator refuses to proceed after realizing they must transfer additional funds from their wallet to cover the shortfall, leaving the position unliquidated.

### Impact

The protocol suffers an approximate loss equivalent to the unliquidated debt value (e.g., potentially millions in USD during a market crash). The user gains nothing directly but exploits the protocol’s vulnerability to accumulate bad debt, potentially destabilizing the system. External liquidators lose funds if they liquidate, discouraging participation.


### PoC

_No response_

### Mitigation

Modify liquidatePosition to allow partial liquidations, reducing the debt incrementally without requiring full repayment in one transaction, lowering the liquidator’s capital burden.
