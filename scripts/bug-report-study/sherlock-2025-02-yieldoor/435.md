# Malicious actors will exploit stale oracle prices causing incorrect liquidations and position valuations

### Summary

The commented-out staleness check in the `PriceFeed` contract will cause incorrect position valuations for all protocol users as malicious actors can take advantage of price discrepancies between stale oracle data and actual market prices. This is particularly critical when the `Leverager` contract calls `getPrice()` to determine position values, liquidation eligibility, and initial collateral value.


### Important note
The commented-out staleness check in `PriceFeed.sol` (which is technically out of scope) directly impacts the Leverager contract's critical functions that rely on accurate price data. When the Leverager calls `IPriceFeed(pricefeed).getPrice()` in functions like `openLeveragedPosition()`, `isLiquidateable()`, and `_calculateTokenValues()`, it receives potentially stale prices without validation, leading to incorrect position valuations and liquidation decisions. Although the root issue exists in `PriceFeed.sol`, the vulnerability manifests in the Leverager contract's operations which are explicitly in scope, making this a valid security finding as it enables attacks that manipulate the timing between market movements and oracle updates to create undercollateralized positions.


### Root Cause

In [PriceFeed.sol:58](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/PriceFeed.sol#L58) and [PriceFeed.sol:60](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/PriceFeed.sol#L60), the crucial price staleness check is commented out:
```solidity
function _getChainlinkPrice(Data memory data) internal view returns (uint256) {
    (, int256 answer,, /* uint256 updatedAt */ ,) = AggregatorV3Interface(data.feed1).latestRoundData();
    require(answer > 0);
    // require(block.timestamp - updatedAt <= heartbeat);
    return uint256(answer);
}
```
This becomes especially problematic when the getPrice() function is called in critical calculations in the Leverager contract, such as in [Leverager.sol:317](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L317) and [Leverager.sol:433-440](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L433-L440) where stale prices would directly impact position valuation and liquidation decisions.

### Internal Pre-conditions

1. The PriceFeed contract has been deployed with the staleness check commented out
2. The heartbeat parameter has been set for a price feed (e.g., 1 hour for ETH)
3. The Leverager contract uses this PriceFeed to calculate position values and determine liquidation eligibility

### External Pre-conditions

1. The Chainlink oracle for a specific asset (e.g., ETH) has not updated its price for a period longer than the intended heartbeat
2. A significant price change has occurred in the market that is not reflected in the oracle data

### Attack Path

1. Attacker monitors oracle updates and market prices to identify periods when Chainlink oracle prices are significantly stale
2. When a price crash occurs (e.g., ETH drops from $2500 to $1000) but the oracle hasn't updated yet
3. Attacker creates a leveraged position by calling `openLeveragedPosition()` using the stale high price, borrowing more than would be allowed with current market prices
4. The position is incorrectly valued at creation due to the `Leverager.sol` calling `IPriceFeed(pricefeed).getPrice()` with stale data
5. Alternatively, when a position should be liquidatable based on actual market prices, the attacker's position avoids liquidation because `isLiquidateable()` uses stale higher prices
6. When oracle finally updates, the protocol has already accepted undercollateralized positions

### Impact

The protocol and its users suffer potential losses due to undercollateralized positions, with affected positions potentially becoming bad debt. The key vulnerable functions are `isLiquidateable()` and `_calculateTokenValues()` in the Leverager contract, which rely on accurate price data to make critical decisions. Liquidators may also be affected as positions that should be eligible for liquidation remain protected by stale prices.

### Mitigation

Uncomment and implement the timestamp validation check in `PriceFeed.sol`:

```solidity
function _getChainlinkPrice(Data memory data) internal view returns (uint256) {
    (, int256 answer,, uint256 updatedAt ,) = AggregatorV3Interface(data.feed1).latestRoundData();
    require(answer > 0, "Invalid oracle price");
    require(block.timestamp - updatedAt <= data.timeInterval, "Oracle price is stale");
    return uint256(answer);
}
```
