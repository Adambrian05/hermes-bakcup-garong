# Malicious user can take many tokens token by first depositing.

### Summary

Malicious user will take most tokens that owner added for vesting position by first depositing.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119
In Vault.sol file, _calcDeposit function allows amount0=0 or amount1 = 0 at first depositing.

### Internal Pre-conditions

Nobody deposit. Attacker needs to be first depositor.

### External Pre-conditions

N/A

### Attack Path

In Vault.sol file.
1. Attacker will deposit with amount1 = 0 at first time. 
2. Owner will add a vesting position to the strategy and get reward after the duration is past.
3. After it, other users can deposit with both amoun0 and amount1.
4. Attacker will withdraw and take most amount1 that owner added for vesting.
5. The other users will get small or same amount than deposit amount even though owner added a vesting position.

### Impact

Attacker steals most tokens that is added for vesting.
Therefore owner will lose most amount for vesting and users can't get profit by vesting.

### Mitigation

_calcDeposit() function needs not allow any amount is 0 when totalSupply=0 (just first deposing).
