Salty Concrete Cow

Medium

# Leverager.sol :: openLeveragedPosition() maxCumulativeBorrowedUSD limit can be bypassed, allowing users to borrow more USD than intended.

### Summary

`openLeveragedPosition()` is used to open a leveraged position. The issue lies in `_checkWithinLimits()`, which verifies that `currBorrowedUSD` does not exceed `maxCumulativeBorrowedUSD` to prevent users from borrowing more than the allowed limit. 

However, `currBorrowedUSD` is static and does not account for the interest accrued on existing borrows, allowing the total borrowed amount to surpass `maxCumulativeBorrowedUSD`.

### Root Cause

[openLeveragedPosition()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L186) calls `_checkWithinLimits()` to ensure the position stays within predefined limits and that the vault's `maxCumulativeBorrowedUSD` has not been exceeded.
```solidity
function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
        require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        require(up.initBorrowedUsd <= vp.maxUsdLeverage, "too high borrow usd amount");
        require(up.borrowedAmount <= maxIndividualBorrow, "too high borrow for the vault");
@>      require(
            vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD, 
            "vault exceeded borrow limit"
        );
    }
```
`vaultParams[up.vault].currBorrowedUSD` is a static value that tracks the total USD borrowed but does not account for the interest accrued on current loans. As a result, `vaultParams[up.vault].maxCumulativeBorrowedUSD` can be exceeded, allowing users to borrow more USD than intended.

### Internal Pre-conditions

1. A leveraged position are enabled in the vault.  
2. Active borrows are accumulating interest.

### External Pre-conditions

The user open a leveraged position.

### Attack Path

None.

### Impact

`maxCumulativeBorrowedUSD` can be circumvented, allowing users to borrow more USD than intended.

### PoC

To better illustrate the issue, let's consider an example where `maxCumulativeBorrowedUSD` is set to `100_000e18`:  

1. Various users open leveraged positions, resulting in a total borrowed amount of `80_000e18` USD.  
2. Over time, interest accrues, increasing the borrowed amount to `95_000e18`.  
3. A user attempts to borrow `10_000e18` USD by opening a leveraged position. The system checks whether `vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD`, which evaluates to `90_000e18` (`80_000e18 + 10_000e18`) ≤ `100_000e18`. Since the condition holds true, the borrow is approved.  
4. However, the actual total borrowed amount is now `105_000e18` (`95_000e18 + 10_000e18`), as interest has increased the total debt.  
5. This results in `maxCumulativeBorrowedUSD` being exceeded, allowing users to borrow more USD than intended.

### Mitigation

To resolve this issue, `vaultParams[up.vault].currBorrowedUSD` should be recalculated each time a new leveraged position is opened. This ensures that the interest accrued on existing borrows is accounted for, preventing users from borrowing more than `maxCumulativeBorrowedUSD`.
