# Incorrect Tokens Value Calculation in `Leverager`

### Summary

The `_calculateTokenValues()` internal function in the `Leverager` contract calculates the value of two tokens in USD.

If one of the tokens does not have a pricefeed, the underlying pool’s TWAP price is used to convert it to the other token, and from there use its pricefeed to convert it to USD.

However, due to improper handling of this scenario, the token values may be over- or under-calculated when the two tokens have different decimal precisions.

### Root Cause

[Leverager.sol#L424-L451](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L424-L451)

```solidity
    function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
    {
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }

        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }

        return usdValue;
    }
```

Let's assume the price feed is unavailable for `token0`.

Then, the given amount of `token0` is evaluated in USD as `(amount0 * price / PRECISION) * chPrice1 / decimals1`.

```solidity
    usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
```

If we take a look at this calculation, we can notice that `(amount0 * price / PRECISION)` has `token0`'s decimals, but is incorrectly divided by `decimals1`.

### Impact

The token values may be over- or under-calculated when the two tokens have different decimal precisions.

### PoC

For test purpose, I made the `_calculateTokenValues()` function public and ran the following test case:

```solidity
    function test_H06_IncorrectTokenValueCalculation() external {
        // Make WBTC price feed unavailable
        vm.startPrank(owner);
        IPriceFeed(priceFeed).setChainlinkPriceFeed(address(wbtc), address(0), 0);
        vm.stopPrank();

        console.log("Calc tokens value:", 
            ILeverager(leverager)._calculateTokenValues(
                address(wbtc),
                address(usdc),
                1e8, // 1 WBTC
                100_000e6, // 100_000 USDC
                90_000e30 // Price: $90,000/WBTC
            )
        );
    }
```

Since `wbtc` does not have a price feed, the value of `1 WBTC` should be calculated from TWAP price.

As the TWAP price is `$90,000` per `WBTC`, the total tokens value should be `$100,000 + $90,000 = $190,000` 

However after running the test case, it was calculated as `$9,100,000(=9_100_000e18)`.
