# Potential Overflow in _calcDeposits Under Extreme Conditions

### Summary

In [Vault.sol:149](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L149), there is a potential overflow risk in the calculation:

```solidity
shares = cross * totalSupply / (bal0 * bal1);
```
The multiplication `cross * totalSupply` could lead to an overflow, particularly for pools with low-priced tokens such as the PEPE-WETH-0.3% Uniswap v3 pool.

### Root Cause

In [Vault.sol:149](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L149), there is a potential overflow risk in the calculation:

```solidity
shares = cross * totalSupply / (bal0 * bal1);
```
The multiplication `cross * totalSupply` could lead to an overflow, particularly for pools with low-priced tokens such as the PEPE-WETH-0.3% Uniswap v3 pool.

To prevent this, the calculation should use FullMath library (or better OpenZeppelin's Math.mulDiv) for precise and safe multiplication and division without overflows:

```solidity
shares = Math.mulDiv(cross, totalSupply, bal0 * bal1);
```

### Internal Pre-conditions

1. `Strategy` should be deployed for low-priced or high-decimal tokens. (PEPE-WETH-0.3%)
2. Initial deposit should take into account the low-priced token, so `totalSupply` corresponds to the amount of the low-priced token

### External Pre-conditions

no

### Attack Path

1. `Depositor` calls `deposit` function in the `Vault.sol`

### Impact

The current implementation in Vault.sol:163 makes it impossible to execute a large deposit in a single transaction due to potential overflows.

### Mitigation

Replace the existing calculation in `Vault.sol:163` with:

```solidity
    shares = Math.mulDiv(cross, totalSupply, bal0 * bal1);
```

Additionally, avoid using `FullMath`, as OpenZeppelin provides a well-tested and optimized alternative.
