# LendingPool accumulates dust debt due to inconsistent rounding in borrowing index calculations


## Summary
A rounding down discrepancy in the leverage position's debt calculation causes the `LendingPool`'s `totalBorrows` to become permanently larger than the sum of all position debts. This discrepancy accumulates over time and creates unrecoverable dust debt in the protocol.

## Root Cause
In [`Leverager.sol#L209-L293`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L209-L293), the `withdraw()` function calculates debt using rounding down:

```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        Position memory up = positions[wp.id];
        require(_isApprovedOrOwner(msg.sender, wp.id), "msg.sender not approved or owner");
        require(wp.pctWithdraw <= 1e18 && wp.pctWithdraw > 0.01e18, "invalid pctWithdraw");

        address borrowed = up.denomination;
        uint256 sharesToWithdraw = up.shares * wp.pctWithdraw / 1e18;

        (uint256 amountOut0, uint256 amountOut1) =
            IVault(up.vault).withdraw(sharesToWithdraw, wp.minAmount0, wp.minAmount1);

        uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(borrowed);
->      uint256 totalOwedAmount = up.borrowedAmount * bIndex / up.borrowedIndex;
        uint256 owedAmount = totalOwedAmount * wp.pctWithdraw / 1e18;

        .............................................................................
    }
```

While in `ReserveLogic.sol`, the `_updateIndexes()` function updates the total borrows:

```solidity
    function _updateIndexes(DataTypes.ReserveData storage reserve) internal {
        uint256 newBorrowingIndex = reserve.borrowingIndex;
        uint256 newTotalBorrows = reserve.totalBorrows;

        if (reserve.totalBorrows > 0) {
            newBorrowingIndex = latestBorrowingIndex(reserve);
            newTotalBorrows = newBorrowingIndex * (reserve.totalBorrows) / (reserve.borrowingIndex);

            require(newBorrowingIndex <= type(uint128).max);

            reserve.borrowingIndex = newBorrowingIndex;
            reserve.totalBorrows = newTotalBorrows;
        }
        reserve.lastUpdateTimestamp = uint128(block.timestamp);
    }
```

The rounding down in `Leverager.sol` combined with the index updates in `ReserveLogic.sol` creates a situation where the total borrows in `LendingPool` becomes larger than the sum of all position debts.

## Internal pre-conditions
1. At least two leveraged positions exist in the system
2. Both positions have borrowed the same denomination token

## External pre-conditions
1. Time has elapsed since `reserve.lastUpdateTimestamp`
2. Borrowing index has increased due to interest accrual

## Attack Path
1. Two positions are created with 1e8 debt each for the same denomination token
   - `LendingPool.totalBorrows = 2e8`
   - Initial `borrowingIndex = 1e27`
2. Time passes and interest accrues
   - New `borrowingIndex = 1.2e27 + 0.5e19`
3. Position debts are updated with rounding down:
   - Each position: `1e8 * (1.2e27 + 0.5e19)/1e27 = 1.2e8`
   - Sum of position debts = `2.4e8`
4. LendingPool updates total borrows:
   - `newTotalBorrows = 2e8 * (1.2e27 + 0.5e19)/1e27 = 2.4e8 + 1`
5. The difference of 1 becomes unrecoverable dust debt
6. This discrepancy compounds with each leverage operation (open, withdraw, liquidate)

## Impact
The protocol accumulates permanent dust debt that:
1. Cannot be recovered through normal operations
2. Grows over time with user actions
3. Creates accounting discrepancies between actual and recorded debt

## Mitigation
Implement consistent rounding across the system
Use rounding up in `Leverager.sol` when calculating total owed debt
