# Incorrect Token Used When Calculating Repayment Amounts During Withdrawals

### Description

There's a serious flaw in the `withdraw` function of the `Leverager` contract. When a user withdraws from a leveraged position where token1 is the borrowed asset, the contract incorrectly determines the amount to repay from the withdrawn tokens. This miscalculation could allow users to underpay their debt while still retrieving their full collateral, potentially leading to insolvency.

### Affected Code

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L226C1-L235C10

```solidity
        // If either token is the borrowed asset, repayment is taken directly.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount; //incorrect token 
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```

### Vulnerability Details

The `withdraw` function contains a logic error when calculating how much of token1 should be used to repay debt. The issue arises because of a variable mismatch:

1. When `amountOut1 < owedAmount`, the calculation incorrectly references `amountOut0` instead of `amountOut1`.
2. The function then reduces `amountOut1` by the miscalculated `repayFromWithdraw` value.
3. This leads to two major issues:
   - If `amountOut0 > amountOut1`, the function may attempt to subtract too much from `amountOut1`, leading to an arithmetic underflow.
   - If `amountOut0 < amountOut1`, the repayment amount may be smaller than it should be, effectively letting users underpay their debt.

This bug becomes exploitable when a leveraged position meets the following conditions:
- token1 is the borrowed asset
- The position has significantly more token0 than token1
- The user can withdraw in a way that triggers the incorrect repayment calculation

**Proof of Concept:**
1. Open a leveraged position borrowing token1.
2. Structure the position so that upon withdrawal, `amountOut1 < owedAmount`, and `amountOut0` is minimized.
3. Call `withdraw` with a percentage that triggers the vulnerable code.
4. The function incorrectly calculates `repayFromWithdraw` based on `amountOut0` instead of `amountOut1`.
5. The user effectively underpays their debt while withdrawing full collateral.

### Tools Used

Manual Review

### Recommended Fix

Correct the token reference in the repayment calculation:

```solidity
if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount; //fix
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
