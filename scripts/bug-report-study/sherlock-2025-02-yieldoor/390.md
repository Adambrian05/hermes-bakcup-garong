# Protocol may accumulate bad debt when collateral and debt token prices decrease simultaneously


## Summary
The protocol's minimum borrow checks fail to account for real-time value of borrowed assets, which can lead to dust-sized debts when both collateral and debt token prices decrease. These positions become economically unviable for liquidators to manage, resulting in accumulated bad debt for the protocol.

## Root Cause
In [`Leverager.sol#L459-L474`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L459-L474), the `_checkWithinLimits()` function checks minimum borrow amount only at position opening:

```solidity
    function _checkWithinlimits(Position memory up) internal {
        VaultParams memory vp = vaultParams[up.vault];
        (uint256 maxIndividualBorrow, uint256 maxLevTimes) =
            ILendingPool(lendingPool).getLeverageParams(up.denomination);

        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

->      require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
        require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        require(up.initBorrowedUsd <= vp.maxUsdLeverage, "too high borrow usd amount");
        require(up.borrowedAmount <= maxIndividualBorrow, "too high borrow for the vault");
        require(
            vaultParams[up.vault].currBorrowedUSD <= vaultParams[up.vault].maxCumulativeBorrowedUSD,
            "vault exceeded borrow limit"
        );
    }
```

However, in the `withdraw()` function, the check only considers the initial borrowed value without accounting for price changes:

```solidity
            // Here, it doesn't matter that the initBorrowedUsd doesn't represent the real value. The scenarios are 2:
            // 1) Price has dropped. In this case, this would allow the user to actually have less than minBorrow opened,
            // but since borrowed asset's price has dropped, position is less likely to be liquidated
            // 2) Price has increased. In this case the user has to remain higher position value.
            require(
                up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18 > minBorrow,
                "remaining should be at least minBorrow"
            );
```

The developer's comment acknowledges price drops but fails to consider the scenario where both collateral and debt token prices decrease simultaneously, leading to economically unviable positions.

## Internal pre-conditions
1. Position exists with borrowed amount close to `minBorrow`
2. Position has been partially withdrawn, leaving borrowed amount near minimum threshold

## External pre-conditions
1. Market conditions cause simultaneous price decrease in both:
   - Position's collateral token
   - Position's debt token

## Attack Path
1. User opens a leveraged position with borrowed amount slightly above `minBorrow`
2. Market conditions cause both collateral and debt token prices to decrease
3. User performs partial withdrawal, leaving position with nominal value above `minBorrow`
4. Real value of debt becomes too small for liquidators to profit from liquidation
5. Position becomes effectively abandoned, creating bad debt for the protocol

## Impact
The protocol accumulates bad debt through positions that:
1. Are too small to be economically viable for liquidation
2. Cannot be effectively managed due to gas costs exceeding potential returns
3. May require protocol intervention or loss socialization to resolve

## Mitigation
Add a logic to `Leverage.sol#withdraw()` so that remained borrowed value is not less than minimum borrowed value.
