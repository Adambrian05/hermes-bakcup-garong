# The partial withdrawal logic in Leverager.sol will permit under-collateralized withdrawals for borrowers as the price of the borrowed asset increases

### Summary

The reliance on a static `initBorrowedUsd` value within `Leverager.sol`’s `withdraw()` function will cause under-collateralized positions for borrowers as the price of the borrowed asset increases, since the protocol does not re-check real-time debt value. An attacker can repeatedly withdraw collateral based on stale pricing information, leaving the protocol exposed to unrecognized bad debt.

### Root Cause

In [`Leverager.sol:209`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L209): 
Within the `withdraw()` function (see below), the leftover debt check uses `up.initBorrowedUsd` recorded at position opening. This value remains fixed and never updates even if the borrowed asset’s market price appreciates significantly.  
   ```solidity
   require(
       up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18 > minBorrow,
       "remaining should be at least minBorrow"
   );
   ```

### Internal Pre-conditions

1. A user must have opened a leveraged position whose `initBorrowedUsd` was recorded at some earlier price point.  
2. The borrowed token’s price must have increased after the position was opened, but `initBorrowedUsd` is never updated.  
3. The protocol’s `positions[_id].initBorrowedUsd` remains the reference for partial-withdraw checks.

### External Pre-conditions

The borrowed asset’s price must have increased compared to its value at position creation.  

### Attack Path

1. The borrower opens a leveraged position at a time when the borrowed token price is X.  
2. The borrowed token’s price then increases to a higher value.  
3. The borrower calls `Leverager.withdraw()` for a partial withdrawal. The code enforces a leftover `initBorrowedUsd > minBorrow`, without re-checking the newly higher USD debt.  
4. Collateral is thus withdrawn while the actual debt, in current USD terms, is significantly higher than accounted for.

### Impact

The protocol and lenders risk taking on bad debt because borrowers can withdraw more collateral than the real-time debt allows. Over multiple such withdrawals or in quickly changing markets, positions can become effectively underwater. If liquidation does not occur immediately, the protocol becomes exposed to significant losses.

### Mitigation

Re-check Real-Time USD Value. During partial withdrawals, compute the current debt value using up-to-date price feeds. Replace the static “initBorrowedUsd” comparisons with a fresh price-based calculation.
