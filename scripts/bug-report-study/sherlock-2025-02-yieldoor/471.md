# Incorrect Observation Access in checkPoolActivity Function Leads to Unreliable Price Manipulation Detection

## Summary
The `checkPoolActivity()` function in the Strategy contract attempts to detect price manipulation by directly accessing Uniswap V3 pool observations by index. This approach is fundamentally flawed because Uniswap V3 uses a circular buffer for observations that requires special handling. The current implementation may fail to detect price manipulation or incorrectly flag normal price movements as suspicious, potentially allowing attackers to manipulate prices during rebalancing or preventing legitimate rebalancing operations.

## Vulnerability Details
The Strategy contract's [`checkPoolActivity()` function is designed to detect abnormal price movements](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L310) in the underlying Uniswap V3 pool by examining historical price observations. However, the implementation incorrectly attempts to access these observations directly:

```solidity
function checkPoolActivity() public view returns (bool) {
    (, int24 tick, uint16 currentIndex, uint16 observationCardinality,,,) = IUniswapV3Pool(pool).slot0();

    uint32 lookAgo = uint32(block.timestamp) - twap;

    (uint32 nextTimestamp, int56 nextCumulativeTick,,) = IUniswapV3Pool(pool).observations(currentIndex);

    int24 nextTick = tick;

    for (uint16 i = 1; i <= observationCardinality; i++) {
        uint256 index = (observationCardinality + currentIndex - i) % observationCardinality;
        (uint32 timestamp, int56 tickCumulative,,) = IUniswapV3Pool(pool).observations(index);
        if (timestamp == 0) {
            revert("timestamp 0");
        }

        tick = int24((nextCumulativeTick - tickCumulative) / int56(uint56(nextTimestamp - timestamp)));

        (nextTimestamp, nextCumulativeTick) = (timestamp, tickCumulative);
        int24 delta = nextTick - tick;

        if (delta > maxObservationDeviation || delta < -maxObservationDeviation) {
            return false;
        }

        if (timestamp < lookAgo) {
            return true;
        }
        nextTick = tick;
    }

    return false;
}
```

This implementation has several critical flaws:

1. **Circular Buffer Mishandling**: Uniswap V3 stores observations in a circular buffer, but the code doesn't properly account for this structure. The index calculation[ `(observationCardinality + currentIndex - i) % observationCardinality`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L320) attempts to handle this but can not correctly identify the right observations.

2. **Timestamp Interpretation**: The code[ assumes direct access to timestamps and cumulative ticks](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L321), but doesn't account for how Uniswap manages these values internally.

3. **Tick Calculation Errors**: The manual calculation of tick differences between observations is error-prone and doesn't match Uniswap's internal logic.

4. **Observation Gaps**: Not all slots in the observation array may be initialized, which the current implementation doesn't handle properly.

## Impact Details
This vulnerability could allow attackers to manipulate pool prices during rebalancing operations without being detected, potentially leading to financial losses for the protocol and its users. Conversely, it might also prevent legitimate rebalancing operations by incorrectly flagging normal price movements as suspicious, reducing the efficiency of the strategy and potentially causing opportunity costs.

## Recommendations
Replace the current implementation with the correct approach using Uniswap V3's `observe()` method:

```js
function checkPoolActivity() public view returns (bool) {
    // Create an array of secondsAgos values to check observations at regular intervals
    uint32 interval = twap / 5; // Check 5 points within the TWAP period
    if (interval == 0) interval = 1;
    
    uint32[] memory secondsAgos = new uint32[](6);
    for (uint i = 0; i < 6; i++) {
        secondsAgos[i] = i * interval;
    }
    
    // Get observations from the pool
    (int56[] memory tickCumulatives, ) = IUniswapV3Pool(pool).observe(secondsAgos);
    
    // Check for large price movements between consecutive observations
    for (uint i = 0; i < 5; i++) {
        int56 tickCumulativeDelta = tickCumulatives[i] - tickCumulatives[i + 1];
        int24 avgTick = int24(tickCumulativeDelta / int32(secondsAgos[i + 1] - secondsAgos[i]));
        
        // If we're looking at the most recent observation compared to the previous one
        if (i == 0) {
            (, int24 currentTick, , , , , ) = IUniswapV3Pool(pool).slot0();
            int24 delta = currentTick - avgTick;
            if (delta > maxObservationDeviation || delta < -maxObservationDeviation) {
                return false;
            }
        } 
        // For older observations, compare them to each other
        else if (i < 5) {
            int56 prevTickCumulativeDelta = tickCumulatives[i - 1] - tickCumulatives[i];
            int24 prevAvgTick = int24(prevTickCumulativeDelta / int32(secondsAgos[i] - secondsAgos[i - 1]));
            
            int24 delta = avgTick - prevAvgTick;
            if (delta > maxObservationDeviation || delta < -maxObservationDeviation) {
                return false;
            }
        }
    }
    
    return true;
}
```

This implementation correctly uses Uniswap V3's observation system by:
1. Creating an array of "seconds ago" values to sample at regular intervals
2. Using the pool's `observe()` method to get the cumulative tick values
3. Properly calculating average ticks between observations
4. Comparing consecutive observations to detect abnormal price movements
