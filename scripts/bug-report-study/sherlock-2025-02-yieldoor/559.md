# `totalOwedAmount` Should Be Calculated by `Rounding Up` in the `Leverager.withdraw()` Function

### Summary

When withdrawing, the `totalOwedAmount` is calculated by rounding down. This rounding down results in the actual total repayment amount being slightly less than the `reserveData`'s `totalBorrows` in the `LendingPool`. Consequently, there will be insufficient amounts in the `LendingPool`.

### Root Cause

The [Leverager.withdraw()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L221) function calculates `totalOwedAmount` by rounding down. This means that users will repay based on this rounded-down value.

As a result, the total repayment amount will be slightly less than the recorded `totalBorrows` in the `reserveData` struct of the corresponding asset in the `LendingPool`. This will lead to an insufficient balance compared to what is actually needed in the `LendingPool`.

```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        Position memory up = positions[wp.id];
        require(_isApprovedOrOwner(msg.sender, wp.id), "msg.sender not approved or owner");
```
