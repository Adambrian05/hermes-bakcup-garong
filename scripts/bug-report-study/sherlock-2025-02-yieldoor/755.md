# Incorrect Token Burning Mechanism Leads to Potential Accounting Errors

### Summary

The [`burn`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/yToken.sol#L47) function in the yToken contract improperly handles token burning, potentially causing significant accounting discrepancies and preventing users from redeeming their tokens.

### Root Cause

In `yToken.sol`, the burn function incorrectly uses `msg.sender` as the account to burn tokens from:

```solidity
function burn(
    address receiverOfUnderlying,
    uint256 yTokenAmount,
    uint256 underlyingTokenAmount
) external onlyLendingPool nonReentrant {
    _burn(msg.sender, yTokenAmount);
    IERC20(underlyingAsset).safeTransfer(
        receiverOfUnderlying,
        underlyingTokenAmount
    );
}
```

### Internal Pre-conditions

1. yToken contract initialized
2. Lending pool as the only authorized caller
3. User has minted tokens

### External Pre-conditions

1. No additional external dependencies
2. Standard ERC20 token mechanics
3. Non-upgradeable contract

### Attack Path

1. Identify the incorrect burning mechanism
2. Attempt to burn tokens from lending pool
3. Prevent users from redeeming their tokens
4. Create accounting discrepancies in the protocol

### Impact

- Users unable to redeem tokens
- Potential permanent locking of user funds
- Significant accounting errors
- Breakdown of token redemption mechanism
- Potential protocol insolvency

### PoC

```solidity
function test_incorrectTokenBurning() public {
    vm.startPrank(owner);
    address testToken = address(new ERC20("Test", "TST"));
    address testLendingPool = address(this);
    
    yToken token = new yToken("yTest", "YTST", 18, testToken);
    
    address user = address(0x123);
    uint256 initialMintAmount = 1000e18;
    
    vm.startPrank(testLendingPool);
    token.mint(user, initialMintAmount);
    
    uint256 burnAmount = 500e18;
    uint256 underlyingAmount = 500e18;
    
    vm.expectRevert("ERC20: burn amount exceeds balance");
    token.burn(user, burnAmount, underlyingAmount);
}
```

### Mitigation

1. Modify burn function to accept the account to burn from
2. Add explicit access control for token burning
3. Implement strict validation of burn parameters
