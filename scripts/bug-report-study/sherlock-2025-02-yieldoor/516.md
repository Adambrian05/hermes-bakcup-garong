# The lack of slippage protection in Strategy.sol's liquidity addition will cause fund loss for liquidity providers (LPs)

### Summary

The lack of slippage protection in Strategy.sol's liquidity addition will cause fund loss for liquidity providers (LPs) as MEV bots will sandwich transactions to force unfavorable prices, extracting value from the protocol.

### Root Cause

In Strategy.sol's `_addLiquidityToMainPosition`, the code mints liquidity without specifying `amount0Min` or `amount1Min`. The parameters are `amount0` and `amount1` as max, but no minimums. This could allow MEV attacks or slippage issues. The fix would be to include slippage parameters here, possibly passed from higher functions.

### Attack Path

1. MEV bot detects liquidity addition tx in mempool
2. Front-runs with large swap to skew pool price
3. Protocol adds liquidity at manipulated price
4. Bot reverses swap to restore original price
5. Result:
- LP tokens minted at inflated price → immediate paper loss
- MEV profit = (manipulatedPrice - actualPrice) * liquidity

### Impact

- LPs lose 1-5% per tx to MEV extraction
- Protocol TVL erosion from repeated attacks

### Mitigation

Add `amount0Min` and `amount1Min` parameters in Strategy's liquidity addition functions, passed from user input with sensible defaults.
