# Users opening leveraged positions in the `Leverager` have no control over the final leverage

### Summary

`Leverager::openLeveragedPosition()` places most key checks but misses checking the leverage that the position ends up with. This is problematic because the leverage may be too risky for the user and could be liquidated unexpectedly.
The collateral tokens amount is controlled by the parameters sent, and so is any swap sent, but the ratio between collateral and debt is not, according to the oracles used. Keep in mind that swaps are not even necessary for users to open borrow positions, so for simplicity this can be ignored.

### Root Cause

In the [Leverager](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L103), the leverage is not checked.

### Internal Pre-conditions

None.

### External Pre-conditions

None.

### Attack Path

1. User calls `Leverager::openLeveragedPosition()`.
2. Token0, token1, borrow asset price update frontruns the user.
3. User gets a significantly higher leverage than intended.

### Impact

User risks being liquidated due to having a bigger leveraged than intended. Or, the user wanted higher leveraged to get better returns and didn't achieve it. 

### PoC

The collateral value of the position is calculated as `up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;`.
`up.initCollateralUsd` is the USD value of the position in the uniswap pool, according to the price fees. `bPrice` is the price of the asset borrowed.
Thus, these prices may be updated since the user calls the function offchain, and will affect the leverage the user gets. Chainlink prices may be updated in not very regular intervals (few hours or even half a day), so the price difference can be very significant. Even in regular updates of [1 hour](https://data.chain.link/feeds/optimism/mainnet/wbtc-usd), the price still changes 1-2%.

### Mitigation

Add a max leverage parameter.
