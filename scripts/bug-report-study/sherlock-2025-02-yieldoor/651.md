# Leverage Validation Bypass via Incorrect Collateral Calculation in `Leverager._checkWithinlimits()`

### Summary

The function `Leverager._checkWithinlimits()` contains a critical vulnerability in its leverage validation logic where borrowed funds are incorrectly included in collateral value calculations. This allows attackers to open positions with 10x leverage while appearing compliant with the 5x maximum policy, creating systemic insolvency risk. The root cause stems from using total deposited amounts (including flash-loaned assets) rather than user-provided collateral when calculating leverage ratios.

### Root Cause

In function `Leverager._checkWithinlimits()` ([`Leverager.sol#L464`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464)), the collateral value calculation incorrectly includes borrowed funds when determining position leverage. The position's `initCollateralValue` is derived from the total deposited amount (contract calls deposit with `lp.vault0In` and `lp.vault1In`, return the total actual deposit `a0` and `a1`), which contains both user-provided collateral and flash-borrowed assets from `Leverager.pullFunds()`, rather than using only the user's actual transferred amounts (`lp.amount0In` and `lp.amount1In`).

This flaw causes the leverage ratio calculation in `Leverager._checkWithinlimits()` ([`Leverager.sol#L464`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464)) to use an artificially inflated collateral base that includes borrowed funds, allowing positions to bypass maximum leverage limits by underreporting their true risk exposure.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. **Attacker deposits 1 ETH collateral** while borrowing 9 ETH via `pullFunds()`
   - Total position size = 10 ETH (1 ETH real collateral + 9 ETH debt)
   
2. **Protocol miscalculates leverage using full position as collateral**
   - Reports: (10 ETH position + 9 ETH debt) / 10 ETH = 1.9x leverage
   - Reality: 10 ETH position / 1 ETH collateral = 10x leverage

3. **Position passes 5x leverage validation**
   - Protocol allows creation despite matching max limit through incorrect math

### Impact

The flawed collateral calculation renders leverage limits ineffective:
- **10x real leverage** positions get approved as "1.9x" through distorted math
- **100% overleverage** compared to 5x maximum policy
- **Protocol insolvency risk** when multiple positions reach 10x leverage - market downturn would create system-wide bad debt

_No response_

### Mitigation

**Update leverage ratio calculation**:

```solidity
        uint256 positionLeverage = up.initCollateralValue * 1e18 / (up.initCollateralValue - up.borrowedAmount);
```
