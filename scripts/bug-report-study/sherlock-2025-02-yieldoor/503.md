# Protocol will accumulate bad debt when positions cannot be liquidated due to USDT/USDC blacklisting

### Summary

The lack of alternative recipient specification for token transfers will cause accumulation of bad debt for the protocol as positions become unliquidatable when USDT/USDC blocks addresses involved in the liquidation process.

### Root Cause

In the Leverager contract, multiple functions hardcode `msg.sender` as the token recipient without providing an alternative mechanism, creating systemic protocol risk when centralized stablecoins block addresses:

In `withdraw` function, `Leverager.sol`:

```solidity
if (amountOut0 > 0) IERC20(up.token0).safeTransfer(msg.sender, amountOut0);
if (amountOut1 > 0) IERC20(up.token1).safeTransfer(msg.sender, amountOut1);
```

In `liquidatePosition` function, `Leverager.sol

```solidity
if (amount0 > 0) IERC20(up.token0).safeTransfer(msg.sender, amount0);
if (amount1 > 0) IERC20(up.token1).safeTransfer(msg.sender, amount1);
```

In `_sweepTokens` function, `Leverager.sol

```solidity
if (bal > 0) IERC20(token0).safeTransfer(msg.sender, bal);
if (bal > 0) IERC20(token1).safeTransfer(msg.sender, bal);
```

The most critical impact occurs in the liquidation process, where positions become unliquidatable if USDT/USDC blacklists liquidator addresses, causing the protocol to accumulate bad debt that cannot be resolved through normal liquidation mechanisms.

### Internal Pre-conditions

1. A leveraged position exists where either `token0` or `token1` is a centralized stablecoin like USDT or USDC
2. The position becomes underwater and eligible for liquidation
3. No alternative recipient option exists in the protocol design for liquidation proceeds

### External Pre-conditions

1. Position owner or potential liquidators become blacklisted by the centralized stablecoin issuer
2. Market conditions make the position eligible for liquidation

### Attack Path

This is not an attack but a vulnerability scenario affecting protocol health:

1. A position involving USDT/USDC becomes underwater and eligible for liquidation
2. Liquidator attempts to liquidate the position by calling `liquidatePosition()`
3. The transaction reverts when trying to transfer USDT/USDC to the liquidator if they are blacklisted
4. Position remains unliquidated, continuing to accrue debt to the protocol
5. Protocol accumulates bad debt as multiple unliquidatable positions can build up over time
6. Additional liquidators face the same issue, preventing protocol recovery

### Impact

The protocol suffers significant risks including:

1. **Bad debt accumulation**: Positions that should be liquidated remain active and continue to accrue debt
2. **Protocol insolvency risk**: As bad debt accumulates, the protocol may become insolvent
3. **Systemic risk**: Other users' positions may be affected as protocol reserves are depleted


### PoC

_No response_

### Mitigation

1. Modify token transfer functions to accept an optional recipient address parameter
2. Implement a protocol-level emergency liquidation mechanism for handling problematic positions

These changes would significantly reduce the protocol's exposure to centralized stablecoin blacklisting risks while maintaining the current functionality.
