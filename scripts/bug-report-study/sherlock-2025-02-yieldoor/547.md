# Incorrect Chainlink Price Precision Handling in Leverager Contract

### Summary

In the Leverager contract, all Chainlink price feeds are assumed to have a precision of 1e18, while some Chainlink oracles actually return prices with a precision of 1e8 (or other values, the [pricefeed](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/PriceFeed.sol#L57-L62) contract does not perform any handling or adjustments.). This incorrect assumption causes the contract to miscalculate initCollateralValue, affecting liquidation logic.
As a result, users might experience:
	1.	Premature liquidation.
	2.	Delayed liquidation.
The exact impact depends on the token’s actual price precision.

### Root Cause

In [Leverager](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L129-L131), the contract assumes that all Chainlink price feeds return prices with 18 decimal places (1e18), when in reality, some Chainlink oracles return 8 decimals (1e8) or other values.

### Internal Pre-conditions

The returned price has a precision different from 1e18 (e.g., 1e8).

### External Pre-conditions

A user opens a leveraged position that relies on the miscalculated price.

### Attack Path

1.	A user opens a leveraged position based on an incorrect price.
2.	The contract miscalculates initCollateralValue, leading to incorrect liquidation thresholds. The precision of `initCollateralUsd` is based on the Chainlink precision of token0 or token1, and `bPrice` is based on the Chainlink precision of the denomination. If one of these precisions is 1e18 and the other is 1e8, then `initCollateralValue` will have a significant deviation.
https://docs.chain.link/data-feeds/price-feeds/addresses?network=optimism&page=2&search=usd

```solidity
        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); // returns the USD price in 1e18
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;
```

### Impact

This could lead to erroneous value assessments by the protocol and incorrect liquidation actions.

### PoC

_No response_

### Mitigation

Scale prices correctly based on actual precision.
