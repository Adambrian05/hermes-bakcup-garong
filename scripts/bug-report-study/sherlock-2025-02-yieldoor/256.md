# rebalancing positions makes vesting position fees unclaimable

### Summary

The `Strategy::collectFees()` function, which collects all outstanding position fees, uses `vestPosition.tickLower` and `mainPosition.tickUpper` to claim vest position fees. However, as `mainPosition.tickUpper` changes and is no longer equal to `vestPosition.tickUpper`, the vest position fees become unclaimable. This causes the protocol to attempt fee collection from a non-existent position, leaving the vest position fees unclaimed.

### Root Cause

Inside the `Strategy::collectFees()` function on [L167](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167), the values of `vestPosition.tickLower` and `mainPosition.tickUpper` are passed to the `Strategy::collectPositionFees()` function to collect the vest position fees. Initially, this is not an issue since `mainPosition.tickUpper` is equal to `vestPosition.tickUpper`. However, as market conditions change and the `Strategy::rebalance()` function is called, the lower and upper ticks of the main position are adjusted, making the upper tick different from that of the vest position.

### Internal Pre-conditions

1. `Strategy::rebalanceInterval` needs to pass for the `Strategy::rebalance()` function to be callable
2. Rebalancer needs to call the `Strategy::rebalance()` function

### External Pre-conditions

1. Market conditions need to change enough for it to be necessary to rebalance positions.

### Attack Path

1. The users perform swaps changing the price of the liquidity pool
2. As market conditions change the rebalancer calls the `Strategy::rebalance()` function
3. As the upper tick of the main position changes after the rebalance and is no longer equal to the vest position upper tick, the vest position fees become unclaimable

### Impact

The vest position fees are left unclaimable, causing the users and the protocol to suffer losses.

### PoC

append the following test to `BaseTest.sol`

```solidity
function test_MainAndVestingPositionsHaveDifferentTicksAfterRebalance() public {
        vm.startPrank(owner);

        //----------Add a new vesting position----------
        deal(address(wbtc), owner, 2e8);
        deal(address(usdc), owner, 100_000e6);

        wbtc.approve(vault, type(uint256).max);
        usdc.approve(vault, type(uint256).max);

        (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();

        int24 tickLower = IStrategy(strategy).getMainPosition().tickLower;
        int24 tickUpper = IStrategy(strategy).getMainPosition().tickUpper;

        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPriceX96, TickMath.getSqrtRatioAtTick(tickLower), TickMath.getSqrtRatioAtTick(tickUpper), 2e8, 100_000e6
        );
        (uint256 amount0, uint256 amount1) = LiquidityAmounts.getAmountsForLiquidity(
            sqrtPriceX96, TickMath.getSqrtRatioAtTick(tickLower), TickMath.getSqrtRatioAtTick(tickUpper), liquidity
        );

        IVault(vault).addVestingPosition(amount0, amount1, 1 days);
        //---------------------------------------------

        console.log("main position tickLower before: ", IStrategy(strategy).getMainPosition().tickLower);
        console.log("main position tickUpper before: ", IStrategy(strategy).getMainPosition().tickUpper);

        console.log("vesting position tickLower before: ", IStrategy(strategy).getVestingPosition().tickLower);
        console.log("vesting position tickUpper before: ", IStrategy(strategy).getVestingPosition().tickUpper);

        // Initially vesting position and main position have the same lower/upper ticks
        assert(IStrategy(strategy).getMainPosition().tickLower == IStrategy(strategy).getVestingPosition().tickLower);
        assert(IStrategy(strategy).getMainPosition().tickUpper == IStrategy(strategy).getVestingPosition().tickUpper);

        vm.stopPrank();

        // User/s perform swap
        swapWbtc(5e8);

        vm.startPrank(rebalancer);

        // Pass enough time for rebalance to be callable
        skip(10 minutes);

        // As market conditions change, the rebalance function gets called by the rebalancer
        IStrategy(strategy).rebalance();

        vm.stopPrank();

        console.log("main position tickLower after: ", IStrategy(strategy).getMainPosition().tickLower);
        console.log("main position tickUpper after: ", IStrategy(strategy).getMainPosition().tickUpper);

        console.log("vesting position tickLower after: ", IStrategy(strategy).getVestingPosition().tickLower);
        console.log("vesting position tickUpper after: ", IStrategy(strategy).getVestingPosition().tickUpper);
    
        // After rebalance is called the lower/upper ticks of main and vesting position are no longer the same
        assert(IStrategy(strategy).getMainPosition().tickLower != IStrategy(strategy).getVestingPosition().tickLower);
        assert(IStrategy(strategy).getMainPosition().tickUpper != IStrategy(strategy).getVestingPosition().tickUpper);

        vm.stopPrank();
    }
```

### Mitigation

Consider making the following change inside the `Strategy::claimFees()` function.
```diff
function collectFees() public {
    (uint256 preBal0, uint256 preBal1) = idleBalances();

    if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
    if (secondaryPosition.liquidity != 0) {
        collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
    if (ongoingVestingPosition) {
-       collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+       collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
    }
    .
    .
    .
}
```
