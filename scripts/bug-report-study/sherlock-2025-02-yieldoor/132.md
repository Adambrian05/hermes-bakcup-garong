# DOS on the function `collectFees()` due to mistakenly using `mainPosition.tickUpper` to collect the fee of `vestPosition`

### Summary

When there exists a vesting position, the function `collectFees()` will also collect the vesting position's fee. However, the `tickUpper` is mistakenly assigned to be the `mainPosition.tickUpper` rather than the `vestPosition.tickUpper`.

[Strategy](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L166-L168)

```solidity
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
        }
```

Although when the vesting position is created, the `vestPosition.tickUpper` will be assigned to be the value of `mainPosition.tickUpper`. But it does not consider the situation when the main position is rebalanced and in that way the value of `mainPosition.tickUpper` will be different from the value of the `vestPosition.tickUpper`. 

Especially, in the circumstance that the value of the `mainPosition.tickUpper` is lower than the value of the `vestPosition.tickLower`, the process of collecting the vesting position's fee will revert due to the `tickLower < tickUpper` check in the pool.

[Strategy](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198-L215)

```solidity
    function rebalance() public onlyRebalancer {
        require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");

        _requirePriceWithinRange(); // we verify that the pool's price is currently not manipulated
        collectFees();

        _removeLiquidity();
        (uint256 amount0, uint256 amount1) = idleBalances();

        (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();

        _setMainTicks(tick);
        (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

        _setSecondaryPositionsTicks(tick);
        _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
        lastRebalance = block.timestamp;
    }
```





### Root Cause

The function `collectFees()` mistakenly uses `mainPosition.tickUpper` to collect the fee of `vestPosition`. And the value of `mainPosition.tickUpper` will be different from the value of `vestPosition.tickUpper` after rebalancing.

### Impact

Especially, in the circumstance that the value of the `mainPosition.tickUpper` is lower than the value of the `vestPosition.tickLower` after rebalancing, the process of collecting the vesting position's fee will revert due to the `tickLower < tickUpper` check in the pool.

This will cause the function `collectFees()` to be DOSed. And since the function `collectFees()` is invoked by the others important functions (i.e. `liquidatePosition`, `deposit`, `withdraw`). The whole protocol's important functions will be DOSed also.

### Mitigation

Use `vestPosition.tickUpper` to collect the fee of `vestPosition`.


```solidity
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
        }
```
