# The calculation in `openLeveragerPosition` will revert the whole transaction because of overflow

### Summary

When user calls `openLeveragedPosition` it may revert due to overflow due to the incorrect calculation within the function.

### Root Cause

[Leverager.sol::119-120](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L119-L120)
```solidity
uint256 delta0 = lp.vault0In - lp.amount0In;
uint256 delta1 = lp.vault1In - lp.amount1In;
if (delta0 > 0) ILendingPool(lendingPool).pullFunds(up.token0, delta0);
if (delta1 > 0) ILendingPool(lendingPool).pullFunds(up.token1, delta1); 
```

If `lp.vault0In < lp.amount0In` or `lp.vault1In < lp.amount1In` the whole transaction will fail due to overflow.

### Internal Pre-conditions

User construct `LeverageParams` to call `openLeveragedPosition`
- `lp.vault0In < lp.amount0In` or `lp.vault1In < lp.amount1In`

### External Pre-conditions

None.

### Attack Path

None.

### Impact

Causing the whole transfer failed.

### PoC

_No response_

### Mitigation

Consider using SafeMath contract from OpenZeppelin or another contract.
