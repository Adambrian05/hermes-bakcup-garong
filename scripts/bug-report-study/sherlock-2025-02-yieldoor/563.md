# First depositors can mint vault shares via token0 or token1

### Summary

In Vault, the first depositor can mint value shares via single token, token0 or token1. This will cause that later depositors can only deposit the token0 or token1. 

### Root Cause

In [Vault.sol:119](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119), we will calculate the minted share amount for the depositor.

As the first depositor, the depositor can choose any ratio between token0 and token1. The depositor can choose to deposit one token, for example 1e18 token0. Because share amount will be calculated via `(amount0 > amount1 ? amount0 : amount1) - (1000)`, the first depositor will get the expected shares.

After the first depositor, later depositors have to deposit the single token, token0. Because when we calculate the needed token1 amount, the needed token1 amount will be 0.

This will cause that we will have one imbalanced token0/token1. When the rebalancer want to rebalance and add liquidity into the uniswap v3 pool. Because we have only token0, the liquidity for the main position will be zero. If the price will keep in current price, our strategy will earn quite less profit than what we expected.

If anyone or the owner wants to donate some token1 into the strategy to make tokens more balanced, the first depositors will earn some profits because of this donation.

```solidity
    function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        uint256 totalSupply = totalSupply();

        assert(totalSupply == 0 || bal0 > 0 || bal1 > 0);

        if (totalSupply == 0) {
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
        } else if (bal0 == 0) {
            amount1 = depositAmount1;
            shares = amount1 * totalSupply / bal1;
        } else if (bal1 == 0) {
            amount0 = depositAmount0;
            shares = amount0 * totalSupply / bal0;
        }
```

### Internal Pre-conditions
One new vault/strategy is created. And the malicious user is the first depositor.

### External Pre-conditions
The sqrtPrice in the related pool keep stable. Then our secondary position's liquidity will not become active liquidity.
