# Incorrect implementation may completely DoS the strategy in rebalance and compound functions

### Summary

Incorrect implementation may completely DoS the strategy in rebalance and compound functions

### Root Cause

In [Strategy::_setSecondaryPositionTicks()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L373C2-L376C10) function, if statement incorrectly implemented. If the tick value has negative sign, it can't rebalance or compound because range still will cover the current price.

While adjusting the secondary position, price range should be always out of range according to current price. That's necessary because secondary position handles single side tokens. For instance, if we have only USDC in WETH/USDC pool. Secondary position will handle the entire USDC collateral with correct price range.

```solidity
        if (bal0in1 < bal1) {
            secondaryPosition.tickLower = mainPosition.tickLower;
            secondaryPosition.tickUpper = tick - modulo; 
        }
```

### Internal Pre-conditions

1. Balance token1 should be higher than balance token0

### External Pre-conditions

1. Tick should be negative

### Attack Path

Environment:
Tick spacing = 60
Current price tick = -130
Main position upper tick = 0
Main position lower tick = -240
Middle point of main position = -120
Pool WETH/USDT

Rebalance is called
Our previous position is out of range and lower than current price which means we have only USDC
Main position rebalanced but no liquidity is added
In second position adjustment bal0in1 < bal1
Modulo will be equal to -10 -> Solidity use following formula A%B = A - B * (A/B)
tick - modulo = -130 + 10 = -120 -> tick higher


Currently price is -130, higher tick is equal to -120, lower thick is equal to -240

Price still in the range

### Impact

In this circumstances, strategy completely DoSed. There is no way to add liquidity with rebalance or compound. In order to add liquidity using secondary position, the range shouldn't cover the current price.

### Mitigation

If modulo is negative it should add modulo instead of substracting
