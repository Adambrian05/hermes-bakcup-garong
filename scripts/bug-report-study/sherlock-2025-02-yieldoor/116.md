# Token amounts mismatch in repayFromWithdraw calculation in Leverager.sol:withdraw() function

### Summary

In [Leverager.sol:withdraw()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) function in case either of the tokens is denomination token, contract will take repay amount from it, but if `token1` is denomination token it will wrongly take the `amountOut0` related to `token0`.

### Root Cause

In `Leverager.sol:withdraw()` function token amounts mismatch:
```solidity
function withdraw(WithdrawParams calldata wp) external nonReentrant {
    ...
    // In case either of the tokens is denomination token, we directly take from it.
    if (borrowed == up.token0) {
        //@audit token0 -> amountOut0 -> correct
        uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
        owedAmount -= repayFromWithdraw;
        amountOut0 -= repayFromWithdraw;
    } else if (borrowed == up.token1) {
        //@audit token1 -> amountOut0 -> incorrect
        uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
        owedAmount -= repayFromWithdraw;
        amountOut1 -= repayFromWithdraw;
    }
    ...
}
```

### Internal Pre-conditions

1. Denomination token is `token1`

### Mitigation

Correct code:
```solidity
} else if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
