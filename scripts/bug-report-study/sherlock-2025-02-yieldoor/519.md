# `repayFromWithdraw` is assigned wrong value in `Leverager::withdraw` function will cause `amountOut1` to be miscalculated or underflow error when subtracting `repayFromWithdraw`

### Summary

`repayFromWithdraw` is assigned wrong value in `Leverager::withdraw` function will cause:
- `amountOut1` to be miscalculated.
Or:
- Underflow error when subtracting `repayFromWithdraw` if `owedAmount` and `amountOut1` are smaller than `repayFromWithdraw`.

### Root Cause

In `withdraw` function, when calculating `repayFromWithdraw`, in [Leverager.sol:L232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232). `repayFromWithdraw` is assigned wrong value. That if `amountOut1` < `owedAmount`, `repayFromWithdraw` must take the `amountOut1` value, but it is assigned `amountOut0` value. Leading to the wrong calculation of `amountOut1` in [Leverager.sol:L234](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L234)

Additionally, if `amountOut0` is greater than `owedAmount` and `amountOut1`, the calculation of `owedAmount` and `amountOut1` in [Leverager.sol:L233-L234](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L233-L234) will throw an underflow error.

### Internal Pre-conditions

User call openLeveragedPosition() with:
- The borrowed token is token1.
- The amount of token 1 when opening leverage position (vault1In) is smaller than or equal the amount that owe to the lending pool.


### External Pre-conditions

The underflow errow will happen when:
- The `amountOut0` is greater than `owedAmount` and `amountOut1`. 
There are many cases leading to this, such as:
1. The decimals of token0 is 18 and token1 is 6.
2. The price value of token0 is smaller than token1.

### Attack Path

1.  The token0 is UNI token (address 0x1f9840a85d5aF5bf1D1762F925BDADdC4201F984),  and token1 is WETH token (address 0xC02aaA39b223FE8D0A0e5C4F27eAD9083C756Cc2).
2. User call openLeveragedPosition() with params like this: 
```solidity
        lp.amount0In = 312e18; // UNI
        lp.amount1In = 0; // WETH
        lp.vault0In = 312e18;
        lp.vault1In = 1e18;
        lp.vault = vault2; // This vault is working with UNI and WETH token.
        lp.maxBorrowAmount = 1e18;
        lp.denomination = address(weth);
```
This transaction goes through.

3. User call withdraw() with any appropriate percentage.
 This transaction will always revert.

### Impact

The withdraw function is not working as intended and in some scenarios will cause underflow error.

### Mitigation

Change `amountOut0` to `amountOut1` in [Leverager.sol:L232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232)

```diff
    function withdraw(WithdrawParams calldata wp) external nonReentrant {

.
.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
```
