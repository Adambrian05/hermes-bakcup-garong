# Temporary DoS in `openLeveragedPosition` via Donation Attack on `denomBalance` Calculation

### Summary

The `openLeveragedPosition` function updates the `up.borrowedAmount variable by subtracting `denomBalance` from `lp.maxBorrowAmount`. However, if an attacker donates a large amount of denomination tokens to the contract, `denomBalance` can become greater than `lp.maxBorrowAmount`. Since `lp.maxBorrowAmount` cannot exceed `reserve.availableLiquidity()`, this causes a situation where the function fails to proceed until the available liquidity in the lending pool exceeds the donated amount.

If the reserve has a `reserveCapacity` limit, a donation greater than `reserveCapacity` can result in a more severe and prolonged DoS attack, as further deposits greater than `reserveCapacity` is not allowed. 

### Root Cause

1. **Incorrect Assumption About denomBalance:**
- The function assumes that `denomBalance` represents only borrowed funds, but external actors (attackers) can inflate it by donating excess tokens to the contract.

2. **Subtraction Logic in `borrowedAmount` Calculation:**
- The function sets:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L177
- If `denomBalance > lp.maxBorrowAmount`, this results in an underflow or prevents the function from continuing, effectively blocking new leveraged positions.

3. **Liquidity Constraints in the Lending Pool:**
- `lp.maxBorrowAmount` cannot be greater than `reserve.availableLiquidity()` because `lp.maxBorrowAmount` is first borrowed from the `lendingPool`.
- If `denomBalance` surpasses `availableLiquidity`, the function cannot proceed until new liquidity is added.
 
4. Impact of `reserveCapacity`:
- If the protocol enforces `reserveCapacity`, a donation exceeding this limit can cause a persistent DoS, as new deposits beyond the capacity are restricted.

### Impact

1. **Temporary Denial of Service (DoS):**
- Attackers can donate large amounts of tokens, making `denomBalance` larger than `lp.maxBorrowAmount`, blocking position openings until the lending pool's available liquidity surpasses the donated amount.

2. **Extended DoS if `reserveCapacity` is Enabled:**
- If `reserveCapacity` is defined, deposits are limited. A donation above `reserveCapacity` can cause a more severe and persistent DoS, as no new liquidity can be added beyond the limit.
