# Lack of Access Control in setMainTicks

### Summary

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L232

The function setMainTicks(int24) allows anyone to modify the main liquidity position ticks, affecting how funds are allocated in Uniswap V3 pools.



### Root Cause

Any user calls setMainTicks(int24).
The function updates mainPosition.tickLower and mainPosition.tickUpper without checking caller permissions.
Malicious users can redirect liquidity to unfavorable price ranges.

### Internal Pre-conditions

Malicious users can redirect liquidity to unfavorable price ranges.


### External Pre-conditions

Any user calls setMainTicks(int24).


### Attack Path

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import "forge-std/Test.sol";
import "../src/Strategy.sol";

contract AccessControlTest is Test {
    Strategy strategy;
    address attacker = address(0xBEEF);

    function setUp() public {
        strategy = new Strategy();
    }

    function testUnauthorizedAccess() public {
        vm.prank(attacker);
        strategy.setMainTicks(99999999);

        assertEq(strategy.mainPosition.tickLower, 99999999, "Unauthorized tick update!");
    }
}

```

### Impact

1- Unprivileged users can manipulate Uniswap pool liquidity.
2- Could result in trading inefficiencies or loss of funds.

### Mitigation

Add an onlyOwner or onlyAdmin modifier.
```diff
+ modifier onlyOwner() {
    require(msg.sender == owner, "Not authorized");
    _;
}

function setMainTicks(int24 newTick) external **onlyOwner** {
    mainPosition.tickLower = newTick;
}
```
