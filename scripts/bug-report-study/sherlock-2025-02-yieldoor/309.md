# When setting the SecondaryPosition, the tick may still be in range, which violates the design.

### Summary

The function _setSecondaryPositionsTicks is used to set the tick range of SecondaryPosition so that it only contains token0 or token1 and is initially out of range (OOR) of the current price. However, since modulo can be negative, this causes the `tick - modulo` to be greater than the `tick`, thus putting the current price within its range, violating the design:
>   /// @notice Sets the secondary position ticks.
    /// @dev This position should always be created consisting of just one of the tokens
    /// @dev Should initially be Out-Of-Range
    function _setSecondaryPositionsTicks(int24 tick) internal {

### Root Cause

The case where modulo is negative is not taken into account, so tickUpper will be greater than tick.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L363-L376

```solidity
        if (bal0in1 < bal1) {
            secondaryPosition.tickLower = mainPosition.tickLower;
            secondaryPosition.tickUpper = tick - modulo;
        } else {
```

### Internal Pre-conditions

1. tick is negative.

### External Pre-conditions

1. Function rebalance is called.

### Attack Path

None

### Impact

The current tick will be within the SecondaryPosition's price tick range, which violates the design.
