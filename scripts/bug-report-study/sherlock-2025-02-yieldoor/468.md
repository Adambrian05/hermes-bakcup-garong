# Incorrect Token Amount Used in Withdrawal Repayment Logic Leading to Token Loss and Potential Underflow


## Summary

In the `Leverager` contract's `withdrawal` function, there is a critical logic error where the wrong token amount (`amountOut0`) is used when calculating repayment amounts for `token1` borrows, leading to potential token loss and arithmetic underflow.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232

## Vulnerability Details

The vulnerability exists in the withdrawal repayment logic when the borrowed token is token1:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235

```solidity
else if (borrowed == up.token1) {
    // INCORRECT: Uses amountOut0 instead of amountOut1 when amountOut1 < owedAmount
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```

The issue arises because:

1. The condition checks if `amountOut1 < owedAmount`
2. If true, it uses `amountOut0` as the repayment amount instead of `amountOut1`
3. This amount is then subtracted from both `owedAmount` and `amountOut1`

## Impact

### 1. Arithmetic Underflow

- If `amountOut0` > `amountOut1`, subtracting `amountOut0` from `amountOut1` will cause an arithmetic underflow

- Example:
  ```solidity
  amountOut0 = 100
  amountOut1 = 50
  owedAmount = 75
  
  repayFromWithdraw = 50 < 75 ? 100 : 75 = 100
  amountOut1 = 50 - 100 // Underflows!
  ```

### 2. Incorrect Debt Accounting

- The wrong amount is subtracted from `owedAmount`, leading to incorrect debt records
- Users could end up with more or less debt than they should have

### 3. Token Loss

- Users could lose tokens if:
  - `amountOut0` is larger than `amountOut1`, causing excessive deduction
  - `amountOut0` is smaller than the actual required repayment amount, leading to insufficient debt repayment

## Root Cause
The root cause is a logical error in the code where `amountOut0` is incorrectly used in the ternary operation instead of `amountOut1` when calculating the repayment amount for token1 borrows.

## Recommended mitigation

Update the code to use `amountOut1` instead of `amountOut0` in the ternary operation.

```diff
  else if (borrowed == up.token1) {
-   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
      owedAmount -= repayFromWithdraw;
      amountOut1 -= repayFromWithdraw;
  }
```
