# Wrong `tickUpper` argument used in `collectFees()` may lead to lock funds permanently

### Summary

[Strategy::collectFees()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L159-L168) uses a wrong `tickUpper` argument. This may lead to a revert on collecting the fees. As  a result, since the  `collectFees()` is called from different contexts, it results in a protocol DoS and permanently locked funds. 

### Root Cause

In [collectFees()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L159-L168), if there is an ongoing vesting position, the `collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);` is called to collect the fees earned by the vesting position. 
The `mainPosition.tickUpper` is erroneously passed instead of the `vestPosition.tickUpper` value. 

As a result, due to market conditions, the `mainPosition.tickUpper` may become smaller than `vestPosition.tickUpper`. When this happens, the `IUniswapV3Pool(pool).burn()` reverts, DoS-ing the entire protocol and permanently locking the funds.
```solidity
    function collectFees() public {
        (uint256 preBal0, uint256 preBal1) = idleBalances();


        if (mainPosition.liquidity != 0) collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }
        if (ongoingVestingPosition) {
@>            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
        }
    ...
    }
```

### Internal Pre-conditions

1. Owner must add a vesting position to the strategy.

### External Pre-conditions

None

### Attack Path

1. Owner adds a vesting position to the strategy. The [vestingPosition ticks are set](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L433-L455) to the `mainPosition` ticks.
The `ongoingVestingPosition ` flag is set to `true`. 

```solidity
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;

@>        vp.tickLower = mainPosition.tickLower;
@>        vp.tickUpper = mainPosition.tickUpper;
...
@>        ongoingVestingPosition = true;

@>        vestPosition = vp;
    }
```
2. `Rebalancer` calls the `rebalance()`:
- `collectFees()` is called, the fees are collected for all 3 type of positions - main, secondary and vesting positions. 
At this step the `vestPosition.tickUpper` is equal to the `mainPosition.tickUpper` and the fees are collected successfully. 
- The `mainPosition` ticks are updated by [_setMainTicks()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L240-L241) and liquidity is rebalanced. 
3. Step 2 can be repeated until, due to market conditions, the `mainPosition.tickUpper` becomes smaller than the  `vestPosition.tickLower`. 
`vestPosition.tickLower` > `mainPosition.tickUpper`
4. `collectFees()` is called. Fees for the vesting position are collected: uniswapPool's `burn()` is called with a  `tickLower` > `tickUpper` arguments.

```solidity
    function collectPositionFees(int24 tickLower, int24 tickUpper) internal {
        IUniswapV3Pool(pool).burn(tickLower, tickUpper, 0);
        IUniswapV3Pool(pool).collect(address(this), tickLower, tickUpper, type(uint128).max, type(uint128).max);
    }
```
In `burn()` -> `_modifyPosition()` -> [checkTicks()](https://arbiscan.io/address/0xC6962004f452bE9203591991D15f6b388e09E8D0#code#F1#L127), the tx reverts with `TLU` message because tick lower is bigger than tick upper. 
```solidity
    function checkTicks(int24 tickLower, int24 tickUpper) private pure {
@>        require(tickLower < tickUpper, 'TLU');
        require(tickLower >= TickMath.MIN_TICK, 'TLM');
        require(tickUpper <= TickMath.MAX_TICK, 'TUM');
    }
```

The `collectFees()` is called from `rebalance()` function before setting the main ticks. As a consequence, once the `mainPosition.tickUpper` becomes smaller than the `vestPosition.tickLower`, the main ticks can't be updated anymore. 
Further calls to `collectFees()` reverts. This function is called from following contexts: 
- [rebalance()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L202)
- [compound()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L221)
- [addVestinPosition()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L427)
- [setProtocolFee()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L577)
- [Leverager::liquidatePosition()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L299) via `collectFees` modifier
- [Vault::deposit()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Vault.sol#L52)
- [Vault::withdraw()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Vault.sol#L84)


### Impact

All functions mentioned above will revert. As a result: 
- traders can't get liquidated
- vault depositors can't withdraw; funds are permanently locked.
