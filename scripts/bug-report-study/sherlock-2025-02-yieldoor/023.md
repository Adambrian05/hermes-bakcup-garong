# First depositor manipulates share-to-asset ratio to gain an unfair advantage over subsequent depositors

### Summary


The vault’s `_calcDeposit()` function lacks proper ratio initialization, allowing the first depositor to manipulate the initial share-to-asset ratio. By depositing disproportionate token amounts, an attacker can secure an excessive share allocation at the expense of subsequent depositors.

### Root Cause

In `vault.sol`, [_calcDeposit](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L56) calculates initial shares based on the maximum of `depositAmount0` and `depositAmount1` without enforcing a balanced deposit ratio. This oversight enables attackers to establish a skewed initial ratio, resulting in unfair share distributions.

### Internal Pre-conditions

1. Vault `totalSupply()` must be `0` (no prior deposits).
2. Vault balances for `token0` and `token1` must be `0`.

### External Pre-conditions

N/A

### Attack Path


### Stage 1: Attacker Skews Initial Ratio  
- **Deposit:** `2000 ether token0` and `1 ether token1`  
- **Share calculation:**  
  Shares = `max(2000 ether, 1 ether) - 1000 ether = 1000 ether`  
- **Post-deposit vault state:**  
  - `bal0 = 2000 ether`, `bal1 = 1 ether`  
  - `totalSupply = 1000 ether`  
- **Resulting share ratio:**  
  `1 share ≈ 2 ether token0 + 0.001 ether token1`

### Stage 2: Innocent User Deposits Balanced Amounts  
- **Deposit:** `1000 ether token0` and `1000 ether token1` (intending fair share allocation)  
- **Expected shares (without manipulation):**  
  In a fair 1:1 ratio vault, depositing `1000 ether` each would yield approximately `1000 ether` shares.  
- **Actual calculation with manipulation:**  
  - `cross0 = 1000 ether * 1 ether = 1000 ether²`  
  - `cross1 = 1000 ether * 2000 ether = 2,000,000 ether²`  
  - `cross = min(cross0, cross1) = 1000 ether²`  
  - Shares = `(cross * totalSupply) / (bal0 * bal1)`  
    = `(1000 ether² * 1000 ether) / (2000 ether * 1 ether)`  
    = `500 ether` shares  
- **Outcome:** The user receives only `500 ether` shares—half of what they would get if the initial ratio had not been manipulated.

### Stage 3: Another User Deposits Large Balanced Amount (≥ 1e18)  
- **Deposit:** `2000 ether token0` and `2000 ether token1`  
- **Expected shares (without manipulation):**  
  A `2000 ether` balanced deposit into a fair vault should yield about `2000 ether` shares.  
- **Actual calculation with manipulation:**  
  - `cross0 = 2000 ether * 1 ether = 2000 ether²`  
  - `cross1 = 2000 ether * 2000 ether = 4,000,000 ether²`  
  - `cross = min(cross0, cross1) = 2000 ether²`  
  - Shares = `(2000 ether² * 1000 ether) / (2000 ether * 1 ether)` = `1000 ether` shares  
- **Comparison:**  
  - **Expected shares:** `2000 ether`  
  - **Actual shares:** `1000 ether`  
  - **Loss:** User loses 50% of their fair share allocation.  
- **Post-deposit vault state:**  
  - `bal0 = 4000 ether`, `bal1 = 2001 ether`  
  - `totalSupply = 2500 ether shares`  
  - Attacker retains `1000 ether` shares (~40% ownership) despite the initial unbalanced deposit.

### Stage 4: Attacker Redeems and Profits  
- **Redemption:** Attacker withdraws `1000 ether` shares  
- **Withdrawal amounts:**  
  - `token0 = (4000 ether * 1000 ether) / 2500 ether ≈ 1600 ether`  
  - `token1 = (2001 ether * 1000 ether) / 2500 ether ≈ 800.4 ether`  
- **Net profit:**  
  - Deposited: `2000 ether token0 + 1 ether token1`  
  - Withdrawn: `1600 ether token0 + ~800.4 ether token1`  
  - **Effective profit:** Gains ~`799.4 ether token1` through ratio manipulation.

### Impact

The manipulated share-to-asset ratio leads to disproportionate returns for the attacker, unfairly diluting subsequent depositors. Innocent users effectively subsidize the attacker’s withdrawal, causing potential financial loss to the protocol.

### Mitigation


- **Enforce Balanced Initial Deposits:** Require initial deposits to have ratios within a 5% deviation (e.g., `0.95 ≤ depositAmount0/depositAmount1 ≤ 1.05`).
- **Set a Fixed Initial Ratio:** Initialize vault shares to a constant baseline ratio (e.g., 1:1) to prevent manipulation.
