# Liquidator will lose funds due to token leakage in liquidatePosition function

## Summary
In the Leverager contract, a discrepancy between calculated and actual repayment amounts in the `liquidatePosition()` function will cause token leakage where more tokens are repaid to the lending pool than necessary, leading to value loss for liquidators.

## Root cause
In [Leverager.sol:396](https://github.com/sherlock-audit/2025-02-yieldoor-oct0pwn/tree/main/yieldoor/src/Leverager.sol#L396) there is a mismatch between the amount that should be repaid to the lending pool and the amount that is actually repaid. The `repayAmount` is set equal to `owedAmount` initially, but then `owedAmount` is reduced through `repayFromWithdraw` calculations while `repayAmount` remains unchanged.

## Internal Pre-conditions
1. A position needs to be liquidatable (health factor below threshold)
2. The liquidated vault position must contain the borrowed token as one of its underlying tokens (i.e., the borrowed token must be either token0 or token1 in the vault)

## External Pre-conditions
* None specific

## Attack Path
1. Liquidator calls `liquidatePosition()` on an underwater position
2. Function calculates the `owedAmount` based on the borrowing index
3. Sets `repayAmount = owedAmount` (line 388)
4. If the position holds some of the denomination token, the function reduces `owedAmount` through the `repayFromWithdraw` calculation (lines 402-411)
5. Liquidator provides additional tokens to cover the reduced `owedAmount` (line 425)
6. Function calls `repay()` with `repayAmount` (line 427) which is still the original amount, not the reduced amount
7. Tokens are leaked as more tokens are repaid than necessary

## Impact
The liquidator suffers a loss equal to the difference between `repayAmount` and `owedAmount` after the `repayFromWithdraw` calculation. This amounts to "double-spending" the tokens that were already accounted for in collateral, effectively causing a portion of the liquidator's funds to be lost. In the worst case, this could be a significant portion of the debt amount, depending on the composition of the position.

## PoC
```solidity
function proveTokenLeak() public {
    // Set up a position where token0 is the denomination token
    // Assume position has 100 token0 and 200 token1
    // owedAmount is 150 token0
    
    // Create a simplified mock of the liquidatePosition function
    uint256 owedAmount = 150;
    uint256 repayAmount = owedAmount; // Set repayAmount = owedAmount
    
    uint256 amount0 = 100; // From position withdrawal
    
    // Calculate repayFromWithdraw
    if (denominationToken == token0) {
        uint256 repayFromWithdraw = amount0 < owedAmount ? amount0 : owedAmount;
        owedAmount -= repayFromWithdraw; // owedAmount reduced to 50
        amount0 -= repayFromWithdraw;    // amount0 reduced to 0
    }
    
    // At this point:
    // - owedAmount = 50 (remaining debt after using collateral)
    // - repayAmount = 150 (original debt amount, unchanged)
    
    // User transfers owedAmount = 50 tokens
    // But contract calls repay with repayAmount = 150
    // Result: 100 extra tokens are sent to the lending pool beyond what's needed
}
```

## Mitigation
Update the `repayAmount` variable after the `repayFromWithdraw` calculations to ensure it matches the adjusted `owedAmount`:

```diff
// In the liquidatePosition function
uint256 currBIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(up.denomination);
uint256 owedAmount = up.borrowedAmount * currBIndex / up.borrowedIndex;
uint256 repayAmount = owedAmount;

// After the repayFromWithdraw calculations
if (up.denomination == up.token0) {
    uint256 repayFromWithdraw = amount0 < owedAmount ? amount0 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amount0 -= repayFromWithdraw;
}

if (up.denomination == up.token1) {
    uint256 repayFromWithdraw = amount1 < owedAmount ? amount1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amount1 -= repayFromWithdraw;
}

+ // Update repayAmount to match current owedAmount
+ repayAmount = owedAmount;

// Rest of the function remains the same
```

Alternatively, simply use `owedAmount` directly in the repay call instead of maintaining a separate `repayAmount` variable:

```diff
- ILendingPool(lendingPool).repay(up.denomination, repayAmount);
+ ILendingPool(lendingPool).repay(up.denomination, owedAmount);
```
