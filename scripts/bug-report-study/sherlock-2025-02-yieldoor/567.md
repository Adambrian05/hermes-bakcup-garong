# The deposit fees are undercharged in `Vault.sol`.

### Summary

When making a deposit, the shares for the deposit fees are not minted, resulting in an undercharge of deposit fees.

### Root Cause

When users make deposits, the new shares to be minted are calculated by `_calcDeposit` (`Vault.sol:L56`). These shares include the share for deposit fees and the share for users. However, in the `deposit` function, only the user's shares are minted （`Vault.sol:L61` and `Vault.sol:L68`）, while the fee shares are not. This will cause the proportion of user shares in the total supply to increase. When withdrawing, users can withdraw more tokens, which means that the deposit fees are undercharged.

### Mitigation

Do not forget to mint the fee shares when depositing.
```solidity
    function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
        external
        returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
    {
        ...
        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

-       if (depositFee > 0) shares -= (shares * depositFee) / 10_000;
+       if (depositFee > 0) {
+           uint256 fees = shares * depositFee / 10_000;
+           _mint(BURN, fees);  // mint fee shares to BURN or fee recipient address
+           shares -= fees;
        }
        ...
    }
```
