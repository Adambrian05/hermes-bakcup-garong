# Zero-Collateral Infinite Leverage Exploit in `Leverager::openLeveragedPosition`: Bypassing Leverage Limits and Misusing Lending Pool Funds for User Causing Risk Free Trades

## Summary

The `openLeveragedPosition` function in the `Leverager` contract contains a critical vulnerability that allows users to open leveraged positions with **zero collateral** by exploiting the incorrect calculation of collateral values. Specifically, the function assumes that `a0` and `a1` (the amounts deposited into the vault) represent only the user's collateral, while in reality, they include funds from flash loans. This allows attackers to open **risk-free leveraged positions**, bypassing the protocol's leverage limits and potentially draining the lending pool. Additionally, the position is not liquidatable upon opening, enabling attackers to open **infinite leverage positions** without any risk of loss.

### Root Cause
The vulnerability arises in `openLeveragedPosition` from the incorrect assumption that `a0` and `a1` (the amounts deposited into the vault) represent only the user's collateral. In reality, these values include funds from flash loans, which are borrowed to cover the difference between the user's deposited amounts (`lp.amount0In`, `lp.amount1In`) and the desired vault deposits (`lp.vault0In`, `lp.vault1In`). This is done via the following lines:

```solidity
uint256 delta0 = lp.vault0In - lp.amount0In;
uint256 delta1 = lp.vault1In - lp.amount1In;
if (delta0 > 0) ILendingPool(lendingPool).pullFunds(up.token0, delta0); // Flashloan to cover the difference
if (delta1 > 0) ILendingPool(lendingPool).pullFunds(up.token1, delta1); // Flashloan to cover the difference
```

However, when calculating the collateral value (`up.initCollateralUsd`), the function incorrectly assumes that `a0` and `a1` represent only the user's collateral:

```solidity
 (uint256 shares, uint256 a0, uint256 a1) = IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);
up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price);
```

The `Leverager::_checkWithinlimits` assumes the collateral passed is the user's deposit, which bypasses this check. This allows attackers to open leveraged positions with **zero collateral** by setting `lp.amount0In` and `lp.amount1In` to zero and relying entirely on flash loans to fund the vault deposits. As a result, the protocol's leverage limits are bypassed, and attackers can open **infinite leverage positions** without any risk of loss.

### Impact of the Vulnerability
1. **Risk-Free Leverage**: Attackers can open leveraged positions with **zero collateral**, as the protocol incorrectly assumes that the deposited funds (`a0`, `a1`) are entirely provided by the user.
2. **Bypass Leverage Limits**: The `_checkWithinlimits` function is bypassed because the collateral value (`up.initCollateralUsd`) is calculated incorrectly, allowing attackers to open positions with **infinite leverage**.
3. **Drain the Lending Pool**: Attackers can repeatedly open leveraged positions using funds from the lending pool, potentially draining it and disrupting legitimate users.
4. **No Risk of Loss**: If the position goes in the attacker's favor, they profit. If it goes against them, they lose nothing, and the protocol bears the loss.

## Recommendations

### Fix the Collateral Calculation
Update the collateral calculation to account for the user's actual deposited amounts (`lp.amount0In`, `lp.amount1In`) rather than the total vault deposits (`a0`, `a1`). 

```solidity
up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, lp.amount0In, lp.amount1In, price);
```

### Enforce Minimum Collateral
Require users to deposit a minimum amount of collateral to open a leveraged position. For example:

```solidity
require(lp.amount0In > 0 || lp.amount1In > 0, "minimum collateral required");
```
