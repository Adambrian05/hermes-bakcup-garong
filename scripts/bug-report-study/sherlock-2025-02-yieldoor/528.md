# The `Leverager::_getTokenIn` does not update the `path` after skip token causing indefinite loop and OOG

## Summary
The `_getTokenIn` function in the `Leverager` contract runs into an Out of Gas (OOG) issue when handling multi-hop swaps. The issue arises because the loop does not update the `path` variable when skipping tokens, causing an infinite loop in some cases. `Path::skipToken`  function returns a new bytes memory object representing the remaining path, but the original implementation in `Leverager::_getTokenIn` does not reassign this value to path. Some tokens do not have single path (pair pool) to execute a swap which will require it to be processed in multiple pools to get the `tokenOut` from `tokenIn`. These tokens will be unusable for users since it will always revert and cause OOG.

## Vulnerability Details
### Affected Function: https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L566-L573
```solidity
function _getTokenIn(bytes memory path) internal pure returns (address) {
    //@audit-issue Loop keeps on running OOG if multiHop!
    while (path.hasMultiplePools()) {
@>        path.skipToken();
    }
    
    (, address tokenIn,) = path.decodeFirstPool();
    return tokenIn;
}
```
#### `Leverager::skipToken` in Path Library: https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/Path.sol#L58-L60

```solidity
  function skipToken(bytes memory path) internal pure returns (bytes memory) {
        return path.slice(NEXT_OFFSET, path.length - NEXT_OFFSET);
    }
```

#### Usage:
The `_getTokenIn` function is used in the `openLeveragedPosition` function to validate the input token for swaps. Specifically, it ensures that the `tokenIn` for a swap matches the expected denomination token. This is critical for maintaining the integrity of leveraged positions and preventing unauthorized swaps.
- https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L146
- https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L158


### Issue Description:
- The function iterates through the swap path using `path.hasMultiplePools()`, intending to traverse to the last token in the path. Example `bytes memory _path = abi.encodePacked(address(tokenC), uint24(3000), address(tokenB),  uint24(3000), address(tokenA))`.
- However, `path.skipToken();` does not modify `path` in place; instead, it returns a new `bytes` object with the updated slice.
- Since `path` is not reassigned within the loop, it remains unchanged, leading to an infinite loop, causing an OOG error when a multi-hop path is provided.

## Impact
- **Denial of Service (DoS):** If a user attempts to open a leveraged position with a multi-hop swap path, since `path` is not updated in the loop, the `hasMultiplePools()` condition may never evaluate to `false`, causing the loop to run indefinitely and the contract execution will revert due to excessive gas consumption (OOG).

## Recommendations
### Fixed Implementation:
```diff
function _getTokenIn(bytes memory path) internal pure returns (address) {
    while (path.hasMultiplePools()) {
-         path.skipToken();
+        path = path.skipToken();
    }
    (, address tokenIn,) = path.decodeFirstPool();
    return tokenIn;
}
```
### Fix Explanation:
- Assigns `path = path.skipToken();` within the loop, correctly updating `path` on each iteration.
- Ensures the loop terminates when the last path is reached, preventing an infinite loop and an OOG error.
