# `collectFees()` calls external, after verifying `_requirePriceWithinRange()`. which cause `_requirePriceWithinRange()` to be uneffective.

### Summary

okay so `_requirePriceWithinRange()` checks the current currentTick is has not deviated to much from the price,  however an extarnal call, is done while collectingFees, an malicious owner can then distort the price during using `onreceivedTokens`, he can call a flashloan, and swap tokens which can affect amount rebalanced or compounded causing dos.

### Root Cause

```javascript
function compound() public onlyRebalancer {
        _requirePriceWithinRange();
        collectFees();
```
if `feeReceipient` is a contract , the contract on receive tokens, can now manipulate the tokens after, causing the previous check to be ineffective.

### Internal Pre-conditions

// price is checked
_requirePriceWithinRange();
//@audit an external call can cause the above requirement to be bypassed
collectFees();  

### External Pre-conditions

na

### Attack Path

1. Owner `setFeeReceipent` to be contract on receive tokens, it borrows a large amount of the `statergy` tokens. and `swaps` them
2. When `rebalancer` calls `compound()` or `rebalance()`, the check is done before attack. 
3. Tokens are sent to the contract which triggers the `flashloan()`, `swap()` and now `slot0` is distorted
4. `Rebalance()` calculates wrongly, therefore token reinvested are 0 or less, causing `dos`

### Impact

Users, will not earn `fees` or will earn less `fees`

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L221

### Mitigation

perform the external call then check the deviation, in `compound()` `rebalance()`
```diff
 function compound() public onlyRebalancer {
+      collectFees();
        _requirePriceWithinRange();
-      collectFees();
```
