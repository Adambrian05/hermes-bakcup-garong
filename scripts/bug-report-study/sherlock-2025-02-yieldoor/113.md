# Paused state prevents withdrawals leads to fund lockup during emergencies

## Summary
The `LendingPool#redeem` function includes the `notPaused` modifier, preventing users from withdrawing their funds when the contract is paused. This creates a critical risk of fund lockup during emergency situations.

## Relevant Context
The `LendingPool` contract includes a pause mechanism controlled by the owner that can halt all operations. The `repay` function was specifically modified to work even when paused, showing awareness of the need for certain critical functions to remain operational during emergencies.

## Root Cause
The `redeem` function includes the `notPaused` modifier, which prevents execution when the contract is paused. While pausing functionality is important for emergency situations, preventing withdrawals contradicts basic DeFi safety principles where users should always be able to exit their positions, especially during emergencies.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/LendingPool.sol#L85

The issue is particularly concerning because:
1. The pause function can be activated by the owner at any time via `emergencyPauseAll`
2. There is no timelock or governance process for pausing
3. Users have no recourse to withdraw their funds while paused

## Attack Path

1. Contract owner calls `emergencyPauseAll()` due to a potential security issue or maliciously
2. Users attempt to call `redeem()` to withdraw their funds
3. All withdrawal attempts revert due to the `notPaused` modifier
4. Users' funds remain locked in the contract until the owner calls `unPauseAll()`

## Impact Explanation
Medium. The users can not withdraw when the `LendingPool` contract is paused.

## Proof of Concept
Scenario:
1. Alice deposits 100 USDC using `deposit()`
2. Owner notices a potential exploit and calls `emergencyPauseAll()`
3. Alice attempts to withdraw using `redeem()`
4. Transaction reverts due to "contract paused" error
5. Alice's funds remain locked until owner unpauses

## Recommendation
Remove the `notPaused` modifier from the `redeem` function to ensure users can always withdraw their funds:

```solidity
    function redeem(address underlyingAsset, uint256 yAssetAmount, address to)
        public
        // notPaused  // Remove this modifier
        nonReentrant
        returns (uint256)
    {
        // ... existing code ...
    }
```

Consider implementing a more granular pause system that specifically excludes withdrawals from being paused, similar to how `repay` was modified to work during paused states.
