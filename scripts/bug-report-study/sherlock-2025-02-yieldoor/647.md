# Vesting position can be rendered useless due to missing position adjustment

### Summary

Vesting position can be rendered useless due to missing position adjustment

### Root Cause

In [Strategy::addVestingPosition()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L426) function admin can create a position externally.

This position is withdrawn in time and shared with the users. In first creation, the upper and lower ticks are set same as main position. 

```solidity
        VestingPosition memory vp;

        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;

        (uint160 sqrtPrice,,,,,,) = IUniswapV3Pool(pool).slot0();
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPrice,
            TickMath.getSqrtRatioAtTick(vp.tickLower),
            TickMath.getSqrtRatioAtTick(vp.tickUpper),
            amount0,
            amount1
        );
```
There is no problem until that point. Main position and second position are adjusted for better leveraged farming with rebalance function. Rebalance function simply adjust the tick points because if v3 pool doesn't use our provided liquidity, it will return nothing as a farming. 

The problem is rebalance function doesn't handle vesting position. It will be useless position if the tick points of position is completely unrelated with current price. 

```solidity
    function rebalance() public onlyRebalancer {
        require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");

        _requirePriceWithinRange(); // we verify that the pool's price is currently not manipulated
        collectFees();

        _removeLiquidity();
        (uint256 amount0, uint256 amount1) = idleBalances();

        (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();

        _setMainTicks(tick);
        (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

        _setSecondaryPositionsTicks(tick);
        _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
        lastRebalance = block.timestamp;
    }
```

### Internal Pre-conditions

None

### External Pre-conditions

1. Price goes out from vesting position range

### Attack Path

WETH/USDC
Price: 2500
Main position upper tick: 2600
Main position lower tick: 2400

1. We created a vested position, upper tick holds 2600, lower tick holds 2400 for 1 week
2. After 2 hours, price went outside of the range, let say 2700
3. It never came back to 2400-2600 range for whole week

Our rebalance function did not handle the vesting position and we never earned any farming value from position.

### Impact

This issue makes vesting position useless. Vesting position should be rebalanced as the others. Missing farming value from vesting position will be loss of yield for strategy users.

### Mitigation

Rebalance vesting position too as the other positions
