# `MINIMUM_YTOKEN_AMOUNT` check even when `totalSuppy !=0` will set the bar high for users to deposit assets in the `LendingPool`

### Summary

It is reasonable to check the `yTokenAmount > MINIMUM_YTOKEN_AMOUNT` when the user is the first one to deposit to avoid an inflation attack. However, this check will also apply when `totalSuppy !=0`. This will set the bar high for users who are not the first one to deposit. 

Since as the time goes by, the assets per share will go high as the interest accumulated. Users will have to deposit a bigger amount of assets to satisfy the check of `MINIMUM_YTOKEN_AMOUNT`.

[LendingPool](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L120-L126)

```solidity
        require(yTokenAmount > MINIMUM_YTOKEN_AMOUNT, "deposit is dust amount");
        if (IyToken(reserve.yTokenAddress).totalSupply() == 0) {
            // Burn the first 1000 yToken, to defend against lp inflation attacks
            IyToken(reserve.yTokenAddress).mint(DEAD_ADDRESS, MINIMUM_YTOKEN_AMOUNT);

            yTokenAmount -= MINIMUM_YTOKEN_AMOUNT;
        }
```



### Root Cause

`MINIMUM_YTOKEN_AMOUNT` check will also apply when `totalSupply !=0`.

Only apply the `MINIMUM_YTOKEN_AMOUNT` check when `totalSupply ==0`.


```solidity
        if (IyToken(reserve.yTokenAddress).totalSupply() == 0) {
```
