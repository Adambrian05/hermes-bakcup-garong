# Protocol will derive more protocol fees than normal for charging the protocol fee on the all vested position

### Summary

When protocols fees are charged for all collected positions (main, secondary and vested), it will derive more protocol fees than normal. Protocols will benefit from the vested position establish to incentivize the vault depositors.


### Root Cause

[collectFees()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L159) is the root cause.

This vulnerability will arise when there is an ongoing vested position. When the first ongoingVestingPosition condition in the collectFees function is met, protocol will collect fees from the all positions (main, secondary and vested). 

The second condition was to make sure that "doing that now, otherwise we'd charge protocol fee for the vested position.": The rationale was to ensure that the protocol fee is not applied on the vested position (vested liquidity).

However, current implementation is designed to benefit the protocol over the vault depositors. It takes protocol fee from the position vested to incentivize the vault depositors.

Here is an explanation of the control flow and functions involved in the `collectFees` function:

Inspect the `collectPositionFees` and `_removeFromPosition` functions:

collectPositionFees burns no liquidity but takes all fees derived from the tick range.

This implementation reneges on the principal reason behind vesting position.

> In order to incentivize users to LP in a certain Vault, owners can add a vested position which is distributed among Vault depositors over time. Only one Vested position can exist at a time.

- Protocol documentation

### Internal Pre-conditions

1. Admin adds a new vesting position to a strategy
2. Vault depositors are lured to the LP
3. Protocol earns 10% on (main, secondary and vesting) positions when functions with collectedFees are called 

### External Pre-conditions

1. Protocol always get 10% on the collected fees from the vesting/vested period.
2. Fees are collected on deposit and withdrawl to the Vaults, and also liquidatePosition in 

### Attack Path

Assume the following fees earned by positions:
- Main position: 3000 tokens
- Secondary position: 2000 tokens
- Vesting position: 1000 tokens
- Protocol fee rate: 10%
- Vesting period: 100 days
- Current time: 25 days (25% vested)

Current Implementation:
1. Protocol collects fees from all positions:
   - Total fees collected = 3000 + 2000 + 1000 = 6000 tokens
   - Protocol fee (10%) = 600 tokens
   - Remaining in idle balance = 5400 tokens

2. Then withdraws vested portion:
   - 25% of vesting position is burned
   - There will be no position fees to collect again, collection happened in step 1.

3. Final result:
   - Total in idle balance = 5400 tokens
   - Total protocol fees = 600 tokens

Expected Implementation:
1. Protocol should collect fees only from main and secondary positions:
   - Fees from main + secondary = 3000 + 2000 = 5000 tokens
   - Protocol fee (10%) = 500 tokens
   - Remaining in idle balance = 4500 tokens

2. Then handle vesting position separately:
   - 25% of vesting position is burned
   - Collect vesting position fees = 1000 tokens
   - No protocol fee should be charged on these
   - Add full amount to idle balance = 1000 tokens

3. Final result:
   - Total in idle balance = 4500 + 1000 = 5500 tokens
   - Total protocol fees = 500 tokens
   
This shows that the current implementation overcharges protocol fees by 100 tokens (600 vs 500) by incorrectly including the vesting position in the protocol fee calculation.

### Impact

- Protocol will derive more protocol fees than normal for position added to incentivize vault depositors.

- Exempt derived vesting/vested position collected fees from protocol fee which is strictly for vault depositors risks.
