# The function liquidatePosition incorrectly calculates borrowedValue, causing borrowedValue to be abnormally large.

### Summary

The code for calculating borrowedValue is incorrect and should be `owedAmount * bPrice / 10** ERC20(up.denomination).decimals()`, which makes the value of borrowedValue abnormally large. 
Since the value of borrowedValue is abnormally large, totalValueUSD will no longer be greater than borrowedValue, so the protocol cannot charge fees, resulting in protocol loss.

### Root Cause

Code mistake:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L318

```solidity
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(up.denomination);
        uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals(); //@@@audit: 10**decimals

        if (totalValueUSD > borrowedValue) {
```

### Internal Pre-conditions

None

### External Pre-conditions

1. User calls liquidatePosition.

### Attack Path

1. User calls liquidatePosition.

### Impact

The protocol loses all the fees that may be incurred when liquidating positions.

### PoC

_No response_

### Mitigation

```solidity
uint256 borrowedValue = owedAmount * bPrice / 10**ERC20(up.denomination).decimals();
```
