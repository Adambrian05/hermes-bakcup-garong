# Inability to perform partial liquidations allows WHALE positions to accrue bad debt in the system

### Summary

The [liquidatePosition](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L299)  function allows liquidators to burn vault token for position id 

The issue is that the current functionality only allows burning of the whole vault token amount minted by the position id. This means that partial liquidations cannot be performed and prevents liquidators from liquidating vault tokens minted by whales that hold huge positions in the system. Since the liquidations cannot be performed unless the liquidator can match up to the collateral deposited and vault token minted by the whale, the system will be undercollaterized causing bad debt to accrue.





### Impact

High as the liquidators could not liquidate such positions.

### PoC

In the [liquidatePosition](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L299) function below, we can see on Line 299 that when the `withdraw()` function is called on the vault token, it burns the whole minted vault tokens instead of allowing the liquidator to supply a specific amount they can burn to improve the collateral ratio of the id and the overall health of the system.

But since this is not allowed, liquidators trying to liquidate whales, who have minted a huge amount of vault tokens, would fail due to the position being extremely big and the inability to partially liquidate

`Leverager.sol(299)`

```solidity
    function liquidatePosition(LiquidateParams calldata liqParams) external collectFees(liqParams.id) nonReentrant {
        Position memory up = positions[liqParams.id];

        require(isLiquidateable(liqParams.id), "isnt liquidateable");

        uint256 currBIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(up.denomination);
        uint256 owedAmount = up.borrowedAmount * currBIndex / up.borrowedIndex;
        uint256 repayAmount = owedAmount;

        uint256 price = IVault(up.vault).twapPrice();
        // we do not check here for pool activity, in order to be able to liquidate during very volatile markets
        // otherwise, we'd risk accruing bad debt.

        (uint256 amount0, uint256 amount1) =
            IVault(up.vault).withdraw(up.shares, liqParams.minAmount0, liqParams.minAmount1);


```

`Vault.sol(line 80)`

Here it burns the entire vault tokens - 

```solidity
  function withdraw(uint256 shares, uint256 minAmount0, uint256 minAmount1)
        public
        returns (uint256 withdrawAmount0, uint256 withdrawAmount1)
    {
        IStrategy(strategy).collectFees();

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        uint256 totalSupply = totalSupply();
        _burn(msg.sender, shares);

        withdrawAmount0 = totalBalance0 * shares / totalSupply;
        withdrawAmount1 = totalBalance1 * shares / totalSupply;

        (uint256 idle0, uint256 idle1) = IStrategy(strategy).idleBalances();

        if (idle0 < withdrawAmount0 || idle1 < withdrawAmount1) {
            // When withdrawing partial, there might be a few wei difference.
            (withdrawAmount0, withdrawAmount1) = IStrategy(strategy).withdrawPartial(shares, totalSupply);
        }

        require(withdrawAmount0 >= minAmount0 && withdrawAmount1 >= minAmount1, "slippage protection");

        IERC20(token0).safeTransferFrom(strategy, msg.sender, withdrawAmount0);
        IERC20(token1).safeTransferFrom(strategy, msg.sender, withdrawAmount1);

        return (withdrawAmount0, withdrawAmount1);
    }
```

### Mitigation

Implement a mechanism to allow liquidators to partially liquidate positions
