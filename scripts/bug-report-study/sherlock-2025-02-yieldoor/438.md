# Missing State Updates of the reserve in the `setBorrowingRateConfig` function.

### Summary
When the admin changes the interest rate configuration, the protocol does not immediately update the state or interest rates of the reserve. As a result, the old interest rate configuration is used for new interest accrual, while the new fee rate is applied to previous interest periods.

### Root Cause
The [`setBorrowingRateConfig`](https://github.com/sherlock-audit/2025-02-yieldoor/tree/main/yieldoor/src/LendingPool.sol#L348) modifies the the rate configs but doesn't update the interest rate to reflect the new config:

```solidity
    function setBorrowingRateConfig(
        address asset,
        uint16 utilizationA,
        uint16 borrowingRateA,
        uint16 utilizationB,
        uint16 borrowingRateB,
        uint16 maxBorrowingRate
    ) public onlyOwner notPaused {
        DataTypes.ReserveData storage reserve = reserves[asset];
        setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    }
```
This causes incorrect interest accrual, because the interest rate is not updated to reflect the new config.

### Internal pre-conditions
None

### External pre-conditions

1. None

### Attack Path
- In the 0 timestamp: lastUpdateTime = 0, borrowRate = 5%
- In the 10 timestamp: Admin changes rate config(10% rate)
- In the 20 timestamp: User deposits or withdraws assets
Interest between timestamp 10 and 20 uses old 5% rate (based on old config) instead of 10% rate.

### Impact
Incorrect interest accural will cause the loss of funds to the protocol or users.

### PoC
None

### Mitigation
Add the `reserve.updateState()` and `reserve.updateInterestRates()` code in the `setBorrowingRateConfig` function.
