# Collateral Repayment Calculation Bug in Leveraged Position Withdraw Function

### Summary

A vulnerability exists in the `withdraw` function of the Leverager contract. When a user withdraws a portion of their leveraged position where the borrowed token is token1, the code is intended to use the withdrawn amount of token1 (`amountOut1`) to partially repay the debt. However, due to a coding error, the function incorrectly uses `amountOut0` in the repayment calculation instead of `amountOut1`. [See here](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231C8-L235C10)

### Root Cause

The vulnerability is caused by an incorrect variable reference in the repayment logic within the `withdraw` function. Specifically, when the borrowed token is token1, the code mistakenly uses `amountOut0` in a ternary operation instead of `amountOut1`. This results in an incorrect calculation of the repayment amount from the collateral.

### Impact

This miscalculation could allow an attacker to withdraw more collateral than intended, effectively enabling a cheaper exit from their leveraged position. In a worst-case scenario, the vulnerability could be exploited to deplete collateral from the protocol, adversely affecting liquidity providers.

### Mitigation

```diff
else if (borrowed == up.token1) {
-   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+   uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
