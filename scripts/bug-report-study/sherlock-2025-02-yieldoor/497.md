# Missing Enforcement of leverage Limits in borrow() function

### Summary

The `borrow()` function does nit enforce the leverage constraints set by `setLeverageparams()`. This allows users to:
1. Exceed the maximum individual borrow limit (maxIndividualBorrow).
2. Surpass the maximum leverage ratio (maxLeverage).
This would lead to over-leveraging, protocol insolvency, over borrowing of asset that are meant to be reserved and as well potential liquidation failures.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L372

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L373

### Root Cause

In the `borrow()` function there is a missing check to check against maxLeverage and maxBorrow for an individual

```solidity
 reserve.leverageParams.maxIndividualBorrow = _maxBorrow;
        reserve.leverageParams.maxLeverage = _maxLeverage;
    }
```

### Internal Pre-conditions

The borrower needs to be a levarager
Borrowing more than their asset

### External Pre-conditions

simple borrowing 100,000 gas in wei 10,000,000,000 
which also cost 0.00001ETH

### Attack Path

- Initial Deposit:
Leverager deposits minimal collateral (e.g $10,000)

- Over borrowing
Since `borrow()` lacks enforcement, the attacker borrows an unlimited amount (e.g., $1,000,000 instead of $50,000 allowed)

- Liquidation becomes hard

### Impact

1. **Protocol Insolvency:** since there is  no enforcement of `maxLeverage`, a user can borrow relative to their collateral.
- If the market moves against them, liquidators may not cover the debt
- The protocol is forced to absorb bad debt.
2. **Liquidation Failure & Bad Debt Accumulation:** If users can exceed max leverage, they might become unliquidatable when their debt surpasses their collateral value.
