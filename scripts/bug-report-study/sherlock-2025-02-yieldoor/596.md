# If tickSpacing is "1" then the main and secondary positions will not be accurately calculated

### Summary

 Because of the modulo being "0" on pools with tickSpacing "1" main position will always assume the position is "lowerSided" although its not.

### Root Cause

If the pools `tickSpacing` is "1" then the modulo will ALWAYS be "0". Hence, the position will always assume its `lowerSided`
https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L234-L236

### Internal Pre-conditions

None needed

### External Pre-conditions

1. Pools that has `tickSpacing` as "1" will be enough

### Attack Path

None needed, it will naturally happen all the time when `tickSpacing` for a pool is "1". 

### Impact

Pools with `tickSpacing` of "1" are mostly stable pools where tick precision is crucial since even small differences in ticks matter due to the similarity of the assets. Due to a miscalculation in `lowerSided` ticks, they will always be ahead of the actual ticks that should be set. This breaks the intended functionality, hence the medium severity.

### PoC

Assume DAI-FRAX pool where the `tickSpacing` is "1" and positionWidth is "4" and current tick is "10".

Let's calculate the main ticks:
```solidity
function _setMainTicks(int24 tick) internal {
        int24 halfWidth = int24(positionWidth / 2);
        int24 modulo = tick % tickSpacing; // 
        if (modulo < 0) modulo += tickSpacing; // if tick is negative, modulo is also negative
        bool isLowerSided = modulo < (tickSpacing / 2); // 1 < 0

        int24 tickBorder = tick - modulo;
        if (!isLowerSided) tickBorder += tickSpacing;
        mainPosition.tickLower = tickBorder - halfWidth;
        mainPosition.tickUpper = tickBorder + halfWidth;

        emit NewMainTicks(tickBorder - halfWidth, tickBorder + halfWidth);
    }
```

halfWidth = 2
modulo = 0
isLowerSided = 0 < 0 = false (WRONG)

tickBorder = 10
since lowerSided is false tickBorder += 1 = 11
tickLower = 11 - 2 = 9
tickUpper = 10 + 2 = 12

so the tickLower is unnecessarly close to the current tick. Though, since tickSpacing is "1" position could be easily created on ticks 8-12. 

This can be more problematic if the strategy is extremely concentrated where positionWidth is 2.


### Mitigation

If `tickSpacing` is "1" do not calculate the `tickBorder` with `isLowerSided`.
