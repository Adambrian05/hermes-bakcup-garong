# Token Mismatch in Withdraw Function Leads to Protocol Insolvency

### Summary

 https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232

A logical error in the withdraw function's ternary operation will cause significant fund loss for the protocol as users can withdraw their collateral without properly repaying borrowed funds.

### Root Cause

 https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232
 In the `leverager::withdraw`  the borrowed token is token1, the code incorrectly uses amountOut0 instead of amountOut1 in the ternary operation to determine the repayment amount.

```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```

### Internal Pre-conditions

No response

### External Pre-conditions

No response

### Attack Path

 1.Attacker creates a position by depositing collateral (predominantly in token0) and borrowing token1
2.Attacker calls withdraw with parameters ensuring amountOut1 < owedAmount
3.The function erroneously uses amountOut0 (collateral token) in the repayment calculation
4.This results in incorrect accounting of repaid amounts

### Impact

 The protocol suffers significant loss as users can withdraw their collateral while repaying incorrect amounts of debt

### PoC

 When a user withdraws with the following values:

amountOut0 = 3e18 (ETH)
amountOut1 = 3000e6 (USDC)
owedAmount = 3333.33e6 (USDC)

The condition 3000e6 < 3333.33e6 evaluates to true, causing the code to select amountOut0 (3e18 ETH) instead of amountOut1 (3000e6 USDC) for debt repayment calculations. This causes a mismatch in token types and values.

### Mitigation

Replace:

 ```diff
- uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+ uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
```
