# Leverager::withdraw repayFromWithdraw error

### Summary

`Leverager::withdraw` performs some shortcuts when **executing a repayment**, such as verifying that the token received in `Vault::withdraw` matches `up.denomination`. However, there is a typo in one of these shortcuts.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235

```solidity
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```

The assignment to `repayFromWithdraw` is incorrect because it assigns amountOut0 instead of amountOut1.

### Internal Pre-conditions

* `up.token1 == up.denomination`

### External Pre-conditions

None

### Attack Path

None

### Impact

It seems that the user could **perform a withdraw while paying less than required**, since `LendingPool::repay` can only be called by `Leverager`, and it **relies on the assumption that no misinterpretation of amounts used in inputs will occur**.

### PoC

_No response_

### Mitigation

```diff
        } else if (borrowed == up.token1) {
-           uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+           uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```
