# Failure to update `path` in multi-pool swaps results in an out-of-gas (OOG) error during leveraged position openings

### Summary

he function `_getTokenIn()` does not correctly update path after calling `skipToken()`. As a result, when users attempt to open a leveraged position that involves a multi-pool swap, the function enters an infinite loop, leading to an out-of-gas (OOG) error

### Root Cause


The remaining token and fee elements returned by the `skipToken` function  in [Leverager.sol:145](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L146) (and [L158](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L158)) are not assigned to the original `path`. As a result the same `path` is repeatedly  checked if it has multiple pools.
When `path` has multiple pools, `_getTokenIn` enters an infinite loop causing the transaction to revert with an out-of-gas error. 
```solidity
    function _getTokenIn(bytes memory path) internal pure returns (address) {
        while (path.hasMultiplePools()) {
@>            path.skipToken();
        }
        (, address tokenIn,) = path.decodeFirstPool();
        return tokenIn;
    }
```

### Internal Pre-conditions

1. The position's tokens must be enabled for trading 
2. The borrowed token must have a lending pool reserve

### External Pre-conditions

1. Trader needs to use a multi-pool swap path when opening a leveraged position. 

### Attack Path

The issue occurs every time a leveraged position requires a multi-pool swap
1. trader wants to  borrow wBTC to leverage his ARB/USDC position.
- A wBTC/USDC pool exists allowing a direct swap: `wBTC-> USDC`
- No wBTC/ARB pool exists, requiring an intermediate swap : `wBTC -> ETH -> ARB`
2. the trader calls `openLeveragedPosition` with `swapParams1.path` and `swapParams2.path` using the paths above.
3. `_getTokenIn()` is called with the multi pool path `wBTC -> ETH -> ARB`.
- `skipToken()` removes the first token + fee but does not update path
- `hasMultiplePools()` continues evaluating the original path, leading to infinite iterations until the transaction runs out of gas.

```solidity
    function _getTokenIn(bytes memory path) internal pure returns (address) {
        while (path.hasMultiplePools()) {
@>            path.skipToken();
        }

        (, address tokenIn,) = path.decodeFirstPool();
        return tokenIn;
    }
```

```solidity
// Path.sol
    /// @notice Skips a token + fee element from the buffer and returns the remainder
    /// @param path The swap path
    /// @return The remaining token + fee elements in the path
    function skipToken(bytes memory path) internal pure returns (bytes memory) {
        return path.slice(NEXT_OFFSET, path.length - NEXT_OFFSET);
    }
```

### Impact

Users will be unable to open leveraged positions that require multi-pool swaps, significantly limiting borrowing options.

The test reverts with `EvmError: OutOfGas`.

### Mitigation

To prevent infinite loops, update path with the shortened value returned by `skipToken()`. 
```diff
    function _getTokenIn(bytes memory path) internal pure returns (address) {
        while (path.hasMultiplePools()) {
-            path.skipToken();
+           path = path.skipToken();
        }


        (, address tokenIn,) = path.decodeFirstPool();
        return tokenIn;
    }
```
