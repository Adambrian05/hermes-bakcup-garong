# The vesting position will not undergo rebalancing, which may impact the accumulation of fees for the vesting position.

### Summary

In the `rebalance()` function, the vesting position is not rebalanced. Therefore, if the price exits the tick range of the vesting position, it will affect the fee accumulation of the vesting position. In the worst case, the fee accumulation may completely stop, causing the `Strategy` contract to lose these fees.

### Root Cause

When adding a vesting position, the range of the vesting position is set to be the same as that of the main position (`Strategy.sol:433-434`).
```solidity
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;

433:    vp.tickLower = mainPosition.tickLower;
434:    vp.tickUpper = mainPosition.tickUpper;
        ...
    }
```
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L433-L434

The `rebalancer` can call the `rebalance()` function to rebalance the positions within the strategy, including the main position and the secondary position, but not the vesting position.
```solidity
    function rebalance() public onlyRebalancer {
        require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");

        _requirePriceWithinRange(); // we verify that the pool's price is currently not manipulated
        collectFees();

204:    _removeLiquidity();
        (uint256 amount0, uint256 amount1) = idleBalances();

        (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();

209:    _setMainTicks(tick);
210:    (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

212:    _setSecondaryPositionsTicks(tick);
213:    _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
        lastRebalance = block.timestamp;
    }
```
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198-L215

As a result, the tick range of the vesting position remains unchanged during the entire vesting period. If the price exits the range of the vesting position, it will affect the fee accumulation of the vesting position. In the worst case, the fee accumulation may completely stop, causing the `Strategy` contract to lose these fees.

### Internal Pre-conditions

1. `Owner` invoke `Vault.sol:addVestingPosition()` to add a vesting position. The tick range of the vesting position will be the same as that of the main position.

### External Pre-conditions

1. The price exits the tick range of the vesting position during the vesting period.


### Attack Path

_No response_


### Impact

When the price exits the tick range of the vesting position during the vesting period, the `Strategy` contract will lose some fees of the vesting position.


### PoC

_No response_

### Mitigation

Rebalance the vesting position in the `rebalance()` function as well.
