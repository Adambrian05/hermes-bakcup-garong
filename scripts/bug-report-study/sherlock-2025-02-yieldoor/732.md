# Direct Token Injection Leading to LP Token Dilution

### Summary

Assume that the Vault is built on a Uniswap V2-like mechanism, which requires users to deposit two tokens in proportion to the current pool balances. In the first deposit, the contract “burns” a portion of the shares (for example, 1,000 shares) to ensure stable LP token share calculations for later deposits. An attacker can bypass the deposit function and directly transfer one of the tokens into the strategy contract, thereby artificially inflating that token’s balance in the pool without minting corresponding LP tokens. This can lead to lp token dilution

### Attack Path

Initial State (Before Legitimate Deposits):

1.User A deposits 10,000 token0 and 10,000 token1.
The first deposit calculates shares as:
```solidity
shares = (max(amount0, amount1)) - 1000;
```
Assume this results in 9,000 LP tokens (with an additional 1,000 permanently burned to prevent dilution).At this point, the strategy contract holds:totalBalance0 = 10,000,totalBalance1 = 10,000.The Vault’s total supply is 9,000 LP tokens.

2.Attacker B bypasses the deposit function and directly transfers 100,000 token0 to the strategy contract.This transfer does not mint any LP tokens, so the attacker receives no shares.However, the strategy’s balances become:totalBalance0 = 10,000 + 100,000 = 110,000,totalBalance1 remains at 10,000.The token ratio in the pool becomes extremely imbalanced.

3.User C then attempts to deposit 1,000 token0 and 1,000 token1, with slippage controls (amount0Min and amount1Min) to ensure the deposit meets the expected amounts.The contract calls _calcDeposit with :bal0 = 110,000,bal1 = 10,000,depositAmount0 = 1,000,depositAmount1 = 1,000.

4.The calculation proceeds as follows:

```solidity
cross0 = 1,000 * 10,000 = 10,000,000
cross1 = 1,000 * 110,000 = 110,000,000
cross = min(10,000,000, 110,000,000) = 10,000,000
```
```solidity
amount0 = (cross - 1) / 10,000 + 1 ≈ 1,000
amount1 = (cross - 1) / 110,000 + 1 ≈ 91
shares = cross * totalSupply / (bal0 * bal1) ≈ 10,000,000 * 9000 / (110,000 * 10,000) ≈ 81.8 shares
```
5. Result: User C ends up depositing roughly:1,000 token0 , 91 token1

### Impact

1.This can cause the computed deposit amounts (amount0, amount1) and LP token shares (shares) to deviate significantly from the actual value the user intended to deposit.
