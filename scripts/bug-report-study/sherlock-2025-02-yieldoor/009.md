# Users will experience logic errors due to rebase tokens

#### Summary
The lack of handling for rebase tokens will cause logic errors for users as these tokens will change the actual balance without updating the stored balance.

#### Root Cause
In `LendingPool.sol:deposit` and `LendingPool.sol:withdraw` the lack of handling for rebase tokens causes logic errors.

#### Internal Pre-conditions
Users need to deposit or withdraw rebase tokens.

#### External Pre-conditions
Rebase tokens need to be used within the protocol.

#### Attack Path
1. User deposits rebase tokens into the protocol.
2. The protocol records the initial deposit amount.
3. The rebase token undergoes a rebase event, changing the actual balance.
4. User withdraws the tokens, and the protocol calculates the withdrawal amount based on the initial deposit without accounting for the rebase.
5. User suffers a loss or gain due to the discrepancy between the recorded and actual token amounts.

##### Impact
The users suffer an approximate loss or gain due to the discrepancy between the recorded and actual token amounts. The protocol does not gain or lose anything directly.

##### PoC
```solidity
// Assuming a rebase token that increases supply by 10%
function testRebaseToken() public {
    address user = address(0x1234567890123456789012345678901234567890);
    
    RebaseToken token = new RebaseToken();
    LendingPool lendingPool = new LendingPool();
    
    // User deposits 100 tokens
    token.mint(user, 100e18);
    vm.prank(user);
    token.approve(address(lendingPool), 100e18);
    vm.prank(user);
    lendingPool.deposit(address(token), 100e18, user);
    
    // Protocol records 100 tokens
    assertEq(lendingPool.totalLiquidityOfReserve(address(token)), 100e18);
    
    // Rebase event increases supply by 10%
    token.rebase(10);
    
    // User withdraws the tokens
    vm.prank(user);
    lendingPool.redeem(address(token), 100e18, user);
    
    // User receives 100 tokens instead of 110 due to the rebase
    assertEq(token.balanceOf(user), 100e18); // User suffers a loss
}
```
