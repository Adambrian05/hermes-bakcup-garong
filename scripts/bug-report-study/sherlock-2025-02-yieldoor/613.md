# Incorrect Share Calculation in First depositor in Deposit Function

### Summary

In the deposit function, the protocol developers implemented a mechanism to prevent the first depositor from owning 100% of the pool after their initial deposit. However, this mitigation is incorrectly designed. Upon the first deposit, the function first deducts 1000 shares from the user, and then mints an additional 1000 shares to the BURN address. This leads to an unintended effect, as it causes the first depositor to lose 1000 shares while also introducing extra shares into circulation without reducing the effective share ownership.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119-#L151

### Root Cause



The line in deposit():
```solidity
if (totalSupply() == 0) _mint(BURN, 1000);
```

1000 shares are already minted to BURN address
ensures that the first depositor doesn’t have complete control because the first 1000 shares are already allocated elsewhere.


 First Depositor

If the _calcDeposit() function also reduces their shares by 1000, the first depositor is penalized .
Example:
Suppose the first depositor should receive 5000 shares based on their deposit.
The -1000 logic in _calcDeposit() reduces it to 4000.
Meanwhile, deposit() also mints 1000 shares to BURN  address.
Now the effective supply becomes 5000 (4000 to user + 1000 burned) instead of 6000 (5000 to user + 1000 burned).

Hence the -1000 shares deduction should be applied since even when user gets 5000 shares it doesnt result of him owning the whole liquidity pool since 1000 shares are also minted to BURN address.


```solidity
 function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
        external
        returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
    {
        IStrategy(strategy).collectFees();

        (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

        if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

        require(shares > 0, "shares cant be 0");
        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);

function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        uint256 totalSupply = totalSupply();

        // If total supply > 0, vault can't be empty
        assert(totalSupply == 0 || bal0 > 0 || bal1 > 0);

        if (totalSupply == 0) {
            // For first deposit, just use the amounts desired
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000); 
        } else if (bal0 == 0) {
            amount1 = depositAmount1;
            shares = amount1 * totalSupply / bal1; //pool balance
        } else if (bal1 == 0) {
            amount0 = depositAmount0;
            shares = amount0 * totalSupply / bal0;
        } else {
            uint256 cross0 = depositAmount0 * bal1;
            uint256 cross1 = depositAmount1 * bal0;
            uint256 cross = cross0 > cross1 ? cross1 : cross0;
            require(cross > 0, "cross");

            // Round up amounts
            amount0 = (cross - 1) / bal1 + 1;
            amount1 = (cross - 1) / bal0 + 1;
            shares = cross * totalSupply / bal0 / bal1;
        }
    }
```
