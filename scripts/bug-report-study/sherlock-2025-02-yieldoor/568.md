# Incorrect decimals conversion in `Leverager::_calculateTokenValues`, when one of the tokens is missing a oracle

### Summary

When opening, withdrawing and liquidating positions, the usd value of the position is calculated in `Leverager::_calculateTokenValues`.

```solidity
  function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
    {
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();

        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }

        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);

            usdValue += amount1 * chPrice1 / decimals1;
        }

        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            // 6 + 30 - 30 + 18 - 8 = 16 -> Incorrect
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }

        return usdValue;
    }
```

In the situations where both tokens have a price feed, we only calculate the price using the price feeds.

However, in cases where one of assets does not have an oracle, we use the `price` parameter, which is the Uniswap's TWAP, which is in 30 decimals precision.


In the case where token0 does not have an oracle, the price will be calculated incorrectly, because of incorrect division by `decimals1`, and for `token1` we are incorrectly dividing by `decimals0`.


### Root Cause

Incorrect asset division in [_calculateTokenValues](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L443-L448)

### Internal Pre-conditions

1. One of the tokens must not have an oracle

### External Pre-conditions

None

### Attack Path

1. The user has a position of:
  - `100_000e6` USDC
  - `1e8` WBTC 
2. `chPrice1` is returned in 18 decimals, and `price` is in 30 decimals
3. usdValue = `(6 * 30 /  30) * 18 / 8 = 16`, however, the price should've been in 18

### Impact

This under/over value of the position assets might cause the `Strategy::isLiquidatable`, to falsely asume the position is under/over the minimum collateral ratio.
