# The TWAP oracle can be manipulated

in Leverager.sol:openLeveragedPosition.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L103
The TWAP oracle can be manipulated because the TWAP interval is configurable and can be as low as 1 minute (see Q&A) and the price check happens before the actual operations
also there is no minimum TWAP interval is enforced.
so:
The attacker can:
-Manipulate the pool price for a short duration
-Open a leveraged position with manipulated prices
-Potentially extract value through incorrect position valuations

You should enforce minimum TWAP

```solidity 
// In Strategy.sol
function setTwap(uint32 _twap) external onlyOwner {
    require(_twap >= 60, "TWAP must be at least 1 minute");  // Enforce minimum TWAP
    twap = _twap;
}

// In Leverager.sol
function openLeveragedPosition(LeverageParams calldata lp) external nonReentrant {
    // ...
    require(IVault(lp.vault).checkPoolActivity(), "market too volatile");
    uint256 price = IVault(lp.vault).twapPrice();
    uint256 spotPrice = IVault(lp.vault).price();
    require(abs(price - spotPrice) <= price * maxPriceDeviation / 10000, "price deviation too high");
    // ...
}
```
