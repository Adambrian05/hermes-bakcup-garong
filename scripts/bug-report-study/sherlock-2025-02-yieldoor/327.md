# Incorrect Repayment Calculation (token0 vs token1) in Withdraw Function Leads to Asset Losses or Liquidation

### Summary

In the withdraw function, when calculating repayment amount for token1, the code incorrectly uses `amountOut0` instead of `amountOut1`, which could lead to incorrect repayment calculations and potential asset loss.

### Root Cause

The bug exists in the token repayment logic where the wrong token amount (amountOut0) is used in the comparison when the borrowed token is token1. This leads to incorrect calculation of the repayment amount.

[yieldoor/src/Leverager.sol:withdraw#L232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232)
```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        // In case either of the tokens is denomination token, we directly take from it.
        if (borrowed == up.token0) {
            uint256 repayFromWithdraw = amountOut0 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut0 -= repayFromWithdraw;
        } else if (borrowed == up.token1) {
            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;    // @audit incorrectly uses `amountOut0` instead of `amountOut1`
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```

### Internal Pre-conditions

- The position must have borrowed token1

### External Pre-conditions

- Can be exploited under normal operating conditions

### Attack Path

1.Initial Setup:
- Create a leveraged position borrowing token1
- Denomination token is token 1
- Withdraw from the position, the contract will incorrectly use amountOut0 for repayment calculation

2.Scenario 1:
- `amountOut0 < owedAmount < amountOut1`
- This leads to incorrect repayment amount
- For example:
amountOut0 = 500
amountOut1 = 1000 
ownedAmount = 1200
repayFromWithdraw = 500 instead of 1000
incorrect repayment: 1000 -500 = 500

3.Scenario 2:
- `amountOut1 < owedAmount < amountOut0`
- Transaction reverts due to underflow: owedAmount -= amountOut0
- Users cannot reduce position or repay and gets liquidated when market volatility increases 
- For example:
amountOut0 = 1500
amountOut1 = 1000 
ownedAmount = 1200
repayFromWithdraw = 1500 instead of 1000
Transaction reverts: 1200 - 1500
Users cannot repay and gets liquidated

### Impact

- Incorrect calculation of repayment amounts when `amountOut0 < owedAmount < amountOut1`
- Users cannot reduce position or repay and gets liquidated when market volatility increases and `amountOut1 < owedAmount < amountOut0`
- Potential loss of assets

### Mitigation

It is recommended to fix the comparison in token1 branch.

```solidity
if (borrowed == up.token1) {
       uint256 repayFromWithdraw = amountOut1 < owedAmount
-           ? amountOut0
+           ? amountOut1    // @audit Use correct amountOut1
        : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```
