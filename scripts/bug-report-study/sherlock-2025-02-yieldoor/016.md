# Incorrect State Management in Fund Operations Due to Memory Usage

## Summary
The `pullFunds` and `pushFunds` functions in the `LendingPool` contract use memory instead of storage for `ReserveData`, resulting in state changes not being persisted to the blockchain. This causes critical accounting errors and incorrect interest rate calculations.

## Description
```solidity
// In LendingPool
function pullFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData memory reserve = getReserve(asset);  // CRITICAL: Using memory
    IyToken(reserve.yTokenAddress).transferUnderlyingTo(_msgSender(), amount);
}

// In LendingPool
function pushFunds(address asset, uint256 amount) external nonReentrant {
    require(msg.sender == leverager, "borrower not leverager");
    DataTypes.ReserveData memory reserve = getReserve(asset);  // CRITICAL: Using memory
    IERC20(asset).safeTransferFrom(msg.sender, reserve.yTokenAddress, amount);
}

// In ReserveLogic
function utilizationRate(DataTypes.ReserveData storage reserve) internal view returns (uint256 rate) {
    (uint256 total, uint256 borrows) = totalLiquidityAndBorrows(reserve);
    if (total > 0) {
        rate = borrows * (PRECISION) / (total);  // Calculation based on inaccurate state
    }
}
```
In the `pullFunds` and `pushFunds` functions, it can be seen that `ReserveData` is stored as memory, not storage, which means that changes will not be saved to the state because memory only copies data, not updates the state. This will cause total liquidity not to decrease and funds to enter but not be recorded in the reserve. Because the state is not updated, the interest rate calculation becomes inaccurate and the rate will be wrong because total liquidity is inaccurate.

## Scenario
1.	Initial State:
•	Reserve has 1000 tokens
•	Correct utilization rate is 50%
2.	Steps:
```diff
// Step 1: User (authorized leverager) calls pullFunds
pullFunds(tokenAddress, 500);
// - 500 tokens transferred out
// - State not updated due to memory usage
// - System still shows 1000 tokens

// Step 2: Interest rate calculation
utilizationRate();
// Returns incorrect rate based on 1000 tokens instead of 500

// Step 3: New deposits use wrong exchange rate
deposit(tokenAddress, 1000);
// Uses incorrect exchange rate due to wrong total liquidity
```

## Impact
-	Incorrect interest rate calculations affecting APY
-	Wrong exchange rates for deposits/withdrawals

## Recommendation
Change `memory` to `storage`.
