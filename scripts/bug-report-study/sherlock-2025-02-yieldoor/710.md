# Price manipulators will trigger unfair liquidations for users with leveraged positions

### Summary

The asymmetric liquidation calculation in the Leverager contract will cause unexpected liquidations for position holders as an attacker will manipulate borrowed asset prices upward to force liquidations that shouldn't occur under proper risk parameters.

### Root Cause

In `Leverager.sol`, the liquidation check converts the position's USD value to the denomination token by dividing by the denomination token price:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L399-L401

This calculation creates an asymmetric response to price movements. When the denomination token (borrowed asset) price increases, the position's value in terms of the denomination token decreases significantly, making it more likely to be liquidated, even when the position's USD value remains stable.


### Internal Pre-conditions

1. User has opened a leveraged position with `denomination` set to a volatile asset (e.g., WETH)
2. Position is not initially liquidatable under normal market conditions
3. `minCollateralPct` in VaultParams is set to a non-zero value (e.g., 0.1e18 as in tests)




### External Pre-conditions

1. Price of the borrowed asset needs to increase significantly (e.g., from 2000e18 to 6000e18 as shown in tests)
2. Oracle must allow price updates from authorized addresses without time-based protection



### Attack Path

Attacker identifies a target position with borrowed assets in a volatile token
Attacker manipulates the price of the borrowed asset upward (through flash loans or other means in low-liquidity markets)
The position becomes liquidatable due to the asymmetric liquidation mechanism
Attacker liquidates the position, potentially profiting from liquidation bonuses


### Impact

The position holders suffer unfair liquidations when borrowed asset prices increase, even when their collateral value is stable or increasing in USD terms. This creates a counterintuitive risk scenario where users are more vulnerable during bull markets (when borrowed assets appreciate) than bear markets (when collateral depreciates).

This asymmetry enables opportunistic liquidations that weren't intended by the protocol design, potentially leading to loss of user funds through liquidation penalties during favorable market conditions.

### Mitigation

1. Modify the liquidation check to evaluate position health based on USD values rather than denomination token units:

```solidity
// Calculate position health directly in USD terms
uint256 totalValueUSD = _calculateTokenValues(pos.token0, pos.token1, userBal0, userBal1, price);
uint256 borrowedUSD = owedAmount * bPrice / (10 ** ERC20(pos.denomination).decimals());

// Check if position is healthy based on USD values
if (borrowedUSD > totalValueUSD || totalValueUSD - borrowedUSD < vp.minCollateralPct * baseUSD / 1e18) return true;
```

2. Implement circuit breakers for large price movements in either direction to prevent flash loan manipulation
3. Add time-weighted price checks for significant price increases of the borrowed asset
