# Interest accounting when `checkCapacity()` is called can block deposits

### Summary

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/ReserveLogic.sol#L109-L118 

New interest accrual may block the ability to deposit into LendingPool.sol when checking the reserve in `ReserverLogic.checkCapacity()` 


At deposit time, `LendingPool.sol` contains a check for exceeding the allowable reserve size.
It is checked by comparing: 
```solidity 
require(totalLiquidity + (depositAmount) <= reserve.reserveCapacity);
``` 

`totalLiquidity` is calculated by addition: 
 
`total = availableLiquidity(reserve) + (borrows);`

`borrows` is calculated by taking into account borrowed funds + accrued interest

Due to the accrual of interest on borrowings, the total liquidity of the reserve (`totalLiquidity`) may exceed the prescribed `reserveCapacity` limit over time.

Because of the accrual of interest on loans, `borrowedLiquidity` and, as a result, `totalLiquidity` may increase over time. If totalLiquidity exceeds reserveCapacity, it will result in the impossibility of new deposits.

The Protocol could be left with bad debts and deposits would not be possible.


### Vulnerability Details

1. In `ReserveLogic.sol`, debts with interest are also taken into account when calculating total liquidity:
```solidity
function totalLiquidityAndBorrows(DataTypes.ReserveData storage reserve)
    internal
    view
    returns (uint256 total, uint256 borrows)
{
    borrows = borrowedLiquidity(reserve);
    total = availableLiquidity(reserve) + (borrows);
}
```

2. The `reserveCapacity` is checked at each deposit:
```solidity
function checkCapacity(DataTypes.ReserveData storage reserve, uint256 depositAmount) internal view {
    (uint256 totalLiquidity,) = totalLiquidityAndBorrows(reserve);
    require(totalLiquidity + (depositAmount) <= reserve.reserveCapacity);
}
```

The problem may arise as follows:

1. Bad debts accumulate and interest accrues on them through:
```solidity
function latestBorrowingIndex(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
    return reserve.borrowingIndex
        * (InterestRateUtils.calculateCompoundedInterest(reserve.currentBorrowingRate, reserve.lastUpdateTimestamp))
        / (PRECISION);
}
```

2. This increases `totalLiquidity` even if the real assets are smaller

3. When `totalLiquidity` approaches `reserveCapacity`, new deposits become impossible due to the check in `checkCapacity`

### Code Snippet

  ```solidity 
 function checkCapacity(DataTypes.ReserveData storage reserve, uint256 depositAmount) internal view {
        (uint256 totalLiquidity,) = totalLiquidityAndBorrows(reserve);

        require(totalLiquidity + (depositAmount) <= reserve.reserveCapacity);
    }

    function totalLiquidityAndBorrows(DataTypes.ReserveData storage reserve)

    function borrowedLiquidity(DataTypes.ReserveData storage reserve) internal view returns (uint256 liquidity) {
        liquidity = latestBorrowingIndex(reserve) * (reserve.totalBorrows) / (reserve.borrowingIndex);

   function latestBorrowingIndex(DataTypes.ReserveData storage reserve) internal view returns (uint256) {
        if (reserve.lastUpdateTimestamp == uint128(block.timestamp)) {
            //if the index was updated in the same block, no need to perform any calculation
            return reserve.borrowingIndex;
        }

        return reserve.borrowingIndex
```

### Recomendation
- Modify the `reserveCapacity` check to consider only real assets
- Add a mechanism to dynamically adjust `reserveCapacity`.
