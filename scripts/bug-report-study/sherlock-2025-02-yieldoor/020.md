# Missing zero address validation in deposit function

The `deposit` function allows users to specify an `onBehalfOf` address to receive the minted yTokens, but does not validate that this address is not the zero address (0x0000000000000000000000000000000000000000).

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L128

Impact:
If a user accidentally provides the zero address as the `onBehalfOf` parameter, the minted yTokens will be sent to the zero address. Since the zero address has no known private key, these tokens will be permanently locked, and the user will lose access to their deposited assets.

Recommendation:
Add a zero address check at the beginning of the `deposit` function:

```solidity
function deposit(address asset, uint256 amount, address onBehalfOf)
    public
    notPaused
    nonReentrant
    returns (uint256 yTokenAmount)
{
    require(onBehalfOf != address(0), "Cannot deposit on behalf of zero address");
    yTokenAmount = _deposit(asset, amount, onBehalfOf);
}
```

This simple check will prevent users from accidentally losing their assets due to input errors.
