# `twapTick()` Implementation is Inadequate

### Summary

The `Strategy.twapTick()` function currently calculates the TWAP tick by consistently rounding down. This approach is inappropriate; instead, the calculation should utilize half-rounding for improved accuracy.

### Root Cause

As highlighted in lines 351-352, the function [twapTick()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L351-L352) always rounds down when calculating the TWAP tick. This can lead to inaccuracies.

For instance, if the exact TWAP tick is `67453.98`, the function will return `67453`, leading to a TWAP price based on this value. This results in a discrepancy of nearly 1 tick. Consequently, a TWAP price that is approximately `1.0001` times different from the actual price may be used. In this scenario, `67454` would be the more accurate tick.

```solidity
    function twapTick() public view returns (int24) {
        uint32[] memory secondsAgos = new uint32[](2);
        secondsAgos[0] = twap;
        (int56[] memory tickCumulatives,) = IUniswapV3Pool(pool).observe(secondsAgos);
        int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0];

351     int24 tick = int24(tickCumulativesDelta / int32(twap));
352     if (tickCumulativesDelta < 0 && (tickCumulativesDelta % int32(twap) != 0)) tick--;
        return tick;
    }
```

### Mitigation

Implement half-rounding instead of always rounding down.

```diff
    function twapTick() public view returns (int24) {
        uint32[] memory secondsAgos = new uint32[](2);
        secondsAgos[0] = twap;
        (int56[] memory tickCumulatives,) = IUniswapV3Pool(pool).observe(secondsAgos);
        int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0];

+       int24 tick = int24((tickCumulativesDelta + int56(twap) / 2) / int32(twap));

-       int24 tick = int24(tickCumulativesDelta / int32(twap));
-       if (tickCumulativesDelta < 0 && (tickCumulativesDelta % int32(twap) != 0)) tick--;
```
