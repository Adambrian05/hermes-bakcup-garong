# Absent Liquidation Incentives and Protocol Fees Due to Flawed Liquidation Logic Resulting in Negative Returns for Liquidators

## Summary
The Leverager contract's liquidation mechanism contains critical flaws that eliminate liquidator incentives and protocol fees. The `isLiquidateable()` function allows positions to become underwater before triggering liquidation, while the `liquidatePosition()` function requires liquidators to cover the full debt repayment without adequate compensation. This creates a situation where liquidators face guaranteed losses when performing liquidations, effectively breaking the protocol's liquidation mechanism and potentially leading to systemic accumulation of bad debt.

## Vulnerability Details
The liquidation mechanism in the Leverager contract has multiple design flaws that collectively eliminate liquidator incentives:

1. **Late Liquidation Trigger**: The `isLiquidateable()` function only marks a position as liquidatable when `owedAmount > totalDenom` (among other conditions), meaning the position is already underwater when liquidation is triggered.

2. **No Liquidator Incentive**: When a position is liquidated, the liquidator must repay the full debt to the LendingPool, but the collateral they receive in return is worth less than this repayment amount.

3. **Protocol Fee Collection Failure**: The protocol fee is only collected when `totalValueUSD > borrowedValue`, but this condition is never true during liquidation since positions are only liquidatable when they're underwater.

4. **Liquidator Losses**: Liquidators must provide additional funds from their own wallet to cover the full debt repayment, as shown in this code section:

```solidity
if (owedAmount > 0) IERC20(up.denomination).safeTransferFrom(msg.sender, address(this), owedAmount);
```

Let's [examine the liquidation flow in `liquidatePosition()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L385-L413):

```solidity
// Withdraw the position's collateral
(uint256 amount0, uint256 amount1) = IVault(up.vault).withdraw(up.shares, liqParams.minAmount0, liqParams.minAmount1);

// Calculate values
uint256 totalValueUSD = _calculateTokenValues(up.token0, up.token1, amount0, amount1, price);
uint256 borrowedValue = owedAmount * bPrice / ERC20(up.denomination).decimals();

// This condition will never be true during liquidation
if (totalValueUSD > borrowedValue) {
    // Protocol fee calculation - never executed
    uint256 protocolFeePct = 1e18 * liquidationFee * (totalValueUSD - borrowedValue) / (totalValueUSD * 10_000);
    // ...
}

// Liquidator must cover any shortfall
if (owedAmount > 0) IERC20(up.denomination).safeTransferFrom(msg.sender, address(this), owedAmount);

// Repay the full debt
ILendingPool(lendingPool).repay(up.denomination, repayAmount);

// Transfer remaining tokens to liquidator (which will be worth less than what they paid)
if (amount0 > 0) IERC20(up.token0).safeTransfer(msg.sender, amount0);
if (amount1 > 0) IERC20(up.token1).safeTransfer(msg.sender, amount1);
```

## Proof of Concept
Consider a scenario with the following parameters:
- Position collateral value: 800 USDC
- Borrowed amount + interest: 900 USDC
- Position is liquidatable because owedAmount > totalDenom

During liquidation:
1. The liquidator calls `liquidatePosition()`
2. The contract withdraws the position's collateral (worth 800 USDC)
3. The condition `totalValueUSD > borrowedValue` is false (800 < 900), so no protocol fee is taken
4. The liquidator must provide 900 USDC to repay the debt
5. The liquidator receives the position's collateral worth 800 USDC
6. Net result: Liquidator loses 100 USDC on the transaction

This creates a negative incentive for liquidation, as liquidators are guaranteed to lose money.

## Impact Details
This vulnerability completely breaks the liquidation mechanism of the protocol. Rational actors will never perform liquidations since they're guaranteed to lose money, leading to an accumulation of bad debt in the system. Without functioning liquidations, the protocol cannot maintain solvency during market downturns, potentially leading to cascading failures and significant losses for users and the protocol itself.

## Recommendations
1. **Modify Liquidation Trigger**: Update `isLiquidateable()` to trigger liquidations before positions become underwater, using a safety margin.

2. **Implement Liquidation Bonus**: Add a liquidation bonus that ensures liquidators receive more value than they pay for debt repayment:

```solidity
// Example implementation
uint256 liquidationBonus = 1.1e18; // 10% bonus
uint256 maxRepayAmount = totalValueUSD * 1e18 / (liquidationBonus * bPrice / decimals);
uint256 repayAmount = owedAmount < maxRepayAmount ? owedAmount : maxRepayAmount;
```
