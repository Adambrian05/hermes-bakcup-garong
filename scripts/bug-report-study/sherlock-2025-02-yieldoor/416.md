# Incorrect Tick Range in Vesting Position Fee Collection

### Summary

The collectFees() function in [Strategy.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L166-L167) incorrectly uses mainPosition.tickUpper instead of vestPosition.tickUpper when collecting fees from the vesting position, resulting in fees being collected from an incorrect tick range.

### Root Cause

```solidity
function collectFees() public {
    // ...
    if (ongoingVestingPosition) {
        collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
    }
    // ...
}
```
The code incorrectly uses mainPosition.tickUpper instead of vestPosition.tickUpper when calling collectPositionFees() for the vesting position. This creates a mismatch between the tick range used when creating the position and the tick range used when collecting fees.

### Internal Pre-conditions

1. The `collectFees` function is called when there is an ongoing vesting position.
2. The `vestPosition.tickLower` and `vestPosition.tickUpper` are different from the `mainPosition` tick range.

### External Pre-conditions

1. The Uniswap V3 pool has accumulated fees that need to be collected.
2. There is a vesting position with a valid liquidity amount.


### Attack Path

1. The vault calls `collectFees()`.
2. The function mistakenly collects fees from `vestPosition.tickLower` to `mainPosition.tickUpper` instead of using `vestPosition.tickUpper`.
3. The collected fees are misallocated, leading to inaccurate distribution

### Impact

This bug has several critical implications:

1. Lost Fees: Fees earned by the vesting position may not be collected properly if `vestPosition.tickUpper` != `mainPosition.tickUpper`.

2. Incorrect Fee Attribution: Fees from tick ranges that don't correspond to the vesting position might be incorrectly attributed to it.

3. Potential Fee Theft: In scenarios where multiple positions overlap, this could result in collecting fees that belong to other positions.

4. Accounting Inconsistencies: The strategy's overall accounting will be incorrect, potentially impacting withdrawals,` rebalances`, and protocol fee calculations.

### Mitigation

Replace the incorrect tick range reference with the proper one:
```solidity
function collectFees() public {
    // ...
    if (ongoingVestingPosition) {
        collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
    }
    // ...
}
```
This ensures that fees are collected from the correct tick range that corresponds to the vesting position.
