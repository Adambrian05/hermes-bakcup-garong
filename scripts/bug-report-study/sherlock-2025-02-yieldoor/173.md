# Inaccurate Share Allocation During Initial Vault Deposits

### Summary

The current share calculation method for initial deposits in the vault contract is flawed. When `totalSupply == 0`, the contract assigns shares based solely on the larger of the two deposited token amounts (amount0 or amount1), disregarding their combined value. This approach leads to an inaccurate representation of a user's total deposit, causing potential misallocations of shares.

### Root Cause

In the vault's deposit function, when totalSupply == 0, the calculation `shares = (amount0 > amount1 ? amount0 : amount1) - 1000;` assigns shares based only on the larger token amount, neglecting the total value of both tokens combined.

```solidity
if (totalSupply == 0) {
    // For first deposit, just use the amounts desired
    amount0 = depositAmount0;
    amount1 = depositAmount1;
    shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
}
```

**Reference:** https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L129-L133

### Attack Path

1. A user initiates the first deposit into the vault with unequal values of two tokens (e.g., a large amount of a lower-value token and a small amount of a higher-value token).
2. The vault calculates shares based solely on the larger token amount, ignoring the combined deposit value. 
3. The user receives shares that do not accurately reflect their total deposited value, leading to potential over- or under-allocation.

### Impact

Users will receive an incorrect number of shares relative to their total deposit value during the initial deposit. This miscalculation can result in disproportionate ownership stakes within the vault.

### PoC

For First deposit in Vault

**Example 1 (amount0 > amount1):**
- **Deposit:** 2 WBTC (200,000,000 units) and 1,000 USDC (1,000,000,000 units)
- **Calculated Shares:**
    Since 200,000,000 > 1,000,000, the function uses WBTC’s raw value:
    shares = 200,000,000 - 1000 = 199,999,000
-  **Actual USD Value:**
    2 WBTC ≈ $160,000, plus 1,000 USDC ≈ $1,000 gives $161,000.
- **Issue:**
    The share calculation ignores the USDC’s $1,000, basing shares solely on WBTC. This misrepresents the total deposit value.

**Example 2 (amount1 > amount0):**
- **Deposit:** 0.5 WBTC (50,000,000 units) and 10,000 USDC (10,000,000,000 units)
- **Calculated Shares:**
    Since 10,000,000,000 > 50,000,000, the function uses USDC’s raw value:
    shares = 10,000,000,000 - 1000 = 9,999,999,000
- **Actual USD Value:**
    0.5 WBTC ≈ $40,000, plus 10,000 USDC ≈ $10,000 gives $50,000.
- Issue:
    Here, the shares are based only on USDC, ignoring the extra $40,000 from WBTC. Again, the deposit’s true value isn’t fully captured.

**Comparison:**
- In Example 1, shares are calculated as 199,999,000 based on the larger WBTC deposit, while the actual combined value is $161,000.
- In Example 2, shares are 9,999,999,000 based on USDC alone, despite the total value being $50,000.
