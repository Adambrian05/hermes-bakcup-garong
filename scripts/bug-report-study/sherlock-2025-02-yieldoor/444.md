# The `rebalance` function could be reverted

### Summary
The `rebalance` function may revert with a panic error due to identical `tickLower` and `tickUpper` values.

### Root Cause
`secondaryPosition.tickLower` could be same with `secondaryPosition.tickUpper`.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L377
```solidity
    function _setSecondaryPositionsTicks(int24 tick) internal {
        int24 modulo = tick % tickSpacing;
        uint256 bal0 = IERC20(token0).balanceOf(address(this));
        uint256 bal1 = IERC20(token1).balanceOf(address(this));
        uint256 _price = price();
        uint256 bal0in1 = bal0 * _price / PRECISION; // usually either of them should be 0, but might be non-zero due to rounding when minting

        if (bal0in1 < bal1) {
            secondaryPosition.tickLower = mainPosition.tickLower;
            secondaryPosition.tickUpper = tick - modulo;
        } else {
377:        secondaryPosition.tickLower = tick - modulo + tickSpacing;
            secondaryPosition.tickUpper = mainPosition.tickUpper; // TODO check if these need to be reversed.
        }

        emit NewSecondaryTicks(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
```

Let's consider the following senario:
    `tickSpacing := 60`, `current tick = -50`, the calculations are as follows:
In the `_setMainTicks`function: 
    `positionWidth = 240`, `halfWidth = 120`, `modulo = 10`, `isLowerSided = true`, `tickBorder = -60`,
    `mainPosition.tickLower = -180`, `mainPosition.tickUpper = 60`
In the `_setSecondaryPositionsTicks` function, 
    `module = -50`,
    if `bal0in1 >= bal1`:
        `secondaryPosition.tickLower = -50 -(-50) + 60 = 60`, 
        `secondaryPosition.tickUpper = mainPosition.tickUpper = 60`
    if `bal0in1 < bal1`:
        secondaryPosition.tickLower = -180;
        secondaryPosition.tickUpper = 0;
