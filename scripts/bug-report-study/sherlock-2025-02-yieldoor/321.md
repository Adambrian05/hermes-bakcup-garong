# The function _calculateTokenValues uses an incorrect formula when using twapPrice to calculate the price, causing the number of decimals of the result to be seriously deviated.

### Summary

When using Chalink price and TWAP price to calculate the USD value, the formula was used incorrectly, resulting in serious deviations in the results. 
According to the code piece:

```solidity
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }
```

We know that the number of decimals of the returned usdValue should be 8, which is the number of digits of the price returned by chainlink.

However, the number of decimals obtained by subsequent calculations is seriously inconsistent.

```solidity
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1; // @@@audit: / decimals0
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0; //@@@audit: ETH/USD, usdValue will be 0 because division precedes multiplication; * decimals1 
        }
```

For example, taking WETH/USDC as an example (WETH is token0 and USDC is token1), so the `price` will 3000e36 and chPrice1(price of USDC) will be 1e8. So, if amount = 1e18, `(amount0 * price / PRECISION) * chPrice1 / decimals1` = 1e18 * 3000e36 / 1e30 * 1e8 / 1e6 = 3000e26, instead of 3000e8. 

And if amount1 = 3000e6, amount1 * PRECISION / price * chPrice0 / decimals0 = 3000e6 * 1e30 / 3000e36 * 3000e8 / 1e18 = 0, instead of 3000e8.

So, the usdValue will be totally wrong.

### Root Cause

Incorrect formula when using twapPrice to calculate the price:

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L442-L448

```solidity
        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }
```

### Internal Pre-conditions

1. chPrice0 == 0 or chPrice1 == 0

### External Pre-conditions

None

### Attack Path

None

### Impact

The function _calculateTokenValues  will return a wrong usdValue, causing the the initial collateral price to be seriously high or low, and the contract may be DOS as a result.

### PoC

_No response_

### Mitigation

The correct implementation might be

```solidity
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1 / decimals0; // @@@audit: / decimals0
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0; //@@@audit: ETH/USD, usdValue will be 0 because division precedes multiplication; * decimals1 
        }
```
