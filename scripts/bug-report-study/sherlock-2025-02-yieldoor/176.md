# Infinite loop in path parsing leads to broken core contract functionality for opening leveraged positions with multiple pool swaps

## Summary
The `Leverager#_getTokenIn` function contains an infinite loop due to incorrect path manipulation, which breaks the core functionality of opening leveraged positions when using multiple pool swaps.

## Relevant Context
The `_getTokenIn` function is intended to extract the input token address from a swap path used in exact output swaps. It processes a path that may encode multiple token swaps.

## Root Cause
In `Leverager#_getTokenIn`, the call to `path.skipToken()` does not update the `path` variable. As a result, the original path remains unchanged, causing the `while` loop condition `path.hasMultiplePools()` to always evaluate to true if the initial path contains multiple pools. This leads to an infinite loop.

[`Leverager.sol#L568`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L568)

The function is invoked by `Leverager#openLeveragedPosition`, meaning any attempt to open a leveraged position with a multi-pool swap path will result in the transaction running out of gas.

## Attack Path

1. A user attempts to open a leveraged position by calling `openLeveragedPosition` with a swap path that includes multiple pools.
2. The function calls `_getTokenIn` to extract the input token from the provided path.
3. `_getTokenIn` enters an infinite loop while processing the multi-pool path due to the unchanged `path` variable.
4. The transaction runs out of gas and reverts, preventing the user from successfully opening the leveraged position.

## Impact Explanation
Medium. This issue results in broken core contract functionality, specifically the ability to open leveraged positions with multiple pool swaps. Users can work around the issue by using single-pool swaps, but this reduces the efficiency of the contract's functionality.

## Proof of Concept
Consider this sequence:

1. A user wants to swap USDC -> WETH -> DAI when opening a leveraged position.
2. The user provides a swap path encoding USDC-WETH-DAI pools.
3. `_getTokenIn` is called to extract the input token.
4. The function enters an infinite loop while processing the multi-pool path.
5. The transaction reverts due to out of gas.

## Recommendation
Update the path variable with the result of `skipToken()`:

```diff
function _getTokenIn(bytes memory path) internal pure returns (address) {
    while (path.hasMultiplePools()) {
-       path.skipToken();
+       path = path.skipToken();
    }

    (, address tokenIn,) = path.decodeFirstPool();
    return tokenIn;
}
```
