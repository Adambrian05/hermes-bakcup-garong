# Incorrect Accounting of Borrowed Amounts in Leverager Contract

## Description:
In the `Leverager` contract, there is a systematic accounting issue when updating the total borrowed amount for a vault. Both the `liquidatePosition()` and `withdraw()` functions decrease `currBorrowedUSD` by the initial borrowed amount (`up.initBorrowedUsd`) rather than the current debt value including accrued interest.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L376
```solidity
// Leverager::liquidatePosition()
vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
```

Similarly in `withdraw()` when fully withdrawing:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L270
```solidity
// Leverager::withdraw()
if (wp.pctWithdraw == 1e18) {
    vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
    delete positions[wp.id];
    _burn(wp.id);
}
```

And for partial withdrawals:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L285
```solidity
// Leverager::withdraw()
vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
```

While there are developer comments explaining the intentional use of `initBorrowedUsd` for partial withdrawals, those comments apply only to the partial withdrawal case and do not address the same issue in the full withdrawal case or in the `liquidatePosition()` function.

This issue creates a discrepancy between the tracked borrowed amount and the actual borrowed amount in the system, as interest accrual is not accounted for when positions are liquidated or fully withdrawn.

**Example**  
Suppose that:  
- A user borrowed 1000 USD (`up.initBorrowedUsd = 1000`)
- Over time, with accrued interest, the debt increased to 1100 USD (`borrowedValue = 1100`)
- During liquidation or full withdrawal, `currBorrowedUSD` is reduced by 1000 USD instead of 1100 USD 
- This creates a 100 USD discrepancy between `currBorrowedUSD` and the actual borrowed amount

## Impact:
This accounting error leads to an underreporting of the total borrowed amount across the protocol. Over time, as interest accrues on multiple positions, the gap between `currBorrowedUSD` and the actual borrowed amount will grow significantly.
The primary impacts are:
- The protocol may allow more borrowing than intended
- Risk metrics and protocol health indicators will be inaccurate

The issue is particularly concerning because it affects both liquidation and withdrawal flows, meaning that virtually all debt repayment scenarios will contribute to the accounting discrepancy.

## Recommended Mitigation:
Update both the `liquidatePosition()` and `withdraw()` functions to decrease `currBorrowedUSD` by the current debt value including accrued interest:

For `liquidatePosition()`:
```diff
- vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
+ vaultParams[up.vault].currBorrowedUSD -= borrowedValue;
```

For `withdraw()` when fully withdrawing:
```diff
- vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
+ vaultParams[up.vault].currBorrowedUSD -= borrowedValue;
```
