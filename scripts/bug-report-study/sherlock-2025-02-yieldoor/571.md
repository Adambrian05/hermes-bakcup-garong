# Withdrawal Failure in Leverager.withdraw() Due to Incorrect Repayment Calculation

### Summary

In the Leverager contract’s withdraw() function, when borrowed == up.token1, the variable amountOut0 is incorrectly used in repayment calculations. Since amountOut0 can be greater than amountOut1, this can cause an arithmetic underflow, preventing users from withdrawing funds and locking their assets in the contract.

```solidity
        } else if (borrowed == up.token1) {
@>            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;  // Underflow risk
        }
```

### Root Cause

In [Leverager.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L232), when borrowed == up.token1, the repayment calculation incorrectly uses amountOut0 instead of amountOut1.

### Internal Pre-conditions

1.	borrowed == up.token1.
2.	amountOut0 > amountOut1.
3.	amountOut1 < owedAmount.

### External Pre-conditions

A user attempts to withdraw funds after borrowing up.token1.

### Attack Path

1.	A user deposits funds and borrows token1.
2.	The user tries to withdraw their remaining balance.
3.	The contract uses amountOut0 instead of amountOut1 in repayment calculations.
4.	If amountOut0 > amountOut1, underflow occurs, causing the transaction to revert.
5.	The user’s funds remain locked in the contract.

### Impact

Users cannot withdraw their funds, all affected funds remain locked in the contract.

### PoC

_No response_

### Mitigation

```diff
        } else if (borrowed == up.token1) {
-            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+            uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw; 
        }
```
