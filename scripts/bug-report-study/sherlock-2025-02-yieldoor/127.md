# `Strategy::rebalance()` does not rebalance the vested position leading to loss of funds

### Summary

`Strategy::addVestingPosition()` places the vested position liquidity in the ticks of the main position. The main position is rebalanced over time to keep the ticks in the range that earns the most fees. However, `Strategy::rebalance()` does not also [rebalance](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L198) the vested position, which is still expected to collect fees, but will not collect as much as it should.

### Root Cause

In `Strategy:198`, the vested position is not rebalanced (removed and set again to the main position ticks).

### Internal Pre-conditions

None.

### External Pre-conditions

Pool price moves.

### Attack Path

1. Owner adds vested position.
2. Uniswap pool price moves and ticks must be updated.
3. Vested position does not update the ticks.

### Impact

Loss of fees from the [vested position](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167) which is not in the right ticks.

### PoC

`addVestingPosition()` sets the ticks of the vested position to be equal to the main ticks.
`rebalance()` updates the main position ticks but not the vested position.
`collectFees()` will not update as many fees as it should for the vested position.

### Mitigation

Update the ticks of the vested position when rebalancing.
