# Improper `minBorrow` Check in the `Leverager.withdraw()` Function

### Summary

When withdrawing, the remaining borrowed USD amount should exceed the `minBorrow`. However, the remaining amount used for this check differs from the actual remaining amount.

### Root Cause

Let's consider the `minBorrow` check at [line 280](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L280) of the `Leverager.withdraw()` function.

In this context, the remaining amount used for the check is calculated as `up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18`. This value differs from the actual remaining amount, which is determined at line 287.

This discrepancy can lead to the reversal of a legitimate withdrawal.

```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        ...

        if (wp.pctWithdraw == 1e18) {
            vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
            delete positions[wp.id];
            _burn(wp.id);
        } else {
            // Here, it doesn't matter that the initBorrowedUsd doesn't represent the real value. The scenarios are 2:
            // 1) Price has dropped. In this case, this would allow the user to actually have less than minBorrow opened,
            // but since borrowed asset's price has dropped, position is less likely to be liquidated
            // 2) Price has increased. In this case the user has to remain higher position value.
            require(
280             up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18 > minBorrow,
                "remaining should be at least minBorrow"
            );

            // here the BorrowedUSD variables do not represent the current value of the borrowed asset, that's intentional.
            vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;

287         positions[wp.id].initBorrowedUsd -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
            positions[wp.id].initCollateralValue -= up.initCollateralValue * wp.pctWithdraw / 1e18;
            positions[wp.id].borrowedAmount = totalOwedAmount - amountToRepay;
            positions[wp.id].borrowedIndex = bIndex;
            positions[wp.id].shares -= sharesToWithdraw;
        }
    }
```

### Attack Path

Consider the following scenario:

- `initBorrowedUsd` = 25e18 + 1
- `pctWithdraw` = 20%
- `minBorrow` = 20e18

In this case, the actual remaining amount is calculated as: `25e18 + 1 - (25e18 + 1) * 20% = 20e18 + 1`. This value is greater than `minBorrow`, suggesting that the transaction should succeed.

However, in the `minBorrow` check, `(25e18 + 1) * 80% = 20e18` is not greater than `minBorrow`, leading to the reversion of a legitimate withdrawal.

### Impact

Legitimate withdrawals could be incorrectly reverted.

### Mitigation

To address this issue, the check should be improved as follows:

```diff
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        ...

        if (wp.pctWithdraw == 1e18) {
            vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd;
            delete positions[wp.id];
            _burn(wp.id);
        } else {
            // Here, it doesn't matter that the initBorrowedUsd doesn't represent the real value. The scenarios are 2:
            // 1) Price has dropped. In this case, this would allow the user to actually have less than minBorrow opened,
            // but since borrowed asset's price has dropped, position is less likely to be liquidated
            // 2) Price has increased. In this case the user has to remain higher position value.
            require(
-               up.initBorrowedUsd * (1e18 - wp.pctWithdraw) / 1e18 > minBorrow,
+               up.initBorrowedUsd - up.initBorrowedUsd * wp.pctWithdraw / 1e18 > minBorrow,
                "remaining should be at least minBorrow"
            );

            // here the BorrowedUSD variables do not represent the current value of the borrowed asset, that's intentional.
            vaultParams[up.vault].currBorrowedUSD -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;

            positions[wp.id].initBorrowedUsd -= up.initBorrowedUsd * wp.pctWithdraw / 1e18;
            positions[wp.id].initCollateralValue -= up.initCollateralValue * wp.pctWithdraw / 1e18;
            positions[wp.id].borrowedAmount = totalOwedAmount - amountToRepay;
            positions[wp.id].borrowedIndex = bIndex;
            positions[wp.id].shares -= sharesToWithdraw;
        }
    }
```
