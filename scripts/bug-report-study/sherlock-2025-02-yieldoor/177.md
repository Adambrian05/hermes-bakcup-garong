# Incorrect use of `mainPosition.tickUpper` instead of `vestPosition.tickUpper`

### Summary

Incorrect use of `mainPosition.tickUpper` instead of `vestPosition.tickUpper` in fee collection will cause a miscalculation of fees for vesting positions for liquidity providers as an attacker (or even an operational error) will exploit the discrepancy by triggering fee collection from an incorrect tick range.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L167

### Root Cause

In `collectFees()` (see code snippet below), the vesting position fee collection is implemented as:
```

if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
}

```

This is a mistake because it uses `mainPosition.tickUpper` instead of the correct `vestPosition.tickUpper`. As `Uniswap V3 pools` rely on precise tick boundaries to determine fee accrual, using the wrong upper tick causes fees to be collected from an unintended price range.



### Internal Pre-conditions

ongoingVestingPosition must be true.
vestPosition.tickUpper is set to a value different from mainPosition.tickUpper.
The collectFees() function is called while the vesting position is active, allowing fees to accumulate over time.

### External Pre-conditions

The Uniswap V3 pool must experience significant trading activity within the price ranges corresponding to both the main and vesting positions.
Market volatility causes the tick ranges (price intervals) to diverge notably, so that the vesting position’s intended tick range does not overlap with the main position’s.

### Attack Path

An attacker (or an operator exploiting the error) observes that fee collection for the vesting position is using an incorrect tick range.
The attacker triggers a sequence of deposits and withdrawals to manipulate the fee accrual process.
Fees are collected from the wrong price interval (defined by mainPosition.tickUpper), resulting in either under-collection or misallocation of fees.
The attacker then withdraws funds, capturing a larger share of the misallocated fees at the expense of legitimate vesting LP rewards.

### Impact

Liquidity providers with vesting positions may suffer a significant loss in expected fee rewards due to the incorrect fee calculation. In an active exploit scenario, an attacker could extract additional fees from the protocol, thereby diminishing the overall yield for genuine users. 

### PoC

_No response_

### Mitigation

Replace the incorrect parameter in the vesting fee collection call:

````solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
}

```

This change ensures that fees are collected based solely on the vesting position’s actual tick range, preventing misallocation of rewards.
