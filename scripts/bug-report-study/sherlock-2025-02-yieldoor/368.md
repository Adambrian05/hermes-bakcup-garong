# Precision Loss in `_calculateTokenValues()` Makes the Total USD Value Less Than Actual

### Summary

The function `_calculateTokenValues()` performs division before multiplication in its calculations, causing precision loss in some special situations. This results in an inaccurate total USD value, which can affect downstream operations such as liquidation calculations.

### Root Cause

Inside the function `_calculateTokenValues()` of the Leverager contract, in the case where the tokens price feeds are not available, the function calculates the total `usdValue` using the preceding formula:

```Solidity
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }
```
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L444-L448

As we can see from the code, there is a precision loss in `usdValue` computation. Specially in the case where the `chPrice1` is equal to 0, the function faces a large precision (in some cases).
Considering the `price` is the twap price, its value is at the order of 42 ~ 44:

```Solidity
    function twapPrice() public view returns (uint256) {
        int24 tick = twapTick();
        uint160 sqrtPrice = TickMath.getSqrtRatioAtTick(tick);
        return (FullMath.mulDiv(sqrtPrice, 1e15, 2 ** 96) ** 2);
    }
```
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L357C1-L361C6

Also the `chPrice0` would be the Chainlinks price, thus its Order is at `1e8`. Considering these amounts, in some cases we may face a precision loss which can affect the liquidation calculations.
 

### Internal Pre-conditions

The `decimals0` needs to be less than 18 (e.g. 8 or 6)

### External Pre-conditions

The `price` amount needs to be larger than the `amount1` (neglecting the decimals)

### Attack Path

-

### Impact

The inaccurate USD value directly affects the liquidation calculations. A smaller USD value (in some cases) can incorrectly indicate that a position is safe from liquidation, exposing the protocol to the risk of bad debt accumulation.

### PoC

```Solidity
    function getAccuratePrice(uint amount1, uint price, uint chPrice0, uint decimals0) public pure returns(uint act, uint acc) {

        uint PRECISION = 1e30;
        act = amount1 * PRECISION / price * chPrice0 / decimals0;

        acc = (amount1 * PRECISION * chPrice0) / (decimals0 * price);
    }
```

### Mitigation

Consider prioritizing the multiplication over the division inside the `_calculateTokenValues()` function
