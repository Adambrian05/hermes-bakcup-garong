# Incorrect Tick Usage Leads to Fee Misallocation or DoS in Vesting Position

### Summary

In the `collectFees` function, when collecting fees for the ongoing vesting position, the contract mistakenly uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper`. This can lead to a DoS or incorrect fee collection behavior, potentially resulting in protocol revenue loss or incorrect distribution of collected fees. Over time, this could accumulate into a significant financial discrepancy, affecting the expected revenue distribution or even leaving the vesting functionality completely bricked.

### Root Cause

In `Strategy.sol:167` there is an incorrect reference to `mainPosition.tickUpper` instead of `vestPosition.tickUpper` in the fee collection logic.

```javascript
        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper); // @audit-issue mainPosition?
        }
```

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L167

### Internal Pre-conditions

- The protocol must have an ongoing vesting position.
- The `collectFees` function is executed.

### External Pre-conditions

- An external user calls `collectFees`.

### Attack Path

- `collectFees` is called, causing fees to be misallocated or DoS.

- The protocol distributes incorrect fee amounts due to the incorrect tick reference.

- Over time, this results in financial discrepancies that can harm the protocol and its participants.

### Impact

- Misallocation of fees leads to financial discrepancies and potential revenue loss for the protocol.
- The incorrect fee distribution could weaken protocol sustainability and fairness among users.
- Potential Denial-of-Service (DoS) risk if incorrect fee collection logic causes unexpected failures or imbalances in fee accrual.
- If `collectFees` reverts, It will also lead to `addVestingPosition` being reverted, as `collectFees` is being called in the function. This will lead to the vesting completely bricked. There is no way to withdraw the vesting position.
- If `collectFees` reverts, the core functions `rebalance` and `compound` will lead to DoS, if there is an ongoing vesting position.

### Mitigation

Replace `mainPosition.tickUpper` with `vestPosition.tickUpper` in the fee collection logic to ensure accurate fee accounting:

```diff
 if (ongoingVestingPosition) {
-           collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+           collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
        }
```
