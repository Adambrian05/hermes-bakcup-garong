# Dust debt remains to LendingPool even if borrowers repays all debt.

### Summary

The calculation of leverage position's debt amount used rounding down with borrowingIndex.   
This will cause that lendingPool's totalBorrows is bigger than sum of positions' borrowed amounts.


### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L221

`Leverage.sol#withdraw()` function is as follows.
```solidity
    function withdraw(WithdrawParams calldata wp) external nonReentrant {
        Position memory up = positions[wp.id];
        require(_isApprovedOrOwner(msg.sender, wp.id), "msg.sender not approved or owner");
        ...

        uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(borrowed);
@>      uint256 totalOwedAmount = up.borrowedAmount * bIndex / up.borrowedIndex;

        ...
    }
```
As we can see above, totalOwedAmount is calculated with rounding down.   
And `ReserveLogic.sol#_updateIndexes()` function is as follows.
```solidity
    function _updateIndexes(DataTypes.ReserveData storage reserve) internal {
        uint256 newBorrowingIndex = reserve.borrowingIndex;
        uint256 newTotalBorrows = reserve.totalBorrows;

        if (reserve.totalBorrows > 0) {
            newBorrowingIndex = latestBorrowingIndex(reserve);
@>          newTotalBorrows = newBorrowingIndex * (reserve.totalBorrows) / (reserve.borrowingIndex);

            require(newBorrowingIndex <= type(uint128).max);

            reserve.borrowingIndex = newBorrowingIndex;
@>          reserve.totalBorrows = newTotalBorrows;
        }
        reserve.lastUpdateTimestamp = uint128(block.timestamp);
    }
```
Rounding down in Leverage.sol will cause that `reserve.totalBorrows` in `LendingPool` is bigger than sum of positions' debt.


### Internal Pre-conditions

Leverage has two positions.


### External Pre-conditions

Time is passed from reserve.lastUpdateTimestamp.


### Attack Path

First postion has 1e8 of debt and second position has 1e8 of debt for same denomination(borrow token).   
The `reserve.totalBorrows` for same token in LendingPool is 2e8.   
And reserve.borrowingIndex = 1e27 and newBorrowingIndex = 1.2e27 + 0.5e19.   
Then, updated positions' debts both is 1e8 * (1.2e27 + 0.5e19) / 1e27 = 1.2e8.   
Therefore, sum of positions' debts becomes 1.2e8 + 1.2e8 = 2.4e8.
The newTotalBorrows in LendingPool becomes 2e8 * (1.2e27 + 0.5e19) / 1e27 = 2.4e8 + 1.   
So dust debt is remained even if all positions are withdrawed.

This loss is expanded by user's action in Leverage such as opening, withdrawing and liquidating.


### Impact

The protocol suffers dust debt.


### PoC

_No response_

### Mitigation

Use rounding up in calculation of total owed debt in Leverage.sol.
