# Lack of minimum position size checks can lead to uneconomical liquidations and bad debt

## Description:
The Yieldoor protocol currently lacks minimum size checks for both leveraged positions and lending positions. This absence creates a scenario where small positions that become liquidatable may never be liquidated because the cost of liquidation (gas fees) exceeds the potential profit for liquidators.
In both the `Leverager` and `LendingPool` contracts, users can create positions of any size, no matter how small:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L103
```solidity
// Leverager.sol
function openLeveragedPosition(LeverageParams calldata lp) external nonReentrant returns (uint256 _id) {
    // Checks for valid parameters, but no minimum size check
    require(lp.amount0In > 0 || lp.amount1In > 0, "No tokens provided");
    // ...
}
```

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L159
```solidity
// LendingPool.sol
function borrow(address asset, uint256 amount, address onBehalfOf) external nonReentrant {
    // Various checks, but no minimum borrow size check
    // ...
}
```

When these small positions become undercollateralized, liquidators (who are typically automated bots) evaluate whether liquidating the position would be profitable. If the liquidation bonus is smaller than the gas cost required to execute the liquidation transaction, rational liquidators will not perform the liquidation.

## Impact:
This vulnerability can lead to:
Accumulation of bad debt in the protocol as small undercollateralized positions remain unliquidated
Potential insolvency of the protocol if enough small bad positions accumulate
Possible attack vector where malicious actors intentionally create many small positions to destabilize the protocol

## Recommended Mitigation Steps:
Implement minimum size checks for both leveraged positions and borrowing
