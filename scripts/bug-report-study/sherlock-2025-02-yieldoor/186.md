# Infinite Loop

### Summary
There is an infinite loop in the `Leverager::_getTokenIn` function.

### Root Cause
In the `_getTokenIn` function, the `path` does not change. 
Therefore, if `path.hasMultiplePools() == TRUE`, the loop becomes infinite.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L568
```solidity
    function _getTokenIn(bytes memory path) internal pure returns (address) {
        while (path.hasMultiplePools()) {
568:        path.skipToken();
        }

        (, address tokenIn,) = path.decodeFirstPool();
        return tokenIn;
    }
```

### Internal pre-conditions
`path.hasMultiplePools() == TRUE`.

N/A

### PoC
The issue arises from the `skipToken` function in the Path library, which slices the `path` but does not update the original `path` variable in `_getTokenIn`.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/Path.sol#L58
```solidity
58: function skipToken(bytes memory path) internal pure returns (bytes memory) {
        return path.slice(NEXT_OFFSET, path.length - NEXT_OFFSET);
    }
```
The slice function returns a new value, but in line 568 of `Leverager.sol`, the path does not get updated with this new value.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/BytesLib.sol
