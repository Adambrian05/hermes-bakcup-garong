# Leverager Withdraw Will Fail Due to Arithmetic Underflow, Preventing Funds Retrieval

### Summary

Wrong calculation of `repayFromWithdraw` will raise `arithmetic underflow or overflow (0x11)` error when try to withdraw and if the below condition meets.
`denomination = token1 and amountOut1 < owedAmount and amountOut0 > amountOut1`

### Root Cause

Calculation of `repayFromWithdraw` is wrong.
[https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L231-L235)

It should be `uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;`, not `uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;`.

### Internal Pre-conditions

1. Position's `denomination` is `token1`.


### External Pre-conditions

1. The price  of `token0` should be smaller than the price of `token1` (when compare, the decimals should be concerned as well)
 

### Attack Path

1. Open leveraged position with the token0 and token1 which meets the precondition.(for example, `token0=dai`, `token1=weth`, `denomination=weth`)
 
2. After some times later, try to withdraw.

### Impact

Withdraw will fail with `arithmetic underflow or overflow (0x11)` error when `amountOut0 > amountOut1 and amountOut1 < owedAmount` because of below part of code.

```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
owedAmount -= repayFromWithdraw;
amountOut1 -= repayFromWithdraw;
```

### Mitigation

Replace
```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
```

With
```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
```
