# Incorrect Variable Usage in Withdraw Function Causes Repayment Miscalculation

### Summary

The use of amountOut0 instead of amountOut1 in the calculation of [repayFromWithdraw](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) will cause an incorrect repayment amount for the withdrawal operation, as an attacker could exploit this error to manipulate the repayment calculation, resulting in a loss of funds for users.

### Root Cause

In Leverager.sol (within the withdraw function), on the branch handling the case where the borrowed token is equal to up.token1, the ternary operation mistakenly uses amountOut0 instead of amountOut1. This error results in an incorrect deduction from the withdrawn amount, leading to improper debt repayment calculations.

### Internal Pre-conditions

The leveraged position is set up with the borrowed token being up.token1.
The withdraw function is called with a pctWithdraw value triggering a withdrawal.
The withdrawn amount for token1 (amountOut1) is less than the owed amount, but due to the error, amountOut0 is used in the repayment calculation.
The contract state allows the withdrawal branch to be executed without additional checks on the token source.

### External Pre-conditions

The external price feed and token balances must allow a scenario where the withdrawal involves token1 having a lower balance than the owed repayment amount.


### Attack Path

An attacker sets up or targets a leveraged position where the borrowed token is up.token1.
The attacker initiates a withdrawal with a specific percentage (pctWithdraw) that triggers the branch handling token1.
Due to the error, the calculation uses amountOut0 (instead of amountOut1) in the ternary operation, leading to an insufficient repayment amount.
The attacker leverages this miscalculation to withdraw more funds than they should or leave an under-collateralized position, potentially draining funds from the protocol or affecting the position's health.

### Impact

Users with leveraged positions where the borrowed token is up.token1 may suffer a loss of funds. The miscalculation in the repayment amount can leave positions under-repaid, allowing attackers to exploit the discrepancy to either drain additional funds from the protocol or manipulate collateral balances in their favor.

### PoC

none

### Mitigation

Correct the Variable: Update the repayment calculation in the withdraw function for the branch where borrowed == up.token1 to use amountOut1 instead of amountOut0: 
```solidity
if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}

```
