# Strategy Contract Will Incorrectly Collect Fees From Wrong Uniswap V3 Positions

### Summary

A bug in the Strategy contract's fee collection logic will cause a misalignment of tick ranges leading to potential loss of accrued fees for vesting positions. The contract incorrectly uses the main position's upper tick instead of the vesting position's upper tick when collecting fees, causing it to collect from a non-existent or incorrect position.

### Root Cause

In [Strategy.sol](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167), the code for collecting fees from vesting positions incorrectly uses `mainPosition.tickUpper` instead of `vestPosition.tickUpper`. This creates a mismatched position identifier (`vestPosition.tickLower`, `mainPosition.tickUpper`) that doesn't match the actual vesting position (`vestPosition.tickLower`, `vestPosition.tickUpper`) where liquidity and fees are located.



### Internal Pre-conditions

1. The Strategy contract must have an active vesting position (`ongoingVestingPosition` is true)
2. The vesting position must have different upper tick bounds than the main position (`vestPosition.tickUpper != mainPosition.tickUpper`)
3. The vesting position must have accrued fees that need to be collected

### External Pre-conditions

1. The Uniswap V3 pool must allow operations on both the correct and incorrect tick ranges (for the bug to remain undetected).

### Attack Path

1. The Strategy contract calls `collectFees()` to collect fees from positions
2. For the vesting position, it burns liquidity correctly with `vestPosition.tickLower` and `vestPosition.tickUpper`
3. When collecting fees, it uses `vestPosition.tickLower` but incorrectly uses `mainPosition.tickUpper`
4. The contract tries to collect fees from position (`vestPosition.tickLower`, `mainPosition.tickUpper`) instead of (`vestPosition.tickLower`, `vestPosition.tickUpper`)
5. This results in attempting to collect fees from a position that doesn't match where fees were actually accrued

### Impact

The contract's users (LPs) suffer a loss of accrued fees from vesting positions. When the tick ranges don't match, the fees remain uncollected in the correct position while the contract attempts to collect from a non-existent or incorrect position. This results in:

If the incorrect position doesn't exist: The transaction reverts with "Invalid tick range"
If the incorrect position exists but belongs to someone else: The transaction reverts due to lacking permission
If the incorrect position exists and belongs to the contract: The contract collects fees from the wrong position, potentially causing accounting errors

        return true;

        return _allowances[owner][spender];

        _approve(msg.sender, spender, amount);
        return true;

        _transfer(sender, recipient, amount);
        uint256 currentAllowance = _allowances[sender][msg.sender];
        require(currentAllowance >= amount, "ERC20: transfer amount exceeds allowance");
        _approve(sender, msg.sender, currentAllowance - amount);
        return true;
    }
    
    function _transfer(address sender, address recipient, uint256 amount) internal {
        require(sender != address(0), "ERC20: transfer from the zero address");
        require(recipient != address(0), "ERC20: transfer to the zero address");
        require(_balances[sender] >= amount, "ERC20: transfer amount exceeds balance");
        _balances[sender] -= amount;
        _balances[recipient] += amount;
    }
    
    function _approve(address owner, address spender, uint256 amount) internal {
        require(owner != address(0), "ERC20: approve from the zero address");
        require(spender != address(0), "ERC20: approve to the zero address");
        _allowances[owner][spender] = amount;
    }

### Mitigation

Fix the `collectFees()` function in the Strategy contract to use the correct tick range when collecting fees from the vesting position:

```solidity
if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);  // <-- BUG HERE
}

if (ongoingVestingPosition) {
    collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);  // <-- FIXED CODE
}
```
