# Front running attacks possible in `liquidatePosition()` on Ethereum mainnet.

### Summary

Front running attacks are possible on Ethereum Mainnet. In the function `liquidatePosition`, any adversary can front run valid liquidation calls with calls containing invalid parameters (liqParams.minAmount0/liq.Params.minAmount1). It will cause some gas fee to frontrunners but will cause delays to the protocol in liquidating positions. This delay may cause losses to the protocol in volatile markets.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L299-L380

Adversarial Frontrunning on Ethereum Mainnet make delaying `liquidatePosition()` possible. Not possible on L2.

### Internal Pre-conditions

1. A position is `liquidateable`.


### External Pre-conditions

1. Bad/Adversarial user front runs multiple times with invalid parameters which fail but delay the liquidation.

### Attack Path

1. A position is `liquidateable`.
2. Bad/Adversarial user front runs multiple times with invalid parameters which fail but delay the liquidation.

### Impact

Repeated delays may cause asset values to plummet further and cause losses to the protocol
