# Precision Issue in Midpoint Calculation within _setMainTicks Function

### Summary

In the [_setMainTicks](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L232) function, the [original logic](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L236) uses modulo < (tickSpacing / 2) to determine whether the current price tick is closer to the left (lower) or right (higher) valid tick.
The logic aims to align liquidity positions symmetrically around the nearest valid tick.
 However, when `tickSpacing` is an odd number, the integer division of `tickSpacing / 2 `truncates decimal precision, leading to incorrect midpoint alignment. reducing capital efficiency and increasing slippage risks in Uniswap V3 pools.

```solidity
function _setMainTicks(int24 tick) internal {  
    // ...  
    bool isLowerSided = modulo < (tickSpacing / 2); // Flawed logic  
    // ...  
}  
```

### Root Cause

The root cause lies in the integer division error during [midpoint calculation](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L236).

Example Scenario:
**Odd tickSpacing**
Parameters:` tickSpacing` = 15 (odd), tick = 22.
Valid Ticks: 15 (left), 30 (right).

```solidity
function _setMainTicks(int24 tick) internal {  
    // ...  
    bool isLowerSided = modulo < (tickSpacing / 2); // 

    int24 tickBorder = tick - modulo;
    if (!isLowerSided) tickBorder += tickSpacing;
    // ...  
}  
```
Calculation:
[modulo](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L234) = 22 % 15 = 7 (distance from left tick).

[Original logic](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L236):        7 < (15 / 2 = 7) --> false, incorrectly aligns to 30 (`tick - modulo+tickSpacing`).

True midpoint:           15 + 7.5 = 22.5 -->  tick = 22 should align to left tick 15.



**Even tickSpacing**

Example:
Parameters: `  tickSpacing` = 10, tick = 24
Valid Tick Candidates: 20 (left) and 30 (right).
Calculation:
`modulo` = 24 % 10 = 4.
Original Logic: 4 < 5 (since 10 / 2 = 5) → correctly aligns to the left tick (tickBorder = 20).

The original logic works correctly for even values, as the midpoint aligns with an exact integer (e.g., 20 vs. 30).
