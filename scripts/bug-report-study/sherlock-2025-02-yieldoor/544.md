# Integer overflow leading to the contract being DoS

# Summary

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L129-L134

The _calcDeposit code does not check for minimum values, leading to an integer overflow vulnerability, which could result in the contract being vulnerable to DoS attacks.

# Vulnerability Detail

In the _calcDeposit code logic, when the total supply is 0, it indicates this is the first deposit, so the amounts that the user wants to deposit, depositAmount0 and depositAmount1, are directly used. When calculating shares, the larger of the two amounts is selected, and 1000 is subtracted as the shares for the initial deposit. 

However, there is no check to ensure that the maximum of amount0 and amount1 is greater than 1000, which can lead to an integer overflow. In Solidity version 8.0+, this integer overflow would be automatically detected, triggering a runtime error, potentially resulting in a DDoS attack on the contract.

```solidity
function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        uint256 totalSupply = totalSupply();
        assert(totalSupply == 0 || bal0 > 0 || bal1 > 0);
        if (totalSupply == 0) {
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
        } 
        ...
    }
```
