# Chainlink oracle zero price leads to DOS of time-sensitive functionalities: opening leveraged positions and liquidations


## Summary
When Chainlink oracle returns a zero price, `PriceFeed#_getChainlinkPrice` reverts, causing `Leverager#_calculateTokenValues` to fail even when valid TWAP prices are available. This prevents liquidations and opening of leveraged positions during critical market events.

## Relevant Context
The `Leverager` contract allows users to open leveraged positions that can be liquidated when they become undercollateralized. The `_calculateTokenValues` function is critical for determining position values during both position opening and liquidation checks. It uses both Chainlink oracles and TWAP prices as price sources, with TWAP serving as a fallback when Chainlink prices aren't available for a token.

## Root Cause
In `PriceFeed#_getChainlinkPrice`, there is a strict requirement that the oracle price must be greater than zero:

[`PriceFeed.sol#L59`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/PriceFeed.sol#L59)

```solidity
require(answer > 0);
```

Chainlink oracles can return zero prices in several scenarios:
- During extreme market volatility or flash crashes
- When the oracle is paused due to detected anomalies
- During network upgrades or maintenance
- When there are insufficient valid oracle responses from node operators
- If the heartbeat (maximum time between updates) is exceeded
- During L1 congestion events affecting oracle updates

However, `Leverager#_calculateTokenValues` is designed to fall back to TWAP prices when Chainlink prices are unavailable. The current implementation causes the entire function to revert when Chainlink returns zero, preventing the use of valid TWAP prices as fallback.

[`Leverager.sol#L434`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L434)

[`Leverager.sol#L438`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L438)

## Attack Path

1. Market conditions cause Chainlink oracle to return zero price for either token0 or token1
2. User attempts to either:
   - Open a leveraged position via `openLeveragedPosition`
   - Liquidate an undercollateralized position via `liquidatePosition`
3. `_calculateTokenValues` is called to determine position value
4. Call to `PriceFeed#getPrice=>_getChainlinkPrice` reverts due to zero price
5. Transaction fails, despite valid TWAP prices being available
6. Protocol functionality is blocked until Chainlink price normalizes

## Impact Explanation
Medium. The function `_calculateTokenValues` is used in the functions `openLeveragedPosition` and `liquidatePosition`, which are both time-sensitive functions. When the chainlink oracle returns zero answer, the DoS would be triggered.

While this vulnerability affects core protocol functions, it requires specific conditions where Chainlink oracles return zero prices, which is relatively rare due to Chainlink's multiple safety mechanisms. However, when triggered, it completely blocks critical protocol operations, making it a medium-severity issue.

## Proof of Concept

1. User opens leveraged position with token0 and token1
2. Market crash causes Chainlink oracle for token0 to return zero price
3. Position becomes undercollateralized due to price movement
4. Liquidator attempts to liquidate position:
```solidity
liquidator.liquidatePosition(positionId);
```
5. Transaction reverts in `_calculateTokenValues` due to zero Chainlink price
6. Position cannot be liquidated despite being undercollateralized

## Recommendation
Modify `_calculateTokenValues` to handle zero Chainlink prices gracefully by falling back to TWAP prices for both tokens:

```solidity
    if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
        try IPriceFeed(pricefeed).getPrice(token0) returns (uint256 price) {
            chPrice0 = price;
            usdValue += amount0 * chPrice0 / decimals0;
        } catch {}
    }
    if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
        try IPriceFeed(pricefeed).getPrice(token1) returns (uint256 price) {
            chPrice1 = price;
            usdValue += amount1 * chPrice1 / decimals1;
        } catch {}
    }

    require(chPrice0 > 0 || chPrice1 > 0, "No pricefeed available");

    // Rest of the function
```

This allows the function to continue execution and use TWAP prices when Chainlink prices are unavailable.
