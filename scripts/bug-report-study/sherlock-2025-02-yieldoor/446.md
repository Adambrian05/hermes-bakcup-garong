# Incorrect Handling of Decimals

### Summary
The calculation of `usdValue` is incorrect due to improper handling of decimals.

### Root Cause
In line 445 of the `_calculateTokenValues` function, there is an incorrect handling of decimals.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L445

### PoC
Consider the following scenario:
`decimals0 = 8`(example: wbtc), `decimals1 = 18`(example: weth), `token0Price = 100,000 usd`, `token1Price = 2500 usd`, .
When the `_calculateTokenValues` function is called with the following arguments:
`amount0 = 1e8 (1 wbtc)`, `amount1 = 40e18 (40 weth)`, `price = 40e30`.
The `usedValue` should be `100,000 + 100,000 = 200,000 usd`.
Let's assume that there are no pricefeed of token0, so `chPrice0 = 0`, `chPrice1 = 2500e18`, 
In L439, `usdValue = 40e18 * 2500e18 / 1e18 = 100,000e18 (100,000 usd)`.
In L445, `usdValue = 100,000e18 + 1e8 * 40e30 / 1e30 * 2500e18 / 1e18 = 100,000e18 + 100,000e8`.
Therefore, the calculated `usdValue` is `100,000e18 + 1e13`, which is not equal to the actual `usdValue` of `200,000 usd`.

This issue occurs when the decimals of token0 and token1 are different, and one of them does not have a pricefeed.

The `_calculateTokenValues` function is used in the liquidation.

### Impact
Leverage positions that are healthy could be liquidated, leading to loss of funds for the position owner.
