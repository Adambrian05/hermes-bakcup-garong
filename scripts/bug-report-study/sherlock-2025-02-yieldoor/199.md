# The owner will lose funds when addVestingPosition.

### Summary

The `Strategy.sol#addVestingPosition()` function is for releasing liquidity for vestDuration.   
But extra funds remaines idle to strategy.   
This is owner's loss.   
And by using this vulnerability, rebalancer can instantly release funds from owner.


### Root Cause

The `Strategy.sol#addVestingPosition()` function is as follows.
```solidity
    function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
        collectFees(); // we collect fees first, in case there hasn't been a call since previous vested position ended
        require(!ongoingVestingPosition, "there's a currently ongoing VestingPosition");

        _requirePriceWithinRange();
        VestingPosition memory vp;

        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;

        (uint160 sqrtPrice,,,,,,) = IUniswapV3Pool(pool).slot0();
        uint128 liquidity = LiquidityAmounts.getLiquidityForAmounts(
            sqrtPrice,
            TickMath.getSqrtRatioAtTick(vp.tickLower),
            TickMath.getSqrtRatioAtTick(vp.tickUpper),
            amount0,
            amount1
        );

        vp.initialLiquidity = liquidity;
        vp.remainingLiquidity = liquidity;

        IUniswapV3Pool(pool).mint(address(this), vp.tickLower, vp.tickUpper, liquidity, "");

        vp.startTs = block.timestamp;
        vp.lastUpdate = block.timestamp;
        ongoingVestingPosition = true;
        vp.endTs = block.timestamp + _vestDuration;

        vestPosition = vp;
    }
```
As we can see above, remained funds are not refunded to owner.   
And vestingPosition is configured with mainPosition's ticks which are updated by rebalancer.   

The extra funds are remained with idle state to Strategy.   
This breaks owner's purpose for releasing funds for vestDuration.

### Internal Pre-conditions

The rebalanceInterval is expired from lastRebalance.


### External Pre-conditions

Pool is stable for twap duration.   
And currentTick is moved away from center of main position's tick range.


### Attack Path

The rebalancer frontruns owner's addVestingPosition transaction.   
Then, main position's ticks are changed unexpectedly.   
Therefore, expected liquidity of owner is not added for vesting.   
Then, remained funds are idle and this means instant releasing.


### Impact

- Owner lose remained funds after adding liquidity.
- Rebalaner can instantly release owner's funds.


### PoC

_No response_

### Mitigation

1. Add logic for refunding remained funds after adding liquidity.
2. VestingPosition's ticks have to be passed by owner.
