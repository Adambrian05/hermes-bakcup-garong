# Incorrect Debt Repayment Calculation Due to Token Mismatch in Withdraw Function

### Summary

The `Leverager.sol::withdraw` function contains a critical flaw in how it processes debt repayment when withdrawing a percentage of a leveraged position. Specifically, when the borrowed asset matches `up.token1`, the function mistakenly deducts the repayment amount from `amountOut0` instead of `amountOut1`. This incorrect deduction leads to an underpayment of the debt, causing an imbalance in the protocol’s accounting.

As a result, users can withdraw more than they should while leaving part of their debt unpaid. This discrepancy can accumulate over time, leading to bad debt in the system and potentially making the protocol insolvent.

### Root Cause

```solidity
uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount; // @audit-issue should be amountOut1 instead of amountOut0
```

In the condition where borrowed == `up.token1`, the repayment amount should be deducted from `amountOut1`, but the code mistakenly references `amountOut0`. This leads to an underpayment of the debt when the borrowed asset is `token1`, creating an accounting imbalance in the protocol.

### Attack Path

User Holds a Leveraged Position:

A user has an active leveraged position where `token1` is the borrowed asset.
User Initiates a Withdrawal:

The user calls the withdraw function with `wp.pctWithdraw` set to withdraw a portion of their position.
Incorrect Debt Repayment Calculation:

The function attempts to deduct the repayment amount from the withdrawn funds.
If borrowed == `up.token1`, the repayment should be deducted from `amountOut1`, but due to the bug, it incorrectly references `amountOut0`.
This results in less debt being repaid than required.
Debt Imbalance is Created:

Since the borrowed debt is not fully repaid, the protocol's accounting is incorrect.
The user effectively pays less than they should, leaving the protocol with an outstanding debt.
Potential Exploit Scenario:

An attacker could repeatedly withdraw portions of their leveraged position while leveraging this incorrect repayment logic.
Over multiple withdrawals, the attacker accumulates an unfair profit by underpaying their debt each time.
If this is exploited at scale, the protocol could become insolvent due to unaccounted liabilities.

### Impact

Imagine a DeFi lending platform that allows users to take leveraged positions by borrowing assets against their collateral. A trader deposits $10,000 worth of ETH and takes a leveraged position, borrowing $5,000 USDC.

Due to the bug in the withdrawal logic, when the trader tries to partially withdraw their position, an incorrect debt repayment calculation occurs. Instead of properly deducting the owed amount from their withdrawn funds, the smart contract misallocates repayment from one token (token0) instead of the correct token (token1).

This results in:

Underpayment of debt – The protocol falsely believes the trader repaid more than they actually did.

Bad debt accumulation – Over time, users withdrawing can leave unpaid debt in the system, putting the protocol at financial risk.

Exploitable arbitrage opportunity – Malicious users could repeatedly withdraw, take advantage of miscalculated repayments, and drain protocol reserves.

Potential insolvency – If enough users exploit this bug, the lending pool could run out of funds, leaving honest lenders unable to withdraw their deposits.
