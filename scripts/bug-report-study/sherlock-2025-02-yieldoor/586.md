# Exact input swap amount validation failure leads to liquidation transaction failures

## Summary
In the `Leverager` contract, when performing swaps during liquidation or withdrawal, the contract doesn't validate that the `amountIn` parameter is less than or equal to the available token balance. This can cause transactions to fail when the withdrawn amount is slightly less than expected due to pool activity or rounding errors.

## Relevant Context
The `Leverager` contract allows users to create leveraged positions by borrowing assets from a lending pool. When positions become liquidatable or when users withdraw from their positions, tokens may need to be swapped to repay debt. These swaps are performed using the Uniswap V3 router's `exactInput` function.

## Root Cause
In the `liquidatePosition` and `withdraw` functions, when performing swaps, the contract uses the `amountIn` value directly from the swap parameters provided by the caller without checking if there are sufficient tokens available. 

[`Leverager.sol#L237-L261`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L237-L261)

[`Leverager.sol#L346-L367`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L346-L367)

This is problematic because the amount of tokens withdrawn from the vault might be slightly different from what was expected due to:

1. Trading activity in the pool affecting the share value
2. Rounding errors in the vault's accounting
3. Precision loss in calculations

When the actual withdrawn amount is less than the expected `amountIn` (even by a few wei), the swap will fail because there aren't enough tokens available in the contract.

## Attack Path

1. A position becomes liquidatable, and a liquidator attempts to liquidate it by calling `liquidatePosition`
2. The liquidator calculates that they should receive exactly 1 WETH from the position and configures their swap parameters with `amountIn = 1e18` (1 WETH)
3. Due to trading activity in the pool, the actual withdrawn amount is 1e18 - 2 wei
4. When the contract attempts to execute `exactInput` with `amountIn = 1e18`, the transaction reverts because the contract only has 1e18 - 2 wei available
5. The liquidation fails, preventing the liquidator from liquidating the position

The same issue can occur in the `withdraw` function when users are trying to withdraw from their positions.

## Impact Explanation
Medium. This issue can prevent liquidations from being executed in time-sensitive situations, potentially leading to bad debt for the protocol if positions cannot be liquidated during market volatility. It also affects user experience when withdrawing from positions. However, it doesn't directly lead to loss of funds, as transactions simply fail rather than causing incorrect behavior.

## Proof of Concept
Consider the following scenario:

1. A user has a leveraged position with:
   - Denomination token: USDC
   - Token0: WETH
   - Token1: USDC
   - 1 WETH = 2500 USDC
   - Borrowed amount: 3000 USDC
   - Position has 1 WETH and 500 USDC in the vault

2. The position becomes liquidatable, and a liquidator attempts to liquidate it

3. The liquidator wants to swap all WETH to USDC to repay the debt, so they set:
   ```solidity
   swapParams.amountIn = 1e18; // 1 WETH
   ```

4. When the liquidator calls `liquidatePosition`, the contract withdraws the position's shares from the vault

5. Due to trading activity, the actual WETH amount withdrawn is 1e18 - 2 wei

6. When the contract tries to execute:
   ```solidity
   IERC20(up.token0).forceApprove(swapRouter, swapParams.amountIn);
   IMainnetRouter(swapRouter).exactInput(swapParams);
   ```
   The transaction reverts because there aren't enough tokens available

7. The liquidation fails, and the position remains unliquidated

## Recommendation
Modify the swap logic to use the minimum of the available token amount and the requested swap amount:

```solidity
// In liquidatePosition function
if (swapParams.amountIn > 0) {
    (address tokenIn,,) = swapParams.path.decodeFirstPool();
    require(tokenIn == up.token0, "tokenIn should be token0");
    // Use the minimum of available amount and requested amount
    uint256 actualAmountIn = swapParams.amountIn < amount0 ? swapParams.amountIn : amount0;
    IERC20(up.token0).forceApprove(swapRouter, actualAmountIn);
    
    // Update the swap parameters with the actual amount
    swapParams.amountIn = actualAmountIn;
    IMainnetRouter(swapRouter).exactInput(swapParams);
    amount0 -= actualAmountIn;
}
```

Apply the same fix to all similar swap operations in both the `liquidatePosition` and `withdraw` functions.
