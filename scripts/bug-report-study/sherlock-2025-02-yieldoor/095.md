# Secondary position in the Strategy unallocated capital due to incorrect tick allocation

### Summary

The secondary position in the strategy sets the ticks by doing:
```solidity
if (bal0in1 < bal1) {
    secondaryPosition.tickLower = mainPosition.tickLower;
    secondaryPosition.tickUpper = tick - modulo;
} else {
    secondaryPosition.tickLower = tick - modulo + tickSpacing;
    secondaryPosition.tickUpper = mainPosition.tickUpper; // TODO check if these need to be reversed.
}
```
Note that this will be incorrect for negative ticks, and will actually place the second position in the active tick range, not allocating any liquidity as the amounts left consist only of one token to allocate. Thus, the second position will never be used and the capital will be unallocated.

### Root Cause

In `Strategy:373-379`, tick [calculation](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L373-L379) is wrong when ticks are negative.

### Internal Pre-conditions

None.

### External Pre-conditions

Tick must be negative.

### Attack Path

1. Protocol rebalances but a significant amount of liquidity will not be allocated to the secondary position.

### Impact

Significant loss of fees as the capital is not allocated.

### PoC

```solidity
tick = -80
modulo = -80 % 60 = -20
tickUpper = -80 - (-20) = -60
```
So the upper tick is bigger than the current tick, which means the position will require both token amounts, but only of the token amount is available and nothing will be allocated.

### Mitigation

Adjust for negative ticks.
