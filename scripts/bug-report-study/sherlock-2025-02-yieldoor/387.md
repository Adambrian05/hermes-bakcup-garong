# Protocol functions will attempt to transfer zero amounts which can cause reverts with certain tokens


## Summary
The lack of zero-amount checks in multiple contract functions will cause transaction reverts for users when interacting with tokens that don't support zero-value transfers, as the protocol will attempt to execute these transfers under specific conditions.

## Root Cause
In multiple locations, the protocol attempts token transfers without checking if the amount is zero:

- In [`Vault.sol#L58-L59`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L58-L59) during deposits:
```solidity

        external

    {

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

        if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);
```

## Internal pre-conditions
1. Strategy must contain only one type of token
2. Borrowed token must be either `token0` or `token1` of the pool

## External pre-conditions
1. Current tick must be outside of strategy's main and secondary tick range

## Attack Path
1. When a strategy contains only one token type, deposits and withdrawals will attempt zero-amount transfers for the other token
2. During liquidation, if the borrowed token matches the pool's token and certain conditions are met, `owedAmount` can be reduced to zero
3. The protocol attempts to transfer these zero amounts without validation

## Impact
Users will experience transaction reverts when interacting with tokens that don't support zero-value transfers, leading to failed operations and potential loss of gas fees.
