# The balances of the strategy can be manipulated to decrease a leveraged position's collateral value in the `Leverager`

### Summary

The balances of the strategy consist of three parts:
1. the idle balances in the contract strategy
2. the amount0 and amount1 of the `mainPosition`
3. the amount0 and amount1 of the `secondaryPosition`

As for the amount0 and amount1 of the `mainPosition` and `secondaryPosition`, they are determined by the spot price of the pool. If a malicious user manipulates the spot price of the pool, the balances of the strategy will be manipulated too. As the collateral value of a leveraged position in the `Leverager` is calculated with the strategy's balances and oracle prices.

In that way, the collateral value of a leveraged position can be manipulated to decrease too, and a malicious user can liquidate other users' leveraged positions to make profits.

[Strategy](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L502C2-L521C6)

```solidity
   function balances() public view returns (uint256 amount0, uint256 amount1) {
        (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();

        (uint256 idle0, uint256 idle1) = idleBalances();
        (uint256 m0, uint256 m1) = LiquidityAmounts.getAmountsForLiquidity(
            sqrtPriceX96,
            TickMath.getSqrtRatioAtTick(mainPosition.tickLower),
            TickMath.getSqrtRatioAtTick(mainPosition.tickUpper),
            mainPosition.liquidity
        );
        (uint256 s0, uint256 s1) = LiquidityAmounts.getAmountsForLiquidity(
            sqrtPriceX96,
            TickMath.getSqrtRatioAtTick(secondaryPosition.tickLower),
            TickMath.getSqrtRatioAtTick(secondaryPosition.tickUpper),
            secondaryPosition.liquidity
        );

        amount0 = idle0 + m0 + s0;
        amount1 = idle1 + m1 + s1;
    }
```

As for the amount0 and amount1 of the `mainPosition` and `secondaryPosition`, they are determined by the spot price of the pool. The formula is as follows.

We assume the `sqrtRatioAX96=FixedPoint96.Q96`, `sqrtRatioBX96=4*FixedPoint96.Q96`.
And we assume the oracle prices and token decimals of token0 and token1 are both same, and we use `price` to represent for simplification.

1. A malicious user manipulates the sport price of the pool to be `sqrtRatioX96 <= sqrtRatioAX96`:
amount0 = 0.75*liquidity
amount1 = 0
orcale price of token0 == orcale price of token1 == `price`(for simplification)
Then the collateral value in USD of amount0 and amount1 is: `0.75*liquidity*price`

2. A malicious user manipulates the sport price of the pool to be `sqrtRatioAX96 < sqrtRatioX96 < sqrtRatioBX96` and `sqrtRatioX96=2*FixedPoint96.Q96`:
amount0 = 0.25*liquidity
amount1 = liquidity
orcale price of token0 == orcale price of token1 == `price`(for simplification)
Then the collateral value in USD of amount0 and amount1 is: `1.25*liquidity*price`

3. A malicious user manipulates the sport price of the pool to be `sqrtRatioX96 >= sqrtRatioBX96`:
amount0 = 0
amount1 = 3*liquidity
orcale price of token0 == orcale price of token1 == `price`(for simplification)
Then the collateral value in USD of amount0 and amount1 is: `3*liquidity*price`

As we can see, the collateral value in USD of amount0 and amount1 will be decreased by the spot price of the pool, since the amount0 and amount1 are determined by the pool.slot0.

Thus, 
1. A malicious user can make a flash loan to manipulate the spot price of the pool to decrease the collateral value in USD of a leveraged position in the `Leverager`
2. The attacker immediately liquidate the leveraged position to get the collateral which real value is actually higher than the debt.
3. Then repay the flash loan.
4. The attacker get more valuable collateral with paying less valuable debt.

```solidity
function _calculateTokenValues(address token0, address token1, uint256 amount0, uint256 amount1, uint256 price)
        internal
        view
        returns (uint256 usdValue)
    {
        uint256 chPrice0;
        uint256 chPrice1;
        uint256 decimals0 = 10 ** ERC20(token0).decimals();
        uint256 decimals1 = 10 ** ERC20(token1).decimals();
        if (IPriceFeed(pricefeed).hasPriceFeed(token0)) {
            chPrice0 = IPriceFeed(pricefeed).getPrice(token0);
            usdValue += amount0 * chPrice0 / decimals0;
        }
        if (IPriceFeed(pricefeed).hasPriceFeed(token1)) {
            chPrice1 = IPriceFeed(pricefeed).getPrice(token1);
            usdValue += amount1 * chPrice1 / decimals1;
        }

        // If chPrice0 is 0, it means token0 doesnt have a pricefeed.
        // Therefore, convert it token1 and from there, convert it to USD
        if (chPrice0 == 0) {
            usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
        } else if (chPrice1 == 0) {
            usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
        }

        return usdValue;
    }
```
