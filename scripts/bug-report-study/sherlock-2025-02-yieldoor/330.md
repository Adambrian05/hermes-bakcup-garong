# Missing validation of minCollateralPct in Leverager:changeVaultMinCollateralPct()

### Summary

The `changeVaultMinCollateralPct()` function in the `Leverager.sol`contract allows the owner to modify a vault’s minimum collateral percentage without enforcing any constraints on the input value. This oversight introduces risks such as insolvency due to extremely low collateral requirements or complete vault inaccessibility due to excessively high collateral demands.

### Root Cause
https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L529C5-L533C6
There's no constraint on the `minCollateralPct`
```solidity
/// @notice Changes a vault's minimum collateral percentage
    function changeVaultMinCollateralPct(
        address vault,
        uint256 minColateral
    ) external onlyOwner {
        VaultParams storage vp = vaultParams[vault];
        vp.minCollateralPct = minColateral;
    }
```
Though Owner is trusted. There should have some constraint on the `minCollateralPct`. The range can be 10% to 20% or 10% to 30% or any chosen range. Users who create their leverage position they would know in advance that this the range in which the admin can change. This creates huge centralization risk.

### Impact

Impact



Risk of Insolvency: If minColateral is set too low (e.g., <10%), users can borrow with minimal collateral, increasing the risk of undercollateralized positions and protocol insolvency.

Loss of Functionality: If minColateral is set too high (e.g., >100%), vaults may become unusable as users cannot meet the excessive collateral requirement.

Potential for Admin Abuse or Exploitation: A compromised or malicious admin could manipulate this parameter to cause financial loss or denial of service.
