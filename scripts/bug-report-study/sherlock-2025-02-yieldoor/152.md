# `Leverager::isLiquidateable()` `base` calculation is incorrect when `base >= pos.initCollateralValue`

### Summary

The base [calculation](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L409) is intended to calculate the base collateral needed if the leveraged used was the max. As the debt grows, the base amount will be updated to reflect the collateral that would be needed. In the calculation, the base amount should never exceed the init collateral given, otherwise the base will be too big and the user will get liquidated even if the init collateral has not dropped more than `vp.minCollateralPct`.

### Root Cause

In `Leverager:409`, the base is calculated using the full position amount instead of the init collateral deposited. 

### Internal Pre-conditions

None.

### External Pre-conditions

None.

### Attack Path

1. User will be liquidated when it shouldn't due to `Leverager::isLiquidateable()` returning true.

### Impact

User is unfairly liquidated even when the initial collateral didn't reach `vp.minCollateralPct` yet.

### PoC

Borrow = 1000
Deposit = 1000
Total position = 2000 = `pos.initCollateralValue`
Borrow goes to 1100 = `owedAmount`
Base = 1100 / 1 < 2000 = 1100 (`vp.maxTimesLeverage` is 2)
2000 - 1100 < 0.1x1100 = 110

110 is more than 10% of the initial collateral, which is 100 (0.1x1000), so the user is liquidated too soon.

### Mitigation

Base should be capped at the initial collateral deposited.
