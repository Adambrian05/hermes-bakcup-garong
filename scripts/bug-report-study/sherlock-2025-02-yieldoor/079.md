# Attacker can steal user funds through TWAP manipulation and forced liquidations

### Summary

The reliance on TWAP prices for position valuation in `Leverager::liquidatePosition()` can cause theft of user funds as an attacker can manipulate the price downward, artificially trigger liquidations, and profit from the liquidation process

### Root Cause

In `Leverager::liquidatePosition()`, the protocol calculates the position value using Uniswap V3 TWAP without ensuring sufficient observation cardinality or using a more manipulation-resistant oracle like chainlink in case one of the assets has no chainlink price feed

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L308-L315

The protocol uses this potentially manipulated price to determine if positions are eligible for liquidation, creating an attack vector.

### Internal Pre-conditions

1. The protocol needs to have a leveraged position open
2. The opened position must have at least one token without chainlink price feed

### External Pre-conditions

1. Uniswap V3 pool needs to have low observation cardinality

### Attack Path

1. Attacker identifies a leveraged position using a token without chainlink
2. Attacker executes a large swap to significantly drive down the price of the token
3. The manipulated TWAP causes `totalValueUSD` to decrease below the liquidation threshold
4. Attacker calls the liquidation function to liquidate the position
5. Attacker swaps the tokens back to their original price, profiting from the difference

### Impact

The users with leveraged positions suffer a complete loss of their collateral as their healthy positions are artificially forced into liquidation.

N/A

### Mitigation

Implement multiple layers of protection against TWAP manipulation:

1. Use Chainlink oracles for all supported tokens, or fallback to a time-weighted average of multiple DEXes
2. Implement minimum observation cardinality requirements before accepting TWAP values
