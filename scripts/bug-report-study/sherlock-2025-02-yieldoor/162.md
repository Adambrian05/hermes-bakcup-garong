# Ticks set in the Strategy constructor can be extremely off as there are no deviation checks, leading to loss of fees

### Summary

`Strategy:constructor()` sets the position ticks and the rebalance timestamp to now. Thus, it will not be possible to rebalance until the next rebalance interval, being only possible to compound. `Strategy::compound()` consists of adding liquidity to the current ticks, so if these ticks are off, the position will not earn any fees. Thus, until the rebalance interval passes, the protocol is vulnerable to not getting fees.

### Root Cause

In `Strategy:104/105`, ticks are [set](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L104-L105) without checking pool activity.

### Internal Pre-conditions

None.

### External Pre-conditions

Pool is imbalanced when the strategy is deployed.

### Attack Path

1. Strategy is deployed and ticks are set when the pool is imbalanced.
2. Users/protocol add liquidity, but the ticks are off so no fees are earned until the rebalance interval passes.

### Impact

The protocol suffers loss of fees for the rebalance interval. Fees come from swaps, not necesserily time, so big swaps and thus big fees can be missed.

### Mitigation

Check pool activity on deployment.
