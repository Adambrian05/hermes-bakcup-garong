# collectFees()

**Short Answer**  

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Strategy.sol#L167
The bug is in **`collectFees()`**, where it calls  
```solidity
collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
```  
instead of using  
```solidity
collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
```  
This mismatch will break fee collection for the vesting position whenever the main position’s upper tick differs from the vesting position’s upper tick.

---

## Explanation

1. **Where it happens**  
   In the `collectFees()` function, you will see:

   ```solidity
   if (ongoingVestingPosition) {
       collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
   }
   ```
   However, the vesting position is defined by both a lower and upper tick stored in `vestPosition.tickLower` and `vestPosition.tickUpper`. If the main position is later updated to different ticks, the code still tries to collect fees using `mainPosition.tickUpper` instead of the vesting position’s own upper tick.

2. **Why it matters**  
   - The contract mints the vesting position with:
     ```solidity
     vp.tickLower = mainPosition.tickLower;
     vp.tickUpper = mainPosition.tickUpper;
     ```
     That works at the moment of minting. But if the main position is subsequently rebalanced (and thus its ticks change), you now have:
     - A vesting position stored at (`vestPosition.tickLower`, `vestPosition.tickUpper`)  
     - A main position stored at (`mainPosition.tickLower`, `mainPosition.tickUpper`)  

     They can diverge. The vesting position might still be at the *old* ticks, but the call `collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper)` incorrectly uses the new main position’s upper tick.

3. **The correct fix**  
   Instead of using `mainPosition.tickUpper`, the function should collect fees on the vesting position’s own ticks:
   ```solidity
   // old code
   collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);

   // correct code
   collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
   ```
   This ensures fees are properly collected for the actual vesting position and not accidentally tied to the main position’s ticks if they have changed.

4. **Implications**  
   - If the main position’s upper tick changes, the contract would fail to collect fees from the real vesting position range.  
   - In the worst case, the vesting position accumulates fees but never has them properly collected if it truly sits at (`vestPosition.tickLower`, `vestPosition.tickUpper`) while the code is looking at (`vestPosition.tickLower`, `mainPosition.tickUpper`).
