# Protocol may fail to collect the fees from the vesting position

### Summary

Protocol will fail to collect the fees from the vesting position if the vesting position's upper tick is different with the main position's upper tick.

### Root Cause

In [Strategy.sol:167](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167), when users collect fees, the protocol will charge one part of the uniswap v3 swap fees to the protocol recipient.

The problem here is that when we try to collect fees from the vesting position, we use the `mainPosition.tickUpper`. When the owner creates one vesting position, the initial tick(upper/lower) will be the same as the main position's upper tick and lower tick. But the rebalancer will rebalance the main position periodically. The main position's tick(upper/lower) will be changed according to current tick price. Then main position's upper tick will be different with vesting position's upper tick. This will cause that the range with lower tick`vestPosition.tickLower` and upper tick `mainPosition.tickUpper` will be one invalid position for the strategy, and we cannot collect any fees from this input position.

```solidity
    function rebalance() public onlyRebalancer {
        require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");
        _requirePriceWithinRange(); // we verify that the pool's price is currently not manipulated
        collectFees();
        _removeLiquidity();

        (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

        _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
        lastRebalance = block.timestamp;
    }
```

### Internal Pre-conditions

Rebalancer trigger the rebalance periodically. And the main position's tick is changed and different with vesting position's tick.

### External Pre-conditions
The price in the v3 pool changes. When we rebalance this via the `rebalance`, the main position's tick will change.

### Attack Path
0. Current main positions' upper tick is 20, lower tick is -20.
1. The owner adds one vesting position to incentive LPs. The vesting position's tick will be initialized as upper tick(20), lower tick(-20).
2. After one period of time, the rebalancer rebalance the main position. Main position's upper tick is 18, lower tick is -22. But we will not update the vesting position.
3. When we want to collect vesting fees, we try to collect fees from tick range (-20, 18). However, we donot add any liquidity in the range (-20, 18). So we will not collect any fees from vesting positions via `collectPositionFees`.
4. When we withdraw part of the vesting position, we will collect this vesting position correctly, but the protocol cannot charge the protocol fee for this part.

### Impact
The protocol will fail to charge protocol fee from the vesting position if vesting position's tick is different with the main position's tick.

N/A

### Mitigation
Collect the vesting position's fee with the correct vesting position's upper tick and lower tick.
