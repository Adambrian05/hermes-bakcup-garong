# The `Strategy.sol::price` calculation may overflow

### Summary

The `price` function queries the pool to fetch the `sqrtPriceX96` and calculates the spot price, but the calculation might overflow.


### Root Cause

[Strategy.sol::L125-L129](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L125-L129)
```Solidity
    function price() public view returns (uint256 _price) {
        (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();
>       _price = FullMath.mulDiv(sqrtPriceX96, 1e15, 2 ** 96) ** 2;
    }

```
The multiplications in the line 128 may eventually overflow.

### Internal Pre-conditions

None.

### External Pre-conditions

None.

### Attack Path

None.

### Impact

Causing the whole transaction to fail when user calls a function that invokes `price`.

### PoC

_No response_

### Mitigation

Consider using [OracleLibrary.sol::getQuoteAtTick](https://github.com/Uniswap/v3-periphery/blob/main/contracts/libraries/OracleLibrary.sol#L49-L69) from Uniswap V3 periphery contracts.
Here `PRECISION` is 1e30
```diff
    function price() public view returns (uint256 _price) {
-       (uint160 sqrtPriceX96,,,,,,) = IUniswapV3Pool(pool).slot0();
-       _price = FullMath.mulDiv(sqrtPriceX96, 1e15, 2 ** 96) ** 2;
+       (, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();
+       _price = OracleLibrary.getQuoteAtTick(tick, uint128(PRECISION), token0, token1);
    }

```
