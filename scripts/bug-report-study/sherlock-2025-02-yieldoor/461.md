# Absence of Recovery Mechanism for Residual Assets in yToken Contract Leads to Permanent Value Lock

## Summary
The yToken contract lacks any functionality to recover residual underlying assets that may accumulate due to rounding errors in token calculations. When users deposit, withdraw, or borrow from the lending pool, small amounts of tokens can remain in the [yToken contract ](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/yToken.sol#L14)due to division rounding. Without a recovery mechanism, these tokens become permanently locked, resulting in value loss for the protocol and its users over time. This is particularly problematic as the protocol scales and the accumulated dust amounts become more significant.

## Vulnerability Details
The yToken contract serves as the tokenized representation of deposits in the LendingPool. It handles the minting, burning, and transfer of underlying assets. However, it lacks any function to recover residual tokens that may accumulate.

The contract has only three methods for moving underlying assets:
```solidity
// Burns yTokens and transfers underlying assets to a user
function burn(address receiverOfUnderlying, uint256 yTokenAmount, uint256 underlyingTokenAmount)
    external
    onlyLendingPool
    nonReentrant
{
    _burn(msg.sender, yTokenAmount);
    IERC20(underlyingAsset).safeTransfer(receiverOfUnderlying, underlyingTokenAmount);
}

// Transfers underlying tokens to a target address
function transferUnderlyingTo(address target, uint256 amount)
    external
    onlyLendingPool
    nonReentrant
    returns (uint256)
{
    IERC20(underlyingAsset).safeTransfer(target, amount);
    return amount;
}
```


Rounding errors can occur in several places:

1. In the LendingPool's `_deposit` function when calculating yToken amounts:
```solidity
yTokenAmount = amount * exchangeRate / (PRECISION);
```


2. In the LendingPool's `_redeem` function when calculating underlying token amounts:
```solidity
underlyingTokenAmount = reserve.yTokenToReserveExchangeRate() * yAssetAmount / PRECISION;
```


These division operations can result in dust amounts that remain in the yToken contract. Over time, as the protocol processes many transactions, these dust amounts can accumulate to significant value.

## Impact Details
This issue results in a gradual but permanent loss of value as tokens accumulate in the yToken contract with no way to recover them. The impact increases with protocol usage and transaction volume, potentially leading to significant locked value over time. This represents an inefficiency in the protocol and a direct value loss for users, as these locked tokens could otherwise contribute to the lending pool's liquidity or be distributed to users.

Manual

## Recommendations
Add a recovery function to the yToken contract that allows authorized parties (e.g., governance) to sweep residual tokens:

```solidity
/**
 * @notice Recovers stuck tokens and sends them to the recipient
 * @param recipient The address to receive the recovered tokens
 * @dev Can only be called by governance or authorized admin
 */
function recoverResidualAssets(address recipient) external onlyGovernance {
    uint256 balance = IERC20(underlyingAsset).balanceOf(address(this));
    
    // Calculate expected balance based on total supply and exchange rate
    uint256 expectedBalance = ILendingPool(lendingPool).totalLiquidityOfReserve(underlyingAsset);
    
    // If there's excess balance, transfer it
    if (balance > expectedBalance) {
        uint256 excessAmount = balance - expectedBalance;
        IERC20(underlyingAsset).safeTransfer(recipient, excessAmount);
        emit ResidualAssetsRecovered(recipient, excessAmount);
    }
}
```
