# changePositionWidth needs to accept wider inputs

### Summary

It should be noted that **_newWidth is only 2 * tickSpacing wide**, which would cause **unexpected reverts** when calling `Strategy::rebalance`.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L395-L399

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L373-L379

This implies that the mainPosition is **only 2 * tickSpacing wide**, and since the `secondaryPosition` must be included within `mainPosition` due to the following code:

```solidity
        if (bal0in1 < bal1) {
            secondaryPosition.tickLower = mainPosition.tickLower;
            secondaryPosition.tickUpper = tick - modulo;
        } else {
            secondaryPosition.tickLower = tick - modulo + tickSpacing;
            secondaryPosition.tickUpper = mainPosition.tickUpper;
        }
```

This is problematic because, as the pool's tick falls within the `mainPosition`, it’s impossible to split into two possible `secondaryPosition` (one-side liquidity) depending on `bal0in1 < bal1`. This is due to the fact that a position cannot be created where `lowerTick == upperTick` because of the following UniswapV3 error:

> TLU: The lower tick must be below the upper tick

https://docs.uniswap.org/contracts/v3/reference/error-codes#:~:text=TLU%3A%20The%20lower%20tick%20must%20be%20below%20the%20upper%20tick
