# Adding liquidity to secondary position might revert in some cases

### Summary

When calculating rebalancing first the main position ticks are set and then the secondary position ticks work with the main position ticks.


```solidity
    function rebalance() public onlyRebalancer {
        require(block.timestamp - lastRebalance >= rebalanceInterval, "too soon since last rebalance");

        _requirePriceWithinRange(); // we verify that the pool's price is currently not manipulated
        collectFees();

        _removeLiquidity();
        (uint256 amount0, uint256 amount1) = idleBalances();

        (uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();

        _setMainTicks(tick);
        (amount0, amount1) = _addLiquidityToMainPosition(sqrtPriceX96, amount0, amount1);

        _setSecondaryPositionsTicks(tick);
        _addLiquidityToSecondaryPosition(sqrtPriceX96, amount0, amount1);
        lastRebalance = block.timestamp;
    }

    function _setMainTicks(int24 tick) internal {
        int24 halfWidth = int24(positionWidth / 2);
        int24 modulo = tick % tickSpacing;
        if (modulo < 0) modulo += tickSpacing; // if tick is negative, modulo is also negative
        bool isLowerSided = modulo < (tickSpacing / 2);

        int24 tickBorder = tick - modulo;
        if (!isLowerSided) tickBorder += tickSpacing;
        mainPosition.tickLower = tickBorder - halfWidth;
        mainPosition.tickUpper = tickBorder + halfWidth;

        emit NewMainTicks(tickBorder - halfWidth, tickBorder + halfWidth);
    }

    function _setSecondaryPositionsTicks(int24 tick) internal {
        int24 modulo = tick % tickSpacing;

        uint256 bal0 = IERC20(token0).balanceOf(address(this));
        uint256 bal1 = IERC20(token1).balanceOf(address(this));

        uint256 _price = price();

        uint256 bal0in1 = bal0 * _price / PRECISION; // usually either of them should be 0, but might be non-zero due to rounding when minting

        if (bal0in1 < bal1) {
            //create a position on the left side of the ticks
            secondaryPosition.tickLower = mainPosition.tickLower;

            secondaryPosition.tickUpper = tick - modulo;
        } else {
            secondaryPosition.tickLower = tick - modulo + tickSpacing; // The next tick
            secondaryPosition.tickUpper = mainPosition.tickUpper; // Tick upper
        }

        emit NewSecondaryTicks(secondaryPosition.tickLower, secondaryPosition.tickUpper);
    }
```

If  `bal0in1 > bal1` the ticks are calculated like:

`lower = tick - modulo + tickSpacing`
`upper = mainPosition.tickUpper`

In the situation where `halfWidth == tickSpacing`, the lower and upper tick of the secondary position will be the same, which will revert in [checkTicks](https://github.com/Uniswap/v3-core/blob/d8b1c635c275d2a9450bd6a78f3fa2484fef73eb/contracts/UniswapV3Pool.sol#L315) when modifying the position.

### Root Cause

Secondary position `tickUpper` and `tickLower` will be the same causing `UniswapV3Pool::mint` to revert with:

```solidity
    function checkTicks(int24 tickLower, int24 tickUpper) private pure {
        require(tickLower < tickUpper, 'TLU');
        ...
    }
```

### Internal Pre-conditions

1. `halfWidth == tickSpacing`

### External Pre-conditions

1. `modulo == 0`

### Attack Path

None

### Impact

The rebalancer will not be able to rebalance the pools in this conditions.

### PoC

  -  `tickSpacing = 4`
  -  `tick = 56`
  -  `halfWidth = 4`
  -  `modulo = 0`
  -  `isLowerSide = 0 < 2 = true`
  -  `tickBorder = 56`
   - `mainPosition.lowerTick = 52`
   - `mainPosition.upperTick = 60`
  
When setting the ticks for the secondary position:

`bal0in1 > bal1` so we add liquidity on the right side

- `secondaryPosition.tickLower = 56 - 0 + 4 = 60`
- `secondaryPosition.tickUpper = mainPosition.tickUpper = 60`

Now `tickLower == tickUpper`, which causes `UniswapV3Pool::checkTicks` to revert disallowing the position to be rebalanced.


### Mitigation

In cases of equality consider incrementing `secondaryPosition::tickUpper` by `tickSpacing`.


```diff
            secondaryPosition.tickLower = tick - modulo + tickSpacing; // The next tick
            secondaryPosition.tickUpper = mainPosition.tickUpper; // Tick upper

+          if(secondaryPosition.tickLower ==  secondaryPosition.tickUpper) secondaryPosition.tickUpper += tickSpacing
```
