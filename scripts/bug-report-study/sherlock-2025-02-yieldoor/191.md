# Unfair Liquidation

### Summary
Relying solely on the initial collateral and estimated collateral in the liquidation logic leads to unfair liquidations.

### Root Cause
The calculation of the liquidation threshold is incorrect, resulting in unfair liquidations.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L409
```solidity
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        Position memory pos = positions[_id];
        VaultParams memory vp = vaultParams[pos.vault];

        uint256 vaultSupply = IVault(pos.vault).totalSupply();

        // Assuming a price of X, a LP position has its lowest value when the pool price is exactly X.
        // Any price movement, would actually overvalue the position.
        // For this reason, attackers cannot force a position to become liquidateable with a swap.
        (uint256 vaultBal0, uint256 vaultBal1) = IVault(pos.vault).balances();
        uint256 userBal0 = pos.shares * vaultBal0 / vaultSupply;
        uint256 userBal1 = pos.shares * vaultBal1 / vaultSupply;
        uint256 price = IVault(pos.vault).twapPrice();

        uint256 totalValueUSD = _calculateTokenValues(pos.token0, pos.token1, userBal0, userBal1, price);
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(pos.denomination);
        uint256 totalDenom = totalValueUSD * (10 ** ERC20(pos.denomination).decimals()) / bPrice;

        uint256 bIndex = ILendingPool(lendingPool).getCurrentBorrowingIndex(pos.denomination);
        uint256 owedAmount = pos.borrowedAmount * bIndex / pos.borrowedIndex;

        /// here we make a calculation what would be the necessary collateral
        /// if we had the same borrowed amount, but at max leverage. Check docs for better explanation why.
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
409:    base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
        else return false;
    }
```

### PoC
Let's consider the following senario.
`token0 := wbtc`, `token1 := weth`, `denomination := usdc`, `maxTimesLeverage := 2`, `minCollateralPct := 10%`, 
`wbtcPrice := 40,000 usd`, `wethPrice := 1000 usd`, `usdcPrice := 1 usd`.
Alice's Position: 
    collateral: 0.1 wbtc, 4 weth, borrowed: 4000 usdc
    `Alice's collateralUsd = 0.1 * 40,000 + 4 * 1000 = 8000 usd`
    `Alice's borrowed = 4000 usd`
    `Alice's initCollateralValue = 8000 usd`
    `totalDenom = 8000 usd`, `owedAmount = 4000 usd`, `base = min(4000, 8000) = 4000 usd`.
    Liquidation Risk: `totalDenom - owedAmount < 4000 * 10% = 400 usd`.
1. In the Vault, a profit of 25% is earned from Uniswap fees, and the prices of both wbtc and weth have increased by 60%.
    `wbtcPrice = 56,000 usd`, `wethPrice = 1600 usd`,
    `Alice's collateralUsd = 8000 * 1.25 * 1.6 = 16,000 usd`.
2. In the LendingPool, the borrow index has increased by two times.
    `Alice's borrowed = 4000 * 2 = 8000 usd`
    `Alice's initCollateralValue = 8000 usd`
3. Alice withdraw 50%.
    `Alice's collateralUsd = 8000 usd`
    `Alice's borrowed = 4000 usd`
    `Alice's initCollateralValue = 4000 usd`
    `totalDenom = 8000 usd`, `owedAmount = 4000 usd`, `base = min(4000, 4000) = 4000 usd`.
    Liquidation possibility: `totalDenom - owedAmount < 4000 * 10% = 400 usd`.

Step 1, 2, 3 are repeated.
    `Alice's collateralUsd = 8000 usd`
    `Alice's borrowed = 4000 usd`
    `Alice's initCollateralValue = 2000 usd`
    `totalDenom = 8000 usd`, `owedAmount = 4000 usd`, `base = min(4000, 2000) = 2000 usd`.
    Liquidation possibility: `totalDenom - owedAmount < 2000 * 10% = 200 usd`.

As collateral prices increase, Alice's liquidation risk decreases. 
Ultimately, she will only be liquidated if her position becomes underwater. 
This invalidates the liquidation percentage value.

Let's consider the scenario for another user.
Now `wbtcPrice = 89,600`, `wethPrice = 2560`.
Bob opens a leveraged position with: 0.0390625 wbtc, 1.5625 weth and borrowed 4000 usdc
    `Bob's collateral = 0.0390625 * 89,600 + 1.5625 * 2560 = 8000 usd`
    `Bob's borrowed = 4000 usd`
    `Bob's initCollateralValue = 8000 usd`
    `totalDenom = 8000 usd`, `owedAmount = 4000 usd`, `base = min(4000, 8000) = 4000 usd`.
    Liquidation possibility: `totalDenom - owedAmount < 4000 * 10% = 400 usd`.

Alice and Bob, who have the same amount of collateral and owed, have different liquidation thresholds. 
When the collateral prices fall, it is possible for Bob to be liquidated while Alice is not. 
This results in Alice's profit and Bob's loss.

There is also a problem with the calculation of `base`.
The formula is: `base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);`
As `maxTimesLeverage` is increases the `base` is decreased.
In other words, as the user can borrow more initially, the liquidation threshold decreases.

Another Senario:
`token0 := wbtc`, `token1 := weth`, `denomination := usdc`, `maxTimesLeverage := 5`, `minCollateralPct := 10%`, 
`wbtcPrice := 40,000 usd`, `wethPrice := 1000 usd`, `usdcPrice := 1 usd`.
Alice's Position: 
    collateral: 0.1 wbtc, 4 weth, borrowed: 4000 usdc
    `Alice's collateral = 0.1 * 40,000 + 4 * 1000 = 8000 usd`
    `Alice's borrowed = 4000 usd`
    `Alice's initCollateralValue = 8000 usd`
    `totalDenom = 8000 usd`, `owedAmount = 4000 usd`, `base = min(4000 / 4, 8000) = 1000 usd`.
    Liquidation Risk: `totalDenom - owedAmount < 1000 * 10% = 100 usd`.
Alice's liquidation threshold is 100 usd, which is 1.25% of totalDenom and 2.5% of owedAmount.
However, if `maxTimesLeverage := 2`:
    `base = min(4000 / 1, 8000) = 4000 usd`,
    Liquidation Risk: `totalDenom - owedAmount < 4000 * 10% = 400 usd`.

### Impact
The liquidation function is unfair and can lead to gains or losses for users.

### Mitigation
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L409
```diff
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
409:    base = base < pos.initCollateralValue ? base : pos.initCollateralValue;
+       base = base > totalDenom ? base : totalDenom;

```
This mitigation is not perfect, but the `base` should be greater than `totalDenom` or `owedAmount`.
