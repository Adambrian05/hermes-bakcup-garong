# `Leverager::changeVaultMaxLeverage()` may instantly liquidate some positions

### Summary

[Leverager::changeVaultMaxLeverage()](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L526) will update the max leverage parameter `vp.maxTimesLeverage`. It directly [affects](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L408) the health of user positions, and a change may instantly make users liquidatable.

### Root Cause

In `Leverager:408`, the liquidation depends on `vp.maxTimesLeverage` which may be changed at any time.

### Internal Pre-conditions

1. Admin calls `Leverager::changeVaultMaxLeverage()` and some positions become instantly liquidated.

### External Pre-conditions

None

### Attack Path

1. Admin calls `Leverager::changeVaultMaxLeverage()`.
2. Positions become underwater.

### Impact

Users that are liquidated take instant losses.

### PoC

None.

### Mitigation

Save the max leverage at the time of the position opening and use this to calculate the liquidation health.
