# Wrong vesting position upper tick passed to `collectFees` will block vesting position funds and claiming fees

### Summary

Wrong vesting position upper tick value passed when collecting fees would revert and dos the hole function because univ3 pool will not recognize the position.

### Root Cause

In `Strategy::collectFees` the main position's upper tick is passed to `collectFees` for vesting position instead of vesting position upper tick.

### Internal Pre-conditions

none

### External Pre-conditions

Pool tick moves boundaries. Happens when one token is sold more than the other, ratio changes, hence price and tick moves.

### Attack Path

1. Some funds locked in main and secondary position
2. Admin creates vesting position
Note: The vesting position ticks are set as the main position's ticks
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L433-L434
```javascript
function addVestingPosition(uint256 amount0, uint256 amount1, uint256 _vestDuration) external onlyVault {
...
        vp.tickLower = mainPosition.tickLower;
        vp.tickUpper = mainPosition.tickUpper;
...
```
3. `rebalance()` is called. The main position ticks are updated with different values before the vesting position period is over. The tick values are based on the current tick of the position as it uses `tick` from slot0 to set the main position ticks. The tick can easily have moved to the next or previous value because of the altered token balances made by executing swaps.
```javascript
(uint160 sqrtPriceX96, int24 tick,,,,,) = IUniswapV3Pool(pool).slot0();
_setMainTicks(tick);
```
Note that the main position ticks are updated, but the vesting position ticks stay the same.
4. `collectFees` is called. Fees for main and secondary positions are successfully collected and then on the vesting position the transaction reverts.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L167
```javascript
        if (mainPosition.liquidity != 0) {
            collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        }

        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }

        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
        }
```

### Impact

The vesting position funds will be lost because the upper tick is wrong and calling `UniswapV3Pool ::burn()` would revert. 
Also the `collectFees` function would be dos'ed because uniV3's pool would not be able to find a position with the passed ticks and revert with:
```log
    │   ├─ [16811] 0x99ac8cA7087fA4A2A1FB6357269965A2014ABc35::burn(67440 [6.744e4], 67690 [6.769e4], 0)
    │   │   └─ ← [Revert] revert: NP
```
The reason for the **complete** dos is because the `collectFees` function collects the fees for all 3 positions - main, secondary and vesting 

### PoC

The scenario can be simulated by just adding  a small value to `mainPosition.tickUpper` when it is passed to `collectPositionFees` for the vesting position. This simulates that `token1` of the pool is bought more and the tick  value went up.
```diff
    function collectFees() public { // ok
        (uint256 preBal0, uint256 preBal1) = idleBalances();

        if (mainPosition.liquidity != 0) {
            collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        }

        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }

        if (ongoingVestingPosition) {
            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper + 10); // <=
        }
```
The run the following test 
```bash
forge test --fork-url {Your Fork URL} --mt test_addVestingPosition -vvv
```

The result is that when burn is called on the vesting position it reverts iwth the following uni v3 pool error 
```log
    │   ├─ [18811] 0x99ac8cA7087fA4A2A1FB6357269965A2014ABc35::burn(67260 [6.726e4], 67510 [6.751e4], 0)
    │   │   └─ ← [Revert] revert: NP
    │   └─ ← [Revert] revert: NP
```

This error occurs when `burn` calls `_modifyPosition()`, it calls `_updatePosition()` and it calls `update()` on the position, But since it doesn't exist because the upper tick is wrong it reverts.

### Mitigation

Use `vestPosition.tickUpper` instead of `mainPosition.tickUpper` as upper tick when collecting fees for the vesting position
```diff
    function collectFees() public {
        (uint256 preBal0, uint256 preBal1) = idleBalances();

        if (mainPosition.liquidity != 0) {
            collectPositionFees(mainPosition.tickLower, mainPosition.tickUpper);
        }

        if (secondaryPosition.liquidity != 0) {
            collectPositionFees(secondaryPosition.tickLower, secondaryPosition.tickUpper);
        }

        if (ongoingVestingPosition) {
-            collectPositionFees(vestPosition.tickLower, mainPosition.tickUpper);
+            collectPositionFees(vestPosition.tickLower, vestPosition.tickUpper);
        }
...
```
