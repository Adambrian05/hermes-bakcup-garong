# Incorrect Token Repayment in Leverager Withdraw



## Summary 

A critical logic error exist in the withdraw function of the Leverager contract when repaying borrowed tokens. specifically, when the borrowed asset is token1 as the code incorrectly references the amountOut0 variable instead of amountOut1 leading to improper repayment calculations. This results in either under-repayment (leaving debt unpaid) or over-repayment (overpaying debt). 

## Description 
The withdraw function in Leverager.sol is designed to close a leveraged position. During this process, the contract must repay the borrowed funds which are denominated in either token0 or token1. When handling repayments for token1, the code use the amountOut0 which is the withdrawn amount of token0 instead of amountOut1 to be the withdrawn amount of token1. This mistake cause the protocol to miscalculate how much of the borrowed debt is repaid leading to incorrect accounting.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L227-L230

## Vulnerability Details 


**Code Snippet**
The problem is in the `withdraw` function of the `Leverager` contract. when repaying debt denominated in `token1`, the code incorrectly reference`amountOut0` instead of `token1` withdrawn balance (`amountOut1`).  
 
```solidity
if (borrowed == up.token1) {
    // @audit: Incorrectly uses amountOut0 instead of amountOut1
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
    owedAmount -= repayFromdraw;
    amountOut1 -= repayFromWithdraw;
}
```


## **Proof of Concept**
The values are:  

**Borrowed Asset**: `token1` (USDC)
**Withdrawn Amounts**:  
  `amountOut0` (token0): 100 wei (WETH)
  `amountOut1` (token1): 200 wei (USDC).  
**Owed Debt**: `owedAmount = 300 wei` (USDC).  

## **Execution Flow**:  
1. **Reviewing the repayment shows**:  
   ```solidity
   repayFromWithdraw = (200 < 300) ? 100 : 300; //@audit: it evaluate to 100 (amountOut0) 
   ```  
   - Because `amountOut1 (200) < owedAmount (300)`, the code incorrectly used the `amountOut0 (100)` instead of `amountOut1 (200)`.  

2. **Then updating the  Debt and Balances**:  
   ```solidity
   owedAmount = 300 - 100 = 200; //The debt reduced by 100 instead of 200 
   amountOut1 = 200 - 100 = 100; // Token1 balance incorrectly reduced by 100   
   ```  

 So the outcome is :
**Debt Underpayment**: Only 100 wei of `token0` (WETH) is applied to repay `token1` (USDC) debt, leaving **200 wei unpaid**.  
**Balance Corruption**: `amountOut1` (USDC) is reduced by 100 wei (now 100 wei), but the user’s actual USDC withdrawal is 200 wei.  


## **Impact**  
Unpaid debt will accumulate destabilizing the lending pool and users overpay with unrelated tokens for example WETH to repay USDC debt.  
-Debt tracking and token balances become inconsistent violating invariant

The fix should be :
```solidity
if (borrowed == up.token1) {
    //  Correctly uses amountOut1 for token1 repayment
```

1. **Correct Calculation should be **:
