# Deposit fees are incorrectly distributed to existing depositors instead of being collected


## Summary
In `Vault.sol`, deposit fees are deducted from the user's shares but are not minted to any address. This results in the fees being implicitly distributed to previous depositors instead of being collected by the protocol.

## Root Cause
The [`deposit()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L48-L72) function in `Vault.sol` incorrectly handles deposit fees:

```solidity
    function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
        external
        returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
    {
        IStrategy(strategy).collectFees();

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

->      if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

        require(shares > 0, "shares cant be 0");
        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);
        // TODO - emit event
    }
```

As shown in the code above, the deposit fee is subtracted from the user's shares, but these deducted shares are not minted to any address. This means the value of these shares is implicitly distributed to all previous depositors through share dilution.

## Internal Pre-conditions
- At least one user has already deposited funds into the vault

## External Pre-conditions
None

## Attack Path
1. Initial user deposits funds into vault
2. Second user deposits funds into vault
3. Deposit fee is deducted from second user's shares
4. Deducted shares are not minted to protocol/owner
5. First depositor gains value from diluted shares
6. Process repeats for each new deposit

## Impact
- Protocol loses revenue from deposit fees
- Fees are incorrectly distributed to existing depositors
- Misalignment with protocol's intended fee collection mechanism

## Mitigation
Modify the `deposit()` function in `Vault.sol` to properly mint fee shares to the owner:

```solidity
    function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
        external
        returns (uint256 shares, uint256 depositAmount0, uint256 depositAmount1)
    {
        IStrategy(strategy).collectFees();

        (uint256 totalBalance0, uint256 totalBalance1) = IStrategy(strategy).balances();

        (shares, depositAmount0, depositAmount1) = _calcDeposit(totalBalance0, totalBalance1, amount0, amount1);

        IERC20(token0).safeTransferFrom(msg.sender, strategy, depositAmount0);
        IERC20(token1).safeTransferFrom(msg.sender, strategy, depositAmount1); // after deposit, funds remain idle, until compound is called

-       if (depositFee > 0) shares -= (shares * depositFee) / 10_000;
+       if (depositFee > 0) {
+           uint256 fee = shares * depositFee / 10_000;
+           _mint(owner(), fee);
+           shares -= fee;
+       }

        require(shares > 0, "shares cant be 0");
        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);
        // TODO - emit event
    }
```
