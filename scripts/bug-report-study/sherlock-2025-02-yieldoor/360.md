# The attacker can exploit lack of slippage control on user-provided swapParams that leads to over-spending on swaps, causing immediate undercollateralization


### Summary
Lack of slippage control on user-provided  `swapParams.amountInMaximum`  in Leverager.sol. The attacker can exploit this by setting max input to an extremely high value. This leads to over-spending on swaps, causing immediate undercollateralization.

### Root Cause
In Leverager.sol `swapParams.amountInMaximum`, the exactOutput() swap uses unvalidated swapParams.amountInMaximum:
```solidity
         if (a1 > lp.amount1In && up.token1 != lp.denomination) {
                swapParams = abi.decode(lp.swapParams2, (IMainnetRouter.ExactOutputParams));
                address tokenIn = _getTokenIn(swapParams.path);
                require(tokenIn == lp.denomination, "token should be denomination 2 ");
@>                IERC20(tokenIn).forceApprove(swapRouter, swapParams.amountInMaximum); //No cap

                swapParams.amountOut = a1 - lp.amount1In;
                IMainnetRouter(swapRouter).exactOutput(swapParams);
                IERC20(tokenIn).forceApprove(swapRouter, 0);
            }
```
The protocol fails to validate swapParams.amountInMaximum against a reasonable slippage threshold, allowing attackers to set it to type(uint256).max.

- https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L156-L165

### Internal Pre-conditions

1. Leverager contract must allow user-provided swapParams for swaps
2. swapParams.amountInMaximum is set to type(uint256).max by the attacker
3. Admin has not enforced global slippage limits

### External Pre-conditions

### Attack Path

1. Attacker sets amountInMaximum = type(uint256).max.
2. Swap uses 90% of collateral due to high slippage.
3. Position becomes underwater immediately.

### Impact

- Position instant underwater due to 90%+ slippage
- Collateral loss from malicious swap parameters.

_No response_

### Mitigation

Enforce max slippage: 
```solidity
// Enforce max slippage
require(
    swapParams.amountInMaximum <= theoreticalMax * 110 / 100,
    "Slippage too high"
);
```
