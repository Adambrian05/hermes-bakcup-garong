# Incorrect base calculation in Leverager#isLiquidateable() prevents normal liquidations

### Summary

The Leverager#isLiquidateable() determines whether a user's position should be liquidated. However, the current formula incorrectly calculates the required collateral threshold (`base`), leading to positions that should be liquidated remaining open.
This results in users maintaining undercollateralized positions, causing the protocol to lose funds when borrowers default.

### Root Cause

Let's look at document explaination.
`However, in scenarios where the users are not using max leverage, this could cause 
unfair liquidations. Assume minPctCollateral is 10%. Consider the following scenario: 
max Leverage is 2x, user has opened a 1.25x and has since then lost 90% of their 
collateral, meaning that 0.1X collateral has remained and 0.25X still borrowed. We 
treat the borrowed amount as if it was opened at max leverage, which would make 
the initial collateral `0.25 * (2 - 1) = 0.25X`. Since minimum collateral pct is 10%, this 
would mean that the position will become liquidateable once collateral drops below 
`0.25 * 0.1 = 0.025X`  `
Here, liquidatable condition is:
collateral < borrowedAmount * (max leverage - 1) * minmum collateral pct
But, actually this implies incorrect.
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L406-L411
that is:
collateral < borrowedAmount / (max leverage - 1) * minmum collateral pct
base calculation is incorrect.
`uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);`

### Internal Pre-conditions

A user has an open leveraged position and after a while his collateral has significantly decreased due to market fluctuations.

### External Pre-conditions

 The protocol allows high leverage (maxTimesLeverage > 2x).
The borrowed amount (owedAmount) remains unpaid, and collateral value decreases.

### Attack Path

In case of document in root cause and its numerical example:
`To put it into a numerical example, user opens up a $1,250 position with 
$1,000 of collateral (1.25x leverage). User’s position would have to fall below 
$275 value ($250 borrowed, $25 collateral) in order to become liquidateable.`
Assume max leverage = 1.5x.
250 / (1.5 - 1) * 0.1 = 50 => $50 collateral
Thus liquidatable condition is that user's position falls below $300 value ($250 borrowed, $50 collateral).
As a result, the fewer max leverage decreases, the more collateral is needed.
the more max leverage increases, the fewer collateral is needed.

### Impact

Protocol accumulates bad debt, as undercollateralized positions are not liquidated.
Users can abuse high leverage, extracting value without proper liquidation enforcement.
Due to liquidation needs fewer collateral, protocol will lose funds.
Also maintain fewer leverage, user should need more collateral, thus user's funds will be locked to prevent liquidate.

_No response_

### Mitigation

Modify isLiquidateable() to correctly compute `base` according to document:
```diff
- uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
+ uint256 base = owedAmount * (vp.maxTimesLeverage - 1e18) / 1e18;
```
