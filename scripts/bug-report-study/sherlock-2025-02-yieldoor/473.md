# Incorrect Leverage Calculation Due to Double Counting Borrowed Amount Prevents Users from Opening Valid Positions

## Summary
The `_checkWithinlimits` function [incorrectly calculates position leverage](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Leverager.sol#L464) by adding the borrowed amount to a value that already includes it, resulting in artificially inflated leverage ratios. This causes the function to reject valid positions that should be within the protocol's leverage limits.

## Vulnerability Details
When a leveraged position is created in `openLeveragedPosition`, the `initCollateralValue` is calculated based on the total tokens deposited into the vault, which includes both user-provided tokens and borrowed tokens.

For example, if a user:
1. Provides 1 ETH as collateral
2. Borrows 1 ETH
3. Total position value (initCollateralValue) = 2 ETH

The actual leverage is 2x (2 ETH total / 1 ETH user equity).

However, in `_checkWithinlimits`, the calculation:
```solidity
uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```

Would result in:
```js
positionLeverage = (2 ETH + 1 ETH) * 1e18 / 2 ETH = 1.5e18
```

This incorrectly suggests 3x leverage when the actual leverage is 2x.

## Proof of Concept
```solidity
function _checkWithinlimits(Position memory up) internal {
    // ... other checks ...
    
    // Current incorrect calculation
    uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
    
    // This will revert with "too high x leverage" for positions that should be valid
    require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
    
    // ... remaining checks ...
}
```

## Impact Details
The incorrect leverage calculation prevents users from opening valid positions that should be within the protocol's leverage limits. This directly impacts protocol usage and revenue generation as users are unable to create positions they should be allowed to create. Additionally, this creates a poor user experience as transactions unexpectedly revert.

## Recommendations
Modify the leverage calculation to correctly compute the ratio between total position value and user equity:

```solidity
// Correct calculation
uint256 positionLeverage = (up.initCollateralValue) * 1e18 / (up.initCollateralValue - up.borrowedAmount);
```

This ensures the leverage is calculated as:
```js
leverage = total position value / user equity
        = total value / (total value - borrowed amount)
```
