# Interest rate changes don't apply immediately due to missing state updates in setBorrowingRateConfig

## Description:
`LendingPool` contract allows the owner to modify the interest rate configuration, but these changes don't immediately affect the current borrowing rate due to missing state update calls. This creates an unpredictable delay in applying new rates.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L348
```solidity
// LendingPool.sol
function setBorrowingRateConfig(
    address asset,
    uint16 utilizationA,
    uint16 borrowingRateA,
    uint16 utilizationB,
    uint16 borrowingRateB,
    uint16 maxBorrowingRate
) public onlyOwner {
    DataTypes.ReserveData storage reserve = reserves[asset];
    setBorrowingRateConfig(reserve, utilizationA, borrowingRateA, utilizationB, borrowingRateB, maxBorrowingRate);
    // Missing calls to updateState(reserve) and updateInterestRates(reserve)
}
```

The internal function only updates configuration parameters but doesn't update the current borrowing rate:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L241
```solidity
// LendingPool.sol
function setBorrowingRateConfig(
    DataTypes.ReserveData storage reserve,
    uint16 utilizationA,
    uint16 borrowingRateA,
    uint16 utilizationB,
    uint16 borrowingRateB,
    uint16 maxBorrowingRate
) internal {
    reserve.borrowingRateConfig.utilizationA = utilizationA;
    reserve.borrowingRateConfig.borrowingRateA = borrowingRateA;
    reserve.borrowingRateConfig.utilizationB = utilizationB;
    reserve.borrowingRateConfig.borrowingRateB = borrowingRateB;
    reserve.borrowingRateConfig.maxBorrowingRate = maxBorrowingRate;
}
```

The current borrowing rate is only updated when other operations occur:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/libraries/ReserveLogic.sol#L140
```solidity
// ReserveLogic.sol
function updateInterestRates(DataTypes.ReserveData storage reserve) internal {
    reserve.currentBorrowingRate =
        InterestRateUtils.calculateBorrowingRate(reserve.borrowingRateConfig, utilizationRate(reserve));
}
```

New interest rate configurations don't apply until the next reserve operation
Unpredictable delay in applying new rates
Borrowers continue paying old rates until next reserve update
Unpredictable timing of rate changes
Borrowers face sudden rate changes at unpredictable times

## Impact:
Protocol don't have control of when the new `borrowingRateConfig` will be actually activated
Protocol may lose revenue when increasing rates

## Recommended Mitigation:
Update state and rates immediately when changing configuration
