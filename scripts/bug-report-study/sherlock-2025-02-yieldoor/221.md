# The calculation of the `initCollateralValue` is incorrect when the vault has a `depositFee`

### Summary

The function `openLeveragedPosition` in the contract `Leverager` calculates the value of `initCollateralUsd` with the a0 and a1 which are the deposit amounts of token0 and token1 when depositing to the vault.

[Leverager](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L126C1-L132C1)
```solidity
        (uint256 shares, uint256 a0, uint256 a1) =
            IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);

        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); // returns the USD price in 1e18
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);
        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;
```

However, when the vault has a `depositFee`>0, the shares that minted to the depositor will be less than the actual share converted from the deposit amounts of token0 and token1. Thus, the value of `initCollateralUsd` calculated with a0 and a1 is relatively larger than the actual value of `up.shares`. This leads to the value of `initCollateralValue` is also relatively larger than the actual value. 

Since the value of `initCollateralValue` will be used to calculated the `positionLeverage`. And it cause the value of `positionLeverage` to be relatively smaller than the actual value. And in that way, users could open a leveraged position exceeds the limit of `maxTimesLeverage` or `maxLevTimes`.

Also, the value of `initCollateralValue` will be used in the function `isLiquidateable` to determine the value of `base`. The value of `vp.minCollateralPct * base / 1e18` could be relatively larger than the actual value. This will finally cause the leveraged position which should be liquidiated but not liquidateable.

[Vault](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L61-L70)
```solidity
        if (depositFee > 0) shares -= (shares * depositFee) / 10_000;

        require(shares > 0, "shares cant be 0");
        require(depositAmount0 >= amount0Min, "slippage0");
        require(depositAmount1 >= amount1Min, "slippage1");

        if (totalSupply() == 0) _mint(BURN, 1000);
        _mint(msg.sender, shares);

        return (shares, depositAmount0, depositAmount1);
```


### Root Cause

The function `openLeveragedPosition` didn't consider the circumstance when the vault has a `depositFee`>0, the shares that minted to the depositor will be less than the actual share converted from the deposit amounts of token0 and token1.
