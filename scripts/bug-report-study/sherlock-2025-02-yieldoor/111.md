# Unvalidated TWAP Interval in Strategy



## Summary
The Strategy contract allows setting an insufficiently short TWAP (Time-Weighted Average Price) interval which enabling attacker to manipulate the price oracle and trick the protocol into making incorrect liquidity management decision.

## **Vulnerability Details**
The Strategy contract allows the owner to set a **TWAP (Time-Weighted Average Price)** interval as low as **31 seconds**, making the price oracle vulnerable to manipulation via flash loan or short-term price spikes. Attackers can exploit this to force the Strategy into rebalancing liquidity positions based on inaccurate prices, leading to financial losses.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L547-L550

**1. TWAP Configuration**
```solidity
twap = 300; // 5 minutes which is the initial value


function setTwap(uint32 _twap) external onlyOwner {
    require(_twap > 30, "twap has to be at least 30 seconds"); // Allows intervals ≥31 seconds
    twap = _twap;
}
```
-The `setTwap` function enforce a minimum interval of **31 seconds**. Short intervals are insufficient to average out price volatility which enable manipulation.

**2.TWAP Usage in Price Validation**
```solidity
function _priceWithinRange() internal view returns (bool) {
    int24 _twapTick = twapTick(); // @audit: use the vulnerable TWAP interval
    (, int24 currentTick,,,,,) = IUniswapV3Pool(pool).slot0();
    //@audit: Checking if currentTick is within acceptable deviation from _twapTick
}
```
The `twapTick()` function calculate the average tick over the configured TWAP interval. A short interval increase to manipulation.

**3. The TWAP Calculation Logic state**
```solidity
function twapTick() public view returns (int24) {
    uint32[] memory secondsAgos = new uint32[](2);
    secondsAgos[0] = twap; //@audit: Use the vulnerable interval
    (int56[] memory tickCumulatives,) = IUniswapV3Pool(pool).observe(secondsAgos);
    int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0];
    int24 tick = int24(tickCumulativesDelta / int32(twap));
    return tick;
}
```
 A short `twap` interval will then reduce the number of historical observation average making the TWAP easier to manipulate.



## **Proof of Concept**
1. **Set-up**: 
   -TWAP interval is set to **30 seconds** as `setTwap(30)`
   - Then the pool has low liquidity as new or niche token pair.

2. **Attack**:
   **Step 1**: Attacker take a flash loan to swap a large amount of `token0` for `token1` spiking the spot price from **$100  to $150**.
    **Step 2**: The attacker wait **30 seconds** for the TWAP to update. Due to the short interval, the TWAP reflect the manipulated price.
    **Step 3**: The Strategy `_priceWithinRange` check the TWAP against the current price since both are manipulated, it falsely validates the price as "accurate."
    **Step 4**: The Strategy then rebalance liquidity into the pool at the inflated price  adding more `token1` liquidity as it assume the high price to be sustainable.

3. **Exploit**:
   -Then the  attacker repay the flash loan causing the price to crash back to **$100**.
   -The Strategy liquidity position are now **undercollateralized** as the actual price diverge from the TWAP-based rebalancing.



## Impact
it results to **Direct Losses**: Users funds are deposited into positions at manipulated prices leading to losses when prices correct.
 **Protocol Instability**: Frequent rebalancing based on inaccurate TWAP values destabilize the vault’s liquidity..



## Recommendation
Minimize the **TWAP interval to 10 minutes** in order to reduce the short-term price manipulation.
```solidity
function setTwap(uint32 _twap) external onlyOwner {
    require(_twap >= 600, "TWAP interval must be ≥10 minutes"); // 10-minute minimum
    twap = _twap;
}
```


- **10-minute intervals** are long enough to average out most short-term price spikes which are  caused by flash loans.
