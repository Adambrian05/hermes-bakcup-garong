# Attacker can control the minimum amount next depositors will deposit (EDoS attack)

### Summary

The way `shares` is calculated gives an attacker control over how many tokens a next user can deposit, since the vault doesn't distinguish between tokens that entered the strategy via deposit and via external transfers, which may make it impractical for some users causing a EDoS ( Economic DoS ).

### Root Cause

In [`Vault.sol:149`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L149) , the way `shares` is calculated is by diving by `bal1` and `bal0` , and both bal0 and bal1 are attacker controlled and can be inflated using external deposits.

The same issue is present in [`Vault.sol:139`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L139) and `Vault.sol:135`.

### Attack Path

1. Attacker externally transfer tokens to the strategy without depositing.
2. This inflates bal0 and bal1 , but doesn't increase totalSupply , so the calculation `shares = cross * totalSupply / bal0 / bal1;` will result in 0.
3. Victim tries to deposit 2000 tokens, but it will revert since shares will be rounded to 0 , and get the error `shares cant be 0`
4. Now the attacker manipulated the vault into accepting deposits that are > 2000 tokens only , which is impractical for a lot of users and causes a Economic DoS, which turn users away from investing in the protocol.

### Impact

- The attacker artificially inflates the vault’s balance without increasing totalSupply, making the share calculation round to zero.
- This prevents deposits below a certain threshold, forcing users to deposit impractically large amounts. 
- Smaller investors are effectively locked out of participating.
