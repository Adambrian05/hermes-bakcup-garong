# Leverager::_checkWithinlimits incorrectly calculates positionLeverage

### Summary

`Leverager::_checkWithinlimits` checks that the position is within predefined limits. One of its checks ensures that `positionLeverage` is less than or equal to the maximum allowed leverage. Unfortunately, `positionLeverage` is not being calculated correctly.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464

`leveragePosition` should be calculated as `(Collateral + Borrow) / Collateral`, but in this case, `up.initCollateralValue `already includes the borrowed amount used to create the position:

```solidity
        // a0 and a1 represent the actual amounts deposited within the vault.
        // We keep track of them as we later make exactOutput swaps based on them
        (uint256 shares, uint256 a0, uint256 a1) =
            IVault(lp.vault).deposit(lp.vault0In, lp.vault1In, lp.min0in, lp.min1in);
 
        up.initCollateralUsd = _calculateTokenValues(up.token0, up.token1, a0, a1, price); 
 
        uint256 bPrice = IPriceFeed(pricefeed).getPrice(lp.denomination);

        up.initCollateralValue = up.initCollateralUsd * (10 ** ERC20(lp.denomination).decimals()) / bPrice;
```

Therefore, we are calculating something similar to `(Collateral + Borrow + Borrow) / (Collateral + Borrow)`, which makes the leverage check incorrect:

```solidity
uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```

```solidity
require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage")
```

### Mitigation

positionLeverage should be calculated as:

```diff
- uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
+ uint256 positionLeverage = (up.initCollateralValue ) * 1e18 / (up.initCollateralValue - up.borrowedAmount);
```
