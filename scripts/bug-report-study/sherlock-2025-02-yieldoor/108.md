# Missing Price Feed Check in Leverager Vault Initialization



#### **Summary**  
The `LendingPool` contract allows the creation of vaults without verifying that at least one underlying token (token0 or token1) has a reliable price feed. This violate the protocol core requirement and force reliance on easily manipulated TWAP prices, creating risk of undervalued collateral or unfair liquidations.  

## Project Requirement
## "At least one of the assets in each whitelisted vault within the Leverager must have a set trustworthy pricefeed."


https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L75-L96


## Vulnerability details*
**1. Missing Validation in `initVault` Function**  
When initializing a vault via `LendingPool.initVault`, the function skip checking if the **token0** or **token1** has a valid price feed then this allows vaults to operate with *both* tokens depending solely on TWAP prices which attackers can exploit in low-liquidity pools.  



**Code Snippet (Flawed Logic):**  
```solidity
function initVault(
....) external onlyOwner {
    require(!vaultParams[vault].leverageEnabled, "already enabled");
    //@audit: No validation for price feeds here 🚨
    ...
}
```  

**2. Unsafe Fallback to TWAP in Valuations**  
The `_calculateTokenValues` function use TWAP prices if neither token has a price feed so it expose the protocol to price manipulation:  
```solidity
// Leverager.sol
function _calculateTokenValues(.....) internal view {
    // @audit: If both tokens lack feeds, use TWAP 
    if (chPrice0 == 0) {
        usdValue += (amount0 * price / PRECISION) * chPrice1 / decimals1;
    } else if (chPrice1 == 0) {
        usdValue += amount1 * PRECISION / price * chPrice0 / decimals0;
    }
}
```  



## Proof of Concept 
1. **Create a Malicious Vault**:  
   - Deploy a vault with two fake tokens (**FAKE0** and **FAKE1**) that lack price feeds.  
   - then call `initVault` to whitelist this vault.  

2. **Manipulate TWAP**:  
   - Execute a large swap in the FAKE0/FAKE1 pool to distort the TWAP price to  inflate FAKE0’s value

3. **Exploit Overvalued Collateral**:  
   - Open a leveraged position using FAKE0 as collateral borrowing $1M based on the manipulated TWAP.  

4. **Profit from Collapse**:  
   - When TWAP is correct, the collateral value crash leaving the protocol with bad debt.  



##  **Impact**  
- The borrowers exploit inflated TWAP prices to take loans exceeding their collateral’s real value resulting to under collateralized loan
- unfair Liquidations as honest positions are liquidated due to manipulated price drops.  
- Accumulated bad debt from multiple exploited positions will bankrupt the system.  



## Recommendation*
Add a validation step in `initVault` to enforce at least one price feed:  
```solidity
function initVault(.....) external onlyOwner {
    require(!vaultParams[vault].leverageEnabled, "already enabled");
    
    address token0 = IVault(vault).token0();
    address token1 = IVault(vault).token1();
    require(
        IPriceFeed(pricefeed).hasPriceFeed(token0) || 
        IPriceFeed(pricefeed).hasPriceFeed(token1),
        "At least one token must have a price feed"
    );
   
}
```
