# Deposit/Withdraw ratio invariant broken for first depositor when there are pre-existing strategy balances


## Summary
The `Vault#_calcDeposit` function does not account for existing strategy balances when calculating shares for the first depositor, leading to a broken invariant where deposit and withdraw ratios differ.

## Relevant Context
The vault should maintain a consistent ratio between deposits and withdrawals. This invariant is mentioned in the contest's `README`

> If a user performs a deposit and then immediately withdraws the amount of shares they've just received, they should always get funds back in the same ratio as when they deposited them (excluding rounding down of a few wei).

## Root Cause
In `Vault#_calcDeposit`, when `totalSupply == 0`, the function calculates shares based solely on the deposit amounts without considering existing strategy balances:

[`Vault.sol#L129-L133`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/b5a0f779dce4236b02665606adb610099451a51a/yieldoor/src/Vault.sol#L129-L133)

```solidity
if (totalSupply == 0) {
    amount0 = depositAmount0;
    amount1 = depositAmount1;
    shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
}
```

This creates a mismatch between the deposit ratio and withdrawal ratio when there are pre-existing balances in the strategy, as withdrawals are calculated proportionally to total strategy balances:

```solidity
withdrawAmount0 = totalBalance0 * shares / totalSupply;
withdrawAmount1 = totalBalance1 * shares / totalSupply;
```

## Attack Path
1. Strategy has existing balance of token0 but no token1
2. First depositor deposits both tokens
3. First depositor immediately withdraws
4. Receives tokens back in a different ratio than deposited

## Impact Explanation
Medium. Breaks the invariant where deposit/withdraw ratios should match.

## Proof of Concept
Using USDC (6 decimals) as token0 and WETH (18 decimals) as token1:

1. Initial strategy balance:
   - token0: 100e6 USDC
   - token1: 0 WETH

2. First deposit:
   - Deposits 100e6 USDC and 1e18 WETH
   - Receives (1e18 - 1000) shares
   - Deposit ratio = 1e18/100e6 = 1e10

3. Strategy balance after deposit:
   - token0: 200e6 USDC
   - token1: 1e18 WETH

4. Immediate withdrawal of all shares:
   - Receives 199,999,999 USDC (200e6 * (1e18 - 1000) / 1e18)
   - Receives (1e18 - 1000) WETH (1e18 * (1e18 - 1000) / 1e18)
   - Withdrawal ratio = (1e18 - 1000)/199,999,999 = 5,000,000,024

5. The ratio difference is 1e10 - 5,000,000,024 = 4,999,999,976, demonstrating the broken invariant

## Recommendation
Since this behavior only affects the first depositor and could potentially be profitable for them, there is no mitigation needed. The protocol should explicitly document this edge case in their technical documentation and acknowledge that the deposit/withdraw ratio invariant can be broken for the first depositor when there are pre-existing strategy balances.
