# a frozen reserve should not be able to accept redeem() calls

### Summary

`LendingPool.redeem()` fails to check if the asset's reserve is frozen by admin.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/LendingPool.sol#L83-L101

### Root Cause

In `LendingPool.redeem()`, there's no check to ensure frozen reserves can't accept redeem() calls.

```solidity
   function redeem(address underlyingAsset, uint256 yAssetAmount, address to)
        public
        notPaused
        nonReentrant
        returns (uint256)
    {//@audit-issue a frozen reserve should not be able to accept redeem() calls
   
        DataTypes.ReserveData storage reserve = getReserve(underlyingAsset);

        if (yAssetAmount == type(uint256).max) {
            yAssetAmount = IyToken(reserve.yTokenAddress).balanceOf(_msgSender());
        }
        // transfer yTokens to this contract
        IERC20(reserve.yTokenAddress).safeTransferFrom(msg.sender, address(this), yAssetAmount);

        // calculate underlying tokens using yTokens
        uint256 underlyingTokenAmount = _redeem(underlyingAsset, yAssetAmount, to);

        return (underlyingTokenAmount);
    }
```

Lenders can redeem their yAssets into underlying assets of frozen reserves this makes the ability of admins to freeze a reserve useless.
