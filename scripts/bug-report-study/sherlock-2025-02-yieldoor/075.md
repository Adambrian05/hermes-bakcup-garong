# Cannot set liquidation fee recipient

### Summary

There is no way to set `feeRecipient` in `Leverager` contract. This will lead to liquidation failure because transfer to empty address is not allowed in most ERC20 tokens.

### Root Cause

In [`Leverager.sol`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L1), `feeRecipient` address is not initialized in the constructor and does not have setter method either.

So when liquidation fee is claimed, `Leverager` contract will try to send tokens to empty address `address(0)`:

```solidity
@>          if (pf0 > 0) IERC20(up.token0).safeTransfer(feeRecipient, pf0);
@>          if (pf1 > 0) IERC20(up.token1).safeTransfer(feeRecipient, pf1);

```

This will revert in most cases as any sane ERC20 tokens will prevent transfer to empty address.

### Internal Pre-conditions

1. Liquidator tries to liquidate a position that has total value USD is greater than borrowed value USD

### External Pre-conditions

N/A

### Attack Path

N/A

### Impact

This will lead to liquidation DoS, if transferred token prevents transferring to empty address.
If the token allows transferring to empty address, liquidation fee is lost forever.
