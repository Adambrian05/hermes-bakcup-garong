# Incorrect repayment calculation in withdraw function

## Summary
A calculation error in the withdraw function will cause incorrect repayment handling when token1 is the borrowed denomination, as the code incorrectly uses amountOut0 instead of amountOut1 in the comparison. This will lead to users receiving excess token1 when withdrawing positions, potentially causing economic loss to the protocol.

## Root cause
* In [Leverager.sol:232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232) the variable comparison for repayFromWithdraw incorrectly uses amountOut0 instead of amountOut1 when calculating the repayment amount for token1 denominations.

## Internal Pre-conditions
1. A user needs to open a leveraged position where the borrowed denomination is token1
2. The position's amountOut0 must be less than the owed amount when withdrawing
3. The position's amountOut1 must be greater than the owed amount when withdrawing

## External Pre-conditions
*None required*

## Attack Path
1. User opens a leveraged position with token1 as the borrowed denomination
2. User calls withdraw() to withdraw from the position partially or fully
3. When the function calculates repayFromWithdraw, it incorrectly uses amountOut0 in the comparison instead of amountOut1
4. This results in an incorrect calculation of how much token1 should be used to repay the debt
5. Consequently, owedAmount is reduced by the incorrect amount and amountOut1 is reduced incorrectly
6. User receives excess token1 that should have been used for debt repayment

## Impact
The protocol suffers an economic loss as users can withdraw more token1 than they should be entitled to when token1 is the borrowed denomination. The impact depends on the difference between amountOut0 and amountOut1 and how many withdrawals occur with these conditions.

## POC
```solidity
// The vulnerability exists in the withdraw function
// The problematic code is here:
else if (borrowed == up.token1) {
    // BUG: Should be using amountOut1 in the comparison not amountOut0
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}

// The correct code should be:
else if (borrowed == up.token1) {
    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```

To reproduce:
1. Create a leveraged position with token1 as the borrowed denomination
2. Withdraw from the position ensuring amountOut0 < owedAmount < amountOut1
3. Observe that the user receives excess token1 that should have been used for debt repayment

## Mitigation
Update the calculation to use the correct variable in the comparison:

```diff
else if (borrowed == up.token1) {
-    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
+    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
    owedAmount -= repayFromWithdraw;
    amountOut1 -= repayFromWithdraw;
}
```

This ensures that when token1 is the borrowed denomination, the correct amount of token1 is used for debt repayment.
