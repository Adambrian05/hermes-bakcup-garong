# Liquidation criteria is wrongly calculated.

### Summary

In leveraged trading, a higher leverage rate increases the risk of liquidation. In contrast, a lower leverage rate has lower liquidation risk.

However, due to the incorrect calculation of liquidation criteria in the `isLiquidateable()` function, a position is exposed to a higher-than-expected risk of liquidation.

### Root Cause

The `VaultParams.maxTimesLeverage` is used to ensure that the applied leverage is not greater than the maximum in the [`_checkWithinlimits()`](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L459-L474) function when opening a position.

```solidity
    function _checkWithinlimits(Position memory up) internal {
        ... ...
        uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;

        require(up.initBorrowedUsd >= minBorrow, "position must be at least minBorrow amount");
@>      require(positionLeverage <= vp.maxTimesLeverage && positionLeverage <= maxLevTimes, "too high x leverage");
        ... ...
    }
```

However, this value is also used when calculating a liquidation factor in the `isLiquidateable()` function:

```solidity
    function isLiquidateable(uint256 _id) public view returns (bool liquidateable) {
        ... ...
        uint256 base = owedAmount * 1e18 / (vp.maxTimesLeverage - 1e18);
        base = base < pos.initCollateralValue ? base : pos.initCollateralValue;

        if (owedAmount > totalDenom || totalDenom - owedAmount < vp.minCollateralPct * base / 1e18) return true;
        else return false;
    }
```

Therefore, every position will have the same liquidation factor rate, regardless of whether its leverage rate is high or low.

*None*

### Impact

Since all positions share the same liquidation factor rate, which is set to the highest possible value, even low-leverage positions become more susceptible to liquidation.

### Mitigation

The liquidation factor should be calculated differently per position based on the leverage rate like in the `_checkWithinlimits()` function.

In the `_checkWithinlimits()` function, the leverage rate is calculated like below:
```solidity
    uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```

I suggest adopting this calculation in the `isLiquidateable()` function.
