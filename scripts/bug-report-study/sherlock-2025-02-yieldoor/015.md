# Strategy rebalances the secondary position into incorrect ticks when encountering negative ticks.

### Summary

The calculation logic for the second position in `Strategy.sol:367` (https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L367) is invalid when the tick is negative, potentially causing incorrect position placement or a revert during the `rebalance` call.

### Root Cause

The calculation logic for the second position in `Strategy.sol:367` (https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Strategy.sol#L367) is flawed when the tick is negative, potentially resulting in incorrect position placement or a revert during a rebalance call. Specifically, when the tick is negative, the modulo operation also yields a negative result (if nonzero), making subsequent calculations invalid and causing the secondary position to remain active after rebalancing.

### Internal Pre-conditions

1. `Rebalances` needs to call `rebalance` function

### External Pre-conditions

1.  The following condition holds true for the spot tick in the pool: `spotTick % tickSpacing != 0 && spotTick % tickSpacing < 0`

### Attack Path

1. `Rebalancer` calls `strategy.rebalance()` function

### Impact

The secondary position remains active, resulting in an invalid system state and idle funds in both tokens on the strategy balance after rebalancing.

### Mitigation
