# Initial Vault Deposit Manipulation

### Summary

Lack of minimum deposit validation in the Vault contract will cause a loss of funds for subsequent depositors as an attacker will create an imbalanced initial deposit to extract value from future liquidity providers. If an attacker is careful enough he can wait for the contract deployment and front run to deposit first in the vault which will create several problems...

### Root Cause

In Vault.sol the [_calcDeposit](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119) function has inadequate safeguards for initial deposits, which allows users to create highly imbalanced vault states with minimal capital:
```solidity
if (totalSupply == 0) {
    // For first deposit, just use the amounts desired
    amount0 = depositAmount0;
    amount1 = depositAmount1;
    shares = (amount0 > amount1 ? amount0 : amount1) - (1000);
}
```
The choice to allow any values for the initial deposit is a mistake as it permits tokenomic unsound ratios that extract value from subsequent depositors.

### Internal Pre-conditions

The vault must be newly created or have zero total supply
No minimum deposit requirements are enforced in the vault contract

### External Pre-conditions

none

### Attack Path

Attacker identifies a new vault 
Attacker makes the first deposit with a strategically imbalanced ratio of tokens (e.g., minimal amount of one token and larger amount of the other)
Attacker waits for legitimate users to deposit significant amounts of both tokens at proper ratios
Legitimate users deposit tokens at fair market ratios, unaware that the vault's share pricing is skewed
Attacker can withdraw their funds extracting additional value from the system due to the initial imbalance

### Impact

The depositors suffer an approximate loss of 1% of their deposits. The attacker gains this 1% from legitimate depositors with minimal risk or capital requirement. The impact scales with the size of subsequent deposits, meaning larger protocol deposits result in larger attacker profits.

### Mitigation

Implement minimum deposit requirements that are commensurate with token values:
```solidity
function deposit(uint256 amount0, uint256 amount1, uint256 amount0Min, uint256 amount1Min)
    external

{

        require(amount1 >= MIN_INITIAL_DEPOSIT_TOKEN1, "Initial deposit too small for token1");
```
