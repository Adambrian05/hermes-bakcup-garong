# Tick spacing of 1 does not work properly

### Summary

Tick spacing of 1 does not work properly

### Root Cause

Root cause is not accounting for the fact that when tick spacing is 1, we are always on an initializable tick and we don't need to normalize based on `isLowerSided` value which is also always false making the issue possible.

Ticks of the main position are set based on a tick border to which we add and subtract half of the position width. The tick border is computed based on the closest tick initializable tick to the current one (one to which we can provide liquidity). However, for a tick spacing of 1, it doesn't work properly and we break that intention as we always add 1 to the tick border:
```solidity
bool isLowerSided = modulo < (tickSpacing / 2);
if (!isLowerSided) tickBorder += tickSpacing;
```
`isLowerSided` is always false as `modulo` is always 0 and tick spacing rounds to 0.

### Internal Pre-conditions

1. Tick spacing is 1

### External Pre-conditions

_No_

### Attack Path

1. Let's imagine position width is 2 and tick spacing is 1, current tick is 6, thus the lower and upper tick of the position should be 5 and 7 as the current tick is on an initializable tick, thus the we should simply add and subtract half the width from it
2. `modulo` is 0 as we are on an initializable tick, tick spacing is 1
3. `isLowerSided` is false as `modulo < (tickSpacing / 2) -> 0 < (1 / 2) -> 0 < 0` is false
4. `tickBorder` is properly set to the current tick of 6
5. Due to the `isLowerSided` being false, we incorrectly increase the border by 1, now it will be 7:
```solidity
if (!isLowerSided) tickBorder += tickSpacing;
```
6. Lower tick is 6 and upper tick is 8, this is incorrect as it should have been 5 and 7

### Impact

Position has incorrect ticks. Now, when the tick decreases by 1, our main position will not be generating any fees. Instead, if it drops by 1 which is the tick spacing, it should actually go to our lower tick and still generate fees. This results in loss of funds for the protocol.

Also, the function does not work as specified and intended. The idea is for the tick border to be the nearest initializable tick which for tick spacing of 1 should be the current tick, the function does not do that.

### PoC

_No response_

### Mitigation

```diff
- if (!isLowerSided) tickBorder += tickSpacing;
+ if (!isLowerSided && tickSpacing != 1) tickBorder += tickSpacing;
```
