# Maximum leverage can be exceeded due to insufficient positionLeverage calculation

### Summary

The positionLeverage is calculated wrongly which could result in opening positions with a higher leverage than the maximum allowed.

### Root Cause

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L464
In this code we can see that the leverage is calculated as:
```solidity
 uint256 positionLeverage = (up.initCollateralValue + up.borrowedAmount) * 1e18 / up.initCollateralValue;
```
This will assume that the `initCollateralValue` contains only the collateral amount.
However here we can see that it is actually the collateral+borrowed:
https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L129

As a result leverage will be underestimated.

### Attack Path

A user wants to open a position with a 10x leverage while the maximum allowed is 2x
He deposits $1000 as collateral and then borrows $9000 so the total position value is $10000.
This however is incorrect as the leverage will be calculated as 10000+9000/10000 = 1.9x which is incorrect.
This will allow users to open positions at extreme leverage

### Impact

Users will be able to open positions at extremely high leverage, breaching the maximum allowed. This could also result in accruing bad debt in volatile markets.
