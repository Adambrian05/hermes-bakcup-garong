# Attackers canl open risk-free leveraged positions causing bad debt for the protocol

### Summary


The **missing minimum deposit check** in `openLeveragedPosition()` will cause **bad debt** for the **protocol** as **an attacker will open a leveraged position with zero initial collateral**, allowing them to borrow funds and create a highly leveraged, risk-free position that can easily become undercollateralized and leave the protocol with bad debt.


### Root Cause


In `openLeveragedPosition()` [line 116 -117](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L116C1-L118C1), the **function allows for `amount0In` and `amount1In` to be zero**. This enables a user to open a position without contributing any initial collateral, while still borrowing assets from the protocol's lending pool.


### Internal Pre-conditions


1. Vault must have leverage enabled (`leverageEnabled` set to `true` for the target vault).
2. Attacker calls `openLeveragedPosition()` with `amount0In = 0` and `amount1In = 0`, providing **no collateral**.
3. `lp.maxBorrowAmount` is set to a non-zero value, allowing the attacker to borrow assets from the lending pool.
4. There is no check ensuring the user-provided `amount0In` and `amount1In` are above zero.

### External Pre-conditions

NA

### Attack Path


1. Attacker calls `openLeveragedPosition()` with `amount0In` and `amount1In` both set to `0`, and `maxBorrowAmount` set to a high value.
2. The function does not enforce any minimum collateral requirement and proceeds.
3. The attacker is able to **borrow funds** from the protocol’s lending pool without contributing any of their own capital.
4. The position is highly leveraged (infinite leverage since collateral is zero).
5. If the price moves unfavorably or the position is liquidated, the protocol will incur a **bad debt** since the borrowed funds exceed the value of the collateral (which was zero to begin with).
6. This allows the attacker to effectively **shift all risk to the protocol**, creating an exploit where they can walk away risk-free.


### Impact


- The protocol will accumulate **bad debt** whenever such zero-collateral positions are liquidated.
- The attacker takes on **no risk**, while the protocol bears all the downside.
- Protocol solvency is compromised as malicious users can continuously exploit this to drain liquidity through toxic debt positions.

### Mitigation

- Add a **minimum initial collateral check** in `openLeveragedPosition()` to ensure users cannot open positions without contributing meaningful collateral.
  ```solidity
  require(lp.amount0In > 0 || lp.amount1In > 0, "Insufficient initial collateral");
  ```
- Optionally, enforce a **minimum collateral ratio check** upon opening the position to avoid edge cases where users borrow excessive amounts relative to initial deposits.
- Review all leverage and borrowing functions to ensure that similar **zero-collateral exploits** are not possible elsewhere in the codebase.
