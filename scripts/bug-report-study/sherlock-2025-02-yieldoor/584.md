# Deposit Function (Share Inflation Attack)

### Summary

A rounding issue in the _calcDeposit() function allows users to artificially inflate their shares by repeatedly depositing and withdrawing. This can be exploited to drain liquidity from the pool over time, leading to a "free money" attack.

https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Vault.sol#L119-#L151

### Root Cause

Even If depositFee is introduced it wont be more than 0. Only when its abused however until depositFee is setted to different value than 0 from the owner Users will continue doing that. Thats why depositFee should always be > 0. Not like its written in Docs
The problem lies in the rounding up of amount0 and amount1 when calculating shares:
```solidity
amount0 = (cross - 1) / bal1 + 1;
amount1 = (cross - 1) / bal0 + 1;
shares = cross * totalSupply / bal0 / bal1;
```
The +1 operation rounds up amount0 and amount1, which slightly inflates the deposit amounts.
This results in users getting more shares than they should.
A malicious user can deposit, receive extra shares, withdraw, and repeat, profiting each time.
Example Exploit Scenario
Initial state: Vault has some liquidity (bal0 > 0, bal1 > 0).
Attacker deposits a small amount, gaining slightly more shares than expected due to rounding.
Attacker withdraws immediately, getting more tokens than they originally deposited.
Repeating the process, they drain the vault without any real cost.

### Attack Path

1. User calls deposit  when both tokens in the strategy are > 0  which leads to user getting +1 shares since it rounds up.
2. User calls withdraw and withdraws more liquidity

Repeats

```solidity
function _calcDeposit(uint256 bal0, uint256 bal1, uint256 depositAmount0, uint256 depositAmount1)
        internal
        view
        returns (uint256 shares, uint256 amount0, uint256 amount1)
    {
        uint256 totalSupply = totalSupply();

        // If total supply > 0, vault can't be empty
        assert(totalSupply == 0 || bal0 > 0 || bal1 > 0);

        if (totalSupply == 0) {
            // For first deposit, just use the amounts desired
            amount0 = depositAmount0;
            amount1 = depositAmount1;
            shares = (amount0 > amount1 ? amount0 : amount1) - (1000); 
        } else if (bal0 == 0) {
            amount1 = depositAmount1;
            shares = amount1 * totalSupply / bal1; //pool balance
        } else if (bal1 == 0) {
            amount0 = depositAmount0;
            shares = amount0 * totalSupply / bal0;
        } else {
            uint256 cross0 = depositAmount0 * bal1;
            uint256 cross1 = depositAmount1 * bal0;
            uint256 cross = cross0 > cross1 ? cross1 : cross0;
            require(cross > 0, "cross");

            // Round up amounts
            amount0 = (cross - 1) / bal1 + 1;
            amount1 = (cross - 1) / bal0 + 1;
            shares = cross * totalSupply / bal0 / bal1;
        }
    }
```

### Impact

User gains more shares than they should for their deposit.
By repeating the deposit/withdrawal process, they extract excess value.
