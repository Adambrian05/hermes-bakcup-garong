# debt repayment is wrongly calculated when withdrawing funds

### Summary

The wrong value of amount used, causes incorrect repayment by deducting token0 instead of token1 when token1 is borrowed. This can leave some debt unpaid or reduce the wrong token balance. As a result, the position may face liquidation risks or unintended token losses.

### Root Cause

On [Leverage.sol#L232](https://github.com/sherlock-audit/2025-02-yieldoor/blob/main/yieldoor/src/Leverager.sol#L232), `withdraw` function settles token amounts and repay amounts, but for the token1, token0 amount is used, which leads to incorrect calculation.

### Attack Path


Scenario: Overpayment Attack (Loss of Funds)
Assume amountOut0 = 100 and amountOut1 = 50, but the user only needs to repay 40 tokens.
The bug causes amountOut0 (100) to be used instead of amountOut1 (50).
Since 100 > 40, the user overpays debt using tokens from amountOut0, losing excess funds.

same goes for underpayments..


### Impact

Potential Underpayment of Debt – If amountOut0 is smaller than amountOut1, less debt is repaid, increasing liquidation risk.
Potential Overpayment – If amountOut0 is larger than amountOut1, more than required might be deducted, causing unintended token loss.

### Mitigation

Use amountOut1 in place of amountOut0.

 ```diff
       else if (borrowed == up.token1) {
       -     uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut0 : owedAmount;
       +    uint256 repayFromWithdraw = amountOut1 < owedAmount ? amountOut1 : owedAmount;
            owedAmount -= repayFromWithdraw;
            amountOut1 -= repayFromWithdraw;
        }
```
