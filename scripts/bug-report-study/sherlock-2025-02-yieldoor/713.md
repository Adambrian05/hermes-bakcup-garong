# Potential TWAP Calculation Error Due to Uninitialized `secondsAgos[1]`

### Summary

The TWAP calculation in `Strategy::twapTick()` relies on the `observe()` function from Uniswap V3. However, `secondsAgos[1]` is not explicitly set to 0, which may lead to unintended behavior:

-Uniswap V3's `observe()` function expects `secondsAgos[1]` to represent the current timestamp.
-If 0 is not explicitly interpreted as "now," the function may return outdated tick cumulative data, affecting price calculations.


### Root Cause

```  solidity
function twapTick() public view returns (int24) {
        uint32[] memory secondsAgos = new uint32[](2);
        secondsAgos[0] = twap;
>>   // @audit need secondAgo[1] = 0   ---to now
        (int56[] memory tickCumulatives, ) = IUniswapV3Pool(pool).observe(
            secondsAgos
        );
        int56 tickCumulativesDelta = tickCumulatives[1] - tickCumulatives[0];

        int24 tick = int24(tickCumulativesDelta / int32(twap));
        if (
            tickCumulativesDelta < 0 &&
            (tickCumulativesDelta % int32(twap) != 0)
        ) tick--;
        return tick;
    }
```

### Internal Pre-conditions

-The contract does not explicitly set `secondsAgos[1] = 0 `in the `twapTick(`) function.
-Uniswap V3’s `observe()` function may return outdated tick cumulative values if `secondsAgos[1]` is not explicitly set to the current timestamp.
-The system relies on this function to fetch the latest TWAP-based price, which is used in other contract logic (e.g., liquidation checks, price feeds).

### External Pre-conditions

-The contract interacts with Uniswap V3’s oracle mechanism, which depends on stored tick cumulative values.
-The price of an asset in the Uniswap V3 pool is fluctuating, causing TWAP calculations to change.
-The protocol uses TWAP as a price reference for key financial operations such as lending, collateralization, or 
 stablecoin minting.

### Attack Path

An attacker waits for a price movement in the Uniswap V3 pool, causing the current tick to deviate significantly from the correct TWAP.

The contract calls twapTick(), but due to the missing explicit `secondsAgos[1] = 0`, it may receive outdated cumulative tick data instead of the latest value.

The incorrect TWAP is used for pricing, lending, or liquidation logic, allowing an attacker to:

- Manipulate collateral values, causing undercollateralized loans to remain active.

- Trigger false liquidations of other users’ positions.

- Obtain assets at incorrect prices, leading to arbitrage opportunities.

### Impact

The protocol’s price feed becomes unreliable, leading to incorrect financial decisions.
Liquidations, lending, and collateral management may be compromised, potentially leading to user losses.
Attackers could extract value by exploiting outdated TWAP values, leading to unfair market conditions.
