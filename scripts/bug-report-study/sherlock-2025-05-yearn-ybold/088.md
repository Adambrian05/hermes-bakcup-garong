# Incorrect auction pricing will let users acquire collateral below market value

### Summary

A miscalculated starting price in the `LiquityV2SPStrategy` will cause a mispriced auction for the protocol as users will acquire underpriced collateral via auction due to an incorrect arithmetic operation

### Root Cause

In `LiquityV2SPStrategy.sol`, the starting price for the auction is set using the following flawed expression:

```solidity
   AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction
```

This results in multiple divisions by WAD, drastically reducing the auction's starting price and allowing users to buy collateral significantly below market value.

**There appears to be an issue with the WAD division.**
1. WAD is defined as `1e18` (standard precision for Ethereum)
2. MIN_BUFFER_PERCENTAGE is defined as `WAD + 1e17` which is `1.1e18` (110%)
3. The bufferPercentage is initialized to MIN_BUFFER_PERCENTAGE

**For the calculation:**
1. `_available` is the amount of collateral in base units
2. `_price` is the oracle price with WAD precision (1e18)
3. `_bufferPercentage` is in WAD precision (1e18)

The calculation should convert collateral to its BOLD value `(_available * _price / WAD)` and then apply the buffer percentage `(* _bufferPercentage / WAD)`.
However, the extra /WAD reduces the starting price by a factor of 1e18, making collateral essentially free to bidders.

### LOC
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241

### Impact

The protocol suffers a significant loss of collateral value, proportional to the price miscalculation.
Users gain collateral at a deeply discounted rate.

### Mitigation
```solidity
   AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD); // Reverts if there's an active auction
```
