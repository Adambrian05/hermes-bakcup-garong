# Incomplete asset reporting will misrepresent strategy value affecting vault users

### Summary

Exclusion of COLL token value in `LiquityV2SPStrategy.estimatedTotalAssets` will cause inaccurate accounting for vault users as the strategy underreports its true asset base, leading to incorrect withdrawal limits and performance metrics.

### Root Cause

In `LiquityV2SPStrategy.sol`, the `estimatedTotalAssets()` function only sums the BOLD token balance and Stability Pool deposits while ignoring:
1. COLL tokens held by the strategy (`COLL.balanceOf(address(this))`)
2. COLL tokens in active auctions (`AUCTION.available(address(COLL))`)
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L105-L107

This is a mistake because COLL tokens represent a material portion of the strategy's value that should be accounted for in total assets.

### Internal Pre-conditions

1. **Strategy holds COLL**: The strategy must have accumulated COLL tokens from Stability Pool rewards.
2. **Active auctions**: The strategy may have COLL tokens deposited in auctions via `AUCTION`.

### External Pre-conditions

- COLL token must have non-zero market value (oracle price > 0)


### Attack Path

1. **Normal operation**: Strategy earns COLL rewards from Stability Pool over time.
2. **Asset reporting**: When `estimatedTotalAssets()` is called:
```solidity
   // Current implementation (incomplete):
   return asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this));
```
3. Underreporting: The function returns a value that excludes:
100 COLL tokens held (worth 1 ETH via oracle)
50 COLL in auctions (worth 0.5 ETH)

### Impact

Withdrawal limits: Users may be unable to withdraw full value due to artificially low reported assets.

Performance metrics: Strategy APY appears lower than actual since COLL gains are excluded.

Protocol risk: Vaults may over-allocate to other strategies due to undervaluation.

### PoC

Setup:

Strategy holds:

100 BOLD in SP (value = 100)

50 COLL (oracle price = 1 → value = 50)

`estimatedTotalAssets()` returns 100 (missing 50 value from COLL)

User impact:

User tries to withdraw 120 (should be allowed: 100 + 50 = 150 total)

Withdrawal fails due to incorrect 100 limit

### Mitigation

Modify `estimatedTotalAssets()` to include COLL value:
```solidity
function estimatedTotalAssets() public view returns (uint256) {
    uint256 boldValue = asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this));
    
    // Calculate COLL value
    (uint256 collPrice, ) = COLL_PRICE_ORACLE.fetchPrice();
    uint256 collBalance = COLL.balanceOf(address(this)) + AUCTION.available(address(COLL));
    uint256 collValue = collBalance * collPrice / 1e18;
    
    return boldValue + collValue;
}
```
