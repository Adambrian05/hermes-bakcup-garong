# Precision Loss in Auction Starting Price Calculation

### Summary

The auction starting price calculation in the `_tend` function incorrectly performs divisions before multiplications, which can lead to significant precision loss. This could result in auctions starting at prices lower than intended, potentially causing the strategy to recover less BOLD tokens than possible.

The current implementation divides intermediate results multiple times before completing all multiplications, which in fixed-point arithmetic leads to truncation errors compounding throughout the calculation.

### Root Cause

The problematic code exists in the `_tend` function:
[Reference](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L240-L241).

```solidity
// slither-disable-next-line divide-before-multiply
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
```

Even though there is a Slither warning comment, the issue has not been fixed. Let's analyze what this calculation is doing:

1. It multiplies the available collateral amount (_available) by the price (_price)
2. It divides by WAD (1e18)
3. It multiplies by buffer percentage
4. It divides by WAD twice more

Due to Solidity's integer division behavior, each division operation truncates any remainder. When performing division before multiplication, this truncation compounds and can lead to significant precision loss.

For example, if `_price / WAD` truncates from 1.9 to 1, and then we multiply by `_bufferPercentage`, we've already lost ~47% of the intended value.

### Mitigation

Rearrange the calculation to perform all multiplications before divisions to minimize precision loss:
```solidity
function _tend(
    uint256 /*_totalIdle*/
) internal override {
    // ...existing code...
    
    if (_available > dustThreshold) {
        (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
        uint256 _bufferPercentage = bufferPercentage;
        if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
            _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
        }

        // Fixed calculation - all multiplications first, then divisions
        AUCTION.setStartingPrice((_available * _price * _bufferPercentage) / (WAD * WAD * WAD));
        
        COLL.safeTransfer(address(AUCTION), _toAuction);
        AUCTION.kick(address(COLL));
    }
    // ...existing code...
}
```
This revised calculation performs all multiplications first, then performs all divisions at the end, minimizing precision loss. The mathematical result is identical, but the fixed-point arithmetic implementation is more precise.
