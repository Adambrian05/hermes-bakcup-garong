# `Accountant.report` will undermine `totalFees` when it shouldn't

## Summary
The loss check in `Accountant.report` compares `totalSupply` against `totalAssets` and subtracts their difference from `totalFees` whenever PPS is below 1. However it fails to take into consideration the Yearn Vault gradual profit unlocking, meaning it will continously underestimate `totalFees` until the price-per-share is >= 1. 
## Description
In order to understand this issue, we need to understand how yearn vaults handle positive pnl.

Yearn vaults are designed to gradually release profits in order to deal with sudden price-per-share appreciations whenever a strategy generates yield. If a strategy has 100 shares and 100 assets and earns 50 assets as profit, it will mint 50 shares to the vault so the price-per-share remains 1. These shares are gradually decaying over time until they expire and the PPS becomes 1.5. In contrast, losses are accrued instantly. 
```solidity
def _unlocked_shares() -> uint256:
    """
    Returns the amount of shares that have been unlocked.
    To avoid sudden price_per_share spikes, profits can be processed 
    through an unlocking period. The mechanism involves shares to be 
    minted to the vault which are unlocked gradually over time. Shares 
    that have been locked are gradually unlocked over profit_max_unlock_time.
    """
    _full_profit_unlock_date: uint256 = self.full_profit_unlock_date
    unlocked_shares: uint256 = 0
    if _full_profit_unlock_date > block.timestamp:
        # If we have not fully unlocked, we need to calculate how much has been.
        unlocked_shares = self.profit_unlocking_rate * (block.timestamp - self.last_profit_update) / MAX_BPS_EXTENDED

    elif _full_profit_unlock_date != 0:
        # All shares have been unlocked
        unlocked_shares = self.balance_of[self]

    return unlocked_shares
```
The report flow in `Accountant.sol` determines loss the following way
```solidity
            // Only take fee if there's no loss.
            uint256 supply = vault.totalSupply();
            uint256 assets = vault.totalAssets();
            if (assets < supply) {
                uint256 needed = supply - assets;
                totalFees = gain < needed ? 0 : gain - needed;
            }
```
It fetches `totalSupply` and `totalAssets` from the vault. Total assets are determined by summing idle funds plus current debt. Total supply is calculated like this
```vyper
def _total_supply() -> uint256:
    # Need to account for the shares issued to the vault that have unlocked.
    return self.total_supply - self._unlocked_shares()
```
Total supply of shares returns values according to how much profit had been unlocked. Comparing `supply` and `assets` is incorrect here since the accountant will keep reporting that the vault is at loss even if it was already made back but profit is not yet unlocked. Each subsequent profitable strategy call will have its' `totalFees` wrongfully decreased.

A practical example:
Vault has `totalSupply = totalAssets = 100`, price-per-share is 1, has multiple strategies
Vault accrues 50 asset loss, price-per-share is 0.5
Another strategy generates 50 asset profit and starts an unlocking period with gradually increasing price-per-share
During this time, every strategy will have it's gains and `totalFees` undermined, sometimes even zero'd despite the loss already being offset.

## Impact
Loss of funds
## Mitigation
Re-design loss checking in `Accountant.sol` to check if previous losses had already been offset.
