# Inconsistent check of dust threshold in _tend and _tendtrigger could break the invariant

### Summary

in strategy.sol, there is _tend() internal function, in which if available balance is greater than dustthreshold than it should be transfer to auction contract.

now issue here is, there is another functionallity _tendTrigger(), which returns bool ( true/ false) if our contract is ready for tending. but here available balance check is slightly different from which it is in _tend(). which could lead to wrong bool return from here, or if conidtion in _tendtrigger is right , than issue can occur in _tend(). 

so any one of them condition , which is intended should persist and consistency should be there.

there is one invariant which is mentioned, 
```Solidity
Tending needs to be time-sensitive—once collateral is available for the strategy to claim, a keeper must call tend. The tend trigger must return true to signal that tending is required.
```
