# Enabling a non-zero protocol fee breaks the invariant of yBOLD gains being fully minted to the Accountant

### Summary

When the Yearn V3 vault's `protocol_fee_bps` is set to a non-zero value, a portion of the BOLD rewards earned by yBOLD will be minted to the protocol fee receiver, as yBOLD shares. 

This breaks the [invariant](https://github.com/sherlock-audit/2025-05-yearn-ybold?tab=readme-ov-file#q-what-propertiesinvariants-do-you-want-to-hold-even-if-breaking-them-has-a-lowunknown-impact) which states:
> When process_report is called on yBOLD, any gain must be fully minted as yBOLD to Accountant.sol, from which it will be distributed to st-yBOLD.

Note, the team has [stated in the README](https://github.com/sherlock-audit/2025-05-yearn-ybold?tab=readme-ov-file#q-what-propertiesinvariants-do-you-want-to-hold-even-if-breaking-them-has-a-lowunknown-impact) that the protocol fee can be set to non-zero values:
> protocol_fee_bps is currently "0" for all Yearn V3 vaults. However, this can be set up to some other value in future. We would love to know if setting the protocol fee would break any of our invariants.

### Root Cause

In the VaultV3 contract (yBOLD), within `process_report()`, it [issues shares](https://github.com/yearn/yearn-vaults-v3/blob/104a2b233bc6d43ba40720d68355b04d2dc31795/contracts/VaultV3.vy#L1278) to the accountant:
```solidity
        self._issue_shares(total_fees_shares - protocol_fees_shares, accountant)
```
It reduces the amount issued by the `protocol_fees_shares`, which will be non-zero if the `protocol_fee_bps` is non-zero.

This breaks the invariant stated in the README:
> When process_report is called on yBOLD, any gain must be fully minted as yBOLD to Accountant.sol, from which it will be distributed to st-yBOLD.

### Internal Pre-conditions

1. Admin sets the `protocol_fee_bps` to be non-zero

### External Pre-conditions

N/A

### Attack Path

1. Keeper calls `process_report()` on yBOLD
2. It detects a gain of 100 BOLD, so accountant reports a fee of 100 BOLD
3. Due to a `protocol_fee_bps` of 10% for example, only 90 yBOLD shares are issued to the accountant

This reduced issuance to the accountant breaks the invariant stated in the README, since the entire gain (100 BOLD) is not minted to the accountant as yBOLD shares

### Impact

Breaks the invariant stated in the README, under the heading "What properties/invariants do you want to hold even if breaking them has a low/unknown impact?"
