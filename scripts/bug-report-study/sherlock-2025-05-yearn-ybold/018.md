# [High Severity] Loss Handling Vulnerability in Accountant.sol

### Summary

`Accountant.sol` ([Line 130-180](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L130-L180)) processes strategy reports, charging 100% fees on gains only if `totalAssets ≥ totalSupply`. If assets < supply, fees are zeroed, but no mechanism covers losses to restore the yBOLD:BOLD 1:1 peg. The `skipHealthCheck` bypasses `maxLoss` checks, risking unvalidated losses and undercollateralization.



### Root Cause

- No loss coverage in `report` ([Line 161-166](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L161-L166)).
- `skipHealthCheck` allows bypassing `maxLoss` ([Line 175-177](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L175-L177)).
- No peg restoration logic.
- No handling for multiple losses or Liquity V2 volatility.

### Internal Pre-conditions

1. Vault added to `vaults` ([Line 190](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L190)).
2. Strategy reports loss via `report` ([Line 130](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L130)).
3. `totalAssets < totalSupply` ([Line 161](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L161)).
4. `skipHealthCheck` may be set ([Line 241](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L241)).

### External Pre-conditions

1. Liquity V2 reports losses (e.g., collateral price drop).
2. `feeManager` is compromised or centralized.
3. Users expect 1:1 yBOLD:BOLD redemption.

### Attack Path

1. `feeManager` calls `turnOffHealthCheck` (LoC 241), sets `skipHealthCheck = true`.
2. Strategy reports excessive loss via `report` (LoC 130).
3. `maxLoss` check bypassed, loss accepted.
4. `totalAssets` drops, PPS < 1.
5. Users redeem yBOLD at reduced value.

### Impact

- Financial Loss: Users redeem yBOLD at PPS < 1, losing funds.
- Systemic Risk: Broken 1:1 peg affects yBOLD and `st-yBOLD`.
- User Trust: Withdrawals reduce TVL.
- Severity: High, due to fund loss and peg violation.
