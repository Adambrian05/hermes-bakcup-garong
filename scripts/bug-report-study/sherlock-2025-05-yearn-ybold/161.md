# Insufficient handling of scenario where Oracle is down

### Summary

In `Strategy::_tend` THe protocol attemtps to start a a new auction, which it needs to do IN A TIMELY MANNER to get BOLD from collateral.

To do this, it starts a new auction. It sets the starting price of the auction, which should be the value of the amount of collateral it is going to auction * a buffer percentage. The auction relies on this value being correct - BUT when the oracle is down, `price` can be returned as a 0 value - and this situation is not handled.

THis will cause the auction to be started with a `startingPRice` of 0 - which will ruin the auction.

### Root Cause

If the `oracle` is down, there is some speicific logic to handle this situation, by updating the bufferPercentage.

BUT there is no consideration to the fact that if the oracle actually is down, the `price` can be returned as ZERO.

```solidity     
  if (_available > dustThreshold) {
            (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
            uint256 _bufferPercentage = bufferPercentage;
            if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
                _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
            }

            // slither-disable-next-line divide-before-multiply
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction
```

### Internal Pre-conditions

1. none

### External Pre-conditions

1. the oracle is down

### Attack Path

`1. Strategy` calls `_tend` 
2. The oracle is called to fethch the price 
3. The oracle is down and returns 0
4. Auction is started with a `startingPRice` of 0

### Impact

The Strategy relies on the efficiency and effectiveness of the tend function. IT relies on being able to quickly sell off collateral for BOLD, and it relies on that efficient process of starting an auction to do that. IF this process is effected by starting an auction with a price of 0 - this will cause delays for the strategy as it will have to wait until the ENTIRE auction period ends before it can start it again.
