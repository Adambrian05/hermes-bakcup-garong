# Division Error in Auction Starting Price Calculation

### Summary

An extra WAD (1e18) division in the auction price calculation will cause a catastrophic underpricing of collateral assets for strategy users as malicious actors will be able to purchase COLL tokens at 0.1% of their actual value by exploiting the incorrect price computation (`_available * _price / WAD * _bufferPercentage / WAD / WAD`), resulting in immediate 99.9% loss of funds through severely underpriced auctions.

### Root Cause

In [`Strategy.sol:241`](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241) the auction price calculation includes an extra division by WAD (1e18) in the formula:

```solidity
 function _tend(
        uint256 /*_totalIdle*/
    ) internal override {
        if (isCollateralGainToClaim()) claim();
        if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));

        uint256 _toAuction = COLL.balanceOf(address(this));
        uint256 _available = COLL.balanceOf(address(AUCTION)) + _toAuction;
        if (_available > dustThreshold) {
            (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
            uint256 _bufferPercentage = bufferPercentage;
            if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
                _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
            }

            // slither-disable-next-line divide-before-multiply
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);  // @>  // Reverts if there's an active auction

            COLL.safeTransfer(address(AUCTION), _toAuction);
            AUCTION.kick(address(COLL));
        }
    }
```

This extra division causes the auction starting price to be lower than intended, resulting in underpricing of collateral assets. The calculation divides by WAD three times when it should only divide by WAD twice to normalize the decimals.

```solidity
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
```

The incorrect decimal handling occurs because:
1. First /WAD normalizes the price multiplication
2. Second /WAD normalizes the buffer percentage
3. Third /WAD is redundant and incorrectly reduces the price by way more lower value than intended 



### Internal Pre-conditions

1. `_tend()` function needs to be called
2. No active auction should exist for COLL token (checked by `AUCTION.setStartingPrice()`)

### External Pre-conditions

Nil

### Attack Path

1. Attacker monitors for strategy auctions
2. When auction starts, COLL is priced at 0.1% of actual value
3. Attacker purchases COLL at severely discounted price
4. Strategy users lose 99.9% of their collateral value
5. Attacker gains the difference.

### Impact

The strategy users suffer an approximate loss of 99.9% of collateral value during auctions. The attacker gains this value by purchasing COLL tokens at 0.1% of their actual market price.


### PoC

Nil

### Mitigation

Remove one /WAD division from the auction price calculation.
