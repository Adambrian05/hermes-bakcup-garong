# `LV2SPStakerStrategy`'s `pure` functions will prevent fund deployment and retrieval, rendering active management non-operational

### Summary

The `LV2SPStakerStrategy` [contract](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Staker.sol#L9), which inherits from `BaseHealthCheck`, overrides the `_deployFunds(uint256 _amount)` and `_freeFunds(uint256 _amount)` functions. However, in `LV2SPStakerStrategy.sol`, these overridden functions are declared `internal pure` and have empty implementations:

```solidity
// In LV2SPStakerStrategy.sol
function _deployFunds(
    uint256 /* _amount */
) internal pure override {
    return;
}

function _freeFunds(
    uint256 /* _amount */
) internal pure override {
    return;
}
```

The pure keyword in Solidity restricts functions from reading from or writing to the contract's state and from calling other contracts. For a strategy contract, _deployFunds is the core mechanism to invest assets into an external yield-generating protocol (e.g., staking), and _freeFunds is essential for withdrawing them. By making these functions pure and empty, the LV2SPStakerStrategy is incapable of performing these fundamental operations. Any assets allocated to this strategy for deployment via these functions will remain idle within the strategy contract itself, not being staked or otherwise invested externally.


### Root Cause

The root cause is the incorrect implementation of _deployFunds and _freeFunds in LV2SPStakerStrategy.sol. They are marked with the pure visibility modifier and have empty function bodies. This prevents them from executing any state-changing operations or external calls, which are necessary for deploying funds to, and withdrawing funds from, an external yield-generating venue.


### Internal Pre-conditions

An instance of LV2SPStakerStrategy is deployed (e.g., via StakerFactory.newStrategy()).
The strategy is integrated with a vault or a similar system that relies on the _deployFunds function to invest assets and _freeFunds to retrieve them from a deployed state.
The vault or system attempts to utilize these functions, for example, during a harvest operation to deploy idle assets, or during a withdrawal process to free up assets.


### External Pre-conditions

Users or a vault deposit assets into a system that utilizes LV2SPStakerStrategy.
There is an expectation that these assets will be actively managed and deployed by the strategy to generate yield through staking or other external interactions.

### Attack Path

This issue is primarily a functional bug rather than a typical exploitable vulnerability for direct fund theft by an external attacker. The "path" describes how the flaw leads to malfunction:

1. A deployer (e.g., vault manager) uses StakerFactory to create and set up an LV2SPStakerStrategy instance for a vault.
2. The vault receives user deposits and allocates a portion of these assets to the LV2SPStakerStrategy.
3. During its operational cycle (e.g., harvest), the vault calls upon the strategy to deploy idle funds. This eventually triggers the strategy's internal _deployFunds(amount) function.
4. Because _deployFunds in LV2SPStakerStrategy is pure and empty, it executes without performing any actual deployment operations (e.g., transferring tokens to a staking contract). The funds remain in the LV2SPStakerStrategy contract.
5. Similarly, if the vault attempts to free funds managed by the strategy by calling _freeFunds(amount), this function will also do nothing to retrieve funds from an external position.
6. As a result, assets intended for active deployment remain idle, and the strategy fails to perform its core fund management role.


### Impact

- Funds Not Deployed: Assets intended to be deployed by LV2SPStakerStrategy into external yield-generating positions will not be invested. They will remain idle within the strategy contract.
- No Yield Generation from Active Staking: Since the funds are not deployed externally via _deployFunds, they will not generate yield that would typically be expected from an active "StakerStrategy." This negatively affects the APY of any vault utilizing this strategy. (Note: The strategy might still generate yield if ACCOUNTANT.distribute provides rewards for merely holding the asset, but active deployment is crippled).
- Strategy Non-Functional for Active Management: The strategy fails to perform its primary functions of deploying and freeing funds from external protocols, rendering its active management capabilities non-operational.
- Misleading Purpose: If LV2SPStakerStrategy is presented or used as a strategy that actively stakes funds, its implementation is misleading, as it cannot fulfill this role through _deployFunds and _freeFunds.
- Opportunity Cost: Users whose funds are allocated to this strategy (expecting active deployment) will suffer an opportunity cost, as their capital could have been deployed in genuinely active strategies to earn better returns.
