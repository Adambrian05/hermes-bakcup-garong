# Incorrect logic to trigger keeper job

### Summary

The implementation of `_tendTrigger()` should consider collateral present in the stability pool, in the strategy, or pending to be settled in the auction.

### Root Cause

The `_tendTrigger()` implementation returns true if the available collateral from the stability pool or the balance present in the strategy is greater than the dust threshold.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L253-L263

This is incorrect as it misses the collateral pending to be settled from the auction, and also it should consider all balances COMBINED to compare with the threshold.

### Internal Pre-conditions

- There are collateral tokens in the auction contract left from a previous auction, or
- `isCollateralGainToClaim() + COLL.balanceOf(address(this) > dustThreshold`, but not individually.

### External Pre-conditions

N/A.

### Attack Path

N/A.

### Impact

The trigger fails to consider all collateral in the condition, causing false negatives and preventing the correct upkeep of the strategy.

### Mitigation

The implementation should consider:

- Collateral in stability pool
- Collateral in strategy contract
- Collateral in Auction contract
