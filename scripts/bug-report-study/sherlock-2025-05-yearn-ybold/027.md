# Precision Loss in Auction Price Calculation in Strategy.sol

### Summary

Division-before-multiplication precision loss will cause zero auction starting prices for strategy depositors and protocol as any attacker will trigger collateral claims when available * price < WAD, causing the auction price calculation _available * _price / WAD * _bufferPercentage / WAD / WAD to truncate to zero, allowing them to bid minimal amounts and acquire valuable collateral tokens for free

### Root Cause

n Strategy.sol:233 the auction price calculation performs division before multiplication which causes precision loss truncation to zero when available * price < WAD

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241

### Internal Pre-conditions

1. Strategy needs to accumulate collateral gains to set _available (collateral amount) to be at most WAD / _price where WAD = 1e18
2. Oracle needs to report price to set _price (oracle price) to be at most WAD / _available to ensure _available * _price < WAD
3. Strategy needs to have collateral gains above dust threshold to set collateral gain amount to be at least dustThreshold + 1 to trigger the _tend() function execution
4. Buffer percentage needs to be set to set _bufferPercentage to be any value (vulnerability occurs regardless of buffer percentage due to initial division truncation)



### External Pre-conditions

1. Oracle needs to report low collateral price to set _price (from COLL_PRICE_ORACLE) to be at most WAD / _available to ensure the vulnerability condition _available * _price < WAD is met
2. Stability Pool needs to accumulate small collateral gains to set collateral gain amount to be between dustThreshold + 1 and WAD / oracle_price to trigger vulnerability while remaining above dust threshold
3. Market conditions need to create small liquidations to set individual liquidation amounts to be at most vulnerability threshold values (e.g., < 1000 units when price = 1e15)
4. Network gas prices need to be low enough to set transaction costs to be at most profitable exploitation threshold to make the attack economically viable

### Attack Path

1. Attacker monitors strategy contract for collateral gains accumulation in the Stability Pool that meet vulnerability conditions where available * price < WAD
2. Attacker waits for vulnerable market conditions where oracle price and collateral gain amounts satisfy the mathematical condition _available * _price < 1e18 (confirmed by test results showing vulnerable scenarios like available=999, price=1e15)
3. Attacker calls tend() function to trigger the vulnerable auction price calculation at Strategy.sol:233: _available * _price / WAD * _bufferPercentage / WAD / WAD
4. Strategy executes vulnerable calculation causing precision loss where step2 (step1 / WAD): 0 due to integer division truncation, setting auction starting price to zero regardless of buffer percentage
5. Attacker verifies zero auction price by checking AUCTION.startingPrice() returns 0, confirming the precision loss vulnerability was successfully triggered
6. Attacker places minimal bid by calling AUCTION.bid(collateralToken, 1) with just 1 wei to win the auction at zero starting price
7. Attacker claims valuable collateral for essentially free, acquiring tokens worth potentially thousands of dollars while only paying gas fees and 1 wei bid amount



### Impact

The impact represents a critical financial vulnerability where attackers can acquire valuable collateral tokens for free through mathematical precision loss, resulting in complete loss of auction value for the strategy and its depositors.

### Mitigation

Replace the vulnerable calculation in Strategy.sol:233 to perform multiplication before division:
```solidity
// VULNERABLE (current implementation):
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);

// FIXED (multiplication before division):
AUCTION.setStartingPrice(_available * _price * _bufferPercentage / WAD / WAD / WAD);
```
