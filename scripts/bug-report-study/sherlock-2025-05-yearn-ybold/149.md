# Strategy constructor misconfiguration will block collateral liquidation, causing stuck funds for yBOLD users

### Summary

The strategy constructor initializes the auction for the strategy’s underlying asset (_asset) but later uses the collateral token (COLL) for auction operations. This mismatch will cause a permanent failure in collateral liquidation, resulting in stuck funds and inability to recover value for yBOLD users. As a consequence, the invariant that collateral losses must be coverable through auctions before fees are taken is broken, since auctions cannot be properly settled. A malicious or misconfigured strategy deployment will cause failed auctions and block withdrawals by locking collateral indefinitely.

### Root Cause

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L84-L85

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225-L246

In the strategy contract constructor (e.g., Strategy.sol: constructor), the auction is created and initialized for the strategy’s underlying asset (\_asset), but later auction interactions in \_tend() use the collateral token (COLL) instead. This token mismatch causes all auction-related calls (settle, kick, deposit) to fail because the auction only accepts the originally initialized token.


### Internal Pre-conditions

1. The strategy contract must be deployed with the auction created for the strategy’s underlying asset (\_asset) instead of the collateral token (COLL).

2. The strategy must accumulate a non-zero balance of the collateral token (COLL) within itself, e.g., from liquidations or collateral gains.

3. The \_tend() function must be triggered (e.g., by keeper or automated calls) when the strategy holds collateral (COLL) intended to be auctioned.

4. The auction contract expects interactions with the initialized token (\_asset), causing calls with COLL as argument to revert.


### External Pre-conditions

1. The external AuctionFactory contract must remain unchanged, continuing to create auctions strictly tied to a single token specified at creation.

2. The collateral token (COLL) price oracle must function normally, enabling \_tend() to attempt collateral liquidation based on current prices.

3. The external Stability Pool or other systems must deliver collateral gains (COLL) to the strategy, increasing the strategy’s COLL balance to a non-zero amount.

4. No external protocol adjustments must have been made to allow auctions to handle multiple tokens or to decouple auction token initialization from actual collateral.


### Attack Path

1. **Strategy contract** is deployed with `_asset` set to the strategy’s underlying token (e.g., BOLD).

2. In the constructor, the strategy creates an auction for `_asset` by calling `AUCTION_FACTORY.createNewAuction(_asset)`.

3. The strategy attempts to handle collateral tokens (`COLL`, e.g., ETH) by enabling them in the auction and depositing them later.

4. When `_tend()` is called (either by keeper or governance), it checks if there is an active auction for `COLL` and tries to settle it.

5. The strategy attempts to transfer collateral (`COLL`) to the auction contract and calls `AUCTION.kick(address(COLL))` to start the auction.

6. Since the auction was created only for `_asset` (BOLD), it does not recognize `COLL` and rejects all auction-related calls involving collateral tokens.

7. The auction interactions revert, causing `_tend()` to fail and collateral to remain locked within the strategy without liquidation.

8. This leads to stuck funds, inability to auction collateral, and broken protocol assumptions about collateral liquidation.

### Impact

The **yBOLD protocol** users and stakers suffer a severe operational impact because the **core invariant** that *collateral must be auctioned/liquidated properly to cover losses or rebalance the protocol* is broken.

* The **strategy cannot liquidate collateral tokens (COLL)** because the auction contract was created for the underlying asset (\_asset), not the collateral.
* This causes **all attempts to settle, kick, or interact with auctions on collateral to revert**, making collateral liquidation impossible.
* As a result, **collateral gains remain locked indefinitely** in the strategy contract without being auctioned off or converted back to the protocol’s asset.
* This leads to **funds getting stuck, stalled auctions, and inability to realize collateral value**, which could cascade into liquidity shortfalls or increased protocol risk during stress events.
* The **protocol’s expected flow to cover temporary or realized losses through auctions is broken**, violating the invariant that losses are covered by collateral liquidation before fees or losses are finalized.
* Ultimately, this could lead to **unrecoverable losses for the protocol and its users**, as collateral cannot be converted or rebalanced in downturns or liquidations.

No direct attacker gain here, but the protocol and its users are severely impacted by operational failure and potential loss of funds due to stuck collateral.

### Mitigation

* **Fix the auction initialization** to create the auction contract for the **correct token — the collateral token (COLL)** rather than the strategy’s underlying asset (\_asset).
  For example, replace:

  ```solidity
  AUCTION = AUCTION_FACTORY.createNewAuction(_asset);
  ```

  with:

  ```solidity
  AUCTION = AUCTION_FACTORY.createNewAuction(address(COLL));
  ```

* **Ensure all auction interactions (\_tend, \_emergencyWithdraw, etc.) consistently use the collateral token (COLL) when interacting with the auction contract.**

* Add **unit and integration tests** to verify that auctions can be kicked, settled, and collateral liquidated successfully without revert.

* Review and update documentation and comments to clarify that auctions are always tied to the collateral token, preventing future confusion or mismatches.

By aligning the auction contract and all related interactions to the collateral token, the protocol’s invariant of collateral liquidation coverage is restored, preventing stuck funds and ensuring robust loss management.
