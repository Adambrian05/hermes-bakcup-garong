# Vault Removal During Active Auction Leads to Permanent Loss of User Funds

### Summary

When a vault is removed from the Accountant while it has an active auction, profits from the auction become permanently inaccessible to `st-yBOLD `holders, resulting in direct financial loss to users.

### Root Cause

The Accountant's [removeVault](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L221) function immediately removes a vault without checking for active auctions or pending profits. Once removed, the strategy cannot report profits to the Accountant, breaking the profit distribution mechanism to `st-yBOLD `holders.

We can show this by this simple scenario : 
**Initial Setup:**

1- Users have deposited `BOLD` into `yBOLD` vault.
2- Some users have staked `yBOLD` into `st-yBOLD `to earn yield.
3- The strategy has deposited `BOLD` into the Liquity Stability Pool

**Liquidation Event:**

1- A liquidation occurs .
2- The strategy's `BOLD` balance is reduced (e.g., from 1,000,000 to 900,000 BOLD).
3- The strategy receives collateral (e.g., 50 WETH worth ~100,000 BOLD).

**Auction Initiation:**

The strategy claims the collateral via `_tend`:
```solidity
function _tend(uint256 /*_totalIdle*/) internal override {
    if (isCollateralGainToClaim()) claim();
    // ...
    uint256 _toAuction = COLL.balanceOf(address(this));
    // ...
    AUCTION.kick(address(COLL));
}
```
The auction begins for the 50 WETH

**Vault Removal:** As per Docs says : 

**All roles are trusted to modify the parameters they are authorized to manage on their respective contracts. However, if any role is able to set a value in a way that could result in the theft of depositor funds, this would be considered a valid finding.
**No role should be capable of stealing from depositors or permanently blocking withdrawals.****


```solidity 
A vault manager calls `removeVault` on the Accountant:

function removeVault(address vault) external virtual onlyVaultOrFeeManager {
    // ...
    vaults[vault] = false;
    // ...
}
```
The vault is immediately removed from the Accountant's registry.

**Auction Completion:**

The auction completes successfully
The strategy receives 95,000 BOLD from the auction.

**Failed Profit Reporting:**

The strategy attempts to report the 95,000 BOLD profit
The report fails because the vault is no longer registered:

```solidity
function report(...) public virtual onlyAddedVaults returns (...) {
    // Reverts due to onlyAddedVaults modifier
}

function _checkVaultIsAdded() internal view virtual {
    require(vaults[msg.sender], "vault not added");
}
```
As a result : 
**Blocked Distribution to st-yBOLD:**
```solidity
The Staker contract cannot claim rewards:
function _harvestAndReport() internal override returns (uint256 _totalAssets) {
    ACCOUNTANT.distribute(address(asset)); // This fails because no profits were reported
    // ...
}
```
- The 95,000 BOLD remains trapped in the strategy.
- `st-yBOLD `holders permanently lose access to these funds.

### Impact

This vulnerability directly causes financial loss to `st-yBOLD `holders. In our example, they lose 95,000 BOLD worth of value that they were entitled to receive.

The issue violates two key requirements from the documentation:

"When process_report is called on `yBOLD`, any gain must be fully minted as `yBOLD` to Accountant.sol, from which it will be distributed to `st-yBOLD.`"

"No role should be capable of stealing from depositors or permanently blocking withdrawals."

The vault manager effectively steals funds by preventing their distribution to the rightful recipients `st-yBOLD holders`.

### Mitigation

Implement a two-phase vault removal process:

- Mark the vault as "pending removal" but allow it to complete ongoing operations.
- Require confirmation that no auctions are active before finalizing removal
- you can also Add an emergency function for immediate removal that properly handles pending profits
Alternatively, modify the `removeVault` function to check for active auctions and either:

1- Prevent removal until auctions complete.
2- Force settlement of auctions and distribution of profits before removal.
