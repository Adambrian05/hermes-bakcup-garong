# Missing access control allows malicious strategy substitution in deployments mapping

## Description:
The `StakerFactory.sol` contract lacks access control on the `newStrategy()` function, allowing any user to overwrite legitimate strategy entries in the deployments mapping. This mapping serves as the primary registry for tracking deployed strategies by asset address. When a malicious actor creates a new strategy for an asset that already has an official strategy deployed, the new malicious strategy overwrites the existing entry, effectively hiding the legitimate strategy from discovery mechanisms that rely on this mapping.
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L46
```solidity
function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
    // ... strategy creation logic ...
    deployments[_asset] = address(_newStrategy); // Overwrites existing entry!
    return address(_newStrategy);
}
```
The `deployments` mapping uses a simple `asset => strategy` structure that cannot distinguish between official and malicious strategies, making it vulnerable to substitution attacks.

## Impact:
Users seeking to stake yBOLD may discover malicious strategies through the compromised deployments mapping, leading to loss of staking rewards or inability to properly unstake their yBOLD tokens

## Recommended Mitigation:
Add access control to `newStrategy()` function
