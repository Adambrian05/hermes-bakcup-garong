# Two-Dimensional Mapping Overwrite Vulnerability Enabling Silent Strategy Replacement in StakerFactory.sol

### Summary

Lack of validation in the newStrategy() function will cause silent strategy replacement and fund redirection for protocol users and integrators as any unauthorized actor will call newStrategy() with existing asset addresses to overwrite legitimate strategy mappings without detection, causing users to interact with malicious strategies instead of intended ones.

### Root Cause

In StakerFactory.sol:newStrategy() function there is a missing validation check before the deployments[_asset] = address(_newStrategy); assignment which allows unconditional overwriting of existing strategy mappings without verifying if a strategy already exists for the given asset, enabling silent replacement of legitimate strategies with malicious ones.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32

### Internal Pre-conditions

1. Factory needs to be deployed with valid management, performanceFeeRecipient, keeper, and emergencyAdmin addresses to enable strategy deployment functionality
2. At least one legitimate strategy needs to be deployed via newStrategy() to set deployments[_asset] to contain a valid strategy address for the target asset
3. Target asset contract needs to implement required interface functions (accountant(), decimals(), symbol(), name()) to allow strategy initialization to complete successfully
4. Attacker needs to identify existing asset addresses that have deployed strategies to target specific deployments[_asset] mappings for overwrite
5. No access control mechanism needs to be implemented on newStrategy() function to allow unauthorized callers to execute the overwrite attack
6. Factory contract needs to be in operational state with no paused or emergency modes that would prevent new strategy deployments

### External Pre-conditions

1. No external pre-conditions are required for this vulnerability - the attack can be executed at any time regardless of external protocol states, oracle prices, or network conditions

### Attack Path

1. Attacker identifies existing asset addresses with deployed strategies by querying the deployments mapping or monitoring NewStrategy events on the StakerFactory contract
2. Attacker calls newStrategy(targetAsset, "Malicious Strategy") function on StakerFactory contract without any authorization checks
3. StakerFactory deploys a new malicious strategy contract via new Strategy(targetAsset, "Malicious Strategy") and configures it with factory parameters
4. StakerFactory unconditionally executes deployments[targetAsset] = address(maliciousStrategy) assignment, silently overwriting the existing legitimate strategy mapping
5. StakerFactory emits NewStrategy event for the malicious strategy without any indication that an existing strategy was replaced
6. Users and protocols querying factory.deployments(targetAsset) now receive the malicious strategy address instead of the legitimate one
7. Legitimate strategy becomes completely orphaned and untrackable through the factory, with isDeployedStrategy(originalStrategy) returning false or reverting
8. All future interactions intended for the legitimate strategy are redirected to the attacker-controlled malicious strategy, enabling fund theft, manipulation, or protocol disruption

### Impact

The protocol users and integrators suffer an approximate loss of 100% of funds deposited through factory-referenced strategies. The attacker gains complete control over user funds by redirecting all interactions to malicious strategy contracts, enabling unlimited fund extraction, yield manipulation, and protocol disruption without detection.

```solidity
contract StrategyOverwriteExploit {
    StakerFactory public immutable factory;
    address public immutable targetAsset;
    address public originalStrategy;
    address public maliciousStrategy;
    
    event StrategyOverwritten(address indexed asset, address oldStrategy, address newStrategy);
    
    constructor(address _factory, address _targetAsset) {
        factory = StakerFactory(_factory);
        targetAsset = _targetAsset;
    }
    
    function executeOverwrite() external {
        originalStrategy = factory.deployments(targetAsset);
        require(originalStrategy != address(0), "No existing strategy found");
        
        maliciousStrategy = factory.newStrategy(targetAsset, "Malicious Strategy");
        
        address currentStrategy = factory.deployments(targetAsset);
        require(currentStrategy == maliciousStrategy, "Overwrite failed");
        require(currentStrategy != originalStrategy, "Strategy not replaced");
        
        emit StrategyOverwritten(targetAsset, originalStrategy, maliciousStrategy);
    }
    
    function verifyExploit() external view returns (bool success) {
        address currentStrategy = factory.deployments(targetAsset);
        return (currentStrategy == maliciousStrategy && 
                currentStrategy != originalStrategy && 
                originalStrategy != address(0));
    }
}
```

### Mitigation

1. Add Existence Validation
```solidity
function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
    require(deployments[_asset] == address(0), "Strategy already exists for this asset");
    
    IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));
    // ... rest of function
}
```
2. Implement Access Control
```solidity
function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
    require(msg.sender == management, "Only management can deploy strategies");
    require(deployments[_asset] == address(0), "Strategy already exists for this asset");
    
    // ... rest of function
}
```
