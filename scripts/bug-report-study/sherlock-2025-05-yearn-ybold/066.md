# Faulty fee logic will unfairly reduce performance fees for the vault

### Summary

Isolated strategy-level loss accounting in `Accountant.report` will cause incorrect fee deductions for the vault as it fails to consider cross-strategy losses, leading to undercharged performance fees during multi-strategy downturns.

### Root Cause

In `Accountant.sol`, the fee calculation in `report()` only checks if the vault's total assets are below its total supply (`assets < supply`) https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L182-L185 to determine whether to take fees. This is a mistake because:
1. It doesn't account for losses from other strategies that may have already eroded the vault's value.
2. The current logic allows strategies to report gains and take full fees even if the vault is in an overall loss state due to other strategies' underperformance.

### Internal Pre-conditions

1. **Multiple loss-making strategies**: At least two strategies must report losses in the same epoch.
2. **One profitable strategy**: At least one strategy must report gains while others report losses.
3. **Vault in deficit**: The vault's total assets must be below total supply due to cumulative losses.

### External Pre-conditions

- None. The issue manifests purely based on the vault's internal accounting.

### Attack Path

1. **Strategy A reports loss**: A strategy suffers a 10% loss, reducing the vault's assets below its total supply.
2. **Strategy B reports gain**: Another strategy reports a 5% gain while the vault is still in an overall loss state.
3. **Faulty fee calculation**: The accountant incorrectly allows Strategy B to take full performance fees (100% of gains) despite the vault's net loss position.

### Impact

- **Vault loss**: The protocol loses performance fees that should have been withheld during overall loss periods.
- **Unfair advantage**: Strategies can "game" reporting by front-running loss events to capture fees.
- **Economic imbalance**: Long-term vault profitability is reduced as fees aren't properly aligned with performance.

### PoC

1. **Setup**: Vault has:
   - Total supply: 1000 shares
   - Strategy A (loss): Reports 100 loss (assets now 900)
   - Strategy B (gain): Reports 50 gain (assets now 950)
2. **Faulty execution**:
   ```solidity
   // In Accountant.report():
   if (assets < supply) { // 950 < 1000 → true
       totalFees = gain < needed ? 0 : gain - needed; // 50 < 50 → false → fees = 0
   }
```
Result: No fees taken despite Strategy B reporting gains during a loss period.

### Mitigation

Modify fee logic to track vault-level P&L across strategies:
```solidity
// Track vault-level cumulative gains/losses
uint256 vaultCumulativeGains;
uint256 vaultCumulativeLosses;

function report() external returns (uint256 totalFees, uint256) {
    // Update vault-level tracking
    if (gain > 0) vaultCumulativeGains += gain;
    if (loss > 0) vaultCumulativeLosses += loss;
    
    // Only take fees if vault is net profitable
    if (vaultCumulativeGains > vaultCumulativeLosses) {
        totalFees = gain;
    }
}
```
