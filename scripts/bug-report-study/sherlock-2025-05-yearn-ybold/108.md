# Users can override deployed Staker strategy

### Summary

In the StakerFatory any user can call the `newStrategy` function, as it is missing the validation necessary to only allow the management to be able to create new strategies. This is problematic as it would make the currently used strategy not considered deployed by the contract.

### Root Cause

In `StakerFactory.newStrategy.sol:32` the `onlyManagement` modifier is not used, contrary to the StrategyFactory contract:

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32-L48
```solidity
    function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
        // tokenized strategies available setters.
        IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));

        _newStrategy.setPerformanceFeeRecipient(performanceFeeRecipient);

        _newStrategy.setKeeper(keeper);

        _newStrategy.setPendingManagement(management);

        _newStrategy.setEmergencyAdmin(emergencyAdmin);

        emit NewStrategy(address(_newStrategy), _asset);

        deployments[_asset] = address(_newStrategy);
        return address(_newStrategy);
    }
```

### Internal Pre-conditions

No internal pre-conditions needed.

### External Pre-conditions

No external pre-conditions needed.

### Attack Path

1. Management deploys a staker strategy used for staking yBOLD.

2. `deployments[_asset]` is set to the address of the strategy, thus the address will be reported as a deployed strategy by `isDeployedStrategy`.

3. Yield is accrued by the strategy.

4. Another user also calls `newStrategy`, resetting the `deployments[_asset]` to a different address, now `isDeployedStrategy` will not consider the actual strategy used for staking yBOLD deployed.

### Impact

As a result, the actual strategy used for staking yBOLD will not be reported as deployed by the StakerFactory. This is problematic as third-party protocols, relying on querying the correct Staker strategy currently used for staking yBOLD will be compromised.

_No response_

### Mitigation

Consider allowing only management to call `newStrategy`.
