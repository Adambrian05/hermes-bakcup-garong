# Anyone will trigger unintended side effects via claim()

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L185

**Summary**
The unrestricted access to `claim()` will cause unintended asset withdrawals from the `StabilityPool` as any external caller will trigger `withdrawFromSP(0, true)`.

**Root Cause**
In `Strategy.sol#L185`, `claim()` is publicly callable and internally calls `SP.withdrawFromSP(0, true)`, which may harvest gains or cause accounting changes.

**Internal Pre-conditions**

1. `claim()` is called by any externally owned account.

**External Pre-conditions**

1. `StabilityPool.withdrawFromSP()` performs gain distribution or collateral transfers even for `amount=0`.

**Attack Path**

1. Attacker calls `claim()` repeatedly.
2. Each call triggers `withdrawFromSP(0, true)`.
3. Gains are harvested or state is mutated unexpectedly.

**Impact**
The protocol suffers unexpected state changes or reward distribution skew. The attacker may grief the system or frontrun expected rewards.

**PoC**

```solidity
strategy.claim(); // triggers SP.withdrawFromSP(0, true)
```

**Mitigation**
Restrict `claim()` to trusted roles (e.g. `onlyManagement`) or make sure `withdrawFromSP()` with 0 has no side effects.
