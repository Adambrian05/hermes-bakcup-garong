# Predictable Auction Pricing Enables MEV Front-Running, Leading to Suboptimal Collateral Sales

### Summary

The `LiquityV2SPStrategy` calculates auction starting prices using real-time on-chain oracle data, creating a predictable pricing model exploitable by MEV bots. Attackers can front-run `tend()` transactions to trigger auctions at artificially inflated/deflated prices, then immediately arbitrage the collateral on external markets. This results in **consistent value leakage** from the protocol to adversarial bots.


### Root Cause

1. **Transparent Pricing Logic**:  
   Auction starting prices derive directly from the latest oracle price and a static `bufferPercentage`. Bots algorithmically predict auction timing and pricing.  
   ```solidity  
   (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();  
   AUCTION.setStartingPrice(_available * _price * bufferPercentage / WAD);  
   ```  
   https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L234

2. **Oracle Latency Exploitation**:  
   MEV bots monitor pending `tend()` transactions. If the oracle price updates mid-block, bots front-run to: Force auctions at stale prices, then arbitrate post-auction at updated rates.

### Attack Path


- **Collateral**: 1,000 wstETH (Value = $2.5M at $2,500/wstETH).  
- **Oracle Update**: Price drops to $2,400 mid-block.  

### Attack Flow  
1. **Front-Run**:  
   - Bot detects pending `tend()` and front-runs it, triggering an auction at the stale $2,500 price.  
   - Starting Price = $2,500 * 1.1 (buffer) = $2,750/wstETH.  
2. **Back-Run**:  
   - After the oracle updates, bot buys wstETH externally at $2,400.  
   - Sells to the auction at $2,750, profiting $350/wstETH → **Total Profit: $350,000**.  


### Impact

- **Loss per Auction**: 1-5% of collateral value siphoned via MEV.
