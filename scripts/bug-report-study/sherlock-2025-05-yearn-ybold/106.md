# Strategy missing gains from StabilityPool will underreport total assets leading to loss of value for depositors

## Summary

**Missing accounting for collateral and yield gains in _harvestAndReport will cause a loss of value for depositors as the strategy will underreport total assets, leading to incorrect profit/loss calculations.**

## Root Cause

In `Strategy.sol:252-269` the `_harvestAndReport()` function only accounts for the asset balance and the compounded BOLD deposit in the Stability Pool, but fails to account for the collateral gains (`getDepositorCollGain`) and yield gains (`getDepositorYieldGain`) that are available to the strategy. It only accounts for `getCompoundedBoldDeposit` from the Stability Pool.
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L208-L215
```solidity

253:         if (!TokenizedStrategy.isShutdown()) {
```

These values represent additional assets that the strategy has earned but are not being accounted for in the total assets calculation.

## Internal Pre-conditions

1. The strategy must have deposited assets into the Stability Pool
2. The Stability Pool must have generated collateral gains or yield gains for the strategy
3. The `_harvestAndReport()` function is called to calculate total assets

## External Pre-conditions

1. Liquidations must have occurred in the Liquity protocol, generating collateral gains for Stability Pool depositors
2. Yield distribution must have occurred in the Stability Pool, generating yield gains for depositors

## Attack Path

1. **Strategy deposits assets into the Stability Pool**
2. **Liquidations occur in Liquity, generating collateral gains for the strategy**
3. **Yield is distributed to Stability Pool depositors, generating yield gains for the strategy**
4. **The `report(...)` is called on the strategy, it will call `_harvestAndReport()` that will get the new total assets by doing following but doesn't account for these gains**
5. **The strategy reports lower total assets than it actually has access to**
6. **When profit/loss is calculated, the strategy may report a loss or lower profit than it should**
7. **Depositors receive fewer shares or suffer a loss due to the underreporting**

## Impact

The depositors suffer a loss of value proportional to the uncounted collateral and yield gains. This loss can be significant if large liquidations occur in the Liquity protocol or if substantial yield is distributed. The strategy effectively undervalues its position, which directly impacts the share price and the value that depositors can withdraw.

In the worst case, if the strategy reports a loss when it should have reported a profit, depositors may lose a significant portion of their potential gains.

## PoC

Consider the following scenario:

1. Alice deposits 100 BOLD tokens into yBold which then deposits to the strategy
2. The strategy deposits these tokens into the Stability Pool
3. Liquidations occur in Liquity, generating 10 WETH  in collateral gains for the strategy
4. The Stability Pool distributes 5 BOLD in yield gains to the strategy
5. When `_harvestAndReport()` is called, it only accounts for:
   - Asset balance: 0 BOLD (all deposited)
   - Compounded BOLD deposit: 100 BOLD
   - Total reported: 100 BOLD
6. The actual assets available to the strategy are:
   - Asset balance: 0 BOLD
   - Compounded BOLD deposit: 100 BOLD
   - Collateral gains: 10 WETH (worth ~20 BOLD at current exchange rate)
   - Yield gains: 5 BOLD
   - Total actual: 125 BOLD equivalent
7. The strategy underreports its assets by 25 BOLD (20% of its actual value)
8. When Alice withdraws, she receives only 100 BOLD instead of her fair share of 125 BOLD

## Mitigation

Update the `estimatedTotalAssets()` function to include the value of collateral gains and yield gains:

```solidity
function estimatedTotalAssets() public view returns (uint256) {
    uint256 boldBalance = asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this)) + SP.getDepositorYieldGain(address(this));
    
    // Convert collateral gains to BOLD equivalent using price oracle
    uint256 collGain = SP.getDepositorCollGain(address(this));
    if (collGain > 0) {
        (uint256 collPrice, bool isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
        if (!isOracleDown && COLL_PRICE_ORACLE.priceSource() == IPriceFeed.PriceSource.primary) {
            // Convert collateral value to BOLD equivalent
            // This assumes BOLD price is 1:1 with USD for simplicity
            // In a real implementation, you would need to get the BOLD price as well
            boldBalance += collGain * collPrice / WAD;
        }
    }
    
    // Also account for any collateral in the strategy or auction contract
    uint256 collInStrategy = COLL.balanceOf(address(this));
    uint256 collInAuction = COLL.balanceOf(address(AUCTION));
    if (collInStrategy > 0 || collInAuction > 0) {
        (uint256 collPrice, bool isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
        if (!isOracleDown && COLL_PRICE_ORACLE.priceSource() == IPriceFeed.PriceSource.primary) {
            boldBalance += (collInStrategy + collInAuction) * collPrice / WAD;
        }
    }
    
    return boldBalance;
}
```

This ensures that all assets available to the strategy are properly accounted for, including collateral gains and yield gains from the Stability Pool, as well as any collateral held by the strategy or in the auction contract.
