# Creating a strategy overrides previous one

## Summary
In both `StakerFactory` and `StrategyFactory`, creating a new strategy with the same asset overrides the `deployments` mapping, allowing only the last created strategy to return `true` on `isDeployedStrategy`. 
## Description
Strategy creation method looks like this
```solidity
    function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
 
        IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));

        _newStrategy.setPerformanceFeeRecipient(performanceFeeRecipient);
        _newStrategy.setKeeper(keeper);
        _newStrategy.setPendingManagement(management);
        _newStrategy.setEmergencyAdmin(emergencyAdmin);

        deployments[_asset] = address(_newStrategy);

        return address(_newStrategy);
    }
```
A new strategy contract is deployed, managerial roles are set and then a `deployments` mapping is overriden. This mapping is used in `isDeployedStrategy` to check whether an address is indeed a deployed strategy. 

```solidity
    function isDeployedStrategy(
        address _strategy
    ) external view returns (bool) {
        address _asset = IStrategyInterface(_strategy).asset();
        return deployments[_asset] == _strategy;
    }
```
Yearn vaults are designed to have more than 1 strat [as per their docs](https://docs.yearn.fi/developers/smart-contracts/V2/vault#:~:text=Vaults%20are%20not%20limited%20to%20a%20single%20Strategy%2C%20they%20can%20have%20as%20many%20Strategies%20as%20can%20be%20designed), however the current design allows only 1 strategy to return `true` at a time and once a new one is created, older ones can never populate the `deployments` mapping again, always returning `false` in `isDeployedStrategy`.

In the current scope there are no critical methods that rely on this data correctness, however it is expected that these contracts will be integrated into a broader Yearn scope. Both internal and external integrations that rely on this method returning valid data will be flawed. Furthermore, the design is in direct contradiction with the design described in the documentation. 

Drop this test in `DualToken.t.sol`
```solidity
    function test_evilStrat() external {
        vm.startPrank(management);
        address goodStrat = stakerFactory.newStrategy(address(vault), "Staked yBOLD Strategy");
        assert(stakerFactory.isDeployedStrategy(address(goodStrat)));
        vm.stopPrank();

        address user = address(0x1337);
        vm.startPrank(address(user));
        address evilStrat = stakerFactory.newStrategy(address(vault), "Staked yBOLD Strategy");
        assert(stakerFactory.isDeployedStrategy(address(evilStrat)));
        assert(!stakerFactory.isDeployedStrategy(address(goodStrat)));
        vm.stopPrank();

    }
```
## Impact 
Broken accounting, unexpected return values
## Mitigation 
Allow multiple strategy deployments
