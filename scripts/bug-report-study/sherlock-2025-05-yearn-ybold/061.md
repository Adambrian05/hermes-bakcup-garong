# Temporary losses during auctions cause incorrect fee calculations in Accountant

## Description:
The `Accountant.sol` contract reduces or eliminates performance fees when the vault reports a loss, even if the loss is temporary. In the context of `LiquityV2SPStrategy`, temporary losses frequently occur during the normal operational cycle when collateral is being auctioned. The `estimatedTotalAssets()` function in `Strategy.sol` does not account for collateral that has been sent to auction but not yet sold, causing the strategy to appear to have losses when it actually has assets being converted.
The problematic logic in `Accountant.sol`:
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L176
```solidity
// 100% performance fee
totalFees = gain;

// Only take fee if there's no loss.
uint256 supply = vault.totalSupply();
uint256 assets = vault.totalAssets();
if (assets < supply) {
    uint256 needed = supply - assets;
    totalFees = gain < needed ? 0 : gain - needed;
}
```
The `estimatedTotalAssets()` function only accounts for BOLD on the strategy's balance and in the stability pool:
```solidity
function estimatedTotalAssets() public view returns (uint256) {
    return asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this));
}
```
This does not include:
- Unclaimed collateral rewards in the stability pool
- Collateral that has been transferred to the auction contract but not yet sold

## Impact:
Protocol permanently loses performance fees during normal operational cycles
Reduced rewards flowing to st-yBOLD stakers affects protocol economics
