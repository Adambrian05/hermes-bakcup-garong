# Incorrect Fee Calculation Logic in `report()` Function

### Summary

The `report()` function in the Accountant contract contains flawed logic for calculating performance fees when a vault is underwater (`assets < supply`). The current implementation does not properly account for simultaneous gains and losses in the same report, potentially leading to incorrect fee assessments.

### Root Cause

The issue stems from the fee calculation logic:

```solidity
uint256 supply = vault.totalSupply();  
uint256 assets = vault.totalAssets();  
if (assets < supply) {  
    uint256 needed = supply - assets;  
    totalFees = gain < needed ? 0 : gain - needed;  
}  
```
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L180

The fee calculation does not differentiate between profit and loss. The function responsible for computing protocol fees uses the gross asset value (i.e., totalAssets) without checking whether the vault's value has increased compared to its principal or previous state. This oversight allows fee extraction even when the vault has depreciated.

### Internal Pre-conditions

- The protocol must define a `feeRate` and have logic that collects fees based on a function of `totalAssets` or similar.

- There must be a mechanism for the protocol to withdraw or accumulate protocol fees during asset operations (e.g., on position reduction, closure, or claiming rewards).

- `totalAssets` reflects the current vault value but does not compare it to the user's original deposited amount or principal.

### External Pre-conditions

- A loss must occur in the vault due to adverse market conditions or poor performance of the underlying position.

- A user action (e.g., reduction or closure of position) must trigger the fee logic.

- The vault must not validate whether the current value is greater than the initial investment (profit) before taking a fee.

### Attack Path

1. A user deposits assets into the vault, e.g., $10,000.

2. The vault’s position decreases in value to $9,000 due to adverse market performance.

3. The user initiates a reduction or full exit of their position.

4. The fee logic calculates a protocol fee based on the $9,000 gross value (e.g., 1%), leading to a $90 protocol fee.

5. The user receives only $8,910, absorbing the entire $1,090 loss, while the protocol incorrectly profits.

### Impact

- Users lose more than the actual loss due to unjustified fee extraction.

- Undermines user trust and can result in user churn or reputational damage.

- Creates an inconsistent fee model that disincentivizes usage under volatility.

### Mitigation

- Adjust the fee logic to charge fees only on net gains, i.e., when the vault's current value exceeds the principal or prior state.

- Implement a check:

```solidity
if (currentAssets > principal) {
    uint256 profit = currentAssets - principal;
    uint256 protocolFee = profit * feeRate / 1e18;
   
}
```
- Ensure that any fee charged is derived from realized profit and not on gross value when losses are present.
