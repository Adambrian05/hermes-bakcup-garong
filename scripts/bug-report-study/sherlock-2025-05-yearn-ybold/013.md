# Management will permanently whitelist bad actors via setAllowed()

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L162

**Summary**
The lack of revocation in `setAllowed()` will cause permanent access control bypasses for the strategy as management will allow malicious depositors indefinitely.

**Root Cause**
In `LiquityV2SPStrategy.sol:60`, `setAllowed()` only allows `true` assignment and lacks a revoke mechanism.

**Internal Pre-conditions**

1. Management calls `setAllowed(addr)` for an address.

**External Pre-conditions**

1. Malicious address is added to the `allowed` list.

**Attack Path**

1. Management mistakenly or maliciously calls `setAllowed(badActor)`.
2. Bad actor retains access forever with no way to revoke.

**Impact**
The protocol suffers from a permanently trusted user who may grief or game deposits. The attacker gains long-term access privileges.

**Mitigation**
Add a `setAllowed(address, bool)` function to support both add and remove flows.
