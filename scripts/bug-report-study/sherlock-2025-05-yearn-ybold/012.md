# User can manipulate vaults assets and supply in order to make the pricePerShare expensive than it actually is.

### Summary
The vault's fee calculation mechanism is vulnerable to price manipulation attacks due to incorrect comparison between `totalSupply()` and `totalAssets()`. This can lead to incorrect fee assessments and potential fund extraction through manipulated price per share values.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L180C1-L181C50

### Root Cause
The root cause lies in the fee calculation logic in the Accountant contract where it directly compares `totalSupply()` and `totalAssets()` without considering the price per share. This assumes a 1:1 relationship between vault tokens and underlying assets, which can be manipulated.

You can checkout this article [The CREAM Finance Hack](https://www.halborn.com/blog/post/explained-the-cream-finance-hack-october-2021)

### Internal Pre-conditions
1. The vault must have an active strategy with reported gains
2. The vault must have a non-zero total supply
3. The vault must allow direct asset deposits without minting new shares

### External Pre-conditions
1. Attacker must have access to sufficient capital (can be obtained through flash loans)
2. The vault must have enough liquidity to execute the attack
3. The vault's price per share must be manipulable through large deposits/withdrawals

### Attack Path
1. Attacker withdraws almost all assets from the vault, leaving minimal vault tokens in circulation
2. Attacker deposits a large amount of assets directly into the vault without minting new shares
3. This manipulation increases the price per share significantly
4. When the strategy reports gains, the Accountant's fee calculation will be incorrect due to the manipulated price per share
5. The Accountant will calculate fees based on the manipulated values, potentially extracting funds incorrectly

### Impact
- **Severity**: High
- **Impact**: Direct loss of funds through incorrect fee calculations
- **Likelihood**: Medium (requires significant capital but is technically feasible)

### PoC
```solidity
// 1. Initial state
uint256 initialSupply = vault.totalSupply(); // e.g., 1,000,000 vault tokens
uint256 initialAssets = vault.totalAssets(); // e.g., 1,000,000 USDC

// 2. Attacker withdraws almost all assets
vault.withdraw(initialAssets - 1); // Leaves 1 USDC in vault

// 3. Attacker deposits large amount without minting new shares
uint256 attackAmount = 1,000,000 USDC;
vault.deposit(attackAmount);

// 4. New state
uint256 newSupply = vault.totalSupply(); // Still ~1,000,000 vault tokens
uint256 newAssets = vault.totalAssets(); // Now ~1,000,001 USDC

// 5. Strategy reports gains
uint256 reportedGain = 100,000 USDC;
accountant.report(strategy, reportedGain);

// 6. Fee calculation in Accountant
if (assets < supply) {
    uint256 needed = supply - assets;
    totalFees = gain < needed ? 0 : gain - needed;
}
// Due to manipulated price per share, this calculation will be incorrect
```
