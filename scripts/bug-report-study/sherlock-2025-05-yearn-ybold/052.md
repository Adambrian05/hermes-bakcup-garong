# Third party auction spam blocks `tend()` permanently

### Summary

Once `AUCTION.enable(address(COLL))` has been called, anyone can deposit 1 wei of `COLL` (or call `IAuction.kick`) into the auction. Because

```solidity
if (AUCTION.available(address(COLL)) > 0) return false;
```

in `tendTrigger()`, keep-bots will forever see an active auction and never call `tend()` again. The strategy stops claiming and auctioning new collateral, leading to continuous loss reports and eventual vault insolvency.

### Root Cause

- `tendTrigger()` refuses to run whenever `AUCTION.available(COLL) > 0`.
- There is no access control on sending COLL to the auction or on `IAuction.kick`, so a malicious third party can spam the auction.

### Internal Pre-conditions

Strategy has already called `AUCTION.enable(COLL)` in its constructor.

### External Pre-conditions

None. Any on-chain actor holding ≥1 wei of `COLL` can trigger it.

### Attack Path

1. Wait for a deployed strategy to finish construction (so its auction is enabled).
2. Transfer 1 wei of `COLL` to the auction contract
3. Alternatively, call `IAuction.kick(COLL)` if permitted by the auction.
4. From that point on, AUCTION.available(COLL) ≥ 1, so `_tendTrigger()` always returns `false`. No keeper will ever call `tend()` again.

### Impact

**Perma-DOS of a time-sensitive function:** `tend()` never executes, so newly claimed collateral remains locked.

**Continuous fund drain:** On each liquidation, unclaimed collateral means the strategy’s BOLD balance shrinks; the vault records perpetual losses.

No privileged role needed. Any external actor can perform this attack.

Under Sherlock rules, this is a DOS of a time-sensitive function without external conditions—the highest severity category.
