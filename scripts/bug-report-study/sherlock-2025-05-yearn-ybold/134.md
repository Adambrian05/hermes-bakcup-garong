# Strategy doesn't take yield into account for total assets leading to wrong reported profits and losses

### Summary

According to the guide to build strategies, its common practice to claim rewards such that total assets are adequately increased or decreased before the report in `_harvestAndReport`

https://docs.yearn.fi/developers/v3/strategy_writing_guide#_harvestandreport

However its not followed here, leading to wrong reported amounts when the keeper calls `Strategy.report` as is, which would return the wrong amounts that doesn't contain extra yield from the stability pool affecting profits and losses from the reported value.



### Root Cause

In Strategy.sol

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L208-L215

We see that `estimatedTotalAssets` is called 

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L105-L107

Which in turn relies on `getCompoundedBoldDeposit` from the stability pool to get the total assets.

However doing this directly is wrong as the stability pool doesn't take into account the extra yield earned and return correctly.

We see there is a `claim` function which does update the yield into the net asset value but its not called in the Keeper's function.

```solidity
    function getCompoundedBoldDeposit(address _depositor) public view override returns (uint256 compoundedDeposit) {
        uint256 initialDeposit = deposits[_depositor].initialValue; //@audit relied here 
        if (initialDeposit == 0) return 0;

        Snapshots storage snapshots = depositSnapshots[_depositor];

        uint256 scaleDiff = currentScale - snapshots.scale;

        // Compute the compounded deposit. If one or more scale changes in `P` were made during the deposit's lifetime,
        // account for them.
        // If more than `MAX_SCALE_FACTOR_EXPONENT` scale changes were made, then the divisor is greater than 2^256 so
        // any deposit amount would be rounded down to zero.
        if (scaleDiff <= MAX_SCALE_FACTOR_EXPONENT) {
            compoundedDeposit = initialDeposit * P / snapshots.P / SCALE_FACTOR ** scaleDiff;
        } else {
            compoundedDeposit = 0;
        }
    }
```

We now see that the compoundedBoldDeposit relies heavily on the initial deposit value which is updated only from `withdrawFromSP` and that the view function doesn't compute the yield owed on its own.

The issue is more pressing if its a decentralized keeper as it would likely not call `claim()` manually like in the test cases.

### Mitigation

simply claim before returning total assets in `_harvestAndReport`
```diff
    function _harvestAndReport() internal override returns (uint256 _totalAssets) {
        if (!TokenizedStrategy.isShutdown()) {
+           claim();
            uint256 _toDeploy = asset.balanceOf(address(this));
            if (_toDeploy > dustThreshold) _deployFunds(_toDeploy);
        }

        return estimatedTotalAssets();
    }
```
