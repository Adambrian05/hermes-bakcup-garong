# The `Strategy` contract does not implement functions to call sweep() or disable() on the auction contract

### Summary

The `AuctionFactory` sets the strategy as the `governance` of the Auction contract. The issue is that the strategy contract does not implement any method to invoke the governance only functions `sweep()` and `disable()` in the Auction. As a result, those functions are permanently inaccessible.

### Root Cause

The [createNewAuction call](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/Strategy.sol#L84) in the strategy's constructor,[ sets the strategy contract](https://github.com/yearn/tokenized-strategy-periphery/blob/8442563a8d2b7a71057c76bdcead9b346927c301/src/Auctions/AuctionFactory.sol#L31-L40) as the `governance` for the auction contract. 

The issue is that the strategy contract lacks functions to invoke `Auction.sweep()` or `Auction.disable()`.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

None

### Impact

Tokens stuck in the Auction contract cannot be recovered via `sweep()`. 

The auction also cannot be disabled via `disable()`. This prevents emergency deactivation in the event of a discovered vulnerability in the `Auction` contract.

### PoC

_No response_

### Mitigation

Implement access controlled functions in the strategy contract to call `sweep()` and `disable()`
