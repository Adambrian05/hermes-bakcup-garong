# Incorrect Auction Starting Price Calculation in `Strategy.sol::_tend` Due to Double WAD Division Leads to Loss of Fund

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241
## Description
In the `LiquityV2SPStrategy` contract, there is a critical mathematical error in the calculation of the auction starting price. The issue occurs in the `tend()` function where the starting price for the auction is set using the `setStartingPrice()` method .

The problematic line is (line 264):

```solidity
 File: src\Strategy.sol
248:     function _tend(
249:         uint256 /*_totalIdle*/
250:     ) internal override {
251:         if (isCollateralGainToClaim()) claim();
252:         if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));  
253: 
254:         uint256 _toAuction = COLL.balanceOf(address(this));
255:         uint256 _available = COLL.balanceOf(address(AUCTION)) + _toAuction;
256:         if (_available > dustThreshold) {
257:             (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
258:             uint256 _bufferPercentage = bufferPercentage;
259:             if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
260:                 _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
261:             }
262: 
263:             // slither-disable-next-line divide-before-multiply
264:             AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction 
265: 
266:             COLL.safeTransfer(address(AUCTION), _toAuction);
267:             AUCTION.kick(address(COLL));
268:         }
269:     }

```

The calculation incorrectly divides by `WAD` (which equals 1e18) three times:
1. Once to normalize `_price` (which is likely in WAD precision)
2. Once to normalize `_bufferPercentage` (which is also in WAD precision)
3. An additional, unnecessary division by `WAD`

This extra division by `WAD` causes the starting price to be set 1e18 times lower than intended. As demonstrated in the test, this results in a starting price of just 56 wei, while the amount needed for the auction is 55999999999999999999 wei (approximately 56e18 wei).
## Impact
The severe undervaluation of the starting price means that auctions will start at an extremely low price, potentially allowing attackers to purchase collateral at a tiny fraction of its actual value, resulting in significant loss of funds for users.

The issue is demonstrated in the `test_StartingPriceBug()` test function, which shows:

1. A user deposits 100e18 tokens into the strategy
2. The test simulates a collateral gain scenario
3. The keeper calls `tend()`, which claims the collateral gain and kicks off an auction
4. The test then checks the auction's starting price and the amount needed
5. The console output shows:
   - Starting Price: 56 (wei)
   - Amount Needed: 55999999999999999999 (approximately 56e18 wei)

This proves that the starting price is 1e18 times lower than it should be, making it trivial for anyone to purchase the collateral at an extremely undervalued price.

## Recommendation
Remove the extra division by `WAD` in the starting price calculation:

```diff
- AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
+ AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD);
```
