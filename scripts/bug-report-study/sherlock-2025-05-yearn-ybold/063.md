# Auction Settlement DoS via Direct Token Transfers

### Summary

The auction settlement mechanism in `Strategy.sol `is vulnerable to a `denial-of-service` attack. An attacker can prevent auction settlement by directly transferring a small amount of collateral tokens to the auction contract, causing the settlement condition to never be satisfied.

### Root Cause

The strategy settles auctions using the following condition:

`if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));` This condition requires that `AUCTION.available(address(COLL)) `returns zero, which represents the total balance of collateral tokens in the auction contract.

As we can see , The `available` function likely returns the total balance of tokens in the auction contract, not just those that are part of the active auction.

### Attack Path

A malicious user who Acquire a minimal amount of the collateral token `(COLL)` can : 
- Obtain the auction contract's address by calling `strategy.AUCTION()`
- Transfer tokens directly to the auction contract using `COLL.transfer(auctionAddress, amount)`.

This transfer would make `AUCTION.available(address(COLL))` return a non-zero value, preventing the settlement condition from ever being satisfied.

Code Snippet : the [_tend](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225) : 

```solidity
 function _tend(
        uint256 /*_totalIdle*/
    ) internal override {
        if (isCollateralGainToClaim()) claim();
        if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));

        uint256 _toAuction = COLL.balanceOf(address(this));
        uint256 _available = COLL.balanceOf(address(AUCTION)) + _toAuction;
        if (_available > dustThreshold) {
            (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
            uint256 _bufferPercentage = bufferPercentage;
            if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
                _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
            }

            // slither-disable-next-line divide-before-multiply
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction

            COLL.safeTransfer(address(AUCTION), _toAuction);
            AUCTION.kick(address(COLL));
        }
    }

```

### Impact

- Permanent DoS: The active auction can never be settled through the normal mechanism.
- Blocked New Auctions: New auctions cannot be started as `setStartingPrice`reverts if there's an active auction.
- Trapped Collateral: Collateral claimed from the Stability Pool becomes trapped in the strategy, unable to be auctioned.
- Reduced Yield: The strategy cannot convert collateral to BOLD, reducing yield for users.

### Mitigation

Modify the auction `settlement` logic to not rely solely on the `available` function returning zero. Consider these options:

- Time-Based Settlement: Add a timeout mechanism to force settlement after a certain period.
- Manual Settlement Function: Add a function that allows authorized parties to manually settle an auction.
- Track Auction Tokens Separately: Modify the auction contract to distinguish between tokens that are part of the active auction and those that were directly transferred.
