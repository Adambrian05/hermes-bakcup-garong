# Lack of Access Control and Overwrite Vulnerability in newStrategy Function of StakerFactory

### Summary

The newStrategy function in the StakerFactory contract lacks access control, allowing any external user to deploy new strategy contracts. Additionally, the function overwrites the existing deployment mapping for a given asset without any checks, enabling replacement of previously deployed strategies. This combination poses serious security and management risks.

### Root Cause

The newStrategy function does not implement any access control modifier, making it publicly callable by anyone.

The deployments mapping for an asset is updated unconditionally, which causes previously deployed strategies for the same asset to be overwritten without any validation or restriction.

### Attack Path

An unauthorized user calls the newStrategy function with any _asset and _name parameters.

The factory deploys a new strategy contract and sets the mapping deployments[_asset] to this new address, regardless of any previous strategy address.

This new deployment overwrites the existing strategy reference for that asset in the mapping.

The attacker can repeatedly call this function, deploying multiple new strategies and replacing the original deployment address.

Users, frontends, or governance tools relying on the mapping for the strategy address will interact with potentially unauthorized or malicious contracts.

### Impact

Loss of Control: The management team cannot control who deploys strategy contracts, enabling potential spam, malicious deployments, or governance circumvention.

Data Integrity Issues: Overwriting existing deployments leads to loss of the original strategy reference, which may cause operational confusion and break integrations relying on stable addresses.

### Mitigation

Implement Access Control: Add an access control modifier (e.g., onlyManagement) to restrict newStrategy calls to authorized roles only.

Prevent Overwrites: Add a require check to prevent redeploying a strategy for an asset that already has an existing strategy deployed
