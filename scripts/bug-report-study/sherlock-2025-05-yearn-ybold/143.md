# Strategy ignores BOLD yield gains from the stability pool

### Summary

The estimated total assets include BOLD present in the contract and compounded BOLD from the stability pool, but fails to account for potential BOLD gains.


### Root Cause

The implementation of `estimatedTotalAssets()` is the following:

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L105-L107

This accounts for BOLD in the contract and BOLD compounded in the stability pool. However, the stability pool has another component, which is BOLD from gains. This can be seen for example in the implementation of `provideToSP()`:

```solidity
        uint256 currentYieldGain = getDepositorYieldGain(msg.sender);
        uint256 compoundedBoldDeposit = getCompoundedBoldDeposit(msg.sender);
        (uint256 keptYieldGain, uint256 yieldGainToSend) = _getYieldToKeepOrSend(currentYieldGain, _doClaim);
        uint256 newDeposit = compoundedBoldDeposit + _topUp + keptYieldGain;
```

Note `newDeposit` is composed of the compounded bold, the new deposit AND THE YIELD RETURNED FROM `getDepositorYieldGain()`.

### Internal Pre-conditions

- Strategy has a positive pending BOLD yield gain in the stability pool.

N/A.

### Impact

This value is key since it is the return value of `_harvestAndReport()` which is used to report performance to the Yearn vault. Failing to account for BOLD yield gain will return an incorrect value when calculating gains and losses. 

### PoC

_No response_

### Mitigation

`estimatedTotalAssets()` should account for potential BOLD yield gains.

```solidity
    function estimatedTotalAssets() public view returns (uint256) {
        return asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this)) + SP.getDepositorYieldGainWithPending(address(this));
    }
```
