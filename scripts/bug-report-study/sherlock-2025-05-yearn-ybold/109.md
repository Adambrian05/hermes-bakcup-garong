# Lack of Slippage Protection in Strategy's Auction Mechanism

### Summary

The LiquityV2SPStrategy contract lacks slippage protection in its auction mechanism, which could lead to collateral being sold at unfavorable prices during market volatility.

### Root Cause

In the LiquityV2SPStrategy contract, the `_tend` function initiates auctions for collateral tokens but does not implement any slippage protection or minimum price guarantees. The auction starting price is calculated based on the current oracle price and a buffer percentage, but there's no mechanism to ensure that the auction doesn't clear at a significantly lower price than expected:
```solidity
// Calculate and set the starting price
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);

// Transfer collateral to the auction contract
COLL.safeTransfer(address(AUCTION), _toAuction);

// Start the auction
AUCTION.kick(address(COLL));
```
This is particularly concerning because:

1. The auction mechanism relies on external price oracles which may lag during high volatility.
2. The `bufferPercentage` provides some protection, but it's a fixed value that doesn't adapt to market conditions.
3. There's no minimum clearing price or ability to cancel auctions if market conditions deteriorate.

This vulnerability is specific to the Yearn yBOLD protocol's auction mechanism, which is critical for converting collateral rewards into BOLD tokens. The issue affects the economic efficiency of the protocol and could lead to value extraction by sophisticated traders.
The root cause is in:
https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L234-L240:
```solidity
// slither-disable-next-line divide-before-multiply
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);

COLL.safeTransfer(address(AUCTION), _toAuction);
AUCTION.kick(address(COLL));
```

### Internal Pre-conditions

1. The existing buffer percentage provides some protection, reducing the likelihood of extreme losses.

### External Pre-conditions

1. Market volatility is a common occurrence in cryptocurrency markets.
2. The issue will manifest during periods of high volatility when oracle prices lag behind market prices.
3. The vulnerability requires specific market conditions to cause material losses.

### Attack Path

Explicit description and PoC provided.

### Impact

1. During market volatility, collateral could be sold at prices significantly below market value, resulting in economic loss for the protocol.
2. The issue doesn't directly lead to fund theft but creates conditions where economic value could be extracted unfairly.
3. The impact is limited to the auction mechanism and doesn't affect the entire protocol's security.
4. Similar slippage issues in other DeFi protocols have led to economic inefficiencies and MEV extraction.

The economic impact depends on market conditions and the value of collateral being auctioned. During extreme market volatility, the losses could be substantial.

### Mitigation

Implement slippage protection in the auction mechanism to ensure collateral is not sold at unfavorable prices:
```diff
function _tend(
    uint256 /*_totalIdle*/
) internal override {
    if (isCollateralGainToClaim()) claim();
    if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));

    uint256 _toAuction = COLL.balanceOf(address(this));
    uint256 _available = COLL.balanceOf(address(AUCTION)) + _toAuction;
    if (_available > dustThreshold) {
        (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
        uint256 _bufferPercentage = bufferPercentage;
        if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
            _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
        }

+       // Calculate minimum acceptable price (e.g., 95% of current price)
+       uint256 minAcceptablePrice = (_price * 95) / 100;
+       
+       // Store the minimum price for this auction
+       auctionMinPrices[address(COLL)] = minAcceptablePrice;
+       
        // Calculate starting price with improved precision
-       // slither-disable-next-line divide-before-multiply
-       AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
+       uint256 startingPrice = (_available * _price * _bufferPercentage) / (WAD * WAD * WAD);
+       AUCTION.setStartingPrice(startingPrice);

        COLL.safeTransfer(address(AUCTION), _toAuction);
        AUCTION.kick(address(COLL));
    }
}
```
Additionally, modify the auction contract to include a minimum price check:
```solidity
function bid(address _token, uint256 _bid) external {
    // Existing bid logic
    
    // Check that the bid meets minimum price requirements
    require(_bid >= auctionMinPrices[_token], "Bid below minimum price");
    
    // Continue with bid processing
}
```
Consider also implementing a mechanism to cancel auctions if market conditions deteriorate significantly:
```solidity
function cancelAuction(address _token) external onlyManagement {
    require(AUCTION.isActive(_token), "No active auction");
    
    // Cancel the auction and return collateral
    AUCTION.cancel(_token);
    
    // Retrieve the collateral
    uint256 amount = COLL.balanceOf(address(AUCTION));
    COLL.safeTransfer(address(this), amount);
}
```
These changes would provide better protection against unfavorable market conditions and reduce the risk of economic loss.
