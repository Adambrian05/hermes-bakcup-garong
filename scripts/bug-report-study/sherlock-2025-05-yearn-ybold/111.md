# Inconsistent dustThreshold Check Between _tendTrigger() and _tend()

### Summary

The strategy performs inconsistent dustThreshold checks in _tendTrigger() and _tend(). Specifically, _tendTrigger() considers only the strategy’s local COLL balance, while _tend() includes both the strategy's and the auction contract's COLL balances. This mismatch can lead to protocol invariant violations, where tending is necessary but not triggered, or triggered when it has no effect.

### Root Cause

The logic to determine whether enough COLL is available to trigger a tend() is duplicated in _tendTrigger() and _tend(), but implemented inconsistently:

_tendTrigger() checks:

```solidity
COLL.balanceOf(address(this)) > dustThreshold
```
_tend() checks:

```solidity
uint256 _available = COLL.balanceOf(address(this)) + COLL.balanceOf(address(AUCTION));
if (_available > dustThreshold) { ... }
```

### Attack Path

An auction contract with COLL to suppress tendTrigger().

Keepers following protocol-specified behavior would not call tend(), believing it is not required.

Strategy would stall, failing to auction off rewards.

Protocol yield is delayed or lost entirely due to inactivity.

### Impact

Violation of protocol invariants: "Once collateral is available, tending must occur promptly."

Liveness failure: Tending does not occur even when actionable collateral exists.

Yield degradation: Strategy may hold unauctioned collateral indefinitely.

Keeper inefficiency: Keepers may miss opportunities or waste gas if false positives/negatives occur.
