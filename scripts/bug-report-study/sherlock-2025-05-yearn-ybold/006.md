# Oracle Price Manipulation Risk in Strategy.sol

### Summary

The strategy's auction mechanism relies on a single price oracle to determine auction starting prices for collateral tokens. This design allows an attacker to manipulate the oracle price, leading to either underpriced auctions (resulting in direct loss of value) or overpriced auctions (preventing successful execution). The current buffer mechanism (`bufferPercentage and ORACLE_DOWN_BUFFER_PCT_MULTIPLIER`) is insufficient to protect against sophisticated price manipulation attacks.


### Root Cause

In `Strategy.sol`, the auction pricing mechanism relies on a single price oracle (COLL_PRICE_ORACLE) without any additional validation or fallback mechanisms. The price is used directly to calculate auction starting prices, making the system vulnerable to oracle manipulation.

`(uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
// ... later used in auction pricing
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);`


### Internal Pre-conditions

1. The strategy must have collateral gains to auction (`_available > dustThreshold`)
2. The oracle must be reporting a price (not down)
3. The auction must not be currently active
4. The strategy must have sufficient collateral to auction

### External Pre-conditions

1. The attacker must have the ability to manipulate the price oracle
2. Attacker must have sufficient capital to execute the manipulation
3. The manipulated price must be outside the `bufferPercentage` protection
4. The attack must be executed before other market participants can react

### Attack Path

1. The Attacker monitors the strategy for pending collateral auctions

2. When a collateral gain is detected, attacker manipulates the oracle price

3. Strategy calls _tend() which fetches the manipulated price

4. Strategy sets auction starting price based on manipulated price

5. An attacker can now:

- Buy collateral at artificially low prices if price was manipulated down

- Cause auctions to fail if price was manipulated up

### Impact

- Direct loss of funds through mispriced auctions

- If the price is manipulated down, Collateral is sold below market value

- If the price is manipulated up, Auctions may fail to execute, locking collateral

- Potential loss of all collateral value in worst case

- Loss of user confidence in the protocol

### Mitigation

Implementing price validation against other on-chain sources will help. Also, consider implementing multiple price feeds and use median price.

Add time-weighted average price (TWAP) mechanism
