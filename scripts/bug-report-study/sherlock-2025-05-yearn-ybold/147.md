# Missing access control allows to override the staker in StakerFactory

### Summary

The `newStrategy()` function can be called by anyone to override the Staker contract for any asset.

### Root Cause

The StakerFactory contract allows the creation and registration of staker contracts for assets.

The implementation of `newStrategy()` fails to implement access control rules, allowing anyone to create and override the Staker contract for any asset.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32-L48

### Internal Pre-conditions

- A Staker contract has been created for a particular asset through the StakerFactory.

### External Pre-conditions

N/A.

### Attack Path

- Attacker calls `newStrategy()` with the same asset to override the current registered contract.

### Impact

The registered Staker contract for any asset can be overridden by deploying a new version of it. This action can be performed by anyone, as the functionality doesn't implement access control rules.

### PoC

_No response_

### Mitigation

Implement access control rules to allow trusted roles to manage deployments in the factory. Additionally, check if the Staker contract for the given asset has been already deployed, to prevent accidentally overriding it.
