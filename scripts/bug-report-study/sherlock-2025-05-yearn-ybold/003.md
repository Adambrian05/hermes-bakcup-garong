# Incorrect Auction Starting Price Calculation

### Summary

An extra `/ WAD` in the price formula will cause an almost‐zero starting price for the collateral auction, allowing an attacker to buy off all collateral for pennies on the dollar and drain value from yBOLD/st-yBOLD holders as the attacker triggers _tend() after any liquidation.

### Root Cause

the code does three successive / WAD operations instead of two:
```sol
AUCTION.setStartingPrice(
    _available * _price      // collateral amount * price
    / WAD                    // 1st scale
    * _bufferPercentage      // apply buffer
    / WAD                    // 2nd scale
    / WAD                    //  EXTRA, unintended scale-down
);
```

- https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241

### Internal Pre-conditions

1. The strategy holds `_available > 0` collateral from a recent liquidation.
2. `COLL_PRICE_ORACLE.fetchPrice()` returns `_price > 0`.
3. `bufferPercentage` has been set

### External Pre-conditions

None beyond normal oracle price feeds and liquidation triggers.

### Attack Path

1. crediting the strategy with _available collateral.
2.  calls `Strategy._tend()`.
3. `_tend()` reads `_available`, `_price`, and `_bufferPercentage`.
4. It calls `AUCTION.setStartingPrice()` with the malformed formula.
5. The auction start price becomes (available × price × buffer) / 1e18^3.
6. Attacker bids price, winning all collateral.
7. Attacker resells collateral at market price, pocketing the difference; strategy incur the full loss.

### Impact

yBOLD and st-yBOLD depositors suffer an loss of the collateral’s value

### PoC
Test
```sol
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

contract WADTest {
    uint256 constant WAD = 1e18;
    function demo() external pure returns (uint256 wrong, uint256 correct) {
        uint256 available = 10 * WAD;
        uint256 price     = 2  * WAD;
        uint256 buffer    = 11 * WAD / 10;  // 1.1 × WAD

        wrong = available * price / WAD * buffer / WAD / WAD; // => (10*2*1.1*1e18) / 1e54 = 22  (wei)
        correct = available * price / WAD * buffer / WAD;  // => (10*2/1e18*1.1e18) = 22e18 (wei)
    }
}
```

### Mitigation

Use exactly two / WAD operations:
```sol
- AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
+ AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD);
```
