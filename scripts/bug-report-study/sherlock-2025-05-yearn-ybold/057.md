# Strategy asset mappings in the Staker Factory can be overwritten

### Summary

Deployed strategies are mapped to their assets within the [StakerFactory](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol), but no checks are in place to prevent subsequent users or malicious actors from overwriting these mappings.

### Root Cause

New strategies are deployed using [StakerFactory::newStrategy()](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32-L48):

```solidity
    function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
        // tokenized strategies available setters.
        IStrategyInterface _newStrategy = IStrategyInterface(address(new Strategy(_asset, _name)));

        _newStrategy.setPerformanceFeeRecipient(performanceFeeRecipient);

        _newStrategy.setKeeper(keeper);

        _newStrategy.setPendingManagement(management);

        _newStrategy.setEmergencyAdmin(emergencyAdmin);

        emit NewStrategy(address(_newStrategy), _asset);

        deployments[_asset] = address(_newStrategy);   // @audit: can be overwritten by subsequent deployments
        return address(_newStrategy);
    }
```

Before the function returns, the `deployments` mapping is updated with the newly created strategy and asset. But no checks are in place to prevent subsequent users from redeploying new strategies under assets that have already been deployed.

### Internal Pre-conditions

1. An asset needs to have been deployed to a strategy.

### External Pre-conditions

None

### Attack Path

1. A legitimate user deploys a new strategy to an asset - USDT by calling `StakerFactory::newStrategy(USDT_address, "USDT-strategy")`.
2. Another user or malicious actor deploys that same asset - USDT using the same or different `name` parameter.
3. `deployments[USDT_address]` is now overwritten with the address of the new strategy.

### Impact

Frontends that perhaps rely on strategy discovery by parsing `emit NewStrategy(address(_newStrategy), _asset)` logs from the `StakerFactory` contract, or even verifying deployed strategies by calling [StakerFactory::isDeployedStrategy()](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L57-L62) could be misled into promoting these other strategies to users.

Strategy accumulated yields could also be potentially missed and assets deployed into malicious actor-controlled strategies..

### PoC

_No response_

### Mitigation

Revert if the given asset already exists in the `deployments` mapping:

```solidity
    function newStrategy(address _asset, string calldata _name) external virtual returns (address) {
        require(deployments[asset] == address(0), "asset already deployed to strategy");
        ...

        deployments[_asset] = address(_newStrategy);    // @audit-fix: no longer overwrites
        ...
    }
```
