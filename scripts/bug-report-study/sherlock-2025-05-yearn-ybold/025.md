# Incorrect Fee Calculation in Accountant.sol

## Summary
The `Accountant.sol` contract has a flaw in its fee calculation logic, allowing performance fees to be distributed before a strategy has fully recovered from prior losses. This violates the intended invariant that fees should only be taken when the price per share (PPS) returns to 1, ensuring a 1:1 ratio between yBOLD and BOLD.

---

## Finding Details
The `report` function in `Accountant.sol` calculates fees based on the immediate gain or loss in a single report:
- **If there’s a gain**, it sets `totalFees` to the full gain amount (100% performance fee).
- **If there’s a loss** (i.e., `assets < supply`), it calculates `needed = supply - assets` and adjusts `totalFees` to `gain - needed` if `gain >= needed`, otherwise sets it to 0.
-  issue in in [line](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L184)

This approach only considers the current report and does not track cumulative losses across multiple reports. The protocol’s invariant requires that fees are only taken after the strategy fully recovers from all prior losses, meaning the PPS (calculated as `totalAssets / totalSupply`) must return to 1. Without tracking cumulative losses, the current logic allows fees to be taken prematurely when a gain occurs, even if the strategy remains in a net loss position.

---

## Impact
This issue has several significant consequences:
- **Invariant Violation**: Fees distributed before full recovery break the 1:1 yBOLD:BOLD ratio, as `st-yBOLD` receives fees while the strategy’s value is still below its initial state.
- **Overpayment of Fees**: Fees may be calculated on gains that don’t fully offset previous losses, leading to incorrect distributions.
- **User Harm**: Investors holding yBOLD may see reduced value in their holdings, as premature fee extraction misrepresents the strategy’s true performance.

---

## Recommendation
To address this issue, the following changes are recommended:
1. **Add a State Variable**: Introduce `cumulativeLosses` to track the total unrecovered losses per vault over time.
2. **Update Fee Logic**: Modify the `report` function to only set `totalFees` when the strategy has fully recovered, i.e., when `totalAssets >= totalSupply` after accounting for cumulative losses.
3. **Offset Losses First**: Ensure gains are applied to reduce `cumulativeLosses` before any fees are calculated.

This ensures fees are only taken when the strategy is back to a PPS of 1 or higher, preserving the intended invariants.

---

## Proof of Concept
Consider this sequence of events:
1. **Initial State**: `totalAssets = 1000 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 1).
2. **First Report**: A loss of 100 BOLD occurs.
   - `totalAssets = 900 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 0.9).
   - Cumulative loss = 100 BOLD.
3. **Second Report**: A gain of 50 BOLD is reported.
   - `totalAssets = 950 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 0.95).
   - Current logic: Since there’s a gain of 50 BOLD and no immediate loss, `totalFees = 50 BOLD`.
   - Problem: The strategy is still 50 BOLD short of recovery (PPS < 1), so fees shouldn’t be taken yet.

This demonstrates how the current implementation incorrectly distributes fees before full recovery.

## Example
Using the same scenario:
- **Initial State**: `totalAssets = 1000 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 1).
- **After First Report**: Loss of 100 BOLD.
  - `totalAssets = 900 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 0.9).
  - Cumulative loss = 100 BOLD.
- **After Second Report**: Gain of 50 BOLD.
  - `totalAssets = 950 BOLD`, `totalSupply = 1000 yBOLD` (PPS = 0.95).
  - Current logic: `totalFees = 50 BOLD` (since gain = 50 BOLD).
  - Correct logic: Cumulative loss reduces to 50 BOLD (100 - 50), and since PPS = 0.95 < 1, `totalFees = 0`.

**Proposed Fix**:
- Track `cumulativeLosses = 100 BOLD` after the first report.
- After the second report, reduce it to 50 BOLD with the gain.
- Only allow fees when `cumulativeLosses = 0` and `totalAssets >= totalSupply`.

This example highlights the flaw and shows how the fix ensures fees align with full recovery.
