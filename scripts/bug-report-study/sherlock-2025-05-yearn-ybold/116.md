# The stakers will face reversion issues during asset distribution

### Summary

The access control in the `distribute` function will cause a failure to execute the `_harvestAndReport` function for the staker as the `msg.sender` will not have the required permissions.

### Root Cause

In [[src/Staker.sol](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/Staker.sol#L49), the `_harvestAndReport` function calls the `distribute(address token)` function, which calls the `distribute(address token, uint256 amount)` on the Accountant contract, which has an access control modifier that restricts its execution.

- In `src/Staker.sol`, the `distribute(address token)` function calls `distribute(address token, uint256 amount)`, which is protected by the `onlyFeeManagerOrRecipient` modifier. Since the `msg.sender` (Staker.sol) is neither the fee manager nor the recipient, this will lead to a reversion.

### Internal Pre-conditions

1. The `_harvestAndReport` function must be called to initiate the asset distribution process.
2. The Accountant contract must be properly initialized with a fee manager and recipient.

### External Pre-conditions

none

### Attack Path

1. **Staker calls `_harvestAndReport` to initiate the asset distribution process.**
2. The function calls `ACCOUNTANT.distribute(address(asset))` to claim.
3. The `distribute` function attempts to call `distribute(address token, uint256 amount)`.
4. The call fails due to the `onlyFeeManagerOrRecipient` modifier, as the `msg.sender` is not authorized.

### Impact

The staker cannot successfully distribute assets, which leads to breaking the invariants:

>> When `process_report` is called on yBOLD, any gain must be fully minted as yBOLD to `Accountant.sol`, from which it will be distributed to `st-yBOLD`.

If `process_report` reports a loss, `Accountant.sol` will not take any fees until the yBOLD price per share returns to 1.

_No response_

### Mitigation

To mitigate this issue, the access control on the `distribute` function should be reviewed. Consider allowing the Staker contract to call the `distribute` function or implement a mechanism that allows the Staker to act as a valid recipient for the distribution process.
