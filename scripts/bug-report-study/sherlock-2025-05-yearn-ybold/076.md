# Incorrect Auction Starting Price Calculation in `LiquityV2SPStrategy`

### Summary

The `LiquityV2SPStrategy` contains a critical arithmetic error in its auction starting price calculation, causing collateral tokens with 18 decimals (e.g., wstETH, rETH) to be sold at **1e18 times below their fair value**. The error stems from redundant divisions in the price formula, collapsing the starting price to near-zero levels even for properly scaled tokens. This flaw allows attackers to purchase collateral for virtually nothing, resulting in total loss of user funds.


### Root Cause


The strategy calculates the auction starting price as:  

```solidity
// Incorrect formula (divides by WAD three times)
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction

```  

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241


For 18-decimal collateral (e.g., wstETH), this introduces a **1e18x under-pricing error**:  
1. **Redundant Division**: Three divisions by `WAD` (1e18) reduce the price by `1e54`, even though `_available` and `_price` are already in 18 decimals.  
2. **Buffer Misapplication**: The safety margin (`_bufferPercentage`) is applied to an already incorrect base value, failing to protect against losses.

### PoC


### Scenario  
- Collateral: **100 wstETH** (1e20 units, value = $100M at $1,000/wstETH).  
- Oracle Price: **$1,000 per wstETH** (`_price = 1e21`; 1e18 = $1).  
- `_bufferPercentage`: 10% (1.1e18).  

### Incorrect Calculation  

```js
Starting Price = (1e20 * 1e21 / 1e18) * 1.1e18 / 1e18 / 1e18  
               = (1e23 / 1e18) = 1e5  
               1e5 * 1.1e18 = 1.1e23  
               1.1e23 / 1e36 = 1.1e-13 (≈$0.00000000000011 per wstETH)  
Total Proceeds = 100 wstETH * $0.00000000000011 = $0.000000000011  
```  

### Correct Calculation (Expected)  
```js  
Starting Price = (1e20 * 1e21 * 1.1e18) / (1e18 * 1e18)  
               = 1.1e21 (≈$1,100 per wstETH)  
Total Proceeds = 100 wstETH * $1,100 = $110,000  
```  

### Mitigation


Update the calculation in `_tend()` to remove the redundant division:  
```solidity
AUCTION.setStartingPrice(
    (_available * _price * _bufferPercentage) / (WAD * WAD)
);
```
