# Accountant Will never be able to cover losses of the vault

### Summary

The `Accountant` has the responsibility of covering losses of the `vault` when it is reporting a loss. However, the Vault will never be able to have the losses actually covered with this current design. 

`yBond` (vault) is responsible for calling `report` [https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L146](url) 
on the `Accountant` contract. If the vault is reporting a loss, the `Accountant` is responsible for covering that loss by transferring the amount to the vault. 

But the design is such that:
- `Accountant` returns a value for the amount of loss it will cover `totalRefunds` 
- The `vault` uses `totalRefunds` value to then PULL the funds from the `Accountant` contract 

This design will never work because `Accountant` never give the vault any `approval` / `allowance` to pull funds from it.

This also breaks an invariant declared in the contest page:
`In the event of a loss, the Accountant.sol contract will first cover the loss before distributing any fees to st-yBOLD.`

### Root Cause

In the `VaultV3.vy` (which is the yBond contract that will call the `Accountant`) - upon reporting to the accountant, it will determine if it needs to mint shares to the Accountant (gain) or pull funds from the Accountant to cover losses. If the `Accountant` returns a value of loss to cover `totalRefunds` - the vault (yBond) will then PULL that amount from the `Accountant` 

```solidity
->   # Pull refunds
    if total_refunds > 0:
        # Transfer the refunded amount of asset to the vault.
  ->      self._erc20_safe_transfer_from(_asset, accountant, self, total_refunds)
        # Update storage to increase total assets.
        self.total_idle += total_refunds
```

Because `Accountant` does not PUSH any funds to the Vault, and instead only returns `totalRefunds` and relies on the vault to PULL that amount, the `Accountant` must have `approved` the Vault for at least that amount. 

But the Vault has 0 approval

### Internal Pre-conditions

1. No internal pre-conditions

### External Pre-conditions

1. The vault reports a loss to the accountant, and the accountant attempts to cover the loss

### Attack Path

1. A vault calls `process_report` and has a `loss`
2. Vault calls `report` on `Accountant` and passes in the loss amount 
3. `Accountant` returns to the Vault `totalRefund` amount which is the amount of loss it will cover
4. Vault attempts to PULL `totalRefunds` amount from the Accountant - but fails
5. losses are never covered

### Impact

The 2 main purposes of the accountant is:
1. to be able to receive yBold for any gains 
2. 2. To be able to cover losses that are reported by the vault 

Currently, the Accountant is unable to ever cover any loss reported by a vault because the Vault will never be able to pull funds from the accountant.

### PoC

In `Accountant` - There is functionality to `add` and `remove` a Vault. In the `remove` logic, the Accountant rescinds any `allowance` / `approval` that the vault has:

```solidity
   function removeVault(
        address vault
    ) external virtual onlyVaultOrFeeManager {
        // Ensure the vault has been previously added.
        require(vaults[vault], "not added");

        address asset = IVault(vault).asset();
->        // Remove any allowances left.
        if (ERC20(asset).allowance(address(this), vault) != 0) {
            // slither-disable-next-line reentrancy-no-eth
            ERC20(asset).safeApprove(vault, 0);
        }

        vaults[vault] = false;
```

BUT in the `add` logic, the Vault that is added is never given any `approval` / `allowance` - also, there is no place in any part of the `Accountant` that gives any approval to a vault:

```solidity
  function addVault(
        address vault
    ) external virtual onlyVaultOrFeeManager {
        // Ensure the vault has not already been added.
        require(!vaults[vault], "already added");

        vaults[vault] = true;

        emit VaultChanged(vault, ChangeType.ADDED);
```

When `removing` a vault, it is assumed that the Vault has prior `allowance` because it is necessary that it does to fulfill the ability to cover losses, but the Vault is never given any approval.

### Mitigation

The `Accountant` needs to give approval to the `Vault` to spend its funds. This can be done either:

- In the process of `adding` a vault, and give the newly added vault a 1 time approval amount 
- Or, in `report` if the vault reports a loss , approve the Vault for the `totalRefunds` amount
