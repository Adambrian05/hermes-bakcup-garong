# LiquityV2SPStrategy - Auction Starting Price Calculation Error Leads to Severe Underpricing of Collateral

### Summary

The `LiquityV2SPStrategy` contract contains a critical calculation error in its `_tend` function when setting the starting price for collateral auctions. An erroneous extra division by `WAD` (1e18) is performed, causing the auction starting price to be set at `1/1e18` (one divided by ten to the power of eighteen) of its intended fair market value plus buffer. This vulnerability would allow arbitrageurs to purchase collateral from auctions at virtually zero cost, leading to immediate and substantial financial losses for the strategy and its depositors.

### Root Cause

In the `_tend` function of `LiquityV2SPStrategy.sol`, the auction starting price is calculated as:
`AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);`

Let's break this down assuming WAD arithmetic (amounts and prices scaled by 1e18):
*   `_available`: Amount of collateral to auction (e.g., `100 * 1e18` for 100 units).
*   `_price`: Oracle price of collateral in terms of asset (e.g., `2000 * 1e18` for 2000 asset/collateral).
*   `_bufferPercentage`: Buffer factor (e.g., `1.1 * 1e18` for a 10% buffer).
*   `WAD = 1e18`.

The intended calculation for a WAD-scaled total price should be:
`TotalValue = (_available * _price / WAD)` (This gives total value in asset, WAD-scaled)
`BufferedTotalValue = TotalValue * _bufferPercentage / WAD` (Applies buffer, result still WAD-scaled)

The contract's calculation is:
1.  `_available * _price / WAD`: Correctly calculates total value (WAD-scaled). Let this be `X`.
2.  `X * _bufferPercentage / WAD`: Correctly applies buffer to `X` (WAD-scaled). Let this be `Y`. This `Y` is the intended starting price.
3.  `Y / WAD`: **This final division by `WAD` is erroneous.** It de-scales the correctly buffered WAD-scaled price, making it `1/1e18` times smaller.

If `Y` was `2200e18` (representing 2200 units of asset), the contract sets the price to `2200`.

```solidity
// Strategy.sol (LiquityV2SPStrategy)
// ...
    function _tend( uint256 /*_totalIdle*/ ) internal override {
        // ...
        if (_available > dustThreshold) {
            (uint256 _price, bool _isOracleDown) = COLL_PRICE_ORACLE.fetchPrice();
            uint256 _bufferPercentage = bufferPercentage;
            // ... (buffer adjustment for oracle down) ...

            // slither-disable-next-line divide-before-multiply
            // THE BUG IS HERE: extra "/ WAD" at the end
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); 
            
            COLL.safeTransfer(address(AUCTION), _toAuction);
            AUCTION.kick(address(COLL));
        }
    }
// ...
```

### Internal Pre-conditions

*   `LiquityV2SPStrategy` is deployed and operational.
*   It has accumulated some `COLL` (collateral token) to auction, exceeding `dustThreshold`.
*   `COLL_PRICE_ORACLE` is functioning and returns a `_price`.
*   `AUCTION` contract (created via `AUCTION_FACTORY`) is available and its `setStartingPrice` function is callable.
*   `WAD` constant is `1e18`.

### External Pre-conditions

*   The `tend()` function is triggered (e.g., by a keeper).
*   Arbitrageurs are monitoring auctions created by this strategy.

### Attack Path

1.  `LiquityV2SPStrategy` has `_available = 1 * 1e18` (1 unit of `COLL`).
2.  `COLL_PRICE_ORACLE` returns `_price = 2000 * 1e18` (COLL is worth 2000 units of `asset`).
3.  `bufferPercentage` is `1.1 * 1e18` (10% buffer).
4.  Correct WAD-scaled starting price should be: `(1e18 * 2000e18 / 1e18) * 1.1e18 / 1e18 = 2200 * 1e18`.
5.  Strategy's `_tend()` is called.
6.  The calculation becomes:
    *   `_available * _price / WAD = (1e18 * 2000e18) / 1e18 = 2000e18`.
    *   `(...) * _bufferPercentage / WAD = (2000e18 * 1.1e18) / 1e18 = 2200e18`. (This is `Y`, the correct value).
    *   `(...) / WAD = 2200e18 / 1e18 = 2200`.
7.  `AUCTION.setStartingPrice(2200)` is called.
8.  An arbitrageur sees an auction for 1 `COLL` (worth 2000 `asset`) starting at a price of `2200 / 1e18` `asset` per `COLL` (if `AUCTION` interprets the price per unit) or a total price of `2200` (if `AUCTION` interprets it as total lot price, but this usually means scaled by `1eN` where N is asset decimals, not unscaled). Assuming `setStartingPrice` expects a WAD-scaled total value, this is `1/1e18` of the actual value.
9.  Arbitrageur immediately buys the `COLL` for a pittance, e.g., for `2200` wei of `asset` instead of `2200 * 1e18` wei.
10. The strategy loses almost the entire value of the auctioned `COLL`.

### Impact

*   **Catastrophic Financial Loss:** Collateral assets will be sold at prices vastly below their market value (effectively for free), leading to rapid and irrecoverable depletion of strategy funds. Depositors will bear these losses directly. The strategy's core economic function of profitably liquidating collateral is inverted into a mechanism for value destruction.

### Mitigation

Remove the final erroneous division by `WAD` in the `AUCTION.setStartingPrice` calculation within `LiquityV2SPStrategy._tend()`. The corrected calculation should ensure the price remains WAD-scaled.

```diff
// Strategy.sol (LiquityV2SPStrategy)
// ...
    function _tend( uint256 /*_totalIdle*/ ) internal override {
        // ...
            // slither-disable-next-line divide-before-multiply
            // Corrected calculation:
-           AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);
+           uint256 bufferedValue = (_available * _price / WAD) * _bufferPercentage / WAD;
+           AUCTION.setStartingPrice(bufferedValue);
            
            COLL.safeTransfer(address(AUCTION), _toAuction);
            AUCTION.kick(address(COLL));
    }
// ...
```
