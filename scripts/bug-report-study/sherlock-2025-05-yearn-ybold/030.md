# Oracle Downtime Causes Permanent Auction DoS and Fund Locking

### Summary

Extreme price inflation during oracle downtime will cause permanent auction `DoS` and fund locking for strategy  as no one will bid on unrealistically priced auctions and new auctions cannot be started while a failed auction remains active.

### Root Cause

When the oracle is down, the strategy applies an extreme `1000x `multiplier to the buffer percentage` (_bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER),` resulting in an unrealistically high starting price.
This extremely high starting price virtually guarantees that no one will bid on the auction, leaving collateral unsold. This makes The strategy cannot start new auctions while a current one is active (as indicated by the comment` "Reverts if there's an active auction" `on the `setStartingPrice` call. 
As matter of fact , according to the [_tend](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225) function , The strategy only settles auctions when all collateral is sold (AUCTION.available(address(COLL)) == 0), which never happens if no one bids.

### Internal Pre-conditions

[AUCTION.setStartingPrice](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241) uses [ORACLE_DOWN_BUFFER_PCT_MULTIPLIER](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L237) when oracle is down.

### External Pre-conditions

No bidders participate in the auction due to the extremely high starting price.

### Attack Path

1- Oracle goes down Thus  stops using primary price source.
2- Strategy calls _tend() to auction the collateral.
3- Due to oracle downtime, the buffer percentage is multiplied by 1000x.
4- Starting price is set unrealistically high (e.g., 10 ETH at $2,000 with normal 10% buffer becomes $22,00,000 instead of $22,00)
5- Strategy transfers collateral to the auction contract and starts the auction.
6- No one bids on the auction due to the unrealistic starting price.
7- The auction remains active indefinitely as the condition available `(address(COLL)) == 0 `is never met.
8- Strategy cannot start new auctions because `setStartingPrice` reverts if there's already an active auction.
All future collateral rewards accumulate in the strategy but cannot be auctioned

### Impact

The strategy  suffer a complete `loss` of the collateral tokens `locked` in the auction.  Additionally, the strategy becomes permanently unable to process any new collateral rewards through auctions, effectively breaking a core functionality of the strategy .
