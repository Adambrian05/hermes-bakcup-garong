# Oracle downtime will cause permanent collateral lockup for depositors

### Summary

The 1000x oracle down buffer multiplier will cause permanent collateral lockup for depositors as the strategy will create economically impossible auctions when the price oracle experiences downtime or switches to non-primary price sources.

### Root Cause

In [`Strategy.sol:_tend()`](https://github.com/johnnyonline/yv3-liquityv2-sp-strategy/blob/99bdf0a9ade3af6f68e7d6b008b3c5a379e94f16/src/Strategy.sol#L225-L246) at lines 236-238, when the collateral price oracle reports downtime (`_isOracleDown == true`) or switches to a non-primary price source, the buffer percentage is multiplied by `ORACLE_DOWN_BUFFER_PCT_MULTIPLIER` which is hardcoded to 1000:

```solidity
uint256 public constant ORACLE_DOWN_BUFFER_PCT_MULTIPLIER = 1_000; // 1000x multiplier

if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
    _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
}

```

This transforms a reasonable 110% buffer (`MIN_BUFFER_PERCENTAGE`) into an economically impossible 110_000% buffer, making auction participation mathematically impossible.

### Internal Pre-conditions

1.  Strategy needs to have collateral rewards available above `dustThreshold` to trigger auction creation
2.  `tend()` function needs to be called during oracle issues (automatically triggered when `_tendTrigger()` returns true)
3.  `block.basefee` needs to be at or below `maxGasPriceToTend` for the tend trigger to activate


### External Pre-conditions

1.  Liquity's collateral price oracle needs to report `_isOracleDown = true` OR switch to non-primary price source
2.  Oracle must still return a price (even if marked as "down") for the calculation to proceed
3.  Network conditions must allow transaction execution

### Attack Path

1.  **Oracle experiences natural downtime** - Liquity's collateral price oracle goes down or switches to backup/fallback price source due to network issues, data feed problems, or maintenance
2.  **Strategy accumulates collateral** - Normal operation results in collateral rewards from stability pool liquidations
3.  **Tend trigger activates** - `_tendTrigger()` returns true due to available collateral above dust threshold and acceptable gas price
4.  **Keeper calls `tend()`** - Either automated keeper or manual call triggers the auction creation process
5.  **Extreme buffer applied** - `_bufferPercentage` becomes 1000x normal: 110% → 110,000%
6.  **Impossible auction created** - `setStartingPrice()` called with economically impossible price (e.g., $33M for $30K collateral)
7.  **Auction runs with zero participation** - No rational economic actor can afford to participate in auction
8.  **Collateral permanently locked** - Auction completes with no bids, collateral remains inaccessible in auction contract with no recovery mechanism

### Impact

**Depositors suffer complete loss of collateral rewards during oracle downtime periods. The strategy loses approximately 100% of pending collateral gains with no recovery mechanism available.**

The economic impossibility is demonstrated by realistic scenarios:
-   10 ETH collateral worth $30,000 requires $33,000,000 payment during oracle downtime
-   Even 1 ETH worth $3,000 requires $3,300,000 payment
-   No individual, institution, or protocol can economically participate in these auctions

### Mitigation


**Option 1: Implement reasonable maximum buffer cap**

```solidity
uint256 public constant MAX_BUFFER_PERCENTAGE = 5e18; // 500% maximum

if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
    _bufferPercentage = Math.min(
        _bufferPercentage * ORACLE_DOWN_BUFFER_PCT_MULTIPLIER, 
        MAX_BUFFER_PERCENTAGE
    );
}

```

**Option 2: Reduce multiplier to reasonable level**

```solidity
uint256 public constant ORACLE_DOWN_BUFFER_PCT_MULTIPLIER = 2; // 2x instead of 1000x

```

**Option 3: Pause auctions during oracle issues**

```solidity
if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
    return; // Skip auction creation during oracle downtime
}
```
