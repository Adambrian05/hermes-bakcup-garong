# Attacker will acquire collateral cheaply causing loss of funds for strategy depositors

### Summary

An incorrect calculation in `Strategy.sol` (within `_tend`) will cause a loss of funds for strategy depositors as an attacker will acquire collateral cheaply by participating in an undervalued auction triggered via `tend()`

### Root Cause

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225

In `Strategy.sol` (within the `_tend` function, specifically the line `AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD);`) the auction starting price calculation includes an extra division by WAD

### Internal Pre-conditions

- `claimableCollateralGains` or `COLL.balanceOf(address(this))` needs to be greater than `DUST_THRESHOLD` to allow  `_tendTrigger` to return true.
- `AUCTION.auctionActive()` needs to return false.
- `_bufferPercentage` needs to be set (default or via `setBufferPercentage`).

### External Pre-conditions

- Oracle price (`_price` from `ORACLE.getPrice(COLL)`) needs to be available and non-zero

### Attack Path

- Keeper calls `tend()` when `_tendTrigger` returns true.
- Strategy calculates `startingPrice = _available * _price / WAD * _bufferPercentage / WAD / WAD` inside `_tend()`.
- Strategy calls `AUCTION.setStartingPrice(startingPrice)`, setting a near-zero starting price due to the extra division.
- Attacker observes the auction starting with an extremely low price.
- Attacker calls `AUCTION.buy(amount_to_buy)` with a minimal amount of BOLD required by the auction mechanics.
- Attacker receives the `_available` COLL tokens from the strategy for significantly less than their fair market value.

### Impact

The strategy depositors suffer an approximate loss equivalent to the fair value of the sold collateral minus the near-zero BOLD received. The attacker gains the difference between the fair value of the collateral and the price paid.

### PoC

see Attack Path

### Mitigation

Remove the extra division by `WAD` in the starting price calculation in `Strategy.sol` (within the `_tend` function). The corrected calculation should likely be:
```solidity
AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD);
```
Ensure this corrected calculation aligns perfectly with the expected input format and scaling for the `IAuction::setStartingPrice` function used by the strategy.
