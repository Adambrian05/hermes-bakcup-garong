# possible to DoS withdrawal if `Accountant::maxLoss` is set to 0

### Summary

because of how the report function handles loss, it would revert if the max loss is set to 0.

### Root Cause

in the `report` function, when the strategy would incurr losses, the health check would then check if the loss is within the maxLoss percentage:
[Accountant.sol#L193-L195](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L193-L195)
```solidity
            } else if (fee.maxLoss < MAX_BPS) {
                require(loss <= (strategyParams.current_debt * (fee.maxLoss)) / MAX_BPS, "too much loss");
            }
```

but this require check would not passed if the fee.maxLoss is 0, resulting the report to be reverted.

### Internal Pre-conditions

1. vault hold 1000 asset
2. vault then proceed to deposit 900 asset into strategy
3. now vault have 100 asset only

### External Pre-conditions

1. fee manager set the max loss to 0

### Attack Path

1. user wants to withdraw 500 asset
2. vault then need to pull funds from strategy
3. but a loss is happening
4. proceed to call report to realize the diff
5. the report would check that loss amount is greater than 0, the withdrawal would revert

### Impact

in the README stated that `No role should be capable of stealing from depositors or permanently blocking withdrawals.`

in this report, we clearly see that the fee manager role can block the withdrawal as there are no other role can change the max loss value beside the fee manager.

### PoC

_No response_

### Mitigation

the max loss should have minimum limit that is non zero.
