# Missing Asset Allowance in Vault Addition

## Finding Description and Impact

**Root Cause:**
The `addVault()` function registers a new vault in the accountant's fee charging system but fails to grant the necessary asset allowance to the vault contract. While the function successfully adds the vault to the `vaults` mapping and emits the appropriate event, it does not call `ERC20(asset).safeApprove(vault, amount)` to authorize the vault to transfer assets from the accountant contract.

## code snippet: https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L206-L215

**Technical Details:**
- In `addVault()`: The vault is registered (`vaults[vault] = true`) but no asset allowance is granted
- In `removeVault()`: The function explicitly checks for and removes any existing allowances using `ERC20(asset).safeApprove(vault, 0)`
- This asymmetry creates a state where vaults are registered but non-functional

**Impact:**
1. **Functional Failure:** Newly added vaults cannot perform their intended fee charging operations as they lack permission to transfer assets from the accountant contract
2. **Silent Failure:** The vault addition appears successful (transaction completes, event emitted) but the vault remains non-operational, leading to potential confusion and debugging difficulties

## Recommended Mitigation

 **Modify the `addVault()` function** to include asset allowance setup:
   ```solidity
   function addVault(address vault) external virtual onlyVaultOrFeeManager {
       require(!vaults[vault], "already added");
       
       address asset = IVault(vault).asset();
       // Grant appropriate allowance to the vault
       ERC20(asset).safeApprove(vault, type(uint256).max); // or specific amount
       
       vaults[vault] = true;
       emit VaultChanged(vault, ChangeType.ADDED);
   }
   ```
