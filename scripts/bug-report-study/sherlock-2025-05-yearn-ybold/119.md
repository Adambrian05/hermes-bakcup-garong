# The call to `AUCTION##setStartingPrice()` will fail in case of tokens with low decimals (<18) due to rounding

### Summary

In the `Strategy.sol##_tend` function after some validations and calculations , the function calls the `Auction.setStartingPrice` in order to set the starting price for the auction [here](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241). However in cases of when the `available` token is lets say USDC that have 6 decimals, the passed in calculation in the input param of the function will round down to 0.
And due to this the function will revert and that is due to the require in the `setStartingPrice` function's implementation in the `Auction.sol` [click here](https://github.com/yearn/tokenized-strategy-periphery/blob/8442563a8d2b7a71057c76bdcead9b346927c301/src/Auctions/Auction.sol#L417) as can be seen it requires the starting price should NOT be = 0


### Root Cause

Rounding due to calculations done/passed in the `AUCTION.setStartingPrice` in the `_tend` function

```solidity
    function _tend(
        uint256 /*_totalIdle*/
    ) internal override {
   
// SNIP...


            // slither-disable-next-line divide-before-multiply
//AUDIT- Rounding issues in the below calculation
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction
```

### Internal Pre-conditions

The `COLL` should be a token with 6 decimals- USDC for eg.

### External Pre-conditions

N/A

### Attack Path

Lets see the issue with a calculation: firstly
```solidity
            AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction
```
Suppose:
`_available` = 10_000e6
`price = 1e18` (I am assuming that the price is scaled to 18 dec precision)
`WAD` = 1e18
`_bufferPercentage` = 1.1e18

-> (10_000e6 * 1e18 / 1e18 * 1.1e18 / 1e18 / 1e18)- this will round down to 0


### Impact

Due to the rounding the Auction.sol 's `setStartingPrice` function will revert due to the reason provided in the Summary and the revert lead to the AUCTION not starting for the collateral
