# Lack of Asset Allowance in Vault Addition



## Finding Description and Impact  

**Root Cause:**  
The `addVault()` function successfully registers a new vault in the accountant contract's fee management system but neglects to approve the vault for asset transfers. Although the function updates the `vaults` mapping and emits a `VaultChanged` event, it omits a critical `safeApprove()` call that would enable the vault to pull assets from the accountant.  

## Code Snippet: https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L206-L215  

**Technical Details:**  
- The `addVault()` function sets `vaults[vault] = true` without granting an allowance via `ERC20(asset).safeApprove()`  
- Conversely, `removeVault()` properly revokes allowances using `ERC20(asset).safeApprove(vault, 0)`  
- This inconsistency leaves vaults in an approved-but-inoperable state  

**Impact:**  
1. **Operational Disruption:** Newly registered vaults cannot collect fees due to insufficient transfer permissions, breaking core protocol functionality  
2. **Undetected Failure Mode:** Transactions complete successfully and events emit normally, masking the underlying issue and complicating troubleshooting  

## Recommended Mitigation  

**Update `addVault()` to include allowance approval:**  
```solidity  
function addVault(address vault) external virtual onlyVaultOrFeeManager {  
    require(!vaults[vault], "already added");  
      
    address asset = IVault(vault).asset();  
    // Grant unlimited approval for fee operations  
    ERC20(asset).safeApprove(vault, type(uint256).max);  
      
    vaults[vault] = true;  
    emit VaultChanged(vault, ChangeType.ADDED);  
}  
```
