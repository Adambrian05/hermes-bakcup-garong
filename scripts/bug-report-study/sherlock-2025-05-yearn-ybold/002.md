# Distribute Function Allows Premature yBOLD Distribution

## Summary
The Accountant contract's `distribute` function allows the feeRecipient to withdraw yBOLD tokens without ensuring losses are covered first. This violates a core protocol invariant where yBOLD should maintain a 1:1 peg with BOLD except during losses, and the Accountant must cover losses before distributing fees.

## Vulnerability Details
The `distribute` [function](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L369) allows withdrawing any token, including yBOLD, without checks:

```solidity
function distribute(address token, uint256 amount) public virtual onlyFeeManagerOrRecipient {
    ERC20(token).safeTransfer(feeRecipient, amount);
    emit DistributeRewards(token, amount);
}
```

The key issue is:
1. When gains are reported, yBOLD is minted to the Accountant
2. FeeRecipient can immediately withdraw this yBOLD via `distribute`
3. If losses occur later, the Accountant has no yBOLD reserves to cover them
4. This breaks the 1:1 peg since losses remain uncovered

## Impact
- Critical severity
- Breaks fundamental protocol invariant of 1:1 peg between yBOLD and BOLD
- Loss of user funds due to depegging
- Undermines the core loss coverage mechanism

## Proof of Concept
```solidity
function testDistributeBreaksPeg() public {
    // Setup
    uint256 initialBold = 1000e18;
    uint256 gain = 100e18;
    uint256 loss = 50e18;
    
    // Fund strategy and report gain
    deal(address(bold), address(strategy), initialBold);
    vm.prank(address(strategy));
    accountant.report(address(strategy), gain, 0);
    
    // FeeRecipient distributes all yBOLD
    uint256 accountantBalance = yBold.balanceOf(address(accountant));
    vm.prank(feeRecipient);
    accountant.distribute(address(yBold), accountantBalance);
    
    // Strategy reports loss
    vm.prank(address(strategy));
    accountant.report(address(strategy), 0, loss);
    
    // Check peg is broken
    assertLt(vault.totalAssets(), vault.totalSupply());
    // Price per share < 1, peg broken
    assertLt(vault.pricePerShare(), 1e18);
}
```



## Recommendations
Add checks to prevent distributing yBOLD when losses need to be covered:

```solidity
function distribute(address token, uint256 amount) public virtual onlyFeeManagerOrRecipient {
    // If distributing yBOLD, check vault is fully collateralized
    if (token == address(yBold)) {
        for (uint i = 0; i < vaults.length; i++) {
            IVault vault = IVault(vaults[i]);
            require(
                vault.totalAssets() >= vault.totalSupply(),
                "Cannot distribute while underwater"
            );
        }
    }
    
    ERC20(token).safeTransfer(feeRecipient, amount);
    emit DistributeRewards(token, amount);
}
```

Additionally:
1. Implement a reserve system to lock minimum yBOLD for loss coverage
2. Add timelock for yBOLD distributions
3. Only allow distributing excess yBOLD above required reserves
