## Description
The `LiquityV2SPStrategy` contract has a critical accounting issue in the `_harvestAndReport()` function. This function is responsible for providing an accurate accounting of all funds held by the strategy, which is used for profit/loss calculations. However, it currently fails to account for two important asset sources:
1. The collateral token (`COLL` e.g WETH or rETH) balance held directly by the strategy
2. The collateral token balance in the auction contract that belongs to the strategy
```solidity
  function _harvestAndReport() internal override returns (uint256 _totalAssets) {
        if (!TokenizedStrategy.isShutdown()) {
            uint256 _toDeploy = asset.balanceOf(address(this));
            if (_toDeploy > dustThreshold) _deployFunds(_toDeploy);
        }

        return estimatedTotalAssets();
    }

    function estimatedTotalAssets() public view returns (uint256) {
        return asset.balanceOf(address(this)) + SP.getCompoundedBoldDeposit(address(this)); 
    
    } 
```


According to the documentation in competition page:
> When BOLD from the stability pool is used for liquidations, depositors' BOLD balances are reduced, and collateral is distributed pro rata to them. Since the strategy is also a depositor, it receives collateral tokens which are then auctioned off for BOLD to restore the strategy's position.

The issue occurs in the `_harvestAndReport()` function which wrongly returns `estimatedTotalAssets()`, and this function only accounts for:
- The strategy's BOLD balance
- The strategy's BOLD deposits in the Stability Pool


The function comment explicitly states in `_harvestAndReport` of `BaseStrategy.sol`: "All applicable assets including loose assets should be accounted for in this function" and "Care should be taken when relying on oracles or swap values rather than actual amounts as all Strategy profit/loss accounting will be done based on this returned value." However, the implementation violates these requirements by not accounting for collateral value.

## Impact
This result in loss of fund for users and share price manipulation.


## Proof of Concept
1. The strategy has deposited its `asset` (BOLD) into the Liquity Stability Pool (`SP`). This is standard operation via `_deployFunds`.
2. A liquidation event occurs in the Liquity protocol.
3. The strategy's BOLD balance in the Stability Pool is reduced
4. The strategy receives collateral tokens as compensation
5. The `tend()` function is called, which:
   - Claims collateral from the Stability Pool
   - Transfers collateral to the auction contract
   - Kicks off an auction to sell the collateral for BOLD
6. During the auction period, `report` is called which then calls `_harvestAndReport()` 
7. The function only returns `estimatedTotalAssets()` which doesn't account for:
   - Collateral tokens held by the strategy
   - Collateral tokens in the auction contract
8. This results in wrong calculations of strategy's total assets, potentially leading to incorrect profit/loss calculations and share price manipulation
9.  When user withdraws all their funds after the first report, the user will bear this loss.

## Recommendation
Modify the `_harvestAndReport()` function to account for all assets, including collateral tokens. The value of collateral tokens should be calculated using the price oracle.
