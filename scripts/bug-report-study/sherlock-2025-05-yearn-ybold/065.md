# Staker Strategy Cannot Call Accountant.distribute()

### Summary

The `LV2SPStakerStrategy` contract's harvest and report functionality will fail due to an access control restriction when trying to distribute rewards through the `Accountant` contract. This creates a critical operational failure that prevents the strategy from completing its core reward claiming mechanism.


### Root Cause

### Execution Flow Trace

#### 1. Entry Point: BaseHealthCheck.harvestAndReport()

The execution begins when `harvestAndReport()` is called on the strategy:

```solidity
// BaseHealthCheck.sol - Lines 123-131
function harvestAndReport()
    external
    override
    onlySelf
    returns (uint256 _totalAssets)
{
    // Let the strategy report.
    _totalAssets = _harvestAndReport();

    // Run the healthcheck on the amount returned.
    _executeHealthCheck(_totalAssets);
}
```

#### 2. Strategy Implementation: Staker._harvestAndReport()

The `BaseHealthCheck` calls the overridden `_harvestAndReport()` method in the `Staker` contract:

```solidity
// Staker.sol - Lines 50-55
function _harvestAndReport() internal override returns (uint256 _totalAssets) {
    ACCOUNTANT.distribute(address(asset)); // Claim yBOLD
    
    // Return total balance
    _totalAssets = asset.balanceOf(address(this));
}
```

**Key Point**: At this stage, `msg.sender` for any subsequent calls to the `Accountant` contract will be the **address of the Staker contract**.

#### 3. External Call: Accountant.distribute(address token)

The `Staker` calls the external `distribute` function:

```solidity
// Accountant.sol - Lines 397-401
function distribute(
    address token
) external virtual {
    distribute(token, ERC20(token).balanceOf(address(this)));
}
```

**Critical Detail**: This external function has **no access control modifier** - it appears to be callable by anyone.

#### 4. Internal Call: Accountant.distribute(address token, uint256 amount)

The external `distribute` function makes an **internal call** to the overloaded `distribute` function:

```solidity
// Accountant.sol - Lines 409-413
function distribute(address token, uint256 amount) public virtual onlyFeeManagerOrRecipient {
    ERC20(token).safeTransfer(feeRecipient, amount);

    emit DistributeRewards(token, amount);
}
```

**The Problem**: This function has the `onlyFeeManagerOrRecipient` modifier.

#### 5. Access Control Check Failure

The modifier performs this check:

```solidity
// Accountant.sol - Lines 68-72
modifier onlyFeeManagerOrRecipient() {
    _checkFeeManagerOrRecipient();
    _;
}

function _checkFeeManagerOrRecipient() internal view virtual {
    require(msg.sender == feeRecipient || msg.sender == feeManager, "!recipient");
}
```

**The Critical Issue**: In Solidity, when making internal function calls within the same contract, `msg.sender` **does not change**. It remains the original external caller - in this case, the **Staker contract address**.

Therefore, the require statement effectively becomes:
```solidity
require(StakerContractAddress == feeRecipient || StakerContractAddress == feeManager, "!recipient");
```
Link : https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L409 

### Why This Fails

Unless the `Staker` contract address is explicitly set as either:
- The `feeManager` in the `Accountant` contract, OR  
- The `feeRecipient` in the `Accountant` contract

The `require` statement will evaluate to `false`, causing the transaction to revert with the error message `"!recipient"`.

### Attack Path

```bash
External Call → BaseHealthCheck.harvestAndReport()
                ↓ (msg.sender = caller)
Internal Call → Staker._harvestAndReport()  
                ↓ (msg.sender = caller)
External Call → Accountant.distribute(token)     [msg.sender = Staker contract]
                ↓ (msg.sender = Staker contract)
Internal Call → Accountant.distribute(token, amount) 
                ↓ (msg.sender = Staker contract - UNCHANGED!)
Access Check  → require(Staker == feeManager || Staker == feeRecipient)
                ↓
Result        → REVERT (unless Staker is explicitly set as feeManager/feeRecipient)
```

### Impact

The `_harvestAndReport()` function will always revert

### Mitigation

```solidity
function _distribute(address token, uint256 amount) internal {
    ERC20(token).safeTransfer(feeRecipient, amount);
    emit DistributeRewards(token, amount);
}

// Keep external function unrestricted for strategy access
function distribute(address token) external virtual {
    _distribute(token, ERC20(token).balanceOf(address(this)));
}

// Keep public function restricted for direct external calls
function distribute(address token, uint256 amount) public virtual onlyFeeManagerOrRecipient {
    _distribute(token, amount);
}
```
