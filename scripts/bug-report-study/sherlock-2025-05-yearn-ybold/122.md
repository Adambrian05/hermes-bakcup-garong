# Improper access control renders `_harvestAndReport` unusable

## Summary
`_harvestAndReport` calls `ACCOUNTANT.distribute` which is a function only callable by fee management and fee recipient, however `_harvestAndReport` is a method found in strategy contracts exclusively. 
## Description
Let's observe the flow of `_harvestAndReport`
```solidity 
    function _harvestAndReport() internal override returns (uint256 _totalAssets) {
        ACCOUNTANT.distribute(address(asset)); 
        _totalAssets = asset.balanceOf(address(this));
    }
```
Calls `distribute` in accountant which looks like this 
```solidity
    function distribute(
        address token
    ) external virtual {
        distribute(token, ERC20(token).balanceOf(address(this)));
    }

    function distribute(address token, uint256 amount) public virtual onlyFeeManagerOrRecipient {
        ERC20(token).safeTransfer(feeRecipient, amount);

    }
```
The public `distribute` has `onlyFeeManagerOrRecipient` modifier which limits the callers to only 2 addresses. However `_harvestAndReport` is inherited from `BaseStrategy.sol` and is a method called whenever a strategy reports profits via `report` . All strategies are expected to be able to invoke `report -> harvestAndReport -> _harvestAndReport` however it will revert due to the improper access control. 
## Impact
Broken core functionality, improper access control
## Mitigation
Allow strategies to call `distribute` too.
