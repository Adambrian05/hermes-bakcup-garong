# Mixing Shares and Assets in report function

### Summary

Shares (totalSupply): This is the total number of yBOLD tokens (ERC-4626 shares) issued by the vault.
Assets (totalAssets): This is the total amount of BOLD tokens (the underlying asset) held by the vault.

In ERC-4626 vaults, 1 share ≠ 1 asset after the first profit/loss.
The price per share is:

`pricePerShare = totalAssets / totalSupply`

​
 
After any profit or loss, this ratio will change.
Directly comparing assets < supply is only valid if 1 share = 1 asset, which is almost never true after the first deposit.
If the price per share is >1 (vault has made a profit), assets < supply will always be false, even if the vault is underwater.
If the price per share is <1 (vault has taken a loss), assets < supply may be true even if the vault is not truly underwater


### Root Cause

In the `report` function in `Accountant.sol`: https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L146

```Solidity
    function report(
        address strategy,
        uint256 gain,
        uint256 loss
    ) public virtual onlyAddedVaults returns (uint256 totalFees, uint256 /* totalRefunds */ ) {
        // Declare the config to use as the custom.
        Fee memory fee = customConfig[msg.sender];

        // Check if there is a custom config to use.
        if (!fee.custom) {
            // Otherwise use the default.
            fee = defaultConfig;
        }

        // Retrieve the strategy's params from the vault.
        IVault vault = IVault(msg.sender);
        IVault.StrategyParams memory strategyParams = vault.strategies(strategy);

        // Only charge performance fees if there is a gain.
        if (gain > 0) {
            // If we are skipping the healthcheck this report
            if (skipHealthCheck[msg.sender][strategy]) {
                // Make sure it is reset for the next one.
                skipHealthCheck[msg.sender][strategy] = false;

                // Setting `maxGain` to 0 will disable the healthcheck on profits.
            } else if (fee.maxGain > 0) {
                require(gain <= (strategyParams.current_debt * (fee.maxGain)) / MAX_BPS, "too much gain");
            }

            // 100% performance fee
            totalFees = gain;

            // Only take fee if there's no loss.
            uint256 supply = vault.totalSupply();
            uint256 assets = vault.totalAssets();
            if (assets < supply) {
                uint256 needed = supply - assets;
                totalFees = gain < needed ? 0 : gain - needed;
            }
        } else {
            // If we are skipping the healthcheck this report
            if (skipHealthCheck[msg.sender][strategy]) {
                // Make sure it is reset for the next one.
                skipHealthCheck[msg.sender][strategy] = false;

                // Setting `maxLoss` to 10_000 will disable the healthcheck on losses.
            } else if (fee.maxLoss < MAX_BPS) {
                require(loss <= (strategyParams.current_debt * (fee.maxLoss)) / MAX_BPS, "too much loss");
            }
        }

        return (totalFees, 0);
    }
```



`totalSupply()` returns the number of vault shares.
`totalAssets()` returns the amount of underlying tokens.
These are not directly comparable. After any profit/loss, the price per share changes, so comparing these values is meaningless and will lead to incorrect fee logic.

### Impact

If the vault is underwater `(assets < shares * pricePerShare)`, the check may not work as intended.
This can result in:
* Overcharging fees when the vault is underwater (users lose more).
* Undercharging fees or skipping fees when the vault is not underwater (protocol loses revenue).
* Broken accounting and user balances.

### PoC

After even one successful report, the vault’s pricePerShare will almost never remain exactly 1 token/share. If pricePerShare = 1.05, then

supply = 1 000 000 shares → underlying value should be 1 050 000 BOLD

assets = 1 050 000 BOLD
But the code checks 1 050 000 < 1 000 000 → false, so it thinks the vault is solvent when in fact it’s exactly at break-even.

### Mitigation

Convert both values to the same unit before comparing.
For example, convert supply (shares) to assets using the vault's price per share:

```Solidity
  uint256 supplyInAssets = (supply * vault.pricePerShare()) / 1e18;
  if (assets < supplyInAssets) { ... }
```

Or, convert assets to shares using the vault's conversion function.
