# Unauthorized user can deploy arbitrary strategies affecting protocol integrity

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32

#### Summary

The absence of access control in the `newStrategy` function allows any user to deploy new strategies, potentially compromising the protocol's integrity.

#### Root Cause

In [`StakerFactory.sol:32`](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32), the `newStrategy` function lacks access control, permitting any user to invoke it and deploy a new strategy instance.

#### Internal Pre-conditions

1. Any user calls `newStrategy()` with arbitrary parameters.

#### External Pre-conditions

1. No external conditions are required; the function is publicly accessible.

#### Attack Path

1. An unauthorized user calls `newStrategy()` with malicious parameters.
2. A new strategy is deployed and registered in the `deployments` mapping.
3. The malicious strategy interacts with the protocol, potentially leading to unauthorized actions or fund mismanagement.

#### Impact

The protocol suffers potential integrity breaches, unauthorized fund access, and reputational damage.

#### PoC

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.0;

import "./StakerFactory.sol";

contract MaliciousActor {
    StakerFactory factory;

    constructor(address _factory) {
        factory = StakerFactory(_factory);
    }

    function exploit(address _asset, string calldata _name) external {
        factory.newStrategy(_asset, _name);
    }
}
```



#### Mitigation

Implement access control in the `newStrategy` function to restrict its usage to authorized roles, such as the `management` address.
