# Overflow in Auction Price Calculation Can Cause Denial of Service

### Summary

Unchecked multiplication and division in `_tend()` will cause an overflow for the auction contract as an attacker will send a large amount of collateral to the contract, making the price calculation revert and block future auctions

### Root Cause

In `Strategy.sol:_tend()` the starting price calculation `AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD)` performs multiple multiplications before divisions without upcasting, which can overflow when _available is manipulated

The attacker needs to have a large amount of `COLL` tokens

The attacker transfers a large amount of `COLL` directly to the strategy contract to inflate `_toAuction`

### Attack Path

1. Attacker sends large amount of COLL to the strategy contract (e.g., 1e50)

2. `_tend()` is triggered (manually or via automation)

3. `_available` * `_price` overflows due to large _available

4. `AUCTION.setStartingPrice()` reverts

5. Auction cannot be kicked and `_tend()` fails repeatedly

6. Protocol cannot auction collateral, causing a denial of service

### Impact

The protocol cannot execute auctions for this collateral. This causes a denial of service that halts collateral liquidation. The attacker does not directly gain funds but can freeze functionality, possibly enabling other attacks like stale collateral pricing or griefing users.

### PoC

```solidity
function testOverflowAuction() public {
    // Deploy and setup
    address strategy = deployStrategy();
    address coll = getCollToken();

    // Attacker sends large collateral directly to the contract
    IERC20(coll).transfer(strategy, 2**128); // large enough to cause overflow

    // Call _tend which will try to calculate price
    vm.expectRevert(); // Should revert due to overflow
    Strategy(strategy).tend();
}

```

### Mitigation

AUCTION.setStartingPrice(_available * _price / WAD * _bufferPercentage / WAD / WAD); // Reverts if there's an active auction
