# In `##Strategy.sol##_tend` the `claim` when called will be useless due to 0 being passed in the param of `_freeFunds` fn

### Summary

According to the README **Design Choices** it says - "To reduce exposure to fluctuations in the collateral-to-BOLD exchange rate, the strategy aims to call tend() as soon as collateral is available. Tending claims the collateral gains and initiates an auction to convert them back into BOLD." this and normally also the the `_tend` will be called as soon an if there is collateral available. What `tending` does is that it claims the collateral gains and initiates the auction in order to convert those in to the `BOLD` token. However the issue here is that when the `_tend` is called right in the [first line](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L228C8-L228C48) the function checks that if there is any `collateralGainToClaim` and if it returns true meaning that there are gains to claim, the claim is called. BUT- coming to the issue, in the `claim` function, the function calls [_freeFunds](https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L185C1-L187C6) and the function(_freeFunds) takes amount as input param. This is the amount of collateral and yield gains to claim from the StabilityPool but since 0 is passed in, so the claim wont happen.

### Root Cause

0 being passed in the input param of the `freeFunds` function when it is called internally in the `claim` function.

### Internal Pre-conditions

The _tend needs to be called and there must be some collateral gains present in order for them to be claimed 

### External Pre-conditions

_tend will be called as soon as there are gains present

### Attack Path

The collateral gains gets presented
tend gets called
But the claims will not happen even if there are available due to the issue described above

### Impact

Since the claims will not be claimed. Since what tending does is that it claims the gains and initiates the auction to convert them back in to BOLD. Since this is the very main invariant of the protocol i.e the collateral must be auctioned off also in order to convert them back into BOLD as specified in the README too. This invariant will break due to this issue.

### PoC

```solidity
 function _tend(uint256 /*_totalIdle*/) internal override {
        if (isCollateralGainToClaim()) claim();
```

```solidity
    function claim() public {
        _freeFunds(0); //AUDIT- 0 being passed in
```

### Mitigation

Instead of passing in 0, simply pass in the amount of gains that are to be claimed in order for it to be converted back to BOLD
