# Unrealistic Auction Pricing During Oracle Downtime

### Summary

The `LiquityV2SPStrategy` applies a **1000x multiplier** to its auction buffer percentage (`ORACLE_DOWN_BUFFER_PCT_MULTIPLIER`) when the collateral price oracle is offline. This results in **artificially inflated auction prices** (e.g., 10% → 10,000% buffer) that are unresponsive to actual market conditions.

### Root Cause

When the oracle is down (`_isOracleDown = true`), the strategy blindly applies a 1000x multiplier to the buffer:  

```solidity  
            if (_isOracleDown || COLL_PRICE_ORACLE.priceSource() != IPriceFeed.PriceSource.primary) {
                _bufferPercentage *= ORACLE_DOWN_BUFFER_PCT_MULTIPLIER;
            }
```  

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L236-L238

This creates buffer percentages like **110,000%** (for a base 10% buffer), decoupling prices from reality. The strategy uses the **last known oracle price** even if the collateral’s market value has crashed (e.g., -80%), making auctions non-competitive.

### Impact

Overpriced auctions deter buyers, leaving collateral stuck indefinitely.

### PoC


- **Collateral**: 100 wstETH (value = $200,000 at $2,000/wstETH).  
- **Oracle Status**: Down (`_isOracleDown = true`).  
- **Market Reality**: wstETH price crashes to $1,000, but strategy uses stale $2,000 price.  
- **Buffer**: Base 10% → 10,000% (1000x multiplier).  

### Auction Pricing  

```solidity
Starting Price = $2,000 * 10,000% = $200,000 per wstETH  
Total Auction Value = 100 * $200,000 = $20,000,000  
```  
**Result**: No bids at $200,000/wstETH (10x above market).
