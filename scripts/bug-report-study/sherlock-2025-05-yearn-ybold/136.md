# there is no access control in creating new StakerFactory like it is in StrategyFactory

### Summary

In StakeFactory.sol, there is newStrategy() , which is called to create new strategy and then in which diff roles are being set.
and this strategy is deployments mapping which is 

```Solidity
   /// @notice Track the deployments. asset => pool => strategy
    mapping(address => address) public deployments;

```

As there is no access control here , anyone can create newStrategy with same asset and then it will be assigned in deployment mapping and older one would be overriden. so this will create issue, when this deployment mappping is called for some asset , another value will be written instead of original one

### Root Cause

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/StakerFactory.sol#L32C1-L48C6

### Internal Pre-conditions

A strategy is already created for asset, someone will again call it and override the mappinng

### External Pre-conditions

N/A

### Attack Path

User will call newStrategy with same asset and it would override the mapping . and new strategy would be assigned to the asset . as there is no accesscontrol

### Impact

when this mapping would be used, it will return different strategy address as it is already overridden by someone

### PoC

_No response_

### Mitigation

access control  should be there like it is in strategyfactory.sol
