# Hardcoded multiplier will deny auction access during oracle outages in Strategy.sol

### Summary

Hardcoded 1000x oracle buffer multiplier will cause auction denial of service for all users as oracle downtime will trigger impossible auction starting prices

### Root Cause

In Strategy.sol:44 the hardcoded ORACLE_DOWN_BUFFER_PCT_MULTIPLIER = 1_000 creates impossible auction prices when combined with the multiplication logic in _tend() function at lines 236-237

### Internal Pre-conditions

1. Oracle needs to go down or switch to non-primary price source to set _isOracleDown to be true OR COLL_PRICE_ORACLE.priceSource() to be other than IPriceFeed.PriceSource.primary
2. Strategy needs to have collateral rewards accumulated to set COLL.balanceOf(address(this)) to be at least dustThreshold (minimum 1e15)
3. Auction contract needs to have settled or be inactive to set AUCTION.available(address(COLL)) to be exactly 0
4. Any user needs to call tend function or claim function to trigger the _tend() internal function execution
5. Strategy needs to have total available collateral to set _available (sum of strategy balance + auction balance) to be at least dustThreshold
6. Oracle price feed needs to return a valid price to set _price to be at least greater than 0 from COLL_PRICE_ORACLE.fetchPrice()
7. Buffer percentage needs to be initialized to set bufferPercentage to be at least MIN_BUFFER_PERCENTAGE (1.1e18)





### External Pre-conditions

1. Oracle price feed needs to experience downtime to set COLL_PRICE_ORACLE.fetchPrice() to return _isOracleDown as true
2. Oracle price feed needs to switch from primary source to set COLL_PRICE_ORACLE.priceSource() to be other than IPriceFeed.PriceSource.primary
3. Network conditions need to cause oracle connectivity issues to trigger fallback mechanisms in the price feed contract
4. External price data providers (like Chainlink) need to fail or become unreliable to cause the oracle system to mark itself as down
5. Oracle contract needs to detect stale price data to automatically switch to non-primary price sources due to data freshness thresholds

When either condition occurs, the vulnerable code in Strategy.sol automatically applies the 1000x multiplier:



### Attack Path

1. Oracle experiences downtime - External oracle service becomes unavailable or switches to non-primary price source
2. User calls claim() function - Any user (including legitimate users) calls the public claim() function to harvest collateral rewards
3. System automatically triggers _tend() function - The claim() call internally executes _tend() logic which checks oracle state
4. Vulnerable code applies 1000x multiplier - The hardcoded logic detects oracle downtime and applies the extreme buffer multiplication
5. Auction starting price becomes impossible - The AUCTION.setStartingPrice() calculation uses the inflated buffer, creating prices 1000x higher than normal
6. All users are denied auction participation - The impossibly high starting prices prevent any legitimate bidder from participating in collateral auctions

### Impact

Protocol Level Impact:

 Cannot liquidate collateral rewards through auctions during oracle uncertainty

 Price discovery mechanism becomes non-functional precisely when conservative pricing is most critical

 Accumulated collateral tokens remain stuck in the strategy without liquidation pathway

User Level Impact:

 Cannot participate in auctions due to starting prices being 1000x higher than market value

 Legitimate bidders are economically excluded from auction participation

 No opportunity for users to acquire collateral at reasonable prices during oracle downtime

Economic Impact:

### Mitigation

Replace the hardcoded 1000x multiplier with a reasonable oracle downtime buffer:

```solidity
// Current problematic code:
uint256 public constant ORACLE_DOWN_BUFFER_PCT_MULTIPLIER = 1_000; // 1000x

// Recommended fix:
uint256 public constant ORACLE_DOWN_BUFFER_PCT_MULTIPLIER = 2; // 2x (100% increase)
```
