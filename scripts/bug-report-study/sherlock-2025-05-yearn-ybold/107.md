# Hardcoded IAuctionFactory Address Breaks MultiChain Compatibility and Enables Potential Attack Vectors

### Summary

The LiquityV2SPStrategy contract hardcodes the address of the IAuctionFactory contract, which is only valid on Ethereum. When the strategy is deployed to other chains (e.g., Arbitrum, Optimism, Base, Polygon, Sonic), this address will either be empty, invalid, or point to an unintended contract, leading to failures or potential malicious interactions.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/88a3b89c05fd6e59ec130c79659195cd05d872af/yv3-liquityv2-sp-strategy/src/Strategy.sol#L66C37-L66C53

### Attack Path

A malicious actor front-runs the deployment and deploys a fake IAuctionFactory at 0xCfA510188884F199fcC6e750764FAAbE6e56ec40 on a target chain.

When the strategy is deployed, it interacts with this malicious factory.

The attacker can return a malicious auction contract that can do malicious things.

Alternatively, if the address is unoccupied, contract calls like createNewAuction() will revert, rendering the strategy unusable.

### Impact

Strategy may become non-functional on non-Ethereum chains. Potential risk of loss of funds if a malicious contract is deployed at the expected address on other chains.

### PoC

_No response_

### Mitigation

Replace the hardcoded AUCTION_FACTORY with a constructor parameter:

```solidity
constructor(..., IAuctionFactory _auctionFactory) {
    AUCTION_FACTORY = _auctionFactory;
    ...
}
```
