# attacker can prevent tend() functionallity to execute by sending small wei

### Summary

In strategy.sol, in _tend(), there is condition , in which , settle function of settle is called.

```Solidity
if (AUCTION.isActive(address(COLL)) && AUCTION.available(address(COLL)) == 0) AUCTION.settle(address(COLL));
```
means whenever auction is active for our collalateral, and available balance in auction would be 0, it will call settle.

```Solidity
    function available(address _from) public view virtual returns (uint256) {
        if (!isActive(_from)) return 0;

        return
            Maths.min(
                auctions[_from].initialAvailable,
                ERC20(_from).balanceOf(address(this))
            );
    }
```
so here min of available and balance is passed. In ideal condition both would have been zero
```Solidity
    function settle(address _from) external virtual {
        require(isActive(_from), "!active");
        require(ERC20(_from).balanceOf(address(this)) == 0, "!empty");

        auctions[_from].kicked = uint64(0);
    }
```

so here in settle function 2 checks are there. 1 will be passed , but other can be manipulated by attacker.

### Attack Path

when tend functionallity is going to be called , attacker can pass 1 wei to auction contract , due to which all condition would be passed and it will lastly revert from balance of check

require(ERC20(_from).balanceOf(address(this)) == 0, "!empty");

### Impact

attacker can prevent from calling tend fucntionallity , and it is invariant which is mentioned. 
it is time sensitive , so attacker could break the invariant, whenever this condition would occur and settle has to be called.
