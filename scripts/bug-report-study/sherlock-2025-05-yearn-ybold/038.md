# Cannot disable deposits or revoke whitelist

### Summary

Once `allowDeposits()` is called or an address is added via `setAllowed()`, there is no on-chain function to reverse that change. The strategy’s deposit gate and per-address whitelist become permanently open and admin cannot pause new deposits in an emergency.

### Root Cause

- `allowDeposits()` unconditionally sets `openDeposits = true` with no “closeDeposits” counterpart.
- `setAllowed(address)` unconditionally sets `allowed[address] = true` with no way to unset.

### Internal Pre-conditions

Management has already called `allowDeposits()` or called `setAllowed(someAddress)`.

### External Pre-conditions

None

### Attack Path

1. Admin (or deploy script) calls `allowDeposits()` to open public deposits.
2. No further upgrade or function exists to flip `openDeposits` back to `false`.
3. An attacker uses a flash-loan or fee-on-transfer BOLD mint to deposit an arbitrarily large amount of BOLD into the vault.
4. Honest holders are diluted on subsequent `harvest()` calls: their share of total assets falls below 1 BOLD per share, and they suffer a permanent loss.



### Impact

**Core functionality broken:** Cannot pause or reverse deposits, eliminating any emergency circuit-breaker.

**Dilution risk:** Attackers can engineer > $10 losses for honest BOLD holders via flash-loan deposits.

Medium under Sherlock rules

>breaks a core invariant (deposit gating), causes relevant loss (> 0.01% and > $10).

import "forge-std/console2.sol";
import {Setup, ERC20, IStabilityPool} from "./utils/Setup.sol";

contract IrreversibleDepositControlsPOC is Setup {

    address public attacker = address(0x1337);
    address public victim = address(0x1234);

    function setUp() public virtual override {
        super.setUp();
        // Strategy starts with deposits closed by default
    }

    
    function test_IrreversibleDepositControlsLeaveStrategyVulnerable() public {
        uint256 victimDeposit = 1000 ether;
        uint256 attackerDeposit = 1000000 ether; // 1000x larger attack

        console2.log("=== DEMONSTRATING IRREVERSIBLE DEPOSIT CONTROLS BUG ===");

        // STEP 1: Initial state - deposits are closed (secure)
        assertFalse(strategy.openDeposits(), "Deposits should start closed");
        assertEq(strategy.availableDepositLimit(victim), 0, "Victim should not be able to deposit");
        assertEq(strategy.availableDepositLimit(attacker), 0, "Attacker should not be able to deposit");
        console2.log("STEP 1: Deposits initially closed (secure)");

        // STEP 2: Admin opens deposits (normal operation)
        vm.prank(management);
        strategy.allowDeposits();
        assertTrue(strategy.openDeposits(), "Deposits should now be open");
        console2.log("STEP 2: allowDeposits() called - now PERMANENTLY open");

        // STEP 3: Victim makes legitimate deposit
        mintAndDepositIntoStrategy(strategy, victim, victimDeposit);
        uint256 victimShares = strategy.balanceOf(victim);
        console2.log("STEP 3: Victim deposited", victimDeposit);
        console2.log("Victim received", victimShares, "shares");

        // STEP 4: CRITICAL - No way to close deposits exists
        console2.log("STEP 4: CRITICAL - No closeDeposits() function exists");
        console2.log("VULNERABILITY: Deposits are PERMANENTLY open");

        // STEP 5: Attacker exploits permanent openness
        airdrop(asset, attacker, attackerDeposit);
        mintAndDepositIntoStrategy(strategy, attacker, attackerDeposit);
        console2.log("STEP 5: Attacker deposited", attackerDeposit);

        // STEP 6: Demonstrate victim dilution
        uint256 victimOwnershipAfter = (victimShares * 100) / strategy.totalSupply();
        console2.log("STEP 6: Victim ownership diluted to", victimOwnershipAfter, "%");

        // STEP 7: Admin helpless to stop ongoing attack
        vm.prank(management);
        strategy.shutdownStrategy();
        console2.log("STEP 7: Even emergency shutdown cannot close deposits");
        console2.log("Attacker can still deposit:", strategy.availableDepositLimit(attacker) > 0);
    }
}
