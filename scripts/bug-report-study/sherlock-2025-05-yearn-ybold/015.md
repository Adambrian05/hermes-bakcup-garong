# Oracle manipulation will misprice auctions for strategy

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L225

**Summary**
The insufficient validation on oracle responses will cause incorrect auction price settings for the strategy as a malicious or failing oracle will still be used to compute the `startingPrice`.

**Root Cause**
In `LiquityV2SPStrategy.sol:225`, `_tend()` fetches a potentially manipulated `_price` even when `_isOracleDown == true`, and still uses it to compute the auction starting price.

**Internal Pre-conditions**

1. Anyone calls `TokenizedStrategy.tend()` which in turn calls `LiquityV2SPStrategy._tend()`.
2. `_isOracleDown` returns `true` and a manipulated `_price` is returned.

**External Pre-conditions**

1. Oracle returns `isOracleDown == true` and a manipulated price.
2. Price is significantly different than fair market price.

**Attack Path**

1. Attacker manipulates price feed (if unprotected).
2. `TokenizedStrategy.tend()` is called.
3. `_price` is used even though `isOracleDown == true`.
4. Auction is initiated with manipulated `startingPrice`.

**Impact**
The protocol suffers a loss of collateral due to auctions selling assets too cheaply. The attacker gains the collateral by underpaying at auction.

**PoC**

```solidity
// This is a logical PoC
// Collateral price is manipulated to 1 wei
// auction start price is now negligible
```

**Mitigation**
Abort `_tend()` if `isOracleDown == true` or fallback to a trusted internal price. Never use `_price` when `isOracleDown == true`.
