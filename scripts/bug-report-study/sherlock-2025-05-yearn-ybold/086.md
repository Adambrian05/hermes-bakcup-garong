# Invariants are broken if `protocol_fee_bps` is set to any non-zero amount

### Summary

The contest page has the following Invariant:

`When process_report is called on yBOLD, any gain must be fully minted as yBOLD to Accountant.sol, from which it will be distributed to st-yBOLD.`

This invariant is broken if the protocol ever decides to change `protocol_fee_bps` to any non-zero value, as it applies the fee directly to the gain that is to be minted to `Accountant` - as the gain is not `fully` minted to `Accountant` and the accountant no longer achieves its stated goal of 100% performance fee.

### Root Cause

In the `vault` (yBond) contract, when calling `report` on the `Accountant` contract - it receives back `totalFees` which is the amount of the fees that the Accountant needs to recieve. These fees are the reported gain.

The `Accountant` implements a 100% performance fee, which means that it is supposed to receive yBond EXACTLY the same amount of the reported gain that it reports back to the Vault as `totalFees`. The Vault is then responsible for minting yBond of that EXACT amount to the `Accountant`.

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/periphery/Accountant.sol#L146-L198

However, the Vault has logic that applies the `protocol_fee_bps` directly to the `totalFees` amount that is reported by the `Accountant`.

When applying the `protocol_fee_bps` to the `totalFees` amount, this directly breaks the Invariant as it minimizes the amount of yBond that gets minted to the `Accountant` - leaving the accountant getting less (and depending on the fee, possibly much less) yBond than the gain amount that it should.


### Internal Pre-conditions

1. `protocol_fee_bps` is set to a non-zero value

### External Pre-conditions

1. Vault management decide to update `protocol_fee_bps` to a non-zero value

### Attack Path

1. Accountant returns a value of `totalFees` to the Vault that it should receive in newly minted yBold
2. The Vault applies `protocol_fee_bps` to the amount of fees that belong to the Accountant, reducing that amount
3. The Accountant is then minted significantly less fees 

### Impact

The Vault will reduce the `totalFees` / gain amount that should go to the Accountant by whatever percentage `protocol_fee_bps` is set to. 

If the fee is set to 15%, then the Accountant will effectively receive 15% less than what it should, breaking the Invariant that all gain must be FULLY minted to the Accountant.

The Accountant now does not actually have a 100% performance fee, and each time it receives gain / fee from a vault, it will receive much less than it should. 

### PoC

In the `Vault` (yBond) contract, in the flow of `process_report` - it receives a value back from accountant `totalFees` - which represents the gain that was reported and the amount of yBond that needs to be minted to Accountant for fee's. 

With this value, the Vault calculates the amount of shares corresponding to that EXACT amount that needs to be minted to Accountant.
BUT THEN it applies the `protocol_fee_bps` to that amount of shares that should go to the Accountant - effectively removing a portion of the fees going to accountant so that it can send to the feeReceiever of `protocol_fee_bps` 

```solidity
       # If we have fees then get the proportional amount of shares to issue.
        if total_fees > 0:
            # Get the total amount shares to issue for the fees.
->            total_fees_shares = shares_to_burn * total_fees / (loss + total_fees)

            # Get the protocol fee config for this vault.
            protocol_fee_bps, protocol_fee_recipient = IFactory(self.factory).protocol_fee_config()

            # If there is a protocol fee.
            if protocol_fee_bps > 0:
                # Get the percent of fees to go to protocol fees.
->                protocol_fees_shares = total_fees_shares * convert(protocol_fee_bps, uint256) / MAX_BPS
```

So, for example if `totalFees` that should go to Accountant is 100 and the `protocol_fee_bps` represents 20%, the `protocol_fee_shares` will be 20 - leaving the amount going to the Accountant as 80. 

`protocol_fee_shares` is later sent to the receiver of that fee, and the Accountant is minted `total_fee_shares` - `protocol_fee_shares` 


### Mitigation

If setting `protocol_fee_bps` to a non-zero value, to satisfy the invariants, apply the fee to a different part of the protocol flow. Do not apply it directly to the gain / fee amount that should go to the Accountant, as it will drastically reduce the fee's that the accountant will receive.
