# Zero-Price Auction Bug in _tend() Function

### Summary

A critical bug in the _tend() function of LiquityV2SPStrategy causes the collateral auction’s starting price to be set to zero (or near zero) due to excessive integer division. Attackers can exploit this to buy the strategy’s reward collateral at virtually no cost, leading to a complete loss of these assets from the strategy.

### Root Cause

The logic for calculating the auction’s starting price is:

https://github.com/sherlock-audit/2025-05-yearn-ybold/blob/main/yv3-liquityv2-sp-strategy/src/Strategy.sol#L241
```solidity
AUCTION.setStartingPrice(
    _available * _price / WAD * _bufferPercentage / WAD / WAD
);
```

Because this multiplies and then triple-divides by 1e18 (WAD), even moderate collateral rewards can collapse to zero after integer division floors the result. Consequently, setStartingPrice(0) allows attackers to purchase the entire collateral reward for free.

### Internal Pre-conditions

_available > dustThreshold so that the strategy attempts to start an auction.

Collateral was previously earned by the strategy and is ready to be auctioned in _tend().

_bufferPercentage and _price produce normal-sized numbers, but the triple division floors them to zero.

### External Pre-conditions

An attacker or automated bot monitoring the contract is ready to purchase collateral from the auction the instant the strategy sets startingPrice to zero.

The attacker can trigger or observe the tend process, then quickly call the auction contract to buy the collateral for zero.

### Attack Path

A normal operation triggers _tend() (e.g., keeper calls tend() on the strategy).

The strategy claims or has leftover collateral (_toAuction) that is above dustThreshold.

Because of the triple division, the calculated startingPrice becomes 0.

The attacker immediately calls the auction to buy all collateral for zero cost.

### Impact

All reward collateral that the strategy attempts to auction is essentially given away, causing a total loss of those assets. This permanently damages the strategy’s yields and can result in a reduced share price or direct economic losses to depositors.

### PoC

Call _tend() when there is a small (but nonzero) _available collateral amount, for example 0.1 Coll.

Immediately purchase the entire 0.1 Coll for 0 tokens.

### Mitigation

Replace the triple division by WAD with only two WAD divisions. A correct approach is:

```solidity
uint256 startingPrice = (_available * _price) / WAD;       // Convert to “USD value”
startingPrice = (startingPrice * _bufferPercentage) / WAD; // Apply buffer
AUCTION.setStartingPrice(startingPrice);
```

This ensures integer math doesn’t floor to zero prematurely. Additionally, a higher dustThreshold or built-in checks (e.g., require(startingPrice > 0, "Bad price")) can help detect issues.
