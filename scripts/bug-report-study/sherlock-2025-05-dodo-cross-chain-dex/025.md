# User will drain `GatewayTransferNative` contract tokens by calling `withdraw()` function directly

### Summary

The incorrect public visibility of the `withdraw()` helper function in `GatewayTransferNative.sol` will cause a complete loss of contract funds for the protocol as a user will call the function directly to withdraw any tokens held by the contract without providing any assets.

### Root Cause

In `GatewayTransferNative.sol:285` the `withdraw()` function is marked as `public` instead of `internal`, allowing direct external access to drain contract funds without any validation or asset deposits.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304


### Internal Pre-conditions

1. Contract needs to hold token balances from previous legitimate transactions or deposits

### External Pre-conditions

N/A

### Attack Path

1. **User calls `GatewayTransferNative::withdraw()` directly with their address as sender and any token the contract holds**
2. **The function executes without any access control, balance checks, or deposit validation**
3. **The function calls `gateway.withdraw()` which transfers tokens from the contract to the user's address**
4. **User receives tokens from the contract without providing any assets in return**

### Impact

The protocol suffers a complete loss of all token balances held in the contract. The attacker gains all tokens stored in the contract without providing any assets or paying any fees


### PoC

_No response_

### Mitigation

Change the visibility of `GatewayTransferNative::withdraw()` from `public` to `internal`.
