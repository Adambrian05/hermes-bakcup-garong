# Bitcoin Gas-Fee Mismatch (Missing Gas Limit) Causes Locked Funds

### Summary

When bridging tokens to Bitcoin, the contract calls `withdrawGasFee()` instead of `withdrawGasFeeWithGasLimit()`. As a result, the static gas fee returned may be insufficient to cover actual on-chain Bitcoin‐side gas costs. If `gateway.withdraw(...)` reverts due to an underestimated fee, the user’s principal (minus platform fees) becomes permanently locked in the contract, with no refund mechanism invoked.

### Root Cause

In the `onCall` flow for `dstChainId == BITCOIN_EDDY`, the code uses:

```solidity
(, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
```
rather than

```solidity
(address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);
```

By omitting the `gasLimit` parameter, the returned `gasFee` can be lower than required. When `gateway.withdraw(...)` is called with an insufficient fee, it reverts before recording any refund, leaving user tokens stranded.

### Internal Pre-conditions

- `decoded.dstChainId` equals `BITCOIN_EDDY` (the hardcoded constant for Bitcoin).
- The user has already deposited tokens and paid platform fees.
- `decoded.targetZRC20` correctly identifies a ZRC20 token that supports `withdrawGasFee()` and `withdrawGasFeeWithGasLimit()`.
- The contract holds at least `outputAmount + gasFee` of `decoded.targetZRC20` after any swaps.

### External Pre-conditions

None

### Attack Path

1. User calls `onCall(...)` with `dstChainId` set to `BITCOIN_EDDY`, sending some ZRC20 tokens (or ETH), which convert to `outputAmount` of `decoded.targetZRC20` after any swaps. The contract deducts platform fees and calculates `outputAmount`, leaving `outputAmount` in the contract to forward.
2. Contract executes
```solidity
(, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
```
Suppose `withdrawGasFee()` returns a static fee (e.g., 0.0001 BTC equivalent) that is below the actual on‐chain cost for a Bitcoin transaction at the time.
3. The contract the calls:
```solidity
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
gateway.withdraw(
    externalId,
    decoded.contractAddress,
    decoded.targetZRC20,
    outputAmount,
    gasFee,
    decoded.receiver
);
```
Because `gasFee` is insufficient, `gateway.withdraw(...)` reverts internally with “INSUFFICIENT_GAS_FOR_WITHDRAW” (or similar).
4. The revert occurs within `onCall`, before any `onRevert` or `onAbort` is triggered. The user’s platform fee is already transferred to `EddyTreasurySafe` and the remaining `outputAmount` of tokens remains in `GatewayCrossChain` with no `refundInfos` entry created.
5. Since neither `onRevert` nor `onAbort` was called, there is no on-chain refund record for this transaction. The user cannot recover their `outputAmount` via `claimRefund`. Only the contract owner’s `superWithdraw(...)` can retrieve these tokens—and only if the owner notices and executes it.

### Impact

Users lose platform fees immediately (e.g., 0.5% of their deposit) and have the remainder of their principal irretrievably stuck in the contract unless the owner intervenes.
