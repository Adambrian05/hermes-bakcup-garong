# abortAddress should not be address(0) in GatewayCrossChain and GatewayTransferNative contracts

### Summary

[GatewayCrossChain.sol:withdrawAndCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244) and [GatewayTransferNative.sol:withdrawAndCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L253) calls `gateway.withdrawAndCall()` with `abortAddress = address(0)` **even though both of the contracts implement an** `onAbort()` **functions**. According to [ZetaChain's documented flow](https://www.zetachain.com/docs/developers/chains/zetachain/#onabort:~:text=If%20the%20onRevert%20call%20itself%20reverts%2C%20the%20Gateway%20transfers%20ZRC%2D20%20tokens%20to%20and%20calls%20onAbort%20on%20the%20abortAddress%20on%20ZetaChain.), this prevents proper fallback handling if the `onRevert()` call fails, as `onAbort()` will never be used and tokens will be sent to `address(0)`.

### Root Cause

According to the docs: _If the `onRevert` call itself reverts, the Gateway transfers ZRC-20 tokens to and calls `onAbort` on the `abortAddress` on ZetaChain._
But `GatewayCrossChain.sol:withdrawAndCall()` and `GatewayTransferNative.sol:withdrawAndCall()` calls `gateway.withdrawAndCall() `with `abortAddress = address(0)`:
```solidity
function withdrawAndCall(
    bytes32 externalId,
    bytes memory contractAddress,
    address targetZRC20,
    uint256 outputAmount,
    bytes memory receiver,
    bytes memory message
) internal {
    gateway.withdrawAndCall(
        contractAddress,
        outputAmount,
        targetZRC20,
        message,
        CallOptions({
            isArbitraryCall: false,
            gasLimit: gasLimit
        }),
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            //@audit address where tokens will be sent if onRevert() fails
            abortAddress: address(0), 
            revertMessage: bytes.concat(externalId, receiver),
            onRevertGasLimit: gasLimit
        })
    );
}
```
 This breaks the expected revert behavior for cross-chain interactions as `onAbort()` will never be used and tokens will be sent to `address(0)` if `onRevert()` fails.

### Internal Pre-conditions

1. `onRevert()` function fails

### External Pre-conditions

1. Gateway's call to target contract reverts

### Attack Path

_No response_

### Impact

Tokens will be burned in `address(0)` instead of being properly refunded.

### PoC

_No response_

### Mitigation

Change `abortAddress` to `address(this)`.
