# Cross-chain swaps will always revert on Arbitrum due to a signature mismatch of `mixSwap`

### Summary

A function signature mismatch between `DODORouteProxy.mixSwap` implementations on different chains will cause swaps to always revert on some chains, breaking the protocol's intended cross-chain swap functionality.

### Root Cause

This is the `_doMixSwap` implementation on `GatewayCrossChain` and `GatewaySend`

```solidity
  function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```

But on Arbitrum - one of the chains the protocol intends to be deployed onto, this is the `mixSwap` [function](https://www.arbiscan.io/address/0xe05dd51e4eb5636f4f0e8e7fbe82ea31a2ecef16#code#L1389)

```solidity
function mixSwap(
        address fromToken,
        address toToken,
        uint256 fromTokenAmount,
        uint256 minReturnAmount,
        address[] memory mixAdapters, //@audit - one argument less!
        address[] memory mixPairs,
        address[] memory assetTo,
        uint256 directions,
        bytes[] memory moreInfos,
        bytes memory feeData,
        uint256 deadLine
    )
```

There is only 11 arguments while `_doMixSwap` passes 12 (which matches the signature on other chains, such as ZetaChain).
The consequence is that `_doMixSwap` will always revert on Arbitrum.

### Internal Pre-conditions

- Gateway contracts are deployed on Arbitrum (expected as per Readme.md)
- Users make a cross swap where they intend the `_doMixSwap` call to happen on Arbitrum (whether it is on the source or destination chain)

### External Pre-conditions

N/A

### Attack Path

1. Alice initiates a cross-chain swap on ZetaChain.
2. The gateway forwards the call to Arbitrum, where the local DODO proxy expects only 11 arguments (see above)
2. The call to `GatewayCrossChain.onCall()` eventually calls `_doMixSwap`
4. Because of the arguments mismatch, the call reverts. 

### Impact

Reverts are handled by the TSS, which eventually leads to the revert to be bubbled up back on the source chain.
So no funds are lost, but the cross chain swap functionality is broken on this chain.

Based on the test files (particularly `GatewayCrossChain.t.sol`), we can confirm the protocol intends to support swap functionality on destination chains, so this is a real issue that needs to be tackled.

### Mitigation

Ensure you have a versioning system for `IDODORouteProxy.mixSwap` as the signatures are not the same across all chains.
