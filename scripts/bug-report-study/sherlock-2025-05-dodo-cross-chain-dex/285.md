# ETH Transfer Failure in Cross-Chain Swaps Due to Gas Limit Restriction

### Summary

Using `.transfer()` instead of `.call()` will cause a denial of service for users performing cross-chain swaps to ETH as recipients with contracts requiring >2300 gas will cause transaction failures and fund loss.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L373

### Root Cause

In `GatewaySend.sol:onCall()` the ETH transfer uses `.transfer()` which limits gas to 2300, causing failures for smart contract recipients like multisig wallets, smart contract wallets etc

You can find a similar report here on [solodit](https://solodit.cyfrin.io/issues/use-call-instead-of-transfer-cyfrin-none-woosh-deposit-vault-markdown)


### Internal Pre-conditions

1. User needs to initiate a cross-chain swap with ETH as the destination token
2. Recipient address needs to be a smart contract that requires >2300 gas for ETH reception (multisig, smart wallet, etc.)

### External Pre-conditions

None

### Attack Path

1. User calls `depositAndCall()` to initiate cross-chain swap to ETH
2. Cross-chain execution triggers `onCall()` function
3. `onCall()` attempts ETH transfer using `payable(evmWalletAddress).transfer(outputAmount)`
4. Transfer fails due to 2300 gas limitation for smart contract recipients
5. Entire transaction reverts

### Impact

Users cannot receive ETH from cross-chain swaps when using smart contract wallets causing a denial of service

_No response_

### Mitigation

```diff
if(toIsETH) {
-    payable(evmWalletAddress).transfer(outputAmount);
+    (bool success, ) = payable(evmWalletAddress).call{value: outputAmount}("");
+    require(success, "ETH transfer failed");
} else {
    IERC20(toToken).transfer(evmWalletAddress, outputAmount);
}
```
