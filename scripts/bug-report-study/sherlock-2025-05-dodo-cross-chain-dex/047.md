# Approve Without Reset Causes Transaction Failure on Certain Tokens

## Description
The `GatewayCrossChain` contract makes multiple `approve()` calls on ERC20 tokens without first resetting the allowance to 0. This issue can cause transaction failures when interacting with tokens that implement approve protection such as USDT, which rejects approve transactions if the current allowance is not equal to 0.

The issue was found in several critical functions that handle cross-chain swaps and withdrawals, which are core functions of the protocol.

Note: this issue also occurs in the `_doMixSwap()` function and the `_swapAndSendERC20Tokens()` function in the `GatewayTransferNative` contract.

## Root Cause
The root of the problem lies in the direct use of `approve()` without reset at several locations in the contract:
```solidity
// In _swapAndSendERC20Tokens function
// Approve router to use target token
IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

// In _doMixSwap function
// Approve DODO Approve contract to use input token
IZRC20(params.fromToken).approve(DODOApprove, amount);

// In _handleBitcoinWithdraw function
// Approve gateway to use total amount (output + gas fee)
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

// In _handleEvmOrSolanaWithdraw function
// Approve gateway to use total amount (output + gas fee)
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

// And also in other parts:
IZRC20(gasZRC20).approve(address(gateway), gasFee);
IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);
```
The problem is that tokens like USDT have an implementation of `approve()` that rejects a transaction if `allowance[owner][spender] != 0`. The contract does not reset the allowance to 0 before doing a new approve. If the previous transaction failed or there is remaining allowance, the next approve will fail.

## Impact
Swap and withdraw functions become unusable for certain tokens.

## Scenario Step by Step
USDT Swap Failure
1. Initial Setup:
- User performs cross-chain swap with USDT as input token
- Contract receives USDT and processes swap
2. First Transaction:
- `_doMixSwap()` function is called
- `IZRC20(USDT).approve(DODOApprove, 1000)` succeeds (allowance = 0 → 1000)
- DODO swap succeeds, but only uses 800 USDT
- Remaining allowance = 200 USDT
3. Second Transaction (Same or different user):
- `_doMixSwap()` function is called again with USDT
- `IZRC20(USDT).approve(DODOApprove, 1500)` FAILED
- Reason: USDT rejected because current allowance = 200 (not 0)
- All cross-chain transactions failed

Withdraw Failure
1. Setup:
- User performs swap from ETH to USDT to withdraw to Bitcoin
- Swap successful, resulting in 2000 USDT
2. Withdraw process:
- `_handleBitcoinWithdraw()` is called
- Gas fee = 50 USDT, output = 1950 USDT
- `IZRC20(USDT).approve(gateway, 2000)` is called
3. If There is Remaining Allowance:
- If there was previously an unused USDT allowance to the gateway
- Approve will fail and the user will not be able to withdraw their USDT

## Recommendation (Code Fix)
Need to replace all `approve()` calls with reset pattern.
```solidity
// ❌ BEFORE (Problematic)
IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

// ✅ AFTER (Safe)
if (IZRC20(targetZRC20).allowance(address(this), UniswapRouter) > 0) {
    IZRC20(targetZRC20).approve(UniswapRouter, 0);
}
IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);
```
