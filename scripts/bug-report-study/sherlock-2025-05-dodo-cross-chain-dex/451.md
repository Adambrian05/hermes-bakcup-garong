# Missing native token handling will break swaps in `GatewayCrossChain.sol`

### Summary

The lack of a native token check in `_doMixSwap()` will cause swap failures in `GatewayCrossChain.sol`, as native tokens are incorrectly treated like ERC-20s — triggering invalid approvals and breaking execution.

### Root Cause

In `GatewayCrossChain.sol` https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L346, `.approve()` is called on `params.fromToken` without checking whether the token is native.

### Internal Pre-conditions

1. User provides a native token (`address(0)` or `ZETA`) as `fromToken`

2. Swap path proceeds through `_doMixSwap()` with valid `swapData`

### External Pre-conditions

1. The router does not expect `.approve()` for native tokens

2. The contract receives native tokens via `msg.value`



### Attack Path

1. User tries to swap native tokens using `GatewayCrossChain.sol`

2. `_doMixSwap()` attempts `approve()` on native token

3. The approval fails or has no effect, and the swap breaks



### Impact

Swaps using native tokens in `GatewayCrossChain.sol` will consistently fail, preventing users from executing legitimate cross-chain transactions.
