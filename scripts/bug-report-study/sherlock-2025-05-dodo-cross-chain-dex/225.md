Medium

# onAbort() will always revert because abortAddress is set to address(0).

### Summary

`onAbort()` is triggered when a cross-chain transaction reverts and there are insufficient tokens to cover the gas cost for calling `onRevert()`. The issue arises because the `abortAddress` in the `RevertOptions` struct is set to `address(0)`.

Since the Gateway attempts to call this address, the transaction inevitably reverts, breaking core protocol functionality and preventing proper fallback execution.


### Root Cause

The issue exists in both `GatewayCrossChain.sol` and `GatewayTransferNative.sol`, but for simplicity, this explanation will focus on the latter.

When [withdraw()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304) is called, it constructs a `RevertOptions` struct to handle potential transaction reverts and facilitate refunding the user.
```solidity
function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
@>              abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
As shown, `abortAddress` is set to `address(0)`, which poses a problem because this is the address the Gateway will call via `onAbort()`. More information [here](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions).

This results in the transaction consistently reverting, as the Gateway's [executeAbort()](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/zevm/GatewayZEVM.sol#L502-L513) checks whether the target address is `address(0)`, and if so, reverts with the custom error `EmptyAddress()`.
```solidity
function executeAbort(
        address target,
        AbortContext calldata abortContext
    )
        external
        nonReentrant
        onlyProtocol
        whenNotPaused
    {
@>      GatewayZEVMValidations.validateNonZeroAddress(target);
        Abortable(target).onAbort(abortContext);
    }
```
This causes any transaction that requires `onAbort()` to always revert, breaking the core functionality of the protocol.


### Internal Pre-conditions

Cross-chain transaction reverts and `onAbort()` is triggered.


### External Pre-conditions

None.

### Attack Path

None.

### Impact

If the cross-chain transaction fails and `onAbort()` is called, it will always revert, breaking the core functionality of the protocol.


### PoC

The previous sections demonstrated the issue clearly.


### Mitigation

To resolve the problem, set `abortAddress` to `address(this)` in both `GatewayCrossChain.sol` and `GatewayTransferNative.sol`.
```diff
function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
-               abortAddress: address(0),
+               abortAddress: address(this),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
