# GatewaySend IERC20 function calls will always revert when dealing with USDT

### Summary

`GatewaySend.sol` utilizes the openzeppelin IERC20 interface to make calls such as `approve`, `transfer`, and `transferFrom`. These calls expect `bool` return values. Some tokens, specifically USDT on ETH Mainnet which is listed as supported token of the protcol, do not comply with the standard. These calls will always revert when using these tokens, rendering the contract unusable for them.

The `TransferHelper` library that is included with the project should be used in place of this direct use of `IERC20`.

### Root Cause

There are multiple lines of code in `GatewaySend.sol` that use `IERC20` directly. In particular, lines 184, 199, 239, 317, 359, and 372.

### Internal Pre-conditions

N/A

### External Pre-conditions

Interacting on any EVM chain where USDT or other supported token does not follow ERC20 standard

This will happen on ETH mainnet for USDT which is a listed supported asset of the protocol

### Attack Path

Any call to an entry point in `GatewaySend.sol` such as `onCall` or `depositAndCall` where the `fromToken` is USDT on ETH mainnet (or any other token that does not follow the ERC20 interface used) will always revert.

### Impact

The protocol is not usable for USDT on ETH Mainnet (a listed supported asset). Any other token that does not follow the IERC20 standard used in `GatewaySend.sol` will also be unusable. 

### PoC

Should not be necessary. The below snippet shows the behavior in solidity when an interface specifies a return boolean but the calling contract does not. You can run this in remix and see the call to `checkFalse` always reverts. 

```solidity
pragma solidity 0.8.26;

interface IReturnVal {
    function returnsBool(uint256 num) external returns (bool);
}

contract ReturnVal {
    function returnsBool(uint256 num) external {
        uint256 a = num+1;
    }
 
}

contract CheckBoolRevert {
    ReturnVal r = new ReturnVal();
    address returnAdd = address(r);
    function checkFalse() external {
         IReturnVal(returnAdd).returnsBool(5);
    }
}
```

### Mitigation

Use the `TransferHelper` library included in the project to interact with the tokens anywhere that a direct use of `IERC20` is used.
