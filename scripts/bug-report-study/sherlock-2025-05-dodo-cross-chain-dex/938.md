# GatewayTransferNative's public withdraw() will allow users to drain contract's token balance due to accumulated excess approvals

### Summary

The public access to GatewayTransferNative.withdraw() combined with accumulated excess approvals will allow users to drain the contract's token balance when withdrawing to chains like Bitcoin, as the contract's excess token approvals can be used to cover both the gas fee and the withdrawal amount.

### Root Cause

In GatewayTransferNative.sol, the [withdraw()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286) function is incorrectly made public, and the contract accumulates excess approvals of 1 * gasFee per transaction due to approving outputAmount + gasFee but only transferring outputAmount - gasFee.

### Internal Pre-conditions

1. GatewayTransferNative must have accumulated excess approvals for GatewayZEVM
2. The excess approvals must be sufficient to cover both the gas fee and withdrawal amount
3. The withdraw() function must be accessible to users

### External Pre-conditions

None 

### Attack Path

1. User calls GatewayTransferNative.withdraw() directly:

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {  // <-- Should be internal
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}

```

1. This calls GatewayZEVM.withdraw() where:
    - msg.sender is GatewayTransferNative
    - _withdrawZRC20() tries to transfer:
        - gasFee for the gas fee
        - amount for the actual withdrawal
    - Both transfers come from GatewayTransferNative (msg.sender)
    - GatewayTransferNative has approved outputAmount + gasFee
    - The excess approval of 1 * gasFee can be used to cover both the gas fee AND the amount
2. The user receives the full amount on the target chain without paying anything

### Impact

Users can drain GatewayTransferNative's token balance by:

1. Calling withdraw() directly
2. Having both their gas fee AND amount covered by GatewayTransferNative's excess approvals
3. Getting the full amount on the target chain without paying anything
4. Repeating this process until all excess approvals are used up

_No response_

### Mitigation

1. Make withdraw() internal:

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) internal {  // <-- Change to internal
    // ... rest of the function
}

```

1. Fix the approval amount to match the actual transfer amount:

```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    // Approve only what will be transferred
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
    withdraw(
        externalId,
        decoded.receiver,
        decoded.targetZRC20,
        outputAmount - gasFee
    );
}

```
