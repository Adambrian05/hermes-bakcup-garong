# Malicious user can claim refund for aborts/reverts that has walletAddress as solAddress or btcAddress

### Summary

The missing check for receiver in `GatewayCrossChain.sol:578` will allow malicious users to claim refund when the wallet address is sol address or btc address.


### Root Cause

When `_handleEvmOrSolanaWithdraw()` is called for solana, the receiver will be sol address.
It calls `withdrawAndCall()` where it makes the revert message with byte concat on externalId and receiver.
```solidity
RevertOptions({
    revertAddress: address(this),
    callOnRevert: true,
    abortAddress: address(0),
    revertMessage: bytes.concat(externalId, receiver), // @audit; revert message is longer than 52 bytes because the receiver is sol address
    onRevertGasLimit: gasLimit
})
```

If it aborts or reverts, at `onAbort()` and `onRevert()`, it gets the wallet address from the revert message.
So the wallet address will be sol address.
```solidity
// 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
bytes32 externalId = bytes32(abortContext.revertMessage[0:32]);
bytes memory walletAddress = abortContext.revertMessage[32:]; 
// @audit; the above comment says the walletAddress should be 20 bytes but it's not. The walletAddress is sol address
```

Later, in `GatewayCrossChain.sol:578`, the check for `receiver` is not enough.
When the `walletAddress` is sol address or btc address, receiver remains as `msg.sender`.
And as `receiver` is `msg.sender` it passes other constraints.

```solidity
    address receiver = msg.sender;
    if(refundInfo.walletAddress.length == 20) { // @audit; when the walletAddress is solAddress/btcAddress, receiver remains as msg.sender
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER"); // @audit; this is passed because receiver is msg.sender
    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
```

### Attack Path

1. `GatewayCrossChain.onCall()` is called for solana and it aborts or reverts.
2. The attacker claim refund for the aborted/reverted operation.

### Impact

The attacker can claim refund for the aborts/reverts on solana and btc.
The actual user will lose the fund.

        vm.startPrank(address(gatewayZEVM));

        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp + 600));

    }
}
