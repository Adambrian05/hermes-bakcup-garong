# Unchecked ERC20 Transfer Returns Can Lead to Silent Fund Loss

## Root Cause:
The `onCall` function in the cross-chain bridge contract doesn't check the return value of ERC20 `transfer()` calls. While some ERC20 tokens revert on transfer failure, others (like USDT) simply return `false` without reverting. The current implementation would interpret these silent failures as successful transfers, leading to a mismatch between actual token movements and contract state/events.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L372


### Attack Path:
1. A cross-chain transfer is initiated from chain A to chain B involving a non-standard ERC20 token.
2. The token is one that returns `false` on transfer failure instead of reverting (e.g., USDT).
3. The `onCall` function on the destination chain executes the transfer.
4. The transfer silently fails (returns `false`) due to some condition (e.g., insufficient balance).
5. No revert occurs, so the function continues execution.
6. An event is emitted indicating a successful transfer even though the tokens weren't transferred.
7. The user has no tokens, but the contract accounting indicates a successful transfer.
8. The user has no way to recover their funds as the cross-chain transaction is considered "complete".

### Impact:
1. **Direct Fund Loss:** Users fail to receive tokens from cross-chain transfers with no recovery mechanism.
2. **Accounting Inconsistencies:** Events indicate successful transfers while actual token movements fail.
3. **Decreased Protocol Trust:** Users experiencing silent failures may lose confidence in the protocol.
4. **Difficult Debugging:** Silent failures are hard to diagnose and may lead to extended periods of undetected issues.
5. **Customer Support Overhead:** Support teams have no on-chain evidence to identify why users haven't received funds.


### Mitigation:
Choose one of these approaches to fix the issue:

#### Option 1: Use OpenZeppelin's SafeERC20 (Recommended)
```solidity
import "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";
using SafeERC20 for IERC20;

// In the onCall function:
if(toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
} else {
    IERC20(toToken).safeTransfer(evmWalletAddress, outputAmount);
}
```

#### Option 2: Check Transfer Return Value
```solidity
if(toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
} else {
    require(IERC20(toToken).transfer(evmWalletAddress, outputAmount), "Token transfer failed");
}
```

#### Option 3: Use TransferHelper Library
```solidity
if(toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
} else {
    TransferHelper.safeTransfer(toToken, evmWalletAddress, outputAmount);
}
```
