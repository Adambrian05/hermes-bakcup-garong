# ETH Lock-up in `withdrawToNativeChain` Due to Missing ETH Handling for ZRC20 Transactions

### Summary

The `withdrawToNativeChain` function in `GatewayTransferNative.sol` is correctly marked as `payable` to support ETH transactions, but fails to handle or reject ETH sent during ZRC20 token operations. This design flaw causes any ETH accidentally sent during non-ETH token transactions to be permanently locked in the contract, leading to unintended fund loss for users.

### Root Cause

The vulnerability stems from incomplete ETH handling logic:

```solidity
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {  
    if(zrc20 != _ETH_ADDRESS_) {
        require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
    } 
    // ... rest of function never uses or refunds msg.value for ZRC20 operations
}
```

The [`withdrawToNativeChainneeds`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530) to be `payable` to support ETH withdrawals (`zrc20 == _ETH_ADDRESS_`), but when processing ZRC20 tokens (`zrc20 != _ETH_ADDRESS_`), any ETH sent with the transaction (`msg.value > 0`) is ignored and becomes trapped in the contract.

### Attack Path

This is a user error scenario that leads to fund loss:

1. **User Intent**: User wants to bridge USDC from ZetaChain to another chain
2. **User Error**: User accidentally includes ETH value in the transaction (common wallet UX mistake)
3. **Function Execution**: `withdrawToNativeChain` processes the USDC transfer successfully
4. **ETH Handling**: The sent ETH (`msg.value`) is completely ignored - not used, not refunded
5. **Result**: USDC transfer completes but ETH is permanently locked in the contract


### Impact

 Accidental ETH sent by users is permanently locked.

### PoC

```solidity
function test_PoC_ETHLockupInWithdrawToNativeChain() public {
    // Setup
    address user = address(0x123);
    uint256 usdcAmount = 1000e6; // 1000 USDC
    uint256 accidentalETH = 1 ether; // User accidentally sends 1 ETH
    
    // Give user USDC and ETH
    token1Z.mint(user, usdcAmount);
    vm.deal(user, accidentalETH + 1 ether); // Extra for gas
    
    // Prepare withdraw message for USDC
    bytes memory message = encodeMessage(
        1, // Ethereum
        address(token1Z), // USDC token
        abi.encodePacked(user),
        abi.encodePacked(user),
        "", // No swap
        "",
        "",
        ""
    );
    
    // Record initial balances
    uint256 contractETHBefore = address(gatewayTransferNative).balance;
    uint256 userETHBefore = user.balance;
    
    // User performs USDC withdrawal but accidentally sends ETH
    vm.startPrank(user);
    token1Z.approve(address(gatewayTransferNative), usdcAmount);
    
    // This call processes USDC correctly but locks the ETH
    gatewayTransferNative.withdrawToNativeChain{value: accidentalETH}(
        address(token1Z), // ZRC20 token, not ETH
        usdcAmount,
        message
    );
    vm.stopPrank();
    
    // Verify ETH is locked
    uint256 contractETHAfter = address(gatewayTransferNative).balance;
    uint256 userETHAfter = user.balance;
    
    assertEq(contractETHAfter, contractETHBefore + accidentalETH, "ETH should be locked in contract");
    assertEq(userETHAfter, userETHBefore - accidentalETH, "User should have lost the ETH");
    
    console.log("USDC withdrawal successful, but ETH is lost:");
    console.log("User lost ETH:", accidentalETH);
    console.log("ETH locked in contract:", contractETHAfter);
    console.log("No mechanism to recover the locked ETH");
}
```

### Mitigation

Add ETH validation for ZRC20 operations:

```solidity
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    if(zrc20 != _ETH_ADDRESS_) {
        require(msg.value == 0, "ETH_NOT_ACCEPTED_FOR_ZRC20_WITHDRAWALS");
        require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
    } else {
        require(msg.value > 0, "ETH_AMOUNT_REQUIRED");
        // Handle ETH withdrawal logic
    }
    // ... rest of function
}
```
