# Incorrect Approval Logic Prevents Native ZETA from Being Swapped and Withdrawn

### Summary

The withdrawToNativeChain() function in the GatewayTransferNative contract allows users to:

Deposit native ZETA
Swap it to another ZRC20 token using _doMixSwap()
Withdraw the resulting token to an EVM chain as an ERC20
However, within _doMixSwap(), the following line causes the transaction to revert :

```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount);
When params.fromToken == _ETH_ADDRESS_ (i.e., native ZETA), this call reverts because _ETH_ADDRESS_ is a placeholder and not a real token contract.
```

As a result: Users cannot perform cross-chain withdrawals of native ZETA that involve a swap — a core expected functionality becomes unusable. 


### Root Cause

In _doMixSwap():

```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount);
```
This assumes all input tokens are standard ZRC20 contracts. However, when the input is native ZETA, params.fromToken is set to:

```solidity
address constant _ETH_ADDRESS_ = 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE;
```
Which is not a real token contract .

Calling .approve() on this address always reverts , breaking any flow that involves:

Native ZETA → Swap → Cross-chain withdrawal
