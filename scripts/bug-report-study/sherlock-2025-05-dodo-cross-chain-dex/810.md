# GatewaySend's non-payable onRevert will cause permanent loss of funds for users as native ETH refunds cannot be processed

### Summary

The non-payable onRevert function in GatewaySend.sol will cause a complete loss of funds for users as the contract cannot receive and process native ETH refunds when cross-chain operations fail.

### Root Cause

In GatewaySend, the [onRevert](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393) function is not payable and uses TransferHelper.safeTransfer() for all assets, which cannot handle native ETH transfers. The function needs to be payable and use TransferHelper.safeTransferETH() for native ETH refunds.

```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
        
        TransferHelper.safeTransfer(context.asset, sender, context.amount); // <-- vulnerable part
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```

### Internal Pre-conditions

1. User needs to call depositAndCall() with native ETH (asset = _*ETH_ADDRESS_*)

### External Pre-conditions

1. Cross-chain operation must fail on the destination chain
2. GatewayEVM needs to call executeRevert() to return the funds

### Attack Path

1. User calls depositAndCall() with native ETH for a cross-chain operation
2. Cross-chain operation fails on destination chain
3. GatewayEVM's executeRevert() is called with msg.value containing the ETH to return
4. executeRevert() sends ETH to GatewaySend and calls onRevert()
5. GatewaySend's onRevert() cannot receive the ETH (not payable) and fails to process the refund
6. ETH remains permanently locked in GatewaySend contract

### Impact

Users suffer a complete loss of their native ETH when cross-chain operations fail. The funds become permanently locked in the GatewaySend contract as the refund mechanism is broken for native ETH.

_No response_

### Mitigation

Modify GatewaySend's onRevert function to be payable and handle native ETH differently:

```solidity
function onRevert(RevertContext calldata context) external payable onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));

    if (context.asset == _ETH_ADDRESS_) {
        TransferHelper.safeTransferETH(sender, context.amount);
    } else {
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
    }

    emit EddyCrossChainRevert(
        externalId,
        context.asset,
        context.amount,
        sender
    );
}

```
