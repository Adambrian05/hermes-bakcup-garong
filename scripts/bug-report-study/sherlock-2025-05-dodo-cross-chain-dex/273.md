# When `zrc20 == _ETH_ADDRESS_`, `GatewayTransferNative`.`withdrawToNativeChain` fails when `_handleFeeTransfer`

### Summary

When `zrc20 == _ETH_ADDRESS_`, `_handleFeeTransfer` processes  fee transfer but `zrc20` is not token.
`_handleFeeTransfer` fails when `zrc20 == _ETH_ADDRESS_`, `TransferHelper` can't transfer `_ETH_ADDRESS_`.

### Root Cause

`GatewayTransferNative`.`withdrawToNativeChain` uses  `_handleFeeTransfer` for transferring fee.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L551
But `zrc20` is not token, it is native asset.
```solidity
    function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
```
