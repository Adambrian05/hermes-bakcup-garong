# No validation of msg.value in withdrawToNativeChain function

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530


The withdrawToNativeChain() function is used to withdraw assets, either ERC-20 tokens or ETH, back to a native chain. It checks if the asset being transferred is ETH by comparing the zrc20 address to _ETH_ADDRESS_. If it's a token, it correctly uses transferFrom() to move the tokens. However, when the transfer is ETH, it does not validate that the amount of ETH sent (msg.value) matches the expected amount

### Root Cause

the value of msg.value isnt verified against the request amount 

```javascript

if (zrc20 == _ETH_ADDRESS_) {
    // Missing: require(msg.value == amount, "ETH_AMOUNT_MISMATCH");
    // ETH is received, but amount is not validated
} else {
    require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "TRANSFER_FAILED");
}

```

### Attack Path

The user  calls withdrawToNativeChain() with a specified amount, but intentionally(or by mistake) sends a different msg.value.

### Impact

A user could accidentally send more ETH than intended. The excess ETH would be stuck in the contract or misrouted
A user could send less ETH than declared, but still proceed with the withdrawal, potentially causing accounting mismatches
