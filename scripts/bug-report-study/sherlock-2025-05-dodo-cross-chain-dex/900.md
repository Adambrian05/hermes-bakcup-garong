# Loss of native tokens in connected chains due to incorrect revert handling

### Summary

Loss of native tokens in connected chains due to incorrect revert handling

### Root Cause

The function [`GatewaySend::onRevert()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393) is executed if the function `onCall()` in universal contract fails, i.e `GatewayCrossChain::onCall()` and `GatewayNativeTransfer::onCall()` fail. 

In case native token (gas token) is deposited to Zetachain and `onCall()` fails on Zetachain, then the function `GatewaySend::onRevert()` is executed on connected chains with `RevertContext.asset` set to empty.

Here is the code comment from Zetachain's protocol contracts
```solidity
/// @notice Struct containing revert context passed to onRevert.
/// @param sender Address of account that initiated smart contract call.
/// @param asset Address of asset. On a connected chain, it contains the fungible
/// token address or is empty if it's a gas token. On ZetaChain, it contains the
/// address of the ZRC20.
/// @param amount Amount specified with the transaction.
/// @param revertMessage Arbitrary data sent back in onRevert.
struct RevertContext {
    address sender;
    address asset;
    uint256 amount;
    bytes revertMessage;
}
```
And here is the function which is called by Zetachain TSS to execute the `onRevert()` function (ref: [`GatewayEVM` contract](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/evm/GatewayEVM.sol#L111-L128))
```solidity
    /// @notice Transfers msg.value to destination contract and executes it's onRevert function.
    /// @dev This function can only be called by the TSS address and it is payable.
    /// @param destination Address to call.
    /// @param data Calldata to pass to the call.
    function executeRevert(
        address destination,
        bytes calldata data,
        RevertContext calldata revertContext
    )
        public
        payable
        nonReentrant
        onlyRole(TSS_ROLE)
        whenNotPaused
    {
        if (destination == address(0)) revert ZeroAddress();
        (bool success,) = destination.call{ value: msg.value }("");
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext);

        emit Reverted(destination, address(0), msg.value, data, revertContext);
    }
```

Hence, the logic inside `GatewaySend::onRevert()` will be incorrect. The `TransferHelper.safeTransfer()` wont revert because it uses low-level call to `context.asset`, a non-contract address. As a result, the function `onRevert()` will still be executed successfully, but actually funds are not settled.

### Attack Path

1. An trader calls `GatewaySend::depositAndCall()` on connected chain, with `asset = _ETH_ADDRESS_` and `amount` is small, specifying that it will swap with DODO on Zetachain
2. After swap with DODO on Zetachain, the output token amount is not enough for gas fee => the function revert 
3. `GatewaySend::onRevert()` is executed, but the trader does not receive native token on connected chain.

### Impact

- Loss of funds, i.e the native tokens on connected chains
