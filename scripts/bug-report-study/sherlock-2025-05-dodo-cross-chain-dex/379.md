# Public Access to `withdraw()` Enables Unauthorized ZRC20 Withdrawals from Gateway

### Summary

The [`GatewayTransferNative.withdraw(...)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304) function is intended to interact with the gateway to withdraw funds on behalf of a user. However, it is mistakenly marked public, allowing any external caller to invoke it with arbitrary parameters.

An attacker can exploit this to withdraw ZRC20 tokens approved to the gateway. This leads to direct theft of funds and breaks the trust model of the withdrawal flow.

### Root Cause

- The withdraw() function is marked public instead of internal, exposing it to arbitrary external calls.

### Internal Pre-conditions

1. Any excess approvals of ZRC20 to ZetaChain Gateway.

An example of excess approvals at [line](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L458-L464):
```solidity
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
withdraw(
     externalId, 
     decoded.receiver, 
     decoded.targetZRC20, 
     outputAmount - gasFee
);
```

We can see an approval of `outputAmount + gasFee` but the withdraw call tries to bridge `outputAmount - gasFee`. So `outputAmount` already includes `gasFee`. There is an extra approval of `gasFee`.

### External Pre-conditions

1. Attacker calls the `GatewayTransferNative.withdraw(...)` with arbitrary parameters.

### Attack Path

1. Attacker calls the `GatewayTransferNative.withdraw(...)` with arbitrary data. 

### Impact

The protocol suffers loss of funds sitting idle on the contract with approvals to Gateway.
