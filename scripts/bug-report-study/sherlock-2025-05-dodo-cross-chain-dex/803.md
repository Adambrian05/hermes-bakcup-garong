# Theft of funds due to using mismatched token amount for token transfers

### Summary

Implementation mistake in the function `GatewayTransferNative::onCall()` can cause the funds flow incorrectly handled

### Root Cause

The function [`GatewayTransferNative::onCall()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357) is expected to be called by Zetachain gateway to execute the cross chain swap from connected chain -> zetachain. 

However, in case the trader's `targetZRC20` is not the deposited `zrc20`, i.e `decoded.TargetZRC20 != zrc20`, transfer token amount is incorrectly handled. It is because `amount` is used for the function call `_doMixSwap(decoded.swapData, amount, params)`, which is in term of `zrc20`. When not swapping with DODO (`swapData.length == 0`), then `outputAmount` is set to `amount`. As a result, the later logics will transfer `targetZRC20` token with the `outputAmount` in term of `zrc20` token. The overhead token amount is from the pending claim funds, which is basically from other traders. In other words, traders' pending claim is stolen

Note that the same pattern also happens with other functions/flows that swaps with DODO on Zetachain

### Attack Path

1. An attacker initiated a swap from connected chain -> zetachain, i.e swapping from `SHIB` on Ethereum to `USDT.ETH` on Zetachain
2. The attacker calls `GatewaySend::depositAndCall()`on Ethereum with `asset = SHIB` and `payload` having:
- `targetZRC20 = USDT.ETH`, which will differ from `zrc20 = SHIB.ETH`
- `swapData` (on Zetachain) is empty
- `sender` is his controller address
Assume the `amount` is 100 `SHIB` (= 100e18)
3. When the cross chain swap is executed at the function `GatewayTransferNative::onCall()`,
let's assume fee platform fee is 1% => 100 `SHIB.ETH` (1e18) is taken as platform fee
The function `_doMixSwap()` returns `amount = 100e18` ==> `outputAmount = 100e18`
The function then calls `TransferHelper.safeTransfer(USDT.ETH, <attacker address>, 100e18)` ==> stealing `USDT.ETH` holding by the contract



### Impact

- Theft of funds holding by the contract
- Stealing funds from pending claim
