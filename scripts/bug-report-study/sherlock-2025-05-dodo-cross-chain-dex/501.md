# A malicious user can fully grief the refund mapping of a innocent user causing loss of funds to the users in the contract GatewayTransferNative.sol

### Summary

a malicious user can overwrite the mapping refundInfos in the function onRevert, this is possible when a user transaction failed cross chain and the context.revertMessage.length is not equal to 52,(this will happen when transactions are failed from the solana address as solana address are 32 bytes so when concat is used in the function withdrawAndCall its 64 bytes(32 external + 32 receiver {sol address}) so when these transactions come a malicious user can observe the mempool see there external id put arbitary values in the function withdraw(passing the checks) set a refund amount as low as possible and overwrite the users info

### Root Cause

root cause in this is the function onRevert in which there isnt a check to stop overwriting 
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L607


### Internal Pre-conditions

none

### External Pre-conditions

a transaction fails as explained in the summary

### Attack Path

for this attack path assume a malicious user named alice and a innocent user named bob
1) Bob transaction fails on cross chain ( his value of lets say supported asset of solana sol token failed and its was 500 wrapped sol)
2) alice sees this waits for bob revert to hit the function onRevert 
3) alice calls the function withdraw put the values that only pass all check as
