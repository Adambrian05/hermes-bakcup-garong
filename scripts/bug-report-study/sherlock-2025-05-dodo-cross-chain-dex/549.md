# GatewaySend::onRevert doesn't handle native refunds

### Summary

When `onRevert` is triggered either `GatewayEVM.executeRevert()` or `GatewayEVM.revertWithERC20()` will be called by the ZetaChain system when EVM → ZetaChain cross-chain call failed on ZetaChain. The two function differentiate based on the token (`executeRevert()` for native and `revertWithERC20()` for tokens).

```solidity
function executeRevert(
    address destination,
    bytes calldata data,
    RevertContext calldata revertContext
)
    public
    payable
    nonReentrant
    onlyRole(TSS_ROLE)
    whenNotPaused
{
    if (destination == address(0)) revert ZeroAddress();
    (bool success,) = destination.call{ value: msg.value }("");
    if (!success) revert ExecutionFailed();
    Revertable(destination).onRevert(revertContext);

    emit Reverted(destination, address(0), msg.value, data, revertContext);
}
```

```solidity
function revertWithERC20(
    address token,
    address to,
    uint256 amount,
    bytes calldata data,
    RevertContext calldata revertContext
)
    external
    nonReentrant
    onlyRole(ASSET_HANDLER_ROLE)
    whenNotPaused
{
    if (amount == 0) revert InsufficientERC20Amount();
    if (to == address(0)) revert ZeroAddress();

    IERC20(token).safeTransfer(address(to), amount);
    Revertable(to).onRevert(revertContext);

    emit Reverted(to, token, amount, data, revertContext);
}
```

As you see both will return the tokens or the native to the contract where `onRevert` will be executed (`GatewaySend.sol`), but the issue is that DoDo’s `GatewaySend.onRevert` logic is not working with native tokens and the Native will be locked in the `GatewaySend.sol`.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L396

```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));
    TransferHelper.safeTransfer(context.asset, sender, context.amount); <------------
    
    emit EddyCrossChainRevert(
        externalId,
        context.asset,
        context.amount,
        sender
    );
}
```

### Root Cause

`GatewaySend.onRevert` is always working with tokens, instead to check the `context.asset` and work with Native also.

### Internal Pre-conditions

The `depositAndCall` to be used with chain the chain NATIVE token.

### External Pre-conditions

None

### Attack Path

All operations with Native.

### Impact

Native tokens will be locked in the `GatewaySend` contract.

### PoC

N/A

### Mitigation

Add a check in the `GatewaySend.onRevert` to check and transfer the funds to the sender based on the `context.asset`, making it working with Native as well.
