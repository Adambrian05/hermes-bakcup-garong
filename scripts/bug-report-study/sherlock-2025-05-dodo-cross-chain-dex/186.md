# Incorrect amount check in `GatewaySend::depositAndCall` function

### Summary

`GatewaySend::depositAndCall` has an incorrect amount check, which may cause users to transfer too much and waste unnecessary money

### Root Cause

In `GatewaySend::depositAndCall` function:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L234
```solidity
function depositAndCall(
        address fromToken,
        uint256 amount,
        bytes calldata swapData,
        address targetContract,
        address asset,
        uint32 dstChainId,
        bytes calldata payload
    ) public payable {
        globalNonce++;
        bytes32 externalId = _calcExternalId(msg.sender);
        bool fromIsETH = (fromToken == _ETH_ADDRESS_);

        // Handle input token
        if(fromIsETH) {
            require(
                msg.value >= amount, 
                "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
            );
        } else {
            require(
                IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
                "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
            );
        }
```
When the input token is eth, the code requires `msg.value >= amount` , which may cause users to pay more than `amount` , resulting in unnecessary waste.

### Internal Pre-conditions

The user calls the `GatewaySend::depositAndCall` function, but the eth paid exceeds the `amount` in the function parameter.
