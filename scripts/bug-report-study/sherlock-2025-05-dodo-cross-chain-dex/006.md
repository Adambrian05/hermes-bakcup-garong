# GatewaySend::onRevert() cannot refund native tokens such as ETH or BNB to users.


## Summary

The onRevert() function only handles the logic for refunding ERC20 tokens, causing native tokens like ETH and BNB to fail to be refunded to users.

## Root Cause

It can be observed that onRevert() only calls TransferHelper.safeTransfer() to handle ERC20 token refunds.  
When users cross-chain transfer native tokens like ETH via depositAndCall() and the transaction fails, the Gateway's call to onRevert() will result in an error.

## Impact
Users suffer financial losses.

## PoC
1. Users cross-chain transfer native tokens like ETH via depositAndCall().  
2. The cross-chain call fails during tx execution on the zeta chain (e.g., mixswap trade cannot meet the minAmount condition).  
3. GatewayEVM calls GatewaySend's onRevert(), but the execution fails, unable to refund native tokens like ETH.  

This occurs because when the token is a native asset like ETH, revertContext.asset has an address of 0.

## Mitigation
Add logic in the onRevert() function to determine whether the token to be refunded to the user is an ERC20 or a native token.
