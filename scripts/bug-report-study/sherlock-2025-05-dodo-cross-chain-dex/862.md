# Memory Layout Misunderstanding in `BytesHelperLib` Leading to Incorrect Data Extraction.

## Summary
The `BytesHelperLib` library contains critical bugs in multiple functions (`bytesToAddress` and `bytesToUint32`) due to a fundamental misunderstanding of Solidity's memory layout. These functions incorrectly extract data from byte arrays, which can lead to returning wrong addresses and values when used in cross-chain operations, potentially causing funds to be sent to incorrect recipients.



## Root Cause
The root cause is a systematic misunderstanding of how Solidity stores `bytes` arrays in memory:

1. In Solidity, when a `bytes` array is in memory:
   - The first 32 bytes contain the length of the array
   - The actual data begins at offset 32

2. The incorrect assembly code in `bytesToAddress`:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/libraries/BytesHelperLib.sol#L6

```solidity
bytes memory b = data[offset:offset + 20];
assembly {
    output := mload(add(b, 20))
}
```

This code adds 20 to the memory pointer, which is still within the length word or at the very beginning of the data. The correct approach would be to add 32 (to skip the length prefix) and then handle the proper alignment of the data.

## Attack Path

1. A cross-chain transaction is initiated
2. During processing, the contract needs to extract the recipient's address using `bytesToAddress`
3. Due to the bug, an incorrect address is returned
4. Funds are sent to an unintended address
5. The legitimate recipient never receives their tokens

## Impact
- Tokens sent to incorrect addresses, resulting in permanent loss of funds
- Cross-chain messages may be incorrectly processed
- Chain IDs may be misread, causing transactions to be routed to wrong chains

## Mitigation
Replace the buggy implementations with corrected versions that properly handle Solidity's memory layout:

```solidity
function bytesToAddress(
    bytes calldata data,
    uint256 offset
) internal pure returns (address output) {
    // Add bounds check
    if (offset + 20 > data.length) {
        revert OffsetOutOfBounds();
    }
    
    bytes memory b = data[offset:offset + 20];
    assembly {
        // Correctly read from memory - skip length word (32 bytes) and mask to 20 bytes
        output := and(mload(add(b, 32)), 0xFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFFF)
    }
}

function bytesToUint32(
    bytes calldata data,
    uint256 offset
) internal pure returns (uint32 output) {
    // Add bounds check
    if (offset + 4 > data.length) {
        revert OffsetOutOfBounds();
    }
    
    bytes memory b = data[offset:offset + 4];
    assembly {
        output := and(mload(add(b, 32)), 0xFFFFFFFF)
    }
}
```
