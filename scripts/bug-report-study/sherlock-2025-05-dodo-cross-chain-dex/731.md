# ZRC20 Mismatch in withdrawToNativeChain Enables Arbitrary Token Theft via Crafted Swap Message

### Summary

The `withdrawToNativeChain` function assumes the `zrc20 `token passed as a parameter matches the `fromToken `within the `swapData` encoded in the `message `payload. This assumption is broken: a malicious user can supply a fake or low-value token as `zrc20`, while providing a valid, high-value token in `swapData.fromToken`. If the contract already holds a balance of `swapData.fromToken` (e.g., due to pending claims from `onAbort `or `onRevert`), the swap can proceed using those funds — effectively letting the user **withdraw unowned tokens**.

### Root Cause

The function does not validate that `zrc20 == swapData.fromToken`, allowing the swap to operate on tokens the caller did not supply. This creates an unintended link between externally supplied parameters and internal state-dependent behavior.

### Internal Pre-conditions

- Contract holds a non-zero balance of a token `T `(`swapData.fromToken`) due to past deposits or reserved funds (e.g., for `onAbort`, `onRevert`, etc.).
- `_doMixSwap()` performs the swap using `swapData.fromToken` without verifying it came from the user or matches `zrc20` taken from the user.

### External Pre-conditions

Attacker crafts a message such that `swapData.fromToken` = T (a token the contract already holds).
Attacker calls `withdrawToNativeChain`(zrc20, amount, message) with:
  - zrc20 being a fake or low-value token.
  - amount being less or equal to current  swapData.fromToken balance of `GatewayTransferNative`.
  
Attacker self-declares as the receiver of the output token (in `decoded.receiver`).



### Attack Path

Preparation: Attacker identifies that contract holds unclaimed balance of a valuable token `T`.

Message Crafting: Constructs `message `where:

  - `swapData.fromToken = T`
  - `decoded.receiver = attacker`
 
Call Execution: Calls `withdrawToNativeChain(fakeZRC, currentContractBalanceOfT, craftedMessage)`, passing any token as `zrc20`.

Swap Abuse: `_doMixSwap `uses token `T `(already in contract) for swap, thinking it came from the user.

Output Capture: Attacker receives the swapped token output on the target chain — effectively stealing funds without transferring them in.

### Impact

Unauthorized token withdrawal: Tokens that belong to other users or are reserved can be stolen.
Potential DoS vector: Legitimate users may find their claimable or reserved tokens missing.

### Mitigation

Token Match Validation:
Enforce `require(zrc20 == swapData.fromToken, "ZRC20 mismatch with swap input token")`; before `_doMixSwap`.
