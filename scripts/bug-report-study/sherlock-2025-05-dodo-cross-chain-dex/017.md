# `claimRefund` doesn't check `msg.sender` is `EOA`

### Summary

[`GatewayCrossChain`.`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590), [`GatewayTransferNative`.`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) doesn't check receiver isn't EOA.
### Root Cause 
```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
@>          receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
@>      TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```
This doesn't check `receiver` is not `EOA`.
Even though `receiver` is not `EOA` and it is contract address, this transfers tokens to `receiver`.

>If the receiver of refund info is not an EOA address, refund bots collect the tokens and process the refund manually.

This breaks core functionality.
