# GatewayCC::_doMixSwap doesn't forward msg.value

### Summary

The native token of Zetachain is ZETA and this token is also on Ethereum as ZETA token but in ERC20 representation. If you have it and want the native Zetachain ZETA token, you can use it and you will get the native Zetachain one. But there is a problem inside `GatewayCrossChain.onCall()`. If the user uses ZETA in `GatewaySend`, the native Zetachain Zeta will be transferred to `GatewayCrossChain` and `onCall()` will use it (This is done via `GatewayZEVM.depositAndCall()` for Native and `_transferZETA()`).

```solidity
/// @notice Deposit ZETA and call a user-specified contract on ZEVM.
/// @param context The context of the cross-chain call.
/// @param amount The amount of tokens to transfer.
/// @param target The target contract to call.
/// @param message The calldata to pass to the contract call.
function depositAndCall(
    MessageContext calldata context,
    uint256 amount,
    address target,
    bytes calldata message
)
    external
    nonReentrant
    onlyProtocol
    whenNotPaused
{
    if (target == address(0)) revert ZeroAddress();
    if (amount == 0) revert InsufficientZetaAmount();
    if (target == PROTOCOL_ADDRESS || target == address(this)) revert InvalidTarget();

    _transferZETA(amount, target);
    UniversalContract(target).onCall(context, zetaToken, amount, message);
}
```

```solidity
/// @dev Private function to transfer ZETA tokens.
/// @param amount The amount of tokens to transfer.
/// @param to The address to transfer the tokens to.
function _transferZETA(uint256 amount, address to) private {
    if (!IWETH9(zetaToken).transferFrom(msg.sender, address(this), amount)) revert FailedZetaSent();
    IWETH9(zetaToken).withdraw(amount);
    (bool sent,) = to.call{ value: amount }("");
    if (!sent) revert FailedZetaSent();
}
```

Then inside `onCall` there can have a swap if the user wants another token on chain B. And since `onCall` received Native Zeta as shown above, the swap should be from Native to X token (whatever was passed inside `swapDataZ`). But `_doMixSwap` does not pass `msg.value` to `DODORouteProxy.mixSwap`.

```solidity
function _deposit(
    address from,
    address to,
    address token,
    uint256 amount,
    bool isETH
) internal {
    if (isETH) {
        if (amount > 0) {
            require(msg.value == amount, "ETH_VALUE_WRONG");
            IWETH(_WETH_).deposit{value: amount}();
            if (to != address(this)) SafeERC20.safeTransfer(IERC20(_WETH_), to, amount);

    } else {
        IDODOApproveProxy(_DODO_APPROVE_PROXY_).claimTokens(token, from, to, amount);
    }
}
```

### Root Cause

`msg.value` not passed to `mixSwap`.

### Internal Pre-conditions

**The user should use NATIVE Zeta token as the fromToken.**

### External Pre-conditions

None

### Attack Path

None

### Impact

`OnCall` will fail because Native ZETA will not be used as the `from` token since it is not forwarded to `mixSwap`.

### PoC

N/A

### Mitigation

`_doMixSwap()` approves `fromToken`, indicating that they want it to work with Wrapped ZETA, but as we saw, `GatewayZEVM` will pass native ZETA, not Wrapped, so to make this work with NATIVE Zeta, either forward `msg.value` or wrap the Native before using `mixSwap`.
