# No Refund Mechanism for Excess ETH

### Summary

The contract lacks a mechanism to refund excess ETH sent by users in transactions.

[Link to code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L236).

### Root Cause

In both `depositAndCall` functions, the contract only checks if the sent ETH amount (`msg.value`) is sufficient to cover the specified amount but does not refund any excess ETH to the sender. This forces users to precisely calculate the required ETH amount, and any excess sent will remain locked in the contract.

For the first `depositAndCall` function (with swap functionality), the entire `msg.value` is forwarded to `_doMixSwap` regardless of the actual amount needed for the swap, which may lead to unintended behavior if DODO's swap router processes the entire value.

### Attack Path

1. User calls a function with `msg.value` greater than the required `amount`
2. The contract validates that enough ETH has been sent (`msg.value >= amount`)
3. The contract does not refund any excess ETH to the user
4. Excess ETH remains in the contract balance, inaccessible to the user who sent it

### Impact

Impact: Medium - Users lose access to excess funds, but they can avoid this by sending exact amounts.

Likelihood: High - Users frequently send transactions with round numbers of ETH, which often results in excess amounts.

### Mitigation

Implement a refund mechanism to return excess ETH to the sender:
```solidity
function depositAndCall(
    address fromToken,
    uint256 amount,
    bytes calldata swapData,
    address targetContract,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // ...existing code...
    if(fromIsETH) {
        require(
            msg.value >= amount, 
            "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
        );
        
        // Refund excess ETH
        uint256 excess = msg.value - amount;
        if (excess > 0) {
            (bool success, ) = msg.sender.call{value: excess}("");
            require(success, "ETH refund failed");
        }
    }
    // ...existing code...
}
```
Apply a similar refund mechanism to the other `depositAndCall` function. This ensures users receive back any excess ETH they may have sent with the transaction.
