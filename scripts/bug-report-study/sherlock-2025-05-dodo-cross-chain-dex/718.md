Brief Grey Mustang

Medium

# Attacker will cause failed deposits for users

### Summary

A lack of validation in the [`depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L285) function will cause failed deposits for users as an attacker will specify an incorrect asset that does not match the swap’s output token, leading to the contract attempting to deposit tokens it does not possess.


### Root Cause

In `GatewaySend.sol` the [`depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L244-L246) function (lines 244-246) performs a token swap but fails to verify that the user-specified `asset` matches the swap’s output token (`toToken`), resulting in a mismatch that triggers a deposit failure.
```solidity
// Swap on DODO Router
        uint256 outputAmount = _doMixSwap(swapData);
```


### Internal Pre-conditions

1. User needs to call `depositAndCall` to set `fromToken`, `amount`, `swapData`, `targetContract`, `asset`, `dstChainId`, and `payload` with valid values.
2. User needs to configure `swapData` to set the swap output to be exactly `toToken`.
3. User needs to specify `asset` to be other than `toToken` from the swap.


### External Pre-conditions

1. The DODO router (`IDODORouteProxy`) needs to be operational to execute the swap as defined in `swapData`.
2. The gateway (`GatewayEVM`) needs to be active to process deposit attempts.


### Attack Path

1. Attacker calls `depositAndCall` with `fromToken` as ETH, `amount` as 1 ETH, `swapData` configured to swap ETH to USDC, and `asset` set to DAI.
2. The contract executes the swap via [`_doMixSwap`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L195-L216), converting 1 ETH to 1000 USDC (`toToken` = USDC).
3. The contract attempts to deposit 1000 units of `asset` (DAI) to the gateway, but since it only holds USDC, the deposit fails.
4. The transaction reverts due to insufficient DAI balance.


### Impact

This issue allows failed deposits that waste users’ gas and disrupt cross-chain transfers, undermining the contract’s reliability and usability.

### Mitigation

To resolve this, validate that asset matches the swap’s output token by updating _doMixSwap to return toToken and adding a check in depositAndCall. Here’s the fix:
```diff
- function _doMixSwap(bytes calldata swapData) internal returns (uint256) {
+ function _doMixSwap(bytes calldata swapData) internal returns (uint256, address) {
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);
    // ... swap logic ...
    uint256 outputAmount = IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(/* params */);
+   return (outputAmount, params.toToken);
}
```
```diff
function depositAndCall(

-   uint256 outputAmount = _doMixSwap(swapData);
+   (uint256 outputAmount, address toToken) = _doMixSwap(swapData);
+   require(asset == toToken, "Asset must match swap output token");
    // ... rest of the function ...
}
```
