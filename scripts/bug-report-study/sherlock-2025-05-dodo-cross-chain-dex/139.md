# GatewayTransferNative.onCall() function does not deduct fees in some cases which would lead to dos of execution

### Summary

During `GatewayTransferNative.onCall()` the platform fees are transferred in `zrc20` tokens from the amount received by the gateway. 

The issue is that when `targetZRC20 != zrc20`, the `amount` is not adjusted by the `platformFeesForTx`, and the DODO swap in the internal `_doMixSwap()` will revert, dosing the cross-chain interaction.

### Root Cause

Gateway calls the `GatewayTransferNative.onCall()` function and transfers `amount` of `zrc20` tokens. Later, the function [calculates the platform fees](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L370) from the `amount` value:
```solidity
uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
```
And the `_handleFeeTransfer()`:
```solidity
function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```

As you can see, the `_handleFeeTransfer()` transfers the `platformFeesForTx` from contract to `EddyTreasurySafe`.

Then, the `onCall()` function enters the `else` branch if `decoded.targetZRC20 != zrc20`, and tries to perform the swap on DODO:
```solidity
 uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
```

However, it does not subtract the `platformFeesForTx` from `amount` value.

Suppose that length of the `swapData` is zero. Then the function `_doMixSwap()` will simply [return the `amount`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L430C9-L432C10):
```solidity
if (swapData.length == 0) {
            return amount;
        }
```

The return value is the `outputAmount`, which in our case equals to the `amount`. And later the `onCall()` will try to [transfer the `outputAmount`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L397-L407) from contract. However, at that point the contract does not have the exact `amount` because it was not adjusted by the platform fees, and the transaction will revert.

### Internal Pre-conditions

1. Gateway calls the `GatewayTransferNative.onCall()` function;
2. Platform fees not equal zero;
3. The `targetZRC20 != zrc20` token;
4. `swapData.length == 0`;

### External Pre-conditions

None

### Attack Path

See internal pre-conditions

### Impact

DoS of cross-chain interaction.

### PoC

_No response_

### Mitigation

In the `onCall()` function:
```diff
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
