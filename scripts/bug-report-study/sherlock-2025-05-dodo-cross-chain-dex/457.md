# An attacker will steal protocol funds from reverted cross-chain txs

### Summary

The missing validation check in `GatewaySend._doMixSwap` will cause unauthorized token withdrawals for the protocol as an attacker will craft malicious `swapData` pointing to valuable tokens already held by the contract (e.g., from previously reverted cross-chain transactions) and can set the value to any amount. 


### Root Cause

In `GatewaySend.sol` whenever [`depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L218) or `onCall` is called it triggers`_doMixSwap()` to perform swap when necessary , but  the function fails to validate that `params.fromToken` and `params.fromTokenAmount`  in the decoded swapdata match the actual `fromToken` and `amount` deposit by the user. This allows the attacker to swap tokens already held by the contract instead of only the tokens provided by the attacker.


### Internal Pre-conditions

1. The contract `gatewaySend` must hold a non-zero balance of token/eth (e.g., from a reverted cross-chain swap).
2. An attacker needs to approve and call `depositAndCall` with a low value token and maliciously crafted `swapData`.


### External Pre-conditions

N/Q

### Attack Path

1. The attacker identifies or waits for the contract to hold a token balance from a prior legitimate operation.
2. The attacker prepares swap parameters (`swapData`) that reference this already-held token as the input (`fromToken`) and an inflated `params.fromTokenAmount`. note the attacker can decide to check the `params.fromToken` token to an high value toke too
3. The attacker initiates a swap function with a small deposit of a different token, passing in the malicious `swapData`.
4. Due to missing validation, the swap executes using the tokens already held in the contract rather than the tokens deposited by the attacker.
5. The attacker receives the swap output, effectively extracting value from the protocol's internal funds.


### Impact

The protocol  can suffers an approximate loss equal to the contract-held token balance that is swapped out. The attacker deposits a smaller or unrelated amount and gains tokens funded by protocol assets.

### Mitigation

Inside `_doMixSwap`, enforce:

```solidity
require(params.fromToken == actualFromToken, "Invalid fromToken");
require(params.fromTokenAmount == actualAmount, "Invalid fromTokenAmount");
```

Where `actualFromToken` and `actualAmount` are derived from the user’s actual deposit.
