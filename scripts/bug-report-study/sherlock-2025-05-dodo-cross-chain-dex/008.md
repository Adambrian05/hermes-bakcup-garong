# depositAndCall will revert if fromToken does not return bool on transferFrom

### Summary

There are multiple instances of the following pattern in GatewaySend.sol:

```solidity
require(
                IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
                "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
            );
```

This will result in revert if `fromToken` is missing return value on `transferFrom`

### Root Cause

The following codes will revert if `fromToken` is missing return value on `transferFrom`:

[File: omni-chain-contracts/contracts/GatewaySend.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L316-L319)
```solidity
238:             require(
239:@>               IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
240:                 "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
241:             );
...
316:             require(
317:@>               IERC20(asset).transferFrom(msg.sender, address(this), amount),
318:                 "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
319:             );
```

For example USDT token does not return true on successful `transferFrom`.

It is mentioned in the [protocol doc](https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets) that USDT is in scope.
