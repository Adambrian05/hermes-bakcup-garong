# The `feePercent` of GatewayCrossChain,GatewayTransferNative contract has no value range check

### Summary

The `feePercent` variable of the GatewayCrossChain and GatewayTransferNative contract has no value range restrictions in the `initialize` function and the `setFeePercent` function, which may cause the `feePercent` to exceed expectations, resulting in the handling fee not being consistent with the expected value.

### Root Cause

In the GatewayCrossChain and GatewayTransferNative contract, the `feePercent` state variable is used to calculate the transaction fee. Normally, this variable should be 5, because the code comment says:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L345
```solidity
function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```
However, there is no restriction on the value range of `feePercent` in the `initialize` function and `setFeePercent` function of the GatewayCrossChain contract.

### Internal Pre-conditions

The owner incorrectly set `feePercent`, resulting in excessively high fees

The owner incorrectly set `feePercent`, resulting in excessively high fees

### Impact

Transaction fees may exceed the expected 0.5%.
