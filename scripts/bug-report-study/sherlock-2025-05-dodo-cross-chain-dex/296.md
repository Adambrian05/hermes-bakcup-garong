# Security Issues Caused by Non-Standard ERC20 Tokens

## Summary

When using IERC20 transfer and transferFrom functions, they typically return a boolean value indicating success. However, when encountering non-standard ERC20 tokens (such as early USDT and BNB), they may have no return value or directly revert, leading to security vulnerabilities.

## Root Cause

The standard ERC20 requires transfer and transferFrom functions to return a boolean value (bool success). However, some tokens (like early USDT and BNB) return no value and only handle failures by reverting transactions.

The GatewaySend contract uses the return value of IERC20's transferFrom as a condition in require statements. When encountering non-standard ERC20 tokens that have no return value or revert, this causes errors during calls and prevents normal completion of cross-chain operations.

Tokens like USDT supported by the contract do not correctly implement the EIP20 standard. Their transfer/transferFrom functions have no bool return value. Calling these functions with standard EIP20 function signatures will always cause transaction reverts.

The GatewaySend contract also has other calls using IERC20.transfer(), IERC20.transferFrom(), and IERC20.approve() that require modification.
