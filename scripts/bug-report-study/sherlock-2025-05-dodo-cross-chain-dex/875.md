# Swap failure due to insufficient token approval



## Summary: 
The[`_doMixSwap`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337-L361) function in the [`GatewayCrossChain.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L347-L360) contract may fail when the user-specified swap amount exceeds the available token amount after fees, leading to a transaction revert.

## Root Cause: 
In [`GatewayCrossChain.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L347-L360), the [`_doMixSwap`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337-L361) function approves the DODO proxy to spend the available `amount` after fee deduction but executes the `mixSwap` function with the user-provided `params.fromTokenAmount`, which can exceed the approved amount. This discrepancy arises because the approval is based on the reduced `amount` after fees, while the swap uses the original `params.fromTokenAmount`, leading to an insufficient allowance error when the DODO proxy attempts the transfer.

```solidity
        return IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
```

## Internal Pre-conditions: 
1. The user needs to initiate a cross-chain swap by calling the `onCall` function, providing a `message` that specifies `params.fromTokenAmount`.
2. The platform fee (`feePercent`) needs to be greater than zero, resulting in a deduction from the received `amount`.
3. The user’s specified `params.fromTokenAmount` needs to be greater than the `amount` remaining after the fee deduction.

## External Pre-conditions: 
None required, as the issue is entirely internal to the `GatewayCrossChain` contract and its interaction with the DODO proxy.

## Attack Path
1. The user calls `onCall` in `GatewayCrossChain`, sending a transaction with a `message` that includes `params.fromTokenAmount` and triggers the swap process.
2. The `onCall` function decodes the `message` to retrieve `params` and calculates the platform fee, reducing the received `amount` to `amount - platformFeesForTx`.
3. The contract invokes `_doMixSwap`, passing the reduced `amount` and the original `params`.
4. Inside `_doMixSwap`, the contract approves the DODO proxy to spend the reduced `amount` using `IZRC20(params.fromToken).approve(DODOApprove, amount)`.
5. The contract then calls `IDODORouteProxy(DODORouteProxy).mixSwap`, passing `params.fromTokenAmount` as the amount to swap.
6. The DODO proxy attempts to transfer `params.fromTokenAmount` from the contract, but since this exceeds the approved `amount`, the transaction reverts due to insufficient allowance.

## Impact: 
The swap transaction fails, preventing the user from completing their cross-chain operation whenever `params.fromTokenAmount` exceeds the post-fee `amount`. This disrupts the user experience and may require manual intervention to resolve.

## Mitigation
To resolve this, the contract should validate that the swap amount does not exceed the available amount after fees. Adding a check in _doMixSwap ensures the swap only proceeds if params.fromTokenAmount is feasible, preventing failures.
