# Slippage protection calculation can underflow during gas token swaps

## Vulnerability Details

The protocol implements slippage through an admin-adjustable parameter during the conversion of ZRC20 tokens to their corresponding gasZRC20 tokens via a Uniswap pair pool. The problem arises because gas fees can actually be very low in nature, which means the intended slippage protection provided by the protocol will underflow for lower decimal tokens (e.g. USDC)

```solidity
    function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

@>        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000; //@audit slippage calculation uses only 4 decimal precision, which is not enough for low decimal tokens like USDC swaps for gas tokens
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

## POC

Consider the following scenario

1. Alice plans to send some USDC.ETH to her Ethereum receiving address by using `GatewayTransferNative.withdrawToNativeChain`.
2. In the process, she invokes `GatewayTransferNative._swapAndSendERC20Tokens` to convert 0.0002 (200 wei) worth of USDC.ETH into an equivalent amount of `gasUSDC` tokens.
3. If the slippage is set at a fixed rate of 1%, her `amountInMax` calculates to 200 wei + (10 * 200 / 1000) = 200 wei, which is required for the swap to gasUSDC tokens.
4. Consequently, Alice doesnt receive any slippage protection, and her transaction is likely to revert continuously.

## Root Cause

Low precision usage when calculating slippage for tokens to gas tokens swaps

## Impact

No slippage protection present for user since slippage calculation always underflows for low decimal tokens and gas price is low

## Mitigation

Consider using higher precision when calculating slippage. 18 precision would be recommended
