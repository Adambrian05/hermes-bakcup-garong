# `GatewayTransferNative::withdrawToNativeChain` always reverts for native ZETA

### Summary
The `withdrawToNativeChain` function in the `GatewayTransferNative` contract is non-functional for native ZETA as `_handleFeeTransfer` is cannot accomodate the transfer of native ZETA.

### Root Cause

The `withdrawToNativeChain` function calls `_handleFeeTransfer` without accounting for the asset type. When a user tries to withdraw native ZETA, `zrc20` is `_ETH_ADDRESS_`. This address is passed to `_handleFeeTransfer`, which unconditionally calls `safeTransfer` on it.

```solidity
// file: omni-chain-contracts/contracts/GatewayTransferNative.sol

function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    // ...
    // The following call will revert if zrc20 == _ETH_ADDRESS_ and a fee is charged.
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
    // ...
}

function _handleFeeTransfer(
    address zrc20,
    uint256 amount
) internal returns (uint256 platformFeesForTx) {
    platformFeesForTx = (amount * feePercent) / 1000;
    // This call fails if zrc20 is not a contract 
    // it is _ETH_ADDRESS__
    TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
}
```
The fee handling logic is incompatible with the contract's native asset withdrawal functionality.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Users call `GatewayTransferNative::withdrawToNativeChain` and specify in `MixSwapParams::params` that `fromToken` is `_ETH_ADDRESS`. Do note that developers intentions to allow this is evident by marking the function as `payable` as seen [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L534).

2. `_handleFeeTransfer` is entered, and `TransferHelper::safeTransfer` is called on `_ETH_ADDRESS`.

3. As `TransferHelper::safeTransfer` only works on ERC20/ZRC20 tokens, execution reverts.
### Impact

1. Denial of Service for this use case, as there is no work around to swap native ether for other tokens.


### PoC

Please see attack path.

### Mitigation

```diff

        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
+        if (zrc20 == _ETH_ADDRESS){

+        } else {
+       TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);            
+        }
-        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```
