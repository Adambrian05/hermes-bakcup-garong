# `_swapAndSendERC20Tokens` incorrectly uses the balance of the contract to ensure there is enough gas which can lead to loss a user refunds in the contract

### Summary

`_swapAndSendERC20Tokens` checks that there is enough of a gas token in the contract after completing the swap to the native gas token on the destination chain. The problem is that there could be users who have a refund in the contract for a gas token which may be used to withdraw from the gateway.

### Root Cause

There is this check after a swap is complete to ensure the balance of the contract can cover gas costs. This would include any refund amounts users may be potentially eligible for in the contract. Lets say the swap transaction resulted in significantly less gasZRC20 than intended, this check could still pass due to refunds currently within the contract
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L328


### Internal Pre-conditions

1. A call is made to `onCall` which somehow triggers a revert in the gateway contract
2. Gateway refunds the contract in the `onRevert` callback

### External Pre-conditions

1. Gateway is up and running

### Attack Path

1. Users cross chain swap reverted 
2. Gateway calls `onRevert` with the refund amount and user eligible for the refund
3. `onCall` is called from gateway which triggers a swap to a native gas token
4. Swap produces significantly less than intended gas token amount
5. Check still passes due to refund tokens in the contract
6. Users refund is used as gas in the gateway contract

### Impact

Loss of user funds 

### PoC

_No response_

### Mitigation

Contract should ensure amounts out of the swap is sufficient enough to cover gas cost, not the balance of the contract.
