# Excess ETH Sent During depositAndCall Is Not Refunded, Leading to Locked Funds

## Description
In the contract GatewaySend,

The root cause arises in the two function depositAndCall implemented, The first function depositAndCall, when fromIsETH is true, it checks msg.value >= amount, but it does not handle excess ETH sent (i.e., msg.value > amount). This could lead to funds being locked in the contract.
```solidity
if(fromIsETH) {
    require(
        msg.value >= amount, 
        "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
    );
}
```
Problem:

This check ensures the user sent at least amount of ETH.

However, it does not handle the case where msg.value > amount.

The excess ETH remains locked in the contract, since it is neither refunded to the sender nor used for any purpose.


The second  function depositAndCall in the contract GatewaySend, 
It is allowing extra ETH to be sent (msg.value > amount), but not refunding the excess. This could result in funds being stuck

In the ETH handling path:
```solidity
if (isETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
    _handleETHDeposit(
        targetContract, 
        msg.value, // <-- this sends the full msg.value, not just `amount`
        message, 
        revertOptions
    );
}
```
The function:

Validates that msg.value >= amount,

But uses msg.value instead of amount,

And does not refund or reject excess ETH (msg.value > amount).

Impact
Loss of Funds: Users who overpay will unknowingly lock excess ETH in the contract or transfer more ETH than intended.

Incorrect Accounting: Using msg.value instead of the user-specified amount could lead to mismatches in logs, vault tracking, or revert behavior.

## Recommendation
For the first function depositAndCall
Add logic to refund the excess ETH back to the sender after validation:
```solidity
if (fromIsETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
    uint256 excess = msg.value - amount;
    if (excess > 0) {
        (bool success, ) = msg.sender.call{value: excess}("");
        require(success, "Refund failed");
    }
}
```

For the second  function depositAndCall
Update the logic to use only the specified amount and refund the rest:
```solidity
if (isETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");

    // Only use `amount`, not `msg.value`
    _handleETHDeposit(
        targetContract,
        amount,
        message,
        revertOptions
    );

    // Refund excess ETH
    uint256 excess = msg.value - amount;
    if (excess > 0) {
        (bool success, ) = msg.sender.call{value: excess}("");
        require(success, "ETH refund failed");
    }
}
```
This also assumes ReentrancyGuard or the checks-effects-interactions pattern is used.
