# ETH Sent But Ignored When Using ERC20 in depositAndCall

## Description
The root cause lies in the first function depositAndCall in the contract GatewaySend, if fromisETH == false, and msg.value > 0, then ETH is sent but ignored, which could cause lost funds.

In the first function depositAndCall, when fromIsETH is false (using an ERC20 token) and msg.value > 0 (1 ETH sent), the ETH is received by the contract (balance increases by 1 ETH) but ignored (not recorded in ethDeposited, which remains 0). This confirms the potential for lost funds, as the ETH is not processed or refunded when fromToken is not ETH.

Code Block of Interest:
```solidity
bool fromIsETH = (fromToken == _ETH_ADDRESS_);

if(fromIsETH) {
    require(
        msg.value >= amount, 
        "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
    );
} else {
    require(
        IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
        "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
    );
}
```
Problem Description:
When fromIsETH == false, the contract assumes the user is depositing ERC20 tokens, and executes:
```solidity
IERC20(fromToken).transferFrom(...)
```
However, there is no check for whether msg.value > 0 in this branch.

Impact
This bug can lead to permanent loss of user funds in the form of ETH.
The contract accepts the ETH, increasing its balance.

But the ETH is never used, tracked, or refunded.

It becomes inaccessible and locked in the contract

        balanceOf[to] += amount;
        allowance[from][msg.sender] -= amount;
        return true;
    }

        allowance[msg.sender][spender] = amount;
        return true;

## Recommendation
Update the input token handling block in depositAndCall as follows:
```solidity
bool fromIsETH = (fromToken == _ETH_ADDRESS_);

if (fromIsETH) {
    require(
        msg.value >= amount,
        "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
    );
} else {
    require(
        msg.value == 0,
        "INVALID TX: ETH NOT EXPECTED"
    );
    require(
        IERC20(fromToken).transferFrom(msg.sender, address(this), amount),
        "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
    );
}
```
Why This Is the Best Solution
 Prevents loss: Reverts the transaction if ETH is mistakenly sent when it's not needed.

Simple and efficient: One-line check (require(msg.value == 0)) with clear revert message.

 Avoids reliance on refund logic, which could be error-prone or gas-constrained.

 Explicit: Makes developer/user intent clear — either you're sending ETH, or you're not.
