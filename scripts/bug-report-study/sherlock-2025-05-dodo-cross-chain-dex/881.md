# Function `claimRefund` implementation was wrong, makes attacker to steal the tokens within the contract

### Summary

Attacker can steal the tokens of the reverted cross-chain transactions by the calling the `claimRefund` from `GatewayCrossChain` or `GatewayTransferNative` contract

### Root Cause

The function [`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) in `GatewayTransferNative` (or `GatewayCrossChain`) contract assumes that this function only being called by the aborted cross-chain transactions, but it will also being called but actually the user position updated on `onRevert` function can also call the `claimRefund` function.

On [`onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L607-L638) function, we can clearly see that `refundInfos` get also updated if the revert message is more than 20 bytes. But the issue here is that the updating the `walletAddress` isn't being done in 20 bytes, which lead a massive bug in `claimRefund` function.

```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];


        if(context.revertMessage.length == 52) {
            address receiver = address(uint160(bytes20(walletAddress)));
            TransferHelper.safeTransfer(context.asset, receiver, context.amount);


            emit EddyCrossChainRevert(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        } else {
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: context.asset,
                amount: context.amount,
>@                walletAddress: walletAddress
            });
            refundInfos[externalId] = refundInfo;
            
            emit EddyCrossChainRefund(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        }
    }
```
```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
>@        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```

As you can see this function checks 20 bytes length, but `onRevert` function there are more than 20 bytes users so eventually the if check passes, which makes very big bug to steal the funds of user by receiver, i.e., attacker here

### Internal Pre-conditions

`refundInfos` mapping is mapped with at least one user with `walletAddress` more than 20 bytes

### External Pre-conditions

N/A

### Attack Path

Attacker calls the `claimRefund` function with user `externalId` and left with user funds within the contract

### Impact

The impact is HIGH, because attacker can steal the tokens of user that are within the contract for their reverted cross-chain transaction
