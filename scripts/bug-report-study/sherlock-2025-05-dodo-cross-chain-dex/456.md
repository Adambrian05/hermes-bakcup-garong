# Missing Swap Data Validation in _doMixSwap() Allows Bypassing Intended Token Swaps

### Summary

The _doMixSwap() function assumes that an empty swapData means a direct token transfer with no actual swap needed:

```solidity
if (swapData.length == 0) {
    return amount;
}
```
However, this logic is used to determine how much of the target token should be sent to the user — even though no actual token conversion occurs .

This opens up a serious exploit path:

A user can bridge a low-value token (e.g., DAI),
Request to receive a high-value token (e.g., WETH or WZETA),
Provide empty swapData ,
And still receive the full amount of high-value token without any real swap occurring.

### Root Cause

there is no validation in _doMixSwap or in the functions that use it that a swap is skipped only when fromToken == toToken 

### Internal Pre-conditions

the contract holds valuable funds from previous reverts and aborts 

### External Pre-conditions

none 

### Attack Path

User Intent
ETH price = $4,000
Contract holds 10 WETH from previous failed swaps/refunds
Attacker wants to drain contract liquidity

 Step-by-step Flow
Attacker calls depositAndCall() on Ethereum with:
asset = DAI
amount = 10e18 DAI (~$10)
message encodes:
targetToken = WETH
swapData = "" (empty)

On ZEVM:
onCall() decodes message
Since targetToken != asset, it proceeds to call _doMixSwap("", 10e18, params)
_doMixSwap() sees swapData.length == 0 → returns outputAmount = 10e18
System assumes a successful swap and:
Sends 10 WETH to attacker
Keeps attacker’s 10 DAI in the contract

Result:
Attacker receives $40,000 worth of WETH
For only $10 cost
Contract balance now has more DAI, but less WETH

### Impact

malicious users can drain the zevm contracts
