# Missing ETH Validation in onCall()

### Summary



if (fromToken == toToken) {
    outputAmount = amount;
} else {
    outputAmount = _doMixSwap(swapData);
}

if (toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
}




If fromToken == toToken == _ETH_ADDRESS_, then you assume the ETH is already available (outputAmount = amount) and proceed to transfer amount ETH to the user.


BUT... there's no check to make sure that the actual ETH received (msg.value) is at least amount.



 Why It’s Dangerous
You might attempt to send more ETH (amount) than was actually sent to the contract via msg.value.

This will cause a revert, potentially breaking the entire cross-chain flow.

Worse, if the ETH shortfall is due to a bug in the sender chain or the Gateway, this could cause systemic failure across all such transfers.



 Example Scenario

Suppose:

fromToken = toToken = _ETH_ADDRESS_

amount = 1 ether

msg.value = 0.5 ether (e.g., incorrect or partial transfer)


outputAmount = amount; // 1 ether
...
payable(evmWalletAddress).transfer(outputAmount); // tries to send 1 ether
 But you only have 0.5 ether. This causes a revert at runtime.

### Mitigation


Add a proper check for ETH sufficiency before making the transfer:


if (toIsETH && fromToken == toToken) {
    require(msg.value >= amount, "INSUFFICIENT ETH RECEIVED");
}
Or a more general fix:

if (toIsETH) {
    require(msg.value >= outputAmount, "INSUFFICIENT ETH RECEIVED");
}
