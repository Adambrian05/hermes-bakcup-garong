# Theft of user refunds through `claimRefund` if `refundInfo::walletAddress` is not `20 bytes`

### Summary

The `claimRefund` function in `GatewayCrossChain` contains a critical vulnerability that allows any user to steal refunds intended for non-EVM compatible wallet addresses. When `refundInfo.walletAddress` is not exactly 20 bytes, the function defaults the receiver to `msg.sender`, enabling theft of funds belonging to legitimate users.

### Root Cause

In `GatewayCrossChain.sol`, the `claimRefund` function has flawed logic for handling non-EVM wallet addresses:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590
```solidity
function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];
    
    address receiver = msg.sender; // DEFAULT TO CALLER
    if (refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
    // If walletAddress != 20 bytes, receiver remains msg.sender
    
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
    // When receiver == msg.sender (non-20-byte addresses), this always passes
}
```
The vulnerability occurs because:
- Non-EVM addresses (solana addresses) are encoded in place (> 20 bytes)
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L265
```solidity
       RevertOptions({
           revertAddress: address(this),
           callOnRevert: true,
           abortAddress: address(0),
           revertMessage: bytes.concat(externalId, receiver), // NOTE for solana chain, we are encoding the receiver which is more than 
           // 20 bytes, solana addresses are 32 bytes
          onRevertGasLimit: gasLimit
      })
```
- in `onRevert` function if `revertMessage` length is more than 52 bytes the the [`refundInfo.walletAddress` (32 bytes) is set to `walletAddress`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L532-L539), in case that we are withdrawing to solana chain, the `revertMessage` length is 64 bytes, hence the second condition is entered:
```solidity
        if (context.revertMessage.length == 52) {
            // THIS IS NOT ENTERED
        } else {
            // ENTERED HERE
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: context.asset,
                amount: context.amount,
                walletAddress: walletAddress //@audit here the walletAddress is 32 bytes
            });
            refundInfos[externalId] = refundInfo;
```
- Attacker calls `claimRefund` function, since `walletAddress` length is 32 bytes, the first if condition is not entered and `receiver == msg.sender`:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L574-L579
```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        //@audit walletAddress is not 20 bytes, so dont enter this condition
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        //@audit second condition is true, if above condition is not entered
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");

        TransferHelper.safeTransfer(
            refundInfo.token,
            receiver, //@audit transfer funds to receiver (attacker)
            refundInfo.amount
        );
```

### Internal Pre-conditions

- `refundInfo.walletAddress != 20 bytes` (which happens if destination chain is solana and CCTX reverted)

### External Pre-conditions

- CCTX on solana chain reverted and `GatewayCrossChain::onRevert` is called with `revertMessage`

### Attack Path

**Example:**
1. `walletAddress` on solana is `59TBXPAU4D8vZCKqa83BAJaVdmwmH5Eb23tLow9Sk3o5` to receive solana coins
2. CCTX to solana chain reverts and `onRevert` is called with `revertMessage`
3. `revertMessage` is `[externalId, 59TBXPAU4D8vZCKqa83BAJaVdmwmH5Eb23tLow9Sk3o5]`
4. `refundInfo.walletAddress` is set to `revertMessage[32:]` or `59TBXPAU4D8vZCKqa83BAJaVdmwmH5Eb23tLow9Sk3o5`
5. `claimRefund` is called from attacker address, since `walletAddress` is not 20 bytes, receiver remains `msg.sender`
6. since `msg.sender == receiver`, the critical authentication condition passes and funds are transferred to `receiver`

### Impact

- theft of user refunds if `walletAddress` is not 20 bytes

### PoC

_No response_

### Mitigation

- if `walletAdderss > 20 bytes`, `msg.sender` must be authenticated for being able to withdraw the refund on user behalf, or be a valid `bot`
