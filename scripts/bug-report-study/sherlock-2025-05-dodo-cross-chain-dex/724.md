# An Attacker can grief user of thier refund in GatewayCrossChain.sol and GatewayTransferNative.sol

### Summary

An attacker can grief user of thier refund by creating the `Externalid ` for their transaction and calling the gateway directly using abort address as the `targetContract` and passing in the revert `message` as the generated `Externalid ` and ensuring that the call aborts.
`onAbort` on zetachain is triggered, which overwrites the `refundInfos` for the `Externalid ` trapping users refunds .

### Root Cause

This is due to the fact that [`ExternalId`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L160) can easily be generated and the `onRevert` and `onAbort` functions overwrite the `externalId` in `refundInfos`.

```solidity
function _calcExternalId(address sender) internal view returns (bytes32 externalId) {
        externalId = keccak256(abi.encodePacked(address(this), sender, globalNonce, block.timestamp));
    }
```
All required parameters  ( contract address, sender, globalNonce, block.timestamp) required to create the `ExternalId` can easily be gotten by the attacker to create the `ExternalId` for any transaction.


And in [onRevert](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L539) and [onAbort ](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L651)functions in the GatewayCrossChain.sol and GatewayTransferNative.sol the `refundInfos` is easily overdiden without any check if it already exists .
```solidity
     * @notice Function called by the gateway to revert the cross-chain swap
     * @param context Revert context
     * @dev Only the gateway can call this function
     */
    function onRevert(RevertContext calldata context) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];


        if(context.revertMessage.length == 52) {
            address receiver = address(uint160(bytes20(walletAddress)));
            TransferHelper.safeTransfer(context.asset, receiver, context.amount);


            emit EddyCrossChainRevert(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        } else {
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: context.asset,
                amount: context.amount,
                walletAddress: walletAddress
            });
@>          refundInfos[externalId] = refundInfo;
            
            emit EddyCrossChainRefund(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        }
    }


    function onAbort(AbortContext calldata abortContext) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(abortContext.revertMessage[0:32]);
        bytes memory walletAddress = abortContext.revertMessage[32:];


        RefundInfo memory refundInfo = RefundInfo({
            externalId: externalId,
            token: abortContext.asset,
            amount: abortContext.amount,
            walletAddress: walletAddress
        });
@>      refundInfos[externalId] = refundInfo;
        
        emit EddyCrossChainRefund(
            externalId,
            abortContext.asset,
            abortContext.amount,
            walletAddress
        );
    }
```

According to the [Zetachain docs](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions), in an Incoming transaction, if `revert` fails, `onAbort()` on ZetaChain is called.
> If the amount is insufficient or zero (for example, when it's a no-asset call) the Gateway calls onAbort on the abortAddress on ZetaChain.

### Attack Path

* After a transaction reverts or is aborted.
* Before the original `Externalid` owner calls `claimRefund()`
* The attacker generates `Externalid ` using the parameters that can be easily gotten. (address(this), sender, globalNonce, block.timestamp), 
* All these required parameters will be manually inputted by the attacker to generate the `Externalid `
* The attacker calls `depositAndCall` or `call` on the gateway directly passing in RevertOptions.abortAddress as either GatewayCrossChain.sol or GatewayTransferNative.sol with this `Externalid` as the `revertMessage`.
* The transaction is structured to cause an abort (passing in an invalid receiver that reverts when called and a micro amount to prevent a revert by being too low to cover revert gas fees).
* The abort function is called by the gateway on the RevertOptions.abortAddress with `AbortContext` that matches the current attacker's transaction.
* onAbort() overrides `refundInfos[externalId]` with the new `token, amount and wallet address`.
* The original `Externalid` owner will lose the refunded funds 

### Impact

Owners of the asset during a refund will lose all their assets because of the actions of the attacker.
