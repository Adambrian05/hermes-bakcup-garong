# Insuficcient slippage procetion could cause the user to spend more

### Summary

When withdrawing through [[GatewayTransferNative::withdrawToNativeChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L580-L585)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L580-L585), the internal `_swapAndSendERC20Tokens` function is used to convert the target token to the necessary gas token:

```solidity
function _swapAndSendERC20Tokens(address targetZRC20, address gasZRC20, uint256 gasFee, uint256 targetAmount)
    internal
    returns (uint256 amountsOut)
{
    uint256[] memory amountsQuote = UniswapV2Library.getAmountsIn(
        UniswapFactory,
        gasFee,
        getPathForTokens(targetZRC20, gasZRC20)
    );

    uint256 amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;

    IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

    uint256[] memory amounts = IUniswapV2Router01(UniswapRouter).swapTokensForExactTokens(
        gasFee,
        amountInMax,
        getPathForTokens(targetZRC20, gasZRC20),
        address(this),
        block.timestamp + MAX_DEADLINE
    );

    require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
    require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

    IZRC20(gasZRC20).approve(address(gateway), gasFee);
    IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

    amountsOut = targetAmount - amounts[0];
}
```

Currently, the function computes `amountInMax` based on current on-chain reserves and a hardcoded slippage tolerance. This provides **no actual protection** for the user if market conditions change while the transaction is pending. Any front-running or pool manipulation could cause the swap to execute at a significantly worse rate than expected.

### Root Cause

Slippage tolerance is calculated on-chain and fixed at the time of execution, which does not reflect the user's intended acceptable price impact.

### Internal Pre-conditions

None

None

N/A (no active attacker needed)

### Impact

Users can unintentionally execute swaps at significantly worse rates than expected, particularly in volatile markets or manipulated pools.

### PoC

*No response*

### Mitigation

Allow users to specify slippage tolerance off-chain as part of the calldata. This ensures that if the price changes beyond the user's acceptable limits before execution, the swap fails gracefully rather than proceeding with excessive cost.
