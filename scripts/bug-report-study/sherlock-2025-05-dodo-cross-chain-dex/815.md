# `GatewaySend.onRevert` cannot handle ETH transfer

### Summary

`GatewaySend.onRevert` cannot handle ETH transfer

### Root Cause

When a user sends tokens to Zetachain using GatewaySend, if the transaction reverts on Zetachain, GatewaySend.onRevert will be called, causing the tokens to be returned to the original sender. However, the current way Zetachain handles ETH reverts is by first transferring the tokens and then calling onRevert.

https://github.com/zeta-chain/protocol-contracts/blob/main/contracts/evm/GatewayEVM.sol#L107
```solidity
        (bool success,) = destination.call{ value: msg.value }("");
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext);
```

This means that the ETH tokens have already been transferred to the gateway, but they still cannot be processed.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L524
```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];

        if(context.revertMessage.length == 52) {
            address receiver = address(uint160(bytes20(walletAddress)));
            TransferHelper.safeTransfer(context.asset, receiver, context.amount);

            emit EddyCrossChainRevert(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );

```
