# Attacker will steal tokens from GatewayTransferNative due to lack of token transfer check

### Summary

[GatewayTransferNative.sol:onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357) uses `decoded.targetZRC20` instead of `params.toToken` when sending tokens. This allows an attacker to manipulate `targetZRC20` and receive a more valuable token than the one he originally transferred.

### Root Cause

`GatewayTransferNative.sol:onCall()` uses `decoded.targetZRC20` instead of `params.toToken` when sending tokens if swap is used:
```solidity
function onCall(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    bytes calldata message
) external override onlyGateway {
    // Decode the message
    // 32 bytes(externalId) + bytes message
    (bytes32 externalId) = abi.decode(message[0:32], (bytes32)); 
    bytes calldata _message = message[32:];
    //@audit @note this is arbitrary data
    (DecodedNativeMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeNativeMessage(_message);
    ...
    if (decoded.targetZRC20 == zrc20) {
        ...
    } else {
        // Swap on DODO Router
        uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
        //@audit @note instead of sending params.toToken it will send decoded.targetZRC20
        if (decoded.targetZRC20 == WZETA) {
            // withdraw WZETA to get Zeta in 1:1 ratio
            IWETH9(WZETA).withdraw(outputAmount);
            // transfer wzeta
            TransferHelper.safeTransferETH(receiver, outputAmount);
        } else {
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                outputAmount
            );
        }
    ...
}
```
While in [GatewaySend.sol:depositAndCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L287) we can set any `swapData` we want:
```solidity
function depositAndCall(
    address targetContract,
    uint256 amount,
    address asset,
    uint32 dstChainId,
    bytes calldata payload //@audit @note arbitrary data
) public payable {
    globalNonce++;
    bytes32 externalId = _calcExternalId(msg.sender);
    bool isETH = (asset == _ETH_ADDRESS_);
    //@audit any swap data we set
    bytes memory message = concatBytes(externalId, payload);
    ...
    if (isETH) {
      ...
    } else {
        require(
            IERC20(asset).transferFrom(msg.sender, address(this), amount),
            "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
        );
        _handleERC20Deposit(
            targetContract, 
            amount,
            asset, 
            message, 
            revertOptions
        );
    }
    ...
}
```
All this will allow attacker to use less valuable token on source chain to get more valuable token on ZetaChain.

### Attack Path

Assume there is `1 ETH` of [ETH.ETH](https://zetachain.blockscout.com/address/0xd97B1de3619ed2c6BEb3860147E30cA8A7dC9891) token waiting for refund to some user on `GatewayTransferNative.sol` contract.
1. Attacker calls `GatewaySend.sol:depositAndCall()` with:
    ```solidity
    asset = USDC
    amount = 1e6
    swapData = {fromToken: USDC.ETH, toToken: DAI.ETH, fromTokenAmount: 1e6, expReturnAmount: 1e18}
    nativeMessage = {targetZRC20: ETH.ETH}
    ```
2. On ZetaChain `GatewayZEVM.sol` calls `GatewayTransferNative.sol:onCall()` with:
    ```solidity
    zrc20 = USDC.ETH
    amount = 1e6
    message = swapData + nativeMessage
    ```
3. `onCall()` function makes swap (assume rate is 1:1) `1 USDC.ETH` to `outputAmount = 1 DAI.ETH (1e18)`
4. Now contract uses `nativeMessage.targetZRC20` (`ETH.ETH`) to send `outputAmount = 1 ETH`
5. Attacker get token much more valuable than he sended

### Impact

Attacker will steal tokens from `GatewayTransferNative.sol` contract.

_No response_

### Mitigation

Use `params.toToken` instead of `decoded.targetZRC20`.
