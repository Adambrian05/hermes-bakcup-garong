# No Slippage Protection in _doMixSwap Calls

### Summary


In both depositAndCall() and onCall() functions, the contract calls:

uint256 outputAmount = _doMixSwap(swapData);
Which internally does:

return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
    params.fromToken,
    params.toToken,
    params.fromTokenAmount,
    params.expReturnAmount,
    params.minReturnAmount, //  THIS is the only slippage guard!
    ...
);


 What’s the Problem?


Although minReturnAmount exists in MixSwapParams, your contract does not validate the actual output against it after the swap. It fully trusts the DODO router.


That means:

If DODO returns less than expected due to slippage, price impact, MEV, or front-running,

Your contract will continue operating with fewer tokens than needed, potentially triggering:

Cross-chain revert

Broken user experience

Lost gas fees

Underfunded destination transfers


 Risky Behavior
You send amount tokens expecting minReturnAmount, but due to slippage, receive less.

The contract uses the returned value without verifying that it meets a minimum requirement.

This can result in incorrect or insufficient cross-chain payload execution (e.g., not enough tokens deposited into the target contract on the destination chain).

### Mitigation


After calling _doMixSwap, check that outputAmount meets params.minReturnAmount:


uint256 outputAmount = _doMixSwap(swapData);
require(
    outputAmount >= params.minReturnAmount, 
    "INSUFFICIENT OUTPUT: Slippage too high"
);
