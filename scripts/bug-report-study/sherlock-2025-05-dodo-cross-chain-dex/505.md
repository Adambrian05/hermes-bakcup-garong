# Use safeApproval instead of Approval

### Summary

USDT token come under the scope of the audit.

In the function [GatewaySend._handleERC20Deposit()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L184) , the contract is giving allowances to the gateway contract. But if the [onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442) fn gets revert from the Zetachains  Universal Conrtact (GatewayCrossChain) , the amount will be refunded to the sender[here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L396), but the allowance remains the same.

So when the next time another user  tries to call depositAndCall() for usdt from GatewaySend contract, considering its weird behaviour on approval , it will revert.

### Root Cause

Usage of approval instead of safeApproval() for handling the case of weird tokens

### Internal Pre-conditions

the asset , the user uses to depositAndCall() is USDT. But the onCall() fn reverts from the Zetachains gatewayCrossChain contract as mentioned [in this document](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions).

### External Pre-conditions

NIL

### Attack Path

User calls gatewaySend.depositAndCall()  to deposit usdt and withdraw any other token from the another connected chain.The  GatewaySend._handleERC20Deposit() fn gives allowances to the gateway contract to lock the depsoited tokens.
But the fn onCall() in GatewayCrossChain() contract reverts.For eg. the amount of supplied tokens is not enough to cover the withdraw gas fee to the conneccted destination chain, so the transaction reverts[code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L388). The revert is handled by refunding the amount from the source contract.
Since the allowance is not cleared, the protocol cannot support USDT anymore.

### Impact

 The protocol cannot support USDT transactions.

use safeApproce() from transferHelper library.
