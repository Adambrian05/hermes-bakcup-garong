# A user can lose all funds permanently if a cross-chain transaction fails due to missing escrow unlock logic

### Summary

The lack of a lock and unlock mechanism tied to the externalId in depositAndCall() will cause permanent loss of funds for users as their tokens are transferred into the contract with no way to recover them if the cross-chain message fails to deliver or onCall() reverts.

### Root Cause

In [GatewaySend.sol:depositAndCall] user tokens are transferred into the contract and an externalId is computed, but there is no mapping to track this deposit as an escrowed lock. If onCall() on the destination chain fails or never triggers, the user’s deposit is unrecoverable because the contract does not support any refund or unlock mechanism.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L286

### Internal Pre-conditions

1. A user submits a transaction to depositAndCall() with ETH or ERC20 tokens.
2. The tokens are transferred into the contract, and externalId is generated.
3. No lockedTransfers[externalId] or similar mapping is written to persist the lock state.

### External Pre-conditions

1. The cross-chain call to onCall() on the destination chain fails (e.g., gas issues, chain outage, relayer bug).
2. LayerZero does not retry or the retry does not succeed.

### Attack Path

1. A user calls depositAndCall() and sends 100 USDT to be swapped cross-chain.
2. The tokens are successfully moved to GatewaySend, but no lock state is recorded.
3. The onCall() on the destination chain fails due to invalid swap data or expired parameters.
4. The user cannot withdraw their funds because the contract:
	•	Has no lockedTransfers record
	•	Has no claimRefund() or unlock() fallback
5. User funds are stuck permanently.


### Impact

The user suffers a complete loss of their deposited tokens.
If many users are affected or this is automated via bots, the protocol loses credibility and exposes itself to griefing.

_No response_

### Mitigation

Introduce an escrow lock system in depositAndCall():
lockedTransfers[externalId] = LockedTransfer({
    user: msg.sender,
    token: fromToken,
    amount: amount,
    refunded: false
});

And in onCall() or onRevert():
	•	Mark the transfer as complete or refunded.
	•	Add a claimRefund() function for users to reclaim locked funds on failure.
