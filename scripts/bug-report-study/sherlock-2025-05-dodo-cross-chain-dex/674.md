# ERC20 Non-Standard Return Value Compatibility (USDT Transfer Failure)

### Summary

The GatewaySend contract uses raw IERC20.transferFrom() calls wrapped in require() statements, which fail for tokens like USDT that don't return boolean values. This causes legitimate transfers to revert even when successful, making the contract incompatible with major tokens including USDT (one of the largest stablecoins by market cap). The contract already imports TransferHelper for safe transfers but uses it inconsistently.

### Root Cause

The contract assumes all ERC20 tokens follow the standard and return a boolean value from transferFrom(). However, many tokens (especially early implementations) have void return types:
```solidity
require(
    IERC20(asset).transferFrom(msg.sender, address(this), amount),
    "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
);
```
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L238C13-L241C15

When Solidity expects a boolean return but receives nothing, it interprets this as false, causing the require to fail regardless of actual transfer success.

NA

### External Pre-conditions

Token Compatibility: User attempts to use tokens with non-standard return values:

USDT (Tether): Most popular stablecoin, void return type
BNB: Binance native token, void return type

### Attack Path

1. Alice wants to bridge 10,000 USDT from Ethereum to other chain
2. Alice approves GatewaySend contract to spend 10,000 USDT
3. Alice calls depositAndCall() with USDT as the asset
4. Contract attempts: IERC20(USDT).transferFrom(alice, contract, 10000)
5. USDT transfer executes successfully (Alice's balance decreases, contract balance increases)
6. USDT's transferFrom returns nothing (void) instead of true
7. Solidity interprets void return as false
8. require() statement fails with "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
9. Transaction reverts despite successful token transfer
10. Alice loses gas fees and transaction fails

### Impact

This causes legitimate transfers to revert even when successful, making the contract incompatible with major tokens including USDT.

### PoC

_No response_

### Mitigation

Replace all instances of raw transferFrom calls with TransferHelper.safeTransferFrom.
