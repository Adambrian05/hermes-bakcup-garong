# `onAbort()` will never be invoked

### Summary

The issue is plain and simple, we have the struct `RevertOptions` that specifies several things, one of them is the `abortAddress`.

Since that in every place in which it is invoked, it is written that the abort address is the zero address, which is not correct as we have the `onAbort()` function declared specifically for that purpose.

This is broken functionality as the `onAbort()` will never be called, impacting the expected functionality of the protocol.

### Root Cause

The root cause is that this is in place `abortAddress: address(0)`, instead of having an actual address, such as `address(this)` for invoking the `onAbort()`

### Internal Pre-conditions

none

### External Pre-conditions

none

### Attack Path

1. User initiates a cross chain request such as a swap, expecting that in the case of abort, `onAbort()` will be called
2. Abort happens, but `onAbort()` is never called due to the root cause I've explained

### Impact

Broken functionality as the `onAbort()` will never be invoked.
