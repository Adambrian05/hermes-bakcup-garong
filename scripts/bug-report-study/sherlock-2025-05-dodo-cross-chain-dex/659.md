# Ineffective deadline in `GatewayCrossChain::_swapAndSendERC20Tokens`

### Summary

in [`GatewayCrossChain::_swapAndSendERC20Tokens`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L325) we can see that the deadline param has been set to `block.timestamp + MAX_DEADLINE` which offers no real protection because the deadline check of uniswap will always pass

### Root Cause

As we can see below the deadline whilst swapping is being set to `block.timestamp + MAX_DEADLINE`

```solidity
 uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
>                block.timestamp + MAX_DEADLINE
        );
```

which offers no real protection because deadline can never be reached.

The function call `IUniswapV2Router01(UniswapRouter).swapTokensForExactTokens` has a modifier which checks the deadline as we can see below

```solidity
    modifier ensure(uint deadline) {
        require(deadline >= block.timestamp, 'UniswapV2Router: EXPIRED');
        _;
    }

```
so from the modifier above we can see the require check will always pass

### Mitigation

Introduce a deadline function param
