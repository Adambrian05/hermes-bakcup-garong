# Unchecked ERC20 Transfer Return Value in `onCall`

__Summary:__ The `onCall` function does not check the boolean return value of the ERC20 `transfer` call when sending tokens to the recipient, which can lead to silent failures with non-standard tokens.

__Vulnerability Detail:__ When the target token (`toToken`) is an ERC20, `onCall` sends the tokens to the recipient using `IERC20(toToken).transfer(evmWalletAddress, outputAmount);`. The ERC20 standard specifies that the `transfer` function should return a boolean indicating success (`true`) or failure (`false`). However, some older or non-standard token implementations might return `false` on failure instead of reverting. The current code does not check this boolean return value.

__Impact:__ If the `IERC20(toToken).transfer` call fails and returns `false` (without reverting), the `GatewaySend` contract will not detect the failure. It will proceed as if the transfer was successful, potentially emitting the `EddyCrossChainReceive` event with incorrect information. This can lead to an inconsistent state within the contract and potentially confuse or mislead downstream systems that rely on the emitted events, especially when interacting with non-standard or potentially malicious ERC20 tokens.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L372

__Recommendation:__ Use the TransferHelper.safeTransfer function (already imported and used in onRevert) which correctly checks the boolean return value of ERC20 transfer and transferFrom calls and reverts on failure. Alternatively, manually check the return value: require(IERC20(toToken).transfer(evmWalletAddress, outputAmount), "ERC20 transfer failed");.
