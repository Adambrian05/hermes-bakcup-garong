# withdrawToNativeChain reverts transactions for Native ZETA users

### Summary

In the `withdrawToNativeChain` function, the `_handleFeeTransfer` function is responsible for transferring a fee deducted from the `fromToken`. The fromToken can be the native  address `(_ETH_ADDRESS_)`.

 `_handleFeeTransfer` uses `TransferHelper.safeTransfer` for all token transfers. This approach causes transactions to revert when `zrc20` is set to `_ETH_ADDRESS_`





### Root Cause

The [`_handleFeeTransfer`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341) function uses `TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx)` to transfer the calculated platform fee. This function assumes zrc20 is always set to a token and attempts to call the transfer function on it.

 However in [withdrawToNativeChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530)  `zrc20` parameter can be  ` _ETH_ADDRESS_`
```solidity
        if(zrc20 != _ETH_ADDRESS_) {
            require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
        } 
```
 `msg.value` can be  passed for Swaps in `_doMixSwap`.

 The fee transfer logic in `_handleFeeTransfer` does not account for this distinction and incorrectly uses `safeTransfer` for all tokens including native token while `TransferHelper` provides a `safeTransferETH` that can be used for Native token transfers.

 All calls with `zrc20=_ETH_ADDRESS_` fails because `_ETH_ADDRESS_` is not a contract and does not implement the `transfer` function.






### Internal Pre-conditions

1. A user needs to call `withdrawToNativeChain` to set `zrc20` to be exactly `_ETH_ADDRESS_` with `msg.value` equal to `amount`.

2. The contract needs to have `feePercent` set to be greater than `0`



### External Pre-conditions

None

### Attack Path

1. User calls `withdrawToNativeChain` with `zrc20 = _ETH_ADDRESS_,`  and `msg.value` = `amount`
2. The function calculates `platformFeesForTx` = `(amount * feePercent) / 1000`
3. The `_handleFeeTransfer` function calls `TransferHelper.safeTransfer(_ETH_ADDRESS_, EddyTreasurySafe, platformFeesForTx)`
4. safeTransfer attempts to call `transfer` on `_ETH_ADDRESS_` which is not a contract causing the transaction to revert.









### Impact

Users cannot execute transactions with `_ETH_ADDRESS_` as the `fromToken` in `withdrawToNativeChain` due to transaction reverts.

_No response_

### Mitigation

use `safeTransferETH` for ETH transfers in `_handleFeeTransfer `
