# transfer()/transferFrom() will not work with some of the tokens

### Summary

The GatewaySend contract directly uses ERC20.transfer and ERC20.transferFrom, which can fail when interacting with non-standard ERC20 tokens, such as USDT on Ethereum. These tokens do not return a boolean value on transfer operations, leading to potential reverts and making them incompatible with the current implementation.




### Root Cause

In certain instances within the GatewaySend contract, there are ERC20.transfer/transferFrom calls. For tokens that do not implement correctly the EIP20 standard, these calls could fail, such as USDT (which does not return a boolean on transfers) on Ethereum.

### Attack Path

1. User calls depositAndCall in gatewaySend contract with the asset set as USDT token
2. Since the asset is not Native token the function tries to call transferFrom to transfer token amount to the gatewaySend
3. Since the USDT is asset and since the USDT doesn't return the bool on transfer the transferFrom call fill fail
4. This means that the USDT and tokens like USDT will be unusable by gatewaySend where the functions transfer/transferFrom are used

### Impact

Tokens like USDT on Ethereum will be unusable since they revert to not implementing correctly the EIP20 standard (due to the missing bool return value)
