# Over-Approval in Withdrawal Functions

### Summary

The `_handleBitcoinWithdraw` and `__handleEvmOrSolanaWithdraw` function in `GatewayTransferNative.sol` approves more tokens than are actually consumed by the `Gateway` contract during a Bitcoin withdrawal. This results in persistent **unused allowance**, which could be exploited if the gateway contract is ever compromised or maliciously upgraded.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L451-L465

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L467-L484

### Root Cause

In `GatewayTransferNative.sol:451-465` and `GatewayTransferNative:467-484`, the `_handleBitcoinWithdraw` and `_handleEvmOrSolanaWithdraw` functions approves `outputAmount + gasFee` tokens to the `Gateway`, but the `Gateway` only ever consumes `outputAmount` tokens:

- `gasFee` is transferred to the protocol address via `gasZRC20.transferFrom(...)`
- `outputAmount - gasFee` is transferred to the gateway for burning

Thus, the gateway is **over-approved** by `gasFee` tokens.

### Internal Pre-conditions

1. User needs to call `withdrawToNativeChain()` to set destination chain to be Bitcoin (chain ID 8332)
2. User needs to call `withdrawToNativeChain()` to set destination chain to be EVM/Solana with `decoded.targetZRC20 == gasZRC20`
3. The `outputAmount` needs to be greater than `gasFee` to pass the revert check

### External Pre-conditions

- No external input is needed beyond the standard withdrawal call.


### Attack Path

1. User calls `withdrawToNativeChain()` targeting Bitcoin or EVM/Solana (same token scenario)
2. Contract approves `outputAmount + gasFee` tokens to Gateway contract
3. Gateway only consumes required amount, leaving `gasFee` as unused allowance
4. If Gateway contract becomes compromised or maliciously upgraded, attacker can exploit the unused allowance
5. Attacker drains the unused allowance equal to `gasFee` amount per affected withdrawal

### Impact

The protocol suffers potential security exposure equal to the gas fee amount for each affected withdrawal. While no immediate loss occurs, this creates unnecessary attack surface.


### PoC

_No response_

### Mitigation

Approve only the actual amount the `Gateway` consumes
