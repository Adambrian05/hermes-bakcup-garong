# Predictable External ID Generation Could Enable Fund Collision Across Chains During Cross-Chain Reverts

### Summary

The _calcExternalId() function generates unique identifiers for cross-chain refund operations using:

```solidity
keccak256(abi.encodePacked(address(this), sender, globalNonce, block.timestamp))
This means uniqueness relies on:
```

Contract address (address(this))
Sender (msg.sender)
Nonce (incremented per call)
Timestamp (block.timestamp)
However, if:

Two transactions are initiated by the same user
On two different chains
Using identically deployed GatewaySend contracts (same address on both chains)
With matching nonces
And landing in blocks with the same timestamp
Then it becomes possible for both flows to generate the same externalId .

if both transactions fail and fall back to onAbort(), one refund will overwrite the other — causing permanent fund loss .

### Root Cause

In the GatewayCrossChain and GatewayTransferNative contracts on ZEVM, refundable operations are tracked via:

```solidity
mapping(bytes32 => RefundInfo) public refundInfos;
Where externalId is computed in _calcExternalId():
```

```solidity
function _calcExternalId(address sender) internal view returns (bytes32) {
    return keccak256(
        abi.encodePacked(
            address(this),
            sender,
            globalNonce,
            block.timestamp
        )
    );
}
```
This logic assumes that the combination of inputs ensures uniqueness , but in reality:

the gatewaysend contracts could be deployed at the same address across multiple chains especially if the deployer address has the same nance across multiple chains or the deployment is done with create2 
Users may send cross-chain transactions from the same wallet .
The globalNonce is incremented independently per chain, but can be matched with timing control or spamming.
Timestamps often match or are very close between chains.
Thus, collision becomes entirely plausible .

 Transaction 2: BSC → ZEVM
Alice calls depositAndCall() on GatewaySendBSC (BSC).
Swap also fails on ZEVM → triggers onRevert() on BSC.
onRevert() also fails.
System falls back to calling onAbort() on ZEVM.



Refund info overwrites the previous one.



### Impact

the funds form the overriden are permanently lost

### Mitigation

add a chain specific identifier 


```solidity
function _calcExternalId(address sender) internal view returns (bytes32 externalId) {
    externalId = keccak256(
        abi.encodePacked(
            address(this),
            sender,
            globalNonce,
            block.timestamp,
            block.chainid 
        )
    );
}
```
