# GatewayTransferNative.sol -- `_existsPairPool()` does not verify contract existence

### Summary

In `GatewayCrossChain.sol`, the `_existsPairPool()` function https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L220 incorrectly assumes that non-zero token balances at a computed Uniswap pair address imply the existence of a deployed contract. This check is unreliable — any address can receive tokens, including EOAs or non-deployed addresses — causing the function to return true even when the pair contract doesn't exist. As a result, `getPathForTokens()` may construct invalid swap paths, leading to downstream reverts and potential denial of service.

### Root Cause

In `GatewayTransferNative.sol`, the` _existsPairPool()` function determines the existence of a UniswapV2 pair by checking token balances at the derived address. However, this is insufficient — balances can exist even at addresses with no deployed contract.

### Internal Pre-conditions

1. The function getPathForTokens() calls _existsPairPool().

2. A malicious or accidental transfer of tokens to a random EOA mimicking a pair address occurs.

### External Pre-conditions

1. Tokens are transferred to a non-pair EOA or uninitialized contract address.

2. That address now has non-zero balances.

### Attack Path

1.  _existsPairPool() returns true for a non-existent pair.

2.  getPathForTokens() constructs a 2-token swap path based on this.

3. Swaps relying on this path revert at runtime.

### Impact

Denial of service to users attempting token swaps via invalid Uniswap paths, causing transaction reverts.
