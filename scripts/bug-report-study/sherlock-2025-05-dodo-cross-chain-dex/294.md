# User's fund will be lost because of lack of check about receiver address

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L613
users' funds can be lost becuase there is no check about length of the receiver address

### Root Cause
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L613
there is no check about receiver address that it is a valid address or not

### Internal Pre-conditions

no need

### External Pre-conditions

no need

### Attack Path

1. Attacker provides: `decoded.receiver = hex"1234"`
2. The cast becomes: `bytes20(decoded.receiver) = 0x0000000000000000000000000000000000001234`
3. The final receiver: `address(receiver) = 0x0000000000000000000000000000000000001234`
4. Contract sends ETH or ZRC20 to that unintended address.

### Impact

Users's funds can be lost by attacker an passing wrong address

### PoC

no need

### Mitigation

check about an address of the receiver must be added
````solidity
require(decoded.receiver.length == 20, "Invalid receiver address length");
address receiver = address(uint160(bytes20(decoded.receiver)));
```
