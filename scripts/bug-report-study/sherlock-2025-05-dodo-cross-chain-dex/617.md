# Theft of funds in `GatewayTransferNative` contract

### Summary

Missing validation on message payload can cause pending claim funds in the contract to be stolen

### Root Cause

The function [`withdrawToNativeChain()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530) allows user to swap tokens from Zetachain to connected chains, in which the swap with DODO is optional on Zetachain. In such case, the returned `outputAmount` is the `amount` passed from calldata
```solidity
    function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
@>        if (swapData.length == 0) { // <<<<<<<<<<<<< skip swap
            return amount;
        }
        ...
    }
```

Besides, the function also does not validate token information `zrc20` with the information in decoded message, such that the value `decoded.targetZRC20`. By this, the user can send a `zrc20` token address different than the actual token to be withdrawn from Zetachain `decoded.targetZRC20`

In the mean time, the contract also holds funds which is the pending claim funds for the failed cross chain swaps.

So, an attacker can prepare a malicious payload `message` and spend arbitrary `zrc20` token amounts to initiate a call to Zetachain gateway to withdraw funds, effectively stealing pending claim funds. 

### Internal Pre-conditions

NA

### External Pre-conditions

NA

### Attack Path

1. There are failed cross chain swaps so the contract is now holding pending funds
2. An attacker prepares message payload with:
- `swapDataZ` length = 0 -> Do not swap with DODO on Zetachain
- `targetZRC20` is wanted token address to steal
- `receiver` address is his controlled address
- Arbitrary `amount` and `zrc20` arguments
3. Call `withdrawToNativeChain()` to steal funds


### Impact

- Pending claim funds are stolen
- Funds held by the contract can also be stolen

### PoC

_No response_

### Mitigation

Validate the calldata `zrc20` and `amount` against data extracted from `message`
