# Improper handling of USDT `transferFrom` return value

### Summary

[USDT](https://etherscan.io/token/0xdac17f958d2ee523a2206206994597c13d831ec7) token does not comply with standard ERC20 token resulting in failure of transactions. This will cause a DoS for users trying to bridge/swap USDT for other tokens.

### Root Cause

The IERC20 interface used for funds transfer in [`GatewaySend.depositAndCall(...)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L238-L241) expects a boolean value which the USDT token contract does not return. 

### Internal Pre-conditions

1. The protocol uses the standard `IERC20` interface for interacting with tokens, including USDT.
2. Functions involving `USDT` use `transferFrom` without checking for non-standard behavior.
3. The contract logic assumes these functions return a bool value.

### External Pre-conditions

1. A user or contract triggers `GatewaySend.depositAndCall(...)` to perform a swap/bridge.
2. USDT transfer fails as the contract is expecting a boolean.

### Attack Path

NA

### Impact

Users are not able to swap/bridge USDT.
