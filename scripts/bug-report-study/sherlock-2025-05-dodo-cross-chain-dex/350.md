# GatewaySend.onRevert() function fails to handle native ETH refunds, User Funds Permanently Locked in GatewaySend

### Summary

The GatewaySend.onRevert() function fails to handle native ETH refunds. If a cross-chain transaction involving ETH fails on the ZetaChain side, and a refund is initiated via executeRevert(), the ETH is sent back to the GatewaySend contract. However, onRevert() only supports ERC20-based refunds and does not correctly forward ETH back to the original sender. This results in permanent loss of funds, as the ETH becomes stuck in the contract with no withdrawal path

```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
      //@audit - ETH transfers doesn't happen because it considers only token transfers not native ETH
        TransferHelper.safeTransfer(context.asset, sender, context.amount);

        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```

This issue has been confirmed as a valid bug by the protocol team through the private Discord support channel

### Root Cause

The onRevert() function assumes all assets are ERC20 tokens and does not include logic to handle native ETH.

ETH is sent to the `GatewaySend.sol` contract via `gateway.executeRevert()` by TSS but never forwarded to the original user from `GatewaySend.sol` contract

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393

### Internal Pre-conditions

NA

### External Pre-conditions

onCall() in ZetaCrosschain must revert/fail during execution

### Attack Path

1. User calls `GatewaySend.depositAndCall()` and sends 100 ETH.
2. The call fails on ZetaChain during onCall().
3. The 100 ETH now needs to be refunded to the user.
4. ZetaChain TSS detects the failure and calls executeRevert() on the Ethereum gateway.
5. executeRevert() forwards 100 ETH to the GatewaySend contract and invokes onRevert() with _ETHADDRESS and the ETH amount.
6. `GatewaySend.onRevert()` does not support native ETH transfers — it only handles ERC20 tokens — so it fails
7. The 100 ETH remains stuck in the GatewaySend contract and will never be sent to the user

### Impact

High severity: Users can permanently lose ETH in `failed` cross-chain transfers.

### Mitigation

Update onRevert() to check if the asset is _ETH_ADDRESS_, and if so, refund ETH directly using:

```diff
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
+        if(context.asset == _ETH_ADDRESS_)
+        {
+             TransferHelper.safeTransferETH(sender, context.amount);
+      }
+        else {
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
      }
       
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```
