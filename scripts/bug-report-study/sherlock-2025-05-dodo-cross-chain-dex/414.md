# ETH Cannot Be Used as `fromToken` Due to `approve` Call

### Summary

In the `GatewayTransferNative`, the `_doMixSwap` function blindly calls `approve `on `params.fromToken`, which is not valid if `fromToken` is the native token (i.e 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE). As a result, using ETH as a source token is disabled in `withdrawToNativeChain`.

### Root Cause

Calling `approve `on `params.fromToken` without checking if it is the native ETH address disables ETH usage, since ETH does not support the ERC-20 `approve` method.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L434

### Attack Path

User supplies `_ETH_ADDRESS_` as `fromToken`.
`_doMixSwap` attempts `approve `on `_ETH_ADDRESS_` address, which reverts.
`ETH` is not processed, breaking the swap logic.

### Impact

**Loss of functionality**: ETH as `fromToken` which should also be passed `zrc20` is permanently disabled for `withdrawToNativeChain`.
