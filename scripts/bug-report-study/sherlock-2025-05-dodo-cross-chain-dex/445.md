# ETH Amount Handling Inconsistency

### Summary

The second `depositAndCall` function forwards the entire `msg.value` to ZetaChain's gateway instead of the specified amount parameter when handling ETH transfers.

[Link to code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L307-L315).

Code with issue:
```solidity
function depositAndCall(
    address targetContract,
    uint256 amount,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // ...
    if (isETH) {
        require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
        _handleETHDeposit(
            targetContract, 
            msg.value, // Issue: Using msg.value instead of amount
            message, 
            revertOptions
        );
    }
    // ...
}
```

### Root Cause

When users call the second `depositAndCall` function with ETH as the asset, the contract checks if `msg.value >= amount` but then passes the entire msg.value to the _handleETHDeposit function. This inconsistency could lead to users unintentionally sending more ETH than they intended for the cross-chain transaction.

The contract validates that the user has sent enough ETH to cover the specified amount, but it does not ensure that only the specified amount is used for the cross-chain transfer. Users might send excess ETH expecting it to remain in their balance, but the entire amount will be forwarded to the ZetaChain gateway.

### Attack Path

1. User calls `depositAndCall` with amount = 1 ETH but sends msg.value = 1.5 ETH
2. The function checks `msg.value >= amount`, which passes
3. The function then calls `_handleETHDeposit` with msg.value (1.5 ETH) instead of amount (1 ETH)
4. The entire 1.5 ETH gets forwarded to the ZetaChain gateway, not just the 1 ETH specified by the user

### Impact

Impact: High - Users will lose more funds than they intended to use for the transaction.

Likelihood: High - This will occur every time a user sends more ETH than the specified amount parameter.

### Mitigation

Replace `msg.value` with amount when calling `_handleETHDeposit`:
```solidity
function depositAndCall(
    address targetContract,
    uint256 amount,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // ...existing code...
    if (isETH) {
        require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
        _handleETHDeposit(
            targetContract, 
            amount,  // Fixed: Using amount instead of msg.value
            message, 
            revertOptions
        );
    }
    // ...existing code...
}
```
