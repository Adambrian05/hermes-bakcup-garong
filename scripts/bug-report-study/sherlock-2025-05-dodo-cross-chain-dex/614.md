# Incompatibility of `ERC20::transferFrom` function with USDT tokens on Ethereum Mainnet chain

## Summary

The `ERC-20` standard specifies that `transfer` and `transferFrom` should return a bool indicating success. However, some widely-used tokens such as `USDT` omit the return value. When interacting with such tokens using high-level Solidity calls (`IERC20(token).transferFrom`), the EVM expects a return value. If none is returned, decoding fails and the transaction reverts.

## Root Cause

The [`GatewaySend::depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L218-L318) functions and [`GatewaySend::onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L359) function use the `IERC20::transferFrom` and `IERC20::transfer` functions to transfer a given amount of asset/token from the caller to the contract and from the contract to the given address:

According to the [`README`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/README.md#q-on-what-chains-are-the-smart-contracts-going-to-be-deployed) the contract will be deployed on Ethereum Mainnet chain and will use [USDT](https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets) tokens.

The problem is that the `ERC20` interface expects the `transferFrom` and `transfer` functions to return a boolean value, but `USDT` token on Ethereum dosn't have a return value. This means the transfer of the tokens from the users to the contract and from the contract to a given wallet address will always revert.


## Impact

Users are unable to use properly important functions of the protocol: `GatewaySend::depositAndCall` functions and `GatewaySend::onCall` function with USDT token on Ethereum mainnet chain, these functions will always revert due to the use of `IERC20::transferFrom` and `IERC20::transfer` functions. USDT is one of the tokens that the protocol will use, therefore the failure to handle its non-boolean transfer return is a critical issue due to breaking core functionality for a supported token.

## PoC

The following test shows that the call of `transferFrom` function to the USDT token contract reverts on Ethereum mainnet chain. For simplicity, I created a new test file and directly called the function:

```solidity

contract TransferFromTest is StdInvariant, Test {
    IERC20 public assetUsdtETH;
    address public usdtETH = 0xdAC17F958D2ee523a2206206994597C13D831ec7;
    uint256 ethFork;
    string ETH_RPC_URL = vm.envString("ETH_RPC_URL");
    
    function testTransferFromMainnet() public{
        address user = address(0x123);
        ethFork = vm.createFork(ETH_RPC_URL);
        vm.selectFork(ethFork);
        assetUsdtETH = IERC20(usdtETH);
        
        deal(address(assetUsdtETH), user, 100*10**6, true);

        vm.startPrank(user);
        assetUsdtETH.transferFrom(address(user), address(0x444), 10*10**6);
    }
}

```

## Mitigation

Use OpenZeppelin's `SafeERC20` library or use `TransferHelper::safeTransferFrom/safeTransfer` instead of `IERC20::transferFrom/transfer` function.
