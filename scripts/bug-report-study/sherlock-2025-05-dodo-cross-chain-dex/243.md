# Incorrect fee transfer method for native ETH in `GatewayTransferNative::_handleFeeTransfer` leads to failed withdrawals

### Summary

Improper handling of native ETH in `_handleFeeTransfer` will cause fee transfer failures for users as the contract will attempt to call `safeTransfer` on ETH (a non-ERC20 asset), leading to transaction reverts during withdrawals.

### Root Cause

In [`GatewayTransferNative.sol:_handleFeeTransfer`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341-L347) function is called by `withdrawToNativeChain`, which allows the asset to be ETH (`zrc20 == _ETH_ADDRESS_`). However, `_handleFeeTransfer` unconditionally uses `safeTransfer`, which is intended for ERC-20 tokens. This will cause ETH withdrawals to revert, as native ETH must be sent using `safeTransferETH` instead.

### Internal Pre-conditions

1. Caller needs to invoke `withdrawToNativeChain()` with zrc20 set to `_ETH_ADDRESS_`
2. `withdrawToNativeChain()` must successfully pass preliminary checks and reach the `_handleFeeTransfer()` call
3. The contract must attempt to send ETH as a fee via `_handleFeeTransfer()` using `safeTransfer`, which is incompatible with native ETH transfers

### External Pre-conditions

1. The `withdrawToNativeChain` function is payable, allowing native ETH to be sent with the call.
2. The external environment expects native ETH transfers (not ERC20 token transfers) when `zrc20 == _ETH_ADDRESS_`.

### Attack Path

1. User calls `withdrawToNativeChain` with `zrc20` set to `_ETH_ADDRESS_` and sends ETH along with the call (because the function is payable).
2. Inside `withdrawToNativeChain`, the contract calls `_handleFeeTransfer`.
3. `_handleFeeTransfer` incorrectly calls `safeTransfer` (ERC20 transfer) instead of `safeTransferETH` (native ETH transfer) when `zrc20 == _ETH_ADDRESS_`.
4. This mismatch causes the fee transfer to fail, potentially locking ETH or reverting the transaction unexpectedly.

### Impact

The users cannot successfully withdraw ETH when calling `withdrawToNativeChain` because the fee transfer fails due to using `safeTransfer` instead of `safeTransferETH`. This causes withdrawal transactions to revert, effectively blocking withdrawals of native ETH.

### PoC

_No response_

### Mitigation

Update the `_handleFeeTransfer` function to detect when the asset is native ETH (i.e., when `zrc20 == _ETH_ADDRESS_`) and call `safeTransferETH` instead of `safeTransfer`.
