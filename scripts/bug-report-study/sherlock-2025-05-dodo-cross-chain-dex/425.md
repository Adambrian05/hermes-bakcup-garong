# An attacker will cause transaction reverts for users by spoofing Uniswap V2 pool existence

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L501C30-L501C31

The flawed logic in the `getTokenPath()` function will cause persistent transaction reverts for users as an attacker will spoof Uniswap V2 pool existence by sending tokens to computed pair addresses without deploying pool contracts.
```solidity
     function _existsPairPool(
        address uniswapV2Factory,
        address zrc20A,
        address zrc20B
    ) internal view returns (bool) {
        address uniswapPool = uniswapv2PairFor(
            uniswapV2Factory,
            zrc20A,
            zrc20B
        );
        return
            IZRC20(zrc20A).balanceOf(uniswapPool) > 0 &&
            IZRC20(zrc20B).balanceOf(uniswapPool) > 0;
    }

    function getPathForTokens(
        address zrc20,
        address targetZRC20
    ) internal view returns(address[] memory path) {
        bool existsPairPool = _existsPairPool(
            UniswapFactory,
            zrc20,
            targetZRC20
        );

        if (existsPairPool) {
            path = new address[](2);
            path[0] = zrc20;
            path[1] = targetZRC20;
        } else {
            path = new address[](3);
            path[0] = zrc20;
            path[1] = WZETA;
            path[2] = targetZRC20;
        }
    }

```

### Root Cause

In `GatewayTransferNative.sol:getTokenPath()`, the existence of a Uniswap V2 pool is inferred solely by checking whether the token balances at a computed pair address are greater than zero. This is flawed because it does not verify whether contract code is deployed at that address.



### Internal Pre-conditions

1. The user must attempt a cross-chain withdrawal involving an ZRC20 token that requires a swap of the ZRC20 token to gas ZRC20 token.  
2. The direct  pool for  ZRC20 token to gas ZRC20 token must not exist  .  


### External Pre-conditions

n/p

### Attack Path

1. The attacker selects two valid zRC20 tokens, `tokenA` and `tokenB`.  
2. The attacker computes the Uniswap V2 pair address using `create2` logic.  
3. The attacker transfers a minimal amount(1 wei) of both tokens to that address.  
4. The user initiates a withdrawal that requires a token swap.  
5. The contract, using `getTokenPath()`, checks the spoofed address, sees a non-zero balance, and assumes the pool exists.  
6. The swap logic attempts to interact with the non-existent pool contract and reverts.  
7. The withdrawal fails, denying service to the user.


### Impact

The users cannot complete withdrawals involving ERC20 swaps. This causes a denial of service. The attacker gains no financial profit but can block users from withdrawing, effectively griefing the protocol and degrading user experience.

### Mitigation

Update getTokenPath() to verify that code is deployed at the computed pair address. This can be done using:
```solidity
if (pair.code.length > 0) {
    // Safe to assume pool exists
}
```
