# Public withdraw function allows unauthorized fund extraction

### Summary

The `withdraw` function in `GatewayTransferNative` is incorrectly declared as `public`, allowing any external actor to call it with arbitrary parameters. This function directly interacts with the ZetaChain Gateway to initiate cross-chain withdrawals without any access control.

### Root Cause

The vulnerability stems from an [incorrect visibility modifier](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L291) on the `withdraw` function:

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}
```

The function was intended to be called only by other internal contract functions (such as `_handleBitcoinWithdraw`) but is exposed to external callers due to the public visibility.

### Attack Path

1. Attacker calls the public function directly
2. The function executes without validation
3. ZetaChain Gateway processes the withdrawal request
4. Tokens are transferred from contract to attacker's address on the destination chain

### Impact

All tokens held by the contract can be stolen.

### PoC

_No response_

### Mitigation

Restrict access to the `withdraw` function by changing its visibility from `public` to `internal`.
