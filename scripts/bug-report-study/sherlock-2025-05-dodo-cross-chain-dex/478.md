# Token Drain via Unrestricted Withdrawals and Over-Approval

### Summary

Over-approval of tokens combined with missing access control will cause complete fund drainage for the protocol as any attacker will directly exploit accumulated unused allowances through the public withdraw function.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L451-L477

### Root Cause

In `GatewayTransferNative.sol:451-477`, the contract over-approves tokens by `gasFee` amount that remains unused, while `GatewayTransferNative.sol:286-304` has a public withdraw function without access control that allows direct exploitation of these accumulated allowances.


### Internal Pre-conditions

1. Users need to perform Bitcoin or EVM withdrawals to accumulate unused token allowances
2. Contract needs to hold approved tokens from previous withdrawal operations

### External Pre-conditions

None

### Attack Path

1. Legitimate users call `withdrawToNativeChain()` targeting Bitcoin or EVM chains
2. Each withdrawal leaves `gasFee` amount of unused allowance to Gateway contract
3. Attacker identifies accumulated allowances and calls public `withdraw()` function
4. Gateway processes withdrawal using accumulated allowances and sends tokens to attacker's address
5. Attacker repeats for all tokens with accumulated allowances


### Impact

The protocol suffers complete loss of all accumulated over-approved tokens. The attacker gains all drained tokens with minimal effort.


### PoC

_No response_

### Mitigation

Make withdraw function internal and approve only the actual amount consumed by Gateway
