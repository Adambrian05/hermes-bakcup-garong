# Users will lose fund when deposit on ETH reverts

### Summary

In `onRevert()` of `GatewaySend.sol`, it doesn't handle the revert of ETH deposit properly, therefore users will lose fund when the deposit on ETH reverts.

### Root Cause

At `GatewaySend.sol->depositAndCall()`, the user can deposit ETH.

When it reverts, the `onRevert()` of `GatewaySend.sol` will be called from gateway.
But at `GatewaySend.sol:396`, it doesn't handle the revert on ETH deposit properly.

`TransferHelper.safeTransfer` will fail for ETH.

```solidity
  address sender = address(uint160(bytes20(context.revertMessage[32:])));
  TransferHelper.safeTransfer(context.asset, sender, context.amount); // @audit; when context.asset is ETH, this won't work
```

### Attack Path

1. User calls `depositAndCall()` for ETH at `GatewaySend.sol`.
2. It reverts and the gateway calls `onRevert()`.
3. The revert will fail as the asset is ETH.

### Impact

Users will lose fund when the deposit on ETH reverts.
