# withdraw function is public

### Summary

in `GatewayTransferNative` has a public visibility and will allow anyone to steal all the tokens that are left in the contract at no cost.

### Root Cause

1. Wrong access control, making the `withdraw` function public and callable by anyone:

[[GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304)

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {//<----
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}
```

1. `_handleEvmOrSolanaWithdraw` gives excess approval to the Gateway, which is not being exhausted. The approval is for `outputAmount + gasFee`, but in reality only `outputAmount` will be used by the `gateway`, because `outputAmount - gasFee` is forwarded to `withdrawAndCall`. If we add numbers, let’s say `outputAmount` = 100, `gasFee` = 10, gateway is approved for 110, but 90 is passed as an argument. 
Gateway will take and burn the 90 tokens and will recalculate the 10 tokens gas fee and take them as well, totaling to 100 tokens and leftover approval of 10 tokens.

[[GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L467-L528)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L467-L528)

```solidity
function _handleEvmOrSolanaWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    bytes memory receiver
) internal returns (uint256 amountsOutTarget) {
    (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);

    if (decoded.targetZRC20 == gasZRC20) {
        if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

        bytes memory data = SwapDataHelperLib.buildOutputMessage(
            externalId, 
            outputAmount - gasFee, 
            decoded.receiver, 
            decoded.swapDataB
        );
        
        bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
            ? AccountEncoder.encodeInput(AccountEncoder.decompressAccounts(decoded.accounts), data)
            : data;

        withdrawAndCall(
            externalId, 
            decoded.contractAddress, 
            decoded.targetZRC20, 
            outputAmount - gasFee, 
            receiver, 
            encoded
        );

        amountsOutTarget = outputAmount - gasFee;
    } 
```

### Internal Pre-conditions

- `GatewayTransferNative` to have non-zero balance for the chosen token.
- Token, that the attacker will steal to be a valid `gasZRC20`.
- [`[ISystem(SYSTEM_CONTRACT_ADDRESS).gasPriceByChainId(CHAIN_ID);](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/zevm/ZRC20.sol#L267)`](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/zevm/ZRC20.sol#L267) of the `ZRC20` token to decrease. This is possible, because gas pricing of the chains is dynamic and [[Zeta constantly monitors the changes and pushes new updates](https://github.com/zeta-chain/node/blob/7e707805e142bb43f9781b8566fcdb6da56e4405/x/crosschain/keeper/abci.go#L144-L206)](https://github.com/zeta-chain/node/blob/7e707805e142bb43f9781b8566fcdb6da56e4405/x/crosschain/keeper/abci.go#L144-L206).

### External Pre-conditions

None

### Attack Path

1. Internal pre-conditions are satisfied.
2. The attacker don’t need to sent tokens before that, just need to wait the `gasFee` of the `targetToken` to drop and the old approved gas to be more and he will steal the difference, if the difference is balance in the `GatewayTransferNative`.
3. He can give his own target contract that way will fail 100% and he will get the tokens on dest chain. As there is no validation inside withdraw.
4. Even if there is validation, he can trigger the `onRevert` on `GatewayTransferNative` and the tokens will be transferred to him again as a refund, but he wasn’t the one supplying them.
5. He can spam this unlimited times and steal all token balances that have been transferred by mistake or are left by the Dodo Mix swap, if the exact output swap is being used, where it has to give exact amount tokens out to the user for minimum token in amount. That will leave the excess tokens in the `GatewayTransferNative`.

### Impact

Stolen funds when attacker steal the residue tokens.

N/A

### Mitigation

Make the `withdraw` function internal and  `+ gasFee` in all approves.
