# Improper Uniswap pair existence check may incorrectly assume pool presence, leading to DoS

### Summary

The `_existsPairPool()` function in `GatewayCrossChain.sol` assumes a Uniswap pool exists if both tokens have a non-zero balance at the computed pool address. However, it does not verify that the address contains contract code. This can result in false positives when EOAs or empty contracts hold tokens. As a result, `getPathForTokens()` may incorrectly select a direct path between tokens, skipping the fallback through `WZETA`, which leads to downstream transaction reverts when trying to interact with a non-existent pool.

### Root Cause

In `GatewayCrossChain.sol`, https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L220 the `_existsPairPool()` function determines if a UniswapV2 pool exists based on token balances at the computed pair address. However, it does not verify whether a contract is actually deployed at that address. This results in `getPathForTokens()` https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L222-L242  potentially returning a direct path to a non-existent pool.

### Internal Pre-conditions

1. zrc20 and targetZRC20 must be a pair with some balance at the computed pair address, even if no contract exists there.

2. getPathForTokens() must be called with those tokens, and the pool must not have been deployed yet.

3. The returned path must be used in a downstream swap operation (e.g. DEX call) that expects a valid pool contract.

### External Pre-conditions

1. UniswapV2-style factory must not have created the pair pool yet.

2. Another contract may have accidentally or intentionally transferred tokens to the computed pair address (leading to false positive).

### Attack Path

1. Attacker front-loads `zrc20` and `targetZRC20` tokens into a non-existent computed pair address.

2. User or protocol calls `getPathForTokens()` which assumes the pool exists.

3. Path `[zrc20, targetZRC20]` is returned instead of fallback path.

4. Downstream swap operation (e.g. `uniswapV2Router.swapExactTokensForTokens`) is attempted.

5. Revert occurs due to missing contract at computed pair address → causes denial of service.

### Impact

The protocol or user cannot perform swaps using the returned path in `getPathForTokens()` if no contract exists at the computed pair address. This causes unnecessary transaction failures and can be exploited to force reverts (griefing).
