# Untrusted caller will hijack refund claims

### Summary

The use of msg.sender to determine the rightful refund recipient will cause unauthorized token claims for users as any caller can impersonate the recipient or exploit bots[msg.sender] to extract funds from the refund pool.

### Root Cause

In GatewayTransferNative.sol:578, the claimRefund() function infers the rightful refund recipient using:
if (refundInfo.walletAddress.length == 20) {
    receiver = address(uint160(bytes20(refundInfo.walletAddress)));
}
require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");

This allows any msg.sender that is whitelisted as a bot — or can spoof the walletAddress — to illegitimately claim tokens.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L681


### Internal Pre-conditions

1. [A refund is created] and stored in refundInfos[externalId]
2. [refundInfo.walletAddress] is a 20-byte field (i.e., an EVM-compatible address)
3. [Attacker becomes a bot or intercepts externalId]
4. [Attacker calls] claimRefund() using spoofed or matching refund input

### External Pre-conditions

1. [Bots are managed manually] via setBot() and assumed to be trustworthy
2. [EOAs or refund processors] interact off-chain to manage refunds

### Attack Path

1. Refund is created with walletAddress = bytes20(victim)
2. Attacker calls setBot(attacker, true) (if owner role is compromised or misused)
3. Attacker calls claimRefund(externalId)
4. Protocol transfers refundInfo.token to attacker, not intended recipient

### Impact

The user suffers loss of refunded tokens. The attacker receives tokens meant for another party. If repeated across multiple refunds, this becomes a systemic refund drain.

_No response_

### Mitigation

• Require refund claims to include a cryptographic signature or Merkle proof bound to recipient
• Disallow bot claims on walletAddress-based refund
• Enforce refund recipient via direct matching with walletAddress and disallow msg.sender impersonation
