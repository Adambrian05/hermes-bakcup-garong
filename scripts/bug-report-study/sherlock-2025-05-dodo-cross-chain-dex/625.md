# Users will permanently lose overpaid ETH in deposit/withdraw operations

### Summary

The absence of native token refund mechanisms will cause permanent fund loss for users as both gateway contracts retain excess ETH sent during transactions, violating standard DeFi refund conventions and creating hidden traps for overpayments.

### Root Cause

In `GatewaySend.sol:202-204` and `GatewayTransferNative.sol:408`, the choice to omit ETH refund logic is a mistake as it fails to return surplus native tokens after transaction processing, contrary to established DeFi patterns like Uniswap's exact output handling.

### Internal Pre-conditions

- User must send ETH exceeding required amount by ≥1 wei
- Transaction must execute successfully (failed tx would refund)
- Contract must have no withdrawal mechanism for trapped ETH
- Owner must not manually return funds

### External Pre-conditions

- Network must have ≥50 gwei gas prices (increases overpayment likelihood)

### Attack Path

- User intends to swap 1 ETH via GatewaySend
- Wallet miscalculates 5% slippage buffer as 1.05 ETH instead of 1.00 ETH
- User sends 1.05 ETH to `depositAndCall{value: 1.05 ether}()`
- Contract uses 1.00 ETH for swap, leaves 0.05 ETH in balance
- User receives no refund and cannot recover trapped ETH

### Impact

Users suffer 100% loss of overpaid ETH (average: 0.05-0.5 ETH per tx). Protocol permanently locks funds

Implement refund logic in both contracts
