# Double Slippage Calculation Leading to Excessive Token Consumption

## Description
There is a slippage calculation error in the `_swapAndSendERC20Tokens` function in the `GatewayCrossChain` contract. The function double counts the slippage tolerance, causing users to pay more input tokens than they should to get the desired amount of gas tokens.

The issue occurs because the contract adds an additional slippage tolerance on top of the result already provided by `UniswapV2Library.getAmountsIn()`, even though the function already provides an accurate estimate based on the current pool conditions.

Note: this issue also occurs with the same function in the `GatewayTransferNative` contract.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L313-L319

## Root Cause
The root of the problem lies in the `_swapAndSendERC20Tokens` function:
```solidity
// getAmountsIn already gives the correct value
uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
    UniswapFactory,
    gasFee,                                           // Desired output (gas fee)
    getPathForTokens(targetZRC20, gasZRC20)          // Path swap
);

// PROBLEM - Adding slippage again
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
```
`UniswapV2Library.getAmountsIn()` calculates the required input amount based on an AMM formula that takes into account the trading fee (0.3%) and the current pool conditions. The resulting `amountsQuote[0]` is an accurate estimate of the `gasFee` amount of `gasZRC20`. Adding slippage tolerance above this value causes `amountInMax` to be larger than necessary. This results in the contract taking more `targetZRC20` from the user for swaps.

## Impact
Users lose more tokens than necessary on every cross-chain transaction.

## Scenario
Normal Scenario (Without Problem):
1. User wants to do a cross-chain swap with output 1000 USDC
2. Gas fee required: 10 ETH
3. `getAmountsIn()` calculates: it takes 1005 USDC to get 10 ETH (including trading fee)
4. Contract should use maximum 1005 USDC for swap
5. Remaining USDC (1000 - 1005 = -5) → not enough, transaction fails or user needs to add input

Scenario with Problem:
1. User wants to do a cross-chain swap with output 1000 USDC
2. Gas fee required: 10 ETH
3. `getAmountsIn()` calculates: it takes 1005 USDC to get 10 ETH
4. PROBLEM: Contract adds 1% slippage → `amountInMax = 1005 + (10 * 1005 / 1000) = 1015.05 USDC`
5. The contract uses up to 1015.05 USDC for swap (10.05 USDC more)
6. The user loses more tokens than he should

Concrete Calculation Example:
```diff
Target Amount: 1000 USDC
Gas Fee Required: 10 ETH
getAmountsIn() result: 1005 USDC
Slippage setting: 10 (1%)

Problem Calculation:
amountInMax = 1005 + (10 * 1005 / 1000) = 1005 + 10.05 = 1015.05 USDC

User Loss: 10.05 USDC per transaction
```

## Recommendation
Remove additional slippage.
```solidity
function _swapAndSendERC20Tokens(
    address targetZRC20,
    address gasZRC20,
    uint256 gasFee,
    uint256 targetAmount
) internal returns(uint256 amountsOut) {
    // Calculate how many ZRC20 targets are needed to get TRC20 gas fee gas
    uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
        UniswapFactory,
        gasFee,
        getPathForTokens(targetZRC20, gasZRC20)
    );

    // FIX: Use getAmountsIn result directly without adding slippage
    uint amountInMax = amountsQuote[0];
    
    // Approve router to use target token
    IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

    // Make a swap: exchange the ERC20 target with TRC20 gas for the amount of gasFee
    uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
        .swapTokensForExactTokens(
            gasFee,
            amountInMax,
            getPathForTokens(targetZRC20, gasZRC20),
            address(this),
            block.timestamp + MAX_DEADLINE
    );

    // Validate that the contract has enough gas tokens after the swap
    require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
    
    // Validate that there are still tokens left to send after being deducted for gas
    require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

    // Approve gateway to use gas token (to pay gas fee)
    IZRC20(gasZRC20).approve(address(gateway), gasFee);
    
    // Approve gateway to use remaining target tokens (to be sent to users)
    IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

    // Return the number of tokens to be sent to the user (after deducting the gas fee)
    amountsOut = targetAmount - amounts[0];
}
```
