# Empty `swapData` in `GatewayTransferNative.onCall` Bypasses Swap and Allows Draining of Arbitrary `targetZRC20`

### Summary

If [`GatewayTransferNative.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L394-L408) is called with `decoded.swapData` being empty and `decoded.targetZRC20` being different from the deposited `zrc20`, the intended DODO swap is bypassed. The function `_doMixSwap` returns the original `amount` of `zrc20`, which `onCall` then incorrectly uses as the amount to transfer `decoded.targetZRC20` from `GatewayTransferNative`'s own balance to the `receiver`. This allows an attacker to deposit any amount of token and receive an equivalent amount of a different, potentially more valuable token held by `GatewayTransferNative`.

### Root Cause

The bug exists in how `GatewayTransferNative.onCall` handles the DODO swap logic when `decoded.swapData` is empty.

1.  **Cross-chain Message & Payload Decoding:** `GatewayTransferNative.onCall` receives `amount` of `zrc20` tokens and a `message`. The `message` payload is decoded into `DecodedNativeMessage memory decoded` and `MixSwapParams memory params`. If `decoded.swapData` is empty, `params` will be initialized with default/zeroed values by `SwapDataHelperLib.decodeCompressedMixSwapParams`.

    ```solidity
    function onCall(
        MessageContext calldata context,
        address zrc20, // e.g DAI.ETH
        uint256 amount, // e.g. 1e18 DAI.ETH
        bytes calldata message 
    ) external override onlyGateway {
        // ...
        bytes calldata _message = message[32:]; 
        (DecodedNativeMessage memory decoded, MixSwapParams memory params) =
            SwapDataHelperLib.decodeNativeMessage(_message); 
        // @audit If decoded.swapData is empty, params will be {fromToken: address(0), toToken: address(0), ...}
        // @audit decoded.targetZRC20 can be ETH.ETH (from payload)
        // ...
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
        uint256 amountAfterFee = amount - platformFeesForTx; // e.g., 1e18 of DAI.ETH
        address receiver = address(uint160(bytes20(decoded.receiver)));
        // ...
        if (decoded.targetZRC20 == zrc20) { 
            // @audit Path NOT taken if decoded.targetZRC20 = ETH.ETH and zrc20 = DAI.ETH
        } else { 
            // @audit This path IS taken. decoded.swapData is empty. amountAfterFee is quantity of DAI.ETH. params is zeroed.
            uint256 outputAmount = _doMixSwap(decoded.swapData, amountAfterFee, params);

            if (decoded.targetZRC20 == WZETA) {
                // ...
            } else {
                // @audit This transfers ETH.ETH using the amount of DAI.ETH
                TransferHelper.safeTransfer(decoded.targetZRC20, receiver, outputAmount); 
            }
        }
    }
    ```

2.  **Logic in `_doMixSwap` with Empty `swapData`:** The `_doMixSwap` function is called. If `swapData` is empty, it bypasses the entire DODO swap logic.

    ```solidity
    function _doMixSwap(
        bytes memory swapData, // @audit EMPTY
        uint256 amount,        // @audit Amount of DAI.ETH (amountAfterFee)
        MixSwapParams memory params // @audit Zeroed params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) { // @audit TRUE
            return amount; // @audit Returns amount of DAI.ETH
        }
        // ...
    }
    ```
    `_doMixSwap` returns `amount` (`1e18 DAI.ETH`).

3.  **Incorrect Token Transfer:** Back in `onCall`, `outputAmount` is now equal to `amountAfterFee`. The code then proceeds to transfer `decoded.targetZRC20` using this `outputAmount`. `TransferHelper.safeTransfer(decoded.targetZRC20, receiver, outputAmount)` effectively becomes `TransferHelper.safeTransfer(ETH.ETH, receiver, 1e18)`. This transfers `ETH.ETH` from `GatewayTransferNative`'s balance, but the quantity is based on the amount of `DAI.ETH` the attacker sent. No actual swap or value conversion has occurred.

### Internal Pre-conditions

1.  The `GatewayTransferNative` contract must have a non-zero balance of the `decoded.targetZRC20` that the attacker intends to drain. This is plausible due to the refund mechanism.

### External Pre-conditions

1.  ZetaChain's Gateway and the source chain's Gateway must be operational to relay the transaction and payload.

### Attack Path

1.  **Pre-condition:** `GatewayTransferNative` contract holds `1e18` of `ETH.ETH` ZRC20.
2.  **Attacker's Action:** Attacker initiates a cross-chain transaction via `GatewaySend.depositAndCall` on the Ethereum.
    *   Attacker deposits `1e18` wei of `DAI`  (1 DAI). This `DAI` becomes `DAI.ETH` ZERC20 in `onCall`, and `amount` becomes `1e18`.
    *   The `payload` sent to `onCall` is crafted such that when `SwapDataHelperLib.decodeNativeMessage` processes it:
        *   `decoded.targetZRC20`: `address(ETH.ETH)`.
        *   `decoded.receiver`: Attacker's ZetaChain address.
        *   `decoded.swapData`: `""` (empty bytes).
3.  **Execution within `GatewayTransferNative.onCall`:**
    *   `onCall` receives `amount = 1e18` of `zrc20 = DAI.ETH`.
    *   Assume platform fees are zero. `amountAfterFee` remains `1e18`.
    *   The condition `decoded.targetZRC20 (ETH.ETH) == zrc20 (DAI.ETH)` is false.
    *   The `else` block is executed: `outputAmount = _doMixSwap("", 1e18, params)`.
    *   `_doMixSwap` sees `swapData.length == 0` and returns `1e18`. So, `outputAmount = 1e18`.
    *   The condition `decoded.targetZRC20 (ETH.ETH) == WZETA` is false.
    *   `TransferHelper.safeTransfer(decoded.targetZRC20, receiver, outputAmount)` is called as `TransferHelper.safeTransferETH(ETH.ETH, 1e18);`. This sends `1e18` wei of ETH.ETH to the attacker.
4.  **Result**: `GatewayTransferNative`'s ETH.ETH balance is reduced by `1e18` wei (1 ETH). The attacker used 1 DAI to obtain 1 ETH from the contract. 

### Impact

Direct loss of any ZRC20 tokens held by `GatewayTransferNative`. An attacker can specify a `targetZRC20` they wish to drain, send a nominal amount of a different `zrc20`, provide empty `swapData`, and receive the `targetZRC20` from the contract's balance. This can be repeated.

### Mitigation

In `GatewayTransferNative.onCall`, if `decoded.targetZRC20 != zrc20`, the contract should ensure that `decoded.swapData` is NOT empty. If a token transformation is expected, swap parameters must be provided.

```solidity
require(decoded.swapData.length > 0, "GTN: Swap data required for different target ZRC20");
uint256 outputAmount = _doMixSwap(decoded.swapData, amountAfterFee, params);
```

This ensures the `_doMixSwap` function cannot return early due to empty `swapData` if a different `targetZRC20` is specified, thereby forcing the DODO swap logic (with its own checks and approvals based on `params`) to execute.
