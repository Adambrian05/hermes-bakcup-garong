# The cross chain swap can fail when it should not

### Summary

The redundant slippage protection can cause the cross chain swap to fail when it should not

### Root Cause

The function [`_swapAndSendERC20Tokens()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302) handles logics to swap token to gas token to cover gas fee. The function integrates with UniswapV2 Router to handle the swap, such that it first calculate the amount token in (from the exact amount out of gas fee), then increase the value by `slippage` percents to handle slippage and finally call Uniswap router to execute the swap. However, here the [Router will only use exactly the quoted amount returned from `UniswapV2Library.getAmountsIn()`](https://github.com/Uniswap/v2-periphery/blob/0335e8f7e1bd1e8d8329fd300aea2ef2f36dd19f/contracts/UniswapV2Router02.sol#L238-L251) for the swap because the process of (calculating amount in -> execute swap) is within `_swapAndSendERC20Tokens()` function, which will not incur slippage. 

The problem arises with the check `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW")`. Indeed, the actual amount used for the trade is `amountsQuote[0]` which can be less than `amountInMax` when `slippage > 0`. So the check can cause the function to revert in case `amounts[0] < targetAmount < amountInMax`, but actually the transaction results are valid: gas fee is covered, and there is still amount out for the trader.
```solidity
    function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
@>        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

@>        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
@>        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
@>        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

NA

### Attack Path

1. There is an outgoing swap from Zetachain -> connected chain with `targetZRC20 != gasZRC20` -> need to swap for gas fee
2. Assume that the gas fee is $3, `slippage = 10` (1%) => `maxAmountIn = $3.03`. 
Assume that the USD value of target amount is about $3.02 => actual gas fee is $3, remain target amount = $0.02 but the transaction will fail because `targetAmount < maxAmountIn`

Note that: depending on network activity, the needed as fee can be extremely high, causing the range `[amounts[0]; maxAmountIn]` gets wider

### Impact

- Some cross chain swaps (having target amount value slightly higher than gas fee value) can be failed even when it should not be
