# GatewayTransferNative fails to properly deduct the fee when zrc20 != targetZRC20 in the onCall

### Summary

When a the cross-chain transaction reaches the GatewayNative in order to execute the onCall there's a mechanism to deduct a fee from the amount and send it to the EddyTreasureSafe.
The problem is that if a swap needs to take place (i.e. the zrc20 being bridged isn't the targetZRC20) the fee isn't deducted from the amount resulting in one of two scenarios:

1. If the contract has a positive token balance to cover the fee (likely from reverted transaction which are not claimed yet), the fee will be paid from other user's funds;
2. Transaction reverts at some point as the swap can't be executed (low balance) due to trying to swap the whole amount without taking the fee out of it.

### Root Cause

From the code excerpt below we can see the two cases:

- First one the if-clause in which zrc20 == targetZRC20 (no swap needs to be performed), the `platformFeesForTx` are subtracted from the amount which is sent to the receiver. 
- In the second case the else-clause, the `platformFeesForTx` isn't subtracted from the `amount` which is passed to the `_doMixSwap`.

```solidity

 // Fee for platform
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        address receiver = address(uint160(bytes20(decoded.receiver)));

        if (decoded.targetZRC20 == zrc20) {
            // same token
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx
            );

    
            );
        } else {
            // Swap on DODO Router
            uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

            if (decoded.targetZRC20 == WZETA) {
                // withdraw WZETA to get Zeta in 1:1 ratio
                IWETH9(WZETA).withdraw(outputAmount);
                // transfer wzeta
                TransferHelper.safeTransferETH(receiver, outputAmount);
            } else {
                TransferHelper.safeTransfer(
                    decoded.targetZRC20,
                    receiver,
                    outputAmount
                );
            }

        
            );
        }
    }

```

This means that if the contract has a positive balance which can cover the platform fee (from stored reverts for example), a malicious user can initiate a transaction on the native Gateway that should perform a swap:

```solidity
 function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```

Considering that the full amount is approved to Dodo, they can receive an output amount which matches the full one (without the fee subtracted).  This basically means that they've received the full amount worth (in the target token) and the fee was paid by other users/protocol instead of the user-in-question making the transaction.

### Internal Pre-conditions

None

### External Pre-conditions

A user making a transaction to the Native Gateway as the target with a different originating ZRC20 token and a different target one (swap needs to be performed).

### Attack Path

A user initiates a transaction to the native gateway with a different originating ZRC20 token and a different target one which would initiate the else-clause and cause a swap to take place.
The fee amount isn't subtracted from the amount which is approved to Dodo, allowing the user to swap the full amount and for other users/the protocol to pay the fee.

### Impact

The fee subtracted and sent to the fee collector address isn't paid for by the user-in-question, but by the underlying balance of the contract (other users).

_No response_

### Mitigation

Subtract the fee from the amount which is forwarded to the `_doMixSwap` and later approved to DODO.
