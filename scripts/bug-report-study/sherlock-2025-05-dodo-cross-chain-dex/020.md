# Improper ETH Handling in `_doMixSwap`

__Summary:__ The `_doMixSwap` function unconditionally forwards any attached ETH (`msg.value`) to the external DODO router, even when the swap is for an ERC20 token, potentially leading to user fund loss.

__Vulnerability Detail:__ The `_doMixSwap` function is called by the `depositAndCall` overload that handles token swaps. When calling the external DODO router's `mixSwap` function, `_doMixSwap` includes `{value: msg.value}` in the call. This means any ETH sent by the user with the initial `depositAndCall` transaction is forwarded to the router. If the user intends to swap an ERC20 token (`params.fromToken != _ETH_ADDRESS_`) but mistakenly sends ETH with the transaction, this ETH will be sent to the DODO router. DODO's `mixSwap` is typically designed to use attached ETH only when the input token is ETH (or WETH). If the input token is an ERC20, the forwarded ETH is unlikely to be used for the swap and may become stuck in the DODO router contract or cause the router call to fail if it doesn't handle unexpected ETH.

__Impact:__ Users who mistakenly send ETH along with an ERC20 token when calling the `depositAndCall` function (with swap data) will lose the sent ETH, as it is forwarded to the DODO router without being utilized or returned.
