# Incorrect Slippage Handling Causes Unnecessary Reverts in Cross-Chain Withdrawals

### Summary

The _swapAndSendERC20Tokens() function performs a token swap to pay for gas fees during cross-chain withdrawals.

It calculates amountInMax with slippage buffer:

```solidity
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
```

Then checks:

```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
However:
```

This check compares targetAmount against the maximum possible input , not the actual input used in the swap . 

As a result:

Valid transactions where there are enough tokens to both: 

Pay for gas
Leave something to send back
Still revert unnecessarily , breaking expected functionality.

This leads to confusing transaction failures , even when all balances are sufficient.

### Root Cause

The actual amount used is amounts[0], which can be less than  amountInMax
But the system uses amountInMax in the check:
