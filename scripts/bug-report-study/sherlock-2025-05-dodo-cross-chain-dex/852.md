# onCall() in the Universal Contract causes the cross-chain transaction to always revert if a swap is performed on DODO and feePercent is not zero.

### Summary

`onCall()` is invoked by the Gateway to execute the cross-chain transaction. The platform charges a fee, which is subtracted from the total amount sent. 

However, if a swap is performed via DODO, the approved token amount is the *net* amount (after fees), while the swap parameters still reference the *full* original amount. This mismatch leads to a transaction failure due to insufficient allowance.




### Root Cause

This issue exists in both `GatewayCrossChain.sol` and `GatewayTransferNative.sol`, but for simplicity, it is demonstrated using the former.

[onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442-L510) is imeplmented as follows.

As shown, a portion of the funds is deducted as platform fees, and the remaining amount is used to perform the swap in `_doMixSwap()`.
```solidity
function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```
As you can see, the contract approves DODO using the net `amount` (amount - fees), but `mixSwap()` uses `params.fromTokenAmount`, which reflects the full amount before fees. This mismatch causes the transaction to revert with `ERC20InsufficientAllowance()`, as `params.fromTokenAmount` exceeds the approved allowance.

This highlights the problem with the current implementation: in reality, the amount used for the swap should be `amount` (amount - fees), not `params.fromTokenAmount` (the full original amount), since the fees are sent to the `EddyTreasurySafe`. 

In short, although the approved amount is technically correct, the transaction still reverts because there aren’t enough tokens available to complete the swap, and that’s the real issue.


### Internal Pre-conditions

- `feePercent != 0`
- `onCall()` is invoked by the Gateway to execute a cross-chain transaction and token swap is performed using DODO.


### External Pre-conditions

None

### Attack Path

None.

### Impact

Cross-chain transactions that perform a swap using DODO will always revert.

### Mitigation

To resolve the issue, replace `params.fromTokenAmount` with `amount` in `mixSwap()`.
```diff
function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
-           params.fromTokenAmount,
+           amount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```
