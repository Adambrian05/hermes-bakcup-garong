# GatewayTransferNative::withdraw allows for users to steal over-approved tokens.

### Summary

Due to an over-approval of zrc20 tokens to GatewayZEVM, and a public access modifer to `GatewayTranferNative::withdraw`, anyone can steal `gasFee` amount of tokens everytime `withdrawToNativeChain` is called.

### Root Cause

There are two root causes.

1. `public` access modifier on `GatewayTransferNative::withdraw`

2. Overapproval to GatewayZEVM when `_handleEvmOrSolanaWithdraw` and/or `_handleBitcoinWithdraw` is excuted as shown [here] (https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L370) and [here] (https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L389)

In both scenarios, `outputAmount + gasFee` of `allowance` is given to `GatewayZEVM`, when only `outputAmount` of ZRC20 tokens are withdrawn from `GatewayTransferNative`. This leaves a residual allowance of `gasFee` amount of ZRC20 tokens after each execution.

### Internal Pre-conditions

`GatewayTransferNative::withdrawToNativeChain` is called, and either `_handleEvmOrSolanaWithdraw` or `_handleBitcoinWithdraw` is executed.

### External Pre-conditions

None

### Attack Path

1. Wait for someone to call `GatewayTranferNative::withdrawTONativeChain` that executes`_handleEvmOrSolanaWithdraw` or `_handleBitcoinWithdraw`.

2. Query the excess allowance given the GatewayZEVM. This should equal to `gasFee` of the previous call.

3. Call `GatewayTranferNative::withdraw` by specifying the previous call with the following arguments:
```solidity
    bytes32 externalId: any externalId of his choice
    bytes memory sender: attacker evm address
    address outputToken : zrc20 of choice that has with excess allowance
    uint256 amount : excess allowance amount
```

### Impact

Anyone can steal `gasFee` amount of ZRCTokens after each call of `GatewayTransferNative::withdrawToNativeChain`  where either`_handleEvmOrSolanaWithdraw` or `_handleBitcoinWithdraw` is executed.

### PoC

Please refer to Attack Path.

### Mitigation
In `GatewayTransferNative::withdraw`, change the following
```diff
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) 
- public
+ internal
 { 
    // ...
}
```

Also, should not over approve in `GatewayTransferNative::_handleEvmOrSolanaWithdraw`
```diff
function _handleEvmOrSolanaWithdraw(
        bytes32 externalId,
        DecodedMessage memory decoded,
        uint256 outputAmount,
        bytes memory receiver
    ) internal returns (uint256 amountsOutTarget) {
        (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);

        if (decoded.targetZRC20 == gasZRC20) {
            if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
-            IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
+           IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
            //...
```

and in `GatewayTransferNative::_handleBitcoinWithdraw`
```diff

    function _handleBitcoinWithdraw(
        bytes32 externalId, 
        DecodedMessage memory decoded, 
        uint256 outputAmount,
        uint256 gasFee
    ) internal {
        if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
+       IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
-        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
        withdraw(
            externalId, 
            decoded.receiver, 
            decoded.targetZRC20, 
            outputAmount - gasFee
        );
    }
```
