# The `revertMessage` parameter is incorrectly set in the `GatewayCrossChain` and `GatewayTransferNative` contracts.



## Summary
The `revertMessage` parameter is incorrectly set in the `GatewayCrossChain` and `GatewayTransferNative` contracts.  

It was mistakenly set as `bytes.concat(externalId, receiver)`, which prevents fund recovery when the `receiver` is a BTC or Solana address.  

Even if the destination chain is EVM-compatible, setting it to `receiver` is still incorrect. If the `receiver` is not an EOA (Externally Owned Account), the `receiver` on the ZetaChain does not necessarily have the same controller as the `receiver` on the EVM-compatible chain.

In `withdrawToNativeChain()` -> `_handleEvmOrSolanaWithdraw()` -> `withdrawAndCall()`, the value of `decoded.receiver` is passed as the `receiver` parameter.  

However, we know that `decoded.receiver` is the recipient address on the destination chain (e.g., a Solana address), which means this address is not 20 bytes long.
