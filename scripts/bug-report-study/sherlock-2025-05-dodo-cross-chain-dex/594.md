# `withdraw` in contract GatewaytransferNative can drain or steal the refund money deposited there.

### Summary

[withdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286) function in contract `GatewayTransferNative` is open for everyone in which a malicious attacker can take advantage of to use it to steal the refund money deposited inside the contract.

### Root Cause

Here is the detail of the function `withdraw` and look at line 291 with tag of public, it means anyone can access it. The malicious attacker will simply use its address as recipient under parameter `sender`.

Line 149 from previous code snippet will execute the following below function, look at line 116 below, the zrc-20 to be withdrawed will be eventually be burned. This will emit event in zetachain and picked up by observers. Observers will process this transaction and reflect withdrawal transaction in destination chain. The recipient address in destination chain is the address used by malicious attacker. This is equivalent to stealing of funds.

### Internal Pre-conditions

1. If there is a refund deposited inside GatewayTransferNative`, this can be stolen or drained.

### External Pre-conditions

None

### Attack Path

This could be the scenario.

1. `GatewayTransferNative`  has refunds deposited.
2. Malicious actor detected the refund event deposited.
3. He immediately executed withdraw with its own address as recipient in destination chain and transfer the refunds to `GatewayZEVM`.
4. `GatewayZEVM` burned the tokens and will emit event to be processed by Zetachain observers in destination chain.
5. The tokens in destination chain will be released from protocol custody contract to the recipient malicious actor address. 

### Impact

Refunds deposited inside `GatewayTransferNative` can be stolen or drained.

### PoC

see attack path

### Mitigation

Make the `withdraw` function accessible only by protocol.
