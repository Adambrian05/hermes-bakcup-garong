# The `msg.value` of the `GatewaySend::depositAndCall` function may be inconsistent with the `amount` parameter, causing unnecessary losses to users

### Summary

In`GatewaySend::depositAndCall` function, if the `msg.value` paid by the user is greater than the parameter `amount`, it will cause unnecessary losses.

### Root Cause

If the user wants to swap on zetachain: ETH -> token3Z -> token2Z, `GatewaySend::depositAndCall` function will be called:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L308-L335
```solidity
function depositAndCall(
        address fromToken,
        uint256 amount,
        bytes calldata swapData,
        address targetContract,
        address asset,
        uint32 dstChainId,
        bytes calldata payload
    ) public payable {
        globalNonce++;
        bytes32 externalId = _calcExternalId(msg.sender);
        bool fromIsETH = (fromToken == _ETH_ADDRESS_);

        // Handle input token
        if(fromIsETH) {
            require(
                msg.value >= amount, 
                "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
            );
        } else {
            // ...

        emit EddyCrossChainSend(
            externalId,
            dstChainId,
            fromToken,
            asset,
            amount,
            outputAmount,
            msg.sender,
            message
        );
    }
```
This function requires that the Ether sent by the user must be greater than or equal to the parameter `amount`. 
However, if the Ether sent by the user is greater than the parameter `amount`, it will cause unnecessary losses. This is because the event emitted at the end of the function directly uses the parameter amount instead of the actual amount of msg.value sent by the user:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L334-L335


### Internal Pre-conditions

The amount of Ether sent by the user is greater than the parameter `amount`

### External Pre-conditions

N/A

### Attack Path

1. User1 attempts to perform a zetachain swap: ETH -> token3Z -> token2Z
2. User1 has `1000` ether in total. He wants to send `100` ether. However, the actual amount of ether sent exceeds 100 ether, for example, `800` ether.
3. After the swap is successful, user1 loses `800` ether, and the `GatewayEVM` contract receives `800` ether from user1. However, the function only records the amount as `100` ether when emitting the event.


### Impact

The `msg.value` of the `GatewaySend::depositAndCall` function may be inconsistent with the `amount` parameter, causing unnecessary losses to users

### Mitigation

Change all `require(msg.value >= amount);` checks to `require(msg.value == amount);` to ensure that the `amount` of ether sent by the user is consistent with the `amount` of the emit event, thus avoiding unnecessary losses.
