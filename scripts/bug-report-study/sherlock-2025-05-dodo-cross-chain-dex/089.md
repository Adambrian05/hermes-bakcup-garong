# Malicious users could steal tokens from 'GatewayCrossChain' contract

### Summary

In `GatewayCrossChain.sol`, it is possible to transfer an amount of cheap zrc20 token to `oncall()` function and withdraw an expensive zrc20 token with nearly the same amount(only 0.5% fee deducted). If there is some  tokens in the contract waiting for refunding, it will be stolen.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442C5-L511C1

When users call `depositAndCall()` function from the source chain, the `GatewayCrossChain.sol::oncall()` function above will be called. An amount of zrc20 token will transfer to `GatewayCrossChain` contract and it will calculate the target zrc20 token with `outputAmount` and send these information to gateway.  In `GatewayCrossChain.sol:465`, `outputAmount` is calculated by `_doMixSwap(decoded.swapDataZ, amount, params)`, but when  the user set `swapDataZ` to empty in their call, `outputAmount` is equal to `amount`.(as shown below)

    function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

After the `_doMixSwap`, the contract call `gatewayZEVM` contract to help users withdraw target zrc20. The `gatewayZEVM` contract will charge target zrc20 from the `GatewayCrossChain` contract and then send token to the receiver. 
Therefore, a malicious user could transfer cheap zrc20 token to `GatewayCrossChain` contract and withdraw an expensive token. Since there are some refund tokens in the contract, attackers could steal these tokens.


### Internal Pre-conditions

`GatewayCrossChain` have tokens

### External Pre-conditions

none

### Attack Path
1. Attacker set all `swapdata` to empty and choose a cheap asset and an expensive target zrc20 token in his payload
2.He set the amount to  `GatewayCrossChain` contract's balance of the target zrc20 token
3.He set all `swapData` to empty
4.Attacker call `GatewaySend::depositAndCall()` function from a source chain and `targetContract` is `GatewayCrossChain`
5.After the process finished, the target token in `GatewayCrossChain` contract is stolen!

### Impact

Attackers could steal tokens in `GatewayCrossChain` contract

        bytes memory accounts = "";

            dstChainId,
            targetZRC20,
