# Native withdrawals from zetachain to bitcoin receiver addresses wrongly assumes gas tokens are same as `targetZRC20` tokens

## Vulnerability Details

When a user begins a withdrawal to the destination chain (Bitcoin), the process follows the path from `GatewayTransferNative.withdrawToNativeChain` to `GatewayTransferNative._handleBitcoinWithdraw`. However, a problem occurs because the protocol incorrectly assumes that the gas token is identical to the `targetZRC20` token.

As a result, this could lead to either reversion of withdrawal calls to Bitcoin addresses or the use of `gasZRC20` tokens within the `GatewayTransferNative` contract, which do not belong to the users.

## POC

Consider the following scenario

1. Alice transfers 100 USDC to her Bitcoin receiving address using `GatewayTransferNative.withdrawToNativeChain`.
2. She goes through `GatewayTransferNative._handleBitcoinWithdraw` -> `GatewayTransferNative.withdraw` -> `GatewayZEVM.withdraw` -> `GatewayZEVM._burnProtocolFees`.
    - Here, the `gasZRC20` is identified as `gasUSDC`, rather than the USDC token itself.
3. As a result, Alice's transaction either fails, or she resorts to using leftover `gasUSDC` tokens in `GatewayTransferNative` to cover gas fees, leading to a loss of funds for the protocol.

## Root Cause

Incorrect assumption that `targetZRC20` token is the `gasZRC20` token for withdrawals to bitcoin addresses

## Impact

No transfers to bitcoin receiver addresses can be done. Protocol core functionality is DOS-ed
Loss of funds for protocol

## Mitigation

Consider first swapping the `targetZRC20` tokens for `gasZRC20` tokens similar to how `_handleEvmOrSolanaWithdraw` does it.
