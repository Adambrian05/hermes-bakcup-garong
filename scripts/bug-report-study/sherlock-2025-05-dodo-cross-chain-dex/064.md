# Protocol is not compatible with USDT due to lack of an approval reset and no return value

### Summary

The protocol is expected to be compatible with all ZRC-20 tokens on Zeta chains. On this list is USDT, however currently any USDT deposits will fail due to a lack approval reset to 0 and the fact it does not return true on a succesful transfer
https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets

### Root Cause

In both `_handleERC20Deposit` and `_doMixSwap`, approvals are needed to the gateway and DODO router respectfully. The issue is that both of them call the ERC20 contract directly and dont first clear any existing approvals first. This will cause any call to this function with USDT as the approval token to fail as it requires the current approval to be zero first.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L184
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L199

Also here, we check that the transfer function returns true. However for USDT, nothing is returned and this check will fail.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L239
### Internal Pre-conditions

1. Users are able to deposit as soon as contract is deployed

### External Pre-conditions

1. Gateway is currently accepting deposits

### Attack Path

1. A user calls `depositAndCall` with USDT as either the from token or the to token
2. An existing approval for USDT on the `GatewaySend` contract already exists
3. Call will fail on `_doMixSwap` if its the to token
4. Call will fail on the transfer if its the from token because it will not return true

### Impact

The protocol cannot use USDT the most widely used stablecoin
