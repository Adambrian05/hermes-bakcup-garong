# Attacker will steal stored tokens in `GatewaySend` as `fromToken` parameter validation is missing

### Summary

Missing validation between user-provided `fromToken` and swap `params.fromToken` will cause complete loss of stored tokens for the protocol as an attacker will exploit parameter mismatch to drain contract balances.

### Root Cause

In `GatewaySend.sol:218-245` there is missing validation that the `fromToken` parameter matches `params.fromToken` from the decoded swap data in `_doMixSwap()`.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L245


### Internal Pre-conditions

1. Contract needs to hold any ERC20 tokens from previous failed transactions or leftover balances

### External Pre-conditions

N/A

### Attack Path

1. Attacker calls `GatewaySend::depositAndCall()` with `fromToken=USDC`, `amount=1`, but encodes `swapData` containing `params.fromToken=WETH`, `toToken=BTC`, and `asset=BTC`.
2. Function transfers 1 USDC from attacker to contract via `transferFrom()`
3. Function calls `_doMixSwap()` which decodes `swapData` and finds `params.fromToken=WETH`
4. `_doMixSwap()` approves and swaps the contract's existing WETH balance instead of the deposited USDC into BTC to later deposit BTC to the gateway.
5. Attacker repeats this process for all token types held by the contract to drain them completely

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all stolen tokens from the contract while only depositing minimal amounts of other tokens.

### PoC

_No response_

### Mitigation

Add validation to ensure the `fromToken` parameter matches the `params.fromToken` from the decoded swap parameters.
