# Missing amount validation in `onCall`

## Finding description and impact

In the `onCall` function, when `fromIsETH` is true, the function accepts ETH with no checks:

* No validation that `amount > 0`
* No check that `msg.value == amount`

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386

## Potential impacts:

* Function may execute with zero-value transfers
* Inconsistent state or lost ETH if `msg.value != amount`
* Potential bugs or abuse if zero-amount messages are used to trigger logic without real value

## Mitigation

Add validation for ETH inputs:

```solidity
if (fromIsETH) {
    require(amount > 0, "INVALID: Zero amount");
    require(msg.value == amount, "MISMATCH: ETH value and amount differ");
}
```

These checks ensure proper ETH accounting and prevent silent failures or malicious zero-value calls.
