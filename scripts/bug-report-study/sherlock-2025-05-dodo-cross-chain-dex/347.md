# Anyone can call `claimRefund` function.

### Summary

In `GatewayCrossChain.claimRefund` function, there is check for validate `msg.sender` but the check has no real effect due to `receiver = msg.sender`.

### Root Cause

You can notice that `INVALID_CALLER` check has no real effect, in [`GatewayCrossChain.claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L574-L578) function.

```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

@>      address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
@>      require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");

        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```

If `refundInfo.walletAddress.length` isn't 20, anyone can `claimRefund` function to steal funds.

### Internal Pre-conditions

If `abortContext.revertMessage` doesn't have length of 52 in `onAbort` function, `walletAddress` doesn't have length of 20.
