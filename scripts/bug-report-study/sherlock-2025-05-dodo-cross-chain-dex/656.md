# Malicious overwrite of refund Information via `onAbort` in ZetaChain Cross-Chain Swap

## Summary
The ability to specify an existing `externalId` in `RevertOptions` will cause a complete loss of refundable funds for the original user as an attacker will overwrite their refund information in `refundInfos`, rendering it unclaimable.

## Root Cause
The choice to allow user-specified `externalId` in `RevertOptions` without uniqueness validation is a mistake as it enables an attacker to overwrite existing refund information in `refundInfos` on ZetaChain.

[GatewayCrossChain.onAbort](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L550)

## Internal Pre-conditions
1. A legitimate user needs to initiate a cross-chain swap via `depositAndCall` on Chain A (e.g., Ethereum), resulting in a revert of `onCall` on ZetaChain and insufficient gas for `onRevert` on Chain A, triggering `onAbort` and storing refund information in `refundInfos` with a specific `externalId`.
2. The legitimate user’s `externalId` must be known to the attacker (e.g., through monitoring `EddyCrossChainRefund` events emitted by the Universal App on ZetaChain).

## External Pre-conditions
1. Gas prices on Chain A (e.g., Ethereum) must be high enough to cause insufficient gas for `onRevert`, triggering `onAbort` on ZetaChain (e.g., during a market bull run where gas prices exceed the deposited amount).

## Attack Path
1. The attacker monitors `EddyCrossChainRefund` events emitted by the Universal App on ZetaChain to identify an existing `externalId` associated with a legitimate user’s refund in `refundInfos`.
2. The attacker deploys a malicious `GatewaySend` contract on Chain A that mimics a legitimate `depositAndCall` call but specifies the identified `externalId` in the `revertMessage` of `RevertOptions`, along with the attacker’s `walletAddress`.
3. The attacker initiates a cross-chain swap via `depositAndCall`, using a small amount of ETH (e.g., 0.01 ETH) to ensure insufficient gas for `onRevert` on Chain A.
4. The `onCall` function in the Universal App on ZetaChain reverts (e.g., due to an invalid swap configuration provided by the attacker).
5. Due to insufficient gas for `onRevert` on Chain A, ZetaChain triggers `onAbort` in the Universal App, which overwrites the legitimate user’s `refundInfos[externalId]` with the attacker’s `walletAddress` and the attacker’s deposited amount.
6. The attacker calls `claimRefund` with the `externalId` on ZetaChain, recovering their own deposited funds (e.g., 0.01 ETH), while the legitimate user’s refund information is erased, preventing them from claiming their funds.

## Impact
The original user suffers a 100% loss of their refundable funds due to the overwritten `refundInfos` entry. The attacker incurs a negligible cost (e.g., gas fees for the malicious transaction) and recovers their deposited funds, gaining no direct profit but causing significant loss to the legitimate user (griefing attack).

See Atack Path

## Mitigation
1. **Validate `externalId` Uniqueness**: Modify the `onAbort` function in the Universal App to check if `externalId` already exists in `refundInfos` before storing a new `RefundInfo`. Revert if a duplicate is detected:
   ```solidity
   function onAbort(AbortContext calldata abortContext) external onlyGateway {
       bytes32 externalId = bytes32(abortContext.revertMessage[0:32]);
       require(refundInfos[externalId].externalId == bytes32(0), "Duplicate externalId");
       // Proceed with storing refundInfo
   }
   ```
