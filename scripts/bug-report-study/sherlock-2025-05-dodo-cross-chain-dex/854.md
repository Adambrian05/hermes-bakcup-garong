# Account abstraction and other wallet can have diff address on diff chains

### Summary

The GatewaySend contract contains a severe flaw where funds from failed cross-chain transactions are refunded to msg.sender on the destination chain, assuming wallet addresses remain consistent across chains. This assumption breaks down with modern wallet types like Account Abstraction wallets or Safe multisigs, which may have different addresses on different chains due to deployment variations. As a result, refunds can be sent to non-existent addresses, causing permanent fund loss, or to unintended recipients, enabling theft.

### Attack Path

Consider a user, Bob, who uses an Account Abstraction wallet with the address X on Ethereum to initiate a cross-chain transfer of 500 DAI to Polygon via depositAndCall(). Due to deployment differences, Bob’s wallet address on Polygon is Y. If the cross-chain transaction fails on Polygon, the onRevert() function is triggered, extracting X from the revertMessage as the refund recipient. The contract attempts to send the 500 DAI to X on Polygon. If this address doesn’t exist on Polygon, the funds are lost forever. Worse, if X belongs to another user on Polygon, that user receives Bob’s 500 DAI, effectively losing pf the funds.

### Impact

 Refunds sent to non-existent addresses on the destination chain result in unrecoverable funds.
