# Refunds can be claimed by anyone when the walletAddress isn't an EVM address

### Summary

In the `claimRefund()` function in both `GatewayTransferNative` and `GatewayCrossChain`, the receiver is set to msg.sender initially and then set to `refundInfo.walletAddress` if the length of the address is 20 bytes (an EVM address). However, if `refundInfo.walletAddress` is a non-EVM wallet address, receiver persists as the msg.sender, passing the require statement and allowing anyone to steal these refunds. 

```solidity
function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
>>>     if(refundInfo.walletAddress.length == 20) {
>>>         receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
>>>     require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```

### Root Cause

claimRefund() doesn't handle non-EVM addresses properly.

### Internal Pre-conditions

1. There must be a refund where the walletAddress is a non EVM address.

### External Pre-conditions

n/a

### Attack Path

Attacker calls claimRefund where the refundinfo.walletAddress is a non EVM address, allow the attacker to steal the refund. 

### Impact

Loss of funds. 

### PoC

_No response_

### Mitigation

Handle non-evm addresses in claimRefunds on both `GatewayTransferNative` and `GatewayCrossChain`
