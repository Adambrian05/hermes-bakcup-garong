# A attacker will steal user fund by overwritting refund user information

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L533-L539
attacker can overwrite refund user information and steal user fund

### Root Cause

there is no guard to prevent from malicious refund user information overwritten

### Internal Pre-conditions

no need

### External Pre-conditions

no need

### Attack Path

1. Attacker initiates swap with chosen `externalId`, `receiver`
2. These go into `revertMessage = bytes.concat(externalId, receiver)`
3. Gateway stores this` revertMessage`
4. Swap fails → triggers `onRevert(...)`
5. Your contract stores `refundInfos[externalId] = ...` blindly
6. Legit refund is overwritten or hijacked

### Impact

1. User A swaps 1000 ZRC20 and a refund is triggered → stored under `externalId = 0xABC123`
2. Before user A claims it, attacker initiates a bogus transaction with the same `externalId = 0xABC123`, but inserts:

- Their own wallet as `walletAddress`

- Low amount

3. A failed swap triggers `onRevert`, overwriting the refund
4. Attacker calls `claimRefund(0xABC123)` — gets funds.
5. User A’s refund is now lost.

### PoC

no need

### Mitigation

add following check before definding user refund information
`require(refundInfos[externalId].externalId == 0, "Refund already exists");`
