# User get charged unneccessarily for making a cross-chain swap

### Summary

When user tries to swap the transferred asset in the Zetachain, the transaction get reverted due to the wrong implementation of function [`GatewayTransferNative::onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357-L423), eventually user get charged for the cross-chain transfer but the operation what user wanted to use this protocol isn't happened, which lose the credibility of the protocol

### Root Cause

**The root cause for this issue is the wrong implementation of `outputAmount` variable in the `GatewayTransferNative::onCall` function.** 

When user transfers asset on chain A to Zetachain:
1. 1st calls the `GatewaySend::depositAndSend` function, which will call the `GatewayEVM::depositAndSend` function, in which user assets on chain A gets transferred to the custody account, which under the control of TSS address
2. Observers see the transaction and forward the call to the `GatewayZEVM` which then forwards to the `GatewayTransferNative::onCall` function
3. This is where user gets the desired tokens in the destination chain. Before this function get called `GatewayZEVM` mints ZRC20 representing the user assets in chain A to `GatewayTransferNative` contract
4. platform fee will get deducted from this `GatewayTransferNative::onCall` function, now contract left with `amount-fee` ZRC20 tokens
5. Now as user call this transaction to get his swap happen on Zetachain, so this is where it happens. But it got reverted as in the below code you can see the [`outputAmount`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395) is being sent to DODO Router contract, but there are only `amount-fee` tokens.

As you can see there is an approval of `amount` tokens in [`GatewayTransferNative::_doMixSwap`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L449) function, but within the contract there are only `amount - fee` tokens. So eventually transaction gets reverted, so users left with the only cross-chain transfer assets, which gets back by `onRevert` functionality of Zetachain

### Attack Path

1. User initiates the transaction for cross-chain swap
2. When the function `onCall` in `GatewayTransferNative` contract tries to do swap (in Zetachain), it gets reverted due to wrong implementation of `outputAmount`
3. User loses credibility on the protocol, because he will get charged for cross-chain transaction by observers and TSS addresses without his assets getting swapped in the zetachain 

### Impact

The impact is Medium, likelihood is very High (for every cross-chain swap in zetachain). Because protocol loses its credibility and users losses his part of assets for unintended cross-chain transfer, because what user desired is cross-chain swap
