# Cross-chain transaction for USDT, BNB always get reverted

### Summary

Because of the weird ERC20 behavior of USDT, BNB tokens (which is in supported assets provided by Readme file), when user tries to do cross-chain transaction using these token they get reverted, because they will not return any Boolean, and the depositing asset takes place inside the require statement. So, ended up reverting

### Root Cause

The root cause is using IERC20 `transferFrom` method rather than using the `TransferHelper` library `safeTransferFrom`, because of this weird tokens, like USDT, BNB, transaction get reverted upon transferring the asset to the `GatewaySend` contract.

In both functions of [`GatewaySend::depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L339) (one with swap and other without it), you can see to transfer the asset from user to `GatewaySend` , the contract uses require statement as shown in below lines

```solidity
            require(
                IERC20(asset).transferFrom(msg.sender, address(this), amount),
                "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
            );
```

As USDT, and BNB will not return any Boolean for the successful transfer, so the check remains false, by ending up reverting the transaction. Which make users not able to do cross-chain transactions.

### Impact

The impact is HIGH, because most people hold these tokens because of their stable nature that peg to dollar, so many user tries to get their tokens swap from USDT, to other tokens over cross-chain. But that functionality is missing in the protocol codebase.

### PoC

Upon using USDT as the user from token, then the cross-chain transaction reverts, because of the weird behavior of USDT, which doesn't return any Boolean for ERC20 methods. Same for BNB token also

### Mitigation

Use `TransferHelper` Library in `GatewaySend` contract, like how `GatewayTransferNative` and `GatewayCrossChain` uses. Which avoid this edge cases and returns the Boolean if the asset transfer is successful or not
