# Incorrect wallet address utilized when a call is aborted from EVM chains to ZetaChain (`GatewaySend` -> `GatewayTransferNative`)

## Vulnerability Details

In the `GatewaySend` contract, when a user calls `GatewaySend.depositAndCall` and designates `GatewayTransferNative` as the `targetContract`, if the transaction fails on the ZetaChain, the sequence of events may unfold as follows: Ethereum → ZetaChain onCall fails → ZetaChain onAbort is triggered when traditional `onRevert` cannot be completed. In this case, the `targetContract` will also serve as the address for the `abortAddress` (i.e., `GatewayTransferNative`).

If this situation occurs, the `GatewayTransferNative.onAbort` function will be invoked. While the flow is correct, the problem arises when the `GatewaySend` contract includes the EVM chain address of the caller in the `RevertOptions.revertMessage`. This leads to the funds becoming trapped in `GatewayTransferNative`, as the Ethereum address should not be utilized; instead, the address owned by the user on ZetaChain should be utilized.

A similar issue may also occur in the `GatewayCrossChain` contract.

## POC

Consider the following scenario

1. Alice invokes `GatewaySend.depositAndCall` on Ethereum, designating the `GatewayTransferNative` contract on Zetachain as the target contract 
    - which includes the `RevertOptions.revertMessage` formatted as `bytes.concat(externalId, bytes20(0xEthereumAlice))`
2. Her call to `GatewayTransferNative.onCall` results in a revert
3. This triggers the `GatewayTransferNative` to revert to the `onAbort` function 
    - In `onAbort`, the revertMessage generated in `GatewaySend.depositAndCall` is forwarded to the `onAbort` function
    - The wallet address extracted is `0xEthereumAlice`, rather than the address that should be derived from the `payload` (specifically the `decoded.receiver`), which corresponds to the user's address on `Zetachain`
    - Consequently, her `refundInfos[externalId]` will store `0xAliceEthereum` as her `walletAddress`
4. When Alice attempts to claim her token refund through `GatewayTransferNative.claimRefund`, she is unable to do so, as she may not possess the `0xEthereumAlice` address on Zetachain

## Root Cause

The address provided (Ethereum) in `GatewaySend.depositAndCall` is wrong on Zetachain, making it incompatible for claiming refunds on Zetachain.

## Impact

Loss of funds for user.

## Mitigation

In `GatewaySend.depositAndCall`, allow the user to specify the receiver address
