# Uniswap Gas Fee Swap Reverts Due to Incorrect Token Transfer Attempt

## Summary
The protocol incorrectly reverts legitimate cross-chain swaps because Uniswap's `swapTokensForExactTokens` attempts to transfer more tokens than the contract holds, even when the actual swap would succeed with the available balance.

## Root Cause
In `GatewayCrossChain.sol:_swapAndSendERC20Tokens`, the function uses Uniswap's `swapTokensForExactTokens` which:
1. First attempts to `transferFrom` the full `amountInMax` (worst-case with slippage)
2. Then executes the swap using only what's actually needed
3. Finally refunds unused tokens

The contract only has `targetAmount` tokens but approves and Uniswap tries to pull `amountInMax`, causing revert at step 1.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302-L326
```solidity
function _swapAndSendERC20Tokens(...) internal returns(uint256 amountsOut) {
    // Contract has exactly targetAmount tokens after DODO swap
    
    // Calculate worst-case with slippage buffer
    uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
    
    // This reverts if amountInMax > targetAmount (contract balance)
    uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
        .swapTokensForExactTokens(
            gasFee,
            amountInMax,  // Uniswap tries to pull this full amount first!
            ...
        );
}
```

## Impact
Valid cross-chain swaps fail when:
- Contract has 100 tokens
- Actual swap needs 92 tokens (would succeed)
- But `amountInMax` = 103 tokens (with slippage buffer)
- Transaction reverts trying to pull 103 from balance of 100

Users lose gas fees on legitimate transactions that should succeed under current market conditions.

## Attack Path

-  Contract balance: 100 USDT (from DODO)
-  Gas fee needs: 90 USDT at current price = 103.5 USDT with slippage
-  Actual market swap would use: ~92 USDT
-  Result: Reverts trying to transfer 103.5 from balance of 100
-  Should: Succeed because 100 > 92 (actual need)

## Mitigation
Add validation before the swap attempt:
```solidity
require(targetAmount >= amountInMax, "Insufficient balance for worst-case swap");
```
