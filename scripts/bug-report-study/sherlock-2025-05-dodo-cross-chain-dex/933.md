# DODO Parameter Injection

### Summary

A critical vulnerability exists in the _doMixSwap function of the GatewaySend.sol contract, where an attacker can inject malicious parameters by manipulating the assetTo array within the MixSwapParams struct. This array, decoded from user-supplied swapData, is passed directly to the mixSwap function of the DODO Router without any validation. The assetTo array specifies the recipient addresses for tokens at each step of the swap, with the final element determining the ultimate recipient of the output tokens. Since this array is entirely under user control, an attacker can craft it to redirect the swap output to their own address, effectively stealing the tokens intended for the legitimate recipient.

### Root Cause

The vulnerability stems from insufficient validation of the assetTo array derived from the user-provided swapData. The _doMixSwap function blindly trusts this input, failing to verify that the recipient addresses—particularly the final one—conform to the protocol's intended flow (e.g., returning tokens to the contract or user). This lack of scrutiny allows attackers to dictate the destination of the swap output.

### Attack Path

An attacker can inject malicious parameters by manipulating the assetTo array within the MixSwapParams struct.



### Impact

Token Theft: By altering the assetTo array, an attacker can siphon off the output tokens to their address, leaving none for the intended recipient, such as the contract or the original user.

Disruption of Cross-Chain Transfers: In cross-chain scenarios, the loss of tokens before the transfer phase halts the process, leading to failed transactions and potential financial losses for users.





### PoC

Enforce that the last element of the assetTo array is the contract's address (address(this)), ensuring that output tokens are returned to the contract for subsequent handling (e.g., cross-chain transfers).
