# Refund Loss Due to Incorrect `abortAddress` in ZetaChain Cross-Chain Calls

### Summary

According to ZetaChain documentation, if a cross-chain call fails on the destination chain, the `onRevert` function is invoked on the address specified by the `revertAddress` in the [`RevertOptions`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L262) struct.

> *The Gateway invokes the `onRevert` function on the `revertAddress` on ZetaChain.*

If the `onRevert` itself reverts, ZetaChain's fallback mechanism is to transfer ZRC-20 tokens to the `abortAddress` and call `onAbort` on that address:

> *If the `onRevert` call itself reverts, the Gateway transfers ZRC-20 tokens to and calls `onAbort` on the `abortAddress` on ZetaChain.*

However, in both the [`GatewayCrossChain`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L264) and [`GatewayTransferNative`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L273) contracts, `address(0)` is incorrectly passed as the `abortAddress`.

### Root Cause

The main problem here is that `address(0)` is passed as abort address in both contracts [`GatewayCrossChain`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L264) and [`GatewayTransferNative`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L273)


```solidity 
 function withdrawAndCall(
        bytes32 externalId,
        bytes memory contractAddress,
        address targetZRC20,
        uint256 outputAmount,
        bytes memory receiver,
        bytes memory message
    ) internal {
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
    }
```

### External Pre-conditions

The `onRevert` call also should revert.

### Impact

If a cross-chain call and `onRevert` both fail, the refunded ZRC-20 tokens are sent to `address(0)` (burned), permanently locking user funds and resulting in **loss of user refunds**.


### Mitigation
Pass `GatewayCrossChain` and `GatewayTransferNative` address instead of address(0) as abort address
