# Incorrect validation amount in gas-swap causes legitimate cross-chain transactions to fail

### Summary

An incorrect validation check using the maximum slippage amount instead of the actual swapped amount will cause a failed transaction and loss of gas fees for users as a user will perform a cross-chain swap where the total amount is only slightly larger than the gas fee required.

### Root Cause

* In [GatewayCrossChain.sol:329](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L329) the validation for remaining funds incorrectly uses `amountInMax` instead of the actual amount spent in the swap.
* In [GatewayTransferNative.sol:333](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L333) the same incorrect validation logic is present.

### Internal Pre-conditions

1. A user needs to initiate a swap where the `targetAmount` is greater than the estimated gas fee, but less than the estimated gas fee plus the slippage buffer (`amountInMax`).

### External Pre-conditions

1. Gas price on the destination chain needs to be high relative to the user's total swap amount, making the gas fee a significant portion of the transaction value.

### Attack Path

1. A user calls a function that triggers `_swapAndSendERC20Tokens` to perform a cross-chain swap. Let's say their available `targetAmount` is 100 tokens.
2. The contract calculates that 90 tokens are needed for the gas fee (`amountsQuote[0] = 90`).
3. With a e.g., 20% slippage setting, the contract calculates `amountInMax` to be 108 tokens (`amountInMax = 108`).
4. The swap for gas tokens executes successfully and might only cost 92 tokens (`amounts[0] = 92`).
5. The validation `require(targetAmount - amountInMax > 0)` is checked.
6. The check becomes `require(100 - 108 > 0)`, which is **false**, and the entire transaction reverts.

### Impact

The user cannot execute a valid cross-chain swap and loses the gas fees paid to initiate the failed transaction. This breaks the core functionality of the protocol for a subset of valid transactions.

### PoC

_No response_

### Mitigation

The validation check should use the actual amount returned from the swap, `amounts[0]`, instead of `amountInMax`.
```diff
- require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
+ require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");.
```
