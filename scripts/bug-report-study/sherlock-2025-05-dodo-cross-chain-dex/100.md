# USDT on Ethereum may not be supported

### Summary

USDT is also among the supported list in scope. However, USDT's approve function behave in a non-standard way, which requires allowance to be reduced to zero, before a new approval. The current implementation doesn't support it. 

### Root Cause

The `GatewaySend` contract will be deployed on all supported chains in scope, which includes Ethereum. By looking at how ERC20 transfers are handled, we can see [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L177):
```solidity
    function _handleERC20Deposit(
        address targetContract,
        uint256 amount,
        address asset,
        bytes memory message,
        RevertOptions memory revertOptions
    ) internal {
        IERC20(asset).approve(address(gateway), amount);

        gateway.depositAndCall(
            targetContract,
            amount,
            asset,
            message,
            revertOptions
        );
    }
```

After this approve call, it's not reduced back to 0. This contradicts with USDT's logic, which can be found [here](https://etherscan.io/address/0xdAC17F958D2ee523a2206206994597C13D831ec7#code).
