# Fixed Gas Limit Causes Cross-Chain Transaction Failures

### Summary

Fixed gas limit configuration will cause transaction reverts for users as the ZetaChain gateway will reject cross-chain operations when insufficient gas is allocated for complex swaps.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L253-L278


### Root Cause

In `GatewayTransferNative.sol:268` and `GatewayTransferNative.sol:275`, the contract uses a single fixed `gasLimit` value for all cross-chain operations regardless of operation complexity or destination chain requirements.

### Internal Pre-conditions

1. Admin needs to call `initialize()` to set gasLimit to a fixed value insufficient for complex operations
2. Contract needs to process operations with varying gas requirements (simple transfers vs complex swaps)
3. Contract needs to handle multiple chains with different gas costs (Bitcoin, Solana, EVM)


### External Pre-conditions

1. User needs to initiate complex swap operations requiring more gas than the fixed limit
2. ZetaChain gateway needs to enforce gas limit validation

### Attack Path

1. User calls `withdrawToNativeChain()` with complex swap data requiring high gas
2. Contract executes `withdrawAndCall()` with insufficient fixed gasLimit
3. ZetaChain gateway rejects the transaction due to inadequate gas allocation
4. Transaction reverts and user cannot complete cross-chain swap


### Impact

Users cannot execute complex cross-chain swaps when operations require more gas than the fixed limit. Protocol becomes unusable for multi-step operations while simple transfers waste gas through over-allocation.

### PoC

_No response_

### Mitigation

Implement dynamic gas estimation based on operation type and destination chain.
