# Memory Layout Error in `BytesHelperLib` Causes Incorrect Data Parsing

## Description
There is a critical error in the implementation of the `bytesToAddress()` and `bytesToUint32()` functions in the `BytesHelperLib` library. Both of these functions use incorrect offsets when reading data from memory, which leads to inaccurate data parsing. This issue occurs due to a misunderstanding of Solidity's memory layout for the `bytes` data type.

## Code Snippet
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/libraries/BytesHelperLib.sol#L12
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/libraries/BytesHelperLib.sol#L22

## Root Cause
The root of the problem lies in a misunderstanding of Solidity's memory layout for `bytes memory`. In Solidity, when bytes data is stored in memory, the storage structure is:
```solidity
[32 bytes length prefix] [actual data...]
 ^                       ^
 position 0-31           position 32 dst
```
Problematic part in `BytesHelperLib`:
```solidity
function bytesToAddress(
    bytes calldata data,
    uint256 offset
) internal pure returns (address output) {
    bytes memory b = data[offset:offset + 20];
    
    assembly {
        // ❌ WRONG! Reading from position 20, which is still in the length prefix area
        output := mload(add(b, 20))
    }
}

function bytesToUint32(
    bytes calldata data,
    uint256 offset
) internal pure returns (uint32 output) {
    bytes memory b = data[offset:offset + 4];
    
    assembly {
        // ❌ WRONG! Reading from position 4, which is still in the length prefix area
        output := mload(add(b, 4))
    }
}
```
Positions 0-31: Length prefix (32 bytes) which stores the length of the data and positions 32+: The actual data to be read. `mload(add(b, 20))` reads from positions 20-51, which mixes the length prefix with the data and `mload(add(b, 4))` reads from positions 4-35, which also mixes the length prefix with the data.

## Impact
Tokens sent to wrong or invalid addresses and incorrect parameter parsing cause reverts.

## Scenario
1. Data Initialization:
- Contract receives cross-chain message with target address: `0x1234567890123456789012345678901234567890`
- Data is encoded in bytes format
2. Calling bytesToAddress():
- Function `decodeMessage()` calls `bytesToAddress(message, 24)` to extract target address
- Slice data `data[24:44]` is fetched (20 bytes for address)
3. Memory Layout After Slice:
```diff
Position: [0-31]                    [32-51]
Content : [0x0000...0014]           [0x1234567890123456789012345678901234567890]
          ^length=20 in hex         ^actual address
```
4. Incorrect Assembly Read:
- `mload(add(b, 20))` reads from position 20-51
- Result: `0x0014123456789012345678901234567890123456` (contaminated data)
5. Impact on Transaction:
- Incorrect parsed address: `0x0014123456789012345678901234567890123456`
- Transaction sent to invalid address

## Recommendation
Use `mload(add(b, 32))` to read from the correct position.
```solidity
function bytesToAddress(
    bytes calldata data,        // Input data in calldata format (saves gas)
    uint256 offset              // Start reading position (in bytes)
) internal pure returns (address output) {
    // Extract 20 bytes from offset position to offset + 20
    // Ethereum addresses are always 20 bytes (160 bits)
    bytes memory b = data[offset:offset + 20];
        
    // Use assembly for efficient conversion
    assembly {
        // ✅ FIXED: mload(add(b, 32)) reads from correct position
        // Position 32 is the start of the actual data after the length prefix (32 bytes)
        // This takes 20 bytes of the address data we want
        output := mload(add(b, 32))
    }
}

function bytesToUint32(
    bytes calldata data,        // Input data is in calldata format
    uint256 offset              // Start reading position (in bytes)
) internal pure returns (uint32 output) {
    // Extract 4 bytes dari posisi offset sampai offset + 4
    // uint32 membutuhkan 4 bytes (32 bits)
    bytes memory b = data[offset:offset + 4];
        
    // Use assembly for efficient conversion
    assembly {
        // ✅ FIXED: mload(add(b, 32)) reads from correct position
        // Position 32 is the start of the actual data after the length prefix (32 bytes)
        // Then we shift right to get the desired 4 bytes
        output := shr(224, mload(add(b, 32)))
    }
}
```
