# GatewayTransferNative.withdrawToNativeChain() will revert if zrc20 is native ZETA

### Summary

`GatewayTransferNative._handleFeeTransfer()` function can not handle native tokens fee transfer.

The issue is that `GatewayTransferNative.withdrawToNativeChain()` can be called with `zrc20 == _ETH_ADDRESS_` (so that later it can be swapped in dodo for `targetZRC20`) but subsequent `_handleFeeTransfer()` will revert execution because it will try to call `TransferHelper.safeTransfer` with zrc20 token being native address.

### Root Cause

`GatewayTransferNative.withdrawToNativeChain()` allows user to swap native zeta token on dodo for `targetZRC20` token:
```solidity
function withdrawToNativeChain(
        address zrc20,
        uint256 amount,
        bytes calldata message
    ) external payable { //@< payable
        if(zrc20 != _ETH_ADDRESS_) {
            require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
        } 
...
// Swap on DODO Router
        uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
```
The `_doMixSwap()` then calls `DODORouteProxy.mixSwap()` with msg.value supplied:
```solidity
return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            ...
        );
```
However, prior to that the `withdrawToNativeChain` [tries to deduct fees from `zrc20`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L551-L552) in `_handleFeeTransfer()` internal function:
```solidity
uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        amount -= platformFeesForTx;
```

The issue is that `_handleFeeTransfer()` calls the `TransferHelper.safeTransfer` on the `zrc20` function and will revert if `zrc20 == _ETH_ADDRESS_`:
```solidity
function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```
And the `TransferHelper` lib:
```solidity
function safeTransfer(address token, address to, uint value) internal {
        // bytes4(keccak256(bytes('transfer(address,uint256)')));
        (bool success, bytes memory data) = token.call(abi.encodeWithSelector(0xa9059cbb, to, value));
        require(success && (data.length == 0 || abi.decode(data, (bool))), 'TransferHelper: TRANSFER_FAILED');
    }
```

The revert will happen even if `feePercent` is zero, because it will still try to call `safeTransfer` on native token address.

Thus, any meaningful interaction with native token through `GatewayTransferNative.withdrawToNativeChain()` will revert with dos.

### Internal Pre-conditions

1. Users try to call `withdrawToNativeChain()` with native token.

### External Pre-conditions

None.

### Attack Path

See internal pre-conditions.

### Impact

DoS of meaningful interaction with native token through `GatewayTransferNative.withdrawToNativeChain()`.

### PoC

_No response_

### Mitigation

In `GatewayTransferNative._handleFeeTransfer` check if `zrc20` is native token and call with `safeTransferETH`:
```diff
function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
+       if (zrc20 == _ETH_ADDRESS_) {
+           TransferHelper.safeTransferETH(EddyTreasurySafe, platformFeesForTx);
+       } else { 
            TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
+       }
    }
```
