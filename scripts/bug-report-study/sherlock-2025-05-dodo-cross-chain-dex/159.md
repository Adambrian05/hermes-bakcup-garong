# Attacker can drain unrelated token balances from GatewayCrossChain and steal user or treasury funds

### Summary

Because `_doMixSwap` trusts the user-supplied `params.fromToken` and `params.fromTokenAmount`, the function approves and swaps whatever token the attacker names instead of the token that was actually deposited. This allows an attacker to drain any ERC-20/ZRC-20 that the contract is holding for the protocol or other users.

### Root Cause

In `GatewayCrossChain.sol` the contract never checks that the token/amount inside the cross-chain message matches the incoming deposit:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L346

```solidity
// GatewayCrossChain._doMixSwap
IZRC20(params.fromToken).approve(DODOApprove, amount);      // approves attacker-chosen token
return IDODORouteProxy(DODORouteProxy).mixSwap(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount,                              // pulls attacker-chosen amount
        ...
);
```

The helper that decodes the message (`SwapDataHelperLib.decodeCompressedMixSwapParams`) simply copies `fromToken` and `fromTokenAmount` from calldata; it performs no validation.

All other parts of the contract (fee accounting, refund tracking, withdrawals) are written with explicit token checks; allowing a message to redirect approvals to an arbitrary token contradicts that pattern.



### Internal Pre-conditions

1. **Protocol** (or previous users) must already have left a non-zero balance of some token **B** inside `GatewayCrossChain` (e.g., unclaimed refunds, mis-routed fees, dust).
2. **Attacker** deposits token **A** (any supported ZRC-20) to trigger `onCall`.

### External Pre-conditions
NA
### Path

1. Attacker deposits token A (`zrc20`) with amount **X** and crafts the cross-chain message so that

   * `params.fromToken = token B` (which the contract already holds)
   * `params.fromTokenAmount = Y` (≤ contract’s balance of B).
2. `onCall` subtracts platform fee, then calls `_doMixSwap`.
3. `_doMixSwap` executes

   * `approve(token B, amount=X)` — giving the DODO router allowance over token B.
   * `mixSwap(..., Y, …)` — router pulls **Y** of token B from the contract and swaps it to the attacker’s chosen asset.
4. Contract ends up short **Y** of token B; attacker receives the proceeds on any chain they like.

### Impact

`GatewayCrossChain` (and therefore its users and treasury) can lose **all** of whatever ERC-20/ZRC-20 balances are accidentally or temporarily held by the contract; the attacker gains the same amount. Loss is unbounded up to the total idle balances.

### Mitigation

* **Validation:** Before calling `_doMixSwap`, add strict checks:

  ```solidity
  require(params.fromToken == zrc20, "FROM_TOKEN_MISMATCH");
  require(params.fromTokenAmount == amount, "AMOUNT_MISMATCH");
```
