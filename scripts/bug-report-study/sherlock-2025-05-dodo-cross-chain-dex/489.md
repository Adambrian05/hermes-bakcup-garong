# `GatewaySend::onRevert()`  is invalid in the revert process when user deposits native tokens through GatewaySend

### Summary

If the incoming cross-chain transaction(Connected Chain → ZetaChain ) fails to call `onCall()` function in zetachain, the zetachain will start a revert process and return all the ERC20 token/native token back to the revert address in the the connected chain, which in the case of `dodo cross chain dex` will be the `GatewaySend`. However the `GatewaySend::onRevert()`  only includes the situation of returning ERC20 token, and miss the situation of returning ETH or other native token.

### Root Cause

If the incoming cross-chain transaction starts a revert process of returning native token, the protocal will call `GatewayEVM::executeRevert()` to send native tokens and call `GatewaySend::onRevert()`.
```solidity
    /// @notice Transfers msg.value to destination contract and executes it's onRevert function.
    /// @dev This function can only be called by the TSS address and it is payable.
    /// @param destination Address to call.
    /// @param data Calldata to pass to the call.
    function executeRevert(
        address destination,
        bytes calldata data,
        RevertContext calldata revertContext
    ) public payable nonReentrant onlyRole(TSS_ROLE) whenNotPaused {
        if (destination == address(0)) revert ZeroAddress();
        (bool success, ) = destination.call{value: msg.value}("");
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext);

        emit Reverted(destination, address(0), msg.value, data, revertContext);
    }
```

However,`GatewaySend::onRevert()` [only handles the ERC20 token transaction.](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404)
```solidity
    /**
     * @notice Function called by the gateway to revert the cross-chain swap
     * @param context Revert context
     * @dev Only the gateway can call this function
     */
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```

`GatewayEVM::executeRevert()` will definitely revert because no ERC20 token is transfered and `context.asset` is a zero address.


### Internal Pre-conditions

Incoming revert process starts, and `GatewayEVM` calls `GatewaySend::onRevert()`

### External Pre-conditions

A user call `GatewaySend::depositAndCall()` with a native token.

### Attack Path

None

### Impact

 `GatewaySend::onRevert()`  is invalid in the revert process when user deposits native tokens through GatewaySend.
And user will only have to claim their assets of zrc20 in zetachain after `onAbort()` is called

### PoC

_No response_

### Mitigation

Add a check for `context.asset`, if the address is a zero address, transfer the native token to receiver.
