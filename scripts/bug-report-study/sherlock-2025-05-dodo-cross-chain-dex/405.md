# Incorrect Fee Deduction During Swap in `onCall` Function

### Summary

In the `onCall` function of `GatewayTransferNative`, platform fees are correctly deducted via `_handleFeeTransfer`, but the `amount `passed to the `_doMixSwap `function (when `decoded.targetZRC20 != zrc20`) is not adjusted to exclude those fees. This leads to the swap being executed with a wrong amount, potentially causing swap failures, or overdrawn balances.

### Root Cause

The `amount `variable, which includes the fee portion, is passed directly to the `_doMixSwap `function. However, since a portion of the `amount `is transferred out as platform fees before the swap, the contract no longer has the full `amount` available to perform the swap.

### Impact

- Transaction may revert due to insufficient funds if there is no balance prior to the `onCall`.
- Users may receive funds without fees being deducted, causing an overdraw of funds which can disrupt other contract functions relying on accurate accounting.

### Mitigation

Use the net amount (after fee deduction) in the `_doMixSwap `call:

```diff
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
