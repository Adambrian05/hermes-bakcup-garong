# Slippage Calculation Error - Improper Application of Basis Points

## Description / Vulnerability Detail
There is an error in the implementation of slippage tolerance calculation in the `_swapAndSendERC20Tokens` function. The contract uses a basis point system that is not in accordance with industry standards. In this section `uint256 public slippage;` slippage is declared in basis points, but the implementation uses a divisor of 1000 instead of 10000 which is the standard basis point.

This issue causes inaccurate slippage protection and can harm users or cause unexpected transaction failures.

## Code Snippet
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L36
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L319

## Root Cause
The root of the problem lies in an improper implementation in the `_swapAndSendERC20Tokens` function in the following line:
```solidity
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
//                                                                    ^^^^
//                                                              Wrong divisor!
```
The problem is in this section `uint256 public slippage;` slippage is declared in basis points but the implementation does not use the standard basis points, namely using a divisor of 1000 instead of 10000 (standard basis points). The same system (divisor of 1000) is used for fee calculation, which shows that the contract uses a custom system instead of standard basis points.

Problematic section:
```solidity
uint256 public slippage; // Slippage tolerance for swaps (in basis points)

// Wrong implementation
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
```

## Impact
Users may receive far fewer tokens than expected.

## Scenario
1. Setup: The system sets `slippage = 50` assuming it is 0.5% (50 basis points)
2. Expectation: The user expects a slippage tolerance of 0.5%
3. Reality: With a divisor of 1000, the slippage becomes 5% (50/1000 = 0.05 = 5%)
4. Impact: The user receives far fewer tokens than expected because the slippage is too loose

## Recommendation
Use standard basis points (divisor 10000).
```solidity
// ✅ FIX: Use standard basis points (10000 divisor)
// Example: if slippage = 50 (0.5%), then tolerance = 50/10000 = 0.005 = 0.5%
uint amountInMax = amountsQuote[0] + (slippage * amountsQuote[0]) / 10000;
```
