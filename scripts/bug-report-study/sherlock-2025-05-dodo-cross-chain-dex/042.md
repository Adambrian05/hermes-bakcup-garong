# GatewaySend contract does not support USDT

### Summary

According to the docs, the protocol only integrates tokens that are included in ZetaChain’s [supported assets list](https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets:~:text=ETH%20Mainnet-,USDT.ETH,-ERC20), which includes USDT.
However, the issue with USDT is that its `transfer` function does not return a value, while the `GatewaySend.sol` contract assumes a bool return value. This mismatch will cause the calls to revert.

### Root Cause

In both `depositAndCall()` functions [GatewaySend.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L316) contract uses this way to handle token transfers:
```solidity
require(
    IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
    "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
);
```
This will revert when user will try to use USDT because this token does not return anything on transfers.

### Internal Pre-conditions

1. User calls `depositAndCall()` with USDT
