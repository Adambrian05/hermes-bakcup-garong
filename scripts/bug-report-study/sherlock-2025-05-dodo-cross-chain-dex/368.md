# Attacker can drain the funds of user from the GatewayTransferNative and GatewayCrossChain contracts

### Summary

Attacker can drain the funds of user, whose cross-chain transactions got reverted, from both [`GatewayTransferNative`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol) and [`GatewayCrossChain`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol) contracts.

### Root Cause

The function [`GatewayTransferNative::claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) (or [`GatewayCrossChain::claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590)) can be called by anyone with the correct `externalId`, which maps to the appropriate asset of the user for cross-chain transaction reversion.

Attacker can see the reverted cross-chain transaction and extract the `externalId` of the user or he can also read the data of mapping based upon the slot position of mapping `refundInfos` within the contract. Once attacker gets the `externalId`'s of the mapping then attacker calls the `claimRefund` function and claim all the tokens within that associated user funds.

In the below code of [`GatewayCrossChain::onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L517-L548) function, we can see that [`rewardInfos`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L539) mapping get set only if the revert message is not equal to 52 bytes. And also the `claimRefund` function also been called for the user (whose cross-chain transaction got reverted) with more than 52 bytes of the revert message, which mean more than 20 bytes will be in the [`walletAddress`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L520) variable. So, the `if` check in the code will get pass because wallet address bytes only check for 20 bytes of more than 20 bytes `walletAddress`.

### Internal Pre-conditions

- Assumes the mapping `refundInfos` non-empty and some user cross-chain transactions got reverted with more than 52 bytes revert message 

### External Pre-conditions

N/A

### Attack Path

Because of the flaw in the function logic, attacker can call the `claimRefund` function with known `externalId`, which being either extracted from the slot data or may extract it from by watching the mempool of the call that goes to `onRevert` or `onAbort` function of `GatewayCrossChain` and `GatewayTransferNative`. And leave with the funds of the user, ultimately loses funds of user

### Impact

The impact is HIGH, because the funds of user get been drained by the attacker because of the flaw in the contract function logic.

### Mitigation

Make sure to get the wallet address from the remaining bytes of the revert message and store re convert it into 20 bytes of wallet address, such that the function `claimRefund` can only be called wither by bot or the user whose cross-chain transaction got reverted.
