# Incorrect Swap Amount After Fee Deduction

### Summary

Incorrect fee handling will cause transaction reverts for users as the contract will attempt to swap tokens using an amount that exceeds the available balance after platform fees have already been transferred.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L370-L395

### Root Cause

In `GatewayTransferNative.sol:370-395` the platform fees are deducted from the contract balance via `_handleFeeTransfer()`, but then the full original `amount` is passed to `_doMixSwap()` instead of the reduced amount (`amount - platformFeesForTx`).


### Internal Pre-conditions

1. `onCall()` needs to be called with `decoded.targetZRC20 != zrc20` (requiring a token swap)
2. Platform fee percentage (`feePercent`) needs to be greater than 0

### External Pre-conditions

None

### Attack Path

1. Gateway calls `onCall()` with tokens that require swapping (different input/output tokens)
2. Contract deducts platform fees via `_handleFeeTransfer()`, transferring fees to treasury
3. Contract attempts to call `_doMixSwap()` with the original full `amount`
4. Transaction reverts due to insufficient token balance in the contract


### Impact

Swaps revert when platform fees are enabled, breaking cross-token transfers and blocking user transactions.










### PoC

_No response_

### Mitigation

```diff
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
