# Platform Fee Bypass in Zeta Swap Execution

### Summary

Inconsistent use of `msg.value` vs fee-adjusted `amount` will cause a platform fee bypass for the protocol as the swap execution uses the full `msg.value` while platform fees were already deducted from the `amount` parameter.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L449

### Root Cause

In `_doMixSwap()` at line 425, the function uses `msg.value` for the swap execution, but the platform fees were already deducted from the `amount` parameter in `withdrawToNativeChain()`, effectively allowing users to swap the full deposited amount without paying platform fees.

![Image](https://sherlock-files.ams3.digitaloceanspaces.com/gh-images/80bee9e0-2d65-4c04-8204-b3da45914909)


### Internal Pre-conditions

1. User needs to call `withdrawToNativeChain()` with `zrc20` set to `_ETH_ADDRESS_`
2. User needs to send Zeta via `msg.value`

### External Pre-conditions

None

### Attack Path

1. User calls `withdrawToNativeChain()` with `zrc20 = _ETH_ADDRESS_` and `msg.value = 100 Zeta`
2. Platform fee is calculated and deducted: `amount = 100 Zeta - platformFee`
3. The `_doMixSwap()` function ignores the fee-adjusted `amount` and uses full `msg.value` (100 Zeta) for the swap
4. User swaps the full 100 Zeta while the protocol loses the platform fee

### Impact

The protocol suffers a loss of all platform fees on Zeta transactions. Users effectively swap their full Zeta deposits without paying any platform fees.
