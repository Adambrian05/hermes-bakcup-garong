# Incorrect post-swap check in `_swapAndSendERC20Tokens` can make successful withdrawals revert

### Summary

the code compares the maximum swap cost instead of the actual swap cost in`_swapAndSendERC20Tokens`, which will cause valid swaps to revert.

### Root Cause

In `GatewayCrossChain._swapAndSendERC20Tokens`, the contract calculates `amountInMax` using slippage and compares it to `targetAmount`:
```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
but This line should compare against the actual input `amounts[0]`.

If the swap is done at a better-than-expected price (ie `amounts[0] < amountInMax`) and `slippage > 0`, the require fails and the transaction reverts while it should go through.

### Internal Pre-conditions

-slippage is non-zero.
-swap executes at a better price than expected.
-swap is of low value

### External Pre-conditions

Normal market movement - better priced swap are common

### Attack Path

1- Alice makes a cross-chain swap and receives `8.5 USDC` as `targetAmount` from the swap.
2- The contract estimates the required gas fee as `8 USDC`, then applies a `10% slippage`, resulting in `amountInMax = 8.8 USDC`.
3- The contract checks `8.5 - 8.8 > 0`, which fails and reverts, even though the actual gas spent was only `8 USDC`, and `8.5 - 8 = 0.5 > 0` would have passed.



### Impact

No funds lost, but incorrect functionality as the whole cross swap incorrectly reverts while the conditions are good.

### PoC

N/A

### Mitigation

Compare to `amounts[0] ` instead: 
```solidity
require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
