# Missing setter for `gasLimit` in `GatewayCrossChain` can cause protocol to lose yield.

## Vulnerability Details 

In `GatewayCrossChain`, the protocol establishes a fixed `gasLimit` during the contract's initialization. The problem occurs due to the absence of a setter for the `gasLimit`. Consequently, when the protocol needs to modify the `gasLimit` to facilitate transactions, it is unable to do so, leading to potential losses in platform fees.

Given that the `gasFee` retrieved on Zetachain can vary, one possible scenario is that if the `gasLimit` is excessively high, users may refrain from engaging with the protocol unless protocol can reduce the `gasLimit` to facilitate transactions. This decline in user interaction ultimately results in a decrease in platform fees for the protocol.

In `GatewayCrossChain`

## POC

Consider the following scenario

1. A user notices that the gas limit is set to 1 million wei, while their transaction only requires 500k wei.
2. The user is reluctant to engage with the protocol due to the excessively high gas limit.
3. The protocol lacks a mechanism to modify the gas limit.
4. As a result, the protocol misses out on platform fees, which represent a percentage of the amount the user intends to withdraw to the destination chain.

## Root Cause

Lack of setter to modify static `gasLimit` variable

## Impact

Loss in yield for protocol

## Mitigation

Add a setter for `gasLimit` variables
