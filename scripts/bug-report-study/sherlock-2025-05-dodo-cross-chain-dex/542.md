# `onCall()` uses deprecated transfer() method instead of call() to send ETH

### Summary

The `onCall()` function in `GatewaySend` contract, uses Solidity’s transfer() method to send ETH to an arbitrary EVM address (evmWalletAddress). This approach is outdated and potentially unsafe because it only forwards a fixed amount of 2300 gas and can make the transaction fail and will cause DoS.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L370

`GatewaySend::onCall()` uses deprecated transfer() method instead of call() => return true pattern in order to send ETH

### Impact

the transaction might fail when:

1. The claimer smart contract does implement a payable fallback which uses more than 2300 gas unit.
2. The claimer smart contract implements a payable fallback function that needs less than 2300 gas units but is called through proxy, raising the call's gas usage above 2300.
3. using higher than 2300 gas might be mandatory for some multi-signature wallets.
4. Potentially, the gas cost of EVM instructions may change significantly during hard forks which may break already deployed contract systems that make fixed assumptions about gas costs, E.g. EIP 1884 broke several existing smart contracts due to a cost increase of the SLOAD instruction.

### Mitigation

use `safeTransferETH()` function from "TransferHelper.sol" library:

```diff
    function onCall(
        MessageContext calldata /*context*/,
        bytes calldata message
    ) external payable onlyGateway returns (bytes4) {
        
        ...
        
        if(toIsETH) {
-            payable(evmWalletAddress).transfer(outputAmount);
+            TransferHelper.safeTransferETH(evmWalletAddress, outputAmount);
        } else {
            IERC20(toToken).transfer(evmWalletAddress, outputAmount);
        }
        
        ...

        return "";
    }
```
