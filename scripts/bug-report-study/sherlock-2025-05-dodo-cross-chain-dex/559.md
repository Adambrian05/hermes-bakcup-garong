# Anyone can use the ZetaChain gateway to trigger `onCall` and drain contract-held tokens

### Summary

The `onCall `functions in both `GatewayTransferNative `and `GatewayCrossChain `contracts rely solely on the `onlyGateway `modifier, which checks that the caller is the ZetaChain gateway contract. However, the ZetaChain gateway is a public contract that can be called by anyone. This means any user can instruct the gateway to call `onCall `on these contracts with arbitrary parameters, allowing them to transfer out tokens held by the contracts (such as unclaimed refunds) to any address, resulting in a loss of funds for users.



### Root Cause

In both the `GatewayTransferNative `and `GatewayCrossChain `contracts, the `onCall `function is protected only by the `onlyGateway `modifier, which restricts access to calls coming from the ZetaChain gateway contract. However, the ZetaChain gateway is a public contract that allows any user to trigger cross-chain calls by specifying arbitrary target contracts and calldata. As a result, any user can instruct the gateway to call `onCall `on these contracts with attacker-controlled parameters.

Inside `onCall`, the contracts do not verify that the tokens being transferred out were actually deposited for the current cross-chain transaction. Instead, they trust that the gateway has already transferred the expected tokens to the contract and proceed to transfer tokens held by the contract (such as unclaimed refunds or previously deposited tokens) to the recipient specified in the attacker-controlled calldata. There is no check to ensure that the contract's token balance increased as a result of the current transaction, nor is there any mechanism to tie the outgoing transfer to a legitimate deposit.

This design allows any user to use the gateway as a relay to call `onCall `and drain tokens held by the contract, including user refunds, by specifying arbitrary recipients and amounts. The contracts' reliance on the gateway as a trusted intermediary is insufficient, as the gateway itself does not enforce any restrictions on who can initiate calls or how they are routed.

### Internal Pre-conditions

1. The contract holds tokens (e.g., from previous reverted transactions or unclaimed refunds).
2. The ZetaChain gateway contract is deployed and callable by anyone.

### External Pre-conditions

An attacker is able to call the ZetaChain gateway contract and make it call `onCall `on the current contract with arbitrary parameters.


### Attack Path

1. The contract holds tokens (e.g., from a reverted transaction).
2. The attacker calls the ZetaChain gateway, instructing it to call `onCall `on the contract, specifying a recipient and amount.
3. The contract, trusting the gateway, transfers out the tokens to the attacker's chosen address.
4. The attacker drains tokens that should have been claimable only by the legitimate user.

### Impact

Any user can drain all tokens held by the contract, including user refunds, resulting in loss of funds for users and a complete breakdown of trust in the protocol.

### PoC

_No response_

### Mitigation

Implement additional checks in `onCall `to ensure that only tokens deposited for the current cross-chain transaction can be transferred out.
