# No Withdraw OnlyOwner funtionality in `gatewaySend`: ETH Can Get Permanently Stuck

### Summary

The `gatewaySend` contract can **receive ETH** via `receive()` and `fallback()`, but provides **no withdrawal or recovery function**. If ETH is accidentally sent, or get stuck due to cross-chain failure scenarios, they become **permanently locked**, as `gatewaySend` has no `withdraw()` `onlyOwner` sweep function. This breaks fund safety assumptions and undermines recoverability.


### Root Cause

1. `gatewaySend` defines:

   ```solidity
   receive() external payable {}
   fallback() external payable {}
   ```

   * Accepts arbitrary ETH transfers.

2. **No function exists** to withdraw ETH:

   * No `withdrawETH()`, or `onlyOwner` fund recovery logic.
   * Once ETH enter in this contract through these functions, they cannot be removed.

### Attack Path

1. Simulate failed ETH call:

   * Use a contract address as `evmWalletAddress` with no `receive()`
   * Trigger `onCall()` with ETH — it fails, and ETH is retained in `gatewaySend`.
2. Check contract balance.
   ```solidity
   gatewaySend.balance // ETH > 0
   ```

3. Try calling any public function to withdraw ETH — **none exist**.

### Impact

* Any ETH accidentally or programmatically sent to `gatewaySend` becomes **unrecoverable**

* High likelihood of real stuck funds from:
   * **Failed ETH transfer** in `onCall()` (e.g., recipient is a contract without fallback)
   * Refund logic like `onRevert()` or `onAbort()` does not successfully refund ETH.
   * Accidental transfers to `gatewaySend` address.

### Mitigation

Consider having this function as a backup

```solidity
function withdrawETH(address to, uint256 amount) external onlyOwner {
    (bool success, ) = to.call{value: amount}("");
    require(success, "Withdraw failed");
}
```
