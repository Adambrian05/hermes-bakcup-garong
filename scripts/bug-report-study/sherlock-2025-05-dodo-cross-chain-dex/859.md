# Refund information can be unauthorizedly updated

### Summary

The flaw in the integration with Zetachain gateway can cause the traders' refund information to be unauthorizedly updated

### Root Cause

The function `GatewayCrossChain::onAbort()` and `GatewayNativeTransfer::onAbort()` is expected to handle the failed cross chain swap from connected chain, especially the abort cases. This is because the `abortAddress` is [set to the contract address of `GatewayCrossChain` and `GatewayNativeTransfer` on `GatewaySend::depositAndCall()` function](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L248C1-L255C12).

According to [Zetachain's docs on revert transactions](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions), the incoming transaction (swap from connected chain -> zetachain) is aborted when
> If the amount is insufficient or zero (for example, when it's a no-asset call) the Gateway calls onAbort on the abortAddress on ZetaChain.

and for outgoing transaction
> If the onRevert call itself reverts, the Gateway transfers ZRC-20 tokens to and calls onAbort on the abortAddress on ZetaChain.

Besides, these contracts `GatewayCrossChain` and `GatewayNativeTransfer` can be called by Zetachain's gateway without any further checks. This means that an arbitrary arbitrary calls from connected chain can trigger the function `onCall()` on these contracts. 

Combining the above points, it is possible for an attacker to trigger the function `onAbort()` in these contracts. For example
1/ An attacker prepares his malicious contract on connected chain
2/ The contract calls to Zetachain's `GatewayEVM` with
```solidity
gateway.depositAndCall(
            GatewayTransferNative_address,
            small_amount,  // << to be insufficient for gas fee
            asset,
            message,
            revertOptions ({... abortAddress: GatewayTransferNative_address, revertMessage: malicious_payload})
        );
```
with `malicious_payload` can `valid_externalId.concat(attack_address)`
3/ When Zeta's `GatewayZEVM` calls `GatewayTransferNative::onCall()`, the `amount` is insufficient => `onAbort()` is triggered with the malicious payload
4/ The function uses the information in the payload to track the refund info ==> The refund info for `valid_externalId` will be override with `small_amount` ==> effectively erase the refund information of the valid trader


**Note**: the same pattern can happen when processing cross chain swap from Zetachain to connected chain, such that the function `onRevert()` is unauthorizedly executed in these contracts on Zetachain
