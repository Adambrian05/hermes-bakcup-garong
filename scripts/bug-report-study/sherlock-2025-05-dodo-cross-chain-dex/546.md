# SwapDataZ parameters in `GatewayCrossChain` and `GatewayTransferNative` are not verified resulting in attacker being able to steal user refunds

## Summary

The `swapDataZ` parameters (specifically `fromToken`) are not properly verified, allowing any attacker to manipulate the `fromToken` parameter to point to any valid ZRC20 token present in `GatewayTransferNative` or `GatewayCrossChain` contracts. This enables attackers to swap the entire balance of any `fromToken` to their desired `toToken` and withdraw the funds to a native chain.

## Root Cause

The `params.fromToken` parameter is not verified to match the token that `msg.sender` (user/GatewayZEVM) actually provided:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337-L361

```solidity
function _doMixSwap(
    bytes memory swapData,
    uint256 amount,
    MixSwapParams memory params
) internal returns (uint256 outputAmount) {
    if (swapData.length == 0) {
        return amount;
    }
    IZRC20(params.fromToken).approve(DODOApprove, amount);
    return
        IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken, //@audit ==> fromToken is not verified 
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
}
```

### Additional Issues

1. **Unverified `fromTokenAmount`**: The `fromTokenAmount` parameter is not validated against the actual amount of tokens the user provided.

2. **Approval Bypass**: Although `IZRC20(params.fromToken).approve(DODOApprove, amount)` prevents `mixSwap` from spending more than the specified `amount`, an attacker can exploit this by:
   - Setting `fromToken` to a ZRC20 token with lower decimals than the token originally supplied to `GatewayCrossChain::onCall` or `GatewayTransferNative::withdrawToNativeChain`, or a token with equal
   decimals but lower value
   - This provides the `DODORouter` with sufficient allowance to spend the entire `fromTokenAmount` from the gateway contracts
   - The `fromTokenAmount` can represent the entire refund balance held by `GatewayTransferNative` or `GatewayCrossChain`:

3. **Unauthorized Fund Transfer**: After the swap completes, the `outputAmount` represents the result of swapping the entire user refund balance for `params.toToken`, which is then transferred to the attacker.

// Swap on DODO Router
uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
// @audit funds sent to attacker
if (decoded.targetZRC20 == WZETA) {

### Internal Pre-conditions
- ZRC20 token balance of `GatewayTransferNative` or `GatewayCrossChain` must be greater than 0

### External Pre-conditions
- Cross-Chain Transaction (CCTX) on destination chains (non-EVM) reverts and `onRevert` is called
- Attacker front-runs legitimate users with higher gas fees to withdraw refunds from the contract

### Attack Path

**Step-by-Step Attack Path:**

1. **Setup**: There are **10,000 USDT** (`10,000,000,000` with 6 decimals) sitting in the contract as user refunds

2. **Malicious Call**: Attacker calls `GatewayTransferNative::withdrawToNativeChain` with:
   - `zrc20` parameter set to `ETH`
   - `amount` parameter set to `10,000,000,000 wei` of ETH

3. **Token Transfer**: `10,000,000,000 wei` of ETH is [transferred](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L535-L537) from the attacker to the contract

4. **Malicious Approval**: In `_doMixSwap`, the DODORouter is [approved to spend `10,000,000,000` USDT (`params.fromToken`) from the contract](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L434) instead of the ETH that was actually deposited

5. **Unauthorized Swap**: DODORouter swaps `params.fromTokenAmount` (`10,000,000,000`) **USDT** for `params.toToken` (`ETH`)

6. **Profit Calculation**: `outputAmount` is set to approximately `4 ETH` (assuming ETH price of $2,500)

7. **Fund Extraction**: `_handleEvmOrSolanaWithdraw` is called and all swapped tokens are withdrawn to the attacker's native chain address (`decoded.receiver`)

## Impact

- **Complete theft of user refund balances** stored in the gateway contracts
- **Loss of funds** belonging to legitimate users whose transactions were reverted
- **Manipulation of cross-chain swap parameters** without proper validation
- **Potential for systematic drainage** of contract balances across multiple tokens

## Recommended Mitigation

Implement the following security measures:

1. **Verify Token Consistency**: Ensure that `params.fromToken` matches the `zrc20` argument provided in `GatewayCrossChain::onCall` or `GatewayTransferNative::withdrawToNativeChain`

2. **Validate Token Amount**: Verify that `params.fromTokenAmount <= amount` to prevent over-spending

3. **Verify Target Token**: Ensure that `params.toToken == decoded.targetZRC20`
