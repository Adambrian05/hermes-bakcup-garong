# Incorrect Fee Deduction in onCall Function Leads to Protocol Loss

### Summary

The onCall function in the GatewayTransferNative contract mishandles platform fees (platformFeesForTx) during swap transactions. While fees are correctly deducted and sent to the treasury in the "same token" transfer path (when decoded.targetZRC20 == zrc20), the swap path (the else branch) fails to subtract these fees from the input amount before calling _doMixSwap. As a result, the full input amount, including fees, is used for the swap, leading to users receiving more output tokens than intended and causing revenue loss for the protocol. If the protocol lacks sufficient funds, the swap transaction reverts, disrupting functionality.

### Attack Path

A user initiates a cross-chain swap by depositing 500 DAI, with a 0.5% platform fee (2.5 DAI). The _handleFeeTransfer function correctly sends the 2.5 DAI fee to the treasury. However, due to the bug, _doMixSwap processes the full 500 DAI instead of the correct 497.5 DAI (after fee deduction). Assuming a swap rate of 0.9x to USDC, the user receives 450 USDC (500 DAI * 0.9) instead of the expected 447.75 USDC (497.5 DAI * 0.9), gaining an extra 2.25 USDC. This overpayment comes at the protocol’s expense. If the protocol lacks sufficient funds to cover the swap, the transaction fails, forcing the user to retry or seek a refund, which disrupts the user experience

### Impact

Users receive additional tokens equivalent to the fee amount, reducing the protocol’s revenue. And also dos could also happens  ,if there is insufficient funds
