# Slippage is not set when users withdraw ZETA to spoke chains

### Summary

`onCall()` and `withdrawToNativeChain()` is used by the gateway to handle withdrawals to EVM, Solana and Bitcoin chains respectively, however due to a missing slippage protection, the user may end up receiving less token forcing the user to accept a loss.

The `gasFee` here is estimated using the `withdrawGasFeeWithGasLimit()` on source chain considering the set `gasLimit`

Per the [ZETA Docs](https://www.zetachain.com/docs/developers/evm/gas/#outgoing-calls-and-withdrawals)
> `gasFee` is the required amount for the specified gas limit.

The problem is that gas fees can be volatile on the destination chain  and thus user will not be  receiving `outputAmount - gasFee` in the destination chain after accounting for the gas fees off chain becuase extra funds may be removed from the resulting difference of `outputAmount - gasFee`. Hence the transferred token amounts to a recipient/dapp in the destination chain might not be enough to execute the required transaction in the dapp `gasFee` not being enough to complete the transaction. This will create unintended and uncertain behaviour for the user withdrawal transactions which could lead to even DoS in the destination chain which will degrade the end user experience.

Another issue is that In such instance where the gas ffee increase in the destination chain, [`_swapAndSendERC20Tokens()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L413) function can revert because the the gas fee can exceed the approval given initially below on L331  (especially is in situation where the user doesn't mind slippage)

### Internal Pre-conditions

NIL

### External Pre-conditions

Gas fee increases in the destination chain due to traffic congestion

### Attack Path

See root cause section

### Impact

Possible 
- loss of funds for user at the destination chain
- the withdrawal call could revert entirely leading to a DOS

### PoC

_No response_

### Mitigation

Consider allowing user to estimate their preferred gas limit especially when the fees are likely to be volatile on the destination chain
