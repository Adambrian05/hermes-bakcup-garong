# Unvalidated `swapData` parameters in `depositAndCall` allow theft of contract funds

### Summary

The `_doMixSwap` function blindly trusting a `swapData` payload will cause a direct theft of all tokens for the protocol as a malicious user will call `depositAndCall` with a nominal token amount but a malicious `swapData` payload, tricking the contract into swapping its own separate funds.

### Root Cause

- In [GatewaySend.sol:245](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L245) the `_doMixSwap` function is called with a `swapData` payload that is not validated against the function's `fromToken` and `amount` parameters.
- In [GatewaySend.sol:195-216](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L195-L216) the `_doMixSwap` function then decodes and trusts the parameters inside this `swapData` payload to perform the token swap, ignoring the validated inputs from the parent call.

### Internal Pre-conditions

- The GatewaySend.sol contract needs to hold any amount of any token. This can happen from a previously failed or reverted user transaction.

### External Pre-conditions

None

### Attack Path

1. Attacker sees that the GatewaySend.sol contract holds e.g., 10,000 USDC from a previous failed transaction.
2. Attacker crafts a `swapData` payload. The payload contains instructions to swap 10,000 USDC for another token.
3. Attacker calls the `depositAndCall` function. For the function arguments, they use a tiny amount of a different token (e.g., `fromToken = ATTACKER_TOKEN`, `amount = 1 wei`) and provide `swapData` from the previous step.
4. The contract checks and receives the 1 wei of ATTACKER_TOKEN from the Attacker, passing the initial validation.
5. The contract calls `_doMixSwap`, which decodes the malicious `swapData`. It now thinks it needs to swap 10,000 USDC.
6. `_doMixSwap` approves the router to spend the contract's 10,000 USDC.
7. The swap executes, and the resulting funds are sent to the Attacker's address on the destination chain.

### Impact

- Protocol suffers a loss of all tokens held within the GatewaySend.sol contract at the time of the attack.
- Attacker gains the full value of these stolen tokens.
- Users suffer a loss of tokens that were held by the contract after failed transactions.

### PoC

Add this function at the end of [test/GatewaySend.t.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewaySend.t.sol). Use `forge test --match-test test_Poc_UnauthorizedSwap`.
```solidity
function test_Poc_UnauthorizedSwap() public {
    address attacker = user1;
    uint256 contractFunds = 100 ether;
    token1A.mint(address(gatewaySendA), contractFunds);

    vm.startPrank(attacker);
    
    uint256 attackerPledgeAmount = 1 ether;
    token2A.mint(attacker, attackerPledgeAmount);
    token2A.approve(address(gatewaySendA), attackerPledgeAmount);

    bytes memory maliciousSwapData = encodeCompressedMixSwapParams(
        address(token1A),
        address(token2A),
        contractFunds,
        0,
        0,
        new address[](0),
        new address[](0),
        new address[](0),
        0,
        new bytes[](0),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );

    gatewaySendA.depositAndCall(
        address(token2A),
        attackerPledgeAmount,
        maliciousSwapData,
        address(gatewaySendB),
        address(token2A),
        1,
        ""
    );

    vm.stopPrank();

    assertEq(token1A.balanceOf(address(gatewaySendA)), 0);
}
```

### Mitigation

The `_doMixSwap` function should not decode the `fromToken` and `fromTokenAmount` from the `swapData` payload. Instead, `depositAndCall` should pass its own validated `fromToken` and `amount` parameters to `_doMixSwap` to use for the swap:
```diff
- function _doMixSwap(bytes calldata swapData) internal returns (uint256) {
+ function _doMixSwap(address fromToken, uint256 fromTokenAmount, bytes calldata swapData) internal returns (uint256) {
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);

-   if(params.fromToken != _ETH_ADDRESS_) {
-      IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
+   if(fromToken != _ETH_ADDRESS_) {
+      IERC20(fromToken).approve(DODOApprove, fromTokenAmount);
    }

    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
-       params.fromToken,
+       fromToken,
        params.toToken,
-       params.fromTokenAmount,
+       fromTokenAmount,
        params.expReturnAmount,
        params.minReturnAmount,
        params.mixAdapters,
        params.mixPairs,
        params.assetTo,
        params.directions,
        params.moreInfo,
        params.feeData,
        params.deadline
    );
}
```
