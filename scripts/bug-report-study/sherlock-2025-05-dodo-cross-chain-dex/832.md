# User funds get stuck inside either in TSS address or DoDoFeeRoute contract

### Summary

When user sends more ether to `GatewaySend` contract than required the excess amount get transferred to TSS address or DoDoFeeRoute contract

### Root Cause

The root cause for this is [`require`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L233-L236) statement in `GatewaySend::depositAndCall` function, because the contract allows more tokens than the required amount to transfer, the remaining funds get transferred to TSS address if there is no swap takes place in source chain, if not they get transferred to DoDoFeeRoute contract, as this is where swap happens in source chain.

This make user funds to stuck inside those address, which may make them loose those ether, as in the emit logs also there is only mention of `amount` in both the `GatewaySend` and `GatewayEVM` contract as see below emit events.

```solidity
// in GatewaySend contract
        emit EddyCrossChainSend(
            externalId,
            dstChainId,
            fromToken,
            asset,
            amount,
            outputAmount,
            msg.sender,
            message
        );

// in GatewayEVM contract
        emit DepositedAndCalled(msg.sender, receiver, amount, asset, payload, revertOptions);
```

### Attack Path

- user sends more ether than the amount provided in the parameter of deposit function in `GatewaySend` contract
- the funds either stuck inside TSS address or DoDoFeeRoute contract

### Impact

The impact is HIGH, because the funds either stuck inside the `DoDoFeeRoute` contract or in TSS address, and user need to approach the team to resolve this issue, and makes other users risky as their funds getting stuck because of over allowance allowed, which reduces credibility of protocol

### PoC

Replace the test case of `test_ANative2ZSwap` on [`GatewayTransferNative.t.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewayTransferNative.t.sol) file, and run forge test

```solidity
    function test_ANative2ZSwap() public {
        address targetContract = address(gatewayTransferNative);
        uint256 amount = 100 ether;
        uint32 dstChainId = 7000;
        address asset = _ETH_ADDRESS_;
        address targetZRC20 = address(token2Z);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = abi.encodePacked(user2);
        bytes memory swapDataZ = encodeCompressedMixSwapParams(
            address(token3Z),
            address(token2Z),
            amount,
            0,
            0,
            new address[](1),
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0),
            block.timestamp + 600
        );
        bytes memory payload = encodeNativeMessage(
            targetZRC20,
            sender,
            receiver,
            swapDataZ
        );

        // 1. user sends more ether than required for cross-chain transfer
        vm.startPrank(user1);
        gatewaySendA.depositAndCall{value: amount * 2}(
            targetContract,
            amount,
            asset,
            dstChainId,
            payload
        );
        vm.stopPrank();

        // 2. assets permanently locked inside the TSS address and user get only 100 ether on dest Chain
        assertEq(user1.balance, initialBalance - amount * 2);
        assertEq(token2Z.balanceOf(user2), 100 ether);
    }
```

### Mitigation

Add the require statement in such a way that use can strictly send the amount he provided in the parameters while calling the function
