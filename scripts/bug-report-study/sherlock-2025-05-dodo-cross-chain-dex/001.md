# Unsafe ERC20 Operation issues


## Summary
The IERC20.transfer() and IERC20.transferFrom() functions return a boolean value indicating success. This parameter needs to be checked for success. Some tokens do not revert if the transfer failed but return false instead.


## Root Cause
USDT tokens on the BSC Mainnet and ETH Mainnet are weird tokens that do not fully comply with interfaces such as IERC20.transfer(), IERC20.transferFrom(), and IERC20.approve().  

In the GatewaySend contract, IERC20 is used instead of SafeERC20, which will cause these weird tokens to encounter errors during calls and fail to complete cross-chain operations.

Weird tokens (like USDT) don't correctly implement the EIP20 standard and their transfer/ transferFrom function return void instead of a success boolean. Calling these functions with the correct EIP20 function signatures will always revert.

The GatewaySend contract contains multiple instances of IERC20.transfer(), IERC20.transferFrom(), and IERC20.approve()—all of which have this issue and require modification.
