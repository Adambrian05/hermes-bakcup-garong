# Attacker can steal all token through trick the `GatewaySend::depositAndCall` function

### Summary

Attacker can provide different `swapData.toToken` and `asset` address in `depositAndCall` function to steal all token from the protocol:

```solidity
    function depositAndCall(
        address fromToken,
        uint256 amount,
        bytes calldata swapData,
        address targetContract,
        address asset,
        uint32 dstChainId,
        bytes calldata payload
    ) public payable
```

### Root Cause

The code use the different param to indicate the exchange token. 
First, the code decode the user provided `swapData` and use DODO DEX to calculate the exact input token can get how much the output token:

<img width="879" alt="Image" src="https://sherlock-files.ams3.digitaloceanspaces.com/gh-images/54529b55-edf3-41bc-ac8c-ca1e22bbc976" />

As you can see, the target exchange token address is from the `swapData`, the code returns the `outputAmount`:

<img width="721" alt="Image" src="https://sherlock-files.ams3.digitaloceanspaces.com/gh-images/ae95ffb3-a05b-40da-83b8-8acbcede78ed" />

Then, the code use the `outputAmount` to handle deposit, but in this deposit, the code use the provided `asset` address not the target exchange token (from the `swapData`)

<img width="633" alt="Image" src="https://sherlock-files.ams3.digitaloceanspaces.com/gh-images/856245d7-e74f-4233-99f6-b5ea3ad303ef" />

If attacker provide the `swapData.param` with a low value token(such as 1000 tokenA / 1 ETH) , and provide the `asset` with a high value token.( 0.001 tokenB / 1 ETH). it makes much much more tokenB to be transfered to the attacker:

<img width="682" alt="Image" src="https://sherlock-files.ams3.digitaloceanspaces.com/gh-images/68d8d809-b153-4017-ab51-546b78730206" />

### Internal Pre-conditions

No pre conditions

### External Pre-conditions

No pre conditions

### Attack Path

1. Attacker provide low value tokenA's address in the `swapData` param
2. Attacker provide high value tokenB's address as the `asset` param
3. Attacker call the `depositAndCall` function
4. Attacker will receive all the token the contract belong

### Impact

The attacker will steal all the asset from the contract

### PoC

_No response_

### Mitigation

Verify the target exchange token asset address and the transfered asset address
