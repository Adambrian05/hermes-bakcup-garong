# Incorrect amount passed to _doMixSwap in GatewayTransferNative

### Summary

The GatewayTransferNative contract incorrectly passes the full received token amount (before deducting platform fees) to the _doMixSwap function during cross-chain swaps. This results in an inflated swap input amount, which can cause swap failures or unintentionally affect other users' funds pending redemption.

### Root Cause

When the GatewayTransferNative contract receives a call from the gateway contract (onCall is called) and the target ZRC20 token is not the same as the received ZRC20 token, the _doMixSwap function is called. The problem is that the function is called with amount as an argument, which represents the amount of ZRC20 tokens received before transferring the fee (so the protocol fee is not deducted).

### Attack Path
1. gatewayTransferNative will receive onCall call from gateway
2. fee is payed and transferred but not deducted from amount deposited
3. when decoded.tragedZRC20 is not equal as zrc20 received the swap has to be executed
4. since the amount (from which the fee is NOT deducted) is passed to _doMixSwap and if the from token amount is higher then it should (not deducted the fee from it as well), then its possible for users to use additional tokens for swap that are waiting to be refunded to other uses via claimRefund function
5. in that way users can "steal" tokens that should have been refunded to the other users( still up to the fee amount ) also that will render bots/users to not be able to claim refund since there can be shortage of asset that should be refunded 


### Impact

This mistake would result in an incorrect amount being passed to the function, which could lead to potential failed trades or the stealing of other users' funds that are held for redemption.

### Mitigation

Consider updating call to _doMixSwap function.
```diff
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
