# GatewaySend cannot refund native token to user on reverts.

### Summary

`RevertContext.asset` is `address(0)` if asset is gas token (i.e. native token).

However, `GatewaySend::onRevert` function do not handle such case, thus it is unable to refund native token back to user on transaction reverts.


### Root Cause

According to [ZetaChain doc](https://www.zetachain.com/docs/developers/chains/zetachain/#:~:text=On%20a%20connected%20chain%2C%20asset%20is%20the%20ERC%2D20%20originally%20deposited%20(or%20zero%20address%20for%20gas%20assets).), `RevertContext.asset` property is set to `address(0)` if it is native token:

> - On a connected chain, asset is the ERC-20 originally deposited (or zero address for gas assets).
> - On ZetaChain, asset is the ZRC-20 withdrawn during the original call.

Since `GatewaySend` is deployed to connected chains, `onRevert` function can have `RevertContext` with zero asset address, especially when asset is `_ETH_ADDRESS_`:

[File: omni-chain-contracts/contracts/GatewaySend.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L164-L175)
```solidity
218:     function depositAndCall(
219:         address fromToken,
220:         uint256 amount,
221:         bytes calldata swapData,
222:         address targetContract,
223:@>       address asset,
224:         uint32 dstChainId,

...

170:@>       gateway.depositAndCall{value: amount}(

```

For example, if `asset` in L223 is `_ETH_ADDRESS_`, then L259 will be reached, and native token will be deposited to gateway in L170.

If the transaction reverts in target universal contract, `GatewaySend::onRevert` function will be executed:

[File: omni-chain-contracts/contracts/GatewaySend.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L393-L396)
```solidity
393:     function onRevert(RevertContext calldata context) external onlyGateway {
394:         bytes32 externalId = bytes32(context.revertMessage[0:32]);
395:         address sender = address(uint160(bytes20(context.revertMessage[32:])));
396:@>       TransferHelper.safeTransfer(context.asset, sender, context.amount);
```

Since `context.asset` is `address(0)`, transfer will revert, thus `GatewaySend` contract cannot refund native token back to user.

### Internal Pre-conditions

1. User invokes `GatewaySend::depositAndCall` with `asset = _ETH_ADDRESS_`
2. The Gateway forwards the call to a universal contract on ZetaChain.
3. Universal contract's `onCall` function reverts, and the original amount is enough to cover revert gas fee
4. `GatewaySend::onRevert` is invoked with `RevertContext.asset == address(0)`


### External Pre-conditions

N/A

### Attack Path

See internal pre-conditions

### Impact

The protocol is unable to refund native token to user on reverts.


Note: `GatewayNativeTransfer` does not suffer from the vulnerability because it's on Zeta chain and `RevertContext.asset` will always be corresponding ZRC-20 address.

> On ZetaChain, asset is the ZRC-20 withdrawn during the original call.

### Mitigation

Handle `address(0)` case in `GatewaySend::onRevert` function.
