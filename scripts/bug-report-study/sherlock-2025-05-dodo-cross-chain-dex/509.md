# Public withdraw() Function Enables Unauthorized Token Extraction in GatewayTransferNative.sol

### Summary

The withdraw() function in GatewayTransferNative.sol is declared as public with no access control, allowing any attacker to drain all ZRC20 tokens held by the contract. This bypasses the intended cross-chain bridging flow and enables direct theft of funds meant for legitimate users.

### Root Cause

Withdraw function is marked as public and can be called by anyone.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286C5-L291C15


### Internal Pre-conditions

NA

### External Pre-conditions

An attacker must monitor the contract balance for deposited ZRC20 tokens.

### Attack Path

1. User deposits funds: A legitimate user calls withdrawToNativeChain(), depositing ZRC20 tokens into the contract.

2. Attacker follows up:

- Calls withdraw() with arbitrary externalId.

- Sets their own address as the receiver.

- Requests the full contract balance of the ZRC20 token.

3. Funds stolen: The gateway processes the withdrawal, sending the tokens directly to the attacker instead of the intended recipient.

### Impact

All deposited ZRC20 tokens can be drained which are in the contract.

### Mitigation

Mark withdraw function as internal.
