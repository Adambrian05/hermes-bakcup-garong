# USDT Allowance Reset Requirement Causing Cross-Chain Transaction Failures

### Summary

The `GatewaySend` contract performs cross-chain token transfers and swaps, interacting with ERC20 tokens through `depositAndCall()` and `onCall()`, and subsequently through internal functions like `_handleERC20Deposit()` and `_doMixSwap()`.  

But USDT requires that its allowance be set to zero before being updated to a new value. This behavior can disrupt the contract's operations, particularly affecting the external function `depositAndCall()` and 'onCall()'.

### Root Cause

In the `GatewaySend` contract, the internal functions `_handleERC20Deposit()` and `_doMixSwap()` are utilized by the external functions `depositAndCall()` and `onCall()`. These internal functions handle the approval of token transfers. However, when dealing with `USDT`, the approvals given to `gateway` and `DODOApprove` are not reset to zero before setting a new allowance. 

This oversight can lead to failed transactions due to USDT's requirement that the allowance be explicitly set to zero before updating to a new value. This behavior can disrupt the intended operations of the contract, causing transaction failures.

### Internal Pre-conditions

1. Network should be Ethereum mainnet and token should be `USDT`

### External Pre-conditions

None

### Attack Path

**1. Failed Deposits:**
- When a user calls `depositAndCall()` with `USDT`, the function attempts to approve the gateway to transfer the specified amount of `USDT`.
- If the allowance is not reset to zero before setting a new allowance, the approval may not be updated correctly. This can result in the gateway being unable to transfer the tokens, causing the deposit operation to fail.
- The user may experience unexpected failures in their cross-chain transactions, leading to delays or the need for additional transactions to correct the issue.

**2. Unsuccessful Swaps:**
- Within **depositAndCall()**, the function `_doMixSwap()` is called to perform token swaps via the DODO Router.
- If the allowance for the `DODOApprove` contract is not reset to zero before being updated, the swap operation may fail silently. This is because the contract might not have the correct allowance to execute the swap.
- Users may not receive the expected output tokens from the swap, leading to discrepancies in the intended versus actual transaction outcomes.

### Impact

Users may encounter failed deposit and swap operations due to incorrect allowance settings, resulting in incomplete or unsuccessful cross-chain transactions. Similarly, the gateway may face challenges in completing cross-chain transactions on the destination chain.
