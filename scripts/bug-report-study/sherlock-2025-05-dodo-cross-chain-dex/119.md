# Function `contracts/GatewayTransferNative.sol#withdraw()` is public and allows to withdraw refund funds

## Description

The function `contracts/GatewayTransferNative.sol#withdraw()` is public and accessible for everyone. If contract has any ZRC20 assets, for example, refund funds, a malicious user can to steal them.



https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304

```solidity
function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```



But `gateway` must to have an allowance to spend the token. 

If we look in the function `_handleBitcoinWithdraw()` and `_handleEvmOrSolanaWithdraw()` they has a small discrepancy between approved amount and the amount actually used.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L451-L465

```solidity
    function _handleBitcoinWithdraw(
        bytes32 externalId, 
        DecodedMessage memory decoded, 
        uint256 outputAmount,
        uint256 gasFee
    ) internal {
        if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
 @=>       IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
        withdraw(
            externalId, 
            decoded.receiver, 
            decoded.targetZRC20, 
 @=>          outputAmount - gasFee
        );
    }
```

Due to this discrepancy, which can be formed in the amount of 2 gasFee, an attacker can use this unspent allowance amount.



## Attack scenario

- attacker observes `refundInfos` for a new record
- call `withdraw()` function and receive funds at his account on another chain



## Proof Of Concept

## Recommended mitigation

Change `withdraw()` modifier to internal.
