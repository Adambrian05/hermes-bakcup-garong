# GatewaySend Contract Will Cause Fund Loss or Transaction Failures for Users

### Summary

A missing validation in the [`onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386) function will cause fund loss or transaction failures for users as the GatewaySend contract will process ETH transfers using its own balance or revert when insufficient ETH is provided by the gateway.

### Root Cause

In [`GatewaySend.sol:357-360`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L357-L360), the [`onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386) function fails to verify that the `msg.value` received matches the `amount` specified in the message when handling ETH as the input token. This oversight allows the contract to either dip into its own ETH reserves to complete the transfer or fail entirely if the reserves are inadequate.

### Internal Pre-conditions

1. The gateway calls `onCall` with a message where the input token is ETH and the decoded `amount` exceeds the `msg.value` sent.
2. The GatewaySend contract holds some ETH in its balance, accumulated from prior transactions or calls.


### External Pre-conditions

The GatewayEVM contract, due to a misconfiguration or bug, forwards a `msg.value` lower than the `amount` encoded in the message during a cross-chain transfer.

### Attack Path

1. A user invokes `depositAndCall` on the GatewayEVM contract, sending 1 ETH to initiate a cross-chain transfer.
2. The GatewayEVM, erroneously, calls `onCall` on the GatewaySend contract with `msg.value` set to 0.5 ETH, while the message specifies `amount` as 1 ETH.
3. The `onCall` function identifies ETH as the input token and skips token-specific transfers, proceeding directly to transfer the full `amount` (1 ETH) to the recipient.
4. The contract executes `payable(evmWalletAddress).transfer(1 ETH)`, either supplementing the shortfall from its own balance or reverting if the total ETH available is less than 1 ETH.

### Impact

Users may lose funds if the contract uses its own ETH to cover transfer shortfalls, depleting its reserves, or face failed transactions if the contract’s balance cannot support the transfer, disrupting cross-chain operations.

### PoC

add this poc test into : `GatewaySend.t.sol`

```bash
forge test --match-test test_OnCallFromTokenIsETH_InsufficientValue -vv
```

```solidity
function test_OnCallFromTokenIsETH_InsufficientValue() public {
        uint256 amount = 100 ether;
        uint256 insufficientValue = 50 ether; // Only half of required amount
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        address fromTokenB = _ETH_ADDRESS_;
        address toTokenB = address(token1B);
        bytes memory swapDataB = encodeCompressedMixSwapParams(
            _ETH_ADDRESS_,
            address(token1B),
            amount,
            0,
            0,
            new address[](1),
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0),
            block.timestamp + 600
        );
        bytes memory message = buildOutputMessage(
            externalId,
            amount,
            abi.encodePacked(user2),
            abi.encodePacked(
                fromTokenB, 
                toTokenB, 
                swapDataB
            )
        );
        
        // Give gateway some ETH but less than required
        deal(address(gatewayB), insufficientValue);
        
        // Give contract some ETH to demonstrate fund loss
        deal(address(gatewaySendB), 50 ether);
        
        uint256 initialContractBalance = address(gatewaySendB).balance;
        uint256 initialRecipientBalance = token1B.balanceOf(user2);
        
        vm.prank(address(gatewayB));
        gatewaySendB.onCall{value: insufficientValue}(
            MessageContext({
                sender: address(this)
            }),
            message
        );

        // Verify that the contract used its own ETH to complete the transfer
        assertEq(token1B.balanceOf(user2) - initialRecipientBalance, amount, "Recipient should receive full amount");
        assertEq(initialContractBalance + insufficientValue, amount, "Total ETH used should equal amount");
        
        // Log the values to help understand what happened
        console.log("Initial contract balance:", initialContractBalance);
        console.log("Insufficient value sent:", insufficientValue);
        console.log("Final contract balance:", address(gatewaySendB).balance);
        console.log("Amount received by recipient:", token1B.balanceOf(user2) - initialRecipientBalance);
    }

```

### Mitigation

Add a check in onCall when fromIsETH is true:

```solidity
if (fromIsETH) {
    require(msg.value >= amount, "Insufficient ETH received from gateway");
}
```
