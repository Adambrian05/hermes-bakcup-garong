# OnCall transaction will revert when targetZRC20 != zrc20 in GatewayTransferNative

### Summary

When a user wants to transfer tokens to zetachain, the user first calls the depositAndCall function in GatewaySend contract.
The gateway then calls the OnCall function in the GatewayTransferNative contract and transfers the tokens.
If the user requires a different token than the sent zrc20 token a swap will take place to the targetZRC20 token.

          uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        address receiver = address(uint160(bytes20(decoded.receiver)));

        if (decoded.targetZRC20 == zrc20) {
            // same token
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx //@audit-info not subing the fee in the else block?
            );

            emit EddyCrossChainSwap(
                externalId,
                uint32(context.chainID),
                ZETACHAIN,
                zrc20,
                decoded.targetZRC20,
                amount,
                amount - platformFeesForTx,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx
            );
        } else {
            // Swap on DODO Router
            uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

            if (decoded.targetZRC20 == WZETA) {
                // withdraw WZETA to get Zeta in 1:1 ratio
                IWETH9(WZETA).withdraw(outputAmount);
                // transfer wzeta
                TransferHelper.safeTransferETH(receiver, outputAmount);
            } else {
                TransferHelper.safeTransfer(
                    decoded.targetZRC20,
                    receiver,
                    outputAmount
                );
            }

            emit EddyCrossChainSwap(
                externalId,
                uint32(context.chainID),

                decoded.targetZRC20,
                amount,
                outputAmount,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx

        }

But checking the targetZRC20 token, the code takes a fee ` uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);`.

          function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }

After transferring the fee, leftover balance will be amount - fee. But in the else block, the input amount is `amount` without subtracting the fee which will cause a revert due to less funds after transferring the fee.

### Root Cause

Fee will be [transferred](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L370)
Not subtracting the fee [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395-L408)

The [swap](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395) will fail because the balance amount will be amount - platform fee.



### Impact

The transaction always reverts if targetZRC20 != zrc20.


### Mitigation

Input `amount - platformFeesForTx` in the swap param.
