# Malicious callers will steal excess contract balances

### Summary

The absence of validation between `amount` sent to contract and the decoded `params.fromTokenAmount`  from `swapData`  in `depositAndCall` creates a vulnerability. Malicious users can manipulate swapData to mismatch amounts  withdrawing residue tokens from the contract.



### Root Cause

The vulnerability originates in the  [`depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218) function of `GatewaySend.sol` .

The `depositAndCall` function transfers`amount` of `fromToken` from users but uses unvalidated swapData containing `params.fromTokenAmount`  for swaps.

 More specifically,  the  `_doMixSwap` function  calls [`approve`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L199) for `params.fromTokenAmount`  instead of `amount` that the users have sent to the contract.

A malicious user can set a higher `params.fromTokenAmount` than the `amount` provided.If the contract hold excess tokens ,the `DODOApprove` is approved to spend them,swap and return an output amount sent to a destination address

Similarly,if the `params.fromTokenAmount` is smaller than `amount` users get to swap only `params.fromTokenAmount` leaving`amount-params.fromTokenAmount` in the contract thats stuck and can be stolen by the attack



### Internal Pre-conditions

1. User calls `depositAndCall` with  `swapData.fromTokenAmount`> `amount` 
2. The contract must hold excess tokens (e.g., from direct  deposits).



### External Pre-conditions

None

### Attack Path

1. Contract holds excess 5000 USDC (from previous residuals or direct deposits) 
2. Attacker calls `depositAndCall` with:
   - `amount = 1 USDC`
   - `swapData.fromTokenAmount = 5001 USDC` (maliciously set higher)
3. The contract executes `transferFrom(msg.sender, address(this), 1)`, transferring 1 token
4. The contract holds 5000 excess tokens.
5. `_doMixSwap(swapData)` approves `DODOApprove` to spend 5001 tokens (`params.fromTokenAmount`)
6. The DODO proxy swaps 5001 tokens (1 user-provided + 5000 excess) producing an `outputAmount`
7. Contract loses 5000 USDC

### Impact

- Protocol suffers loss of entire residual token balance in contract.
- User funds can be trapped in the contract or stolen.

### PoC

_No response_

### Mitigation

Instead of approving `params.fromTokenAmount`, approve only the exact `amount` that is transferred to the  contract
```solidity
IERC20(params.fromToken).approve(DODOApprove, amount);
```
or/and

Implement strict validation checks in depositAndCall:
```solidity
  require(params.fromTokenAmount == amount, "AMOUNT_MISMATCH");
```
