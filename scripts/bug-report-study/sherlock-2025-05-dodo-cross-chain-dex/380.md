# hardcoded gas limit can cause `_handleEvmOrSolanaWithdraw()` and `withdrawAndCall()` to revert

### Summary

A hardcode `gasLimit` value which is not adjustable after initialization is passed in when withdrawing ZRC20 tokens. This can cause withdrawals to fail depending on the recipient.

### Root Cause

ZRC20 tokens are not just token representing spoke ERC20s on Zetachain. they can also be EVM chain native tokens like ETH.

For most token, hardcoding a `gasLimit` will work fine but for others it may not. As in most cases transferring ERC20 tokens gas cost is constant for all tokens, it can differ but gas used will always be the same when ever you transfer, and who ever the receiver, so Making the value is constant is OK

The problem is that Native gas used is not constant depending on the receiver which can be either an
- EOA
- Smart Contract Wallet (Safe wallet consumes more gas for example)
- Account Abstraction wallet
- a Smart Contract (with fallback handler)

In summary, withdrawing native using withdraw will ends up with transferring the tokens and therefore eventually calling a fallback.

But in case ZRC20 was a native token, we can't estimate a constant `gasLimit` for transferring of coins as the cost will differ if the receiver is EOA, Smart Contract Wallet, MultiSig Wallet, AA wallet, Smart Contract, etc... which will make forcing `gasLimit` leading to issues of OOG in case of consuming more.

For examples, smart contracts / Safe Wallets, the Fallback is like doing an action when you receive gas tokesn (ETH).

- AA Wallets can make a direct deposit to the Entry point for example in that case
- Smart Contract Wallets design can can transfer the received amount of Gas to the treasury
