# Rounding Error in `_handleFeeTransfer` Leads to Undercharged Fees

### Summary

`GatewayTransferNative::withdrawToNativeChain` [L530](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530) allows users to perform cross-chain withdrawals. It uses the `_handleFeeTransfer` [function](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341-L347) to calculate and transfer platform fees. However, the `_handleFeeTransfer` function is vulnerable to rounding error due to Solidity's integer division. 

### Root Cause

### VULNERABLE CODE
```solidity
    function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000;
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```

- ` platformFeesForTx = (amount * feePercent) / 1000;` 

### Internal Pre-conditions

none

### External Pre-conditions

none

### Attack Path

- User calls `GatewayTransferNative::withdrawToNativeChain`
- Suppose amount = 1750, and feePercent = 50 (i.e., 5%)
- Raw fee = (1750 * 50) = 87500
- Division: 87500 / 1000 = 87.5, but Solidity rounds this down to 87
- Result: 0.5 units of the token are lost per transaction
- `amount -= platformFeesForTx;` in [GatewayTransferNative::withdrawToNativeChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L552) will subtract 87 from the amount.

### Impact

When a high volume of transactions is processed using this fee calculation logic, the cumulative loss from rounding errors can become significant over time
