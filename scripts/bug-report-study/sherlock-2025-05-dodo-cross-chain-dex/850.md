# Invalid Type Casting in withdraw Function Causes Corrupted Revert Message

##Description
There is a critical issue in the function withdraw, specificially in how revertMessage is constructed using bytes.concat(externalId, bytes20(sender)). This is likely incorrect and unsafe because: sender is of type, not address. It is attempting to cast it to bytes20(sender)-this is not valid. bytes20(...) requires a 20-byte value(e.g., an address), not a dynamic bytes object. Even if sender was originally an address encoded into bytes, forcibly casting it this way will truncate or corrupt data.
```solidity
revertMessage: bytes.concat(externalId, bytes20(sender)),
```
Problem Description

The expression bytes20(sender) is invalid and unsafe, because:

1. sender is of type bytes, which is a dynamic byte array, not a fixed-size 20-byte value like address or bytes20.


2. bytes20(...) expects a 20-byte value, such as an address, or a fixed-size byte array of length at least 20. Forcing a cast from a dynamic bytes object will:

Truncate or corrupt data, since only the first 20 bytes of sender will be used, which may not even exist.

Introduce undefined behavior in the revert message, potentially breaking downstream logic relying on structured revert data.

Why This Is Dangerous

If sender was originally an address encoded as abi.encodePacked(address), you'd need to decode it properly, not cast it.

If the sender is arbitrary-length data (e.g., a public key, or an off-chain identifier), truncating it is almost certainly incorrect.

The revert message may not match the format expected by the off-chain logic or receiving contracts.
##Proof of Concept
```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {Test} from "forge-std/Test.sol";
import {GatewayEVMMock} from "../contracts/mocks/GatewayEVMMock.sol";
import {ERC20Mock} from "../contracts/mocks/ERC20Mock.sol";

contract WithdrawSenderTruncationTest is Test {
    GatewayEVMMock public gateway;
    ERC20Mock public token;
    address public testUser = address(0xABCD);
    uint256 public constant withdrawAmount = 1 ether;

    function setUp() public {
        gateway = new GatewayEVMMock();
        token = new ERC20Mock("MockToken", "MOCK", 18);

        // Set user balance and approve gateway
        token.mint(testUser, withdrawAmount);
        vm.prank(testUser);
        token.approve(address(gateway), withdrawAmount);
    }

function testUnsafeCastOfBytesToBytes20() public {
        // Simulate a sender encoded as bytes (e.g., from another chain or protocol)
        bytes memory encodedSender = abi.encodePacked("veryLongSenderIdentifierWithData");

        // Prove sender is not a valid address or bytes20 — it's dynamic bytes
        assertGt(encodedSender.length, 20, "Sender must be longer than 20 bytes");

        // Emulate the behavior: casting dynamic bytes to bytes20
        // This is invalid from a data integrity point of view but allowed by Solidity
        bytes20 unsafeCast = bytes20(encodedSender); //  this truncates data

        // Extract expected truncated version
        bytes memory first20 = new bytes(20);
        for (uint256 i = 0; i < 20; i++) {
            first20[i] = encodedSender[i];
        }

        bytes20 expected;
        assembly {
            expected := mload(add(first20, 32))
        }

        // Check the cast was simply truncation (first 20 bytes only)
        assertEq(unsafeCast, expected, "bytes20(sender) just truncates without warning");

        // Confirm truncation leads to loss of critical information
        bytes32 fullHash = keccak256(encodedSender);
        bytes32 truncatedHash = keccak256(abi.encodePacked(unsafeCast));
        assertFalse(fullHash == truncatedHash, "Data loss due to unsafe cast not detected");

        // Final logging to document the finding
        emit log("Test confirms: casting bytes to bytes20 is unsafe and truncates data");
    }
}
```

##Recommendation
If sender is meant to be included as-is (e.g., it contains a user ID, public key, or an address encoded via abi.encode):

```solidity
revertMessage: bytes.concat(externalId, sender)
```
If sender encodes an address (e.g., via abi.encode(address)), decode it properly first:
```solidity
address decodedSender = abi.decode(sender, (address));
revertMessage: bytes.concat(externalId, bytes20(decodedSender));
```
DO NOT use bytes20(sender) — it causes silent truncation, invalid memory access, and unsafe type casting.
