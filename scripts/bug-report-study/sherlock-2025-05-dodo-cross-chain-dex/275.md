# Unchecked Transfer in GatewaySend.onCall

### Summary

In the function GatewaySend.onCall, the contract transfers tokens to the recipient using IERC20(toToken).transfer(evmWalletAddress, outputAmount) without verifying the returned boolean value. If the token is a non-standard ERC20 implementation that silently fails and returns false instead of throwing an exception, this could result in the transfer appearing successful while it actually fails.



### Root Cause

The transfer function of the ERC20 interface returns a bool to indicate the success or failure of the operation. The code does not check this return value, assuming all tokens adhere to the standard behavior. However, non-standard ERC20 tokens may return false silently if the transfer fails.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L372

### Internal Pre-conditions

The function onCall is invoked, and toToken is set to an ERC20 token address.

The outputAmount is calculated correctly and approved for transfer.

### External Pre-conditions

A non-standard ERC20 token is used, which silently fails transfers and returns false.

The recipient evmWalletAddress is expecting the transfer to succeed based on emitted events.



### Attack Path

Deploy or use a non-standard ERC20 token that always returns false for transfer calls.

Interact with the GatewaySend.onCall function, specifying the malicious token.

Observe that the transfer operation silently fails, but the emitted events indicate success, causing downstream components to incorrectly assume the funds have been transferred.

### Impact

Tokens might not be transferred, leading to a mismatch between the state of the contract and the expected balances.

Recipients might never receive the funds, resulting in a loss of trust or funds in a cross-chain operation.

Downstream operations might proceed under the assumption of successful token transfers, causing further inconsistencies or errors.

### PoC

```solidity
// Malicious token contract
contract FakeToken {
    function transfer(address, uint256) public pure returns (bool) {
        return false; // Simulate silent failure
    }
}

// Deployment
FakeToken badToken = new FakeToken();
uint256 amount = 1000;

// GatewaySend interaction
gatewaySend.onCall(
    /* MessageContext */ ...,
    address(badToken),
    amount,
    /* other params */
);

```

Result: The onCall function will proceed as if the transfer succeeded, while the token remains with the contract.



### Mitigation

Add a check for the return value of the transfer function:


```solidity

require(IERC20(toToken).transfer(evmWalletAddress, outputAmount), "TRANSFER_FAILED");

```
This ensures that the function reverts if the transfer operation fails, preventing silent failures and maintaining consistency in the contract's state.
