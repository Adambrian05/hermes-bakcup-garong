# Silent Transfer Failures in USDT Transactions on Ethereum as Destination Chain

### Summary

The `GatewaySend` contracts uses `IERC20.transfer()` and `IERC20.transferFrom()` for handling ERC20 token transfers. This approach can lead to silent failures with tokens like USDT, which do not revert on failed transfers. Such behavior can result in incorrect state updates and logic errors, as the contract may assume a successful transfer when it has actually failed.

### Root Cause

The `onCall` function in the `GatewaySend` contract is responsible for processing incoming cross-chain messages and executing token transfers and it is invoked by the gateway.

The above code uses,  `IERC20(fromToken).transferFrom()` and ` IERC20(toToken).transfer()`. If USDT is used as the tokens, these lines will not return a boolean indicating success or failure. If the transfer fails, the function will not detect it, potentially leading to incorrect assumptions about the state of the contract and treat the transaction as success.


### Internal Pre-conditions

None

### External Pre-conditions

1. Destination chain should be Ethereum mainnet and asset should be USDT

### Attack Path

1. A user initiates a cross-chain transaction to transfer USDT to Ethereum as the destination chain.
2. The gateway executes the `onCall` function on Ethereum, passing the necessary parameters, including the `USDT` token.
3. The gateway calls `onCall` function attempts to transfer USDT to the recipient
4. Due to USDT's non-standard behavior, if the transfer() fails, it does not return a boolean value. The failure is silent, meaning the function does not detect it and does not revert.
5. The `onCall` function proceeds as if the transfer was successful, potentially logging a successful transaction 
6. The recipient on Ethereum does not receive the intended USDT, resulting in a loss of funds for the recipient.

### Impact

**Financial Loss for Recipient:**

**Unreceived Funds:** The recipient on Ethereum does not receive the intended USDT due to the silent failure in the transfer process.
**Loss of Expected Value:** This results in a direct financial loss for the recipient, who expected to receive the transferred funds.
