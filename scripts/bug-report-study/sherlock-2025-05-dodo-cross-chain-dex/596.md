# Incorrect balance validation in _swapAndSendERC20Tokens will prevent valid user withdrawals

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L329

### Summary

The use of amountInMax instead of the actual swap input amounts[0] in the balance validation check will cause a revert for users especially when slippage is high, even though they still have sufficient funds. As a result, users will be unable to withdraw tokens under volatile market conditions due to an overly strict condition in _swapAndSendERC20Tokens.

### Root Cause

In GatewayCrossChain.sol:L329, the `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");` check incorrectly uses the quoted max input **(amountInMax)** rather than the actual input used in the swap **(amounts[0])** to validate that enough funds remain after paying for gas. This causes the function to revert when slippage is high and the actual input is significantly less than the quoted max.

### Internal Pre-conditions

- The user submits a withdrawal with a targetAmount of tokens that is meant to include both their deliverable amount and the portion to be swapped for gas.

- The current market conditions (price impact or low liquidity) cause a high slippage buffer, leading to a large difference btw amountInMax and amounts[0] (actual amount used)

### External Pre-conditions

- The Uniswap pool's reserves for targetZRC20 -> gasZRC20 are low, causing high slippage.
- The price of the gas token spikes temporarily, increasing the required slippage margin (amountInMax - gasFee) during getAmountsIn.

### Attack Path

User initiates a legitimate withdrawal through onCall() --->_handleEvmOrSolanaWithdraw with a reasonable targetAmount.

_swapAndSendERC20Tokens performs getAmountsIn() and computes amountInMax = quoteIn * 1005 / 1000.

Uniswap executes the swap successfully, using only amounts[0], which is significantly lower than amountInMax.

The function reaches:

require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
which fails despite targetAmount - actualUsed being sufficient.

Transaction reverts unnecessarily even though user has enough balance.

### Impact

The user cannot withdraw tokens under volatile conditions due to excessive conservatism in the slippage guard. This reduces protocol reliability, blocks user access to their funds, and causes denial-of-service in edge market scenarios.

### PoC

_No response_

### Mitigation

### **Replace:**

`require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`

### **With:**

`require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`
