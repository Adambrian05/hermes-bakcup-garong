# Fixed `gasLimit` can lead to DoS if gas cost changes

### Summary

In the gateway contract, there is a gas limit parameter set in constructor, but there is no function to update it. The gas cost on different chains are subjected to change, and when it rises, it may always lead to reversion.

### Root Cause

In gateway contract's [`initialize`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L108C1-L126C6) function:
```solidity
    function initialize(
        address payable _gateway,
        address _EddyTreasurySafe,
        address _dodoRouteProxy,
        address _dodoApprove,
        uint256 _feePercent,
        uint256 _slippage,
        uint256 _gasLimit
    ) public initializer {
        __Ownable_init(msg.sender);
        __UUPSUpgradeable_init();
        gateway = GatewayZEVM(_gateway);
        EddyTreasurySafe = _EddyTreasurySafe;
        DODORouteProxy = _dodoRouteProxy;
        DODOApprove = _dodoApprove;
        feePercent = _feePercent;
        slippage = _slippage;
        gasLimit = _gasLimit;
    }
```

We see `gasLimit` is set, and also used in later operations:
```solidity
    function withdrawAndCall(
        bytes32 externalId,
        bytes memory contractAddress,
        address targetZRC20,
        uint256 outputAmount,
        bytes memory receiver,
        bytes memory message
    ) internal {
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
    }
```

This sets the gas limit for gateway interactions, and it reverts if more than limit's gas is consumed. However, by exmaning the contract, there is no other way of updating `gasLimit`. This would introduce one issue, which is the gas cost may change on each chain, and fixed value will likely be outdated when the gas changes are applied. 

For example, if the `gasLimit` is set to 0.0001 ether, but due to changes, any cross chain call would cost 0.00011 ether, this makes it impossible to do exchanges as it keeps reverting.

### Internal Pre-conditions

1. Admin sets `gasLimit`

### External Pre-conditions

1. Any of the chain changes the gas cost, and now any cross chain message would consume more than `gasLimit`'s native token to send.

### Attack Path

none

### Impact

This can cause some messages be unable to send, break core functionality.

### PoC

_No response_

### Mitigation

While the upgradeable contract will allow protocol team to update it, however, so far in scope concerned, there should be a function to update gas limit in cases of gas cost change.
