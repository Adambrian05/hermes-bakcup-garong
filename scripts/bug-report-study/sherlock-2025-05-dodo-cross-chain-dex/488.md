# Account Abstraction users can lose funds

### Summary

If a user utilizes an account abstraction wallet, the onRevert logic in gatewayCrossChain and gatewayTransferNative may transfer the reverted funds to an address the user does not control. This could result in a permanent loss of funds,

### Root Cause

The protocol assumes that users will have the same address across all EVM-based chains. However, this is incorrect when account abstraction wallets are used, as they may result in different addresses per chain.

The issue arises during the construction of the revertMessage. The receiver field in decoded message is assumed to be the same address across both ZetaChain and destination chain(EVM based chains). If the user uses an account abstraction wallet (or intentionally provides a different address on the destination chain), the receiver address embedded in the revertMessage will not match the user’s actual ZetaChain address.

When the revert is triggered, the refund will be sent to the receiver address from the destination chain, which might not be controlled by the user on ZetaChain, resulting in fund loss.

```solidity
function withdrawAndCall(
        bytes32 externalId,
        bytes memory contractAddress,
        address targetZRC20,
        uint256 outputAmount,
        bytes memory receiver,
        bytes memory message
    ) internal {
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
    }
```

### Attack Path

1. User calls gatewaySend.depositAndCall with a payload where decoded.receiver contains users address on the destination chain (since user uses AA wallet address on Ethereum, ZetaChain and destination chain would be different).
3. Cross-chain swap is initiated successfully.
4. gatewayCrossChain.onCall is triggered by the gateway on ZetaChain.
5. _handleEvmOrSolanaWithdraw is invoked, which calls withdrawAndCall ( note that both _handleEvmOrSolanaWithdraw and withdrawAndCall are called with decoded.receivers address as the arguments)
6. The revert message is constructed using bytes.concat(externalId, decoded.receiver).
7. A bridging failure occurs, and onRevert is triggered (by gateway).
8. The receiver address is extracted from the revert message.
9. Since this receiver is the address from the destination chain, and not the user's ZetaChain-controlled address, the refund is sent to an address the user cannot access.
10. The user permanently loses their funds.

### Impact

If the receiver address on ZetaChain and the destination chain differ due to the use of account abstraction or intentional use of separate addresses, the reverted funds will be sent to an address that may not be controlled by the user, resulting in permanent loss of funds
