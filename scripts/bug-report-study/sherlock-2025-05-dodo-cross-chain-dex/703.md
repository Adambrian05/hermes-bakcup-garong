# Missing Fee Deduction Leads to Loss of Funds

### Summary

When GatewayTransferNative receives a call from the GatewayZEVM, Dodo charges a protocol fee that is immediately sent to an admin wallet. When the `targetZRC20` does not equal the `zrc20` input param, the protocol swaps into the `targetZRC20`, but doesn't subtract the `platformFeesForTx`:

```solidity
function onCall(
        MessageContext calldata context,
        address zrc20, // zrcUSDC
        uint256 amount, // 100e18
        bytes calldata message
    ) external override onlyGateway {
        
        // charge fee and send to EddyTreasurySafe
>>>     uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); 
        address receiver = address(uint160(bytes20(decoded.receiver)));

        if (decoded.targetZRC20 == zrc20) {
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx // correctly subtract fee from amount
            );

            ...
        } else {
            // @audit platformFeesForTx is not subtracted from amount
>>>         uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

...SNIP...
        }
    }
```

There are two problems with this.

Problem 1:
If a normal user doesn't swap on Zetachain, then _doMixSwap will return `amount`:
```solidity
function _doMixSwap(
        bytes memory swapData, 
>>>     uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
>>>     if (swapData.length == 0) {
>>>         return amount;
        }
...
}
```

Next, the contract will try to transfer that amount to the user. The problem is the contract only holds `amount - platformFeesForTx`, so the transfer will fail and the onRevert sequence will run. Ultimately, the user loses gas and the protool fee.


Problem 2:
If the contract holds unclaimed refunds, an attacker can steal the protocol fee amount from unclaimed refunds by swapping `amount` instead of `amount - platformFeesForTx`. 

```solidity
function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }
           // @audit approves entire amount

        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount, // @audit attacker can swap entire amount instead of amount - platformFeesForTx
            ...

```

### Root Cause

Failure to subtract the protocol fee (platformFeesForTx) from the swap amount.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L465

### Internal Pre-conditions

Either:
1. The user doesn't swap on Zetachain OR
2. There's unclaimed refund

Note: If there's no unclaimed refunds and the user does swap, then the user would be able to input a `fromTokenAmount` that takes into account the fee. This is obviously not how the protocol intends to work, but is worth mentioning. 


### External Pre-conditions

N/A

### Attack Path

1. User calls `GatewaySend:depositAndCall` where GatewayTransferNative is the target contract and no swap is to be performed on Zetachain.
2. `GatewayTransferNative:onCall` calls `_handleFeeTransfer`, deducting the platform fees and sending them to the admin wallet.
3. `_doMixSwap` returns the original amount without subtracting fees.
4. GatewayTransferNative attempts transferring the full amount to the user but fails due to insufficient funds.
5. Transaction reverts, causing the user to lose the gas fee and the protocol fee.

### Impact

Loss of funds. 

### PoC

_No response_

### Mitigation

```diff 
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
