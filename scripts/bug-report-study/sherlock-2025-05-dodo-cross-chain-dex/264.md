# Griefing vulnerability via external ID collision in `GatewayCrossChain::onCall` leading to refund data overwrite

### Summary

A lack of uniqueness in `externalId` calculation will cause a refund data overwrite vulnerability for legitimate users as an attacker can reuse the same `externalId` to trigger `onRevert` and overwrite refund information.

### Root Cause

In [`GatewayCrossChain::onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L449), the `externalId` is calculated by decoding the first 32 bytes of the message (`abi.decode(message[0:32], (bytes32)`)) without ensuring uniqueness, which allows reuse of the same `externalId` and leads to `refundInfos` being overwritten during [`onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L533-L539), leading to griefing attack.

### Internal Pre-conditions

1. The gateway needs to send a crafted `message` where the first 32 bytes decode to an `externalId` that already exists in `refundInfos`.
2. A withdrawal triggered by the legitimate user must revert, causing the system to enter the onRevert flow.
3. During `onRevert`, the contract overwrites the existing `refundInfos[externalId]` with attacker-controlled data.
4. The contract allows overwriting `refundInfos[externalId]` without verifying if the refund was already claimed or is valid, leading to griefing of the real user.

### External Pre-conditions

1. The cross-chain messaging protocol (`GatewayCrossChain`) must allow replay or injection of messages with identical `externalId` values.
2. The underlying blockchain or network must permit a withdrawal transaction from the legitimate user to fail or revert.
3. No external mechanism (e.g., anti-replay protection or message uniqueness enforcement) prevents the attacker from sending duplicate or conflicting messages with the same `externalId`.


### Attack Path

1. Attacker crafts a cross-chain message with a chosen `externalId` by encoding data via `abi.encode`.
2. Attacker sends this `message` to gateway which triggers `GatewayCrossChain::onCall`, triggering `onCall` with the crafted message.
3. Because `externalId` is derived from `abi.decode(message[0:32], (bytes32))` without uniqueness checks, the same `externalId` can be reused.
4. The withdrawal from the gateway reverts.
5. The system calls `onRevert` with the same `externalId`, the` refundInfos[externalId]` data is overridden with the attacker’s data.
6. This causes the real user’s refund information to be replaced, resulting in denial or griefing of their refund.

### Impact

The real users suffer the inability to receive their rightful refunds due to their `refundInfos` being overridden. The users cannot successfully execute refund withdrawals, leading to a denial-of-service (griefing) attack. The attacker gains the ability to disrupt refunds but does not directly gain funds.

### Mitigation

Implement the `_calcExternalId` function to generate a unique and collision-resistant `externalId` for each refund request. This prevents multiple calls from producing the same `externalId`, thereby avoiding overwriting existing `refundInfos` and mitigating the griefing attack vector.
