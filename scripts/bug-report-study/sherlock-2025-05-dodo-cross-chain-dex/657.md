# `OwnableUpgradeable` uses single-step ownership transfer

### Summary

When called, the transferOwnership function immediately sets the contract owner to
the provided address. The use of a single step to make such a critical change is error-prone;
if the function is called with erroneous input, the results could be irrevocable or difficult to
recover from.
The `GatewayCrossChain`, `GatewaySend` and `GatewayTransferNative` contracts inherits ownership logic from the OpenZeppelin
OwnableUpgradeable contract, which allows the current owner to transfer the contract
ownership to another address using the transferOwnership function
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L128-L130

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L82-L84
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L129-L131

### Root Cause

use of single step `transferOwnership` function

### Attack Path

Alice invokes transferOwnership to change the contract owner but accidentally enters
the wrong address. She permanently loses access to the contract.

### Impact

Permanent loss of access to the contract

### PoC

_No response_

### Mitigation

Implement a two-step process for all irrecoverable critical operations, such as
by replacing the OwnableUpgradeable contract with the Ownable2StepUpgradeable
contract.
