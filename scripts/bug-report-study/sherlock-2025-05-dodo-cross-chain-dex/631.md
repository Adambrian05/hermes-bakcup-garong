# Incorrect check in `_swapAndSendERC20Tokens` leading to wrong reverts and possible underflows.

### Summary

In `_swapAndSendERC20Tokens`, after the swap, an incorrect amount is used to calculate the remaining amount for withdrawal, leading to reverts due to zero amount left or underflow.

### Root Cause

In [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302) and [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L306), the function `_swapAndSendERC20Tokens` is used when the token to be withdrawn is different from its gas token. This function is used to swap a part of the `target amount` into the required gas amount, then use for withdrawal.

The function first calculates the amount of target token needed for the swap, then adds a percentage of this amount as `slippage`, performs the swap using Uniswap v2, and then approves the `gateway` contract.

```solidity
  function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

@>      uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
@>     require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

The `issue` here is that it calculates the remaining withdrawal amount from the `slippage value` in the require statement, which is wrong as the check may underflow or revert incorrectly.
```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
`amountInMax` is an inflated value and does not reflect the actual amount used for the swap; it's an inflated number by some percentage to act as a `slippage` for the call. 

In situations where the `target amount` is close to the `fee amount` this extra value added for slippage may cause `amountInMax` to become equal to or greater than `targetAmount`, causing wrong revert or underflow, respectively.

### Attack Path

Note: using assumed values to explain the issue further.

For example, let's take,
* targetAmount = 100 units
* The fee amount after calculation is 90 units 
* Slippage is 150 --> 15% slippage
* amountInMax becomes 103.5 units
* The swap executed, and the actual amount used is 93 uints
* meaning there should be enough for the withdrawal (7 units left).
* In the require statement, (100 units - 103.5 units) is attempted.
* The require statement fails and reverts, preventing withdrawal.

### Impact

The require statement is improperly written, leading to underflows and unnecessary reverts, preventing withdrawal.

### Mitigation

_swapAndSendERC20Tokens should be corrected to use the actual amount used for the swap, rather than the slipage-inflated amount.
```diff
--   require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
++  require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
