# Incorrect abortAddress prevents fallback handling when onRevert fails

### Summary

The `GatewayCrossChain` and `GatewayTransferNative` contracts set `abortAddress` to `address(0)` in their `RevertOptions`, preventing the gateway from calling the `onAbort` fallback function when `onRevert` fails or reverts.

### Root Cause

In `withdrawAndCall`, the `RevertOptions` struct incorrectly sets [abortAddress](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L264) to `address(0)`:

```solidity
RevertOptions({
    revertAddress: address(this),
    callOnRevert: true,
>   abortAddress: address(0),
    revertMessage: bytes.concat(externalId, receiver),
    onRevertGasLimit: gasLimit
})
```

When `onRevert` fails (due to gas issues, contract state problems, or other failures), the gateway should call `onAbort` at the specified `abortAddress` as a fallback mechanism. Setting this to `address(0)` disables this critical fallback.

### Attack Path

Example scenario from the [ZetaChain Documentation](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions):

ZetaChain → Connected Chain (Outgoing)

Flow:

1. A universal contract on ZetaChain initiates a call to a connected chain via `withdrawAndCall` or `call`.
2. The Gateway forwards the message and/or tokens to the target contract on the connected chain.
3. If the target contract reverts, ZetaChain initiates the revert process.

Revert Behavior:

* If `callOnRevert` is `true`:
  * The Gateway invokes the `onRevert` function on the `revertAddress` on ZetaChain.
  * The remaining ZRC-20 tokens are passed along with the revert context.
  * If the `onRevert` call itself reverts, the Gateway transfers ZRC-20 tokens to and calls `onAbort` on the `abortAddress` on ZetaChain.

Both `GatewayCrossChain` and `GatewayTransferNative` have the `onAbort` function implemented. However, with `abortAddress` set to `address(0)`, `onAbort` will never be called and funds will be stuck with no recovery mechanism.

### Impact

Users lose access to both automatic refunds (via failed `onRevert`) and manual refund claims (via `claimRefund`) since `RefundInfo` is never created. This can result in the loss of all user funds.

### Mitigation

In the `withdrawAndCall` function, update the `abortAddress` in `RevertOptions` to enable proper fallback handling:

```diff
RevertOptions({
    revertAddress: address(this),
    callOnRevert: true,
-   abortAddress: address(0),
+   abortAddress: address(this),
    revertMessage: bytes.concat(externalId, receiver),
    onRevertGasLimit: gasLimit
})
```
