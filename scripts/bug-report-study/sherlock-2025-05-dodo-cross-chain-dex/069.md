# Attacker will drain all contract funds as onRevert lacks sender validation

### Summary

Missing validation of transaction origin in `GatewaySend::onRevert()` will cause complete loss of all stored tokens for the protocol as an attacker will exploit ZetaChain's revert mechanism to drain contract balances by setting the contract as revertAddress for their own transactions.

### Root Cause

In `GatewaySend.sol:393-403` there is missing validation that `context.sender` equals `address(this)`, allowing any external transaction that sets `GatewaySend` as the revertAddress to trigger fund transfers upon reversion.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404

### Internal Pre-conditions

1. Contract needs to hold any tokens from previous failed transactions or operations

### External Pre-conditions

N/A

### Attack Path

1. Attacker initiates a cross-chain transaction through ZetaChain (not through GatewaySend)
2. Attacker sets `revertAddress` to the `GatewaySend` contract address in the transaction
3. Attacker crafts `revertMessage` to encode their own address in bytes 32-52
4. Attacker ensures the transaction fails on the destination chain (can be done intentionally)
5. ZetaChain gateway calls `GatewaySend::onRevert()` with context containing attacker's crafted data
6. Function extracts sender address from `revertMessage` bytes 32-52 (attacker's address)
7. Function transfers `context.amount` of `context.asset` to the attacker without validating the transaction origin

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all tokens held by the contract by exploiting the missing sender validation in the revert mechanism.

### PoC

_No response_

### Mitigation

Add validation to ensure the revert is from a transaction initiated by the contract itself:

```solidity
    require(context.sender == address(this), "Unauthorized revert sender");
```
