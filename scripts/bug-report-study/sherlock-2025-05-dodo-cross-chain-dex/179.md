# Users will permanently lose ETH in cross-chain swaps when withdrawals fail due to broken onRevert mechanism

### Summary

Missing ETH handling in the `onRevert` function will cause permanent fund loss for users as cross-chain swap participants whose transactions involve ETH assets will lose their funds when the revert mechanism fails to transfer ETH back using the wrong transfer method.

### Root Cause

In [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L522-L524) the `onRevert` function uses `TransferHelper.safeTransfer()` for all assets including `_ETH_ADDRESS_`, but `safeTransfer()` only works for ERC20 tokens and will fail when trying to transfer ETH represented by `_ETH_ADDRESS_`.

```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    bytes memory walletAddress = context.revertMessage[32:];

    if(context.revertMessage.length == 52) {
        address receiver = address(uint160(bytes20(walletAddress)));
        TransferHelper.safeTransfer(context.asset, receiver, context.amount);
        // ↑ FAILS when context.asset = _ETH_ADDRESS_
    }
}
```

### Attack Path

1. User initiates cross-chain swap involving ETH through another contract (like GatewaySend)
2. The source chain gateway calls `onCall()` on GatewayCrossChain with `zrc20` that maps to ETH
3. GatewayCrossChain processes the swap and calls gateway withdrawal functions with ETH-related ZRC20
4. The withdrawal fails on the destination chain
5. The gateway calls `onRevert()` with `context.asset = _ETH_ADDRESS_` 
6. `TransferHelper.safeTransfer(_ETH_ADDRESS_, receiver, amount)` silently fails because `_ETH_ADDRESS_` is not a valid ERC20 contract
7. The function continues executing and emits the success event, making it appear the revert worked
8. But the user's ETH remains permanently trapped in the contract

### Impact

Users suffer loss of funds during `onRevert` transactions that involve ETH.

### Mitigation

Modify the `onRevert` function to handle ETH separately
