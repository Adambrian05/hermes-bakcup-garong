# `GatewayTransferNative::onCall` mishandles native ZETA deposits, causing failed transactions, or transferring other users' wZETA

### Summary

`GatewaySend::_handleEthDeposit` calls `GatewayEVM::depositAndCall{value}`, where `GatewayEVM` is the already deployed Gateway on ETH mainnet, Base, etc.

A successful of `GatewayEVM::depositAndCall{value}` will then trigger the `GatewayZEVM.depositAndCall` function that first transfers native ZETA to the `targetContract`, and then calls `onCall` passing the ZRC20 `zetaToken` or Wrapped ZETA address as the `zrc20` parameter.

However, `GatewayTransferNative::onCall` is implemented wrongly.

It fails to account that `zrc20` argument in `onCall` would be wZeta `0x5F0b1a82749cb4E2278EC87F8BF6B618dC71a8bf` if `GatewaySend` calls `depositAndCall{value}` to transfer native gas token to `GatewayTransferNative`. This causes `GatewayTransferNative::onCall` to  either always revert, or to transfer out someone else's wZETA.

### Root Cause

Below is the `GatewayZEVM::depositAndCall` and `GatewayZEVM::_transferZETA`: 
```solidity
// file: omni-chain-contracts/node_modules/@zetachain/protocol-contracts/contracts/zevm/GatewayZEVM.sol
function depositAndCall(...) {
    // ...
    _transferZETA(amount, target); // Sends native ZETA via a .call{value: ...}
    // @audit zetaToken here is wrappedZeta
    UniversalContract(target).onCall(context, zetaToken, amount, message); // Reports the transfer as a ZRC20 token
    
}

function _transferZETA(uint256 amount, address to) private {
        if (!IWETH9(zetaToken).transferFrom(msg.sender, address(this), amount)) revert FailedZetaSent();
        IWETH9(zetaToken).withdraw(amount);
        (bool sent,) = to.call{ value: amount }("");
        if (!sent) revert FailedZetaSent();
    }

```
Sequence of events are:
1. Transfer native zeta token via `_transferZETA`.
2. Then calls `GatewayTransferNative::onCall`, where `zetaToken` is wrappedZETA's address at `0x5F0b1a82749cb4E2278EC87F8BF6B618dC71a8bf`


3. Due to incorrect `if-else` logic  in `GatewayTransferNative::onCall` as seen [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L373-L408), The first `if` statement is always excuted when `decoded.targetZRC20 == wZETA`. This will cause GatewayTransferNative::onCall` to always revert in the case whenever ether is sent from `GatewaySend` to `GatewayTransferNative` via `GatewayEVM::depositAndCall{value}`.

4. Revert is due to `TransferHelper::safeTransfer` not handling native ZETA, or that it will transfer out another user's wZETA.

5. the `else` statement where it checks `  if (decoded.targetZRC20 == WZETA) ` will never occur
```solidity

            //....
            } else {
              //...
            }

          //...
        }
    }
```


### Internal Pre-conditions

None.

### External Pre-conditions

GatewaySend calls `GatewayEVM::depositAndCall{value}`, and the transaction is successful on external connected chain.

### Attack Path

1. User initiates `GatewaySend::_handleETHDeposit` flow via `GatewaySend::depositAndCall`. Transaction succeeds.

2. GatewayZEVM will then call the following:
```solidity
    function depositAndCall(
        MessageContext calldata context,
        uint256 amount,
        address target,
        bytes calldata message
    )
        external
        nonReentrant
        onlyProtocol
        whenNotPaused
    {
        if (target == address(0)) revert ZeroAddress();
        if (amount == 0) revert InsufficientZetaAmount();
        if (target == PROTOCOL_ADDRESS || target == address(this)) revert InvalidTarget();

        _transferZETA(amount, target);
        // what is the zetaToken if its transferring eth
        UniversalContract(target).onCall(context, zetaToken, amount, message);
    }
```
3. GatewayTransferNative::onCall will always revert if it does not have any `wZETA`, or will transfer someone else's wrapped zeta in `GatewayTransferNative::_handleFeeTransfer`.


### Impact

DoS or stuck native ZETA combined with unintended theft of other users' wrapped ZETA

### PoC

Please refer to attack path.

### Mitigation
Non trivial fix, a step towards the correct solution would be to change the first `if` statement to

```solidity
 if (decoded.targetZRC20 == WZETA) {
    IWETH9(WZETA).withdraw(outputAmount);
    TransferHelper.safeTransferETH(receiver, outputAmount-platformFeesForTx);
 }
```
