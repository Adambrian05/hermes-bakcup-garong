# Excessive Token Approval Leading to Potential Fund Drainage

## Description
The `GatewayCrossChain` contract approves tokens to gateways in excess of the amount to be transferred. This issue occurs in the withdraw functionality for Bitcoin and EVM/Solana chains, where the contract approves `outputAmount + gasFee` but only transfers `outputAmount – gasFee`. This creates a loophole that allows gateways to access more tokens than necessary, potentially leading to loss of user funds.

## Root Cause
`_handleBitcoinWithdraw` function.
```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    // Validate that the output amount is sufficient to pay the gas fee
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    
    // ❌ PROBLEM: Excessive approval
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    
    // ✅ What is actually sent to the user
    withdraw(
        externalId,                    
        decoded.receiver,              
        decoded.targetZRC20,           
        outputAmount - gasFee          // ← Only this is sent
    );
}
```
Function `_handleEvmOrSolanaWithdraw`.
```solidity
function _handleEvmOrSolanaWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    bytes memory receiver
) internal returns (uint256 amountsOutTarget) {
    (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);

    if (decoded.targetZRC20 == gasZRC20) {
        if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        
        // ❌ PROBLEM: Excessive approval
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

        // Build message data for contract call in target chain

            externalId,                
            outputAmount - gasFee,     // ← Only this is sent
            decoded.receiver,          
            decoded.swapDataB          
        );
        
        // ✅ What is actually sent to the user
        withdrawAndCall(
            externalId,                
            decoded.contractAddress,   
            decoded.targetZRC20,       
            outputAmount - gasFee,     // ← Only this is sent
            receiver,                  
            encoded                    
        );

        amountsOutTarget = outputAmount - gasFee;
    }
    // ... other codes
}
```
The root of the problem is the wrong approval calculation, because the contract uses the formula `outputAmount + gasFee` for approval, while the correct transfer calculation is the contract uses the formula `outputAmount - gasFee for` the actual transfer. This can lead to excessive gaps, where the gateway gets access to `2 * gasFee` more than necessary and there is no mechanism to revoke excessive approvals after the transaction.

## Impact
Users lose tokens equal to `2 * gasFee` per transaction.

## Scenario
Scenario 1: Bitcoin Withdraw with Excess Tokens
1. Transaction Setup:
```diff
// User wants to withdraw 1000 USDT to Bitcoin
uint256 outputAmount = 1000e6;  // 1000 USDT
uint256 gasFee = 50e6;          // 50 USDT for Bitcoin gas
```
2. Execute `_handleBitcoinWithdraw`:
```diff
// Contract approve gateway to withdraw 1050 USDT
IZRC20(USDT).approve(address(gateway), 1000e6 + 50e6); // = 1050 USDT

// Contract only send 950 USDT to user
withdraw(externalId, receiver, USDT, 1000e6 - 50e6);   // = 950 USDT
```
3. Conditions After Transaction:
- Gateway has approval for 1050 USDT
- User only receives 950 USDT
- Gateway can take additional 100 USDT without authorization

Scenario 2: EVM Withdraw with Same Token
1. Transaction Setup:
```diff
// User wants to withdraw 5 ETH to Ethereum
uint256 outputAmount = 5 ether;
uint256 gasFee = 0.1 ether;
// targetZRC20 == gasZRC20 (both ETH)
```
2. Execute `_handleEvmOrSolanaWithdraw`:
```diff
// Approve 5.1 ETH
IZRC20(ETH).approve(address(gateway), 5 ether + 0.1 ether); // = 5.1 ETH

// Send only 4.9 ETH to user
withdrawAndCall(..., 5 ether - 0.1 ether); // = 4.9 ETH
```
3. Impact:
- Gateway can access 5.1 ETH
- User receives 4.9 ETH

## Recommendation
Immediate fix for Bitcoin withdraw and EVM/Solana withdraw.
```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    // Validate that the output amount is sufficient to pay the gas fee
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    
    // ✅ FIX: Approve only the total required
    // Gateway will automatically deduct gas fee from the approved amount
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
    
    // Make a simple withdraw to Bitcoin (without contract call)
    withdraw(
        externalId,                    // Transaction ID
        decoded.receiver,              // Recipient address in Bitcoin
        decoded.targetZRC20,           // Tokens to be withdrawn
        outputAmount - gasFee          // Net amount after deducting gas fee
    );
}

function _handleEvmOrSolanaWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    bytes memory receiver
) internal returns (uint256 amountsOutTarget) {
    // Get gas token and gas fee information for target chain
    (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);

    // Check if the target token is the same as the gas token
    if (decoded.targetZRC20 == gasZRC20) {
        // If it is the same, there is no need to swap for gas fees
        
        // Validate that the output amount is sufficient to pay the gas fee.
        if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        
        // ✅ FIX: Approve only the total required
        // Gateway will automatically deduct gas fee from the approved amount.
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);

        // Build message data for contract call in target chain
        bytes memory data = SwapDataHelperLib.buildOutputMessage(
            externalId,                // Transaction ID
            outputAmount - gasFee,     // Net amount for user
            decoded.receiver,          // Recipient address
            decoded.swapDataB          // Swap data for target chain
        );
        
        // Encode data specifically for Solana if needed
        bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
            ? AccountEncoder.encodeInput(AccountEncoder.decompressAccounts(decoded.accounts), data)
            : data;

        // Make a withdrawal with a call contract
        withdrawAndCall(
            externalId,                // Transaction ID
            decoded.contractAddress,   // Contract to be called
            decoded.targetZRC20,       // Token sent
            outputAmount - gasFee,     // Number of tokens for user
            receiver,                  // Recipient address
            encoded                    // Data for contract call
        );

        // Set the number of outputs for return
        amountsOutTarget = outputAmount - gasFee;
    } else {
        // If the target token is different from the gas token, a partial swap is needed for the gas fee
        
        // Swap some target tokens to get gas tokens
        amountsOutTarget = _swapAndSendERC20Tokens(
            decoded.targetZRC20,       // Tokens to be swapped in part
            gasZRC20,                  // Gas tokens required
            gasFee,                    // The amount of gas fee required
            outputAmount               // Total amount available
        );

        // ✅ FIX: Approve is already handled in _swapAndSendERC20Tokens
        // No need for additional approve here as that function
        // already does the proper approve for both tokens

        // Build message data for contract call in target chain
        bytes memory data = SwapDataHelperLib.buildOutputMessage(
            externalId,                // Transaction ID
            amountsOutTarget,          // Net amount for user (after gas deduction)
            decoded.receiver,          // Recipient address
            decoded.swapDataB          // Swap data for target chain
        );
        
        // Encode data specifically for Solana if needed
        bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
            ? AccountEncoder.encodeInput(AccountEncoder.decompressAccounts(decoded.accounts), data)
            : data;

        // Make a withdrawal with a call contract
        withdrawAndCall(
            externalId,                // Transaction ID
            decoded.contractAddress,   // Contract to be called
            decoded.targetZRC20,       // Token sent
            amountsOutTarget,          // Number of tokens for user (after gas deduction)
            receiver,                  // Recipient address
            encoded                    // Data for contract call
        );
    }
}
```
