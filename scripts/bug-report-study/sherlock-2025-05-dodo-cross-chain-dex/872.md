# onCall() will cause loss of refunds as it blindly uses amount parameter when called via GatewayZEVM.execute()

### Summary

The absence of token balance validation in GatewayCrossChain.onCall() will cause a loss of refunds as the function blindly uses the amount parameter when called via GatewayZEVM.execute() instead of depositAndCall(), potentially allowing sophisticated users to trigger the same behavior.

### Root Cause

In GatewayCrossChain.sol, the [onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442) function uses the amount parameter to calculate fees and perform swaps without validating if it actually received the tokens. When called via GatewayZEVM.execute() (which doesn't transfer tokens), it will use any tokens in its balance (from unclaimed refunds) to fulfill the operation.
```solidity
function onCall(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    bytes calldata message
) external onlyGateway {
		// [...]
    // Transfer platform fees
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
    amount -= platformFeesForTx;

    // Swap on DODO Router
    uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);

    // Withdraw
    if (decoded.dstChainId == BITCOIN_EDDY) {
        (, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
        _handleBitcoinWithdraw(externalId, decoded, outputAmount, gasFee);
    } else {
        uint256 amountsOutTarget = _handleEvmOrSolanaWithdraw(
            externalId,
            decoded,
            outputAmount,
            decoded.receiver
        );
    }
}

```

```solidity
function execute(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    address target,
    bytes calldata message
) external nonReentrant onlyProtocol whenNotPaused {
    if (zrc20 == address(0) || target == address(0)) revert ZeroAddress();
    UniversalContract(target).onCall(context, zrc20, amount, message);
}

```

### Internal Pre-conditions

1. GatewayCrossChain must have tokens in its balance (from unclaimed refunds)
2. The tokens must match the zrc20 parameter in the call
3. The amount of tokens must be sufficient for the requested operation

### External Pre-conditions

1. GatewayZEVM.execute() must be called instead of depositAndCall()
2. (Optionally) A sophisticated user must be able to trigger execute() calls (depends on ZetaChain implementation)

### Attack Path

1. GatewayZEVM.execute() is called (either naturally by protocol or by sophisticated user)
2. Which triggers GatewayCrossChain.onCall()
3. The function will:
    - Calculate fees based on the provided amount
    - Use any tokens in its balance (from unclaimed refunds) to:
        - Pay platform fees
        - Perform swaps
        - Withdraw the resulting tokens to the attacker's address via _handleEvmOrSolanaWithdraw or _handleBitcoinWithdraw

### Impact

Users suffer a loss of their refunds as GatewayCrossChain will use any tokens in its balance to fulfill cross-chain operations when called via execute() instead of depositAndCall(). A sophisticated user who can trigger execute() calls would profit from this by:

1. Observing unclaimed refunds in GatewayCrossChain
2. Triggering execute() with their address as the receiver
3. Having the contract use the refund tokens to:
    - Pay platform fees
    - Perform swaps
    - Withdraw the resulting tokens to their address via _handleEvmOrSolanaWithdraw
