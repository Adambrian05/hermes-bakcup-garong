# Encoding/Decoding Format Mismatch in `AccountEncoder` Library Causes Data Corruption

## Description
There is a critical data format mismatch between the `encodeInput()` and `decompressAccounts()` functions in the `AccountEncoder` library. The `encodeInput()` function uses Solidity's standard encoding ABI, while `decompressAccounts()` uses a custom binary format with assembly. This mismatch causes data encoded by `encodeInput()` to not be correctly decoded by `decompressAccounts()`, which will cause cross-chain transactions to fail.

## Code Snippet
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/libraries/AccountEncoder.sol#L15-L17
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/libraries/AccountEncoder.sol#L20-L25

## Root Cause
`encodeInput()` function - ABI Encoding Standar.
```solidity
function encodeInput(Account[] memory accounts, bytes memory data) internal pure returns (bytes memory) {
    // Create an Input structure from the given parameters
    // Then encode using Solidity's standard encoding ABI
    return abi.encode(Input(accounts, data));
}
```
The resulting ABI encoding format:
```solidity
[32 bytes: offset to accounts array]
[32 bytes: offset to data bytes]  
[32 bytes: accounts array length]
[32 bytes per account: offset to struct Account]
[32 bytes: data length bytes]
[data bytes content]
[Account structs: 32 bytes publicKey + 32 bytes isWritable per account]
```
`decompressAccounts()` function - Custom Binary Format.
```solidity
assembly {
    // Starting from the 32nd byte (past the length prefix of bytes)
    let ptr := add(input, 32)
    
    // Read account array length from first 2 bytes (uint16)
    let len := add(shl(8, byte(0, mload(ptr))), byte(1, mload(ptr)))
    ptr := add(ptr, 2)
}
```
Expected custom binary format:
```solidity
[2 bytes: uint16 array length]
[33 bytes per account: 32 bytes publicKey + 1 byte isWritable]
```
The main problem lies in the fundamental difference in data format, `encodeInput()` produces data with a complex ABI encoding structure with multiple offsets and padding. `decompressAccounts()` expects simple binary data with a fixed-size format.

When `decompressAccounts()` tries to read data from `encodeInput()`. It reads the first 2 bytes as length, even though it is part of the ABI encoding offset and tries to read 33 bytes per account, even though the ABI encoding structure has a different format which will result in corrupted data or parsing errors.

## Impact
Solana account data became corrupted and could not be processed and cross-chain transactions to Solana failed systematically.

## Scenario
1. Cross-Chain Transactions to Solana:
```diff
bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
    ? AccountEncoder.encodeInput(AccountEncoder.decompressAccounts(decoded.accounts), data)
    : data;
```
2. Process that occurs:
- `decompressAccounts(decoded.accounts)` tries to decode data with a custom format
- If `decoded.accounts` is the result of `encodeInput()`, parsing will fail
- `encodeInput()` is called with corrupted data
- The encoding result becomes invalid
3. Impact on Transactions:
- Cross-chain transaction to Solana fails

## Recommendation
Change `encodeInput()` to use the same format as `decompressAccounts()`.
```solidity
function encodeInput(Account[] memory accounts, bytes memory data) internal pure returns (bytes memory) {
    uint256 accountsLength = accounts.length;
    require(accountsLength < type(uint16).max, "Too many accounts");
    
    // Calculate total size: 2 bytes length + (33 bytes * jumlah account) + 2 bytes data length + data
    uint256 totalSize = 2 + (accountsLength * 33) + 2 + data.length;
    bytes memory result = new bytes(totalSize);
    
    assembly {
        let ptr := add(result, 32) // Skip bytes length prefix
        
        // Write accounts length (uint16)
        mstore8(ptr, shr(8, accountsLength))
        mstore8(add(ptr, 1), and(accountsLength, 0xff))
        ptr := add(ptr, 2)
        
        // Write each account (33 bytes each)
        for { let i := 0 } lt(i, accountsLength) { i := add(i, 1) } {
            let account := add(add(accounts, 32), mul(i, 64)) // Each account is 64 bytes in memory
            
            // Write publicKey (32 bytes)
            let publicKey := mload(account)
            mstore(ptr, publicKey)
            ptr := add(ptr, 32)
            
            // Write isWritable (1 byte)
            let isWritable := mload(add(account, 32))
            mstore8(ptr, iszero(iszero(isWritable)))
            ptr := add(ptr, 1)
        }
        
        // Write data length (uint16)
        let dataLength := mload(data)
        mstore8(ptr, shr(8, dataLength))
        mstore8(add(ptr, 1), and(dataLength, 0xff))
        ptr := add(ptr, 2)
        
        // Write data content
        let dataPtr := add(data, 32)
        for { let i := 0 } lt(i, dataLength) { i := add(i, 32) } {
            mstore(add(ptr, i), mload(add(dataPtr, i)))
        }
    }
    
    return result;
}
```
