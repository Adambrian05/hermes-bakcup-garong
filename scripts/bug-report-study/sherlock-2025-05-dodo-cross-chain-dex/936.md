# Unrestricted Access to Cross-Chain Token Withdrawal Function Enables Asset Theft

## Summary
The `GatewayTransferNative` contract contains a critical vulnerability in its `withdraw` function. This function lacks any access control mechanism, allowing any external caller to withdraw tokens from the contract to any destination chain. The equivalent function in the related `GatewayCrossChain` contract is properly protected as `internal`, but in this contract, it's exposed as `public` without access restrictions. This vulnerability enables attackers to drain assets from the contract by initiating unauthorized cross-chain transfers.

## Root Cause
The root cause is an improper implementation of the `withdraw` function:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286

```solidity
// $question - is it missing access modifier ?
// @audit - most probabily because in gatewaycrosschain.sol it is internal.
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}
```

The function is exposed as `public` without any access control modifiers or internal validation checks, despite being designed for internal use only as evidenced by the developer comments. This allows any external caller to execute cross-chain withdrawals for arbitrary tokens and amounts.

## Attack Path
1. Attacker monitors the `GatewayTransferNative` contract for token balances
2. Attacker crafts a malicious transaction calling the unprotected `withdraw` function:
   ```solidity
   gatewayTransferNative.withdraw(
       bytes32(uint256(1)),             // Any arbitrary externalId
       abi.encodePacked(attackerWallet), // Destination wallet encoded as bytes
       valueableToken,                   // Token address to steal
       contractBalance                   // Amount to withdraw
   );
   ```
3. The `withdraw` function processes this transaction without any access checks
4. The ZetaChain gateway processes the cross-chain message
5. Tokens are withdrawn from the contract and sent to the attacker's wallet on the destination chain
6. The transaction completes successfully as it passes all existing validations

## Impact
 Very big

The severity is High as it allows direct, unauthorized access to all assets held by the contract with minimal technical barriers and no recovery mechanisms.


## Mitigation
Apply appropriate access control to the `withdraw` function.
