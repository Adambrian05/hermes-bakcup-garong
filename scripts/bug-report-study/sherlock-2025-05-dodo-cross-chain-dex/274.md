# `claimRefund` can't return native asset to `receiver`.

### Summary

[`GatewayCrossChain`.`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590), [`GatewayTransferNative`.`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) returns `aborted` or `reverted` funds to receiver.

### Root Cause

Users or bots call `claimRefund` to refund reverted or aborted funds but this can't process about native assets. 
```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
@>      TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount); // @audit this fails when refundInfo.token is _ETH_ADDRESS_
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```
This doesn't check `refundInfo.token` is `_ETH_ADDRESS_`.
