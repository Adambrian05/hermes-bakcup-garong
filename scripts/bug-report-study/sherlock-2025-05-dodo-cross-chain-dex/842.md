# Lack of externalId validation will cause loss of refunds for users as attackers can overwrite existing refund information

### Summary

The absence of externalId validation in onRevert() will cause a complete loss of refunds for users as attackers can overwrite existing refund information by calling GatewayZEVM.withdraw() directly with the same externalId.

### Root Cause

In GatewayTransferNative.sol (and also GatewayCrossChain.sol), the [onRevert()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L607) function stores refund information in the refundInfos mapping without checking if the externalId already exists, allowing attackers to overwrite existing refunds.

### Internal Pre-conditions

1. There must be unclaimed refunds stored in refundInfos mapping. The refunds must be for non-EVM addresses (to be stored in refundInfos instead of immediate payout)

### External Pre-conditions

1. The attacker must have sufficient gas to execute the attack
2. The attack must fail on the destination chain

### Attack Path

1. Attacker scans refundInfos mapping for unclaimed refunds
2. For each unclaimed refund, attacker:
a. Calls GatewayZEVM.withdraw() directly with:
    - revertAddress = GatewayTransferNative address
    - revertMessage = same externalId + attacker's address
    
    b. When the withdraw fails, it triggers onRevert()
    c. onRevert() overwrites the existing refund info in refundInfos
    d. Attacker receives their refund (on non-EVM address) by a bot that called claimRefund()

### Impact

Users suffer a complete loss of their refunds as attackers can systematically overwrite all unclaimed refund information. The original users will never be able to claim their refunds, while attackers can claim all the refunds for themselves.

### PoC

_No response_

### Mitigation

Add validation in onRevert() to prevent overwriting existing refunds.
