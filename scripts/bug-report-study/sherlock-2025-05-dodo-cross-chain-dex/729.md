# `GatewaySender::onRevert` functions does not support transferring native tokens

### Summary
Current implementation of `GatewaySender::onRevert` functions do not support transferring native tokens, it only transfers ERC20 tokens using `safeTransfer`.

### Root Cause
`GatewayEVM::executeRevert` transfers `msg.value` to destination then calls `destination::onRevert`:
```solidity
    function executeRevert(
        address destination,
        bytes calldata data,
        RevertContext calldata revertContext
    )
        public
        payable
        nonReentrant
        onlyRole(TSS_ROLE)
        whenNotPaused
    {
        if (destination == address(0)) revert ZeroAddress();
        (bool success,) = destination.call{ value: msg.value }(""); //-----> transfer msg.value to destination
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext); //-----> call onRevert
        emit Reverted(destination, address(0), msg.value, data, revertContext);
    }
```
But `GatewaySender::onRevert` tries to call `transfer(address,address,uint256)` on `context.asset`:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404
```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
        TransferHelper.safeTransfer(context.asset, sender, context.amount); //-----> tries to transfer 
        //context.asset which might not be an ERC20 token
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```
while it should transfer native tokens to `sender` when dealing with native assets.

### Internal Pre-conditions
- User depositing native tokens to zeta-chain

### External Pre-conditions
- User CCTX on zeta-chain fails
- `GatewaySender::onRevert` is called with native tokens

### Attack Path
1. Alice calls `GatewaySender::depositAndCall` to deposit 1 ETH to zetachain
2. Alice's CCTX fails and `GatewayCrossChain::executeRevert` is called to refund Alice's remaining funds (ETH)
3. `GatewaySender::onRevert` fails to refund Alice's remaining ETH

### Impact
https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions
According to the above documentation:
- If the amount is sufficient, the `GatewaySender::onRevert` on source will be called but will fail to deliver user refunds.
- User refund process will be disrupted on EVM (excluding zeta) chains

### PoC
*No response*

### Mitigation
Check if refunded assets are native and `call` sender with native assets.
