# Untrusted caller will gain owner privileges

### Summary

The use of msg.sender in the initialize() function will cause ownership hijack for the contract as any EOA or contract can call initialize() post-deploy if not already initialized via the proxy.

### Root Cause

In GatewayTransferNative.sol:117, the initialize() function uses __Ownable_init(msg.sender) to set the contract owner. If the function is not correctly restricted via initializer modifier or called securely during proxy deployment, any address can become the owner.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L109-L128


### Internal Pre-conditions

1. [No one has called] initialize() yet after proxy deployment
2. [Attacker calls] initialize() to set themselves as the owner

### External Pre-conditions

None required; this is a local EVM condition

### Attack Path

1. Attacker waits for the proxy contract to be deployed but initialize() not yet called
2. Attacker calls initialize() with their own address as msg.sender
3. Attacker becomes owner
4. Attacker uses functions like superWithdraw(), setDODORouteProxy(), or setFeePercent() to extract or redirect funds

### Impact

The protocol suffers complete administrative compromise. The attacker gains control over fee logic, fund routing, and bot permissions. Fund theft or misdirection becomes trivial.

_No response_

### Mitigation


• Use initializer modifier on initialize() and validate it’s used in a secure proxy deployment
• Deploy via a factory that immediately invokes initialize()
• Consider constructor-based deployments for singleton patterns
