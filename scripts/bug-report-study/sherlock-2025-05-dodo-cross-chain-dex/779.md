# Incomplete Slippage Protection in _swapAndSendERC20Tokens Allows Excessive Token Consumption During Swap

## Description
function withdrawToNativeChain and function onCall which calls internal function _handleEvmOrSolanaWithdraw that also calls another internal function _swapAndSendERC20Tokens which has an issue.

 The issue originated in the function _swapAndSendERC20Tokens, it is adding slippage when calculating amountInMAx, but not validating how far off the actual amount[0] was will cause a bad swap route or price spike could consume nearly all targetAmount, leaving too little for withdrawal.

The function _swapAndSendERC20Tokens uses a slippage-adjusted amountInMax as an upper bound for the token swap, calculated as:
```solidity
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
```
This sets a ceiling for how much of targetZRC20 the contract is willing to spend to acquire the required gasFee amount of gasZRC20. However, the actual amount spent in the swap (amounts[0]) is not validated after the swap occur

 Why This is Dangerous
The function does not re-verify that the actual amount spent (amounts[0]) is within a safe or expected range.

A bad swap route, price manipulation, or extreme price impact could cause amounts[0] to be close to or nearly equal to targetAmount, leaving very little or no remainder for the actual withdrawal.

Although there is a check:
```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
this is pre-swap and based on amountInMax, not on the actual swap result amounts[0].

This allows the swap to silently consume nearly all of targetZRC20, potentially leaving less than expected for the withdraw process—violating user expectations and introducing loss potential.

// Base GatewayCrossChain contract
contract GatewayCrossChain {
    IUniswapV2Router public uniswapRouter;
    address public gateway;
    uint256 public slippage;
    address public uniswapFactory;
    uint256 constant MAX_DEADLINE = 300;

    constructor() {
        slippage = 50; // 5% slippage in basis points
    }

    function getPathForTokens(address tokenIn, address tokenOut) internal pure returns (address[] memory) {
        address[] memory path = new address[](2);
        path[0] = tokenIn;
        path[1] = tokenOut;
        return path;
    }

    function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns (uint256 amountsOut) {
        uint256[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            uniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20)
        );

        uint256 amountInMax = amountsQuote[0] + (slippage * amountsQuote[0]) / 1000;
        require(amountInMax <= targetAmount, "AmountInMax exceeds targetAmount");
        IERC20(targetZRC20).approve(address(uniswapRouter), amountInMax);

        uint256[] memory amounts = uniswapRouter.swapTokensForExactTokens(
            gasFee,
            amountInMax,
            getPathForTokens(targetZRC20, gasZRC20),
            address(this),
            block.timestamp + MAX_DEADLINE
        );

        require(IERC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IERC20(gasZRC20).approve(address(gateway), gasFee);
        IERC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
}

## Recommendation
Replace or augment the current pre-swap check with a post-swap validation using the actual amount spent (amounts[0]) to ensure it does not consume too much of targetAmount.
```solidity
require(amounts[0] <= targetAmount * (MAX_SWAP_PERCENTAGE) / 100, "SWAP_CONSUMED_TOO_MUCH_TARGET");
```
Or alternatively, replace the pre-swap check with a post-swap version:
```solidity
require(targetAmount - amounts[0] > MIN_WITHDRAWAL_AMOUNT, "INSUFFICIENT_LEFT_FOR_WITHDRAW");
```
This ensures that after gas conversion, there's still a guaranteed remainder of targetZRC20 tokens left for the withdrawal.
