# Protocol fee is not subtracted from deposit amount in  `GatewayTransferNative` when the target ZRC20 is not the same as the deposited token.

### Summary

the `GatewayTransferNative` contract contains an `onCall` function for native transfers. A 5% platform fee is charged on the deposited ZRC20 token amount. The problem is this fee is not subtracted when the target zrc20 is not the same as the deposited leading to a loss in revenue to the protocol.

### Root Cause

In `onCall` there is a check if the deposit token is the same as the target token. If it is, the transfer is made directly to the receiver as no swap is needed. The transferred amount is the amount minus the 5% platform fee thats charged in [_handleFeeTransfer](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341). When the target token is different, a swap is made through the DODO router. The swap amount however is the full amount without the platform fee. The output amount is then transferred to the receiver in full leading to a loss in revenue to the protocol.

### Internal Pre-conditions

1. Users are able to deposit on the connected chain

### External Pre-conditions

1. Gateway is currently accepting deposits

### Attack Path

1. User deposits through `GatewaySend`
2. `onCall` function in `GatewayTransferNative` is called
3. Swap is made to target token and user receives full amount with no fee charged

### Impact

Loss of protocol revenue

### PoC

_No response_

### Mitigation

Subtract the platform fee from the deposit amount similarly to how its done in `GatewayCrossChain`
