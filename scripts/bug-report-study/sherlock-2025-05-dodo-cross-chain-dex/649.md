# claimRefund improperly validates the receiver/msg.sender when claiming funds

### Summary

During onRevert/onAbort calls the revert info can be stored as part of the revertInfos mapping so that it's later claimed by the owner or by a bot. In case the revertData isn't 52 bytes, (i.e. the receiver address is larger than 20 bytes), or the revertMessage is greater than that as a whole due to being malformed, anyone is able to claim the funds from the stored revert information.

### Root Cause

In both GatewayCrossChain and GatewayNative there's a `claimRefund` function:

```solidity

 function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }

```

If the wallet address stored as part of the revert/refund information is larger than 20 bytes:

```solidity

if(context.revertMessage.length == 52) {
            address receiver = address(uint160(bytes20(walletAddress)));
            TransferHelper.safeTransfer(context.asset, receiver, context.amount);


        } else {
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: context.asset,
                amount: context.amount,
                walletAddress: walletAddress
            });
            refundInfos[externalId] = refundInfo;
            
```

Anyone will be able to claim the stored refund. This is because the `claimRefund` flow sets the receiver to msg.sender and if the receiver address is larger than 20 bytes it never changes it. So the check will check if msg.sender == msg.sender which will always be true:

```solidity
require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
```

This will allow anyone to claim the particular stored refund.

### Internal Pre-conditions

There's a stored refund whose address is larger than 20 bytes;

### External Pre-conditions

A malicious user calls claimRefund;

### Attack Path

1. Malicious user calls claimRefund with an externalId matching a stored one whose address is larger than 20 bytes.

### Impact

Arbitrary users are able to steal stored refunds whose addresses are larger than 20 bytes.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590

_No response_

### Mitigation

Either allow only bots to claim stored refunds with addresses larger than 20 bytes OR always include a field which will have a 20 byte address, regardless of whether the receiver/sender isn't a 20 byte address (i.e. Solana for e.g.).
