# Griefing Attack: Attacker can re-update the refundInfo of the user to very low amount, making them lose of tokens

### Summary

In both the `GatewayCrossChain` and `GatewayTransferNative` contracts, attacker can re-update the struct of `RefundInfo` upon intentionally reverting the cross-chain transaction from his own created universal contract by making it call the `onRevert` function of `GatewayCrossChain` (or `GatewayTransferNative`) contract with the first 32 bytes same as of the user `externalId`, whose cross-chain transaction got reverted, in the revert message of revert context

### Root Cause

1. When user initiates the cross-chain transaction, user has full authority to choose the [`targetContract`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L288), as 1st parameter, which represents the universal contract in the Zetachain. And this is the contract that responsible for passing the cross-chain transaction to destination chain. 
2. `onRevert` function in the universal contract get triggers when the cross-chain transaction get reverts on target chain, if it reverts again `onAbort` function triggers

Now malicious user calls the [`GatewaySend::depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218-L285) function with targetContract as his own created contract on Zetachain, which is exact copy of `GatewayCrossChain` contract by changing the `withdraw` and `withdrawAndCall` functions

Now the universal contract was ready (**The code attached in PoC section, please refer to see the full updated contract**), so now upon intentionally reverting the cross-chain transaction, the `onRevert` of `GatewayCrossChain` (or `GatewayTransferNative`) get called as we put the revert address as this contract address. As the bytes of revert message is greater than the 52 bytes the data of the pre-existing user get  over written with our wallet address and very low amount. 

Now user cannot claim the funds within the contract, as he lost the track of the `refundInfos` mapping.

You may get how can we revert the cross-chain transaction? it is simply by pointing the destination address to our own created `GatewaySend` contract on `contractAddress` part of payload user sends and `GatewaEVM` on destination chain calls the `onCall` function of morphed `GatewaySend` contract, in which we simply revert the transaction, such that `GatewayCrossChain::onRevert` function get called in zetachain

### Internal Pre-conditions

- Assumes there `refundInfos` mapping is non-empty, i.e., there are user with their `externalId` mapped to the associated struct such that they can claim the failed cross-chain transaction funds

### External Pre-conditions

N/A

### Attack Path

1. Attacker creates his own universal contract in zetachain
2. Attacker intentionally reverting the cross-chain transaction leading to call `onRevert` on `GatewayTransferNative` or `GatewayCrossChain` contract
3. Re-update the `refundInfos` mapping of `externalId` of user
4. Making the user lose of track of his reverted tokens

### Impact

The impact is HIGH, as user loses his track of tokens within the `GatewayTransferNative` or `GatewayCrossChain` contract, such that there is no way he can redeem the tokens back like before because he can't redeem them upon calling `claimRefund` function as the `refundInfos` mapping is now pointed to the attacker structure as the struct is over-written.

### Mitigation

Add a check before executing the `onRevert` function on both `GatewayTransferNative` and `GatewayCrossChain` contracts. Which makes revert if attacker tries to re-update the data of existing user.

```diff
    function onRevert(RevertContext calldata context) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];

+        if (refundInfos[externalId].walletAddress != bytes(0)) {
+               revert("User data already exists");
+        }

        if (context.revertMessage.length == 52) {
            address receiver = address(uint160(bytes20(walletAddress)));
            TransferHelper.safeTransfer(
                context.asset,
                receiver,
                context.amount
            );

            emit EddyCrossChainRevert(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        } else {
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: context.asset,
                amount: context.amount,
                walletAddress: walletAddress
            });
            refundInfos[externalId] = refundInfo;

            emit EddyCrossChainRefund(
                externalId,
                context.asset,
                context.amount,
                walletAddress
            );
        }
    }
```
