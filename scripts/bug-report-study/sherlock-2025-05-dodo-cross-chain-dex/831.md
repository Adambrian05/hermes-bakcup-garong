# The `GatewayTransferNative::onCall()` function lacks the calculation of `platformFees`.



## Summary

The `GatewayTransferNative::onCall()` function lacks the calculation of `platformFees`.

In the `onCall` function, there is a logic error in handling `platformFees`. In the `decoded.targetZRC20 == zrc20` branch, `platformFees` are deducted, but in the `else` branch, the deduction of `platformFees` is missing, and `amount` is incorrectly used directly for `mixSwap`.  

Now let's examine the consequences when the value set for `fromTokenAmount` is the same as `amount` in common scenarios:  

(1) **GatewayTransferNative lacks excess `fromToken`**: Since `mixSwap` attempts to trade an amount larger than the available quantity (`amount - platformFeesForTx`), this creates a discrepancy between the actual funds and the `mixSwap` parameters, leading to a potential DoS.  

(2) **GatewayTransferNative holds sufficient excess `fromToken` (originally intended for refunds)**:  
`mixSwap()` will execute the exchange based on the full `amount`, consuming the extra `platformFees` quantity on `GatewayTransferNative` that should have been reserved for user refunds.  
This results in the cross-chain transaction user profiting at the expense of `GatewayTransferNative`, which then lacks sufficient funds to refund users.
