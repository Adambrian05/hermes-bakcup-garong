# Approval-Spending Mismatch in _doMixSwap Can Lead to Transaction Failure or Overspending

## Description
The function onCall calls internal  function _doMixSwap which has potential issue.
The issue lies in the function _doMixSwap, it takes an amount parameter and uses it for the approve call, but the mixSwap call uses params.fromTokenAmount instead of amount. This could lead to a mismatch if amount and params.fromTokenAmount are not equal. If params.fromTokenAmount is greater than amount, the mixSwap call will spend more tokens than approved while if is less the approval will lock more tokens than needed.

The function takes two relevant inputs:

uint256 amount: used for the approval call.

params.fromTokenAmount: used for the actual swap.

However, there is a mismatch in how these are used:

```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount); // approval for `amount`

params.fromTokenAmount, // actual amount passed to mixSwap
```
Why This Is a Problem
If params.fromTokenAmount > amount:
The call to mixSwap() may fail due to insufficient allowance, or worse, if the router has previous approval, it could spend more tokens than intended, creating a security vulnerability.

If params.fromTokenAmount < amount:
The approval allows more tokens than needed, potentially leaving a larger allowance than necessary. This:

Breaks the principle of least privilege.

Leaves the user/token vulnerable to unauthorized spending

## Recommendation
Ensure consistency by using the same value for both approval and swap:
Option 1: Use params.fromTokenAmount exclusively

```solidity
IZRC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);

params.fromTokenAmount, // passed to mixSwap
```
Option 2: Validate that amount == params.fromTokenAmount
```solidity
require(amount == params.fromTokenAmount, "Amount mismatch");
IZRC20(params.fromToken).approve(DODOApprove, amount);
```
