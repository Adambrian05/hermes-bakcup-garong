# Incorrect slippage calculation causes unnecessary transaction failures due to misunderstanding of slippage concept

### Summary

The redundant validation check `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW")` in `_swapAndSendERC20Tokens` will cause transaction failures for users as legitimate cross-chain swaps will be rejected due to incorrect use of maximum swap amount instead of actual consumed amount.

### Root Cause

In [GatewayCrossChain.sol:329](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L329) there is an unnecessary validation check `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW")` that uses `amountInMax` (maximum possible swap amount) instead of `amounts[0]` (actual consumed amount). In fact, the protocol **misunderstands slippage concepts** by calculating amountInMax based on slippage and amountsQuote, but in this context there are no competing transactions, so amountsQuote **should equal the actual amountIn without any slippage**.

### Internal Pre-conditions

1. User needs to perform cross-chain swap where `targetZRC20 != gasZRC20` requiring gas fee payment through token swap
2. Market conditions cause `targetAmount - amountInMax <= 0` while `targetAmount - amounts[0] > 0`

### External Pre-conditions

None

### Attack Path


This is not an attack but a design flaw affecting normal users:

1. Protocol queries Uniswap for exact amount needed: amountsQuote = getAmountsIn(gasTokens)
2. Protocol incorrectly adds slippage calculating amountInMax = amountsQuote * (1000 + slippage) / 1000
3. Protocol executes swap consuming exactly amountsQuote (since no competition exists)
4. Validation check uses wrong value require(targetAmount - amountInMax > 0) instead of require(targetAmount - amounts[0] > 0)
5. Transaction may fail unnecessarily when targetAmount - amountInMax <= 0 but targetAmount - amounts[0] > 0

### Impact

Users cannot complete legitimate cross-chain transactions due to overly restrictive validation. This leads to poor user experience, forced parameter adjustments, and potential missed trading opportunities.

### PoC

_No response_

### Mitigation

```diff
- require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
