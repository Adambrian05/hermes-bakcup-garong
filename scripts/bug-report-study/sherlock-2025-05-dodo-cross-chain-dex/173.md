# Any user can deplete the `ZRC20` tokens held in the `GatewayTransferNative` contract through withdrawal requests

## Vulnerability Details

In the `GatewayTransferNative` contract, the protocol permits any user to initiate a withdrawal request through `GatewayTransferNative.withdraw`, allowing them to withdraw ZRC20 tokens from Zetachain in exchange for the corresponding ERC20 tokens on the destination chain.

The issue arises when this function can be called by anyone and does not verify whether the caller has previously sent the ZRC20 tokens to the `GatewayTransferNative` contract on Zetachain before invoking the `GatewayZEVM.withdraw` function to process the token withdrawals.

As a result, any individual can drain any remaining `ZRC20` tokens in the contract (which are accumulated from reverted calls that are eligible for refunds to users who initiated withdrawals that failed). This situation can lead to the contract being drained, potentially rendering the protocol insolvent.

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {
@>    gateway.withdraw( //@audit Anyone can call this. Internally in GatewayZEVM.withdraw, msg.sender is use when transferring ZRC20 token which wil refer to GatewayTransferNative contract and anyone can drain the contract
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}
```

## POC

Consider the following scenario:

1. The GatewayTransferNative contract holds 100 USDC.ETH ZRC20 tokens that have accumulated from reverted calls.
2. Alice notices this and invokes `GatewayTransferNative.withdraw` to exchange the 100 USDC.ETH for 100 USDC on the Ethereum chain.
3. Ultimately, she does not utilize any of her own USDC.ETH ZRC20 tokens but instead exploits the funds from the `GatewayTransferNative` contract.

## Root Cause

Lack of checks that user has first transferred `ZRC20` token before initiating the gateway withdrawal call

## Impact

Protocol Insolvency. Draining of funds in `GatewayTransferNative`. Loss of funds for other users.

## Mitigation

Consider first checking that the user has transferrred the relevant ZRC20 token amount before initiating the gateway withdrawal call
