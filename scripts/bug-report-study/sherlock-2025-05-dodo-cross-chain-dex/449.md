# Missing native token handling will break swaps for users supplying native tokens

### Summary

The absence of native token detection in `_doMixSwap()` will cause failed swaps for users supplying native tokens in `GatewayTransferNative.sol`, as the contract attempts to approve and swap them using ERC-20 logic, thereby leading to failed approvals and broken execution paths.

### Root Cause

In `GatewayTransferNative.sol`,https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L434 the `_doMixSwap()` function attempts to call approve() on params.fromToken without checking whether it is a native token.

### Internal Pre-conditions

1. User supplies a native token (e.g., ZETA or address(0)) as `fromToken`

2. The swap routes through `_doMixSwap()` with valid `swapData`



### External Pre-conditions

1. Native token support is expected to use `msg.value`, not ERC-20 logic

Router does not accept `.approve()`  for native tokens

### Attack Path

1. User initiates a native token swap via the function calling `_doMixSwap()`

2. Contract calls `approve()` on a native token

3. Approval fails, breaking the swap logic

### Impact

Native-token swaps via `GatewayTransferNative.sol` fail completely. User experience and protocol usability are disrupted.
