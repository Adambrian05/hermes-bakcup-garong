# Insufficient Validation in onCall Function Exposes Protocol to Silent Corruption and Incorrect Asset Transfers


## Root Cause
The `onCall` function in the `GatewaySend` contract lacks necessary validation for cross-chain messages. While ZetaChain validators are trusted entities, the contract blindly processes potentially malformed messages through `decodePackedMessage` without verifying:

- The integrity of message structure (sufficient length, correct field boundaries).
- The validity of critical recipient address data (proper 20-byte length).
- The correctness of swap parameters before executing transfers.

This creates a critical robustness gap during protocol upgrades, validator software updates, or edge case scenarios where message corruption can occur unintentionally.

Code Reference: [onCall function in GatewaySend contract](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L114-L141)

## Proof of Concept

### 1. Protocol Version Mismatch
During a protocol upgrade, validator software is updated to optimize address encoding (e.g., truncating to save gas), but destination contracts remain unchanged:

```solidity
// Validator-side "optimization" in a new version
function encodeAddress(address addr) returns (bytes memory) {
    // Only use first 4 bytes to "optimize" gas
    return abi.encodePacked(bytes4(uint32(uint160(addr))));
}
```
The message correctly indicates `length=4`, but the contract expects 20 bytes, causing silent address corruption.

### 2. Edge Case Processing
When handling transactions with unusual parameters, validator software experiences an off-by-one error in length calculation:

- Original recipient: `0x71C7656EC7ab88b098defB751B7401B5f6d8976F`
- Corrupted (due to buffer error): `0x71C7656EC7ab88b098defB751B7401B5f6d89`

Without validation, funds transfer to an unintended address with no error indication.

## Impact
1. **Permanent Fund Loss**  
   Cross-chain transfers are irreversible by design; corrupted messages result in unrecoverable user assets.

2. **Silent Failure Mode**  
   Particularly dangerous as no errors are thrown—users see "successful" transactions while funds are irrecoverably misdirected.

3. **Historical Precedent**  
   Similar robustness issues have led to major bridge incidents:
   - **Nomad Bridge ($190M)**: Improper message validation.
   - **Wormhole ($320M)**: Trusted component failure without verification.
   - Multiple smaller bridge hacks: Combined losses over $500M.

Even if the probability is low, the catastrophic impact and irreversible nature of blockchain transactions warrant defensive measures.

### 2. Add Critical Address Validation

These changes ensure robust validation of message structure and recipient address integrity, significantly reducing the risk of fund loss and silent transaction failures.
