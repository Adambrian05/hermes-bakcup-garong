# Denial of Service in `GatewayCrossChain::onCall` Due to Incorrect `targetAmount` vs `amountInMax` Check

### Summary

We identified a **Denial of Service (DoS)** vulnerability in the `GatewayCrossChain::onCall` execution flow, when `decoded.targetZRC20 != gasZRC20`. In this case, `_swapAndSendERC20Tokens` is invoked to perform a token swap via a Uniswap pool. However, a **logical error** in the validation check causes unintended transaction failures.


Within `_swapAndSendERC20Tokens`, the following check is currently performed:

```solidity
require(targetAmount <= amountInMax, "Exceeds slippage");
```

This is **incorrect**, because:

* `amountInMax` is meant to **bound the input token** (e.g., ZRC20 amount), which corresponds to `amounts[0]`.

As a result:

* Since `targetAmount` is generally **greater than `amounts[0]`**, the condition `targetAmount <= amountInMax` may fail.
* In valid cases, this causes unnecessary reverts — creating a **denial of service** for otherwise safe and acceptable swap transactions.

### Root Cause

Incorrect check against `targetAmount`.

No need

### Impact

### Mitigation

Replace the current check with a proper  check:
```diff
-        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
+        require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
