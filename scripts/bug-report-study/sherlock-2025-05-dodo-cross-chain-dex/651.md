# Unbounded feePercent Allows Overcharging or Reverts in _handleFeeTransfer

## Description
When the function onCall is being called, there is an issue because it calls _handleFeeTransfer, which has potential issue that will propagate ( to the onCall function).

The root cause lies in the function _handleFeeTransfer, in the function _handleFeeTransfer: platformFeesForTx = (amount * feePercent) / 1000; it assumes that feePercent is less than or equal to 1000, meaning the maximum fee is 100% of the amount. If feePercent is greater than 1000(e.g., 1500), the fee becomes: platformFeesForTx = (amount * 1500) / 1000 = 1.5 * amount, this would charge more than the entire amount as a fee

Problem

The function calculates the platform fee as:
```solidity
platformFeesForTx = (amount * feePercent) / 1000;
```
This assumes that feePercent is a fixed-point value where 1000 represents 100% (i.e., feePercent = 5 means 0.5%).
However, there is no upper bound check on feePercent, which can lead to:

Overcharging: If feePercent > 1000, the fee becomes greater than 100% of amount.

For example, if feePercent = 1500, the calculated fee would be 1.5 * amount, meaning the contract tries to transfer more than the full amount.

Impact
Loss of Funds

## Recommendation
Enforce a maximum value for feePercent in the contract, such as:
```solidity
require(feePercent <= 1000, "Fee percent cannot exceed 100%");
```
