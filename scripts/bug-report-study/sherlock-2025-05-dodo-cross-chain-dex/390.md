# Dangerous use of block.timestamp in deadline parameter

### Summary

The protocol uses Uniswap to swap into the gas token needed to pay for a Zetachain withdraw, but is using `block.timestamp + MAX_DEADLINE` as the deadline argument in `swapTokensForExactTokens`:
```solidity
function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
...
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, 
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), 
                address(this),
>>>             block.timestamp + MAX_DEADLINE 
        );
...
    }
```
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L329

Using `block.timestamp + MAX_DEADLINE` as a deadline provides no protection, as the deadline check will always pass.
https://github.com/Uniswap/v2-periphery/blob/0335e8f7e1bd1e8d8329fd300aea2ef2f36dd19f/contracts/UniswapV2Router01.sol#L15-L18

What's worse is the `amountInMax` is calculated when the transaction is mined effectively removing the slippage protection.

### Root Cause

Using `block.timestamp` in the deadline argument.

Note, this same problem exists in GatewayCrossChain.

### Internal Pre-conditions

1. A user submits a cross chain EVM / Solana transaction and the protocol needs to swap into the gas token to pay for the withdraw. 

### External Pre-conditions

1. A malicious miner / MEV bot picks up the transaction

### Attack Path

1. A user submits a cross chain EVM / Solana transaction and the protocol needs to swap into the gas token to pay for the withdraw. 
2. `block.timestamp` is used as the deadline argument so a malicious miner / MEV bot picks up the transaction, and executes it later, stealing of positive slippage. 

### Impact

Failing to set a proper deadline allows pending transactions with insufficient gas to be mined later by malicious actors or MEV bots, potentially harming the original submitter.

### PoC

_No response_

### Mitigation

Allow the user to input a deadline and the `amountInMax`.
