# Users will permanently lose ETH when native chain withdrawals fail due to broken `onRevert` mechanism

### Summary

Missing ETH handling in the `onRevert` function will cause permanent fund loss for users as those who withdraw ETH via `withdrawToNativeChain` will lose their funds when the `onRevert` mechanism fails to transfer ETH back using the wrong transfer method.

### Root Cause

In [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L607-L638) the `onRevert` function uses `TransferHelper.safeTransfer()` for all assets including `_ETH_ADDRESS_`, but `safeTransfer()` only works for ERC20 tokens and will silently fail when trying to transfer ETH represented by `_ETH_ADDRESS_`.

```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    bytes memory walletAddress = context.revertMessage[32:];

    if(context.revertMessage.length == 52) {
        address receiver = address(uint160(bytes20(walletAddress)));
        TransferHelper.safeTransfer(context.asset, receiver, context.amount);
        // ↑ FAILS when context.asset = _ETH_ADDRESS_
    }
}
```

### Attack Path

1. User calls `withdrawToNativeChain(_ETH_ADDRESS_, amount, message)` with ETH value
2. The function skips the ERC20 transfer check (line 534) but continues processing
3. The message is decoded and may contain `decoded.targetZRC20 = _ETH_ADDRESS_`
4. During withdrawal processing, gateway functions are called with `_ETH_ADDRESS_` as the target ZRC20
5. The withdrawal fails on the destination chain
6. The gateway calls `onRevert()` with `context.asset = _ETH_ADDRESS_`
7. `TransferHelper.safeTransfer(_ETH_ADDRESS_, receiver, amount)` silently fails because `_ETH_ADDRESS_` is not a valid ERC20 contract
8. The function continues executing and emits the success event, making it appear the revert worked
9. But the user's ETH remains permanently trapped in the contract

### Impact

Users suffer loss of funds during `onRevert` transactions that involve ETH.
