# Protocol will send refund to incorrect address if withdraw to Bitcoin reverts

### Summary

Incorrect `bytes -> bytes20` casting in [`GatewayTransferNative.sol:300`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L300) will lead to refund to an incorrect address on ZetaChain if Bitcoin withdraw operation reverts.

`GatewayCrossChain` also suffers from the same vulnerability.

### Root Cause

`GatewayTransferNative::withdrawToNativeChain` allows withdrawing ZRC20 tokens to native chains.

If target chain is Bitcoin, the following will happen:

File: omni-chain-contracts/contracts/GatewayTransferNative.sol

In L293 and L300, sender represents `decoded.receiver` in L461, which [represents the Bitcoin receiver address](https://www.zetachain.com/docs/developers/chains/zetachain/#:~:text=The%20receiver%20is%20of%20type%20bytes%20to%20accommodate%20different%20address%20formats%20used%20by%20various%20chains%20(e.g.%2C%20Bech32%20for%20Bitcoin).):

> The receiver is of type bytes to accommodate different address formats used by various chains (e.g., Bech32 for Bitcoin). 
>
> When withdrawing to non-EVM chains make sure to encode the receiver address to bytes as string, meaning you take an address as a string of characters and convert it into bytes.

Thus, Bitcoin address has different bytes length, but in L300, it is truncated to `bytes20`.

This will lead to incorrect refund transfer in `onRevert` function:
