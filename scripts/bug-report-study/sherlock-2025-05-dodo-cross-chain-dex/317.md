# wrong value checked in `_swapAndSendERC20Tokens` in both `GatewayTransferNative` and `GatewayCrossChain` would make tx revert where it should not

### Summary

after the actual amount token is used to swap for gas fee, it would check the `targetAmount - amountInMax > 0` instead of how much actual token left after the swap.
this potentially cause unnecessary revert where `amountInMax` can be the same or exceed `targetAmount` because this amount is calculated and increased by slippage amount.

### Root Cause

this issue happen because of the implementation of both [GatewayTransferNative.sol#L319-L333](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L319-L333) and [GatewayCrossChain.sol#L315-L329](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L315-L329):

```solidty
@>        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
@>        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
@>        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```

after getting the quote of token needed for swapping to gasFee amount of gasZRC, it then proceed to calculate the quote with slippage resulting the `amountInMax`

however, by using `swapTokensForExactTokens` then the return value would then returned the actual amount that is used to swap for gasZRC.

but this amount are not used to check if the corresponding token still above 0, instead it use the `amountInMax` which can cause revert if the targetAmount < amountInMax

### Attack Path

1. user wants to bridge 100 token (`targetAmount`) from zeta chain to eth chain. current slippage at 1%
2. user call `GatewayTransferNative::withdrawAndCall`
3. it needs gasZRC, so first the function would swap it for necessary gasFee
4. the swap quote that it needs 91 token for gasFee amount of gasZRC
5. `amountInMax` would became 91 + 91 * 1% = 91 + 9.1 = 100.1 token
6. `swapTokensForExactTokens` using this amountInMax would still pass, as the amount used is only 91 token
7. but the check of `targetAmount - amountInMax > 0` would revert because underflow

### Impact

function revert because of wrong require check although the corresponding swap succeed

### Mitigation

use the amounts[0] instead of maxAmountIn:

```diff
-        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
+        require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
