# Lack of Replay Protection Enables Double-Spending

### Summary

Missing replay protection for externalId will cause fund drain for the protocol as attackers can replay processed messages to duplicate transfers.

### Root Cause

    No storage mechanism exists to track processed externalId values.

    The same externalId can be reused in multiple calls to onCall().

(https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L341C5-L386C6)

### Internal Pre-conditions

    Attacker observes a valid externalId from a prior transaction.

### External Pre-conditions

.

### Attack Path

    Legitimate user executes cross-chain transfer (generating externalId = X).

    Attacker copies message with externalId = X.

    Attacker resubmits message via gateway.

    onCall() reprocesses the message, sending duplicate funds.

### Impact

    Protocol suffers direct fund drain from duplicated transfers.

    Losses scale with replay frequency (e.g., 2x replay = 2x transferred value).

### PoC

_No response_

### Mitigation

```solidity
mapping(bytes32 => bool) public processedExternalIds;

function onCall(...) ... {
    ...
    require(!processedExternalIds[externalId], "Replayed");
    processedExternalIds[externalId] = true;
    ...
}
```
