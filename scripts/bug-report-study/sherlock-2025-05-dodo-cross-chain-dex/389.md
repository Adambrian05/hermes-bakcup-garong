# [H-1] `msg.value` is Not Validated Strictly – Allows Sending Extra ETH While Receiving Fixed Output

### Summary

The `GatewaySend::depositAndCall(...)` function allows users to deposit tokens (e.g., ETH/BNB) and transfer them cross-chain via a bridge system. However, the contract only checks whether `msg.value >= amount`, not equality.

This means:
> A user can send more ETH than declared , but only the declared amount is used for output calculations — the extra ETH remains stuck in the contract. 

This leads to: Loss of excess ETH

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L232-L236

### Root Cause

In the `GatewaySend::depositAndCall(...)` function:
```solidity
if(fromIsETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
}
```

✅ - This ensures the user sends at least the declared amount.
❌ - But it does not check if they sent more.

So:
1) `_doMixSwap(...)` uses amount as input
2) Contract assumes amount was received
3) Extra ETH stays missing forever

> No logic exists to return, withdraw or forward the excess.

### Internal Pre-conditions

1) The contract must accept native token deposits (fromToken == _ETH_ADDRESS_)
2) The `_doMixSwap(...)` function must be called with amount
3) The output token must be native (e.g., ETH on destination chain)

### External Pre-conditions

1) User calls `depositAndCall(...)` with fromToken == _ETH_ADDRESS_
2) User sends more ETH than amount in `msg.value`
3) The swap path must succeed and produce valid output

### Attack Path

NA

### Impact

The impacts include:
1) Users lose funds when sending more ETH than intended
2) Funds remain stuck indefinitely

function test_depositAndCall_takesMoreThanNecessary_SHADES() public {
    uint256 initialBalanceUser1 = user1.balance;
    uint256 initialBalanceContract = address(gatewaySendA).balance;

    address targetContract = address(gatewayTransferNative);
    uint256 amount = 100 ether;          // Expected to send and receive back
    uint256 amount_extra = 200 ether;     // Actually sent
    uint32 dstChainId = 7000;
    address asset = _ETH_ADDRESS_;
    address targetZRC20 = address(token2Z);
    bytes memory sender = abi.encodePacked(user1);
    bytes memory receiver = abi.encodePacked(user2);
    bytes memory swapDataZ = encodeCompressedMixSwapParams(
        address(token3Z),
        address(token2Z),
        amount,
        0,
        0,
        new address[](1),
        new address[](1),
        new address[](1),
        0,
        new bytes[](1),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );
    bytes memory payload = encodeNativeMessage(
        targetZRC20,
        sender,
        receiver,
        swapDataZ
    );

    vm.startPrank(user1);
    gatewaySendA.depositAndCall{value: amount_extra}(
        targetContract,
        amount,
        asset,
        dstChainId,
        payload
    );
    vm.stopPrank();

    // ✅ Only `amount` is accounted for
    assertEq(token2Z.balanceOf(user2), amount);

    // ❌ `user1` loses the extra ETH sent
    assertEq(user1.balance, initialBalanceUser1 - amount_extra);
}

### Mitigation

Update the native token validation to enforce strict equality:
```solidity
if(fromIsETH) {
    require(msg.value == amount, "INCORRECT_ETH_SENT");
}
```
