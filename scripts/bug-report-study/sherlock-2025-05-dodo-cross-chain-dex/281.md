# Refund Hijack by Whitelisted Bots (Lack of Authorization Separation)

### Summary



In the contract GatewayTransferNative.sol     [L668](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L668)  `claimRefund()` allows any address in the `bots` whitelist to claim refunds on behalf of users. If a bot is compromised or maliciously added, it can monitor mempool and claim refunds before the user, stealing funds.

### Root Cause



```solidity


function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];

    address receiver = msg.sender;
    if(refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }

// ❌ ANY BOT CAN CLAIM ANY USER'S REFUND
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");

    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");

    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
    delete refundInfos[externalId];
}

```
 Bots[msg.sender] allows any whitelisted bot to claim refunds.
 No user authorization/signature required.
 Bots can front-run legitimate users.
 No mechanism to prevent bot abuse.
This means a bot can front-run and steal refunds intended for others.

### Internal Pre-conditions

**1. Malicious address exists in `bots[]`.
2. Refund info exists.
3. Attacker monitors mempool/refund queue.**

### External Pre-conditions

### External Pre-conditions

1. No user signature verification on refund claims.
2. Mempool visible to attacker bots.

### Attack Path


1. Bot detects refund to user.
2. Bot calls `claimRefund()` before user.
3. Bot receives tokens or ETH meant for use

### Impact



Users lose refunds; bots steal funds.

### PoC


```solidity

function testRefundHijackByBot() public {
    // 1. Setup refund for victim
    bytes32 externalId = keccak256("refund1");
    mockToken.mint(address(refundContract), 1000 ether);
    refundContract.setRefundInfo(
        externalId,
        "", // no walletAddress — should default to msg.sender
        address(mockToken),
        1000 ether
    );

    // 2. Whitelist attacker as bot
    refundContract.setBot(attacker.address, true);

    // 3. Run attack
    vm.startPrank(attacker);
    refundContract.claimRefund(externalId); // attacker steals refund
    vm.stopPrank();

    // 4. Assert attacker received stolen funds
    assertEq(mockToken.balanceOf(attacker), 1000 ether);
}

```


### Mitigation

**Remove or restrict bot privileges** and require **user signature** authorization:

```diff
function claimRefund(bytes32 externalId, bytes calldata userSignature) external nonReentrant {
    RefundInfo storage refundInfo = refundInfos[externalId];

    address receiver = msg.sender;
    if(refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }

-   require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
+   // Verify user signature to authorize refund claim
+   require(verifySignature(receiver, externalId, userSignature), "INVALID_SIGNATURE");

    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");

    delete refundInfos[externalId];
    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);

    emit EddyCrossChainRefundClaimed(
        externalId,
        refundInfo.token,
        refundInfo.amount,
        abi.encodePacked(msg.sender)
    );
}

```
