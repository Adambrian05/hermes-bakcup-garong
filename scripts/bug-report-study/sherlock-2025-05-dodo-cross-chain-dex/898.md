# Users can exploit the token amounts of others in `GatewayCrossChain.onCall` due to a mismatch between `params.fromToken` and `zrc20`, enabling them to execute a swap and reap profits

## Vulnerability Details 

The `GatewayCrossChain.onCall` function can be triggered via the universal Gateway when a user employs the EVM-compatible `GatewaySend` to deposit assets and selects `GatewayCrossChain` as the target contract. In this process, the user has the ability to define `params.fromToken`, which is extracted from the `_message` created during the `GatewaySend` call and supplied by the user through `GatewaySend.depositAndCall`. Concurrently, the user will initiate the transfer of a `ZRC20` token, representing the token that `GatewayCrossChain` will receive when the universal Gateway contract calls the `GatewayCrossChain.onCall` function.

The issue arises from the lack of validation to ensure that `params.fromToken` matches `zrc20`. This oversight permits any attacker to utilize any tokens with higher value within the `GatewayCrossChain` contract to exchange for output tokens and forward it to their address in the next EVM compatible chain, thereby profiting and leading to financial losses for the protocol.

## POC

Consider the following scenario

1. Alice initiates her attack by transferring 1 USDC (1e6) from Ethereum to Zetachain and then to Polygon.
    - This process involves calling `GatewaySend.depositAndCall`, which triggers `GatewayCrossChain.onCall` by transferring 1 USDC.ETH from universal Gateway to `GatewayCrossChain`
    - Within the `GatewaySend.depositAndCall` function, she configures the `payload` with `params.fromToken` set to `WBTC.ETH` and `params.toToken` set to `USDT.ETH`
2. She notices that the `GatewayCrossChain` contract contains 1e6 worth of `WBTC.ETH` allocated for refunds.
3. Since the decoded.targetZRC20 token is not equal to the zrc20 (USDC) token, she executes the swap using `GatewayCrossChain._doMixSwap`.
    - However, as `params.fromToken` is `WBTC.ETH`, she utilizes the 1e6 `WBTC.ETH` worth of tokens in the `GatewayCrossChain` contract intended for refunds to exchange for `USDT.ETH`.
    - Let's assume she receives `1e12` worth of `USDT.ETH` in return to her zetachain address.
4.  In the end, Alice forfeits her 1e6 worth of `USDC.ETH` (which was meant to be swapped for `USDT.ETH`) but acquires 1e12 worth of `USDT.ETH` by swapping with the `WBTC.ETH` funds in the GatewayCrossChain contract, putting the protocol at risk.

## Root Cause

Lack of checks that ZRC20 token supplied by user is the inteded token to be use for swaps in `GatewayCrossChain.onCall`

## Impact

Loss of funds for protocol. Insolvency.

## Mitigation

Check that `params.fromToken = zrc20` supplied in `GatewayCrossChain.onCall`
