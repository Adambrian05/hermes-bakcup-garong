# Incorrect balance check in `_swapAndSendERC20Tokens`

## Finding description and impact

The function `_swapAndSendERC20Tokens` checks `require(targetAmount - amountInMax > 0)` to ensure there's enough of the target token left after the gas token swap. But this is incorrect.

The actual token amount used for the swap is `amounts[0]`, not `amountInMax`.

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L333

Impact:

* The `require` check may revert even when sufficient tokens remain
* Token approval for withdrawal may be based on the wrong leftover amount
* Misalignment between actual swap behavior and balance validation logic

## Mitigation

Replace the balance check:

```solidity
require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
