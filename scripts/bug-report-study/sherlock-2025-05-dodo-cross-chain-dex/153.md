# Permanently lock ETH deposits from cross-chain


### Summary

The lack of a value/token-type consistency check will cause permanent ETH loss for cross-chain swap users, as a malicious relayer will attach ETH (`msg.value`) while declaring an ERC-20 `fromToken`, sending the ether to `DODORouteProxy` where it remains unreachable.

---

### Root Cause

In [`[GatewaySend._doMixSwap]` the contract forwards **all** ether it receives without verifying that the swap’s `fromToken` is actually ETH:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L195

```solidity
function _doMixSwap(bytes calldata swapData) internal returns (uint256) {
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);

    if (params.fromToken != _ETH_ADDRESS_) {
        IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
    }

    // ⚠️ Missing: require(msg.value == 0 || params.fromToken == _ETH_ADDRESS_);
    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount,
        params.expReturnAmount,
        params.minReturnAmount,
        params.mixAdapters,
        params.mixPairs,
        params.assetTo,
        params.directions,
        params.moreInfo,
        params.feeData,
        params.deadline
    );
}
```

`DODORouteProxy.mixSwap` treats the flow as an ERC-20 swap and, via `_deposit`, **ignores the ETH**—leaving it on the proxy’s balance:

```solidity
// DODORouteProxy._deposit
if (isETH) {                // ← false for ERC-20 swaps
    require(msg.value == amount, "ETH_VALUE_WRONG");
    ...
} else {
    IDODOApproveProxy(_DODO_APPROVE_PROXY_).claimTokens(...);
    // msg.value is never checked → ETH stays in contract
}
```

---

### Internal Pre-conditions

1. **Relayer** crafts the cross-chain `payload` so that `swapData.fromToken` ≠ `_ETH_ADDRESS_`.
2. **Relayer** calls `GatewaySend.onCall` (via the Zeta Gateway) **with `msg.value > 0`**.

---

### External Pre-conditions
NA
---

### Path

1. Relayer submits a forged ERC-20 swap message but attaches ETH.
2. `GatewaySend.onCall` receives the ETH and forwards swapData to `_doMixSwap` unchanged.
3. `_doMixSwap` calls `mixSwap{value: msg.value}` with the mismatched ETH.
4. In `mixSwap`, `_deposit` takes the *ERC-20* branch; `msg.value` is ignored.
5. Swap completes (or even reverts gracefully), but the ETH now sits in the `DODORouteProxy` contract with no withdrawal path.

---

### Impact

The **cross-chain swap user** loses the entire attached ETH (up to the full `msg.value`), the locked funds can accumulate indefinitely.

---

### Mitigation

* **Invariant check** – add

  ```solidity
  require(msg.value == 0 || params.fromToken == _ETH_ADDRESS_,
          "unexpected ETH for ERC-20 swap");
  ```
