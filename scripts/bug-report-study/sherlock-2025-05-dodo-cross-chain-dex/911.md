# `_doMixSwap` blindly approves whatever token is specified in params.fromToken

### Summary

Missing token validation in `_doMixSwap`  will cause complete loss of contract-held tokens for the protocol as an attacker will specify arbitrary tokens in `MixSwapParams.fromToken` to drain gateway contract balances

### Root Cause

In there is missing validation that `params.fromToken` matches the actual received token (zrc20) from the cross-chain message.
[https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425](url)

### Attack Path

1. Attacker initiates cross-chain transaction sending Token A (e.g., 100 USDC) to `GatewayCrossChain`
2. In the message payload, attacker sets `params.fromToken` to the contract's WETH address (not USDC)
3. When `onCall` processes this, it calls `_doMixSwap` with the malicious params
4. The function approves and swaps the contract's WETH instead of the received USDC
5. Attacker receives WETH value while only paying USDC cost

### Impact

The gateway contracts `(GatewayCrossChain and GatewayTransferNative)` suffer complete loss of any tokens they hold temporarily during cross-chain operations. The attacker gains the full value of drained tokens with minimal cost (only gas fees and the cheaper token sent)
