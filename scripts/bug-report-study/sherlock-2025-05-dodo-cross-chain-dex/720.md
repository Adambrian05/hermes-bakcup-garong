# Native Zeta Can't Be Withdrawn in withdrawToNativeChain

### Summary

`GatewayTransferNative::withdrawToNativeChain` is intended to handle native Zeta withdraws as stated in the README, the fact that the function is payable, and there's logic distinguishing between native Zeta and ZRC20s:
```solidity
function withdrawToNativeChain(
        address zrc20,
        uint256 amount,
        bytes calldata message
    ) external payable {
        if(zrc20 != _ETH_ADDRESS_) {
            require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
        } 
...SNIP...
}

```
However, if native Zeta is withdrawn (and not swapped to a ZRC20 on Zetachain), the function will always revert.

### Root Cause

GatewayZEVM has two withdrawAndCall functions:
1. One for native Zeta
2. One for ZRC20s

```solidity
// Native Zeta withdrawAndCall on GatewayZEVM
 function withdrawAndCall(
        bytes memory receiver,
        uint256 amount,
        uint256 chainId,
        bytes calldata message,
        CallOptions calldata callOptions,
        RevertOptions calldata revertOptions
    ) {...}

// ZRC20 withdrawAndCall on GatewayZEVM
function withdrawAndCall(
        bytes memory receiver,
        uint256 amount,
        address zrc20,
        bytes calldata message,
        CallOptions calldata callOptions,
        RevertOptions calldata revertOptions
    ) {...}
```
https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/zevm/GatewayZEVM.sol#L227-L234
https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/zevm/GatewayZEVM.sol#L292-L299

The protocol only uses the `withdrawAndCall` for ZRC20s which is incompatible with Native Zeta.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L261-L276

### Internal Pre-conditions

1. A user calls `withdrawToNativeChain` with Native Zeta (so they're receiving the ERC20 Zeta on the destination chain, then possibly swapping to something else).

### External Pre-conditions

N/A

### Attack Path

1. A user calls `withdrawToNativeChain` with Native Zeta (so they're receiving the ERC20 Zeta on the destination chain, then possibly swapping to something else).
2. The call always reverts because there's no path that calls the correct gateway.withdrawAndCall function.

### Impact

Native Zeta can't be withdraw to native chain breaking intended protocol functionality and the user wasting gas.
