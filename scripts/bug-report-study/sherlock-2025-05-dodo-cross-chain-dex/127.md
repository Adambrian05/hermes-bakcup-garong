# Any user will lock Bitcoin withdrawals for non-ZETA assets

---

### Summary

The arithmetic mix-up between ZETA-denominated gas fee and the bridged asset (`decoded.targetZRC20`) will cause **permanent withdrawal failure** for users who try to bridge any token *other than ZETA* to Bitcoin, because the contract approves/withdraws the wrong amounts while still owing ZETA gas; any user who initiates such a transfer will therefore brick the withdrawal path and trap the funds.


### Root Cause

In `contracts/GatewayTransferNative.sol`, function `_handleBitcoinWithdraw` uses the ZETA-denominated `gasFee` as if it were denominated in `decoded.targetZRC20`:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L451


```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();

    // ❌ gasFee is in ZETA, outputAmount is in decoded.targetZRC20
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

    // ❌ subtracts ZETA amount from non-ZETA balance
    withdraw(
        externalId, 
        decoded.receiver, 
        decoded.targetZRC20, 
        outputAmount - gasFee
    );
}
```

Because `withdrawGasFee()` always quotes the fee in **ZETA**, adding or subtracting it from an arbitrary ZRC-20 token is invalid, leaving the gateway without the ZETA it needs and causing the call to revert.

---

### Internal Pre-conditions

1. User (EOA) must call `withdrawToNativeChain` with
   `decoded.dstChainId == BITCOIN_EDDY` **and** `decoded.targetZRC20 ≠ ZETA ZRC-20`.
2. Contract’s balance of `decoded.targetZRC20` must be ≥ `outputAmount`.
3. Contract’s balance of **ZETA** is *insufficient* to cover `gasFee` (the common case).

---

### External Pre-conditions

1. GatewayZEVM expects the caller to supply `gasFee` in ZETA when processing a Bitcoin withdraw.
2. Bitcoin network fees are non-zero (so `gasFee > 0`).

---

### Attack Path

1. User swaps any non-ZETA asset (e.g., wETH-ZRC20) and selects Bitcoin as the destination.
2. `withdrawToNativeChain` executes, calling `_handleBitcoinWithdraw`.
3. `_handleBitcoinWithdraw`:

   * approves `outputAmount + gasFee` of **wETH-ZRC20** to the gateway (over-approving an amount it does not own),
   * calls `gateway.withdraw` with **(outputAmount – gasFee) wETH-ZRC20** but **zero ZETA** gas.
4. Gateway detects the missing ZETA fee; the transaction reverts.
5. Control returns to `onRevert`, emitting a refund event and trapping the user’s funds until an admin-driven refund.

---

### Impact

*Affected party*: any user bridging non-ZETA tokens to Bitcoin
*Loss*: up to 100 % of the bridged amount remains stuck in the contract until manually refunded; the withdrawal never reaches Bitcoin.

---

### Mitigation

* **Correct denomination** – retrieve the tuple `(gasZRC20, gasFee)` from `withdrawGasFee()`
