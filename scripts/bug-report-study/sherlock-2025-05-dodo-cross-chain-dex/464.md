# Incorrect onRevert handling for ETH

### Summary

GatewayEVM calls onRevert on connected chain if something went wrong. But there is quirk which is unaccounted for in dodo contracts. i.e when the token is native gas token, then RevertContext's asset address is [empty](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/Revert.sol#L26-L38). 

### Root Cause

RevertContext's asset address will be empty but GatewaySend blindly thinks of the token as a ERC20 & [calls](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L396) TransferHelper.safeTransfer on it. Which will lead to reverts.


### Internal Pre-conditions

None

### External Pre-conditions

Revert flow is triggered on zetachain

### Attack Path


1. onRevert is called by gatewayEVM on GatewaySend contract
2. since the original bridged asset was ETH, the reverContext's asset address is empty.
3.  This leads to unnecessary reversion of onRevert() call. 

### Impact

onRevert() reverts.

### PoC

_No response_

### Mitigation

In revertContext check wether the context.asset address is empty,  if empty handle eth transfer.
