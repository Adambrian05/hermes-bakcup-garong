# Incorrect refund receiver set in revertMessage

### Summary

[GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L265) and [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L274) use `decoded.receiver` as the refund address in `RevertOptions.revertMessage`. However, `decoded.receiver` may be a Solana or Bitcoin address. As a result, if withdraw fails and ZetaChain protocol call `onRevert()`, tokens will be sent to incorrect `walletAddress`.
If withdraw is to an EVM chain, `decoded.receiver` may differ from the sender. On revert, ZetaChain will send the refund to `receiver`, but it should go to the original sender.

### Root Cause

Take for example [GatewayTransferNative.sol:withdraw()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286) (but this also happens in `withdrawAndCall()` and in `GatewayCrossChain.sol` same functions), `sender` here is address on Bitcoin network:
```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) public {
    gateway.withdraw(
        sender, //@audit address on Bitcoin network that will receive tokens
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            //@audit revert context for onRevert() or onAbort()
            revertMessage: bytes.concat(externalId, bytes20(sender)),
            onRevertGasLimit: gasLimit
        })
    );
}

function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee

    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();

        externalId, 
        decoded.receiver, 
        decoded.targetZRC20,
```

If withdraw reverted then `onRevert()` will be called, this function will transfer tokens to some truncated EVM-style version of the original Bitcoin/Solana address, instead of the actual sender:
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    bytes memory walletAddress = context.revertMessage[32:];

    if(context.revertMessage.length == 52) {
        address receiver = address(uint160(bytes20(walletAddress)));
        TransferHelper.safeTransfer(context.asset, receiver, context.amount);
        ...
    } else {
        RefundInfo memory refundInfo = RefundInfo({
            externalId: externalId,
            token: context.asset,
            amount: context.amount,
            walletAddress: walletAddress
        });
        refundInfos[externalId] = refundInfo;
        ...
    }
}
```

### Mitigation

In `GatewayNativeTransfer.sol` use `msg.sender` in `revertMessage` as `receiver`, while in `GatewayCrossChain.sol` use `decoded.sender`.
