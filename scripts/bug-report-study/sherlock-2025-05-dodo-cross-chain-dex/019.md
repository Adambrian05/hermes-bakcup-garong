# Missing Length Validation in `decodePackedMessage`

__Summary:__ The `decodePackedMessage` function lacks boundary checks when decoding dynamic-length fields from the input byte array, enabling a denial-of-service vulnerability.

__Vulnerability Detail:__ The `decodePackedMessage` function uses assembly to extract `receiverLen` and `crossChainDataLen` from the input `message` byte array. However, it does not validate if the calculated offsets plus these lengths (`offset + receiverLen` or `offset + crossChainDataLen`) exceed the actual length of the `message` array.

__Impact:__ An attacker can craft a `message` with excessively large `receiverLen` or `crossChainDataLen` values. When the contract attempts to slice the `message` array using these invalid lengths, it triggers an out-of-bounds access, causing an EVM panic (`Panic(0x51)`). This panic reverts the entire `onCall` transaction, effectively preventing legitimate cross-chain receive operations and leading to a denial-of-service.

__Code Snippet:__
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L114-L141

__Recommendation:__ Add explicit checks to ensure that offset + receiverLen and offset + crossChainDataLen do not exceed message.length before performing the slicing operations. Revert the transaction if the lengths are invalid.
