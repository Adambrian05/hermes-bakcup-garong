# Frontrun by creating UniV2 pair can cause users lose all their funds

### Summary

Attacker can harm user by frontrunning to deploy a pair with 1 wei liquidity, then this `_existsPairPool` returns TRUE and getAmountsIn in `_swapAndSendERC20Tokens` will either revert with underflow when `getAmountsIn`, blocking the withdrawal since the [`[reserveOut < amountOut](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L57)`](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L57), or will cause the user to overpay for the `amountOut`.

### Root Cause

Insufficient check for UniV2 pair’s ability to swap the funds.

```solidity
function _existsPairPool(
        address uniswapV2Factory,
        address zrc20A,
        address zrc20B
    ) internal view returns (bool) {
        address uniswapPool = uniswapv2PairFor(
            uniswapV2Factory,
            zrc20A,
            zrc20B
        );
        return
            IZRC20(zrc20A).balanceOf(uniswapPool) > 0 &&
            IZRC20(zrc20B).balanceOf(uniswapPool) > 0;
    }

```

Note that the issue applies to both ZEVM files - `GatewayCrossChain` and `GatewayNativeTransfer`, with the same attack path and details.

### Attack Path

1. There’s a `[zrcA, WZETA], [WZETA, zrcB]` path that has enough liquidity to satisfy the `gasFee` swap
2. Attacker frontrun by deploying and transferring 1 wei of both tokens
3. Step 2 causes `_existsPairPool` to return true, then `getPathForTokens` gives the 2-token path, but doesn’t verify that the liquidity in this pool is enough.

4a. If [`[reserveOut < amountOut](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L57)`](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L57), execution reverts

4b. Additionally, the attacker can manipulate the reserves, causing the user to lose funds, versus the execution going through the mutual `WZETA` pair.

[`[UniswapV2Library](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L53C5-L59C6)`](https://github.com/Uniswap/v2-periphery/blob/master/contracts/libraries/UniswapV2Library.sol#L53C5-L59C6)

```solidity
function getAmountIn(uint amountOut, uint reserveIn, uint reserveOut) internal pure returns (uint amountIn) {
        require(amountOut > 0, 'UniswapV2Library: INSUFFICIENT_OUTPUT_AMOUNT');
        require(reserveIn > 0 && reserveOut > 0, 'UniswapV2Library: INSUFFICIENT_LIQUIDITY');
        uint numerator = reserveIn.mul(amountOut).mul(1000);
        uint denominator = reserveOut.sub(amountOut).mul(997);
        amountIn = (numerator / denominator).add(1);
    }

```

The attacker can make `reserveOut - amountOut = 1`, then `reserveIn * amountOut(gasFee)` = maximum amount the user approves, or in case there’s an infinite approval mechanism, his entire balance, by increasing the `reserveIn`.

1. If 4b is performed, `amountInMax` in `_swapAndSendERC20Tokens` will be inflated, resulting in users losing their funds.

[[GatewayCrossChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302C5-L327C1)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302C5-L327C1)

```solidity
function _swapAndSendERC20Tokens(
    address targetZRC20,
    address gasZRC20,
    uint256 gasFee,
    uint256 targetAmount
) internal returns(uint256 amountsOut) {
    // Get amountOut for Input gasToken
    uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
        UniswapFactory,
        gasFee,
        getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
    );

    uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
    IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

    // Swap TargetZRC20 to gasZRC20
    uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
        .swapTokensForExactTokens(
            gasFee, // Amount of gas token required
            amountInMax,
            getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
            address(this),
            block.timestamp + MAX_DEADLINE
    );
```

1. Then, the attacker can observe if there’s a direct profit from doing the inverse swap and selling the received token for `WZETA` in the stable pool or simply griefing the user.

### Impact

Loss of funds for the withdrawals, by inflating the ratio of the UniV2 pair, from which the `gasFee` will be received.

### PoC

N/A

### Mitigation

Refactor the `_existsPairPool` to check which pair can handle the swap, add a view function for estimating the cost of the swap, and allow the users to define the slippage.
