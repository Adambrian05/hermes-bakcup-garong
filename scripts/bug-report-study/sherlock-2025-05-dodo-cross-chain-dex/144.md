# Token Drain via Unvalidated mixAdapters in _doMixSwap()

### Summary
The _doMixSwap function in GatewaySend.sol (lines 128-142) lacks validation for mixAdapters, enabling an attacker to drain whitelisted ZRC-20 tokens (e.g., ETH.ETH, BTC.BTC) held by the contract. An adapter is a smart contract that executes swap logic for DODORouteProxy, and an unvalidated mixAdapter is an untrusted adapter address in swapData that _doMixSwap executes without verification. By crafting malicious swapData in a cross-chain message via depositAndCall, the attacker deploys a malicious adapter to call IERC20.transferFrom, draining tokens to their address. The attacker requires only minimal gas or cross-chain fees, not a token deposit, and can repeat the attack whenever the contract holds ZRC-20 tokens from ZetaChain’s supported assets list (e.g., USDC.ARB, BTC.BTC). The project’s restriction to whitelisted ZRC-20 tokens does not mitigate the attack, as the vulnerability lies in unvalidated adapters, not token types. Tokens are drained as they are sent to the attacker’s addresses.

**Function of onCall:** The onCall function in Gatewaysend.sol [L341-L386](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386) external entry point triggered by ZetaChain’s GatewayZEVM to process cross-chain messages from depositAndCall on chain A. It decodes the message to extract evmWalletAddress and swapData, then either transfers tokens directly (if token == evmWalletAddress) or calls _doMixSwap (if token != evmWalletAddress) to execute a swap. In this attack, the attacker exploits onCall by providing malicious swapData that triggers _doMixSwap.

**_doMixSwap Visibility:**_doMixSwap is an internal function, only callable within GatewaySend.sol (or derived contracts). It’s invoked by onCall when processing a cross-chain message. The attacker indirectly triggers _doMixSwap by manipulating swapData in depositAndCall, which reaches onCall via ZetaChain’s messaging.

### Internal Pre-conditions



**1. Attacker crafts swapData with mixAdapters[0] as a malicious contract.
2. GatewaySend.sol holds at least 1 WETH or equivalent tokens.
3. token != evmWalletAddress in onCall triggers _doMixSwap.**

### External Pre-conditions

**1. ZetaChain’s GatewayEVM and GatewayZEVM process the cross-chain message.
2. DODORouteProof delegates to mixAdapters[0] with access to DODOApprove’s approval.**

 ##  Impact

The protocol loses all whitelisted ZRC-20 tokens (e.g., ETH.ETH, BTC.BTC) in GatewaySend.sol. The attacker gains these tokens with minimal cost (gas/fees) and can repeat the attack whenever the contract is replenished with supported tokens, profiting each time.

### Mitigation

- Adds a mapping to track trusted adapters, managed by the contract owner.
- Validates each mixAdapters[i] before approving tokens, blocking malicious contracts.
- Preserves existing functionality


solidity

```solidity
// GatewaySend.sol// --- Secure GatewaySend ---
contract GatewaySend is ... {
// --- Whitelist adapters ---
    mapping(address => bool) public isWhitelistedAdapter;

// --- Manage whitelist ---
    function setWhitelistedAdapter(address adapter, bool isWhitelisted) external onlyOwner {
        isWhitelistedAdapter[adapter] = isWhitelisted;
    }

// --- Secure _doMixSwap ---
    function _doMixSwap(address fromToken, uint256 fromTokenAmount, bytes memory swapData) internal returns (uint256) {
// --- Decode swapData ---
        MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);
// --- Validate adapters ---
        for (uint256 i = 0; i < params.mixAdapters.length; i++) {
            require(isWhitelistedAdapter[params.mixAdapters[i]], "Untrusted adapter");
        }
// --- Approve tokens ---
        IERC20(fromToken).approve(DODOApprove, fromTokenAmount);
// --- Execute swap ---
        uint256 outputAmount = IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
            fromTokenAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixSignatures,
            params.deadline
        );
        return outputAmount;
    }
}
```

- Token Whitelisting: The project restricts tokens to ZetaChain’s supported ZRC-20 assets (e.g., BTC.BTC, USDC.ARB). This limits the attack to whitelisted tokens but doesn’t prevent it due to unvalidated adapters.
- Attacker’s Deposit: Only minimal gas or cross-chain fees are needed for depositAndCall, as the attack drains GatewaySend.sol’s ZRC-20 tokens.
- Repeatability: The attacker can repeat the attack by sending new depositAndCall transactions with malicious swapData whenever the contract holds whitelisted tokens.
- Adapters: An adapter is a contract for swap logic; an unvalidated mixAdapter is an untrusted contract in swapData that enables drainage.
