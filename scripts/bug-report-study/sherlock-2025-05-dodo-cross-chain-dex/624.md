# Slippage in `GatewayCrossChain::_swapAndSendERC20Tokens` is atomically manipulable leading to loss of user funds

### Summary

The `_swapAndSendERC20Tokens` function in `GatewayCrossChain.sol` attempt to swap some tokens to the necessary gas token on the destination chain in the case where the desired token is not the gas token.

The issue is, this function gets a quote for the amount of tokens X to swap for gas tokens onchain and applies the slippage as well. Onchain quotes and slippage calculations and able to be manipulated by sandwich attacks. This is because when the slippage calculation is applied, the price has already been manipulated by the attacker, so any slippage protection is applied to an already manipulated value.

All quotes that deal with a minimum required output value should be done off-chain to prevent this.

### Root Cause

Imagine a user is attempting a swap of token 2A -> 1B. The route taken will be 2A -> 2Z -> 2B -> 1B where A is the source chain, B is the destination chain, and Z is the zetachain. Also, 2B is not the gas token on B. 

`GatewaySend::depositAndCall` will be called on Chain A
`GetwayCrossChain::onCall` will be called on ZetaChain
`_handleEvmOrSolanaWithdraw` will be called internally
`_swapAndSendERC20Tokens` will be called internally <--- ISSUE IS HERE
`withdrawAndCall` will be called internally which calls the `gateway` on ZetaChain to chain B

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302-L335

### Internal Pre-conditions

1. The gas token on the destination chain needs to be different than the desired token so `_swapAndSendERC20Tokens` is triggered

### External Pre-conditions

N/A

### Attack Path

1. An attacker sees the gateway transaction that will call `onCall` on `GatewayCrossChain` that requires a swap to gas tokens
2. Attacker manipulates the price of the pool to make it extremely expensive to purchase gas tokens by buying a bunch of gas tokens
3. The user ends up overpaying for the required gas tokens since the price has already been manipulated, the quote and slippage offer no protection
4. Attacker sells tokens back for a profit (sandwich attack)

### Impact

Users can lose a large portion of their initial deposit for swap. In the case of a swap of token 2A -> 2Z -> 2B -> 1B, the swap receiving 2Z will incur heavy losses. This will cause the ultimate amount received to be very small, or in many cases to revert on the destination chain when the output requirement cannot be met by the swap.
