# Uncontrolled Access to `withdraw` Function



## Finding description and impact

The `withdraw` function is designated as `public` and lacks proper access control or input validation.

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L280-L304

### Any external caller can:

* Initiate withdrawals on behalf of any `sender`
* Utilize arbitrary values for `amount` and `outputToken`

## Potential impacts:

* Illegitimate withdrawals
* Improper token routing or value loss
* Elevated risk if gateway contract relies on this input

## Mitigation

Implement the following input validations:

```solidity
require(amount > 0, "Amount must be greater than zero");
require(outputToken != address(0), "Invalid output token");
require(sender.length == 20, "Invalid sender address length");
```

Limit access to authorized contracts or roles using a modifier like `onlyOwner`, `onlyGateway`, or a custom role-based verification.

```solidity
modifier onlyTrusted() {
    require(msg.sender == address(gateway), "Unauthorized caller");
    _;
}

function withdraw(...) public onlyTrusted { ... }
```

Validate `sender` against expected user identities and prevent arbitrary withdrawal triggers.
