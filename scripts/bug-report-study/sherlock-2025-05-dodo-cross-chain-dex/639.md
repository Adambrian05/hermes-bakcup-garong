# Users can evade fees by exploiting truncation in fee calculations

### Summary

The integer division truncation in fee calculations will allow users to evade fees for small transaction amounts as the protocol fails to enforce a minimum fee, leading to revenue loss and potential micro-transaction spam.

### Root Cause

In `_handleFeeTransfer()` of `GatewayCrossChain.sol:297-300` and `GatewayTransferNative.sol:341-347`, the fee calculation `(amount * feePercent) / 1000` truncates to zero for amounts below the threshold of `1000/feePercent`, allowing users to avoid fees entirely.

### Internal Pre-conditions

- Transaction amount must be less than `1000/feePercent` (e.g., <100 for feePercent = 10)
- User must initiate multiple transactions to exploit the fee evasion
- Protocol must not have a minimum fee enforcement mechanism

### External Pre-conditions

Fee percentage must be set low enough to allow for truncation (e.g., `feePercent` = 10 or 5)
Users must be aware of the fee structure and exploit it intentionally

### Attack Path

- User initiates a transaction with an amount below the truncation threshold (e.g., 50 with `feePercent = 10`)
- The `_handleFeeTransfer()` function calculates the fee as `(50 * 10) / 1000 = 0`
- The transaction proceeds without any fees being deducted
- User repeats this process with multiple small transactions, effectively evading fees

### Impact

The protocol suffers a loss of fee revenue, which can accumulate significantly over time with numerous small transactions. Additionally, this creates a potential spam vector where users can flood the network with micro-transactions without incurring costs.

### Mitigation

Implement a minimum fee enforcement mechanism to ensure that fees are always collected, regardless of the transaction amount.
