# Excess ETH is not handled or refunded in depositAndCall, leading to silent overpayment

### Summary

The missing validation or refund of msg.value in the depositAndCall function will cause silent overpayment for users as any actor (including benign ones) who sends more ETH than the intended amount will have the entire msg.value forwarded to downstream contracts, possibly leading to loss of funds or unintended behavior in receiving contracts.



### Root Cause

In depositAndCall() implementation, the function checks that msg.value >= amount when depositing ETH, but forwards the full msg.value (instead of just amount) to _handleETHDeposit() without refunding or validating the excess.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L307-L319

### Internal Pre-conditions

A user calls depositAndCall() with asset == _ETH_ADDRESS_ (i.e., ETH deposit).

The amount parameter is correctly set to the intended ETH deposit.

The user provides a msg.value that is greater than the amount (e.g., due to UI bug or misconfiguration).

### External Pre-conditions

The downstream contract (e.g., the targetContract that receives ETH via _handleETHDeposit) does not handle or refund extra ETH.

ETH price or gas fee volatility causes user wallets or dApps to overestimate msg.value.



### Attack Path

A user calls depositAndCall() with:

amount = 1 ether

msg.value = 1.5 ether (accidental or assumed extra)

The require(msg.value >= amount) check passes.

The entire 1.5 ether is forwarded to _handleETHDeposit(), and possibly to targetContract.

The user unknowingly loses 0.5 ether which is not used or refunded.

This behavior may go unnoticed or lead to loss depending on how targetContract handles it.

### Impact

The user suffers an approximate loss of any ETH sent in excess of amount (e.g., 0.5 ETH in the example above).

### Mitigation

Option 1: Strict validation

require(msg.value == amount, "EXCESS ETH SENT");

Option 2: Refund excess ETH

uint256 excess = msg.value - amount;
if (excess > 0) {
    (bool refundSuccess, ) = msg.sender.call{value: excess}("");
    require(refundSuccess, "ETH REFUND FAILED");
}
_handleETHDeposit(targetContract, amount, message, revertOptions);
This ensures user funds are never lost due to UI error or overpayment.
