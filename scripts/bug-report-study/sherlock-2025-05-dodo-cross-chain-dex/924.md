# Replay Attack via Missing `externalId` Validation Will Drain Tokens from Users

### Summary

The missing `externalId` check in the cross-chain gateway receiver will cause duplicate fund transfers for users as an attacker will replay an old cross-chain message using the same `externalId`, triggering fund withdrawal and token swap again without permission.

### Root Cause

in https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442

In `onCall()` (the message-handling entry point), the lack of replay protection (e.g., checking a processed mapping for `externalId`) allows re-submission of the same message.

### Internal Pre-conditions

1. Cross-chain protocol gateway sends a message containing an externalId used in onCall.
2. externalId is not checked or stored to prevent reprocessing.
3. The onCall handler performs fund transfers or swaps on message receipt.

### External Pre-conditions

1. Gateway or relayer permits resending a previously signed message, or allows low-level replay (e.g., via fallback or manual relay).
2. The externalId remains unchanged in the message payload.
3. Blockchain permits multiple transactions with same calldata under different txHashes (usual).

### Attack Path

Attacker monitors a valid message execution with a known externalId.

They copy the original calldata and replay the message via the gateway or a custom call to onCall.

Since onCall does not validate uniqueness, it executes again:

Transfers tokens (e.g., withdraw(..., outputAmount - gasFee)).

Swaps tokens (e.g., swapTokensForExactTokens(...)) to fund gas or user balance.

The same logic is executed multiple times, draining tokens or gas funds.

### Impact

The protocol and users suffer permanent loss of tokens or gas tokens on each replay.
Each replayed message:

Triggers a duplicate withdrawal

Executes a duplicate Uniswap swap

Subtracts gasFee multiple times

The attacker gains nothing, but users permanently lose funds due to idempotency failure and fee double payment.

_No response_

### Mitigation

```solidity
mapping(bytes32 => bool) public processed;

function onCall(...) external {
    require(!processed[externalId], "REPLAY");
    processed[externalId] = true;

    // proceed with swap, withdrawal, etc.
}

```
