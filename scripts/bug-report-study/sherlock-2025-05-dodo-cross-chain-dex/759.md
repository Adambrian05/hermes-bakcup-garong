# Spoofed externalId in onRevert Function Overwrites Legitimate Refunds

### Summary

A critical flaw in the onRevert function of the GatewayCrossChain and GatewayTransferNative contracts allows attackers to hijack legitimate users' refund information. By crafting a malicious revertContext with a spoofed externalId, an attacker can overwrite the refundInfos mapping, potentially stealing funds or blocking users from accessing their rightful refunds.

The onRevert function overwrites the refundInfos mapping using the externalId provided in the revertContext, without verifying whether an entry for that externalId already exists. Since attackers can manipulate the externalId in their revert calls, they can target and corrupt existing refund records.

### External Pre-conditions

To exploit this vulnerability, an attacker must first deploy a malicious universal contract on ZetaChain to initiate rogue transactions. They then need to craft a revertContext payload that includes a spoofed externalId matching a legitimate user’s pending refund, along with attacker-controlled fields like token, amount, and walletAddress (e.g., pointing to their own address).

### Attack Path

The attack begins when an attacker identifies a legitimate user’s externalId associated with a pending refund stored in the refundInfos mapping. Using a malicious universal contract deployed on ZetaChain, the attacker initiates a cross-chain transaction designed to fail. They intentionally trigger a revert in their contract, which prompts ZetaChain to call the onRevert function on the gateway contract. The attacker crafts the revertContext to include the spoofed externalId of the legitimate user, along with malicious refund details, such as their own address as the recipient. When the gateway contract processes this, it overwrites the existing refundInfos[externalId] entry with the attacker’s data, effectively hijacking the refund. As a result, the legitimate user loses access to their funds, and the attacker may even claim the refund themselves.

### Impact

The attacker can redirect or steal a legitimate user’s refund. And also Overwritten refund data prevents honest users from recovering their funds.
