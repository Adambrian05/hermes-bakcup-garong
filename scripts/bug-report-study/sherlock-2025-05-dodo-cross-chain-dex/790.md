# `_handleBitcoinWithdraw()` and other functions contain the same logical flaw in regards to gas fee and output amount

### Summary

A user expects the gas fee to be send separately from the output amount and in the approve function, we can see that we approve `outputAmount + gasFee`, which is correct, but the flaw is below it.

We then send `outputAmount - gasFee`, which is totally wrong as we expected to send both together and send the receive the `outputAmount`, not the output amount minus the gas fee.

### Root Cause

User will request a cross chain swap with a lower amount than what he has send, losing money in the process (we need to send output amount + gas fee, not output amount - gas fee)

### Internal Pre-conditions

none

### External Pre-conditions

none

### Attack Path

1. User sends a request that is composed of 101e18 of some token, 100e18 output amount and 1e18 gas fee, but the amount that will be requested and processed is 99e18 as it will be calculated as `100e18 - 1e18)

### Impact

User creates a request with much less than expected, even though he has send more, losing money in the process

### PoC

_No response_

### Mitigation

Make an addition instead of an subtraction
