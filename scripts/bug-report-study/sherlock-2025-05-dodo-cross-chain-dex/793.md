# Ineffective use of the deadline patameter in `_swapAndSendERC20Tokens`

### Summary

The deadline parameter in `swapTokensForExactTokens` is supposed to guard against transactions being exected at unfavorable times. However the `block.timestamp + MAX_DEADLINE` provides no meaningful protection against pending transactions being executed at unfavourable times. 

The deadline parameter is meant to protect users by ensuring their transactions are executed within a reasonable time window of 200 seconds (from the time at which they made the call). The issue here is that there is no guarantee that the transaction will get executed at the current block at which it was processed or intended. 

The deadline check in Uniswap's router compares `block.timestamp + MAX_DEADLINE` against the current block.timestamp which will always pass the check, since `block.timestamp` is the same value .

The check is supposed to revert if the transaction is not performed after 200 seconds from the time at which the user made the call, but the current implemetation will always pass even after hours of making this call
```solidity
    function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );
        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                //@audit ineffective deadline oparameter
  @>>           block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

### Root Cause

Use of block.timestamp in deadlines

### Internal Pre-conditions

N/A

### Attack Path

* User makes the call at timestamp `100`
* Transaction gets added to a block at timestamp `500`
* User's transaction will not revert since the check perfromed on uniswap router will be;
```solidity
if (500 + 200 < 500) revert
```
which will never happen
