# Uniswap v2 pair check is not sufficient

### Summary

A malicious user can DoS all users who perform cross-chain transactions from GatewayCrossChain to other chains using a specific path.










### Root Cause

Currently, when the protocol converts a certain ZRC20 token into gasZRC20, it uses the following logic to check whether a Uniswap pair exists:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207
```solidity
     function _existsPairPool(
        address uniswapV2Factory,
        address zrc20A,
        address zrc20B
    ) internal view returns (bool) {
        address uniswapPool = uniswapv2PairFor(
            uniswapV2Factory,
            zrc20A,
            zrc20B
        );
        return
            IZRC20(zrc20A).balanceOf(uniswapPool) > 0 &&
            IZRC20(zrc20B).balanceOf(uniswapPool) > 0;
    }
```

This is insufficient — a malicious user can simply send 1 wei to the address corresponding to an uncreated pool to make it appear as a valid pair.










### Internal Pre-conditions

N/A

### External Pre-conditions

There exists a ZRC20-gas path, but currently no Uniswap V2 pool exists for it.

### Attack Path

1. The attacker directly transfers 1 wei of both tokens to the pair address.
2. All users who perform cross-chain transactions using this ZRC20-gas path will have their assets stuck, as the pool doesn't exist.

### Impact

A malicious user can DoS all users who perform cross-chain transactions from GatewayCrossChain to other chains using a specific path.










### PoC

_No response_

### Mitigation

Use try-catch to verify whether uniswap v2 reserves exist.
