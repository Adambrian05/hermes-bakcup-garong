# `_swapAndSendERC20Tokens` has no slippage protection

### Summary

This affects both `GatewayCrossChain` and `GatewayTransferNative`.

The function [_swapAndSendERC20Tokens](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302C14-L302C37) is used to swap the `targetZRC20` to it's gas token and for it's gas fee, this is done so that the gas fees for the withdrawal can be paid.

The function does the following:

```js
function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

Notice that the code computes slippage on demand based on the return result of `UniswapV2Library.getAmountsIn`.


```js
int[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
```

This is the same function that UniswapV2 uses to compute how much tokens it needs for the swap:

```js
 function swapTokensForExactTokens(
        uint amountOut,
        uint amountInMax,
        address[] calldata path,
        address to,
        uint deadline
    ) external override ensure(deadline) returns (uint[] memory amounts) {
        amounts = UniswapV2Library.getAmountsIn(factory, amountOut, path);
```

This means that the protocol is calculating slippage on demand in the same transaction the swap is taking place, meaning there is technically no slippage, as `UniswapV2Library.getAmountsIn` just gets the spot price for the swap, which can easily be exploited via MEV.

### Root Cause

Calculating the slippage on demand, based on spot pricing

### Internal Pre-conditions

Calculating the slippage on demand, based on spot pricing

### External Pre-conditions

None

### Attack Path

1. Attacker MEVs the uniswap pool prior to the swap taking place, in such a way that he can extract the maximum amount of `targetZRC20` tokens. He must only calculate it like so that `targetAmount > amountInMax`, which again he can easily do as the calculation is done on demand .
2. The swap occurs and much more of the victims tokens are consumed then they would have been.

### Impact

Loss of funds for users that have to swap their tokens for gas token

### PoC

_No response_

### Mitigation

Allow the user to specify slippage, instead of calculating it on demand
