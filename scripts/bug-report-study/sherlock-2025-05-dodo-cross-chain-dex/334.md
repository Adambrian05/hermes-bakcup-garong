# superWithdraw() Sends All Tokens to EddyTreasurySafe, Violating Its “Fees-Only” Trust

### Summary

`superWithdraw()` lets the owner transfer **any ERC20 token or ETH** into `EddyTreasurySafe`, but per project docs the `EddyTreasurySafe` address is only trusted for protocol‐fee collection. If any other funds are sent this will violate the trust assumptions provided in the docs

https://audits.sherlock.xyz/contests/991
EddyTreasurySafe is only trusted to collect the fees correctly.

> **EddyTreasurySafe** is only trusted to collect the fees correctly.

This code snippet correct shows that platform fees will be sent to `EddyTreasurySafe`
```solidity
    function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }

```

However look in the below code snippet taken from `GatewayCrossChain.sol` contract which shows `EddyTreasurySafe` can also receive funds apart from platformFeesForTx which violates the trust assumption given in sherlock docs hence marking it as medium vulnerability

```solidity
    function superWithdraw(address token, uint256 amount) external onlyOwner {
        if (token == _ETH_ADDRESS_) {
            require(amount <= address(this).balance, "INVALID_AMOUNT");
//@audit - check the receiver
            TransferHelper.safeTransferETH(EddyTreasurySafe, amount);
        } else {
            require(amount <= IZRC20(token).balanceOf(address(this)), "INVALID_AMOUNT");
//@audit - check the receiver
            TransferHelper.safeTransfer(token, EddyTreasurySafe, amount);
        }
    }
```

### Root Cause

Hardcoding `EddyTreasurySafe` as the sole recipient in Owner withdraw function ignores the README’s rule that it “only collects fees"

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L161

### Attack Path

1. Owner calls `superWithdraw(token, amount)`.
2. Function always forwards `token` or ETH to `EddyTreasurySafe`.
3. Result: all contract assets(gas fees) will be sent to `EddyTreasurySafe` address
4. `EddyTreasurySafe` address holds both contract balances + platformFees

### Impact

Violate's the trust assumptions for `EddyTreasurySafe` as per the Sherlock's readme

### Mitigation

Allow the owner to specify a `recipient` when calling superWithdraw function in both `GatewayCrossChain.sol` and `GatewayTransferNative.sol` contracts

```diff
-    function superWithdraw(address token, uint256 amount) external onlyOwner {
+    function superWithdraw(address recipient, address token, uint256 amount) external onlyOwner {
        if (token == _ETH_ADDRESS_) {
            require(amount <= address(this).balance, "INVALID_AMOUNT");
-            TransferHelper.safeTransferETH(EddyTreasurySafe, amount);
+            TransferHelper.safeTransferETH(recipient, amount);
        } else {
            require(amount <= IZRC20(token).balanceOf(address(this)), "INVALID_AMOUNT");
-           TransferHelper.safeTransfer(token, EddyTreasurySafe, amount);
+            TransferHelper.safeTransfer(token, recipient, amount);
        }
    }

```
