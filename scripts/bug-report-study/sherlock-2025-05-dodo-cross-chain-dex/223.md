# `GatewaySend.depositAndCall` will perpetually revert for specific flow due to payload size

## Vulnerability Details

User can go through the `(EVM chain) GatewaySend.depositAndCall` -> `GatewayEVM.depositAndCall` -> `(ZetaChain) GatewayCrossChain.onCall` -> receiver address on destination chain flow to initiate token flows to the receiving destination address. The problems lies with the fact that through a version of that flow, the `GatewayEVM.depositAndCall` enforces a strict 1024 bytes maximum payload size which can cause all calls with payload size bigger than 1024 to revert.

Payload size being greater than 1024 bytes is possible for a supported protocol flow

Consider the following **Scenario** 

Bob calls `GatewaySend.depositAndCall` and specifies `GatewayCrossChain` as the target contract as he wants to 
- Send USDC from `GatewaySend` (BNB chain) to `GatewayCrossChain` (ZetaChain)
- Swap USDC.BNB with USDC.ETH (since their decimal precisions are different) on ZetaChain (via `GatewayCrossChain`)
- Subsequently do a swap again on receiver address on destination chain (e,g Ethereum) using his USDC for DAI

In this process we would need to provide the following parameters which will be compressed in a call data `payload` passed into `GatewaySend.depositAndCall`

This would mean the total bytes for the above scenario is 
- 32 bytes for `externalId` concatnated to payload to get `message`
- 464 + 569 = 1033 bytes for `payload`
- 52 bytes for `reverOptions.revertMessage`
- Total bytes is 1117 bytes

The total size significantly exceeds the permitted 1024 bytes in `GatewayEVM.depositAndCall`. Now I may make some small errors in my calculations, but the point of the issue is that users attempting to go through `GatewaySend -> GatewayCrossChain (to swap Zetachain tokens) -> EVM-compatible chain (to swap ERC20 tokens)` will find this flow unreachable, as the payload size consistently surpasses the maximum limit set by Zetachain. The protocol must redesign the payload to minimize the size to enable this process.

## Root Cause

Payload size for GatewaySend -> GatewayCrossChain (swap zetachain tokens) -> EVM compatible chain (swap ERC20 token) flow always exceeds maximum allowed Payload size

## Impact

Broken protocol core functionality due to lack of considerations for maximum payload size.
