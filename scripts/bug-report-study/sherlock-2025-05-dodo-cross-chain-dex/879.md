# `_swapAndSendERC20Tokens` will lead to a DoS even in correct conditions

### Summary

The `_swapAndSendERC20Tokens` function in `GatewayCrossChain` and `GatewayTransferNative` contracts will lead to a DoS even if all the conditions are correct. It incorrectly uses `amountInMax` in place of the actual amount of tokens that is required to execute the swap.

### Root Cause

The `_swapAndSendERC20Tokens` function tries to swap `X` amount of `targetZRC20` tokens into `gasFee` amount of `gasZRC20`, where user supplies `targetAmount` of `targetZRC20` tokens, and the rest of the `targetZRC20` tokens ( targetAmount - X ) are forwarded. But however the require condition in the function is incorrect.

```solidity
   function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        @> require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW"); // @audit-issue amounts[0] instead of amountInMax

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L329

It checks if `targetAmount - amountInMax > 0`, but it actually has to be `targetAmount - amounts[0] > 0`, checking if there are `targetZRC20` tokens left after the swap. You’re comparing against the maximum you could spend (`amountInMax`), not what you actually spent.

### Attack Path

1. `targetAmount` = 105
2. Swap spends 100 (the quoted amount, within slippage)
3. `amountInMax` = 110
4. `targetAmount - amountInMax = 105 - 110 = -5`  → `require(-5 > 0)`  ❌  // fails
5. `targetAmount - amounts[0] = 105 - 100 = 5`   → `require(5 > 0)`  ✔️  // should pass
- The correct check should pass (user has 5 tokens left), but comparing against `amountInMax` (110) makes it fail, blocking perfectly valid withdrawals.

### Impact

- Valid withdrawls will lead to a DoS
