# Anyone Can Claim Refunds for Non-EVM Addresses

__Summary:__ A critical flaw in the `claimRefund` function allows any third party to steal refund funds intended for users who initiated transactions from non-EVM chains.

__Vulnerability Detail:__ The `claimRefund` function is used by users to retrieve funds that were reverted and stored in the `refundInfos` mapping. When determining who the refund should be sent to, the function checks the length of the stored `refundInfo.walletAddress`. If the length is *not* 20 bytes (which is the case for non-EVM addresses like Bitcoin or Solana), the function incorrectly sets the refund recipient (`receiver`) to the caller's address (`msg.sender`). The subsequent permission check `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");` then effectively becomes `require(bots[msg.sender] || msg.sender == msg.sender, "INVALID_CALLER");`. This check always passes for any caller, regardless of whether they are the legitimate recipient or a whitelisted bot.

__Impact:__ Any attacker who knows the `externalId` of a reverted transaction originating from a non-EVM chain can call `claimRefund` and steal the user's refund funds before the legitimate recipient can claim them.

__Recommendation:__ Correct the logic in `claimRefund` to accurately determine the intended recipient based on the stored `refundInfo.walletAddress`, regardless of its length. Implement a secure mechanism for non-EVM users to prove ownership of the original `walletAddress` (e.g., via a signed message) to claim their refunds, ensuring only the legitimate owner can access the funds.
