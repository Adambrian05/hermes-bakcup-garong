# Missing Peer-Contract validation results in overwriting RefundInfo

### Summary

Any contract can call `GatewayCrossChain.onAbort(...)` via Zetachain's Gateway contract with arbitrary data resulting in overwriting existing data or creating a new refund position.

### Root Cause

Missing validation for `AbortContext.sender` in [`GatewayCrossChain.onAbort(...)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L569) opens the function for any cross-chain call via Zetachain's Gateway on any supported chain to the protocol's `GatewayCrossChain.onAbort(...)`.

The contract fails to verify the authenticity of the request made in `onAbort`. It fails to verify if the request was made by a trusted called on source chain.

### Internal Pre-conditions

1. Protocol integrates with Zetachain bridge and implements `onRevert` and `onAbort`.
2. Zetachain's `GatewayCrossChain.onAbort` is callable externally via Zetachain's Gateway.
3. No validation exists to ensure that the origin of the message was from a known/whitelisted contract address on the source chain.
4. GatewayCrossChain trusts calldata from the Zetachain Gateway without authenticating it.

### External Pre-conditions

1. Attacker can access or simulate the Zetachain `GatewayCrossChain.onAbort` call.
2. Zetachain Gateway does not enforce strict source contract validation by default (provides metadata but leave verification to the app).

### Attack Path

> RevertOptions.revertAddress: address(0)
> RevertOptions.callOnRevert: true
> RevertOptions.abortAddress: `address(GatewayCrossChain)`
> RevertOptions.revertMessage: bytes.concat(anyExternalId, bytes20(address(attacker))
> RevertOptions.gasLimit: gasLimit

1. Attacker calls `Zetachain::Gateway.depositAndCall{value: value}(address(anyUniversalContractDesignedToRevert), bytes(""), revertOptions)`.
2. Cross-chain transaction fails on Zetachain
3. Zetachain Gateway on source chain attempts to call `onRevert` on attacker's address which also fails.
4. Zetachain Gateway on Zetachain calls `GatewayCrossChain.onAbort` which do not validate if AbortContext.sender trusted.

### Impact

1. Users whose refund positions are yet to be claimed can be overwritten using existing `externalId` resulting in user's  loss of fund.
2. Attacker can create an entirely new position to drain the protocol's contract.
