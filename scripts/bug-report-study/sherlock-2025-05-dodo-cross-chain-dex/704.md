# `GatewaySend:onRevert` fails to handle native gas token transfers

### Summary

The `GatewaySend:onRevert` function incorrectly uses `safeTransfer` when `context.asset` is the native gas token (ETH) instead of the appropriate `safeTransferETH` method.

### Root Cause

The current implementation doesn't distinguish between ERC20 tokens and native ETH transfers:

[`GatewaySend#L396`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L396)
```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));

@>      TransferHelper.safeTransfer(context.asset, sender, context.amount);
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```

It's important to note that onAbort is only available on ZetaChain, and `GatewaySend` doesn't provide users with a way to claim their funds.

### Internal Pre-conditions

context.asset is the native gas token.

### External Pre-conditions

`depositAndCall` reverts on ZETAchain.

### Impact

When `GatewaySend:depositAndCall` reverts with ETH as the asset:
- GatewaySend:onRevert will also revert
- User funds become locked in the Gateway contract
