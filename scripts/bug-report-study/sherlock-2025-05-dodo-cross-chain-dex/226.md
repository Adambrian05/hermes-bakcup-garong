# Users will permanently lose excess funds sent to the GatewaySend contract

### Summary

The lack of withdrawal mechanisms in the GatewaySend contract will cause a permanent loss of funds for users as any excess ETH or ERC20 tokens sent to the contract will be locked forever with no way to recover them.

### Root Cause

In `omni-chain-contracts/contracts/GatewaySend.sol` the contract accepts ETH and ERC20 tokens but provides no function to withdraw excess funds that accumulate in the contract.
Specific issues:
In `GatewaySend.sol` the `depositAndCall` function accepts more ETH than required (`msg.value >= amount`) but only uses `amount`
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L232-L237

In `GatewaySend.sol` the onCall function is marked as payable but has no mechanism to handle excess ETH
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L344

In `GatewaySend.sol` the contract implements receive() and fallback() functions to accept ETH but provides no way to withdraw it
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L406-L408


### Internal Pre-conditions

1. User needs to send more ETH than required when calling the `depositAndCall` function
2. User needs to approve more ERC20 tokens than needed for the transaction
3. Any transaction involving token swaps via `_doMixSwap` can leave dust amounts in the contract

### External Pre-conditions

No additional external conditions are required for this vulnerability

### Attack Path

This is a vulnerability path rather than an attack path:
1. User sends a cross-chain transaction with excess ETH (e.g., calls `depositAndCall` with `msg.value > amount`)
2. The contract only forwards `amount` ETH to the ZetaChain gateway
3. The excess ETH (i.e., `msg.value - amount`) remains locked in the contract
4. Similarly, any ERC20 tokens that are not fully swapped or transferred will remain in the contract
5. Users have no way to recover these funds as there is no withdrawal function in the contract

### Impact

The users suffer permanent loss of any excess ETH or ERC20 tokens sent to the contract. This includes:
* Excess ETH sent in transactions
* Dust amounts of tokens remaining after swaps
* Any tokens directly sent to the contract
* Tokens that might remain in the contract after failed transactions
The severity of this issue increases over time as more funds accumulate in the contract with no possibility of recovery, even by the contract owner.

### Mitigation

To fix the token lockup vulnerability in the GatewaySend contract, implement these simple solutions:
1. Add basic withdrawal functions for the owner:
```solidity
   function withdrawETH() external onlyOwner {
       payable(owner()).transfer(address(this).balance);
   }

   function withdrawERC20(address token) external onlyOwner {
       uint256 balance = IERC20(token).balanceOf(address(this));
       IERC20(token).transfer(owner(), balance);
   }
```
2. Refund excess ETH to users automatically:
```solidity
   if (fromIsETH && msg.value > amount) {
       payable(msg.sender).transfer(msg.value - amount);
   }
```
These simple changes will prevent funds from being permanently locked in the contract and allow recovery of any accidentally sent tokens.
