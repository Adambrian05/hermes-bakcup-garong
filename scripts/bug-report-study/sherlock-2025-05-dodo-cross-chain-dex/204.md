# Cross-chain swaps will fail for USDT

### Summary

The `GatewaySend` contract uses unsafe ERC20 transfer patterns that cause transaction failures when interacting with non-standard tokens like USDT. Both `depositAndCall()` and `onCall()` functions attempt to decode boolean return values from transferFrom() calls, but many major tokens (including USDT) implement these functions with void return types, causing ABI decoding failures. USDT is officially supported and whitelisted in ZetaChain and as such should be supported by Dodo.

### Root Cause

The contract [uses](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L239) the standard IERC20 interface which expects boolean return values from transfer functions:
```solidity
// In depositAndCall()
require(
    IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
    "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
);

// In onCall()  
IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
```
However, tokens like USDT implement transferFrom() with no return value. When contract tries to ABI-decode the expected boolean return value, it fails because no data was returned, causing the entire transaction to revert.

### Internal Pre-conditions

None

### External Pre-conditions

User initiates cross-chain swap using tokens like USDT or BNB, as either source token or destination token.

### Attack Path

Scenario 1 - Source Chain Failure:
- User calls depositAndCall() with USDT as fromToken
- Contract executes IERC20(USDT).transferFrom(...)
- Solidity fails to ABI-decode expected boolean, transaction reverts

Scenario 2 - Destination Chain Failure:
- Cross-chain swap completes to destination chain
- GatewaySend.onCall() attempts to transfer USDT to final recipient
- Contract executes IERC20(USDT).transferFrom(...)
- ABI decoding failure causes transaction to revert
- Revert/abort mechanism is triggered

### Impact

USDT is officially supported by ZetaChain: https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets

However, due to bug in the code, USDT cannot be successfully used in Dodo cross-chain swaps. That breaks the core contract functionality and qualifies as MEDIUM severity issue.

Use 'safe' alternatives for IERC20 functions.
