# Fee not compatible with all tokens

## Summary
According to the competition docs it protocol integrates with various chains and accept weird tokens
> ZetaChain, Ethereum, Polygon, Arbitrum, Base, BNB Chain.
The project only integrate tokens inside ZetaChain supported asset list.

Assets and tokens which contains 6 decimals , However when a user makes a crossChain call through gateway a platform fee is being accounted for But it uses hardcoded number which wont favor all tokens. 
## Description
```solidity
    function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
 @>       platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```
As we can see tokens with more than 18 decimals pays more than tokens with 6 decimals which can be rounded down to zero for small call deposits.
## Impact
Higher charge of tokens with 18 decimals than 6 decimals

## Recommended Mitigation
Handle tokens deposits with less than 18 decimals
