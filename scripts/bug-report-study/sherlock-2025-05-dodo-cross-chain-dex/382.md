# [M-1] Unsafe Token Transfers + Approval Reverts in Gateway Functions

### Summary

`GatewaySend` and `GatewayTransferNative` contracts assume that all token transfers (e.g., transferFrom) return a boolean success flag. However, native tokens like `ETH` or `BNB` do not return any bool value, causing some functions in these contracts to proceed with downstream logic (e.g., swaps) even if no funds were actually sent.

This leads to:
1) Incorrect swap execution
2) Potential protocol losses
3) Funds being swapped or sent without proper backing

Additionally, some tokens (e.g., USDT ) will revert if a non-zero allowance is already set, breaking the deposit flow.

### Root Cause

Several functions in `GatewaySend.sol` (`function depositAndCall()`, `function onCall()`) and `GatewayTransferNative.sol` (`function withdrawToNativeChain()`) assume that `IERC20.transferFrom(...)` returns a boolean:
```solidity
require(
    IERC20(fromToken).transferFrom(msg.sender, address(this), amount),
    "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
);
```

However, this assumption only holds for standard ERC-20 tokens. Tokens such as USDT and BNB don’t return a boolean — they revert on failure or silently pass on success.

As a result:
> "The require(..., "TRANSFER FAILED") check is ineffective, and the function continues as if transfer succeeded." 

---

Some tokens (USDT ) revert if you try to approve a new non-zero amount while an existing non-zero allowance exists, for security reasons.

Example:
- User approves 1000 USDT to contract A
- Later tries to deposit again → calls approve(1500)
- If contract hasn't reset to zero first → reverts
- This breaks the deposit flow silently

This affects any function using:
```solidity
IERC20(token).transferFrom(...)
```

### Impact

For functions such as `depositAndCall`, even when the `transfer or transferFrom` fails, the function will still:

1) Proceed to _doMixSwap(...):
```solidity
uint256 outputAmount = _doMixSwap(swapData);
```
2) and deposit the outputAmount:
```solidity
_handleERC20Deposit(
                targetContract,
                outputAmount, <@
                asset,
                message,
                revertOptions
            );
```

This technically results in: Loss of protocol funds

### Mitigation

We advise the team to use TransferHelper library to handle token transfers and approvals safely.
For instance, you should replace:
```solidity
IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
```

With:
```solidity
fromToken.safeTransferFrom(msg.sender, address(this), amount);
```
