# Native Currency Loss on Cross-Chain Transaction Failure in the contract GatewaySend.sol

### Summary

When a Transaction gets failed in the GatewaySend.sol contract the function onRevert is used to give the principal amount back to the failed transaction user but the function is not declared as payable, which means it cannot receive native currency if there are failed transactions that were originally sent using _handleETHDeposit(). The gateway's depositAndCall() function sends native currency to the TSS address, but if it fails and reverts, the onRevert() function cannot accept the native currency back.

### Root Cause

the root cause is the function onRevert on the contract GatewaySend.sol
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393

### Internal Pre-conditions

User needs to call depositAndCall() with native currency, triggering _handleETHDeposit()
The _handleETHDeposit() function calls gateway's depositAndCall() which sends native currency to TSS address
Cross-chain transaction needs to fail and trigger the revert mechanism

### External Pre-conditions

Gateway needs to call onRevert() function to handle the failed transaction due to failure for x y z reason

### Attack Path

User calls depositAndCall() with native currency - User sends native currency where asset == _ETH_ADDRESS_
Contract calls _handleETHDeposit() - The function calls gateway.depositAndCall{value: amount}() sending native currency to TSS address
Cross-chain transaction fails - The destination chain transaction fails for any reason
Gateway attempts to call onRevert() with native currency - The gateway tries to send native currency back through onRevert()
onRevert() function is not payable - The function cannot receive native currency, causing the revert transaction to fail
Native currency is permanently lost for the user 
no bot can return this as there is no funds directly in the contract for the name of that particular user

### Impact

Users suffer a 100% loss of their native currency when cross-chain transactions fail. The native currency becomes locked because the onRevert() function cannot receive the native currency from the gateway due to missing payable modifier
this is applicable on all the chains its being deployed
