# Attacker will steal stored tokens in GatewaySend as `onCall()` `toToken` validation is missing

### Summary

Missing validation between decoded `toToken` and swap `params.toToken` in `GatewaySend::onCall()` will cause complete loss of stored tokens for the protocol as an attacker will exploit parameter mismatch to drain contract balances.

### Root Cause

In `GatewaySend.sol:341-386` there is missing validation that the `toToken` parameter from decoded message matches `params.toToken` from the swap data in `_doMixSwap()`.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386

### Internal Pre-conditions

1. Contract needs to hold any ERC20 tokens from previous failed transactions or leftover balances

### External Pre-conditions

N/A

### Attack Path

1. Attacker initiates a cross-chain transaction through ZetaChain that calls `GatewaySend::onCall()`
2. Attacker crafts message with `toToken=WETH` but encodes `swapData` containing `params.toToken=USDC`
3. Function decodes message and extracts `toToken=WETH` and malicious `swapData`
4. Function calls `_doMixSwap(swapData)` which decodes `swapData` and finds `params.toToken=USDC`
5. `_doMixSwap()` performs swap and outputs USDC to the contract, returning USDC amount as `outputAmount`
6. Function calls `IERC20(toToken).transfer(evmWalletAddress, outputAmount)` transferring WETH from contract's existing balance
7. The USDC from the swap remains in the contract while attacker receives WETH from contract's balance
8. Attacker repeats this process for all token types held by the contract to drain them completely

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all stolen tokens from the contract while the swap output tokens accumulate in the contract without being properly distributed.

### PoC

_No response_

### Mitigation

Add validation to ensure the decoded `toToken` parameter matches the `params.toToken` from the swap data
