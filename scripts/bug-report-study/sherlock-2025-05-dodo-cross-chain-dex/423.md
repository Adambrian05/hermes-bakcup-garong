# Attacker will drain unintended tokens from the contract by faking swap input value.

### Summary

A missing verification in `_doMixSwap()` will cause a token mismatch vulnerability for the protocol as an attacker will spoof the input token in compressed swap data and trigger a fake swap with a lower-value token while claiming a higher-value one (e.g., sending 2 USDC but pretending it was 2 ETH).

### Root Cause

In `GatewayTransferNative.sol`, the `_doMixSwap()` function relies entirely on user-supplied `swapData`, including `fromToken` and `fromTokenAmount`, without verifying that the actual transferred tokens and amounts align with what's claimed. This unchecked trust in user input opens up potential for spoofing or manipulation. The issue originates [here (L425–L449)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L449) and is used [here (L394–L395)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L394-L395).

### Internal Pre-conditions

1. User constructs and submits `swapData` with a high-value fromToken (e.g., ETH) and matching `fromTokenAmount`.

2. User actually transfers a low-value token (e.g., USDC) in a matching amount (e.g., 2 USDC).

3. No internal logic checks if the claimed `fromToken` aligns with the actual token used for approval or swap.



### External Pre-conditions

1. The contract accepts arbitrary `swapData` from users without validation.

2. The swap adapter contract does not independently verify the legitimacy of the input token/amount in `params`.

### Attack Path

1. Attacker crafts malicious `swapData`, claiming to send `fromToken = ETH` and `fromTokenAmount = 2 ETH.`

2. Attacker actually sends `2 USDC` instead, relying on lack of enforcement in `_doMixSwap()`.

3. `mixSwap()` processes the swap under the assumption that 2 ETH was sent, providing a higher-value token in return.

4. Attacker receives more value than they actually provided.

### Impact

The protocol suffers a permanent loss of assets as attackers can extract more value than deposited by spoofing swap input values. The attacker gains the difference between the real token value and the spoofed one.
