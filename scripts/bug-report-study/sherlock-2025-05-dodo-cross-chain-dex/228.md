# Users withdrawing to Bitcoin will lose funds permanently when transactions fail

### Summary

The `bytes20()` cast in the withdraw function will cause permanent fund loss for users withdrawing to Bitcoin as failed Bitcoin transactions will create revert messages that send funds to uncontrolled EVM addresses instead of proper refund mechanisms.

### Root Cause

In [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L461) the `withdraw()` function is called with `decoded.receiver` (Bitcoin address) as the `sender` parameter:

```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    withdraw(
        externalId, 
        decoded.receiver,  // ❌ Bitcoin address passed as "sender" parameter
        decoded.targetZRC20, 
        outputAmount - gasFee
    );
}
```

This leads to the main issue in [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L300) where the revert message construction uses `bytes20(sender)` where `sender` is actually `decoded.receiver` (the Bitcoin destination address):

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,  // ❌ Misleading name - actually Bitcoin destination address
    address outputToken,
    uint256 amount
) public {
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)), // ❌ BUG: Truncates Bitcoin address
            onRevertGasLimit: gasLimit
        })
    );
}
```

The `bytes20()` cast truncates it to 20 bytes.This creates a valid EVM address derived from the first 20 bytes of the Bitcoin address, but this address is not controlled by the user, causing permanent fund loss when `onRevert` is triggered.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. User calls `withdrawToNativeChain()` with Bitcoin destination and valid parameters
2. Function calls `_handleBitcoinWithdraw()` which internally calls `withdraw()`
3. The `withdraw()` function creates revert message: `bytes.concat(externalId, bytes20(decoded.receiver))`
   - `decoded.receiver` is a Bitcoin address (e.g., "bc1qxy2kgdygjrsqtzq2n0yrf2493p83kkfjhx0wlh" = 42 bytes)
   - `bytes20()` truncates it to first 20 bytes: `0x6263317178793267647967...` (valid EVM address format)
4. Transaction fails and calls `onRevert()` with the revert message containing the truncated address
5. Since `revertMessage.length == 52` (32 bytes externalId + 20 bytes truncated address), the code executes:
   ```solidity
   address receiver = address(uint160(bytes20(walletAddress))); // Valid but uncontrolled address!
   TransferHelper.safeTransfer(context.asset, receiver, context.amount);
   ```
6. Funds are permanently sent to the uncontrolled EVM address (derived from Bitcoin address) with no way to recover

### Impact

Users suffer 100% loss of their withdrawal amount when Bitcoin transactions fail. The funds are permanently lost as they are sent to EVM addresses derived from Bitcoin addresses that the user does not control.

_No response_

### Mitigation

Fix the revert message construction to use the actual EVM address that initiated the withdrawal. Ensures that failed Bitcoin withdrawals properly refund tokens to the user's EVM address.
