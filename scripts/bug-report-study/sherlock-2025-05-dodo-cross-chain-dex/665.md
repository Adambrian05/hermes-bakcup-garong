# Function Visibility Misconfiguration in `GatewayTransferNative::withdraw()` function, malicious user can steal token from contract

### Summary


-   The `withdraw()` function is declared as `public` without any restrictions. Plus, `_handleBitcoinWithdraw()` and `_handleEvmOrSolanaWithdraw()` approve to `gateway` contract more token than needed. Allow any user to call and steal token from contract.


### Root Cause


1.  The `withdraw()` function is declared as `public` without any restrictions:
    [GatewayTransferNative.sol#L291](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L291)
    So, anyone can call it directly.

```solidity
    function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
@>  ) public {
        gateway.withdraw(
...
        );
    }
```

2.  Combined with when user call `withdrawToNativeChain` the `_handleBitcoinWithdraw()` and `_handleEvmOrSolanaWithdraw()` functions approve to `gateway` contract more token than needed. The correct number is only `outputAmount`, not `outputAmount + gasFee`. [GatewayTransferNative.sol#L458](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L458) and [GatewayTransferNative.sol#L477](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L477) :

        ```solidity
                IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
        ```

    In the case of `GatewayTransferNative` contract has token `targetZRC20`, and other users called `withdrawToNativeChain` to withdraw the same `targetZRC20` token. Hackers can call the `withdraw` function and withdraw the number equal to the total amount that has been extra approved from previous calls.


### Internal Pre-conditions

There is `targetZRC20` token in `GatewayTransferNative` contract.


### External Pre-conditions

Other users call `withdrawToNativeChain` successful with the same token within contract.


### Attack Path

- Hacker call `withdraw` function when the above conditions are satisfied.

### Impact

`GatewayTransferNative` contract loss `targetZRC20` token.

### PoC

_No response_

### Mitigation

1.   Set `withdraw()` function visiblity to `internal`.

```diff
    function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
-   ) public {
+   ) internal {
        gateway.withdraw(
...
        );
    }
```

2.   Set amount to approve in `_handleBitcoinWithdraw()` and `_handleEvmOrSolanaWithdraw()` equal `outputAmount`.

```diff
-    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
+    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
```
