# Invalid Solana Chain ID Breaks Cross-Chain Functionality

### Summary

Incorrect chain ID constant will cause transaction routing failures for users as cross-chain operations will fail when attempting to interact with Solana through ZetaChain's gateway system.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L19-L26

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L20-L27

### Root Cause

In both `GatewayTransferNative` and `GatewayCrossChain` contracts, the `SOLANA_EDDY` constant is set to `1399811149` instead of the official ZetaChain Solana chain ID `900`.

You can access the documentation [here](https://www.zetachain.com/docs/developers/chains/list/)


### Internal Pre-conditions

1. User needs to initiate a cross-chain transaction targeting Solana
2. Contract needs to use the `SOLANA_EDDY` constant for chain identification

### External Pre-conditions

None required - the bug exists in the hardcoded constant values.


### Attack Path

1. User calls any cross-chain function targeting Solana
2. Contract uses incorrect chain ID `1399811149` instead of `900`
3. ZetaChain's routing system fails to recognize the invalid chain ID
4. Transaction fails or gets routed incorrectly

### Impact

Users cannot execute cross-chain transactions to Solana, resulting in failed transactions and potential loss of gas fees. In worst case scenarios, funds could be lost if the invalid chain ID causes misrouting.


### PoC

_No response_

### Mitigation

Update the Solana chain ID constant to match ZetaChain's official documentation:

```diff
- uint32 constant SOLANA_EDDY = 1399811149; // chain Id from eddy db
+ uint32 constant SOLANA_ZETACHAIN = 900; // Official ZetaChain Solana chain ID
```
