# getPathForTokens fails to account for liquidity  in pools

### Summary

The getPathForTokens() function incorrectly assumes that because a pool exists, there is enough liquidity to complete a swap. This would cause unnecessary reverts as the contract would try to route swaps through pools that may have not have sufficient liquidity to complete the swap causing the call to fail

### Root Cause

```solidity
function getPathForTokens(
        address zrc20,
        address targetZRC20
    ) internal view returns (address[] memory path) {
        bool existsPairPool = _existsPairPool(
            UniswapFactory,
            zrc20,
            targetZRC20
        );

        if (existsPairPool) {
            path = new address[](2);
            path[0] = zrc20;
            path[1] = targetZRC20;
        } else {
            path = new address[](3);
            path[0] = zrc20;
            path[1] = WZETA;
            path[2] = targetZRC20;
        }
    }
```

This is a conceptual mistake :
Because a pool exists doesnt mean that there is enough liquidity in the pool to complete the swap

### Attack Path

1. Alice needs to swap from tokenA to some zeta tokens to pay for swap
2. there is a uniswap deployed pool for this tokens but very little liqudiity
3. getPathForTokens would return the path for this pair despite it having insufficient liquidity
4. the swap call will fail due to this

### Impact

users will be griefed from performing swaps from pairs that have deployed pools but with insufficient liquidity
