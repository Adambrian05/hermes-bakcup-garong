# Incorrect `abortAddress` configuration will lead to loss of funds if the `onRevert` function fails

### Summary

The `GatewayTransferNative` and `GatewayCrossChain` contracts contain a critical security vulnerability related to the configuration of `abortAddress` in `RevertOptions`. Currently set to `address(0)`, this parameter should instead be set to `address(this)` to properly handle transaction reverts according to ZetaChain's documented behavior. This misconfiguration could lead to loss of funds if the onRevert function fails.

### Root Cause

In `GatewayTransferNative` contract, both `withdrawAndCall` and `withdraw` functions implement `RevertOptions` with `abortAddress = address(0)`:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L253-L278
```solidity=253
function withdrawAndCall(
        bytes32 externalId,
        bytes memory contractAddress,
        address targetZRC20,
        uint256 outputAmount,
        bytes memory receiver,
        bytes memory message
    ) internal {
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304
```solidity=286
function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
As per ZetaChain Documentation(https://www.zetachain.com/docs/developers/chains/zetachain/#withdraw-zrc-20-tokens-and-call-a-contract-on-a-connected-chain):

1. When `callOnRevert` is `true`:
    1.1 Gateway invokes `onRevert` on the `revertAddress` (current contract)
    1.2 Remaining ZRC-20 tokens are passed with revert context
    1.3 If `onRevert` call itself reverts:
          Gateway transfers ZRC-20 tokens to `abortAddress`
          Calls `onAbort `on the `abortAddress`
2. When callOnRevert is false:
    2.1 Gateway transfers tokens to `revertAddress` without function invocation

With `abortAddress` set to `address(0)`, if `onRevert` fails, funds would be sent to the zero address and users will permanently lose their funds.

The same issues exist in `withdrawAndCall` and `withdraw` functions in `GatewayCrossChain` contract.

### External Pre-conditions

none

### Attack Path

1. The `withdrawAndCall` or `withdraw` function needs to be called
2. The `onRevert` call itself should revert

### Impact

With `abortAddress` set to `address(0)`:

1. If `onRevert` fails, funds would be sent to the zero address
2. Permanent loss of user funds in failure scenarios
3. Inability to properly handle secondary failures in the revert process
4. Violation of ZetaChain's recommended security practices
