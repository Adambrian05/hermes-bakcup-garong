# GatewayCC::withdraw sender is btc address and onRevert doesn't work

### Summary

When A → ZetaChain → Bitcoin is done, if Bitcoin fails for some reason, Zetachain's `onRevert` will be called.

Which `onRevert` and with what message is set when the outbound tx is initiated (in `GatewayCrossChain` or `GatewayTransferNative`).

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L363-L377

```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    withdraw(
        externalId, 
        decoded.receiver, 
        decoded.targetZRC20, 
        outputAmount - gasFee
    );
}
```

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L277-L295

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,
    address outputToken,
    uint256 amount
) internal {
    gateway.withdraw(
        sender, <-------------------
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)), <---------------
            onRevertGasLimit: gasLimit
        })
    );
}
```

The revertMessage will be the user `externalId` and `sender`.

But here's the problem - the same `sender` is used as the Bitcoin recipient and `onRevert` `recipient`. Which in the case of `onRevert` will fail because the Bitcoin addresses are completely different and `onRevert` will be executed on Zetachain where the address will be unknown.

### Root Cause

Same address for receiver on BTC and in case of onRevert.

### Internal Pre-conditions

None

### External Pre-conditions

When BTC tx fails, Zetachain offchain logic will call Zetachain's `onRevert`, but the BTC address will be used.

### Attack Path

None

### Impact

`onRevert` will fail, `onAbort` will not be called since `abortAddress` is `address(0)` and the tokens will be lost forever.

### PoC

N/A

### Mitigation

Add different `onRevert` receiver.
