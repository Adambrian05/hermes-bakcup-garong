# Extra allowance to the gatewayZEVM can cause protocol to loose funds.

# Description
In the GatewayCrossChain contract, the _handleEvmOrSolanaWithdraw function approves the gateway contract to spend outputAmount + gasFee of the target ZRC20 token when the target token is the same as the gas token

```solidity
if (decoded.targetZRC20 == gasZRC20) {
    // ...
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    // ...
}
```

However, according to the [GatewayZEVM contract documentation](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/zevm/GatewayZEVM.sol#L21):

> /// @dev The contract doesn't hold any funds and should never have active allowances.

This means that the gateway contract should only be approved for the exact amount required for the withdrawal, and not for any excess. Approving more than necessary increases the risk that, if the gateway contract is ever upgraded or compromised, it could drain the extra tokens from the contract.

# Impact
By approving outputAmount + gasFee instead of just outputAmount, the contract exposes itself to the risk of the gateway contract spending more tokens than intended.

# Recommendation
Change the approval to only the exact outputAmount needed for the withdrawal.

```solidity
// ...existing code...
if (decoded.targetZRC20 == gasZRC20) {
    // ...existing code...
    // Fix: Approve only the outputAmount, not outputAmount + gasFee
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
    // ...existing code...
}
// ...existing code...
```
