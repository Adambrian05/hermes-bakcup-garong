# Protocol will deny valid withdrawals as `amountInMax` validation uses incorrect value

### Summary

Using slippage-inflated `amountInMax` instead of actual swap amount `amounts[0]` in `GatewayCrossChain::_swapAndSendERC20Tokens()` and `GatewayTransferNative::_swapAndSendERC20Tokens()` validation will cause denial of valid withdrawal operations for users as the protocol incorrectly calculates remaining token amounts after gas fee swaps.

### Root Cause

In `GatewayCrossChain.sol:329` and `GatewayTransferNative.sol:333` the validation `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW")` uses `amountInMax` (which includes slippage buffer) instead of `amounts[0]` (the actual amount consumed by the swap).

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302-L335

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L333

### Internal Pre-conditions

1. User needs to initiate a cross-chain withdrawal where `decoded.targetZRC20 != gasZRC20` 
2. The `targetAmount` needs to be close to but greater than the actual swap amount plus slippage buffer

### External Pre-conditions

N/A

### Attack Path

1. User initiates a legitimate cross-chain withdrawal through `GatewayCrossChain::onCall()`
2. Function calls `_swapAndSendERC20Tokens()` to swap some target tokens for gas tokens
3. Function calculates `amountInMax = amountsQuote[0] + slippage` (includes slippage buffer)
4. Function performs swap using `swapTokensForExactTokens()` which consumes `amounts[0]` tokens (actual amount)
5. Function validates `require(targetAmount - amountInMax > 0)` using the inflated `amountInMax`
6. Validation fails even though `targetAmount - amounts[0] > 0` would pass
7. Valid withdrawal transaction reverts with "INSUFFICIENT_AMOUNT_FOR_WITHDRAW"

The same applies for `GatewayTransferNative` as well.

### Impact

Users cannot perform legitimate cross-chain withdrawals when the remaining amount after actual swap would be sufficient but insufficient when considering the slippage buffer. This breaks core contract functionality and prevents users from accessing their funds.

### PoC

_No response_

### Mitigation

Use the actual swap amount instead of the maximum amount with slippage:

```solidity
require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
