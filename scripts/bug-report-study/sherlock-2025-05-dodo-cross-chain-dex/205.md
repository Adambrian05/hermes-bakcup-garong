# Protocol unusable for multisig and account abstraction wallets

### Summary

The [GatewaySend.onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341) function uses the `.transfer()` method to send ETH to recipient addresses. This is problematic because `transfer` provides only 2300 gas for execution. This means transactions will fail when receiver is smart contract wallet or account that requires more than 2300 gas for execution. This includes multisig wallets, smart contract wallets, and even EOAs which use EIP-7702 delegation.

### Root Cause

The contract [uses](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L358..L360) the deprecated .transfer() method which forwards only 2300 gas:
```solidity
if(toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
}
```
The 2300 gas limit was designed to prevent reentrancy but is insufficient for many legitimate use cases that need to execute logic in their receive() or fallback() functions, such as:

- Gnosis Safe multisig wallets
- smart contract wallets with logging
- proxy wallets with forwarding logic
- EOAs using EIP-7702 code delegation that have custom `receive()` logic

### Internal Pre-conditions

None

### External Pre-conditions

Asset being transferred is ETH and recipient's `receive()` or `fallback()` function exceeds the 2300 gas limit

### Attack Path

1. User initiates cross-chain swap with smart contract wallet or EIP-7702 upgraded EOA as recipient
2. Swap executes successfully through ZetaChain to destination chain
3. GatewaySend.onCall() attempts ETH transfer using .transfer(outputAmount)
4. Recipient's receive() function requires >2300 gas and fails
5. Transfer failure triggers ZetaChain's revert mechanism
6. Cross-chain transaction gets reverted back to origin chain
7. User experiences failed transaction despite valid setup

### Impact

Users are completely unable to receive ETH at smart contract wallet addresses or EOAs doing code delegations. That breaks core contract functionality and as such is a medium severity issue.

_No response_

### Mitigation

Use 'call' for ETH transfer
