# Public Withdraw Function Allows Unauthorized Asset Drains

### Summary

The `withdraw()` function is public, enabling any external caller to initiate a withdrawal of arbitrary tokens and amounts via the `GatewayTransferNative`, bypassing intended access controls. This exposes the protocol to unauthorized asset drains, as no validation restricts the `sender`, `outputToken`, or `amount`.

### Root Cause

The [withdraw()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286) function is declared public instead of internal or private, and lacks access control checks to validate the `caller`, `sender`, `outputToken`, or `amount`. This allows anyone to call `GatewayTransferNative.withdraw()`, triggering a transfer of amount tokens (outputToken) to an arbitrary sender address, without authorization or balance verification.

### External Pre-conditions

None

### Attack Path

1. In `GatewayTransferNative.sol` the attacker calls withdraw with:
    - `externalId`: Any bytes32 value.
 
    - `sender`: A bytes address controlled by the attacker (e.g., their Bitcoin or EVM address).
    - `outputToken`: Address of a valuable token held by the contract or gateway (e.g., btcZ).
    - `amount`: An arbitrary amount (e.g., 1000 ether).

8. The function invokes `gateway.withdraw()`, transferring amount of `outputToken `to the sender address.
9. The attacker receives the tokens, draining protocol funds without authorization.

### Impact

The protocol is drained of it's asset tokens.
