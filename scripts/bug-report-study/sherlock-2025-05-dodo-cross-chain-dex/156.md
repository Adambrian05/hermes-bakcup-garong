# The `onCall` function in the `GatewayTransferNative` contract  use wrong amount in swap operation

## Summary
The `onCall` function in the `GatewayTransferNative` contract has a critical issue where the swap operation uses the full input amount (`amount`) instead of the fee-adjusted amount (`amount - platformFeesForTx`) when `targetZRC20` and `zrc20` differ. If the contract has enough `zrc20` liquidity, the swap executes without deducting fees from the user’s amount. That means the fee (`platformFeesForTx`) is paid from the contract’s balance, not the user’s.

## Vulnerability Detail
The `onCall` function in the `GatewayTransferNative` contract is called by the gateway to execute the cross-chain swap

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357-L423
```solidity
function onCall(
        MessageContext calldata context,
        address zrc20,
        uint256 amount,
        bytes calldata message
    ) external override onlyGateway {
        // Decode the message
        // 32 bytes(externalId) + bytes message
        (bytes32 externalId) = abi.decode(message[0:32], (bytes32)); 
        bytes calldata _message = message[32:];
        (DecodedNativeMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeNativeMessage(_message);

        // Fee for platform
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        address receiver = address(uint160(bytes20(decoded.receiver)));

        if (decoded.targetZRC20 == zrc20) {
            // same token
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx
            );

            emit EddyCrossChainSwap(
                externalId,
                uint32(context.chainID),
                ZETACHAIN,
                zrc20,
                decoded.targetZRC20,
                amount,
                amount - platformFeesForTx,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx
            );
        } else {
            // Swap on DODO Router
            uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

            if (decoded.targetZRC20 == WZETA) {
                // withdraw WZETA to get Zeta in 1:1 ratio
                IWETH9(WZETA).withdraw(outputAmount);
                // transfer wzeta
                TransferHelper.safeTransferETH(receiver, outputAmount);
            } else {
                TransferHelper.safeTransfer(
                    decoded.targetZRC20,
                    receiver,
                    outputAmount
                );
            }

            emit EddyCrossChainSwap(
                externalId,
                uint32(context.chainID),
                ZETACHAIN,
                zrc20,
                decoded.targetZRC20,
                amount,
                outputAmount,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx
            );
        }
    }
```

It first charges `platformFeesForTx` fees from `amount` by calling `_handleFeeTransfer `:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L370
```solidity
uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
```

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341-L347
```solidity
function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```

Then if  `targetZRC20 == zrc20`, it transfers `amount - platformFeesForTx` to the receiver(which is correct):

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L373-L393
```solidity
if (decoded.targetZRC20 == zrc20) {

                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx
            );

                externalId,
                uint32(context.chainID),
                ZETACHAIN,
                zrc20,
                decoded.targetZRC20,
                amount,
                amount - platformFeesForTx,
                decoded.sender,

```
However if `targetZRC20 != zrc20`, it calls `_doMixSwap(swapData, amount, params)` without deducting fees first. This call effectively swaps the full amount, meaning the platform fee was deducted but the swap still uses the original amount.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395
```solidity
uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
```

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L449
```solidity
function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```
In `_doMixSwap`,  it approves the swap router to spend the full input amount, the `params` is user-provided params, which means the user can specify how much of `fromToken` to swap.  Since `amount` (pre-fee) is approved, the swap can consume up to the full amount, ignoring the fee that was supposed to be deducted.

If the contract has enough `zrc20` liquidity, the swap executes without deducting fees from the user’s amount. That means the fee (`platformFeesForTx`) is paid from the contract’s balance, not the user’s.

## Example Scenario
1. User sends 100 USDC (`zrc20`) to swap to targetZRC20 (e.g., `ETH`).
2. Fee = 5 USDC (`platformFeesForTx`).
3. Current Buggy Logic:
     `_handleFeeTransfer()` deducts 5 USDC from the contract’s balance (not the user’s).
     `_doMixSwap(100 USDC)` executes, swapping the full 100 USDC (instead of 95 USDC).
     User gets the full swap value (100 USDC → ETH), but only the contract loses the 5 USDC fee.

## Impact
High (High Impact * High Likelihood)
Users benefit unfairly (they avoid paying fees).
The contract loses funds (it covers the fee from its own balance).
If repeated frequently, the contract could be drained of fees.

## Recommendation
Consider following fix:
```solidity
uint256 outputAmount = _doMixSwap(decoded.swapData, amount-platformFeesForTx, params);
```
