# Attacker will re enter onCall and execute malicious logic in GatewaySend

### Summary

The lack of a reentrancy guard in `GatewaySend.onCall()` will cause a reentrant execution vulnerability for the `GatewaySend` contract as an attacker will craft a malicious token contract to exploit `transferFrom()` and call back into `GatewaySend` during the same transaction.

### Root Cause

In [`GatewaySend.sol:onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341), there is no reentrancy protection on the `onCall()` function, which makes it unsafe to call user-defined token contracts that can re-enter during `transferFrom`.

### Internal Pre-conditions

1. The gateway must call `onCall()` and pass a malicious token as `fromToken`
1. The malicious token must override `transferFrom()` to perform a reentrant call
1. `GatewaySend.depositAndCall()` must be exposed and reachable by reentrant call from `transferFrom`



### External Pre-conditions

The gateway must accept this token address as a valid `fromToken`

### Attack Path

1. The attacker deploys a `MaliciousToken` that overrides `transferFrom()` and holds a reference to the target `GatewaySend`
1. Inside `transferFrom()`, the attacker makes a reentrant call to `depositAndCall()`
1. The `onCall()` function is called again before it finishes its original execution, leading to unexpected state changes or logic abuse

### Impact

The protocol suffers a critical reentrancy vulnerability. The attacker may bypass intended logic, drain tokens.

### PoC

```solidity
function transferFrom(address from, address to, uint256 amount) external override returns (bool) {
    balances[from] -= amount;
    balances[to] += amount;

    if (!_reentrancyFlag) {
        _reentrancyFlag = true;

        bytes memory payload = abi.encodeWithSignature(
            "depositAndCall(address,uint256,address,uint32,bytes)",
            address(this),
            1,
            address(this),
            1,
            ""
        );
        (bool success, ) = address(gatewaySend).call(payload);
        require(success, "Reentrant call failed");
    }
    return true;
}
```

### Mitigation

Add a reentrancy guard using OpenZeppelin’s ReentrancyGuard
