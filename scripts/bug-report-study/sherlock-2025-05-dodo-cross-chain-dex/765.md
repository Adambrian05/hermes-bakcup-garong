# Platform Fee Transfer Reverts for ETH in withdrawToNativeChain

### Summary

The `withdrawToNativeChain` function attempts to transfer platform fees using `_handleFeeTransfer` for all token types, including ETH, but fails because it uses `TransferHelper.safeTransfer` which is incompatible with ETH transfers.


### Root Cause

This issue arises when, zrc20 = _ETH_ADDRESS_, when it gets to the line to transfer [platform fees](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L551), 

``uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);``

It reverts, this is because [_handleFeeTransfer](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341) function uses `TransferHelper.safeTransfer` which is not suitable for ETH transfers as it is only designed for ZRC20 tokens.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. User calls `withdrawToNativeChain` with `zrc20 = _ETH_ADDRESS_`
2. Function attempts to transfer platform fees using `_handleFeeTransfer`
3. `_handleFeeTransfer` uses `TransferHelper.safeTransfer`
4. Transaction fails because `safeTransfer` cannot handle ETH transfers

### Impact

Platform fees cannot be collected for ETH transactions

### PoC

_No response_

### Mitigation

Handle the case when zrc20 = _ETH_ADDRESS_
