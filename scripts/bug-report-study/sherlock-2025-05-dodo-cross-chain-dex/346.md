# User can bypass `platformFees` by exploiting precision loss

### Summary

While calculating `platformFees` in `GatewayCrossChain.onCall` function, precision loss happens and user can bypass the fee.


### Root Cause

In [`GatewayCrossChain.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L297-L300) function, fee is calculated with rounding down:

```solidity
    function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
@>      platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```

When `platformFee` is 5 (e.g. 0.5%) and `amount` is less than 200 (e.g. 199), the fee is 0.
If the `zrc20` is high valuable and has small decimal (e.g. `WBTC`), the bypassed fee is worth more than gas fee on L2.

### Internal Pre-conditions

token is `WBTC`

### External Pre-conditions

L2 with low gas fee

### Attack Path

User can repeat `onCall` function with dust amount to bypass fee.

### Impact

User can bypass `platformFees`


### PoC

Not response

### Mitigation

Use rounding up while calculating fee.
