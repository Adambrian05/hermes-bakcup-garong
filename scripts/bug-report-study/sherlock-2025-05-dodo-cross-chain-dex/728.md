# `_swapAndSendERC20Tokens` effectively has no `deadline`

### Summary

This affects both `GatewayCrossChain` and `GatewayTransferNative`

[_swapAndSendERC20Tokens](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L325) is used for swapping the `targetZRC20` token to the gas token, when the tokens are different.

```js
function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

To facilitate the swap, UniswapV2 is used. Notice that the deadline parameter is set to `block.timestamp + MAX_DEADLINE`. Using `block.timestamp` in any way for a deadline parameter effectively means there is no deadline, since the deadline will be set to the timestamp of the transaction being executed, which will also be the timestamp of the swap itself. Adding `MAX_DEADLINE` at the end does nothing as well, because we use `block.timestamp` as a deadline.

### Root Cause

Using `block.timestamp` in a deadline for a swap

### Internal Pre-conditions

Needing to swap `targetZRC20` to gas token

### External Pre-conditions

None

### Attack Path

The market is volatile in nature, prices can swing wildly in very short periods of time, which will result in an unfair loss of funds for users.

### Impact

All calls to `_swapAndSendERC20Tokens` will have no deadline, they can be executed at anytime, because the web3 market is volatile in nature, a price 10 minutes ago can be wildly different than the current price, that is what the deadline is used for in swaps. Here we do not have a deadline, so the code will not care at what time the swap is executed, which can lead to a loss of funds for the user, as he might need to swap more tokens for the gas fee, effectively losing his funds unfairly as he has no control over the deadline

_No response_

### Mitigation

Let users choose their own deadline parameters, this can be encoded in their payloads and then decoded on ZetaChain's gateways.
