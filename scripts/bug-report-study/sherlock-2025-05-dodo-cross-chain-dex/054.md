# Fake Liquidity Pool Injection via Incomplete Pair Existence Check

### Summary

The lack of rigorous validation in _existsPairPool() will cause a false positive liquidity pool detection for cross-chain DEX users as an attacker will deploy a malicious UniswapV2 pair with minimal liquidity, tricking the router into using a fake path for swaps or fee extraction.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L217-L220
In GatewayCrossChain.sol:~90, the _existsPairPool function only checks that both tokens have non-zero balance in a computed pair address, without confirming the existence of a real Uniswap pair via getPair() or checking totalSupply.

### Internal Pre-conditions

1. Attacker deploys a malicious pair via the correct UniswapV2 factory between zrc20A and zrc20B.

2. Attacker calls addLiquidity() with a small amount (e.g., 1 wei each) to make balanceOf(pair) > 0 for both tokens.

3. Router contract calls _existsPairPool() which returns true.
