# Event Data Corruption Due to Premature State Deletion

### Summary

Storage reference corruption after `delete` operation will cause event data corruption for external monitoring systems as the `claimRefund()` function emits events with zeroed values instead of actual refund data.

### Root Cause

In [GatewayCrossChain.sol:claimRefund()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L581-L587) and [GatewayTransferNative.sol:claimRefund()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L671-L677), the `delete refundInfos[externalId]` operation occurs before the `EddyCrossChainRefundClaimed` event emission, causing the storage reference to point to zeroed data when the event is emitted.

```solidity
function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];  // Storage reference
    
    // ... validation and transfer logic ...
    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);  // ✅ Uses correct values
    
    delete refundInfos[externalId];  //  Zeros the storage location
    
    emit EddyCrossChainRefundClaimed(
        externalId,
        refundInfo.token,        // NOW address(0)
        refundInfo.amount,       // NOW 0
        abi.encodePacked(msg.sender)
    );
}
```

### Internal Pre-conditions

1. A refund must exist in the `refundInfos` mapping (created via `onRevert` or `onAbort`)
2. The refund must be claimable (either by the original receiver or by authorized bots)

### External Pre-conditions

None - this is an internal code logic issue that occurs during normal refund operations.

### Attack Path

This is not an attack but a data integrity vulnerability that occurs during normal operations:

1. User's cross-chain transaction fails, triggering `onRevert` or `onAbort`
2. Refund information is stored in `refundInfos[externalId]` with correct token address and amount
3. Authorized user/bot calls `claimRefund(externalId)`
4. Function creates storage reference to refund info
5. Token transfer executes successfully using correct values
6. `delete refundInfos[externalId]` zeros the storage location
7. Event emission uses the corrupted storage reference, emitting `address(0)` and `0`

### Impact

External monitoring systems, indexers, and audit trail systems suffer from corrupted event data. Off-chain services tracking refunds receive incorrect information showing zero amounts and null token addresses, while the actual transfers work correctly. This breaks:

- Audit trail integrity for compliance reporting
- Real-time monitoring and alerting systems
- Block explorer and analytics platform accuracy
- Integration with external services relying on events

The core functionality (token transfers) remains secure with no fund loss.

### PoC

```solidity
function test_EventCorruptionProof() public {
    bytes32 externalId = keccak256("corruption_test");
    uint256 refundAmount = 50 ether;
    address refundToken = address(token1Z);
    
    // Refund scenario
    token1Z.mint(address(gatewayCrossChain), refundAmount);
    vm.prank(address(gatewayZEVM));
    gatewayCrossChain.onAbort(
        AbortContext({
            sender: abi.encode(address(this)),
            asset: refundToken,
            amount: refundAmount,
            outgoing: false,
            chainID: 7000,
            revertMessage: bytes.concat(externalId, solAddress)
        })
    );
    
    // Verify correct values exist before claiming
    (, address correctToken, uint256 correctAmount,) = gatewayCrossChain.refundInfos(externalId);
    assertEq(correctToken, refundToken);
    assertEq(correctAmount, refundAmount);
    
    // Expect the CORRUPTED event data
    vm.expectEmit(true, true, false, true, address(gatewayCrossChain));
    emit EddyCrossChainRefundClaimed(
        externalId,
        address(0),  // Corrupted - should be refundToken
        0,           //  Corrupted - should be refundAmount
        abi.encodePacked(bot)
    );
    
    // Execute claimRefund - this will emit corrupted event
    vm.prank(bot);
    gatewayCrossChain.claimRefund(externalId);
    
    // Verify transfer worked correctly despite event corruption
    assertEq(token1Z.balanceOf(bot), refundAmount);
}
```

### Mitigation

Emit event before deletion:
```solidity
function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];
    
    // ... validation logic ...
    
    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
    
    // Emit event BEFORE deletion
    emit EddyCrossChainRefundClaimed(
        externalId,
        refundInfo.token,
        refundInfo.amount,
        abi.encodePacked(msg.sender)
    );
    
    delete refundInfos[externalId];  // Safe to delete after event
}
```
