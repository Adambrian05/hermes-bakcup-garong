# Malicious Users Will Cause Denial of Service (DoS) for Cross-Chain Users

### Summary

Insufficient validation in the [`decodePackedMessage()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L114-L141) function will cause a denial of service (DoS) for cross-chain users as malicious users will craft malformed payloads to trigger transaction reverts on the destination chain.


### Root Cause

In [`GatewaySend.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L128-L133), the `decodePackedMessage()` function fails to adequately check the length of the `message` parameter. This allows a maliciously crafted `payload` to produce a `message` that is too short or improperly structured, leading to a revert when decoded in the `onCall()` function on the destination chain.

### Internal Pre-conditions

1. A user needs to call `depositAndCall()` to set the `payload` such that the resulting `message` length is less than 68 bytes.
2. The system needs to construct the `message` by concatenating a 32-byte `externalId` with the user-provided `payload`, resulting in `message.length` equaling 32 plus `payload.length`.

### External Pre-conditions

No external conditions are required, as the vulnerability is entirely exploitable through user input within the contract's own functions.

### Attack Path

1. A malicious user calls `depositAndCall()` with a `payload` shorter than 36 bytes, producing a `message` less than 68 bytes—for example, a 10-byte `payload` results in a 42-byte `message`.
2. The `GatewayEVM` contract on the destination chain invokes `onCall()` with this malformed `message`.
3. Within `onCall()`, the `decodePackedMessage()` function attempts to extract fixed-length fields and dynamically sized data, but the short `message` length causes a slicing error and triggers a revert.


### Impact

This vulnerability allows malicious users to halt cross-chain operations, preventing legitimate users from completing transfers or swaps, resulting in a DoS. Even if refunds are processed via `onRevert()`, the disruption of intended functionality persists.


### PoC

add this poc test into : `GatewaySend.t.sol`

```bash
forge test --match-test test_DecodePackedMessageVulnerability -vvv
```
```solidity
function test_DecodePackedMessageVulnerability() public {
        // Create a malformed message that's too short (less than 68 bytes)
        bytes memory malformedMessage = abi.encodePacked(
            bytes32(0), // externalId
            uint256(100 ether), // outputAmount
            uint16(0), // receiverLen
            uint16(0)  // crossChainDataLen
            // Missing receiver and crossChainData
        );

        // Mint tokens to gateway for the test
        token1B.mint(address(gatewayB), 100 ether);

        // Simulate gateway calling onCall with malformed message
        vm.startPrank(address(gatewayB));
        token1B.approve(address(gatewaySendB), 100 ether);
        
        // This should revert due to invalid message length
        vm.expectRevert();
        gatewaySendB.onCall(
            MessageContext({
                sender: address(this)
            }),
            malformedMessage
        );
        vm.stopPrank();

        // Create another malformed message with invalid lengths
        bytes memory malformedMessage2 = abi.encodePacked(
            bytes32(0), // externalId
            uint256(100 ether), // outputAmount
            uint16(1000), // receiverLen (too large)
            uint16(1000), // crossChainDataLen (too large)
            bytes("a") // Only 1 byte of data
        );

        // Simulate gateway calling onCall with second malformed message
        vm.startPrank(address(gatewayB));
        
        // This should also revert due to invalid message length
        vm.expectRevert();
        gatewaySendB.onCall(
            MessageContext({
                sender: address(this)
            }),
            malformedMessage2
        );
        vm.stopPrank();
    }
}
```

### Mitigation

Add bounds checking before decoding:
```solidity

require(message.length >= 68, "Message too short for decoding");
uint16 receiverLen = uint16(bytes2(message[64:66]));
uint16 crossChainDataLen = uint16(bytes2(message[66:68]));
require(message.length >= 68 + receiverLen + crossChainDataLen, "Message length mismatch");
```
