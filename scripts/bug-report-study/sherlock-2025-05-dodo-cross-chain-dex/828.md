# `GatewayTransferNative` does not support native token withdrawals

### Summary

The [[GatewayTransferNative::withdrawToNativeChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L537)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L537) function attempts to support native token withdrawals but fails due to incompatible logic in the fee transfer mechanism.

```solidity
function withdrawToNativeChain(address zrc20, uint256 amount, bytes calldata message) external payable {
    if (zrc20 != _ETH_ADDRESS_) {
        require(
            IZRC20(zrc20).transferFrom(msg.sender, address(this), amount),
            "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED"
        );
    }

    globalNonce++;
    bytes32 externalId = _calcExternalId(msg.sender);

    (DecodedMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeMessage(message);

    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
    amount -= platformFeesForTx;

    uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
```

However, `_handleFeeTransfer` fails to differentiate between native tokens and ERC20 tokens:

```solidity
function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
    platformFeesForTx = (amount * feePercent) / 1000;
    TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
}
```

If `zrc20 == _ETH_ADDRESS_`, the `TransferHelper.safeTransfer` call will fail, since native ETH must be sent via `call{value: ...}`.

### Root Cause

`_handleFeeTransfer` does not handle native token transfers, breaking the functionality when `zrc20 == NATIVE_TOKEN`.

### Internal Pre-conditions

None

### External Pre-conditions

* User attempts withdrawal with native tokens (e.g., ETH).

### Attack Path

None. This is a denial-of-service bug rather than an exploit path.

### Impact

The `GatewayTransferNative` contract fails to support withdrawals using native tokens, blocking a valid and intended use case.

### PoC

*No response*

### Mitigation

Update `_handleFeeTransfer` to check for the native token and use a native transfer when applicable:

```solidity
if (zrc20 == _ETH_ADDRESS_) {
    (bool success, ) = EddyTreasurySafe.call{value: platformFeesForTx}("");
    require(success, "Native transfer failed");
} else {
    TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
}
```
