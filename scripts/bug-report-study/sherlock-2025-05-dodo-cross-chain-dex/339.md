# Platform fund Loss due to `platformFeesForTx` Not Deducted in Swap Branch of `GatewayTransferNative.onCall()`

### Summary
In `GatewayTransferNative.onCall()`, fees are correctly subtracted when `decoded.targetZRC20 == zrc20`, but in the “else” (cross‐token swap) branch, `platformFeesForTx` is never deducted. This means the platform never collects its fee after the swap

```solidity
else {
        TransferHelper.safeTransfer(
               token,
               receiver,
        -      outputAmount
        +      outputAmount - platformFeesForTx
            );
}
```

### Root Cause

Please note that fees are sent to the EddyTreasury and not directly deducted from the user’s balance.
Fees are charged upfront via _handleFeeTransfer, but they must also be deducted when transferring tokens back to the user.
This deduction is correctly implemented in the if block, but missing in the else block, which causes incorrect token amounts to be sent

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L406

### Attack Path

* Setup cross-token swap where `zrc20 != decoded.targetZRC20` (e.g., tokenA → tokenB).
* Send amount with platform fee configured (e.g., 0.5% of 1,000,000 = 5,000 units).
* `GatewayTransferNative .onCall()` is called with this swap message.
* User receiver gets full output amount without fee deduction. 
* So which Tokens were sent to `EddyTreasurySafe` address - It was funds of `GatewayTransferNative` contract
* Result: Platform loses funds on all cross-token swaps, causing revenue loss.

### Impact

* **Platform revenue loss** on every swap done in `GatewayTransferNative.sol` contract
* **Accounting mismatch**: users receive the full swapped amount

### Mitigation

When transferring the tokens deduct the platform fees

```diff
else {
   TransferHelper.safeTransfer(
        token,
        receiver,
-       outputAmount
+      outputAmount - platformFeesForTx
    );
}
```
