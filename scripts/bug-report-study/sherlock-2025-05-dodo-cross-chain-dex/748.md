# `onAbort::refundInfos` can be overriden resulting in lost funds

### Summary

`GatewaySend` is a contract deployed on each EVM chain, which means that under the right circumstances there could be matching `externalId` from different chains because `stcChainId` is not taken into account in [_calcExternalId](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L160):
```js
    function _calcExternalId(address sender) internal view returns (bytes32 externalId) {
        externalId = keccak256(abi.encodePacked(address(this), sender, globalNonce, block.timestamp));
    }
```

If malicious listener manage to submit a transaction from different EVM chain resulting in the same id, but different ERC and dust amount, he can corrupt `refundInfos` on `GatewayCrossChain`.
__NOTE__ that on different chains, timestamp can have small discrepancies, which make the exploit possible.
Also, it is possible if the victim uses smart wallet and don't own the private key on the different chains.

### Root Cause

Not hashing chain id in `externalId`

### Internal Pre-conditions

Victim's transaction enters `onAbort`

### External Pre-conditions

Malicious bot listener.

### Attack Path

-

### Impact

Loss of funds.

### PoC

_No response_

### Mitigation

Hash the chain id into `externalId`
