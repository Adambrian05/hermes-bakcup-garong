# Continuous `mixSwap()` during cross-chain may result in asset loss and transaction failure

### Summary

`mixSwap()` requires that the parameters contain the exact amount of input tokens. When multiple mixSwaps occur in a cross-chain transaction, the actual amount of input tokens may not match the parameters.

### Root Cause

When a user initiates a cross-chain transaction, the token may call `mixSwap()` multiple times for token exchange, for example, [GatewaySend.depositAndCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L245-L246) occurs first, then [GatewayCrossChain.onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L465-L466) occurs second, and [GatewaySend.onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L366-L367) occurs third.

The problem here is that for each exchange, the user needs to provide the exact amount of input tokens, rather than directly using the token balance in the protocol. Since the user cannot predict the token amounts to be exchanged, this will cause the parameters provided by the user to be inconsistent with the actual token amount, resulting in transaction failure or tokens left in the contract.
