# `GatewayTransferNative::withdraw` allows attacker to overwrite refund info using the same `externalId` leading to user fund loss

### Summary

`GatewayTransferNative::withdraw`is public and allows any user to provide a crafted `externalId`. If an attacker observes a failed cross chain swap they can submit their own transaction using the same `externalId` and trigger a failure. ZetaChain will call onRevert for both transactions. Since refund data is stored using only externalId as the key and no duplication check exists the attacker’s record will overwrite the original user’s refund. As a result the legitimate user is unable to claim their refund and loses the funds.

### Root Cause

In `GatewayTransferNative` users perform cross chain transfers using `withdrawToNativeChain`. If the cross chain swap fails on the external chain the `GatewayZEVM` will call onRevert to trigger a refund on ZetaChain.

Inside onRevert the contract creates a refund record and stores it using `externalId` as the key. However it does not check if an entry already exists:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L623-L636


```solidity
        RefundInfo memory refundInfo = RefundInfo({
            externalId: externalId,
            token: context.asset,
            amount: context.amount,
            walletAddress: walletAddress
        });
@>       refundInfos[externalId] = refundInfo;

```

Because [`GatewayTransferNative::withdraw`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304) is a public function any user can craft a transaction with a chosen `externalId`, `sender`, `outputToken`, and `amount`:

```solidity
    function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
A malicious user can forge a refund by reusing the same `externalId` and intentionally making their transaction fail on the external chain. This triggers a second onRevert call on ZetaChain which overwrites the original refund record. As a result only the attacker can claim the refund and the legitimate user permanently loses access to their funds.


### Internal Pre-conditions

None

### External Pre-conditions

None


### Attack Path

1. Alice submits a cross-chain swap of SOL from ZetaChain via `withdrawToNativeChain`, which fails on the external chain.
2. The attacker monitors mempool or events, captures the failed transaction, and quickly prepares a duplicate transaction.
3. The attacker calls `withdraw` with the same `externalId` and crafted parameters, and ensures it also reverts on the external chain.
4. ZetaChain’s GatewayZEVM processes Alice’s `onRevert` callback first.
5. Then it processes the attacker’s `onRevert`, overwriting the previous refund record.
6. The attacker claims the refund successfully.
7. Alice attempts to claim the refund, but the call reverts.
As a result, Alice permanently loses her funds on ZetaChain.

### Impact

Legitimate users may permanently lose access to their refunds if malicious transactions overwrite them.
Attackers can steal or block refund claims, leading to potential financial loss and erosion of trust in the protocol.

### Mitigation

- Add a duplication check before writing to `refundInfos[externalId]`. Reject or ignore updates if the key already exists.
- Restrict the `withdraw` function so that only trusted contracts (such as `GatewayZEVM`) can call it.
