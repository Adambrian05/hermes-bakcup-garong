# lack of setter function for gasLimit Causes message Failures

### Summary

The contract assigns the gasLimit value during the initialize() call but provides no mechanism, such as a setter function or governance hook, to modify it later. As gas requirements on destination chains can fluctuate over time, this static configuration risks execution failures.his inflexible design prevents the contract from adjusting to changing gas requirements on the destination chain, which could lead to locking of funds, gas usage ,message failure etc.

### Attack Path

When a user initiates a cross-chain transaction through the send(...) function, the contract uses the hardcoded gasLimit to execute the transaction on the destination chain. If the destination contract requires more gas than the preset gasLimit allows in future, the transaction is sent but fails to execute. This failure can result in the message being marked as failed, potentially locking user funds in the contract. Users may then need to retry the transaction or request a manual refund, which consumes additional funds or relayer gas. Repeated failed attempts further exacerbate the issue, leading to wasted resources and disrupted functionality.
