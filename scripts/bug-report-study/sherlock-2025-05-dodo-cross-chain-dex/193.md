# Incorrect abortAddress configuration will cause loss of funds for users

### Summary

The incorrect abortAddress configuration in withdraw functions will cause a complete loss of funds for users as failed transactions will not trigger the abort mechanism when both withdraw and revert operations fail.

### Root Cause

In `GatewayCrossChain.sol:264`, `GatewayCrossChain.sol:290`, `GatewayTransferNative.sol:273`, and `GatewayTransferNative.sol:299` the `abortAddress` is set to `address(0)` instead of `address(this)`, preventing the abort callback mechanism from functioning when both the main transaction and `onRevert` transaction fail for example by insufficient funds to transfer.

### Attack Path

1. **User calls withdraw/withdrawAndCall functions** which internally set `abortAddress: address(0)`
2. **The cross-chain transaction fails** on the destination chain due to any reason (insufficient gas, contract error, etc.)
3. **ZetaChain attempts to call `onRevert()`** but this call also fails (due to insufficient contract funds or other contract state issues)
4. **ZetaChain should call `onAbort()`** but cannot because `abortAddress` is set to `address(0)` instead of a valid contract address
5. **User funds remain locked** in the failed transaction state with no recovery mechanism

### Impact

The users suffer a complete loss of their deposited funds. The funds become permanently locked in the ZetaChain system when both the primary transaction and revert mechanism fail, with no abort callback to recover the assets.

### PoC

_No response_

### Mitigation

Set `abortAddress: address(this)` instead of `address(0)` in all withdraw and withdrawAndCall functions to ensure the abort callback mechanism functions properly.
