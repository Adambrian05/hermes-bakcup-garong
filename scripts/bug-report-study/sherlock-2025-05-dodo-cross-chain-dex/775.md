# Amount Verification Issue in `onCall`



## Finding description and impact

In the `onCall` function, when `fromIsETH` is true, the function receives ETH without proper validation:

* No verification that `amount > 0`
* No confirmation that `msg.value == amount`

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386

## Potential impacts:

* Function could proceed with zero-value transactions
* State inconsistencies or ETH loss when `msg.value != amount`
* Possible exploits or misuse if zero-amount messages trigger functionality without actual value

## Mitigation

Implement validation for ETH inputs:

```solidity
if (fromIsETH) {
    require(amount > 0, "INVALID: Zero amount");
    require(msg.value == amount, "MISMATCH: ETH value and amount differ");
}
```

These validations ensure accurate ETH accounting and prevent silent failures or malicious zero-value invocations.
