# Malicious user with a non evm wallet address can steal funds by calling `claimRefund`

### Summary

In `GatewayCrossChain.sol` and `GatewatTransferNative.sol`, `claimRefund` should be called by the receiver after an aborted transaction or be called by the bot created to handle cases when the receiver is not an EOA. 
The `claimRefund` function further checks if the wallet of the receiver is equal to 20. This is okay for evm wallet address as they contain 20 bytes, but for solana addresses with 32 bytes, there is no check for that, Hence a user with a solana address can call `claimRefund` using another user's valid `externalId` to steal funds.

### Root Cause

`claimRefund()` checks if the length address is equal to 20, this will only check for evm wallet addresses. 

```solidity
function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

   @>     address receiver = msg.sender;
    @>    if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```
From the code snippet above, firstly the msg.sender was made the reciever. The receiever passes the if check if  the address is not an evm wallet address
