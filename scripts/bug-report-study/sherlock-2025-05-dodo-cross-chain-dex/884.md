# Excess Ether will be permanently lost by users if msg.value > amount

### Summary

In the GatewaySend::depositAndCall function, if the msg.value sent by the user is greater than the amount parameter, it will result in unnecessary loss of funds.

### Root Cause

In https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/test/GatewayTransferNative.t.sol#L97-L98, this function requires that the Ether sent (msg.value) must be greater than or equal to the amount parameter. However, if the user sends more Ether than specified in the amount, the excess is not refunded, resulting in an unnecessary loss. This happens because the function only uses the amount parameter at the end, not the actual msg.value.

### Internal Pre-conditions

1. The user must call `depositAndCall` with `amount = 100 ETH`
2. The user must send `msg.value = 200 ETH` (i.e. `msg.value > amount`)

### External Pre-conditions

1. No external protocol interactions are required for this issue.

### Attack Path

1. User mistakenly sends 200 ETH while setting the `amount` parameter to 100 ETH in `depositAndCall`.
2. Contract accepts the call since `msg.value >= amount` holds true.
3. Only 100 ETH is used in the actual processing, and the remaining 100 ETH is neither refunded nor recorded.
4. The user permanently loses 100 ETH.


### Impact

If a user sends a msg.value greater than the amount parameter, the extra Ether is not refunded, resulting in unnecessary loss of funds.
