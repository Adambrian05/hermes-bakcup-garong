# Unsafe ERC20 Token Approval Without Reset to Zero

### Summary 

In `GatewaySend.sol` there's a direct approval call without resetting to zero first which will cause transaction failures for users as ERC20 tokens (like USDT) will revert when `approve()` is called with a non-zero allowance already set.


https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L195-L200

### Root Cause

In `GatewaySend.sol:186` the `IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount)` call directly sets a new approval amount without first resetting the allowance to zero.

USDT is a support token since it is supported on [zetachain](https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets)

You can find a similar issue on [solodit](https://solodit.cyfrin.io/issues/m-17-did-not-approve-to-zero-first-sherlock-notional-notional-git)

### Internal Pre-conditions

1. User needs to call `depositAndCall()` with a fromToken that has non-zero allowance protection (like USDT)
2. The contract needs to have previously approved the DODOApprove contract for the same token
3. The previous approval amount needs to be non-zero

### External Pre-conditions

1. Token contract (like USDT) needs to implement approval protection that reverts on non-zero to non-zero approvals

### Attack Path

1. User calls `depositAndCall()` with USDT as fromToken for the first time - transaction succeeds
2. User calls `depositAndCall()` with USDT as fromToken again 
3. The `approve()` call in `_doMixSwap()` attempts to set new approval while existing approval is non-zero
4. USDT contract reverts the transaction due to its approval protection mechanism



### Impact

Users cannot execute subsequent swaps with USDT and similar tokens after their first successful transaction, effectively breaking core functionality for major stablecoins.

### Mitigation

```diff
        if(params.fromToken != _ETH_ADDRESS_) {
+           IERC20(params.fromToken).approve(DODOApprove, 0);
            IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
        }
```

or

```diff
        if(params.fromToken != _ETH_ADDRESS_) {
+         IERC20(params.fromToken).safeApprove(DODOApprove, params.fromTokenAmount);
-         IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);

        }
```
