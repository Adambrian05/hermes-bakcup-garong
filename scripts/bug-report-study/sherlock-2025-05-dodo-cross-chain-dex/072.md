# Attacker will steal all contract funds as onAbort() lacks sender validation

### Summary

Missing validation of transaction origin in `GatewayCrossChain::onAbort()` and `GatewayTransferNative::onAbort()` will cause complete loss of all stored tokens for the protocol as an attacker will exploit ZetaChain's abort mechanism to create fake refund entries by setting the contract as abortAddress for their own transactions.

### Root Cause

In `GatewayCrossChain.sol:550-569` and `GatewayTransferNative.sol:640-659` there is missing validation that `abortContext.sender` equals `address(this)`, allowing any external transaction that sets these contracts as the abortAddress to trigger creation of refundable entries upon transaction abortion.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L569

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L640-L659

Then the attacker can call `claimRefund()` to receive the tokens from the contract's balance.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680

### Internal Pre-conditions

1. Contract needs to hold any tokens from previous failed transactions or operations

### External Pre-conditions

N/A

### Attack Path

1. Attacker initiates a cross-chain transaction through ZetaChain (not through GatewayCrossChain/GatewayTransferNative)
2. Attacker sets `abortAddress` to the target contract address in the RevertOptions
3. Attacker crafts `revertMessage` to encode their own address in the message
4. Attacker ensures the transaction fails and revert execution also fails to trigger abort mechanism
5. ZetaChain gateway calls `GatewayCrossChain::onAbort()` or `GatewayTransferNative::onAbort()` with context containing attacker's crafted data
6. Function creates `RefundInfo` struct with `token: abortContext.asset`, `amount: abortContext.amount`, and `walletAddress` extracted from attacker's `revertMessage`
7. Function stores this refund entry in `refundInfos` mapping without validating transaction origin
8. Attacker calls `claimRefund()` with the externalId to receive tokens from the contract's balance

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all tokens held by the contract by exploiting the missing sender validation in the abort mechanism through the refund claiming system.

### PoC

_No response_

### Mitigation

Add validation to ensure the abort is from a transaction initiated by the contract itself:

```solidity
require(abi.decode(abortContext.sender, (address)) == address(this), "Unauthorized abort sender");
```
