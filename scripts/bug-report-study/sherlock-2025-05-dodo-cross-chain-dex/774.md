# `_swapAndSendERC20Tokens()` has a flawed require statement

### Summary

The flawed statement I am talking about is - `require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW")`.

If the `targetAmount` is the same as `amountInMax`, it will revert, but that is totally wrong.

The check should make `>=`, not `>` as the user should be allowed to swap the `amountInMax` to the last wei.

### Root Cause

Wrong check in the require statement: `>` instead of `>=` causing reverts in scenarios that shouldn't revert

### Internal Pre-conditions

none

### External Pre-conditions

none

### Attack Path

1. User initiates a cross chain request/swap providing same `amountMax` and `targetAmount`
2. Given that the check is `>` instead of `>=`, there will be revert in some scenarios in which they're equal, we should be able to swap the max amount 100%, but not revert when there's zero, as this means that we have just swapped the entire max amount, which should be allowed

### Impact

Broken functionality, which will cause reverts when the `amountMax` and `targetAmount` are the same.

### PoC

_No response_

### Mitigation

Remove `>` and replace it with `>=` check
