# User can bypass fee in `GatewayCrossChain`.`onCall`

### Summary

In `GatewayCrossChain`.`onCall`, when `amount` is small enough, user can bypass fee.

### Root Cause

`GatewayCrossChain`.`onCall` process fee in [`_handleFeeTransfer`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L461).
```solidity
    function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
@>      platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }
```
When `feePercent = 5`, if amount is less than 200,  `platformFeesForTx` is zero.
So user can bypass fee.

.

### External Pre-conditions

.

### Attack Path

1. `feePercent` = 5
2. `amount` = 199
3. `_handleFeeTransfer` returns 0
4. User bypassed `fee`.
When `token` is `WBTC`, bypassed fee amount is not small.

### Impact

User can bypass `fee`,so `Protocol` can't receive fee.

### PoC

`feePercent` = 5 , `amount` = 199
`platformFeesForTx = (amount * feePercent) / 1000 = 0` 
`EddyTreasurySafe` can't receive any fee.

### Mitigation

Revert when `platformFeesForTx` is zero.
