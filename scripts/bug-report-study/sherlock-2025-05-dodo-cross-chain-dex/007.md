# An amount greater than msg.value can be used

### Summary

The `onCall()` function does not check whether msg.value is greater than or equal to the amount, so if a small amount of ETH is sent while specifying a very large amount, it can lead to incorrect outcomes. Additionally, the `EddyCrossChainReceive()` event may be triggered with incorrect information as well.

### Root Cause

```solidity
    function onCall(
        MessageContext calldata /*context*/,
        bytes calldata message
    ) external payable onlyGateway returns (bytes4) {
        (
            bytes32 externalId, 
            uint256 amount, 
            bytes calldata recipient, 
            address fromToken, 
            address toToken, 
            bytes calldata swapData
        ) = decodePackedMessage(message);

        bool fromIsETH = (fromToken == _ETH_ADDRESS_);
        bool toIsETH = (toToken == _ETH_ADDRESS_);
        address evmWalletAddress = address(bytes20(recipient));

        if(!fromIsETH) {
            IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
        }

        uint256 outputAmount;
        if(fromToken == toToken) {
            outputAmount = amount;
        } else {
            outputAmount = _doMixSwap(swapData);
        }

        if(toIsETH) {
            payable(evmWalletAddress).transfer(outputAmount);
        } else {
            IERC20(toToken).transfer(evmWalletAddress, outputAmount);
        }
        
        emit EddyCrossChainReceive(
            externalId,
            fromToken,
            toToken,
            amount,
            outputAmount,
            evmWalletAddress,
            message
        );

        return "";
    }
// https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341
```
Unlike `depositAndCall()`, the `onCall()` function does not validate the msg.value and amount values

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. The Gateway calls the fuction like withdrawAndCall() function, passing a msg.value that is less than the amount

### Impact

It is possible to provide a small msg.value and attempt to withdraw an amount greater than this, which can trigger incorrect information through the event

### PoC

_No response_

### Mitigation

The onCall() function also needs logic to verify that msg.value is greater than or equal to the amount
