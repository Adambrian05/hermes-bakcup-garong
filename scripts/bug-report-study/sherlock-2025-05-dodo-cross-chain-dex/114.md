# GatewayCrossChain::_doMixSwap() cannot handle transactions involving the native token zeta.



## Summary
The _doMixSwap() function calls IDODORouteProxy(DODORouteProxy).mixSwap() without including the {value: amount} parameter, making it unable to trade the native token zeta on the zeta chain.

It can be observed that when the _doMixSwap() function calls IDODORouteProxy(DODORouteProxy).mixSwap(), it does not include the {value: amount} parameter.  

Meanwhile, we can see that when transferring zeta tokens from other chains (such as Ethereum) to the Zeta chain, the gateZevm call code is implemented as follows:

The use case is as follows: ERC20 zeta on the Ethereum chain is cross-chained to the Zeta chain, swapped into ZRC20 USDT.BSC, and then cross-chained to the BSC chain to become USDT.  

This is a normal use case, but due to the code error, the `mixSwap()` call on the Zeta chain will fail.  

`GatewayTransferNative::_doMixSwap()` has a similar issue when processing cross-chain messages. Although it includes `{value: msg.value}`, as seen in the `gateZevm` call code above, the `msg.value` passed via `onCall` is always **0** because the native zeta has already been transferred to the `GatewayTransferNative` contract via `_transferZETA`.

## Impact
When users perform a cross-chain ERC20 Zeta to Zeta chain swap to exchange for assets on other chains, it reverts on the Zeta chain.  
The system functionality fails to work properly, and users' gas fees are wasted.

## Mitigation
Modify the `mixSwap()` call to use the parameter `{value: amount}`.
