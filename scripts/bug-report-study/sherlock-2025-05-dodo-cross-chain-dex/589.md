# Unable to swap native ZETA token from Zetachain to connected chain

### Summary

Mistakes in fee logics can cause users unable to swap native ZETA token from Zetachain to connected chains

### Root Cause

The function [`withdrawToNativeChain()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530C14-L530C35) is expected to support case when user swaps native ZETA token from Zetachain to connected chain, by setting `zrc20 = _ETH_ADDRESS_`

Here, even though the function [`_handleFeeTransfer()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341C14-L347) also makes an external call to `_ETH_ADDRESS_` address, but it wont fail because it is using `TransferHelper.safeTransfer()`, which using low-level `call()` to a non-contract address hence the call is returned as successful. 

However, the problem arises when execution step goes into [`_doMixSwap()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425). The function approve tokens by `IZRC20(params.fromToken).approve(DODOApprove, amount)` which will revert when input token is `_ETH_ADDRESS_`.
