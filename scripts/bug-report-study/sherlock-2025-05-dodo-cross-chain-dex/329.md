# Harcoded slippage offers limited protection for users in `GatewayTransferNative._swapAndSendERC20Tokens`

## Vulnerability Details

The protocol implements slippage through an admin-adjustable parameter during the conversion of ZRC20 tokens to their corresponding gasZRC20 tokens via a Uniswap pair pool. The problem arises because hardcoded slippage does not safeguard users against token prices that may decline beyond the slippage threshold (expressed as a percentage) set by the protocol.

This issue is particularly pronounced in volatile market conditions, which can lead to significant price fluctuations for tokens.

```solidity
    function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

@>        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000; //@audit hardcoded slippage may cause user to lose funds
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }
```

## POC

Consider the following scenario

1. Alice intends to transfer some USDC.ETH to her Ethereum receiver address using `GatewayTransferNative.withdrawToNativeChain`.
2. During this process, she calls `GatewayTransferNative._swapAndSendERC20Tokens` to exchange 1 USDC.ETH for an equivalent amount of `gasUSDC` tokens.
3. Given that the slippage is hardcoded at 1%, her `amountInMax` becomes 1.01 USDC.ETH, which is necessary for the swap to gasUSDC tokens.
4. However, the actual amount needed to swap for 1 `gasUSDC` fluctuates between 1.005 and 1.007.
5. Her swap can be executed at either 1.005 or 1.007 USDC, but if it executes at the latter, she incurs a loss of 0.002 USDC in token value, which can represent more than 0.01% of her principal for smaller transfers.
6. If she had the option to reduce her slippage to, for example, 0.5%, she would have been able to receive a greater number of tokens at her destination address.

## Root Cause

Hardcoded slippage protection causes user to lose more funds than intended.

## Impact

Loss of funds for user

## Mitigation

Consider allowing user to specify slippage used for gas token swaps when doing token withdrawls to destination chain
