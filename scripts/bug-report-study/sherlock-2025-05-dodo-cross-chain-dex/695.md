# Slippage check in _swapAndSendERC20Tokens after swap is incorrect and may affect other user’s token balances

### Summary

Considering that both GatewayCrossChain and GatewayNative are going to hold token balances from onRevert and onAbort calls, due to improper slippage checks, swaps performed by users may affect the balances of other users (the stored ones in the Gateways).  

This is due to improper check performed in _swapAndSendERC20Tokens.

### Root Cause

The `_swapAndSendERC20Tokens` utilizes the UniswapV2Router in order to swap the ZRC20 token for a gas token so that the gas fees on Zeta can be paid (this is if the ZRC20 token != gas token needed for that transaction):

```solidity

function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );
        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

        require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
        require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

        IZRC20(gasZRC20).approve(address(gateway), gasFee);
        IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

        amountsOut = targetAmount - amounts[0];
    }


```

The problem is that the only check performed to make sure that the outputAmount from the `swapTokensForExactTokens` call is the following:

```solidity
require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
```

But considering that the Gateways will hold token balances, it's possible that the output amount from the swap is less than the gasFee, but the check still passes due to other users' amounts stored in the contract as part of the refund infos stored through onRevert and onAbort calls.

Take the following situation into consideration:

gasFee: 10e18
gasToken Balance: 100e18 (due to refunds stored in the contract)
output from the Uniswap swap transaction: 5e18

The require check will still pass as 105e18 is greater than 10e18, but this means that 5e18 tokens belonging to other users will still be utilized to pay for the gas fee.

### Internal Pre-conditions

There's an underlying gas token balance in the contract (same as the one being used in the transaction) due to stored refunds;

### External Pre-conditions

Swap performed through Uniswap's router returns less than the gasFee needed to execute the transaction;

### Attack Path

N/A

### Impact

Due to an improper slippage check in  _swapAndSendERC20Tokens after a swap is performed, the output amount may be less than the gas fee, but the transaction will still succeed, as other user's tokens (underlying balance will be utilized to pay for the fee).
