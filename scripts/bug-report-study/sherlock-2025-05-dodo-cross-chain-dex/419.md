# Use of `address.transfer()` risks a flawed recovery for contract wallets

### Summary

The [`GatewaySend.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341) function uses the low-level [`address.transfer()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L370) to send native ETH to the final recipient. If the recipient is a smart contract that requires more than 2300 gas (e.g., a multisig wallet), the transfer will fail. This reverts the transaction and triggers a refund process that returns funds to the user on the wrong chain (ZetaChain) and in the wrong format (ZRC-20s), breaking the protocol's core promise.

### Root Cause

The root cause is the use of the deprecated `.transfer()` function. This function has a hardcoded gas limit that is insufficient for many modern smart contract interactions. The modern best practice is to use the low-level `.call{value: ...}("")` pattern, which forwards all available gas and handles errors more gracefully.

### Internal Pre-conditions

- The [`onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341) function is triggered by the gateway.
- The logic determines that the final payout token ([`toToken`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L350)) is native ETH.

### External Pre-conditions

- The final recipient address ([`evmWalletAddress`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L370)) is a smart contract.
- This smart contract's `receive()` or `fallback()` function consumes more than 2300 gas.

### Attack Path

This is a functionality failure scenario, not a malicious attack.

1.  A user initiates a cross-chain swap, with the final destination being their smart contract wallet which they intend to fund with ETH on Arbitrum.
2.  The swap completes on ZetaChain, and the [`onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341) function in `GatewaySend.sol` is triggered on Arbitrum to deliver the final ETH payment.
3.  The function executes [`payable(evmWalletAddress).transfer(outputAmount)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L370).
4.  The user's smart contract wallet `receive()` function runs out of gas because its logic costs more than the 2300 gas provided by `.transfer()`.
5.  The `transfer` call fails, causing the entire `onCall` transaction on Arbitrum to revert.
6.  The ZetaChain gateway triggers the [`onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393) function back on [`GatewayCrossChain.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol) on the ZetaChain network. The user's funds are refunded as ZRC-20 tokens to their address on **ZetaChain**, not as native ETH on Arbitrum.

### Impact

The impact is a **break of the protocol's core promise** and a **temporary freezing of user funds**.

-   The protocol fails to deliver native ETH to the destination chain as advertised. The user is left with assets on a different chain (ZetaChain) and in a different format (ZRC-20s).
-   The user's funds are not available for use on their intended destination chain. To recover them, the user is forced to perform a new, manual withdrawal from ZetaChain, costing them additional time and gas fees. This creates a significant, negative user experience and undermines the protocol's reliability for any user with a smart contract wallet.

### Mitigation

Replace the use of `.transfer()` with the currently recommended low-level `.call()`. This method forwards all available gas and allows for explicit checking of the success condition, ensuring that transfers to smart contract wallets do not fail due to gas limitations.

// ...
if(toIsETH) {
    // payable(evmWalletAddress).transfer(outputAmount); // Unsafe

    require(success, "ETH_TRANSFER_FAILED");
