# Small token withdrawals may fail due to an incorrect amount check in _swapAndSendERC20Tokens

### Summary

After performing the Uniswap swap in `_swapAndSendERC20Tokens` one of require statements incorrectly checks if the remaining amount is greater than 0 by using amountInMax, instead of amounts[0].

Considering that amountInMax is a slippage adjusted amount (usually higher than the real amount), withdrawals may fail for small amounts, due to a require statement revert.

### Root Cause

In cases in which the zrc20 token != the gas token, the Uniswap v2 router is used in order to swap a portion of the token for the gas token in order to pay the Zeta Gateway fee via `_swapAndSendERC20Tokens`:

```solidity
 function _swapAndSendERC20Tokens(
        address targetZRC20,
        address gasZRC20,
        uint256 gasFee,
        uint256 targetAmount
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );
        uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

        // Swap TargetZRC20 to gasZRC20
        uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
            .swapTokensForExactTokens(
                gasFee, // Amount of gas token required
                amountInMax,
                getPathForTokens(targetZRC20, gasZRC20), // path[0] = targetZRC20, path[1] = gasZRC20
                address(this),
                block.timestamp + MAX_DEADLINE
        );

```

The problem is that the amounts[0] which is the actual amount that the router took will likely be less than the amountInMax in most of the cases, this is because amountInMax includes max allowed slippage:

```solidity

    function swapTokensForExactTokens(
        uint amountOut,
        uint amountInMax,
        address[] calldata path,
        address to,
        uint deadline
    ) external override ensure(deadline) returns (uint[] memory amounts) {
        amounts = UniswapV2Library.getAmountsIn(factory, amountOut, path);
        require(amounts[0] <= amountInMax, 'UniswapV2Router: EXCESSIVE_INPUT_AMOUNT');
        TransferHelper.safeTransferFrom(path[0], msg.sender, UniswapV2Library.pairFor(factory, path[0], path[1]), amounts[0]);
        _swap(amounts, path, to);
}

```

Considering that amounts[0] is the amount being taken from msg.sender this would likely be less than the amountInMax, but the check in the `_swapAndSendERC20Tokens` checks if:

```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```

The amount is greater than 0 using the amountInMax, instead of the amounts[0] which is the actual taken amount. 

As an example, take the following situation into account:
- targetAmount: 1010e18
- AmountInMax: 1010e18
- amounts[0]: 1000e18

The require statement will fail as targetAmount - AmountInMax isn't greater than 0, but on the other hand the actual used amount by the swap is 1000e18, leaving a 10e18 token amount available for withdraw.

### Mitigation

Instead of:

`require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`

Use:

`require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`
