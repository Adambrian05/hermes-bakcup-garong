# Attacker will drain all contract funds as GatewayCrossChain::onRevert() and GatewayTransferNative::onRevert() lacks sender validation

### Summary

Missing validation of transaction origin in `GatewayCrossChain::onRevert()` and `GatewayTransferNative::onRevert()` will cause complete loss of all stored tokens for the protocol as an attacker will exploit ZetaChain's revert mechanism to drain contract balances by setting the contract as revertAddress for their own transactions.

### Root Cause

In `GatewayCrossChain.sol:517-547` and `GatewayTransferNative.sol:607-638` there is missing validation that `context.sender` equals `address(this)`, allowing any external transaction that sets `GatewayCrossChain` or `GatewayTransferNative` as the revertAddress to trigger fund transfers upon reversion.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L517-L548

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L607-L638 

### Internal Pre-conditions

1. Contract needs to hold any tokens from previous failed transactions or operations

### External Pre-conditions

N/A

### Attack Path

1. Attacker initiates a cross-chain transaction through ZetaChain (not through GatewayCrossChain)
2. Attacker sets `revertAddress` to the `GatewayCrossChain` contract address in the transaction
3. Attacker crafts `revertMessage` with exactly 52 bytes: 32 bytes externalId + 20 bytes attacker's address
4. Attacker ensures the transaction fails on the destination chain (can be done intentionally)
5. ZetaChain gateway calls `GatewayCrossChain::onRevert()` with context containing attacker's crafted data
6. Function checks `context.revertMessage.length == 52` and enters direct transfer branch
7. Function extracts receiver address from `revertMessage[32:]` (attacker's address)
8. Function transfers `context.amount` of `context.asset` to the attacker without validating the transaction origin

The same applies for `GatewayTransferNative` as well.

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all tokens held by the contract by exploiting the missing sender validation in the revert mechanism.

### PoC

_No response_

### Mitigation

Add validation to ensure the revert is from a transaction initiated by the contract itself:

```solidity
require(context.sender == address(this), "Unauthorized revert sender");
```
