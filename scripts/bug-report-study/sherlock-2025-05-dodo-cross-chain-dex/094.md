# issue with gas fee handling logic

### Summary



function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {

    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee(); // Problematic check
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    withdraw(
        externalId, 
        decoded.receiver, 
        decoded.targetZRC20, 
        outputAmount - gasFee //  Potential underflow
    );
}


Insufficient Gas Check


The condition gasFee >= outputAmount only protects against withdrawals where gas fee exactly equals or exceeds the amount. However:

When gasFee > outputAmount, outputAmount - gasFee underflows (reverts)

When gasFee == outputAmount, withdrawal amount becomes zero (invalid)




Approval Vulnerability

Approving outputAmount + gasFee is incorrect because:

Only outputAmount tokens are available

Gateway only needs outputAmount (gas fee is deducted from this amount)

### Mitigation


function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    // Ensure sufficient funds after gas deduction
    if (gasFee > outputAmount) revert NotEnoughToPayGasFee();
    if (outputAmount - gasFee == 0) revert ZeroWithdrawalAmount();

    // Only approve the actual output amount
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
    
    withdraw(
        externalId, 
        decoded.receiver, 
        decoded.targetZRC20, 
        outputAmount - gasFee  // Valid positive amount
    );
}
