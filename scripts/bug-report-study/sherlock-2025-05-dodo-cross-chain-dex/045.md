# Missing Pause Check Before ZetaChain Gateway Call Can Lead to Revert and Gas Loss

## Summary

The protocol’s missing check for whether the ZetaChain gateway is paused will cause a denial-of-service (DoS) for protocol users as the gateway admin can pause the gateway, causing calls to revert and blocking deposits and withdrawals.

---

## Root Cause

Functions in this protocol (e.g. `GatewayTransferNative::withdraw`, `GatewayTransferNative::withdrawAndCall`, `GatewaySend::depositAndCall`) directly call the ZetaChain gateway functions without checking if the gateway is paused. The gateway’s `depositAndCall()` function uses the `whenNotPaused` modifier, so calls revert when paused, but the protocol does not pre-check the paused status.

---

## Internal Pre-conditions

1. The protocol must rely on direct calls to the ZetaChain gateway functions without internal pause guards.
2. Protocol functions like `_handleETHDeposit` and withdrawal functions call gateway functions directly.

---

## External Pre-conditions

1. The ZetaChain gateway contract must be in the paused state, set by the gateway admin.

---

## Attack Path

1. Gateway admin pauses the ZetaChain gateway contract.
2. Protocol users call deposit or withdrawal functions that internally call the paused gateway functions.
3. Gateway functions revert due to the `whenNotPaused` modifier.
4. User transactions fail, wasting gas and blocking normal protocol operations.
5. The protocol effectively suffers a denial-of-service until the gateway is unpaused.

---

## Impact

Protocol users cannot deposit or withdraw tokens, causing loss of usability and gas fees due to transaction reverts. This creates a denial-of-service condition on the protocol’s cross-chain operations.

---

## PoC
For example 
In the function [_handleETHDeposit](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L170) the protocol calls:

```solidity
gateway.depositAndCall{value: amount}(...);
```

without checking if the gateway is paused. Since `depositAndCall()` has a [whenNotPaused](https://github.com/zeta-chain/protocol-contracts/blob/a2b6c07814ed108fcba4f2f124757bf45af2f8aa/contracts/evm/GatewayEVM.sol#L330) modifier, this call reverts if the gateway is paused, causing:

* User transaction revert and gas loss
* Denial-of-service until the gateway is unpaused

Example:

```solidity
function _handleETHDeposit(...) internal {
    gateway.depositAndCall{value: amount}(...); // Reverts if paused
}
```

## Mitigation
Implement a Pausing mechanism
