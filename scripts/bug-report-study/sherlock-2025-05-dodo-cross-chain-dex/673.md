# Reliance on Bots for Refunds (Non-EVM Chains)

## Summary
The `claimRefund` function in [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590) and [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680) handles refunds for failed cross-chain transactions. For EVM chains, the `walletAddress` is 20 bytes, allowing the `receiver` to be set to the user's address for direct refund claims. However, for non-EVM chains (e.g., Bitcoin or Solana), where `walletAddress` lengths differ (e.g., ~34 bytes for Bitcoin), the `receiver` defaults to `msg.sender`. Since these contracts operate on ZetaChain (an EVM-compatible chain), non-EVM users cannot directly call `claimRefund`. Instead, they depend on authorized bots to initiate refunds, introducing a centralization risk. If bots fail, are compromised, or act maliciously, users' funds could remain locked.

## Root Cause
The `claimRefund` function assumes a 20-byte `walletAddress` for setting the `receiver`, which works for EVM chains but not for non-EVM chains. When `walletAddress` exceeds 20 bytes, `receiver` defaults to `msg.sender`, restricting refund initiation to bots for non-EVM users. This design does not provide a direct, decentralized refund mechanism for non-EVM users on an EVM-based chain.

## Impact
- **Centralization Risk:** Dependence on bots creates a single point of failure. Bot downtime, misconfiguration, or compromise could prevent refund processing, leaving users without recourse.
- **Fund Lockup:** Non-EVM users risk having funds stuck in the contract if bots fail to operate, undermining the protocol's usability across chains.
- **Reduced Reliability:** This reliance on external entities weakens the protocol's robustness, especially for non-EVM users, potentially reducing trust and adoption.

## Recommendation
Develop a decentralized refund mechanism for non-EVM users to reduce reliance on bots. Potential solutions include:
- **Cross-Chain Messaging:** Enable non-EVM users to submit signed refund requests via cross-chain messages, verifiable on ZetaChain, allowing direct refund initiation.
- **Multi-Sig Relayers:** Replace single bots with a multi-signature relayer system, requiring multiple trusted parties to approve refunds, enhancing security and decentralization.
- **Documentation and Safeguards:** Provide clear documentation on the refund process for non-EVM chains and implement fallback mechanisms (e.g., time-locks or user-initiated recovery) to ensure fund access if bots fail.
