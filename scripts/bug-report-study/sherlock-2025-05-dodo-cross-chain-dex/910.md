# `GatewaySend::_handleERC20Deposit`approve` will revert for non-standard ERC20 tokens like USDT.

### Summary

Note that USDT is one of ZetaChain's supported assets.

The `_handleERC20Deposit` function in `GatewaySend.sol` calls `IERC20(asset).approve()` directly. The standard `IERC20` interface mandates that `approve` returns a boolean value. However, USDT does not. This will case the transaction to revert.

### Root Cause
The vulnerability lies in the direct call to `approve` as seen [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L184)through a standard `IERC20` interface.
```solidity
// file: omni-chain-contracts/contracts/GatewaySend.sol

function _handleERC20Deposit(
    address targetContract,
    uint256 amount,
    address asset,
    bytes memory message,
    RevertOptions memory revertOptions
) internal {
    // This call assumes the 'asset' contract's approve function
    // returns a boolean, as defined in the standard IERC20 interface.
    // For tokens like USDT where approve returns void, this call will revert.
    IERC20(asset).approve(address(gateway), amount);

    gateway.depositAndCall(
        targetContract,
        amount,
        asset,
        message,
        revertOptions
    );
}
```


### Impact

DoS for legitimate users who want to use USDT.

### Mitigation

Use `TransferHelper::safeApprove` instead of `IERC20::approve`.
