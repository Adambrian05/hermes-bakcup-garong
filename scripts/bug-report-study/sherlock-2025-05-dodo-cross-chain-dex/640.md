# Users that have Account Abstraction wallets are unable to use `GatewaySend::onCall` function

## Summary

The `GatewaySend` contract facilitates cross-chain token transfers and swaps, including the handling of ETH transfers. The contract uses the `transfer` method to send ETH, which has specific implications, especially when interacting with account abstraction wallets like Gnosis Safe.

## Root Cause

The [`GatewaySend::onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L370) function performs ETH transfer using the `transfer` function:

```solidity

    function onCall(
        MessageContext calldata /*context*/,
        bytes calldata message
    ) external payable onlyGateway returns (bytes4) {
        (
            bytes32 externalId, 
            uint256 amount, 
            bytes calldata recipient, 
            address fromToken, 
            address toToken, 
            bytes calldata swapData
        ) = decodePackedMessage(message);

        bool fromIsETH = (fromToken == _ETH_ADDRESS_);
        bool toIsETH = (toToken == _ETH_ADDRESS_);
        address evmWalletAddress = address(bytes20(recipient));

        if(!fromIsETH) {
            IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
        }

        uint256 outputAmount;
        if(fromToken == toToken) {
            outputAmount = amount;
        } else {
            outputAmount = _doMixSwap(swapData);
        }

        if(toIsETH) {
@>          payable(evmWalletAddress).transfer(outputAmount);
        } else {
            IERC20(toToken).transfer(evmWalletAddress, outputAmount);
        }
        
        emit EddyCrossChainReceive(
            externalId,
            fromToken,
            toToken,
            amount,
            outputAmount,
            evmWalletAddress,
            message
        );

        return "";
    }

```

The problem is that the `transfer` function uses exactly 2300 gas for transfering the funds and this is not sufficient when the recipient is an Account Abstraction wallet. The Account Abstraction wallets rely on `fallback` or `receive` functions to handle ETH, therefore they have more complex code and need more than 2300 gas to accept ETH and the ETH will not be received, and the transaction will revert.
Also, there is even no check if the transferring transaction is suceeded.

## Impact

The intended cross-chain transaction will not complete, and the recipient will not receive the expected funds.

## Mitigation

Use `call` instead of `transfer` for transferring of native tokens.
