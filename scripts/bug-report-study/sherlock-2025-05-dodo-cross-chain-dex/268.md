# Users can steal funds meant for refunds using a `decoded.targetZRC20`

### Summary

When user bridge from chain A to chain B, it always go trough zeta chain `GatewayTransferNative`, or `GatewayCrossChain` contract. 
User provides `payload` data, which holds `(DecodedMessage memory decoded, MixSwapParams memory params)` for ZetaChain, or destination chain. 
```solidity
struct DecodedMessage {
    address targetZRC20;
    uint32 dstChainId;
    bytes sender;
    bytes receiver; // compatible for btc/sol/evm
    bytes swapDataZ;
    bytes contractAddress; // empty for withdraw, non-empty for withdrawAndCall
    bytes swapDataB;
    bytes accounts;
}
```

User can supply whatever params he wants for `DecodedMessage` and this is never verified. The exploiter can exploit it to steal stale funds from `GatewayCrossChain` , or `GatewayTransferNative` by bridging a cheap token, but providing the more expensive one (waiting for claim refund) as `decoded.targetZRC20`.

- One way is to provide no swap data, which will make [_doMixSwap](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L342-L344) return the bridged amount of the cheap token as `outputAmount`
- Another way is to make the swap params between the bridged token (DAI) to another token with the same value (USDC) -> this will be `outputAmount`, but again we will be transferring the more expensive token, because that's what we have provided in `targetZRC20`

### Root Cause

Not checking that `DecodedMessage.targetZRC20`  matches the bridged token, or swapped `toToken` 

### Internal Pre-conditions

Having stale funds in `GatewayTransferNative`, or `GatewayCrossChain` waiting to be claimed

### External Pre-conditions

None

### Attack Path

1. There is 1e8 BTC standing in `GatewayCrossChain` waiting to be claimed as a refund
2. Exploiter calls `GatewaySend::depositAndCall` with 1e8 DAI, empty swap data and `decoded.targetZRC20 == BTC`
3. Transaction reaches `GatewayCrossChain::onCall`( `_doMixSwap` just returns amount (1e8) ) -> `_handleBitcoinWithdraw` -> `withdraw` is invoked with  `decoded.targetZRC20` (BTC) and `outputAmount` is 1e8 (but user bridged 1e8 DAI)
4. User paid some dust amount and stole 1 BTC

### Impact

Theft of funds allocated for refunds

### PoC

_No response_

### Mitigation

Check that 

```solidity
bool valid = swapParams.length == 0 ? decoded.targetZRC20 == zrc20 : swapParams.toToken == decoded.targetZRC20 == zrc20
```
