# Attacker will steal stored tokens in GatewaySend as `onCall()` `fromToken` validation is missing

### Summary

Missing validation between decoded `fromToken` and swap `params.fromToken` in `GatewaySend::onCall()` will cause complete loss of stored tokens for the protocol as an attacker will exploit parameter mismatch to drain contract balances.

### Root Cause

In `GatewaySend.sol:341-386` there is missing validation that the `fromToken` parameter from decoded message matches `params.fromToken` from the swap data in `_doMixSwap()`.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L386

### Internal Pre-conditions

1. Contract needs to hold any ERC20 tokens from previous failed transactions or leftover balances

### External Pre-conditions

N/A

### Attack Path

1. Attacker initiates a cross-chain transaction through ZetaChain that calls `GatewaySend::onCall()`
2. Attacker crafts message with `fromToken=USDC` but encodes `swapData` containing `params.fromToken=WETH`
3. Function decodes message and extracts `fromToken=USDC` and malicious `swapData`
4. Function calls `IERC20(fromToken).transferFrom(msg.sender, address(this), amount)` expecting USDC from gateway
5. Function calls `_doMixSwap(swapData)` which decodes `swapData` and finds `params.fromToken=WETH`
6. `_doMixSwap()` approves and swaps the contract's existing WETH balance instead of the expected USDC
7. Attacker repeats this process for all token types held by the contract to drain them completely

### Impact

The protocol suffers complete loss of all stored token balances. The attacker gains all stolen tokens from the contract while the gateway only transfers the minimal expected token amount.

### PoC

_No response_

### Mitigation

Add validation to ensure the decoded `fromToken` parameter matches the `params.fromToken` from the swap data.
