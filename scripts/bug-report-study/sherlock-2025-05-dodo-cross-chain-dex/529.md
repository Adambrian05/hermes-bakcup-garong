# Critical recovery mechanism disabled by misconfigured abort address

### Summary

Contracts `GatewayCrossChain` and `GatewayTransferNative` are both doing Zeta -> EVM cross-chain TXs. While doing so, both contracts set `abortAddress: address(0)` in all `RevertOptions`, making the abort fallback mechanism non-functional. When `onRevert` execution fails or is underfunded, the protocol cannot call the abort mechanism, causing permanent fund loss.

### Root Cause

Contract `GatewayCrossChain` sets abort address to address(0) in [withdrawAndCall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244):
```solidity
    function withdrawAndCall(
        bytes32 externalId,
        bytes memory contractAddress,
        address targetZRC20,
        uint256 outputAmount,
        bytes memory receiver,
        bytes memory message
    ) internal {
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                // @audit should be address(this)
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
    }
```

Same thing happens in [GatewayCrossChain :: withdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L290), [GatewayTransferNative :: withdrawAndCall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L273) and [GatewayTransferNative :: withdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L299).

Abort mechanism is used by ZetaChain protocol as fallback when `onRevert` fails or is underfunded. In that case `abortAddress` is used to rescue the funds being bridged. Since Dodo gateways set `abortAddress` to 0, it means funds will be permanently lost.

[Reference](https://www.zetachain.com/blog/zetachains-new-revert-handling-for-cross-chain): 
```bash
However, if onRevert itself fails on ZetaChain, the onAbort function is triggered to provide a final fallback: ZetaChain → Connected chain onCall reverts → ZetaChain onRevert reverts → ZetaChain onAbort
```

### Internal Pre-conditions

None

### External Pre-conditions

The `onRevert` execution fails due to any reason: insufficient gas funding, gas limit exceeded, contract state issues, etc.

### Attack Path

This is not an attack but a systematic failure:

1. User initiates cross-chain transaction
2. Transaction fails on destination chain
3. Protocol attempts to call `onRevert` on `revertAddress` on this contract (GatewayCrossChain or GatewayTransferNative)
4. `onRevert` execution fails due to gas issues, contract state, or external factors
5. Protocol attempts to fall back to `onAbort` on abortAddress
6. `abortAddress` is `address(0)` - no valid address to save funds
7. User's funds are lost 

### Impact

High severity - this vulnerability causes direct loss of user funds due to misconfigured abort mechanism

### PoC

_No response_

### Mitigation

Set `address(this)` as `abortAddress`, since gateways already have `onAbort` implementation to save the funds in case of cross-chain transaction failures.
