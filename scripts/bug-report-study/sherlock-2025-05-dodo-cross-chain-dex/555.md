# Anyone can call GatewayTransferNative.withdraw() to withdraw assets from GatewayTransferNative

### Summary

`GatewayTransferNative.withdraw()` is a public function. When anyone calls `GatewayTransferNative.withdraw()`, the gateway will transfer the assets in GatewayTransferNative to the user across chains.

### Root Cause

[GatewayTransferNative.withdraw()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L291) is a public function. When anyone calls `GatewayTransferNative.withdraw()`, the gateway will transfer the assets in GatewayTransferNative to the user across chains.
This is because:
1. In general cross-chain transactions, GatewayTransferNative approves too many tokens to the gateway. In fact, only the outputAmount needs to be approved, and gasFee does not need to be added
```solidity
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
```
2. When mixSwap is used in cross-chain transactions, the input token amount in the protocol may be greater than the input token amount in the parameters provided by the user(See issue "Continuous mixSwap() during cross-chain may result in asset loss and transaction failure"), which will cause some input tokens to be left in GatewayTransferNative.
```solidity
        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
```

Since there are remaining tokens in GatewayTransferNative and GatewayTransferNative has remaining approval for the gateway, anyone can call `GatewayTransferNative.withdraw()` to withdraw them.
