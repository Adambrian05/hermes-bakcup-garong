# Platform Fee Handling Causing Swap Failures and Balance Discrepancies in Cross-Chain Operations

## Description
There is a critical issue in the handling of platform fees in the `onCall()` function that causes different treatment between two operation scenarios:
1. Identical token scenario: The platform fee is correctly deducted from the amount transferred to the user
2. Different Token Scenario (Swap): The platform fee has been deducted and transferred to the treasury, but the swap operation still uses the full amount (before the fee deduction)

This happens because the `_handleFeeTransfer()` function physically transfers the platform fee to the treasury (reducing the contract balance), but the `amount` variable used for the swap is not adjusted to reflect the deduction.

## Code Snippet
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L346
-	https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395

## Root Cause
The `_handleFeeTransfer()` function that deducts from the contract balance:
```solidity
function _handleFeeTransfer(address zrc20, uint256 amount) internal returns (uint256 platformFeesForTx) {
    // Calculate platform costs
    platformFeesForTx = (amount * feePercent) / 1000;
    
    // ⚠️ PROBLEM: Transfer fees to treasury - contract balance decreases!
    TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    // After this line, contract balance = initial balance - platformFeesForTx
}
```
Problem in `onCall()` Function:
```solidity
function onCall(...) external override onlyGateway {
    // Decode message
    (bytes32 externalId) = abi.decode(message[0:32], (bytes32)); 
    (DecodedNativeMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeNativeMessage(_message);

    // CUT PLATFORM FEES - CONTRACT BALANCE HAS BEEN REDUCED!
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
    
    address receiver = address(uint160(bytes20(decoded.receiver)));

    if (decoded.targetZRC20 == zrc20) {
        // ✅ CORRECT: Using the amount after deducting costs
        TransferHelper.safeTransfer(
            decoded.targetZRC20,
            receiver,
            amount - platformFeesForTx  // Consistent with contract balance
        );
    } else {
        // ❌ WRONG: Using full amount for swap
        uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
        //                                                   ^^^^^^
        //                                    Try using the full amount
        //                                    But the contract balance has decreased!
    }
}
```
The root of the problem is that after `_handleFeeTransfer()` is called, the contract balance is reduced by `platformFeesForTx`, but the `amount` variable is not adjusted. The identical token case uses `amount – platformFeesForTx`, while the swap case uses the full `amount` and there is no synchronization between the physical balance reduction and the parameters used for the next operation.

## Impact
All cross-chain swap transactions via `onCall()` will fail and the platform fee is already transferred to the treasury even though the transaction failed.

## Scenario
Setup Conditions:
- User sends 1000 USDC from Ethereum to ZetaChain
- Platform fee: 5 (0.5% = 5 USDC)
- Target token: WZETA (requires swap)
- Contract receives 1000 USDC via onCall()

## Recommendation
Modify `onCall()` function to swap using `amount` after cost.
```solidity
function onCall(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    bytes calldata message
) external override onlyGateway {
    // Decode message
    (bytes32 externalId) = abi.decode(message[0:32], (bytes32)); 
    bytes calldata _message = message[32:];
    (DecodedNativeMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeNativeMessage(_message);

    // Cut platform costs
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
    
    // ✅ FIX: Calculate amount after platform fees
    uint256 amountAfterFee = amount - platformFeesForTx;
    
    address receiver = address(uint160(bytes20(decoded.receiver)));

    if (decoded.targetZRC20 == zrc20) {
        // Transfer amount setelah biaya
        TransferHelper.safeTransfer(
            decoded.targetZRC20,
            receiver,
            amountAfterFee  // ✅ Consistent
        );

        emit EddyCrossChainSwap(
            externalId,
            uint32(context.chainID),
            ZETACHAIN,
            zrc20,
            decoded.targetZRC20,
            amount,
            amountAfterFee,  // ✅ Update output amount
            decoded.sender,
            decoded.receiver,
            platformFeesForTx
        );
    } else {
        // ✅ FIX: Swap using amount after fees
        // Update swap parameters too
        params.fromTokenAmount = amountAfterFee;
        
        uint256 outputAmount = _doMixSwap(decoded.swapData, amountAfterFee, params);

        if (decoded.targetZRC20 == WZETA) {
            IWETH9(WZETA).withdraw(outputAmount);
            TransferHelper.safeTransferETH(receiver, outputAmount);
        } else {
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                outputAmount
            );
        }

        emit EddyCrossChainSwap(
            externalId,
            uint32(context.chainID),
            ZETACHAIN,
            zrc20,
            decoded.targetZRC20,
            amount,
            outputAmount,
            decoded.sender,
            decoded.receiver,
            platformFeesForTx
        );
    }
}
```
