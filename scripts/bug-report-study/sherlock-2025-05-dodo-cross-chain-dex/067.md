# Missing Return Statements in Core Internal Functions Break Swap and Routing Logic

### Summary

A missing return statement in sortTokens() and getPathForTokens() will cause Uniswap path resolution to fail or return uninitialized values for swaps and gas logic, even though zero-address inputs are guarded with a revert. The problem is not in safety, but in execution — these functions do not return the computed values.

### Root Cause

In GatewayCrossChain.sol:sortTokens, the function lacks a return (token0, token1) even though it declares output values.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L174-L184
In GatewayCrossChain.sol:getPathForTokens, the function lacks return path despite assigning it.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L222-L243
Solidity does not implicitly return named values unless return is used explicitly.

### Internal Pre-conditions

1. getPathForTokens() or sortTokens() is called during swap or withdrawal.

2. No return statement exists despite named return values being declared.

3. The caller function (e.g., _swapAndSendERC20Tokens) assumes valid data is returned from these helpers.

### External Pre-conditions

1. A  cross-chain swap or withdrawal is triggered involving Uniswap route logic or pair computation.

2. The involved tokens are valid and supported by ZetaChain.

3. The contract relies on the UniswapV2 path or pair derived from sortTokens() or getPathForTokens().



### Attack Path

1. A user initiates a swap via onCall(), triggering _swapAndSendERC20Tokens.

2. _swapAndSendERC20Tokens() calls getPathForTokens() which assigns values to path but does not return it.

3. UniswapV2Library.getAmountsIn() receives an empty or garbage path, leading to incorrect gas fee computation.

4. The swap may revert or route through invalid token paths, leading to loss of tokens, wasted gas, or broken execution.

### Impact

Swaps or gas conversions will fail or behave unexpectedly due to invalid routing paths. Users may suffer full transaction reverts or end up with incorrect swap outputs. In the worst case, the swap passes with a broken path, routing to an incorrect address.

### PoC

_No response_

### Mitigation

Add explicit return statements to all internal functions that define named return values:

- return (token0, token1); in sortTokens()

- return path; in getPathForTokens()
