# Contradiction Between Readme Trust Assumptions and superWithdraw() Function Allowing Arbitrary Transfers to EddyTreasurySafe

### Summary

The superWithdraw() function allows the contract owner to transfer arbitrary ETH or token balances from the contract to the EddyTreasurySafe. This contradicts the README's stated assumption that EddyTreasurySafe is only trusted to collect protocol fees. This discrepancy can mislead integrators or users into overestimating the system’s trust boundaries, and it opens up potential for misuse or fund misappropriation.

### Root Cause

The README states:

"EddyTreasurySafe is only trusted to collect the fees correctly."

But the superWithdraw() function allows the contract owner (admin) to send any amount of ETH or token held by the contract to EddyTreasurySafe.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L161C5-L169C6

### Attack Path

1. Owner calls superWithdraw(token, amount) with a value that includes user funds or operational balances — not just fees.

2. The entire amount is transferred to EddyTreasurySafe.

3. From a user’s perspective, this contradicts the expected role of EddyTreasurySafe, which was only trusted to collect protocol fees.

### Impact

Violation of trust boundaries as described in readme of the contest page. Potential misappropriation of funds by transferring contract balance instead of only fees.

### Mitigation

Protocol should not allow to withdraw any funds to EddyTreasurySafe except fees.
