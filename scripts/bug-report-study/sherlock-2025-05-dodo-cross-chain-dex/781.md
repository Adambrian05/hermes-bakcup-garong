# Erroneous Balance Verification in `_swapAndSendERC20Tokens`



## Finding description and impact

The function `_swapAndSendERC20Tokens` validates `require(targetAmount - amountInMax > 0)` to confirm sufficient target token remains after the gas token swap. However, this validation is flawed.

The actual token quantity consumed in the swap is `amounts[0]`, not `amountInMax`.

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L333

Impact:

* The `require` validation may fail even when adequate tokens are available
* Token authorization for withdrawal could be calculated using incorrect remaining amounts
* Disconnect between actual swap execution and balance validation mechanisms

## Mitigation

Correct the balance verification:

```solidity
require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
