# transfer method prevents the use of USDT token on GatewaySend contract

### Summary

The Protocol aims to deploy on mainnet, and will also be supporting USDT as can be seen in the contest readMe. However, the `GatewaySend` contract has multiple instances of `transfer` and `transferFrom`, whiich are not compatible with USDT on mainnet. Using these methods on directly on the standard EIP20 interface will lead to a revert, due to abi decoding error.

### Root Cause

Multiple instances of `transfer` and `transferFrom` in `GatewaySend.sol`

### Attack Path

* User intends to bridge USDT or other supported tokens that do not return bool on transfer
* Transaction reverts
