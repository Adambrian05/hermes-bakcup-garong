# `iszero(iszero(mload(ptr)))` checks if the entire 32-byte word is zero, not just the first byte corrupting Solana account permissions.

### Summary

The fn `_handleEvmOrSolanaWithdraw()` decompress `decoded.accounts` [code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L398) in case the destination chain is Solana.
But `decompressAccounts()` uses [iszero(iszero(mload(ptr)))](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/libraries/AccountEncoder.sol#L44) which reads 32 bytes for boolean parsing but only advances the pointer by 1 byte (`ptr := add(ptr, 1)`), causing it to evaluate the entire 32-byte word (including next account's data) instead of just the single boolean byte. This results in false positives where isWritable becomes true when the following account data is non-zero, potentially corrupting Solana account permissions and causing transaction failures in cross-chain operations.

### Root Cause

`iszero(iszero(mload(ptr)))` evaluates the entire 32-byte word, not just the single byte boolean value. But in the code,  even though it reads the 32 byte to check for the boolean value to assign it for `isWritable` parameter of the solana accnt , `ptr` only advances by 1 byte

```solidity
function decompressAccounts(bytes memory input) internal pure returns (Account[] memory accounts) {
    assembly {
        for { let i := 0 } lt(i, len) { i := add(i, 1) } {
            // Load publicKey (32 bytes)
            mstore(acc, mload(ptr))
            ptr := add(ptr, 32)

            .....

            // Load isWritable - INCORRECT BOOLEAN LOGIC
     =>       mstore(add(acc, 32), iszero(iszero(mload(ptr))))
     =>       ptr := add(ptr, 1)  // Only advance 1 byte but read 32 bytes
        }
    }
}
```

### Internal Pre-conditions

Destination chain is Solana. (decoded.accounts contain the encoded solana accounts details needed for the withdrawal transaction)

### External Pre-conditions

NIL

### Attack Path

in the line [#44](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/libraries/AccountEncoder.sol#L44)

mload(ptr) reads: 0x00FF... (32 bytes) where first byte is for boolean.
iszero(iszero(0x00FF...)) = true
Account incorrectly marked as writable and advanced by 1 byte. 

### Impact

 Solana account permissions gets corrupted due to this since non writable account is made writable.
This will also cause unauthorized state modifications which leads to the transaction failures.

### Mitigation

```solidity
mstore(add(acc, 32), iszero(iszero(byte(0, mload(ptr)))))
```
As a result it will only read first byte.
