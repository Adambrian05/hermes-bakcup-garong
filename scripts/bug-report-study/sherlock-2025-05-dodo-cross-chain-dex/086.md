# The `onRevert` Function In `GatewaySend` Does Not Handle Native Token

## Summary
The `onRevert` function in the `GatewaySend` contract fails to handle native gas token (e.g., ETH/BNB) reversals, violating ZetaChain's cross-chain specifications. This oversight could lead to permanent fund loss when reverting cross-chain transactions involving native assets. The issue stems from unconditionally using `safeTransfer` without checking if `context.asset` is `address(0)` (the designated value for gas tokens).

## Vulnerability Detail
Revert Behavior from [zetachain](https://www.zetachain.com/docs/developers/chains/zetachain/):
```solidity
onRevert

struct RevertContext {
    address asset;
    uint64 amount;
    bytes revertMessage;
}
 
interface Revertable {
    function onRevert(RevertContext calldata revertContext) external;
}


On a connected chain, asset is the ERC-20 originally deposited (or zero address for gas assets).
On ZetaChain, asset is the ZRC-20 withdrawn during the original call.
```

The current Implementation of `onRevert` function:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```
The function assumes `context.asset` is always an ERC20 address, but ZetaChain explicitly states:
```solidity
On a connected chain, asset is the ERC-20 originally deposited (or zero address for gas assets).
```
You can also find this behavior in zetachain's [GatewayEVM](https://sepolia.basescan.org/address/0x7e10457ab8f12a2c114b5e46c938b807cd9eddc1#code) which is deployed at testnet. There is a function `executeRevert`:
```solidity
/// @notice Transfers msg.value to destination contract and executes it's onRevert function.
    /// @dev This function can only be called by the TSS address and it is payable.
    /// @param destination Address to call.
    /// @param data Calldata to pass to the call.
    function executeRevert(
        address destination,
        bytes calldata data,
        RevertContext calldata revertContext
    )
        public
        payable
        nonReentrant
        onlyRole(TSS_ROLE)
        whenNotPaused
    {
        if (destination == address(0)) revert ZeroAddress();
        (bool success,) = destination.call{ value: msg.value }("");
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext);

        emit Reverted(destination, address(0), msg.value, data, revertContext);
    }
```
This function will send ether to `destination` and call `onRevert` on it.

As a result, if a user initiates a cross-chain transfer with native tokens (e.g., sending `ETH`), the contract will attempt to call `safeTransfer(0x0...)`, which will revert, trapping funds.



## Impact
Medium Severity(High Impact * Medium Likelihood):
Native tokens sent in failed cross-chain transactions become unrecoverable.
Violates the principle of atomicity in cross-chain operations (users expect reversibility).

## Recommendation
Consider following fix:
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));

    if (context.asset == address(0)) {
        // Native token refund
        (bool success, ) = sender.call{value: context.amount}("");
        require(success, "Native token transfer failed");
    } else {
        // ERC20 refund
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
    }

    emit EddyCrossChainRevert(externalId, context.asset, context.amount, sender);
}
```
