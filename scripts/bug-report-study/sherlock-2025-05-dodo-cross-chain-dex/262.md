# The chainId that represents Solana blockchain was wrongly initiated in GatewayCrossChain and GatewayTransferNative contracts

### Summary

The `chainId` that represents Solana blockchain in the universal contracts (`GatwayCrossChain.sol` and `GatewayTransferNative.sol`) that going to deploy in the ZetaChain was initiated wrongly. It should be equal to 900, but in `GatwayCrossChain.sol` and `GatewayTransferNative.sol` they point Solana `chainId` to 1399811149

### Root Cause

The `chainId` in [GatewayCrossChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L25) and [GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L26) were pointed to 1399811149, rather it should point to 900. 

[ZetaChain List of Chains ](https://www.zetachain.com/docs/developers/chains/list/), here you can see the `chainId`'s of the blockchain that can have cross-chain transactions. In the docs, clearly mentioned that the `chainId` of Solana in ZetaChain is 900, but here `GatwayCrossChain.sol` and `GatewayTransferNative.sol` contracts they were pointed wrongly.

### Impact

The impact is High, because the `chainId` of the blockchain is pointed to wrong value, the operation eventually point to that `chainId`, but there will be no functionalities there as it intended to be Solana. So total Cross-Chain transaction and native Transactions (Zetachain -> Solana) will fail, and user gets charged for the work done by TSS address so finally gets back less amount than intended. So user lose his charging fee without knowing anything because of wrongly pointed `chainId`

### Mitigation

In both `GatewayCrossChain` and `GatewayTransferNative` contracts
```diff
-        uint32 constant SOLANA_EDDY = 1399811149; // chain Id from eddy db
+       uint32 constant SOLANA_EDDY = 900; // chain Id from eddy db
```
