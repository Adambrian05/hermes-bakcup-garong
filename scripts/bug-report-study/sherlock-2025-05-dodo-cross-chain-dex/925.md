# The ETH balance of gatwayCrosschain.sol can be drained

### Summary

From README.
> Are there any limitations on values set by admins (or other roles) in the codebase, including restrictions on array lengths?
Owner and Bot are trusted.
EddyTreasurySafe is only trusted to collect the fees correctly.

This means that Treasury Safe is only trusted to collect the the fees or specific amount sent to it. 
However, the Eddy treasurySafe can drain the protocol of all ETH whenever an owner makes a call to send a specified amount of ETH to it **without the permission of the owner**.

### Root Cause

In GateWayCrossChain.sol, line 161. There is a risk of reentrancy when the owner wants to tranfer an ETH to the treasury Safe.
```solidity
function superWithdraw(address token, uint256 amount) external onlyOwner {
if (token == _ETH_ADDRESS_) {
require(amount <= address(this).balance, "INVALID_AMOUNT");
TransferHelper.safeTransferETH(EddyTreasurySafe, amount);
} else {
require(amount <= IZRC20(token).balanceOf(address(this)), "INVALID_AMOUNT");
TransferHelper.safeTransfer(token, EddyTreasurySafe, amount);
}
}
```
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L161

From the ReadMe, we already Eddy TreasureSafe is not fully trusted. It should only be able to receive the amount sent by the owner.
However, this is not the case for ETH transfers. 
**NOTE**: As shown in the function parameter above, the owner has the freedom to specify any amount


Let's look at `safeTransferETH()` function:

```solidity

    function safeTransferETH(address to, uint value) internal {
        (bool success,) = to.call{value:value}(new bytes(0));
        require(success, 'TransferHelper: ETH_TRANSFER_FAILED');
    }
}
```
For example, If an owner wants to send 10 ETH out of 50 ETH the contract holds. The ReadMe makes it clear that Eddy TreasureSafe should be able to collect only the 10 ETH. However, the Eddy TreasureSafe can simply reenter to drain it of all ETH
This breaks the trust assumption should only be able to collect the amount sent by the owner. But it can reenter the contract to drain it completely.


### Internal Pre-conditions

The owner attempts to send a specific amount of ETH

### External Pre-conditions

Eddy TreasureSafe is not fully trusted. It is trusted to collect only the specified amount from the owner.

### Attack Path


1. The owner sends 20 ETH but the contract holds 50 ETH.
2. The treasury Safe reenters the contracts drains it completely.
3. The owner expects the treasury safe to collect fees correctly as stated in the ReadMe but the treasury safe drains the contract of all ETH tokens.


### Impact

Loss of fund

### PoC

_No response_

### Mitigation

Use nonReentrancy modifier on `superWithdraw`.
