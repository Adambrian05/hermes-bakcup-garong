Micro Tin Squirrel

Medium

# Attacker will cause transaction failures for users by sending tokens to non-existent pair addresses"

### Summary

The incorrect pool existence check in [_existsPairPool](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207) function will cause transaction failures for users as an attacker will manipulate the pool detection by transferring small amounts of tokens to computed pair addresses without actual pair contracts existing.

### Root Cause

In [contracts/GatewayCrossChain.sol:207-220](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207) and [contracts/GatewayTransferNative.sol:216-229](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L216) the _existsPairPool function only checks token balances at computed pair addresses without verifying if actual Uniswap V2 pair contracts exist at those addresses.


### Internal Pre-conditions

- Protocol needs to perform cross-chain operations that require token swaps for gas fees through _swapAndSendERC20Tokens function
- Target token needs to be different from gas token (i.e., decoded.targetZRC20 != gasZRC20) to trigger the swap logic
- getPathForTokens function needs to be called to determine swap route for gas fee payment

### External Pre-conditions

No actual Uniswap V2 pair contract exists for the specific token combination


### Attack Path

- Attacker calculates the deterministic pair address using uniswapv2PairFor(factory, tokenA, tokenB) for a non-existent pair
- Attacker transfers small amounts (1 wei each) of both tokenA and tokenB to this computed address
User initiates cross-chain transaction that requires swapping tokens for gas fees (e.g., swapping USDC to ETH for Ethereum gas)
- Protocol calls _existsPairPool which returns true because both IZRC20(tokenA).balanceOf(pairAddress) > 0 and IZRC20(tokenB).balanceOf(pairAddress) > 0
- Protocol selects direct swap path [tokenA, tokenB] instead of safer path [tokenA, WZETA, tokenB]
- UniswapV2Router.swapTokensForExactTokens() is called with the direct path, but fails because no contract exists at the pair address
- User's cross-chain transaction fails and funds may be temporarily locked requiring claimRefund

### Impact

Users suffer transaction failures and potential temporary fund lockup during cross-chain operations. The attacker loses minimal amounts (1 wei per token) but can cause significant disruption to protocol operations and user experience.

### Mitigation

```solidity
function _existsPairPool(
    address uniswapV2Factory,
    address zrc20A,
    address zrc20B
) internal view returns (bool) {
    address uniswapPool = uniswapv2PairFor(
        uniswapV2Factory,
        zrc20A,
        zrc20B
    );
    
    // Check if a contract exists at the pair address
    uint256 codeSize;
    assembly {
        codeSize := extcodesize(uniswapPool)
    }
    if (codeSize == 0) return false;
    
    // Additional validation: check that both tokens have reserves
    return
        IZRC20(zrc20A).balanceOf(uniswapPool) > 0 &&
        IZRC20(zrc20B).balanceOf(uniswapPool) > 0;
}
```
