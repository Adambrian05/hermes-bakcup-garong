Innocent Banana Opossum

Medium

# GatewayTransferNative::withdraw - The function is public and can be called by anyone

### Summary

## Description
The fact that [withdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L305) is public can be exploited by the ghost approval inside `_handleBitcoinWithdraw`

```solidity
    function _handleBitcoinWithdraw(
        bytes32 externalId, 
        DecodedMessage memory decoded, 
        uint256 outputAmount,
        uint256 gasFee
    ) internal {
        if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee); // @sus this should be only outputAmount
        withdraw(
            externalId, 
            decoded.receiver, 
            decoded.targetZRC20, 
            outputAmount - gasFee
        );
    }
```

The code approves `outputAmount + gasFee`, but the contract only has `outputAmount` in it, so it's impossible to spend more than `outputAmount`, since the `gasFee` is spent from the `outputAmount`

This ghost approval can be exploited when the contract has refunds that are waiting to be claimed and the tokens are gas tokens.

From here an attacker can specify the amount of gas tokens that have the ghost approval, chose a `sender` (actually receiver, name is incorrect) and then just steal the tokens.

Another exploit path is to override a `refundInfos` entry because we can specify any `externalId`

### Root Cause

- `withdraw` function being public 
- Ghost approval of gas tokens to the gateway inside `_handleBitcoinWithdraw`

### Internal Pre-conditions

Having stale gas funds in the contract to be claimed (btc)

### External Pre-conditions

None

### Attack Path

1. Victim transaction fails on BTC and now 0.1 BTC is left in the contract
2. The contract has 0.2 BTC ZRC20 gateway approval from past bitcoin withdraws (from approving gasFee, which is not spend)
3. Attacker calls `GatewayTransferNative::withdraw` specifying his address as `sender`, 0.1 as amount and BTC as output token
4. Victim refund tokens are stolen

### Impact

- Theft of funds allocated for refunds
- Bricking refund mechanism, if `refundInfos` is overriden

### PoC

_No response_

### Mitigation

Make the function internal and remove the ghost approval from `_handleBitcoinWithdraw`
