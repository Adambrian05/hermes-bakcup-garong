# `GatewayCrossChain::claimRefund` sends refunded BTC to bitcoin address on ZetaChain, instead of a legitimate ZetaChain address.

### Summary
The `claimRefund` function in `GatewayCrossChain` is intended to return assets to users whose cross-chain transactions have failed. However, if a 20-byte `walletAddress` is stored in the `RefundInfo` struct that does not correspond to a valid, token-receivable address on ZetaChain, the funds will be permanently lost when the refund is claimed.

### Root Cause
The `claimRefund` function has a path for handling 20-byte wallet addresses, which are assumed to be standard EVM addresses.

Bitcoin addresses are also 20 bytes long, but in `withdrawAndCall`, the receiver it set to a user's `BTC` address in `decoded.receiver`.

This can be seen in `_handleBitcoinWithdraw` [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L363-L377)

```solidity
   function _handleBitcoinWithdraw(
        bytes32 externalId, 
        DecodedMessage memory decoded, 
        uint256 outputAmount,
        uint256 gasFee
    ) internal {
        if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
        withdraw(
            externalId, 
            decoded.receiver,  // bitcoin address
            decoded.targetZRC20, 
            outputAmount - gasFee
        );
    }

```

However, if the broadcast fails on BTC Network. `GatewayCrossChain::onAbort` is called and stores the `BTC` address in `refundInfo[externalId].walletAddress` as seen [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L561)

So when users want to call `claimRefund`, the `receiver` is now set to a bitcoin address, and funds are sent to that bitcoin address (`receiver`) on ZetaChain. 
```solidity
// file: omni-chain-contracts/contracts/GatewayCrossChain.sol

function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];

    address receiver = msg.sender;
    // If walletAddress is 20 bytes, it's assumed to be an EVM address.
    if(refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
    
    // Authorization check
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
    require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
    
    // The transfer will be sent to the casted 'receiver' address.
    // @audit bitcoin address
    TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);

    // ...
}
```

### Attack Path / Scenario of Loss
Not an attack path, as the bug manifests normally. 

### Impact
ZRC20 Bitcoin are refunded to an invalid address on ZetaChain.

### Mitigation
Non trivial fix
