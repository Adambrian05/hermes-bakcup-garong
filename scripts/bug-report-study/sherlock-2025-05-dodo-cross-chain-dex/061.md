# Malicious users could steal money from ‘GatewayTransferNative’ contract

### Summary

In `GatewayTransferNative::withdrawToNativeChain()` function, users could spend an amount of a cheap zer20 token but withdraw nearly the same amount (only 0.5%fee deducted) of an expensive zrc20 token. Since `GatewayTransferNative` contract has some tokens waiting for `claimRefund`, these tokens could be stolen.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530C5-L601C1



In `GatewayTransferNative::withdrawToNativeChain()` function above, it allows users to exchange the zrc20 token to the target zrc20 token with user's specified `swapData`, which enable malicious users to steal target zrc20 token using a very cheap zrc20 token without doing `_doMixSwap()`.

        // Swap on DODO Router
        uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
        
The `_doMixSwap()` function is shown below but the parameter `swapDataZ` is decoded from message specified by the user. They can leave `swapData` empty to make `ouputAmount=amount`.

    function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

The contract will only check that the source zrc20 token is safely transfered but the target zrc20 token is given by users. After the `_doMixSwap()` function, the contract calls the `withdrawAndCall()` function of `GatewayZEVM`(in evm case) which will charge `outputAmount` of target zrc20 token from the  `GatewayTransferNative` contract (sometimes a little bit smaller for gasfee). 


If the contract has some target zrc20 tokens waiting for `claimRefund`, it will be spent by the `GatewayZEVM` and attackers will get the value with only a small cost.


### Internal Pre-conditions

`GatewayTransferNative.sol` owns zrc20 tokens

### External Pre-conditions

none

### Attack Path

1. Attacker choose a cheap zrc20
2. Attacker choose a target zrc20 token such that `GatewayTransferNative`  contract has a positive balance 
3. Attacker encode the message with the target token but set the swapdata to empty.
4. Attacker call `GatewayTransferNative.sol::withdrawToNativeChain()`with the zrc20 token and message above to withdraw target zrc20 to Ethereum 
5. The target zrc20 token is stolen from `GatewayTransferNative`  contract!

### Impact

The `GatewayTransferNative` contract lose zrc20 tokens.
