# onAbort will fail if message originates from ZEVM

### Summary

All the `ZEVM` outbounds aborts will fail, because no `abortAddress` is being given. 

[[GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L253-L304)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L253-L304)

The same applies for the other ZEVM contract - [`[GatewayCrossChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244-L295)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244-L295)

### Root Cause

Giving `address(0)` as `abortAddress`, while the Zetachain requires a valid address, which exposes the `onAbort` function to be given.

### Internal Pre-conditions

None

### External Pre-conditions

Call to fail, which causes `onRevert` to be invoked, which also has to fail. This is a completely viable scenario, since there are a lot of moving parts that can cause that behaviour. Insufficient liquidity for the swap is one example.

### Attack Path

All the aborts, whose messages originate from ZEVM, will be lost, and to understand that, we must understand how ZETA processes them:

1. https://github.com/zeta-chain/node/blob/develop/x/crosschain/keeper/abort.go#L21C1-L62C3

1. `target` is the 1st argument of the [`[GatewayZEVM::executeAbort](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/zevm/GatewayZEVM.sol#L559C4-L570C6)`](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/zevm/GatewayZEVM.sol#L559C4-L570C6):

```solidity
 function executeAbort(
        address target,
        AbortContext calldata abortContext
    )
        external
        nonReentrant
        onlyProtocol
        whenNotPaused
    {
        if (target == address(0)) revert ZeroAddress();
        Abortable(target).onAbort(abortContext);
    }
```

Execution will revert with `ZeroAddress` and cause the refund assignment to fail.

### Impact

Loss of funds, instead of being refunded to the message creators.

### PoC

N/A

### Mitigation

Pass `address(this)` instead of `address(0)`
