# GatewaySend does not process a revert with a native token

### Summary

[GatewaySend.sol:onRevert()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393) function does not handle reverts when refunding native tokens, leading to a DoS for the refund mechanism.

### Root Cause

If native token was deposited to Gateway and protocol reverted the cross-chain swap, then [GatewayEVM.sol:executeRevert()](https://etherscan.io/address/0x6dac33435d5fd884fd6da4163168bafc39a2ef0d#code#F1#L118) will be called sending tokens back to destination contract:
```solidity
function executeRevert(
    address destination,
    bytes calldata data,
    RevertContext calldata revertContext
)
    public
    payable
    nonReentrant
    onlyRole(TSS_ROLE)
    whenNotPaused
{
    if (destination == address(0)) revert ZeroAddress();
    (bool success,) = destination.call{ value: msg.value }("");
    if (!success) revert ExecutionFailed();
    Revertable(destination).onRevert(revertContext);

    emit Reverted(destination, address(0), msg.value, data, revertContext);
}
```
But `GatewaySend.sol:onRevert()` can only handle ERC20 tokens:
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));
    //@audit @note will revert because asset will be address(0)
    TransferHelper.safeTransfer(context.asset, sender, context.amount);
    ...
}
```
This will revert whole refund process of native tokens.

### Internal Pre-conditions

1. Deposit with native token

### External Pre-conditions

1. Protocol reverted the cross-chain swap

### Attack Path

_No response_

### Impact

DoS of the refund mechanism for native tokens.

_No response_

### Mitigation

If asset is native token use `TransferHelper.safeTransferETH` and if ERC20 use `TransferHelper.safeTransfer`.
