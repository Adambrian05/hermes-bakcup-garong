# Incorrect fee transfer mechanism for native ZETA in `_handleFeeTransfer` function

## Summary

The `_handleFeeTransfer` function in `GatewayTransferNative.sol` uses `TransferHelper.safeTransfer` for all fee collections, including those involving native ZETA (represented by _ETH_ADDRESS_). This is incorrect, as `safeTransfer` is intended for `ZRC20` tokens. Consequently, any transaction requiring fee collection in native ZETA will revert, leading to transaction failures and an inability to collect fees.

## Root Cause

The `_handleFeeTransfer` function, located in `GatewayTransferNative.sol`, does not differentiate between ZRC20 tokens and native ZETA when processing fee transfers. It consistently calls `TransferHelper.safeTransfer`, which attempts to invoke an ERC20 transfer method. When zrc20 is `_ETH_ADDRESS_` (the placeholder for native ZETA), this call fails because the `_ETH_ADDRESS_` does not implement the ERC20 `transfer` interface, causing the transaction to revert with a TRANSFER_FAILED error from TransferHelper.

## Internal pre-conditions

1. A call to the `_handleFeeTransfer` function within `GatewayTransferNative.sol`.
2. The `zrc20` parameter passed to `_handleFeeTransfer` is `_ETH_ADDRESS_`.

## External pre-conditions

1. A user initiates a cross-chain transfer or a `withdrawToNativeChain` operation that involves native ZETA as the asset from which fees are to be collected.

## Attack Path

1. A user initiates a cross-chain operation (e.g., via  `withdrawToNativeChain`) where the input  asset is native ZETA.
2. The `withdrawToNativeChain` function invokes `_handleFeeTransfer` to collect protocol fees.
3. Inside `_handleFeeTransfer`, the zrc20 parameter is `_ETH_ADDRESS_`.
4. The function attempts to execute `TransferHelper.safeTransfer(_ETH_ADDRESS_, EddyTreasurySafe, platformFeesForTx)`.
5. `TransferHelper.safeTransfer` attempts to call a non-existent transfer function on the `_ETH_ADDRESS_`, leading to a transaction reversion with the error `"TransferHelper: TRANSFER_FAILED"`.

## Impact

All cross-chain transactions or native chain withdrawals involving native ZETA, where fees are to be collected, will consistently fail.


## Mitigation
```js
// ... existing code ...
    function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; 

        if (zrc20 == _ETH_ADDRESS_) {
            TransferHelper.safeTransferETH(EddyTreasurySafe, platformFeesForTx);
        } else {
            TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
        }
```
