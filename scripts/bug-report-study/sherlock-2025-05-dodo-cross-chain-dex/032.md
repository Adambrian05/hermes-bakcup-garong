# Approve is Incompatible with Non-Standard ERC20 Tokens

### Summary

The [`approve()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L320) logic does not account for the non-standard behavior of some ERC-20 tokens (like USDT), which require setting the allowance to 0 before updating it to a new value. This may cause approvals to fail silently or revert, breaking token interactions.


### Root Cause
The approve function used in the contract is incompatible with some non-standard ERC20 tokens that do not correctly implement the EIP20 standard. For example, tokens like USDT on Ethereum return void instead of a success boolean, causing transactions to revert when interacting with these tokens. Additionally, some tokens require setting the allowance to 0 before a new approve call, and failing to do so results in the transaction reverting.
This incompatibility can lead to transaction failures when attempting to approve or interact with non-compliant tokens.


The code directly calls:
```solidity
 IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);
```
without first setting the allowance to zero. For some tokens (e.g., USDT), this pattern is not supported. If a non-zero allowance already exists, setting a new non-zero allowance **without zeroing first** will **fail** or **revert**.

### Internal Pre-conditions

- The protocol already has a non-zero allowance for the token and spender - someone already swapped.
- Someone attempts swap again.

### Impact
The swapping between tokens that requires **approve to 0 first** will cаuse DoS(Denial-Of-Service) and the swap cannot be executed

### PoC

Мinimal example with USDT:

```solidity
IERC20 usdt = IERC20(USDT_ADDRESS);

// Initial approval
usdt.approve(router, 1000); // succeeds

// Second approval without resetting
usdt.approve(router, 2000); // will fail silently or revert with USDT
```

### Mitigation

Use a **safe approval pattern** for non-standard tokens, and make a function that first approve to 0.
IMPORTANT: The function should be reused everywhere where the protocol approves addresses
