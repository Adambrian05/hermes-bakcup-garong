# Malicious arbitrary user will withdraw funds from native transfer pool

### Summary

The setting of the receiver variable in the claimRefund() function will cause refunds to be taken by non-affiliated party as malicious actor can claim refund on their behalf.

### Root Cause

In the [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661) file there is a function claimRefund(bytes32 externalId) that allows for any external party to claim a refund on behalf of another.

The function fetches a refundInfo from memory, based on arbitrary input externalId. After this, the receiver is set to msg.sender, which in an attack scenario is a malicious party. The receiver value is only updated if [if(refundInfo.walletAddress.length == 20)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L575), which may not always be the case, depending on the specific chain (such as Bitcoin).

If this is the case, this check is bypassed, leading to the receiver variable staying as msg.sender, and thus passing [the caller check and the valid refund check](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L578).

After this, a safeTransfer is made to the receiver with the value of the refund, leading to arbitrary funds theft for any refund with a walletAddress.length != 20.

### Internal Pre-conditions

1. A valid refund needs to be stored in the contract memory, in the `refundInfos` object.
2. The walletAddress inside that object needs to be `length != 20`


### External Pre-conditions

N/A

### Attack Path


1. User calls claimRefund() with an externalId of a valid refund.

### Impact

The protocol (or end user originally owed the refund) suffers a loss of 100% of the refund value. The attacker gains 100% of this refund value.

### PoC

See POC from similar issue, [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-smellslikecarrots/issues/1#issuecomment-2932102818).

### Mitigation

The receiver variable should always be sourced from the [refundInfo](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L572C41-L572C52) stored in the contract.
