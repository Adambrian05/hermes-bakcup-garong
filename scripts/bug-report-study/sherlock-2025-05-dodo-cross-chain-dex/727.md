# Fee deduction before swap causes loss of funds for users

### Summary

Deducting the platform fee from the user’s input before executing the swap will cause the swap to revertbecause the contract no longer holds the full amount required by the swap parameters.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L551


### Root Cause

 the code subtracts the platform fee from the user’s input before calling _doMixSwap, but still passes the original params.fromTokenAmount into the DODO router’s mixSwap. This mismatch means the contract tries to swap more tokens than it actually holds, leading to a revert.



### Internal Pre-conditions

1. _handleFeeTransfer deducts a non-zero fee, so amount < params.fromTokenAmount.

2. _doMixSwap is then invoked with the reduced amount, yet calls mixSwap(..., fromTokenAmount = originalAmount, …).

### External Pre-conditions

None

### Attack Path

1. User calls onCall(...) with amount = 1 ETH.

2. Platform fee of 0.005 ETH is deducted → amount = 0.995 ETH.

3. _doMixSwap invokes DODO’s mixSwap with fromTokenAmount = 1 ETH, but the contract balance is only 0.995 ETH → revert.

### Impact

The swap reverts after the fee has been deducted

### PoC

_No response_

### Mitigation

1. Swap first, then charge fees on the actual output:
```solidity 
uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
uint256 fee = (outputAmount * feePercent) / 1000;
_handleFeeTransfer(decoded.targetZRC20, fee);
uint256 userAmount = outputAmount - fee;
_transferToUser(userAmount);
```

2. Add the fee to the amount 
```Solidity 
require(params.fromTokenAmount >= AMOUNT + FEE)
```
