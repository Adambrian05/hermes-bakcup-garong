# Excessive Token Approval Allows Over-Withdrawal and Token Loss

## Description
The function onCall calls internal function _handleBitcoinWithdraw  and  function _handleEvmOrSolanaWithdraw which has potential issue that will affect function onCall when it is being called.
The root cause lies in both the function _handleBitcoinWithdraw and  function _handleEvmOrSolanaWithdraw.

 In the function _handleBitcoinWithdrawIZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee), it is approving outputAmount + gasFee, but in the actual withdrawal call it is only sending outputAmount - gasFee allowing more withdrawal of tokens than intended causing permanent loss of tokens from the contract.

In the function _handleEvmOrSolanaWithdraw, in the first branch (decoded.targetZEC20 == gasZRC20), the function approves outputAmount + gasFee to the gateway address for the targetZRC20 token. However, the actual amount withdrawn is outputAmount - gasFee. This over-approval allow more tokens withdrawal than necessary.
 
Problem Summary
For  function _handleBitcoinWithdraw
```solidity
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
withdraw(
    externalId, 
    decoded.receiver, 
    decoded.targetZRC20, 
    outputAmount - gasFee
);
```
For function _handleEvmOrSolanaWithdraw
```solidity
if (decoded.targetZRC20 == gasZRC20) {
    if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    
    // Over-approval happens here
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    
    // Only outputAmount - gasFee is actually withdrawn 
    ...
    withdrawAndCall(..., outputAmount - gasFee, ...);
}
```
The function approves outputAmount + gasFee to the gateway.

But it only withdraws outputAmount - gasFee.

This means the gateway now has permission to pull more tokens than it actually needs for this withdrawal — specifically, 2 * gasFee more than necessary.
Consequences
Excess token allowance: The gateway contract is now allowed to transfer extra tokens from the contract that are never accounted for.

Token loss: This would result in permanent token loss from the current contract if the gateway over-withdraws.

Lack of alignment between allowance and actual transfer creates a security vulnerability.

    event Approval(address indexed owner, address indexed spender, uint256 value);

    function mint(address to, uint256 amount) external {
        balanceOf[to] += amount;
        totalSupply += amount;
        emit Transfer(address(0), to, amount);
    }

    function approve(address spender, uint256 amount) external returns (bool) {
        allowance[msg.sender][spender] = amount;
        emit Approval(msg.sender, spender, amount);
        return true;
    }

    function transferFrom(address from, address to, uint256 amount) external returns (bool) {
        require(allowance[from][msg.sender] >= amount, "Insufficient allowance");
        allowance[from][msg.sender] -= amount;
        balanceOf[from] -= amount;
        balanceOf[to] += amount;
        emit Transfer(from, to, amount);
        return true;
    }
}
