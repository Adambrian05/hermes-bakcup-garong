# ETH Amount Mismatch in `depositAndCall` Leading to Fund Loss

### Summary

The `GatewaySend::depositAndCall`  when handling ETH transfers, only validates that `msg.value >= amount`, but then uses `msg.value` for the actual deposit instead of the specified amount. 

### Root Cause

In the ETH handling branch of GatewaySend::depositAndCall, the function calls `_handleETHDeposit` with msg.value as the amount parameter, not the amount parameter that was passed to the function. The result in user passing the enter value they inputted instead of the required amount.

[https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L309](url)

### Internal Pre-conditions

1. User enters msg.value > amount
2.  msg.value is sent and only Amount to deposit is deposited 
3. mgs.value - amount is loss in transaction

### External Pre-conditions

1. Users loses what is left from `msg.value - amount`

### Attack Path

1. User sends 300 ETH via msg.value
2. User specifies 200 ETH as the amount parameter
3. The contract deducts 300 ETH from the sender
4. The receiver only gets 300 ETH (since msg.value is used), but the event logs show amount (200 ETH)
5. The difference (100 ETH) gets stuck in the contract

### Impact

 Permanent fund loss for users who accidentally send more ETH than they specify in the amount parameter.

### PoC

place this in the GatewaySend.t.sol
```solidity
  function test_depositAndCall_TakesExtra() public {
        address targetContract = address(gatewayTransferNative);
        uint256 amount_specified = 200 ether;
        uint256 amount_sent = 300 ether;

        address asset = _ETH_ADDRESS_;
        address targetZRC20 = address(token2Z);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = abi.encodePacked(user2);
        bytes memory swapDataZ = encodeCompressedMixSwapParams(
            address(token3Z),
            address(token2Z),
            amount_specified,
            0,
            0,
            new address[](1),
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0),
            block.timestamp + 600
        );
        bytes memory payload = encodeNativeMessage(
            targetZRC20,
            sender,
            receiver,
            swapDataZ
        );

        vm.startPrank(user1);
        gatewaySendA.depositAndCall{value: amount_sent}(
            targetContract,
            amount_specified,
            asset,
            dstChainId,
            payload
        );
        vm.stopPrank();

        assertEq(user1.balance, initialBalance - amount_sent);
        console.log("amount_sent:", amount_sent);
        console.log("user1 balance after depositAndCall:", user1.balance);

        assertEq(token2Z.balanceOf(user2), amount_specified);  
        console.log("user2 token2Z balance after depositAndCall:", token2Z.balanceOf(user2));
    }
```

### Mitigation

Update the native token validation to enforce strict equality:
```solidity
if(fromIsETH) {
    require(msg.value == amount, "INCORRECT_ETH_SENT");
}
```
