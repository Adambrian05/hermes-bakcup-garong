# CCTX is not atomic, users may end up receiving tokens they did not intend to receive.

### Summary

Currently, the protocol supports complex cross-chain paths: execute A -> B on one chain, and then execute B -> C on another chain. This means if the user’s second transaction fails, their first transaction cannot fail simultaneously. This can cause users who intended to swap token A for token C to end up holding a large amount of token B. Since such paths are often computed automatically, token B may not be the token the user actually wants.

### Root Cause

When the latter half of a swap path reverts, the former half does not revert.
