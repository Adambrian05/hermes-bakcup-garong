# Bots Fail to Collect Tokens from EVM Contract Addresses in onRevert Functions

### Summary

The README states:
> If the receiver of refund info is not an EOA address, refund bots collect the tokens and process the refund manually.

However, in all the contracts with an `onRevert` function, refund bots don't collect the tokens from EVM smart contract addresses.

### Root Cause

None of the onRevert functions in the Gateway contracts check if an address is an EOA or smart contract and instead just use the length of the address.
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];
```

### Attack Path

1. A cross-chain transaction reverts so onRevert is called. 
2. The receiver of the refund is an EVM smart contract address.
3. Instead of creating the RefundInfo in storage, the contracts send the tokens directly to the smart contract going directly against the desired behavior in the README
