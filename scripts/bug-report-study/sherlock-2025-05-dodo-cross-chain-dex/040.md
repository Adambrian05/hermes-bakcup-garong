# Amount Calculation in `_swapAndSendERC20Tokens` Function Causes Inaccurate Calculation of Remaining Tokens

## Description
There is a critical issue in the calculation of the number of tokens in the `_swapAndSendERC20Tokens` function in the `GatewayCrossChain` contract. This function uses two different values to calculate the number of tokens remaining after the swap:
1. `amountInMax` - used for token availability validation
2. `amounts[0]` - used for the final calculation of tokens sent to users

This issue causes inaccurate calculations and leads to problems in properly allocating tokens to users.

## Root Cause
The root of the problem lies in the `_swapAndSendERC20Tokens` function.
```solidity
// Calculation of amountInMax with slippage tolerance
uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;

// Validation using amountInMax
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

// Approve using amounts[0] (actual swap value)
IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

// Return value using amounts[0]
amountsOut = targetAmount - amounts[0];
```
The problem is that `amountInMax` is the maximum estimate required (including slippage tolerance), while `amounts[0]` is the actual amount used in swap (usually ≤ `amountInMax`). Validation uses `amountInMax` but final calculation uses `amounts[0]`.

## Scenario
1. Initial Setup:
- `targetAmount` = 1000 tokens
- `gasFee` required = 100 gasToken
- `amountsQuote[0]` = 200 tokens (estimated to get 100 gasToken)
- `slippage` = 10 (1%)
2. Calculation of `amountInMax`:
```diff
amountInMax = 200 + (10 * 200) / 1000 = 200 + 2 = 202 token
```
3. Validation with `amountInMax`:
```diff
require(1000 - 202 > 0) // ✅ Pass: 798 > 0
```
4. Actual Swap:
- Uniswap performed the swap and only used 195 tokens (more efficient than estimated)
- `amounts[0]` = 195 tokens
5. Approve and Return:
```diff
// Approve: 1000 - 195 = 805 token
IZRC20(targetZRC20).approve(address(gateway), 805);

// Return: 805 token
amountsOut = 805;
```
6. Problem:
- Validation assumes only 798 tokens are left
- But actually 805 tokens are left
- The difference of 7 tokens is not calculated correctly

## Impact
Token calculation is inaccurate, because the number of tokens sent to the user can be greater than the one validated. Data inconsistency, because validation and execution use different calculation bases.

## Recommendation
Use `amounts[0]` for all calculations.
```solidity
function _swapAndSendERC20Tokens(
    address targetZRC20,
    address gasZRC20,
    uint256 gasFee,
    uint256 targetAmount
) internal returns(uint256 amountsOut) {
    // Calculate how many ZRC20 targets are needed to get TRC20 gas fee gas
    uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
        UniswapFactory,
        gasFee,
        getPathForTokens(targetZRC20, gasZRC20)
    );

    // Add slippage tolerance to the maximum input amount
    uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
    
    // Approve router to use target token
    IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

    // Make a swap: exchange the ERC20 target with TRC20 gas for the amount of Fee gas
    uint[] memory amounts = IUniswapV2Router01(UniswapRouter)
        .swapTokensForExactTokens(
            gasFee,
            amountInMax,
            getPathForTokens(targetZRC20, gasZRC20),
            address(this),
            block.timestamp + MAX_DEADLINE
    );

    // Validate that the contract has enough gas tokens after the swap
    require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
    
    // ✅ FIX: Use amounts[0] for consistent validation
    require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
    
    // Calculate the remaining amount available after the actual swap
    uint256 remainingAmount = targetAmount - amounts[0];

    // Approve gateway to use gas token and remaining target token
    IZRC20(gasZRC20).approve(address(gateway), gasFee);
    IZRC20(targetZRC20).approve(address(gateway), remainingAmount);

    // ✅ FIX: Return amount consistent with calculation
    amountsOut = remainingAmount;
}
```
