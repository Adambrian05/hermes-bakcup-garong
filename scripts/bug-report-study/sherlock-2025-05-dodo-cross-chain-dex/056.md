# Platform fees deducting is missing in GatewayTransferNative::onCall() swap path

### Summary

Missing platform fee deduction in swap path will cause loss of protocol fees for the protocol as users will receive more tokens than intended when swapping occurs in `GatewayTransferNative::onCall()`.

### Root Cause

In `GatewayTransferNative.sol:390` the full `amount` is passed to `_doMixSwap()` without deducting `platformFeesForTx`, unlike the same token path which correctly deducts fees and other contract implementations like `GatewayCrossChain.sol:461` which properly deducts fees before swapping.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L369-L395

### External Pre-conditions

### Attack Path

1. User sends a cross-chain message to `GatewayTransferNative::onCall()` with `decoded.targetZRC20 != zrc20` to trigger the swap path
2. Function calculates `platformFeesForTx = _handleFeeTransfer(zrc20, amount)` and transfers the fee amount to the protocol 
3. Function calls `_doMixSwap(decoded.swapData, amount, params)` passing the full original `amount` instead of `amount - platformFeesForTx`
4. User receives swap output based on full amount, effectively getting more tokens than they should since platform fees were not deducted from the swap input

### Impact

The protocol suffers loss of platform fees (0.5% of transaction amount) on every swap transaction. Users gain the additional tokens that should have been collected as fees by the protocol.

### PoC

_No response_

### Mitigation

Deduct platform fees from amount before swapping, consistent with the same token path and other contract implementations
