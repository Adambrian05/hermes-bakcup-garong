# Incorrect Assumption of ERC-20 Compliance Breaks USDT Support in Cross-Chain Bridging

### Summary

The depositAndCall() function assumes all assets conform to the standard ERC-20 interface:

```solidity
require(
    IERC20(asset).transferFrom(msg.sender, address(this), amount),
    "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
);
```
However, Tether (USDT) is known to not return any data when transfer() or transferFrom() succeed.
This causes Solidity to interpret the call as having failed — even though the token transfer actually succeeded — leading to an unnecessary revert.
As a result:
Any attempt to bridge USDT across chains will revert , even with valid approvals and balances. 



### Root Cause

In depositAndCall():

```solidity
IERC20(asset).transferFrom(msg.sender, address(this), amount);
This line uses the standard IERC20.transferFrom() interface, which returns a bool.
```

However, USDT does not return any data upon successful transfer — only reverts on failure.

When calling .transferFrom() on USDT:

The transfer may have succeeded
But no return value is provided
Solidity interprets this as a revert or false
Contract reverts with "ERC20 TRANSFER FROM FAILED"
This behavior affects only non-compliant ERC-20 tokens like USDT.
