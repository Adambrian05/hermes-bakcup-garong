# User can enforce message to enter `onAbort` in Zetachain to skip protocol fee

### Summary

Dodo has a [platformFeesForTx](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357-L371), which is taken inside `GatewayCrossChain::onCall` and `GatewayTransferNative::onCall` from the bridged `zrc20`. The fee is always taken:
- if user makes a cross chain swap -> From A to B trough ZetaChain (fee is taken of Zeta)
- if user makes a bridge/swap from A to Zetachain (fee is taken on Zeta)
- if user makes bridge/swap from Zetachain -> A (fee is taken on Zeta)

However, there is a way to skip the fee, if the user initiated a transaction from a connected chain and enforce the transaction to enter Zeta `onAbort` function.
The flow of operations is `Connected chain -> depositAndCall` -> `revert on Zetachain` -> enter `onRevert` on source (connected), where the transaction also reverts -> enter `onAbort` on Zetachain, where the raw bridged amount is written to `refundInfos`

### Root Cause

Not distinguishing messages inside onAbort that originate from a connected chain.

That's the case because when `onAbort` is called from a message, which has created inside the ZetaChain contract (withdraw/withdrawAndCall), we have already transferred the fee and subtracted the amount, but that's not the case when the message is initiated from connected and has reverted in `onRevert` on the initiated chain

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Malicious actor initiates a message to bridge 10000 USDT from Mainnet to Zeta
- His address is blocklisted, so he transfers eth to `GatewaySend` and executes a swap for USDT 
- revert message is set the following way:
```solidity
        RevertOptions memory revertOptions = RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: targetContract,
            revertMessage: bytes.concat(externalId, bytes20(msg.sender)),
            onRevertGasLimit: gasLimit
        });
```
- this will result in failing `onRevert` message on source chain because we ill try to transfer the USDT tokens to a blocklisted address
- The actor has encoded a message for destination, which will result in revert inside `_doMixSwap` because of unrealistically large `minAmount`
2. The message reverts on dest `onCall` and then on source `onRevert`
3. Then we enter `onAbort` on `GatewayCrossChain/GatewayTransferNative` and write to `refundInfos` the raw `amount`
4. User calls `claimRefund` skipping the protocol fee

### Impact

Users bypassing protocol fees 

### PoC

_No response_

### Mitigation

Implement additional bool to `revertMessage` structure to validate if the message is initiated from connected chain, or from zetachain. If it is from connected -> take the fee inside `onAbort`
