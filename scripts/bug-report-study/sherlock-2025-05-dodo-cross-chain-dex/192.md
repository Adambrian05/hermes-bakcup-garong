# Vulnerability in onRevert() and onAbort() function in GatewayCrossChain.sol

### Summary

The `GatewayCrossChain.sol::onRevert()` function is able to modify `refundInfos`. However, the only requirement in the function is `onlyGateway` modifier which means if attackers call `GatewayCrossChain.sol::onRevert()` through `GatewayZEVM` contract, they can modify the `refundInfos` for any `externalId`.

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L517C1-L548C6

In GatewayCrossChain.sol:517, the `onRevert()` function could only be called by `GatewayZEVM` and the parameter is `RevertContext.` Notice that anyone could call `GatewayZEVM` with their specified `revertAddress` and `revertMessage`.
Suppose an attacker set `revertAddress` to `GatewayCrossChain` and the `externalId` part in the `revertMessage` to some existing `externalId`, and he set a receiver on Ethereum to revert any call. Then he ask `GatewayZEVM` to execute his cross-chain call request to send ETH to Ethereum. The transaction reverts and `GatewayZEVM` call `onRevert()` function of `GatewayCrossChain` which enables the modification of `refundInfos[externalId]`. There is no checks of whether the `refundInfos[externalId]` is empty, which gives the attacker a chance to modify other user's `refundInfo`.
Similar method could also attack `onAbort()`.

### Internal Pre-conditions

`refundInfos` is not empty

### External Pre-conditions

none

### Attack Path

1.Suppose Bob has 1000ETH in  `GatewayCrossChain` contract waiting for `claimRefund()`, his `externalID` is "BobID..."
2.Alice call `GatewayZEVM::withdrawAndCall()` with `receiver`:an contract deployed by Alice to revert any call,  `amount`:10e13 wei, `zrc20`: ETH, `message`: "", `CallOptions`:(10e4, true), `revertOptions`:(
`revertAddress` : `GatewayCrossChain`,
 `callOnRevert`: true
  `abortAddress`: address(0)
  `revertMessage`: concat("BobID...",a 21 bytes long string)
    `onRevertGasLimit`: 10e5)
3.Her request reverts on Ethereum because the receiver reverts
4.`GatewayZEVM` call `executeRevert()`, the target is `GatewayCrossChain` and the `revertContext` is `sender`:Alice, `asset`:ETH, `amount`:10e13, `revertMessage`: concat("BobID...",a 21 bytes long string)
5.The `GatewayZEVM::executeRevert()` call `GatewayCrossChain::onRevert()`
6. Since `revertMessage.length` is greater than 52, the `refundInfos["BobID..."]` will be changed
7. Bob cannot get his refunds back forever


### Impact

The `refundInfos` in `GatewayCrossChain`  contract will be modified and users cannot get their refunds back.
