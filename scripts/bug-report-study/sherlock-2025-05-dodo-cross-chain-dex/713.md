# GatewaySend’s depositAndCall will fail for tokens with missing return values due to the usage of transferFrom

### Summary

GatewaySend utilizes transferFrom in multiple instances in order to transfer the tokens from the user-in-question/Zetachain Gateway to the DODO Gateway. The problem is that instead of utilizing the SafeERC20 library (for e.g. the one from OZ) in order to handle edge case scenarios originating from weird ERC20 tokens, like missing return values, they're directly using transferFrom.

Considering that the GatewaySend and DODO cross-chain in general will utilize all assets supported by ZetaChain:
https://www.zetachain.com/docs/developers/tokens/zrc20/

This also includes USDT on Mainnet, which is a token which doesn't return a value during the transferFrom method.
https://etherscan.io/token/0xdac17f958d2ee523a2206206994597c13d831ec7#code

### Root Cause

Considering the intefrace used is the IERC20 interface from OpenZeppelin, the transferFrom method here (and in almost all ERC20 token) expects to return a boolean value which would indicate the successful transfer. Since this isn't the case with USDT on Mainnet, the GatewaySend contract won't be functional for this token in multiple instances:

1. depositAndCall -> transferring the token from msg.sender to address(this): 
```solidity

    function depositAndCall(
        address fromToken,
        uint256 amount,
        bytes calldata swapData,
        address targetContract,
        address asset,
        uint32 dstChainId,
        bytes calldata payload
    ) public payable {
        globalNonce++;
        bytes32 externalId = _calcExternalId(msg.sender);
        bool fromIsETH = (fromToken == _ETH_ADDRESS_);

        // Handle input token
        if(fromIsETH) {
            require(
                msg.value >= amount, 
                "INSUFFICIENT AMOUNT: ETH NOT ENOUGH"
            );
        } else {
            require(
                IERC20(fromToken).transferFrom(msg.sender, address(this), amount), 
                "INSUFFICIENT AMOUNT: ERC20 TRANSFER FROM FAILED"
            );
        }

```


2. onCall -> transferring the token from the ZetaChain Gateway to address(this), i.e. DODO Gateway:
```solidity
 function onCall(
        MessageContext calldata /*context*/,
        bytes calldata message
    ) external payable onlyGateway returns (bytes4) {
        (
            bytes32 externalId, 
            uint256 amount, 
            bytes calldata recipient, 
            address fromToken, 
            address toToken, 
            bytes calldata swapData
        ) = decodePackedMessage(message);

        bool fromIsETH = (fromToken == _ETH_ADDRESS_);
        bool toIsETH = (toToken == _ETH_ADDRESS_);
        address evmWalletAddress = address(bytes20(recipient));

        if(!fromIsETH) {
            IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
        }

```

### Internal Pre-conditions

None

### External Pre-conditions

USDT is being bridged either from Mainnet to another destination chain or is being bridged to mainnet, in both cases the GatewaySend contract won't be able to handle it due to a missing return value.

N/A

GatewaySend is incompatible with tokens who have missing return values, such as USDT which will be utilized in the DODO ecosystem.
