# Draining of excess approval through `GatewayTransferNative::withdraw`

### Summary

The [[GatewayTransferNative::withdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304) function is publicly accessible and is used to initiate a message relay via the gateway. However, this function should be internal. Its current public visibility introduces a critical risk where excess token approvals—left over from refund scenarios—can be maliciously exploited.

During withdrawal through `GatewayTransferNative::withdrawToNativeChain`, both `_handleBitcoinWithdraw` and `_handleEvmOrSolanaWithdraw` approve a `gasFee` amount **in excess** of what is actually withdrawn:

```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    // Approves more than withdrawn
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    withdraw(externalId, decoded.receiver, decoded.targetZRC20, outputAmount - gasFee);
}
```

```solidity
function _handleEvmOrSolanaWithdraw(
    bytes32 externalId,
    DecodedMessage memory decoded,
    uint256 outputAmount,
    bytes memory receiver
) internal returns (uint256 amountsOutTarget) {
    (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(gasLimit);

    if (decoded.targetZRC20 == gasZRC20) {
        if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        // Approves more than withdrawn
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
```

Since the approval exceeds the actual transfer amount, the surplus (`gasFee`) remains approved and unspent.

If a revert occurs, the `onRevert` function is invoked, and tokens are refunded to the contract. However, due to the public `withdraw` function, **any user** can later exploit this leftover approval to drain these refunded tokens, which were intended for the original user.

### Root Cause

1. Both `_handleEvmOrSolanaWithdraw` and `_handleBitcoinWithdraw` approve `outputAmount + gasFee`, but only `outputAmount - gasFee` is actually transferred.
2. `GatewayTransferNative::withdraw` is incorrectly marked `public`.

### Internal Pre-conditions

None

### External Pre-conditions

1. A revert must occur, causing a refund to be held by the contract.
2. A prior withdrawal attempt must leave a surplus approval.

### Attack Path

1. Alice initiates a withdrawal, which reverts, triggering a refund.
2. The approval for `outputAmount + gasFee` remains active.
3. Bob discovers the public `withdraw` function and uses it to spend the leftover approval and drain the refund.
4. Alice attempts to claim her refund but fails due to insufficient balance.

### Impact

1. Users' refunds can be stolen.
2. Contract becomes insolvent for rightful refund claims.

### PoC

*No response*

### Mitigation

* Restrict visibility of `withdraw` to `internal` to prevent unauthorized use.
* Modify approval logic to match the exact amount being transferred:

```diff
- IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
+ IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount - gasFee);
```
