# Attacker can send 1 wei of tokenA/B to precomputed UniV2 pool and grief users

### Summary

An attacker can send 1 wei to the precomputed UniV2 pair address of the `[zrc20A, zrc20B]` and grief the users, causing their messages not to be possible.

The reason is that the `_existsPairPool` will return falsy `true`.

[`[GatewayCrossChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L242)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L242), [`[GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L216-L251)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L216-L251):

```solidity
function _existsPairPool(
    address uniswapV2Factory,
    address zrc20A,
    address zrc20B
) internal view returns (bool) {
    address uniswapPool = uniswapv2PairFor(
        uniswapV2Factory,
        zrc20A,
        zrc20B
    );
    return
        IZRC20(zrc20A).balanceOf(uniswapPool) > 0 &&
        IZRC20(zrc20B).balanceOf(uniswapPool) > 0;
}
```

Since we can send tokens to addresses that are not used. But when the execution invokes the `getAmountsIn`:

[`[GatewayCrossChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L242)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L207-L242), [`[GatewayTransferNative](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L216-L251)`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L216-L251):

```solidity
uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
);
```

With the false indication of having `[targetZRC, gasZRC]` pair, execution reverts inside, when `reserves` are tried to be fetched, because there’s no such function and the address is in reality empty:

```solidity
function getAmountsIn(address factory, uint amountOut, address[] memory path) internal view returns (uint[] memory amounts) {
        require(path.length >= 2, 'UniswapV2Library: INVALID_PATH');
        amounts = new uint[](path.length);
        amounts[amounts.length - 1] = amountOut;
        for (uint i = path.length - 1; i > 0; i--) {
            (uint reserveIn, uint reserveOut) = getReserves(factory, path[i - 1], path[i]);
            amounts[i - 1] = getAmountIn(amounts[i], reserveIn, reserveOut);
        }
    }
```

### Root Cause

Wrong UniV2 pool existence check, as it should verify reserves are non-zero, not the balances, allows adversaries to send 1 wei of each token, to trick the DODO Gateway contracts to believe there’s a **direct** `[targetZRC, gasZRC]` pair.

### Internal Pre-conditions

NONE

### External Pre-conditions

NONE

### Attack Path

1. Attackers decide which pairs to target, as more favorable are the ones that already have `[targetZRC, WZETA], [WZETA, gasZRC]` pairs that are actively used.
2. They precompute the address of the to-be `[targetZRC, gasZRC]` pool with the `uniswapv2PairFor` function, as the UniV2 pair deployment is deterministic and can be guessed for each set of tokens.
3. Send 1 wei of each token to the EMPTY precomputed address
4. ZEVM withdrawals for these 2 tokens start reverting until the actual pool is deployed, but that’s not enough, as there will be low liquidity, which won’t be able to satisfy the swap, causing more reverts until liquidity is added.

### Impact

Blocked withdrawals, causing inability to perform cross-chain swaps.

### PoC

N/A

### Mitigation

Use the `quote` function in a `try/catch` first to check if the pool exists, and if it exists, can it satisfy the swap. If either one of these is false, opt in for the intermediate `WZETA` swap.
