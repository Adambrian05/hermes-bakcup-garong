# Incorrect Chain ID for Solana Hardcoded in GatewayTransferNative, Breaking Cross-Chain Compatibility

### Summary

The `GatewayTransferNative.sol` and `GatewayCrossChain.sol` hardcodes an incorrect chain ID for Solana 

```solidity
uint32 constant SOLANA_EDDY = 1399811149; // chain Id from eddy db
```

However [Zeta docs](https://www.zetachain.com/docs/developers/chains/list)  specifies the correct Solana chain ID as **900**. This mismatch causes the contract to reject valid Solana-based transactions or route them incorrectly, breaking cross-chain functionality and making the system incompatible with future Solana integrations. 

The value `BITCOIN_EDDY = 8332` in `GatewayTransferNative` is correctly provided and matches the official chain ID for Bitcoin from ZetaChain’s docs. But `SOLANA_EDDY = 1399811149` is wrong - the actual chain ID for Solana is `900`. This should be fixed to make sure Solana transactions work properly.

Due to an incorrect Solana chain ID, the `_handleEvmOrSolanaWithdraw()` function will not be executed. As a result, the transaction will fail or revert because Solana will not receive the correctly formatted input specifying which accounts to operate on. This will make the Cross chain protocol useless for all Solana cross chain transactions hence marketing it as High vulnerability

```solidity
     bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
                ? AccountEncoder.encodeInput(
                    AccountEncoder.decompressAccounts(decoded.accounts),
                    data
                )
                : data;
```

### Root Cause

- `GatewayTransferNative` hardcodes `SOLANA_EDDY = 1399811149`
- This does **not match** the ZetaChain-standard chain ID of `900` for Solana

### PoC

1. Attempt a cross-chain call from/to Solana using `dstChainId = 900`
2. Observe contract logic bypasses or fails due to:
    
    ```solidity
    if (dstChainId == SOLANA_EDDY) { ... }
    ```
    
    where `900 != 1399811149`, hence conditional logic is skipped
    
3. Transaction fails

### Mitigation

Replace the incorrect constant:

```diff
- uint32 constant SOLANA_EDDY = 1399811149;
+ uint32 constant SOLANA_EDDY = 900;
```

Alternatively consider this approach of fetching chain IDs dynamically from a trusted mapping or allow mapping via governance:

```solidity
mapping(string => uint32) public chainIds;
function setChainId(string calldata name, uint32 id) external onlyOwner {
    chainIds[name] = id;
}
```
