# Anyone can steal a refund from Solana

### Summary
This affects both `GatewayCrossChain` and `GatewayTransferNative`

Solana account addresses are 32 bytes. When we bridge to solana, we should provide a `receiver` address, which is 32 bytes:
In `GatewayCrossChain::onCall` -> `_handleEvmOrSolanaWithdraw` -> `withdrawAndCall` we set `receiver` inside the revert message:
```solidity
        gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
        );
```

If the message reverts, we will enter [onRevert](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L532-L540) and write to `refundInfos`
Then anyone can call [claimRefund](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L574-L579) which will result in withdrawing the funds. 

### Root Cause

That's the case because the following check is flawed and in `walletAddress != 20 bytes` there is no check. `receiver` is always set to `msg.sender`, so `msg.sender == receiver` check passes and anyone can claim the funds.

```solidity
        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
```

### Internal Pre-conditions

Someone has bridged to Solana

### External Pre-conditions

None

### Attack Path

1. Someone bridges 1 sol to Solana from main net 
2. Tx fails on Solana
3. Searcher calls `claimRefund` on Zetachain after the `refundInfos` has been updated

### Impact

Funds theft

### PoC

_No response_

### Mitigation

Add a field inside the revert message to indicate a user's address on ZetaChain, which will be set in `refundInfos` and compared to the `msg.sender` in `claimRefund`
