# Missing access controls on GatewayTransferNative::withdraw allow draining of unclaimed refunds

### Summary

Anyone can call `GatewayTransferNative::withdraw()` (due to public visibility) without depositing any ZRC20 tokens to withdraw. If there are refunded token in GatewayTransferNative prior to being claimed by refund bots, these tokens can be stolen by an attacker calling `withdraw()`.

### Root Cause

Missing access controls on `GatewayTransferNative::withdraw`.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L291

### Internal Pre-conditions

1. There are unclaimed refunds in GatewayTransferNative.

### External Pre-conditions

n/a

### Attack Path

Attacker calls `GatewayTransferNative::withdraw()`, inputting their address as the `sender`, the amount of pending refunds as the token `amount` minus gas fees, and the `outputToken` as the token the pending refunds are in. This allows the attacker to drain these tokens from GatewayTransferNative. 

### Impact

Unclaimed refunds are drained from the contract.

### PoC

_No response_

### Mitigation

Change visibility on withdraw() to internal.
