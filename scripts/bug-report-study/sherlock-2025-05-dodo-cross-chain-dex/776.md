# WithdrawToNativeChain will not work when ZETA is fromToken since the function tries to call approve on native token

### Summary

Calling withdrawToNativeChain with ZETA as the fromToken will fail because the contract attempts to call approve on the native token address, which is not a contract (but rather a convention to indicate that the native token is used). This makes native token swaps via this function impossible.

### Root Cause

When the user tries to call withdrawToNativeChain with ZETA (the native token on ZetaChain) as the fromToken, the zrc20 variable is set to the native token (as expected), and the amount is the same as msg.value. After the fee is paid (assuming the issue where fees cannot be paid when the ZRC20 is a native token is fixed), the _doMixSwap function is called, where the following line is executed:
```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount);
```
The problem is that the contract tries to call approve on the native token address. Since that address is not actually a contract, but rather a convention used by developers to signal that the native token is being used, this call will fail.
```solidity
function _doMixSwap(
        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```

### Attack Path

1. A user calls withdrawToNativeChain with fromToken/zrc20 set to ZETA (native token) and the amount equal to msg.value.
2. The fee is calculated and paid.
3. The _doMixSwap function is invoked.
4. Inside _doMixSwap, the following line is executed:
```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount);
```
5. Since fromToken is ZETA (native token), the approve call fails.

### Impact

Since it is expected that the withdrawToNativeChain function should support native token swaps (e.g., swapping the native token to a certain ZRC20), this vulnerability prevents that functionality. The attempt to call approve on a non-contract address causes the function to revert, making such swaps impossible.

### Mitigation

Consider checking if fromToken is the native token. If it is, then the approve call should be skipped.
