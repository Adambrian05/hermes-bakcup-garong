# User will drain contract native balance by specifying arbitrary amounts without validation

### Summary

The missing validation of `msg.value` against `amount` parameter in `GatewayTransferNative::withdrawToNativeChain()` will cause a loss of contract funds for the protocol as a user will specify arbitrary amounts when using ETH without sending equivalent value.

### Root Cause

In `GatewayTransferNative.sol:535-537` there is a missing validation to ensure that when `zrc20` equals `_ETH_ADDRESS_`, the `amount` parameter matches `msg.value`.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L537

This missing validation will allow an attacker to drain the contract ETH balance by specifying an arbitrary amount without sending equivalent value.

To avoid doing a swap, the attacker can specify a swapData with length equal to 0.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L555

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L432

Transferring later the same specified amount 
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L580-L585

### Internal Pre-conditions

1. Contract needs to have some native balance from previous transactions

### External Pre-conditions

N/A

### Attack Path

1. **User calls `GatewayTransferNative::withdrawToNativeChain()` with `zrc20 = _ETH_ADDRESS_`, sends 0.01 ETH via `msg.value`, but specifies `amount = 100 ETH`**
2. **The validation check `if(zrc20 != _ETH_ADDRESS_)` is false, so no transferFrom validation occurs**
3. **Since swapData length is 0, `_doMixSwap()` returns the full 100 ETH amount without performing any swap**
4. **The withdrawal processing continues with 100 ETH despite user only sending 0.01 ETH**

### Impact

The protocol suffers loss of ETH stored in the contract as users can specify arbitrary amounts without sending equivalent value. Users gain access to contract's ETH funds beyond what they actually deposited.

### PoC

_No response_

### Mitigation

Add validation for ETH value and amount:

```solidity
if(zrc20 != _ETH_ADDRESS_) {
    require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
} else {
    require(msg.value == amount, "ETH amount mismatch");
}
```
