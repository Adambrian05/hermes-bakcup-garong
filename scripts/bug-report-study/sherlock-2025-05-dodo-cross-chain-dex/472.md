# Users Might Lose All their Tokens When Withdrawing Due to the `abortAddress` Not Being Set

### Summary

The `GatewayTransferNative::withdrawAndCall` and `GatewayTransferNative::withdraw` functions do not have the `abortAddress` set. The abort function is called when the revert function fails. Since the `abortAddress` is set to `address(0)`, the abort function can never be called. This can cause the user to lose out on all tokens when withdrawing their tokens. 

### Root Cause

The `GatewayTransferNative::withdrawAndCall` and `GatewayTransferNative::withdraw` functions have the `RevertOptions` settings which are set for when the transaction fails in the destination chain. If the `onRevert` function fails, then it calls the `onAbort` function as stated in the [docs](https://www.zetachain.com/docs/developers/chains/zetachain/#:~:text=and%20outgoing%20transactions.-,Summary,onAbort()%20on%20ZetaChain,-Withdraw%20ZRC%2D20). Both the `withdrawAndCall` and `withdraw` functions have the following [`RevertOptions`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L273): 

```solidity
gateway.withdrawAndCall(
            contractAddress,
            outputAmount,
            targetZRC20,
            message,
            CallOptions({
                isArbitraryCall: false,
                gasLimit: gasLimit
            }),
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
@>                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
```
The line noted above shows how the `abortAddress` is set to `address(0)`. This means that if the `onRevert` function fails for whatever reason, the abort function will never be called. 

This can cause users to lose all their tokens since the transfer succeeds in the ZetaChain but reverts in the destination chain.

### Attack Path

1. User withdraws their tokens from the `GatewayTransferNative`.
2. The withdrawal fails in the destination chain. 
3. The `onRevert` function fails. 
4. There is no `onAbort` function to call. 

### Impact

The user will lose all the tokens they tried to withdraw because the transaction succeeds in the originating chain, but fails in the destination chain in which they expect to receive their tokens. If both the withdraw and the `onRevert` function fails, they lose all their tokens since there is no `onAbort` function logic set.
