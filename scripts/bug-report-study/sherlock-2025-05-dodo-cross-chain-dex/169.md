# `GatewayTransferNative::_handleFeeTransfer` has loss of precision may cause less fee than expect

### Summary

The `GatewayTransferNative::_handleFeeTransfer` use the solidity native division to calculate the fee, but the solidity's division has loss of precision which cause less fee than expect.


### Root Cause

In the following code, the `platformFeesForTx` is calculated by the native solidity division. In solidity if 999 / 1000 = 0 actually.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L345 

### Internal Pre-conditions

No

### External Pre-conditions

No

### Attack Path

Attacker can seprate large amount transfer to small batches (such as per 999 amount each batch). Attacker can avoid pay the fee to the platform.

### Impact

Though the loss the precision is small, the loss can be accumulated thourgh time and use times. In the end, the loss of precision can be very massive. It mainly has following impact:
1. Attacker can split large amount transfer to small batches to avoid the platform fee
2. With more and more user and more and more time, the loss of precision can be very large

### PoC

_No response_

### Mitigation

Use fixpoint math to avoid the loss of precision.
