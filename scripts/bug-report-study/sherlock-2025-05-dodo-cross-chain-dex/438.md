# Amount Mismatch Between Approval and Swap Will Cause Transaction Failures and Fee Loss

## Summary

**The amount mismatch in `_doMixSwap` will cause transaction failures and fee loss for users as any user performing cross-chain swaps will trigger DODO swap failures due to insufficient token approvals.**

## Root Cause

In `GatewayCrossChain::_doMixSwap` and `GatewayTransferNative::_doMixSwap`, the function approves `amount` (reduced after fee deduction) but calls `mixSwap` with `params.fromTokenAmount` (original amount before fee deduction).

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337-L350
```solidity
function _doMixSwap(
    bytes memory swapData, 
    uint256 amount, 
    MixSwapParams memory params
) internal returns (uint256 outputAmount) {
    if (swapData.length == 0) {
        return amount;
    }

    IZRC20(params.fromToken).approve(DODOApprove, amount); // Approves reduced amount
    return IDODORouteProxy(DODORouteProxy).mixSwap(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount, // Uses original amount - MISMATCH
        // ...
    );
}
```

## Internal Pre-conditions

1. Admin needs to set `feePercent` to be greater than `0` (default is `5` representing 0.5%)
2. Protocol needs to have platform fee collection enabled (standard operating condition)

## External Pre-conditions

None.

## Attack Path

1. **User initiates cross-chain swap** by calling `onCall` in `GatewayCrossChain` with tokens worth `X` amount
2. **Platform fee is deducted** via `_handleFeeTransfer`, reducing available amount to `X - platformFee`
3. **`_doMixSwap` is called** with the reduced amount `X - platformFee`
4. **Contract approves** `X - platformFee` tokens to `DODOApprove`
5. **DODO mixSwap is called** requesting `params.fromTokenAmount` (original `X` amount)
6. **Transaction reverts** because DODO tries to transfer `X` tokens but only `X - platformFee` was approved
7. **User loses platform fee** permanently as the fee was already transferred to treasury before the swap failure

In onCall flow:
1. User sends 1000 USDC for cross-chain swap
2. Platform fee: 1000 * 5 / 1000 = 5 USDC (sent to treasury)
3. Remaining amount: 995 USDC
4. _doMixSwap called with amount = 995 USDC
5. Contract approves 995 USDC to DODOApprove
6. mixSwap tries to use params.fromTokenAmount = 1000 USDC
7. DODO fails: "ERC20: transfer amount exceeds allowance"
8. Transaction reverts, user loses 5 USDC fee permanently

## Impact

**Users suffer guaranteed loss of platform fees (0.5% by default) on every cross-chain swap transaction that fails due to insufficient approvals. The protocol's core functionality becomes completely unusable when fees are enabled, causing both immediate financial loss and rendering the cross-chain DEX non-functional.**


## Mitigation

Update `params.fromTokenAmount` to equal the actual available `amount` (after fee deduction) before calling DODO's `mixSwap`. Additionally, proportionally scale down `params.expReturnAmount` and `params.minReturnAmount` by the same ratio to maintain realistic slippage expectations based on the reduced input amount.
