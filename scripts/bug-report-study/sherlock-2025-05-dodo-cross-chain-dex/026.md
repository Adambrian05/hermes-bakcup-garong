# Unsafe ETH transfer will cause transaction failures for users

### Summary

The use of unsafe `.transfer()` method for ETH transfers will cause transaction failures and potential fund locks for users as smart contract recipients or future gas cost changes will exceed the 2300 gas limit.

### Root Cause

In `GatewaySend.sol:370` the contract uses `payable(evmWalletAddress).transfer(outputAmount)` which has a hardcoded 2300 gas limit that can fail when transferring to smart contracts or if gas costs change.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L370

### Attack Path

1. **Call to `GatewaySend::onCall()` with a swap to ETH where recipient is a smart contract**
2. **The function executes swap logic successfully and calculates `outputAmount`**
3. **When `toIsETH` is true, the function calls `payable(evmWalletAddress).transfer(outputAmount)`**
4. **The recipient smart contract requires more than 2300 gas to receive ETH (e.g., has receive() function with logging)**
5. **The `.transfer()` call fails due to gas limit, reverting the entire transaction**
6. **User's funds remain locked in the contract as the transaction cannot complete**

### Impact

Users suffer complete transaction failure and potential fund locks when receiving ETH. Smart contract recipients cannot receive their swapped ETH, breaking core functionality of the cross-chain swap protocol.

### Mitigation

Replace the unsafe `.transfer()` method with `TransferHelper.safeTransferETH()` which is already available in the codebase.
