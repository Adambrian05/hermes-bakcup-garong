# GatewayTransferNative incorrectly handles fees when using native token

### Summary

`GatewayTransferNative.sol:_handleFeeTransfer()` function always sends tokens as ZRC20, even though native token can be used. 

### Root Cause

[GatewayTransferNative.sol:_handleFeeTransfer()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341) always handles fee transfer as ZRC20:
```solidity
function _handleFeeTransfer(
    address zrc20,
    uint256 amount
) internal returns (uint256 platformFeesForTx) {
    platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
    //@audit only ZRC20
    TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
}
```
But [withdrawToNativeChain()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530) may use native tokens:
```solidity
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    if(zrc20 != _ETH_ADDRESS_) {
        require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
    } 
   ...
    // Transfer platform fees
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
   ...
}
```
`_handleFeeTransfer()` function will revert because it calls to non-existent contract.
