# User can avoid gas fees and steal from refunds by creating small pool

### Summary

Whenever an EVM or Solana withdrawal occurs through `GatewayTransferNative::withdrawToNativeChain`, the [\[_handleEvmOrSolanaWithdraw](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L467-L528)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L467-L528) function is invoked. This function swaps the token to be withdrawn into the required gas token using `_swapAndSendERC20Tokens`:

```solidity
function _swapAndSendERC20Tokens(address targetZRC20, address gasZRC20, uint256 gasFee, uint256 targetAmount)
    internal
    returns (uint256 amountsOut)
{
    uint256[] memory amountsQuote = UniswapV2Library.getAmountsIn(
        UniswapFactory,
        gasFee,
        getPathForTokens(targetZRC20, gasZRC20)
    );

    uint256 amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000;
    IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);

    uint256[] memory amounts = IUniswapV2Router01(UniswapRouter).swapTokensForExactTokens(
        gasFee,
        amountInMax,
        getPathForTokens(targetZRC20, gasZRC20),
        address(this),
        block.timestamp + MAX_DEADLINE
    );

    require(IZRC20(gasZRC20).balanceOf(address(this)) >= gasFee, "INSUFFICIENT_GAS_FOR_WITHDRAW");
    require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");

    IZRC20(gasZRC20).approve(address(gateway), gasFee);
    IZRC20(targetZRC20).approve(address(gateway), targetAmount - amounts[0]);

    amountsOut = targetAmount - amounts[0];
}
```

The swap path is determined by:

```solidity
function getPathForTokens(address zrc20, address targetZRC20) internal view returns (address[] memory path) {
    bool existsPairPool = _existsPairPool(UniswapFactory, zrc20, targetZRC20);

    if (existsPairPool) {
        path = new address[](2);
        path ;
        path[0] = zrc20;
        path[1] = WZETA;
        path[2] = targetZRC20;
    }
}
```

If no direct ZRC20 -> GAS ZRC20 pair exists, `WZETA` is inserted in the middle. This enables a user to manipulate the system by creating a pool with an intentionally skewed reserve ratio, making the input requirement for `swapTokensForExactTokens` deceptively low:

```solidity
function getAmountIn(uint256 amountOut, uint256 reserveIn, uint256 reserveOut)
    internal
    pure
    returns (uint256 amountIn)
{
    require(amountOut > 0, "UniswapV2Library: INSUFFICIENT_OUTPUT_AMOUNT");
    require(reserveIn > 0 && reserveOut > 0, "UniswapV2Library: INSUFFICIENT_LIQUIDITY");

     // 2 * 1e18 = 2e18
     // denom = (3e18) - 1e18 = 2e18
     // amountIn = (2e18 / 2e18) + 1 = 2

    uint256 numerator = reserveIn.mul(amountOut).mul(1000);
    uint256 denominator = reserveOut.sub(amountOut).mul(997);
    amountIn = (numerator / denominator).add(1);
}
```

### Root Cause

In `getPathForTokens`, the system allows arbitrary pool usage, including malicious pools designed to minimize `amountIn`, allowing users to drain gas token refunds.

### Internal Pre-conditions

1. A refund must be pending in the gas token (gasZRC20).

### External Pre-conditions

1. No direct path exists from tokenIn to gasZRC20.

### Attack Path

1. Alice's transaction reverts, and gasZRC20 tokens are refunded to the contract.
2. Bob creates a malicious pool with high `reserveOut` and low `reserveIn`, making `getAmountIn` return an unrealistically small input requirement.
3. Bob executes `_swapAndSendERC20Tokens` using only a minimal input from his token.
4. The system checks only for balance of `gasZRC20`, not the legitimacy of the swap source.
5. Bob's gas is covered at Alice’s expense.
6. Alice attempts to claim a refund and fails due to insufficient balance.

### Impact

1. Refunded gas tokens can be drained by malicious users.
2. Contract becomes insolvent for legitimate refund claims.

*No response*

### Mitigation

Restrict swap paths to only pre-determined pools with sufficient liquidity to prevent manipulation through custom pool creation.
