# Potential Underpayment Due to Misuse of amountInMax Instead of Actual Swap Amount

## Description
function withdrawToNativeChain and function onCall which calls  internal function _handleEvmOrSolanaWithdraw that also calls another internal  function _swapAndSendERC20Tokens which has an issue.

The problem arises in the function _swapAndSendERC20Tokens, it incorrectly checks if enough targetZRC20 tokens remain after the swap by comparing targetAmout - amountInMax, instead of using the actual amount spent (amounts[0]), which can to underpayment
```solidity
require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
This line intends to ensure that there are enough targetZRC20 tokens left after the swap to send to the destination. However, it mistakenly assumes that amountInMax is the amount actually spent during the swap.

 Impact
Underpayment Risk

## Recommendation
Replace the incorrect check that uses amountInMax with the actual amount of targetZRC20 tokens spent in the swap:
```solidity
require(targetAmount > amounts[0], "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
```
