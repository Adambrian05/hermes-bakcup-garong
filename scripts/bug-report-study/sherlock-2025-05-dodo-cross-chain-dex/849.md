# `_handleFeeTransfer` does not handle fees for Native currency

### Summary

The `_handleFeeTransfer` function uses `TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx)` , which assumes the token being transferred is an ERC20/ZRC20 token.

However, for true native tokens (like ETH on Ethereum), this approach won't work because Native tokens require different handling.

### Root Cause

In the `_handleFeeTransfer` function is no approach to handle native token fee
[https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L341](url)

### Internal Pre-conditions

1. A transaction must involve actual native tokens
2. The contract must attempt to call `TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx)` where zrc20 represents a native token
3. This will fail because native tokens don't have a contract address that supports the transfer() function

### Impact

1. When the contract attempts to collect fees from true native tokens (like unwrapped ZETA), the TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx) call will fail because native tokens don't have a contract address that supports the transfer() function. This will cause the entire transaction to revert.
2. Users attempting to transfer native tokens will experience failed transactions, leading to:  Gas fees paid for failed transactions
Inability to complete intended transfers
