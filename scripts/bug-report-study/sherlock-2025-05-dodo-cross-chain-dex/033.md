# ETH Refunds Always Fail Due to Incorrect Transfer Function Usage in `onRevert`

### Summary

Using `TransferHelper.safeTransfer` instead of `TransferHelper.safeTransferETH` for ETH assets will cause a permanent fund loss for users as failed cross-chain ETH transactions will be unable to refund users when the revert mechanism is triggered.

### Root Cause

In [GatewaySend.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404) the `onRevert` function uses `TransferHelper.safeTransfer(context.asset, sender, context.amount)` for all assets including ETH, which fails because `safeTransfer` attempts to call the ERC20 `transfer(address,uint256)` function on the ETH placeholder address `0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE`, causing the transaction to revert with "TransferHelper: TRANSFER_FAILED".

```solidity

function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));
    
    //  @audit : Uses safeTransfer for ALL assets (including ETH)
    TransferHelper.safeTransfer(context.asset, sender, context.amount);
    
    emit EddyCrossChainRevert(
        externalId,
        context.asset,
        context.amount,
        sender
    );
}
```

### Internal Pre-conditions

1. User needs to initiate a cross-chain transaction involving ETH using `depositAndCall` 
2. The cross-chain transaction needs to fail on the destination chain or during processing
3. Gateway needs to call `onRevert` to refund the user


### External Pre-conditions

none

### Attack Path

1. User calls `GatewaySend.depositAndCall` with ETH (msg.value > 0, asset = `_ETH_ADDRESS_`)
2. Cross-chain transaction is initiated and ETH is locked in the contract
3. Transaction fails on destination chain or during gateway processing
4. Gateway attempts to call `onRevert` with `context.asset = _ETH_ADDRESS_`
5. `onRevert` calls `TransferHelper.safeTransfer(_ETH_ADDRESS_, sender, context.amount)`
6. `safeTransfer` attempts to call `_ETH_ADDRESS_.call(abi.encodeWithSelector(0xa9059cbb, sender, amount))`
7. Call fails because `_ETH_ADDRESS_` is not a real contract address
8. Transaction reverts with "TransferHelper: TRANSFER_FAILED"
9. User's ETH remains permanently locked in the contract

### Impact

Users suffer a 100% loss of their ETH when cross-chain transactions fail and need to be reverted. The ETH becomes permanently locked in the contract as the refund mechanism is completely broken for ETH assets.
