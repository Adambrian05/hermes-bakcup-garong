# Incorrect revertMessage for GatewayCrossChain and GatewayTransferNative

### Summary

The revertMessage of GatewayCrossChain and GatewayTransferNative incorrectly used the address on the target chain as the refund recipient, which may cause the refund to be unable to be collected.

### Root Cause

In [GatewayTransferNative.sol#L274](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L274-L275) and [GatewayCrossChain.sol#L265](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L265-L266), they use the address on the target chain as the refund recipient.
```solidity
                revertMessage: bytes.concat(externalId, receiver),
```
Once the transaction on the target chain is reverted, the onRevert() function on ZetaChain will be called.
```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        bytes memory walletAddress = context.revertMessage[32:];
```
Since the address on the target chain is used as the refund recipient in RefundInfo, when the target chain is bitcoin or solona, ​​the address is invalid on ZetaChain, resulting in the user being unable to receive the refund.
```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
```

### Mitigation

For GatewayTransferNative, use msg.sender directly as the refund recipient.
For GatewayCrossChain, since the sender is on the source chain, it is recommended to include the ZetaChain address in the source chain message and use it as the refund recipient
