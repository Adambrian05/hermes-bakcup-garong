# Lack of Adequate Slippage Protection in Cross-Chain Swap Function

## Description
The `GatewaySend` contract has a serious issue regarding the lack of adequate slippage protection mechanism in the cross-chain swap function. The contract only relies on the `minReturnAmount` parameter provided by the user without any additional validation or implementation of slippage protection at the contract level. This makes users very vulnerable to financial losses due to uncontrolled slippage, especially in volatile market conditions or MEV (Maximal Extractable Value) attacks.

## Code Snippet
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L202-L215

## Root Cause
The root of the problem lies in the implementation of the `_doMixSwap` function which lacks a slippage protection validation mechanism.
```solidity
function _doMixSwap(bytes calldata swapData) internal returns (uint256) {
    // Decode the compressed swap data into MixSwapParams parameters
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);

    // Check if the input token is not ETH
    if(params.fromToken != _ETH_ADDRESS_) {
        // If not ETH, approve DODO to use tokens
        IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
    }

    // ❌ ISSUE: No additional slippage protection validation
    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
        params.fromToken,        
        params.toToken,          
        params.fromTokenAmount,  
        params.expReturnAmount,  
        params.minReturnAmount,  // ❌ Only rely on user parameters
        params.mixAdapters,      
        params.mixPairs,         
        params.assetTo,          
        params.directions,       
        params.moreInfo,         
        params.feeData,          
        params.deadline          
    );
}
```
The root of the problem is that the contract does not validate whether the `minReturnAmount` value is reasonable or even if it can be 0. The contract does not limit the maximum percentage of slippage allowed and there is no comparison with real-time market prices. All protection parameters are completely dependent on user input.

## Impact
Users can lose a large portion of their asset value due to uncontrolled slippage.

## Scenario
1. User initiates a cross-chain swap from Ethereum to BSC when the token price is stable
2. `expReturnAmount` is calculated based on the current price, `minReturnAmount` is set 5% below expected
3. During the cross-chain process (5-10 minutes), a 15% market crash occurs
4. The swap is executed at a price that has dropped drastically
5. User receives 15% less tokens, even though the transaction should be canceled if slippage > 10%

## Recommendation
Implement slippage protection at the contract level.
```solidity
// Add state variables for slippage configuration
uint256 public maxSlippagePercent = 500; // 5% in basis points
uint256 public constant MAX_SLIPPAGE_CAP = 1000; // 10% maximum

// Function to set max slippage (owner only)
function setMaxSlippagePercent(uint256 _maxSlippagePercent) external onlyOwner {
    require(_maxSlippagePercent <= MAX_SLIPPAGE_CAP, "SLIPPAGE_TOO_HIGH");
    maxSlippagePercent = _maxSlippagePercent;
}
```
