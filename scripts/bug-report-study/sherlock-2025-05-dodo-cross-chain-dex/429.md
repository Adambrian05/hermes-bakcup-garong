# Calling `depositAndCall` in `GatewaySend` by deposit ETH with different amount of msg.value and amount will cause loss of user's funds.

### Summary

When calling `depositAndCall` function in `GatewaySend` contract to deposit ETH and especially setting the `amount` is different from `msg.value` will cause loss of funds.


### Root Cause

[GatewaySend.sol:308-314](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L308C13-L314C15)


```solidity
require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
            _handleETHDeposit(
                targetContract, 
                msg.value,
                message, 
                revertOptions
            );
```

In this code, it checks that `msg.value` is greater than `amount` and call `_handleETHDeposit` internal function by passing `msg.value` as amount.
When user is calling this function by providing `msg.value` as greater than `amount`, in this case user's intention is swap only `amount` passed by parameter.
But calling `_handleETHDeposit` function with `msg.value` parameter will swap all of `msg.value` not the `amount`.
It will cause loss of user's funds.

### Internal Pre-conditions

User call `depositAndCall` function from `GatewaySend` contract to deposit ETH with setting different `value` and `amount`.


### External Pre-conditions

No external condition is needed.

### Attack Path

1. `depositAndCall` function calls `_handleETHDeposit` with `msg.value` which is greater than `amount` (user's actual intention).
2. In `_handleETHDeposit` it calls ZetaChain's gateway contract's depositAndCall with `msg.value`.
3. Gateway's depositAndCall method will lock ETH `msg.value` and mint corresponding ZRC20 token.
4. Finally, user's unable to access ETH amount as `msg.value-amount'.

### Impact

Impact: Medium
This will cause loss of portion of user's funds.
Likelihood: Medium
This loss of user's funds occur when setting the great msg.value than amount and deposit native ETH.
Severity: Medium

Add this test code into `GatewaySend.t.sol`.
As explained above, when setting `msg.value` and `amount` as different when deposit ETH, it will cause loss of user's funds exactly `msg.value-amount`

### Mitigation

It should return the rest amount of `msg.value` when it is greater than `amount`.
```solidity
if (msg.value > amount) {
                payable(msg.sender).transfer(msg.value - amount);
            }
```
