# It is impossible to prevent attackers from claiming a non-existent `externalId`.

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L579
The incorrect type comparison in the claimRefund() function causes a missing refund existence check, allowing an attacker to call claimRefund() with forged externalId values and potentially claim unauthorized refunds or exploit uninitialized storage slots, leading to a loss of funds for users.

### Root Cause

 the following line performs an invalid comparison between a bytes32 value and an empty string:
```solidity
require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
```
Since externalId is a bytes32 value and "" is a dynamic string (compiled as bytes), the condition is always true and does not serve as a valid existence check. As a result, the function will continue executing even if refundInfo is uninitialized.

### Mitigation

Replace the invalid type comparison with a valid existence check:
```solidity
require(refundInfo.amount > 0, "REFUND_NOT_EXIST");
```
