# GatewaySend::depositAndCall() lacks validation.






## Summary

GatewaySend::depositAndCall() lacks validation, allowing attackers to exploit this function to steal funds from the GatewaySend contract.

The root cause of the issue is that the depositAndCall function does not verify the relationship between the input amount (user-specified funds) and the actual funds used for MixSwap transactions.  

This allows attackers to exploit the vulnerability and steal funds from the contract.  
For example, an attacker could set the amount to **1 wei** while manipulating the actual transaction to siphon out much larger amounts.

But the `fromTokenAmount` can be set to an extremely large value (e.g., the total token balance of the contract), causing `mixSwap` to convert all the contract's tokens into `toToken`.  

This allows an attacker to use `depositAndCall` to drain all the tokens from the contract.
