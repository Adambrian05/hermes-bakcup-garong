# Malicious receiver will seize every refund from failed cross-chain swaps, draining the original payer

### Summary

Hard-coding `decoded.receiver` into the `revertMessage` means any failure on the destination chain returns funds to that receiver, not the caller of `withdrawToNativeChain`. Consequently, a dishonest or mis-typed receiver can collect the entire refund while the ZetaChain payer is left uncompensated as the contract blindly routes the refund to whichever address it embedded.

---

### Root Cause

In **`GatewayTransferNative.sol`** the contract concatenates the receiver address—not the payer—into the revert payload, and later pays that address back:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286

```solidity
//   Building the revert message
withdraw(
    externalId,
    decoded.receiver,           // <-- writes receiver
    decoded.targetZRC20,
    outputAmount - gasFee
);

// onRevert pays whoever is in revertMessage[32:]
bytes32 externalId = bytes32(context.revertMessage[0:32]);
bytes memory walletAddress = context.revertMessage[32:];
address receiver = address(uint160(bytes20(walletAddress)));
TransferHelper.safeTransfer(context.asset, receiver, context.amount);

//  claimRefund enforces the same rule
require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
```

Because the sender’s address is never stored, the contract cannot reimburse the true payer once the transaction reverts.

---

### Internal Pre-conditions

1. **User (payer)** calls `withdrawToNativeChain`, supplying
   `[decoded.receiver] = attacker-controlled EVM address`.
2. Contract deducts the platform fee and pushes the cross-chain request.
3. Destination chain swap **reverts** or **aborts**, invoking `onRevert` / `onAbort`.
4. `revertMessage` still contains `decoded.receiver` chosen in step 1.

### External Pre-conditions

N/A

---

### Attack Path

1. Attacker persuades or tricks a payer into setting the attacker’s address as the receiver (e.g., “Please bridge 1 ETH to me on chain X”).
2. Payer calls `withdrawToNativeChain`, paying 1 ETH + gas/fees.
3. Swap on the destination chain fails (slippage, liquidity, or deliberate sabotage).
4. Gateway calls `onRevert`; contract transfers the full refund to the attacker address embedded in `revertMessage`.
5. Payer cannot reclaim the funds; only the attacker (or an authorized bot) can call `claimRefund` if the fast path did not fire.

---

### Impact

* **Affected party:** ZetaChain payer / bridge user
* **Estimated loss:** Up to **100 % of the bridged value** per failed transaction, plus unrecovered platform fees.
* **Attacker gain:** Same amount (less minuscule gas costs); attacker bears no risk.

---

### Mitigation

* **Encode the true payer:** Replace `decoded.receiver` with `bytes20(msg.sender)` when building `revertMessage`, or store the payer in a mapping keyed by `externalId`.
