# Unconstrained Cross-Chain Withdrawal Vulnerability

### Summary

The `withdrawAndCall` function allows cross-chain withdrawals without proper amount validation or state tracking, enabling potential fund draining through replay attacks.

```solidity
function withdrawAndCall(
    bytes32 externalId,
    bytes memory contractAddress,
    address targetZRC20,
    uint256 outputAmount,
    bytes memory receiver,
    bytes memory message
) internal {
    gateway.withdrawAndCall(
        contractAddress,
        outputAmount,
        targetZRC20,
        message,
        CallOptions({...}),
        RevertOptions({...})
    );
}
```

### Root Cause

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244C4-L270C1

- No validation of withdrawal amounts against user balances
- Missing withdrawal limits and rate limiting
- No tracking of cumulative withdrawals
- Implicit trust in external parameters

### Internal Pre-conditions

- Contract must have sufficient balance
- Valid targetZRC20 token
- Caller has appropriate permissions
- No withdrawal cooldown active

### External Pre-conditions

- Gateway contract is operational
- Cross-chain messaging system functional
- Target chain is accessible
- Gas fees available for cross-chain tx
