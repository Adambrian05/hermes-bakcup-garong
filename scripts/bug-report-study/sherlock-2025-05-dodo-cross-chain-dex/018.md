# Anyone can `claimRefund` in `GatewayCrossChain` and `GatewayTransferNative` when `refundInfo.walletAddress.length != 20`

### Summary

When `onRevert` or `onAbort`, `refundInfos` stores information for refunding.
But when `refundInfo.walletAddress.length != 20`, anyone can call `claimRefund` even though `msg.sender` is not `bot`

### Root Cause

[`GatewayTransferNative`.`onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L623-L636), [`GatewayTransferNative`.`onAbort`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L640-L659), [`GatewayCrossChain`.`onRevert`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L533-L546) and  [`GatewayCrossChain`.`onAbort`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L569) stores information for refunding.
In `onRevert`, when `context.revertMessage.length != 52`, it stores refunding information.
`externalId` is 32 bytes, so `walletAddress.length` is not `20` and this means `walletAddress` is not `address`
In `onAbort`, `bytes memory walletAddress = abortContext.revertMessage[32:];`, the case that `walletAddress.length != 20` can happen.

```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

@>      address receiver = msg.sender;
@>      if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
@>      require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];


        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```
`refundInfo.walletAddress.length != 20` and `receiver` is initialized as `msg.sender`, so it can bypass `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");`
Even though `msg.sender` is not `bot`, user can call `claimRefund` and malicious user can steal fund from `protocol`

### Attack Path

1. Attacker find out `externalId` that `refundInfo.walletAddress.length != 20` (`onRevert`, `onAbort` stores information)
2. Attacker calls `claimRefund` with `externalId`
He can steal funds from `protocol`.

### Impact

Attacker can steal funds from `protocol`.

### PoC

_No response_

### Mitigation

Doesn't initialize `receiver` as `msg.sender`.
```diff
-     address receiver = msg.sender;
+     address receiver;
      if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
      require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
```
