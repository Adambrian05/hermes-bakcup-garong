# `GatewayCrossChain::withdraw` sets `abortAddress` to `address(0)`, risking permanent fund loss.


### Summary
The `GatewayCrossChain.withdraw` function sets the `abortAddress` to `address(0)` within the `RevertOptions`. This configuration disables ZetaChain's `onAbort` fail-safe mechanism, in that if a withdraw of asset transfer fails on the external connect chain, `onAbort` will never be called, and funds will be lost.

### Root Cause
`GatewayCrossChain::withdraw` hardcodes `abortAddress: address(0)` as seen [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L290)

```solidity
// file: omni-chain-contracts/contracts/GatewayCrossChain.sol
function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) internal {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0), // @audit address(0)
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
By not specifying a valid abort address, the contract opts out of a crucial layer of ZetaChain's multi-layered error-handling design.

### Internal Pre-conditions

`GatewayCrossChain::onCall` is called, which calls `GatewayCrossChain::_handleBitcoinWithdraw`, which calls `GatewayCrossChain::withdraw` which succeeds.

### External Pre-conditions

Transaction broadcast fails due to network issues.

### Attack Path

1. A user initiates `GatewayCrossChain::onCall`, which calls `GatewayCrossChain::_handleBitcoinWithdraw` to withdraw BTC on BTC network. This transaction on ZetaChain succeeds.

2. The transfer of BTC on the BTC network fails due to Invalid Address set, Network, Nonce or Gas issues.

3. Since `GatewayZEVM::withdraw` is called, and failure occured on the external connected chain, `onRevert` will be skipped, and `onAbort` would be the final fail-safe.

4. However, since `abortAddress` was set to `address(0)` in `RevertOptions`, `onAbort` will not be triggered, and funds are lost
### Impact

Funds are lost when withdraw on external connected chain fails.

### PoC

Please refer to attack path.

### Mitigation

In `GatewayCrossChain::withdraw` 
```diff
// ...
RevertOptions({
    revertAddress: address(this),
    callOnRevert: true,
+    abortAddress: address(this), // Set to a valid recovery address
-    abortAddress: address(0),
    revertMessage: bytes.concat(externalId, bytes20(sender)),
    onRevertGasLimit: gasLimit
})
// ...
```
