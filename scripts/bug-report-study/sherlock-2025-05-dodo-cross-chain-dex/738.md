# Unbounded Message Slicing in onCall prone to out-of-bounds error

## Description
The issue lies in the in the function onCall, the code slices the message parameter to extract externalId and _message: if the message length is less than 32 bytes, the slicing operation message [0:32] will cause out-of-bounds error.

In the onCall function, the following line slices the incoming message parameter:
```solidity
(bytes32 externalId) = abi.decode(message[0:32], (bytes32));
```
This operation assumes that message is at least 32 bytes long. However, if message.length < 32, this will trigger an out-of-bounds slice error.

Similarly, the following line will also revert if message.length == 32
```solidity
bytes calldata _message = message[32:];
```

## Recommendation
Add a length check before slicing to ensure safe decoding:
```solidity
require(message.length >= 32, "onCall: message too short");
```
