# Users will lose funds permanently when Bitcoin withdrawals fail

### Summary

The `bytes20()` cast of Bitcoin addresses in revert message construction will cause permanent fund loss for users as failed Bitcoin withdrawal transactions will send refunds to uncontrolled EVM addresses derived from truncated Bitcoin addresses instead of user's own address.

### Root Cause

In [GatewayCrossChain.sol:362](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L363-L377) the `_handleBitcoinWithdraw()` function passes `decoded.receiver` (Bitcoin destination address) as the `sender` parameter to `withdraw()`:

```solidity
function _handleBitcoinWithdraw(
    bytes32 externalId, 
    DecodedMessage memory decoded, 
    uint256 outputAmount,
    uint256 gasFee
) internal {
    if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
    IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
    withdraw(
        externalId, 
        decoded.receiver,  // ❌ Bitcoin address passed as "sender" parameter
        decoded.targetZRC20, 
        outputAmount - gasFee
    );
}
```

In [GatewayCrossChain.sol:289](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L277-L295) the `withdraw()` function creates revert messages using `bytes.concat(externalId, bytes20(sender))` which truncates Bitcoin addresses from ~42 bytes to 20 bytes:

```solidity
function withdraw(
    bytes32 externalId,
    bytes memory sender,  // ❌ Misleading name - actually Bitcoin destination address
    address outputToken,
    uint256 amount
) internal {
    gateway.withdraw(
        sender,
        amount,
        outputToken,
        RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: address(0),
            revertMessage: bytes.concat(externalId, bytes20(sender)), // ❌ BUG: Truncates Bitcoin address
            onRevertGasLimit: gasLimit
        })
    );
}
```

When [onRevert()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L522-L524) is called, the truncated address creates a valid but not the users own EVM address:

```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    bytes memory walletAddress = context.revertMessage[32:];

    if(context.revertMessage.length == 52) {  // 32 bytes externalId + 20 bytes truncated address
        address receiver = address(uint160(bytes20(walletAddress)));  // ❌ Uncontrolled address!
        TransferHelper.safeTransfer(context.asset, receiver, context.amount);
        // ❌ Funds permanently lost to address user doesn't control
    }
}
```

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. `onCall` is triggered by the gateway
2. Function calls `_handleBitcoinWithdraw()` which internally calls `withdraw(externalId, decoded.receiver, targetZRC20, amount)`
3. `withdraw()` function creates revert message: `bytes.concat(externalId, bytes20(decoded.receiver))` where `decoded.receiver` is a Bitcoin address that gets truncated to 20 bytes
4. Bitcoin transaction fails due to any normal network/protocol issue
5. `onRevert()` gets called with revert message containing truncated Bitcoin address
6. Since `revertMessage.length == 52`, funds are sent directly to the uncontrolled truncated address

### Impact

Users suffer 100% loss of their funds when cross-chain transactions with Bitcoin as destination fail. The funds are permanently lost as they are sent to EVM addresses derived from Bitcoin addresses that users do not control and cannot access. This affects every cross-chain transaction to Bitcoin that fails for any reason during normal protocol operations.

### Mitigation

Fix the revert message construction in `_handleBitcoinWithdraw()` to use the actual user's address instead of Bitcoin destination address
