# GatewayCrossChain and GatewayTransferNative do not set abortAddress

### Summary

According to the documentation, abort of transactions initiated by ZetaChain will happen on ZeatChain, so GatewayCrossChain and GatewayTransferNative should set abortAddress to address(this) instead of address(0)

### Root Cause

According to the [documentation](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions), abort of a transaction initiated by ZetaChain will occur on ZeatChain instead of the target chain.

> Flow:

> A universal contract on ZetaChain initiates a call to a connected chain via withdrawAndCall or call.
The Gateway forwards the message and/or tokens to the target contract on the connected chain.
If the target contract reverts, ZetaChain initiates the revert process.
Revert Behavior:

> If callOnRevert is true:

> The Gateway invokes the onRevert function on the revertAddress on ZetaChain.
The remaining ZRC-20 tokens are passed along with the revert context.
If the onRevert call itself reverts, the Gateway transfers ZRC-20 tokens to and calls onAbort on the abortAddress on ZetaChain.

Since [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L264-L265) and [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L273-L274) set abortAddress to address(0), the refund cannot be processed correctly when the abort occurs, resulting in the user losing assets.
```solidity
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, receiver),
                onRevertGasLimit: gasLimit
            })
```
