# Missing Bounds Check in SwapDataHelperLib.decodeCompressedMixSwapParams

__Summary:__ The `decodeCompressedMixSwapParams` function in `SwapDataHelperLib.sol` fails to perform bounds checks when reading fixed-size fields and variable-length data lengths using assembly. This allows attackers to craft input data that causes out-of-bounds reads, leading to incorrect parameter decoding and potential fund loss.

__Vulnerability Detail:__ The function parses a packed byte array (`data`) using an increasing `offset`. It uses `calldataload` to read fixed-size values (addresses, uint256) and length prefixes (uint8, uint16) for variable-length data (arrays, bytes). Before performing a `calldataload` at `add(data.offset, offset)`, the code does not verify that `offset` plus the size of the data being read is less than `data.length`. Attackers can provide truncated data or manipulate internal length fields in cross-chain messages to trigger these out-of-bounds reads when the message is processed by `GatewayCrossChain` or `GatewayTransferNative`.

__Impact:__ Reading beyond the actual data boundary will result in zero values being loaded for the affected parameters in the `MixSwapParams` struct. If these incorrectly decoded parameters (e.g., zero addresses for tokens or pairs, zero amounts) are subsequently used in critical operations like token swaps or transfers, it can lead to unintended behavior, transaction failures, or direct loss of user funds (e.g., tokens sent to the zero address).

__Code Snippet:__
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/libraries/SwapDataHelperLib.sol#L144

__Recommendation:__ Before each `calldataload` operation in the assembly blocks and before reading length prefixes (uint8/uint16) in the loops, add explicit checks to ensure that the current `offset` plus the size of the data being read does not exceed `data.length`.
