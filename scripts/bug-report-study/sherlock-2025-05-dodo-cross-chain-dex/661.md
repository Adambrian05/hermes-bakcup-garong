Clumsy Raisin Viper

Medium

# a malicious address can override a user refundInfo

### Summary

in the onAbort and onRevert functions, the zevm contracts attempts to store the remaining token amount under the original sender external id so that they can claim later 
but there is one crucial vulnerability, here and that is external Ids can override each other 
this means an attacker can craft a revert message from a contract totally not in the dodo system that has the same external id as another user and hence override the users refund claim 

### Root Cause

there isnt a check to confirm that there isnt data already at refundInfos before setting storage 

### Internal Pre-conditions

none 

### External Pre-conditions

none

### Attack Path

normal user 
1. alice triggers withdraw to solana on GatewayTransferNative 
2.  the call reverts on solana 
3. alice refund data is stored with her external data on onRevert 

attacker 
1. bob sends a random call to any chain from any contract on zetachain , setting onRevert address to the GatewayTransferNative and encoding the revert message as alice external id and any random bytes that is more than 20 bytes 
2. bobs call reverts and triggers onRevert on GatewayTransferNative 
result :
because the external id submitted by bob is the same as alice , it would override hers and hence she would lose all her funds 

### Impact

permanent loss of funds for users
