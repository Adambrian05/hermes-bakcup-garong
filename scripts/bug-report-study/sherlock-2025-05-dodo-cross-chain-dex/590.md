# Excessive token approval in `GatewayCrossChain.sol` and `GatewayTransferNative.sol`

## Finding description and impact

The `_handleBitcoinWithdraw` function approves `outputAmount + gasFee` for the gateway. But the actual withdrawal only uses `outputAmount - gasFee`.

This leads to an over-approval of `gasFee * 2`.

## code snippet : https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L370

## Potential impacts:

* Tokens approved beyond what’s needed may be misused if the gateway is compromised or behaves unexpectedly
* Allowances persist across transactions, accumulating over time which Increases the attack surface for token draining issues

This violates the principle of least privilege.

## Mitigation

Approve only the amount actually used:

* If `withdraw` handles the gas fee separately:

  ```solidity
  IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount - gasFee);
  ```

* If `gateway` deducts gas fee internally:

  ```solidity
  IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
  ```

Review how gas fee is handled inside `withdraw` or `gateway` and approve accordingly.
