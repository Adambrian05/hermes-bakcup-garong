# Unrestricted access to `withdraw` function

## Finding description and impact

The `withdraw` function is marked as `public` and lacks access control or input validation.

## code snippet: https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L280-L304

### Any external caller can:

* Trigger withdrawals on behalf of any `sender`
* Use arbitrary values for `amount` and `outputToken`

## Potential impacts:

* Unauthorized withdrawals
* Incorrect token routing or value loss
* Increased risk if gateway contract trusts this input

## Mitigation

Add the following input checks:

```solidity
require(amount > 0, "Amount must be greater than zero");
require(outputToken != address(0), "Invalid output token");
require(sender.length == 20, "Invalid sender address length");
```

Restrict access to trusted contracts or roles using a modifier like `onlyOwner`, `onlyGateway`, or a custom role-based check.

```solidity
modifier onlyTrusted() {
    require(msg.sender == address(gateway), "Unauthorized caller");
    _;
}

function withdraw(...) public onlyTrusted { ... }
```

Verify `sender` matches expected user identities and prevent arbitrary withdrawal triggers.
