# Any user can lock or short-pay Bitcoin withdrawals, stripping funds from withdrawers

### Summary

A missing token-denomination check will cause **an incorrect fee arithmetic** for Bitcoin withdrawals, locking or under-delivering funds for withdrawers, as *any caller* triggers a cross-chain transfer in which the contract subtracts a gas fee that is actually denominated in a **different ZRC-20**.

### Root Cause

In `GatewayCrossChain.sol`(the gas-fee value returned by `withdrawGasFee()` (denominated in `gasZRC20`) is added to / subtracted from the withdrawal amount that is denominated in `decoded.targetZRC20` **without verifying the two tokens match**:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L469

```solidity
(address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee(); // gasFee is in gasZRC20
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);      // ❌ mixed units
withdraw(externalId, decoded.receiver, decoded.targetZRC20, outputAmount - gasFee); // ❌ mixed units
```

### Internal Pre-conditions

1. \[Caller triggers X-chain swap] `decoded.dstChainId` must equal `BITCOIN_EDDY`.

### External Pre-conditions
NA

### Path

1. User requests a cross-chain swap/withdraw of `TokenX-ZRC20` to a Bitcoin address.
2. `onCall` decodes the message, routes to `_handleBitcoinWithdraw`.
3. Contract fetches `(gasZRC20, gasFee)` but **discards** `gasZRC20`.
4. Contract approves `outputAmount + gasFee` of **TokenX** to the Gateway, even though `gasFee` is priced in **gasZRC20**.
5. Contract calls `withdraw` with `outputAmount - gasFee` (still mixing units).
6. Result:

   * If `gasFee` > `outputAmount`, call reverts (`NotEnoughToPayGasFee` ⇒ user’s swap already executed, funds now trapped in contract).
   * Else, Gateway receives wrong approvals/amounts, potentially finalising a withdrawal short by `gasFee` units of `TokenX` or reverting later and trapping funds.

### Impact

The **withdrawer** can lose up to **100 % of the attempted withdrawal** (all `outputAmount`) which remains stranded in `GatewayCrossChain`; no one gains the value, but it is effectively frozen until an admin rescue.

### Mitigation

* Mirror the safeguard already used for EVM/Solana:

```solidity
(address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
if (gasZRC20 != decoded.targetZRC20) {
    // swap or revert – same logic as _handleEvmOrSolanaWithdraw
}
```
