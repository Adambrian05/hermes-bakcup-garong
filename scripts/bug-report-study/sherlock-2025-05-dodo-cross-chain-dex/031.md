# User refund can be lost in `GatewayCrossChain` if receiver is a multisig wallet

### Summary

If a transaction is aborted or reverted in the `GatewayCrossChain` contract, a user is eligible for a refund. For evm addresses, the msg.sender must the original receiver from the revert message. A problem arises if the receiving address is a multisig as they can have different addresses across different chains.

### Root Cause

When we look in `claimRefund` if the wallet address in the refund info is an evm address, the msg.sender must be the receiver in the revert message. This receiver is defined in `RevertOptions`when making a withdraw and call.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L265
If a multisig initiated the call on ETH mainnet for example, and they wish to receive their funds on another chain, this address could be different. If the call were to revert and the refund info is updated with the address on the other chain, it could be different than the users address on Zeta chain because they use a multisig wallet  and this call would fail
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L578


### Internal Pre-conditions

1. User is able to initiate a cross chain call through DODO

### External Pre-conditions

1. Gateway is up and running

### Attack Path

1. a multisig calls `depositAndCall` wishing to send funds to another chain
2. They pass a receiver in the message
3. Call from the `GatewayCrossChain` contract to the gateway reverts or aborts
4. User is eligible for a refund from the evm wallet they defined in the message 
5. Their address is different on Zeta chain becayse they use a multisig wallet
6. They will be unable to call `claimRefund`

### Impact

Loss of funds to users initiating calls from a multisig

### PoC

_No response_

### Mitigation

Allow user to define the address they wish to receive the refund if needed
