# Missing function to change the gasLimit in GatewayCrossChain

### Summary

Once set in the `initialize` function, the gasLimit of the `GatewayCrossChain` cannot be updated, since there’s no setter function.

### Root Cause

Missing setter function for the `gasLimit` in `GatewayCrossChain` contract.

It can be set only from the `initialize`:

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L125

```solidity
    function initialize(
        address payable _gateway,
        address _EddyTreasurySafe,
        address _dodoRouteProxy,
        address _dodoApprove,
        uint256 _feePercent,
        uint256 _slippage,
        uint256 _gasLimit
    ) public initializer {
        __Ownable_init(msg.sender);
        __UUPSUpgradeable_init();
        gateway = GatewayZEVM(_gateway);
        EddyTreasurySafe = _EddyTreasurySafe;
        DODORouteProxy = _dodoRouteProxy;
        DODOApprove = _dodoApprove;
        feePercent = _feePercent;
        slippage = _slippage;
        gasLimit = _gasLimit;
    }
```

### Internal Pre-conditions

None

### External Pre-conditions

Reason to update the `gasLimit`.

### Attack Path

None. Permanently removes the ability to update the parameter. That can cause issues with users, overpaying for the gas when the total gas cost on the destination is being lowered by the Zeta team, or becoming insufficient if the destination execution requires more gas.

### Impact

Configuration malfunction.  The fact that both `GatewaySend` and `GatewayTransferNative` have setter functions indicates that there will be a need for modifications.

### PoC

N/A

### Mitigation

Add the following function:

```solidity
function setGasLimit(uint256 _gasLimit) external onlyOwner {
        gasLimit = _gasLimit;
    }

```
