# GatewayTransferNative Sets abortAddress to address(0) so funds from abort cctx will be lost.

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L299

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L551

Whenever  `withdrawToNativeChain` on  `GatewayTransferNative`  the contract will  the contract sets  the `abortAddress` `address(0)` when building the `RevertOptions`
```solidity
function withdraw(bytes32 externalId, bytes memory sender, address outputToken, uint256 amount) public {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```

this  can be very problematic because when a cctx abort zetachain  send the token  to the abortaddress 

below is a flow of a cctx from zetachain to a conntected  as explained in the zetachain docs  read more [here](https://www.zetachain.com/docs/developers/chains/zetachain/#revert-transactions)

**Flow:**

1. A universal contract on ZetaChain initiates a call to a connected chain via `withdrawAndCall` or `call`.
2. The Gateway forwards the message and/or tokens to the target contract on the connected chain.
3. If the target contract reverts, ZetaChain initiates the revert process.

**Revert Behavior:**

* If `callOnRevert` is `true`:

  * The Gateway invokes the `onRevert` function on the `revertAddress` on ZetaChain.
  * The remaining ZRC-20 tokens are passed along with the revert context.
  * If the `onRevert` call **itself reverts**, the Gateway transfers ZRC-20 tokens to and calls `onAbort` on the `abortAddress` on ZetaChain.

* If `callOnRevert` is `false`:

  * The Gateway transfers tokens to the `revertAddress` without invoking any function.

so the token will be sent to address(0) and lost forever.

### Root Cause

 In `GatewayTransferNative.sol`,  whenever `withdrawToNativeChain`   is called   the contract will  sets  the `abortAddress`   to `address(0)` when building the `RevertOptions` struct.

### Attack Path

1. User calls `withdrawToNativeChain`, the `withdrawAndCall` builds the `RevertOptions` struct with `abortAddress`  == `address(0)` 
 2.  the cctx transaction aborts 
 3. zeta chain  refund the token  to abortAddress which is address(0)
 4. token is lost forever

### Impact

 Users suffer lost of funds
### Note 
this issue exist in `GatewayCrossChain` too.
