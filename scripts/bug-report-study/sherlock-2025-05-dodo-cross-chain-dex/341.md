# `GatewayTransferNative.sol::onCall()` did not substract `platformFeesForTx` when`decoded.targetZRC20 != zrc20`

### Summary
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357C1-L423C6

The `onCall()` logic in `GatewayTransferNative` first calls `_handleFeeTransfer()` to transfer `platformFeesForTx` to `EddyTreasurySafe`. So, the actual zrc20 token amount now in the contract is `amount-platformFeesForTx`. This number is used in the first bracket of if condition, but forget to substract the `platformFeesForTx` in the swap on DODO Router (`uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);`).

As a result, the transaction will revert when the amount of token in the contract is less than `platformFeesForTx`, or the contract will tranfer more token to receiver than expected when the amount of token in the contract is greater than `platformFeesForTx`, causing a loss of funds.


### Root Cause

`GatewayTransferNative` is a `UniversalContract` that is deployed in zetachain to receive minted zrc20 token when the other chain's token/gas is transfered to zeta protocal, and `GatewayZEVM` will call `GatewayTransferNative::onCall()` to execute the specific logic on zetaChain, and the input `zrc20` and `amount` are exactly the information of the amount of a certain zrc20 token that is minted(see more in https://www.zetachain.com/docs/developers/evm/gateway/)

The `onCall()` logic in `GatewayTransferNative` first calls `_handleFeeTransfer()` to transfer `platformFeesForTx` to `EddyTreasurySafe`. So, the actual zrc20 token amount now in the contract is `amount-platformFeesForTx`. This number is correctly calculated in the first bracket, but it does not substract the `platformFeesForTx` in the swap on DODO Router (`uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);`)



### Internal Pre-conditions

None

### External Pre-conditions

When the `decoded.targetZRC20 != zrc20`

### Attack Path

The user can use this vulnerability to bypass the deduction of `platformFeesForTx` as long as there are enough relavent zrc20 token left in the contract.

### Impact

If no swap is needed, `_doMixSwap()` will return the original amount without substracting the `platformFeesForTx`. Or approve more amount than expected for DODOrouter to swap when the swapData is not empty.

The user can exploit this vulnerability to bypass the deduction of `platformFeesForTx` as long as there are enough relavent zrc20 token left in the contract due to `onRevert/onAbort`. Otherwise most transaction will revert due to lack of enought fund.
