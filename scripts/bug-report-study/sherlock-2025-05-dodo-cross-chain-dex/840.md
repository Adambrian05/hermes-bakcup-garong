# onRevert will always revert when refunding native ETH or native Zeta (gasToken), locking user funds

### Summary

Calling TransferHelper.safeTransfer on a native‐ETH refund (context.asset == address(0)) will revert, because safeTransfer assumes an ERC-20 token and uses token.transfer(...).

### Root Cause

In onRevert(RevertContext), the code unconditionally does:

```solidity
TransferHelper.safeTransfer(context.asset, sender, context.amount);
```
If context.asset is the zero address (signifying native ETH), safeTransfer will attempt to call IERC20(0).transfer(sender, amount), which reverts. There is no separate handling for ETH.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L396


### Internal Pre-conditions

A cross-chain call reverts on a chain where the gas token is native ETH (so context.asset == address(0)).

The gateway invokes onRevert with context.amount of ETH to return.

### External Pre-conditions

None

### Attack Path

A cross-chain transaction fails after being sent with asset = address(0) (ETH).

The gateway calls onRevert with context.asset = 0x000…000.

onRevert does safeTransfer(0x00, sender, amount).

TransferHelper.safeTransfer tries IERC20(0).transfer(sender, amount) → revert.

The revert of onRevert leaves the user’s ETH locked in the gateway contract.

### Impact

All native-ETH refunds will fail and remain stuck in the contract, permanently preventing users from recovering their ETH.

### PoC

_No response_

### Mitigation

Branch on context.asset and handle ETH separately
