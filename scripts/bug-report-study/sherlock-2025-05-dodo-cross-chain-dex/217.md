# Any attacker will steal refund tokens from `GatewayTransferNative` users with failed cross-chain transactions to non-EVM chains

### Summary

Missing verification of original transaction initiator in `claimRefund` function will cause a complete loss of refund tokens for users with failed cross-chain transactions to non-EVM chains (esp. Solana).

### Root Cause

In `GatewayTransferNative.sol` the `claimRefund` function defaults the receiver to msg.sender for non-EVM wallet addresses (length != 20 bytes), making the authorization check `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER")` always pass since `msg.sender == receiver` becomes always true.

**Vulnerability Chain for Solana Destinations:**

**Step 1**: RevertMessage construction in [withdrawAndCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L270-L275)
```solidity
RevertOptions({
    revertAddress: address(this),
    callOnRevert: true,
    abortAddress: address(0),
    revertMessage: bytes.concat(externalId, receiver), // ← 32 + 32 = 64 bytes for Solana
    onRevertGasLimit: gasLimit
})
```

**Step 2**: Vulnerable path triggered in [onRevert()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L612-L630)
```solidity
if(context.revertMessage.length == 52) {
    // Protected: Direct transfer to EVM address (20 bytes)
    address receiver = address(uint160(bytes20(walletAddress)));
    TransferHelper.safeTransfer(context.asset, receiver, context.amount);
} else {
    // VULNERABLE: 64-byte Solana revertMessage goes here
    RefundInfo memory refundInfo = RefundInfo({
        externalId: externalId,
        token: context.asset,
        amount: context.amount,
        walletAddress: walletAddress // ← 32-byte Solana address stored
    });
    refundInfos[externalId] = refundInfo;
}
```

**Step 3**: Authorization bypass in [claimRefund()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661-L680)

```solidity
function claimRefund(bytes32 externalId) external {
    RefundInfo storage refundInfo = refundInfos[externalId];
    
    address receiver = msg.sender;  // ← Defaults to caller
    if(refundInfo.walletAddress.length == 20) {
        receiver = address(uint160(bytes20(refundInfo.walletAddress)));
    }
    // For Solana addresses (32 bytes), receiver remains as msg.sender
    
    require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
    // Always passes: attacker == attacker
}
```

Even though gateway contracts are deployed on EVM chains (ZetaChain, Ethereum, etc.), users can send transactions **TO** non-EVM destination chains. When targeting Solana, the destination address is 32 bytes, creating the vulnerability.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Attacker monitors the blockchain for `EddyCrossChainRefund` events emitted from onRevert()
2. Attacker extracts the `externalId` from the event (publicly visible parameter)
3. Attacker calls `claimRefund(externalId)` with the stolen externalId
4. The function sets `receiver = msg.sender` (attacker's address) since `walletAddress.length != 20`
5. The authorization check `require(bots[msg.sender] || msg.sender == receiver)` passes because `"attacker == attacker"`
6. Tokens are transferred to the attacker via `TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount)`
7. The RefundInfo is deleted, preventing the legitimate user from ever claiming their refund

### Impact

The legitimate users suffer a 100% loss of their refund tokens intended for failed cross-chain transactions to non-EVM chains. The attacker gains the full amount of tokens from each stolen refund with no cost except gas fees.

### Mitigation

Update `claimRefund` to verify against the original initiator
