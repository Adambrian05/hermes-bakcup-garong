# ETH Gets Trapped in Dodorouterproxy which should have been returned to the initial user

### Summary

The `GatewaySend.sol` contract contains a logical flaw where excess ETH sent by users can become trapped within the https://github.com/DODOEX/contractV2/blob/main/contracts/SmartRoute/proxies/DODOFeeRouteProxy.sol contract while calling the [depositandcall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L218)  and does not get refunded to the initial user. This occurs due to a mismatch between the validation logic for ETH deposits and the actual amount used in DODO swap operations. The contract validates that `msg.value >= amount` but forwards the entire `msg.value` to DODO's `mixSwap`, while DODO only uses the `params.fromTokenAmount` specified in the swap data.

In the other depositandcall where there is no swapping done all the msg.value is forwarded that is being bridged so that is not an issue, but up here the excess msg.value will be lost for the user. 

### Root Cause

The vulnerability stems from inconsistent ETH amount handling in the first `depositAndCall` function:

1. **Validation Logic**: The contract checks `msg.value >= amount` (line 234-237)
2. **Swap Execution**: The entire `msg.value` is forwarded to DODO's `mixSwap` (line 202)
3. **DODO Usage**: DODO only consumes `params.fromTokenAmount` from the swap data, not the full `msg.value`

### Attack Path

1. **User Calls depositAndCall**: User invokes the swap version of `depositAndCall` with:
   - `fromToken = 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE` (ETH)
   - `amount = 1 ETH`
   - `msg.value = 1 ETH`
   - `swapData` containing `params.fromTokenAmount = 0.8 ETH`

2. **Validation Passes**: The require statement passes because `1 ETH >= 1 ETH`

3. **Full msg.value Forwarded**: The `_doMixSwap` function forwards the entire `1 ETH` to DODO

4. **DODO Uses Partial Amount**: DODO's `mixSwap` only uses `0.8 ETH` for the swap operation

### Impact

user loses his excess eth which should have been returned to the initial user.

### Mitigation

Modify the `_doMixSwap` function to validate that `msg.value` exactly matches `params.fromTokenAmount` for ETH swaps:

```solidity
function _doMixSwap(bytes calldata swapData) internal returns (uint256) {
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);

    if(params.fromToken == _ETH_ADDRESS_) {
        require(msg.value == params.fromTokenAmount, "ETH amount mismatch with swap data");
    } else {
        IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
    }

    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount,
        params.expReturnAmount,
        params.minReturnAmount,
        params.mixAdapters,
        params.mixPairs,
        params.assetTo,
        params.directions,
        params.moreInfo,
        params.feeData,
        params.deadline
    );
}
```
