# NO refund mechanism when excess eth is sent

### Summary

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L307



In the `GatewaySend.sol::depositAndCall` function,when asset is ETH, excess ETH sent isn't refunded. The function checks msg.value >= amount but deposits the full msg.value to the gateway instead of amount. The function checks if the msg.value is >= the amount but still transafers msg.value instead of amount.

```javascript

   function depositAndCall(
        address targetContract,
        uint256 amount,
        address asset,
        uint32 dstChainId,
        bytes calldata payload
    ) public payable {
        globalNonce++;
        bytes32 externalId = _calcExternalId(msg.sender);
        bool isETH = (asset == _ETH_ADDRESS_);
        bytes memory message = concatBytes(externalId, payload);

        RevertOptions memory revertOptions = RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: targetContract,
            revertMessage: bytes.concat(externalId, bytes20(msg.sender)),
            onRevertGasLimit: gasLimit
        });

        if (isETH) {
            require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
            _handleETHDeposit(
                targetContract, 
                msg.value,
                message, 
                revertOptions
            );


```

if isEth is true and the msg.value is greater than the required amount, there is going to be no way to refund.

### Root Cause

The root cause is the contract uses msg.value instead of the amount

### Attack Path

2. but msg.value is 2 eth

### Impact

Users lose excess ETH sent with the transaction.
