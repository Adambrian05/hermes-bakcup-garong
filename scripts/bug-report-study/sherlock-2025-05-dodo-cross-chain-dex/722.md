# Reverts for some tokens for approve and transfers

### Summary

The codebase contains multiple instances of direct calls to ERC20 transfer(), transferFrom(), and approve() functions that expect boolean return values. However, USDT on Ethereum mainnet do not return boolean values from these functions, causing transactions to revert when the EVM attempts to decode non-existent return data.

### Root Cause

Its is stated in the ReadMe, the supported list of tokens to include USDT. But USDT doesn't return any bool for transfers or approvals which causes it to revert when trying to transfer or approve tokens.
Details for the project : For token supported, please refer to: https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets
Some instances - [1](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L239) , [2](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L317), [3](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L372)


### Impact

Can't transfer USDT to any chain. 


### Mitigation

Use safeApprove, safeTransfer and safeTransferFrom.
