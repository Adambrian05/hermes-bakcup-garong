# Use of .transfer() for ETH forwarding causes potential transaction reverts with complex recipient contracts

### Summary

The use of Solidity’s .transfer() function in onCall will cause transaction reverts for recipients that are contracts requiring more than 2300 gas to receive ETH. This results in failed ETH transfers and broken cross-chain message handling, impacting users sending ETH to such contracts as their received ETH never arrives and transactions revert.

### Root Cause

In onCall function, the code uses:

payable(evmWalletAddress).transfer(outputAmount);

The .transfer() method forwards a fixed stipend of 2300 gas, which is insufficient for recipient contracts with complex receive() or fallback() functions that require more gas. This limitation is well-known and often causes revert failures when sending ETH to certain smart contracts.



https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L370

### Internal Pre-conditions

The evmWalletAddress is a smart contract, not an externally owned account (EOA).

The recipient contract’s fallback or receive() function requires more than 2300 gas to execute.

### External Pre-conditions

None specific; applies to any deployed smart contract with fallback or receive functions that consume gas beyond 2300 (which is common in modern contracts).



### Attack Path

A cross-chain message triggers the onCall function with toToken == _ETH_ADDRESS_.

The function attempts to send ETH to evmWalletAddress using .transfer().

The recipient contract’s fallback function requires more gas than 2300, causing .transfer() to revert.

The entire onCall transaction reverts, failing to deliver the funds and execute subsequent logic.



### Impact

The protocol fails to deliver ETH to contract recipients, breaking user expectations and blocking ETH cross-chain transfers to a significant class of users (smart contracts).

### Mitigation

Replace:

payable(evmWalletAddress).transfer(outputAmount);
With:

(bool success, ) = evmWalletAddress.call{value: outputAmount}("");
require(success, "ETH_TRANSFER_FAILED");

This allows full gas forwarding (within remaining gas) and prevents unexpected reverts when interacting with contracts. Make sure to guard against reentrancy if additional logic follows this transfer.
