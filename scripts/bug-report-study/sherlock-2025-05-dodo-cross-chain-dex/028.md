# Protocol will fail all USDT deposits due to non-standard transferFrom implementation

### Summary

The use of direct `transferFrom()` calls without safe transfer wrappers will cause transaction failures for users as USDT on Ethereum mainnet does not return a boolean value from `transferFrom()`, causing `require()` statements to revert.

### Root Cause

In `GatewaySend.sol:238-241` and `GatewaySend.sol:316-319` the contract uses `require(IERC20(fromToken).transferFrom(...), "...")` which expects transferFrom() to return a boolean value, but USDT's transferFrom() implementation does not return any value.

https://etherscan.io/address/0xdac17f958d2ee523a2206206994597c13d831ec7#code

USDT is listed as a supported asset on ZetaChain documentation https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets and is used in the protocol.

### Attack Path

1. **User calls `GatewaySend::depositAndCall()` with USDT as the input token**
2. **The function reaches the require statement with `IERC20(fromToken).transferFrom(msg.sender, address(this), amount)`**
3. **USDT's transferFrom() executes successfully but returns no value**
4. **The require() statement expects a boolean return value but receives nothing**
5. **Transaction reverts with the error message, preventing USDT deposits**

### Impact

Users cannot deposit USDT tokens through the protocol, breaking core functionality for one of the major supported assets. This renders the cross-chain functionality unusable for USDT, which is a widely used stablecoin.

### Mitigation

Replace direct transferFrom() calls with `TransferHelper.safeTransferFrom()` which is already available in the codebase.
