# Attacker will cause transaction failures or leave excess approvals due to amount mismatch

### Summary

The mismatch between approved amount and swap amount in `_doMixSwap` will cause transaction failures for users as an attacker will craft parameters where `params.fromTokenAmount` differs from the approved amount.

### Root Cause

In the following locations, the function approves an amount but uses `params.fromTokenAmount` without proper validation:
[GatewayCrossChain.sol (Line 337-360)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337-L360)
[GatewayTransferNative.sol (Line 424-448)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L424-448)


```solidity
IZRC20(params.fromToken).approve(DODOApprove, amount);
return IDODORouteProxy(DODORouteProxy).mixSwap(
    params.fromToken,
    params.toToken,
    params.fromTokenAmount,  // This could differ from 'amount'
    ...
);
```


### Internal Pre-conditions

1. User needs to initiate a swap through any of the gateway contracts.
2. The `swapData` parameter contains encoded `MixSwapParams`.
3. No validation exists between `amount` and `params.fromTokenAmount`.

### External Pre-conditions

None.

### Attack Path

1. Attacker crafts malicious swapData with:

      -   `params.fromTokenAmount` set to `2000`.
      -   Actual passed `amount` set to `1000`.

2. Contract approves `1000` tokens to `DODOApprove`.
3. DODO’s `mixSwap` attempts to pull `2000` tokens.
4. Transaction reverts due to insufficient approved tokens.

 Alternatively:
 
1. Attacker crafts `params.fromTokenAmount` as `500` and passes `amount` as `1000`.
2. `500` tokens used in the swap, leaving an excess `500` tokens approved unnecessarily.

### Impact

The users suffer failed transactions when `params.fromTokenAmount > amount`.
The protocol suffers security risks due to lingering excessive approvals when `params.fromTokenAmount < amount`.

### PoC

```solidity
/// Attack vector 1: DoS
// User sends amount = 1000
// Attacker crafts params.fromTokenAmount = 2000
// Result: Transaction fails

// Attack vector 2: Excess approval
// User sends amount = 1000
// Params has fromTokenAmount = 100
// Result: 900 tokens remain approved to DODOApprove

```


### Mitigation

Add validation logic before calling the swap to ensure consistency between approved tokens and swap amounts.
```solidity
require(params.fromTokenAmount == amount, "Amount mismatch");

```
