# GatewayTransferNative.sol :: withdrawToNativeChain() if the native token is used to perform a swap during the cross-chain withdrawal, the transaction will always revert.

### Summary

The `withdrawToNativeChain()` enables cross-chain withdrawals from ZetaChain using either ZRC-20 tokens or the native token, ZETA. 

However, when ZETA is used, the function mistakenly attempts to call `approve()` which is invalid for native tokens. This causes the transaction to revert, making it impossible to use ZETA for withdrawals and breaking protocol functionality.


### Root Cause

[withdrawToNativeChain()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L600) is implemented as follows.

As shown, the function attempts to approve `fromToken`—in this case, ZETA—to `DODOApprove`. However, this always reverts because ZETA is the native token and does not implement the `approve` function. As a result, ZETA cannot be used for cross-chain withdrawals, breaking the intended functionality of the protocol.


### Internal Pre-conditions

The issue is inherent in the code itself.


### External Pre-conditions

Users are required to use the native token ZETA as the `fromToken` to perform a swap during the cross-chain withdrawals.


### Attack Path

None.

### Impact

Users cannot use the native token ZETA to perform swaps during cross-chain withdrawals, which breaks the functionality of the function.

### Mitigation

To fix the issue, check if the fromToken is ZETA and skip calling `approve()` if it is.
```diff

        bytes memory swapData, 
        uint256 amount, 
        MixSwapParams memory params
    ) internal returns (uint256 outputAmount) {
        if (swapData.length == 0) {
            return amount;
```
