# Unsafe ERC20 transfer in GatewaySend

### Summary

USDT cannot be transferred in `GatewaySend`, and other tokens may result in silent fund loss.

### Root Cause

The `onCall` function in the `GatewaySend` contract relies on [IERC20.transfer](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L372):

```solidity
if(toIsETH) {
    payable(evmWalletAddress).transfer(outputAmount);
} else {
>   IERC20(toToken).transfer(evmWalletAddress, outputAmount);
}
```

1. USDT is not fully ERC20-compilant and will always revert.
2. Other tokens may return `false` on failure instead of reverting. This can result in token loss, as the `onCall` logic proceeds without ensuring the transfer was successful.

It is recommended to always rely on the SafeERC20 library instead of calling `transfer`,
`transferFrom` and `approve` of ERC20 tokens directly.
