# Unauthorized calls to `GatewayTransferNative::withdraw` allows steal/override user refunds

### Summary

`GatewayTransferNative::withdraw` doesn't implement any kind of access control, which allows attackers to withdraw user refunds or override `refundInfo` of other users in some extreme cases.

### Root Cause

The `withdraw` function doesn't implement any access control:
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L286-L304
```solidity
    function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
    ) public { //----> no access control
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
This allows any address to call this function with arbitrary fields (including `externalId`). For this call to work, the gateway must have approval to spend `amount` of `outputToken` from `GatewayTransferNative`. Looking at some parts of `GatewayTransferNative`, we can see that it's possible for the `gateway` to still have some dust approval on behalf of `GatewayTransferNative`. In `_handleBitcoinWithdraw`: 
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L458
```solidity
    function _handleBitcoinWithdraw(
        bytes32 externalId, 
        DecodedMessage memory decoded, 
        uint256 outputAmount,
        uint256 gasFee
    ) internal {
        if(gasFee >= outputAmount) revert NotEnoughToPayGasFee();
        //@audit excessive approve, outputAmount + gasFee, while gasFee is deducted from outputAmount
        IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
        withdraw(
            externalId, 
            decoded.receiver, 
            decoded.targetZRC20, 
            outputAmount - gasFee
        );
    }
```
When withdrawing BTC, instead of approving the contract with only `outputAmount`, we are approving with `outputAmount + gasFee`, which is excessive because we are withdrawing `outputAmount - gasFee` and the rest will be allocated to gas fees.

An attacker can use this excessive approval to withdraw this amount of BTC from the contract:
`GatewayTransferNative::withdraw(id, attacker_addr, zrc_btc, excessive_approval)`
and steal user refunds.

### Internal Pre-conditions

- `gateway` must have enough allowance to spend `amount` of `outputToken` (used in `withdraw` call) from `GatewayTransferNative`

### Attack Path

1. Alice tries to withdraw `1` BTC from `GatewayTransferNative` so she calls `withdrawToNativeChain`
2. `gasFee` is calculated as `0.001 BTC` but gateway is approved with `1.001` BTC
3. There are `0.1` BTC sitting in the contract as user refunds
4. Attacker calls the `withdraw` function with their own address as recipient and `amount` set to `0.0008` to account for `0.0002` as gas fees (low traffic network)
5. `gateway` transfers `0.0002 BTC` from `GatewayTransferNative` as `gasFee` and `0.0008` as assets and transfers it to the attacker

The attacker might even choose an `externalId` belonging to a user. If the CCTX of the attacker fails, then the `refundInfo` of the victim will be overridden with new amounts and the user will lose their refunds.

### Impact

- Theft of user refunds
- Some users won't be able to claim their refunds
- Attacker might be able to override user refunds

### Mitigation

The `withdraw` function must be internal:
```diff
    function withdraw(
        bytes32 externalId,
        bytes memory sender,
        address outputToken,
        uint256 amount
-    ) public {
+    ) internal {
        gateway.withdraw(
            sender,
            amount,
            outputToken,
            RevertOptions({
                revertAddress: address(this),
                callOnRevert: true,
                abortAddress: address(0),
                revertMessage: bytes.concat(externalId, bytes20(sender)),
                onRevertGasLimit: gasLimit
            })
        );
    }
```
