# Chain ID Mismatch in GatewayCrossChain::onCall Enables Unauthorized Bitcoin Withdrawals

### Summary

The `GatewayCrossChain::onCall()` function fails to validate `dstChainId` against targetZRC20, allowing an attacker to set `dstChainId == BITCOIN_EDDY (8332)` to trigger a Bitcoin withdrawal, even when the token is EVM-based (e.g., token2Z). This enables unauthorized withdrawal of Bitcoin (btc) to a Bitcoin address, bypassing intended token-chain alignment.

### Root Cause

The [onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442) function does not enforce that `dstChainId` corresponds to the chain associated with `targetZRC20` or `swapDataZ.toToken`. When `dstChainId == BITCOIN_EDDY (8332)`, it invokes `_handleBitcoinWithdraw()`, which processes a withdrawal to a Bitcoin address, regardless of whether `targetZRC20 `is a Bitcoin-related token (e.g., btcZ) or an EVM token (e.g., token2Z). This lack of validation allows attackers to misrepresent EVM token transactions as Bitcoin withdrawals.

### Attack Path

1. The attacker crafts a `depositAndCall` transaction on chain A via `GatewaySendA`, depositing 100 ether token1A (no swap), with a payload specifying:
    
     - dstChainId = 8332 (BITCOIN_EDDY).
     - swapDataZ.toToken = token2Z (EVM token).
     - targetZRC20 = token2Z (EVM token).
     - receiver = btcAddress (e.g., 0x000...0333).

3. The transaction bridges 100 ether `token1Z` to ZetaChain, invoking `onCall()` of `gatewayCrossChain.sol`.
4. `onCall()` swaps 100 ether token1Z to 200 ether token2Z (1:2 ratio) based on swapDataZ.
 ```solidity
uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
```
5. Path: Instead of token2Z being a evm address it is treated as BTC and below path gets executed
 ```solidity
        if (decoded.dstChainId == BITCOIN_EDDY) {
            (, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
            _handleBitcoinWithdraw(externalId, decoded, outputAmount, gasFee);
            // x8 audits
            emit EddyCrossChainSwap(
                externalId,
                uint32(context.chainID),
                decoded.dstChainId,
                zrc20,
                decoded.targetZRC20,
                amount,
                outputAmount - gasFee,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx
            );
```
6. Event will be emitted with `decoded.dstChainId = BITCOIN_EDDY`.  Validators will mine this transaction and transfer `outputAmount - gasFee` worth of BTC to the `btcaddress` of the  attacker.

Same attack can also be carried out in GatewayTransferNative.sol: 
1. Attacker calls withdrawToNativeChain() of GatewayTransferNative with:
   dstChainId = 8332 (BITCOIN_EDDY)
2. The below part of code gets triggered and event is emitted:
```solidity
        if (decoded.dstChainId == BITCOIN_EDDY) {
            (, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee();
            _handleBitcoinWithdraw(externalId, decoded, outputAmount, gasFee);

            emit EddyCrossChainSwap(
                externalId,
                ZETACHAIN,
                decoded.dstChainId,
                zrc20,
                decoded.targetZRC20,
                amount,
                outputAmount - gasFee,
                decoded.sender,
                decoded.receiver,
                platformFeesForTx
            );
```

### Impact

Asset Drain: Attackers can withdraw Bitcoin (btc), a high-value asset, by setting dstChainId = 8332 with EVM tokens (e.g., token2Z), potentially depleting protocol reserves. For 100 ether token1A, the attacker gains 199 ether token2B as btc, which may be valued higher.

        bytes memory swapDataZ = encodeCompressedMixSwapParams(

            0,
