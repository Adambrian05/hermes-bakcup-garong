# Malicious User can claim refund

### Summary

`GatewayCrossChain::claimRefund` [function](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590) assigns `address receiver = msg.sender;` and if `refundInfo.walletAddress.length` is not 20. This check will be bypassed `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");` allowing anyone to claim refund if the conditions are met with just the externalId. 

### Root Cause


```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];
        // @audit-issue : Anyone can call this function and claim refund
        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }
```

-  `address receiver = msg.sender;` assigns receiver  as the caller
- ` require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");` this check will be bypassed


### Internal Pre-conditions

The exploit is possible only if there are entries in the refundInfos mapping where walletAddress.length is not equal to 20 bytes. In such cases, the contract defaults the receiver to msg.sender, allowing unauthorized users to claim refunds.

### External Pre-conditions

None

### Attack Path

- If a refund entry exists where `refundInfo.walletAddress.length != 20`
- Then any arbitrary user can call `claimRefund(externalId)` with the externalId of the refund where `refundInfo.walletAddress.length != 20`
- Because `receiver = msg.sender` is assigned in [#L574](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L574) , This check will pass `require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");` without any issues
- The token gets transferred to the attacker. `TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);`

### Impact

Any user can call `claimRefund(externalId)` for refunds where `refundInfo.walletAddress.length != 20` and claim the refund.
