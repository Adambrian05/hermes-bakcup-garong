# Unsafe Usage of transfer() Instead of safeTransfer() Can Lead to User Fund Loss with USDT

### Summary

In the `GatewaySend.sol` contract, the following code uses `IERC20.transfer()` directly:

```solidity
} else {
    IERC20(toToken).transfer(evmWalletAddress, outputAmount);
}
```

This approach is unsafe because some ERC-20 tokens like USDT do not return a boolean value, causing `transfer()` to succeed silently even if the transfer fails. Because of this user will lose funds and transaction says it is successful transfered to the user

We should use `TransferHelper.safeTransfer`  as we already using this in other places

```solidity
} else {
    ITransferHelper.safeTransfer(evmWalletAddress, outputAmount);
}
```

### Root Cause

The contract assumes all ERC-20 tokens strictly follow the standard and reverts when there is a failure. However, tokens like USDT deviate from this and return nothing.

We should use `TransferHelper.safeTransferFrom`  as we already using this in other places

### Mitigation

Replace `IERC20.transfer()` with `TransferHelper.safeTransfer()`:

```diff
} else {
-    IERC20(toToken).transfer(evmWalletAddress, outputAmount);
+    TransferHelper.safeTransfer(address(toToken), evmWalletAddress, outputAmount);
}
```

This ensures support for non-standard ERC-20 tokens safely
