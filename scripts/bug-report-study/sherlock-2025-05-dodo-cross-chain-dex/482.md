# externalId collision across different chains

### Summary

`_calcExternalId` [function](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L160-L162) does not factor in chainId. which in an edge case can lead to two different txn having same externalId. which is problematic as externalId is used to do refund for failed txns. 

### Root Cause

if 2 GatewaySend contracts on different chains have the same address then a user's calculated `externalId` s can collide on these chains. & if both of these txns reach the `abort` flow on zetachain. then user will only get refund for one of these txn. as `onAbort` function of `GatewayCrossChain.sol` [overwrites](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L550-L569) the refundInfos mapping, without checking whether a refundInfo for the given `externalId` exists or not. 

Hence causing a loss of funds. 

### Internal Pre-conditions

None

### External Pre-conditions

GatewaySend is deployed on 2 chains at the same address. which is a fairly common procedure.

### Attack Path

Lets assume a Market Maker triggers rebalance on 2 EVM chains through dodo at the same block.timestamp , now if his EOA is the same on both chains & globalNonce on these chains the same (which an attacker can make sure of by sending bogus depositAndCall txns)

Now if both his txns reached the abort state then zetachain calls onAbort on the given address, which is GatewayCrossChain contract address deployed on zetachain. 

Lets assume for chain A he was transfering 1 WBTC & on other 60k USDC. 
Zeta first calls onAbort for chain A. which stores the relevent details in refundInfo\[externalId] mapping. 
But since externalId is the same for both txns then when it calls onAbort for the 2nd txn, the onAbort overwrites the existing refundInfo\[externald] with 60k USDC. 

So at the end the MM will only be able to claim 60K USDC, loosing is 1 WBTC. 

### Impact

Loss of funds. 

### PoC

_No response_

### Mitigation

hash chain.id as well when calculating externalId.
