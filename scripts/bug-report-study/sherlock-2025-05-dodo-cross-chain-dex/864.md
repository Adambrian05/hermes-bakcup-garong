# Attacker can drain unclaimed refunds in Zeta using Bitcoin chainId

### Summary

When a cross chain transaction occurs, an attacker can set the `decoded.dstChainId` to be Bitcoin, but the targetZRC20 as a ZRC20 the GatewayCrossChain contract holds in unclaimed refunds.

This excutes the Bitcoin path which eventually calls GatewayZEVM.withdraw(), sending the unclaimed refunds directly to the attacker.

The way this is profitable is if the attacker deposits in a lower value token (e.g. USDC) than the one the unclaimed refund is in (e.g. wBTC).


### Root Cause

Missing validation that when decoded.dstChainId == BITCOIN_EDDY, the targetZRC20 is also Bitcoin.

### Internal Pre-conditions

1. Unclaimed refunds exist in GatewayCrossChain

### External Pre-conditions

n/a

### Attack Path

1. There are wBTC unclaimed refunds in GtewayCrossChain.
2. Attacker calls depositAndCall depositing DAI, but setting `decoded.dstChainId` equal to Bitcoin and the targetZRC20 to wBTC.
3. Attacker deposits DAI, but receives and equal amount of wBTC

### Impact

Loss of funds.

### PoC

_No response_

### Mitigation

Add a check to ensure that if the chainID is Bitcoin that the zrc20 is also Bitcoin (i.e. 0x13A0c5930C028511Dc02665E7285134B6d11A5f4).
