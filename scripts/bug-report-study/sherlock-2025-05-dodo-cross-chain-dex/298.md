# Malicious user will avoid fees in GatewayTransferNative

### Summary

In [GatewayTransferNative.sol:onCall()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L357) function `platformFeesForTx` are not deducted from `amount` if user want to swap tokens. This will allow him to use some leftover tokens (intended for refunds).

### Root Cause

When swapping via DODO Router, contract calls `_doMixSwap()` with full `amount` without subtracting `platformFeesForTx`:
```solidity
function onCall(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    bytes calldata message
) external override onlyGateway {
    ...
    // Fee for platform
    //@audit function calculates fees
    uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
    address receiver = address(uint160(bytes20(decoded.receiver)));

    if (decoded.targetZRC20 == zrc20) {
        // same token
        TransferHelper.safeTransfer(
            decoded.targetZRC20,
            receiver,
            amount - platformFeesForTx  //@audit if no need for swap, then platformFeesForTx correctly deducted from amount
        );
        ...
    } else {
        // Swap on DODO Router
        //@audit if swap, then platformFeesForTx are NOT deducted from amount
        uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

        if (decoded.targetZRC20 == WZETA) {
            // withdraw WZETA to get Zeta in 1:1 ratio
            IWETH9(WZETA).withdraw(outputAmount);
            // transfer wzeta
            TransferHelper.safeTransferETH(receiver, outputAmount);
        } else {
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                outputAmount
            );
        }
        ...
    }
}

function _doMixSwap(
    bytes memory swapData, 
    uint256 amount,
    MixSwapParams memory params
) internal returns (uint256 outputAmount) {
    if (swapData.length == 0) {
        return amount; //@audit we can return amout without fees
    }
    //@audit also approve amount is more than should be
    IZRC20(params.fromToken).approve(DODOApprove, amount);
    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount, //@audit set as amount
        ...
    );
}
```
This lets an attacker bypass the fee if the contract holds some tokens on balance (e.g. from pending refunds).

### Attack Path

Assume the `GatewayTransferNative.sol` contract holds `1000 USDC.ETH` intended for a refund:
```solidity
USDC.ETH.balanceOf(contract) = 1000 USDC.ETH
fee = 5%
```
1. A malicious user wants to receive `DAI.ETH` on ZetaChain, so:
```solidity
swapParams = {
    fromToken: USDC.ETH, 
    toToken: DAI.ETH, 
    fromTokenAmount: 1000 USDC.ETH, 
    expReturnAmount: 1000 DAI.ETH
} (assume rate 1:1)
targetZRC20 = DAI.ETH
```
2. User calls `GatewaySend.sol:depositAndCall()` on Ethereum with `asset = USDC, amount = 1000 USDC`
3. ZetaChain protocol calls `GatewayTransferNative.sol:onCall()`
4. The contract now has `2000 USDC.ETH` (1000 from user + 1000 from unclaimed refund).
5. `_handleFeeTransfer()` deducts the 5% fee (`50 USDC.ETH`) and sends it to treasury.
6. Contract now holds `1950 USDC.ETH`
7. Contract approves the full `1000 USDC.ETH` (without fee deduction).
8. `mixSwap()` swaps `1000 USDC.ETH` → `1000 DAI.ETH`.
9. `DAI.ETH.transfer()` is called and user gets `1000 DAI.ETH` successfully avoiding fees.

### Impact

Attacker avoids platform fees and drains tokens intended for refunds

### Mitigation

Substract `platformFeesForTx` from `amount`:
```diff
- uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);
+ uint256 outputAmount = _doMixSwap(decoded.swapData, amount - platformFeesForTx, params);
```
