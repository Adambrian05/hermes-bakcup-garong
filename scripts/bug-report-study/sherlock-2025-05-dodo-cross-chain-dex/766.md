# Unauthorized Refund Claims for Non-EVM Addresses

### Summary

The `claimRefund` function in `GatewayCrossChain.sol` and `GatewayTransferNative` allows unauthorized users to claim refunds meant for non-EVM chain addresses due to improper access control validation.


### Root Cause

The [claimRefund](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L661) function sets the receiver to `msg.sender` by default and only overwrites it for EVM addresses (20 bytes). For non-EVM addresses, the access control check `msg.sender == receiver` always passes because `receiver` is still `msg.sender`.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Attacker identifies a pending refund for a non-EVM address (e.g., Solana)
2. Attacker obtains the `externalId` for the refund
3. Attacker calls `claimRefund(externalId)`
4. Since `walletAddress.length != 20`, receiver stays as `msg.sender`
5. Access control check passes because `msg.sender == receiver`
6. Attacker successfully claims the refund

### Impact

Malicious users can claim refunds meant for non-EVM addresses

_No response_

### Mitigation

Add additional validation for non-EVM address format
