# `GatewaySend` can't handle native ETH refunds

### Summary

The protocol send outbound messages from connected chains using [GatewaySend::depositAndCall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L250-L265).  The function always construct `RevertOption` params the following way:
```solidity
        RevertOptions memory revertOptions = RevertOptions({
            revertAddress: address(this),
            callOnRevert: true,
            abortAddress: targetContract,
            revertMessage: bytes.concat(externalId, bytes20(msg.sender)),
            onRevertGasLimit: gasLimit
        });
```

If the transaction reverts on source, or destination, ZetaChain validator will execute `GatewayEVM::executeRevert` to handle revert for native tokens:
```solidity
    function executeRevert(
        address destination,
        bytes calldata data,
        RevertContext calldata revertContext
    )
        public
        payable
        nonReentrant
        onlyRole(TSS_ROLE)
        whenNotPaused
    {
        if (destination == address(0)) revert ZeroAddress();
        (bool success,) = destination.call{ value: msg.value }("");
        if (!success) revert ExecutionFailed();
        Revertable(destination).onRevert(revertContext);
```

However, in `GarewaySend::onRevert`  we don't handle a case to transfer native fund and the transaction will always revert because we will try to call transfer function on `address(0)`:

```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {  // @ok
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:]))); 
        TransferHelper.safeTransfer(context.asset, sender, context.amount);
```

### Root Cause

`onRevert` not covering a case, where `asset == native`

### Internal Pre-conditions

None

User calling `

### Attack Path

User calls `depositAndCall` with `asset == _ETH_ADDRESS_`.

### Impact

Broken protocol functionality to refund native assets on connected chains.

### PoC

_No response_

### Mitigation

In `onRevert` check if the `context.asset == address(0)` and handle the case correctly (You can implement the update in `TransferHelper.safeTransfer` Lib)
