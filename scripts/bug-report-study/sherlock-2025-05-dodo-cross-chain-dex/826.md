# Improper Fallback to msg.sender in claimRefund Enables Unauthorized Refund Claims

### Summary

The claimRefund function in the GatewayCrossChain contract defaults to using msg.sender as the refund recipient when the stored walletAddress is not exactly 20 bytes long. This design flaw skips proper ownership verification, enabling attackers to claim refunds meant for other users by exploiting valid externalId values paired with malformed or corrupted walletAddress data.

### Attack Path

In the claimRefund function, the contract sets the refund recipient to msg.sender by default. It only decodes the stored walletAddress as the recipient if its length is exactly 20 bytes. If the walletAddress length is invalid—due to data corruption or an error during storage—the contract falls back to msg.sender, creating a vulnerability that allows unauthorized refund claims.

An attacker identifies a valid externalId in the refundInfos mapping where the associated walletAddress has an invalid length (not 20 bytes), possibly due to a data error or manipulation. The attacker then calls claimRefund(externalId). Since the walletAddress length is invalid, the contract defaults to setting the recipient as msg.sender (the attacker). The subsequent check msg.sender == receiver passes automatically, allowing the contract to transfer the refund funds to the attacker. This permanently deprives the rightful owner of their refund.

### Impact

Attackers can steal refunds intended for legitimate users.
