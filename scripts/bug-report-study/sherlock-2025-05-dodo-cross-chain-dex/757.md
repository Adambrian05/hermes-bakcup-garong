# `onRevert` & `onAbort` functions will not work with account abstraction wallets

### Summary

## Description
The two functions are invoked when either the cross-chain message reverted or aborted. 

In both cases the code transfers or stores the `walletAddress` in the `refundInfos`  to be later claimed by using `claimRefund`.

The `walletAddress` is encoded in `withdrawAndCall` inside the `revertMessage`. `receiver` is `decoded.receiver` which is the address which is meant to receive the tokens on the destination chain. For the EVM this is fine, if the `receiver` is an EOA, but if it's an account abstraction wallet this will not work correctly.

Account abstraction wallets have different addresses on different chains, as they are not EOAs, so using the same address meant to be receiving the tokens on the destination chain and the address meant to receive/be stored in case of a revert/abort will result in a loss of funds.

The same problem also exists in `GatewaySend::depositAndCall`. -> We set [bytes20(msg.sender)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L303-L304) on `revertMessage`, but it is a valid scenario that transaction reverts on dest -> call `onRevert` on source -> revert -> call `onAbort` on destination (ZetaChain) where this address may not be owned by the source `msg.sender`


__NOTE__ that the same issue exists in `GatewayCrossChain` and `GatewayTransferNative`, not on `GatewaySend` as `GatewaySend::onRevert` will have the same `recipient == msg.sender` and thus it will work on `GatewaySend`, the issue is that the same `recipient` is used for the connected chain and for ZetaChain.

### Root Cause

- Mixing EVM addresses on different chains
- Assuming caller's on connected chains own the same addresses on ZetaChain, etc

### Internal Pre-conditions

None

### External Pre-conditions

User with account abstraction wallet such as Safe initializes a transaction, which reverts

### Attack Path

1. User initializes transaction From Mainnet to Polygon and set his Safe wallet as a receiver 
2. Transaction reverts on Polygon and `onRevert` on ZetaChain uses Polygon safe wallet as receiver for the refund
3. Funds are lost

### Impact

Loss of funds

### PoC

_No response_

### Mitigation

Allow users to specify the refund address, instead of using the receiving address directly
