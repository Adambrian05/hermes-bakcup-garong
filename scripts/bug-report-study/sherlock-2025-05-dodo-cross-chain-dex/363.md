# Cross-Chain and Native Decimal Normalization Issues for Solana/BTC/ETH

### Summary

The contracts do not properly handle decimal normalization when transferring tokens between chains with different decimal places:

- Bitcoin (BTC) uses 8 decimals
- Ethereum (ETH) uses 18 decimals  
- Solana (SOL) uses 9 decimals on most tokens

This can cause:
1. Value loss when going from higher to lower decimals
2. Incorrect amounts when going from lower to higher decimals


### Root Cause

### GatewayTransferNative.sol

`_handleBitcoinWithdraw` does not convert to 1e8. `_handleEvmOrSolanaWithdraw` do not convert to 1e9(Solana) and (1e18) ETH.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L451C3-L528C6

### GatewayCrossChain.sol

Also `_handleBitcoinWithdraw` does not convert to 1e8. `_handleEvmOrSolanaWithdraw` do not convert to 1e9(Solana) and (1e18) ETH.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L363C1-L441C1

### Internal Pre-conditions

Contract has sufficient permissions to interact with gateway
Gateway contract is properly initialized
Valid message encoding for cross-chain communication
Token contracts (ZRC20) are deployed and accessible
Liquidity exists in relevant pairs for token swaps

### External Pre-conditions

User initiates a cross-chain transfer between chains with mismatched decimals
Transaction includes sufficient gas fees
Source chain tokens are approved for transfer
Valid destination address exists

### Attack Path

None

### Impact

High. Incorrect decimal handling between chains can lead to significant value loss or unintended token amounts being transferred.

### Mitigation

Add decimal normalization helper:

```solidity
uint256 constant BTC_DECIMALS = 8;
uint256 constant EVM_DECIMALS = 18;
uint256 constant SOLANA_DECIMALS = 9;

function _normalizeToDestinationDecimals(
    uint256 amount,
    uint256 srcDecimals, 
    uint256 dstDecimals
) internal pure returns (uint256) {
    if (srcDecimals > dstDecimals) {
        return amount / (10 ** (srcDecimals - dstDecimals));
    }
    return amount * (10 ** (dstDecimals - srcDecimals));
}
```

Update withdraw functions to use this normalization both on `GatewayTransferNative` and `GatewayCrossChain`
