# User can steal funds from `GatewayCrossChain` exploiting `BITCOIN_EDDY` path

### Summary
This affects `GatewayCrossChain` and `GatewayTransferNative`

The issue will describe the attack on `GatewayCrossChain` so not to repeat the same example and description twice.

When user initiates a cross-chain transaction from a connected chain, he provides arbitrary `payload`, which is the data for the message on the Hub and any following chain.
The message includes `targetZRC20`, `dstChainId`, `sender`, etc.
However, most of those params are never validated, nor has a relation with the others. For example: `targetZRC20` may be a token from different chain than `dstChainId`.
This can be exploited by malicious user to spend stale funds in `GatewayCrossChain` that are waiting for refund to pay for connected chain gas costs.
If the exploiter makes a cross-chain transaction and provide [dstChainId == BITCOIN_EDDY](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L468-L469), we enter a path where we assume that `decoded.targetZRC20 == gasToken`, but this isn't enforced:
```solidity
        if (decoded.dstChainId == BITCOIN_EDDY) {
            (, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFee(); // @sus targetZRC20 may be different from dstChainId
            _handleBitcoinWithdraw(
                externalId, 
                decoded, 
                outputAmount,
                gasFee
            );
```

The exploit may be executed as long as there are funds in the contract and standing approval on the gateway.
__NOTE__ that the contract always [approve the gateway to spend more than being](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L379-L390) used on each interaction when target == gasFee:
Approves `outputAmount + gasFees`, but `gateway::withdraw` is transferring only `outputAmount` because we pass [outputAmount - gasFees](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L406-L407) as `amount` to the function.

### Root Cause

Not validating important `DecodedMessage memory decoded` params in `onCall` functions.

### Internal Pre-conditions

Having gas (eth:Mainnet, eth:arb, pol:pol, etc.) funds inside `GatewayCrossChain` waiting for refund

### External Pre-conditions

None

### Attack Path

Imagine that user bridges DAI:AVAX -> DAI:MAINNET, but provides `dstChainId == BITCOIN_EDDY`. 
- `IZRC20(decoded.targetZRC20).withdrawGasFee()` will return the cost for Eth Mainnet in native wei because `targetZRC20` is a Mainnet token. 
- Inside `_handleBitcoinWithdraw` we will call `withdraw` with `outputAmount - gasFee`, where `outputAmount` is in DAI currency and `gasFee` is in eth wei => this will result in decreasing bridged DAI amount with a dust amount, instead of swapping it for the needed gas tokens. In `gateway.withdraw`, Zatachain's contract will transfer the correct gas token (Eth:Mainnet) from `GatewayCrossChain`. Those are the victim's funds waiting to be refunded. 
The path is valid because `_handleEvmOrSolanaWithdraw` always approve the gateway for `outputAmount + gasFee`, but transfers only `outputAmount`.

### Impact

Theft of funds allocated for refunds in `GatewayCrossChain` contract.

### PoC

_No response_

### Mitigation

Validate `decoded.targetZRC20.CHAIN_ID == decoded.dstChainId`
