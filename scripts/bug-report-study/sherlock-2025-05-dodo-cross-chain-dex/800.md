# Any user can use any user's amount of token to swap for output tokens in `GatewayTransferNative.onCall` due to `params.fromToken` anad `zrc20` token send from `GatewayEVM` mismatch to do a swap and reap profits

## Vulnerability Details 

The `GatewayTransferNative.onCall` function can be triggered via the universal Gateway when a user employs the EVM-compatible `GatewaySend` to deposit assets and selects `GatewayTransferNative` as the target contract. In this process, the user has the option to define `params.fromToken`, which is extracted from the `_message` created during the `GatewaySend` call and supplied by the user through `GatewaySend.depositAndCall`. At the same time, the user will initiate the transfer of a `ZRC20` token, which signifies the token that `GatewayTransferNative` will receive when the universal Gateway contract invokes the `GatewayTransferNative.onCall` function.

The problem occurs due to the absence of checks ensuring that `params.toToken` = `zrc20 (passed in from the universal gateway)`. This oversight permits any caller to utilized funds in the `GatewayTransferNative` contract  to conduct their swap from `params.fromToken` to `params.toToken`. Consequently, user can reap profits off of this process

## POC

Consider the following scenario

1. Alice sends 1 USDC (1e6) from Ethereum to her Zetachain address through the following sequence:
    - GatewaySend.depositAndCall -> GatewayTransferNative.onCall -> TransferHelper.safeTransfer -> her address on Zetachain
    - In the `GatewaySend.depositAndCall` function, she configures the `payload` with decoded.targetZRC20 = WBTC.ETH, params.fromToken = WBTC.ETH, and params.toToken = USDT.ETH.
2. She notices that the GatewayTransferNative contract contains 1e6 worth of `WBTC.ETH` allocated for refunds.
3. Since the decoded.targetZRC20 token is not equal to the zrc20 (USDC) token, she executes the swap using `GatewayTransferNative._doMixSwap`.
    - However, as `params.fromToken` is `WBTC.ETH`, she utilizes the 1e6 `WBTC.ETH` worth of tokens in the `GatewayTransferNative` contract intended for refunds to exchange for `USDT.ETH`.
    - Let's assume she receives `1e12` worth of `USDT.ETH` in return to her zetachain address.
4. In the end, Alice forfeits her 1e6 worth of `USDC.ETH` (which was meant to be swapped for `USDT.ETH`) but acquires 1e12 worth of `USDT.ETH` by swapping with the `WBTC.ETH` funds in the GatewayTransferNative contract, putting the protocol at risk.


## Root Cause

Lack of checks that ZRC20 token supplied by user is the inteded token to be use for swaps in `GatewayTransferNative.onCall`

## Impact

Loss of funds for protocol. Insolvency

## Mitigation

Check that `params.fromToken = zrc20` supplied in `GatewayTransferNative.onCall`
