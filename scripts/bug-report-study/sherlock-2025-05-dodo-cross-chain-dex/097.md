# ETH Amount Parameter Usage Leading to Unintended Fund Transfer

## Description
The `GatewaySend` contract contains a critical issue in the `depositAndCall` function (non-swap version) that causes an inconsistency between the user's intended `amount` parameter and the actual amount of ETH sent to the destination blockchain. The contract uses `msg.value` (the total ETH the user sent) instead of the `amount` parameter (the amount actually sent), which can result in inadvertent loss of user funds.

## Code Snippet
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L309-L314

## Root Cause
The root of the problem lies in an improper implementation in the swap-free version of the `depositAndCall` function:
```solidity
function depositAndCall(
    address targetContract,
    uint256 amount,           // Parameters that the user means
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // ...
    if (isETH) {
        // ✅ Validation using the amount parameter
        require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
        
        // ❌ EXECUTION using msg.value, not amount
        _handleETHDeposit(
            targetContract,
            msg.value,        // ROOT CAUSE: Should be 'amount'
            message,
            revertOptions
        );
    }
}
```
The contract should validate that `msg.value >= amount`, but the contract uses `msg.value` for the transfer. The amount parameter is ignored in the execution and there is no mechanism to return excess ETH.

## Impact
Users lose more ETH than intended and there is no mechanism to return the excess ETH.

## Scenario
Setup:
- User wants to send 1 ETH to Polygon
- User accidentally sends 2 ETH to the contract
- Parameter `amount` = 1 ETH
- `msg.value` = 2 ETH

Execution Steps:
1. User Call: `depositAndCall{value: 2 ether}(targetContract, 1 ether, ETH_ADDRESS, 137, payload)`
2. Validation: `require(2 ETH >= 1 ETH)` → ✅ PASS
3. Execution: `_handleETHDeposit(targetContract, 2 ETH, ...)` → ❌ WRONG
4. Cross-Chain Transfer: Gateway sends 2 ETH to Polygon
5. Result: User loses 1 extra ETH without refund

## Recommendation
Use the `amount` parameter, not `msg.value`.
```solidity
function depositAndCall(
    address targetContract,
    uint256 amount,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {
    // Input validation
    require(amount > 0, "ZERO_AMOUNT");
    require(targetContract != address(0), "INVALID_TARGET");
    
    globalNonce++;
    bytes32 externalId = _calcExternalId(msg.sender);
    bool isETH = (asset == _ETH_ADDRESS_);
    
    bytes memory message = concatBytes(externalId, payload);
    RevertOptions memory revertOptions = RevertOptions({
        revertAddress: address(this),
        callOnRevert: true,
        abortAddress: targetContract,
        revertMessage: bytes.concat(externalId, bytes20(msg.sender)),
        onRevertGasLimit: gasLimit
    });

    if (isETH) {
        // ✅ FIX: Correct amount validation
        require(msg.value >= amount, "INSUFFICIENT_ETH");
        
        // ✅ FIX: Use amount parameter, not msg.value
        _handleETHDeposit(targetContract, amount, message, revertOptions);
        
        // ✅ FIX: Return excess ETH to users
        uint256 excess = msg.value - amount;
        if (excess > 0) {
            (bool success, ) = payable(msg.sender).call{value: excess}("");
            require(success, "ETH_REFUND_FAILED");
        }
    } else {
        // Handle ERC20 transfer
        require(
            IERC20(asset).transferFrom(msg.sender, address(this), amount),
            "ERC20_TRANSFER_FAILED"
        );
        
        _handleERC20Deposit(targetContract, amount, asset, message, revertOptions);
    }

    // ✅ FIX: Events with consistent amounts
    emit EddyCrossChainSend(
        externalId,
        dstChainId,
        asset,
        asset,
        amount,        // Consistent with what was sent
        amount,
        msg.sender,
        message
    );
}
```
