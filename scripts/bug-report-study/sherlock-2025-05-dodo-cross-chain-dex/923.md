# GatewayTransferNative's withdrawToNativeChain will allow users to drain contract's token balance via arbitrary token swaps

### Summary

The absence of validation between zrc20 and params.fromToken in GatewayTransferNative.withdrawToNativeChain() will cause a loss of funds as it allows attackers to execute arbitrary token swaps using the contract's existing balance, effectively stealing the difference in value between the deposited and swapped tokens.

### Root Cause

In GatewayTransferNative.sol, the [withdrawToNativeChain()](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530) function accepts a zrc20 parameter and swap parameters without validating that params.fromToken matches zrc20, allowing attackers to use the contract's existing token balances for swaps.
```solidity
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    if(zrc20 != _ETH_ADDRESS_) {
        require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
    }

    // ... decodes message ...
(DecodedMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeMessage(message);

    // Swap on DODO Router
    uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);

    // ... continues with withdrawals ...
}

```

### Internal Pre-conditions

1. GatewayTransferNative must have tokens in its balance (from unclaimed refunds or other sources)
2. The tokens in balance must have higher value than the deposited tokens

### External Pre-conditions

1. The attacker must have sufficient tokens to deposit (amount parameter)
2. The attacker must have sufficient allowance for the deposit
3. The DODO router must have sufficient liquidity for the swap

### Attack Path

1. Attacker calls withdrawToNativeChain() with:
    - zrc20 = DAI
    - amount = 1e18 (1 DAI)
    - params.fromToken = WETH (in ‘message)
    - params.toToken = USDC (in ‘message’)
    - params.fromTokenAmount = 1e18 (1 WETH) (in ‘message’)
2. The contract will:
    - Accept 1 DAI from the attacker
    - In _doMixSwap():
        - Approve DODOApprove to spend 1e18 WETH
        - Execute the swap using GatewayTransferNative's WETH balance
    - Send the resulting USDC (worth ~$2600) to the attacker's address on another chain

### Impact

Users suffer a loss of their funds as GatewayTransferNative will use its existing token balances to fulfill arbitrary swaps. An attacker can deposit a small amount of one token (e.g., 1 DAI) and use the contract's balance of another token (e.g., 1 WETH) to execute a swap, effectively stealing the difference in value (e.g., $2600 worth of USDC).

_No response_

### Mitigation

Add validation in withdrawToNativeChain() to ensure params.fromToken matches zrc20:

```solidity
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    // ... existing code ...

    (DecodedMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeMessage(message);

    // Add validation
    require(params.fromToken == zrc20, "Invalid swap token");

    // ... rest of the function
}

```

This ensures that users can only swap the tokens they deposit, preventing unauthorized use of the contract's token balances.
