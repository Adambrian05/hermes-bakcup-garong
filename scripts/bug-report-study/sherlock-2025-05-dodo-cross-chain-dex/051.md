# The `claimRefund()` function does not support ZetaChain's native token (ZETA).






## Summary
The `claimRefund()` function does not support ZetaChain's native token (ZETA).


## Root Cause

When using `claimRefund()` to obtain a refund, since `safeTransfer()` is employed to transfer funds to the user, and this function only supports the transfer of ERC20 tokens, an error will occur if `refundInfo.token` address is 0 (indicating ZetaChain's native token, ZETA). This will prevent the user from receiving the refunded ZETA.  

This scenario is possible because the gateway supports cross-chain transfers of ZETA (ERC20: 0xf091867EC603A6628eD83D274E835539D82e9cc8) from Ethereum to ZetaChain.  

1. When transferring ZETA (ERC20) from Ethereum to ZetaChain, the process involves calling `depositAndCall()` for cross-chain operations, which is identical to handling any other ERC20 token.  

2. On ZetaChain, the GatewayZEVM has a dedicated `depositAndCall` function for receiving ZETA tokens, as shown below. This function will invoke either `GatewayTransferNative::OnCall()` or `GatewayCrossChain::OnCall()`.

4. And if the `amount` is insufficient to execute `onRevert()` on Ethereum—  

According to the zeta documentation(https://www.zetachain.com/docs/developers/chains/zetachain/):  
*If the amount is insufficient or zero (for example, when it's a no-asset call), the Gateway calls `onAbort` on the `abortAddress` on ZetaChain.*  

Additionally, there is another scenario:  
When withdrawing ZETA to another chain via `GatewayTransferNative`, if the execution fails and `GatewayTransferNative::onRevert()` also fails, the Gateway will call `GatewayTransferNative::onAbort()` and refund the ZETA to the `GatewayTransferNative` contract.
