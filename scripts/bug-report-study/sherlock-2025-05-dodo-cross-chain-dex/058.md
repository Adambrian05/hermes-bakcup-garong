# Cross-chain Transfers to Account Abstraction Wallets Will Lose Funds and Break Reward Claims

### Summary

The choice to use the source chain's address (decoded.receiver) on the destination chain will cause a complete loss of tokens and reward claim failure for Account Abstraction wallet users, as GatewayCrossChain.sol will send funds to an incorrect or undeployed contract address.

### Root Cause

The choice to rely on decoded.receiver for withdrawal in GatewayCrossChain.sol:onCall() is a mistake, as it assumes address equivalence across chains. Account Abstraction wallets like Safe generate different addresses per chain unless deterministically deployed.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L277-L296

### Internal Pre-conditions

1. A user connects an Account Abstraction wallet (e.g., Safe) on Ethereum.

2. The frontend encodes that address as decoded.receiver for cross-chain reallocation.

3. GatewayCrossChain uses this receiver address on the destination chain without verification.

### External Pre-conditions

1. The AA wallet is not deployed or uses different salts on the destination chain.
2. User has no control over the destination address derived from the source chain's wallet.


### Attack Path

1. User initiates a cross-chain token reallocation.

2. LiFi completes the swap and triggers onCall(), providing source-chain Safe address as receiver.

3. GatewayCrossChain.sol withdraws or calls withdrawAndCall() to this invalid address.

4. Tokens are sent to an address the user cannot access.

5. If rewards are also indexed to this address, user becomes permanently ineligible.

### Impact

1. A wallet users suffer a 100% loss of cross-chain tokens.

2. Associated rewards become unclaimable.

3. Affects all reward-based protocols layered on top (e.g., NugeCampaign.sol).

4. Funds cannot be recovered via rescue functions due to unmatchable reward keys.

### PoC

bytes memory fakeReceiver = abi.encodePacked(address(0xAb...)); // Safe wallet address on Ethereum
DecodedMessage memory decoded = DecodedMessage({
  receiver: fakeReceiver,
  ...
});
gateway.onCall(..., decoded);


### Mitigation

- Add an explicit destinationReceiver field in the message payload.

- Reject contract receivers unless proven deployed and user-owned.

- Optionally add require(receiver.code.length == 0) to enforce EOA-only receipt.

- Log and quarantine suspected AA wallet addresses for manual handling.
