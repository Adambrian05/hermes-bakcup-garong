# Attackers will drain accumulated ZRC20 token balances through parameter mismatch exploitation in `GatewayTransferNative` contract

### Summary

Missing validation between swap output token and target transfer token will cause complete loss of accumulated ZRC20 balances for the protocol as attackers will craft malicious cross-chain transactions with mismatched swap parameters to drain valuable tokens that have accumulated in the `GatewayTransferNative` contract.

### Root Cause

In [GatewayTransferNative.sol:395](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395-L408) the `onCall` function performs a token swap using `_doMixSwap()` with `params.toToken` as the output, but then transfers using `decoded.targetZRC20` without validating that these tokens match. This allows an attacker to swap to one token type but transfer a different accumulated token type.

```solidity
        // Swap on DODO Router
        uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params); // Swap occurs with params.toToken as output  

        if (decoded.targetZRC20 == WZETA) { 
            // withdraw WZETA to get Zeta in 1:1 ratio
            IWETH9(WZETA).withdraw(outputAmount); // Uses targetZRC20 (no validation against swap output)
            // transfer wzeta
            TransferHelper.safeTransferETH(receiver, outputAmount);
        } else {
            TransferHelper.safeTransfer(
                decoded.targetZRC20, // Uses targetZRC20 (no validation against swap output)
                receiver,
                outputAmount
            );
        }
```

### Attack Path

1. Attacker monitors GatewayTransferNative contract balance and identifies accumulated high-value ZRC20 tokens (e.g., 1000 ETH.ZRC20)
2. Attacker crafts a malicious cross-chain transaction with:
   - `swapData` configured to swap from input token to a different, cheaper output token (e.g., USDC.ZRC20) 
   - `targetZRC20` set to the accumulated high-value token they want to drain (e.g., ETH.ZRC20)
3. Attacker calls `depositAndCall` on source chain with cheap input tokens (e.g., 0.02 BTC)
4. ZetaChain processes the transaction:
   - Contract receives input tokens and swaps them to USDC.ZRC20 via `_doMixSwap`
   - Contract attempts transfer using `targetZRC20` (ETH.ZRC20)
   - Since contract has accumulated ETH.ZRC20 balance, the transfer succeeds
5. Attacker receives valuable ETH.ZRC20 tokens on ZetaChain while only providing cheaper output tokens
6. Attacker repeats the process to drain all accumulated ZRC20 balances of various token types

### Impact

The protocol suffers complete loss of accumulated token balances.

### Mitigation

Add validation in the `onCall` function to ensure swap output token matches the target transfer token
