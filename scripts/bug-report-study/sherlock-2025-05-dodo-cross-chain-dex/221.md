# The `GatewayEVM` cannot call `GatewayCrossChain.onCall` because the modifier restricts access solely to the `GatewayZEVM` contract for calling the callback function.

## Vulnerability Details

The `GatewayCrossChain.onCall` serves as a important component for interactions between chain A -> Zetachain -> chain B. Users can go through the flow of `(EVM) GatewaySend.depositAndCall` -> `(Zeta) GatewayCrossChain.onCall` -> the receiver address on the destination chain

The problem arises because the `onlyGateway` modifier restricts access solely to the `GatewayZEVM` contract, excluding the `GatewayEVM` contract. Consequently, any subsequent calls from EVM chain A to Zeta chain will either revert or fail due to this overly restrictive modifier.

In `GatewayCrossChain`

```solidity
@> GatewayZEVM public gateway; //@audit this refers GatewayZEVM and not GatewayEVM

modifier onlyGateway() {
@>    if (msg.sender != address(gateway)) revert Unauthorized(); 
    _;
}

function onCall(
    MessageContext calldata context,
    address zrc20,
    uint256 amount,
    bytes calldata message
@> ) external onlyGateway {  // @audit only allows GatewayZEVM to call but not GatewayEVM
```

## Root Cause

Restrictive modifier validations on permitted gateways for triggering `GatewayCrossChain.onCall`

## Impact

Denial of Service (DOS) on cross-chain calls from EVM to Zeta chain. Broken core functionality as all calls will revert, leading to guaranteed losses in gas fees for users.

## Mitigation

Consider modifiying the modifier to accept a mapping of gateways instead of just the `GatewayZEVM` address
