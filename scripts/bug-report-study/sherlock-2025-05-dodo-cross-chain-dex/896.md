# Malicious users can steal all funds from GatewayTransferNative contracts using withdrawToNativeChain.

### Summary

in GatewayTransferNative.Sol the function `withdrawToNativeChain` can be used by users to move their zrc20 tokens back to their native chains. But due to failure to ensure that the token deposited is equal to the `from token` in the swap parameter and the difference in decimals, an attacker can steal all zrc20 tokens in the contract.

### Root Cause

When users try to withdraw zrc20 tokens, the function [withdrawToNativeChain](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L600) is called.
```solidity

The issue here is that if there is a difference in the token transferred in by the caller and the one in the message passed in by the caller, it can be exploited to steal other zrc20 tokens in the contract due to the difference in their decimals.

### External Pre-conditions

According to Zeta chain docs [supported assets list](https://www.zetachain.com/docs/developers/tokens/zrc20/#supported-assets) there are multiple zrc20 tokens with 6 decimals and 18 decimals .


### Attack Path

* contract zrc20 USDC.AVAX balance is 300,000 dollars (300,000e6)
* An attacker calls withdrawToNativeChain with zrc20 as an 18 decimal token (eg ETH.ARB) and amount 3e11
* Tranfers in the zrc20 ETH.ARB amount (3e11) which is a micro small amount.
* The attacker passes a message which has a`MixSwapParams params`, which has values `params.fromToken` = USDC.AVAX and `params.fromTokenAmount` = 300,000e6.
* In _doMixSwap the approval is given using `params.fromToken`, which is unverified and the swap is carried out using the contract's balance.
* Then after some more logic `withdrawAndCall` is called, moving assets to the attacker on the other chain.
* Therefore, the attacker drains the contract of all 300k worth of USDC tokens for basically nothing.

### Impact

The attacker will drain all zrc20 tokens of lower decimals in the contract.

### PoC

_No response_

### Mitigation

The ``withdrawToNativeChain` function should ensure that the token transferred in by the caller is the same as that in the swap param.
