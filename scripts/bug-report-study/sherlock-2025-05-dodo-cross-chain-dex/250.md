# Missing ETH and token recovery mechanism leads to potentially stuck funds

### Summary

The absence of an owner-controlled withdrawal function will cause a loss of access to ETH or tokens for the contract owner as any actor can send funds to the contract via `receive` or `fallback`, but the owner will be unable to retrieve them due to missing withdrawal logic.

### Root Cause

In `GatewaySend.sol`, the contract includes [`receive()` and `fallback()`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L406-L408) functions to accept ETH, but there is no corresponding function to allow the owner to withdraw or recover ETH, leading to potentially stuck funds.

### Internal Pre-conditions

1. Any user needs to send ETH directly to the contract (via `receive()` or `fallback()`) to increase the contract's ETH balance to at least 1 wei.
2. The contract must not implement any function that allows the owner to withdraw or recover ETH or tokens.
3. The owner needs to lose access to the funds once they are sent, as the balance remains locked within the contract with no retrieval path.

### External Pre-conditions

1. An external user or contract sends tokens or ETH to `GatewaySend` via a direct transfer
2. The ZetaChain gateway or DODO protocol refunds excess ETH to GatewaySend as part of cross-chain or swap execution flows.
3. Gas prices remain stable enough that attackers or users do not avoid accidental transfers due to excessive fees.

### Attack Path

1. Any external user sends ETH directly to the `GatewaySend` contract, triggering the `receive()` or `fallback()` function.
2. The ETH is accepted and added to the contract’s balance, as there is no logic preventing the deposit.
3. The contract owner attempts to recover the ETH but finds there is no withdraw or superWithdraw function implemented.
4. The ETH remains permanently locked in the contract with no authorized way to retrieve it, effectively causing a loss of funds.

### Impact

The contract owner cannot recover ETH or tokens accidentally sent to the contract, leading to stuck funds. Any ETH or tokens received via the `receive()` or `fallback()` functions become permanently inaccessible, resulting in a loss for the sender and unmanageable contract balances.

### Mitigation

Implement an owner-only withdrawal function like the following to enable recovery of stuck ETH and tokens:
```solidity
function superWithdraw(address token, uint256 amount) external onlyOwner {
    if (token == _ETH_ADDRESS_) {
        require(amount <= address(this).balance, "INVALID_AMOUNT");
        TransferHelper.safeTransferETH(EddyTreasurySafe, amount);
    } else {
        require(amount <= IERC20(token).balanceOf(address(this)), "INVALID_AMOUNT");
        TransferHelper.safeTransfer(token, EddyTreasurySafe, amount);
    }
}
```
This will allow the owner to safely withdraw any ETH or ERC20 tokens held by the contract, preventing permanent loss of funds.
