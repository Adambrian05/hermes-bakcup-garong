# User can underpay the fee in withdrawToNativeChain when setting amount lower then msg.value

### Summary

Users can underpay protocol fees when calling withdrawToNativeChain with ZETA as the native token by setting amount < msg.value, potentially bypassing intended fee mechanics and causing protocol loss.

### Root Cause

When a user calls the withdrawToNativeChain function with Zeta (native token) as fromToken (set in swapParams) and as zrc20, but sends msg.value = 1000 ZETA and sets amount = 1 ZETA, the fee paid will be very small (assuming the problem with the inability to pay fees using ZETA is fixed).
If amount is set to 0, no fee would be paid to the protocol (EddyTreasurySafe).
The issue stems from not checking whether amount is equal to or greater than msg.value.

Since the user is allowed to understate the amount, they can pay significantly lower (or zero) fees than they should. This results in financial loss for the protocol.

### Attack Path

1. User calls withdrawToNativeChain with amount set to less than msg.value, and both fromToken and zrc20 set to the native token.
2. Fee is calculated and paid (assuming the inability to pay fee when zrc20 token is native token issue is fixed), but due to amount < msg.value, the fee is smaller than it should be.
3. _doMixSwap is called and the swap is executed.
4. Withdrawal process is initiated.
5. User receives the target ERC20 on the destination chain, having paid a reduced or zero fee.



### Impact

Users can underpay fee by setting amount < msg.value, resulting in minimal or no fee being transferred to the protocol and potential revenue loss to the protocol.
