# Incorrect Gas Fee Comparison in _handleEvmOrSolanaWithdraw Prevents Valid Withdrawals

## Description
The problem arises from the function _handleEvmOrSolanaWithdraw.

The function onCall calls  the function _handleEvmOrSolanaWithdraw which has issue in the check, the check if (gasFee >= outputAmount) revert NotEnoughToPayGasFee(), if outputAmount == gasFee, it could prevent valid withdrawals where the output exactly matches the gasFee.
```solidity
if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
```
The condition gasFee >= outputAmount will revert the transaction even when outputAmount == gasFee, which might not be the intended behavior. In this case:

The user may be deliberately withdrawing an amount equal to the required gas fee.

No value would be transferred to the receiver, but it may still be a valid operational use case (e.g. signaling, zero-value tx).

This logic prevents such transactions entirely, possibly excluding valid use cases.
Impact
Prevents valid withdrawals where the entire outputAmount is intended to cover only the gas fee.

Causes user-facing transactions to fail unnecessarily.

        bytes32 externalId,
        DecodedMessage memory decoded,
        uint256 outputAmount,
        bytes memory receiver

        (address gasZRC20, uint256 gasFee) = IZRC20(decoded.targetZRC20).withdrawGasFeeWithGasLimit(1);

        if (decoded.targetZRC20 == gasZRC20) {
            if (gasFee >= outputAmount) revert NotEnoughToPayGasFee();
            IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);

            bytes memory data = SwapDataHelperLib.buildOutputMessage(
                externalId, 
                outputAmount - gasFee, 
                decoded.receiver, 
                decoded.swapDataB
            );
            
            bytes memory encoded = (decoded.dstChainId == SOLANA_EDDY)
                ? AccountEncoder.encodeInput(AccountEncoder.decompressAccounts(decoded.accounts), data)
                : data;

            withdrawAndCall(
                externalId, 
                decoded.contractAddress, 
                decoded.targetZRC20, 
                outputAmount - gasFee, 
                receiver, 
                encoded
            );

            amountsOutTarget = outputAmount - gasFee;
        } else {
            revert("Not implemented");
        }
    }

    function withdrawAndCall(
        bytes32 externalId,
        address contractAddress,
        address zrc20,
        uint256 amount,
        bytes memory receiver,
        bytes memory encoded

        GatewayMock(gateway).withdrawAndCall(externalId, contractAddress, zrc20, amount, receiver, encoded);

        DecodedMessage memory decoded,
        uint256 outputAmount,
        bytes memory receiver

        return _handleEvmOrSolanaWithdraw(externalId, decoded, outputAmount, receiver);
    }

## Recommendation
Update the condition to:
```solidity
if (gasFee > outputAmount) revert NotEnoughToPayGasFee();
```
This allows exact-fee payments and ensures only underfunded withdrawals are blocked.
