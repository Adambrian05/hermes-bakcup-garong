# Missing Zeta Amount Validation

### Summary

Missing validation that `msg.value` equals `amount` parameter will cause transaction reverts or accounting inconsistencies for users as any user can pass mismatched values leading to failed operations or incorrect contract state.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L530-L555

### Root Cause

In `GatewayTransferNative.sol:withdrawToNativeChain` when `zrc20 == _ETH_ADDRESS_`, the function uses the `amount` parameter for all calculations but doesn't verify that `msg.value` matches this `amount`, creating potential for inconsistent state or failed transactions.

Check out a similar report [here](https://solodit.cyfrin.io/issues/excess-fees-retention-in-assetcontroller-halborn-lucid-labs-contracts-v1-markdown)

### Internal Pre-conditions

1. User needs to call `withdrawToNativeChain()` with `zrc20` parameter set to `_ETH_ADDRESS_`
2. User needs to send `msg.value` that differs from the `amount` parameter

### External Pre-conditions

None

### Attack Path

1. User calls `withdrawToNativeChain()` with `zrc20 = _ETH_ADDRESS_`, `amount = 10 Zeta`, but sends `msg.value = 100 Zeta`
2. Function calculates platform fees based on `amount` (10 Zeta) instead of actual received Zeta (100 Zeta)
3. Contract receives 100 Zeta but only deducts 10 Zeta worth of fees
4. User gets processed for 10 Zeta swap while contract holds the extra 90 Zeta

### Impact

Users may accidentally send incorrect Zeta amounts leading to locked funds in the contract or failed transactions. The contract may accumulate excess Zeta that doesn't get properly accounted for in the fee structure.

### Mitigation

```diff
function withdrawToNativeChain(
    address zrc20,
    uint256 amount,
    bytes calldata message
) external payable {
    if(zrc20 != _ETH_ADDRESS_) {
        require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
+   } else {
+       require(msg.value == amount, "Zeta_AMOUNT_MISMATCH");
    }
```
