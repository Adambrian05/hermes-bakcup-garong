# Users will receive lesser assets than expected

### Summary

Everywhere in the `GatewayCrossChain` and `GatewayTransferNative` contracts, they approve the gateway to pull `outputAmount + gasFee` tokens but then instructs it to withdraw only `outputAmount - gasFee`. This mismatch means the actual tokens received by the user are significantly less than intended, and leaves an excess allowance unused (or potentially locked).

### Root Cause

```solidity
IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount + gasFee);
withdraw(externalId, decoded.receiver, decoded.targetZRC20, outputAmount - gasFee);
```

- The approved amount (`outputAmount + gasFee`) is larger than the withdrawn amount (`outputAmount - gasFee`), where the user expects to receive `outputAmount` amount of assets but receive only `outputAmount - gasFee` amount of assets.

### Impact

- **User Receives Less Than Expected**: Instead of receiving outputAmount - gasFee, users end up with an even smaller balance; effectively, an extra gasFee is never withdrawn nor refunded.

- **Excess Allowance Locked**: The gateway holds permission for more tokens than it ever pulls, potentially leaving tokens stranded or exposed to misuse until the allowance is reset.

- **Confusing Accounting & UX**: Both end users and integrators will see inconsistent balances, making reconciliation difficult and eroding trust in the cross-chain flow.
