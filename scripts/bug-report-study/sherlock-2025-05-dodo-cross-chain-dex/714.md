# Send::depositAndCall doesn't ensure asset == params.toToken

### Summary

`depositAndCall` in the `GatewaySend` contract doesn’t validate if the `asset`, passed as an argument, matches the swapData’s `toToken` parameter, also provided by the user, which should be the token received from the Dodo swap.

[[GatewaySend](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L219)](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-blckhv/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L219)

```solidity
function depositAndCall(
    address fromToken,
    uint256 amount,
    bytes calldata swapData,
    address targetContract,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {

    // Swap on DODO Router
    uint256 outputAmount = _doMixSwap(swapData);
else {
        _handleERC20Deposit(
            targetContract,
            outputAmount,
            asset,
            message,
            revertOptions
        );
    }

    emit EddyCrossChainSend(
        externalId,
        dstChainId,
        fromToken,
        asset,
        amount,
        outputAmount,
        msg.sender,
        message
    );
}

function _doMixSwap(bytes calldata swapData) internal returns (uint256) {//OK
    MixSwapParams memory params = SwapDataHelperLib.decodeCompressedMixSwapParams(swapData);

    if(params.fromToken != _ETH_ADDRESS_) {
        IERC20(params.fromToken).approve(DODOApprove, params.fromTokenAmount);
    }

    return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
        params.fromToken,
        params.toToken,
        params.fromTokenAmount,
        params.expReturnAmount,
        params.minReturnAmount,
        params.mixAdapters,
        params.mixPairs,
        params.assetTo,
        params.directions,
        params.moreInfo,
        params.feeData,
        params.deadline
    );
}

```

As a result, anyone can steal any residue tokens from the `GatewaySend` by manipulating the swap outcome with their own `toToken` and `fromToken`, but pass a valid, whitelisted token, whose entire balance can be stolen.

### Root Cause

Insufficient validation of the asset, which will be passed to the Zeta’s `GatewayEVM` contract to be bridged to `ZEVM`, is the same as the token that is received from the DODO swap.

### Internal Pre-conditions

- Any whitelisted token’s balance in the `GatewaySend` to be non-zero.

### External Pre-conditions

### Attack Path

1. Let’s say there are 500 USDC tokens in the `GatewaySend`.
2. Attacker creates his own pair contract, with 2 malicious tokens, of which he controls the mint/burn functions, so he can define the exact ratio that will give `outputAmount` =< `500`.
3. Attacker calls the `depositAndCall` by passing `asset = USDC`, `params.fromToken == fromToken` and `params.toToken` are his own tokens, `amount` doesn’t matter since the `outputAmount` gets passed to `GatewayEVM`.
4. Dodo router does the swap and returns 500 `toToken`.
5. `_handleERC20Deposit` uses this `outputAmount` to invoke the `gateway.depositAndCall` and does an Inbound transaction which grants the Attacker USDC on ZEVM:

```solidity
function depositAndCall(
    address fromToken,
    uint256 amount,
    bytes calldata swapData,
    address targetContract,
    address asset,
    uint32 dstChainId,
    bytes calldata payload
) public payable {

    // Swap on DODO Router
    uint256 outputAmount = _doMixSwap(swapData);
else {
        _handleERC20Deposit(
            targetContract,
            outputAmount,
            asset,
            message,
            revertOptions
        );
    }

    emit EddyCrossChainSend(
        externalId,
        dstChainId,
        fromToken,
        asset,
        amount,
        outputAmount,
        msg.sender,
        message
    );
}

function _handleERC20Deposit(
    address targetContract,
    uint256 amount,
    address asset,
    bytes memory message,
    RevertOptions memory revertOptions
) internal {
    IERC20(asset).approve(address(gateway), amount);

    gateway.depositAndCall(
        targetContract,
        amount,
        asset,
        message,
        revertOptions
    );
}
```

### Impact

Tokens can be stolen from the `GatewaySend` contract.

### PoC

N/A

### Mitigation

Add a check if the `toToken == asset`.
