# Possible token loss if external contract (e.g. DODO Router) turns malicious.

### Summary

Using an example: `token1A -> ETH -> token3Z -> token2Z`, when a user calls `GatewaySend::depositAndCall` to execute a cross-chain swap, they specify an `amount` and a `payload` that contains the amount of token3Z they want to swap for token2Z on the destination chain (i.e ZetaChain). In the process `GatewayTransferNative::_doMixSwap` is called and `amount` is used to approve the DODO Router to spend an allowance, while `params.fromToken` is the amount that is used for the swap on ZetaChain. 

It is possible for `params.fromTokenAmount` to be less than `amount` since this is not enforced; and after the swap it leaves a surplus of the `fromToken` in the `GatewayTransferNative` contract and a non-zero spending allowance. Leaving a non-zero allowance after such a swap exposes `GatewayTransferNative` to possible theft of funds if external contracts turn malicious.

### Root Cause

In [`GatewayTransferNative::_doMixSwap`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L425-L449), token approvals remain and are not reset to 0 after the call to the DODO Router:
```solidity
        IZRC20(params.fromToken).approve(DODOApprove, amount);
        return IDODORouteProxy(DODORouteProxy).mixSwap{value: msg.value}(
            params.fromToken,
            params.toToken,
            params.fromTokenAmount,
            params.expReturnAmount,
            params.minReturnAmount,
            params.mixAdapters,
            params.mixPairs,
            params.assetTo,
            params.directions,
            params.moreInfo,
            params.feeData,
            params.deadline
        );
    }
```

### Impact

If token approvals and fully not revoked, the surplus from the swap remains available for the DODO Router to spend, exposing funds to possible theft from the external contract if it turns malicious.

### PoC

The cross-chain swap path is as follows: token1A -> ETH -> token3Z -> token2Z. And based on the ratio set up in the test suite, we expect `100` token1A to yield `300` token2Z at the end of the swap. But in this test, the parameters for the swap on ZetaChain specifies only `100` token3Z to swap for token2Z, thus the recipient only receives `100` token2Z, but `200` token3Z remains in `GatewayTransferNative`.

```solidity
    // A native token swap - zetachain swap: token1A -> ETH -> token3Z -> token2Z
    // Expected if swap using correct amounts: 1 token1A = 3 ETH = 3 token3Z = 3 token2Z
    function test_ANativeSwap2ZSwap() public {
        address targetContract = address(gatewayTransferNative);
        uint256 amount = 100 ether;
        uint32 dstChainId = 7000;
        address fromToken = address(token1A);
        address asset = _ETH_ADDRESS_;
        bytes memory swapDataA = encodeCompressedMixSwapParams(
            address(token1A),
            _ETH_ADDRESS_,
            amount, // 100 ether
            0,
            0,
            new address[](1),
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0),
            block.timestamp + 600
        );
        address targetZRC20 = address(token2Z);
        bytes memory sender = abi.encodePacked(user1);
        bytes memory receiver = abi.encodePacked(user2);
        bytes memory swapDataZ = encodeCompressedMixSwapParams(
            address(token3Z),
            address(token2Z),
            amount, // 100 ether
            0,
            0,
            new address[](1),
            new address[](1),
            new address[](1),
            0,
            new bytes[](1),
            abi.encode(address(0), 0),
            block.timestamp + 600
        );
        bytes memory payload = encodeNativeMessage(
            targetZRC20,
            sender,
            receiver,
            swapDataZ
        );

        vm.startPrank(user1);
        token1A.approve(
            address(gatewaySendA),
            amount
        );
        gatewaySendA.depositAndCall(
            fromToken,
            amount,
            swapDataA,
            targetContract,
            asset,
            dstChainId,
            payload
        );
        vm.stopPrank();

        assertEq(token1A.balanceOf(user1), initialBalance - amount);
        assertEq(token2Z.balanceOf(user2), 100000000000000000000);  //100 because only 100 token3Z was swapped to token2Z
        assertEq(token3Z.balanceOf(address(gatewayTransferNative)), 200 ether); //300 token3Z remains in the contract
        assertEq(token3Z.allowance(address(gatewayTransferNative), address(dodoRouteProxyZ)), 200 ether); //unrevoked allowance
    }
```
