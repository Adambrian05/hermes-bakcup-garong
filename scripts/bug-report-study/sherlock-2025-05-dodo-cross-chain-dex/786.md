# One `gasLimit` being set, there isn't any other function to reupdate, which may cause unwanted behavior in future

### Summary

After the `initialize` function of `GatewaySend`, `GatewayTransferNative`, `GatewayCrossChain`, there isn't any set function for `gasLimit`, which says the gas limit for `onRevert` function, which may cause unwanted behavior if the gas usage of the `onRevert` function increases

### Root Cause

The root cause for the function is after the `initialize` function in 3 core contracts of the codebase, In the below code we can see that `gasLimit` is being set, but the issue here is that there isn't any function in `GatewayTransferNative`, `GatewayCrossChain` contracts to set `gasLimit` again unlike remaining variables.

```solidity
    function initialize(
        address payable _gateway,
        address _EddyTreasurySafe,
        address _dodoRouteProxy,
        address _dodoApprove,
        uint256 _feePercent,
        uint256 _slippage,
        uint256 _gasLimit
    ) public initializer {
        __Ownable_init(msg.sender);
        __UUPSUpgradeable_init();
        gateway = GatewayZEVM(_gateway);
        EddyTreasurySafe = _EddyTreasurySafe;
        DODORouteProxy = _dodoRouteProxy;
        DODOApprove = _dodoApprove;
        feePercent = _feePercent;
        slippage = _slippage;
        gasLimit = _gasLimit;
    }
```

`gasLimit` is being used in the [`withdraw`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L277-L295) and [`withdrawAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244-L269) functions of universal contracts in zetachain. We can see that while assigning the revert option it sets the `onRevertGasLimit` to the variable in the contract

`onRevert` function triggers for cross-chain transaction reversion, so if the gas usage of that function exceeds the `gasLimit` then the transaction reverts and cross-chain transaction got aborted and user again need to call [`claimRefund`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L571-L590) to claim those stuck assets in the destination chain universal contract
