# `GatewayTransferNative::onCall` don't decrease `amount` when platform fee is deducted

### Summary

In [onCall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395-L396), a fixed `feePercent` is taken from the transferred `zrc20` token. However, we don't decrease the `amount` provided when it is done:
```solidity
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        address receiver = address(uint160(bytes20(decoded.receiver)));
```

In the `(decoded.targetZRC20 == zrc20)` branch we correctly decrease it in the `safeTransfer` block, but in the `else` branch we pass the raw `amount` to `_doMixSwap` func.

The impact is even bigger because in `_doMixSwap` we use `params.fromTokenAmount`, which is amount contolled by the user, so he can use all token balance that is approved to `DODO Approve`. In such case a victim may not be able to claim his refund because the contract balance may be only 0.05% below `refundInfo.amount`, which will result in revert on the following line:
`TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);`


### Root Cause

Not decreasing `amount` after fee deduction in `GatewayTransferNative::onCall` function

### Internal Pre-conditions

None


For resulting in further impact -> A condition is that there are funds in the contract (waiting for refunds)

### External Pre-conditions

None

### Attack Path

1. Victim's transaction aborts and has `refundInfo` for 1000 tokens
2. Exploiter bridges 1000 zrc20 and 0.5% is 5 tokens which are transferred to the treasury
3. However, we approve dodo router for 1000 and user from token amount = 1000
4. After the exploiter transaction, `GatewayTransfer` contract balance becomes 995 
5. If the victim tries to call `claimRefund`, tx will fail because `refundInfo.amount == 1000`

### Impact

Using stale funds (waiting to be refunded) to pay protocol fees

### PoC

_No response_

### Mitigation

In `GatewayTransferNative::onCall` override `amount` after `_handleFeeTransfer` with the decreased and use the amount in both if/else branches
