# Slippage calculated on current market price resulting to  huge risk

### Summary

_swapAndSendERC20Tokens() applies slippage to real-time price calculations , providing no MEV protection.




### Root Cause

fn [getAmountsIn( UniswapFactory, gasFee,getPathForTokens(targetZRC20, gasZRC20))](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L309) uses current pool state (already price-adjusted) to calculate `amountsQuote` for the targetZRC20 inorder to swap for the  `gasFee` amount of ZRC20.

Later the slippage is added on top of the calculated `amountsQuote ` which has already undergone the price calulcation.[code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L315)

```solidity
function _swapAndSendERC20Tokens(
......
    ) internal returns(uint256 amountsOut) {
        // Get amountOut for Input gasToken
        uint[] memory amountsQuote = UniswapV2Library.getAmountsIn(
            UniswapFactory,
            gasFee,
            getPathForTokens(targetZRC20, gasZRC20) // [targetZRC, gasZRC] or [targetZRC, WZETA, gasZRC]
        );

 =>  uint amountInMax = (amountsQuote[0]) + (slippage * amountsQuote[0]) / 1000; //@audit-issue incorrect usage of slippage
        IZRC20(targetZRC20).approve(UniswapRouter, amountInMax);
        ..........
}

```

Slippage added to current price ≠ protection against price movement.



### Internal Pre-conditions

slippage parameter configured (typically 0.5-5%)
Function called during cross-chain gas fee payment

### External Pre-conditions

Volatile market conditions or MEV activity

### Attack Path

Uniswap order :  Quote: 200 zrctokenA for 0.1 zrctokenB 
MEV bot monitors mempool - Sees pending transaction
Front-run attack - Bot manipulates pool price to 230 zrctokenA /0.1 zrctokenB 
getAmountsIn() returns 230 zrctokenA (current inflated price)
slippage applied to manipulated price: 230 + 1.15 = 231.15 zrctokenA 
User overpays 231.15 zrctokenA instead of expected ~210 zrctokenA (15.5% loss)
 Bot back-runs to restore original price and profits from spread

### Impact

Receive from user a userQuote as a pareameter in the payload and apply slippage on it.
