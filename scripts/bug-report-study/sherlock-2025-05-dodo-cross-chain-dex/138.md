# Return Value Ignored in ERC20 Transfers

### Summary



In your contract, several calls to IERC20.transfer(...) and IERC20.transferFrom(...) do not check the return value:

Example 1 – in onCall():

if (!fromIsETH) {
    IERC20(fromToken).transferFrom(msg.sender, address(this), amount); //  No return check
}
...
IERC20(toToken).transfer(evmWalletAddress, outputAmount); //  No return check



Example 2 – in depositAndCall():

IERC20(asset).transferFrom(msg.sender, address(this), amount); // This one is checked


Why This Is Dangerous
The ERC20 standard (as per OpenZeppelin) defines:


function transfer(address recipient, uint256 amount) external returns (bool);
But not all ERC20 tokens strictly follow the standard. Some:

Return false on failure rather than reverting.

Silently fail and return false, without throwing.

Still succeed in execution, but transfer no tokens.

If you ignore the return value, your contract may assume a transfer succeeded when it didn’t — causing:

Cross-chain swaps to be underfunded.

onCall to transfer 0 tokens.

User funds to appear missing or "lost".




 Real-World Risk
For tokens like:

USDT (Tether) on Ethereum — returns bool but doesn’t revert on failure.

Custom or proxy ERC20s — may have non-standard implementations.

### Mitigation


You must always check the return value from any transfer or transferFrom call:


require(IERC20(fromToken).transferFrom(msg.sender, address(this), amount), "TRANSFER_FROM_FAILED");
require(IERC20(toToken).transfer(evmWalletAddress, outputAmount), "TRANSFER_FAILED");
Or, use OpenZeppelin’s SafeERC20:


Edit
import { SafeERC20 } from "@openzeppelin/contracts/token/ERC20/utils/SafeERC20.sol";

SafeERC20.safeTransferFrom(IERC20(fromToken), msg.sender, address(this), amount);
SafeERC20.safeTransfer(IERC20(toToken), evmWalletAddress, outputAmount)
