# Incorrect Fee Deduction in onCall Leads to User incorrect payment

### Summary

In the onCall function, the contract calculates and transfers platform fees (platformFeesForTx) but fails to deduct them from the input amount before executing swaps. As a result, users receive more output tokens than intended, while the protocol loses potential revenue from the fee portion that should have been excluded from swaps.

### Root Cause

Fees are correctly deducted in the "same token" transfer case (if (decoded.targetZRC20 == zrc20)).

Not deducted in the swap path (else branch), where the full amount (including fees) is passed to _doMixSwap.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L395

### Attack Path

1. User submits a swap:

Sends 1000 USDT (input) with a 0.5% fee (5 USDT).

2. Bug triggers:

_handleFeeTransfer sends 5 USDT to the treasury.

_doMixSwap uses 1000 USDT (instead of 995 USDT) for the swap.

3. User gains extra tokens:

Receives swap output for 1000 USDT (e.g., 1100 DAI at 1.1x rate) instead of 995 USDT (expected 1094.5 DAI).

Profit: +5.5 DAI (difference due to fee not being deducted).

If protocol does not have funds then swap will not be executed and function will revert.

### Impact

The swap operates on an inflated input amount, converting the fee portion into extra tokens for the user leads to loss of funds for the protocol if protocol has funds otherwise swap will not be executed.
