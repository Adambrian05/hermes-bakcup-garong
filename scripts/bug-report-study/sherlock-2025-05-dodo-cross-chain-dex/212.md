# function `GatewaySend::onRevert` does not handle if the original asset is native token

### Summary

`GatewaySend::onRevert` only assume the asset token is ERC20 or similar, it does not handle well if the original asset from original chain is a native token.

### Root Cause

the issue happen because faulty logic in [GatewaySend.sol#L393-L404](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L393-L404):

```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
        bytes32 externalId = bytes32(context.revertMessage[0:32]);
        address sender = address(uint160(bytes20(context.revertMessage[32:])));
@>        TransferHelper.safeTransfer(context.asset, sender, context.amount);
        
        emit EddyCrossChainRevert(
            externalId,
            context.asset,
            context.amount,
            sender
        );
    }
```

because of how zeta chain can handle native token like ETH where it would be converted to ZRC-20 equivalent, then it is expected that the original asset is also can be a native token.
but here in the function it would only use the library `TransferHelper.safeTransfer` which only compatible with ERC20 or similar.

### Attack Path

1. victim create cross chain swap via `GatewaySend::depositAndCall` using ETH native token to receive token X at zetachain
2. the `onCall` in universal app function revert (caused by slippage for example), and because the amount sent can cover gas fee in zetachain, it then proceed to continue the revert via the `GatewaySend::onRevert` on the original chain
3. but this function `onRevert` also revert because it use native token originally and it wants to use ERC20 transfer call to send native token

### Impact

if the `onRevert` function that is called by gateway revert, it would prevent the user to claim their funds from failed transaction.
this effectively a loss of user funds.
even if the `onAbort` would be invoked in the zeta chain, user needs to claim then bridge back the ETH into the ETH chain by paying fees for their funds to sent back.
