# ETH Refund Failure in onRevert() Function

### Summary

The GatewaySend.onRevert() function fails to properly handle native ETH refunds when cross-chain transactions fail. The function uses TransferHelper.safeTransfer() for all assets including ETH, but this helper is designed only for ERC20 tokens. When ETH refunds are attempted, the transaction fails or ETH becomes permanently stuck in the contract, preventing users from recovering their funds after failed cross-chain ETH transfers.

### Root Cause

The onRevert() function treats all assets uniformly using ERC20 transfer methods, without accounting for ETH's different transfer mechanism:
```solidity
function onRevert(RevertContext calldata context) external onlyGateway {
    bytes32 externalId = bytes32(context.revertMessage[0:32]);
    address sender = address(uint160(bytes20(context.revertMessage[32:])));
    TransferHelper.safeTransfer(context.asset, sender, context.amount); // Fails for ETH
    // ...
}
```

When context.asset equals _ETH_ADDRESS_ (0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE), TransferHelper.safeTransfer() attempts to call the transfer() method on this address, which doesn't exist as an ERC20 contract, causing the transaction to fail.

### Attack Path

1. Alice wants to bridge 5 ETH from Ethereum to Polygon
2. Alice calls depositAndCall() with 5 ETH
3. Contract successfully receives ETH and forwards to ZetaChain Gateway
4. Cross-chain transaction fails due to network congestion on Polygon
5. ZetaChain Gateway sends 5 ETH back to GatewaySend contract
6. Gateway calls onRevert() with context.asset = _ETH_ADDRESS_
7. Contract attempts TransferHelper.safeTransfer(_ETH_ADDRESS_, alice, 5 ETH)
8. TransferHelper tries to call transfer() on address 0xEeeeeEeeeEeEeeEeEeEeeEEEeeeeEeeeeeeeEEeE
9. Transaction reverts because no contract exists at that address
10. 5 ETH remains stuck in GatewaySend contract
11. Alice cannot recover her funds

### Impact

Users cannot recover ETH from failed cross-chain transactions leads to loss of user funds.
