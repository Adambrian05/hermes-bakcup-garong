# Incorrect Amount Validation in _swapAndSendERC20Tokens

### Summary

Incorrect amount validation in `_swapAndSendERC20Tokens` will cause a complete failure of legitimate transactions for end-users as the validation logic incorrectly uses `amountInMax` instead of `amounts[0]`.

### Root Cause

In [`GatewayTransferNative.sol:L333` ](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L333) and [`GatewayCrossChain.sol:L329`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L329)`, the validation uses `amountInMax` instead of `amounts[0]`:
`require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`


It should use the actual consumed token amount (`amounts[0]`) instead of the maximum allowed (`amountInMax`).

### Internal Pre-conditions

1. User needs to perform a cross-chain swap where `targetZRC20` differs from `gasZRC20`.
2. The `targetAmount` needs to be close to `amountInMax` (within the slippage buffer range).
3. The `slippage` parameter to be set to any non-zero value.

### External Pre-conditions

1. Uniswap liquidity pools need to have normal liquidity depth.
2. No extreme price volatility causing abnormal slippage.

### Attack Path

1. User initiates a cross-chain swap from chain A to chain B with different target and gas tokens.
2. The contract calculates `amountInMax = amountsQuote[0] + (slippage * amountsQuote[0]) / 1000`.
3. The swap executes successfully using `amounts[0]` (which is less than `amountInMax`).
4. The validation check `require(targetAmount - amountInMax > 0)` fails because `amountInMax` includes slippage buffer.
5. Transaction reverts despite having sufficient funds for the actual swap.

### Impact

The users cannot complete cross-chain swaps even with sufficient funds, resulting in failed transactions and gas losses. Users lose the gas fees paid for failed transactions.

### PoC

```solidity
// Scenario: User has 1000 targetTokens, needs 100 gasTokens
// amountsQuote[0] = 95 (tokens needed for 100 gas tokens)
// slippage = 50 (5%)
// amountInMax = 95 + (50 * 95) / 1000 = 99.75
// amounts[0] (actual used) = 95

// User's targetAmount = 1000
// Check: require(1000 - 99.75 > 0) ✓ passes
// But if targetAmount = 100:
// Check: require(100 - 99.75 > 0) ✗ fails (0.25 > 0)
// Even though only 95 tokens were actually used!
```
```solidity
// Simplified PoC


function testIncorrectAmountValidation() public {
    // Case 1: Legitimate transaction that should succeed but fails
    uint targetAmount = 100 ether;
    uint gasFee = 10 ether;
    
    // Uniswap quotes we need 95 tokens to get 10 gas tokens
    uint amountsQuote = 95 ether;
    uint slippage = 50; // 5%
    
    // Contract calculates max amount with slippage
    uint amountInMax = amountsQuote + (amountsQuote * slippage) / 1000; // 99.75 ether
    
    // Actual swap only uses 95 ether (amountsQuote)
    uint actualAmountUsed = 95 ether;
    
    // Bug: Contract checks against amountInMax instead of actualAmountUsed
    // This will fail: require(100 - 99.75 > 0) = require(0.25 > 0) ✗
    require(targetAmount - amountInMax > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
    
    // Should be: require(100 - 95 > 0) = require(5 > 0) ✓
    // require(targetAmount - actualAmountUsed > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");
}
```

### Mitigation

Replace the validation with:
`require(targetAmount - amounts[0] > 0, "INSUFFICIENT_AMOUNT_FOR_WITHDRAW");`
