# `onCall` Dependency on GatewayEVM ERC20 Approval

__Summary:__ The successful reception of ERC20 tokens in the `onCall` function is critically dependent on the GatewayEVM contract having previously granted sufficient approval to the `GatewaySend` contract.

__Vulnerability Detail:__ When a cross-chain transfer involves an ERC20 token as the source asset, the GatewayEVM contract is expected to call `GatewaySend.onCall` on the destination chain. Within `onCall`, the contract attempts to pull the ERC20 tokens from the GatewayEVM's address (`msg.sender`) using `IERC20(fromToken).transferFrom(msg.sender, address(this), amount);`. This operation will only succeed if the GatewayEVM contract has previously approved `GatewaySend` to spend the specified `amount` of `fromToken`.

__Impact:__ This is not a direct exploit vector for external attackers but represents a significant integration risk. If the GatewayEVM contract fails to correctly manage or provide the necessary ERC20 approvals to `GatewaySend` before calling `onCall`, all cross-chain receive operations for that specific ERC20 token will fail, preventing users from accessing their assets on the destination chain.

__Recommendation:__ Ensure robust and verified coordination between the GatewayEVM and GatewaySend contracts regarding ERC20 token approvals for cross-chain transfers. The GatewayEVM must guarantee that sufficient approval is set before initiating the onCall on the destination chain.
