# Missing input validation will cause complete protocol denial-of-service for all users

### Summary

Missing bounds validation in fee setting functions will cause a complete denial-of-service for all users as operational errors, key compromise, or accidental misconfiguration will trigger arithmetic reverts in all cross-chain transactions.

### Root Cause

In [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L142-L145) and [GatewayTransferNative.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L143-L146), the `setFeePercent()` function lacks input validation, creating a systemic vulnerability where any fee value ≥ 1000 (100%) causes arithmetic underflow in subsequent operations:
```solidity
function setFeePercent(uint256 _feePercent) external onlyOwner {
    feePercent = _feePercent;  // ❌ NO BOUNDS VALIDATION
    emit FeePercentUpdated(_feePercent);
}
```

The vulnerability exists in the fee calculation logic in `_handleFeeTransfer()` where `amount -= platformFeesForTx` will underflow when fees exceed 100%.

### Internal Pre-conditions

1. Fee percentage needs to be set to at least 1000 (100%) through `setFeePercent()`
2. Users need to initiate cross-chain transactions via `onCall()` or `withdrawToNativeChain()`

### External Pre-conditions

None required.

### Attack Path

1. Owner calls `setFeePercent()` with value ≥ 1000 during routine administrative operations (due to misconfiguration, typo, or misunderstanding of fee basis)
2. Any user attempts cross-chain operation via `onCall()` or `withdrawToNativeChain()`
3. Contract calculates `platformFeesForTx = (amount * feePercent) / 1000` resulting in fees exceeding input amount
4. Arithmetic underflow protection triggers revert in `amount -= platformFeesForTx`
5. All subsequent user transactions fail, causing complete protocol denial-of-service

### Impact

All users cannot execute any cross-chain transactions due to systematic transaction failures. The protocol becomes completely unusable until the fee is corrected through owner intervention. This represents a critical single point of failure affecting 100% of protocol functionality, with no user funds directly stolen but complete loss of protocol utility.

### PoC

```solidity
function test_MissingInputValidation_DoS() public {
    // Any value accepted
    gatewayCrossChain.setFeePercent(1500); // 150% fee accepted
    assertEq(gatewayCrossChain.feePercent(), 1500);
    
    // Mathematical DoS condition in fee calculation
    uint256 amount = 100 ether;
    uint256 platformFeesForTx = (amount * 1500) / 1000; // 150 ether
    
    // Underflow condition that breaks all transactions
    bool causesUnderflow;
    assembly {
        causesUnderflow := lt(amount, platformFeesForTx) // 100 < 150 = true
    }
    assertTrue(causesUnderflow);
    
    console.log("Amount:", amount);
    console.log("Calculated fee:", platformFeesForTx); 
    console.log("Underflow condition:", causesUnderflow);
    
}
```

### Mitigation

Implement proper input validation with reasonable bounds to prevent operational errors and limit blast radius of potential compromises:
```solidity
uint256 public constant MAX_FEE_PERCENT = 100; // 10% maximum fee

function setFeePercent(uint256 _feePercent) external onlyOwner {
    require(_feePercent <= MAX_FEE_PERCENT, "Fee exceeds maximum allowed");
    feePercent = _feePercent;
    emit FeePercentUpdated(_feePercent);
}
```
