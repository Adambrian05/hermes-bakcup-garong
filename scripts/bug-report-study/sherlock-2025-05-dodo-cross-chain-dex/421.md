# `withdrawToNativeChain` will not work with native Zeta token

### Summary

`withdrawToNativeChain` allows users on Zeta chain to directly withdraw a ZRC20 onto its native chain. The function is payable which allows users to send the native Zeta token to swap. The problem is `_handleFeeTransfer` would fail as it does not properly handle native token transfers.

### Root Cause

`withdrawToNativeChain` is payable, meaning users have the option to send the native Zeta token and swap it to another token before withdrawing to another chain. We can see that this function is expected to handle this behavior from this check.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L535C9-L537C11
```Solidity
        if(zrc20 != _ETH_ADDRESS_) {
            require(IZRC20(zrc20).transferFrom(msg.sender, address(this), amount), "INSUFFICIENT ALLOWANCE: TRANSFER FROM FAILED");
        } 
```
The problem is that `_handleFeeTransfer` does not handle native token transfers. When transferring the fee to the treasury, this call would fail.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol#L346

### Internal Pre-conditions

1. `GatewayTransferNative` is deployed to Zeta chain

### External Pre-conditions

1. Gateway is up and running

### Attack Path

1. User calls `withdrawToNativeChain` and sends native Zeta token
2. User defines a swap path to swap from Zeta to native chain token
3. Call will fail in `_handleFeeTransfer` when it attempts to send Zeta as a ZRC20 token

### Impact

`withdrawToNativeChain` will not work with the native Zeta gas token

### PoC

_No response_

### Mitigation

For the fee transfer, if the zrc20 address = _ETH_ADDRESS_, use the `safeTransferETH` function to transfer the fee in `TransferHelper`
