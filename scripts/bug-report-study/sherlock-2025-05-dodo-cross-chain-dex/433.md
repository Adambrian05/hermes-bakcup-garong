# `GatewaySend.depositAndCall()` can be use to drain the destination chain gas payer

### Summary

Malicious users can simply spam the `GatewaySend.depositAndCall()` function in low gas fee EVM chains to exploit the cross-chain messaging function since they do not need to pay for the message transfer.



https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L287

### Root Cause

The `GatewaySend::depositAndCall()` function can be used for depositing an `amount` of tokens forwarding the a `payload` message. However, it is not certain how the gas on the destination chain is paid by the `msg.sender` and also the amount being sent is not checked to be greater than zero. HEnce a malicious user can call `depositAndCall()` repeatedly or with `msg.sender` equal to zero or 1wei making it possible to create a large number of cross-chain transactions (cctx) from a Connected Chain to ZetaChain in a way that depletes the Threshold Signature Scheme (TSS) funds for gas payments

### Attack Path


- An attacker holds the equivalent of one million dollars in USDC or Native token on ZERC20
- calls `GatewaySend::depositAndCall()` repeatedly with 1 wei or 0 `msg.sender`
- deposit is triggered on `gateway` and the TSS is made to pay for the transaction
- the attacker continues this until the TTS is drained fully


I Assume the TSS pays for the transaction on the Zeta chain for this issue but regardless, if that is not the case and payment of gas is required for deposits on the Zeta chain, then the function will revert since no funds are sent for gas payment purposes.


### Impact

Loss of funds as TSS is drained without without the user paying for transactions

### PoC

_No response_

### Mitigation

Consider implementing gas payment when `GatewaySend.depositAndCall()` is called.
