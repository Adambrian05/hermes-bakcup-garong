# Native and crossChain Gateways’s onCall/onAbort functions fails to account for a situation in which zrc20 token == ZETA

### Summary

Both GatewayCrossChain and GatewayNative fail to account a situation in which the ZRC20 token being received/bridged is ZETA or the native token.

This leads to one of two impacts:
- Broken functionality: The Zeta token can't be transferred to the user on destination leading to triggering revert flows;
- Loss of funds: Considering that onAbort isn't equipped to handle native tokens as well, and onAbort on Zeta is triggered in all cases when a revert fails, this will lead to loss of funds.

### Root Cause

This report will focus on two aspects of this vulnerability:
1. The inability of onCall to process native tokens on both the native and cross-chain gateways;
2. The inability of onAbort to process the native token aborts/reverts;

To focus on the first aspect/impact, imagine the following scenario. A user triggered a ZETA token bridge from Ethereum Mainnet to ZetaChain. The `onCall` flow on the GatewayNative is invoked:

```solidity

 function onCall(
        MessageContext calldata context,
        address zrc20,
        uint256 amount,
        bytes calldata message
    ) external override onlyGateway {
        // Decode the message
        // 32 bytes(externalId) + bytes message
        (bytes32 externalId) = abi.decode(message[0:32], (bytes32)); 
        bytes calldata _message = message[32:];
        (DecodedNativeMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeNativeMessage(_message);

        // Fee for platform
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        address receiver = address(uint160(bytes20(decoded.receiver)));

        if (decoded.targetZRC20 == zrc20) {
            // same token
            TransferHelper.safeTransfer(
                decoded.targetZRC20,
                receiver,
                amount - platformFeesForTx
            );
        } else {
            // Swap on DODO Router
            uint256 outputAmount = _doMixSwap(decoded.swapData, amount, params);

            if (decoded.targetZRC20 == WZETA) {
                // withdraw WZETA to get Zeta in 1:1 ratio
                IWETH9(WZETA).withdraw(outputAmount);
                // transfer wzeta
                TransferHelper.safeTransferETH(receiver, outputAmount);
            } else {
                TransferHelper.safeTransfer(
                    decoded.targetZRC20,
                    receiver,
                    outputAmount
                );
            }

```

The call would always revert as the `_handleFeeTransfer` will try to take the fee out of it by treating it as a regular ZRC20, rather than the native token:

```solidity

    function _handleFeeTransfer(
        address zrc20,
        uint256 amount
    ) internal returns (uint256 platformFeesForTx) {
        platformFeesForTx = (amount * feePercent) / 1000; // platformFee = 5 <> 0.5%
        TransferHelper.safeTransfer(zrc20, EddyTreasurySafe, platformFeesForTx);
    }

```

This will of course fail.

The second point to the vulnerability is if the onRevert flow on the connected chain fails, and onAbort is triggered on Zeta with the native token:

```solidity

 function onAbort(AbortContext calldata abortContext) external onlyGateway {
        // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
        bytes32 externalId = bytes32(abortContext.revertMessage[0:32]);
        bytes memory walletAddress = abortContext.revertMessage[32:];

        RefundInfo memory refundInfo = RefundInfo({
            externalId: externalId,
            token: abortContext.asset,
            amount: abortContext.amount,
            walletAddress: walletAddress
        });
        refundInfos[externalId] = refundInfo;
        
        emit EddyCrossChainRefund(
            externalId,
            abortContext.asset,
            abortContext.amount,
            walletAddress
        );
    }

```

The funds can't be taken out, as `claimRefund` has no mechanism to handle native transfers OR wrap the tokens prior to the native transfer:

```solidity
    function claimRefund(bytes32 externalId) external {
        RefundInfo storage refundInfo = refundInfos[externalId];

        address receiver = msg.sender;
        if(refundInfo.walletAddress.length == 20) {
            receiver = address(uint160(bytes20(refundInfo.walletAddress)));
        }
        require(bots[msg.sender] || msg.sender == receiver, "INVALID_CALLER");
        require(refundInfo.externalId != "", "REFUND_NOT_EXIST");
        
        TransferHelper.safeTransfer(refundInfo.token, receiver, refundInfo.amount);
        delete refundInfos[externalId];

        emit EddyCrossChainRefundClaimed(
            externalId,
            refundInfo.token,
            refundInfo.amount,
            abi.encodePacked(msg.sender)
        );
    }

```
