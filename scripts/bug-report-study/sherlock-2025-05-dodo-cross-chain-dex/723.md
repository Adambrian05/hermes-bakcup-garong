# User can avoid the platform fee by creating their own universal contract without platform fee functionality

### Summary

When user tries to do cross-chain transfer from source chain to zetachain, user gets charged for the platform fee by the protocol apart from the withdraw fee (in simple terms gets charged by Zetachain). So we cannot avoid the withdraw fee because of cross-chain transaction been done by Zetachain, but we can avoid the platform fee by creating our own universal contract (i.e., contract in place of [`GatewayTransferNative`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayTransferNative.sol) contract). Which makes user to use the protocol without letting protocol gain anything from cross-chain transactions

### Root Cause

The main issue is the function [`GatewaySend::depositAndCall`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L287-L293) where user calls this function to initiate the cross-chain transaction, which eventually turn user funds in source chain to desired tokens in the destination chain.

Here in this function user provides the `targetContract`, the universal contract which calls `onCall` function in the Zetachain blockchain. As user can provide it himself, he can write his own fork contract of `GatewayTransferNative` excluding the platform fee part of code. 

If we put `targetContract` as the `GatewayTransferNative` contract, then the protocol charges some fee for the pathway for cross-chain transaction, but actually we can avoid it just by simply pointing the `GatewayZEVM` contract in zetachain to our own contract, where functionality is same as of `GatewayTransferNative`.

### Attack Path

- user creates his own fork contract of `GatewayTransferNative` contract
- point the `GatewayZEVM` to this fork contract instead of `GatewayTransferNative` contract in `GatewaySend::depositAndCall` function using `targetContract` parameter
- Avoid the platform fee charged by the `GatewayTransferNative` contract

### Impact

The impact is high-critical for the protocol. Because of the cross-chain transaction protocol doesn't gain anything, if most user exploit this issue, then there will be severe losses for the protocol, as they would have already burned funds of the production and auditing the protocol. So in the end of the day if most users exploit protocol will be end up in loses
