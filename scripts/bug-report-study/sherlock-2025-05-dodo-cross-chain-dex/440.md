# Protocol fails to validate cross-chain message data against actual gateway holdings causing transaction failures

## Summary

**The protocol fails to validate user-provided message data against actual gateway holdings, causing legitimate cross-chain transactions to fail when the message format doesn't match the tokens actually received by the gateway.**

## Root Cause
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L341-L359

In `GatewaySend.sol`, the `onCall` function trusts user-provided message data instead of validating against actual gateway holdings available in `context.asset` and `context.amount`.

```solidity
function onCall(MessageContext calldata /*context*/, bytes calldata message) {
    (bytes32 externalId, uint256 amount, bytes calldata recipient, 
     address fromToken, address toToken, bytes calldata swapData) = decodePackedMessage(message);
    
    // Protocol trusts message data instead of actual gateway holdings
    if(!fromIsETH) {
        IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
    }
}
```

This design is inconsistent with other protocol contracts like `GatewayCrossChain.onCall` which correctly use actual received tokens as parameters rather than trusting message data.

## Internal Pre-conditions

1. Cross-chain swap where source chain performs intermediate token conversion for optimization
2. Message payload constructed based on user's original intent rather than actual cross-chain token
3. Gateway receives different token than what message claims

## External Pre-conditions

None required - this occurs during normal protocol operation when frontend/integration constructs messages based on user intent rather than actual cross-chain tokens.

## Attack Path

1. **User initiates cross-chain swap** with message specifying `fromToken = USDC, amount = 1000e6`
2. **Cross-chain transfer occurs** with ZetaChain converting USDC to ZRC20-USDC during transit
3. **Gateway receives ZRC20-USDC** (`context.asset = ZRC20_USDC_ADDRESS, context.amount = 1000e6`)
4. **Message still claims** original token: `fromToken = USDC_ADDRESS` 
5. **onCall executes transfer** `IERC20(USDC_ADDRESS).transferFrom(gateway, this, 1000e6)`
6. **Transaction fails** because gateway holds ZRC20-USDC, not original USDC

## Impact

**Protocol breaks core cross-chain functionality for legitimate users when reasonable message construction patterns are used. Users experience failed transactions and funds stuck in gateway until revert mechanisms are triggered, significantly degrading protocol reliability.**
