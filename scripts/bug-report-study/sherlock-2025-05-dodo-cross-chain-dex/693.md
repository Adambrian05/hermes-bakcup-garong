# Asset confusion in `withdrawToNativeChain` allows swapping unauthorized funds


### Summary
The `withdrawToNativeChain` function in `GatewayTransferNative` is vulnerable to an asset confusion attack.

Allows malicious user to use any cheap token of his choice at a low cost, to withdraw valuable tokens that belongs to other users.

### Root Cause
The function `withdrawToNativeChain` decodes `MixSwapParams` from a user-crafted `message`. It then calls `_doMixSwap`, which uses these malicious parameters. 

GatewayTransferNative::withdrawToNative does not have the necessary validation of the swap parameters (`params.fromToken`, `params.fromTokenAmount`) that match the assets that were actually deposited into the function (`zrc20`, `amount`) as shown [here](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayTransferNative.sol#L543-L555)
```solidity
 function withdrawToNativeChain(
        address zrc20,
        uint256 amount,
        bytes calldata message
    ) external payable {
// ...
        // Decode message and decompress swap params
        (DecodedMessage memory decoded, MixSwapParams memory params) = SwapDataHelperLib.decodeMessage(message);
        
        // Check if the message is from Bitcoin to Solana
        // address evmWalletAddress = (decoded.dstChainId == BITCOIN_EDDY || decoded.dstChainId == SOLANA_EDDY)
        //     ? msg.sender
        //     : address(uint160(bytes20(decoded.receiver)));

        // Transfer platform fees
        uint256 platformFeesForTx = _handleFeeTransfer(zrc20, amount); // platformFee = 5 <> 0.5%
        amount -= platformFeesForTx;

        // Swap on DODO Router
        uint256 outputAmount = _doMixSwap(decoded.swapDataZ, amount, params);
// ...
}
```

### Internal Conditions

For example: 

1.  The `GatewayTransferNative` contract holds 100_000e6 `zUSDC` from prior failed transactions.
### External Conditions

1. Pool exists for any asset like `ZetaChain Bridged ETH`.

### Attack Path

1. Attacker calls `GatewayTransferNative::withdrawToNativeChain` with:
    *   `zrc20`: SHIB.ETH (very cheap token)
    *   `amount`: 100_000e6 (for amount of zUSDC the contract has)
    *   `message`: A crafted payload that specifies `MixSwapParams` to swap zUSDC for `ZetaChain Bridged ETH`. Important details include:
    - decoded.swapData : new bytes("abc"); // so that swapData.length != 0
    - decoded.receiver : attackerWallet
    - decoded.targetZRC : `ZetaChain Bridged ETH`
    - decoded.dstChainId : BITCOIN_EDDY
    - MixSwapParams.fromToken : zUSDC
    - MixSwapParams.toToken : `ZetaChain Bridged ETH`

2. `_doMixSwap` is excuted and approves `fromToken` which is zUSDC, executes the swap to receive 100_000e6 zUSDC worth of `ZetaChain Bridged ETH`.

3. `_handleBitcoin` withdraw is executed where the contract will approve targetZRC20 (`ZetaChain Bridged ETH`) to gateway, and withdraw the funds to an address of attacker's choice `decoded.receiver`

### Impact

1. GatewayTransferNative is left with 100_000e6 worth of zSHIB.ETH, which is worth nothing.

2. Attacker gets away with valuable tokens from swapping funds that doesn't belong to him.
