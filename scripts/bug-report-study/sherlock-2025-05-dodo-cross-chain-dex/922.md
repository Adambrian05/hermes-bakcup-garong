# `ERC20::approve` will revert for USDT

### Summary

USDT will revert if the current allowance is greater than 0 and an non-zero approval is made. There are multiple instances throughout the contracts where this can cause issues. In (GatewaySend.sol::_handleERC20Deposit)[https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L177] this can create scenario where it becomes impossible to deposit or swap in (GatewayCrossChain::_swapAndSendERC20Tokens) [https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L302]

### Root Cause

Revert if the target token is USDT

N/A

N/A

N/A

### Impact

Functionality won't work for `depositAndCall`, `onCall` functions in `GatewaySend.sol` and the swap functionality in `GatewayCrossChain.sol`, `GatewayTransferNative.sol`

### PoC

_No response_

### Mitigation

Use `SafeERC20`'s `forceApprove` method instead to support all the ERC20 tokens.
