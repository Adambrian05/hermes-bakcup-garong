# Incorrect Return Value Causes Gateway to Treat All Callbacks as Failures

### Summary

Returning bytes4(0) in onCall() will cause complete failure of cross-chain transfers for users and the protocol as the gateway will treat every callback as a failed transaction.

### Root Cause

    In the onCall function's return statement, return ""; is used instead of returning IGatewayEVM.onCall.selector.

    This violates the gateway interface requirement where a valid function selector must be returned to indicate successful message processing.

(https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L341C5-L386C6)

### Internal Pre-conditions

    The gateway must call onCall() to execute a cross-chain transfer.

    The function must complete token transfers and swaps without reverting.

### External Pre-conditions

    A valid cross-chain message must be delivered by the gateway.

### Attack Path

    User initiates a cross-chain transfer via the gateway.

    Gateway delivers the message to onCall() on the destination chain.

    Contract processes the transfer and outputs tokens to the recipient.

    Function returns bytes4(0).

    Gateway interprets bytes4(0) as failure and reverts source-chain operations.

### Impact

    Users suffer permanent loss of funds: tokens are released on the destination chain, but the source-chain transaction reverts, locking/burning the original assets.

    Protocol loses all cross-chain functionality. Approximate loss: 100% of transferred value per transaction.

### PoC

_No response_

### Mitigation

Replace return ""; with something like this :
```solidity

return IGatewayEVM.onCall.selector;

Add interface definition:
solidity

interface IGatewayEVM {
    function onCall(MessageContext calldata, bytes calldata) external payable returns (bytes4);
}

```
