# Anyone can claim refund and steal tokens

### Summary

whenever a cross chain transaction fails,The `Gateway` contract calls the `onRevert` function in the `GatewayCrossChain.sol` contract to revert the cross-chain swap. The refund of the user's transaction is then stored in the `refundInfos[externalId]` mapping to then be claimed by a verified bot or the user using the `claimRefund()` function but the function lacks critical check fault allowing any user to claim the refunds of users. 

### Root Cause

whenever a cross chain transaction fails,The `Gateway` contract calls the `onRevert` function in the `GatewayCrossChain.sol` contract to revert the cross-chain swap.

https://github.com/Skyewwww/omni-chain-contracts/blob/2fe44d3da76b721e4d32addfecb04ca97a39cb0d/contracts/GatewayCrossChain.sol#L517

in this function, it checks if the length of the revert message is exactly 52.

https://github.com/Skyewwww/omni-chain-contracts/blob/2fe44d3da76b721e4d32addfecb04ca97a39cb0d/contracts/GatewayCrossChain.sol#L522

else, the refundInfo is set in the mapping `refundInfos[externalId]` where a user or the bot can claim the refund of the failed transaction using the `claimRefund()` function.

Now lets look at the `claimRefund()`.

https://github.com/Skyewwww/omni-chain-contracts/blob/2fe44d3da76b721e4d32addfecb04ca97a39cb0d/contracts/GatewayCrossChain.sol#L571

First the function sets the receiver as the `msg.sender` and then it checks if the wallet address length in the `refundInfos[externalId]` mapping is equall to 20.If it is 20 it sets the receiver as the wallet address.
The main problem in the function is that there is no obligation that the walletAddress has to be the length of 20 bytes `(eg:- solana addresses are 32 bytes long)`,This is where the main bug in the function.

https://github.com/Skyewwww/omni-chain-contracts/blob/2fe44d3da76b721e4d32addfecb04ca97a39cb0d/contracts/GatewayCrossChain.sol#L578

The function requires a valid bot or the receiver to be the msg.sender of the call.This statement is broken as the receiver is already set as the `msg.sender` previously.The function then transfers the token to the receviver and deletes the mapping.Thus anyone with a valid `externalId` of a reverted transaction can call this `claimRefund()` function and can claim the refund.

### Internal Pre-conditions
1. a cross chain transaction must revert
2. when the gateway calls the onRevert, the context.revertMessage.length must be less than or greater than 52 and the refundInfo.walletAddress must be a solana address.

### External Pre-conditions
nil


### Attack Path

1. Alice initiates a cross chain transaction by transferring 100 usdc.
2. The transaction fails and the Gateway contract initiates the withdrawal process by calling the onRevert function and alice's refund info is stored in the `refundInfos[externalId]` mapping.
3. Bob sees that Alice's transaction has failed by monitoring the blockchain and gets the `externalId` of Alice's transaction.
4. Bob calls the `claimRefund()` function with alice's `externalId` and steals the tokens of alice.

### Impact

User's will lose all the tokens when their cross-chain transaction reverts as anyone can call the refund and claim the any user's tokens.
