# User can lose funds due to incorrect slippage handling in _swapAndSendERC20Tokens function

### Summary

The misuse of `slippage` in `_swapAndSendERC20Tokens` will cause a loss of funds for users as an attacker will frontrun the transaction and inflate the swap cost.

### Root Cause

In `gatewaycrosschain.sol : _swapAndSendERC20Tokens` , the slippage buffer is added to the input quote `(amountsQuote[0])` and passed as `amountInMax` to `swapTokensForExactTokens`. However, since this quote and the swap occur in the same transaction, the slippage is not a protection mechanism — it only defines how much the user is willing to overpay. If an attacker frontruns the transaction and increases the cost of the output token, the user’s transaction still succeeds but pays far more than expected.

### Internal Pre-conditions

1.The function _swapAndSendERC20Tokens is publicly or indirectly callable via a user-facing function.

2.The slippage parameter is set to a nonzero value, allowing the protocol to overspend input tokens.

3.There is no additional price validation (e.g., TWAP or min-acceptable-rate checks).

### External Pre-conditions

1.The attacker monitors the public mempool and detects a pending _swapAndSendERC20Tokens transaction.

2.The attacker has enough targetZRC20 or gasZRC20 to manipulate the price in the Uniswap pool.

3.Uniswap pools used are public and unprotected from MEV (no private routing or RPC).

### Attack Path

1.Attacker sees a pending _swapAndSendERC20Tokens(...) call in the mempool.

2.Attacker sends a frontrun transaction that increases the price of gasZRC20 in the Uniswap pool by buying it heavily with targetZRC20.

3.When the victim's transaction executes, getAmountsIn calculates amountsQuote[0] based on the now-inflated price.

4.The transaction proceeds with a higher amountInMax, allowing the swap to consume far more targetZRC20 than the user expected.

5.Attacker sends a backrun transaction to reverse the price movement and capture the spread.

### Impact

The user suffers a loss equal to the extra `targetZRC20` spent during the swap. The attacker profits from the manipulated price differential. This allows MEV-style sandwiching, and may result in complete depletion of user funds, especially if the slippage buffer is high.
