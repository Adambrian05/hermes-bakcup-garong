# the usage of address(0) as `abortAddress` would cause user funds stuck in the contract

### Summary

in the gateway contract, the `abortAddress` would be used if in zeta chain the `onRevert` calls revert.
the `abortAddress` would then calls `onAbort` to proceed with the function flow.

but at the current implementation of both `GatewayCrossChain` and `GatewayTransferNative`, the `abortAddress` is zero address. this would cause revert on call and makes the user fund for claim are not accounted inside the contract.

### Root Cause

there are multiple instance of this:

```solidity

                revertAddress: address(this),
                callOnRevert: true,

```

which are implemented inside `withdraw` and `withdrawAndCall` function.

this is problematic as if the function `onRevert` revert, it would not have any fallback for `onAbort` as if the `onAbort` address is zero it would revert in `GatewayZEVM` contract:

```solidity
    /// @notice Call onAbort on a user-specified contract on ZEVM.
    /// this function doesn't deposit the asset to the target contract. This operation is done directly by the protocol.
    /// the assets are deposited to the target contract even if onAbort reverts.
    /// @param target The target contract to call.
    /// @param abortContext Abort context to pass to onAbort.
    function executeAbort(
        address target,
        AbortContext calldata abortContext
    )
        external
        nonReentrant
        onlyProtocol
        whenNotPaused
    {
@>        if (target == address(0)) revert ZeroAddress();
        Abortable(target).onAbort(abortContext);
    }
```

### Attack Path

1. user call withdraw to withdraw ZRC-20 token to original chain
2. the function revert
3. it would then invoke `onRevert` on our gateway contract
4. the onRevert itself revert (in case not enough gas or anyelse), thus proceed to `onAbort` in `abortAddress`
5. because `abortAddress` is zero address, the function revert
6. the funds now unaccounted toward user claim funds and cant be claimed

### Impact

stuck funds which is equal to user loss of funds

### PoC

_No response_

### Mitigation

its preferred to assign `abortAddress` to `address(this)` like `revertAddress`.
as the contract already have `onAbort` function that later would save the claim fund amount to be claimed back by user
