# Redundant Token Authorization in `_handleBitcoinWithdraw`



## Finding description and impact

The `_handleBitcoinWithdraw` function grants approval for `outputAmount + gasFee` to the gateway contract. However, the actual withdrawal process only consumes `outputAmount - gasFee`.

This results in an excessive authorization of `gasFee * 2`.

## code snippet : https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L370

Potential impacts:

* Tokens authorized beyond necessary requirements could be exploited if the gateway becomes compromised or exhibits unexpected behavior
* Allowances remain active between transactions, building up over time which expands the attack surface for token drainage vulnerabilities

This breaches the principle of minimal privilege.

## Mitigation

Authorize only the precise amount that will be consumed:

* If `withdraw` processes the gas fee independently:
  ```solidity
  IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount - gasFee);
  ```

* If `gateway` handles gas fee deduction internally:
  ```solidity
  IZRC20(decoded.targetZRC20).approve(address(gateway), outputAmount);
  ```
