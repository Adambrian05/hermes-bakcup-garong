# onCall function doesn't validate who the CCTX initiator is

### Summary

`onCall` function in all the 3 Dodo Gateway contracts doesn’t verify who the [`[MessageContext::sender](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/evm/interfaces/IGatewayEVM.sol#L229)`](https://github.com/zeta-chain/protocol-contracts/blob/2e61e029e89792c1b10ed15d2aa19818a77dd4d8/contracts/evm/interfaces/IGatewayEVM.sol#L229) is and allows everyone to perform malicious calls from 1 chain and drain the funds on the receiver. As a result, any to-be refunded residue tokens can be stolen.

### Root Cause

Missing check for the source chains initiator in the destination `onCall` functions. 

Users can perform cross chain calls with a malicious payload that can target arbitrary logic from the contracts, steal funds (since payload is distinct from the token and the amount user has locked on the source chain’s Gateway) or overwrite refunds with custom `externalId`.

### Internal Pre-conditions

None

### External Pre-conditions

None

### Attack Path

1. Arbitrary user initiates [`[depositAndCall](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/evm/GatewayEVM.sol#L292-L345)`](https://github.com/zeta-chain/protocol-contracts/blob/v13.1.0-rc1/contracts/evm/GatewayEVM.sol#L292-L345) from his own contract, where he passes either 1 of the 2 DODO Gateways on Zetachain as the recipient and a maliciously crafted payload, which can be successfully decoded, once it arrives.

Furthermore, he can also craft his own malicious `RevertOption::revertMessage` to include an arbitrary `externalId` (to overwrite pending refund, causing the real recipient to lose his tokens), since `externalIds` don’t include the amount and they’re used in the `onRevert` and `onAbort` functions.

```solidity
function depositAndCall(
    address receiver,
    uint256 amount,
    address asset,
    bytes calldata payload,
    RevertOptions calldata revertOptions
)
    external
    whenNotPaused
{
    if (amount == 0) revert InsufficientERC20Amount();
    if (receiver == address(0)) revert ZeroAddress();
    if (payload.length + revertOptions.revertMessage.length > MAX_PAYLOAD_SIZE) revert PayloadSizeExceeded();

    _transferFromToAssetHandler(msg.sender, asset, amount);

    emit DepositedAndCalled(msg.sender, receiver, amount, asset, payload, revertOptions);
}
```

> It’s important to note that, he can lock as low as 1 wei of a given token, since `message` is the one responsible for indicating the due amount.

1. At this point, there are many bad consequences that an attacker can cause, we outline 3 major:
    1. He can intentionally `revert` and cause the `onRevert` function to be called, which will add him to the `refundInfo` mapping
    2. He can steal all the `residue` ZRC20/ERC20 tokens from the contracts (1 example is tokens sent from the bots to satisfy the refunds)
        
        This is possible since the amount and asset that are passed as arguments to the Zeta’s GatewayEVM contract (the actual tokens that are locked) are decoupled from the ones that can be encoded in the payload
        
    3. For TransferNative and CrossChain contracts, he can overwrite `refundInfo` of another user, by passing an existing in the `refundsInfo` mapping `externalId`. That way, the attacker can modify all 4 params of the `RefundInfo` struct. 
    
    ```solidity
    function onRevert(RevertContext calldata context) external onlyGateway {
            // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
            bytes32 externalId = bytes32(context.revertMessage[0:32]);
            bytes memory walletAddress = context.revertMessage[32:];
    
            if(context.revertMessage.length == 52) {
                address receiver = address(uint160(bytes20(walletAddress)));
                TransferHelper.safeTransfer(context.asset, receiver, context.amount);
    
                emit EddyCrossChainRevert(
                    externalId,
                    context.asset,
                    context.amount,
                    walletAddress
                );
            } else {
                RefundInfo memory refundInfo = RefundInfo({
                    externalId: externalId,
                    token: context.asset,
                    amount: context.amount,
                    walletAddress: walletAddress
                });
                refundInfos[externalId] = refundInfo;
                
                emit EddyCrossChainRefund(
                    externalId,
                    context.asset,
                    context.amount,
                    walletAddress
                );
            }
        }
    
        function onAbort(AbortContext calldata abortContext) external onlyGateway {
            // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
            bytes32 externalId = bytes32(abortContext.revertMessage[0:32]);
            bytes memory walletAddress = abortContext.revertMessage[32:];
    
            RefundInfo memory refundInfo = RefundInfo({
                externalId: externalId,
                token: abortContext.asset,
                amount: abortContext.amount,
                walletAddress: walletAddress
            });
            refundInfos[externalId] = refundInfo;
            
            emit EddyCrossChainRefund(
                externalId,
                abortContext.asset,
                abortContext.amount,
                walletAddress
            );
        }
    ```
    

### Impact

Loss of funds of the Dodo contract or users who haven’t claimed their refunds.
