# Missing Return Value Checks for ERC20 transfer in onCall

### Summary

The `onCall` function uses `IERC20(toToken).transfer(...)` to send tokens to the final recipient but does not check the boolean return value of this call.

[Link to code](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L369-L383).

Related code:
```solidity
// ...existing code...
        if(toIsETH) {
            payable(evmWalletAddress).transfer(outputAmount);
        } else {
            IERC20(toToken).transfer(evmWalletAddress, outputAmount); // Issue: Return value not checked
        }
        
        emit EddyCrossChainReceive(
            externalId,
            fromToken,
            toToken,
            amount,
            outputAmount,
            evmWalletAddress,
            message
        );
// ...existing code...
```

### Root Cause

Many ERC20 tokens, including some widely used ones (like USDT), return false on transfer failure instead of reverting. If such a token transfer fails silently (returns false), the onCall function will continue execution as if the transfer succeeded, emitting an EddyCrossChainReceive event that inaccurately suggests success. The funds, however, would remain in the GatewaySend contract, potentially lost to the intended recipient.

### Attack Path

1. `onCall` is invoked by the gateway, carrying a message for token distribution.
2. The message is decoded, and `toToken` is identified as an ERC20 token.
3. If a swap occurs via `_doMixSwap`, `outputAmount` is determined.
4. The contract calls `IERC20(toToken).transfer(evmWalletAddress, outputAmount)`.
5. If this specific toToken returns `false` on failure (e.g., recipient is a blocked address, or token has internal transfer issues), the `GatewaySend` contract does not check this boolean.
6. Execution continues, and `EddyCrossChainReceive` is emitted, logging the transaction as if successful.
7. The `evmWalletAddress` does not receive the tokens, and they remain in the `GatewaySend` contract.

### Impact

Impact: High - Users' funds may not reach them on the destination chain, and the system would incorrectly report success, leading to reconciliation issues and potential fund loss if the tokens are not recoverable. 

Likelihood: Medium - Dependent on the specific ERC20 tokens used. If tokens that return false on failure are processed, this issue is likely to manifest.

```solidity
        require(sender != address(0), "ERC20: transfer from the zero address");
        require(recipient != address(0), "ERC20: transfer to the zero address");
        require(_balances[sender] >= amount, "ERC20: transfer amount exceeds balance");
        _balances[sender] -= amount;
        _balances[recipient] += amount;
        emit Transfer(sender, recipient, amount);
    }

    function _approve(address owner, address spender, uint256 amount) internal virtual {
        require(owner != address(0), "ERC20: approve from the zero address");
        require(spender != address(0), "ERC20: approve to the zero address");
        _allowances[owner][spender] = amount;
        emit Approval(owner, spender, amount);
```

### Mitigation

Use a safe transfer library (like OpenZeppelin's SafeERC20 or the existing `TransferHelper.safeTransfer` which seems to be available) for all ERC20 transfer and `transferFrom` calls. `TransferHelper.safeTransfer` is already used in `onRevert`.
```solidity
// ...existing code...
        if(toIsETH) {
            // For ETH, ensure sufficient balance and handle potential failure of .transfer
            (bool success, ) = payable(evmWalletAddress).call{value: outputAmount}("");
            require(success, "ETH_TRANSFER_FAILED");
        } else {
            // Use TransferHelper for ERC20 tokens
            TransferHelper.safeTransfer(toToken, evmWalletAddress, outputAmount);
        }
        
        emit EddyCrossChainReceive(
            externalId,
            fromToken,
            toToken,
            amount,
            outputAmount,
            evmWalletAddress,
            message
        );
// ...existing code...
```
