# Platform Fee Bypass Through Cross-Chain Message Routing

## Summary
Missing platform fee validation in `GatewaySend.onCall` will cause a financial loss for the protocol treasury as users will bypass the intended 0.5% platform fee by routing `GatewayZEVM.withdrawAndCall` messages to `GatewaySend` contract instead of using `GatewayTransferNative`.

```solidity
// GatewayZEVM::withdrawAndCall

   function withdrawAndCall(
        bytes memory receiver,
        uint256 amount,
        address zrc20,
        bytes calldata message,
        CallOptions calldata callOptions,
        RevertOptions calldata revertOptions
    )
        external
        whenNotPaused
    {
        if (receiver.length == 0) revert ZeroAddress();
        if (amount == 0) revert InsufficientZRC20Amount();
        if (callOptions.gasLimit == 0) revert InsufficientGasLimit();
        if (message.length + revertOptions.revertMessage.length > MAX_MESSAGE_SIZE) revert MessageSizeExceeded();
```

## Root Cause
The choice to implement swap functionality in `GatewaySend.onCall` without platform fee collection is a mistake as it creates an alternative execution path that bypasses the fee mechanism present in `GatewayTransferNative._handleFeeTransfer`.

### Technical Analysis

#### The Problem
Two contracts provide identical swap functionality but different fee collection:

- **GatewayTransferNative**: Collects 0.5% platform fee 
- **GatewaySend.onCall()**: No fee collection 

#### Attack Flow

```js
1. User calls GatewayZEVM.withdrawAndCall()
   ├── receiver = GatewaySend contract address
   └── message = swap instructions

2. Cross-chain routing delivers message to GatewaySend

3. GatewaySend.onCall() executes swap
   ├── Performs token swap
   ├── NO fee collection
   └── Sends full amount to user
```


## Internal Pre-conditions
1. GatewaySend contract needs to be deployed on destination chain with known address
2. Platform fee percentage needs to be set to a non-zero value (typically 0.5%) in GatewayTransferNative
3. Cross-chain infrastructure needs to route messages to user-specified receiver addresses

## External Pre-conditions
None

## Attack Path
1. User calls `GatewayZEVM.withdrawAndCall()` with receiver parameter set to GatewaySend contract address
2. User crafts message parameter containing swap instructions (externalId, outputAmount, recipient, fromToken, toToken, swapData)
3. Cross-chain message gets routed to GatewaySend contract on destination chain
4. `GatewaySend.onCall()` automatically executes the swap without collecting platform fees
5. User receives swapped tokens while avoiding the 0.5% platform fee

## Impact
The protocol treasury suffers ongoing revenue loss of 0.5% on all cross-chain swaps executed through this bypass route. Users gain the avoided platform fee amount.

## Mitigation
Add platform fee collection logic in `GatewaySend.onCall` similar to `GatewayTransferNative._handleFeeTransfer` or restrict `GatewaySend` to only accept calls from authorized contracts.
