# An attacker can replay cross-chain messages to trigger unintended swaps or withdrawals multiple times, draining funds from the protocol.

### Summary

The absence of message replay protection in GatewayCrossChain.sol:onCall and onRevert will cause multiple processing of the same cross-chain message for the protocol, as an attacker can resend identical payloads to exploit swap or refund logic without limit.

### Root Cause

In [GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex-MihV1c-main/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol), the functions onCall() and onRevert() decode and execute cross-chain messages but do not maintain a processed state mapping to prevent the same message from being executed multiple times.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L442L511

### Internal Pre-conditions

1. Attacker submits a valid depositAndCall() cross-chain message with a unique externalId.
2. The onCall() or onRevert() function executes and processes the message correctly, releasing assets or performing a swap.
3. The contract does not mark the externalId or message hash as processed.

### External Pre-conditions

1. The LayerZero protocol permits receipt of identical messages (replayed through relayer or alternate channel).
2. Gas costs are low enough to allow the attacker to profit from repeated execution

### Attack Path

1.Attacker observes or generates a valid depositAndCall() message.
2. They allow the message to be processed once via onCall(), receiving a swap output or triggering a refund.
3. The attacker re-submits the same payload to lzReceive(), invoking onCall() again.
4. The protocol repeats the swap or refund due to absence of replay defense.
5. The attacker drains funds or doubles their output.

### Impact

The protocol suffers an unbounded financial loss equal to the maximum exploitable amount per message, multiplied by the number of replays. The attacker gains this full value in asset swaps or repeated refunds.


### PoC

_No response_

### Mitigation

Introduce a mapping like mapping(bytes32 => bool) public processedMessages; and enforce:

bytes32 key = keccak256(abi.encodePacked(externalId, msg.sender));
require(!processedMessages[key], "Replay detected");
processedMessages[key] = true;

This should be applied at the beginning of both onCall() and onRevert().
