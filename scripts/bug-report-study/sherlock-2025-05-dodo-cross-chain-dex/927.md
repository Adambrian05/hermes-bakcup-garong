# Incorrect ABI Decoding of Dynamic Arrays in AccountEncoder.sol

## Summary

The `decompressAccounts` function in the `AccountEncoder` library incorrectly decodes structs containing dynamic arrays (Account[] and bytes) that were encoded using `abi.encode`. This leads to misinterpretation of data lengths and offsets, resulting in corrupted or invalid deserialization of Account data.

## Root Cause

The `decompressAccounts` function's assembly code makes incorrect assumptions about the ABI encoding layout of dynamic arrays within a struct. Specifically, it expects the array length to be a uint16 and to immediately follow a preceding bytes object's data, which is not how `abi.encode` handles offsets and lengths for dynamic types (they are uint256 and stored as offsets within the static part of the encoding, with actual data and length appearing later).

When decoded.dstChainId is equal to SOLANA_EDDY, the AccountEncoder.decompressAccounts(decoded.accounts) function will be called. Due to the identified bug in decompressAccounts, if decoded.accounts contains ABI-encoded data of dynamic arrays (specifically, Account[]), the decompression will produce corrupted or incorrect Account data.
This corrupted data is then immediately passed to AccountEncoder.encodeInput for re-encoding. Consequently, the encoded bytes variable will contain invalid Account information, even if the original data part is correct. This will lead to:
Transaction failures or incorrect state updates on the SOLANA_EDDY chain, as the relayed account data will be fundamentally wrong.
https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewayCrossChain.sol#L398

## Impact

Attempts to decode Input structs containing Account[] and bytes will fail or produce incorrect Account data. 

## Mitigation

The `decompressAccounts` function must be refactored to accurately by correctly parsing 32-byte offsets and lengths for dynamic types, and adjusting memory pointers accordingly to retrieve `publicKey` and `isWritable` values.
