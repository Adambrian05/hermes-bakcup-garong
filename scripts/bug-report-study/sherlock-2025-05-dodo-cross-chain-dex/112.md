# Excess ETH Forwarding Causes Unintended Cross-Chain Value Transfer

## Root Cause:

In the `GatewaySend` contract's `depositAndCall` function, when handling ETH transfers, the code forwards the entire `msg.value` to the gateway instead of the user-specified `amount`. The function only verifies that `msg.value >= amount` but doesn't enforce equality or refund the excess. This excess ETH is silently forwarded to the destination chain while events report only the intended amount.

https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewaySend.sol#L307-L313

```solidity
if (isETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
    _handleETHDeposit(
        targetContract, 
        msg.value, // Problematic: Should be amount
        message, 
        revertOptions
    );
}
```
## Attack Path:
1. User intends to send 0.5 ETH cross-chain via `depositAndCall`
2. User specifies `amount = 0.5 ETH` in function parameters
3. Due to wallet UI confusion or manual error, user sends `msg.value = 1 ETH`
4. Contract checks `msg.value >= amount` which passes (1 ETH > 0.5 ETH)
5. Contract forwards entire 1 ETH to ZetaChain gateway
6. ZetaChain gateway transfers full 1 ETH to destination chain
7. Emitted event incorrectly shows only 0.5 ETH was transferred
8. User loses 0.5 ETH more than intended with no notification

## Impact:
1. **Unintended Value Loss**: Users can accidentally transfer more ETH than intended across chains, with no refund mechanism
2. **Silent Fund Drain**: No warnings or errors signal to the user that excess ETH is being forwarded
3. **Misleading Accounting**: Event logs show only the intended amount, not the actual transferred amount, creating data integrity issues
4. **User Confusion**: Users expecting DeFi-standard excess refund behavior will instead lose their excess funds
5. **Reduced Trust**: Unexpected fund behavior can damage protocol reputation and user trust

## Mitigation:
**One option is to enforce exact match**
```solidity
if (isETH) {
    require(msg.value == amount, "ETH amount must match exactly");
    _handleETHDeposit(
        targetContract,
        amount,
        message,
        revertOptions
    );
}
```
**or forward only specified amount and refund excess**

```solidity
if (isETH) {
    require(msg.value >= amount, "INSUFFICIENT AMOUNT: ETH NOT ENOUGH");
    _handleETHDeposit(
        targetContract,
        amount, // Only forward the specified amount
        message,
        revertOptions
    );
    
    // Refund any excess ETH
    uint256 excess = msg.value - amount;
    if (excess > 0) {
        (bool success, ) = msg.sender.call{value: excess}("");
        require(success, "ETH refund failed");
    }
}
```
