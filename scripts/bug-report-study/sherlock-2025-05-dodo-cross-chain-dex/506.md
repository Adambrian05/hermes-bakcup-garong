# Non-EOA wallet users may lose refund if cross chain swap reverts

### Summary

If CCTX reverts on outgoing flow (e.g. Zetachain -> Target chain), `GatewayCrossChain::onRevert` is invoked.

If target chain is EVM compatible and `receiver` is a bytes with 32 length, the contract will send ZRC-20 asset to the same address on **Zeta chain**.

However, there is no guarantee that target chain's receiver has the same wallet address on Zeta chain, especially if receiver is a non-EOA (e.g. a safe wallet).

Therefore, refund amount will be sent to incorrect address and user will face a significant loss.

### Root Cause

Root cause resides in `GatewayCrossChain::onRevert` function:

[File:omni-chain-contracts/contracts/GatewayCrossChain.sol](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L517-L524)
```solidity
517:     function onRevert(RevertContext calldata context) external onlyGateway {
518:         // 52 bytes = 32 bytes externalId + 20 bytes evmWalletAddress
519:         bytes32 externalId = bytes32(context.revertMessage[0:32]);
520:         bytes memory walletAddress = context.revertMessage[32:];
521: 
522:@>       if(context.revertMessage.length == 52) {
523:@>           address receiver = address(uint160(bytes20(walletAddress)));
524:@>           TransferHelper.safeTransfer(context.asset, receiver, context.amount);
```

- In L523, `receiver` represents a wallet address on target chain (e.g. Eth)
- In L524, `GatewayCrossChain` transfers refund amount to `receiver` on Zeta chain.

There's no guarantee that Ethereum wallet owner also owns the same address on Zeta chain, especially if receiver is a non-EOA (e.g. a safe wallet).

### Internal Pre-conditions

1. User initiates a cross chain swap with recipient set to a safe wallet on EVM chain
2. Target chain's contract's `onCall` method reverts
