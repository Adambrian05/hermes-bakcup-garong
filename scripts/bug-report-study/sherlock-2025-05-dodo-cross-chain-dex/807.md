# Strict ERC20 Interface Causes Transfer Failures with Non-Compliant Tokens

### Summary

The `GatewaySend` contract uses a strict `ERC20 `interface that expects `transferFrom `to return a bool in the `depositAndCall`  function. This design choice causes compatibility issues with popular some of the suppoted ERC20 tokens such as `USDT.ETH` (ZetaChain ZRC20 USDT on ETH), which do not return any value from `transferFrom`. As a result, transfers using these tokens will revert, potentially disrupting legitimate user operations.

### Root Cause

The contract assumes all supported `ERC20 `tokens strictly conform to the `ERC20 `standard by returning a bool in `transferFrom`. However, some supported tokens (e.g., USDT.ETH : `0xdAC17F958D2ee523a2206206994597C13D831ec7`) do not return any value, violating the standard. When the contract attempts to decode the return value as a `bool`, it fails due to insufficient return data and reverts the transaction.
