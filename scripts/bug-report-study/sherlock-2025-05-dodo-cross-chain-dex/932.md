# Incorrect configuration of `abortAddress` in the `withdrawAndCall` function leads to permanent loss of funds when a transaction aborts.

## Summary
The use of `address(0)` as `abortAddress` in `RevertOptions` will cause a permanent loss of funds for users as the protocol will transfer assets to the zero address on Chain B when `onRevert` on ZetaChain fails and triggers an abort.

## Root Cause
In `GatewayCrossChain.sol:withdrawAndCall`, the `RevertOptions` struct sets `abortAddress` to `address(0)`, which is a mistake as the protocol transfers assets to `abortAddress` on Chain B when `onRevert` on ZetaChain fails, resulting in funds being sent to the zero address and becoming unrecoverable.

[GatewayCrossChain.withdrawAndCall](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/d4834a468f7dad56b007b4450397289d4f767757/omni-chain-contracts/contracts/GatewayCrossChain.sol#L244-L244)

## Internal Pre-conditions
1. A user needs to initiate a cross-chain swap from Chain A to ZetaChain to Chain B (e.g., Ethereum), triggering `onCall` on Chain B.
2. The `onCall` function on Chain B must revert, causing the protocol to invoke `onRevert` on ZetaChain.
3. The `onRevert` function on ZetaChain must fail to execute e.g. because the `depositAndRevert` function in `GatewayZEVM` is paused, triggering `onAbort` on ZetaChain.

## External Pre-conditions
1. `depositAndRevert` function in `GatewayZEVM` must be paused during the time window between the initial block on ZetaChain, the block on Chain B, and the return transaction on ZetaChain.

## Attack Path
This is a vulnerability path, not an attack path, as the issue causes loss of funds due to misconfiguration rather than an exploitable attack:

1. A user initiates a cross-chain swap from Chain A to ZetaChain to Chain B (e.g., Ethereum) via `depositAndCall`, which triggers `onCall` in the target contract on Chain B.
2. The `onCall` function on Chain B reverts (e.g., due to an invalid swap configuration), prompting the protocol to call `onRevert` on ZetaChain , configured with `RevertOptions` setting `abortAddress = address(0)`.
3. The `onRevert` function fails to execute, either because `depositAndRevert` in `GatewayZEVM` is paused (e.g., by protocol administrators during a security incident).
4. The protocol aborts the transaction, triggering `executeAbort` on ZetaChain, which calls `onAbort` in the Universal App (e.g., `target = some address`).
5. Regardless of the outcome of `onAbort`, the protocol transfers the `outputAmount` of `targetZRC20` to `abortAddress` (`address(0)`) on Chain B, causing the funds to be permanently lost or in some unspecified state depending on how the transfer to address(0) is handled.

## Impact
The user suffers a 100% loss of their funds intended for the cross-chain swap, as the assets are transferred to the zero address on Chain B when `onRevert` fails and the transaction aborts, rendering them unrecoverable.
