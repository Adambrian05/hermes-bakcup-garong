# User tokens are pulled twice, resulting in double charge

### Summary

Because both the connector contract and the gateway contract call transferFrom for the same amount, users end up paying twice as many tokens as intended when making an ERC-20 cross-chain deposit.

### Root Cause

Connector’s depositAndCall pulls amount tokens from the user:

```solidity
IERC20(asset).transferFrom(msg.sender, address(this), amount);
```

Connector then approves the gateway but does not forward the tokens, calling:
```solidity
IERC20(asset).approve(address(gateway), amount);
gateway.depositAndCall(...);
```
Gateway’s depositAndCall interprets its msg.sender as the original user and pulls another amount from the user:


```solidity
IERC20(token).safeTransferFrom(msg.sender, custody, amount);
```
Thus, the user is debited twice for one deposit operation.

### Internal Pre-conditions

User grants allowance to the connector for amount tokens.

Connector has allowance to the gateway for amount tokens.

The ERC-20 asset is whitelisted so neither pull reverts immediately.

### External Pre-conditions

None 

### Attack Path

None

### Impact

Users lose 2× amount tokens instead of the intended amount. This double charge can lead to significant unintended token loss

_No response_

### Mitigation

Remove the connector’s transferFrom. Let the gateway perform the only pull from msg.sender
and check the balance with BalanceOf function
