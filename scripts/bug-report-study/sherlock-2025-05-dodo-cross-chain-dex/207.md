# `GatewaySend::onCall` always try to do swap even if the swap already done in prev chain

### Summary

the problem arise because there no check if the swap already done in the previous chain.
example where user try to swap their token A into token B in zeta chain and then bridge it back into the native chain of token B.
here we cleary see the `fromToken` is A and `toToken` is B and the swap are done in the zeta chain.
but later when the tx in native chain of token B are created by the corresponding gateway, the `onCall` would be invoked using previous message and then it would try to transfer the token A from gateway and wants to swap it into token B, which would fails.

### Root Cause

if we see the implementation of `onCall` inside the [`GatewaySend`](https://github.com/sherlock-audit/2025-05-dodo-cross-chain-dex/blob/main/omni-chain-contracts/contracts/GatewaySend.sol#L345-L367):

```solidity
        (
            bytes32 externalId, 
            uint256 amount, 
            bytes calldata recipient, 
            address fromToken, 
            address toToken, 
            bytes calldata swapData
        ) = decodePackedMessage(message);

        bool fromIsETH = (fromToken == _ETH_ADDRESS_);
        bool toIsETH = (toToken == _ETH_ADDRESS_);
        address evmWalletAddress = address(bytes20(recipient));

        if(!fromIsETH) {
@>            IERC20(fromToken).transferFrom(msg.sender, address(this), amount);
        }

        uint256 outputAmount;
        if(fromToken == toToken) {
            outputAmount = amount;
        } else {
@>            outputAmount = _doMixSwap(swapData);
        }
```

we see that the function would decode the message from the source chain, where it would check if the tokens used is native gas token.
the problematic line lies in the one marked, where if the from is not native gas token, it try to transfer the `fromToken` from gateway into this contract. this is problem because if in the source chain its already swapped into `toToken` then there are non existent amount of `fromToken` inside the zeta gateway in this chain.
second problem lies when contract try to swap the `fromToken` into `toToken` using `_doMixSwap`, where this supposed to be done in the original chain.

### Attack Path

1. on zeta chain, user wants to swap their USDC.BASE to USDT.ARB then bridged it into arbitrum
2. user call `GatewayTransferNative` and then it would swap with dodo from USDC.BASE to USDT.ARB
3. USDT.ARB then bridged to arbitrum, gateway would invoke `GatewaySend:onCall` using the same message
4. because from and to token are different, contract GatewaySend then try to transfer the from token and do swap again, but it would revert

### Impact

core function would be broken if the user initiate swap in zeta chain then proceed to bridge into destination chain

### PoC

_No response_

### Mitigation

we should check if the token received in destination chain is already swapped or not beforehand.
if the token already in the target token, proceed into transferring it to the `receiver`.
this logic is similar like the implementation `onCall` of `GatewayTransferNative`.
