```
1. CONTEST FLOW
   → Protocol posts contest (code + prize pool)
   → Watsons (researchers) submit findings during contest period
   → Judging: expert judges evaluate severity + validity
   → Escalation: watsons can dispute judge decisions
   → Payout: prize pool split by severity + uniqueness

2. JUDGING PROCESS
   → Judge reads ALL submissions
   → Classifies: High / Medium / Low / Informational
   → Checks for duplicates (same root cause = split prize)
   → Validates exploit path (must be realistic)
   → Escalation: watson can challenge judge ruling
   → Final: head judge resolves disputes

3. WATSON BEST PRACTICES
   → Submit EARLY (first to find = more prize)
   → Clear exploit path (not just "this looks wrong")
   → PoC or detailed reproduction steps
   → Severity must match IMPACT (not just likelihood)
   → Check trust assumptions (don't report "admin can rug")

4. SEVERITY CRITERIA (Sherlock specific)
   HIGH:
     → Direct loss of funds (user or protocol)
     → Protocol insolvency
     → Permanent freeze of funds
   MEDIUM:
     → Conditional loss (requires specific conditions)
     → Griefing (attacker loses money too)
     → Temporary freeze
   LOW:
     → Best practice violation
     → Gas optimization
     → Code quality
```
